## Overview
<!-- GENERATED:setup:overview start -->
Cross-platform Tauri 2 desktop dashboard for local OpenTelemetry — receives OTLP telemetry from any local app, visualizes traces/metrics/logs in a GPU-accelerated webview, runs as a quarter-screen always-visible glance widget plus a full expanded dashboard, and one-click "Investigate" generates a token-efficient curated markdown snapshot for paste-to-AI debug sessions. Optional MCP stdio sidecar lets AI agents query telemetry directly. Public OSS (MIT OR Apache-2.0) on GitHub Releases.

**Stack:** Rust 2024 / toolchain pinned rustc 1.95.0 (the workspace declares `rust-version = "1.95"`, equal to the pin and set by the dependency graph — wasmtime / cranelift / pulley declare 1.95.0; the workspace's own code needs ≥ 1.89 for `std::fs::File::lock`; the xtask test `declared_floor_equals_the_pinned_channel` holds the declared floor equal to the pin) + Tauri 2.x (single-process modular monolith, 14 library crates + `pulse-app` binary + `xtask`) — `tonic` 0.14 OTLP/gRPC `:4317`, `axum` 0.8 OTLP/HTTP `:4318` on `hyper` 1 + `tower`, DuckDB 1.5 in-memory ring buffer with Apache Arrow zero-copy, persistent SQLite incident corpus (chunk #68; cell-level AES-256-GCM — the key comes from the OS credential store via `keyring` 3 with its explicit platform feature set, with an opt-in `ANDROMEDA_PULSE_CORPUS_PASSPHRASE` fallback; see arch §Occupied Resources), React 19 + Tailwind v4 + WebGPU/WGSL webview via TauRPC, `wasmtime` 25+ Component Model plugins (requirement `"48.0.4"`, resolved 48.0.5 — chunk 2026-10-04-supply-chain-advisories-on-wasmtime-resolved upgrade closing RUSTSEC-2026-0325 / -0326 / -0327 with no advisory ignore; 49.x needs Rust 1.96 while the toolchain is pinned at 1.95), hand-rolled JSON-RPC 2.0 MCP sidecar (`rmcp` 3.x rides feature-gated as a declared anchor dep), `llama.cpp` prebuilt binaries (b9305-pinned series) invoked via subprocess D1 spawn-per-generation as the L4 LLM interpretation runtime (chunk #82 trait surface; session 144 runtime swap from `mistralrs` per upstream issue #1134 CPU deadlock — empirical cross-check showed llama.cpp generates cleanly at 122.3 tok/sec under L4 GBNF constraint on RTX 3090 vs mistralrs zero-token deadlock on the same host; `interpretation` crate hosts the trait surface, concrete impl swaps `MistralRsInference` → `LlamaCliInference` at the binary boundary). The shipped L4 model is the founder's pick, unsloth `gemma-4-E4B-it-Q4_K_M` (selected by `ANDROMEDA_PULSE_MODEL_PATH`), run with its authors' sampling `--temp 1.0 --top-p 0.95 --top-k 64 --min-p 0`, thinking off (`-rea off`), and constrained by the committed GBNF `pulse-app/src/l4-output.gbnf` passed with `--grammar-file` — never `--json-schema-file`, which b9305 prefills and gemma4 fails at sampler init. The GBNF is the b9305 converter's output for the shipped schema, pinned by `pulse-app/tests/unit_l4_grammar.rs`, which runs the vendored test-only converter (`pulse-app/vendor/llama-cpp/`, MIT) and needs Python 3 at test time (chunk 2026-10-05-l4-runs-the-founder-s-pick-with-its-authors-settings).

## Critical Warnings (universal invariants)
<!-- GENERATED:setup:warnings start -->
- OTLP receivers MUST bind to `127.0.0.1` only — loopback is the de-facto authorization boundary; never `0.0.0.0` or any non-loopback interface.
- DuckDB queries MUST use prepared statements with `?` placeholders — never `format!("SELECT … WHERE service_name = '{}'", user_input)`. (2026 DuckDB CVE cluster.)
- OTLP payloads MUST pass post-`prost` invariant checks — `span_id` is 8 bytes, `trace_id` is 16 bytes, attribute keys/values bounded; `prost` only validates wire format.
- **Product-binary** path env vars (`ANDROMEDA_PULSE_*_PATH` / `*_DIR`) MUST canonicalize via `std` both-sides-canonicalize on the `publish_workspace_key` precedent (the single path primitive since 2026-08-29-advisory-backlog — `strict-path` dropped, never used) and assert resolved path lives under the data dir (CWE-22 defense). Carve-out: a harness/xtask-only tool-locator var not consumed by the production binary, resolving an external tool that lives outside the data dir by design (`ANDROMEDA_PULSE_MSEDGEDRIVER_PATH`, `_PIDFILE`, `_LOGFILE`), is guarded by trim + `is_file()` + clean-skip instead; the `agent-run.{sh,ps1}` boot-recorder state files `run/andromeda-pulse.{spawn,exit}` are a sibling harness-only class (never product-read), as are the harness-written `logs/harness-settled.json` / `logs/xvfb.log` and xtask's presence-only read of `DISPLAY` / `DBUS_SESSION_BUS_ADDRESS` / `XDG_RUNTIME_DIR` (labels only). NARROWED EXCEPTION (guard landed 2026-08-26): the PRODUCT-consumed `ANDROMEDA_PULSE_MODEL_PATH` / `_LLAMA_{CUDA,CPU}_BIN_PATH` reject traversal BEFORE canonicalizing + bound length + canonicalize + assert regular-file, with data-dir confinement replaced by OPT-IN `ANDROMEDA_PULSE_L4_ALLOW_ROOT` (fail-closed if set-but-unresolvable) — opt-in because the GGUF and `llama-cli.exe` live outside the data dir by design; unconfined only when unset, and announced once per boot. The L4 guard uses `std` both-sides-canonicalize, NOT `strict-path`. Ratified carve-out (2026-10-04): the system `XDG_RUNTIME_DIR` (Linux) is product-read as the corpus-key lock dir — canonicalize + absolute + is-dir, FAIL CLOSED when set but unusable, deliberately not data-dir-confined (security-plan §Security Anti-Patterns → Input).
- Every TauRPC procedure MUST have its `EXPECTED_PROCEDURES` pin in `xtask/src/main.rs` (what `capability-drift` diffs — against the worktree AND, since 2026-08-30, the staged git-index bindings, with the staged `capabilities/*.json` grants asserted vs `staged_gate::EXPECTED_GRANTS`) plus a validated argument struct — NOT a per-procedure `pulse-app/capabilities/` entry, which does not exist in this project (TauRPC dispatches every method through one invoke handler; measured 2026-08-21). Tauri capabilities remain NEGATIVE-DEFAULT at the IPC-layer and per-CORE-API granularity: `fs` / `shell` / `dialog` / `http` and each `core:window:*` permission require an explicit grant with rationale, and ARE silently rejected at runtime when missing.
- Self-observation NEVER dials own OTLP — `tracing` ecosystem only (no OTel SDK in self-runtime); a network exporter pointed at own `:4317`/`:4318` is infinite recursion.
- NEVER log raw OTLP attribute values, snapshot file contents, clipboard contents, MCP tool response bodies, full plugin paths, or DuckDB query parameter values — incidentally captured secrets from instrumented host apps.
- Errors crossing the TauRPC bridge MUST be `serde`-friendly `AppError` enum variants — convert from `thiserror`/`anyhow` via `From` impls; strip stack traces, file paths, library versions, Rust struct names.
- Every transition MUST respect `prefers-reduced-motion: reduce` (app-wide, token-bound; WCAG 2.1 AAA SC 2.3.3). The Halo State Pulse glow layer is DEFERRED to the next version (ruling 2026-08-29); its degrade-to-static-glow rule (hue still updates per cumulative incident severity) ships WITH it — the live severity signature is the constellation dot hue.
- Fault identity is DECIDED, not inferable from code shape (arch §Established Decisions [Fault Identity]): stacktrace normalization strips only TOKEN-LEADING absolute paths — relative structure is identity-significant, so `src/a.rs` ≠ `src/b/c.rs`; incidents coalesce per cue identity `(kind, scope, scope_id)`, never per `L4Output.fingerprint` (model-authored, constant under the deterministic runner). `Incident.fingerprint` carries the L1 exception fingerprint threaded via `AttentionCue` → `DigestCueRef`, encoded with `triage::contract::hex_lower` (full 32-char hex) — NEVER `fingerprint_to_hex_prefix` (4 bytes, tracing-only; a prefix can never match the retrieval arm). The corpus-retrieval `fingerprint_match` arm is FED — never "simplify" it away. The cue KIND reaches the incident TEXT, never its identity: the producer writes `Incident.title` (and the persisted L4 JSON title) as `{triage::contract::cue_cause_label(kind)}: {model title}`, grounded before the scrub. The digest's `TRIGGER: {cue_cause_label}` line — the L4 prompt's framing of which signal to describe — is keyed on the SAME first cue the identity is taken from; it is framing, never identity. That line carries the kind label ONLY, never the `scope_id` or a service name (ruling 2026-10-04, standing); the service reaches the first hypothesis through the framing instruction, which obliges it to name the cue line's `scope_id`, by reference. The digest's `CORPUS MATCHES:` block is prompt context selected per cue, never identity: under a triggering cue that carries a `scope_id`, `select_corpus_matches` keeps scope matches of that scope only (the founder's choice of `CX`, 2026-10-07; not shown to be the whole remedy), the fingerprint arm unchanged.

## Architecture
<!-- GENERATED:setup:architecture start -->
Local-first, zero-infrastructure modular monolith: every byte of telemetry stays on the developer's machine; fourteen library crates linked into the `pulse-app` Tauri binary (sixteen workspace members total: fourteen library crates + the `pulse-app` binary + the `xtask` task-runner crate — the canonical list is arch §Occupied Resources §Cargo workspace crate names, which any count word defers to) share memory via tokio mpsc + broadcast (ingest → buffer → viz / MCP / snapshot subscribers) so the OS sees one process and ingest→viz latency is microseconds. Standards-track at the edges (OTLP at `:4317`/`:4318`, MCP over stdio, WASM Component Model plugins) and tightly opinionated in the middle (TauRPC bridge, Arrow zero-copy hand-off, `serde`-friendly `AppError`) — external tooling Just Works while agent-driven development stays unambiguous. Capability-scoped extensibility: WASM plugins receive only the host imports declared in their WIT; Tauri's `pulse:default` capability is the negative-default trust model (no auth required because there are no user accounts).

## Session Learnings
_This section is curated by `/wrap-session`. It accumulates universal (Tier 1) rules captured from work sessions — rules that apply to every file and every task. Do not edit manually during wrap-session runs — changes are preserved but wrap-session appends new entries here._

- The product IS the local observer — `tracing` ecosystem only for self-observation; an OTel network exporter pointed at own `:4317`/`:4318` is infinite recursion.
- Tauri capabilities are negative-default at the core-API layer: a new TauRPC procedure needs router registration AND its `EXPECTED_PROCEDURES` pin in `xtask/src/main.rs` — never a per-procedure `pulse-app/capabilities/` entry, which does not exist here — while a missing `fs` / `shell` / `dialog` / `http` / `core:window:*` grant IS silently rejected at runtime. [corrected 2026-10-06: the six capability files hold core and plugin permissions only, no procedure name]
- Telemetry is user-controlled content — incidentally captured secrets in OTLP attribute values mean snapshot files / clipboard / MCP tool responses / DuckDB query parameters NEVER appear verbatim in self-observation logs.
- 2026-05-16: After-MVP evolution goes through `/andromeda-evolve` (within its Refuse 1-6 scope), manual edits to arch.md and the specialist plans where evolve refuses, then `/andromeda-setup-project --delta`; the greenfield skills are write-once and never re-derive existing docs. Full text: `.claude/docs/session-learnings.md`, "Moved from Tier 1: the after-MVP evolution path".
- 2026-05-20: Migration helpers preserve the source on failure: delete the legacy source only on FULL success; a partial migration reports degraded success and keeps the legacy file, a failed one leaves it intact for the next boot's retry. Full text: `.claude/docs/session-learnings.md`, "Moved from Tier 1: migration helpers preserve the source on failure".
- 2026-05-20: `bincode` 1.3.x `deserialize` is UNSAFE on untrusted input (it pre-allocates from the length prefix and aborts on OOM; `with_limit` does not protect map-shaped types): validate the length prefix for plausibility BEFORE bincode sees the bytes. Full text: `.claude/docs/session-learnings.md`, "Moved from Tier 1: bincode 1.3 deserialize on untrusted input".
- 2026-05-20: To scrub `pub(crate)` fields of a lower crate's struct from an upper crate, add `scrubbed_clone<F: Fn(&str) -> String>(&self, scrub: F)` on the lower-crate side and inject the scrubber as a closure; a leaf crate never depends on a sibling crate. Full text: `.claude/docs/session-learnings.md`, "Moved from Tier 1: scrubbed_clone with an injected closure".
- 2026-05-25: Choose in-process bindings, subprocess-spawn or a persistent server for a heavy dependency from the invocation rate MEASURED in the codebase, not from theoretical throughput; for background-cadence calls with no user waiting, a subprocess behind a trait at the binary boundary usually wins.
