## Goal
The `supply-chain` job of the `ci` workflow fails on a push and passes on a pull request for the same tree. The
cause is measured (research.md, the two job logs and the action's source at its pinned commit): the
`rustsec/audit-check` action tries to create a check run, the token may not write one, and the action swallows
that denial only on a pull-request event. It bites whenever the audit has something to report, and the tree
carries 10 informational warnings, so it bites on every push.

The chunk replaces the action with a plain `cargo audit` step. That step publishes nothing, receives no token and
reads no event, so it ends the same on both events by construction: exit 0 when clean, 1 on a vulnerability, 2 when
it could not evaluate. No permission is widened; the step's token input is removed (per security-plan §Secret
Management, GitHub Environment scoping; security-plan §Dependency Security, CI integration).

The repair lands in two places. On the build branch it ships with the chunk. A second branch, cut from `main`,
carries the same repair and the test that holds it, nothing else of 0.4.0, into a pull request the founder merges
by his own hand. His merge is a push to `main`; that push run is the witness, where the defect showed. **A green
pull-request run does not witness this repair** (inputs#I1 item 2): the old step passed there too. This departs
from the direction at `security-plan.md:226` for this repair, on the founder's ruling (founder, 2026-10-09, by
dialog — relayed verbatim by the pc overseer; inputs#I3).
