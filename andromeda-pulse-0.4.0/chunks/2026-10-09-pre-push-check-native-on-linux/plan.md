## Constraints & rejected approaches
- A stage that inherits the developer's session (the bus address, the runtime dir) — rejected: it would reach the
  OS credential store, which the check does not reach today. That is a boundary widening and the founder's own
  word (inputs#I1 item 6; playbook pattern "Boundary widening").
- A regen stage after `test` — rejected by the operator's answer: no stage that exists only for the bridge.
- Running on the host's Node, or pinning the npm major — rejected by the operator's answer: the check exists to
  predict CI, so an unmet pin reads `cannot-evaluate`.
- Probing ci.yml's apt list, through `pacman` or a `pkg-config` name map — rejected: the list is CI's Ubuntu
  spelling, one of its members is absent on a host where every stage passes, and a name map would be a second pin
  not read from the repository. A missing system library surfaces as a red `clippy` stage with the build's own
  error, which is never green.
- `PUPPETEER_SKIP_DOWNLOAD=1` for the `npm` stage — rejected: CI's `npm ci` runs the install scripts, and the
  founder's ruling is to isolate the cache, not to skip the download.
- A local clone or a second worktree for the stages — rejected: the entry removes the clone, and a second
  `target/` on this host is tens of gigabytes.
- Do not delete or rewrite anything under `target/pre-push/` except `run/` and `report.json`, and never
  `~/.cache/puppeteer`.
- Do not rename the verb, add an `agent-run` verb, edit `.github/workflows/ci.yml`, remove a stage, or touch a
  `.ps1` file or another system's branch: each is another entry's or nobody's.
- Do not bind a port or start `pulse-app` from the verb.
- Do not fold the folded watch into a step, a criterion or an entry.
