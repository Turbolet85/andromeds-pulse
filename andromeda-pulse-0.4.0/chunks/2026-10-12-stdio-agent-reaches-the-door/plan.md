## Goal
An agent on the developer's machine that speaks MCP over stdio starts `andromeda-pulse-engine door` and reaches the
console engine's door through it, with no sidecar. The new word is a short-lived relay. It takes the data dir the
way `run` does and resolves the door's socket under it, confined and canonical. Each request line it reads on stdin
gets a connection of its own: the line is written, the write side is closed, and whatever the door answers is copied
to stdout unchanged. Standard input ending ends the relay with exit 0. A door it cannot reach ends it with exit 1 and
one fixed line on stderr. The relay never writes an answer the door did not give.

The form is the operator's P4 answer, PROVISIONAL (the pc overseer, 2026-10-12, inputs#I3; the founder's own word on
the door is still owed): form B, the word `door`; one connection per request; no file, listener, pid file,
environment variable or binary added; proof (b), the relay's own other-account arm on the runner, in the existing
`Door refuses another account` step; door unreachable is exit 1 with one fixed stderr line.

The door's surface does not move (inputs#I2 item 3; architecture §Standard Contracts → Engine door, `:157`). The
sidecar stays (inputs#I2 item 4). The relay is a client of the socket: the door reads its account as it reads any
caller's (per security-plan §Authentication & Authorization), and it writes one `door.call` per answered request in
the engine's own log (per obs-plan §4 Scenario P3). The relay itself writes no record and no file (per obs-plan §3
Logging stack; arch §Occupied Resources → Process / service identity).

## Implementation Steps
1. **The word.** In `pulse-app/src/console.rs` add `Command::Door` to the closed enum. `parse` takes `door` as a third
   word, with the same rules as the other two: exactly one word, case-exact, a non-Unicode word refused. `USAGE`
   becomes `usage: andromeda-pulse-engine <run|version|door>`. `main` sends `Command::Door` to the relay's entry
   (step 2) and returns its exit code. `door` builds no tokio runtime and calls neither `engine_boot::init_process`
   nor `engine_boot::start`.
2. **The relay.** In the new module `pulse-app/src/door_bridge.rs`, registered as `pub mod door_bridge` in
   `pulse-app/src/lib.rs`:
   - **Its socket path:**
     - It takes the data dir from `engine_boot::resolve_data_dir()`, the function `run` uses. No other environment
       variable is read.
     - Both sides are canonicalized: the data dir, and `{canonical data dir}/run/door/sock`.
     - The resolved socket must lie under the canonical data dir and be shorter than 108 bytes.
     - Any failure in this is "the door cannot be reached".
   - **Its loop:**
     - It reads standard input line by line, and a line of whitespace alone opens nothing.
     - Each other line takes one connection over `std::os::unix::net::UnixStream`: the line and its `\n` are written,
       the write side is shut down, and everything the door sends until it closes is copied to stdout and flushed.
       Then the connection is dropped.
     - A line longer than `door::MAX_REQUEST_BYTES` is sent as its first `MAX_REQUEST_BYTES + 1` bytes, so the door
       refuses it as over the bound. The rest of that line is read and discarded up to its `\n`, never sent as a
       request.
   - **Its end:** standard input ending is exit 0. A connect, write or read failure on the socket, or a failed write
     to stdout, writes the one fixed line `andromeda-pulse-engine door: the door cannot be reached` to stderr and
     exits 1.
   - **What it never does:**
     - parse JSON, build an answer, or retry a request;
     - write a log record, a file or a pid file;
     - set or pass an environment variable, or start a process;
     - write anything to stdout but the door's bytes, or to stderr but the fixed line.
   - **Off Unix:** the word prints the fixed line and exits 1, since no door is seated there.
   - The functions the tests drive (path resolution, the loop over a reader and a writer, the fixed line) are `pub` +
     `#[doc(hidden)]`, on the `door.rs` precedent.
3. **The relay's own arms, in process.** In the new test file `pulse-app/tests/unit_door_bridge.rs` (Unix only), over
   a stand-in `UnixListener` in a short temp dir:
   - **(a)** three request lines open three connections, in order. Each one receives its line whole, then the end of
     the stream. Each stand-in answer reaches the output, in order and byte for byte.
   - **(b)** a line the stand-in does not answer (a notification) leaves the output empty and still used one
     connection.
   - **(c)** whitespace-only lines open no connection.
   - **(d)** each of these reads "cannot be reached", with nothing written to the output:
     - no data dir;
     - a data dir with no socket;
     - a `run/door` that is a symlink to a directory outside the data dir;
     - a data dir deep enough that the socket path reaches 108 bytes.
   - **(e)** an over-bound line: the stand-in receives `MAX_REQUEST_BYTES + 1` bytes and then the end of the stream.
     The next line after it arrives on its own connection, whole.
   - **(f)** the fixed line is the exact text step 2 names.
4. **The grammar's pins.**

   then `andromeda-pulse-engine door` spawned by `ENGINE` path.
   - **The relay's environment:** a cleared environment holding only `ANDROMEDA_PULSE_DATA_DIR` = the engine's data
     dir, plus `LLVM_PROFILE_FILE` when this process has one, as `Running::spawn` passes it
     (`integration_door.rs:93-95`). Its working directory is a TempDir outside the data dir, so a coverage build's

   `another_account_through_the_bridge_receives_nothing`. It uses the same skip guard as the three-layer arm
   (`sudo -n true` fails → it prints `door bridge other-account arm: skipped, no second account` and returns).
   - **Setup:**
     - Spawn and ready an engine, and open its data dir and `run/` to 0755, as the three-layer arm does.
     - Copy the built `ENGINE` binary into a TempDir of the arm's own at mode 0755, so another account can execute
       it whatever the checkout path's modes.
     - The relay is run as `nobody` and as root by `sudo -n [-u nobody] env ANDROMEDA_PULSE_DATA_DIR={data dir}
       {copy} door`, with one `ping` request on stdin. Its working directory is the arm's own opened TempDir, so an
       instrumented copy under the `coverage` job writes its profile there and never into the checkout. Nothing else
       runs as another account.
     - The fixed line is read as one line of the relay's stderr, never as the whole of it: an instrumented copy run
       under another account may add the profiler's own line.
   - **The readings:**
     - **As made:** `run/door/` 0700 and the socket 0600.
     - **Opened:** `run/door/` 0755 and the socket 0666, so only the account check is left.
     - In the same run, the owner's own relay with no sudo is answered.
   - **What it asserts:**
     - No reading by another account wrote a byte to stdout.
     - `nobody` as made exits 1 with the fixed line.
     - With the outer layers opened, both readings exit 0 with empty stdout.
     - After the end, the `door.refused` records equal the number of other-account readings that exited 0 (the ones
       that reached the door), each `other_account` / `other`, every field rendered.
     - Exactly one `door.call`, the owner's `ping`.
   - **On success it prints** `door bridge other-account arm: no byte reached another account through the bridge, the
     account check refused`.

## Constraints & rejected approaches
- Form A, the agent dialling the socket through a relay it supplies (`socat STDIO UNIX-CONNECT:…`) — not chosen at
  P4. It holds one connection, so the door's 30 s idle bound (`door.rs:508-512`) ends the agent's session at its
  first pause with a WARN each time, and it rests on a tool the project does not ship or vet.
- Form C, a separate `andromeda-pulse-door` binary — not chosen at P4: a fourth product binary for the same behaviour.
- `andromeda-pulse-engine run --stdio` (the agent starts its own engine and talks to it over stdio) — rejected: a new
  transport on the engine and a second engine on the same ports, a widening of the surface rather than a way to the
  door.
- One connection held for the whole session — rejected: the 30 s idle cut, as form A.
- Calling `engine_boot::init_process` (or any log sink) from `door` — rejected: it writes `run/andromeda-pulse.pid`
  and the engine's log family, which `harness:status` and `check:engine-log` read (`engine_boot.rs:210-251`,
  `:324-331`).
- Parsing a request, answering one on the door's behalf, or retrying — rejected: the relay never writes an answer
  the door did not give (inputs#I3 item 3).
- A new environment variable, a flag or a value on the word — rejected: the word takes no value (inputs#I3 item 1;
  security-plan §Input Validation, the console command-line row: "a later command that takes a value, a path or a
  network address is a new question each time").
- Running the checkout's own `ENGINE` path under `sudo -u nobody` — rejected: whether another account can execute
  files under the runner's checkout is unmeasured, and a skip there would turn the step red for the wrong reason. The
  arm runs a copy from its own opened temp dir.
- Any change to `pulse-app/src/door.rs`, to the tools crate or to the sidecar — out of scope (inputs#I2 items 3 and
  4); the scope guard enforces it.

## Implementation notes
- **What each way reaches, during the interval until `Stdio sidecar retired`** (inputs#I2 item 4; read from
  `crates/mcp-server/src/bin/andromeda-pulse-mcp.rs` and `pulse-app/src/door.rs` at `d3e694d2`):

  | | stdio agent through `andromeda-pulse-engine door` | stdio sidecar `andromeda-pulse-mcp` |
  |---|---|---|
  | Runs when | a console engine `run` holds the door on that data dir (Unix only) | built with `--features mcp-server` and started with `ANDROMEDA_PULSE_MCP_ENABLED=true`; needs no engine |
  | Telemetry tools | read the engine's live buffer | read the sidecar's own empty in-memory DuckDB (`init_buffer_connection`) |
  | Incident tools | the engine's corpus writer and workspace key, in process | the corpus opened through the OS credential store, the key read from `run/workspace-key` |
  | `mark_incident_resolved` | refused `-32001` unless `ANDROMEDA_PULSE_DOOR_RESOLVE` is on | applied under the double gate alone |
  | Undeclared argument member | refused `-32602` by the door | read past (security-plan §Input Validation, the MCP stdio row) |
  | Who is answered | the engine's own account (kernel-read) | whatever process started it |
  | Bounds | the door's (65 536 B line, 1 MiB answer, 5 s call, 8 connections) | none of the door's |
  | Records | `door.call` / `door.refused` in the engine's log | the `mcp.*` chain on the sidecar's stderr |

  Nothing is reachable through the sidecar that the door does not also serve, since both carry the same nine tools
  over the same `jsonrpc.rs` envelope. The differences are the sidecar's empty telemetry store, its unswitched write
  and its looser argument check. The sidecar leaves, with them, at `Stdio sidecar retired`.
- **The idle bound and the relay:** per research (Patterns detected), for one request line followed by the end of the
  stream, the door writes one `door.call`, then the answer, then ends the connection with no record
  (`door.rs:482-484`, `:513`, `:530`, `:540`). That is the equality the one-connection-per-request form rests on. The
  over-bound line is answered `-32600` and closed by the door (`door.rs:514-520`).
- **The relay has no time bound of its own:** the door bounds a call at 5 s and closes an idle connection at 30 s, and
  the relay half-closes after its one line, so a read ends when the door ends the connection.
- **Path length:** the relay refuses a socket path of 108 bytes or more, the door's own bound (`door.rs:350`,
  `:387-389`). A unit arm needs a data dir short enough to stay under it, so use the system temp root directly, never
  the session scratchpad (handoff, Host).
- **The skip exception extends to a second arm:** the relay's other-account arm skips where `sudo -n true` fails (this
  host, in every run), as the three-layer arm does. The step turns its skip red, because the step requires the arm's
  own sentence (rules/security.md, the second-account step; the handoff's stated exception to "a test-only host tool
  FAILS, never skips").
- **Off Unix:** the word exists in the grammar everywhere and on a non-Unix system only prints the fixed line. The
  owner of that branch is `Other operating systems retired from the code`.
