3. **The settle verdict, `cargo xtask harness:settled`.** It polls, bounded by `--timeout-seconds` (default 30),
   until one of three things is true, then prints one JSON object and writes the same object to
   `logs/harness-settled.json` under the resolved data dir:
   - the app's pid is no longer alive → `ended`, exit 1;
   - the log family `agent-latest.jsonl*` holds an `app.boot.window.navigation` record for each of the four window
     labels (`compact-widget`, `main`, `findings`, `report`; emitted once per label 5 s after boot by
     `spawn_navigation_check`, `pulse-app/src/window.rs:270-300`, whether or not the window navigated) and the pid
     is alive → `settled`, exit 0;
   - the timeout passes → `not-settled`, exit 1.
   The object carries, on every arm: the verdict; the pid; `ended` (the exit record, read through `read_ended`);
   `app_exit_record` (`present` · `absent`, whether the log family holds an `app.exit` record);
   `windows_settled` (0 to 4); `display` and `session_bus`, each `reachable` · `gone` · `unset` · `unknown`.
   - `display`: `DISPLAY` unset → `unset`; a local display (`:N` or `:N.S`) → a connection attempt to the X
     socket of that number, `reachable` or `gone`; any other form → `unknown`.
   - `session_bus`: `DBUS_SESSION_BUS_ADDRESS` holding a `unix:path=` address, else the `bus` socket under
     `XDG_RUNTIME_DIR` → a connection attempt, `reachable` or `gone`; neither variable set → `unset`; any other
     address form → `unknown`.
   - No value of any of the three variables is printed or written, only the label.
   - A `--timeout-seconds` below 8 is refused as `cannot-evaluate`, exit 2: the settle record cannot exist before
     5 s, so a shorter window could never read `settled`.
   The decision is a pure function over the probe results, pinned per arm; the two address parsers are pinned on
   each form above; the socket probes are pinned against a real Unix listener in a temp dir and against an absent
   path.

## Constraints & rejected approaches
- A retry, a re-run or a soft-fail around the smoke — hides the end this chunk has to name (test-plan §11; the
  smoke step is gating by an operator-approved amendment).
- A fixed sleep to give the app life — the settle read waits on the app's own record, bounded, or on its end.
- Stopping the app sooner so the smoke never reaches the webview — it would read green every time and show nothing.
- Any change under `pulse-app/src`, `pulse-app/ui` or `crates` — no run has named a cause; a fix aimed at one no
  run has shown is not this chunk's outcome (inputs#I1 item 2).
- A product-side switch or environment default for the harness's benefit (disabling the accessibility bridge,
  compositing or the tray in the product) — a boundary widening, and it would change what ships.
- A new field or arm on `harness:status`, or a sixth `agent-run` verb — both are registered contracts; the two new
  verdicts are their own xtask verbs.
- A new script under `scripts/` for the smoke sequence — unpinned by the mode check and a second harness surface.
- A syscall tracer in the job — not validated on this host (none is installed) and not yet shown to be needed; it
  is the next instrument if a run ends with the display and the bus both reachable.
- Printing or storing the value of `DISPLAY`, `DBUS_SESSION_BUS_ADDRESS` or `XDG_RUNTIME_DIR`, or uploading the
  data dir's `run/` — `run/workspace-key` holds a workspace path.
- Fixing on top of a red first run without the operator's word — the pass stops there.
- Naming a cause from the display-lost control — it shows what a lost display looks like here, not that the
  runner's display goes away.
