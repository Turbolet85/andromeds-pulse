input their job gives them. As measured on `ci#38038281709` and on the dev host (research.md): the coverage step
exits 0 over a report tracking nothing; its branch arm has read `0/0 = 100.0%` on every run, because the pinned
toolchain cannot write a branch count; five nextest invocations pass a run that selects no test; `cargo xtask
ci-gates` prints four NEUTRAL lines and exits 0 over an absent log, and in the boot job its heartbeat and
perf-budget arms read one tick per target and no gradable sample; `cargo xtask quarantine-tracking` prints NEUTRAL
and exits 0 when none of its search dirs exists.

make it fail, or it is gone. An empty coverage report fails and the branch arm is retired; every nextest invocation
fails on an empty selection; `ci-gates` keeps the two arms that read the boot log and makes an absent log an exit
of its own; the quarantine check fails on an absent input and prints what it scanned. Two readings are not repaired
and keep an owner: the a11y upload's path members and the pre-push `ci-gates` stage (per test-plan §9 Pipeline
structure, obs-plan §10 CI gates, architecture §Occupied Resources → xtask CLI surfaces).
