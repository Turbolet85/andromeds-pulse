## Deviations from intent

1. **Added a 7th stage, `widget-close`, beyond the plan's 6-stage table.** The plan's Step 1 says to replace the single `is_widget_hidden_transition` boolean *"with a per-stage predicate set"*, while its Step 3 table enumerates six stages, none of which is the widget close. Following the table literally would have orphaned that predicate — which is the **only** guard on `core:window:allow-close` and the entire deliverable of the immediately preceding chunk, retiring a shipped guard one chunk after it landed. Resolved in the direction Step 1's own wording supports: the close became a **terminal** stage (terminal because the press sends the app to the tray). Surfaced to the operator mid-implement rather than interpreted silently. **Justified: preserves a shipped guard; no scope expansion (same 2 files).**
2. **Split the combined stage predicates into separately reported `obs` / `dom` halves** (+2 unit tests, `StageHalves` with `Option<bool>` for inapplicable halves). Not in the plan. The first live failure reported only "absent", which cannot distinguish *telemetry never landed* from *telemetry never reached the screen* — the first question a red stage raises. **Justified: the plan's Step 1 asks for a verdict "that reports which stages passed and which did not"; this is that requirement met honestly. It directly diagnosed 3 of the 6 fix-loop defects.**
3. **Kept two diagnostics in the shipped harness** — a per-handle dump (Tauri window label + URL + marker presence) and a transition-record dump on close-stage failure. Not in the plan. **Justified: each converted a run that said only "absent" into one that named the cause; a harness that cannot report what it saw is the failure class this chunk exists to close.**
4. **Wired `ANDROMEDA_PULSE_L4_DETERMINISTIC=true` into the driver's spawn environment.** The plan's acceptance says the leg drives the path *"under deterministic-L4"* but names no owner for establishing it, and the app under test is a **grandchild** process (xtask → node → tauri-driver → app), so the gate must ride the driver spawn env. **Justified: without it the L4 path attempted real model inference, found no configured model, and no incident formed — a failure indistinguishable from a broken storm→incident seam.**
