## Goal

Turn the one-press headful leg into a **scripted five-stage assembled-path e2e** that drives the real
product under deterministic-L4 and asserts, at each stage, against an observable the driver can read.
This claims **P-076** (`verification-matrix.json#P-076`) — the capability two prior chunks advanced and
explicitly declined.

The gap P-076 exists to close is intent F15's: 1886 nextest + 801 vitest + a11y all green while the
*integrated* UX was broken. Every existing gate tests a component in isolation; nothing drives
launch → telemetry → Traces → storm → incident → Investigate as one path. The predecessor
(`2026-08-23-webview-self-verify`) built the harness that can — tauri-driver + WebdriverIO under
`cargo xtask webview-drive` — but pressed exactly one control and asserted one record.

The design rests on three things research established, not assumed. **(1) Every observable already
exists.** All three acceptance assertions bind to obs records emitted at HEAD, and none needs a new
allowlist leaf — verified field-by-field (research.md §The three acceptance observables). **(2) The
storm stage needs no new fixture:** `crates/ingest/examples/inject_demo.rs` is purpose-built for this
exact chain and speaks real OTLP gRPC, satisfying arch §Test-time telemetry injection's no-back-door
rule. **(3) The selector convention is mixed** — accessible names ship on the Investigate controls and
`ConnectionDot`, `data-testid` on Traces/EmptyState/footer — so the leg binds per surface to what
actually ships, per the operator decision at P5-preview (a11y-plan §1 P1's `region[aria-label=
"Telemetry traces chart"]` does not exist at HEAD and stays owned by the "A11y verification" entry).

Two disciplines from `rules/verification-harness.md` §2026-08-23 are load-bearing and shape every
stage: **match the effect record, never the target alone** (boot itself emits `ui.layout.transition`,
so a target-only match passes on a record the press did not cause), and **a green-on-arrival
regression guard MUST be mutation-checked or it guards nothing**. Every surface this leg drives works
today, so without a discriminating RED arm the whole leg is decorative.

## Implementation Steps

1. **Model the leg as an ordered list of named stages** in `xtask/src/webview_drive.rs`. Each stage
   carries an id, the driver action it expects, and a **predicate over obs records** that is
   discriminating — it must match on a FIELD VALUE the stage causes, never on the target alone.
   Replace the single `is_widget_hidden_transition` boolean with a per-stage predicate set and a
   staged verdict that reports which stages passed and which did not.

2. **Extend the driver script** `pulse-app/ui/tests-e2e/webview-drive.mjs` from one press into the
   stage sequence below, reusing its existing substrate unchanged: `pollUntil` bounded polling (never
   `sleep(N)`, per test-plan §11), `findWidgetHandle`-style per-stage handle resolution (four windows
   exist and the session lands on an arbitrary one), and the `finally`-guarded `deleteSession`.
   Preserve the split: **the script drives the scenario and presses; it asserts nothing.**

3. **Stage sequence** (the operator-selected set — 3 acceptance stages + the two absorbed CARRYs that
   cost no extra driver mechanic):

   | # | Stage | Driver action | Discriminating assertion (xtask side) |
   |---|---|---|---|
   | 1 | `launch` | boot under det-L4, resolve the dashboard handle | telemetry arrival — `buffer` rows advancing, not merely a booted window |
   | 2 | `traces-empty` | navigate to Traces before injection | `[data-testid="trace-table-empty"]` present — the pre-state stage 3 needs |
   | 3 | `traces-populate` | spawn the injector; do NOT reload or re-navigate | `viz.query.traces` with **`row_count` > 0** (assertion 1 + CARRY #5: empty→populated on its own) |
   | 4 | `storm-incident` | let the injector reach its storm threshold | `interpretation.incident.created` with **`created` == true** (assertion 2) |
   | 5 | `investigate` | press `button[aria-label="Investigate"]` | `investigate.run_action.request` with **`status` == "success"** AND `deterministic_mode` == true (assertion 3) |
   | + | `empty-states` | navigate to `/metrics` and `/logs` | `metrics-empty-state` + its `-hint` present AND `metrics-error-state` absent (CARRY #7; the hint is what the error variant cannot satisfy) |

4. **The injector is spawned by the script, not by xtask.** Ordering is the reason: stage 2 must
   observe the empty table *before* any telemetry exists, and stage 3's honesty depends on the table
   populating with no driver-initiated reload. That ordering lives in the stage sequence. Spawning a
   scenario process is scenario-driving, not asserting, so the press/assert split holds. The script
   already spawns `tauri-driver` the same way; reuse that shape, including child-process cleanup on
   the `finally` path.

5. **Rework the RED arm into a stage-targeting mutation check.** The current `--expect-absent` inverts
   the whole leg. Give the mutation arm a way to name what must be absent, and add the cheap
   discriminating arm this leg's shape makes available: **an injector-suppressed run**. With no
   telemetry, stages 1–4 must ALL go red while stage 5 stays GREEN — and stage 5 staying green is not
   a guess, it is pinned by the existing
   `empty_buffer_still_yields_a_result()` (`pulse-app/tests/integration_investigate_actions.rs:104`).
   One run discriminates four stages at once and proves the telemetry-dependent stages actually
   depend on telemetry.

6. **Colocated unit tests** for every new stage predicate in `xtask/src/webview_drive.rs`'s existing
   `#[cfg(test)] mod tests` (9 today), per test-plan §4. Each predicate needs both a positive case and
   a **near-miss negative** in the shape of the existing `boot_geometry_transition_is_not_a_close` /
   `dashboard_hide_is_not_the_widget_close` pair — a record with the right target but the wrong field
   value must NOT satisfy the predicate. This is where the "match the effect, not the target" rule
   becomes mechanically enforced rather than remembered.

7. **Bound every stage independently.** Per-stage timeouts inside the existing 240s
   `DRIVE_TIMEOUT`; a stage that never observes its record fails that stage and reports which, rather
   than collapsing into one opaque leg failure. Keep the GREEN-only clean-log check
   (`unhealthy_records`) scoped as it is today — test-plan §3 binds the 0-ERROR clause to the GREEN
   leg only, and the injector-suppressed RED arm is by construction an unhealthy run.

## Constraints & rejected approaches

  `viz.query.traces` fires on every 1s poll including empty ones. Every predicate matches a field
  value the stage causes (`rules/verification-harness.md` §2026-08-23 (b)).
- **Moving assertions into the `.mjs` — REJECTED.** The press/assert split is the harness's whole
  point: a press that returned without throwing is not evidence, because the ACL drops a webview IPC
  silently (same rules entry, (a)).
- **Adding `region[aria-label="Telemetry traces chart"]` + `table` to the Traces surface — REJECTED
  for this chunk** (operator decision). It closes an a11y-plan §1 P1 mandate that genuinely is
  unclosed, but it is product-UI work owned by the neighbouring "A11y verification" entry, and
  a11y-plan §3 would oblige an axe spec in the same chunk.
- **A new injector, or extending `inject_demo` — REJECTED.** It already produces the exact
  fixed-fingerprint storm this path needs, over real OTLP.
- **A pre-baked DB / `.sql` seed / production telemetry dump — REJECTED.** test-plan §7 requires
  runtime self-bootstrapping through the live receiver.
- **A retry-once or auto-retry policy to stabilize the leg — REJECTED.** test-plan §10/§11: one flake
  ⇒ quarantine + root cause, never a retry policy.
- **Treating the storm stage as a throughput budget — REJECTED.** It is an incident-creation trigger;
  load-shaped assertions belong to the `load-profiles` suite (test-plan §10).
- **Absorbed CARRYs #6 (footer), #11 (workspace-key divergence), #12 (active-list divergence) —

## Implementation notes

- **Stage ordering is load-bearing.** Stage 2 must observe the empty table before any telemetry
  exists; if the injector starts first, stage 3's empty→populated assertion is vacuous. This is the
  same "passes for the wrong reason" class the predecessor chunk closed.
- **`/metrics` and `/logs` stay empty for the whole run** — `inject_demo` sends traces only
  (`TraceServiceClient`), so the empty-states stage can run at any point without special sequencing.
- **The empty/error discriminator is the hint**, not the message: `EmptyState.tsx:38` renders
  `data-testid="{testId}-hint"` only when a hint is passed, and `MetricsRoute.tsx:38` passes one for
  the empty branch but not the error branch (`metrics-error-state`).
- **`tests-e2e/**` is lint-covered but NOT typecheck-covered** — `eslint.config.mjs:55` includes it;
  `tsconfig.json:22` includes only `src/**/*`. Consistent (the driver is `.mjs`), but it means
  `npm run lint` is the guard on driver changes and `npm run typecheck` is not.
