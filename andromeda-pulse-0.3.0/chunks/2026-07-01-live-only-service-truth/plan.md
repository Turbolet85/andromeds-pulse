## Goal
Make the service constellation tell the truth: with zero live telemetry it must show **no** live services, and
persisted/stale services restored from corpus at boot must never render as live dots (intent F7 — HIGH PAIN).
Today the constellation renders ~6–7 phantom dots on a fresh boot because (a) the corpus `service_registry` is
restored into `InMemoryServiceRegistry` and surfaced verbatim through `services.list_with_states`, and (b)
`set_state_on_corpus_restore` clobbers each restored entry's `last_seen_unix_nano` to boot time
(`registry.rs:264`), so even a recency check would read "just now" (per `research.md` root-cause).

The fix has two coordinated parts, per the P4-approved decisions: **(1)** stop the `last_seen` clobber on
corpus restore so the registry's recency is honest (obs/security/a11y/arch extracts all converge on "never
reset last_seen to boot"); **(2)** gate the constellation on **recency of the honest `last_seen`** — a service
shows a dot only while its last span is within the live window (reuse the FSM's 60 s Active→Quiet threshold),
and non-live services (corpus-restored/stale/long-quiet) are **hidden entirely** (extends the existing
`archived`-hide in `constellation-types.ts::visibleDots`). No new IPC procedure, no broadcast-event change, no
corpus-schema change — `services.list_with_states` + `pulse://stream/service-lifecycle` stay locked
(arch §Occupied Resources).

**RESEARCH-CORRECTS-INTENT (approved P4):** the intent's "Listening · last span · just now" evidence is the
whole-app **ConnectionDot** (chunk #89, `ConnectionDot.tsx:144`), not a per-service constellation label (the
chunk-#93 constellation has no per-dot tooltip). This chunk targets the constellation phantom-dots + the
registry `last_seen` honesty (the true root cause); the connection-dot "just now" phrasing is a distinct
surface deferred to **P-070** (plain-language status). Outcome unchanged ("UI shows services that aren't
live"); the falsified premise was the mechanism (a per-service recency tooltip). Recorded in `scope.md`
§Decisions + the matrix `notes`.

## Acceptance Criteria
- (arch/product) **Zero live telemetry → no live services.** Given a persisted registry restored at boot with
  zero live spans, `visibleDots`/`constellationSummary` (with a current `now`) return no live services and the
  aria summary reads "…no active services." (verification-matrix.json#P-067; per arch §Design Philosophy UI-truth).
- (backend) **Honest recency.** After `set_state_on_corpus_restore`, a restored-but-unobserved service retains
  its persisted `last_seen_unix_nano` (never boot time), so no recency check reads it as current (per
  obs-plan §1 + security-plan §Logging; `registry.rs`).
- (product) **Live shown, stale hidden.** A service whose last span is within the 60 s window renders a dot;
  a service quiet past the window (or corpus-restored/stale) is hidden — both surfaces (compact widget +
  dashboard Traces) behave uniformly (per layout-templates §Halo State Pulse canvas / §IA notes).
- (design/a11y) Live dots keep the activity-driven Halo (brightness/hue by state); hidden services are excluded
  from BOTH the drawn dots and the aria summary (no color-only signal; SC 1.4.1) and do not break focus order
  (per design-system §Brand Identity 2026-05-29 + a11y-plan §1 P1); `prefers-reduced-motion` unaffected.
- (obs) The liveness/restore code path logs no raw registry payload / OTLP attribute values — aggregate/enum
  only (per obs-plan §1 vector 5 + `.claude/rules/observability.md` 2026-05-17 aggregate-only).
- (tests) `cargo nextest run --workspace --profile ci` returns 0; `npm run test --prefix pulse-app/ui`
  returns 0; `cargo xtask test:a11y` passes (0 new violation tuples on P1 constellation); `cargo xtask
  self-verify` passes (or records a display-less skip, never silent-pass).
- (arch) `cargo xtask capability-drift` clean — no new TauRPC procedure / capability entry (resolver unchanged).

## Implementation notes
- **Order sensitivity:** the frontend recency gate is only truthful once the backend `last_seen` clobber is
  fixed — do Step 1 (backend) before relying on Step 2's zero-telemetry behavior end-to-end; the webview unit
  tests are independent (they inject `last_seen` directly).
- **Single consumer:** `services.list_with_states` has exactly one consumer (`use-service-constellation.ts` →
  ConstellationCanvas, widget + dashboard); the resolver is left UNCHANGED (returns honest data; liveness is a
  display rule), preserving stale data for a possible future "historical" view (P-069/P-070) without a schema
  change now.
- **No new procedure/field:** deliberately no `is_live` field on `ServiceListItem` and no resolver filter — the
  recency predicate lives at the single display site, computed from the payload's existing
  `last_seen_unix_nano` + injected `now` (avoids the quadruple-binding + capability-drift + a new serde field
  the security extract cautioned against).
- **jsdom timers:** `ConstellationCanvas.test.tsx` should mock time via `vi.useFakeTimers()`/`vi.setSystemTime`
  or spy `Date.now`; the pure `visibleDots`/`constellationSummary` tests inject `nowUnixNano` directly (no
  clock). Pairs with the WebGPU-mock discipline already in that test file.
- **Threshold mirroring:** `LIVE_RECENCY_WINDOW_NANOS` duplicates the 60 s value across Rust/TS (documented,
  like the inlined WebGPU constants per testing.md 2026-05-09) — acceptable; the TS const's comment must cite
  `ACTIVE_TO_QUIET_THRESHOLD_SECONDS`.
