## Goal

Stop the glance widget from being stretched into absurd proportions, and stop both windows from collapsing to
unusably small sizes — the F2 polish for Epoch 2 (Window & shell hygiene). Today the `compact-widget`
(480×270 = 16:9) and `main` (1280×800) windows are `resizable: true` with **no `minWidth`/`minHeight` and no
aspect constraint** (`pulse-app/tauri.conf.json`), so the widget free-resizes to any dimensions and "looks
absurd when stretched" (intent F2 · verification-matrix.json#P-062 observed_gap).

Two constraint classes, split by how the platform enforces them (research.md §API-availability findings —
**Tauri 2.11 / tao 0.35 has `set_min_size` + static `minWidth`/`minHeight` but NO native aspect-ratio API**):
1. **Min-size** is OS-enforced — declared statically in `tauri.conf.json`, the window manager refuses to drag
   below it. Robust, no event loop needed. Applied to **both** windows (Q2 → widget + main): the widget gets a
   16:9-consistent floor; the `main` dashboard gets a sane minimum (no aspect — a dashboard legitimately holds
   varying proportions).
2. **Aspect-ratio** has no native API, so it is enforced (compact-widget only) by a **`WindowEvent::Resized`
   clamp** in `window::on_window_event` — a pure helper recomputes the size to keep `w/h` inside a configured
   aspect *band* and calls `window.set_size(..)`, guarded by a re-entrancy `AtomicBool` (the `set_size` itself
   re-emits `Resized`). The pure helper + its unit tests land in-chunk (mirroring `compute_snap_position`); the
   **live drag-resize-delta** assertion needs headful tauri-driver and **CARRIES to P-076** — the exact P-061
   precedent (verification-matrix.json#P-061 proved via capability/config/unit in-chunk, live drag-delta carried
   to the Epoch-4 e2e suite).

Per arch §Established Decisions [Tauri 2.x] + research §Conventions: **no new TauRPC procedure, capability JSON,
broadcast topic, env var, or workspace dep** — window ops are Rust/config-side; per P-061's finding, Rust-side
window mutation needs no `core:window:*` grant (capabilities gate webview JS only). `capability-drift` +
`capability-widening-check` are expected no-ops.

## Implementation notes
- **No native aspect API (research §API-availability)** — the only `aspect` hits in tao 0.35 are `DVASPECT_CONTENT`
  OLE constants in the Windows drag-drop handler, unrelated. The `Resized`-clamp is the only path; do not reach
  for `set_resize_increments` (steps the size but does not lock the ratio).
- **Re-entrancy is mandatory** — `set_size` inside a `Resized` handler re-emits `Resized`; without the
  `AtomicBool` guard the handler fights itself (flicker / unbounded loop). Set the guard before `set_size`, clear
  it when the echo arrives.
- **Band, not pin** — the matrix acceptance says the ratio "stays within the configured BOUND"; a tolerance band
  (clamp only when outside) is both the literal reading and less janky than a hard 16:9 pin (Q1 selected).
- **Physical vs logical pixels** — `Resized` carries `PhysicalSize`; clamp in physical pixels (as
  `compute_snap_position` does), and pass a `PhysicalSize`/`Size` to `set_size`.
- **CARRY to record at wrap** — add to the P-076 working-route line (wrap's route-resolve, not /phase): "assert
  the live resize-clamp + aspect-band by driving a real headful resize (P-062 headful e2e residual)" — parallel
  to the existing P-061 headful-drag-delta CARRY already on that line.
