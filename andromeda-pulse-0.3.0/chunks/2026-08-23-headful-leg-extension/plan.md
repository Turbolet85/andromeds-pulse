## Goal

The 7-stage `cargo xtask webview-drive` leg drives one assembled path. Seven residual affordances were
boundaried out of it, and they still rest on unit/config proofs plus operator eyeballs. This chunk extends the
leg with the subset reachable **using only driver mechanics the leg already exercises** — click, window-handle
switch, selector query, and `browser.execute` against the already-granted Tauri getter API — and it takes
ownership of the leg's measured `launch` flake, whose mechanism P3 located in the driver's own control flow.

The operator resolved the breadth fork at P4 in favour of that boundary. **Landing:** the widget↔dashboard
toggle and the per-window close (P-066/P-063 residuals), the Traces internal-scroll layout at default size
(P-082 residual), the incidents floating-window disclosure (2026-07-10 residual), the plain-language
connection-status footer line (P-070 residual), the Traces selector re-point onto the accessible anchors, and
the `launch` flake. **Deferred behind a recorded mechanic probe:** the titlebar drag (P-061), the live
resize-clamp and aspect band (P-062), the production browser-chrome suppression (P-064/P-065), and the
multi-window-size half of P-082 — each needs W3C Actions, `setWindowRect`, or native-menu observation against
a WRY window, none of which has ever been measured on this host.

Ordering is load-bearing rather than cosmetic: the `launch` flake gates every stage behind it, so a leg that
grows to thirteen stages while `launch` succeeds 1-in-4 would rarely produce green evidence for anything.
The flake work comes first (per test-plan §10 Zero-flakiness budget, which requires root-cause and explicitly
bars a retry budget or a longer wait).

Every new stage inherits the leg's verdict discipline: the driver reports and asserts nothing, the Rust caller
owns the verdict, and each predicate matches an effect **FIELD** rather than a target or a non-throwing press
(per test-plan §6 Drivers per surface + §2 Agent-runnable invariants; obs-plan §3/§6).

## Implementation Steps

**Step 1 — Own the `launch` flake (first, because it gates everything else).**
P3 located the mechanism: `webview-drive.mjs:345-364` polls ≤20s for a dashboard *self-mount* keyed on
`TAB_NAV`, and only on absence presses the toggle once and polls ≤30s again. That reproduces the measured
perfect bimodality exactly, and the toggle cannot recover the failure because the recorded mode is `main`'s
webview never leaving `about:blank` — `show()`+`setFocus()` cannot mount an SPA that never navigated.
1.1 Put the diagnosis **into the stage record**, not only the console: extend the `launch` `detail` with the
per-handle `{label, url}` set `dumpHandles` already computes, so a failing run names its cause in
`webview-drive-stages.json` (the harness-reports-what-it-saw rule, `.claude/rules/verification-harness.md`
2026-08-23 trap 3).
1.2 Root-cause from the app's own already-allowlisted boot records — `app.boot.webview.init`,
`app.boot.window.show`, `app.boot.gpu.check` — to establish whether `main` is *never asked* to navigate or
*asked and failing*.
1.3 Fix by waiting on a **positive navigation signal** (the main window leaving `about:blank`) before looking
for `TAB_NAV`, so the stage distinguishes "still mounting" from "never navigated". A longer wait is not an
admissible fix (50s already elapses in failing runs) and neither is a retry.
1.4 **If the root cause proves to sit in the app's boot path rather than the harness**, surface it with the
per-condition tally rather than papering over it, and quarantine the stage with a tracked reason per
test-plan §10 — never a silent retry. Report the outcome either way.

## Implementation notes
- **Occlusion is a measured dead-affordance cause.** The existing `investigate` stage opens a focus-trapping
  modal on the **widget**, and a modal left open swallows later presses on that surface — producing exactly
  `dom:yes obs:NO`. Dismiss modal state before the `findings-window` stage presses the widget's badge
  (`.claude/rules/verification-harness.md` 2026-08-23).
- **Identify windows by an invariant marker or the real Tauri label**, never a route-conditional one: the
  widget-vs-dashboard exclusion once keyed on the trace table, which exists only on `/traces`, so a stage that
  navigated the dashboard elsewhere made it match the widget's exclusion. `dumpHandles` already reads
  `globalThis.__TAURI_INTERNALS__?.metadata?.currentWindow?.label`.
- **Press once, then poll.** Re-invoking a toggling action inside a poll produced ~120 presses whose outcome
  was decided by deadline parity — the trap that shipped as flakiness in the predecessor.
- **Match the effect record, never the target alone.** Boot itself emits `ui.layout.transition`
  (`boot_default → top-right`), so a target-only match passes on a record no press caused. Read the two emit
  sites (`window.rs:122`, `:433`) for the exact `layout_mode_from` / `layout_mode_to` values rather than
  assuming them.
- **The mutation check must rebuild the artifact the tier consumes** — a Playwright/webview arm reads
  `ui/dist`, so a mutation left unbuilt passes and reads as "this pin does not discriminate".
- **Stage order matters:** `widget-close` is terminal (it sends the app to the tray), so every new stage slots
  before it; `findings-window` requires `storm-incident` to have produced an incident.
