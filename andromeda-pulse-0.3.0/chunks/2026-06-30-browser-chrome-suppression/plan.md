## Goal
Suppress the two browser-grade affordances that leak into the desktop app and carry zero meaning in a telemetry
tool: the default WebView2 right-click context menu (Back / Refresh / Save-as / Print / Inspect — **P-064**) and
the canvas "save/drag image" interaction (**P-065**). Both are webview-only frontend hygiene (intent F4/F5;
"Quick wins" per intent §5) on top of the working v0.2.0 shell — no Rust, no IPC, no new capability.

The mechanism is a single app-wide suppression hook plus one global CSS rule. Per research, **both windows
render through the single `App.tsx` root** (it routes `compact-widget` → `<CompactWidget>` else `<Dashboard>`
via `useWindowLabel`), so a `document`-level effect mounted in `App` is app-wide by construction — no per-window
wiring. The context-menu handler is **production-gated** (`import.meta.env.PROD`) so the dev inner loop keeps
right-click → Inspect/devtools (per design-system §Anti-Patterns "dev preserve" + the intent/matrix wording "in
a production build"), and **exempts editable elements** (inputs / textareas / contenteditable) so native
copy/paste/spellcheck survives in the Settings form (a11y SC 3.3.2 / 4.1.2 — **user-confirmed at /phase P4**:
"Exempt text fields"). The canvas affordance is killed two ways for defense-in-depth: a global
`canvas { -webkit-user-drag: none; user-select: none }` CSS rule (covers all 5 existing canvases + any future
one) and a PROD-gated `dragstart` handler in the same hook; the context-menu handler additionally removes the
canvas "Save image as" entry.

Provenance: design-system §Anti-Patterns (desktop-webview) + a11y-plan §1 P7 / §5 (keyboard / editable
exemption) + test-plan §4 (vitest) / §3 (gate set) + arch §Webview IPC capability policy (DOM handler needs no
capability) + obs §8 / §10 (no event logging, no per-event telemetry). **Net-new** — research confirms zero
existing `contextmenu` / `import.meta.env` / `draggable` / `user-select` usage (the P2 extracts' "mirror the
existing PROD-gate pattern" was inaccurate; this is the first use of `import.meta.env.PROD`, standard Vite).

## Implementation Steps
1. **New hook `use-suppress-browser-chrome.ts`** (`pulse-app/ui/src/hooks/`). On mount, when `import.meta.env.PROD`
   is true, attach two `document` listeners and remove them on cleanup:
   - `contextmenu` → if `event.target.closest('input, textarea, [contenteditable="true"]')` is null (target is
     **non-editable**), call `event.preventDefault()` (suppresses the WebView2 menu incl. canvas "Save image as");
     editable targets keep the native menu.
   - `dragstart` → if the target is a `<canvas>` or `<img>`, call `event.preventDefault()` (kills drag-to-save).
   - When `PROD` is false (dev / test), install nothing (dev keeps right-click → Inspect).
   - Handlers call `preventDefault()` only — NEVER read/log target, coordinates, or event content (obs §8); no
     telemetry emission (obs §10 frame-budget).
2. **Mount the hook in `App.tsx`** — call `useSuppressBrowserChrome()` once at the top of `App()` (alongside the
   existing `document.title` effect). Single mount point = app-wide (both windows route through `App`).
3. **Global canvas CSS** — append to `pulse-app/ui/src/styles/tokens.css` (after the `@theme` block) a rule
   `canvas { -webkit-user-drag: none; user-select: none; }`. Always-on (harmless in dev; a canvas is never a
   saveable image) and covers all 5 canvas hosts + future ones in one place. Use CSS, not an inline React style,
   because `-webkit-user-drag` is not in React's `CSSProperties` typing.
4. **Colocated test `use-suppress-browser-chrome.test.tsx`** — vitest jsdom:
   - PROD path (`vi.stubEnv('PROD', true)`): `fireEvent.contextMenu(div)` on a non-editable node →
     `event.defaultPrevented === true`; `fireEvent.contextMenu(input)` on an `<input>` → NOT prevented
     (editable-exempt); `fireEvent.dragStart(canvas)` on a `<canvas>` → prevented.
   - DEV path (default, no stub): `fireEvent.contextMenu(div)` → NOT prevented (handler not installed).
   - `afterEach(() => vi.unstubAllEnvs())` (per the 2026-05-08 unstub discipline). Mount the hook via a tiny test
     host component or `renderHook`.
5. **Run the full gate set** (Test Commands below), including the standing UI gate `cargo xtask self-verify` (boots
   the real app + a11y/contrast harness + clean quit) so the suppression is proven not to regress boot, focus, or
   a11y; webview vitest is the owning affordance proof for P-064/P-065.

## Implementation notes
- **PROD gate + test**: `import.meta.env.PROD` is false in vitest by default → existing `App.test.tsx` is unaffected
  (the hook installs nothing in test). Exercise the PROD path with `vi.stubEnv('PROD', true)` + `vi.unstubAllEnvs()`.
- **Editable-exempt** uses `e.target.closest('input, textarea, [contenteditable="true"]')` (the user-confirmed
  shape at /phase P4). A click on a non-element node (text node) — guard with an `instanceof HTMLElement` /
  `Element` check before `.closest`.
- **`-webkit-user-drag`** is not a typed React `CSSProperties` key → keep it in the global CSS rule (tokens.css),
  not an inline `style={{}}` (avoids a `tsc` error). `tokens.css` is Tailwind v4 input built to `dist/tokens.css`;
  append the raw rule after `@theme` and confirm the css build (or `npm run build`) emits it.
- **Headful CARRY**: the real packaged-WebView2 "no native menu appears on right-click" is proven by `preventDefault`
  (a platform guarantee); a live headful tauri-driver right-click folds into **P-076** (Epoch-4 integration-UX e2e),
  mirroring the P-061 drag-delta / P-062 resize-delta headful CARRYs. The in-chunk webview vitest (real event
  dispatch + PROD stub) is the OWNING affordance proof for P-064/P-065 this chunk.
- **No capability / arch impact**: a DOM `contextmenu`/`dragstart` listener invokes no Tauri IPC → no
  `pulse-app/capabilities/` entry, no `xtask capability-drift` delta, no arch §Occupied Resources change.
