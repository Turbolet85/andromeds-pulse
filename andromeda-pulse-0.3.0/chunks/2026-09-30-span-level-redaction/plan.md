## Goal
A secret inside a larger value stops blanking the whole value. Today every consumer of the P-047 scrubber
replaces the WHOLE value on any match (research.md §Consumer classification — 12 of 13 production sites), so one
card number in an incident digest turns the digest the L4 model reads into `[redacted:credit_card]`
(`pulse-app/tests/unit_digest_runtime_scrub.rs:35`). After this chunk the scrubber MASKS the secret where it
sits, and the rest of the value — the other lines of a digest, the words around a token in a log body, the
fields of an interpretation — keeps reaching storage, the digest, the L4 prompt, the corpus, the Report, MCP
and the training export.

The extent of each mask is the founder-ratified CLASS-AWARE rule: keyed arms (`bearer`, `api_key`,
`secret_kv`) mask from the key word to the end of the line; bare-shape arms (`jwt`, `provider_key`, `email`,
`ssn`) mask the whole whitespace-delimited token; `credit_card` masks the whole digit-group run; overlapping
spans merge into one placeholder labelled by the highest-priority arm in catalog order. That extent is what
keeps the never-weaken outcome: detection is byte-for-byte unchanged (the same eight arms, the same Luhn
whole-group gate, `scrub_attribute` untouched as the verdict), and no secret hidden today becomes readable —
the two places an arm's regex is narrower than the real secret (a multi-word value after `password:`; a
base64 bearer tail past `+`/`/`) are covered by the extent itself (per security-plan §Security Anti-Patterns →
Logging; research.md §Mechanism re-derivations).

Two contracts stay deliberately whole-value: `metrics_points.labels` (`encode_labels`) keeps key-verbatim /
value-redacted per label, because a keyed arm's match spans the key AND the value of the joined form; and the
L1 exception fingerprint is untouched by construction (computed from the RAW stacktrace before the scrub,
`crates/buffer/src/appender.rs:513-524`).

   - For each arm in catalog order, collect its raw match ranges: `find_iter` for the regex arms; for

     candidate run as matched. Scan with char boundaries (`char_indices`), never raw byte steps.

     members.
   - Render: copy the text outside the ranges verbatim; replace each merged range with
     `placeholder(category)`.

     future arm cannot be added without choosing a class.

     (a) detection equivalence — over the existing recall and false-positive `#[rstest]` corpora plus a

## Constraints & rejected approaches
- Changing `ScrubbedValue` or `scrub_attribute` — rejected: they are the detection verdict that `encode_labels`
  and the 8 recall / false-positive tests read; the additive sibling function keeps "detection unchanged"
  checkable byte for byte.
- Span-masking `metrics_points.labels` — rejected: a keyed arm's match on the joined `key=value` spans the key, so
  masking it erases the key; masking the bare value misses the keyed class (security-plan third scrub shape).
- Masking the serialized `L4Output` JSON — rejected: `secret_kv`'s `\S+` crosses compact-JSON delimiters and would
  make `resolution_summary_text` unparseable; mask the string leaves.
- Exact-regex-match extent and whole-line extent — rejected by the founder's ratification (scope.md Boundaries).
- Unifying the three placeholder spellings — not in this chunk: every existing pin and rendered string keeps its
  spelling.
- Counting spans in `redactions_applied` — rejected: the obs-plan §5 unit is per redacted value; a per-span count
  would move the five-cell canary and the counter's meaning.
- Any per-span or per-category tracing record, or logging masked text to prove masking worked — banned (obs-plan
  §11; security-plan NEVER-log bullets).
- Truncating a longer digest to fit the L4 prompt bound — banned; `validate_prompt_bounded` rejects, never
  truncates (security-plan §Input Validation).
- Adding a `security` dependency to `triage` — rejected: the closure injection already carries the change
  (architecture §Cross-cutting Patterns → Module dependency direction).
