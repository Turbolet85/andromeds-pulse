- **Windows pid-numbering nuance:** the sh script's `$!` is an MSYS-side pid; the app overwrites the shared
  file with its canonical Windows pid. Cleanup treats the FILE content as canonical and uses the
  PowerShell-fallback kill/liveness path for pids Git Bash's `kill` does not recognize; each value still
  denotes the same process. ps1 has no such ambiguity.
- **Windows kill semantics:** Git Bash `kill -TERM` on a native pid is effectively a hard terminate (no
  graceful window), so the `tracing_appender` non-blocking guard may drop tail log lines on Windows kills —
  RED/GREEN log assertions read pre-kill content only; this is a recorded limit, not a defect this chunk
  fixes.
- **CI is Linux-only for the smoke step** — the POSIX arms (plain `kill`, `/dev/tcp` probes) must stay
  first-class; the PowerShell fallbacks engage only on a Windows host.
- **MSYS env conversion is measured, not assumed:** exported `/tmp/...` values reach native processes
  converted (`C:/Users/turbo/AppData/Local/Temp/...`), so script and app converge on one physical file
  whenever DATA_DIR is exported — the RED leg therefore NEEDS the divergent-pidfile (or no-export) recipe to
  reproduce the defect.
- The `run` / `logs` / `status` verbs and the UTF-8 relay block are OUT of scope — preserve byte-identical.
