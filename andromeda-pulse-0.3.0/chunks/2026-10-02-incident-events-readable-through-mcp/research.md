## Patterns detected
- **One emission site for every tool** (`tools.rs:178-214`): a new tool reached through `dispatch_tool` inherits the response, metric and error records with no new target, and the sidecar allowlist's `mcp` module key plus the exact metric leaf already carry every field emitted (`tracing_setup.rs:56-103`). A ninth `method` label value stays bounded (a closed tool-name set).
- **Existence-then-read on an incident id** (`load_incident_row`, `tools.rs:480-495`): `load_incident_by_id` → `None` (absent OR undecryptable, the latter with one aggregate `corpus.read.undecryptable` WARN at `contract.rs` `warn_skipped_undecryptable`) → `"incident not found"` → -32603. No incident tool filters by workspace on an id read (`retrieve_report`, `retrieve_telemetry_slice`, `mark_incident_resolved` all call this unfiltered).
- **Lifecycle ledger semantics** (`contract.rs:622-675`, pinned `:1419-1486`): one row per status VALUE change on an Applied write; none at creation, none on a same-status refresh, none on `DeclinedStale`. `event_kind` is whatever status string the writer passed; every production writer passes a `status_label` value.
- **App sink at HEAD = file only** (`observability.rs:2634-2659`); **sidecar sink = stderr + file** (`tracing_setup.rs:248-275`). These are two separate claims; only the app's is false in the specs. App-sink claim sites: obs-plan `:67` (§1 telemetry surfaces, CLI row), `:72` (§1 harness-spec Tracing init step (2), names `with_writer(std::io::stderr)`), `:76` (§1 Logging stack "Dual sink"), `:175` (§3 Init order step (2)), `:198` (§3 Logging stack → Sink "Dual sink for app"), `:281` (§4 CLI / main binary row "log to both stderr + file"), `:437` (§6 Sink configuration "App"), `:471` (§7 Panic hook "logged to both stderr + JSON file sink" — false in a different shape: the JSON record carries no panic message by design, and stderr receives the chained prior hook's text); leaves `.claude/rules/observability.md:20` (init order "composing stderr + …"), `:38` ("Dual sink (app)"), `:151` (the `[correction]` entry to retire), `.claude/docs/obs-summary.md:14`, `:56`. Lines `:76`/`:198`/`:438`/`:740` also carry the SIDECAR's stderr-forced-JSON claim, which is TRUE at HEAD and stays.
