## Goal

Two residuals of the chunk-#84 subprocess design get an enforced, stated guard in place of a convention.
**(A)** The three product-consumed path vars — `ANDROMEDA_PULSE_MODEL_PATH`, `_LLAMA_CUDA_BIN_PATH`,
`_LLAMA_CPU_BIN_PATH` — today trim, `canonicalize()` and assert regular-file, but deliberately omit the
data-dir confinement assert, so an actor who can set them points the product at an arbitrary on-disk file,
read as a model or EXECUTED as the inference binary (per security-plan §Security Anti-Patterns → Input,
whose MEASURED EXCEPTION block names this entry as owner). **(B)** `build_llama_cli_args` puts
digest-derived, OTLP-sourced prompt text on the `-p` argv value, the shape security-plan §Security
Anti-Patterns → Code Patterns bans categorically.

The chunk does NOT apply the categorical confinement rule literally, because the rule was written for
in-tree files and these targets are out-of-tree **by design** — arch §Established Decisions [LLM Inference
Runtime] still carries their distribution as an open caveat, and a data-dir default would break every host
that has run L4, including the one that produced this project's only real-model chain proof. Instead
(operator-decided at the P4 review): unconditional structural hardening for all three vars, plus an
**opt-in** `ANDROMEDA_PULSE_L4_ALLOW_ROOT` that enforces real confinement when set, with a once-per-boot
record announcing which posture is live. That converts a silent convention into a stated posture with
enforcement available, and lets the spec exception be NARROWED with a truthful ground rather than deleted.

Two P3 premise corrections shape the deliverables and override the promotion-time wording. **The prompt is
not raw OTLP text** — `crates/interpretation/src/prompt.rs:143` assembles a first-party template
(`ROLE_DEFINITION` + `CONVENTIONS_SNIPPET` + the JSON schema + `OUTPUT_REMINDER`) with variability entering

`Digest::scrubbed_clone` (`crates/triage/src/contract.rs:589`). The ban still binds because an OTLP-sourced

## Implementation notes
- **The `\n` trap is the likeliest defect.** `char::is_control()` is true for `\n`, `\r` and `\t`, and the
  prompt is multi-line markdown by construction — a naive control-character predicate rejects every prompt and
  turns L4 off entirely. Whitelist the three layout characters and pin that a realistic multi-line prompt is
  ACCEPTED, not only that a NUL-bearing one is rejected.
- **Canonicalize both sides of the confinement comparison.** On this host `canonicalize()` returns a Windows
  `\\?\` extended-length prefix; comparing a `\\?\`-prefixed child against a bare-prefixed root fails
  regardless of the true relationship. This is exactly what `publish_workspace_key` gets right.
- **Order sensitivity:** the traversal-component check runs BEFORE `canonicalize()` — canonicalization
  resolves `..` away, so a post-canonicalize check can never see it.
- **The bare-`interpretation`-key breach is latent, not this chunk's to fix** (owned by the "Diagnostics
  un-muting + harness-truth sweep" entry). Work around it by giving every new target its own exact leaf; do
  not remove the bare key here.
