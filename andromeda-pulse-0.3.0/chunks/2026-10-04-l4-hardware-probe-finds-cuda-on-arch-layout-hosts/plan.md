## Goal
The Linux arm of `detect_gpu_present` (`crates/interpretation/src/hardware.rs:141-153`) checks for the NVIDIA driver
library at two fixed paths only, `/usr/lib/x86_64-linux-gnu/libcuda.so` and `/usr/local/cuda/lib64/libcuda.so`. On an
Arch-layout host such as this Omarchy dev host, the library is `/usr/lib/libcuda.so -> libcuda.so.1 ->
libcuda.so.610.57.04`, so the detector reads GPU-absent. HEAD then classifies this 32-core host `CpuPrimary` and routes
L4 to the CPU `llama-cli`. Measured at P3: `l4_decision_probe` prints `INCONCLUSIVE -
ANDROMEDA_PULSE_LLAMA_CPU_BIN_PATH is unset` (research.md §Equality).

This chunk widens the candidate set to every pair of four directories (the two existing ones plus `/usr/lib` and
`/usr/lib64`) and two file names (`libcuda.so` and the driver's runtime soname `libcuda.so.1`). That is eight
candidates, any present means GPU-present. The candidate set was ruled at P4 by the overseer, founder-delegated
(2026-10-04): "dirs × names". The probe stays a filesystem-presence check over compile-time system paths. It gains no
subprocess, no `dlopen`, no env input and no dependency (security-plan §Security Anti-Patterns → Code Patterns;
architecture §Established Decisions [LLM Inference Runtime]). The safe default is unchanged: a host with none of the
eight reads GPU-absent.

The probe becomes testable without the host's real filesystem. Today no test reaches `detect_gpu_present` at all
(research.md, `hardware.rs:203-283`). A pure function over an injectable ROOT holds the candidate logic, and the
production Linux arm calls it with `/`. Pins run over `tempfile::TempDir` layouts with real files and symlinks; the
seam form is leaned per test-plan.md:614, "**Filesystem:** `tempfile::TempDir` + `assert_fs` symlink helpers … (real
temp dir, not mocked)". No pin asserts a host-dependent verdict (test-plan §2 Agent-runnable invariants; §11).

## Constraints & rejected approaches
- Probing via `dlopen`, `nvidia-smi`, `ldconfig -p` or `lspci` — a second process-spawn site or a driver load
  outside the D1 discipline (security-plan §Security Anti-Patterns → Code Patterns; architecture §Established
  Decisions [LLM Inference Runtime]).
- Parsing `/etc/ld.so.cache` — it would find the library wherever the loader does, but it reads a binary cache
  format: a larger, more fragile change than a fixed candidate set, and not what the entry asked.
- An env- or config-supplied candidate directory — a new product-read path input (a boundary widening needing the
  canonicalize-and-confine guard and its own ratification; security-history 2026-10-04-corpus-key-creation-is-race-free).
- A predicate-injection seam (`&dyn Fn(&Path) -> bool`) instead of a TempDir root — test-plan.md:614 mandates a real
  temp dir; a synthetic predicate cannot exercise the symlink chain this host carries.
- Wiring `detect_gpu_present` into the Linux render-posture default (`render_posture.rs`) — that default is
  NVIDIA-scoped by construction with a detection probe explicitly rejected by founder ruling (arch-history
  2026-10-04-linux-launch-stays-up-on-nvidia-wayland). The two mechanisms stay separate.
- Touching the macOS / Windows arms, `HardwareProfile`, `profile_label`, `tier_for_profile`,
  `binary_target_for_profile` or the `interpretation.hardware.detect` emit sites — out of scope (scope §Boundaries).
- A pin that asserts this host's verdict through `detect_gpu_present` / `HardwareProfileDetector::new()` — a flake
