## 3. Thinking off

- Qwen3.5: no separate instruct checkpoint; `/think` `/no_think` are NOT supported in 3.5. Switch: chat-template kwarg
  `enable_thinking`. llama.cpp: `--chat-template-kwargs '{"enable_thinking":false}'` (plus `-rea off`). The unsloth GGUF templates
  default to non-thinking for 2B/4B (they prefill an empty think block); the official 4B template defaults to THINKING — pass the
  kwarg explicitly anyway. DOCUMENT: unsloth guide; Qwen cards.
- Gemma 4: thinking is on only when `<|think|>` opens the system prompt. llama.cpp: `-rea off` / `--reasoning off` works; users
  report `--chat-template-kwargs '{"enable_thinking":false}'` and `--reasoning-budget 0` did NOT on 26B-A4B (discussion #21338).
  Keep the prompt free of `<|think|>`.
- Grammar with thinking ON is not applied at all (llama.cpp #20345, open) — another reason thinking stays off.

## 4. The grammar failure — upstream state (DOCUMENT, GitHub, read 2026-10-05)

- Exactly our failure: issue #29006 (open) "JSON Schema grammar fails on chat-template control tokens while equivalent GBNF
  succeeds". Fix: PR #29066 "common: do not prefill the generation prompt into output-format grammars" — OPEN, unmerged, so no tag
  carries it. Siblings closed without a fix: #22396 (Gemma 4, llama-cli, `--grammar-file` works), #21600 (Qwen3.5), #23990.
- No reasoning flag avoids the prefill (it is keyed on grammar type). `--grammar-file` with a schema-converted GBNF is the working
  route. `llama-completion` would not prefill either (inferred from code, not run).

## 5. Quantization notes (DOCUMENT; not a change for this series)

- unsloth's starting point for Gemma 4 E2B/E4B is 8-bit, dynamic 4-bit only from 12B up. Google publishes a QAT Q4_0 GGUF for E4B
  (~5.15 GB, July 2026) described as near-bf16. llama.cpp issue #22243 (closed, unconfirmed) claimed PLE weights are
  quantization-sensitive.
- Qwen3.5: unsloth's small-model examples use UD-Q4_K_XL; no statement that Q4_K_M is inadequate.
- The founder's priority is footprint, so this series stays on Q4_K_M for every model; if a Gemma narrowly misses, its Q8 or QAT
  form is a named follow-up, not a mid-series swap.

## 6. LoRA (founder's later plan)

- Qwen3.5 2B/4B: unsloth bf16 LoRA (2B ~5 GB, 4B ~10 GB VRAM); QLoRA advised against; transformers v5.
- Gemma 4 E2B/E4B: unsloth LoRA and QLoRA (E2B 8–10 GB, E4B ~17 GB VRAM); GGUF export.
