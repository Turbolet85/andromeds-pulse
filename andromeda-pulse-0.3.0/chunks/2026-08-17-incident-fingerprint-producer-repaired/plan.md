## Goal

`Incident.fingerprint` is contracted as *"Anonymized fingerprint hash for cross-incident grouping per
capability spec P-047"* (`crates/triage/src/contract.rs:340-342`) and consumed as full-width lowercase hex by
the digest assembler, but produced from the model-authored `L4Output.fingerprint` string
(`pulse-app/src/inference_runtime.rs:700`). The two corpus-retrieval selectors therefore operate on a field
whose value is the wrong *kind*: `select_corpus_matches`'s fingerprint arm is correct-per-contract and
STARVED (never dead — its removal was attempted and fully reverted at the prior chunk, leaving an in-code
guard), and `select_previously_seen` matches every incident against every other under
`ANDROMEDA_PULSE_L4_DETERMINISTIC` because the canned runner emits a constant. This chunk feeds the arm by
threading the real `ExceptionFingerprint` to the incident site, per the DEFERRED path named in
architecture.md §Established Decisions [Fault Identity] — *"the documented path if incident-per-identity is
ever wanted; do not partially implement it."*

The threading rail already exists. `record_occurrence` holds the raw `[u8; 16]`
(`crates/triage/src/pattern/storm.rs:206`) and calls `synthesize_cue` (`:256`, `:276`) without passing it;
`DigestCueRef` already carries `scope`/`scope_id` threaded structurally by chunk #92 for exactly this reason;
the producer already reads the first cue for its identity tuple (`pulse-app/src/inference_runtime.rs:651`).
One field travels the same rail: `AttentionCue` → `DigestCueRef` → `Incident.fingerprint`.

Two constraints shape every step. **Width is the defect's disguise** — `triage` already has a
`fingerprint_to_hex_prefix` (`crates/triage/src/pattern/storm.rs:450`) that is correctly named, adjacent, and
**8 characters** (4 bytes, for bounded-cardinality tracing per obs-plan §5), while the match target is
`hex_lower` over the **full 16 bytes**, 32 characters (`crates/triage/src/digest/assembler.rs:283-288,686`).
Reusing the near helper re-starves the arm while any shape-only assertion still passes. **Layer 2 stays
decided** — incident identity remains `(kind, scope, scope_id)` (architecture.md §Established Decisions
[Fault Identity]); this chunk makes per-fingerprint dedupe *possible*, and deliberately does not adopt it.

dependency direction; test-plan §2/§3/§11; obs-plan §5/§8; security-plan §Security Anti-Patterns → Logging +
§Dependency Security.

## Constraints & rejected approaches

- **Reusing `fingerprint_to_hex_prefix` (`pattern/storm.rs:450`) for the cue value — REJECTED.** It encodes
  4 of 16 bytes (8 chars); the match target is 32. It would re-starve the arm invisibly.
- **Widening that helper to 16 bytes — REJECTED.** Its live caller at `:340` is a tracing field bound by
  obs-plan §5 cardinality discipline; widening trades one silent defect for another.
- **A second full-width encoder beside the shared one — REJECTED** (decisive lean, step 1). Two encoders that
  must agree is precisely the failure shape research measured; one shared function makes agreement structural.
- **Scrubbing the fingerprint in `scrubbed_clone` — REJECTED** (decisive lean, step 6). Measured against
  `crates/security/src/scrubber.rs`: no production pattern matches a bare hex digest (the api-key/token
  patterns at `:77`/`:84` all require a `key=`/`token:` prefix), so scrubbing is a no-op in production — but
  the credit-card pattern `\b(?:\d[ \-]?){13,19}\b` (`:97`) WOULD match an all-digit fixture, so scrubbing
  adds a corruption path that only fires in tests. Document the exemption; the scrub-transparency pin guards it.
- **Adding a `triage → buffer` dependency — REJECTED.** `triage` deliberately carries none
  (`crates/triage/src/pattern/storm.rs:13-18`) and needs none: `ExceptionFingerprint` is a `[u8; 16]` alias
  and the bytes already arrive opaquely through the `FingerprintObserver` seam.
- **Adopting per-fingerprint incident dedupe — OUT OF SCOPE.** Layer 2 stays coalesce-per-cue-identity
  (architecture.md §Established Decisions [Fault Identity]). This chunk makes it *possible*; a future entry
  may decide it. Do not change the predicate at `pulse-app/src/inference_runtime.rs:674-678`.
- **Touching `select_corpus_matches` / `select_previously_seen` — DO NOT.** They are correct; the prior chunk
  reverted an attempted narrowing and left an in-code guard. This chunk feeds them.
