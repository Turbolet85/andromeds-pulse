## Deviations from intent

1. **Shared encoder placed in `contract.rs`, not a new module.** Plan step 1 said "promote to a crate-internal shared helper" without naming a home. **Justification:** `contract.rs` is the module both `pattern` and `digest` already import, so it avoids a `pattern → digest` edge that would invert the intra-crate direction; it also honors the plan's declared "New files: (none)".
2. **`synthesize_cue` takes `&RetryStormDetector` instead of the two threshold args.** The 8th parameter tripped `clippy::too_many_arguments`. **Justification:** both thresholds were always `detector.*` at both call sites, so collapsing them is fewer arguments AND removes the possibility of passing mismatched thresholds — better code rather than an `#[allow]` suppression, which the fix-loop protocol treats as the worse move.

Relaxing either to match the new empty default is the documented anti-pattern (a test is the contract); strengthening preserves what each pin claims to prove.
4. **7 new tests, not the 5 the plan enumerated.** **Justification:** the 5 planned (width, namespace-agreement, absence, scrub-transparency, coalesce-intact) plus a `hex_lower` full-width check and a `DigestCueRef` pre-field-BLOB deserialization pin — the `#[serde(default)]` back-compat guard the plan implied under step 5 but did not list as a test.

## Decisions & corrections

- **Fingerprint width is the chunk's central risk, and is pinned as such.** `triage` already had a correctly-named, adjacent `fingerprint_to_hex_prefix` that encodes **4 of 16 bytes** (8 chars, for bounded-cardinality tracing per obs-plan §5), while the match target is `hex_lower` over all 16 (32 chars). Reusing the near helper would have silently re-starved the arm while any "is it hex?" assertion still passed. The acceptance asserts the **width** and an explicit **inequality** against the 8-char form.
- **The produced fingerprint is deliberately NOT scrubbed, and that is now a guarded decision rather than an omission.** Measured against `crates/security/src/scrubber.rs`: no production pattern matches a bare hex digest (the api-key/token patterns require a `key=`/`token:` prefix), so scrubbing would be a no-op on real values — but the credit-card pattern `\b(?:\d[ \-]?){13,19}\b` **would** match an all-digit hex fixture, so scrubbing adds a corruption path that fires only in tests. Documented as construction-exempt at the site, guarded by a `scrubbed_clone` transparency pin, and the fixture constants deliberately contain `a`–`f` nibbles.
- **The Layer-2 coalesce decision's revisit-dependency is now ACTIVE.** Per-fingerprint incident dedupe was previously impossible (no real fingerprint at the incident site); it is now *possible*. The decision itself stays **DECIDED** and untouched — the predicate was not changed. The in-code comment at `pulse-app/src/inference_runtime.rs` was corrected: two of its stated reasons ("the cue does not carry one"; "the only fingerprint in scope is model-authored") stopped being true, so the rationale was restated on the ground that survives (every downstream surface is already N-safe, so a second concurrent incident would change no rendering and no L4 behaviour).
