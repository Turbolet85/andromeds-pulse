## Goal

Make the silence family reachable for a fresh service inside a **bounded, declared warm-up**, so an external
harness can prove it end-to-end in one scenario run instead of waiting out an hour of wall-clock.

Research narrowed the target sharply and corrected the entry's framing. The 3600s wall-clock gate has exactly
**one** consumer — `evaluate_service_went_silent` (`crates/triage/src/cue/evaluate.rs:164`), which gates on
`snapshot.bootstrap_state != BootstrapState::Ready`. *activity-floor* is not a second family but the substrate
computing that gate (`ActivityFloor` owns `first_observed_unix_nanos` → `BootstrapState`, plus the
quiet-duration t-digest supplying the p95). *error-baseline-spike* is gated by `min_ewma_samples = 10`
(`evaluate.rs:38`) and never touches the hour, so it is already reachable in seconds under load and needs
nothing here.

Research also found a defect the chunk must repair rather than route around: `Thresholds.bootstrap_window_seconds`
(`cue/thresholds.rs:141`) is **inert** — defaulted (`:163`), validated to reject zero (`:243`), and documented
as mirroring `baseline::BOOTSTRAP_WINDOW_SECONDS` "so config-path / hot-reload stay consistent" — yet read by
no evaluation path, and `evaluate_service_went_silent` takes `_thresholds` underscore-prefixed. The effective
gate is the hardcoded const at `activity_floor.rs:33`. Changing the config field alone would be a silent
no-op, so "make the same value reach both constants" is insufficient as the entry stated it: the field must
become **load-bearing**.

The chosen mechanism (operator-selected at P4) is an **env-resolved bound with the production default
unchanged**: the gate consults the threshold field, and that field resolves from a bounded, arch-registered
env var defaulting to 3600. This keeps production detection byte-identical for every user, stays entirely
inside `crates/triage` (so no boot-smoke trigger, no TauRPC binding regen, no npm gates per test-plan §3),
and follows the `ANDROMEDA_PULSE_L4_DETERMINISTIC` precedent for a default-off env gate landed to make
behaviour reproducible for external verification (per architecture.md §Occupied Resources → Environment
variables).
