Formalization has a precise meaning here, set by two measured false-negative shapes the injector has already
produced. First, **rate and lifetime**: the injector today runs `payment-service` at `error_pct: 100` for
`TOTAL_BATCHES = 600` × 500 ms ≈ 300 s and then exits. Research falsified the CARRY's stated reason (300 s
spans the L2→L3 20–60 s window comfortably) but confirmed two real defects in its place — the traces view ages
out against its 60 s window once the injector exits, and a 100 % firehose is the very condition the paused
2026-06-01 run suspected of driving cadence into tier1, where the LWW queue drops digests before L4 at ~4 s per
inference. Sustained mode therefore means **moderate-and-lasting**, not merely longer. Second, **invocation**:
`cargo run … --example inject_demo` inside a timed section measures the compiler — measured 2026-08-16, a cold
cache spent the entire budget building `rustls` + `h2`, was killed at the boundary, and sent zero spans while
the app looked healthy. The supported form is the prebuilt binary by path, which `xtask::webview_drive` already
practises (`build_injector` → `PULSE_INJECTOR`), plus a feed-precondition assertion so "the producer never ran"
is distinguishable from "the feature is broken" (per test-plan §3 Direct-binary smoke variant + obs-plan §1

## Constraints & rejected approaches

- **Changing the injector's default emission — REJECTED.** `webview_drive` threads no arguments, so a new default silently rewrites the 15-stage leg's storm-stage budget. Sustained mode is opt-in.
- **Varying the exception fingerprint to make the stream "unique" — REJECTED.** A storm is many of the *same* fingerprint (the injector's own header), and L2 coalesces incidents on `(kind, scope, scope_id)` so a varied fingerprint is absorbed by design — it buys no second incident and can prevent storm formation outright (arch §Established Decisions [Fault Identity]).
- **Removing the whole `LwwQueue` — REJECTED.** Only the drain surface is dead; the cap path fires in production.
- **Moving the L4 prompt off argv to `--file` — REJECTED for this chunk.** It is a real security-plan tension but pre-existing, and arch scopes L4-runtime changes out (§Established Decisions [LLM Inference Runtime] pin discipline + open caveat). Recorded as a residual instead of silently absorbed.
- **Solving the traces aging-out by widening the `viz.query.traces` window — NOT taken.** The CARRY offered it as an alternative, but research showed the defect is the injector exiting plus a 100 % rate, so the fix belongs in the producer; widening the window would mask a stalled feed, which design/layouts both ban (honest-error before empty).
- **Re-doing the api-surface retirement — REJECTED.** It landed at `5a83771`; only a dangling spec reference remains.
- **Adding an npm devDependency to fix `lint:a11y` — AVOID.** The `pulse-app/ui` npm channel has version updates but no advisory/license/ban scanning, so a new dep lands where no gate would fail on an advisory (per security-plan §Dependency Security).
