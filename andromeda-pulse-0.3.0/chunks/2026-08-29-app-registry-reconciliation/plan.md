## Goal

An incident resolved by a writer outside this process — today the `andromeda-pulse-mcp` sidecar's
`mark_incident_resolved`, which an agent calls — stops being displayed as active by the running app. The
predecessor `2026-08-27-incident-persist-vs-resolve-write-race` made the CORPUS correct via a monotonic
last-writer guard at the `CorpusWriter` choke point, and explicitly recorded the app half as an accepted
residual owned by this entry (per architecture.md §Established Decisions [Corpus Write Arbitration]). This
chunk closes that half.

Research made the shape much smaller than the route entry's three-way fork suggested. **`IncidentRegistry::list_active`
is a single choke point feeding all three consumers** — the `incidents.list_active` resolver
(`pulse-app/src/incidents_router.rs:213`), the `services.list_with_states` max-tier join that drives the
constellation dot hue (`pulse-app/src/services_router.rs:95`, `:97-103`), and the 60 s persist cycle itself —
and **both user-visible surfaces already poll at ~1 s** (`pulse-app/ui/src/hooks/use-findings.ts:41`,
`FINDINGS_REPOLL_MS = 1000`). So a registry-side reconciliation propagates to the findings badge, the findings
window and the constellation hue within about a second, with **no frontend change, no new TauRPC procedure and
no new event topic**. Fork (b) (a sidecar→app notification) would buy latency the poll already provides at the
cost of the unregistered cross-process transport architecture.md §Design Philosophy forbids; fork (c) (surface
the staleness) describes a state a working reconciler removes rather than displays.

The reconciliation folds into the existing 60 s persist cycle (operator-selected at the P4 fork). That cycle
already calls `registry.list_active` and already writes every active row, so it is the exact loop where the
divergence manifests as a declined write — detection and symptom end up in one place, with no new tokio task,
hence no obs-plan §3 heartbeat obligation and no new spawn site to pin. The observability delta is a **leaf
completion** on the existing `triage.incident.persist` target (4 → 5 fields), which obs-plan §8 names as the
canonical pattern for extending an existing record. The chunk additionally discharges the standing
`mcp-incident-read-back-cross-process-coverage` debt (test-plan §1 · §6 P3), which names this same tool.

## Implementation Steps

1. **Declare a narrow read port in `triage`, not a corpus dependency.** `triage` sits BELOW `corpus` in the
   dependency DAG (architecture.md §Established Decisions [Corpus Write Arbitration] — the stated reason
   `IncidentWriteOutcome` is a parallel type rather than a re-export), and the graph confirms no `triage → corpus`
   edge exists. Add a trait to `crates/triage/src/incident/persistence.rs` exposing only what the reconciler
   needs: the set of incident **ids** the durable store still considers active for a workspace, returned as a
   `Result`. Ids only — no payloads, so nothing decrypts or decodes inside `triage` and no corpus type crosses
   the boundary. This is the established trait-in-lower-crate + inject-`&dyn`-at-the-binary-boundary pattern.

2. **Implement the port in `pulse-app` over the handle that already exists.** The adapter wraps
   `Arc<dyn CorpusWriter>` (note: the incident read methods live on `CorpusWriter`, NOT `CorpusReader`, which
   carries only `inspect()` / `path()` — see research §Headline finding) and maps
   `load_active_incidents(workspace)` to the id set. `pulse-app → corpus` already exists, so this adds **zero**
   crate edges.

3. **Add the reconcile step to `run_incident_persist_cycle`, before the write loop.** For each workspace: read
   the durable active-id set; compute the registry-active rows whose ids are absent from it; drive each through
   the existing `IncidentRegistry::mark_resolved` transition. This makes the reconciler the third production
   caller of an existing verb (`mark_resolved @ pulse-app/src/incident_observer.rs:66` and
   `@ pulse-app/src/incidents_router.rs:300`) rather than introducing a new registry state.

4. **Make the failure mode fail SAFE, and pin it.** This is the step with the largest blast radius: if the
   durable read returns `Err` and the code treats it as an empty set, the predicate "absent from the durable
   active set" matches **every** registry row and the reconciler resolves the entire active list. On `Err`,
   skip reconciliation for that workspace entirely and continue to the existing write loop unchanged; log on
   the existing `triage.incident.persist.error` target with a new bounded `persist_kind` token, following the
   established discriminator convention (`incident_auto_resolve` / `incident_mark_resolved` /
   `incident_boot_restore`). A dedicated test must cover Err-does-not-resolve-anything.

5. **Fold `reconciled_count` onto the existing cycle emission.** One counter, folded across the cycle and
   emitted ONCE on `triage.incident.persist` alongside `incident_count` / `persist_kind` / `duration_ms` /
   `declined_count` — never per row and never per reconciled incident (obs-plan §11 Telemetry Strategy; the
   `declined_count` precedent exists for exactly this reason).

6. **Complete the allowlist leaf and its guard together.** Add `reconciled_count` to the
   `"triage.incident.persist"` entry in `pulse-app/src/observability.rs` (currently the four fields at
   `:2325-2330`) and extend `pulse-app/tests/unit_observability_allowlist_incident_diagnostics.rs` so the field
   set is asserted by **equality in both directions** — that is what catches a narrowed leaf, which would leave
   the target partly redacted and make the GREEN measurement read as all-zeroes (obs-plan §8).

7. **Thread the adapter at the one wiring site.** `pulse-app/src/main.rs:1504` already constructs the persist
   loop from the registry + persistence pair inside the `if let Some(persistence)` block, and `corpus_writer`
   is already in scope there. Pass the new adapter as one additional constructor argument — a single site, not
   a chain.

8. **Land the committed cross-process assertion** (operator-selected). A `pulse-app/tests/*.rs` test spawns the
   real `andromeda-pulse-mcp` subprocess and asserts the **response CONTENT** of a
   `tools/call mark_incident_resolved` — the applied shape and the guard's not-applied shape — following the
   `corpus` crate's real-process-boundary precedent (test-plan §4 · §5). This discharges
   `mcp-incident-read-back-cross-process-coverage`, whose standing gap is that a revert to the old
   unconditional `{"resolved": true}` shape would pass every committed cross-process assertion today.

9. **Add `cargo xtask smoke:external-resolve` as the producing invocation for the live legs.** Following the
   `smoke:gap-resume` / `check:ingest-progress` precedent: boot the app on a fresh data dir under
   deterministic L4, drive telemetry over real OTLP via `inject_demo` until an incident forms, resolve it
   through a real sidecar subprocess, then observe across at least two persist cycles. The leg must **prove its
   own preconditions** — reporting INCONCLUSIVE rather than PASS when no incident formed or the sidecar resolve
   did not apply — per the vacuous-PASS lesson from `2026-08-28-ingest-consumer-initiating-freeze`.

## Implementation notes
- **Why "absent from the durable active set" is a safe predicate:** an incident's id originates from the corpus
  INSERT (`save_incident` assigns the rowid) before it enters the registry, so every registry row has a
  corpus row; and `load_active_incidents` filters `WHERE workspace = ?1 AND status != 'resolved'`. Absence from
  that set therefore means resolved, not not-yet-persisted. Confirm this ordering holds at implement before
  relying on it — it is the predicate's whole safety argument.
- **Order sensitivity:** reconcile BEFORE the write loop, so the same cycle stops re-offering the row it just
  reconciled and `declined_count` returns to 0 in the same pass that `reconciled_count` goes positive.
- **The persist loop is spawned with exactly one workspace** (`vec![incident_workspace_for_persist.clone()]`,
  `pulse-app/src/main.rs:1506`), so the per-workspace loop has one iteration in production; keep the signature
  workspace-plural anyway to match the existing shape.
- **`declined_count` has never been observed non-zero in production** — the predecessor's report records it as
  "plumbing proven, arithmetic test-only". The RED leg is what first drives it above zero, so treat a zero
  reading there as evidence the leg did not reproduce, not as evidence the defect is absent.
- **The live leg needs ~150 s of observation** (two 60 s cycles plus formation time). Bound it explicitly and
  make the window a stated precondition, not an implicit assumption.
