## Goal

Two residues of `2026-08-23-headful-leg-extension` get settled by measurement rather than assumption.

**Half A** — four window-mechanic stages (drag · resize · native-menu · every-time-toast repetition) were
deferred because the driver capability they need has never been exercised against a WRY window on this host.
This chunk **probes that capability first**, then lands each stage the probe supports and **declines, with a
recorded measured reason, each stage it does not**. A declined stage is a first-class success outcome; a stage
whose assertion cannot fail is not (test-plan §6 requires every predicate match an effect FIELD, and
test-plan §11 forbids softening a mechanic into a human check).

**Half B** — the per-boot lost-initial-navigation race is remediated only inside the harness driver, while
every production boot creates and navigates the same four windows. Research falsified the route's literal
wording twice here: the dictated guard site (`pulse-app/src/window.rs`) has **no on-show hook** — Tauri 2's
`WindowEvent` exposes no Shown variant and `findings`/`report`/`main` are shown from the FRONTEND — and path
(a) "measure a plain boot's per-webview URLs" has **no existing mechanism**, because nothing in the shipped
product reports a webview's URL and attaching a driver is what makes the boot not-plain. The plan therefore
takes the third shape research surfaced: **instrument, measure, and guard in-chunk if the measurement shows
production exposure** (see the lean in Constraints).

The chunk claims **no new capability** — every capability its CARRYs touch is already `verified`, so the work
strengthens existing evidence, exactly as its predecessor did.

## Implementation Steps

1. **Probe FIRST, before any stage is written** (scope §2). Extend the node driver with a probe that, against
   the live window through the existing tauri-driver → msedgedriver transport, measures:
   (a) whether a W3C pointer Actions sequence (down → move → up) reaches the window at all, and whether one
   performed inside the drag region produces a real OS-level window-position delta;
   (b) whether a driver-side window-rect resize takes effect.
   The probe RECORDS its result into the stage report artifact like any other observation. Its outcome is an
   input to steps 2–5, not a gate that fails the run: "the driver cannot do this" is a finding.

2. **Apply the decision rule to each of the four stages.** For each: the probe supports the mechanism ⇒ land
   the stage in the leg's established shape (a real press/gesture, `StageHalves{obs, dom}` with each half
   independent, a field-level predicate, `--expect-absent`-eligible). The probe does not ⇒ **decline it and
   record the measured reason** in the chunk report and in the test-plan §6 amendment. Do not substitute a
   weaker assertion to keep a stage alive.
   - **Drag** (P-061 residual): assert window-position delta > 0 from a real titlebar drag. Press inside the
     drag region and clear of every control — `Titlebar.tsx:101`'s `titlebar__grow` spacer is the safe target
     (`data-tauri-drag-region` also at `:67`, `:83`, `:90`). The boot-geometry sub-part (widget boots at the
     margin-inset corner, `WIDGET_EDGE_MARGIN = 24`) rides along as a DOM/geometry observation.
   - **Resize** (P-062 residual): assert the live clamp and the 1.4–2.1 aspect band **on release** — the
     clamp is debounced 150 ms (`ASPECT_DEBOUNCE`), so wait on an observable settle signal, never `sleep(N)`
     (test-plan §11). Fold in P-082's multi-window-size half: at every driven size the Traces route shows no
     outer page scrollbar and the table region is the sole scrolling element.
   - **Native menu** (P-064/P-065 residual): probe whether a native WebView2 context menu is observable to
     WebDriver at all. If not, assert the **suppression** side instead — `use-suppress-browser-chrome.ts:27,38`
     installs a document-level `contextmenu` listener, so `defaultPrevented` is a real observable — or decline.
     Never un-suppress the menu to make it observable.
   - **Toast repetition** (P-063 residual): two widget-✕ closes, each requiring the labelled
     `tray.signpost.shown` record with `window_label == "compact-widget"`. The **restore leg between them** is
     the declinable part: tray restore is OS-native (`tray.rs:273`) and out of WebDriver reach. A programmatic
     re-show is acceptable as SETUP (the grant exists) provided both assertions remain real close presses.

3. **Half B — instrument.** Add a one-shot, post-settle boot-time navigation check in `pulse-app` that reads

## Constraints & rejected approaches

- **Half B path — leaned (c) instrument-then-measure, with the guard conditional and in-chunk.** Path (a) as
  the route worded it was rejected on measurement: nothing in the shipped product reports a webview's URL, and
  attaching a driver is exactly what makes a boot not-plain, so pure (a) has no mechanism. Path (b)
  guard-only was rejected because it repairs without ever measuring, leaving the operator's own
  "production exposure UNMEASURED" true forever. (c) answers the open question, leaves a durable detector, and
  composes with the repair; shipping the guard in the same chunk when the measurement warrants it follows the
  standing fix-in-chunk preference. **This lean is the one item to confirm at the P5 review** — a rejection
  sends the plan back to P4 with the promotion intact.
- **No vacuous stage** — a stage whose assertion cannot fail is a defect, not coverage. Decline and record.
- **Never un-suppress the WebView2 context menu, shrink the drag region, pin geometry, or make a window
  non-resizable** to make a mechanic deterministic — the harness adapts to the designed window, not the
  reverse (design-system §Anti-Patterns → Per-Surface Bans).
- **No in-process bypass or test-mode flag** to make a stage observable; telemetry enters only over real OTLP
  via `inject_demo` (architecture.md §Cross-cutting Patterns → Test-time telemetry injection).
- **No `sleep(N)`, no retry-to-settle, no human-judged step** — the 150 ms aspect debounce is waited on by an
  observable signal (test-plan §10, §11).
- **No stage may key on the Halo State Pulse canvas** — it has no production render site and its disposition
  is a separate route entry (layout-templates / design-system, measured 2026-08-21).
- **Do not re-open SC 1.4.10 Reflow / SC 1.4.4 Resize Text** — a11y-plan §1 records both NOT applicable, so
  the P-082 half is a layout assertion, not a reflow one.
- **This leg is not WCAG evidence** — a stage verdict is stage evidence; conformance claims require the
  machine-verifiable `test:a11y` chain (a11y-plan §10, §11 Strategy).
- **Do not CI-wire the leg** — out of scope; test-plan §9 records it gates nothing today, and that stays true.

## Implementation notes

- **Both mechanics are silent at HEAD.** `WindowEvent::Moved` is guarded to the MAIN window only and emits no
  tracing record (it calls `record_move_throttled` into `window-geometry.json`); the widget is deliberately
  excluded per a P-061 correction. A successful aspect clamp emits nothing — only `set_size_failed` warns. So
  drag and resize verdicts are **DOM-half-only** unless an emission is added, which precedent permits (the
  predecessor landed five of six stages DOM-half-only). Adding one is optional and, if done, must ride the
  debounced settle boundary — never per-event at `info` (obs-plan §11).
- **Measured control surface** (bind stages to this, not to memory): `aria-label="Minimize"` / `"Maximize"` /
  `"Close to tray"` (`WindowControls.tsx:45,56,67`) and `"Toggle dashboard"` (`Titlebar.tsx:105`). Note
  `Maximize` ships alongside the pair named in the a11y extract.

  must run before the guard decision (step 4 → step 5). Writing stages first and probing afterward would make
  the decision rule retroactive, which is the failure this chunk exists to avoid.
- **`widget-close` is terminal by nature** — that press sends the whole app to the tray, so the repetition
  stage must sequence around it rather than after it.
- **Matrix disposition — this chunk claims NOTHING, deliberately.** All seven capabilities its CARRYs touch
  (P-061, P-062, P-063, P-064, P-065, P-066, P-082) are already `verified`; the version's two unclaimed
