## Goal

An incident's Diagnostic Report carries the model's actual interpretation and real evidence ids. Today —
measured live on the first real-model chain proof and reproduced first-hand at P3 from the preserved corpus —
every report renders `degraded_mode: true` with "_Interpretation pending_" DESPITE clean parses, because
`get_report` reads only `incident.resolution_summary_text` (`pulse-app/src/incidents_router.rs:437-441`) and
production NEVER writes that field: the create path sets `None` (`inference_runtime.rs:742`) and the
Resolved-attach arm has zero producers (`DigestKind::ResolutionSummary` is constructed nowhere outside tests —
re-verified at HEAD). Deliverable A closes the seam: the latest cleanly-parsed `L4Output` is attached to the
incident — at creation and on every deduped re-generation — through the existing scrub→registry→
`update_incident_status` BLOB-rewrite discipline (chunk #86 shape, minus the Resolved-only guard), so
`degraded_mode` becomes an honest verdict for every status, in-app and cross-process (the MCP sidecar's
`dispatch_retrieve_report` parses the same field with no status gate — data-driven win, zero sidecar change).

Deliverable B makes citing copying: the interpretation prompt gains a delimited CITABLE EVIDENCE IDS section
carrying the digest's real full-hex cue fingerprints (`DigestCueRef.fingerprint` — the only real id at the
seam; per arch §Established Decisions [Fault Identity] L1, full `hex_lower` form, never the 8-char prefix)
plus a copy-don't-invent instruction in the `OUTPUT_REMINDER*` consts (empty list ⇒ emit empty
`evidence_refs`, honest empty over invention — the model-native placeholders `payment-service-123` /
`0x1234567890abcdef` are the defect, per the P-077 report :58/:82). Independently, the producer join grounds
`EvidenceRefs.fingerprint_hashes` as the UNION of the model's refs and the triggering cue's fingerprint, so
the incident RECORD carries ground truth regardless of model behavior (per security-plan §Input Validation
L4-argv row + obs-plan §8 Vector 1 — the injection stays upstream of `validate_prompt_bounded` and no id
value is ever logged).

- **Rejected: keying anything on `L4Output.fingerprint`** — model-authored, constant under the deterministic
  runner (arch §Fault Identity, standing decision).

  leaf edit — and leaf edits are out of scope; zero-obs-delta is a stated acceptance).

  the new method is a SIBLING.

  the dedicated delimited section (leaned per prompt.rs's own delimited-markers design; a
