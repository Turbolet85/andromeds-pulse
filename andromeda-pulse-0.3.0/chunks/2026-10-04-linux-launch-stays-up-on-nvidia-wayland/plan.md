## Goal
Make the default Linux launch survive on an NVIDIA GPU under a native Wayland compositor. P3 measured the death
first, as the founder ruling of 2026-10-04 required (research.md §Host measurement). The default posture dies 3/3
at about 2.0 s, exit 1: GTK's Wayland backend logs `Error 71 (Protocol error)` and calls `_exit(1)` (verified in
`libgdk-3.so.0`). Each of four single-variable levers keeps the app up for 60 s, and their common factor is that
each removes NVIDIA's EGL explicit-sync path on a native Wayland surface. `WEBKIT_DISABLE_DMABUF_RENDERER` is
therefore a lever, not the cause.

The shipped remedy is the founder's option 1. On Linux only, the FIRST statement of `main()` sets
`__NV_DISABLE_EXPLICIT_SYNC=1` when the variable is unset. A value already set (any value, empty included) is
honoured, and it is never parsed and never logged. Only NVIDIA's driver reads that variable, so the default is
NVIDIA-scoped by construction and needs no detection probe. Tauri's own guidance recommends exactly this lever,
set in `main()` before the webview is created, once the app is verified affected (research.md §Platform issues).

One closed-label boot record, `app.boot.render.posture`, names the posture. It sits behind its own exact
allowlist leaf, per obs-plan §8's default-deny posture and §6's once-per-boot rows, and carries only the variable
NAME, per security-plan §Security Anti-Patterns → Logging. macOS and Windows launch behaviour is unchanged
(architecture §Project Intent; §Cross-cutting Patterns → Config management for the precedence of a preset value).

## Implementation Steps
1. **Create `pulse-app/src/render_posture.rs`** (new lib module; ASCII-only; no `#[test]` in it — the dead-lib-src
   ratchet is a flat zero). It holds:
   - `pub const LEVER_ENV: &str = "__NV_DISABLE_EXPLICIT_SYNC"` and `pub const LEVER_VALUE: &str = "1"`.
   - `pub enum RenderPosture { Applied, PresetHonoured, NotApplicable }` with `pub fn label(self) -> &'static str`
     returning exactly `applied` · `preset_honoured` · `not_applicable`.
   - `pub fn decide(is_linux: bool, preset_present: bool) -> RenderPosture`, a pure function. Not Linux →
     `NotApplicable`. Linux with the variable present (any value, empty included) → `PresetHonoured`. Linux with it
     absent → `Applied`. The preset's VALUE is not an input: honouring a preset needs only its presence, so the
     value is never parsed.
   - `pub fn apply_linux_default() -> RenderPosture`. It reads `std::env::var_os(LEVER_ENV).is_some()` and
     `cfg!(target_os = "linux")`, calls `decide`, and only on `Applied` sets the variable inside
     `unsafe { std::env::set_var(LEVER_ENV, LEVER_VALUE) }`. A `// SAFETY:` comment states the precondition:
     the function is called as the first statement of `main()`, before
     `tokio::runtime::Builder::new_multi_thread().build()` (`pulse-app/src/main.rs:285`) spawns any thread, so no
     other thread reads or writes the environment. The doc comment says the function must not be called anywhere
     else.
   - `pub fn emit_posture(posture: RenderPosture)`. It emits target `app.boot.render.posture` with exactly two
     fields, `posture = posture.label()` and `lever = LEVER_ENV`: INFO for `applied` / `not_applicable`, WARN for
     `preset_honoured` (an overridden posture, per obs-plan §6's warn-row rule). It never emits the preset value.

## Constraints & rejected approaches
- `WEBKIT_DISABLE_DMABUF_RENDERER=1` as the default — rejected by the founder ruling (option 2). It costs WebKitGTK's
  faster render path on every Linux GPU, AMD and Intel included.
- A detection probe (`/sys/module/nvidia`, `WAYLAND_DISPLAY`) gating the lever — rejected (option 3). Two more
  product-read inputs and no behavioural gain, since non-NVIDIA drivers never read the variable.
- `GDK_BACKEND=x11` or forcing Mesa's EGL vendor — rejected. Both survive only on a degraded render path (GBM
  buffer failures; Mesa cannot drive the NVIDIA device), per research.md §Host measurement arms D and E.
- Setting the lever anywhere after the tokio runtime build, or after `observability::init` — rejected. The runtime's
  worker threads already exist then, which breaks the edition-2024 `set_var` precondition.
- Parsing, normalising or logging the preset value — rejected. Honouring needs only presence, and a logged value is
  a raw env value on the wire.
- Overwriting a preset (e.g. forcing `1` over a user's `0`) — rejected. It breaks config precedence (process env
  outranks built-in defaults).
- A relaunch-on-crash or retry wrapper around the Wayland death — rejected (obs-plan §11 SLO; it masks the class
  rather than removing it).
- Shipping a different lever if the GREEN leg fails — rejected. The ruled shape is option 1; a change of shape goes
  back to the founder.
- Mutating process env inside the test process — rejected (testing.md §11 Mocking). The real `set_var` path runs
  only in re-exec child processes.
