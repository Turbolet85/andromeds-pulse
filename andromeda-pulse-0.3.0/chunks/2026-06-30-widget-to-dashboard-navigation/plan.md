## Goal
Give the glance widget an explicit, discoverable in-app affordance to expand into the full dashboard (intent
F6 / P-066). Today the `main` dashboard window is reachable only via the tray ("Open Settings"); the
`compact-widget` has no button and no working shortcut.

Research (see `research.md`) corrects the intent's implied mechanism — a **RESEARCH-CORRECTS-INTENT premise
refinement** in the P-061/P-063 family. A cross-window show/focus path already exists
(`use-keyboard-shortcuts.ts::toggleCompactDashboard`, the Cmd+Shift+P handler) but is **silently broken**:
`pulse-app/capabilities/default.json` grants `core:window` start-dragging/minimize/toggle-maximize/close but
**not** `allow-show`/`allow-set-focus`/`allow-hide`, and `core:default` is getters-only (verified P-061
learning) — so its `.show()/.setFocus()/.hide()` calls are silently rejected. The OUTCOME (an in-widget
affordance opens the dashboard) is unchanged; the unstated MECHANISM is that the chunk must **also grant the
missing `core:window` permissions**. The user chose (P4 AskUserQuestion) the **expand-and-hide-widget**
semantics: activating the affordance does `main.show()` + `main.setFocus()` + `compact.hide()` — a true
"expand into" that keeps the always-on-top widget from floating over the dashboard, symmetric with Cmd+Shift+P;
the `allow-hide` grant repairs that dead toggle for free.

Mechanism is settled by codebase precedent: a direct `@tauri-apps/api/webviewWindow` call + an explicit
`core:window:*` grant (per arch §Webview IPC capability policy + the P-061/P-063 titlebar window-control
precedent) — **not** a new TauRPC procedure (that contradicts how every webview window-op in this app already
works and would incur the namespace-binding cost for no benefit). The affordance is a native
`<button aria-label="Expand to dashboard">` (the exact label a11y-plan §P5 already names) in the shared
`Titlebar`, conditionally rendered only on the widget — mirroring the existing Investigate button — styled per
design-system tokens with a visible focus ring and ≥24px hit-target.

## Implementation Steps
1. **New hook `use-expand-to-dashboard.ts`** — export a handler that resolves both windows via
   `getAllWebviewWindows()` (try/catch jsdom-safe, per `use-keyboard-shortcuts.ts:53`) and performs
   `main.show()` → `main.setFocus()` → `compact.hide()`. Prefer extracting a shared `expandToDashboard()` the
   keyboard shortcut's "compact-visible" branch can also call, so the widget→dashboard transition has one
   source of truth (WHAT; the exact share shape is /implement's call).
2. **Grant the missing window permissions** — add `core:window:allow-show`, `core:window:allow-set-focus`,
   `core:window:allow-hide` to `pulse-app/capabilities/default.json` `permissions`, with a dated rationale
   sentence appended to `description` (following the P-061/P-063 precedent in that file): names the new
   in-widget Expand affordance + notes these repair the previously-silent `toggleCompactDashboard` path, and
   states they are core-window perms (no capability-drift impact) and not one of the 3 NEVER-widen caps (no
   capability-widening-check impact).
3. **Add the affordance to `Titlebar.tsx`** — add an optional `onExpandClick?: () => void` prop; when provided,
   render a native `<button type="button" aria-label="Expand to dashboard">` in the actionable cluster
   (beside Investigate/Settings), reusing the existing button styling (`--target-input-min` hit-target,
   `--color-text-secondary`, `--duration-fast`/`--easing-out`, `motion-reduce:` classes) + an appropriate
   `Icon` glyph (a fitting domain glyph if one exists, else a Lucide expand/maximize fallback per
   design §Iconography). Absent prop ⇒ button not rendered (so it does not appear on the dashboard).
4. **Wire it in `CompactWidget.tsx`** — pass `onExpandClick={expandToDashboard}` (from the new hook) to
   `<Titlebar>`.
5. **Repair the stale comment + (optional) share the helper** in `use-keyboard-shortcuts.ts` — correct the
   "covered by core:default capability" comment (now grants are explicit); if the shared helper is extracted in
   step 1, repoint the compact-visible branch at it. The `allow-hide` grant alone already makes Cmd+Shift+P work.
6. **Tests** — (a) `use-expand-to-dashboard.test.ts`: mock `@tauri-apps/api/webviewWindow::getAllWebviewWindows`
   (the `vi.hoisted` + fake-window pattern from `use-keyboard-shortcuts.test.ts`); assert a real invocation
   calls `main.show()` + `main.setFocus()` + `compact.hide()`, and the jsdom-throw path no-ops. (b)
   `Titlebar.test.tsx`: assert the Expand `<button aria-label="Expand to dashboard">` renders + fires
   `onExpandClick` on real click/keyboard when the prop is provided, and is absent when it is not. (c) Update
   any existing render/tabbable assertions affected by the new titlebar button.
