## Goal
The compact widget's Findings (incidents) dropdown renders broken: opening it stretches the widget window
and shows a white / mis-clipped region instead of sitting as a bounded popover. Root cause (research.md
§Patterns): the panel opens **downward** (`FindingsDropdown.tsx` `PANEL_BASE_STYLE.top = calc(100% + var(--spacing-xs))`)
from the `findings-band`, which is the **bottom** child of `<main height: calc(100vh - 32px)>` in
`CompactWidget.tsx` — so the panel is laid out below the widget's bottom edge, off the painted viewport; the
"white" is the native window background showing through the overflow. This violates the compact widget's
fixed-quarter-screen no-reflow contract (per layout-templates §IA Responsive behavior). The panel's own base
style is already a bounded, opaque, design-correct popover (`background: var(--color-raised-2)` — the
design-system popover token; `minWidth 240 / maxWidth 320`).

The fix is **positioning + height-bounding only**: open the panel **upward** from the bottom-anchored trigger
(`bottom: calc(100% + var(--spacing-xs))`) so it renders over the constellation area (which has vertical room)
fully within the widget, and add a viewport-derived `maxHeight` + `overflowY: auto` so a long list scrolls
internally rather than pushing the surface bounds (per layout-templates §Component Investigation modal
"capped … with scrollable overflow"). **Keep the opaque `--color-raised-2` background** — this is a recorded
premise correction: the working-route line suggested `--color-inset`, but design-system + a11y both assign
popovers `--color-raised-2` (per design-system §Surface Scale) and `--color-inset` would regress the popover
role + text contrast; the "white" is the off-viewport symptom, not a wrong token. **Operator-confirmed at
/phase P4 AskUserQuestion** (keep `--color-raised-2`). Everything else — the chunk #87 disclosure a11y
contract (role / aria-expanded / aria-controls / Escape / click-outside / focus-return), the 200ms fade +
reduced-motion, the rows / empty-state / footer, and all handlers — is preserved unchanged (per a11y §4/§5,
design §Motion). This is a webview-only change confined to `pulse-app/ui/**` with zero backend / zero new
Occupied Resources (per arch §Occupied Resources; security §API).
