## Goal
Surface unread incidents (Findings) in a **separate borderless, always-on-top window docked directly BELOW the
compact widget**, replacing the interim in-widget upward popover that `2026-07-06-incidents-panel-dropdown-layout-bug`
(P-080) landed. This closes the operator-directed follow-up from that wrap: an in-widget absolute popover is DOM-clipped
to the fixed-height frameless webview (frontend.md 2026-07-06) — a real disclosure surface needs its own window. The
window **reuses the P-080 `FindingsDropdown` row-list + mark-all-read render verbatim** (this chunk changes the
*container*, not the incident-list rendering), on the opaque `--color-raised-2` popover token (design-tokens.md §Surface
Scale — NOT `--color-inset`; the a11y extract corrected scope.md here).

Per the P4 scope decisions, the mechanism is **frontend-side** (extends the P-066 dashboard-toggle precedent
`use-toggle-dashboard.ts`): a new frontend hook shows / positions-below-the-widget / focuses the window via
`@tauri-apps/api/webviewWindow`, so **no new TauRPC procedure** is introduced (zero capability-drift /
EXPECTED_PROCEDURES / bindings cost — per arch extract + frontend.md capability discipline). The window is a **3rd
declared-hidden window** in `tauri.conf.json` (mirroring `compact-widget`/`main`), selected by a **third window-label
render branch** in `App.tsx`, and its content is a **new `FindingsWindow` wrapper** (leaving the P-080-verified
`FindingsDropdown` + its 3 layout-lock tests untouched).

The chunk also honours the chunk #87 disclosure a11y contract ACROSS the window boundary (a11y-plan §4/§5, SC 2.4.3 /
2.1.2 / 4.1.2): the badge `aria-expanded` tracks the window's visibility, opening moves focus into the panel, and
Esc / blur / row-select / mark-all-read dismiss it AND restore focus to the unread badge in the widget window (via Tauri
IPC, the P5 tray-restore precedent). Folded-in CARRY: fix the `use-findings.ts` fetch-once-no-repoll bug (frontend.md
2026-07-06) with a silent-background-refresh ~1s re-poll (frontend.md 2026-07-07) + a once-polite 0→N announce guard
(a11y.md 2026-07-07, SC 4.1.3). Only `pulse://stream/incidents` / `incidents.*` are consumed — no backend data/lifecycle
change, no new corpus/port/env/crate (arch extract).

   — all intra-`window.rs`, zero cross-crate blast (research §Graph impact).
4. **New `use-findings-window.ts` hook** (sibling of `use-toggle-dashboard.ts`): `openFindingsWindow()` resolves the
   `findings` window via `getAllWebviewWindows()`, reads the widget's `outerPosition()`+`outerSize()`, computes the
   below-widget position, **clamps into the work area** (flip-above when the widget sits near a monitor's bottom edge;
   handle multi-monitor via `currentMonitor()`/`availableMonitors()` bounds), `setPosition(...)` → `show()` →
   `setFocus()`; `hideFindingsWindow()` hides it. Keep-safe try/catch fallbacks mirroring `use-toggle-dashboard`
   (jsdom / pre-init Tauri context). The below-widget-with-clamp geometry is a **pure helper** (unit-testable without a
   live window) + the window calls around it.
5. **New `FindingsWindow.tsx`** (the `findings` render root): a window-fill panel that **reuses `FindingsDropdown`'s
   row-list + mark-all-read footer render** on opaque `--color-raised-2`, custom scrollbar (design-tokens.md), scrollable
   for overflow. Consumes `useFindings()` for rows + `markAllRead`. Esc / window-blur → hide + cross-window focus restore;
   row-select (`onRowClick` → open Report) + mark-all-read → hide. Focus moves into the panel on open; controls show the
   `--border-focus` ring (a11y extract, SC 2.4.7).
6. **Cross-window focus restore** — on dismiss (Esc/blur/row-select/mark-all-read): hide the findings window, `setFocus()`
   the widget window, and signal the widget to focus its unread badge. Use a Tauri event (`emit`/`listen` — `core:event`
   is in `core:default`) that `FindingsCounter` listens for to `.focus()` the badge; the badge `aria-expanded` flips to
   false. (a11y-plan §5, SC 2.4.3 — the P5 "focus returns via Tauri IPC" precedent; a11y extract + 2026-06-30 cross-window
   pattern.)
7. **Wire the badge trigger** — `pulse-app/ui/src/widget/FindingsCounter.tsx`: the badge click opens the Findings WINDOW

   window's visibility (cross-window sync via the event from step 6). `pulse-app/ui/src/App.tsx`: add

   `pulse-app/ui/src/widget/CompactWidget.tsx`: drop the in-widget `<FindingsDropdown>` popover (the window replaces it,
