## Goal
A CI round stops being the bottleneck of the build loop, and Linux-only failures surface on the dev host before a
push. P3 moved where the lever is. The "~2 h round" was a cold-cache round (ci#36574279289, `No cache found`); the
first warm round (ci#36593334009) took **44.8 min**, and its ubuntu leg is a serial chain of separate compiles (test
7.1 · perf 6.1 · mcp nextest 7.2 · boot 7.7 · release 3.2 + 3.2 min warm) around a ~30 s test execution. The
macOS/Windows legs follow at 33.4 / 37.1 min. So this chunk:
- **(A)** splits the workflow into parallel jobs whose longest leg, not their sum, is the round;
- **(B)** keeps the dependency cache when a job fails, and re-allocates cache keys under the measured 10 GB repo cap
  (9.27 GB used today) so that no job rides a cache built for a different purpose;
- **(C)** removes the two measured true-duplicate compiles on Linux;
- **(D)** adds a local WSL Ubuntu pre-push verb that runs the Linux-reachable gates in a synced clone.

The CARRY (E) needs no code: the two scenario verbs already exist, so their arch registration is a wrap amendment.

   - **Host + distro**: runs only on a Windows host with `wsl.exe` and the `Ubuntu` distro. A constant, not an env
     var, so no new env var is introduced. Every distro call is `wsl.exe -d Ubuntu --exec /usr/bin/env -i HOME=…
     PATH=…`, so nothing of the host environment crosses (the `wsl-exec.sh` shape). Absent host or distro →
     `cannot-evaluate`.
   - **Tool pins, read from the repo, never restated**:
     - the Rust channel from `rust-toolchain.toml`, present in the distro's rustup;
     - Node major = `ci.yml`'s `node-version`;
     - `jq`, `git` and `xvfb-run` on PATH;
     - every package in `ci.yml`'s `Install Linux system libraries` apt list installed (`dpkg-query`).

     Any missing → `cannot-evaluate`, naming each missing item and printing the single remediation command built from
     the same list (the operator runs it once with sudo; the verb never escalates).
   - **Sync**: a distro-side clone at `~/andromeda-pulse-pre-push`, brought to the host HEAD plus the working tree as
     ONE binary patch through a temporary index (the real index untouched). Verified by tree-id equality → otherwise
     `red` with `sync-mismatch`. The clone's `target/` is capped (40 GiB, the precedent's cap), and cleared above it.
   - **Stages, inside the clone, in order; each records `{name, ok, ms}`**:
     - `script-modes` — `scripts/agent-run.sh` is git mode 100755.
     - `npm` — `npm ci` + `npm run build` in `pulse-app/ui`.

     - `test` — `cargo xtask test`.
     - `ci-gates` — `cargo xtask ci-gates` against a fresh `ANDROMEDA_PULSE_DATA_DIR` seeded with a few non-metric JSON
       records. This drives `perf-slo-check.sh` / `heartbeat-gap-check.sh` over an empty metric stream on Linux bash.

     The first failing stage stops the run.
   - **Verdict**: one pretty-JSON document on stdout — `verdict` (`green` | `red` | `cannot-evaluate`), `reason`,
     `head`, `tree`, `stages[]`, `missing[]` — plus a report twin `target/pre-push/report.json`. Exits 0 green · 1 red
     · 2 cannot-evaluate.

   - **Unit tests** in the module (`#[cfg(test)]`), for the pure parts: the apt-list and `node-version` readers over a
     `ci.yml` string, the toolchain reader over `rust-toolchain.toml` text, the verdict/exit mapping, and the
     `ls-files -s` mode parse. Each has a known-positive and a known-negative case.

## Constraints & rejected approaches
- `concurrency: cancel-in-progress` on PR pushes — rejected: phase Setup 5a reads the CI verdict of EVERY sha since the
  last wrap, and a cancelled superseded run reads `not green`, which halts the next take-up.
- A per-job target cache for every job — rejected: 9.27 GB of the 10 GB cap is already in use (research.md), so six or
  more target caches evict one another and bring back the cold rounds this chunk removes. Registry-only coverage and
  read-only restores are the budget.
- Dropping the Linux default-features `cargo xtask test` as a "duplicate" of the mcp-feature nextest — rejected: the
  two runs use different feature sets (2398 vs 2433 tests), and default features are the shipping configuration.
- Dropping `test:a11y` on macOS/Windows — rejected: the saving is runner minutes only, with no wall-time gain in the
  new layout; a11y-plan §11 CI "NEVER skip a11y".
- A WSL boot arm (on overridden ports) — deferred, not built: the operator's standing directive forbids starting
  `pulse-app`, and none of the four target classes needs it. A later chunk adds it once the directive is released.
- A new env var for the distro name or clone path — rejected: constants inside the verb keep the production binary's
  env surface untouched (arch §Occupied Resources → Environment variables).
- Making `mcp-server` a default feature to merge the two Linux compiles — forbidden (arch §Conventions → Feature
  flags: default features are minimal; security.md MCP double-gate).
- Lowering a threshold, adding `continue-on-error`, a retry, or `--test-threads=1` to reach green — forbidden
  (test-plan §11 CI; a11y-plan §11; obs-plan §11).
