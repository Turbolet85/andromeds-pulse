## Goal

The Diagnostic Report's **Copy markdown** control is a dead affordance. `pulse-app/capabilities/clipboard.json`
grants `clipboard-manager:allow-write-text` to `["compact-widget", "main"]`, but chunk `2026-07-10` moved the
report into its own `report` window and the capability's window list was never widened — so
`use-report.ts:91`'s `writeText` is silently dropped by the ACL, the bare `catch` at `:93` turns it into
`copyState: "error"`, and the operator sees `Copy failed — retry`. This is exactly the failure class arch
§Cross-cutting Patterns → Webview IPC capability policy and security-plan §Anti-Patterns → API name: a
core/plugin permission that is **silently rejected at runtime when missing**. The fix is to add the `report`
label to the existing outbound grant with a stated rationale — no new permission, and the file's
NEVER-add-`allow-read-text`/`allow-read-image` posture stands untouched.

The larger half of the chunk is the gate. No shipped check catches this class: `capability-drift` parses
procedures from `bindings.ts` and never reads grants, and `capability-widening-check` covers only the three
NEVER-widen capabilities in the widening direction (test-plan §1 `webview-drive-mutation-arm-not-gated`). So
the chunk adds a headful stage that presses the **real** control in the live window and asserts a COPY-SUCCEEDED
**effect field** — never that the button was found and the click returned, which is precisely the check that
would pass in both worlds here, since the rejection is swallowed into component state (test-plan §6 Drivers per
surface).

Research established that the discriminating observable **already ships in two forms** and needs nothing new:
`data-copy-state={copyState}` on `[data-testid="report-copy-markdown"]` (`ReportRenderer.tsx:430`), and the
live-region text that `Report.tsx:29-31,58-59` feeds into `Modal`'s `role="status"` + `aria-live="polite"`
(`Modal.tsx:205-220`; strings at `report-types.ts:127-133`). The chunk therefore lands with **no new TauRPC
procedure, no new obs leaf, and no new capability identifier** (arch §Occupied Resources). The one thing it
does **not** deliver — a machine-readable record of the failure in `agent-latest.jsonl` — is an
operator-selected, explicitly-stated residual, recorded below and owed its own route entry rather than
implied as covered.

## Constraints & rejected approaches

- **Machine-readable diagnostic via a `telemetry.frontend.*` procedure — REJECTED (operator-selected option A).**
  It costs the full 4-place TauRPC binding, and it would not actually satisfy security-plan's
  "log ACL-rejected IPC calls" mandate: the webview's `catch` receives an opaque rejection and cannot know the
  ACL was the cause, so the record would say "a copy failed", not "the ACL rejected it".
- **Routing the copy through a backend procedure (the `snapshot.generate` →
  `AppHandle::clipboard()` shape) — REJECTED for this chunk.** Architecturally the cleanest and it makes the
  ACL moot, but it *replaces* the fix rather than completing it and is its own deliberate chunk, not a side
  effect of repairing a button.
- **Folding the copy assertion into the existing `report-window` predicate — REJECTED.** It would conflate two
  unrelated mechanisms in one verdict (an Escape-chain break and a copy break) and leave the copy behaviour
  inseparable from that stage's `--expect-absent` arm. A distinct id keeps failure attribution clean and gives
  a separable RED arm — the same reasoning that produced the 7 → 13 → 15 lineage. *(Decisive lean per
  test-plan §6's two-half attribution mandate + that precedent; surfaced on the P5 card.)*
- **An in-app clipboard read-back as the "did it copy" observable — BANNED.** It would require
  `clipboard-manager:allow-read-text`, the exact permission this capability's description forbids
  (security-plan §Anti-Patterns → API).
- **Do NOT assert on the button's accessible NAME.** It changes with state (`copyButtonLabel`,
  `ReportRenderer.tsx:449-459`), so a name-bound selector is unstable by construction; bind
  `data-testid="report-copy-markdown"` and read `data-copy-state`. This is the sanctioned exception to
  test-plan §6's accessible-name-first rule.
- **Do NOT widen `pulse:notification` / `pulse:tray` / `pulse:plugin-fs`** as collateral —
  `capability-widening-check` must stay green.
- **Do NOT re-open or navigate to reach the report window** for the copy press — place it inside the existing
  open window (verification-harness 2026-08-25).
