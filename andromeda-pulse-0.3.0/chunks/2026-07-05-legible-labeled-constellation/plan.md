## Goal
Make each dashboard constellation dot identifiable and its health glanceable. Today the dashboard `ConstellationCanvas` renders unlabeled WebGPU blobs: the `ConstellationDot` model already carries `service` (name), `hueFraction` (severity color), `state`, and `priorityTier`, but per-dot identity surfaces only in the aggregate `<section aria-label>` — the user sees fuzzy blue-to-burgundy blobs with no names (intent F9). This chunk adds an **always-on DOM label overlay** over the dashboard canvas: each visible dot gets its **service name** plus a **text severity token** (healthy / curious / suggested / autonomous), positioned at the dot's scatter coordinate.

Two design choices were resolved with the user at P4 (both the research-led recommendation): **always-on labels** (over hover-only / hybrid — best serves "at a glance" + keeps names in the DOM for SR/agent reachability) and a **text severity token** as the non-color cue (over glyph / both — pure DOM text, agent-assertable, reuses the P-068 semantic-token precedent, zero new assets). Research resolved the other two questions: the label layer is **DOM, not canvas text** (canvas text fails SC 4.1.2 + is agent-untestable — a11y-plan §1 + tests §1 converge), and severity is driven by the existing `priority_tier` → `severityToHueFraction` **4-tier model** (design-system Decisions Log 2026-05-29), so **no new TauRPC field/capability** is needed (arch §Occupied Resources — reuse `services.list_with_states`).

Because we chose always-on (no hover/click), P-069 is a **pure-render** capability — the name + non-color severity are asserted in the DOM + by the a11y/contrast harness, not by a headful interaction. The compact widget stays an aggregate-glance surface (no per-dot labels — layout-templates §Wireframe Compact widget). The canvas render loop is untouched, so the WebGPU frame budget (obs-plan §10) holds by construction.

## Implementation notes
- **Two-copies discipline:** the new helpers are additive to the shared module (no `visibleDots`/`constellationSummary` signature change) so the widget copy compiles untouched — only the DASHBOARD renders labels. If a shared signature ever must change, update both `ConstellationCanvas.tsx` copies + both co-located tests in one pass (frontend.md 2026-07-02).
- **Render independent of WebGPU availability:** render the label overlay from `dots` regardless of the `showFallback` branch — this keeps names DOM-reachable on the Fallback path and lets the existing unavailable-adapter test mocks assert labels without an available-adapter stub. Empty `dots` → no overlay (the aggregate aria-label already says "no active services").
- **Position mapping edge cases:** cover centre (0,0 → 50%,50%), corners, and the y-flip in the unit test; keep the scatter margin (`SCATTER_EXTENT` 0.85) so labels stay off the container edge.
- **Severity-token wording:** the 4 tokens must be pairwise-distinct + assertable; `null → "healthy"` reads better than "none" and matches the "no active incidents = calmest baseline" comment in `severity-to-halo.ts`.
- **Matrix affordance note:** because always-on was chosen, the P-069 acceptance is render-level (webview DOM + a11y), NOT an interaction — no tauri-driver headful click is required; set the matrix `method: webview` / render-form `acceptance` at P5 linking.
