## Goal

Make the corpus AES-256-GCM cell key survive a process boundary, and retire the content that the
per-process-ephemeral-key window orphaned.

The defect is one line of dependency configuration with a large blast radius. The workspace manifest
declares `keyring = "3"` under a comment asserting *"Default features auto-select per target"* — that
belief is false for keyring 3.x, so `Cargo.lock` resolves the crate with `[log, zeroize]` only, no
platform credential-store backend is linked, and the crate's non-persisting store hands out a **fresh
random key per process**. Measured at `2026-08-14-workspace-key-alignment`: the second app process emitted
13 `decryption_failed` warnings against rows its own predecessor wrote, and `cmdkey /list` lists zero
entries. The fix restores the posture security-plan.md §Secret Management → Storage → Runtime already
mandates (keychain-primary with `PassphraseFallback`-with-warning, chunk #73 P-049) and that
architecture.md §Occupied Resources → Corpus SQLite → At-rest posture records as INTENDED-but-UNIMPLEMENTED.

Research established that **neither** intended branch executes today: the primary is served by keyring's
mock store, and `BackendKind::PassphraseFallback` is a label with no producer — `OsKeychainBackend::
backend_kind()` returns only Macos/Windows/Linux by `cfg!`, and `Corpus::open` collapses every keychain
error to `Error::KeyringUnavailable`, failing the whole open. So this chunk must make the primary real
**and** give the fallback an execution path, per directive 2.

Research also found that fixing the key alone does **not** restore the read path. `cell_decrypt(...)?`
propagates inside the row loops (`contract.rs:650, :697, :741, :775`), so a single undecryptable row makes
the **entire** query return `Err` — which is why P-075 and P-076 sit behind this whole chunk, not just its
key fix. Two operator decisions were taken at P4 on that basis: orphaned content is **inventoried then
purged** (the keyless audit artifact is written before deletion, so the record of what the ephemeral-key
window destroyed survives even though the content cannot), and the read loops are **hardened to
skip-and-count** so any future undecryptable row degrades the corpus rather than taking it dark.
Recovery of pre-fix content is cryptographically closed and is not attempted — the mock store is
process-local, so every earlier key died with its process; the 13-failure measurement IS that fact.

Provenance: security-plan.md §Secret Management + §Dependency Security · architecture.md §Occupied
Resources → Corpus SQLite → At-rest posture · obs-plan.md §6 + §8 · test-plan.md §3 + §5.

### Step 2 — Make the `PassphraseFallback` branch reachable

**Compose the fallback at the backend layer, inside `crates/corpus/src/keychain.rs`** — not at the
`Corpus::open` seam. Leaned decisively per research (Open Question 2): `Corpus::open` today collapses
every keychain error to `KeyringUnavailable`, so composing there would change the seam's error semantics
for both processes; the backend layer is what the `KeychainBackend` trait exists for, keeps
`contract.rs` untouched, and holds the graph's finding that the only 2 production construction sites
(`OsKeychainBackend @ pulse-app/src/main.rs:327`, `@ crates/mcp-server/src/bin/andromeda-pulse-mcp.rs:65`)
need no signature change.

1. Add a backend that attempts the OS credential store first and falls back to a passphrase-derived key
   when no store is available, reporting `BackendKind::PassphraseFallback` when the fallback path served
   the key. Keep the existing `OsKeychainBackend` and `FakeKeychainBackend` intact.
2. The fallback must **succeed with a warning**, never hard-fail: both call sites treat corpus-open
   failure as non-fatal and degrade to "corpus absent" (`main.rs:336-343`, `andromeda-pulse-mcp.rs:85-90`),
   so a failing fallback silently reproduces today's outcome. Per security-plan.md §Secret Management →
   Storage → Runtime the fallback announces reduced key-custody guarantees.
3. Emit the fallback warning **once per boot** with bounded static fields, mirroring the
   `app.boot.buffer.degraded` shape (obs-plan.md §6) — a fallback boot must be distinguishable from a
   keychain-primary boot by log alone.
4. Preserve the identity that is already correct: service `"com.andromeda.pulse"`, account `"corpus-key"`
   — both processes already agree (research F4), so **no identity reconciliation is in scope**.
5. Key material never enters `Debug`, a log field, or a span — follow `EncryptionKey`'s hand-written
   `Debug` (`encryption.rs:42-48`) and apply `#[tracing::instrument(skip(...))]` at key-handling sites
   (security-plan.md §Secret Management → What counts as secret).

### Step 3 — Harden the read path: skip-and-count instead of fail-whole-query

Operator-selected at P4. Independent of the disposition — it addresses causes the disposition does not
(key rotation, partial write, disk corruption).

1. At each `cell_decrypt` call site inside a row loop (`contract.rs:650`, `:697`, `:741`, `:775`), skip an
   undecryptable row and continue rather than propagating.
2. Emit **one aggregate warn per query** carrying a skipped-row **count only** — never row identity,
   workspace, or payload (obs-plan.md §5 cardinality discipline; §11 hot-path spam ban). The count is what
   keeps the skip from being silent.
3. `load_incident_by_id` (`:741`) is single-row: an undecryptable row there resolves to "not found" rather
   than a query error — same degrade-don't-go-dark principle, no loop to skip within.

### Step 4 — Inventory, then purge the orphaned rows

Operator-selected at P4 (a refinement of directive 1's stated fork — it preserves the inventory the
directive wanted while leaving the DB clean, so no DDL and no `SCHEMA_VERSION` bump are needed).

1. **Detect** orphaned rows without a key: attempt `cell_decrypt` per row and treat failure as orphaned.
   Research F2: **5 of the 6 reserved tables carry `payload BLOB`** (`baseline_state`, `pipeline_metrics`,
   `incidents`, `incident_events`, `digest_archive`); **`service_registry` has no BLOB at all**
   (`schema.rs:44-53`) and is **not orphaned** — do not touch it.
2. **Write the inventory artifact first**, before any deletion. It is buildable with no key: `incidents`
   keeps `workspace`, `status`, `created/updated/resolved/read_unix_nano` in plaintext beside the opaque
   payload (`schema.rs:64-74`). Record per-table counts plus the surviving plaintext metadata.
3. **Then delete** the orphaned rows. Respect the `incident_events → incidents` foreign key
   (`schema.rs:83`) in the deletion order.
4. **Only delete on FULL success** — the 2026-05-20 universal rule (session-learnings): if the inventory
   write fails, preserve the rows and emit a degraded-success outcome; a failed disposition leaves the
   corpus fully intact so the next boot can retry.
5. **Trigger**: once at boot, mirroring `migrate_legacy_baseline_if_present`
   (`pulse-app/src/baseline_persistence.rs:176`, called at `main.rs:395`) — outcome-typed, idempotent
   (a corpus with no orphaned rows is a no-op), aggregate-logged once. Leaned per that precedent rather
   than an operator-invoked action; no new TauRPC procedure, so no capability/EXPECTED_PROCEDURES binding.
6. Any inventory file written at runtime lands **under the resolved data-dir root** — architecture.md
   §Occupied Resources → Filesystem locations authorizes exactly ONE out-of-data-dir exception (the
   training-export Downloads sink) and this chunk is not it. Use atomic `.tmp`+rename.

### Step 7 — Tests

1. **Cross-process persistence (the chunk's whole point)** — a test proving a key minted by one process is
   read back by a later, separate process. Co-located in `crates/corpus/src/` for crate-level units;
   any pulse-app-side probe goes in `pulse-app/tests/*.rs` (`[lib] test = false` makes a
   `pulse-app/src/` `mod tests` compile but never run).
2. **Fallback branch leg** — the fallback engages and emits its warning where no credential store exists.
   This is the leg that headless/CI actually exercises.
3. **Test hygiene (directive 2, non-negotiable)** — any test that mints a **real** credential-store entry
   uses a **test-scoped service name** and cleans up after itself. **Never pollute the operator's actual
   store.** A real OS credential store is process-global, so this is the harness-side expression of
   test-plan.md §7 per-test isolation.
4. **Disposition leg** — seed a corpus with rows encrypted under key A, reopen under key B, assert: the
   inventory artifact is written with correct per-table counts, the orphaned rows are gone afterwards,
   `service_registry` is untouched, and a failed inventory write preserves the rows.
5. **Read-path hardening leg** — a mixed corpus (decryptable + undecryptable rows) returns the good rows
   and a skipped count, instead of `Err`.
6. **Obs leg** — `for_target` resolves each new leaf plus `corpus.open.error`; negative-canary asserts no
   key bytes, passphrase, or ciphertext appear in any captured field.
7. Prefer `env`-gated legs over `#[ignore]` for anything needing a real credential store — `#[ignore]` is
   reserved for flake quarantine (test-plan.md §10), and the capability matrix's `env-gated-runtime` mode
   is the project's existing precedent.

## Constraints & rejected approaches

- **Recovering pre-fix content — REJECTED, cryptographically closed.** The mock store is process-local, so
  every earlier key died with its process; the 13-failure measurement IS that fact. Do not attempt
  recovery, do not add a key-guessing or brute-force path (directive 1).
- **Composing the fallback at the `Corpus::open` seam — REJECTED.** `open` collapses every keychain error
  to `KeyringUnavailable`; composing there changes the seam's error semantics for both processes. The
  backend layer is what the trait exists for and keeps `contract.rs`'s signature untouched (research Open
  Question 2).
- **Tombstoning orphaned rows in place — REJECTED at P4 (operator).** The 5 payload-bearing tables have no
  marker column, so it needs DDL + a `SCHEMA_VERSION` bump + a `WHERE` clause in every read loop.
  Inventory-then-purge achieves the directive's intent at a fraction of the surface.
- **Silent purge — REJECTED at P4 (operator).** Discards the plaintext incident metadata that is still
  readable without a key, leaving only a count as evidence of what the ephemeral-key window destroyed.
- **A bare `"corpus"` allowlist prefix key — DO NOT.** It would silently widen every future `corpus.*`
  target to one field set. Explicit per-target leaves only (obs-plan.md §8).
- **Widening a `cargo deny` ignore to clear the new tree — DO NOT.** ID-scoped reasoned entries naming an
  owner, or a source fix (directive 3; security-plan.md §Dependency Security).
- **A new workspace crate, or a second out-of-data-dir path — DO NOT.** Both are explicit arch bans.
- **Touching Conductor's tree — DO NOT.** Conductor is the instrument; its `architecture.md:174` still
  encodes a now-false belief but that rides the operator's Conductor-side directive, not this chunk.
