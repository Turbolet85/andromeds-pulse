Half 2 closes that structural gap, per the founder's Q1/Q2 rulings. When the L4 producer writes an incident or its
interpretation, the title becomes `{Cause label}: {model title}`, where the label is a closed, ASCII,
human-readable name for the incident's cue kind (`Retry storm` for `CueKind::RetryStorm`). The same grounded title
goes into the persisted L4 JSON at all three write paths: creation, dedupe refresh and resolution final write. The
report header, the Findings rows, the MCP list / `retrieve_report` and the digest's corpus-match lines all read one
of those two fields, so an incident born of a retry storm names the retry everywhere, whatever the model wrote.
Incident identity, the prompt, the report projection and every type and binding are unchanged (arch §Established
Decisions [Fault Identity]; arch §Occupied Resources; security-plan §Security Anti-Patterns → Logging).

  model output; Conductor's v3-09 is not moved by this chunk (Goal).
- Re-keying incident identity on the cue kind or fingerprint — banned (arch §Established Decisions [Fault Identity]).
- Rewriting existing corpus rows to add the prefix — rejected (Q2: existing rows stay unprefixed). No migration
  either way.
