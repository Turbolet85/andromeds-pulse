## Goal
Replace the saturated naming test with a pattern-discrimination series. The predecessor measured S1–S6 retry storms that
Pulse had already flagged, and every candidate read 36–40/40 (inputs#I1 §0). The new series asks two things of each of
the six small models:
- does it catch the non-standard patterns today's digest carries but no detector flags (family A)?
- does it stay quiet on healthy traffic (family B)?

Family C measures what a richer digest would add, in two renders. The output is a quality-vs-footprint table over the six
models, with a recommendation made by a rule fixed before any run. The founder decides from it (inputs#I1 §5). The shipped
model, argv and sampling do not change here: that is the next entry's job, per architecture §Established Decisions
[LLM Inference Runtime] → Model.

The work lives entirely in the dev-only `[[example]]` `pulse-app/examples/l4_decision_probe.rs` and a new module beside
it. It drives the product's own renderer, prompt builder, prompt bound, argv builder, timeout and parser unchanged
(research §Graph impact: the chunk is a pure consumer of `render_payload`, `build_primary_tier_prompt`,
`validate_prompt_bounded` and `build_llama_cli_args`).

Scoring is labels-only from the model's JSON. The synthetic digest texts and raw outputs are kept ONLY in the gitignored
`target/`, for a blind 10 % audit (inputs#I1 §3; inputs#I2). The committed evidence carries labels and aggregates, per
security-plan §Logging & Monitoring and obs-plan §8.

     Every string is synthetic ASCII. The workspace is the probe's `/synthetic/demo-shop`.
   - **Composition:**

       corpus lines, &[], false)`;
     - for `enriched`, a pure text transform: the SERVICES rows gain their baselines, and a `TREND` block follows. It is
       ASCII, anchor-checked exactly once, on the `truthful_overall` / `remove_lines` precedent at
       `l4_decision_probe.rs:362-380,620-636`;
     - then `build_primary_tier_prompt(payload, "workspace=/synthetic/demo-shop", "", citable)`, where `citable` is the
       shape's cue fingerprints (empty for cueless, as the product derives it from `digest.attention_cues`);
     - then `validate_prompt_bounded`. A rejection is an INCONCLUSIVE `prompt rejected: {label}`, never a truncation
       (security-plan §Input Validation, L4 argv row).
   - **The scorer**: pure functions over the run outcome, the extracted object and the ground truth. Closed label sets:
     - `valid` ∈ {`valid`, `parse_failed`, `thinking`, `timeout`, `exit_failure`, `output_too_large`,
       `stdout_utf8_invalid`}. `valid` requires `Spawned::Output`, `extract_json_object_bounded` Ok, `parse_bounded` Ok
       (which runs `validate`, `schema.rs:341`) and `thinking_label` ≠ `present`.
       - The time budget is the runner's own `LLAMA_CLI_TIMEOUT` of 60 s, which `generate` already enforces, so a
         slower row is `timeout` (operator P4 answer). No real clock is read in a scorer.
     - `detect` ∈ {`hit`, `miss`, `false_alarm`, `quiet`, `no_reading`}: `surface` on A/C is `hit`, otherwise `miss`;
       `surface` on B is `false_alarm`, otherwise `quiet`; not-valid is `no_reading`.
     - `cause` ∈ {`hit`, `service_only`, `word_only`, `none`, `not_scored`, `no_reading`}. It reads the FIRST
       hypothesis's `statement` only, case-insensitively: the ground-truth service set AND the shape's cause words.
       B is `not_scored`. Model-authored identity (`L4Output.fingerprint`) is never read (arch §Established Decisions
       [Fault Identity]).
   - **Whole-series grading over stored outputs.** Every label can be recomputed from the kept raw stdout through the
     same extract → parse → score path, with no spawn. The table and the audit both grade this way, so a keyword fix
     re-grades the whole series without regenerating.

     ceil(10 % × rows) across all six models' rows. It writes `audit-sample.md` (opaque row id, shape, ground truth,
     digest text, model output, the keyword labels; no model name) and `audit-key.json` (id → model). Both live under
     the series root in `target/`.
   - **The audit grade:** reads the overseer's `audit-verdicts.txt` (`{id} agree|disagree`, one per drawn row) and
     prints the disagreement and `agree` or `regrade` against the 10 % bar.
   - **The table and rule:** reads every model dir of a series root, grades the whole series, and prints one row per
     model plus `recommendation: {stem|none}`, applying Step 1's rule.
