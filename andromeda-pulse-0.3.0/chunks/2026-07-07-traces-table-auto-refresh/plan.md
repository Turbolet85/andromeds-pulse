## Goal

The Traces table queries `viz.query.traces` exactly once at mount and never re-polls (`use-traces.ts:48-82`, one `useEffect` keyed `[timeWindowSeconds, limit]`, `cursor: null`, `cancelled`-guard). On a fresh boot the query resolves before spans land (`row_count 0`), the table renders "No traces yet", and then freezes there while telemetry flows — the constellation on the *same* Traces route (`useServiceConstellation`, a 1s poll) shows live data, so the frozen table reads as broken for an observability app (operator-hit live at the P-079 wrap). This chunk adds a periodic re-poll to `use-traces.ts` — mirroring the `use-service-constellation.ts` precedent (mount-poll + `setInterval(1000)` + focus listener + cleanup) — so the table transitions out of the empty state once data lands and keeps its rows current, as a **silent background refresh** that preserves the P-068 anomaly-first ordering, the "Errors only" filter, and the active sort across every tick.

Because `TraceTable.tsx` already re-derives its view via `useMemo([rows, sortState, errorsOnly])` (`:34-37`) and `TracesRoute.tsx` renders `<TraceTable rows={rows} …>` with no `key` (`:67`), a `rows`-prop update re-renders in place — filter/sort state and keyboard focus are preserved **by construction** (no remount). The chunk actualizes the a11y-plan "P4 Live trace list" surface (the list becomes live), so it also adds the SC 4.1.3 obligation: a **one-shot polite announcement** on the empty→populated transition via the existing `useStatusAnnouncer` region — never per-tick, never assertive (per a11y-plan §1 P4 + §7; design/layouts §Motion "confirm state, not arrive" ⇒ instant swap, no entrance animation).

Reuse-only at the boundary: the re-poll re-invokes the existing `traces.query` under `pulse:default` — **no new TauRPC procedure, no capability JSON, no capability-drift, no Rust change** (arch §Webview IPC capability policy + security §API). The working-route **CARRY** (viz `next_cursor` keyed on start-time vs P-068's `ORDER BY end_time`) **re-defers**: `crates/viz/src/query.rs:17-18` already documents it as a latent caveat, and the re-poll keeps `cursor: null` (page 1), so pagination is never exercised — it stays a documented latent caveat handed to a future pagination-touching chunk.

## Implementation Steps

1. **Add the re-poll to `use-traces.ts`** (mirror `use-service-constellation.ts:29-54`). Introduce a `POLL_INTERVAL_MS = 1000` const. Inside the existing `useEffect`, factor the fetch into a `poll()` closure over the current `args` (keep `cursor: null` — do NOT touch pagination). On mount: call `poll()` once; then `window.setInterval(poll, 1000)`; add a `window` `"focus"` listener calling `poll()` (mirrors the constellation; catches focus-return). Cleanup returns: set `cancelled = true`, `clearInterval`, `removeEventListener("focus")` — no leaked timer. Effect dep array stays `[options.timeWindowSeconds, options.limit]` (an args change tears down + re-establishes the interval, correct).
2. **Silent background-refresh semantics** in the same `poll()`. Success (guard `!cancelled`): `setState({ rows: res.items, total: res.total, isLoading: false, error: null })`. Error (guard `!cancelled`): branch on whether the first load has completed — if `prev.isLoading` is still `true` (the INITIAL fetch failed, nothing to preserve) keep today's behavior (`{ rows: [], total: 0, isLoading: false, error }`); else (already loaded, a transient re-poll hiccup) **return `prev` unchanged** (keep last-good rows, mirroring the constellation `.catch(() => {})` — no mid-poll blank/flicker). Do NOT re-flip `isLoading` to `true` on re-polls (would flash "Loading…" is guarded by `rows.length === 0`, but re-flipping is semantically wrong for a background refresh).
