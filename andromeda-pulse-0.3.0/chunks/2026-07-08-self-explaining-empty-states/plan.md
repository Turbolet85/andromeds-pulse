## Goal
When the full-dashboard Metrics or Logs surface has **no telemetry to show**, it currently renders a silent
blank (MetricsChart draws nothing on empty `rows` — `MetricsChart.tsx:81`; Logs shows the misleading
filter-empty "No logs match filter"). This chunk makes those surfaces **explain themselves**: a plain-language
message plus an **actionable hint** naming the concrete next step — point an OTLP exporter at the spec-fixed
loopback receivers `:4318` (OTLP/HTTP) / `:4317` (OTLP/gRPC) — with an Observatory glyph, per intent F11.

The delivery is a small **shared, reusable `EmptyState` component** (design + layouts "reads as one system";
resolves scope OQ1). Research found a local `EmptyState` already living in `SnapshotsRoute.tsx` using the
`--color-text-tertiary` token the a11y + design extracts flag as failing **SC 1.4.3** at 14px (LogTable
already fixed this to `--color-text-secondary` at chunk #99, `LogTable.tsx:127`). Per the P4 user decision
(**promote & adopt**), that local component is **promoted** to `components/EmptyState.tsx` on the
`--color-text-secondary` token and adopted by Metrics, Logs, AND Snapshots — de-duplicating (avoiding the
two-copies anti-pattern, frontend.md 2026-07-02) and fixing Snapshots' latent contrast bug in passing.

The surface is **frontend-only**: a pure render branch over the existing `useMetrics`/`useLogs` return shape —
no new TauRPC procedure, `pulse://` topic, capability JSON, or env var (arch §Occupied Resources / §Webview
IPC capability policy; obs adds no self-observation sink). Per the P4 user decision (**minimal honest error
line**), the three-state discipline (frontend.md "handle loading / error / empty explicitly") is honored as
four honest states: the self-explaining empty state is gated to the genuine no-data case (`error === null`),
and a real query failure shows a **distinct static error message** (no exporter hint, no raw `AppError`
echoed — security §Logging), so a failure never masquerades as "point an exporter."

## Implementation notes
- **Branch order matters:** check `error` BEFORE the empty branch (`useMetrics`/`useLogs` set `rows:[]` on
  rejection, so `rows.length===0` is true on error too — the `error` guard is what keeps the exporter hint
  honest, `use-metrics.ts:68-76`).
- **No flash on load:** the empty branch requires `!isLoading`; during the initial fetch the else-branch renders
  (MetricsChart blank canvas / LogTable "Loading…") — the empty state appears only after a settled zero-result
  load (design §Motion "confirm state, not arrive").
- **Two consumers of the shape:** the shared `EmptyState` now has three call sites (Metrics/Logs/Snapshots);
  keep `data-testid` per-surface (`metrics-empty-state` / `logs-empty-state` / default `route-empty-state`) so
  the route tests disambiguate (frontend.md 2026-07-02 two-copies discipline).
- **Zero .rs delta:** this is a webview-only chunk — expect `capability-drift` unchanged and the bindings.ts
  regen discipline to be a no-op (no TauRPC surface change). The warm re-embed boot smoke (npm build →
  `cargo build -p pulse-app`) is still run at /implement P3 per the operator directive.
