boot smoke's app ended `exit 1` 0.27 s after `boot: ready` with no panic and no explanatory record (`ci#36893004900`,
job 110472991644, sha `69f0b93`). Research found why such a death is silent BY CONSTRUCTION

exists. This chunk adds one bounded `app.exit` record per process end on every class that CAN log, with the file sink
drained before the process goes, and records the classes that cannot log (pre-sink panics, SIGKILL, Windows
TerminateProcess) as such. It does NOT explain the 69f0b93 death; it makes the next one name its class. Per obs-plan §3

## Implementation Steps

### PREREQ — exit-cause logging
1. **The exit record surface** (`pulse-app/src/observability.rs`). Add one emit path for target `app.exit` with exactly
   four bounded fields: `exit_class` — a closed enum rendered as a snake_case label, `event_loop` · `outside_event_loop` ·
   `signal`; `exit_code` — `i32`, the code when known, `0` when not; `exit_code_known` — `bool`; `signal` — a closed enum
   label, `none` · `sigterm` · `sigint`. Level: INFO for `event_loop` with code 0; WARN for `signal`; ERROR for
   `event_loop` with a non-zero code and for every `outside_event_loop` record. No path, no payload, no free text
   (security-plan §Security Anti-Patterns → Logging; obs-plan §8 Default-deny). A process-wide once-flag guarantees
   EXACTLY ONE `app.exit` record per process: the first emitter wins, every later path is a no-op.
2. **The exact allowlist leaf** (`pulse-app/src/observability.rs`, `AllowList::production`). Register `app.exit` with
   exactly the four fields Step 1 emits (read from the emit site, never from this plan — observability.md:144). There is
   no bare `app` key, so a leaf-less `app.*` target would redact every field (observability.md:65).
3. **The drainable guard** (`pulse-app/src/observability.rs`). `init` keeps its signature (`-> WorkerGuard`), so its
   two test callers stay untouched (`e2e_p003_panic_hook_propagation.rs:51`, `perf_budget_samples.rs:115`). Add a
   separate holder: `main` hands the guard to a process-wide slot, and a `flush` operation takes it out and drops it
   (`WorkerGuard::drop` is the only drain — research.md §Mechanism 2), idempotently; the emit path of Step 1 flushes
   after it emits.
4. **Event-loop exit** (`pulse-app/src/main.rs:1567-1568`). Replace `.run(tauri::generate_context!()).expect(...)` with a
   build followed by `App::run_return`, so the intended exit code returns to Rust; then emit `exit_class: event_loop`
   with that code, flush, and end with `std::process::exit` of the SAME code. The observable exit code of every
   event-loop exit is unchanged.
5. **At-exit hook** (`pulse-app/src/observability.rs`, registered from `main` after `init`). Register a C `atexit`
   handler through a direct `libc` dependency (`pulse-app/Cargo.toml`, the lockfile's existing `0.2.186`; Edition 2024
   `unsafe extern` / `unsafe` block discipline). On run it emits `exit_class: outside_event_loop`,
   `exit_code_known: false`, then flushes — the once-flag makes it a no-op after Step 4 or Step 6 already recorded.
   This is the class a native GTK/GDK/WebKitGTK `exit()` falls into (research.md §Mechanism 1, 3).
6. **Unix signals** (`pulse-app/src/observability.rs`, installed from `main` after `init`; `cfg(unix)`). On SIGTERM or
   SIGINT: emit `exit_class: signal` with the matching `signal` label, flush, then restore the default disposition and
   re-raise the same signal, so the process still ends BY that signal and the harness wrapper still records
   `signal N (NAME)` (`scripts/agent-run.sh:84-88`; overseer, 2026-10-01). The handler must not deadlock against the
   subscriber: run the emit off the async-signal context (a dedicated listener, e.g. tokio's signal stream on the
   runtime `main` already enters — `tokio` is `features = ["full"]`, `Cargo.toml:31`). Windows: no handler; a
   `Stop-Process -Force` (TerminateProcess) stays unloggable by construction, recorded in Implementation notes.
7. **The leaf guard** — NEW `pulse-app/tests/unit_observability_allowlist_app_exit.rs`: exact resolve of `app.exit`;
   field-set equality both ways with the Step 1 emit site; the banned set absent (any `*_path`, `message` payload
   fields, `panic_message`); the no-bare-`app` discriminator (`is_none()`, obs-history
   2026-08-30-diagnostics-un-muting-harness-truth-sweep). Every fn name carries `app_exit`. Mutation-check: delete the
   leaf → the exact-resolve pin reddens; narrow it by one field → the equality pin reddens (testing.md:268).

   to END, then reads `<dir>/logs/agent-latest.jsonl*` (the family, never the bare name). Arms, each its own child and
