## Implementation Steps

1. **Rework the `credit_card` arm in `crates/security/src/scrubber.rs`** (`patterns()` `:116-122` and `scrub_attribute` `:41-48`).
   The arm becomes a two-stage check.
   - **Candidate.** A candidate is a `\b`-bounded run of ASCII digit groups joined by single ` ` or `-`: the
     shape the current regex already finds, widened to the maximal run so windowing sees every group. Use
     ASCII digits (`[0-9]`, or `(?-u:\d)`). The current `\d` is Unicode-aware, and a non-ASCII digit has no
     Luhn value.

     groups whose digit count totals 13–19.

     window once it passes 19 digits.

## Constraints & rejected approaches
- Exempting the workspace key, a path or `project_context` from scrubbing — REJECTED: it removes an
  enumerated boundary from coverage (security-plan §Security Anti-Patterns → Logging "INTENDED posture"); the
  fix is precision in the one arm.
- Luhn over EVERY digit offset — REJECTED: a 19-digit run has 28 such windows, so at ~10 % per window a
  timestamp would pass Luhn about 95 % of the time. Windows are WHOLE separator groups only (probe:
  `scratchpad/probe_windows.py`, 25 cases, 0 mismatches).
- Luhn over the greedy regex span only — REJECTED: it misses a card beside another digit group, e.g.
  `ref 12 4111111111111111` → an 18-digit span (research E4).
- A separator-grouping grammar (with or without Luhn) — REJECTED by the founder at P4: it misses odd real
  groupings, and without Luhn it leaves contiguous non-card runs redacting.
- Entropy scoring — REJECTED: the catalog's standing ban (security-plan §Security Anti-Patterns → Logging).
- A third-party Luhn or card crate — REJECTED: the check is a few lines; a crate would be a Stack delta
  (architecture §Inherited Defaults → Validation) for no gain.
- Any per-category counter or debug emit to "show" the fix — REJECTED (obs-plan §5, §11 Metrics).
- Editing `assemble_report`, `build_project_context`, `Digest::scrubbed_clone` or `pii_scrub_closure` —
