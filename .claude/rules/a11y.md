# Accessibility Rules

Path-scoped rules for the desktop-webview surface (React 19 + Tailwind CSS v4 + react-aria-components + WebGPU canvas). Loaded only when Claude is working with files matching the `paths:` frontmatter above.

**Authoritative source:** `.andromeda/a11y-plan.md` §3 (Harness Contract) + §3.5 (Bootstrap phases) + §11 (Anti-Patterns). Tier=Standard (WCAG 2.1 AA full ~50 SCs) + AAA escalation **SC 2.3.3 Animation from Interactions** (motion-sensitive trigger).

## Semantic HTML first, ARIA second
- Prefer native HTML (`<button>`, `<nav>`, `<main>`, `<dialog>`, `<label>`, `<input>`, `<table>`) over `<div>` + ARIA roles.
- ARIA labels supplement semantic HTML; they do not replace it.
- NEVER `role="button"` on `<button>` (redundant), `role="presentation"` on a landmark (conflict), or `aria-hidden="true"` on a focusable element.
- Required landmark roles per surface — `<main>` + `<navigation>` minimum on full dashboard layouts; tray menu is OS-native (no ARIA).

## Keyboard navigation (SC 2.1.1, SC 2.1.2)
- Every interactive element MUST be reachable via Tab / Shift+Tab.
- Focus order follows visual reading order (top-to-bottom, left-to-right).
- `tabindex > 0` is forbidden — use natural DOM order per `tabbable` 6.4.x ground-truth.
- Modals (settings, investigation) trap focus via `focus-trap-react` 12.x with `escapeDeactivates: true`; Esc closes; focus restores to the triggering element.
- Compact widget: Esc minimizes to tray; focus returns to tray icon on restoration.
- Separate Tauri windows (findings / report disclosure): focus restores CROSS-WINDOW via first-party Tauri events (`findings:dismissed` / `report:closed`), NOT `focus-trap-react` `returnFocusOnDeactivate` (which cannot cross windows) — findings-dismiss → the widget FindingsCounter badge; report-close → the findings window. A cross-document disclosure trigger uses `aria-haspopup="dialog"` WITHOUT `aria-controls` (a dangling cross-document id-ref fails axe `aria-valid-attr-value`).
- Tray menu: arrow keys navigate items; Return/Space selects; Esc closes (OS-native, manual SR pass required).

## Focus visibility (SC 2.4.7 + SC 1.4.11)
- Every `:focus-visible` element shows the `--border-focus` token outline (3–4 px outset, color `#4A90E2` Earth Blue).
- `outline: none` is forbidden unless paired with an alternative `:focus-visible` style.
- Focus ring contrast ≥3:1 against adjacent surface colors (non-text contrast).

## Color and contrast (SC 1.4.3, SC 1.4.11)
- Text on Base (`#1A1D24`): Primary `#E8EEF7` ≈8.5:1 ✓, Secondary `#B4BCCB` ≈6.8:1 ✓, Tertiary `#7D8697` ≈4.2:1 (large text only), Muted `#56606E` ≈2.1:1 (decorative only).
- UI component boundaries / focus rings / icons: ≥3:1 against background.
- State colors (Success Feedback Cyan `#17B3A3`, Error Alert Burgundy `#C7556A`, Info Earth Blue `#4A90E2`) MUST be paired with text labels and/or iconography — never communicate state with color alone (SC 1.4.1).
- Verify per-token-pair via `axe-core` color-contrast rule + `colorjs.io` 0.6.x custom assertion reading design tokens via `window.getComputedStyle().getPropertyValue('--color-token-name')`.

## Motion and reduced-motion (SC 2.3.3 AAA + SC 2.3.1 A)
- Every transition (chrome AND the data-driven severity signature) MUST respect `prefers-reduced-motion: reduce`.
- The severity signature degrades to a static glow (no pulsing rhythm); hue still updates per cumulative incident severity. **The rule attaches to whichever surface actually renders** — measured 2026-08-21, the Halo State Pulse WebGPU canvas has NO production render site on desktop-webview, so today that surface is the constellation DOT hue (`severityToHueFraction`); the glow layer is DEFERRED to the next version (operator ruling 2026-08-29; design-system §Brand Identity owns the status), and when it lands the rule attaches to it too.
- All `--duration-*` tokens (`--duration-fast` 150ms, `--duration-standard` 200ms, Investigation Capture Collapse 350ms) degrade to 0ms under reduced motion.
- Motion duration ≤5s OR provides pause/stop control (SC 2.2.2).
- NEVER flash content >3 times per second (SC 2.3.1 — risks seizures).
- Use `useReducedMotion` hook from `motion/react` 12.x in React; apply Tailwind v4 `motion-reduce:` variants to CSS transitions.
- Verify via Playwright `page.emulateMedia({ reducedMotion: 'reduce' })` + Lighthouse 13.x prefers-reduced-motion audit.

## Target size (SC 2.5.8 AA, SC 2.5.5 AAA conditional)
- Pointer targets minimum 24×24 CSS px (SC 2.5.8 AA baseline) — apply `--target-input-min` token.
- Touch targets 44×44 (SC 2.5.5 AAA) only if a future scope adds touch mode.
- Verify via `axe-core` target-size rule with `runOnly: { type: 'tag', values: ['wcag22aa'] }`.

## Forms and validation (SC 3.3.1, SC 3.3.2)
- Every form input has an associated `<label htmlFor="…">` (visible, not just placeholder).
- Error messages programmatically associated via `aria-describedby`; required fields marked with `aria-required="true"` AND visible indicator.
- Error messages identify the specific field AND describe how to fix it.

## Status messages (SC 4.1.3)
- Live region for dynamic content: `aria-live="polite"` (non-urgent toasts) or `aria-live="assertive"` (urgent / error focus shifts).
- `role="status"` for confirmations; `role="alert"` for errors.
- Avoid stacking simultaneous alerts — debounce or queue.
- Snapshot generation: Generate button gets `aria-busy="true"` during generation; completion announced via `aria-live="assertive"` in modal.

## WebGPU canvas a11y
- The `<canvas>` has no built-in ARIA — semantics are enforced via a wrapper: `<section aria-label="Telemetry traces chart">…</section>` (a named `<section>` takes the implicit `role="region"`; never write the role explicitly — `no-redundant-roles`). **SHIPPED** at `ConstellationCanvas.tsx:229` since 2026-08-23-a11y-verification. The name is a STABLE literal, never the live state summary: a landmark whose accessible name tracks its data churns the screen-reader rotor. The summary is the region's DESCRIPTION instead — a visually-hidden `<p data-testid="constellation-summary">` wired via `aria-describedby`, aggregate-only (lifecycle counts + findings tally; no service name enters the accessible tree). `role="status"` on it is deliberately omitted (a ~1s poll plus the dashboard's existing live region would stack announcements).
- WebGPU fallback message ("WebGPU not supported in this context") rendered as `font-body` text in `color-text-tertiary` when `navigator.gpu` is undefined — must be screen-reader accessible.

## Anti-patterns (a11y-plan §11)
- NEVER use ARIA on non-semantic HTML (`role="button"` on `<div>` instead of `<button>`).
- NEVER overuse `aria-label` (visible `<label>` first).
- NEVER set `tabindex > 0` (creates non-natural focus order).
- NEVER hide important content from assistive tech (`aria-hidden="true"` on essential content).
- NEVER mix React Aria + Headless UI in the same app.
- NEVER claim WCAG conformance without machine-verifiable evidence.

- 2026-05-09: `<section aria-label="...">` automatically takes implicit `role="region"` per HTML AAM (Accessible Name and Description Computation); writing explicit `role="region"` on the same `<section>` is REDUNDANT and triggers `eslint-plugin-jsx-a11y` 6.10's `no-redundant-roles` rule with: "The element section has an implicit role of region. Defining this explicitly is redundant and should be avoided." The pattern was used pre-chunk-#31 across `pulse-app/ui/src/canvas/CanvasContainer.tsx` (chunk #28) + `pulse-app/ui/src/App.test.tsx` mocks (chunks #28-#30) but went undetected because chunks #28-#30 did NOT include `npm --prefix pulse-app/ui run lint` in their gate list. Chunk #31 added the lint gate and surfaced 4 instances (1 fixed inline in HaloCanvas.tsx + 2 fixed in App.test.tsx mocks + 1 fixed in CanvasContainer.tsx as in-scope-by-extension). Resolution: drop `role="region"` from `<section aria-label="...">`; testing-library `screen.getByRole("region", { name: "..." })` still finds the section via the implicit role. The implicit role is preserved iff `aria-label` (or `aria-labelledby`) is present — a bare `<section>` without accessible name does NOT take role="region" (it's a generic sectioning element). For the canonical canvas wrapper pattern: `<section aria-label="Telemetry traces chart"><canvas /></section>` (NOT `<section role="region" aria-label="Telemetry traces chart">`).

- 2026-05-09: For dialog-with-combobox patterns (Cmd+K command palette / autocomplete dropdown / modal search), put the `onKeyDown` handler on the `<input role="combobox">` itself, NOT on the wrapping `<div role="dialog">`. Two reasons: (a) `eslint-plugin-jsx-a11y` flags `role="dialog"` as non-interactive (`no-noninteractive-element-interactions` rule) — putting keydown on the dialog wrapper triggers a lint error on every fresh chunk; (b) the canonical WAI-ARIA APG combobox pattern keeps focus on the input throughout — Down/Up navigates the listbox via `aria-activedescendant`, not actual focus movement, so the input is the natural keydown source. Tab nav with `role="tablist"` is a sibling case: the tablist coordinates child tab focus but isn't focused itself; satisfy `interactive-supports-focus` by adding `tabIndex={-1}` to the tablist div (does NOT break roving — active tab still gets `tabindex="0"`, others `tabindex="-1"`). Both fixes verified at chunk #33 with `pulse-app/ui/src/dashboard/CommandPalette.tsx` + `pulse-app/ui/src/dashboard/TabNav.tsx` after a fresh-chunk lint gate caught the violations. Tests dispatching synthetic keydown events should target the same element (e.g., `screen.getByRole("combobox").dispatchEvent(new KeyboardEvent("keydown", { key: "ArrowDown", bubbles: true }))`) — events on outer wrappers won't bubble down to the handler.

- 2026-05-10: For backdrop click-outside dismissal on modal/dialog/popover overlays, do NOT put `onClick={handler}` on the non-interactive overlay `<div>` — `eslint-plugin-jsx-a11y` flags it via TWO rules in tandem: `click-events-have-key-events` ("Visible, non-interactive elements with click handlers must have at least one keyboard listener") + `no-static-element-interactions` ("Avoid non-native interactive elements ..."). Adding `role="presentation"` is contradictory (presentation removes implicit role; click handler reintroduces interactivity). The canonical resolution is to move click-outside detection to a `useEffect`-registered document-level `mousedown` listener that checks whether the click target is contained in a ref to the dialog content element: `useEffect(() => { if (!open || !clickOutsideEnabled) return undefined; const handler = (e: globalThis.MouseEvent) => { if (dialogRef.current && !dialogRef.current.contains(e.target as Node)) onClose(); }; document.addEventListener('mousedown', handler); return () => document.removeEventListener('mousedown', handler); }, [open, clickOutsideEnabled, onClose]);`. Esc dismissal stays wired through `focus-trap-react`'s `escapeDeactivates: true` + `onDeactivate` (which can call both `triggerRef.current?.focus()` AND `onClose()`). Pattern verified at chunk #37 (Modal primitive) — initial implementation used `onClick` on the overlay backdrop with an `event.target === event.currentTarget` check, lint flagged 2 errors at line 82, refactor to useEffect document mousedown resolved both rules cleanly. Trade-off vs the `onClick` approach: useEffect requires a ref on the dialog content + careful dependency array including `open` so the listener only attaches when the modal is actually open (prevents the trigger-click that opens the modal from firing the dismiss handler immediately). Production behavior unchanged. Note: `focus-trap-react`'s own `clickOutsideDeactivates: true` option is NOT a substitute when FocusTrap wraps the entire overlay subtree (clicks INSIDE the trap container — including on the backdrop — are NOT considered "outside"); separate document listener is required.

- 2026-07-07: MAKING A FETCH-ONCE LIST LIVE INCURS THE SC 4.1.3 ANNOUNCE OBLIGATION — when a chunk turns a static (fetch-once) webview data list into a live-refreshing one (adds a re-poll per frontend.md 2026-07-06/07), it ACTUALIZES the a11y-plan §1 P4 "Live trace list" surface, so SC 4.1.3 now applies: announce the empty→populated transition ONCE, POLITELY, via the EXISTING `StatusLiveRegion`/`useStatusAnnouncer` (never a new live element, never `assertive`, never per-tick). Recipe: a `useRef(prevRowCount)` + a `useEffect` on `rows.length` firing `announce(...)` ONLY on the `0 → >0` edge, then updating the ref (guards per-tick re-announce AND a mounted-already-populated false-announce). Focus is preserved BY CONSTRUCTION (SC 2.1.1 / 2.4.3) iff the re-poll updates the rows PROP and the list is NOT remounted — no `key` on the component, no subtree unmount — so the derived (`useMemo`) view re-runs in place, keeping component-local filter/sort (`aria-pressed` / `aria-sort`) and `document.activeElement`. So the frontend "add a re-poll" action carries a PAIRED a11y obligation: the polite once-announce + do-not-remount. Verified at 2026-07-07-traces-table-auto-refresh (`TraceTable.tsx` one-shot announce): the `p4-live-trace-list` axe spec stayed green (0 new baseline tuple); vitest asserts announce-once + focus-preserved + filter/sort-survive across a rows update.

- 2026-08-26: ESLINT'S `--rule` CLI FLAG CANNOT CARRY A PLUGIN-SCOPED RULE UNDER FLAT CONFIG — and fixing the shell quoting first HIDES this, because it converts one failure into another. `eslint . --rule jsx-a11y/alt-text:error` builds a TOP-LEVEL config object, while the plugin is declared only inside the `files: ["**/*.{ts,tsx,jsx}"]` block, so the run dies with `A configuration object specifies rule "jsx-a11y/alt-text", but could not find plugin "jsx-a11y"` (exit 2) even once the args are quote-safe. The lint:a11y script had BOTH defects: single-quoted `--rule 'x: error'` args that Windows npm/cmd passed through literally (failing with `No files matching the pattern "error'"`), and behind it this structural one. The fix is to pin the rules in `eslint.config.mjs` inside the same scoped block that declares the plugin, leaving the script a plain `eslint .`. Two things to check before assuming such a script restores lost coverage: the rules may ALREADY be at `error` in the spread `recommended` set (all five were here, so plain `npm run lint` had been enforcing them the whole time the a11y script was broken — no coverage was ever lost, the script just could not run), and a repaired lint gate must be PROVEN to execute rather than merely exit 0 — feed it a deliberate violation (an `<img>` with no `alt`) and require the failure, per the chunk-#99 green-harness-that-never-ran precedent.
