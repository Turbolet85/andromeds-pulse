# Observability Rules

Path-scoped rules for telemetry instrumentation across Rust crates + webview frontend bridges.

**Authoritative source:** `.andromeda/obs-plan.md` §3 (Observability Harness Contract) + §10 (SLO Invariants) + §11 (Anti-Patterns). Tier=Standard. **Architectural choice:** `tracing` ecosystem only — NO OTel SDK linked into the self-observation runtime (recursion-free by construction: the JSON file at `~/.andromeda-pulse/logs/agent-latest.jsonl` IS the agent surface).

## Self-observation runtime (binding)
- **Crates:** `tracing` 0.1 + `tracing-subscriber` 0.3 (JSON formatter + `EnvFilter`) + `tracing-appender` 0.2 (daily-rolling file sink, non-blocking writer) + `tracing-error` 0.2 (SpanTrace).
- **NO OTel SDK** in self-runtime. The product's external OTLP receivers (`tonic` + `axum` + `prost` + `opentelemetry-proto`) parse wire format only — they do not require an OTel SDK runtime.
- **NEVER** add `opentelemetry`, `opentelemetry_sdk`, or `opentelemetry-otlp` as a self-observation exporter. The recursion concern is resolved by construction.
- **Canonical self-observation surface:** `tracing-subscriber::fmt::Layer::json()` writing to `~/.andromeda-pulse/logs/agent-latest.jsonl`. Any legacy reference to `opentelemetry-stdout` in upstream specialist plans (e.g., `security-plan.md` §Data Protection / §Bootstrap phases `logging-redaction-wire` bullet / §Logging & Monitoring "Log format" paragraph) is obsolete-but-equivalent — both produce JSON-per-line at the same path; functionally identical; no security-posture change. Body sites in security-plan.md are annotated with `> **DEPRECATED (2026-05-08)**` blockquotes (preserved verbatim for audit trail; new readers see deprecation notice first). Per amendments `2026-05-08T17-28-25Z-reconcile-otel-stdout-references` (`.andromeda/runs/2026-05-08T17-28-25-spec-amendment-reconcile-otel-stdout-references/amendment.md`; Decisions Log only) + `2026-05-08T21-00-00-obs-pivot-security-bodies` (`.andromeda/runs/2026-05-08T21-00-00-spec-amendment-obs-pivot-security-bodies/amendment.md`; body annotations at security-plan.md lines 154/239/330).
- **Init order at boot, before HTTP/gRPC bind:** load env (`ANDROMEDA_PULSE_LOG_LEVEL` / `RUST_LOG` fallback) → build `tracing_subscriber::registry()` composing the non-blocking file appender + `EnvFilter` + `ErrorLayer` (no stderr layer) → install `std::panic::set_hook` calling `tracing::error!(target: "app.panic.fatal", ...)` → park the returned `WorkerGuard` (`hold_log_guard`) + install the at-exit hook (`install_exit_hook`) + on Unix the SIGTERM/SIGINT listener → spawn Tauri through `run_return`, its code to `exit_after_event_loop` (record `app.exit` → drop the guard → `process::exit` with the same code). `WorkerGuard::drop` is the file sink's only drain — a plain `run` ends in tao's `process::exit` with the worker undrained (a record emitted just before it reached the file 0/20, measured on Windows).

## Service identity (default subscriber fields)
- `service.name` = compile-time `"com.andromeda.pulse"` (Tauri bundle id); for the MCP sidecar = `"andromeda-pulse-mcp"`.
- `service.version` = `env!("CARGO_PKG_VERSION")`.
- `deployment.environment` = `"production"` (hardcoded).
- Register once at subscriber init via `Layer::with_default_fields([service_name, service_version, deployment_environment])` — every JSON line carries identity without per-call boilerplate.

## Log format (binding contract from tests §3)
JSON-per-line via `tracing_subscriber::fmt::Layer::json()`:
```json
{"timestamp":"…","level":"INFO","target":"ingest::grpc","message":"…","fields":{"span_count":N,"service":"…"}}
```
Optional fields: `trace_id` / `span_id` (W3C traceparent strings), `duration_ms`, `plugin_path_basename`, `query_id`, `param_count`, `token_count_actual`, `token_budget_limit`, `body_size_bytes`, `webview_backend`, `tray_api`, `wgpu_backend`, `dedup_count`, `anomaly_markers`, `p50_ms`/`p95_ms`/`p99_ms`/`max_ms`, `error_rate_percent`, `value`.

## Log sink
- **Path:** `~/.andromeda-pulse/logs/agent-latest.jsonl` (per-platform per arch §Occupied Resources Filesystem locations).
- **Rotation:** daily via `tracing_appender::rolling::daily(log_dir, "agent-latest.jsonl")`.
- **Single sink (app):** the file `agent-latest.jsonl` (always JSON) — no stderr `tracing` layer and no TTY pretty-print (measured at chunk 2026-10-02-incident-events-readable-through-mcp); the `app.panic.fatal` record is file-only, stderr carries only the chained prior panic hook's own output.
- **MCP sidecar (`andromeda-pulse-mcp`; hand-rolled JSON-RPC 2.0):** stderr forced JSON (no TTY check) — stdout reserved for JSON-RPC 2.0 framing. ANY accidental `println!` / `dbg!` / library stdout write corrupts MCP protocol and silently disconnects the client.

## Span discipline
- Span naming: `{module}.{operation}` (e.g., `ingest.grpc.export.request`, `duckdb.append`, `snapshot.generate.request`, `plugin.invoke.request`). Avoid high-cardinality names (no per-trace-ID names).
- `#[tracing::instrument(skip(req), fields(rpc.system = "grpc", rpc.service, rpc.method, span_count, traceparent))]` on tonic gRPC handlers.
- `#[tracing::instrument(skip_all, fields(traceparent = %tp))]` on TauRPC routers.
- `#[tracing::instrument(skip(input, output))]` on `wasmtime::component::Instance::call` host wrappers.
- NEVER hold a `tracing::Span` guard across `.await` without `.in_current_span()` — span context bleeds into unrelated tokio tasks, breaking trace_id correlation and bloating memory.
- Manual `tower::Layer` (or `tower-http::TraceLayer` for plain `tracing` spans, NOT OTel-flavored) on the axum router.

## Trace context propagation
- W3C `traceparent` header (HTTP) and gRPC `grpc-trace-bin` metadata extracted at receiver entry; attached as a regular `tracing` field (`fields(traceparent = %tp)`); downstream `tracing::Span::current()` inherits.
- IPC envelope (TauRPC command struct) carries optional `traceparent` field; receiver attaches to local span.
- Real-time push streams (`pulse://stream/spans` etc.) carry trace context in Arrow metadata column `_trace_context` for end-to-end correlation.
- `tokio::spawn` calls use `.in_current_span()` to propagate.

## Heartbeat ticks (stall detection)
- Long-running subsystems emit `tracing::info!(target: "{module}.tick", ...)` every 15s via `tokio::time::interval(Duration::from_secs(15))`: `ingest.tick`, `buffer.tick`, `viz.tick`, `plugins.tick`. Exception: realtime throughput counter ticks at 100ms (animation source).
- Required tick fields per module: `span_count` / `buffer_capacity_pct` / `broadcast_subscribers` / `rows_ingested` / `retention_window_active` / `eviction_count` / `loaded_count` / `active_invocations`; `buffer.tick` additionally carries the fingerprint-feed counters `span_events_seen` / `fingerprints_computed` / `observer_invocations`, the PII-redaction counter `redactions_applied` (aggregate counts, folded once per batch — never per span-event / per scrubbed field), AND — since 2026-08-26 — the drain-progress pair `rows_ingested_delta` / `last_append_age_seconds`, AND — since 2026-08-30 — `append_rejections` (folded once per FAILED batch at `run_consumer`'s two error arms via `BufferState::record_append_rejection`; aggregate count only, the per-failure `duckdb.append` ERROR record unchanged), bringing the tick to 15 fields. The pair is aggregate numerics only (a per-tick row delta and a whole-second age from `BufferStateSnapshot.last_append_at_nanos`, which refreshes on EVERY append and is deliberately distinct from the latch-once `first_append_at_nanos` — a latching age would climb on a healthy buffer); one clock read per batch, never per row. `redactions_applied` is folded by `BufferState::record_redactions`, deliberately separate from `record_feed_counts` because the redaction and fingerprint-feed paths do not coincide; since 2026-08-23 it spans FIVE scrub sites across the four appender record-batch builders (the `spans.service_name` / `span_events.name` / `metrics_points.metric_name` / `log_records.severity_text` write boundaries, plus `metrics_points.labels` since `2026-08-23-metrics-points-labels`) rather than only the `scrub_otlp_field` log/exception paths — the BUILDER count is still four, only the scrub-site count moved — counting one increment per REDACTED LABEL PAIR rather than per persisted cell (a single data point can carry several redacted pairs in one `labels` cell) and, at the column sites, one increment per redacted VALUE however many secrets it masked (span-level masking since chunk `2026-09-30-span-level-redaction`, founder-ratified «Ок давай по типу правила»; as measured at that chunk's e2e: 4 values carrying 10 masked spans → 4), and carries no matched value, category, attribute key, or `service_name` label. It counts redactions to PERSISTED cells ONLY, and since chunk `2026-08-23-metrics-points-identity` that is STRUCTURAL rather than aspirational: each builder RETURNS its per-batch tally (`Result<Option<(RecordBatch, u64)>, Error>`) and `record_redactions` is folded at each table's OWN post-append site in `consumer::dispatch_batch`, so a batch the appender rejects at `flush()` adds nothing (before that chunk the fold fired inside the builders and a rejected batch was measured counting 2 redactions against 0 stored rows). Per-table granularity is load-bearing — a `span_events` failure must not discard the count for rows `spans` already stored — and `build_spans_record_batch` consequently takes no `&BufferState`. The non-storing `extract_service_name` callers still pass `None`, so a canary in all five scrubbed cells reads 5 not 6 (one redacted pair in the `labels` cell).
- Stall detection has TWO signals and tick presence is only the first. (a) LIVENESS — missing tick for >45s = stall signal; CI fails build if any tick gap >45s during the test run. (b) PROGRESS — a consumer can keep ticking while draining nothing: measured 2026-08-26, `rows_ingested` froze for 16 minutes while all four ticks emitted normally with 0 ERROR, and every liveness check read healthy. `buffer.tick` therefore also carries `rows_ingested_delta` + `last_append_age_seconds`; a delta of 0 across consecutive ticks WHILE the ingest channel still holds queued work is a stalled consumer, announced once per transition on `buffer.consumer.stalled` (after 30 such ticks = 450s, sited above obs-plan §10's 420s sustained-drain cap) and asserted by `cargo xtask check:ingest-progress`. `rows_ingested` alone can never separate a stalled consumer from an idle producer — both leave it static; the channel's occupancy is the discriminator.
- **Heartbeat ticks vs TauRPC `health` command:** these are TWO DIFFERENT liveness mechanisms; both must remain. Ticks = asynchronous emission for retroactive analysis (was the subsystem alive during this window?); `health` IPC = synchronous probe for active liveness (runtime health checks; the HARNESS legs read the out-of-process `cargo xtask harness:status` verdict since chunk 2026-08-30-diagnostics-un-muting-harness-truth-sweep — the `status` verb directly, the boot poll through `cargo xtask harness:ready`, which holds that verdict plus an accepted connection on both OTLP ports, since chunk 2026-10-09-boot-smoke-s-early-exit-found-and-closed — the `health` envelope itself is unchanged). Implementations MUST NOT replace tick emission with `health`-only state, MUST NOT treat absence of tick as failure of `health` (or vice versa). No shared state between the two paths required. Per amendment `2026-05-08T17-28-28Z-cross-ref-heartbeat-vs-health` (`.andromeda/runs/2026-05-08T17-28-28-spec-amendment-cross-ref-heartbeat-vs-health/amendment.md`).

- 2026-08-15: THE EMIT SITE IS THE AUTHORITY — for what an allowlist leaf must contain, AND for what a target's silence means. - 2026-08-26: THE ALLOWLIST FALLBACK HAS A THIRD SHAPE — it can resolve to a POPULATED SIBLING set, which is worse than resolving to nothing.
