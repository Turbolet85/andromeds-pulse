## No domain coverage

Chunk #66 "Exception fingerprinting + retry storm detector" is out-of-domain for a11y. Reason: pure backend chunk — `crates/triage/pattern` storm detection algorithm + `crates/buffer/appender.rs` fingerprint write to `span_events.fingerprint` BLOB column. Zero UI surface, zero DOM, zero interactive elements, zero animation/motion, zero color tokens, zero form controls, zero focus management, zero keyboard shortcuts, zero screen-reader announcements introduced by this chunk.

Per a11y-plan §1 A11y Scope table, only `desktop-webview` / `desktop-native` / `WebGPU canvas` / `tray-icon` / `os-notification` / form / modal entities are Assertable. Backend Rust crates (`buffer`, `triage`, OTLP receivers) are explicitly marked "Not-assertable" or "Boundary-only" in §1 — they have no a11y testing scope on their own. Pulse v0.2.0 chunk #66 detail (`docs/v0_2_0/pulse-v0_2_0-route.md` §Phase 2 lines 240-251) confirms: TauRPC delta = none, broadcast topics delta = none (reuses existing `pulse://stream/attention-cues` channel from chunk #62), arch registry delta = none. The `RetryStorm` AttentionCue payload it emits flows through the pre-existing attention-cues broadcast established in chunk #62 — any future webview chunk that renders cues to the UI is where a11y assertions attach (focus management, aria-live announcement, color/icon supplement per SC 1.4.1, etc.), not here.

Per a11y-plan §10 SLO Invariants, "Zero WCAG AA violations on must-be-accessible paths" applies to UI paths (Section 4 ARIA Patterns + Section 5 Keyboard Navigation paths P1–P7). Chunk #66 touches none of P1–P7: not P1 (trace dashboard rendering), not P2 (snapshot modal), not P3 (settings modal MCP toggle), not P4 (live span/metric/log push to UI — chunk #66 writes fingerprints to `span_events` rows, not to a UI live region), not P5 (widget/dashboard/tray toggle), not P6 (snapshot completion notification), not P7 (settings form submission).

The orchestrator may carry forward an a11y advisory only if subsequent chunks add UI consumption of the `RetryStorm` cue payload (per §7 Live regions, that consumer would need `aria-live="polite"` or `role="alert"` per cue severity tier; per §11 Visual anti-pattern, cue rendering would need icon + text supplement to satisfy SC 1.4.1 not-color-alone — but those obligations belong to the rendering chunk, not chunk #66).
