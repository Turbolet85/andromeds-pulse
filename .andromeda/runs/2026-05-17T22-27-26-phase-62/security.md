## Anti-patterns to avoid

- NEVER include raw `exception.message` / `exception.stacktrace` text in the fingerprint hash preimage — the hash is meant to be a STABLE identifier (`exception.type` + normalized first 3 stack frames per `pulse-v0_2_0-route.md` line 251); folding raw message text or unnormalized stack content into the preimage both (a) destabilizes the fingerprint across innocuous content variations (defeating storm detection) AND (b) creates a path for incidentally captured secrets to influence a value that is then re-emitted on the broadcast channel (per security plan §Logging NEVER-log list bullet 1 generalized to derived values).
- NEVER `format!("...{}'", fingerprint_or_exception_field)` against the `duckdb` crate `Connection` when writing `span_events.fingerprint` BLOB or any other user-input-derived field — always `Connection::prepare` + `?` placeholders + `Statement::execute` parameter binding (per security plan §Security Anti-Patterns § Input row 2 + Dagster GHSA-mjw2-v2hm-wj34 / Vanna CVE-2024-5827 / dagster-duckdb CVE-2026-41490 cluster anchor).
- NEVER log fingerprint preimages, raw `exception.*` attribute values, or DuckDB query parameter values from the storm-detector tick or fingerprint-write code path — log the opaque hex digest + occurrence count + service identity only; bind the raw preimage strings via parameter binding without echoing them (per security plan §Security Anti-Patterns § Logging bullets 1 + 3).
