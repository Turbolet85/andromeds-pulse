# arch extract

## Relevance
Relevant — the chunk edits three locked workspace crates (`buffer`, `ingest`, `xtask`) and turns on the DuckDB primary-key convention, the single-write-path record, the error-handling pattern and the formalized injector contract, all of which arch owns.

## Constraints
- Code lands in the locked workspace crates `buffer` / `ingest` / `xtask` only; those names are reserved at workspace level and no new crate is introduced for this repair, and the `Cargo.toml` graph must stay a DAG flowing toward `pulse-app` with no library crate reaching back into the binary (per `architecture.md` §Occupied Resources → Cargo workspace crate names, §Cross-cutting Patterns → Module dependency direction).
- The colliding keys are the locked composite PKs — `spans` on the OTLP-native `(trace_id, span_id)`, `span_events` scoped by its `(trace_id, span_id)` parent — and arch §Conventions → Primary key convention states that no UUID or random surrogate key is introduced, with `seq` the ONE declared exception and scoped to `log_records` + `metrics_points`. The repair may not widen or re-key `spans`/`span_events` to route around the violation. The same section records that the Arrow Appender enforces these keys **at `flush()`** and that a colliding pair fails the ENTIRE batch — the mechanism this chunk is repairing around.
- `architecture.md` §Occupied Resources → DuckDB reserved tables requires that `append_record_batch_to_table` remain the only DuckDB write path in `crates/buffer`, and records it as firing for exactly FOUR tables (`spans`, `metrics_points`, `log_records`, `span_events`). That bounds the repair's blast radius for the chunk's `[inferred]` premise 2; whether the gap-resume dispatch path actually appends to more than `spans` is research's question.
- The storage substrate is fixed: direct SQL via the `duckdb` crate's `Connection` + `Appender`, Arrow zero-copy via `append_record_batch()`, no ORM/migrations layer, DataFusion documented only as a cross-compile-driven swap-out (per `architecture.md` §Established Decisions [Database] + [ORM / Migrations], §Inherited Defaults). A "fail loudly, never hang" repair must stay inside that surface — not a new persistence abstraction.
- A recoverable per-batch failure must surface as a `thiserror`-derived module-internal error returned to the caller (`anyhow` only at boundaries, `AppError` only at the IPC bridge) — arch §Established Decisions [Error Handling Pattern] + §Conventions → Error response schema. Under the scope's "terminal and reported" fork, "reported" must still be a returned/logged error path, not a panic or process abort inside `crates/buffer`.
- The mpsc ingest→appender hand-off with built-in backpressure and the broadcast fan-out are locked (`architecture.md` §Established Decisions [In-Process Channel Architecture]; `crossbeam-channel` explicitly rejected). The wedge symptoms named in scope §1 (`ingest.channel.full`, 0 → 100 %) are that backpressure behaving as designed; the repair must restore consumer drain, not replace the channel topology.
- Any duplicate-resend arm must enter over real OTLP on `:4317`/`:4318` through `crates/ingest/examples/inject_demo` — arch §Cross-cutting Patterns → Test-time telemetry injection forbids an in-process test-mode bypass, a separate "test ingest" feature flag, and a mock-channel back-door, and §Feature-gate hygiene keeps new flags off by default.
- `architecture.md` §Stack → GUI verification harness row requires the injector's arg-less default to keep emitting the finite ~600-batch 100 %-error storm profile, and records that byte-identity as load-bearing for the headful leg's storm-stage budget because `PULSE_INJECTOR` carries the PATH only (xtask threads no arguments). Changing per-restart span identity necessarily perturbs emitted bytes — whether the storm PROFILE (batch count, error rate, stage budget) can be held while identities differ is research's question, and if arch's byte-identity clause is measured false a §Stack amendment is owed at wrap.

## Patterns to follow
- **Formalized injector CLI contract** (`architecture.md` §Stack → GUI verification harness): `--sustained` / `--minutes=N` / `--error-pct=0..100` range-checked, unknown argument REJECTED with exit 2 rather than ignored. Any new flag for a deliberate duplicate-resend arm follows that exact shape.
- **Harness env-var prefix classes** (`architecture.md` §Occupied Resources → Environment variables): `PULSE_*` is the claimed xtask→node relay prefix never crossing into the product; `ANDROMEDA_PULSE_*` is product-consumed; harness-only vars are explicitly tagged "NOT consumed by the production binary". A new seed/identity input picks the class deliberately and gets registered.
- **`cargo xtask` as the single task surface** (`architecture.md` §Infrastructure Patterns → CI/CD, §Established Decisions [CI Task Runner]): shared Rust-needing logic lives in the `xtask` crate so contributors run identical commands locally — the observe-window guard belongs in `xtask/src/gap_resume.rs`, matching the `webview-drive` leg precedent.
- **Agent-driven verification defaults** (`architecture.md` §Cross-cutting Patterns → Development Style): deterministic harness invocations, machine-parseable outputs, schema-stable contracts — the guard that refuses a vacuous PASS should express its verdict in that machine-readable shape.
- **Self-observation discipline** (`architecture.md` §Cross-cutting Patterns): the product's own telemetry goes to the stdout/file exporter under `logs/`, never dialled back at its own `:4317`/`:4318`. The `duckdb.append` ERROR / `reject_reason` observability the chunk relies on rides that route; obs owns the leaf shape.

## Anti-patterns to avoid
- Re-keying, widening, or dropping the `spans` / `span_events` composite PKs, or introducing a surrogate/random key column to make duplicate replay stop violating — the `seq` exception is declared for `log_records` + `metrics_points` only (`architecture.md` §Conventions → Primary key convention).
- Adding an in-process ingest back-door, mock channel, or test-only feature flag to reproduce the duplicate batch instead of resending over real OTLP (`architecture.md` §Cross-cutting Patterns → Test-time telemetry injection; §Cross-cutting Patterns → Feature-gate hygiene).
- Changing the connection/storage topology (extra `Connection`s, a swapped engine, a new persistence layer) as the escape from the hang — the substrate is locked by `architecture.md` §Established Decisions [Database] + [ORM / Migrations], and scope §1 independently forecloses re-opening connection isolation.

## Contract bindings
- **arch ↔ tests (harness)**: the `PULSE_INJECTOR` path-only relay and the arg-less-default storm profile registered in `architecture.md` §Stack + §Occupied Resources are the same objects the `smoke:gap-resume` arms and the 16-stage `webview-drive` leg consume; any injector identity change is jointly owned with the tests domain's stage-budget expectations.
- **arch ↔ obs**: `architecture.md` §Cross-cutting Patterns → Self-observation discipline fixes the route for the `duckdb.append` ERROR + `reject_reason` signal the chunk's `[inferred]` premise 5 leans on; whether that existing signal is sufficient for the repaired path (i.e. whether a new target/leaf is owed) is the obs plan's call, not arch's.
- **arch ↔ tests (registry)**: any new injector flag or env var must land in `architecture.md` §Occupied Resources at wrap, per the standing registration rule the amendment history applies to every harness resource.

## Acceptance criteria contributions
- (arch) The repair lives in `crates/buffer`, `crates/ingest/examples`, and `xtask` — no new workspace crate, no new cross-crate dependency edge, `pulse-app` still the only DAG root (per `architecture.md` §Occupied Resources → Cargo workspace crate names + §Cross-cutting Patterns → Module dependency direction).
- (arch) `spans` and `span_events` primary keys are byte-for-byte unchanged in all DDL representations and no surrogate key column is added to either (per `architecture.md` §Conventions → Primary key convention).
- (arch) A constraint-violating batch RETURNS a `thiserror`-derived error from `crates/buffer` — no panic, no `unwrap`, no abort — and the boundary converts only at the existing `anyhow`/`AppError` seam (per `architecture.md` §Established Decisions [Error Handling Pattern] + §Conventions → Error response schema).
- (arch) Every duplicate-resend arm reaches the appender over real OTLP via `crates/ingest/examples/inject_demo` with no in-process bypass, any new injector flag range-checks its value and exits 2 on an unknown argument, and any new env var is registered in §Occupied Resources under the correct prefix class (per `architecture.md` §Cross-cutting Patterns → Test-time telemetry injection + §Stack → GUI verification harness + §Occupied Resources → Environment variables).
