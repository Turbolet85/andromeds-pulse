## Patterns to follow
- **Do not probe a duplicate INSERT directly.** §4 records that the PK contract is asserted via `information_schema.key_column_usage` in `schema::tests::log_records_primary_key_includes_seq_ordinal` *because a duplicate-INSERT probe is a documented hang on this build* (per test-plan §4 → buffer crate) — the exact hazard this chunk's tests must route around.
- **Hang-safe assertion form**: `appender::tests::append_logs_batch_same_tick_same_severity_keeps_both_records` runs on a worker thread under a 30 s `recv_timeout` so a hang **fails rather than wedges** the suite (per test-plan §4 → buffer crate). This is the established shape for pinning "the next flush after a failed flush returns".
- **Discriminating accepted/rejected pair at the dispatch call site**: `consumer::tests::dispatch_folds_redactions_after_a_successful_append` / `dispatch_folds_no_redactions_when_the_append_is_rejected`, which discriminate only as a pair (per test-plan §4 → buffer crate) — the precedent home if the repair lands at `dispatch_batch` rather than in the appender (`[inferred]` #1).
- **Self-bootstrapping seeds only**: seed via OTLP ingest through the live receiver or direct in-memory DuckDB inserts; `MockTraceSpan` / `MockArrowBatch` / `MockMetricPoint` are specified-but-UNIMPLEMENTED (0 workspace hits) and must not be called (per test-plan §7 → Self-bootstrapping requirement; §3 Bootstrap item 6; §1 `test-data-bootstrap-factories-unimplemented`).
- **Harness/dev-tool bounded-input boundaries are owed per-branch unit tests**, and a `[[example]]` target can host `#[cfg(test)] mod tests` and run under nextest — already the open ask against `inject_demo.rs`, including a pin on the **default-preservation invariant (arg-less emission byte-identical)** the harness depends on (per test-plan §1 → `inject-demo-arg-parse-unit-coverage`). Changing the injector's identity derivation touches exactly that invariant.

## Anti-patterns to avoid
- NEVER use `sleep(N)` for synchronization — wait on an explicit signal (per test-plan §11 → E2E). Applies to the observe-window guard and any stall-threshold wait.
- NEVER mock DuckDB at the integration level, and never share a connection/mutable state across tests — ephemeral in-memory instance per test, or order-dependent failures follow (per test-plan §11 → Integration; §11 → Test Data).
- NEVER add retry-once policies or commit `#[ignore]` without a tracked reason to get a hang-prone test green (per test-plan §11 → Quality; §10 Zero-flakiness budget).
