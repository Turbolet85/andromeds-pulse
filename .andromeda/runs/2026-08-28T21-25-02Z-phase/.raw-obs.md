## Patterns to follow
- Once-per-transition bounded-token WARN: `buffer.consumer.stalled` (`reason`/`consequence` drawn from a bounded static set + two numerics), announced on transition and again on recovery, never per batch — the shape for any new terminal/degraded announcement this repair needs (per obs-plan §6 `warn` row; §8 `buffer.consumer.stalled` leaf).
- New counters ride as FIELDS on the existing 15 s `buffer.tick` (14 fields today), folded once per batch by a `BufferState::record_*` method, rather than as new `metric.buffer.*` targets; per-row/per-batch emission is barred (per obs-plan §5 tick-aggregated Counter rows; §1 Heartbeat ticks).
- Post-append fold at each table's own site in `consumer::dispatch_batch`, builders returning `Result&lt;Option&lt;(RecordBatch, u64)&gt;, Error&gt;` — the existing structural shape the repair edits around (per obs-plan §5 `redactions_applied` row).
- EXACT allowlist leaf enumerating every field its emit site emits, guarded from `pulse-app/tests/` (a src-level `mod tests` guard never runs under `[lib] test = false`), asserting the field set by EQUALITY in both directions plus a fallback-set discriminator (per obs-plan §8 Default-deny posture; `buffer.consumer.stalled` / `triage.incident.persist` precedents).
- Verdict consumes the EXISTING detector: `smoke:gap-resume` reads `buffer.consumer.stalled` + `check:ingest-progress` as its verdict rather than adding a second detector, and absent-signal states report NEUTRAL rather than FAIL (per obs-plan §10 detector-exercised paragraph + the frame-budget two-state posture in §10 Performance budgets).

## Anti-patterns to avoid
- Never log the colliding `(trace_id, span_id)` — or any span/service/fingerprint identity — when reporting a duplicate-key rejection; the `buffer` allowlist is aggregate-counts-only and raw OTLP attributes are banned from spans and logs outright (per obs-plan §8 `buffer` whitelist; §11 Spans/Traces + Logs).
- Never add per-batch or per-row emission inside the appender's failure/retry path, and never log on that path at `info`; stack traces must be one-line SpanTrace, not multi-line backtraces (per obs-plan §11 Telemetry Strategy hot-path ban + §11 Logs).
- Never mask the failure to reach the acceptance — no retry-once policy that swallows the error, no panic-to-escape, no unlogged terminal state (per obs-plan §11 SLO; §10 zero-unlogged-panics).
