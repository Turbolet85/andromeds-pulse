## Anti-patterns to avoid
- NEVER emit raw OTLP attribute values (including attribute-derived per-service identity payloads) into new baseline/cue log events or into corpus writes without the scrubber (per security-plan §Security Anti-Patterns §Logging).
- NEVER add a TauRPC procedure to a router without a matching `pulse-app/capabilities/` entry — the call is silently rejected at runtime; the xtask drift check is the enforcement (per security-plan §Security Anti-Patterns §API). Applies only if the config-surfaced mechanism adds a procedure rather than riding existing `get_settings`/`update_settings`.
- NEVER read an `ANDROMEDA_PULSE_*_PATH` / `*_DIR` env var without canonicalize-and-confine via `strict-path` — relevant if a fresh-data-dir or override affordance is the chosen mechanism (per security-plan §Security Anti-Patterns §Input, CWE-22 class).
