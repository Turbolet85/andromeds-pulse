## Relevance
Relevant — arch governs crate placement, the config-precedence path, resource registration, and the test-reachability discipline this chunk's warm-up mechanism must land inside.

## Constraints
- Baseline/cue warm-up logic belongs to the locked crate `triage`; `ingest`, `buffer`, `viz`, `ui-bridge`, `snapshot`, `curation`, `triage`, `workspace-detector`, `plugins`, `mcp-server`, `corpus`, `security`, `interpretation`, `config-watcher`, `pulse-app`, `xtask` are reserved and no new workspace crate is warranted for a constant/gate change (per architecture.md §Occupied Resources → Cargo workspace crate names; §Project Intent → "the twelve reserved crate names cannot be re-purposed").
- If the bound is config-surfaced, resolution order is fixed: process env `ANDROMEDA_PULSE_*` > `<data_dir>/config.toml` > built-in defaults — a new override may not invent a fourth layer or read config from anywhere else (per architecture.md §Cross-cutting Patterns → Config management; §Inherited Defaults → Config precedence).
- Any user-facing duration field must carry explicit units in the name (`retention_seconds` is the pattern), and any port-shaped or bounded scalar validates via `serde` + smart enum / `TryFrom` rather than a validation library (per architecture.md §Conventions → Configuration units; §Established Decisions → [Validation Library]).
- A new env var, TauRPC procedure, config key, broadcast topic, or data-dir path landed by this chunk MUST be registered in §Occupied Resources at wrap; harness-only vars are registered as a distinct class explicitly marked "NOT consumed by production binary" (per architecture.md §Occupied Resources → Environment variables).
- If warm-up state is exposed over the bridge, it must take one of the two authorized procedure shapes (top-level bare `snake_case` envelope verb, or `<router>.<verb>`), return `Result<T, AppError>`, be `serde::Serialize`, and gain a matching entry in `pulse-app/capabilities/` or the call is rejected at runtime (per architecture.md §Conventions → Endpoint naming + Error response schema (Tauri IPC); §Cross-cutting Patterns → Webview IPC capability policy, Cross-bridge data shape).
- Feature flags are `kebab-case` and off by default; flag-specific deps must not enter the default build graph — so a feature flag is not a free lever for a shortened window (per architecture.md §Conventions → Feature flags; §Cross-cutting Patterns → Feature-gate hygiene).
- Reachability must be demonstrable through the real ingest surface: e2e injection speaks OTLP on `:4317`/`:4318` (port-overridable via `ANDROMEDA_PULSE_OTLP_{GRPC,HTTP}_PORT`) and buffer state is read back through the `traces.*` / `metrics.*` / `logs.*` routers — no in-process bypass (per architecture.md §Cross-cutting Patterns → Test-time telemetry injection).

## Patterns to follow
- Crate template shape: one public contract module as the crate's only `pub` surface, `pub(crate)` internals, `thiserror`-derived error enum — the canonical home for a warm-up constant/threshold that two modules must agree on is that contract surface, so the "same value reaches BOTH mirrored constants" requirement is structural rather than a copied literal (per architecture.md §Project Intent → Template patterns; §Conventions → Module visibility discipline). Whether the two constants are already single-sourced is research's question.
- Config hot-reload path (chunk #96 precedent): `crates/config-watcher` `notify` watcher on `<data_dir>/config.toml` + `tokio::sync::watch` fan-out, with `config.reload` / `config.status` procedures and the aggregate-only `pulse://stream/config-events` topic — the established route if the bound becomes a hot-reloadable setting (per architecture.md §Occupied Resources → Tauri IPC routes / events).
- Env-gated deterministic-affordance shape (`ANDROMEDA_PULSE_L4_DETERMINISTIC`): bounded truthy-parse following the `crates/mcp-server/src/feature_gate.rs` pattern, resolved at `pulse-app` boot, default off, registered at arch level — the precedent to copy if the mechanism is a declared verification affordance rather than a production default change (per architecture.md §Occupied Resources → Environment variables).
- Baseline durability substrate: `baseline_state` is the reserved corpus SQLite table under `corpus/corpus.db`, cell-level AES-256-GCM with OS-credential-store key sourcing; "fresh data dir" means this table is empty, and any DDL there is a schema change requiring registry amendment (per architecture.md §Occupied Resources → Corpus SQLite database / schema names).
- Cue emission stays on the registered topic `pulse://stream/attention-cues`; no new stream topic is needed for a reachability change (per architecture.md §Occupied Resources → Tauri IPC events).

## Anti-patterns to avoid
- No in-process test-mode bypass, no "test ingest" feature flag, no mock-channel back-door to force the warm state — the reachability proof must run the production path (per architecture.md §Cross-cutting Patterns → Test-time telemetry injection).
- No unregistered resource: an env var / procedure / config key / data-dir file that ships without a §Occupied Resources entry is the recurring D-arch-resources drift this plan bans (per architecture.md §Occupied Resources).
- No new crate and no library crate depending on `pulse-app`; the dependency graph is a DAG rooted at the binary, and no library crate depends on a sibling unless its declared contract requires it (per architecture.md §Cross-cutting Patterns → Module dependency direction).

## Contract bindings
- **arch ↔ tests/external harness**: the bound must be observable over registered surfaces (OTLP ingest ports + `traces.*`/`metrics.*`/`logs.*` + `pulse://stream/attention-cues`); the Conductor harness consumes only these, so the "stated contract a harness can rely on" is an arch-registered resource, not an internal constant.
- **arch ↔ config-watcher / ui-bridge Settings**: a config-surfaced bound crosses the TauRPC bridge, so it inherits `serde::Serialize` + `AppError` + capability-file registration, and the hot-reload consistency the scope demands rides the chunk #96 watch fan-out.
- **arch ↔ obs**: whether warm-up/bootstrap state is emitted for L6 self-observability must use `opentelemetry-stdout`/file exporter only — the product never dials its own `:4317`/`:4318` (architecture.md §Established Decisions → [Self-Observation]).
- **arch ↔ security**: any new env var carrying a path or bound value follows the canonicalize-and-confine-under-data-dir rule; the `~/Downloads` training export is the sole registered exception.

## Acceptance criteria contributions
- (arch) All warm-up/bootstrap changes land in `crates/triage` (plus `crates/ui-bridge` / `crates/config-watcher` only if config-surfaced); no new workspace crate, no library-crate dependency on `pulse-app` (per architecture.md §Occupied Resources → Cargo workspace crate names + §Cross-cutting Patterns → Module dependency direction).
- (arch) Any new user-facing bound is named with explicit seconds units and resolves under env > `config.toml` > defaults precedence (per architecture.md §Conventions → Configuration units + §Cross-cutting Patterns → Config management).
- (arch) Every new env var / IPC procedure / config key / broadcast topic introduced is registered in §Occupied Resources at wrap, with a bounded parse and a harness-only marker where it is not consumed by the production binary (per architecture.md §Occupied Resources → Environment variables + Tauri IPC routes).
- (arch) The fresh-service reachability proof drives the production ingest path (OTLP on `:4317`/`:4318`, state read back via the query routers) with no test-mode bypass or default-on feature flag (per architecture.md §Cross-cutting Patterns → Test-time telemetry injection + Feature-gate hygiene).
