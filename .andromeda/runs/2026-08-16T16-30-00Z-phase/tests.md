## Relevance
Relevant — a Rust library-crate change (`crates/triage`) whose acceptance is a time-gated reachability assertion on a fresh data dir, which the test plan governs on gates, clock injection, fixture construction, and coverage.

## Constraints
- **Standard tier depth applies:** unit is "comprehensive — 75% line coverage minimum; all module boundaries tested"; integration is "required" for cross-module boundaries — the reachability claim spans `baseline` state → cue evaluator, so it is not purely a unit-level concern (per `.andromeda/test-plan.md` §1 Test tier, §2 pyramid).
- **The standard gate set is unconditional** in this chunk's `## Test Commands`: `cargo fmt --check`, `cargo clippy --workspace --all-targets --all-features -- -D warnings`, `cargo nextest run --workspace --profile ci`, `cargo xtask capability-drift`, `cargo xtask capability-widening-check`. The three `npm run … --prefix pulse-app/ui` gates are excludable **only** if the Files-to-modify / New-files lists touch zero `pulse-app/ui/**` paths — whether a `contract.rs::Settings` change regenerates TauRPC TS bindings under `pulse-app/ui/**` is research's question (per test-plan §3 Per-chunk gate discipline).
- **Boot-smoke gate is conditional on the mechanism chosen:** its trigger list includes `crates/ui-bridge/src/`, so if the bound is config-surfaced through `crates/ui-bridge/src/contract.rs::Settings` (scope "Surfaces likely touched"), the chunk MUST add a runtime smoke gate; a pure `crates/triage` + `crates/config-watcher` change does not trip it (per test-plan §3 Boot-smoke gate).
- **The clock must be injected, never waited on.** The bootstrap gate is time-since-first-observation, and §7 designates `tokio::time::pause()` + `tokio::time::advance(Duration)` as the strategy for time-sensitive data, with `#[tokio::test(start_paused = true)]` as the pattern (per test-plan §7 Time-sensitive data, §8 Time mocking row).
- **The "fresh service" state must be self-bootstrapped at runtime**, isolated per test via `tempfile::TempDir` + `ANDROMEDA_PULSE_DATA_DIR`; no pre-staged baseline-state file may be committed as a fixture (per test-plan §7 Self-bootstrapping requirement, §1 `agent-driven-discipline: Self-bootstrapping test data`).
- **Test location convention:** library crates use co-located `#[cfg(test)] mod tests { … }` in `src/`; `pulse-app` is the sole exception (`[lib] test = false` ⇒ probes live in `pulse-app/tests/*.rs` reaching internals via `pub` + `#[doc(hidden)]`). Note `triage` is named in **none** of the three places the plan enumerates library crates (§2 pyramid Unit row, §4 "What unit tests cover", §4 test-file-location) — see amendment history (per test-plan §2 Test directory + naming conventions, §4 Conventions).
- **Zero-flakiness and coverage thresholds bind:** ≥ 75% line / ≥ 70% branch / ≥ 85% function; a single flake is quarantine + root-cause, never retry — a warm-up-bound test is exactly the shape that decays into a flake if it leans on real elapsed time (per test-plan §10 Quality Gates, Zero-flakiness budget).

## Patterns to follow
- `rstest` 0.26.1 `#[fixture]` builders composed into `#[rstest]` tests, rather than hand-rolled literals — the plan's declared fixture library for a "fresh-state fixture" (per §7 Fixture library, §4 Fixture pattern at unit level).
- The buffer crate's retention-window pattern is the plan's existing answer for a time-windowed gate: paused clock + `advance()`, with the window value overridable by env (`ANDROMEDA_PULSE_BUFFER_RETENTION_SEC` is the precedent shape for a config-surfaced bound) (per §4 buffer bullet, §3 Test data bootstrap → Per-test isolation).
- Drift-guard-as-a-gate: `cargo xtask capability-drift` / `verify:capability-matrix` are the plan's established shape for "two artifacts must agree or CI fails" — the same shape fits scope In-scope 2's requirement that one declared bound reach both mirrored constants (per §3 standard gate set, §9 Capability verification matrix).
- Direct-binary smoke variant when a verification needs runtime state the harness `run` verb cannot express: launch `target/debug/pulse-app.exe` under a fresh `ANDROMEDA_PULSE_DATA_DIR` and an env-gated mode, seed over the real receiver, then assert from the run's own artifacts (0 `app.panic.fatal` / 0 `ERROR` in `<data_dir>/logs/agent-latest.jsonl*`) and shut down by specific pid with `:4317`/`:4318` confirmed released (per §3 Direct-binary smoke variant).
- Narrow a `pulse-app` selection with `--filter-expr` / `-E` **under `--workspace`**, not `-p` — applies only if a reachability probe lands as a `pulse-app/tests/*.rs` target (per §3 `run` → Test selection).

## Anti-patterns to avoid
- NEVER use real time without injection (`std::time::Instant::now()` / `chrono::Utc::now()`) and NEVER `sleep(N)` for synchronization — a wall-clock wait for the warm-up, even a shortened one, is banned outright (per §11 Universal, §11 E2E).
- NEVER pre-populate test state from committed `.sql` scripts, DB snapshots, or developer-seeded files — the no-prior-baseline condition must be constructed at test runtime (per §11 Test Data).
- NEVER add a retry-once policy or land an `#[ignore]` without a tracking issue to make a time-gated test settle (`#[ignore]` is reserved for flake quarantine) (per §10 Zero-flakiness budget, §11 Quality, §10 Load profiles note).
