## Anti-patterns to avoid

- **NEVER use `wasmtime::Linker` to expose host functions outside the WIT contract** for any guest (per security-plan §Code Patterns ban + §API Security row). Bypasses architecture's capability-scoped sandbox. Per-category host imports stay declared in WIT only; chunk #46's Linker construction MUST come from the WIT bindings, never ad-hoc host-function `define` calls outside the WIT-declared surface.
- **NEVER log full plugin file paths** in any `tracing` event from chunk #46's load / limit-exceeded / WIT-mismatch / epoch-timeout paths — canonicalized basename only (per security-plan §Logging & Monitoring NEVER-log list + §Security Anti-Patterns §Logging row 2).
- **NEVER add a non-Cranelift wasmtime feature flag on x86_64 builds** (per security-plan §Data Protection ban). The April 2026 advisory cluster (CVE-2026-34941, CVE-2026-35195) had Cranelift-on-x86_64 as the unaffected configuration; a "use Winch experimental backend" change re-introduces the exposure.
