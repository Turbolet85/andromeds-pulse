## Constraints

- The webview root document MUST set `<html lang="en">` per a11y plan §1 WCAG omissions list (SC 3.1.1 — single-language English commitment is the documented justification for omitting full i18n) and §3 WCAG 2.1 AA core criteria SC 3.1.1 Language of Page.
- Single `<main>` landmark required at the shell level per a11y plan §7 Landmark roles + §4 desktop-webview required landmarks (`main` + `navigation`); custom titlebar regions wrap in `<header>` (or `role="banner"`) per §7 Landmark roles. Required by SC 1.3.1 Info and Relationships.
- Custom titlebar window-control buttons (minimize/maximize/close) MUST be native `<button>` elements with `aria-label` text identifying purpose ("Minimize", "Maximize", "Close to tray"), not styled `<div>` — per a11y plan §11 ARIA "NEVER use ARIA on non-semantic HTML" + §4 Button row (semantic HTML first).
- The drag region MUST NOT capture focus or break the Tab sequence — drag-handle elements take `aria-hidden="true"` only when they are non-interactive visual surfaces, and never sit on focusable elements per a11y plan §11 Screen Reader "NEVER hide important content from assistive tech" + §11 Keyboard "NEVER nest focusable elements inside other focusable elements".
- Close→minimize-to-tray MUST preserve the focus restoration contract for critical path P5: focus returns to the tray icon on minimize and back to the previously-focused element when the window is restored, per a11y plan §3 Critical Paths P5 + §5 Focus restoration "Tray icon click (minimize widget) → focus returns to compact-widget when re-expanded".
- Window-control buttons MUST display `--border-focus` outline on `:focus-visible` per a11y plan §6 Focus ring tokens + SC 2.4.7 Focus Visible; CSS MUST NOT contain `outline: none` without alternative (a11y plan §11 Keyboard).
- Window-control button hit targets MUST be ≥ 24×24 CSS px per a11y plan §6 Target size tokens + SC 2.5.8 (AA), measured via `--target-button-min` token.
- Document the `<title>` element / `document.title` for SC 2.4.2 Page Titled per a11y plan §3 WCAG 2.1 AA core criteria — initial shell value should be the app name (e.g., "andromeda-pulse") and updated by route changes once SPA routing arrives in later chunks.

## Patterns to follow

- Semantic HTML first, ARIA second per a11y plan §4 Naming convention + §11 ARIA — the custom titlebar uses `<header>` + native `<button>` + `<div role="presentation">` only on non-interactive decorative chrome; do not introduce `role="banner"` on top of `<header>`.
- Skip-to-main link as first focusable element on layouts that wrap the shell, per a11y plan §5 Skip links + SC 2.4.1 Bypass Blocks. The shell SHOULD provide the structural anchor (the `<main id="main-content">` target) so downstream layout chunks can wire the skip link without revisiting the shell.
- Status messages from the close→minimize transition (e.g., "Minimized to tray") emitted via `aria-live="polite"` `<div role="status">` per a11y plan §7 Live regions + SC 4.1.3 — non-blocking announcement so the user knows the window did not actually quit.
- `prefers-reduced-motion` respect for any titlebar / window chrome transitions (window minimize animation, title fade) per a11y plan §6 Motion tokens + SC 2.3.3 AAA — apply Tailwind v4 `motion-reduce:duration-0 motion-reduce:transition-none` variants.
- Apply baseline `eslint-plugin-jsx-a11y` recommended config (already installed in chunk #13 a11y dev stack) at compile time per a11y plan §9 Lint stage + §3.5 a11y-linting-install — catches missing `aria-label` on icon buttons, ARIA-on-non-semantic, redundant role attributes inside the custom titlebar implementation.

## Anti-patterns to avoid

- NEVER omit window-control button labels (icon-only `<button><svg/></button>` without `aria-label="Minimize"`) — per a11y plan §11 Screen Reader "NEVER leave form inputs without associated labels" generalizes via SC 4.1.2 Name, Role, Value to all interactive controls.
- NEVER make the drag region a focusable element (e.g., `tabindex="0"` on the drag bar) — creates phantom Tab stop with no operable behavior; per a11y plan §11 Keyboard "NEVER set `tabindex > 0`" and §1 Critical Paths P5 No Keyboard Trap (SC 2.1.2).
- NEVER trap focus inside the custom titlebar / shell with no Escape route — the shell's close→minimize handler MUST work from any focused descendant per SC 2.1.2 (a11y plan §3 Critical Paths P5 + §11 Keyboard "NEVER create keyboard traps").
- NEVER ship `outline: none` reset on focus styles in the shell CSS without replacement — a11y plan §11 Visual + SC 2.4.7; the Tauri 2 webview default focus ring is browser-engine-dependent (WebView2 vs WKWebView differ), so the shell MUST establish a project-controlled `--border-focus` style that overrides UA defaults.
