## Patterns to follow

- **Boundary-only tray instrumentation**: hook into Tauri tray icon / menu event handlers + `tauri-plugin-notification` event listeners and emit `tracing::info!(target: "tray.{event}", ...)` from the boundary; do not attempt to instrument OS internals (per obs-plan §4 Desktop-native row + §1 row 60).
- **Per-target AllowList registration**: extend `pulse-app/src/observability.rs::AllowList::production()` with the new chunk-introduced targets and their enumerated label set, and co-locate pass+redact tests for each new target — the precedent across chunks #20/#21/#22/#23 (per session-handoff Files Modified §observability.rs across chunks).
- **TauRPC frontend-bridge command shape**: scaffold `telemetry.frontend.record_*` commands in `ui-bridge` such that webview JS can call them; backend handlers convert to `tracing::info!(target: "metric.{name}", value = N, ...)` events with `metric.*` target prefix per §5 emission convention. Even if `web-vitals` instrumentation is deferred to later chunks, the bridge contract scaffolding lands here so platform-tagged boot spans + window-state events flow on day one (per obs-plan §3 Logging stack frontend-bridge bullet + §4 row 273).
- **Span-naming convention `{module}.{operation}`**: use `app.boot.{operation}` for startup spans, `tray.{event}` for tray boundary events, `ui.layout.{operation}` for window-state transitions; avoid high-cardinality span names (no per-window-ID, no per-display-ID names) (per obs-plan §4 span naming + §11 Spans anti-pattern).
- **Heartbeat tick allowlist precedent**: long-running webview state heartbeat (if added — e.g., `ui.tick` for window-position memory) follows the existing 15s interval + `tokio::time::interval(Duration::from_secs(15))` precedent established by `ingest.tick` / `buffer.tick` (per obs-plan §3 Heartbeat ticks).

## Anti-patterns to avoid

- NEVER link a browser OTel SDK into the webview — frontend telemetry MUST go through TauRPC bridge → backend `tracing` event (per obs-plan §11 Universal "NEVER link an OTel SDK into the product's self-observation runtime"); doing so re-introduces the recursion concern the project chose to avoid by construction (per obs-plan §1 row 41 + §3 Tracing init "Why this approach" bullet).
- NEVER emit unstructured stderr text from window-state / tray boundary handlers — always JSON-per-line via `tracing::info!` to file sink (per obs-plan §11 Logs anti-pattern "NEVER use unstructured stderr text").
- NEVER use unbounded label cardinality for `webview_backend` / `wgpu_backend` / `tray_api` — these MUST be enumerated to {WebView2, WKWebView, GTKWebKit} / {vulkan, metal, dx12} / {NotifyIcon, NSStatusItem, AppIndicator} (per obs-plan §5 cardinality discipline + §11 Metrics anti-pattern "NEVER use unbounded label cardinality").
- NEVER emit `app.boot.*` spans before `tracing-subscriber::registry().init()` completes — events emitted before subscriber init are silently dropped, masking instrumentation gaps (per obs-plan §3 Tracing init order).
