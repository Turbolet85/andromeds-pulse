## Constraints

- Both webview surfaces (compact widget + full dashboard) MUST use a custom frameless titlebar at `height: space-lg` with `padding: 0 space-sm` and `gap: space-sm`, `background: color-base`, full-width drag region except over button hit-targets — implemented via Tauri 2 `data-tauri-drag-region` attribute on the titlebar container (per layout-templates.md §Component — Custom titlebar (desktop-webview specific) Layout).
- Titlebar flex segment order is fixed: `[app-icon + title | grow | settings-button | window-controls]` with the bottom 1px `Border Progression Subtle` token applied as the titlebar's bottom border (per layout-templates.md §Component — Custom titlebar Layout + Border).
- Window controls placement is platform-specific and MUST follow OS chrome conventions: traffic-light buttons on the LEFT on macOS (OS-provided), three buttons (minimize / maximize / close) on the RIGHT on Windows / Linux with hover background → `color-raised-2` (per layout-templates.md §Component — Custom titlebar Components).
- Compact widget shell is fixed quarter-screen size, always-on-top, snap-to-edge per Settings; minimum recommended size readable on a 13-inch laptop display; no CSS media-query breakpoints (per layout-templates.md §Decisions Log Responsive breakpoints + §Primary screens Compact widget).
- Close/Esc on the compact widget MUST minimize to system tray (does NOT terminate the process) — only the explicit Quit menu item or OS-level kill terminates; this matches the cross-cutting policy that the tray is the always-on surface (per layout-templates.md §IA notes Navigation model + CLAUDE.md / arch §Cross-cutting Patterns Tray icon policy).
- Custom titlebar design must remain visually identical between compact widget and full dashboard for cross-surface visual cohesion (`color-base` background, aperture gear icon for settings, platform-specific window controls in the same arrangement) (per layout-templates.md §Decisions Log Cross-surface IA decisions).
- App-icon and settings-button glyphs are placeholders for the chunk's structural scaffold — concrete glyph (aperture / constellation-grid) is provided by the iconography registry (Foundation chunk), but the titlebar layout MUST reserve and place the slots per the flex segment order above (per layout-templates.md §Component — Custom titlebar Components).

## Patterns к follow

- Frameless titlebar pattern: a single React component owning the drag region (`data-tauri-drag-region`), the icon+title cluster on the left, a flex grow spacer, then the settings-button + platform-conditional window controls on the right; reused by every webview window the project creates (per layout-templates.md §Component — Custom titlebar (desktop-webview specific) Layout).
- Settings-button hover pattern: `color-text-secondary` default → `color-text-primary` on hover over `duration-fast` ease-out; reuse this transition for any future titlebar icon button (per layout-templates.md §Component — Custom titlebar Components).
- Cross-surface coherence pattern: compact widget + full dashboard share the same titlebar implementation, the same `pulse://stream/*` data feeds, and the same Halo State Pulse shader — chunk #24's titlebar component must be parameterized (title text variant: `"andromeda-pulse"` for compact widget vs `"andromeda-pulse — {view}"` for full dashboard) rather than duplicated (per layout-templates.md §Decisions Log Cross-surface IA decisions + §Component — Custom titlebar Components Title).
- Tray-coordination pattern: closing the main window minimizes to tray rather than quitting; tray icon click focuses/restores the compact widget. Chunk #24 wires the close handler; tray icon itself is later epoch (per layout-templates.md §IA notes Navigation model + §Surface: desktop-native §IA notes Navigation model).

## Anti-patterns к avoid

- Do NOT render OS-provided chrome (no `tauri.conf.json` with `decorations: true`) — frameless is mandatory because the custom titlebar is a structural part of the surface (per layout-templates.md §Wireframe — Compact widget notes + §Component — Custom titlebar).
- Do NOT make the drag region cover button hit-targets — buttons must remain clickable (drag region is "full width except buttons") (per layout-templates.md §Component — Custom titlebar Layout Drag region).
- Do NOT terminate the process on window close — closing must minimize to tray; quit is reachable only via tray menu Quit item or OS-level kill (per layout-templates.md §IA notes Navigation model + CLAUDE.md §Cross-cutting Patterns Tray icon policy).
- Do NOT introduce hard CSS breakpoints for the compact widget — it is fixed quarter-screen (resizable by user but no media-query breakpoints) (per layout-templates.md §Decisions Log Responsive breakpoints).
