## Constraints

- Custom titlebar MUST be 32px height and contain app icon (16px), title text "andromeda-pulse", settings button (aperture icon, 20px), and OS-appropriate window controls (minimize/maximize/close right-aligned on Windows/Linux; traffic-light buttons left-aligned on macOS); drag region spans full titlebar width except buttons (per design plan §Surface: desktop-webview Component Patterns "Navigation / App Shell" titlebar bullet).
- Window MUST be frameless via Tauri config `"decorations": false` — webview chrome is custom-drawn, not OS-default; no browser-style navigation chrome (back/forward/URL bar) present (per design plan §Surface: desktop-webview Platform-Specific Notes Windows bullet + §Anti-Patterns Per-Surface Bans desktop-webview "NEVER use browser-style navigation").
- Page background MUST use `--color-base` (#1A1D24, Deep Control Gray) as the app envelope; no shadows, gradients, or glassmorphic effects on chrome (per design plan §Color Palette Surface Scale Base row + §Depth Strategy borders-only rationale + §Anti-Patterns Universal Bans "NEVER use gradient overlays or glassmorphic effects").
- Closing the main window MUST minimize-to-tray (process keeps running, tray icon remains); explicit Quit (Cmd+Q on macOS, Quit menu item, OS-level kill) is the only termination path — close-button is NOT a quit action (per CLAUDE.md @architecture.md §Cross-cutting Patterns Tray icon policy "closing the main window minimizes to tray rather than terminating the process" + design plan §Surface: desktop-webview Component Patterns "Navigation / App Shell" single-window mode framing).
- Window-control hover/active states (when custom-drawn) MUST use motion tokens `--duration-fast` 150ms with `--easing-out` (cubic-bezier(0.4, 0, 0.2, 1)); NO bounce/spring physics, NO opacity fades >200ms, NO entrance animation on window open (per design plan §Motion Duration scale + §Motion Hard limits).
- All chrome motion MUST respect `prefers-reduced-motion: reduce` and degrade transitions to instant (150ms hover → 0ms, 200ms fade → 0ms) (per design plan §Motion Accessibility bullet).
- Settings button glyph MUST use the custom `aperture` icon at 20px from the icon registry (`<Icon glyph="aperture" />` per chunk #10 iconography registry); no Lucide/Heroicons fallback for this slot (per design plan §Iconography Primary custom set "aperture" entry + Size grid 20px row).
- Title text "andromeda-pulse" MUST use IBM Plex Sans 500 weight at Label size (12px), 0 tracking; no banned font fallback chain (no Inter/Roboto/Arial/Helvetica/Open Sans/Lato/system-ui/Space Grotesk) (per design plan §Typography Label row + §Anti-Patterns Universal Bans banned-fonts list).
- Right-click context menu and text-selection on non-text elements MUST be hidden/disabled at the webview level (per design plan §Anti-Patterns Per-Surface Bans desktop-webview "NEVER ship with visible Chromium/WebView2 artifacts" bullet).
- CSP for the webview MUST be `script-src 'self'` — no eval, no remote scripts, no CDN; WOFF2 fonts already bundled locally per chunk #10 (per design plan §Surface: desktop-webview CSP policy).

## Patterns to follow

- Frameless titlebar with custom-drawn controls: 32px height, drag region attribute on the titlebar background but explicitly excluded from button hitboxes (Windows: minimize/maximize/close 32px from right edge; macOS: traffic lights left side; Linux: right-aligned per Windows convention) (per design plan §Surface: desktop-webview Component Patterns "Navigation / App Shell" + Platform-Specific Notes per-OS bullets).
- Tailwind v4 `@theme` token consumption — chrome surfaces reference `var(--color-base)`, `var(--color-text-primary)`, `var(--font-body)`, `--duration-fast`, `--easing-out` from the @theme block scaffolded in chunk #10 (per design plan §Surface: desktop-webview Tokens block + §Downstream Readiness "For route specialist (webview fonts and `@theme` block)" bullet).
- Custom scrollbar styling: dark background + Earth Blue thumb via Tailwind v4 `scrollbar-*` utilities (do NOT ship default web scrollbars in a desktop app) (per design plan §Anti-Patterns Per-Surface Bans desktop-webview "NEVER use web-style scrollbars without styling").
- Dark mode is the default via `prefers-color-scheme: dark`; light/auto are Settings options persisted to `~/.andromeda-pulse/config.toml` — chunk #24 sets up the initial dark default but does NOT yet ship the toggle UI (deferred to chunk #34 Settings modal form) (per design plan §Surface: desktop-webview Tokens "Dark mode default" bullet + Component Patterns).
- Iconography rule: icons clarify, not decorate — at chrome scale (titlebar) only the aperture settings button + app icon belong; do not introduce decorative icons in window-shell chrome (per design plan §Iconography Rule + §Anti-Patterns Universal Bans "NEVER use color purely for decoration" companion principle).

## Anti-patterns to avoid

- NEVER use generic font families as primary in titlebar text or any chrome label: Inter / Roboto / Arial / Helvetica / Open Sans / Lato / system-ui default / Space Grotesk are explicitly banned; IBM Plex Sans is the locked sans choice (per design plan §Anti-Patterns Universal Bans).
- NEVER ship with OS-default window decorations (system titlebar, OS chrome) coexisting with the custom titlebar — `decorations: false` is mandatory; mixing decorations creates a double-bar artifact (per design plan §Surface: desktop-webview Platform-Specific Notes Windows bullet + Per-Surface Bans desktop-webview).
- NEVER use `alert()` / `confirm()` / `prompt()` for any close-confirmation or minimize-to-tray hint — styled modals only (deferred to chunk #33 Modal primitive scaffold; chunk #24 must NOT introduce native browser dialogs as a stopgap) (per design plan §Anti-Patterns Per-Surface Bans desktop-webview).
- NEVER make the window non-resizable; the compact widget is resizable + the full dashboard is resizable (per design plan §Anti-Patterns Per-Surface Bans desktop-webview "NEVER make the window non-resizable").
- NEVER add entrance/scroll animations or shadows on window-open or focus-restore — chrome motion is state-confirming only, never decorative; entrance animations are explicitly "none" at expression 0.3–0.35 (per design plan §Motion Hard limits + Duration scale "Entrance: none").
