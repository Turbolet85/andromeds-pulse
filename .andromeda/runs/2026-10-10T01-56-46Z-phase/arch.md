## Patterns to follow
- Formalized-CLI-contract rule: a new xtask verb, or a new field on an existing verdict, is one pretty-JSON verdict object on stdout with named arms and exit 0 / 1 / 2, where `cannot-evaluate` is never a pass, and is registered with its implementing file and chunk (per architecture §Occupied Resources → xtask CLI surfaces).
- Reuse the existing harness modules: readiness and settle verdicts live in `xtask/src/harness_ready.rs` over `xtask/src/harness_status.rs`'s `pub(crate)` path, liveness and exit-record helpers; a further reading of how the app ended extends that pair rather than starting a parallel reader (per architecture §Occupied Resources → xtask CLI surfaces).
- Closed labels, never values: the settle verdict's display and session-bus fields are the model for reporting anything read from the runner's environment (per architecture §Occupied Resources → Environment variables).
- The driver pair is registered as sh and ps1 in lockstep over five unchanged verbs; a change to the sh `boot` verb either mirrors into ps1 or the plan states the sh-only departure and why (per architecture §Occupied Resources → xtask CLI surfaces).
- Agent-driven shape: deterministic harness invocations, machine-parseable output, schema-stable contracts; recorded measurements name the run they were read on (per architecture §Cross-cutting Patterns → Development Style).

## Anti-patterns to avoid
- Restoring a non-gating smoke step (`continue-on-error`), or letting an instrument's own failure decide the step's verdict in place of the three registered exit codes (per architecture §Occupied Resources → xtask CLI surfaces).
- Having the production binary write or read a harness state file (`run/andromeda-pulse.spawn`, `run/andromeda-pulse.exit`, `logs/harness-settled.json`) to explain its own end; those are harness-only by registration (per architecture §Occupied Resources → Filesystem locations).
- Closing the cause with a new launch-posture environment default or a webview / GPU flag in product code or `tauri.conf.json`: the product has ONE sanctioned such default and the registry states it licenses no other; a second one is a boundary widening for the founder's word, not a harness fix (per architecture §Occupied Resources → Environment variables).
