## Relevance
**Partial** — no product security surface changes, but the chunk touches four live security-plan boundaries: harness path env vars, Tauri capability grants for window/tray mechanics, obs-field logging bans, and the standing `cargo audit` deferral (PREREQ B).

## Constraints

- **New harness relay env vars stay in the carve-out class and owe a registry row.** The categorical canonicalize-and-confine rule binds *product-binary* `ANDROMEDA_PULSE_*_PATH` / `*_DIR` reads; harness/xtask-only tool-locator vars are guarded instead by trim + `is_file()` + clean skip, with the resolved value never logged (per security-plan §Input Validation → CLI / env var inputs, and §Security Anti-Patterns → Input carve-out). Note the plan-body fact: the env-var row names `ANDROMEDA_PULSE_MSEDGEDRIVER_PATH` and `ANDROMEDA_PULSE_DATA_DIR` but does **not** name the bare xtask→node relay set (`PULSE_BIN` · `PULSE_DATA_DIR` · `MSEDGEDRIVER_PATH` · `PULSE_INJECTOR`), while the row claims to be the complete boundary enumeration (per §Input Validation, per the 2026-08-16 registry-completeness amendment). Whether the existing relay set is already guarded and whether any new var is needed is research's question.

- **A stage that needs a Tauri CORE API or a `core:window:*` permission requires an explicit per-feature capability addition with stated rationale.** Per-procedure capability entries do NOT exist here (TauRPC dispatches through one invoke handler), so the chunk's "no `EXPECTED_PROCEDURES` pin, no capability JSON edit" claim holds only for *new TauRPC procedures*; core-API and `core:window:*` grants ARE silently rejected at runtime when missing (per security-plan §API Security → TauRPC capability authorization, and §Security Anti-Patterns → API). This is precisely the dead-affordance mode the leg's verdict discipline exists to catch, so whether the drag/resize/multi-window/global-shortcut/tray stages need a grant the capability JSON does not carry is research's question.

- **Tray and notification surfaces stay outbound-only.** The tray-lifecycle and close-signpost-toast stages must not widen `pulse:tray` / `pulse:notification` beyond the outbound emit subset; any incoming-event handler (tray menu item wired to invoke IPC, notification action callback re-entering Rust) requires a separately-named capability with stated rationale (per security-plan §Security Anti-Patterns → API).

- **Window-geometry telemetry must not carry coordinate values.** The `<data_dir>/window-geometry.json` boundary mandates bounded integer serde, graceful non-fatal default on a corrupt file, atomic `.tmp`+rename, and that **no coordinate values are logged** (per security-plan §Input Validation → Persisted window geometry row, cross-referencing §Logging). CARRY #1 (position-delta > 0) and CARRY #2 (resize clamp / aspect band) assert exactly over that data, so a stage's obs half must read a derived predicate, not raw x/y/w/h. Whether the existing obs targets already emit coordinates is research's question.

- **PREREQ B is governed by the standing `cargo audit` deferral clause.** Per security-plan §Dependency Security → CI integration (Standing deferral — `cargo audit` unrunnable), the interval is every 3rd wrap with points run at 25/28/31/34/37/40 and the next at 43; between points the chunk must re-verify basis + overlap and the report must record `probe skipped per ratified interval (next: 43)` — **never a silent skip**. The named overlap signal `cargo deny check advisories` still runs every chunk and its owned upgradeable ID set must be **re-enumerated first-hand**, never carried forward (8 IDs at the last probe).

- **New npm devDependencies enter an unscanned channel.** Per security-plan §Dependency Security (MEASURED 2026-08-23), `pulse-app/ui` gets Dependabot version updates but no advisory/license/ban scanning — `cargo audit` / `cargo deny` / `cargo-auditable` all stop at the Rust boundary and `ci.yml` runs `npm ci` with no `npm audit`. Any driver-mechanic dependency added to `webview-drive.mjs`'s package widens a gap with a named route owner; the preferred posture is zero new npm deps, and any addition should be counted (direct + transitive) rather than absorbed silently.

- **Bans on log content apply to every new stage record.** Never log raw OTLP attribute values, snapshot file contents, clipboard contents, MCP tool response bodies, DuckDB query parameter values, or full plugin file paths (per security-plan §Logging & Monitoring → What NEVER to log, and §Security Anti-Patterns → Logging).

## Patterns to follow

- **Harness path-var guard shape** — whitespace-trim + `is_file()` existence check, unset/not-a-file ⇒ clean SKIP (exit 0, prints the fetch recipe) rather than panic or hard fail; only the variable NAME and the fetch URL appear in the skip message, never the resolved value. `ANDROMEDA_PULSE_MSEDGEDRIVER_PATH` is the registered first member of this class (per security-plan §Input Validation → CLI / env var inputs).

- **Registry-completeness-as-routine** — a new external input boundary that is code-validated (bounded parse) *and* unit-tested by rejection name is registered by a routine §Input Validation row addition rather than an escalation. Precedents cited in the plan: `window-geometry.json`, `ANDROMEDA_PULSE_L4_DETERMINISTIC`, `ANDROMEDA_PULSE_BASELINE_BOOTSTRAP_SECONDS` (per security-plan §Input Validation).

- **Capability-rejected IPC calls are a declared security-log event** — the plan lists them under what to log at Minimal tier precisely because Tauri 2 rejects silently (per security-plan §Logging & Monitoring → What to log). A stage's obs half can rest on that record rather than on absence-of-exception, which is the same discipline the scope's verdict rule states.

- **`xtask` is the security enforcement home** — `xtask capability-drift` diffs declared TauRPC procedures against `EXPECTED_PROCEDURES` in `xtask/src/main.rs` and fails CI on mismatch (per security-plan §API Security → TauRPC capability authorization, wired under §Bootstrap phases → `dep-security-ci-gate`). New CLI arms in `xtask/src/webview_drive.rs` land beside that gate; do not perturb it.

- **APPLY-AS-MEASURED disposition** — where the chunk measures a plan claim false (e.g. an unregistered relay var, a capability grant the plan says does not exist), the established handling is to record measured truth plus a named owner in the plan body rather than defer (per the 2026-08-22 / 2026-08-23 amendment precedents).

## Anti-patterns to avoid

- **NEVER grant a Tauri core API (`fs` / `shell` / `dialog` / `http`) or a `core:window:*` permission without an explicit per-feature capability addition with a stated rationale** — those are silently rejected at runtime, which becomes a hard-to-diagnose dead-affordance bug (per security-plan §Security Anti-Patterns → API).
- **NEVER widen `pulse:tray` or `pulse:notification` beyond the outbound emit subset** — granting webview-side input handlers converts an outbound surface into a phishing / IPC-abuse vector (per security-plan §Security Anti-Patterns → API).
- **NEVER read a product-binary `ANDROMEDA_PULSE_*_PATH` / `*_DIR` env var without canonicalize-and-confine** — the carve-out is scoped to exactly harness-only, not-production-consumed, existence-guarded vars and nothing wider (per security-plan §Security Anti-Patterns → Input).

## Contract bindings

- **security ↔ tests (CI gate):** the security CI gate (`cargo audit` + `cargo deny check bans licenses sources` + `Cargo.lock` integrity + capability-drift + `harden-runner`) is security's, wired as jobs in the single `ci.yml` (per security-plan §Bootstrap phases → `dep-security-ci-gate`). The chunk's boundary declines wiring this leg into CI, so no new gate obligation attaches — and correspondingly nothing this leg proves is CI-enforced. If any workflow file *is* touched, the SHA-pinning ban (§Security Anti-Patterns → Secrets: never `@v2` / floating tag, 40-char SHA only) attaches immediately.
- **security ↔ obs (allowlist leaves):** any new obs target/field a stage needs must satisfy the §Logging & Monitoring NEVER-log list and the no-coordinate-values rule before it becomes an obs-plan allowlist leaf; PII scrubbing cross-cuts to obs.
- **security ↔ arch (registry):** a new xtask→node relay var needs registration in arch §Occupied Resources *and* a §Input Validation boundary row on the security side — the two registries are separate obligations.
