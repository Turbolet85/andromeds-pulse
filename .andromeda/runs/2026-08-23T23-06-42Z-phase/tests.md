# tests extract

## Relevance
Relevant — this chunk is test infrastructure itself (E2E headful leg extension + flake ownership + selector re-point), so nearly all of the domain's E2E/harness/quality-gate mandates bind directly.

## Constraints
- **Verdict must come from a positive signal, two halves.** test-plan §6 E2E → Drivers per surface requires the leg's assertions to live in Rust (`xtask/src/webview_drive.rs`) reading BOTH the app's obs log and the driver's `webview-drive-stages.json`, reported as `StageHalves{obs,dom}` (`None` = inapplicable), with every stage predicate matching an effect **FIELD**, never the target alone. Also per §2 Agent-runnable invariants: the driver reports, only the Rust caller asserts. Each new stage in this chunk owes a predicate of that shape.
- **Headful is in scope only while agent-driven.** test-plan §2 Agent-runnable invariants scopes the ban to the human-in-the-loop half — a person confirming a result, or an eyeballed screenshot, is still banned. The window-mechanics CARRYs (drag delta, resize clamp, multi-window disclosure) must therefore resolve to a machine-readable record, not an operator observation.
- **Selector strategy is accessible-name-first, measured at HEAD.** test-plan §6 E2E → Selector strategy requires accessible name where one ships, `data-testid` only where none does, never xpath and never a hashed/utility class; it further requires measuring the selector at HEAD before pinning **and** measuring a claimed ABSENCE against the component that actually owns the surface. The same section already records the Traces anchors (`region[aria-label="Telemetry traces chart"]`, native `table` with `.trace-row`, `data-testid="constellation-summary"`) and states its leg selectors "should migrate off `data-testid`" — this chunk's CARRY #9 is that owed migration.
- **Zero-flakiness is a budget, not a tolerance.** test-plan §10 Quality Gates → Zero-flakiness budget requires: quarantine on the first flake, root-cause investigation (explicitly *not* a retry budget), then fix-or-delete before unquarantining. Whatever "owning the flake" resolves to at P4, a retry policy or a longer wait is not an admissible resolution (§11 → Quality, §11 → E2E).
- **Every chunk owes the standard gate set unconditionally.** test-plan §3 → Per-chunk gate discipline requires `cargo fmt --check` + `cargo clippy --workspace --all-targets --all-features -- -D warnings` + `cargo nextest run --workspace --profile ci` + `cargo xtask capability-drift` + `cargo xtask capability-widening-check`; the webview gates (`npm run lint` / `typecheck` / `test --prefix pulse-app/ui`) are excluded ONLY when zero `pulse-app/ui/**` paths are touched — this chunk names `pulse-app/ui/tests-e2e/webview-drive.mjs`, so they apply. This is also where scope's PREREQ A lands.
- **A green exit code is not evidence the leg ran.** test-plan §6 driver row + §9 CI → E2E stage require treating an unset `ANDROMEDA_PULSE_MSEDGEDRIVER_PATH` as a clean SKIP (exit 0); evidence of record is the per-stage report. Any acceptance claim for a new stage must cite the report, not the exit code.
- **Narrow a `pulse-app` run under `--workspace`, not `-p`.** test-plan §3 → `run` (Test selection) records the measured constraint: run-scope must match build-scope, or the pulse-app test binaries fail to link (`crate X required to be available in rlib format`).

## Patterns to follow
- **`STAGES` entry + `stage_halves` arm + driver step**, with the driver emitting `record(stage, observed, detail)` and asserting nothing — the shipped shape per test-plan §6 Drivers per surface; the scope's verified seam coordinates match it.
- **Telemetry enters only over real OTLP.** test-plan §6 driver row + §7 Self-bootstrapping requirement: seed via `crates/ingest/examples/inject_demo.rs` (built outside the timed section, invoked by path) with `ANDROMEDA_PULSE_L4_DETERMINISTIC` set into the *driver's* spawn env because the app is a grandchild process. No pre-baked fixture data (§1 `agent-driven-discipline: Self-bootstrapping test data`).
- **Colocated `#[cfg(test)] mod tests` for new xtask predicates/readers** per test-plan §4 → Conventions → Test file location (Rust); §1 `webview-drive-msedgedriver-resolver-unit-coverage` records the module already carrying 27 colocated tests around its stage predicates, `read_stage_report` and the `dom_*` readers as the precedent to extend.
- **Wait on an explicit signal, never a sleep** — test-plan §3 `boot` readiness (poll a signal to a bounded timeout) and §11 → E2E; directly applicable to the `launch` race, where §6's flake note already records that a longer wait cannot fix it (50s elapses in failing runs; toggle recovery 0/10).
- **Measure-first RED legs scope their clean-log assertion to the GREEN leg only** — test-plan §3 → Direct-binary smoke variant: a RED arm must produce the ERROR it measures, each leg gets its own fresh data dir, and the RED leg records its expected ERROR as evidence rather than a gate failure.

## Anti-patterns to avoid
- **NEVER xpath, NEVER a hashed/utility CSS class** — test-plan §11 → E2E, both marked operative since `2026-08-23-integration-ux-e2e-test` now that a DOM-driven leg exists.
- **NEVER `sleep(N)` for synchronization; NEVER visual regression or any human-approved screenshot** (Percy / Chromatic / Applitools) — test-plan §11 → E2E and §11 → Universal; canvas pixel inspection stays out of scope.
- **NEVER auto-retry or leave a flake un-quarantined; `#[ignore]` is reserved for flake quarantine and needs a tracked reason** — test-plan §11 → CI + §11 → Quality, §10 Load profiles note.

## Contract bindings
- **tests ↔ obs** — the leg's obs half reads the app's own log, so it binds to the obs-plan log format via test-plan §3 → Log format / Bootstrap item 4 (`log-format-bind-with-obs`) and to the target allowlist: scope states a new stage asserting a not-yet-existing target needs an obs-plan allowlist leaf. Whether each CARRY's intended target + field is already permitted is research's question.
- **tests ↔ a11y** — the Traces re-point consumes the anchors the a11y chunk made load-bearing; test-plan §6 Selector strategy and §1 `traces-surface-a11y-semantics-absent` (LANDED) name the re-point as the one still-owed half, so that a future a11y regression reddens this leg.
- **tests ↔ security** — `ANDROMEDA_PULSE_MSEDGEDRIVER_PATH` is explicitly carved out of the product-binary canonicalize+confine ban as a harness/xtask-only tool-locator var, guarded instead by trim + `is_file()` + clean skip (test-plan §1 path-canonicalization row).
- **tests ↔ arch** — capability JSON: test-plan §1 `webview-drive-mutation-arm-not-gated` records that neither `capability-drift` (parses procedures from `bindings.ts`, never reads grants) nor `capability-widening-check` (3 NEVER-widen caps, widening direction only) would catch a left-revoked grant; a capability-revoke RED arm therefore rests on discipline, and the owed staged-copy assertion over `pulse-app/capabilities/*.json` is CARRY'd elsewhere. Note also test-plan §3 → Boot-smoke gate lists `pulse-app/capabilities/*.json` as a trigger path — whether a revoke/restore cycle counts as touching it is a P4 call.

## Acceptance criteria contributions
- (tests) The full standard gate set passes — `cargo fmt --check`, `cargo clippy --workspace --all-targets --all-features -- -D warnings`, `cargo nextest run --workspace --profile ci`, `cargo xtask capability-drift`, `cargo xtask capability-widening-check`, plus `npm run lint` / `typecheck` / `test --prefix pulse-app/ui` since `pulse-app/ui/**` is touched (per test-plan §3 Per-chunk gate discipline).
- (tests) Each new stage is evidenced by its `webview-drive-stages.json` / obs-log record with BOTH applicable halves observed and a field-level predicate — never a non-throwing press and never a bare exit code (per test-plan §6 E2E → Drivers per surface + §2 Agent-runnable invariants).
- (tests) Each new stage is mutation-checked in both directions: GREEN observes, and a RED arm that still finds and presses the control produces no record (per test-plan §6 Scenario P5 Status, which records the telemetry-suppression arm as code and the capability-revoke arm as still-by-hand).
- (tests) Any `launch`-flake resolution is a root-cause or a deterministic signal, with no retry policy, no added `sleep`, and no un-tracked `#[ignore]` (per test-plan §10 Zero-flakiness budget + §11 E2E/Quality).
