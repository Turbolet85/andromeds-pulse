# arch extract

## Relevance
Relevant — this chunk lands Rust in the reserved `xtask` crate plus the dev-only webview driver, and every affordance it asserts sits on an arch-governed capability, env-var or filesystem resource.

## Constraints
- **Workspace placement is fixed and dev-only.** The leg's Rust half belongs in the reserved workspace member `xtask`; its driver half is a `pulse-app/ui` npm devDependency surface (`@crabnebula/tauri-driver` 2.x + `webdriverio` 9.x, win32 native driver via the napi optional dep — no `cargo install`, no Rust dependency). The harness must stay devDeps-only with no runtime/bundle impact (per architecture.md §Occupied Resources → Cargo workspace crate names; §Stack and Technologies → GUI verification harness (dev-only)).
- **The sanctioned invocation is `cargo xtask webview-drive [flags]`.** All shared Rust harness logic lives in the `xtask` crate so contributors and agents run identical commands locally; new stages extend that one surface rather than adding a sibling entrypoint (per architecture.md §Infrastructure Patterns → CI/CD approach; §Cross-cutting Patterns → Development Style — deterministic harness invocations, machine-parseable outputs).
- **Telemetry may enter only over real OTLP.** Any new stage needing spans/metrics/logs must speak OTLP to the running receiver (the leg's registered route is `crates/ingest/examples/inject_demo`); no in-process bypass, no "test ingest" feature flag, no mock-channel back-door. Non-default ports resolve via `ANDROMEDA_PULSE_OTLP_GRPC_PORT` / `_HTTP_PORT`; buffer read-back goes through the `traces.*` / `metrics.*` / `logs.*` routers (per architecture.md §Cross-cutting Patterns → Test-time telemetry injection; §Stack → GUI verification harness row).
- **Capability granularity governs every window-mechanics affordance in this chunk.** Arch requires that Tauri capabilities stay negative-default at the **IPC layer**, with no per-procedure entries in `pulse-app/capabilities/` — but each `core:window:*` permission a frameless-window affordance needs (`allow-start-dragging`, `allow-close`, `allow-set-size`, `allow-set-position`, …) must be granted individually, and those **are silently rejected at runtime when missing**. That silent-rejection class is precisely the drag / resize / per-window-close / multi-window-docking set this chunk asserts, and it is the correct lever for the RED mutation arm. Whether each needed grant is already present in `pulse-app/capabilities/default.json` is research's question (per architecture.md §Cross-cutting Patterns → Webview IPC capability policy).
- **Env-var namespace discipline.** The registered harness-only set is `ANDROMEDA_PULSE_MSEDGEDRIVER_PATH` (xtask-side; whitespace-trimmed + `is_file()`-guarded; unset / not-a-file must SKIP clean at exit 0 printing the fetch recipe, never hard-fail; deliberately exempt from canonicalize-and-confine) plus the xtask→node relay set `PULSE_BIN` · `PULSE_DATA_DIR` · `MSEDGEDRIVER_PATH` · `PULSE_INJECTOR`. `PULSE_*` is a claimed prefix where a collision would be silent, so any new relay var must be registered in §Occupied Resources at wrap (per architecture.md §Occupied Resources → Environment variables).
- **Window geometry is a registered data-dir artifact.** Arch registers `window-geometry.json` (Rust-owned map of window label → integer x/y, atomic `.tmp`+rename, written on window-move and restored at boot) under the resolved data-dir root, which `ANDROMEDA_PULSE_DATA_DIR` / the `PULSE_DATA_DIR` relay redirects. A drag-delta or boot-geometry stage that asserts persistence must read it under the harness's temp root, never the operator's real root (per architecture.md §Occupied Resources → Filesystem locations).
- **Multi-window disclosure has a contracted event mechanism.** `findings:dismissed` / `report:open` (`{incidentId}`) / `report:closed` are registered as a distinct class from `pulse://stream/*` — first-party webview↔webview events via `@tauri-apps/api/event`, gated by `core:event` in `pulse:default`, carrying no telemetry. Window labels are deliberately NOT arch-registered resources (per architecture.md §Occupied Resources → Tauri IPC events → Cross-window UI-coordination events).

## Patterns to follow
- **Two-sided stage verdict.** Arch's own description of the sanctioned harness is per-stage assertion against the app's obs log and/or the driver's DOM report, with `--no-inject --expect-absent <STAGE>` as the code-driven RED arm — new stages should be shaped by that same contract rather than by press-did-not-throw (per architecture.md §Stack → GUI verification harness row).
- **Clean-SKIP guard for host-provided prerequisites.** The `ANDROMEDA_PULSE_MSEDGEDRIVER_PATH` shape (trim → `is_file()` → SKIP at exit 0 with the fetch recipe) is the in-repo precedent for any new host-side prereq a stage needs (per architecture.md §Occupied Resources → Environment variables).
- **Harness-only env-var registration.** New vars follow the `_PIDFILE` / `_LOGFILE` / `_DATA_DIR_KEEP` class ("NOT consumed by the production binary"), and relay vars register as a *set* rather than one-at-a-time (per architecture.md §Occupied Resources → Environment variables; amendment 2026-08-23-integration-ux-e2e-test).
- **Deterministic-L4 gate for reproducibility.** `ANDROMEDA_PULSE_L4_DETERMINISTIC` is the registered truthy gate the driver sets into the *spawned app's* environment; arch also records that the canned fixture's populated arrays are load-bearing for gradeability, while `trace_id` / `span_ids` / `timestamps_unix_nano` stay empty in every mode — so an absence assertion on those passes for the wrong reason (per architecture.md §Occupied Resources → `ANDROMEDA_PULSE_L4_DETERMINISTIC`).
- **Config precedence.** Env vars > `config.toml` > built-in defaults — a stage that needs the app in a particular state should reach for the registered env layer before touching config files (per architecture.md §Cross-cutting Patterns → Config management; §Inherited Defaults).

## Anti-patterns to avoid
- **No in-process test bypass.** No mock channel, no test-mode feature flag, no direct buffer poke to make a stage green — the OTLP surface is the only injection route (per architecture.md §Cross-cutting Patterns → Test-time telemetry injection).
- **No per-procedure capability JSON edit.** Those entries do not exist under the IPC-layer granularity; the only legitimate capability lever here is a core-API / `core:window:*` grant, and adding a TauRPC procedure (which this chunk states it does not) would instead require an `EXPECTED_PROCEDURES` pin (per architecture.md §Cross-cutting Patterns → Webview IPC capability policy).
- **No unregistered resource landing silently.** A new relay var, a new data-dir file, or a stage-set change to the harness leaves the registry stale — arch requires registration at wrap (per architecture.md §Occupied Resources; §Stack → GUI verification harness row).

## Contract bindings
- **arch ↔ tests** — the §Stack GUI-verification-harness Role cell is arch's only statement of what the sanctioned harness does; changing the stage set or the CLI flags obliges an amendment at wrap (direct precedent: amendment 2026-08-23-integration-ux-e2e-test re-scoped that same cell).
- **arch ↔ obs** — a stage's obs half reads the app's own log; a target with no existing allowlist leaf needs one from the obs plan. Arch's constraint on that boundary: `telemetry.frontend.*` is the only sanctioned route for delegated-timing observables, and a leaf-less `metric.*` target keeps `value` while every label is silently redacted (§Occupied Resources → Tauri IPC routes).
- **arch ↔ security** — `ANDROMEDA_PULSE_MSEDGEDRIVER_PATH` is an explicit carve-out from the canonicalize-and-confine-under-data-dir rule, cross-referenced to security-plan §Input Validation; any new harness path var inherits that carve-out only by being harness-only (§Occupied Resources → Environment variables).
- **arch ↔ design/a11y** — webview source-file conventions and the accessible name/role anchors the selector re-point targets are owned by those specialists; arch constrains only that the driver stays in the devDep surface (§Conventions → File naming).
- **arch ↔ CI** — arch's `ci.yml` step list (fmt → clippy → `cargo xtask test` → build) does not include this leg; PREREQ A's `cargo clippy --workspace --all-targets --all-features -- -D warnings` is the arch-mandated lint gate that a Rust-touching chunk must satisfy (§Infrastructure Patterns → Build system, CI/CD approach).

## Acceptance criteria contributions
- (arch) All new harness code lands in the reserved `xtask` crate and the `pulse-app/ui` devDependency surface; no new workspace crate, no new runtime dependency, no bundle-size delta (per architecture.md §Occupied Resources → Cargo workspace crate names; §Stack → GUI verification harness (dev-only)).
- (arch) Any telemetry a new stage requires enters over real OTLP via the injector binary — no in-process bypass, no test-mode feature flag, no mock channel (per architecture.md §Cross-cutting Patterns → Test-time telemetry injection).
- (arch) Each RED mutation arm neutralises a core-API / `core:window:*` grant (the silently-rejected class) rather than a per-procedure capability entry, and no `EXPECTED_PROCEDURES` pin or capability-JSON edit is required by this chunk's own surface (per architecture.md §Cross-cutting Patterns → Webview IPC capability policy).
- (arch) Every new env var is registered in §Occupied Resources at wrap — including any addition under the claimed `PULSE_*` relay prefix — and the §Stack harness Role cell is amended to the extended stage set (per architecture.md §Occupied Resources → Environment variables; §Stack → GUI verification harness row).
