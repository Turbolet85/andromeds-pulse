## Constraints
- The Traces re-point must bind to the anchors the plan makes load-bearing: `region[aria-label="Telemetry traces chart"]` on the **WebGPU canvas wrapper** (`ConstellationCanvas`, a SIBLING of `TraceTable`) and the trace list's **native `table`** role — a11y-plan §1 Critical paths P1 names "the headful leg's `trace-table` / `trace-row` / `trace-table-empty` handles … their re-pointing is the one half still owed", and §1 P1 permits accessible-name-first binding "per the measured-per-surface convention".
- The region's accessible name is a **stable literal, deliberately not the live summary** — the live aggregate lives in a visually-hidden `aria-describedby` target (`constellation-summary`, aggregate counts only, no service names) and `role="status"` on it is a ratified omission (per a11y-plan §7 Landmark roles; scope §Boundaries re-states the `role="status"` ratification).
- Any Traces keyboard step drives the **row-level** contract, not cell traversal: one tab stop per `<tr>` via roving `tabindex` (`0`/`-1`, never `> 0`), Up/Down/Home/End move row focus, Enter activates the focused row's Investigate, Esc exits to the Errors-only toolbar, and scroll-into-view stays inside the table's own scroll region (per a11y-plan §5 full-dashboard-traces + §11 Keyboard grid-lite carve-out). This last clause is the direct a11y stake in CARRY #5 (`trace-table-scroll`).
- P5's controls are named by accessible name in the plan: `button[aria-label="Toggle dashboard"]` (opens/hides the dashboard; **the widget always stays visible**), `button[aria-label="Minimize"]`, `button[aria-label="Close to tray"]` (the titlebar ✕; **Esc also triggers it**), plus the Cmd/Ctrl+Shift+P binding in both windows (per a11y-plan §1 P5 + §5 compact-widget).
- The findings/report windows carry a cross-window focus contract: focus enters the findings panel on open (first incident row), Tab cycles rows → "Mark all as read", and Esc / blur / mark-all-read dismiss with restoration **across windows via first-party Tauri events, not focus-trap-react**; report is `role="dialog"` with Esc/✕ returning to findings (per a11y-plan §5 findings-window / report-window + Focus restoration).
- Resize/geometry stages (CARRY #2, #5) carry **no reflow obligation**: SC 1.4.10 Reflow and SC 1.4.4 Resize Text are recorded non-applicable (desktop-only Tauri, stable viewport) per a11y-plan §1 "SCs explicitly not applicable".
- A headful drive is **not** the a11y gate and does not substitute for it: WCAG evidence must be machine-verifiable axe-core / Lighthouse / pa11y JSON via `npm run test:a11y` in `ci.yml` (per a11y-plan §3 CI integration + §9 + §11 CI/Universal). The chunk's decision not to wire its leg into CI is orthogonal to that standing gate.

## Patterns to follow
- **Verify a claimed absence against the component that actually owns the surface** before pinning a selector — the prior NOT-SHIPPED claim checked `TraceTable.tsx` for a landmark that lives in `ConstellationCanvas.tsx` (per a11y-plan §7 Landmark roles note; amendment 2026-08-23-a11y-verification). Whether the shipped `<section>` name at HEAD is exactly the literal `Telemetry traces chart` is research's question, not something this extract can attest.
- **Keyboard sequences per ARIA pattern** for any stage that presses a control: Button = Enter/Space; Dialog = Escape closes + Tab cycles within trap; Menu = Arrow Up/Down + Enter + Escape; Switch = Space (per a11y-plan §3 Keyboard test harness).
- **Focus assertion by capture-after-press**: press key → read `document.activeElement` → assert against the expected sequence (per a11y-plan §3 Focus management test harness / Keyboard test harness).
- **Structured violation JSON shape** if any stage emits an a11y-shaped defect record: `wcag_criterion` / `violation_type` / `severity` / `surface` / `selector` / `remediation` / `tool` / `tool_result_id` (per a11y-plan §3 Structured violation JSON schema).

## Anti-patterns to avoid
- NEVER bind a landmark selector to a name that varies with data, or assert the live summary text as the region's accessible NAME — a landmark whose name churns thrashes the SR rotor (per a11y-plan §7 Landmark roles).
- NEVER treat "the control was found and pressed" as WCAG evidence — no conformance claim without machine-verifiable tool JSON (per a11y-plan §11 Strategy + Universal). This coincides with, but does not replace, the chunk's own obs/DOM verdict discipline.
- If the re-point tempts a markup change to make a control findable, NEVER add `tabindex > 0` or a second reachable tab stop inside a row — the in-row Investigate stays `tabIndex={-1}` (per a11y-plan §11 Keyboard grid-lite carve-out).

## Contract bindings
- **a11y ↔ obs**: a11y violation JSON binds to obs §6 field names (a11y-plan §3). The leg's own `webview-drive-stages.json` is harness-internal and per-run (the prior chunk recorded `D-a11y-obs-schema` clean on exactly this shape); if a new stage asserts an a11y-shaped record instead, it inherits the §3 field contract.
- **a11y ↔ tests**: a11y's focus/keyboard harness reuses tests' E2E driver and 5-command discipline (a11y-plan §3 Focus management test harness "Contract binding"); the a11y CI step lives in the same `ci.yml` as tests E2E (§9).
- **a11y ↔ design**: row and widget-button focus must show the `--border-focus` ring on `:focus-visible`, ≥ 3:1 non-text contrast (a11y-plan §6 Focus ring tokens; SC 2.4.7 + SC 1.4.11).
- **a11y ↔ layouts**: per-surface focus order for compact-widget / full-dashboard-traces / findings / report (a11y-plan §5).
