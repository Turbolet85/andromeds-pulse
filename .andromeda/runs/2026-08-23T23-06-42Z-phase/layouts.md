## Constraints
- The compact widget's custom frameless titlebar is a flex row `[app-icon + title | grow | settings-button | window-controls]` with the drag region spanning full width except the buttons (Tauri 2 `data-tauri-drag-region`) — CARRY #1's drag stage must press inside that drag region, not the control cluster (per layout-templates §Component — Custom titlebar).
- The compact widget is a FIXED quarter-screen glance surface with no CSS media-query breakpoints; it is user-resizable but the layout does not reflow (per layout-templates §IA notes — Responsive behavior). CARRY #2's resize-clamp stage therefore asserts window-geometry clamping, not a layout reflow; whether the shipped aspect band (1.4–2.1) is itself layout truth is not something the plan states — the plan mandates only "fixed quarter-screen, no reflow".
- The Traces primary screen is required to be a flex column bounded to the shell's `main` height (`calc(100vh − titlebar 32px − tabnav 40px − footer var(--spacing-lg))`, `overflow:hidden`) so the dashboard shows NO outer page scrollbar at any window size, with hero + `Errors only` toolbar fixed (`flex-shrink:0`) and only the table's own region scrolling (`flex:1 / min-height:0 / overflow-y:auto`, sticky opaque `color-base` thead) — per layout-templates §Wireframe — Full dashboard (Traces primary screen) and §Component — Trace data table (Internal scroll region). CARRY #5's "across a couple of window sizes" stage is exactly this mandate's assertion.
- The constellation hero is required to be a landmark `<section>` carrying the STABLE literal accessible name `"Telemetry traces chart"`, described by a visually-hidden `data-testid="constellation-summary"` via `aria-describedby` (per layout-templates §Wireframe notes — Traces). The selector re-point (CARRY #9) must target that literal stable name; a name that tracks data is banned, so the leg may hardcode the string.
- The full-dashboard footer is required to carry the dashboard-only plain-language `ConnectionStatusLine` — connected-source count ("Receiving from {N} services"), spans/s, buffer fill ("buffer {used} min / {window} min"), live-updating on a 1s poll — while the compact widget stays aggregate-glance with NO worded line (per layout-templates §Component — Footer). CARRY #7's stage must assert the line on the dashboard surface only; asserting it on the widget would contradict the plan.
- The `findings` window is required to be a separate borderless always-on-top window docked directly below the compact widget, positioned from the widget's LIVE geometry with work-area/multi-monitor clamping, sizing itself to the incident count (fits rows, caps ~8 then scrolls); the `report` window is the `Modal` `fill` variant positioned left of findings and clamped (per layout-templates §Primary screens — Findings window / Report window). CARRY #6's multi-window docking-geometry stage inherits those positioning invariants as its geometry oracle.
- The compact widget → full dashboard transition is the specified navigation move (expand via the Settings/toggle affordance or a keyboard shortcut, suggested `Cmd+Shift+P` / `Ctrl+Shift+P`), and `Esc` minimizes the widget to tray (per layout-templates §IA notes — Navigation model + Keyboard shortcuts). CARRY #4's toggle stage asserts that IA move across both entry paths.

## Patterns to follow
- Region-and-role anchoring over testids: the plan already names the load-bearing accessible anchors (hero landmark region + its stable name, native `<table>`, `.trace-row` rows as the roving-tabindex single tab stop) — re-point the leg onto those named structures so a layout/a11y regression reddens the drive (per layout-templates §Wireframe notes — Traces, §Component — Trace data table Keyboard/focus).
- Fixed-vs-scrolling region split: hero and `Errors only` toolbar fixed above, table body scrolling internally — any resize-stage assertion should read the table's own scroll region rather than the page (per layout-templates §Component — Trace data table).
- Row-level (not cell-level) traversal contract for the table: exactly ONE tab stop, Up/Down/Home/End, Enter investigates, Esc returns to the `Errors only` toggle, in-row Investigate is `tabIndex={-1}` — any driver step that "presses Investigate" must go through Enter-on-focused-row or click, never Tab-to-button (per layout-templates §Component — Trace data table Keyboard/focus, §Component — Investigation modal Trigger).
- OS-native notification format for the close-to-tray signpost: terse 1–2 word title, ≤2-line body, fired on window-close-to-tray gated on `notifications_enabled` (per layout-templates §Component — Notifications trigger #4). Note the plan's own wording still says "fires ONCE per session"; the chunk reports shipped behavior as every-time — whether plan text or code is the stale side is research's question, and reconciling it may need a layouts amendment rather than silent divergence.
- Sketch-lag handoff pattern: ASCII wireframes are explicitly allowed to lag current truth with a recorded handoff note (Traces footer row, per-dot labels, findings/report windows) — so any layout discrepancy this chunk observes should be filed as a targeted touch-up, not fixed in passing (per layout-templates §Wireframe notes — Traces, §Primary screens — Findings window).

## Anti-patterns to avoid
- Do not let a hero-region assertion depend on a data-derived accessible name — the landmark name is deliberately static and `role="status"` on the summary is deliberately NOT applied (per layout-templates §Wireframe notes — Traces; also ratified OFF by the operator in this chunk's Boundaries).
- Do not assert the Halo State Pulse canvas as a rendering surface on either webview surface: layout-templates marks it SPECIFIED-BUT-UNBUILT (measured 2026-08-21), with the constellation DOT hue as the live signature — a stage keyed to a halo canvas would pass vacuously or fail on spec, not on behavior (per layout-templates §Component — Halo State Pulse canvas).
- Do not introduce a worded connection-status readout, breakpoint-driven reflow, or per-view chrome onto the compact widget while driving it — the widget is fixed-size, aggregate-glance, minimal chrome (per layout-templates §IA notes — Responsive behavior, §Component — Footer).

## Contract bindings
- **Hero landmark region + trace-row focus order → a11y plan.** The stable name `"Telemetry traces chart"`, the `aria-describedby` summary, and the roving-tabindex single-tab-stop row list are jointly owned with a11y (§Focus Order SC 2.4.3 / grid-lite carve-out cited inside layout-templates §Component — Trace data table). The selector re-point (CARRY #9) is the seam where the leg binds to that shared contract.
- **Modal `fill` variant → design tokens.** The report window's `fill` Modal (edge-to-edge on `--color-base`, no backdrop) is a layout structure whose surface token is design-owned (per layout-templates §Primary screens — Report window).
- **New stage records → obs plan.** Layout-owned assertions land as obs-log records; per the chunk scope, any obs target that does not yet exist needs an obs-plan allowlist leaf — the layout side supplies WHAT region/geometry is asserted, obs owns whether a field is permitted.
- **Findings/report geometry → window-mechanics (arch/routes).** Layout mandates the docking relationship (findings below widget from live geometry, report left of findings, both clamped); the actual multi-monitor/work-area clamp implementation is arch-owned.
