Relevant — the chunk sits on the locked `ingest`→`buffer` channel decision, the `health`/`ready` Standard Contracts that already declare this exact condition, and the obs-allowlist/registry rules any new observable must satisfy.

## Constraints
- The ingest→appender hand-off substrate is LOCKED to a bounded `tokio::sync::mpsc` (backpressure absorbs bursts) with `tokio::sync::broadcast` for buffer→subscriber fan-out; `crossbeam-channel` is a recorded rejection, per architecture.md §Established Decisions [In-Process Channel Architecture] + §Inherited Defaults → Channels. A fix may not swap the substrate or unbound the channel — consistent with the scope's "no new backpressure policy" boundary.
- Code for this seam must live in the already-reserved workspace crates (`ingest`, `buffer`, `pulse-app`); the crate-name list is reserved at workspace level and cannot be reused, per architecture.md §Occupied Resources → Cargo workspace crate names. No new crate is implied by either deliverable.
- Dependency direction is a DAG rooted at `pulse-app`: no library crate may depend on the binary crate, per architecture.md §Cross-cutting Patterns → Module dependency direction. A detector that must read the ingest-side and buffer-side counters *together* (deliverable B) therefore belongs in `pulse-app` — which already owns both heartbeat emitters — or must be fed upward from the crates, never by `buffer` reaching into `pulse-app`.
- The subsystem-degradation surface already exists in contract form: architecture.md §Standard Contracts requires `health` to carry `subsystems.ingest_channel` / `subsystems.buffer` with `status: "degraded"` and a failure-reason string, and `ready` to carry `checks.ingest_mpsc_capacity_pct` + `checks.rows_ingested`. Deliverable B's "reads them together and says so" maps onto a declared contract rather than a new surface. **Whether the running code ever sets `degraded` when the consumer wedges is research's question** — the plan states the envelope, not the emitter's behaviour.
- Any new observable field must carry its OWN exact obs-allowlist leaf: architecture.md §Occupied Resources → Tauri IPC routes (delegated-timing entry) requires this because a bare prefix key keeps `value` and silently redacts every label. This makes the scope's `[inferred]` allowlist premise an arch mandate, not an inference.
- Self-observation is one-way: architecture.md §Established Decisions [Self-Observation] + §Cross-cutting Patterns → Self-observation discipline require the app's own record to go to the stdout/file exporter under `logs/` and forbid pointing an OTLP exporter at the product's own `:4317`/`:4318`. A stall observable must not be emitted as OTLP back into the receiver it is watching.
- Any threshold knob the observable needs is a registered resource: architecture.md §Occupied Resources → Environment variables is canonical for env vars, §Cross-cutting Patterns → Config management fixes precedence (env > `config.toml` > defaults), and §Conventions → Configuration units requires durations in seconds with the unit in the field name (`*_seconds`).

## Patterns to follow
- **Degraded-envelope reporting** — `health` returns per-subsystem strings that become the failure reason, and `ready` returns per-check reason strings (architecture.md §Standard Contracts). This is the in-repo shape for "a subsystem stopped", already covering `ingest_channel` and `buffer`.
- **Boot-resolved bounded env override** — the `ANDROMEDA_PULSE_BASELINE_BOOTSTRAP_SECONDS` entry (architecture.md §Occupied Resources → Environment variables) is the precedent: resolved once at boot, bounded parse, every rejection falls back to a default without panicking, one WARN per boot on a non-default value, env-layer-only so no TauRPC/hot-reload delta.
- **Exact-leaf observable registration** — the `telemetry.frontend.*` delegated-timing trio (architecture.md §Occupied Resources → Tauri IPC routes) shows a target-per-leaf registration with bounds on each input.
- **Crate contract module** — architecture.md §Project Intent → Template patterns and §Conventions → Module visibility discipline: any new type is exposed only through the owning crate's contract module, `pub(crate)` internals, `thiserror`-derived error enum.
- **xtask as the task surface** — architecture.md §Infrastructure Patterns (all shared logic that needs Rust lives in `xtask`) + §Cross-cutting Patterns → Development Style (agent-driven, deterministic harness invocations, machine-parseable output). If deliverable B lands the first *mechanical* feed check, arch puts its entry point under `cargo xtask <task>`.

## Anti-patterns to avoid
- No in-process test bypass to prove draining: architecture.md §Cross-cutting Patterns → Test-time telemetry injection bans a test-mode ingest flag, mock-channel back-door, or any path other than real OTLP on `:4317`/`:4318`, with non-default ports resolved via the two registered port env vars.
- No new workspace crate and no reuse of a reserved crate name for a stall detector (architecture.md §Occupied Resources → Cargo workspace crate names; §Project Intent).
- No unregistered resource: an env var, IPC procedure, event topic, or `health`/`ready` envelope field that lands without a §Occupied Resources / §Standard Contracts entry is registry drift (architecture.md §Occupied Resources; precedent set repeatedly in the amendment history).

## Contract bindings
- **arch ↔ obs** — arch fixes the single in-memory `pulse_buffer` `:memory:` DuckDB identity (§Occupied Resources → DuckDB database / schema names), which is what makes `Connection::try_clone()` the isolation mechanism the obs-plan §10 invariant the scope cites is written against; obs owns the target names and allowlist leaves, arch requires each new target to have its own exact leaf (§Occupied Resources, delegated-timing entry).
- **arch ↔ tests** — if the observable becomes a harness-enforced check, it lands in `xtask` (§Infrastructure Patterns) under the OTLP-only injection rule (§Cross-cutting Patterns). Note the §Stack GUI-verification-harness row is arch's ONLY statement of the assembled stage list and of the injector's CLI contract, so adding a stage or threading an injector argument (e.g. `--sustained`) into `PULSE_INJECTOR` is an arch amendment.
- **arch ↔ security** — a new env var registers in §Occupied Resources → Environment variables; its confinement/parse posture is recorded on the security side, per the pattern noted on the `_LLAMA_*_BIN_PATH` / `MSEDGEDRIVER_PATH` entries.
- **arch ↔ IPC surface** — if the observable reaches the webview, the gate is a router registration + §Occupied Resources entry + the `EXPECTED_PROCEDURES` pin in `xtask/src/main.rs`, **not** a capability-JSON edit (§Cross-cutting Patterns → Webview IPC capability policy).

## Acceptance criteria contributions
- (arch) Changes land only in `crates/ingest`, `crates/buffer`, `pulse-app` (and `xtask` if a task surface is added); no new workspace crate, no reserved-name reuse, and no library crate gains a dependency on `pulse-app` (per architecture.md §Occupied Resources → Cargo workspace crate names + §Cross-cutting Patterns → Module dependency direction).
- (arch) The ingest→appender hand-off remains a bounded `tokio::sync::mpsc`; no channel-substrate swap, no unbounded channel, and `try_send` saturation still surfaces as `ResourceExhausted` (per architecture.md §Established Decisions [In-Process Channel Architecture]).
- (arch) Every new observable field carries its own exact obs-allowlist leaf — no reliance on a bare prefix key (per architecture.md §Occupied Resources → Tauri IPC routes, delegated-timing entry).
- (arch) Any new env var / IPC field / `health`-`ready` envelope change is registered in §Occupied Resources or §Standard Contracts with a bounded, never-panicking parse and `*_seconds` unit naming for durations (per architecture.md §Occupied Resources → Environment variables + §Conventions → Configuration units).
