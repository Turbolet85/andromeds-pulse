## Patterns to follow
- **Detector-branch pinning, not one-time live mutation.** §1's `window-navigation-check-behaviour-unit-coverage` states the rule for exactly this shape: a detector whose classification branch is proven only by a hand-run mutation is a gap — the branch must be lifted into a pure fn and pinned per-outcome. Deliverable B's observable inherits this requirement verbatim.
- **Mutation-check the new pin so it discriminates.** The `buffer` precedent (`redaction_counter_folds_once_per_batch_across_all_four_builders`, neutralize-the-sites → RED) is the plan's stated bar for "pins rather than passing for free" (per §4 buffer crate; §1 LANDED row).
- **Clock as an explicit parameter where the fn already takes an instant** — the `triage` bullet records this as the stronger form than `tokio::time::pause()` when there is no ambient clock (per §4 triage crate). A stall/staleness predicate is precisely that shape.
- **pulse-app unit-shaped probes live in `pulse-app/tests/*.rs`** reaching internals via `pub` + `#[doc(hidden)]` (its `[lib] test = false` makes co-located `mod tests` compile but never run); `buffer`/`ingest` keep co-located `#[cfg(test)] mod tests` (per §4 Conventions → Test file location).
- **Self-bootstrapping fixtures via OTLP ingest through the live receiver + per-test in-memory DuckDB.** Do NOT cite `MockTraceSpan` / `MockArrowBatch` / `MockMetricPoint` — §3 item 6 and §7 both record all three as SPECIFIED BUT NOT IMPLEMENTED (0 workspace hits), tracked as `test-data-bootstrap-factories-unimplemented` (per §7 Self-bootstrapping requirement).
- **The chaos-test trigger for this seam already exists in spec form:** "kill ingest channel mid-stream → assert buffer gracefully pauses; next ingest resumes" plus bounded-memory-under-continuous-injection (per §1 Coverage triggers → `chaos-test: Buffer overflow / retention window enforcement`). Whether any committed test implements it is research's question.

## Anti-patterns to avoid
- **NEVER `sleep(N)` for synchronization** — wait on an explicit signal (`health`/`ready` polling, channel event, log-line match) (per §11 → E2E). Acute here: the condition under test is time-shaped, and a fixed sleep converts a wedge assertion into a flake.
- **NEVER tolerate or retry a flake; zero-flakiness budget is absolute** (quarantine + root-cause, no retry-once) (per §10 Zero-flakiness budget; §11 → CI/Quality). A sustained-feed assertion must be deterministic in its pass condition, not statistical.
- **NEVER mock DuckDB at integration level, and never mock the boundary under test** — use an ephemeral in-memory instance and the live loopback receiver (per §11 → Integration + Mocking). The consumer ↔ appender-connection seam is the subject; stubbing it voids the test.
