## Constraints
- **Any new self-observation field for deliverable B must carry no client-controlled content unscrubbed.** security-plan §Logging & Monitoring ("What NEVER to log") bans raw OTLP attribute values, DuckDB query parameter values and content payloads in the log sink; §Security Anti-Patterns → Logging states the INTENDED posture that any attribute value crossing into `agent-latest.jsonl` passes through `scrub_attribute()` first. Purely numeric counters (`rows_ingested`, `buffer_capacity_pct`, a derived stall predicate) satisfy this by construction; a label naming a service / span / metric does not.
- **Edits inside `crates/ingest` must not weaken the ingest-boundary caps.** security-plan §Input Validation (OTLP/gRPC `:4317` and OTLP/HTTP `:4318` rows) requires `.max_decoding_message_size(8 * 1024 * 1024)` on each `*ServiceServer` builder and `DefaultBodyLimit::max(8 * 1024 * 1024)` on the `:4318` routes, plus post-`prost`-decode invariant checks (`span_id` 8 bytes, `trace_id` 16 bytes, bounded attribute keys/values) before batches reach `buffer::Appender`. The chunk's three named `try_send` call sites (`crates/ingest/src/grpc.rs:147,185,222`) sit on the same servers.
- **A single local producer saturating the OTLP path is the exact case §API Security's rate-limit control exists for.** security-plan §API Security (Rate limiting row) requires a coarse global request-rate cap plus a per-source-port keyed limit on both `:4317` and `:4318` via a version-pinned `tower_governor` layer, so "a runaway local process cannot saturate the OTLP path." Whether that layer is installed at HEAD — and whether it would have bounded the measured 27,675-span accept-then-never-persist window — is research's question, not something this extract can attest.
- **`ResourceExhausted` and any new wedge diagnostic must stay sanitized at the receiver boundary.** security-plan §Error Handling (OTLP receiver) fixes the shape to `tonic::Status` codes / `Status` proto; §Security Anti-Patterns → Logging bans stack traces, Rust struct names, file paths and library versions crossing to consumers. A "consumer wedged" signal may be emitted internally at ERROR but must not gain internal-detail leakage on the wire to the exporter.
- **If the root cause forces a backpressure policy, it must not create a new plaintext at-rest telemetry surface.** security-plan §Data Protection (At rest → DuckDB ring buffer) fixes the buffer as in-memory `:memory:` with no persistent disk database; §Security Anti-Patterns → Data Protection bans enabling DuckDB at-rest encryption (CVE-2025-64429). A spill-to-disk variant would therefore be an *unencrypted* store of client-controlled telemetry requiring a §Data Protection medium row before it ships — which reinforces the scope's own "no new backpressure policy" boundary.
- **Any tuning knob this chunk introduces (stall threshold, drain timeout, channel capacity) is a new input boundary.** security-plan §Input Validation (CLI / env var inputs row) requires bounded parse with a safe default and no panic, and the row's enumeration claims to be the complete list — so a new `ANDROMEDA_PULSE_*` var must be registered there.
- **The folded `cargo audit` PREREQ is governed by security-plan §Dependency Security → CI integration (Standing deferral).** This wrap is not interval point 46, so the obligation is to re-verify basis + overlap and record `probe skipped per ratified interval (next: 46)` — never a silent skip — with `cargo deny check bans licenses sources` at exit 0 and DISTINCT `RUSTSEC-` ids enumerated, never error-block counts (the 10-blocks-for-8-IDs rule).

## Patterns to follow
- **Choke-point scrub over per-push scrub** on the buffer write path: security-plan §Security Anti-Patterns → Logging records `extract_service_name` in `crates/buffer/src/appender.rs` as the single `pub(crate)` choke point feeding three consumers (the `spans` column, the storm `FingerprintObserver`, the baseline `SpanObserver` tap), with the other columns scrubbing at their push sites via `scrub_otlp_field`. Any new field the consumer path derives from batch content should attach at a choke point rather than multiplying raw paths.
- **Bounded-parse-then-register for a new env knob**, following the precedent this plan already carries for `ANDROMEDA_PULSE_L4_DETERMINISTIC` and `ANDROMEDA_PULSE_BASELINE_BOOTSTRAP_SECONDS` (per security-plan §Input Validation, CLI / env var inputs row): trim, reject-empty, range-bound, fall back to a documented default, unit-test each rejection arm by name.
- **Boundary error collapse rather than error propagation**: module-internal `thiserror` enums convert to the `serde`-friendly `AppError::{Validation, NotFound, Internal, Plugin, Storage, Ingest}` at the TauRPC bridge, and to `tonic::Status` at the OTLP receiver (per security-plan §Error Handling + §Bootstrap phases `error-sanitization-wire`). If the wedge is surfaced to the UI as well as the log, it takes the `AppError::Ingest`/`Storage` shape, not a raw internal error.
- **Prepared statements with `?` placeholders** for any diagnostic or probe query added while root-causing DuckDB append contention (per security-plan §Input Validation, DuckDB query parameters row).
- **SHA-pinned third-party Actions** if deliverable B's mechanical check lands in `ci.yml` — `<owner>/<repo>@<40-char-SHA> # vX.Y.Z` (per security-plan §Bootstrap phases `dep-security-ci-gate`).
