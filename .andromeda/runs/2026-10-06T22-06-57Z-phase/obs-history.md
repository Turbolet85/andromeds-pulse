## Relevant amendment history

- **2026-08-30-npm-advisory-coverage** — "web-vitals RETIRED (operator ruling)". The chunk that built the npm gate this chunk turns green again, and the only obs amendment an npm-dependency chunk has produced. It retired `web-vitals` 5.x from five sites (§1 Justification, §1 frontend row, §1 desktop-webview row, §3 Logging stack → Frontend bridge, §4 desktop-webview row) as measured never installed, removed the producer-less `record_web_vital` → `metric.web_vital.{name}` chain, and recorded the hand-rolled TauRPC `telemetry.frontend.*` bridge as the DECIDED frontend mechanism, with the no-browser-OTel-SDK clause unchanged. This is the source of the extract's "0 hits in `package.json` / `package-lock.json`" criterion: an upgrade or `overrides` entry that brought `web-vitals` in, even transitively, would reverse an operator ruling, not merely add a package. The ruling's ground was that an annotation would otherwise mark an ownerless open mandate, so a re-entry needs the founder's word, never a quiet lockfile line.

- **2026-09-29-ci-wall-time-and-round-trips** — "log artifacts per job". §9 Telemetry artifact handling was rewritten when `ci.yml` split into seven jobs: `logs/agent-latest.jsonl*` uploads `if: always()` from `lint-test` per OS as `logs-${{ runner.os }}` and from the Linux `boot` job as `logs-boot-${{ runner.os }}`, with distinct names because upload-artifact v4 refuses a duplicate within a run. It names no artifact for the supply-chain job, so that job's verdict is read from the step's own output. If the Node-major comparison leads to a `ci.yml` edit, these uploads and their distinct names are what must survive it; `ci.yml` at HEAD pins `node-version: '24'` at every `setup-node` step and still carries `logs-perf-samples-`, `logs-` and `logs-boot-` uploads.
- **2026-09-30-perf-budget-gate-reads-real-samples** — "the perf-budget gate grades real samples; frame gate on the dev host". This made the gate the extract cites able to fail: `cargo xtask perf:budget` grades every `agent-latest.jsonl*` member in-process, CI `lint-test` Linux runs the `perf_budget_samples` producer and then `--require memory,snapshot`, while `ci-gates` in `boot` grades with no arm required. It never passes over empty input; p99 is one nearest-rank rule; the old check scripts are deleted. Frame p99 moved to the Windows dev-host `perf:frame-sample` leg, and §9 gained `logs-perf-samples-${{ runner.os }}` (the third upload in the extract's `ci.yml` criterion). For this chunk: the memory and snapshot arms come from a Rust in-process producer, so a green `perf:budget` on the changed lockfile says nothing about the webview tree.
