- **2026-08-30-npm-advisory-coverage** — the direct precedent for this chunk's class of work. An npm advisory disposition crossed two of the plan's pinned tool majors: pa11y 9.x → 10.x (the advisory's only fix was semver-major) and Lighthouse 12.x → 13.x (all of ^12 vulnerable, fix at 13.4.1). The full a11y chain then ran green under both with zero new violation tuples (regression 0/0), so the baseline held without regeneration. It set the standing operator ruling the extract cites: an advisory fix that crosses a pinned a11y tool major is upgraded and re-baselined in the same chunk, not deferred. Three things this chunk rests on: (1) the pin set as it stands after that entry — pa11y 10.x, Lighthouse 13.x, pa11y-ci 4.x (4.1.1 was latest), axe-core 4.11.x with rule-set and tag configuration unchanged; (2) pa11y-ci internally nests pa11y 9, and that nested copy is what the npm-policy `extract-zip` exception (with its closing condition) covers — so if this chunk's change fires that closing condition and the exceptions are pruned, the plan's statement about the nested copy stops describing the tree and an a11y-plan amendment is owed; (3) the trap it names: no detector invariant covers tool-version pins, so a crossing surfaces only at validate — the holder set P3 derives from the lockfile is the only place a moved a11y tool will be noticed before then. The entry touched five body sites (§3 tool-matrix row and Primary-tool line, §3 pa11y `--runner` line, §3.5 `a11y-tooling-install`, §7 Robust row, §9 artifact-table E2E row), which is the site list a new pin move would have to amend.
- **2026-09-29-ci-wall-time-and-round-trips** — moved the a11y assertions out of the shared lint/test/build job into their own blocking `a11y` matrix job (Linux/macOS/Windows, parallel with the test jobs): `npm run build --prefix pulse-app/ui` → Playwright chromium → the PR-only `a11y-violations-base` download → `cargo xtask test:a11y`, artifacts uploaded `if: always()` under per-OS names. The base-artifact download is PR-only, so the per-PR tuple comparison on the runner depends on the run being a PR run.

The bare `npx playwright test --list` reads the deliberately inert default `playwright.config.ts` and prints `Total: 0 tests in 0 files` with exit 1 whatever the suite state, so a plan that copies the bare form inherits a permanent red. The entry's measured reading was exit 0 with 41 tests in 18 files; that count is dated 2026-09-30 and is a reference point, not a current fact — the extract's criterion compares against the count read immediately before the lockfile change, so the plan should take its own before-reading rather than assert 41.
