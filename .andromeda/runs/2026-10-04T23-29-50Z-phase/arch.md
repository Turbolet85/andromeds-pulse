# arch extract

## Relevance
partial — the chunk changes L4 input text (prompt and/or digest rendering) and measures it on the real model; arch governs crate placement, the locked Fault Identity framing-vs-identity line, the L4 runtime pin and the recorded measured clause, and adds no new resource.

## Constraints
- Fault identity is decided, not tuned: incidents coalesce on the cue tuple `(kind, scope, scope_id)`; the cue KIND reaches incident TEXT only (`{cue_cause_label(kind)}: {model title}` grounding at the producer); the digest `TRIGGER:` line stays keyed on `cues.first()`, the same cue identity is taken from, and stays framing, never identity. Any remedy lever (framing instruction wording, TRIGGER line content, corpus framing note, schema hypothesis description) must leave the tuple, the coalesce predicate, severity, priority tier, the evidence union and the title grounding unchanged (per architecture §Established Decisions [Fault Identity]).
- Keying anything on `L4Output.fingerprint` stays REJECTED (model-authored; constant under the deterministic runner); the `fingerprint_match` corpus-retrieval arm stays FED and is never simplified away by a digest-rendering change (per architecture §Established Decisions [Fault Identity]).
- The L4 runtime is llama.cpp prebuilt `llama-cli`, b9305 exact pin, spawn-per-generation, JSON-schema-constrained GBNF (`--json-schema-file`), GPU tier → CUDA + `-ngl 99`, bounded by `-n` cap + `-st` + outer timeout; a build-tag bump is a deliberate chunk-scoped event, so the measurement series must run on the same b9305 pin and the remedy must not alter the runtime or the `LlmInferenceRunner` trait swap boundary (per architecture §Established Decisions [LLM Inference Runtime — L4 interpretation layer]).
- Code placement follows the locked crate names and module boundaries: digest rendering belongs to `triage` (`triage::digest::render_payload`), prompt text / framing instruction / schema to `interpretation` (`interpretation::prompt`), the probe and the concrete runner to `pulse-app`; no new crate, no new cross-crate dependency edge, no library crate depending on `pulse-app` (per architecture §Inherited Defaults → Cargo workspace crate names, §Established Decisions [Module Boundaries], §Cross-cutting Patterns → Module dependency direction).
- No new reserved resource: no port, TauRPC procedure, Tauri event, capability identifier, corpus table, MCP tool or env var; the real-model leg uses only the already-registered `ANDROMEDA_PULSE_MODEL_PATH` · `_LLAMA_CUDA_BIN_PATH` · `_LLAMA_CPU_BIN_PATH` · `_L4_ALLOW_ROOT` · `_HARDWARE_PROFILE` (per architecture §Occupied Resources → Environment variables (reserved at arch level)).
- The deterministic runner (`ANDROMEDA_PULSE_L4_DETERMINISTIC`, canned `L4Output` with POPULATED arrays) is load-bearing for reproducible verification and must stay unaffected by a prompt or digest text change; whether the canned output or its consumers read any changed literal is research's question (per architecture §Occupied Resources → Environment variables, `ANDROMEDA_PULSE_L4_DETERMINISTIC` entry).
- Lint gate is `cargo fmt --check` + `cargo clippy --workspace --all-targets --all-features -- -D warnings`, matching the scope's PREREQ (per architecture §Infrastructure Patterns, Lint line and the `ci.yml` lint-test job).

## Patterns to follow
- Framing at prompt composition, not post-hoc rewriting of model output: the producer leaves model-authored symptom / timeline / ranked hypotheses as written; the model layer is steered by the composed prompt (`TRIGGER_FRAMING_INSTRUCTION` after `CITING_INSTRUCTION` in all three tiers' Output Instructions) and by the rendered digest (per architecture §Established Decisions [Fault Identity]). A remedy extends this shape; rewriting the rank-1 hypothesis at the producer would be a different (identity-adjacent) decision not taken here.
- Prompt lineage is versioned per tier (recorded as v2.4 / v1.3-fallback / v1.3-reflection); a changed template moves the affected tier's version, and the arch record names the lineage it describes (per architecture §Established Decisions [Fault Identity]).
- Measured clauses in arch carry their measurement boundary — model, runtime pin, routing, n per shape, shapes, arm, threshold, result per shape, run-once — and a FAIL stays recorded as measured, never re-thresholded (per architecture §Established Decisions [Fault Identity], the 2026-10-04 measured clause).
- Agent-driven, machine-parseable harness outputs (the probe's bounded verdict lines + `runs.json`) are the evidence form (per architecture §Cross-cutting Patterns → Development Style).

## Anti-patterns to avoid
- Pulling the cue kind, a model-authored field or the remedy's framing into the incident identity key or the coalesce predicate (per architecture §Established Decisions [Fault Identity]).
- Swapping, upgrading or re-tiering the inference runtime (or the model) inside this chunk to move the number — a runtime change is its own chunk-scoped pin event (per architecture §Established Decisions [LLM Inference Runtime — L4 interpretation layer]).
- Adding a new env var, flag or IPC surface to toggle the framing arm in production (per architecture §Occupied Resources).

## Contract bindings
- arch ↔ tests: the measurement series and its pre-registered bar feed the arch [Fault Identity] measured clause; the clause is amended at wrap from this chunk's evidence (PASS or FAIL), and the prompt-version literal recorded there binds to the tests that pin the version (per architecture §Established Decisions [Fault Identity]).
- arch ↔ security: the remedy's template / schema / digest literal text rides llama-cli argv, binding to the ASCII-only argv-transport rule and the prompt size bound; the real-model leg rides the product-consumed L4 path guard with `ANDROMEDA_PULSE_L4_ALLOW_ROOT` opt-in confinement (per architecture §Occupied Resources → Environment variables, `ANDROMEDA_PULSE_MODEL_PATH` / `_L4_ALLOW_ROOT` entries).
- arch ↔ external harness (Conductor): the deterministic runner is the external verification mode and must stay unchanged by this chunk (per architecture §Occupied Resources → Environment variables, `ANDROMEDA_PULSE_L4_DETERMINISTIC` entry).
