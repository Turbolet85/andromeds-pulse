## Patterns к follow

- Status-message live-region pattern: render the backoff countdown and any transient pipeline-health updates in a `role="status"` / `aria-live="polite"` region so screen readers announce changes without stealing focus, exactly as the existing snapshot-progress / live-counter surfaces do (per a11y-plan §4 Status/Alert pattern + §1 P4/P6 rows, SC 4.1.3).
- Focus order: as a Settings sub-view, Diagnostics inherits the settings-modal focus discipline — focus order matches visual top-to-bottom section order; if reached via tab/route navigation, focus moves to the view's main heading or `<main>`/section landmark on entry; Esc returns to the parent Settings surface and restores focus to the trigger (per a11y-plan §5 Focus order per layout (settings-modal) + Focus restoration, SC 2.4.3 + SC 2.1.2).
- Reduced-motion: if any history chart or countdown uses animation/transition, gate it behind `prefers-reduced-motion` via Tailwind `motion-reduce:` variants and/or the `useReducedMotion` hook, and ensure the state is still conveyed via text/color/focus when motion is disabled (per a11y-plan §6 Motion tokens + §9 Motion, SC 2.3.3 AAA).

## Anti-patterns к avoid

- NEVER render metric values or history series as canvas/visual-only with no text alternative — a chart-pixels-only Diagnostics view fails SC 1.1.1 / SC 1.3.1 (per a11y-plan §11 Screen Reader "NEVER hide important content from assistive tech" + §1 WebGPU canvas note).
- NEVER convey connection/model/backoff state by color alone — must pair `--color-accent`/`--color-feedback-success`/`--color-primary` with icon + text label (per a11y-plan §11 Visual, SC 1.4.1).
- NEVER use `aria-live="assertive"` (or `role="alert"`) for the recurring backoff countdown tick — assertive interrupts the SR on every update; use `polite` for non-blocking status (per a11y-plan §7 Live regions + §11 Screen Reader, SC 4.1.3).
- NEVER add ARIA roles on non-semantic `<div>`s for metric labels/values (e.g. `role="term"`/`role="definition"` on divs instead of `<dl>`/`<dt>`/`<dd>`) and NEVER omit focus styles / use `outline: none` without the `--border-focus` replacement (per a11y-plan §11 ARIA + Keyboard, eslint-plugin-jsx-a11y recommended; SC 2.4.7).
