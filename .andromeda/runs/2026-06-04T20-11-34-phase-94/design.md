## Constraints

- The Diagnostics surface MUST consume only `@theme` design tokens (CSS custom properties) — no hardcoded hex / px literals (per design-system §Surface desktop-webview Tokens + §Self-Validation Token Test). All `--color-*` / `--spacing-*` / `--radius-*` / `--font-*` / `--duration-*` values trace to the locked NASA Deep Space palette + 4px-base spacing scale + font stack.
- The data-vs-UI typography split MUST be encoded: all NUMERIC metric values (success rate %, queue depth, last-span-ago, p50/p95/p99, template counts, backoff countdown) render in `--font-code` (JetBrains Mono) at 12px with `font-variant-numeric: tabular-nums`; all section headers / labels / descriptions render in `--font-body` (IBM Plex Sans) — Display 32/600, Heading 20/600, Body 14/400, Label 12/500 (per design-system §Typography table; §Anti-Patterns Rejected Default "Sans-serif with mixed weights for all hierarchy"). The existing ExportForTraining.tsx + TemplateDistribution.tsx already follow this (`fontFamily: "var(--font-code)"` + `fontVariantNumeric: "tabular-nums"` on counts).
- Each Diagnostics section card MUST use the borders-only depth strategy: `--color-raised-1` (#262A33) background + 1px subtle border `rgba(74, 144, 226, 0.3)` + `--radius-md` (6px) + `--spacing-md` (16px) padding — NO shadows, NO gradients, NO glassmorphism (per design-system §Depth Strategy + §Surface Component Patterns Cards/Panels + §Anti-Patterns Universal Ban "gradient overlays / glassmorphic effects on dashboard chrome").
- Connection / Model / backoff / inference-success state indicators MUST pair their state color with a text label and/or icon — never color alone. Map: healthy/success → Earth Blue `--color-primary` or Feedback Cyan `--color-feedback-success`; degraded/error/backoff-active → Alert Burgundy `--color-accent` (non-text token: use for border + icon, with `--color-text-primary` for the adjacent message text) (per design-system §Anti-Patterns Universal Ban "NEVER use color purely for decoration" + Decisions Log 2026-05-03 accent reclassified as non-text token). The existing ConnectionDot.tsx + ExportForTraining anonymization-confirmed pattern (✓ glyph + Feedback Cyan + text) is the precedent.
- "NEVER use the same layout for different information types" — the five Diagnostics sections are a STATUS surface, distinct from a form (Settings) and a data table (Traces). Sections present read-only metric displays; do not reuse the SettingsModalForm form-control layout for metric values (per design-system §Anti-Patterns Universal Ban). The sparkline/history is a metric-display element, not a chrome ornament.
- Any sparkline / history-chart animation (if rendered on a WebGPU canvas or via CSS transition) MUST respect `prefers-reduced-motion: reduce` and stay within the 0.35 chrome expression budget (150ms ease-out micro / 200ms ease-out transition; NO entrance animations, NO scroll effects, NO staggered reveals) (per design-system §Motion duration table + Hard limits + Accessibility). A backoff countdown is a data display, not a chrome transition — render as live updating tabular-num text, not an animated bar with bounce.

## Patterns к follow

- Read-only status display with `role="status"` + `aria-live="polite"` + `var(--font-code)` tabular-num metric values: `pulse-app/ui/src/dashboard/routes/settings/ExportForTraining.tsx` (status region) + `pulse-app/ui/src/dashboard/routes/diagnostics/TemplateDistribution.tsx` (existing diagnostics-namespace surface — directly reusable structural precedent for the Templates section) (per design-system §Surface Component Patterns Loading/Empty States + Tables).
- Metric label/value row layout: `display: flex; justifyContent: space-between; gap: var(--spacing-sm)` with label in `--color-text-secondary` (#B4BCCB) Body and value in `--font-code` + `--color-text-primary` (#E8EEF7) — the exact pattern in ExportForTraining's category-breakdown rows (per design-system §Typography Data role + §Color Palette Text Hierarchy).
- Connection state dot indicator: `pulse-app/ui/src/components/ConnectionDot.tsx` already renders connection state with color + text — reuse it (not a re-implementation) for the Connection section state dimension (per design-system §Brand Identity Halo State Pulse connection-as-orthogonal-axis + §Color Palette Semantic Colors).
- Empty / loading / error states explicit per section: skeleton pulse `--color-raised-1` (discrete opacity pulse, NOT smooth fade), empty text `--color-text-tertiary` (#7D8697) with optional telescope icon (24px), error via `--color-accent` border + `--color-text-primary` text + icon (per design-system §Surface Component Patterns Loading/Empty States; ExportForTraining error block uses `border: 1px solid rgba(199, 85, 106, 0.5)` + `--color-text-primary`).
- Custom Observatory iconography over generic stock: if a section uses an icon, prefer the registered custom glyphs (`aperture` for view/settings, `constellation-grid` for service/template map, `telescope` for inspection) at `src/components/icons/`; Lucide/Heroicons only for generic controls with no domain glyph (per design-system §Iconography + §Anti-Patterns Rejected Default "Generic icons from a stock library").

## Anti-patterns к avoid

- NEVER use uniform monochrome status icons (green ✓ / red ✗ alone) as the sole state encoding — the design system rejects this; pair any status glyph with a text label and use the semantic palette hues, not generic traffic-light green/red (per design-system §Anti-Patterns Rejected Defaults "Uniform monochrome status icons").
- NEVER render shadows, gradient overlays, or glassmorphic cards on the Diagnostics sections — borders-only depth is the discipline; the Halo State Pulse WebGPU layer is the ONLY gradient/blur exception in the whole app (per design-system §Anti-Patterns Universal Ban + §Depth Strategy).
- NEVER introduce a banned font family (Inter, Roboto, Arial, Helvetica, Open Sans, Lato, system-ui default, Space Grotesk) or Tailwind default palette colors (purple/sky/zinc) for any Diagnostics text/surface — JetBrains Mono + IBM Plex Sans + NASA palette are locked (per design-system §Anti-Patterns Universal Bans).
