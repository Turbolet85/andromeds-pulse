## Relevance
Partial — arch governs placement, capability/env/harness boundaries and the locked canvas + dark-mode substrate this a11y work asserts against; the a11y semantics themselves belong to the a11y specialist.

## Constraints
- All webview source and the a11y harness live under `pulse-app/ui/` (webview source root; npm devDependencies for verification harnesses are declared there and must stay dev-only with no runtime/bundle impact) — per architecture.md §Infrastructure Patterns → Project directory structure and §Stack and Technologies → GUI verification harness (dev-only). No new workspace crate; the crate-name list in §Occupied Resources → Cargo workspace crate names is reserved and cannot be reused.
- Tauri capabilities are negative-default but the granularity is the IPC **layer**, not the procedure: `pulse-app/capabilities/` holds no per-procedure entries, and adding a TauRPC procedure would require router registration + an §Occupied Resources entry + the `EXPECTED_PROCEDURES` pin in `xtask/src/main.rs` — not a capability-JSON edit. Core APIs (fs / shell / dialog / http, and each `core:window:*` permission individually) DO require an explicit grant with stated rationale and ARE silently rejected at runtime when missing (architecture.md §Cross-cutting Patterns → Webview IPC capability policy). The chunk's "no new procedure / no capability edit" boundary is therefore coherent — but if any focus or window affordance needs a `core:window:*` permission, whether `pulse:default` already grants it is research's question (arch records a 2026-08-21 measurement of `core:default` + seven `core:window:*` + `updater:default`).
- The constellation surface is a locked `<canvas>` + `navigator.gpu` WebGPU substrate (architecture.md §Established Decisions → [WebGPU Visualization Surface]; §Inherited Defaults → Visualization). A11y for it must be delivered through wrapper semantics / accessible name / text alternatives — arch does not authorize replacing the canvas with a DOM chart to make it assertable.
- The shell is arch-committed as a dense, chart-first, low-chrome developer surface with **dark mode as the default color scheme**; concrete color / motion / typography / density tokens are the design specialist's but must respect that constraint (architecture.md §Design Philosophy → Developer-tool surface). Contrast and `prefers-reduced-motion` checks bind against that palette; arch does not sanction lightening or de-densifying the surface to pass a check.
- Findings and report are **separate webview documents** coordinating via the registered first-party events `findings:dismissed` / `report:open` (`{incidentId}`) / `report:closed` over `@tauri-apps/api/event`, gated by `core:event` in `pulse:default` — a class distinct from the `pulse://stream/*` Rust→webview channels (architecture.md §Occupied Resources → Tauri IPC events → cross-window UI-coordination events). Cross-document ARIA relationships (`aria-controls` across windows) are architecturally unavailable, not an oversight.
- End-to-end telemetry enters only over real OTLP on `:4317`/`:4318` — no in-process bypass, no "test ingest" feature flag, no mock-channel back-door; non-default ports resolve via `ANDROMEDA_PULSE_OTLP_GRPC_PORT` / `_HTTP_PORT` (architecture.md §Cross-cutting Patterns → Test-time telemetry injection). Reproducible L4-backed Investigate states are the registered `ANDROMEDA_PULSE_L4_DETERMINISTIC` gate's job (§Occupied Resources → Environment variables). Whether the shipped Playwright a11y suite already reaches populated states through a sanctioned route, or through a fixture/mock the mandate would forbid, is research's question.
- Every env var — including harness-only ones — must be registered in §Occupied Resources with its class: `ANDROMEDA_PULSE_*` for product-consumed vars, the unprefixed `PULSE_*` xtask→node relay names for harness-only ones (a claimed prefix where a collision would be silent) (architecture.md §Occupied Resources → Environment variables).

## Patterns to follow
- Dev-only verification harness: devDeps in `pulse-app/ui`, native/host binaries located out-of-repo via a guarded env var, driven from a deterministic `cargo xtask` entry point with machine-parseable output — the `cargo xtask webview-drive` 7-stage path is the in-repo precedent (architecture.md §Stack → GUI verification harness row; §Cross-cutting Patterns → Development Style, agent-driven).
- Harness-only env-var shape: whitespace-trimmed, existence-guarded, and **unset ⇒ clean SKIP (exit 0) printing the fetch recipe, never a hard failure** (`ANDROMEDA_PULSE_MSEDGEDRIVER_PATH` precedent, architecture.md §Occupied Resources → Environment variables).
- Deterministic-mode gating for model-backed states: the canned `L4Output` under `ANDROMEDA_PULSE_L4_DETERMINISTIC` is the registered route to reproducible Investigate result/error states, and arch records the load-bearing lesson that empty fixture arrays make identity assertions pass by comparing nothing (§Occupied Resources → `ANDROMEDA_PULSE_L4_DETERMINISTIC`). The p14 result-state assertions should not repeat that failure mode.
- Reuse the registered surfaces rather than inventing new ones: `investigate.run_action` backs the Investigate modal's result/error/progress states, and `telemetry.frontend.*` is the only sanctioned route for webview-measured timings (architecture.md §Occupied Resources → Tauri IPC routes).

## Anti-patterns to avoid
- Reaching a populated / storm / incident state through an in-process bypass, a test-only feature flag, or a mock channel instead of real OTLP (architecture.md §Cross-cutting Patterns → Test-time telemetry injection).
- Adding a Tauri core-API grant (fs / dialog / shell / http, or an unstated `core:window:*`) to serve a11y tooling; arch treats preserving the `pulse:default` surface as a deliberate property (architecture.md §Cross-cutting Patterns → Webview IPC capability policy; §Occupied Resources → training-export entry, "no native file picker … preserves the `pulse:default` capability surface").
- Inventing arch-level rules for webview file naming or visual tokens — architecture.md §Conventions → File naming explicitly defers webview source naming to the design specialist, and §Design Philosophy defers color/motion/density tokens to design.
