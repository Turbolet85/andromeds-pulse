## Relevance
Relevant — five of the six surfaces the working entry names (window chrome, widget→dashboard nav, anomaly controls, constellation, status, empty states) map directly to documented desktop-webview component sections; layouts supplies the structural targets and focus-order surface, not the ARIA/WCAG rules.

## Constraints
- The Traces route must stay a flex column bounded to the shell's `main` height with `overflow:hidden`, hero + `Errors only` toolbar fixed (`flex-shrink:0`), and the table flex-filling the remainder (`flex:1 / min-height:0 / overflow-y:auto`) under a sticky opaque `color-base` thead — no outer page scrollbar at any window size (per layout-templates §Surface: desktop-webview → Wireframe — Full dashboard (Traces primary screen) + §Component — Trace data table). Cell-level keyboard traversal and its scroll-into-view must operate inside that region, not the page.
- Anomaly controls are two distinct placements: a right-aligned `aria-pressed` `Errors only` toggle in its own toolbar row directly above the table, and the anomaly-first (erroring rows hoisted) *unsorted* default, with header clicks cycling asc → desc → unsorted (per §Component — Trace data table, Filter toolbar + Sorting).
- Reduced motion is a layout-attached rule with an explicitly floating render site: the halo must become a static glow while hue still updates per cumulative incident severity, and the plan states the rule "attaches to whichever surface actually renders — today the constellation dot" (per §Component — Halo State Pulse canvas). The plan records as measured (2026-08-21) that the WebGPU canvas has no production render site on either webview surface; whether HEAD still matches that record is research's question.
- The constellation hero's per-dot name + severity-token labels are required always-on (P-069), and the ASCII sketch's per-dot/footer detail is flagged as illustrative lag — the Component/notes prose, not the sketch, is the layout authority (per §Wireframe notes — Full dashboard (Traces primary screen)).
- The shared empty/error region must be a centered column in the primary content area with a decorative `aria-hidden` glyph and **no focusable element** ("read-only, affordance-exempt"), one shared component backing Metrics/Logs/Snapshots, with the error variant checked BEFORE the empty branch and carrying no exporter hint (per §Component — Empty / error state). Its body text is required at `color-text-secondary`, explicitly not `color-text-tertiary`.
- Status surface splits by window: the compact-widget footer is a read-only band, while the dashboard footer carries the read-only `ConnectionStatusLine` plus two genuinely interactive controls (time-range picker, service filter, both button-with-caret) (per §Component — Footer (read-only status bar)). Expected tab stops differ per surface.
- Window/nav model constraints the chunk must verify against rather than pin down: the titlebar segment order is `[app-icon + title | grow | settings-button | window-controls]` with platform-divergent control placement (Windows/Linux right, macOS traffic-lights left) (per §Component — Custom titlebar); dashboard nav is committed as "tabs OR sidebar, both valid, model TBD" with Tab → Enter/Space → Escape keyboard handling, and widget→dashboard expansion shortcuts are marked TBD downstream (per §Component — Primary navigation + §IA notes Navigation model / Keyboard shortcuts).

## Patterns to follow
- Bounded-container pattern (P-082): fixed regions stack, one scroll region flex-fills, sticky thead — any new focus ring, roving-tabindex, or scroll-into-view added for cell nav follows this container rather than introducing a second scroll axis (per §Component — Trace data table, Internal scroll region).
- One shared region component across sibling views so "the data views read as one system" — assertions should target the single `EmptyState` shape across Metrics/Logs/Snapshots, not three bespoke regions (per §Component — Empty / error state).
- Shared modal shell: the Settings modal reuses "the same overlay + card structure as the Investigation modal" — centered card over semi-opaque backdrop, capped ~80% viewport with scrollable overflow, top-right `✕` close (per §Component — Investigation modal + §Component — Settings modal). p14's result/error/progress states render inside that card's scroll region.
- Separate-window disclosure pattern: findings and report are borderless always-on-top *windows* (findings docked below the widget and sized to incident count, capping ~8 then scrolling; report as the `Modal` `fill` variant, edge-to-edge on `--color-base`, no backdrop, positioned left of findings) — separate documents, not in-document dialogs (per §Surface: desktop-webview → Primary screens).
- Sketch-lag handoff discipline: where an ASCII wireframe and a Component section disagree, the Component section is current truth and the sketch is a deferred touch-up (per §Wireframe notes + amendment 2026-07-09).

## Anti-patterns to avoid
- Do not add a focusable affordance (retry button, docs link) to the empty/error region to satisfy a keyboard assertion — the region is specified as affordance-exempt with no focusable element (per §Component — Empty / error state).
- Do not let cell traversal, focus rings, or a focus-visible outline reintroduce an outer page scrollbar or unpin the hero/toolbar from the top of the Traces route (per §Wireframe notes — Full dashboard (Traces primary screen)).
- Do not prescribe a nav model or a widget↔dashboard hotkey the plan deliberately leaves open (tabs-vs-sidebar, `Ctrl+Shift+P`), and do not strip hue when motion is reduced — motion is data-driven, not decorative (per §Component — Primary navigation, §IA notes Keyboard shortcuts, §Component — Halo State Pulse canvas).

## Contract bindings
- **Focus order ↔ a11y §Focus Order SC 2.4.3** — layouts owns the visible reading order the focus order must match: titlebar segments left→right, then hero → `Errors only` toolbar → table → footer on the Traces route (§Wireframe — Full dashboard, §Component — Custom titlebar).
- **Modal structure ↔ a11y §Modal focus trap (Escape dismiss + restore focus)** — applies to the in-document Investigation/Settings card (§Component — Investigation modal). Findings/report are separate OS windows (§Primary screens), so their focus drive is a window-level contract, not a DOM trap — consistent with the scope's out-of-scope boundary for the Headful leg.
- **Reduced motion ↔ a11y SC 2.3.3 ↔ design §Motion** — layouts names the render site (constellation dot per the plan's recorded measurement), a11y owns the SC assertion, design owns the motion/expression budget.
- **Text-region contrast ↔ a11y SC 1.4.3 ↔ design §Color** — the empty-state secondary/tertiary distinction is recorded on the layout section; the dashboard footer's `color-text-tertiary` at `font-label` is the reciprocal case the contrast sweep must adjudicate with design (§Component — Empty / error state, §Component — Footer).
