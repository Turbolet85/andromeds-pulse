## Anti-patterns to avoid
- **NEVER loosen the shipped CSP to make the axe/Playwright harness pass** — no `'unsafe-inline'` on `script-src`, no widening of `connect-src`/`script-src` for test injection. Harness needs are met in the test browser context, not in `tauri.conf.json` (per security-plan §API Security → CSP; §Security Anti-Patterns → API).
- **NEVER add a TauRPC procedure without both its `EXPECTED_PROCEDURES` pin and a validated argument struct, and NEVER grant a Tauri core API or a `core:window:*` permission without an explicit per-feature capability addition with stated rationale** — the latter fails *silently* at runtime, producing exactly the dead-affordance class an a11y chunk is least equipped to spot (per security-plan §Security Anti-Patterns → API).
- **NEVER let a stack trace, Rust struct name, file path, or library version reach the webview** — including into the `role="alert"` live region the new `p14` spec asserts on, and including raw OTLP attribute values echoed into any a11y debug/console output (per security-plan §Security Anti-Patterns → Logging).
