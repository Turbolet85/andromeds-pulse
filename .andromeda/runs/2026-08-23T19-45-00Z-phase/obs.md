# obs extract

## Relevance
**Partial** — the chunk is a11y/tests-owned and ships no backend surface, but it touches three surfaces that carry obs-registered frontend observables (constellation, findings, Investigate modal) and re-enters the exact PII-grep territory that produced a prior obs amendment.

## Constraints
- PII-grep heuristics over a11y fixtures/specs MUST distinguish secret *formats* (regex envelopes: `Bearer [a-zA-Z0-9]{40,}`, `AKIA…`, `sk-…`, `ghp_…`, `password=…`) from UI-label vocabulary — the literal words "token"/"password"/"API key" in an accessible label or SR fixture are NOT leaks (per obs-plan §8 *UI-vocabulary exemption*, which names "the a11y CI gate" as its motivating consumer and the Investigation modal's "Token budget" label as its example). This chunk's `p14` Investigate-states spec lands on precisely that surface.
- Frontend telemetry has exactly ONE permitted path: measure in the webview → TauRPC `telemetry.frontend.record_*` → backend `tracing::info!(target: "metric.{module}.{measure}")` into `~/.andromeda-pulse/logs/agent-latest.jsonl`. No browser OTel SDK, no direct file access from the webview (per obs-plan §1 *Telemetry surfaces → desktop-webview*, §4 *Instrumentation per surface → Desktop-webview*).
- Every `metric.*` target MUST resolve to its OWN EXACT §8 allowlist leaf enumerating every field its emit site emits; a bare `metric` key legitimately exists (`value`/`unit`/`module`), so `for_target`'s first-segment fallback keeps `value` and silently redacts every label of any target lacking a leaf (per obs-plan §8 *three DELEGATED TIMING leaves*). Any field added/renamed on the constellation or findings observables in this chunk requires the matching leaf edit.
- Metric label cardinality is bounded-enumerations-only for product-internal metrics — no per-selector, per-`data-testid`, per-violation-id, or per-trace-id labels (per obs-plan §5 *Metric label cardinality discipline*; §8 records `severity_tier` bounded to `HueSeverityTier`, `discovered_count` clamped/validated, and `service` as NEVER a label on `metric.constellation.discovery_ms`).
- Any log line emitted anywhere in this chunk's path must satisfy the binding JSON-per-line contract — `timestamp` / `level` / `target` / `message` / `fields`, with `service.name` / `service.version` / `deployment.environment` as subscriber default fields (per obs-plan §3 *Log format JSON schema*, §6 *Required fields*; obs-plan states this schema is verbatim from the tests harness contract — obs aligns to tests, not vice versa).
- Any check script this chunk runs over `agent-latest.jsonl` MUST be NEUTRAL-tolerant: an absent metric stream is NOT a FAIL. The frame-budget p99 ≤ 33ms gate is explicitly two-state — NEUTRAL when no webview is booted (headless verification), ACTIVE only when a booted app measures real frames (per obs-plan §10 *Performance budgets → WebGPU canvas frame* and §10 *Load-profile constraints*). A Playwright a11y leg that never boots the Tauri app is the NEUTRAL case.

## Patterns to follow
- **Delegated-timing observable pattern** (§8 *three DELEGATED TIMING leaves*, §5 *Metric event naming*): webview-measured duration → TauRPC bridge → `metric.{module}.{measure}` with a small bounded label set, aggregate-only. The three registered here are the chunk's own surfaces: `metric.constellation.hue_update_ms` (`duration_ms`, `severity_tier`), `metric.constellation.discovery_ms` (`duration_ms`, `discovered_count`), `metric.findings.counter_refresh_ms` (`duration_ms`).
- **Allowlist-guard placement** (§8, same entry): guards live under `pulse-app/tests/` where they actually run — a guard in `observability.rs`'s own `mod tests` compiles but never executes under `[lib] test = false`. The delegated-timing guard (`unit_observability_allowlist_delegated_timing.rs`) is the mutation-checked reference form.
- **`jq`-over-the-JSON-file assertion pattern** (§5 *Why `tracing` events instead of an OTel Meter*, §10 CI gates): percentiles/counts are computed agent-side by tailing `agent-latest.jsonl`; no precomputed quantiles in the emission path, no dashboard-mediated verification.
- **Frontend state-counter bridge** (§1 desktop-webview row, §4 desktop-webview row): skeleton-pulse duration and empty/error-state counters are specified to ride the same `telemetry.frontend.record_*` bridge. The chunk sweeps "empty states" for a11y — whether those counters already emit is research's question, and the chunk's own boundary bars new TauRPC procedures, so a missing counter is a finding to route, not build here.

## Anti-patterns to avoid
- NEVER add unbounded label cardinality to a `tracing` metric event — no per-violation-rule-id, per-selector, or per-testid label on any a11y-derived observable (per obs-plan §11 *Metrics*).
- NEVER emit per-frame/per-event at `info` inside a hot path, and never route webview telemetry anywhere but the TauRPC bridge (no browser OTel SDK, no dashboards-only surface) (per obs-plan §11 *Logs*, §11 *Universal*).
- NEVER let a new or renamed telemetry field ship without its EXACT §8 leaf — the failure mode is silent per-label redaction, not an error (per obs-plan §11 *PII Scrubbing* + §8 default-deny posture).

- **obs ↔ tests harness:** the JSON-per-line log schema in obs-plan §3/§6 is declared verbatim-from-tests §5 Test Harness Contract; tests consume it. Any assertion this chunk makes against the obs log must read that shape.
- **obs ↔ a11y:** obs-plan defines NO a11y-violation JSON schema — the only obs↔a11y contract in the plan is §8's *UI-vocabulary exemption*, which explicitly names "the a11y CI gate" as the grep consumer it constrains. The axe violation-artifact shape is the a11y/tests plans' authority, not obs's.
- **obs ↔ design-system:** obs-plan §8 (`metric.constellation.hue_update_ms` leaf) records that this observable measures the constellation DOT hue via `severityToHueFraction`, and that the **Halo State Pulse canvas has no production render site** (measured 2026-08-21). The chunk's SC 2.3.3 item names "the data-driven Halo State Pulse" as requiring reduced-motion coverage — whether that canvas has a render site at HEAD is research's question, and it decides whether item 4's Halo leg has a target at all.
- **obs ↔ security:** §8 PII vectors 1–6 are enforced at logger config (source `skip(...)` + subscriber Layer); the UI-vocabulary exemption narrows, and does not relax, those vectors.
- **obs ↔ verification matrix:** the three delegated-timing targets are P-025 / P-027 / P-045's observables (§8). The chunk claims zero capabilities, so it must not disturb their emission — if reduced-motion gating suppresses the constellation hue/discovery path, whether those observables still fire is research's question.
