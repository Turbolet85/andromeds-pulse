# design extract

## Relevance
Partial — design owns the token/motion/contrast/focus *source values* that the SC 2.3.3, contrast, empty-state and focus-ring legs of this verification chunk assert against; it owns no WCAG derivation, no per-screen focus order, and nothing in the harness itself.

## Constraints
- All motion must respect `prefers-reduced-motion`: 200ms fades → 0ms, 150ms hover → 0ms, and the Halo State Pulse degrades to a static glow (hue still tracking cumulative incident severity) — per design-system §Motion → Accessibility. This is a *requirement on the target state*; whether every shipped transition already carries the override is research's question, and it is exactly what scope item 4's SC 2.3.3 leg must measure.
- The Halo breathing cadence is specified at period 4–5 s quiet → ~2 s active (≈0.2–0.5 Hz), deliberately ≪ the SC 2.3.1 three-flash threshold, modulating opacity + blur ONLY, never scale — per design-system §Motion → High-impact moments (1). However §Brand Identity → Signature element records a 2026-08-21 measurement that the WebGPU halo canvas layer does not render on desktop-webview, and that what ships is the constellation dot carrying severity hue via `severityToHueFraction`. Whether there is any animating halo on the Traces/constellation surface at *this* HEAD for the SC 2.3.3 sweep to gate is research's question — the answer decides whether item 4's halo clause has a subject.
- Contrast targets are design-supplied, not design-adjudicated: Primary #E8EEF7 ≈8.5:1, Secondary #B4BCCB ≈6.8:1, Tertiary #7D8697 ≈4.2:1 (large text only), Muted #56606E ≈2.1:1 (decorative only) on Base #1A1D24 — per design-system §Color Palette → Text Hierarchy. §Self-Validation Protocol #6 requires that any implementation value diverging from that table be recorded in `design-system-amendments.md`, with formal WCAG conformance derivation belonging to a11y.
- Accent #C7556A is classified a **non-text** token (input borders, error icons, alert badges, divider emphasis): ≈3.8:1 on Base clears SC 1.4.11 and SC 1.4.3 large-text but *not* SC 1.4.3 normal-text. Body-size error message text (≤14px regular) must use `--color-text-primary` with an accent border + icon — per design-system §Color Palette → "Accent usage (non-text token)". That same note states the Error-state component pattern still retains #C7556A for the text role pending the error-UI chunk; whether shipped error text (relevant to the new `p14` error-state spec) is still on accent is research's question.
- The focus indicator is a token, not a per-component choice: 3–4px outset ring in #4A90E2, via `box-shadow: 0 0 0 3px rgba(74,144,226,0.2)` or `outline: 3px solid #4A90E2`, with `:focus-visible` applying to all focusable elements — per design-system §Surface: desktop-webview → Focus / Keyboard Navigation and §Color Palette → Border Progression (Focus). Any newly keyboard-reachable trace-table cell inherits this ring rather than inventing one.
- Empty-state message text is required on #B4BCCB (Secondary), never Tertiary, because body-size text needs ≥4.5:1; the Observatory glyph is decorative (24px, `aria-hidden`); the honest-error variant is a static message with no actionable hint, checked before the empty branch — per design-system §Surface: desktop-webview → Component Patterns → Loading / Empty States.
- Every value the chunk introduces must resolve through the `@theme` custom properties (`--color-*`, `--spacing-*`, `--radius-*`, `--font-*`, `--duration-*`, `--easing-*`) — no raw hex, no magic pixel numbers — per design-system §Surface: desktop-webview → Tokens and §Self-Validation Protocol #4 (Token Test).

## Patterns to follow
- **Telemetry table pattern** (design-system §Surface: desktop-webview → Component Patterns → Tables): transparent rows, hovered row `rgba(74,144,226,0.1)` with *no* transition at 0.35 expression, subtle `rgba(74,144,226,0.1)` row borders, JetBrains Mono 12px tabular-nums cells at space-sm padding. Cell-level keyboard navigation must express its active cell within this vocabulary, not with a new highlight system.
- **Card selected/active emphasis** (§Component Patterns → Cards / Panels): active/selected state is the emphasis border `rgba(74,144,226,0.6)` or solid #4A90E2 — the borrowable idiom for a "current cell/row" affordance under the borders-only depth strategy (§Depth Strategy).
- **Shared `EmptyState` + honest-error variant** (§Component Patterns → Loading / Empty States): one component reused across Metrics / Logs / Snapshots; the empty-states leg of the six-surface sweep should assert against that single shared primitive rather than per-route markup.
- **Skeleton pulse** (§Component Patterns → Loading / Empty States): `animation: pulse 1.2s ease-in-out infinite`, opacity 0.5–1.0. This is an *infinite* animation and therefore an SC 2.3.3 subject under §Motion → Accessibility; whether it is currently gated is research's question.
- **Icon registry** (§Iconography): custom glyphs are React components (`&lt;Icon glyph="telescope" /&gt;`), monochrome on #E8EEF7; decorative usage carries `aria-hidden` per the EmptyState pattern.

## Anti-patterns to avoid
- **Never state-by-color-alone.** Severity conveyed only by the constellation dot's Earth Blue ↔ Alert Burgundy hue (or by an accent border on an input) must be paired with a text/label/icon carrier — per design-system §Anti-Patterns → Universal Bans ("NEVER use color purely for decoration") and §Color Palette → Accent usage. The connection-state grayout is an *orthogonal* axis and cannot substitute for the severity carrier (§Brand Identity → Signature element).
- **Never hover-only interactions without keyboard alternatives** — per design-system §Anti-Patterns → Per-Surface Bans (desktop-webview). The table's hover-row treatment must have a keyboard-reachable equivalent; this is the design-side reason the cell-navigation work is in-scope.
- **Never hardcode hex or magic numbers** into new selectors, spec fixtures, or CSS added by this chunk (§Self-Validation Protocol #4); and add no new canvas/WebGL surface — the Halo layer is the sole exemption (§Motion → Hard limits).

## Acceptance criteria contributions
- (design) Every chrome transition asserted by the chunk collapses to instant under `prefers-reduced-motion: reduce` (200ms fade → 0ms, 150ms hover → 0ms), and any pulsing/breathing visual — skeleton pulse, constellation/halo glow — degrades to a static state with hue still tracking severity (per design-system §Motion → Accessibility).
- (design) Text/background pairs exercised by the contrast leg trace to the Text Hierarchy table (Primary ≈8.5:1, Secondary ≈6.8:1, Tertiary large-text-only, Muted decorative-only); any divergence is recorded as an amendment rather than silently accepted (per design-system §Color Palette → Text Hierarchy and §Self-Validation Protocol #6).
- (design) Accent #C7556A appears only in non-text roles (border / icon / badge); body-size error or alert message text — including the `p14` error state — is on a text token with the accent carried by border + icon, never color alone (per design-system §Color Palette → "Accent usage (non-text token)").
- (design) Any focus indicator introduced for cell-level keyboard navigation is the token ring — 3–4px outset #4A90E2 via `box-shadow`/`outline`, applied through `:focus-visible`, with no hardcoded hex or pixel literal (per design-system §Surface: desktop-webview → Focus / Keyboard Navigation and §Self-Validation Protocol #4).
