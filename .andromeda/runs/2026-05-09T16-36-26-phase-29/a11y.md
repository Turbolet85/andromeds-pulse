## Patterns to follow

- Aggregated badge naming pattern: `<div role="status" aria-label="{N} services, {P}% average error">{N}<span aria-hidden="true"> services</span></div>` — the visual text shows the count + visual decorations; the aria-label provides a complete sentence for SR users (per a11y-plan §1 P5 ARIA Roles Inventory + a11y-plan §1 screen-reader-priority trigger row).
- Footer band semantic shape: `<footer role="status" aria-live="polite" aria-label="Live telemetry summary"><dl><dt>Ingest</dt><dd>{spans/sec}</dd>...</dl></footer>` — definition list (`<dl>` + `<dt>`/`<dd>`) gives the label/value pairing semantic structure for SR announcement; the `<footer>` semantic landmark + `role="status"` + `aria-live="polite"` give the live-updating contract (per a11y-plan §1 P4 ARIA inventory + SC 1.3.1 Info and Relationships).
- Reduced-motion test pattern (chunk #31 precedent): use `mockReducedMotion(true)` in vitest unit tests + `page.emulateMedia({ reducedMotion: 'reduce' })` in any Playwright E2E (deferred to chunk #46) — assert `requestAnimationFrame` not called for the halo + assert color/text/focus state changes still convey error rate transitions (per a11y-plan §1 motion-sensitive trigger row + SC 2.3.3 AAA + chunk #31 phase-28 plan §Acceptance criteria a11y row 1).
- Tabular-numeral readout for the footer numbers consumes `font-variant-numeric: tabular-nums` (design extract) — also a11y-positive because visually-aligned numerals reduce SR cognitive load when announcing changing values (no parallel meaning loss across font-rendering shifts) (per design extract §Constraints + a11y-plan §1 visual-discrimination trigger row).
- Decorative-vs-meaningful icon flip: if the footer fields use icons (e.g., `<Icon glyph="circular-pulse" />` for the ingest field per design extract Patterns), the icon stays `aria-hidden="true"` because the adjacent text label `"Ingest"` carries the meaning — same pattern as chunk #11 icon decorative-default contract (per a11y-plan §1 visual-discrimination trigger row "verify icon/label supplement present for every state color" + chunk #11 icons decorative default).

## Anti-patterns to avoid

- NEVER use color alone (e.g., red footer background) to convey "error state active" without a paired text/icon affordance — violates SC 1.4.1 Use of Color (per a11y-plan §1 visual-discrimination trigger row + design extract §Anti-patterns).
- NEVER announce sub-second-cadence footer numeric churn via `aria-live="assertive"` — that's an SR thrash anti-pattern; use `role="status"` (implicit polite) and consider debouncing announcements to threshold crossings only (per a11y-plan §1 P4 critical path "do NOT steal focus" + screen-reader-priority trigger row).
- NEVER add a new focusable interactive element to the compact widget footer band — the surface is read-only by layout-templates contract; introducing a tab stop in the footer breaks chunk #30's focus order baseline (per a11y-plan §1 P5 critical path focus order + keyboard-only trigger row + layout extract §Anti-patterns).
