## Constraints

- Tray icon MUST be a single monochrome SVG, 16-22 px (platform-dependent), styled as a stylized pulsar / constellation star with circular outline (aperture metaphor) — no animation in the glyph itself; rendering uses macOS template-image flag, Windows + Linux render same SVG with system status-bar tint (per design-system §Surface: desktop-native → Component Patterns → Tray Icon).
- Halo overlay around the tray icon MUST encode the same two dimensions as the desktop-webview Halo: throughput rhythm via pulsing frequency 0.8-2.4 Hz AND error rate via LCH hue interpolation Earth Blue (#4A90E2) ↔ Alert Burgundy (#C7556A); composited as a secondary WebGPU canvas layer for visual consistency with desktop-webview (per design-system §Brand Identity Signature element + §Surface: desktop-native → Tray Icon).
- If WebGPU is unavailable in tray context, SVG-filter fallback is permitted ONLY when it meets the visual-equivalence criteria: blur radius 4-16 px per pulse cycle, LCH color interpolation fidelity >= 95% of the Earth Blue ↔ Alert Burgundy shift, opacity 0.6-1.0 envelope matching WebGPU baseline (per design-system §Surface: desktop-native → Tray Icon visual equivalence).
- Tray menu MUST be flat hierarchy with dividers; menu items in canonical order: "Open andromeda-pulse" (focuses/restores compact widget), read-only summary line "Ingest: {spans/sec} | Error: {%} | Retention: {min} used", "Generate Snapshot", "Toggle MCP Server" (only when `--features mcp-server` is built; checkbox-marked when enabled), "Open Settings", divider, "Quit" (per design-system §Surface: desktop-native → Tray Menu).
- Menu label tone MUST be contemplative / observational voice — "Generate Snapshot" not "Export Data"; "Toggle MCP Server" not "Enable AI Integration"; "Open andromeda-pulse" not "Show Window"; "Quit" not "Exit" (per design-system §Surface: desktop-native → Tray Menu Tone + §Brand Identity contemplative voice).
- Tray menu MUST use OS-native chrome only — no custom styling, no web-style cards/shadows/rounded corners, system font (system-ui), OS-controlled padding / icon sizing / label positioning (per design-system §Surface: desktop-native → Tokens system theme integration + §Spacing surface-conditional).
- Motion at desktop-native surface is constrained to expression level 0.2: only the Halo State Pulse glyph may animate per its data-driven rules (canvas exemption); ALL other state changes are instant per OS convention; tray icon glyph itself draws once at startup + updates on state changes, no real-time animation in the SVG (per design-system §Motion → Expression level 0.2 desktop-native + §Surface: desktop-native → Performance notes).

## Patterns to follow

- Halo State Pulse signature element on tray follows the same data → visual mapping as the existing chunk #31 implementation: frequency clamped 0.8-2.4 Hz from `throughput_hz / 1000`, blur 4-16 px per cycle, 0.6-1.2 s per breath, LCH interpolation between #4A90E2 and #C7556A (per design-system §Brand Identity Signature element + §Motion High-impact moments item 1).
- Iconography follows the custom domain-specific SVG set: prefer `circular-pulse` glyph (compact widget / tray surface toggle metaphor) or a stylized aperture / pulsar variant from the same family — registered as React component at `<Root>/src/components/icons/`, monochrome with #E8EEF7 default text color adaptable per state (per design-system §Iconography Primary custom set).
- Reduced-motion accessibility pattern matches the desktop-webview Halo: `prefers-reduced-motion: reduce` degrades the tray Halo to a static glow (no pulsing rhythm, hue still updates per error rate); other state changes become instant 0 ms (per design-system §Motion Accessibility).
- Notification format on snapshot completion follows the established 2-lines-max / terse template — "Snapshot ready | 2.5k tokens, 42 spans" — with optional OS action button "View" (opens snapshot viewer) or "Copy to Clipboard"; small app-icon attached (per design-system §Surface: desktop-native → Notifications).
- Native dialogs (file picker for snapshot export, confirmation modals if added) MUST use OS-native primitives: NSOpenPanel / IFileDialog / zenity; never custom file browser; respect platform button-ordering convention (Cancel left / Confirm right on macOS; Confirm left / Cancel right on Windows/Linux) (per design-system §Surface: desktop-native → Dialog).

## Anti-patterns to avoid

- NEVER apply web-style design language (cards, shadows, rounded corners, custom typography) inside the tray menu — clashes with OS chrome; tray menu is OS-native, no custom styling (per design-system §Anti-Patterns Per-Surface Bans desktop-native item 1).
- NEVER fight the system font in menu items and notifications — use OS-native labels; brand personality at this surface is expressed through icon design + menu tone + notification copy style, not font choice (per design-system §Anti-Patterns Per-Surface Bans desktop-native item 3 + §Typography Surface-conditional desktop-native).
- NEVER use uniform monochrome status icons (green check / red X) for tray state — Halo State Pulse encodes two independent dimensions (throughput rhythm + error hue) for at-a-glance peripheral detection of "alive" AND "broken" simultaneously; collapsing to a single boolean indicator is a rejected default (per design-system §Anti-Patterns Rejected Defaults item 1).
- NEVER use web notification libraries in place of OS-native notifications (NSUserNotification on macOS, Windows Toast, libnotify on Linux); NEVER block the UI thread with dialogs — snapshots generate asynchronously, completion is signalled by notification not blocking modal (per design-system §Anti-Patterns Per-Surface Bans desktop-native items 4-5).

Reuse existing chunk #31 measurement-intent path; do not introduce new measurement vocabulary at the tray surface (per design-system §Downstream Readiness For obs specialist).
- **design ↔ arch (capability scoping, ack only)**: tray surface activates `pulse:tray` capability per arch §Cross-cutting Patterns "Tray icon policy" + §Occupied Resources Tauri capability identifiers.
