## Constraints

- **Tray menu uses OS-native `menu` / `menuitem` semantics with Arrow-key navigation and Return/Space activation; Escape closes the menu** — the menu items must be authored via Tauri's tray menu API (which delegates to NSStatusItem / NotifyIcon / AppIndicator), NEVER as a custom webview-rendered popup, so the OS-native a11y tree exposes them to UIA / NSAccessibility / ATK. (per a11y-plan §1 desktop-native row + §3 Keyboard Test Harness "desktop-native (tray menu)" + §4 ARIA Patterns Menu row + §5 Keyboard Navigation tray-menu line.)
- **Each menu item ("Open / Snapshot / MCP toggle / Quit") must carry an accessible name string at the OS API layer** — string content authored in code becomes the accessible name announced by NVDA / VoiceOver / Orca; the MCP toggle item must additionally convey checked state via the OS native menu's checkmark/checked attribute (so SR announces "checked" / "unchecked"), satisfying SC 4.1.2 Name, Role, Value for the toggle. (per a11y-plan §1 Tray icon status display row "Interactive roles: menu / menuitem; State roles: button state via native menu item attributes" + §3 Critical paths P3 row "switch role + checked state".)
- **Focus restoration: tray icon click that re-expands the compact widget MUST return keyboard focus to the compact-widget on restore; conversely Esc-minimize from compact widget returns focus to the tray icon** — this is the bidirectional anchor for Critical Path P5. (per a11y-plan §3 Critical paths P5 row + §5 Keyboard Navigation Focus restoration "Tray icon click (minimize widget) → focus returns to compact-widget when re-expanded".)
- **Tray icon glyph + Halo overlay are non-text content carrying state; non-text contrast must meet SC 1.4.11 ≥ 3:1 against the OS tray-bar background** — the monochrome SVG glyph and the unified Halo overlay convey app-running and error-rate state respectively, so each must remain distinguishable; the Halo's Earth-Blue↔Alert-Burgundy LCH gradient that already serves chunk #31 must continue to satisfy 3:1 non-text contrast in tray-bar contexts (light-mode and dark-mode OS themes). (per a11y-plan §6 Color contrast pairs `--color-primary` / `--color-accent` non-text rows + §3 visual-discrimination trigger row.)
- **Halo overlay on the tray icon MUST respect `prefers-reduced-motion: reduce` — the Halo pulse degrades to a static-glow under reduced-motion, with state still conveyed via hue (color) + the SVG glyph (icon) so the channel is not motion-alone** — extends the chunk #31 reduced-motion contract to the tray surface. (per a11y-plan §6 Motion tokens + §11 Motion bans "NEVER autoplay motion without prefers-reduced-motion respect" + SC 2.3.3 AAA + SC 1.4.1 Use of Color.)
- **Tray icon + glyph + Halo overlay state MUST NOT be conveyed by color alone** — pair with the SVG glyph (icon channel) and an OS-level menu item or tooltip text describing app state, so SR users and color-blind users still receive the state signal. (per a11y-plan §6 State color tokens + SC 1.4.1 + creator-brief rigor "Status colors not-color-alone (paired with iconography per WCAG)".)
- **No new TauRPC procedure exposed to webview JavaScript without matching `pulse-app/capabilities/` JSON entry; the existing `pulse:tray` capability is outbound-emit-only** — input-event handlers for tray menu IPC re-entry require a separately-named capability per a11y-adjacent security discipline. (per CLAUDE.md §Critical Warnings + §Session Learnings; a11y-relevance: tray menu IPC return path must not regress focus-restoration contract by silently failing.)

## Patterns to follow

- **OS-native menu role pattern** — author menu via Tauri's tray API surfacing `menu` / `menuitem` roles so OS-native a11y APIs (UIA / NSAccessibility / ATK) expose them; arrow-up/down navigates items, Return/Space activates, Escape closes — no custom keyboard handling required (OS handles it). (per a11y-plan §4 Menu row + §5 Keyboard Navigation tray-menu line.)
- **Switch / toggle state pattern for "MCP toggle" menu item** — use the OS-native menu's checked-item facility (NSMenuItem.state / NotifyIcon checked attribute / AppIndicator radio-or-check group) so SR announces "checked"/"unchecked" rather than relying on glyph rendering alone; this is the menu-item analog of the `switch` ARIA pattern used by Critical Path P3's settings modal MCP toggle. (per a11y-plan §3 Critical paths P3 row + §4 Switch ARIA pattern row.)
- **Focus-restoration pattern for tray ↔ compact-widget transitions** — Esc minimizes compact-widget to tray then OS focuses tray icon; tray "Open" menu item activation re-expands compact-widget then focuses the widget's first focusable element (per chunk #30). Bidirectional restoration matches the focus-trap-react `returnFocusOnDeactivate: true` discipline used for modals. (per a11y-plan §5 Focus trap + Focus restoration sections.)
- **Manual SR test pattern for tray surface (supplemental)** — automated reach is limited (a11y-plan §1 desktop-native row "OS-native tray surfaces expose limited a11y tree to automated tools"); a manual pass per platform is required: NVDA + Windows tray, VoiceOver + macOS menu bar, Orca + Linux indicator panel; verify menu role announcement, item label announcement, MCP toggle state announcement, and Esc-close announcement. (per a11y-plan §3 Screen Reader Test Pattern + §1 desktop-native row + §3 Critical paths P5.)
- **Halo motion respects motion/react `useReducedMotion` AND CSS `motion-reduce:`** — for the webview-side Halo (chunks #31), the same hooks should drive the tray-overlay rendering when the overlay is composited via offscreen canvas / WebGPU before being handed to the OS tray API, so reduced-motion degrades both surfaces consistently. (per a11y-plan §6 Motion tokens verification + §11 Motion ban on animation loops without `useReducedMotion`.)

## Anti-patterns to avoid

- **NEVER replace the OS-native tray menu with a custom webview-rendered popup window** — would forfeit OS-native a11y tree exposure (UIA / NSAccessibility / ATK), break SR announcement contracts, and require re-implementing the entire `menu` / `menuitem` keyboard contract by hand. (per a11y-plan §1 desktop-native a11y APIs note + §11 ARIA bans "NEVER use ARIA on non-semantic HTML".)
- **NEVER convey tray icon state by Halo color alone** — every state hue must be paired with the SVG glyph (icon channel) and ideally a menu item or tooltip text channel; state-by-color-alone is an SC 1.4.1 violation per a11y-plan §11 Visual bans "NEVER convey information by color alone".
- **NEVER autoplay the Halo motion on the tray overlay without reduced-motion respect** — must apply the same reduced-motion degrade-to-static-glow contract used by chunk #31 in the webview; tray-rendered motion that bypasses `useReducedMotion` / `motion-reduce:` violates SC 2.3.3 AAA. (per a11y-plan §11 Motion bans "NEVER autoplay motion without prefers-reduced-motion respect" + "NEVER have animation loops that don't respect window.matchMedia".)
- **NEVER omit accessible-name strings on menu items** — every "Open / Snapshot / MCP toggle / Quit" item must have a non-empty label string at the Tauri tray menu API surface; relying on glyphs without text would fail SC 4.1.2 Name, Role, Value when announced by SR. (per a11y-plan §11 Screen Reader bans + §3 Critical paths P5 SC 4.1.2 row.)

## Contract bindings

- **a11y ↔ design**: The tray icon glyph + Halo overlay must consume the established design tokens (`--color-primary` / `--color-accent` for Halo hue, focus tokens not applicable for OS menu but glyph contrast falls under `--color-text-primary` / OS-tray-bar contrast). The reduced-motion override token contract (`--duration-*`) extends to the tray Halo; design owns token shape, a11y verifies SC 1.4.11 non-text contrast + SC 2.3.3 reduced-motion compliance.
- **a11y ↔ obs**: Manual SR test results for the tray surface (per platform) emit one row per platform pass into the structured violation JSON schema (a11y-plan §3 Structured Violation JSON Schema) with `surface: "desktop-native"` and `selector: "N/A"` (per the schema's native-surface convention); a11y violations log into obs structured-log format with `wcag_criterion` / `violation_type` / `severity` / `tool: "manual"` fields. No axe-core / Lighthouse / pa11y emission for this surface (no automated tool reach).
- **a11y ↔ tests**: Critical Path P5 (compact-widget ↔ dashboard ↔ tray) is jointly owned. A11y contributes the focus-restoration + Esc-close + tray-menu manual-SR assertions; tests harness owns the Playwright-driven webview side (compact-widget Esc minimizes → tray icon receives OS focus) but tray-menu internals are NOT automated — tests harness records the manual-pass outcome via `tests::a11y_p5_manual_tray_*` JSON artifact.
- **a11y ↔ security**: `pulse:tray` capability is outbound-emit-only (per CLAUDE.md §Session Learnings + security.md §Tauri capability gating); any tray-menu IPC re-entry handler (e.g., the "Open" item invoking webview window restore) requires a separately-named capability with explicit rationale — a11y depends on this being correctly configured so the tray "Open" action does not silently fail and orphan focus state.
