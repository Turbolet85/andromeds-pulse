## Constraints

- Tray icon = single monochrome SVG glyph (aperture / constellation-star motif) rendered as the OS template image; ALL motion / colour encoding lives in a SEPARATE secondary Halo State Pulse layer composited behind/around the glyph. Glyph SVG itself is static — no animation in the SVG (per layout-templates §Surface: desktop-native → Wireframe — Tray icon notes + §Component — Tray icon → Design).
- Tray menu MUST be flat hierarchy with NO nested submenus, ordered top-to-bottom: "Open andromeda-pulse" → divider → read-only summary line → divider → "Generate Snapshot" + "[✓] Toggle MCP Server" (visible only when `mcp-server` feature built) + "Open Settings" → divider → "Quit" (per §Component — Tray menu (OS-native) → Structure + §Wireframe — Tray menu).
- Summary line is a non-clickable read-only menu item (`font-label`, `color-text-tertiary`) showing live "Ingest: {spans/sec} | Error: {%} | {min} used" — updates via short-interval polling (1–2 second suggested) or IPC subscription (per §Component — Tray menu (OS-native) → Structure + §Wireframe — Tray menu).
- SVG glyph construction is line-based only (no fills / gradients / shadows): outer circle (1px stroke) + inner star or aperture cross (4–6 strokes); ViewBox sized for crisp rendering at small platform sizes (per §Component — Tray icon → SVG construction).
- Halo State Pulse on the tray surface is UNIFIED (single halo encoding aggregated health + ingest), NOT per-service — visual contract identical to compact widget badge halo, NOT to full-dashboard constellation per-service halos (per §Component — Tray icon → Halo State Pulse (secondary layer) + §Cross-surface coordination).
- Halo composition uses Option A (WebGPU click-through always-on-top transparent overlay window hosting `<canvas>` running same shader as desktop-webview) preferred; Option B (inline SVG with `<feColorMatrix>` + CSS animation) is the fallback path when WebGPU is unavailable in tray context, with visual equivalence ≥95% per design-system Surface: desktop-native criteria (per §Component — Tray icon → Halo State Pulse → Option A/B).
- Menu labels MUST use observational/contemplative voice: "Generate Snapshot" (NOT "Export Data"); "Toggle MCP Server" (NOT "Enable AI Integration"); "Open Settings" (NOT "Preferences" or "Config") (per §Component — Tray menu (OS-native) → Tone (menu labels)).

## Patterns к follow

- Three-surface Halo coherence: tray unified halo shares the same WGSL shader logic + frequency clamping + LCH hue interpolation as the compact widget unified halo + full-dashboard per-service halos — visual consistency maintained because all three subscribe to `pulse://stream/spans` (per §IA notes → Cross-surface coordination + Decisions Log → Three-surface coherence).
- Data-driven state variants for halo: Healthy = `color-primary` smooth pulse; Degraded = intermediate LCH hue, faster pulse; Unhealthy = `color-accent` clamped-max pulse; Silent (zero throughput) = dim low-end opacity, minimum pulse rate (per §Component — Tray icon → State variants).
- Reduced-motion contract: when `prefers-reduced-motion: reduce`, halo becomes static glow but hue STILL updates per error rate — degradation-not-removal pattern matches design-system Motion accessibility section and applies identically to compact widget signature halo (per §Component — Tray icon → Reduced motion + §Component — Halo State Pulse canvas → Reduced motion).
- Left-click vs right-click separation: left-click on tray icon focuses/restores the compact widget (single primary action); right-click opens the menu — single entry point per click type (per §IA notes → Navigation model (tray surface only)).
- Notification-hooks-into-tray-surface pattern: snapshot generation, MCP state changes, and updater state transitions ALL fire OS-native toasts via `tauri-plugin-notification`; user opt-out via `notifications_enabled` boolean in `~/.andromeda-pulse/config.toml` (default true) — when disabled the underlying actions still complete but the toast is suppressed (per §Component — Notifications → Trigger events / Implementation).

## Anti-patterns к avoid

- Do NOT render a custom file browser inside the app for snapshot export — always invoke the OS-native file picker (`NSOpenPanel` / `IFileDialog` / `zenity`) per §Component — File picker. Applies if chunk #36 surfaces any "View / Export Snapshot" affordance from the tray menu.
- Do NOT add nested submenus to the tray menu, do NOT add global hotkeys at the tray level (e.g., `Ctrl+Shift+P` does NOT toggle tray menu visibility), and do NOT include deep-navigation entries (Traces / Metrics / Logs) in the tray menu — deep navigation lives inside the app window (per §Component — Tray menu (OS-native) → Structure + §IA notes → Keyboard shortcuts (tray level) + Navigation model).
- Do NOT animate the SVG glyph itself or add custom emergence chrome to the menu — tray menu emergence is OS-native and instant; the `0.2` desktop-native expression level forbids custom chrome animation at this surface (per §Surface: desktop-native → Expression level + Decisions Log → Tray menu emergence).
