# arch extract

## Relevance
relevant — the chunk decides where a shared test-data set lives in a workspace whose member names and dependency direction are locked, and it moves one test binary's ports into the reserved test-port range.

## Constraints
- The workspace member list is closed and canonical: architecture §Occupied Resources → Cargo workspace crate names requires that no reserved name is reused, and architecture §Project Intent → How new functionality is added routes a NEW workspace crate through a scope decision. A factory set that lands as a new workspace member is therefore a workspace-level addition the plan states at P4, not a silent side effect; a set that lives inside an existing member needs no such word. Which existing member can hold it is research's question.
- Architecture §Cross-cutting Patterns → Module dependency direction requires that no library crate depends on the binary crate and that no library crate depends on a sibling unless its declared contract requires it, with `pulse-app` the only root. The section states no carve-out for a `[dev-dependencies]` edge: if one shared set is to serve tests in more than one crate, the plan names the edge it adds and says whether it reads the rule as covering dev-only edges, for the operator's word.
- Architecture §Conventions → Module visibility discipline requires each crate to expose only its public contract via `pub`, with re-exports confined to the contract module. A product type is not given a wider surface (a constructor, a field, a re-export) so that a factory can build it; whether today's public contracts already let a test build every span, point and record shape the chunk needs is research's question.
- Architecture §Cross-cutting Patterns → Test-time telemetry injection requires end-to-end tests to put telemetry in over real OTLP on the bound receiver and to read state back through the stated read-back paths (the program's own log records on a spawned console run, `EngineHandles` in an in-process arm). The factories supply values for those legs; they do not become a second way in.
- Architecture §Occupied Resources → Network ports requires every port a port-using test binary takes to be a number claimed from the test-only loopback range it reserves (its two harness defaults left out), never bound to port 0, read and released, and requires that no test binds 4317 or 4318. That section names `pulse-app/tests/integration_engine_boot.rs` as the file still outside the rule and this route entry as its owner.
- Architecture §Occupied Resources → Filesystem locations (Test-made port-claim files) fixes `target/test-ports/` as the one place a test's port claim is written, one empty file per number under an advisory lock, never unlinked by a test. The carry's file takes its claims there; the chunk adds no other place on disk.
- Architecture §Conventions → Timestamp handling requires incoming nanosecond stamps to be stored with microsecond truncation beside a `ts_unix_nano` sibling where nanosecond precision is kept. A factory whose event time is settable, and any moved test that reads a stamp back, states which of the two it compares against.

## Patterns to follow
- One shared module over several test binaries of a package: `xtask/tests/common/mod.rs` serving two binaries, per architecture §Stack and Technologies → Gate-script pins (test-only). It is the recorded precedent for sharing inside one package with no manifest or lockfile change; whether that form can reach a second package without a dependency edge is research's question.
- The claimed-port helper and its holder (`claim_port` / `PortClaim`) and the lock-file discipline around them, per architecture §Occupied Resources → Filesystem locations (Test-made port-claim files).
- Identity shapes a default-valued factory must respect: 16-byte trace id with 8-byte span id for spans, and the keys of metric points and log records in which two rows of one resource in one nanosecond are legal, per architecture §Conventions → Primary key convention.
- The existing never-shipped OTLP sender `crates/ingest/examples/inject_demo`, per architecture §Occupied Resources → Environment variables (`ANDROMEDA_PULSE_OTLP_GRPC_PORT`): a dev example that builds telemetry by hand. Whether it is one of the counted hand-built sites, and whether it moves, is research's and the plan's question.
- The crate shape (a contract module as the only `pub` surface, `pub(crate)` internals), per architecture §Project Intent → Template patterns, and `snake_case.rs` file names, per architecture §Conventions → File naming.

## Anti-patterns to avoid
- No in-process test-mode bypass, no separate test-ingest feature flag and no mock-channel back door for the factories' sake, per architecture §Cross-cutting Patterns → Test-time telemetry injection; and no feature that widens the default build graph, per architecture §Cross-cutting Patterns → Feature-gate hygiene.
- No bind-to-port-0, read and release in any test leg the chunk touches, and no test bind of 4317 or 4318, per architecture §Occupied Resources → Network ports.
- No library crate made to depend on `pulse-app`, and no reserved crate name reused for a test-data home, per architecture §Cross-cutting Patterns → Module dependency direction and architecture §Occupied Resources → Cargo workspace crate names.

## Contract bindings
- arch ↔ tests: the injection and read-back rule (architecture §Cross-cutting Patterns → Test-time telemetry injection) and the reserved test-port range (architecture §Occupied Resources → Network ports) are what the test plan's harness and port-using binaries are held to; the tests extract owns the test-side wording.
- arch ↔ security: the port range, the 4317 / 4318 ban for tests and the one test-made place on disk (architecture §Occupied Resources → Network ports; → Filesystem locations) are the measured side of the scope's halts (a new listening socket, a new place on disk).
- arch ↔ wrap: architecture §Occupied Resources → Network ports, architecture §Occupied Resources → Filesystem locations (Test-made port-claim files) and architecture §Stack and Technologies → Gate-script pins (test-only) each name the port-using test binaries by count and by name, and the first names `integration_engine_boot.rs` as still unclaimed. A chunk that moves that file to claims, or folds the helper's twins into one, changes all three statements; they are amended at wrap, from what the chunk measured.
- arch ↔ all domains: if the factories take a new workspace member, the canonical member list (architecture §Occupied Resources → Cargo workspace crate names) and every count word that defers to it (architecture §Design Philosophy → Single-process modular monolith) change with it.

## Acceptance criteria contributions
- (arch) The workspace's members equal the canonical list, or the one added member is named in the plan and accepted by the operator before it lands (per architecture §Occupied Resources → Cargo workspace crate names).
- (arch) No `[dependencies]` edge is added from a library crate to `pulse-app` or to a sibling outside its declared contract, and any dev-only edge the shared set needs is listed in the plan by both ends (per architecture §Cross-cutting Patterns → Module dependency direction).
- (arch) No product crate's `pub` surface and no Cargo feature changes in the chunk's diff against its base for the factories' sake (per architecture §Conventions → Module visibility discipline).
- (arch) Every port taken in `pulse-app/tests/integration_engine_boot.rs` is a claimed number from the reserved test-port range, the file binds no port 0, and no test in the chunk's diff binds 4317 or 4318 (per architecture §Occupied Resources → Network ports).
