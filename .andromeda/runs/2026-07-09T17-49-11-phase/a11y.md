## Patterns to follow
- **Live-region status pattern:** `aria-live="polite"` for non-blocking status, no keyboard interaction, announced by SR on change — the StatusLiveRegion `announce(...)` D4 rewires (per a11y-plan §4 Status/Alert + §7 Live regions).
- **full-dashboard-traces focus order:** skip-to-main (first focusable, SC 2.4.1 Bypass Blocks) → sidebar tabs → main region → table (Tab navigates cells; arrow keys drill rows). D1's stack (hero → toolbar → scrolling table) must keep this sequence (per a11y-plan §5).
- **Not-color-alone assertion is custom, not axe:** state color paired with text/icon is verified by a custom DOM-inspect Playwright script (axe-core does NOT detect it) — relevant to how D3's dot-severity preservation is proven (per a11y-plan §6 State color tokens + §1 visual-discrimination trigger).
- **Canvas wrapper semantics:** `<region aria-label="…">` wrapper + labels/ARIA on control elements; the `<canvas>` itself carries no ARIA (per a11y-plan §7 Landmark roles).
- **Suite-health convention:** confirm the a11y suite is actually live via `npx playwright test --list` (a list-time import failure once silently disabled the whole suite); fixtures live in `helpers/v02-fixtures.ts`, IPC mocked as `TauRPC__<router.path>` (per a11y-plan §3 Harness wiring & conventions).

## Anti-patterns to avoid
- **NEVER convey info by color alone** — D3's collision-avoidance must not drop the non-color severity token / text-or-icon supplement on any dot (a11y-plan §11 Visual).
- **NEVER omit focus styles, create a keyboard trap, or set tabindex > 0** — D1's `overflow-y:auto` scroll wrapper must not trap focus, hide the `--border-focus` ring, or reorder Tab via positive tabindex (a11y-plan §11 Keyboard).
- **NEVER hide essential content from AT (`aria-hidden`/`display:none`) or drop landmark roles** — the fixed-hero refactor must keep off-screen rows in the a11y tree (overflow scroll is fine) and preserve `main`/`region`/`nav` landmarks (a11y-plan §11 Screen Reader).
