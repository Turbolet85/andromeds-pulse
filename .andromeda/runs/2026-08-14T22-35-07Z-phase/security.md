## Relevance
**Partial** — the fix itself is plumbing, but it crosses two security-owned boundaries: env-var/path input validation (the `data_dir`-derived half of the key) and the MCP `query_*` tool-response surface (a read that starts returning real corpus rows).

## Constraints
- The `data_dir`-derived half of the key is an `ANDROMEDA_PULSE_DATA_DIR` product: security-plan §Input Validation (CLI / env var inputs row) and §Security Anti-Patterns §Input require `*_PATH`/`*_DIR` env vars be canonicalized and asserted to resolve under the resolved base, using the `strict-path` primitive named in §Bootstrap phases `input-validation-library-install`. A shared derivation MUST NOT introduce or preserve a raw `to_string_lossy()` path that bypasses that. Whether the current sidecar/app paths already canonicalize `ANDROMEDA_PULSE_DATA_DIR` before deriving the key is research's question.
- The detected-root half is **workspace-detector output**, which §Security Anti-Patterns §Code Patterns names explicitly in the command-injection ban — it must never reach `tokio::process::Command::new(..).arg(..)`. This binds the Conductor-as-instrument leg: any harness that shells out with the derived key/root is in scope of that ban.
- The workspace key is a user-derived filter value flowing into `load_active_incidents`; §Input Validation (DuckDB query parameters row) + §Security Anti-Patterns §Input require prepared statements with `?` placeholders and forbid interpolating user-derived values into SQL. Same class applies to the corpus query even though the ban's anchor text names the `duckdb` crate.
- Editing the sidecar's init path must not regress the MCP double-gate: §API Security (MCP feature double-gate) and §Security Anti-Patterns §Code Patterns require BOTH compile-time `--features mcp-server` and runtime `ANDROMEDA_PULSE_MCP_ENABLED=true`, with the graceful-degrade `warn` preserved (also §Input Validation CLI/env-var row).
- A `query_incident_list` that begins returning rows makes real corpus content cross to an LLM client for the first time. §Data Protection (At rest — persistent incident corpus) requires corpus contents be PII-scrubbed projections written via `security::scrubber::scrub_attribute`, and §Logging & Monitoring (snapshot/clipboard/MCP-tool-response hygiene) classifies MCP `query_*` responses as the documented indirect-prompt-injection surface. No new/changed read path may bypass the scrubbed projection; whether today's incident read path returns already-scrubbed values is research's question.
- Diagnostics that name the mismatch must be sanitized at the boundary: §Error Handling (External responses + MCP server bullet) requires no file paths or implementation detail in JSON-RPC error objects, and §Security Anti-Patterns §Logging bans file paths in `AppError::Internal { message }`. Key-mismatch detail belongs in the internal `agent-latest.jsonl` sink per §Logging & Monitoring (Log format).
- The sidecar's corpus read requires the AES-256-GCM cell key: §Secret Management (Storage — Runtime corpus encryption key) mandates OS keychain primary with the `BackendKind::PassphraseFallback` warn-at-boot posture, and "What counts as secret" requires the key never be logged (`#[tracing::instrument(skip(key))]` at every key-handling call site).

## Patterns to follow
- `strict-path` canonicalize-and-confine as the path primitive (§Bootstrap phases `input-validation-library-install`; §Anti-Patterns §Input) — the scope notes `workspace-detector` already carries `strict-path`, so the candidate shared home already has the sanctioned primitive.
- Registry-completeness playbook for bounded config/env inputs: a code-validated + unit-tested bounded input gets a routine §Input Validation table update, not an escalation (established by both 2026-06-28 and 2026-06-29 amendments below).
- Boundary error collapse: module-internal `thiserror` 2.x → `serde`-friendly `AppError` / JSON-RPC 2.0 error object at the bridge, per §Error Handling + §Bootstrap phases `error-sanitization-wire`.
- Scrubbed-projection-at-write (`scrub_attribute` / the `scrubbed_clone` family) as the uniform persistence-boundary pattern per §Security Anti-Patterns §Logging (uniform scrubber coverage paragraph).

## Anti-patterns to avoid
- Reading `ANDROMEDA_PULSE_DATA_DIR` (or any `*_DIR`/`*_PATH`) into the key without canonicalization + confinement assertion (§Security Anti-Patterns §Input, CWE-22 class).
- Passing workspace-detector output / the derived key to `tokio::process::Command::new(..).arg(..)` in any verification or instrument harness (§Security Anti-Patterns §Code Patterns).
- Single-gating the rmcp sidecar (feature flag OR env var instead of AND) while touching `andromeda-pulse-mcp.rs` init (§Security Anti-Patterns §Code Patterns).
