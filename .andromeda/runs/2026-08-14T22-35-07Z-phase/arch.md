## Relevance
Relevant — the chunk moves a workspace-key derivation across Cargo workspace crate boundaries (`pulse-app` ↔ `mcp-server` ↔ candidate `workspace-detector`) and touches the MCP `query_incident_list` external surface, both core arch concerns.

## Constraints
- The derivation's new home MUST be one of the reserved workspace crate names (`ingest`, `buffer`, `viz`, `ui-bridge`, `snapshot`, `curation`, `triage`, `workspace-detector`, `plugins`, `mcp-server`, `corpus`, `security`, `interpretation`, `config-watcher`, `pulse-app`, `xtask`) — those names are reserved at workspace level and cannot be reused, and a NEW crate would require an arch amendment to §Occupied Resources (per architecture.md §Occupied Resources → Cargo workspace crate names, §Inherited Defaults → Module boundaries).
- Module dependency direction MUST stay a DAG rooted at `pulse-app`: no library crate depends on the binary crate, and no library crate depends on a sibling unless its declared contract requires it (per architecture.md §Cross-cutting Patterns → Module dependency direction). This is the arch rule the scope's cycle constraint instantiates — the derivation cannot live in `pulse-app` if `mcp-server` must call it.
- Boundaries are enforced by the Cargo `[dependencies]` graph plus `pub`/`pub(crate)` visibility, not review discipline; a single-crate `mod` shuffle that leaks `pub(crate)` across modules is not an acceptable substitute (per architecture.md §Established Decisions → [Module Boundaries]).
- Each crate exposes only its public contract module; cross-crate utilities are `pub(crate)`; no `pub use` re-exports across crate boundaries except in the explicit contract module (per architecture.md §Conventions → Module visibility discipline). A shared workspace-key function must therefore surface through the host crate's contract module — matching the existing `workspace-detector` shape (`contract.rs::WorkspaceContext.root`, cited in the chunk's surfaces table).
- Any type crossing the MCP tool response boundary MUST be `serde::Serialize`; the MCP surface itself is JSON-RPC 2.0 over stdio per spec with the fixed 8-method `#[tool]` list including `query_incident_list`, feature-gated behind `--features mcp-server` (default off) so the fix must not pull `rmcp` or new deps into the default build graph (per architecture.md §Standard Contracts → MCP server, §Cross-cutting Patterns → Feature-gate hygiene / Cross-bridge data shape).
- The data-dir root and its `ANDROMEDA_PULSE_DATA_DIR` override are arch-reserved resources with identical subpath layout on every platform; the corpus lives at `corpus/corpus.db` under the resolved root. Any key derivation reading these MUST respect the reserved resolution rules and add no new env var (per architecture.md §Occupied Resources → Filesystem locations / Environment variables).
- Errors: `thiserror` enums inside the module crate, `anyhow` at `main.rs`/boundaries, `AppError` only at the TauRPC bridge (per architecture.md §Established Decisions → [Error Handling Pattern], §Conventions → Error response schema). MCP-side failures use the JSON-RPC 2.0 error object, not `AppError`.

## Patterns to follow
- Contract-module template: each library crate is a public contract module (its only `pub` surface) + `pub(crate)` internals + `thiserror` error enum (per architecture.md §Project Intent → Template patterns). `workspace-detector` already follows this with `contract.rs::WorkspaceContext`; a shared derivation added there follows the existing shape rather than inventing one.
- Adding a sibling dependency edge (here: `mcp-server` → the derivation's host crate) is the sanctioned way to share first-party logic — arch permits sibling deps where the declared contract requires them, and forbids only cycles and binary-crate deps (per architecture.md §Cross-cutting Patterns → Module dependency direction).
- Path/env resolution discipline for data-dir-derived values: the reserved-root + `ANDROMEDA_PULSE_DATA_DIR` override pattern already used across the app, with the canonicalize-and-confine rule flagged in §Occupied Resources (the `~/Downloads` training-export sink is documented as the ONE exception). Whether the current app-side and sidecar-side entry forms already normalize identically — canonicalized `\\?\` verbatim vs raw env string — is research's question.
- Lint/typecheck gate is unconditional: `cargo fmt --check` + `cargo clippy --workspace --all-targets --all-features -- -D warnings` (per architecture.md §Infrastructure Patterns → Build system). `--all-features` means the `mcp-server`-gated code path is compiled and linted by the standard gate, so a feature-gated-only change is still fully covered.
- Naming: Rust `snake_case` functions/modules, `UpperCamelCase` types, `kebab-case` crate directories under `crates/<module-name>/` (per architecture.md §Conventions → File naming / Variable-function naming).

## Anti-patterns to avoid
- Do NOT create a dependency cycle or make a library crate depend on `pulse-app` (per architecture.md §Cross-cutting Patterns → Module dependency direction) — the scope's cycle finding is exactly this ban.
- Do NOT introduce a new workspace crate, new env var, new TauRPC procedure, or new MCP tool method as an incidental side effect of this fix; each is an arch-registered resource requiring an amendment (per architecture.md §Occupied Resources; the scope itself anticipates no new TauRPC procedure).
- Do NOT duplicate the derivation a third time or paper over the mismatch at the call site — arch enforces boundaries via the dependency graph specifically so shared logic has one compile-time-enforced home (per architecture.md §Established Decisions → [Module Boundaries]).

## Contract bindings
- **Workspace crate naming → all domains**: the crate chosen as the derivation's home fixes where tests, obs, and security content for this change must live (per architecture.md §Occupied Resources → Cargo workspace crate names).
- **MCP `query_incident_list` surface → tests**: the arch-locked 8-method MCP tool list and its JSON-RPC 2.0 stdio framing are the observation surface for the chunk's before-evidence leg; the tool list must be unchanged by this chunk (per architecture.md §Standard Contracts → MCP server).
- **Feature-gate hygiene → tests/build**: any test exercising the sidecar path must build with `--features mcp-server`; the default build graph must stay `rmcp`-free (per architecture.md §Cross-cutting Patterns → Feature-gate hygiene).
- **Data-dir + `ANDROMEDA_PULSE_DATA_DIR` → security**: the key derivation consumes an env-overridable path root, so the canonicalize/confinement rule flagged in §Occupied Resources binds to security's path-validation review.
- **Corpus SQLite (`corpus/corpus.db`, `incidents` table, keychain-encrypted cells) → the filter consumer**: `load_active_incidents(workspace_key)` reads an arch-registered store; the key is the filter predicate, and the store's schema/encryption posture is unchanged by this chunk (per architecture.md §Occupied Resources → Corpus SQLite database / schema names).
