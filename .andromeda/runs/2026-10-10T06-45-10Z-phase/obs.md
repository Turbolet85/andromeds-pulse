## Patterns to follow
- Two-state grading by declared expectation: a caller that expects samples names the arm with `--require` and a required empty arm fails; an unrequired arm reads NEUTRAL (per obs-plan §10 DuckDB Connection Isolation & Load-Profile Operational Constraints → Load-profile constraints). Note for P4: this is a plan-sanctioned NEUTRAL (`ci-gates` over the boot-smoke log, no arm required — obs-plan §10 CI gates, perf-budget bullet); it is neither a baseline comparison nor an upload, and whether P-128's closing sentence reaches it is not decided by this extract.
- Producer beside its reader in the same job: the perf-samples producer runs, then the grader reads its data dir, and the graded log is the uploaded artifact (per obs-plan §10 CI gates, perf-budget bullet; obs-plan §9 Telemetry artifact handling → Log file row). A kept upload or comparison in this chunk takes the same shape: its producer is a named step.
- A grader that would silently drop its input fails instead: the plan records one gate that "passed vacuously" by dropping every sample and the rule that replaced it (per obs-plan §10 Performance budgets → L4 constrained inference row).
- Distinct artifact names per job within one run, and one name per uploaded log family (per obs-plan §9 Telemetry artifact handling → Log file row).
- CI readings enter the plan as measured, with the run id and what was read (per obs-plan §9 Telemetry artifact handling → Log file row; obs-plan §10 CI gates): the wrap's amendments for this chunk cite the pre-CI run the same way.

## Anti-patterns to avoid
- NEVER lose telemetry artifacts — log file and snapshot on failure are uploaded with retention (per obs-plan §11 Obs Anti-Patterns → CI). Removing the `logs-${{ runner.os }}` upload because it finds no file stands against this ban as written; it is a fork for the operator at P4 with the ban named, never a silent removal. The same ban names a snapshot-on-failure artifact (also obs-plan §9 Telemetry artifact handling → Snapshot markdown row, `obs-plan.md:500`); the scope's nine uploads name none, and whether any step produces one is research's question.
- NEVER define soft SLO budgets with no enforcement (per obs-plan §11 Obs Anti-Patterns → SLO): a regression comparison that stays in the workflow while it can pass with no baseline is that shape.
- NEVER rely on unstructured output for CI parsing — artifacts are structured and machine-readable (per obs-plan §11 Obs Anti-Patterns → CI): a producer added by this chunk uploads the structured file, not a rendered summary.
