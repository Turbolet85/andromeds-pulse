## Constraints
- a11y-plan §3 CI integration (Per-PR regression detection) requires the per-PR comparison to read a base-branch
  `a11y-violations-summary.json` fetched under the artifact name `a11y-violations-base`. The plan states the consumer
  and names no step that uploads that name. Whether any workflow uploads it is research's question.
- a11y-plan §3 Harness wiring & conventions (Regression baseline) requires the per-PR gate to compare against
  `baselines/a11y-violations-summary.json`. That is a second baseline source in the same plan. Which of the two the
  regression leg reads, and what it does when the downloaded one is absent, is research's question; the fork at P4
  differs by the answer (a baseline held in the tree has a producer that needs no permission, token, trigger or action).
- a11y-plan §10 SLO Invariants & A11y Budgets (Standard+ invariants) requires zero new violations per PR against the
  base branch, detected by artifact comparison. A fork arm that removes the comparison itself, not only the download,
  leaves this invariant without a mechanism; that arm is said at P4 with the plan sites it falsifies.
- a11y-plan §11 A11y Anti-Patterns → CI requires the a11y gate to be fail-fast with no soft gate. A soft-fail key on a
  step of the `a11y` job is inside that ban's reach. Whether the key on the baseline download softens the gate or only
  the fetch is research's question.
- a11y-plan §9 CI Integration (Per-pipeline-stage a11y artifacts) requires five named result files as the uploaded
  artifact of the E2E stage and the summary file again at Aggregation. The per-member read of the `a11y-violations`
  upload is measured against that list. Whether each named file is written on a CI run is research's question. The
  same table's consumer cell names a pull-request comment; whether any step posts one is research's question, and a
  producer for it would need a permission the scope's boundary holds for the founder.
- a11y-plan §3 CI integration (Pipeline integration) requires the job's artifacts uploaded under two names,
  `a11y-violations-Linux` and `playwright-a11y-report-Linux`, and names the PR-only download in the job's step order.
  A step that goes, or a member that goes, makes that label an expected amendment.
- a11y-plan §10 SLO Invariants & A11y Budgets (Build / deploy failure conditions) requires four hard failure
  conditions on the job. The chunk's edits leave the `cargo xtask test:a11y` step gating on all four; the job's suites
  are outside the chunk (the scope's Boundaries).

## Patterns to follow
- a11y-plan §3 Harness wiring & conventions (Adding a surface) already names this chunk's defect in its own harness:
  a sweep over an empty fixture "passes by comparing nothing", and the rule is populated input. The same rule shapes
  the witness: a comparison counts as reading something only when its baseline is shown non-absent on the run.
- a11y-plan §3 Harness wiring & conventions (Adding a surface) gives the cheap health probe for the suite, the
  config-named `--list`; the bare form reads the inert default config and reports nothing whatever the suite's state.
- a11y-plan §3 Harness wiring & conventions (Regression baseline) is the existing shape of a baseline with a producer
  inside the tree, and states what a clean one holds.
- a11y-plan §3 CI integration (Per-PR regression detection) fixes the comparison's shape: a set difference over the
  four-field tuple, with a regression-set file kept for audit. A kept comparison keeps that shape.
- a11y-plan §12 A11y Decisions Log: amendments land in the sidecar at wrap; the plan lists them as expected and phase
  edits no site.

## Anti-patterns to avoid
- Removing the per-PR diff without saying so: a11y-plan §11 A11y Anti-Patterns → SLO bans skipping regression
  detection at this tier.
- Leaving or adding a soft-fail key on an `a11y` job step so an absent input cannot red it: a11y-plan §11 A11y
  Anti-Patterns → CI bans a soft a11y gate.
- Dropping the a11y result upload so a CI run keeps no machine output: a11y-plan §11 A11y Anti-Patterns → Universal
  bans a conformance claim without machine-verifiable evidence, and a11y-plan §2 A11y Strategy (signal pyramid,
  Agent-driven row) names the CI artifact upload among the evidence paths.
