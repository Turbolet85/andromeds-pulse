## Relevance
relevant — the chunk relocates the chunk #87 Findings disclosure (unread badge trigger + dropdown, surface P8) into a separate always-on-top window; cross-window focus restoration, keyboard dismiss, and the reused disclosure ARIA contract are core a11y deliverables (scope item #3).

## Constraints — domain rules that apply
- **Disclosure ARIA contract survives the move**: the unread badge stays a native `<button aria-expanded aria-controls aria-haspopup>` and its `aria-expanded` must now track the panel WINDOW's open/closed state (cross-window sync, not just local `isOpen`); rows stay native `<button>` (not `role=menu`) — per a11y-plan.md §4 Disclosure/Button, SC 4.1.2.
- **Cross-window focus restoration**: opening moves focus into the panel window; Esc/dismiss returns focus to the triggering badge in the WIDGET window. The two are separate documents, so the current same-document `triggerRef.current?.focus()` no longer works — restoration must ride Tauri IPC (the P5 "focus returns to tray icon on restoration via Tauri IPC" precedent) — per a11y-plan.md §5 Focus restoration + §1 P5, SC 2.4.3.
- **No keyboard trap across the window boundary**: Tab cycles within the panel window; Esc must always exit and hand focus back; blur-dismiss must not strand focus — per a11y-plan.md §5 Focus trap + §11 Keyboard, SC 2.1.2.
- **Universal minimums on the new labeled webview surface** (it joins the P1–P12 must-be-accessible set): SC 2.1.1 Keyboard, SC 2.4.3 Focus Order, SC 4.1.2 Name/Role/Value — per a11y-plan.md §10 + §1 surface-set note.
- **Live-badge CARRY carries a status obligation**: making `use-findings.ts` live must preserve focus by construction (re-poll updates props; do NOT remount the open panel/counter) and SHOULD announce the 0→N unread transition ONCE, politely, via the existing StatusLiveRegion/useStatusAnnouncer (never assertive, never per-tick, never a new live element) — per a11y-plan.md §7 Status Messages, SC 4.1.3 (cascaded rule `.claude/rules/a11y.md` 2026-07-07).
- **Focus visible on panel controls**: rows + "Mark all as read" show the `--border-focus` outline on `:focus-visible`; no `outline:none` without replacement — per a11y-plan.md §6 Focus ring + §11, SC 2.4.7 / 1.4.11.
- **Reused content keeps contrast + not-color-alone**: text on the opaque popover background stays ≥4.5:1 and each severity row carries the severity word in its accessible name — per a11y-plan.md §6, SC 1.4.3 / 1.4.1. (Content is reused verbatim and already in the p8 axe sweep; re-verify only if the container token changes — scope says `--color-inset` but the shipped/design-correct popover token is `--color-raised-2`.)

## Patterns to follow
- `pulse-app/ui/src/widget/FindingsCounter.tsx` — the badge already implements §4 Disclosure (native button + aria-expanded/controls/haspopup, count+severity accessible name, `--target-input-min` for SC 2.5.8); reuse it, re-wiring `aria-expanded` to the panel window's visibility.
- `pulse-app/ui/src/widget/FindingsDropdown.tsx` — reused content; its Esc handler currently calls `onClose()` + same-document `triggerRef.current?.focus()` and click-outside via a document `mousedown` listener; the cross-window move must swap the focus call for IPC restoration and add a window-blur dismiss.
- `pulse-app/ui/tests-a11y/keyboard-focus/widget-and-modals.spec.ts` — existing focus spec already asserts "Esc closes findings dropdown, focus returns to counter trigger" + no positive tabindex + visible focus ring; extend (or add a sibling) for the cross-window Esc-restore + panel-window Tab cycle.
- `pulse-app/ui/tests-a11y/axe/p8-findings-dropdown.spec.ts` — existing P8 axe + SC 1.4.1 spec; per the §3 "add an axe spec per new surface" standing rule, cover the new window-label render branch here (or a new pN spec) via `installTauriIpcMock(page, overrides, "<findings-window-label>")`.
- P5 in a11y-plan.md §1 + the 2026-06-30 amendment — the canonical cross-window focus + shortcut-in-both-windows discipline governing the panel↔widget pair.

## Anti-patterns to avoid
- Do NOT leave the panel a keyboard trap — a separate window with no working Esc-to-widget return, or a blur that strands focus, violates SC 2.1.2 (a11y-plan.md §11 Keyboard).
- Do NOT remount FindingsDropdown/counter on each re-poll or flip a loading flag that blanks it — remount drops `document.activeElement` + the open-disclosure state (a11y-plan.md §11 + §7; 2026-07-07 do-not-remount rule).
- Do NOT add ARIA on non-semantic elements or use `outline:none` without a `:focus-visible` replacement on panel controls (a11y-plan.md §11 ARIA/Keyboard).

## Contract bindings
- **Focus ↔ Tauri IPC / layouts**: cross-window focus restoration (panel→badge) depends on the widget window regaining focus and moving focus to the badge via the same `core:window` show/set-focus IPC this chunk grants (a11y-plan.md §5; binds layouts focus-management + the chunk's `core:window:allow-set-focus`/`allow-show`). The capability JSON is out of a11y domain; the focus-restore BEHAVIOR is a11y's.
- **Harness ↔ tests**: p8/keyboard-focus specs run in the tests E2E Playwright chain; the new window label must be handled by `helpers/mock-tauri.ts` (reads `__TAURI_INTERNALS__.metadata.currentWebview.label`) and, if the window has its own route, the pa11y/Lighthouse route config (a11y-plan.md §3 harness wiring; binds tests §9 CI gate + the `baselines/a11y-violations-summary.json` regression baseline).
- **Violation JSON ↔ obs**: any new axe finding emits the §3 structured violation JSON (`wcag_criterion`/`violation_type`/`severity`/`surface`) in obs §6 log format, tagged for the new window surface (a11y-plan.md §3).
- **State color + label ↔ design**: severity dot color paired with the severity word (not-color-alone) reuses the design §Color Palette token pairing (a11y-plan.md §6).

## Acceptance criteria contributions
- (a11y) Cross-window focus restore: with the panel open, Esc (and blur / row-select / mark-all-read) dismisses it AND focus returns to the unread badge in the widget window — asserted in the keyboard-focus spec across the window boundary (a11y-plan §5, SC 2.4.3 / 2.1.2).
- (a11y) The badge `aria-expanded` reflects the panel window's actual open/closed state; opening moves focus into the panel (a11y-plan §4, SC 4.1.2).
- (a11y) axe: the new Findings window surface has zero critical/serious violations, each severity row carries the severity word in its accessible name (not color alone), and 0 new regression tuples vs baseline (a11y-plan §10 + §6, SC 1.4.1).
- (a11y) Live badge: the re-poll/subscription updates the unread count WITHOUT remounting the open panel/counter (focus + scroll preserved); the 0→N transition announces once politely via the existing StatusLiveRegion (a11y-plan §7, SC 4.1.3 / 2.1.1).
