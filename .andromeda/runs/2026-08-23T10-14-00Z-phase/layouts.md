# layouts extract

## Relevance
**Partial** — the chunk's build is storage/ingest/scrub (out of domain), but its read-back surface (`MetricsRoute.tsx` / `MetricsChart`) and its premise 6 empty-vs-error branch sit inside the desktop-webview **Full dashboard (Metrics view)** that layout-templates.md owns.

## Constraints
- The Metrics view is a full-dashboard primary screen — time-series overlay for throughput + latency in the primary content region, carrying **the same header / tab-nav / footer structure as Traces**; any label read-back that becomes user-visible must land in that region, not a new chrome slot (per layout-templates.md §Surface: desktop-webview → Primary screens).
- §Component — Empty / error state requires the **error variant to be checked BEFORE the empty branch**, rendering a static "Couldn't load metrics" (never the raw `AppError`) with **no exporter hint**, "so a failure never masquerades as 'no data'". The chunk's premise 6 records that a *rejected ingest batch* is not a query error and therefore lands in the empty branch — whether that ingest-side silence violates this mandate, or is simply outside its stated trigger, is research's question, not something this plan settles.
- The empty branch may render only on a **settled zero-data load** ("never flashed while loading; hidden once populated"), message + hint in `color-text-secondary` `font-body`, hint naming the OTLP ports in `font-code` (per §Component — Empty / error state → Empty).
- A **single shared `EmptyState` component backs Metrics / Logs / Snapshots** "so the data views read as one system" — a Metrics-only divergence to signal label-drop is barred by that mandate (per §Component — Empty / error state → Applies to).
- The empty/error region is specified with **no focusable element** (read-only, affordance-exempt), so it contributes nothing to tab order; only a *new* interactive affordance would (per §Component — Empty / error state → Layout).
- The full dashboard is **resizable with no hard breakpoints** and the product is desktop-only (no mobile/touch surface); a widened row or new column must not introduce a media-query breakpoint (per §IA notes → Responsive behavior; top-of-file scope note).
- `/metrics` is a routable view and Metrics is a first-class nav entry with the standard active-state indicator; this chunk introduces no new procedure and therefore no new nav entry (per §Component — Primary navigation; §IA notes → Deep-link convention).

## Patterns to follow
- **Bounded-route / internal-scroll region (P-082)** — flex column bounded to the shell's `main` height with `overflow:hidden`, fixed (`flex-shrink:0`) regions stacked on top, and the data region flex-filling (`flex:1 / min-height:0 / overflow-y:auto`) under a sticky opaque `color-base` thead, so the dashboard never grows an outer page scrollbar. layout-templates.md documents this for the **Traces** primary screen only; it is the nearest precedent if label read-back adds any tabular/list surface to Metrics. Whether MetricsRoute already follows it is research's question (per §Wireframe — Full dashboard (Traces primary screen); §Component — Trace data table → Internal scroll region).
- **Shared `EmptyState` component** as the single backing for all three data views' zero-data and failure regions (per §Component — Empty / error state).
- **Column type-role convention** — `font-code` monospace for identity-shaped cells, `font-data` tabular numerals right-aligned for numerics, `font-body` for names; cell padding `space-sm`; transparent rows with 1px subtle bottom border. This is the precedent for how a label-set cell would read if one is surfaced (per §Component — Trace data table → Columns / Layout).
- **Filter toolbar as its own fixed row above the table** — right-aligned, `aria-pressed` toggle, kept fixed above the scroll region (P-068). The precedent if a label-set narrowing affordance ever surfaces (per §Component — Trace data table → Filter toolbar).
- **Read-only status readouts live in the footer band**, not inline in the content region — dashboard footer holds the service filter plus the plain-language `ConnectionStatusLine` (per §Component — Footer → Full dashboard).

## Anti-patterns to avoid
- Rendering the empty branch with its exporter hint in a situation that is actually a failure — layout-templates.md §Component — Empty / error state explicitly bars a failure masquerading as "no data"; the honest-error variant is the required shape.
- Surfacing label read-back through a new modal/dialog — the only specified dialogs on this surface are the trace-scoped Investigation modal and the Settings modal (per §Component — Investigation modal; §Component — Settings modal).
- Introducing a breakpoint-driven or reflowing variant to fit wider label content — the responsive posture forbids hard breakpoints on the dashboard and media queries on the widget (per §IA notes → Responsive behavior).

## Contract bindings
- **Empty/error copy color ↔ a11y contrast** — the plan pins `color-text-secondary` (NOT `color-text-tertiary`) explicitly citing a11y SC 1.4.3 ≥4.5:1 for body-size text; the a11y plan owns the ratio, layouts owns the placement (per §Component — Empty / error state → Empty).
- **Metrics content region ↔ the `metrics.*` TauRPC feed / `MetricRow` DTO** — layout-templates.md states both webview surfaces share the underlying `metrics.*` router feed; a new `MetricRow` field and its bindings regeneration are the route/data contract, not a layout change (per §IA notes → Navigation model; §Amendment 2026-05-02 handoff note "DuckDB query layer").
- **Focus order ↔ a11y §Focus Order SC 2.4.3** — dormant here because the specified region has no focusable element; it activates only if this chunk adds an interactive label affordance.

## Acceptance criteria contributions
- (layouts) Any user-visible label read-back renders in the primary content region of the full dashboard Metrics view, under the same header / tab-nav / footer structure as Traces — no new chrome region (per layout-templates.md §Surface: desktop-webview → Primary screens).
- (layouts) The Metrics view evaluates the error variant BEFORE the empty branch: a load failure shows the static "Couldn't load metrics" with no exporter hint; only a settled zero-data load shows "No metrics received yet" + the `:4318` / `:4317` hint (per layout-templates.md §Component — Empty / error state).
- (layouts) The Metrics empty/error region still renders through the shared `EmptyState` component with no Metrics-only variant, and adds no focusable element to tab order (per layout-templates.md §Component — Empty / error state).
- (layouts) No CSS media-query breakpoint is added to the full dashboard, and the Metrics route grows no outer page scrollbar if a scrolling data region is touched (per layout-templates.md §IA notes → Responsive behavior; §Component — Trace data table → Internal scroll region).
