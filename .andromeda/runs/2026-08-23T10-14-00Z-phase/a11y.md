# a11y extract

## Relevance
**Partial** — the carriage / persistence / scrub half is out of domain (no UI surface); a11y binds only where the label set reaches the desktop-webview read path (`MetricRow` → `metrics.*` IPC → `MetricsRoute.tsx` / `MetricsChart`) plus the standing per-PR no-regression gate that fires on any webview-visible change.

## Constraints
- The metrics dashboard is a must-be-accessible path (P4 real-time push of spans/**metrics**/logs, and P1's chart+table discipline), carrying the universal minimums SC 2.1.1 Keyboard / SC 2.4.3 Focus Order / SC 4.1.2 Name-Role-Value plus SC 4.1.3 Status Messages and SC 1.4.3 Contrast on live values — per a11y-plan.md §1 Critical Paths (P1, P4) and §10 SLO Invariants (coverage applies across P1–P12).
- Zero WCAG AA violations on must-be-accessible paths and **zero new violations per PR** vs the base-branch summary are hard build-failure conditions, with no retry-once and no soft gate — per a11y-plan.md §10 SLO Invariants & A11y Budgets. Whether the metrics route is currently in the audited route set (pa11y/Lighthouse configs, p1–p12 axe specs) is research's question.
- Any label text newly rendered must use a token pair meeting SC 1.4.3 (4.5:1 normal text / 3:1 large) and any label-derived non-text indicator ≥ 3:1 (SC 1.4.11) — per a11y-plan.md §6 Color contrast pairs. `--color-text-tertiary` is only licensed for large text.
- If a label set is what visually distinguishes two otherwise-identical data points (the chunk's stated outcome), that distinction must not be carried by color alone — SC 1.4.1 requires a text or icon supplement, and axe-core does **not** detect this, so a custom assertion is required — per a11y-plan.md §6 State color tokens (not-color-alone) and §1 A11y triggers (visual-discrimination).
- The WebGPU canvas has no built-in semantics; label/series meaning must live on the wrapper (`region` + accessible name) and on the row/table structure, not inside `<canvas>` — per a11y-plan.md §1 Scope (WebGPU canvas entity) and §7 Landmark roles.
- Incremental metric rows arriving over the Tauri IPC channel must not steal focus and must announce via `aria-live="polite"` / `role="log"`, with focus stable across re-renders — per a11y-plan.md §1 Critical Paths P4 and §7 Live regions.
- Semantic HTML first, ARIA second; every WCAG claim needs a machine-verifiable path (axe/Lighthouse/pa11y/Playwright JSON) — manual SR/keyboard/contrast is supplemental, never sole — per a11y-plan.md §2 Agent-runnable invariants.

## Patterns to follow
- **Fixture-backed audit mock:** a11y Playwright specs drive the SPA through `tests-a11y/helpers/mock-tauri.ts` with payloads from `helpers/v02-fixtures.ts`, TauRPC procedures matched as `TauRPC__<router.path>`. A `MetricRow` shape change means the metrics fixture must carry the new label field, otherwise the metrics-route audit renders a label-less UI and proves nothing — per a11y-plan.md §3 Harness wiring & conventions. Whether a metrics fixture exists there today is research's question.
- **Standing rule — one axe spec per surface, same chunk** (p8–p12 are the template), with real (non-hash) route paths configured in the pa11y + Lighthouse configs, served via `helpers/static-server.mjs` SPA fallback — per a11y-plan.md §3 Harness wiring & conventions.
- **Cheap suite-health check** `npx playwright test --list` before trusting a green a11y run — a list-time import failure once silently disabled the whole suite — per a11y-plan.md §3 Harness wiring & conventions.
- **Contrast remediation precedent:** demoted metadata text in tables was moved `--color-text-tertiary` → `--color-text-secondary` rather than left as tertiary; severity/state got a colored **border + text**, not color alone — per a11y-plan.md §6 + §11 Visual (applied at the 2026-06-10 re-audit).
- **Table + region semantics for telemetry rows:** `table` structure for row data, `region[aria-label=...]` wrapper for the chart, `status` for counters — per a11y-plan.md §1 Critical Paths (P1/P4) and §7 Landmark roles.

## Anti-patterns to avoid
- NEVER convey the label-set distinction (or a redaction state) by color alone — state indicators require text/icon supplement per SC 1.4.1 — a11y-plan.md §11 Visual.
- NEVER introduce a foreground/background pair below the WCAG minimum (4.5:1 text / 3:1 large / 3:1 non-text) for new label text or new chart legend chrome — a11y-plan.md §11 Visual.
- NEVER defer a11y to post-merge or ship lint-only coverage: the a11y chain is a FAIL-fast PR gate, and conformance may not be claimed without machine output — a11y-plan.md §11 CI + §11 Universal.

## Contract bindings
- **A11y violation JSON → obs §6 structured log format** (`wcag_criterion` / `violation_type` / `severity` / `surface` / `selector` / `remediation` / `tool` / `tool_result_id`, optional `token_name`, `measured_value` / `required_value`, `affected_component`) — per a11y-plan.md §3 Structured violation JSON schema. This is a **separate** counter surface from the chunk's `redactions_applied` persisted-cells-only rule (obs-plan §5); do not conflate the two.
- **CI a11y gate → tests harness** — `npm run test:a11y` / `cargo xtask test:a11y` runs inside the same `ci.yml` pipeline and reuses tests' 5-command E2E driver (`boot` / `run` / `status` / `cleanup` / `logs`); regression compared against `baselines/a11y-violations-summary.json` on `{surface, wcag_criterion, selector, severity}` tuples — per a11y-plan.md §3 CI integration + §9.
- **Contrast + state color → design-system color palette** — token pairs (`--color-text-primary|secondary|tertiary / --color-base`, `--color-accent`, `--color-feedback-success`, `--border-focus`) are read verbatim from design; a11y only asserts ratios — per a11y-plan.md §6.
- **Read-path DTO → a11y fixtures** — a new `MetricRow` field regenerates `pulse-app/ui/src/bindings/index.ts`; the a11y mock consumes the same DTO shape via `v02-fixtures.ts`, so the binding change propagates into the audit surface — per a11y-plan.md §3 Harness wiring & conventions.

## Acceptance criteria contributions
- If any label content becomes visible in the webview, the full a11y chain (axe-core/playwright + Lighthouse + pa11y) passes with **zero new violation tuples** against `baselines/a11y-violations-summary.json` and Lighthouse a11y ≥ 90 on the metrics route (per a11y-plan.md §10 SLO Invariants + §3 Harness wiring & conventions).
- Any newly rendered label text asserts ≥ 4.5:1 (or ≥ 3:1 large-text) against its background token pair via the colorjs.io/axe contrast harness — no `--color-text-tertiary` for label values at body size (per a11y-plan.md §6 Color contrast pairs).
- Where the label set is the thing distinguishing two data points on screen, the distinction is readable as **text** (or icon + text), verified by DOM inspection rather than by series color — SC 1.4.1 (per a11y-plan.md §6 State color tokens + §1 A11y triggers, visual-discrimination).
- Metric rows added by the live IPC push announce via `aria-live="polite"` without moving focus, and the keyboard-focus spec still passes on the metrics layout — SC 4.1.3 / SC 2.4.3 (per a11y-plan.md §1 Critical Paths P4 + §7 Live regions).

Whether these are already satisfied by the current metrics route (existing axe spec, existing contrast tokens, existing live-region markup) is research's question — the plan states target state only.
