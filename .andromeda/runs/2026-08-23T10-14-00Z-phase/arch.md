# arch extract

## Relevance
Relevant — arch is load-bearing here: the metric-point storage shape, table/column conventions, the cross-bridge DTO rule, and the real-OTLP test-injection discipline all bind this chunk.

## Constraints
- The metric-point key `(metric_name, ts_unix_nano, resource_hash, seq)` is settled, and the plan's own stated reason for it is that `metrics_points` stores **no attributes column at all** — i.e. the gap this chunk closes is recorded as a spec-level fact. `seq` is the ONE declared exception to the no-surrogate-key rule and is mandated to be **never an observable** (absent from `BufferStateSnapshot`, `buffer.tick`, `SELECT_LOGS`/`SELECT_METRICS`/`COUNT_METRICS`, the `metrics.*` IPC response, the MCP response shape). A label representation must neither become a second surrogate nor make `seq` observable (per architecture.md §Conventions → Primary key convention).
- Column names are `snake_case`; the ring-buffer cutoff is a periodic `DELETE FROM <table> WHERE ts < …` task; **§Occupied Resources is the canonical table-name list, the Convention defines only the shape**. Three reserved tables (`resources`, `instrumentation_scopes`, `span_links`) are recorded as declared-but-never-written with dead DELETEs, and their cleanup is owned elsewhere — so any new table this chunk lands must arrive with a producer *and* a sweep entry (per architecture.md §Conventions → Database entity naming; §Occupied Resources → DuckDB database / schema names).
- Nullable columns are reserved for OTLP-spec-**optional** fields; required spec fields are `NOT NULL`. A data-point attribute set is spec-optional, so the nullability disposition of a label column/table must be argued from that rule, not chosen freely (per architecture.md §Conventions → Nullable patterns).
- No ORM and no migration framework: DDL is created on startup via direct SQL through the `duckdb` crate `Connection` + `Appender`, and the ingest hand-off is Arrow zero-copy `append_record_batch()`. A label column must ride the existing record-batch builder, not a second write mechanism (per architecture.md §Established Decisions [ORM / Migrations]; §Stack and Technologies → Columnar interchange; §Inherited Defaults).
- Anything crossing the TauRPC bridge or appearing in an MCP tool response must be `serde::Serialize` (compile-time enforced by the derive macros), and the frontend consumes **only** TauRPC-generated `.ts` bindings — no manual TypeScript re-declaration; the generated bindings are typechecked with `tsc --noEmit` in CI (per architecture.md §Cross-cutting Patterns → Cross-bridge data shape; §Conventions → Workspace API style; §Stack and Technologies → Code quality).
- Workspace crate names are LOCKED (`buffer`, `viz`, `security`, `mcp-server`, `ui-bridge`, `pulse-app`, …) and the dependency graph is a DAG flowing toward `pulse-app`; **no library crate depends on a sibling unless its declared contract requires it**. This is the rule that governs the scope's "`viz` has no `buffer` dep, so its fixture DDL copy is structurally unguarded" — closing that by adding a dep is a contract question, not a convenience (per architecture.md §Occupied Resources → Cargo workspace crate names; §Cross-cutting Patterns → Module dependency direction; §Conventions → Module visibility discipline).
- The OTLP receiver surface is spec-fixed with no project-specific envelope, so label carriage must come from reading the already-decoded `p.attributes` off the OTLP payload — the wire format itself is not a lever (per architecture.md §Established Decisions [API Style — OTLP Receiver Surface 1]; §Standard Contracts → OTLP receiver).

## Patterns to follow
- The `seq` block-reservation precedent from the immediately-prior chunk: a buffer-global per-table counter exposed as one narrow public boundary on `BufferState`, deliberately kept off every read surface (per architecture.md §Conventions → Primary key convention; §Conventions → Module visibility discipline).
- Single Arrow write path — the plan records `append_record_batch_to_table` as the only DuckDB write path in `crates/buffer`, firing for exactly four tables. New columns extend that one batch builder (per architecture.md §Occupied Resources → DuckDB database / schema names; §Stack and Technologies → Columnar interchange).
- The two sanctioned metric read surfaces already exist: the `metrics.*` query router (viz crate) and the `pulse://stream/metrics` Tauri `Channel` carrying **binary Arrow IPC** payloads (no JSON-stringify tax). A read-back proof should use these rather than introduce a third (per architecture.md §Occupied Resources → Tauri IPC routes; §Standard Contracts → Real-time push contract).
- Registry-site discipline for the wrap amendment: §Conventions carries the *shape* rule, §Occupied Resources carries the *enumeration*. Whether a new label column needs a §Occupied Resources entry is answered by that split (per architecture.md §Conventions → Database entity naming; §Occupied Resources).
- E2E injection speaks OTLP to the running receiver on `:4317`/`:4318`, resolving non-default ports via `ANDROMEDA_PULSE_OTLP_GRPC_PORT` / `_HTTP_PORT`, and inspects buffer state through the `traces.*`/`metrics.*`/`logs.*` routers (per architecture.md §Cross-cutting Patterns → Test-time telemetry injection).

## Anti-patterns to avoid
- No UUID or random surrogate keys; `seq` is the sole declared exception and must stay unobservable — a hashed label key that becomes a de-facto second surrogate needs an explicit decision against this rule, not silence (per architecture.md §Conventions → Primary key convention).
- No in-process test-mode bypass, no separate "test ingest" feature flag, no mock-channel back-door — the RED-before-GREEN measurement must run over the real receiver (per architecture.md §Cross-cutting Patterns → Test-time telemetry injection).
- Do not land a reserved table with no producer and no retention-sweep entry; three such tables already exist and the plan states a claim keyed on "the reserved tables" must not be read as "the written tables" (per architecture.md §Occupied Resources → DuckDB database / schema names).

## Contract bindings
- **arch ↔ security**: the write-boundary scrub. Arch's reserved-table/column enumeration is the substrate for security-plan §Anti-Patterns → Logging's scrub-coverage claim (arch records that the same producer-less fact is stated there from the PII side). A new persisted label column/table changes what that enumeration must say; the scrub itself is security's mandate, not arch's.
- **arch ↔ obs**: the persisted-cells-only `redactions_applied` counting rule (obs-plan §5) keys on what arch defines as a persisted column — arch fixes *which* cells count, obs fixes the counting.
- **arch ↔ tests**: §Cross-cutting Patterns → Test-time telemetry injection is the harness contract (OTLP-only ingress, query-router read-back); the tests plan owns the harness invocation, arch owns the ban on bypasses.
- **arch ↔ design/frontend**: a new `MetricRow` field regenerates `pulse-app/ui/src/bindings/index.ts` under §Conventions → Workspace API style (generated bindings only); the rendered treatment in `MetricsRoute.tsx`/`MetricsChart` is design's.
- **Not a binding (per plan, but verify)**: TauRPC capability granularity is the IPC *layer*, and the per-procedure gate is the `EXPECTED_PROCEDURES` pin — not a capability-JSON edit. The scope's `[inferred]` note that a DTO-shape change leaves `capability-drift` untouched is consistent with this, but whether the gate keys purely on procedure names at HEAD is research's question.

## Acceptance criteria contributions
- (arch) All label carriage/persistence/read-back code lands in the locked crates (`buffer`, `viz`, `security`, `mcp-server`, `ui-bridge`/`pulse-app`); no new workspace crate name and no library→binary or unjustified sibling dependency is introduced (per architecture.md §Occupied Resources → Cargo workspace crate names; §Cross-cutting Patterns → Module dependency direction).
- (arch) If the chosen representation adds a reserved table, it is registered in §Occupied Resources, lands a real producer, and is added to the retention sweep (or to the excluded set) — no fourth producer-less or unswept table (per architecture.md §Occupied Resources → DuckDB database / schema names).
- (arch) Any new DTO field crossing the bridge is `serde::Serialize` and reaches the webview only via regenerated TauRPC bindings that pass `tsc --noEmit`; no hand-written TypeScript declaration of the shape (per architecture.md §Cross-cutting Patterns → Cross-bridge data shape; §Conventions → Workspace API style).
- (arch) The pre-fix indistinguishability and the post-fix distinguishability are both measured over the real OTLP receiver and read back through the `metrics.*` query router (or `pulse://stream/metrics`), with no in-process bypass; new columns are `snake_case`, nullability follows the spec-optional rule, and no surrogate key beyond the declared `seq` exception appears (per architecture.md §Cross-cutting Patterns → Test-time telemetry injection; §Conventions → Database entity naming / Nullable patterns / Primary key convention).
