- The widget shell must NOT emit layout_mode or snap-to-edge coordinates in log fields at `info` level in a tight window-move loop — only on discrete state transitions (per obs-plan §11 Anti-Patterns Logs: "NEVER log in hot path at `info` level").

## Patterns к follow

- Layout transition instrumentation uses `#[tracing::instrument(skip_all, fields(layout_mode_from, layout_mode_to, duration_ms, span.kind = "internal"))]` on the Rust handler that performs the window resize/position change — matches `{module}.{operation}` naming convention (`ui.layout.transition`) per obs-plan §4 Span naming convention.
- Tray visibility changes use `tracing::info!(target: "tray.{event}", tray_visible = ...)` on Tauri lifecycle hook callbacks — matches the existing desktop-native tray instrumentation pattern from obs-plan §4 Surface table "Desktop-native (tray icon)".
- Frontend widget lifecycle (skeleton duration, first-paint, empty state) uses the established TauRPC `telemetry.frontend.record_*` bridge already wired in chunk #29 (`telemetry.frontend.record_frame_ms`) — same pattern extended to widget-open and widget-close events, per obs-plan §3 "Frontend bridge" and §4 Surface table "Desktop-webview".
- Platform identity fields on boot spans (`webview_backend`, `wgpu_backend`, `tray_api`) are bounded enumerated values, consistent with obs-plan §5 Metric label cardinality discipline (enumerated values only for product-internal metrics).
- Heartbeat ticks: the compact widget does not introduce a new long-running subsystem, so no new `*.tick` event is needed; the existing `viz.tick` covers the visualization subsystem the widget is part of (per obs-plan §3 Heartbeat ticks tick format).

## Anti-patterns к avoid

- NEVER hold a `tracing::Span` guard across `.await` points inside window-position or snap-to-edge async handlers without `.in_current_span()` — context bleeds into unrelated tokio tasks (per obs-plan §11 "NEVER hold a `tracing::Span` guard across `.await` points").
- NEVER emit raw window coordinates (x/y/width/height) as `tracing` event fields at `info` or `debug` level in the window-drag or snap-to-edge loop — that constitutes hot-path log spam and carries no security-sensitive value but costs throughput (per obs-plan §11 Anti-Patterns Logs "NEVER log in hot path at `info` level" + §11 Metrics "NEVER format expensive payloads inside hot paths without level-gating").
- NEVER skip the platform-specific boot spans (`app.boot.webview.init`, `app.boot.tray.init`) for the compact widget's first window creation — agent loses multi-platform debug correlation across Windows/macOS/Linux (per obs-plan §11 "NEVER skip spans on critical user-facing paths").
