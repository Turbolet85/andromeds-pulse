## Chunk relevance

Five distinct security surfaces touched: (1) new `workspace.*` TauRPC namespace introducing filesystem read of arbitrary host project paths (CWE-22 path-traversal class), (2) snapshot file persistence to `~/.andromeda-pulse/snapshots/` (incidentally captured secrets — Logging hygiene), (3) clipboard write of curated markdown (clipboard contents NEVER-log + visible-signal toast), (4) `tauri-plugin-notification` capability widening risk (`pulse:notification` outbound-emit-only), (5) refined `snapshot.generate` IPC return type crossing the `AppError` sanitization boundary.

## Constraints

- All path inputs to `workspace-detector` (workspace root candidate, `.andromeda/` marker probe, snapshot output dir) MUST canonicalize via `strict-path` and assert the resolved path lives under an explicit base before use; `ANDROMEDA_PULSE_DATA_DIR` override semantics for the snapshot dir MUST honor the same canonicalize-and-confine primitive (per security plan §Input Validation row 6 + §Anti-Patterns Input row 4 CWE-22 class defense + Session Additions 2026-05-09 entry on TauRPC namespace registration).
- The new `workspace.*` and any refined `snapshot.*` procedures MUST land with BOTH (a) router registration in the owning crate AND (b) a matching `pulse-app/capabilities/` JSON entry AND (c) `xtask/src/main.rs::EXPECTED_PROCEDURES` extension in the SAME commit that consumes them — drift is silent runtime rejection (per §API Security TauRPC capability authorization + §Anti-Patterns API row 3 + Session Additions 2026-05-09 / 2026-05-10 coupling discipline).
- `pulse:notification` capability JSON MUST list ONLY the outbound-emit subset of `tauri-plugin-notification` permissions; NEVER add any incoming notification-action handler (e.g., notification click → re-enter Rust with arbitrary string payload) without a separately-named capability with stated rationale (per §Anti-Patterns API row 6 — outbound surface MUST NOT become a phishing / IPC-abuse vector).
- The clipboard-write step MUST emit a `pulse://stream/snapshot-progress` event at write time so the UI can render a non-suppressible "X bytes copied" visible signal that data left the app's address space — this is a load-bearing user-trust requirement, not optional (per §Logging & Monitoring "Snapshot / clipboard / MCP-tool-response hygiene" bullet 2).
- New tracing emission targets MUST scrub: NEVER log raw snapshot file contents, NEVER log clipboard contents, NEVER log full snapshot file path (basename only is acceptable), NEVER log `.andromeda/` marker absolute path or VCS metadata content (basename / boolean-detected only), NEVER log workspace-detector outputs verbatim (host project context can include sensitive directory names) — apply allowlist at observability `AllowList::production()` scrubber per project pattern + §Anti-Patterns Logging rows 1-2.
- The refined `snapshot.generate` IPC return type (replacing chunk #42's `Result<(), AppError>` placeholder) MUST cross the bridge as a `serde::Serialize` shape that does NOT leak filesystem paths, Rust struct names, library versions, or stack traces in any error variant; if `Err(AppError::Internal { message })` carries a path-related failure, the message MUST be sanitized to a one-liner (per §Error Handling TauRPC bridge + §Anti-Patterns Logging row 4).
- Both `tauri-plugin-clipboard-manager` and `tauri-plugin-notification` (or equivalents chosen at /implement) introduced as new dependencies MUST clear `cargo deny check bans licenses sources` + `cargo audit`; any newly-introduced multiple-versions duplicate MUST be listed in `deny.toml [bans] skip` with one-line provenance comment per Session Additions 2026-05-03 entry, NOT by relaxing `multiple-versions = "deny"` (per §Dependency Security CI integration + Session Additions 2026-05-03).

## Patterns to follow

- TauRPC namespace registration triple-binding pattern: arch §Occupied Resources update (via `/andromeda-scope-arch` BEFORE merge) + `pulse-app/capabilities/` JSON addition + `xtask/src/main.rs::EXPECTED_PROCEDURES` const extension — couple all three in the consuming commit per Session Additions 2026-05-09 + 2026-05-10. Chunk #34 + chunk #42 are the recent precedents (chunk #42 added `snapshot.generate`, line 55 + 63 of `pulse-app/ui/src/bindings/index.ts`).
- AllowList scrubber per-leaf entry pattern: every new `tracing::warn!(target: "X.Y.Z.event", field1, field2)` call site needs a matching entry in `pulse-app/src/observability.rs::AllowList::production()` with bounded field names + paired tests (positive resolver fn + negative canary fn) — chunk #41 + chunk #42 establish the unrolled-explicit-fn shape per testing.md Session Addition 2026-05-10. Chunk #43 will introduce new tracing targets for `workspace.detect.request`, `snapshot.generate.success`, `snapshot.copy_to_clipboard.request` (or equivalent leaf names).
- Sanitized `AppError::Internal { message }` From-impl pattern: module-internal `thiserror` 2.x enums in `workspace-detector` + extended `snapshot` errors collapse to `AppError::{Internal, NotFound, Storage}` at the bridge via `From` impls; the impl strips file paths / Rust struct names / library versions per §Error Handling TauRPC bridge bullet. The full chain stays in the internal `tracing-error` SpanTrace.
- Settings-as-default-for-state extension pattern: if chunk #43 needs persistable state (e.g., last-used preset for workspace, snapshot output dir override, "show-secrets-warning" first-run flag), prefer extending `crates/ui-bridge/src/contract.rs::Settings` over introducing a new TauRPC namespace per Session Additions 2026-05-09 entry (lower-cost path; sidesteps the triple-binding entirely for state that fits get/set semantics).
- `strict-path` canonicalize-and-confine pattern: same primitive used for `ANDROMEDA_PULSE_*_PATH` / `*_DIR` env vars (per §Bootstrap phases `input-validation-library-install`) is the right primitive for workspace-root candidate paths arriving via TauRPC argument or env override; verify resolved path before any filesystem read.

## Anti-patterns to avoid

- NEVER `tokio::process::Command::new(...).arg(user_input)` against any string sourced from workspace-detector output (e.g., spawning `git` against a detected workspace path, shelling out to a VCS tool against arbitrary directory names) — this is the live 2025-2026 MCP STDIO command-injection cluster (CVE-2025-49596, CVE-2025-54994, CVE-2025-54136 Cursor, CVE-2026-22252 LibreChat) per §Anti-Patterns Code Patterns row 1. If VCS metadata extraction is needed, prefer pure-Rust git crates (e.g., `gix`) over subprocess invocation.
- NEVER widen `pulse:notification` capability JSON to include input-event handlers (notification click callbacks, action button payloads) — outbound emit subset only per §Anti-Patterns API row 6. The "Snapshot ready" toast is a one-way emission; if the user clicks it to focus the app, that focus action MUST go through the existing OS-level window-focus path, not a notification-action IPC re-entry.
- NEVER log full paths of detected workspace root, `.andromeda/` marker location, VCS metadata, snapshot file destination, or clipboard payload — log basenames only (canonicalized basename for paths) per §Anti-Patterns Logging rows 1-2 + Session Learnings tier-1 entry "Telemetry is user-controlled content".
- NEVER write snapshot files to a path constructed from workspace-detector output without canonicalize-and-confine via `strict-path` against the resolved data dir — a malicious/typo'd workspace path could otherwise traverse to `~/.andromeda-pulse/snapshots/../../etc/...` per §Anti-Patterns Input row 4 CWE-22 class.
