## Constraints

- Arrow IPC binary streaming MUST preserve the data → canvas push path that sidesteps React's VDOM (per design plan §Surface: desktop-webview Performance notes — "Charts (Halo State Pulse, Latency River) are rendered directly to canvas, NOT inside React's render tree — Arrow data is pushed into canvas via WebGPU compute shader, side-stepping VDOM diffing cost"). The broadcast envelope MUST emit binary Arrow (not JSON-stringified) so this contract holds.
- The three event names MUST be `pulse://stream/spans` / `pulse://stream/metrics` / `pulse://stream/logs` — these are the data channels that downstream canvas surfaces (Halo State Pulse, Latency River, throughput counter) subscribe к (per arch §Standard Contracts Real-time push contract; design plan §Surface: desktop-webview Component Patterns "Canvas Container" assumes these stream names exist by chunk #28+).
- Size cap on Arrow IPC payloads MUST hold within the data-viz layer's frame budget assumption — design specifies WebGPU compute shaders consuming Arrow batches per frame, so back-pressure / dropped-batch policy at the Tauri Channel boundary cannot stall the Halo State Pulse 0.8–2.4 Hz rhythm or the canvas paint loop (per design plan §Motion "Halo State Pulse breathing: WebGPU shader-driven, sinusoidal animation at 0.8–2.4 Hz (data-driven frequency, exempt from chrome budget)").
- `_trace_context` Arrow metadata column is а design-tokens-adjacent concern only inasmuch as it must NOT carry user-controlled string content (OTLP attribute values, log message bodies) that could collide with the design plan's "minimal chrome, contemplative" rendering — the column carries traceparent / tracestate identifiers only, and any rendering of trace IDs к UI happens via JetBrains Mono `--font-code` per §Typography Code/Data row (data display tokens already locked).

- Canvas-first push pipeline: Arrow batches arrive at the webview already in а shape WebGPU compute shaders can ingest without copy — preserving the §Surface: desktop-webview "Canvas Container" pattern that the Halo State Pulse, Latency River, and throughput counter are direct canvas paints, not React state mutations.
- Stream-name discipline: `pulse://stream/spans|metrics|logs|snapshot-progress|plugin-events` form а namespace already declared in arch §Occupied Resources Tauri IPC events; chunk #23 reserves the first three. The two unreserved (snapshot-progress, plugin-events) belong к chunks #36 and #37 respectively — do not consume their names here.
- Per-surface stream consumer model: design plan §Surface: desktop-webview "Compact widget" + "Full dashboard" + §Surface: desktop-native "Tray Icon" all subscribe к the same broadcast streams (mpsc → broadcast fan-out one-to-many per arch §Established Decisions [In-Process Channel Architecture]). Chunk #23's broadcast::Sender capacity must accommodate ≥3 simultaneous subscribers without dropping (compact widget canvas + full dashboard canvas + tray icon Halo composite layer per §Self-Validation Protocol Signature Test "(1) full dashboard canvas, (2) compact widget, (3) tray icon").

## Anti-patterns к avoid

- NEVER JSON-stringify span/metric/log payloads on the Tauri Channel — design plan §Surface: desktop-webview Performance notes explicitly mandates "Arrow data is pushed into canvas via WebGPU compute shader, side-stepping VDOM diffing cost". JSON marshalling re-introduces the VDOM tax that the design pipeline is built к avoid.
- NEVER let backpressure manifest as visible canvas stutter — the Halo State Pulse is the §Self-Validation Protocol Signature Test signature element; if frame paints stall waiting on broadcast::Receiver, the rhythm degrades and the design's data-driven motion contract (per §Motion "data-driven and never decorative") breaks. Drop-oldest / lagged-receiver semantics must be chosen at chunk #23 with this constraint named.
- NEVER widen the stream namespace beyond the three reserved here — `pulse://stream/snapshot-progress` is bound к chunk #36's Investigation Capture Collapse supporting moment (per §Motion "supporting moments" + §Decisions Log "Snapshot generation (curated observation log)"); claiming it at chunk #23 would force re-litigation of the supporting-moment timing later.
