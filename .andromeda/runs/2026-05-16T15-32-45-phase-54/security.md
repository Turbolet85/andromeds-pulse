## Patterns to follow

- **Cargo workspace new crate follows existing workspace member shape**: each library crate has a `Cargo.toml` with a minimal `[dependencies]` set + `[lib]` declaration; `deny.toml [bans]` skip list must be extended if the new crate introduces any known-benign duplicate (per security plan §Dependency Security + `.claude/rules/security.md` Session Addition 2026-05-03 "Each Tauri major + minor-version bump…"). For a refactor-only extraction with no new deps, skip-list changes are unlikely but must be verified via `cargo deny check bans` after the new workspace member is wired.
- **Logging redaction applies at the subscriber layer, not call sites**: curation modules that emit `tracing` spans should use structured field names without embedding raw OTLP content — follow the pattern from existing `snapshot` / `viz` crate instrumentation where field names are `query_id`, `param_count`, `service_count`, not `attribute_value` (per security plan §Logging & Monitoring "Log format" + "What NEVER to log").
- **`pub(crate)` default for internals, `pub` only for contract re-exports**: the `curation::contract` module is the only `pub` surface; dedupe / anomaly / critical_path / aggregation internals stay `pub(crate)` within `crates/curation/` — mirrors the existing `snapshot` crate's visibility structure (per arch Conventions §Module visibility discipline; security plan §Threat Model Summary IPC boundary enforcement relies on Cargo visibility as the compile-time enforcement of module boundaries).

## Anti-patterns to avoid

- NEVER expose curation internals (`dedupe`, `anomaly`, `critical_path`, `aggregation` implementation functions beyond the declared `curation::contract` re-export) as `pub` in `crates/curation/src/lib.rs` — this would silently widen the API surface available to future downstream crates, creating an accidental dependency surface that bypasses the module-boundary DAG (per security plan §Security Anti-Patterns §Code Patterns last bullet on `wasmtime::Linker` bypass analogy; arch Conventions §Module visibility discipline).
- NEVER add a new `tracing::event!` in the curation modules that includes raw OTLP-derived content as a field value (span names, attribute values, metric label values) — anomaly detection and dedup modules by definition process OTLP attribute content, which per the threat model may contain incidentally captured secrets from the instrumented host application (per security plan §Logging & Monitoring "What NEVER to log" first bullet; §Threat Model Summary Data classification "Sensitivity note").
- NEVER add a net-new external dependency (crate not already in `Cargo.lock`) to `crates/curation/Cargo.toml` without first verifying `cargo deny check bans licenses sources` passes — refactor-only means the new crate should re-declare existing workspace-internal dependencies only (per security plan §Dependency Security; `.claude/rules/security.md` Session Addition 2026-05-03).
