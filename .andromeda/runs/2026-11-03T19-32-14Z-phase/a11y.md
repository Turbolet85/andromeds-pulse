## Relevance
partial: the chunk is a Rust supply-chain upgrade with product behaviour out of scope, so it adds no UI surface. The a11y CI gate must stay green through it, and the npm supply-chain gate (steps 10–18) may read the a11y toolchain's packages.

## Constraints
- a11y-plan §10 SLO Invariants & A11y Budgets requires zero new WCAG AA violations per PR, measured as no violation tuple missing from the baseline committed in the tree (`pulse-app/ui/tests-a11y/baselines/a11y-violations-summary.json`). A dependency bump that changes rendered UI (for example, a forced API change in code that reaches the webview) must leave that diff empty. Whether any bumped crate reaches the webview's rendered output is research's question.
- a11y-plan §3 CI integration (keyed contract `doc:a11y-plan/contracts/ci-integration`) requires the `a11y` job in `ci.yml` to stay a blocking gate: build, Playwright chromium, `cargo xtask test:a11y`, with artifact uploads that fail when no file is found. Unhiding supply-chain steps 10–18 must not reorder, soften or drop that job.
- a11y-plan §1 A11y Scope Summary pins the a11y tool majors: pa11y 10.x, Lighthouse 13.x, `@axe-core/playwright` / axe-core 4.11.x, pa11y-ci 4.x. pa11y-ci's nested pa11y 9 is covered by the npm-policy extract-zip exception. If the npm supply-chain gate reads red on an a11y tool, the plan's precedent (`2026-08-30-npm-advisory-coverage`) is to upgrade and re-baseline in-chunk with zero new violation tuples. A MAJOR crossing remains a founder fork under this chunk's boundary.
- a11y-plan §3 A11y testing tool pick (keyed contract `doc:a11y-plan/contracts/a11y-testing-tool-pick`) fixes the axe-core `runOnly` tag set (`wcag2a`/`wcag2aa`/`wcag21aa` + `wcag22aa`) and pa11y `--runner axe`. A tool upgrade must keep this configuration intact.
- a11y-plan §1 A11y Scope Summary classes the OTLP receivers, DuckDB and the TauRPC bridge as not-assertable, and the wasmtime plugin runtime as boundary-only. The rustls / quinn-proto / webpki / tokio / zstd / zip / wasmtime bumps therefore carry no a11y assertion of their own. Whether zbus_names / zvariant / event-listener sit under the Linux tray or OS-notification surfaces is research's question. Those surfaces have manual-only verification per a11y-plan §1 A11y Scope Summary.
- a11y-plan §11 A11y Anti-Patterns (CI) requires a11y to stay a fail-fast gate even when the supply-chain job is red. A red elsewhere never licenses skipping or deferring the a11y job.

## Patterns to follow
- Regression detection compares `{surface, wcag_criterion, selector, severity, violation_type}` tuples in `tests-a11y/regression-detector.mjs` (the last leg of `npm run test:a11y`) against the committed baseline. Read its `regression-set.json` to confirm a bump changed nothing (per a11y-plan §3 CI integration).
- Precedent for an advisory forcing an a11y-tool upgrade: upgrade, run the full a11y chain, and keep the committed baseline only when it shows zero new tuples. Record the major move in the tool-pin sentence (per a11y-plan §1 A11y Scope Summary).
- Amendments to pinned a11y tool versions go to the sibling `a11y-plan-amendments.md` through the wrap, never as a phase edit (per a11y-plan §12 A11y Decisions Log).

## Anti-patterns to avoid
- NEVER use a retry-once policy or a soft gate to get a flaky or red a11y leg past this chunk (per a11y-plan §11 A11y Anti-Patterns, SLO).
- NEVER narrow the axe-core configuration (`runOnly` excluding default rules) without an explicit Decisions Log entry, including as a workaround for a tool-upgrade break (per a11y-plan §11 A11y Anti-Patterns, Strategy).
- NEVER skip the a11y gate on CI failure or defer an a11y fix to a follow-up (per a11y-plan §11 A11y Anti-Patterns, CI).

## Contract bindings
- a11y ↔ tests: the `a11y` job shares the `ci.yml` pipeline and the 5-command harness with the tests E2E jobs (per a11y-plan §9 CI Integration). A supply-chain fix that touches shared CI must keep both green.
- a11y ↔ security-plan §Dependency Security: if the npm supply-chain gate reads red, the a11y toolchain devDependencies are the packages it reads. pa11y-ci's nested pa11y 9 relies on the npm-policy extract-zip exception (per a11y-plan §1 A11y Scope Summary).
