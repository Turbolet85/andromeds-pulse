## Constraints

- The custom glyph set is exactly five: `aperture`, `telescope`, `constellation-grid`, `star`, `circular-pulse` — each carrying a specific domain meaning ("view settings" / "investigate" / "service map" / "favorite snapshot" / "compact widget toggle") (per design-system.md §Iconography Primary custom set).
- Glyphs MUST be registered as React components at `<Root>/src/components/icons/` (resolves to `pulse-app/ui/src/components/icons/` per Surface: desktop-webview toolkit), addressable as `<Icon glyph="telescope" />` (per design-system.md §Iconography Primary custom set).
- Custom SVGs MUST be monochrome with `#E8EEF7` (Status White-Blue / `--color-text-primary`) as default fill, adaptable per state via design tokens (no hardcoded hex inside the glyph React component) (per design-system.md §Iconography + §Color Palette Text Hierarchy).
- Glyph rendered sizes are constrained to the size grid: 16px (tray icon, inline labels), 20px (buttons, list items, navigation), 24px (card titles, large buttons, hero elements) (per design-system.md §Iconography Size grid).
- The custom set is the PRIMARY visual language; Lucide / Heroicons may only be installed/referenced as fallback for secondary/generic icons where no domain-specific glyph exists — the registry itself ships only the 5 custom glyphs at this chunk (per design-system.md §Iconography Secondary library).
- Each glyph must visibly emerge from the Observatory / Constellation / Mission Control domain — telescope = observational astronomy, constellation-grid = celestial coordinates, aperture = telescope/microscope diaphragm, star = night-sky reference, circular-pulse = Halo State Pulse rhythm; generic stock-library shapes are explicitly rejected for these slots (per design-system.md §Anti-Patterns Rejected Defaults item 5).

## Patterns to follow

- Token-driven fill: SVG `fill` / `stroke` use `currentColor` (or CSS custom property reference) so callers can re-tint via Tailwind v4 `text-{color}` utilities mapped to the `@theme` tokens shipped in chunk #10 (per design-system.md §Surface: desktop-webview Tokens — `--color-text-primary`, `--color-accent`, `--color-feedback-success`).
- Component shape `<Icon glyph="telescope" size={20} />` (or per-glyph named exports `<TelescopeIcon />`) — design-system specifies the `<Icon glyph="…" />` form; either composition is acceptable as long as the addressable name matches the registry (per design-system.md §Iconography Primary custom set).
- Size + container padding pairing: 16px glyph → 4px padding, 20px glyph → 6px padding, 24px glyph → 8px padding — these padding values map to design tokens (`--spacing-xs` 4px, ~`--spacing-sm` 8px) so consumers compose icon-button surfaces with token-pure padding (per design-system.md §Iconography Size grid + §Spacing).
- "Icons clarify, not decorate" discipline — every glyph component should be authored to be removable without information loss; no purely-ornamental flourishes inside the SVG paths (per design-system.md §Iconography Rule).
- Mission Control / Observatory contemplative aesthetic — geometric precision, sharp-but-not-cold linework consistent with `--radius-sm` / `--radius-md` chrome (per design-system.md §Brand Identity Design direction + §Border Radius Personality).

## Anti-patterns to avoid

- NEVER hardcode hex color values inside the SVG `fill` / `stroke` attributes — must reference `currentColor` or one of the `@theme` color tokens; otherwise glyphs cannot retint per state and break the token-purity rule (per design-system.md §Anti-Patterns Universal Bans "NEVER use color purely for decoration" + Self-Validation Protocol §4 Token Test).
- NEVER substitute a generic stock-library glyph (Lucide / Heroicons / Material) for any of the five custom slots — the custom set IS the primary visual language; stock-library equivalents fail the Sameness Test (per design-system.md §Anti-Patterns Rejected Defaults item 5 + Self-Validation Protocol §5).
- NEVER add motion / animation inside the glyph SVG itself — `circular-pulse` is a static glyph that visually parallels the Halo State Pulse rhythm; the actual pulsing motion lives on the WebGPU canvas layer outside the React render tree, not as SVG `<animate>` (per design-system.md §Iconography + §Motion + Surface: desktop-webview Performance notes).
- NEVER ship the glyph components without the path resolved to `pulse-app/ui/src/components/icons/` exactly — the design plan specifies this path verbatim and downstream consumers (settings panel aperture, Investigate trigger telescope, snapshot favorite star, compact widget circular-pulse) will import from there (per design-system.md §Iconography Primary custom set).

## Contract bindings

- **design ↔ a11y (icons-as-affordances)**: when icons are used as the only label for an interactive control (e.g., titlebar settings aperture, Investigate telescope), the icon component must accept and render an accessible-name surface (`aria-label` / `<title>` inside SVG / `role="img"`) — design provides the glyph; a11y owns the not-icon-alone discipline mandated by the upcoming chunk #13 a11y dev stack (per design-system.md §Iconography Rule "Icons clarify" + binding flagged in design focus guide §Cross-domain bindings "State color + text label pairing").
- **design ↔ a11y (color contrast)**: glyph default `#E8EEF7` (Status White-Blue) on `#1A1D24` (Deep Control Gray) base must satisfy ≥3:1 non-text contrast (WCAG SC 1.4.11) in any chrome surface where the glyph is the sole visual indicator — design provides token + target; chunk #12 contrast verification harness owns the per-pair JSON emission gate (per design-system.md §Color Palette Text Hierarchy + Downstream Readiness "For a11y specialist" Contrast targets).
- **design ↔ tests (anti-pattern lint targets)**: glyph SVG content must not contain banned-effect markers — gradients, glassmorphic filters, `<animate>` blocks; the upcoming tests-domain motion-and-anti-pattern lint will scan the registered components against design-system.md §Anti-Patterns (per design-system.md Downstream Readiness "For tests specialist").
- **design ↔ design-tokens (chunk #10 dependency)**: glyph components consume `var(--color-text-primary)` / `var(--color-accent)` / sizing scale from the `@theme` block already landed in chunk #10; if the registry hardcodes hex it bypasses the token system the previous chunk just installed (per design-system.md §Surface: desktop-webview Tokens + Self-Validation Protocol §4).

## Acceptance criteria contributions

- (design) Five glyph React components — `aperture`, `telescope`, `constellation-grid`, `star`, `circular-pulse` — are exported from `pulse-app/ui/src/components/icons/` and addressable as `<Icon glyph="{name}" />` (or equivalent per-glyph component) per design-system.md §Iconography.
- (design) Each glyph SVG uses `currentColor` (or a `var(--color-*)` token reference) for `fill` / `stroke`; `grep -E '#[0-9a-fA-F]{3,6}'` over `pulse-app/ui/src/components/icons/*.{tsx,svg}` returns no hardcoded hex values per design-system.md §Anti-Patterns Universal Bans + Self-Validation Protocol §4 Token Test.
- (design) Each glyph component renders cleanly at the three size-grid points (16px / 20px / 24px) without rasterization artifacts at the standard 1x device pixel ratio per design-system.md §Iconography Size grid.
- (design) Each glyph SVG contains no `<animate>` / `<animateTransform>` / `<animateMotion>` / inline gradient / filter elements — registry ships static monochrome glyphs only; pulse rhythm lives on the WebGPU layer per design-system.md §Iconography + §Motion Hard limits.
- (design) Sameness Test passes: each of the five glyph names maps to a domain-anchored shape (aperture diaphragm, telescope barrel, celestial-grid lattice, star, ring-with-radial-pulse outline) — a reviewer can identify the Observatory metaphor without reading the filename per design-system.md Self-Validation Protocol §5 Sameness Test.
