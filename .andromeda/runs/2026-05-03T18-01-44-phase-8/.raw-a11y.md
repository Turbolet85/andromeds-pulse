## Constraints

- Custom SVG glyph React components MUST support both decorative (`aria-hidden="true"`) and meaningful (`aria-label` / `role="img"` + label) modes — meaningful icons need accessible name per SC 4.1.2 Name/Role/Value; decorative icons must be hidden from assistive tech to avoid SR noise (per a11y-plan §7 Form labels + §11 Screen Reader anti-patterns: "NEVER add excessive ARIA noise — `role='presentation'` overuse; redundant labels").
- Icons used to supplement state colors (paired with `--color-accent` error / `--color-feedback-success` success / `--color-primary` info / `--color-secondary` warning) MUST be addressable as part of the not-color-alone supplement; the registry's API must allow consumers to render an icon adjacent to state-colored text per SC 1.4.1 Use of Color (per a11y-plan §6 State color tokens not-color-alone + §11 Visual ban "NEVER convey information by color alone — pair `--color-accent` (error) with icon + text label").
- Icons rendered as `<svg>` elements MUST NOT redundantly duplicate ARIA roles already inherited from semantic elements (`role="img"` on a `<button>` containing only the icon is redundant if `aria-label` is on the button) — a11y-plan §11 ARIA: "NEVER add ARIA roles to elements that inherit them — redundant per eslint-plugin-jsx-a11y" (per a11y-plan §11 ARIA anti-patterns).
- Icon component MUST NOT trap focus or introduce `tabindex > 0` — icons are non-interactive presentation; interactivity comes from the wrapping `<button>` / `<a>` / `<menuitem>` (per a11y-plan §11 Keyboard: "NEVER set `tabindex > 0`" + §11 Keyboard: "NEVER nest focusable elements inside other focusable elements").
- Icon stroke / fill colors MUST resolve to design tokens (default `#E8EEF7` = `--color-text-primary`); when used as a UI component indicator (focus ring augmentation, status glyph), the icon-vs-background contrast must satisfy SC 1.4.11 Non-text Contrast ≥ 3:1 — registry must accept `currentColor` so consumers can compose contrast at usage site (per a11y-plan §6 Color contrast pairs SC 1.4.11 + §6 State color tokens "verify icon/label supplement present for every state color").
- Icon target-size enforcement happens at the wrapper element (button / control), not the icon itself; the registry's exported size grid (16/20/24px per design §Iconography) MUST allow embedding inside a `≥ 24×24 CSS px` interactive target — registry sizes alone (16/20/24) are NOT sufficient for SC 2.5.8 unless padding brings the wrapper to 24×24 (per a11y-plan §6 Target size tokens + a11y-plan §3 target-size trigger row).
- Each icon component's behavior under `prefers-reduced-motion: reduce` MUST be neutral — no per-icon JS animations introduced at chunk #11; if the registry pre-wires Halo State Pulse / circular-pulse motion, the motion path MUST honor `useReducedMotion` (chunk #15 dependency) and degrade to static glyph (per a11y-plan §6 Motion tokens SC 2.3.3 + §11 Motion: "NEVER autoplay motion without `prefers-reduced-motion: reduce` respect" + design-system §Iconography "circular-pulse").

## Patterns to follow

- Decorative-first default with explicit override: the registry's React component (`<Icon glyph="telescope" />` per design-system §Iconography line 200) should default to `aria-hidden="true"` and accept an `aria-label="..."` (or `aria-labelledby`) prop that, when provided, sets `role="img"` and removes `aria-hidden` — this matches a11y-plan §4 Per-component pattern catalog "Form input … `aria-label` … (when visible label not feasible, e.g., icon-only button)" semantics (per a11y-plan §4 Per-component patterns).
- Semantic HTML first: when an icon is the visual indicator inside an interactive control, the registry's icon stays presentational (`aria-hidden="true"`) and the wrapping `<button>` carries the accessible name — never combine `role="img"` + `aria-label` on the icon if the wrapper already names the action (per a11y-plan §2 Agent-runnable invariants "No ARIA additions on top of non-semantic HTML" + §11 ARIA: "NEVER use ARIA on non-semantic HTML").
- `currentColor` propagation: icon SVG path attributes use `fill="currentColor"` / `stroke="currentColor"` so token-driven color (e.g., `--color-text-primary` default, `--color-accent` for error state) cascades from the wrapper — preserves the contrast verification harness path (chunk #12 + colorjs.io reads `getComputedStyle(wrapperElement).color`) (per a11y-plan §6 Contrast verification harness + design-system §Iconography line 200).
- ESLint enforcement: configure `eslint-plugin-jsx-a11y` rules `jsx-a11y/img-redundant-alt`, `jsx-a11y/no-redundant-roles`, `jsx-a11y/role-supports-aria-props` against the icon component output (chunk #13 stack install lands the linter — chunk #11 may pre-author component to be lint-clean against `'plugin:jsx-a11y/recommended'`) (per a11y-plan §3 a11y-linting-install bootstrap phase + §11 ARIA: "NEVER add ARIA roles to elements that inherit them — redundant per eslint-plugin-jsx-a11y").
- State-color icon pairing API: registry exports common pairings (e.g., a `feedback-success` icon variant or an explicit "icon + label" composition pattern documented in JSDoc) so consumers in P7 settings-modal / P2 investigation-modal can satisfy SC 1.4.1 by composition rather than ad-hoc — per a11y-plan §6 not-color-alone "verify each state color is paired with text label OR icon".

## Anti-patterns to avoid

- NEVER render icons with `aria-label` + `role="img"` AND duplicate the same label on the parent `<button>` / `<a>` — produces double-announcement screen reader noise per a11y-plan §11 SR anti-patterns ("NEVER add excessive ARIA noise — redundant labels"). One name per accessible target.
- NEVER make an icon focusable (`tabindex="0"` on the `<svg>` or inner `<g>`) — icons are presentational; focusability lives on the interactive wrapper per a11y-plan §11 Keyboard ("NEVER set `tabindex > 0`" + "NEVER nest focusable elements inside other focusable elements").
- NEVER ship state-indicator icons (success / error / info / warning glyphs) without enforcing the not-color-alone pairing at the registry's documented usage examples — per a11y-plan §11 Visual: "NEVER convey information by color alone (state indicators must have text / icon supplement per SC 1.4.1) — pair `--color-accent` (error) with icon + text label". Registry doc must show the icon + text-label pattern, not icon-only state indicators.
- NEVER pre-wire any kinetic SVG animation (e.g., `<animate>` / `<animateTransform>` inside the `circular-pulse` glyph) at chunk #11 — would lock motion ON without honoring `prefers-reduced-motion`. Motion tokens + `useReducedMotion` land at chunk #15 (per a11y-plan §11 Motion: "NEVER have animation loops that don't respect `window.matchMedia('(prefers-reduced-motion: reduce)').matches`" + route §2 chunk #15 motion-tokens-respect-install).
