## Patterns to follow
- Arm-verdict unit pins on the in-process grader, per test-plan §1 Pending coverage triggers, the `perf-slo-check-arm-coverage` row (DISCHARGED). That row records `xtask::perf_budget` as pinned by 15 unit tests: empty ⇒ NEUTRAL · in-budget ⇒ PASS · over-budget ⇒ FAIL · non-numeric graded field ⇒ FAIL · required-but-empty ⇒ FAIL · all-empty ⇒ NEUTRAL, never PASS. Each new frame-cause arm gets its own pin in the same style over synthetic log fixtures. Those include the "no adapter record at all" arm, since that one is exactly the vacuous shape.
- Legs prove their own preconditions, per test-plan §3 Per-chunk gate discipline (`smoke:gap-resume` / `smoke:external-resolve` / `smoke:discovery`). A missing precondition reports INCONCLUSIVE, never PASS. The frame-cause vocabulary should follow the same logic: "the webview never reached the adapter request" is a distinct, named outcome and must not be folded into another cause.
- Measure-first RED/GREEN, per test-plan §3 Per-chunk gate discipline (Direct-binary smoke variant). Measure the snapshot sample at the base `ea50ca2` and again after the fix, and record both readings as evidence. The scope's p99 hypothesis is to be measured, not assumed. Decide the defect shape before choosing evidence: a frame-less run is an ABSENCE (BLOCK-shaped), so a clean log proves nothing about it.
- For a snapshot integration check, stage 500 spans and invoke the generation entry point, per test-plan §5 Boundary types covered (the `snapshot → buffer` row). That matches the §10 budget row's 500-span / 25k-token shape.
- Webview adapter-result reporting gets co-located `*.test.tsx` / `*.test.ts` vitest tests under `pulse-app/ui/src/`, per test-plan §4 Conventions (Webview). A new TauRPC path is tested in-process via `tauri::test::mock_builder()` + `get_ipc_response()`, per test-plan §5 Driver(s).

## Anti-patterns to avoid
- NEVER add retries or `#[ignore]` without a tracked issue, and never lower a threshold, to get the snapshot arm green, per test-plan §11 Quality / §11 CI / §10 Zero-flakiness budget. If the whole-generation p99 lands near 500 ms, report it as measured.
- NEVER assert an fps number, and never let CI's frame arm PASS, per test-plan §10 Frame-budget assertion. NEVER make "human reviews canvas" a step, per test-plan §11 Universal.
- NEVER use real time without injection in the unit tests, per test-plan §11 Universal. Grader and cause-mapping pins read fixed synthetic samples and records. Only the producer binary under `perf-samples` measures real durations.
