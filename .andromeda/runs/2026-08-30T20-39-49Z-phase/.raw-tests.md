## Patterns to follow
- **The `status` verdict shape as the model for Q2's exit taxonomy** — a pure classification fn, one pretty-JSON verdict on stdout, a distinct exit per arm, and one unit pin per arm (§3 `status`, 7 pins over 4 arms; `check:staged-artifacts` uses the same `arm`/`verdict` JSON + 0/1/2 shape).
- **The direct-binary smoke variant for the measure-first pair** — launch the product binary directly under the leg's env in either profile, each leg on its **own fresh `ANDROMEDA_PULSE_DATA_DIR`**, assert from the run's own `&lt;data_dir&gt;/logs/agent-latest.jsonl*` artifacts, and shut down by **specific pid** with `:4317`/`:4318` confirmed released (§3 Direct-binary smoke variant). Note this form already prescribes exactly the teardown discipline this chunk is fixing in the scripts.
- **The SCENARIO-leg family for anything non-gate** — `cargo xtask smoke:gap-resume` and `smoke:external-resolve` are registered in §3 as deliberately **outside** the standard gate set, each proving its own non-borrowable precondition, reporting **INCONCLUSIVE rather than a vacuous PASS**, refusing a structurally-impossible verdict up front (`observe_window_supports_verdict()`), and keying only on fields measured to discriminate (§3 Per-chunk gate discipline).
- **The `logs` verb precedent for a shell-verb change in these same two scripts** — §3 specifies the verb body precisely (rotated `agent-latest.jsonl*` family, three precedence-ordered bases, newest match in the first base that resolves, exit 1 + diagnostic when none does), and §1's `harness-log-family-resolution-coverage` records that the **shell half still ships with only a one-time hand check** while the xtask half landed a committed pin (per §3 `logs` + §1 Pending coverage triggers).
- **Harness/dev-tool boundaries are owed per-branch unit tests** — the precedent chain `webview-drive-msedgedriver-resolver-unit-coverage` (open) → `inject-demo-arg-parse-unit-coverage` (discharged, 0 → 8 pins, incl. the measured `[[example]] … test = true` requirement for nextest collection) (per §1 Pending coverage triggers).

## Anti-patterns to avoid
- **NEVER `sleep(N)` for synchronization** — wait for an explicit signal (port probe, PID liveness, or the `harness:status` verdict). This binds the new cleanup verification loop directly; §3's legacy "wait 5s for graceful shutdown" body text is the shape being repaired (per §11 E2E).
- **NEVER let a leg pass for the wrong reason.** §3 records two instances of this class already — the retired `status` form that exited 0 unconditionally, and the block-shaped-defect RED leg whose clean-log assertion passes **vacuously**. A cleanup verdict derived from the kill's own status, or a RED leg that cannot fail, is this same defect (per §3 `cleanup` Verification + §3 Direct-binary smoke variant).
- **NEVER insert a manual/human verification step or approve a result by eye** — every leg's verdict is exit code plus structured stdout/log artifact (per §11 Universal + §2 Agent-runnable invariants).
