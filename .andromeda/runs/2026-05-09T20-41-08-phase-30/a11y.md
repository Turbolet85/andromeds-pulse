## Constraints

- Tab navigation MUST follow WAI-ARIA Authoring Practices Guide tablist pattern — `role="tablist"` container with `role="tab"` items wired via `aria-controls` к sibling `role="tabpanel"`, `aria-selected` state on active tab, exactly one `tabindex="0"` (active) and others `tabindex="-1"` per roving-tabindex (per a11y-plan §4 ARIA Patterns row Tabs + §11 Anti-patterns "NEVER set tabindex > 0").
- Tab keyboard contract MUST be Arrow Left/Right navigation among tabs + Home/End jump + Enter or Space activation; Tab key moves focus OUT of tablist into tabpanel (single tab stop into tablist) (per a11y-plan §3 Keyboard test harness "Arrow keys: Navigate tab panels (left/right)" + §4 ARIA Patterns Tabs row + §3 Keyboard sequences "Tabs: Arrow keys navigate (Left/Right); Home / End jump").
- Full-dashboard layout MUST place a `skip-to-main` link as the first focusable element (visually hidden, appears on Tab/Focus) per WCAG SC 2.4.1 Bypass Blocks (per a11y-plan §5 Skip links).
- Full-dashboard layout MUST expose semantic landmarks: single `<main>` for primary content, `<nav>` wrapping the tablist (sidebar / tab list), single `<h1>` per route (page title matching active tab) with sequential h2/h3 nesting (per a11y-plan §7 Heading hierarchy + §7 Landmark roles).
- Cmd+K command palette MUST satisfy SC 2.1.4 Character Key Shortcuts — chord (Cmd/Ctrl+K) modifier-required pattern is compliant; if any single-key trigger added it MUST be deactivatable / remappable / active-only-on-focus (per WCAG SC 2.1.4; a11y-plan §3 WCAG criteria mapping AA list "SC 2.1.4 Character Key Shortcuts").
- Cmd+K command palette MUST implement combobox + listbox pattern: `combobox` input with `aria-controls` к listbox, `aria-activedescendant` tracking highlighted option, Down/Up navigates, Enter selects, Escape closes — and MUST trap focus inside the palette while open with Escape returning focus к the trigger (per a11y-plan §4 Combobox row + §5 Focus trap).
- Route change (tab switch via TanStack Router) MUST move focus к the new route's `<main>` landmark or its `<h1>` heading and announce the route change via an `aria-live="polite"` status region (single-page-app focus-restoration per WCAG SC 2.4.3 + SC 4.1.3) (per a11y-plan §5 Focus restoration "Route change (SPA navigation) → focus to main heading or `<main>` landmark").
- Every interactive element in the shell (tabs, palette trigger, palette options, skip link) MUST display the `--border-focus` token outline on `:focus-visible` with ≥ 3:1 non-text contrast against background per SC 2.4.7 + SC 1.4.11 (per a11y-plan §6 Focus ring tokens + §3 visual-focus-appearance trigger).
- Active-tab and palette-active-option indication MUST NOT rely on color alone — pair with iconography, label weight, underline, or `aria-selected`/`aria-activedescendant` state announced by SR per SC 1.4.1 (per a11y-plan §6 State color tokens + §11 Anti-patterns "NEVER convey information by color alone").
- `aria-live` region for route-change announcement MUST stay polite (non-blocking) and MUST NOT steal keyboard focus; live updates rendering inside tabpanels (chunks #34/#35) must preserve current focus per SC 2.1.1 stability (per a11y-plan §3 Critical Path P4 + §7 Live regions).

## Patterns к follow

- **WAI-ARIA Tabs pattern** with React Aria Components 1.17.x `Tabs`/`TabList`/`Tab`/`TabPanel` (handles roving tabindex, arrow keys, Home/End, ARIA wiring out-of-the-box) — single ARIA component library per project, do not mix with Headless UI (per a11y-plan §4 Per-component pattern catalog Tabs row + §11 Universal anti-pattern "NEVER mix ARIA component libraries"; §12 Decisions Log "ARIA component library: React Aria Components 1.17.x").
- **Combobox pattern for Cmd+K palette** with React Aria Components `ComboBox` + `ListBox` (provides `aria-autocomplete`, `aria-activedescendant`, Down/Up/Enter/Escape) inside a `Dialog` shell with focus trap — pair with focus-trap-react 12.x (`escapeDeactivates: true`, `returnFocusOnDeactivate: true`) per modal-overlay convention; tabbable 6.4.x ground-truth for Tab cycle assertion (per a11y-plan §4 Combobox + Dialog rows + §5 Focus trap + §12 Decisions Log "Focus management library: focus-trap-react 12.x + tabbable 6.4.x").
- **Skip-to-main link** as React Aria Components / native `<a href="#main-content">` styled with Tailwind v4 utility class hidden until `:focus-visible` (WCAG SC 2.4.1 Bypass Blocks pattern) — main content gets `id="main-content"` matching the link target (per a11y-plan §5 Skip links).
- **Focus restoration on SPA route change** — TanStack Router subscribers move `document.activeElement` к the new route's `<main>` or `<h1>` after navigation completes; pair with a single mounted `aria-live="polite"` `role="status"` region announcing the new route name (per a11y-plan §5 Focus restoration + §7 Live regions Status update row).
- **eslint-plugin-jsx-a11y 6.10.x recommended config** stays the compile-time gate — catches missing labels, ARIA on non-semantic, redundant role attributes; CI fails on critical violations (per a11y-plan §3 CI integration + §9 Lint stage).
- **Reduced-motion respect for shell chrome** — TanStack Router transition animations + palette open/close + tab indicator slide MUST honor `prefers-reduced-motion: reduce` via Tailwind v4 `motion-reduce:` variants and `useReducedMotion` from motion/react 12.x; degrades к instant per design-plan §Motion (per a11y-plan §6 Motion tokens + §11 Motion anti-patterns).

## Anti-patterns к avoid

- NEVER set `tabindex > 0` on tabs / palette options / shell elements — natural DOM order + roving tabindex (`0` / `-1`) only (per a11y-plan §11 Keyboard "NEVER set tabindex > 0").
- NEVER strip focus styles (`outline: none` without replacement) on tabs, palette input, palette options, or skip link — `--border-focus` token must remain visible on `:focus-visible` per SC 2.4.7 (per a11y-plan §11 Keyboard).
- NEVER add a single-character global keyboard shortcut without modifier (e.g., bare "/" к focus palette) without an opt-out / deactivation / focus-only restriction — violates WCAG SC 2.1.4 Character Key Shortcuts (per a11y-plan §3 WCAG criteria mapping AA list).
- NEVER allow Cmd+K palette to trap focus without an Escape exit + return-к-trigger restoration (per a11y-plan §11 Keyboard "NEVER create keyboard traps" + §5 Focus trap).
- NEVER convey active-tab / active-palette-option state by color alone — pair with text weight / icon / `aria-selected` / `aria-current` (per a11y-plan §11 Visual "NEVER convey information by color alone" + §6 State color tokens).
- NEVER let tab labels be icon-only without `aria-label` or visually-hidden text — labels MUST be unique, descriptive, and announced by SR per SC 4.1.2 + SC 2.4.6 (per a11y-plan §4 Button row + §11 Screen Reader "NEVER add excessive ARIA noise").
- NEVER skip the `<main>` landmark or have multiple `<main>` elements per route view — single `<main>` per page, sequential heading hierarchy without skipped levels (per a11y-plan §7 Heading hierarchy + §11 Screen Reader "NEVER skip landmark roles").
