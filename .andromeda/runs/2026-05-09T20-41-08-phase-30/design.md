## Constraints

- Full dashboard window MUST consume tokens from the `@theme` block already scaffolded in `pulse-app/ui/` (no hardcoded hex / pixel values): page background `--color-base` (#1A1D24), titlebar / chrome panel surfaces from the Surface Scale (`--color-raised-1` for tab bar / cards, `--color-raised-2` for popover-style menus, `--color-raised-3` reserved for modals/Cmd+K palette overlay) (per design plan §Color Palette Surface Scale + §Surface: desktop-webview Tokens).
- Active / hover / focus tab states MUST use the Border Progression hierarchy: subtle `rgba(74,144,226,0.1)` separators, emphasis `rgba(74,144,226,0.6)` on selected tab, focus rings solid `#4A90E2` 3-4px outset via box-shadow `0 0 0 3px rgba(74,144,226,0.2)` (per design plan §Border Progression + §Surface: desktop-webview Focus / Keyboard Navigation).
- Typography MUST split between IBM Plex Sans for chrome (tab labels at Label 12px/500 weight, view headings at Heading 20px/600 weight, Display 32px/600 weight for top-level page titles) and JetBrains Mono reserved for telemetry data within tab content (not for chrome itself) (per design plan §Typography table + §Anti-Patterns Universal Bans monospace-vs-sans semantic split).
- Custom titlebar height = 32px, frameless via Tauri `decorations: false` (already established in chunk #30 compact widget); full dashboard reuses the same titlebar shape with platform-specific window-control placement (right-aligned on Windows/Linux, traffic-light buttons on left for macOS); aperture icon (20px) for settings opener (per design plan §Component Patterns Navigation/App Shell + §Surface: desktop-webview Platform-Specific Notes).
- Cmd+K command palette is a "supporting moment" overlay positioned over `--color-raised-3` background with 1px subtle/emphasis border, `--radius-lg` (8px), and emerges via the 200ms ease-out fade transition (chrome budget) — NO scale-bounce, NO entrance staggering of result rows (per design plan §Motion duration scale + Hard limits + §Border Radius modal usage).
- Tab transitions and route view switches MUST be 200ms ease-out fade (chrome budget at expression 0.35) and degrade to instant when `prefers-reduced-motion: reduce` is set; NO opacity fades >200ms, NO 3D transforms, NO staggered reveals (per design plan §Motion Hard limits + §Accessibility motion override).

## Patterns to follow

- Reuse the established custom-titlebar pattern from compact widget (chunk #30): drag region full titlebar width except buttons, app icon 16px + title text + settings icon 20px (aperture glyph) + window controls — full dashboard inherits this shape with a wider title-area allowing tab bar to occupy a secondary row directly beneath the titlebar (per design plan §Surface: desktop-webview Component Patterns Navigation/App Shell).
- Tab bar follows Card/Panel pattern with Raised-1 (#262A33) background, 1px subtle Earth Blue border on the bottom edge as separator from view content, `--radius-md` (6px) on the tab pill itself, hover state lifts border to emphasis 60% opacity without background change (per design plan §Component Patterns Cards / Panels + Tables hover row semantics).
- Cmd+K palette input field follows Input Field pattern: `--color-inset` (#0F1117) background, 1px subtle Earth Blue border, focused state lifts to 1px solid `#4A90E2` + 3px outset box-shadow `rgba(74,144,226,0.2)`; placeholder text `#56606E` italic (per design plan §Component Patterns Input Fields / Form Controls).
- Tab labels SHOULD use the established custom icon set where a domain-specific glyph fits — `telescope` for Traces, `constellation-grid` for "service map" sub-views, `aperture` for Settings — rather than introducing generic Lucide stand-ins; Lucide is fallback only for genuinely generic controls (per design plan §Iconography primary custom set + Rule "Icons clarify, not decorate").
- View tabs (Traces/Metrics/Logs/Snapshots/Settings) follow the Empty State pattern when uninhabited: centered text with telescope icon at 24px tertiary color `#7D8697`, message tone like "No traces yet" or "Snapshot not generated" (per design plan §Component Patterns Loading / Empty States).

## Anti-patterns to avoid

- NEVER converge on the "common safe choice" of a left sidebar + card grid layout for the dashboard. Tabs across the top with the constellation/observatory voice is the route-specified surface; sidebars conflict with the design plan §Anti-Patterns Universal Bans line on safe convergence (per design plan §Anti-Patterns Universal Bans).
- NEVER use gradient overlays, glassmorphic backdrop-blur, or shadow-based elevation on dashboard chrome (titlebar / tab bar / Cmd+K overlay). Borders-only depth strategy is the discipline; the Halo State Pulse WebGPU canvas is the ONLY exception, and it is not part of the dashboard chrome (per design plan §Depth Strategy + §Anti-Patterns Universal Bans).
- NEVER use bounce/spring easing or scale-bounce entrance for the Cmd+K palette emergence; chrome motion is state-confirming (200ms ease-out fade), not delightful. Palette opens via opacity fade only, no transform-scale (per design plan §Motion Hard limits NO spring physics + NO entrance animations + opacity ceiling 200ms).

## Contract bindings

- **design ↔ a11y**: Focus ring spec (3-4px outset `#4A90E2` via box-shadow with `rgba(74,144,226,0.2)` halo) MUST satisfy SC 2.4.7 Focus Visible across every tab / Cmd+K item / titlebar control; design provides the token, a11y verifies WCAG conformance (per design plan §Border Progression Focus row + §Downstream Readiness for a11y specialist).
- **design ↔ a11y (motion)**: Tab transition + Cmd+K fade + any view-route enter/exit MUST honor `prefers-reduced-motion: reduce` and degrade to instant (200ms → 0ms); design owns the duration tokens, a11y verifies SC 2.3.3 conformance via Playwright + reduce-motion mode (per design plan §Motion Accessibility + §Downstream Readiness a11y motion accessibility).
- **design ↔ a11y (contrast)**: Active/inactive tab text on `--color-raised-1` background must clear 4.5:1 SC 1.4.3 minimum; design plan §Text Hierarchy gives Primary `#E8EEF7` ≈ 8.5:1 on `#1A1D24`, but tab background `#262A33` shifts the ratio — implementation MUST verify via the chunk #12 contrast harness pair set before merge (per design plan §Color Palette Text Hierarchy + chunk #12 contrast verification harness pattern).
- **design ↔ a11y (not-color-alone)**: Active tab MUST be conveyed by BOTH border-emphasis color AND a non-color cue (font-weight shift to 600, or bottom-border thickening, or icon-fill state) — never color alone; binds to SC 1.4.1 Use of Color (per design plan §Anti-Patterns Universal Bans "NEVER use color purely for decoration" + §Decisions Log 2026-05-03 accent reclassification rationale).

## Acceptance criteria contributions

- (design) Full dashboard chrome (titlebar, tab bar, Cmd+K palette) uses only tokens from `pulse-app/ui/src/index.css` `@theme` block — `grep -E '#[0-9A-Fa-f]{3,6}|[0-9]+px' pulse-app/ui/src/dashboard/` returns no hex literals or hardcoded pixel values outside Tailwind utility class names (per design plan §Self-Validation Protocol Token Test).
- (design) Tab transition + Cmd+K palette emergence respect `prefers-reduced-motion: reduce` — Playwright a11y harness with `forcedColors: 'none', reducedMotion: 'reduce'` confirms 0ms fade (instant tab switch, instant palette appear) (per design plan §Motion Accessibility + §Downstream Readiness a11y).
- (design) Active tab state is conveyed by ≥2 distinct visual properties (e.g., border-emphasis + font-weight, OR border-emphasis + filled-icon variant) — not color-only (per design plan §Anti-Patterns Universal Bans not-color-alone discipline + binds to SC 1.4.1).
- (design) Tab icons are sourced from custom set (`telescope` / `constellation-grid` / `aperture` etc.) where a domain-specific glyph fits; Lucide/Heroicons appear only as fallback for genuinely generic controls (e.g., chevron, ellipsis) (per design plan §Iconography Primary custom set + Rule "Icons clarify, not decorate").
