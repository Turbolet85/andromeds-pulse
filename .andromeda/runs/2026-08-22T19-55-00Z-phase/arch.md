## Relevance
Relevant — the chunk edits DuckDB ring-buffer DDL in a locked workspace crate and touches two registered Standard Contracts surfaces (`logs.*` IPC router, MCP `query_logs`).

## Constraints
- Work lands in the `buffer` crate (`crates/buffer/`); `buffer`, `viz`, `mcp-server` are reserved names that cannot be re-purposed, and any reader crate reaches the schema only through the owning crate's declared contract module — dependencies flow toward `pulse-app` as the single DAG root (per architecture.md §Occupied Resources — Cargo workspace crate names; §Cross-cutting Patterns — Module dependency direction; §Conventions — Module visibility discipline).
- `log_records` is already one of the 8 reserved DuckDB tables in the canonical list; a column addition adds no table, so §Occupied Resources needs no table-list edit. What *would* go stale is the §Conventions *Primary key convention* wording ("metric points and log records use OTLP-native identity (timestamp + resource hash + name)") — arch requires that correction as a wrap-time sidecar amendment, not a phase edit (per architecture.md §Occupied Resources — DuckDB database / schema names; §Conventions — Primary key convention).
- No ORM and no migration machinery: the ring buffer is in-memory (`pulse_buffer`, `:memory:`, schema `main`), created on startup, with lifecycle "create on startup" + periodic `DELETE FROM <table> WHERE ts < now() - INTERVAL '<retention> minutes'`. A DDL change therefore carries no migration path and no schema-version bump, and the retention sweep must keep working against whatever key shape lands (per architecture.md §Established Decisions — [ORM / Migrations], [Database], [Telemetry Retention Surface]; §Conventions — Database entity naming).
- Any new column obeys the data-model conventions: `snake_case` name; `NOT NULL` unless it maps to an OTLP-spec-*optional* field; timestamp columns are `TIMESTAMPTZ` with a sibling `BIGINT ts_unix_nano` where nanosecond fidelity matters (per architecture.md §Conventions — Database entity naming / Nullable patterns / Timestamp handling).
- The convention's ban is specifically on **UUID surrogate keys**, on the rationale that "OTLP entities already have spec-defined IDs." The scope establishes that rationale fails for LogRecord. An ordinal per-batch discriminator mirroring the already-reserved `span_events.event_index` / `span_links.link_index` sits inside the convention's letter; a random/UUID surrogate does not (per architecture.md §Conventions — Primary key convention; §Occupied Resources — DuckDB reserved tables).
- Arch has already ruled on the identity question in the adjacent layer with a directional rationale this fork inherits: "for a diagnostic tool over-coalescing hides distinct faults," and identity semantics are recorded as *possible-but-declined / REVISITABLE* rather than closed. This is a lean on the (a)/(b)/(c) fork, not a determination — arch does not govern row identity (per architecture.md §Established Decisions — [Fault Identity — what makes two faults ONE fault]).
- The ingest hand-off is Arrow zero-copy via `Appender::append_record_batch()` / `stream_arrow()`. Whether the DuckDB Appender path engages PK enforcement at all — and therefore whether the claimed loss occurs on that path — is research's question; arch mandates the interchange, not the constraint behaviour (per architecture.md §Inherited Defaults — Columnar interchange; §Stack and Technologies — Columnar interchange, Storage engine).

## Patterns to follow
- **Ordinal-discriminator precedent in the same DDL**: `span_events` and `span_links` are reserved tables whose keys already carry `event_index` / `link_index`. Whether the code's shape matches what the convention implies is research's to confirm; arch registers both tables (architecture.md §Occupied Resources — DuckDB reserved tables).
- **Test-time telemetry injection is the sanctioned measurement route**: E2E tests inject synthetic spans/metrics/logs by speaking real OTLP to `:4317` (gRPC) or `:4318` (HTTP) — the same surface external SDKs use — resolving a non-default port via `ANDROMEDA_PULSE_OTLP_GRPC_PORT` / `_HTTP_PORT`, and inspect buffer state by reading back through the `traces.*` / `metrics.*` / `logs.*` query routers. This is exactly the shape the chunk's MEASURE-FIRST end-to-end leg requires (architecture.md §Cross-cutting Patterns — Test-time telemetry injection; §Occupied Resources — Environment variables).
- **Crate template shape**: public contract module as the only `pub` surface, `pub(crate)` internals, `thiserror`-derived error enum (architecture.md §Project Intent — Template patterns; §Established Decisions — [Error Handling Pattern]).
- **Lint gate is all-features**: `cargo fmt --check` then `cargo clippy --workspace --all-targets --all-features -- -D warnings`, so a schema/type change must also compile clean under `--features mcp-server`, where `query_logs` reads this table (architecture.md §Infrastructure Patterns — Build system).

## Anti-patterns to avoid
- Introducing a UUID or random surrogate key on `log_records` (architecture.md §Conventions — Primary key convention).
- An in-process test-mode bypass, a "test ingest" feature flag, or a mock-channel back-door to stage the colliding records — the collision must be produced over the real receiver surface (architecture.md §Cross-cutting Patterns — Test-time telemetry injection).
- Reaching for persistent disk storage, a versioned migration, or an ORM to "solve" the identity problem — the buffer is in-memory-only by decision and out of scope for persistence (architecture.md §Established Decisions — [Telemetry Retention Surface], [ORM / Migrations]).

## Contract bindings
- **buffer schema ↔ viz `logs.*` TauRPC router + `pulse://stream/logs`** — the live push contract carries binary Arrow IPC payloads over the Tauri `Channel` API, so a column/shape change can reach the streamed record batch and the TauRPC-generated `.d.ts` bindings (architecture.md §Standard Contracts — Real-time push contract; §Occupied Resources — Tauri IPC routes).
- **buffer schema ↔ MCP `query_logs`** — one of the 8 `#[tool]` methods; any response-shape change must stay JSON-RPC 2.0 spec-conformant and `serde::Serialize` (architecture.md §Standard Contracts — MCP server; §Conventions — External wire — MCP; §Cross-cutting Patterns — Cross-bridge data shape).
- **buffer schema ↔ tests harness** — the OTLP-injection + read-back-through-query-routers discipline is arch's, and it is the harness contract the tests specialist builds the survival measurement on (architecture.md §Cross-cutting Patterns — Test-time telemetry injection).
- **`log_records.template_id` ↔ `log_templates`** — both are reserved tables in the same 8-table set; the relation the scope names as blast radius originates in the chunk #69 Phase B registration (architecture.md §Occupied Resources — DuckDB database / schema names).

## Acceptance criteria contributions
- DDL and fix are confined to the `buffer` crate; no new workspace crate and no new reserved table beyond the registered 8 (per architecture.md §Occupied Resources — Cargo workspace crate names / DuckDB database / schema names).
- Any added column is `snake_case`, is `NOT NULL` unless the OTLP field it maps to is spec-optional, and the resulting key introduces no UUID or random surrogate (per architecture.md §Conventions — Primary key convention / Nullable patterns / Database entity naming).
- The end-to-end survival measurement injects the two colliding records over the real OTLP receiver (`:4317`/`:4318`) and reads back through the `logs.*` query router, with no in-process bypass (per architecture.md §Cross-cutting Patterns — Test-time telemetry injection).
- The retention sweep still deletes by the `ts < now() - INTERVAL` cutoff under the new key shape, and no migration/schema-version machinery is introduced for the in-memory buffer (per architecture.md §Conventions — Database entity naming; §Established Decisions — [ORM / Migrations]).
- If a discriminator lands, the wrap files a drift amendment correcting the §Conventions *Primary key convention* "timestamp + resource hash + name" wording — phase does not edit it (per architecture.md §Conventions — Primary key convention).
