## Relevance
Relevant — this chunk lands buffer-crate schema/regression coverage plus an end-to-end ingestion-survival measurement, both squarely inside the test domain.

## Constraints
- Standard tier governs breadth: unit coverage of the `buffer` crate is "Comprehensive" depth, and `buffer` is classified testable specifically via direct SQL queries against the in-memory store — so the mechanism leg belongs in-crate, not only cross-crate (per test-plan.md §1 Coverage scope → buffer row; §2 pyramid Unit row).
- The end-to-end survival leg must self-bootstrap: both colliding log records are generated at test runtime over the real OTLP path or via Rust builders; pre-baked DB state, `.sql` seeds, and developer-staged fixtures are forbidden (per test-plan.md §1 `agent-driven-discipline: Self-bootstrapping test data`; §7 Self-bootstrapping requirement).
- The chunk plan's `## Test Commands` must carry the full standard gate set unconditionally (`cargo fmt --check`, clippy `-D warnings`, `cargo nextest run --workspace --profile ci`, `cargo xtask capability-drift`, `cargo xtask capability-widening-check`); the three `npm run … --prefix pulse-app/ui` gates drop only if the Files-to-modify / New-files lists touch zero `pulse-app/ui/**` paths (per test-plan.md §3 Per-chunk gate discipline).
- Run-scope must match build-scope: any narrowed `pulse-app` selection uses `--filter-expr` / `-E` **under `--workspace`**, not `-p` (per test-plan.md §3 `run` → Test selection). `-p buffer` remains valid for the library crate itself.
- Test-file location is split by crate kind: library-crate tests (including `buffer`) are co-located `#[cfg(test)] mod tests` under `crates/buffer/src/`; `pulse-app` is the exception — its `[lib] test = false` means any pulse-app-level e2e leg must live as a separate target file under `pulse-app/tests/*.rs` reaching internals through `pub` + `#[doc(hidden)]` (per test-plan.md §2 Test directory + naming conventions; §4 Conventions → Test file location).
- Boot-smoke is conditional and its trigger list is explicit (`pulse-app/src/main.rs`, `crates/ui-bridge/src/`, `pulse-app/src/observability.rs`, `tauri.conf.json`, `capabilities/*.json`) — `crates/buffer/src/schema.rs` is not on it. If the measurement needs a fresh `ANDROMEDA_PULSE_DATA_DIR` plus sustained real-receiver load, the **direct-binary smoke variant** is the accepted form: launch `target/debug/pulse-app.exe` under those env vars, assert from the run's own `&lt;data_dir&gt;/logs/agent-latest.jsonl*` artifacts (0 `app.panic.fatal` / 0 `ERROR`), shut down by specific pid, confirm `:4317`/`:4318` released (per test-plan.md §3 Per-chunk gate discipline → Boot-smoke gate + Direct-binary smoke variant).
- Zero-flakiness: a timing-sensitive collision test that flakes once is quarantined and root-caused, never retried (per test-plan.md §10 Zero-flakiness budget).

## Patterns to follow
- The `ingest → buffer` boundary recipe — drive the real receiver with a client, then read back through a direct DuckDB query — is the established shape for "did the row survive" assertions (per test-plan.md §5 Boundary types covered, row 1).
- Scenario P1's ordering is the template for the end-to-end leg: boot → seed over the real receiver → poll `health` until the ingest counter advances → query the data back and assert on decoded field content, never on wire bytes (per test-plan.md §6 Scenario P1 steps 3–6).
- Fixture construction goes through builder factories + `rstest` `#[fixture]` composition (`MockArrowBatch::builder()` is the `buffer`-crate factory named by the bootstrap phase; `MockTraceSpan::builder()` is the ingest-side one) — no raw struct literals (per test-plan.md §3 Bootstrap phases item 6; §4 Fixture pattern at unit level; §7 Fixture library).
- Per-test isolation is `tempfile::TempDir` + a fresh `open_in_memory()` DuckDB per test, with no shared connection across tests (per test-plan.md §5 Setup / teardown lifecycle; §7 Test data lifecycle).
- Clock handling: prefer explicit instant injection where the function under test takes the timestamp as an argument, reserving `tokio::time::pause()` for genuinely ambient-clock retention paths — the pinned `ts_unix_nano` needed to force a collision is a parameter, not a clock to freeze (per test-plan.md §7 Time-sensitive data + the 2026-08-16 amendment precedent below).

## Anti-patterns to avoid
- NEVER mock DuckDB at integration level, and NEVER pre-populate the buffer via `.sql` scripts or snapshots — both legs use an ephemeral in-memory instance seeded at runtime (per test-plan.md §11 Integration + §11 Test Data).
- NEVER synchronize with `sleep(N)` while waiting for the second record to land — wait on an explicit signal (health-status poll or channel event), and never read real wall-clock time without injection (per test-plan.md §11 E2E + §11 Universal).
- NEVER assert against crate-private internals or fixture-internal ids; assert the public contract — that both distinct records are readable back — so the test survives whichever of the three key designs the plan picks (per test-plan.md §11 Unit).

## Contract bindings
- **tests ↔ obs (status endpoint):** the harness's ingest-confirmation signal is `subsystems.buffer.rows_ingested` in the `health` JSON shape (test-plan.md §3 Status endpoint shape). Whether that counter is incremented for log records at all — and whether it counts pre- or post-PK-conflict — is research's question; if it counts pre-conflict it is not a valid survival signal for this measurement and the read-back query is the only authority.
- **tests ↔ obs (log format):** the failure-mode determination (silent drop vs. hard constraint error vs. upsert) is read from the JSON-lines `tracing` output via the plan's agent-parseable error grep (`jq 'select(.level == "ERROR")'`), which binds the harness to obs's NDJSON field schema (test-plan.md §3 Log format → Agent-parseable signals). Whether the write path emits any diagnostic at all on conflict is exactly what P3 must establish.
- **tests ↔ buffer coverage debt:** test-plan.md §1 Pending coverage triggers carries `buffer-redaction-counter-unit-coverage`, an *owed in-crate* `buffer` obligation from chunk 2026-08-22-pii-scrubber-recall. Adjacent, not absorbed — but if this chunk's gate set adds a `-p buffer` invocation, say so, since that trigger's evidence rests on its absence.
