## Constraints
- The standard gate set is unconditional for every chunk plan's `## Test Commands` (fmt / clippy / `nextest --workspace --profile ci` / `capability-widening-check` / `check:ingest-progress` / `capability-drift` LAST), with the webview gates owed only when the chunk's Files-to-modify / New-files touch a `pulse-app/ui/**` path — note the subject file `pulse-app/ui/src/bindings/index.ts` lives under that prefix, so whether the gates are owed turns on whether it appears in a file list (per test-plan §3 Per-chunk gate discipline).
- `capability-drift` must run LAST because every command above it — including the gate set's own `nextest --workspace` — can regenerate `bindings/index.ts`; §3 further states as a mandate that the assertion reads the **STAGED** copy, since the worktree can be correct while the index carries a clobbered version. Whether the shipped `capability-drift` code already reads the index (the chunk's root-cause hypothesis says it reads the worktree) is research's question (per test-plan §3 Per-chunk gate discipline, ordering note).
- A gate listed unconditionally must define a non-vacuous verdict for the "nothing to judge" case — §3 records that `check:ingest-progress` is safe unconditionally *because* of its NEUTRAL arm, and that the scenario legs report INCONCLUSIVE rather than a vacuous PASS when their own precondition is unmet (per test-plan §3 Per-chunk gate discipline).
- The verdict must be agent-readable: exit code plus machine-parseable output, no human-in-loop confirmation; the shipped exit-code convention for gates of this class is 0 green / 1 findings-or-policy / 2 cannot-evaluate (per test-plan §2 Agent-runnable invariants; §9 Supply-chain row; §3 `harness:status` arms).
- New harness/dev-tool bounded-input boundaries are owed a unit test **per branch** — §1 mints a pending trigger every time one ships unpinned (`webview-drive-msedgedriver-resolver-unit-coverage`, `inject-demo-arg-parse-unit-coverage`) (per test-plan §1 Pending coverage triggers).
- Fixture data is generated at test runtime, never pre-staged or committed, and no mutable state is shared across parallel tests — a staged-index scenario must be constructed in a per-test temp repo (per test-plan §7 Test Data & Fixtures; §11 Test Data).
- If the assertion is CI-wired, §9's pipeline table must name it: the plan's own precedent is that a CI stage the table omits reads as not-wired, and a plain `run:` step carries no SHA-pin obligation while any new third-party action does (per test-plan §9 Pipeline structure; §11 CI).

## Patterns to follow
- Pure-classifier + thin-IO split: `harness:status`'s `classify()` is a pure fn with 7 pins over four exit arms, and `gap_resume`'s `observe_window_supports_verdict()` is unit-pinned at its boundary — §1's `window-navigation-check-behaviour-unit-coverage` row states plainly that a decision buried in IO must be lifted into a pure fn to be testable (test-plan §3; §1).
- xtask modules carry co-located `#[cfg(test)] mod tests` (`xtask/src/webview_drive.rs` at 92, `xtask/src/smoke.rs`, `xtask/src/gap_resume.rs`), which is where the new assertion's per-branch pins belong (per test-plan §3; §1 msedgedriver row).
- Mutation-checked discrimination as the house proof: `capability-widening-check`, the buffer redaction pin, and the webview-drive `--no-inject --expect-absent` RED arm are each recorded as discriminating rather than passing for free — and the code-driven RED arm is explicitly preferred over the by-hand one (per test-plan §1 Pending coverage triggers; §1 critical path P5).
- Verdict-signal selection is measured, not assumed: `smoke:external-resolve` deliberately excludes `item_count` because it moved identically in both mutation arms (per test-plan §3 Per-chunk gate discipline).
- Static-analysis-over-committed-JSON is an established gate shape here — `capability-widening-check` already parses `pulse-app/capabilities/*.json` and fails with the named permission + capability; the new grants assertion is its complement in the revocation direction (per test-plan §1 Pending coverage triggers, `capability-widening static analysis` row).

## Anti-patterns to avoid
- Never weaken, skip or `--expect-absent` a shipped gate to obtain a green wrap, and never lower a threshold to pass a build (per test-plan §3 `smoke:gap-resume` never-weaken instruction; §11 CI / Quality).
- Never key the verdict on a signal that stays green under the mutation it exists to catch — the vacuous-pass hazard §3 records for the `status` verb and the BLOCK-shaped RED leg (per test-plan §3 Direct-binary smoke variant).
- Never assert against private plumbing or unlabelled `unwrap()` — pin the public verdict contract (arm + named file/permission in the message); and never `std::env::set_var` mid-test without cleanup, which a git-index test is prone to (per test-plan §11 Unit; §11 Mocking).
