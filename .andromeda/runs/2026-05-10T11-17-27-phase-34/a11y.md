## Anti-patterns к avoid

- NEVER omit Escape close handler — keyboard trap is SC 2.1.2 violation; per a11y plan §11 Anti-patterns Keyboard.
- NEVER use `tabindex > 0` on any modal element — creates non-natural focus order; rely on natural DOM order per a11y plan §11 Anti-patterns Keyboard.
- NEVER apply `:focus { outline: none }` without an alternative focus indicator (`--border-focus` token); per a11y plan §11 Anti-patterns Keyboard + Visual.
- NEVER add ARIA roles to elements that already inherit them (e.g., `role="dialog"` on `<dialog>`, `role="button"` on `<button>`) — redundant per a11y plan §11 Anti-patterns ARIA + eslint-plugin-jsx-a11y rules.
- NEVER hide essential content from assistive tech via `aria-hidden="true"` on focusable elements (axe-core `aria-hidden-focus` rule catches this); per a11y plan §11 Anti-patterns Screen Reader.
- NEVER set `aria-live` on a region that doesn't update OR omit it from a region that does (silent SR experience for status changes); per a11y plan §11 Screen Reader / §7 Live regions.
