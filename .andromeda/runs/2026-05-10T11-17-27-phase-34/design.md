## Constraints

- Modal background MUST be `--color-raised-3` (#343A45) — the maximum-elevation surface in the dark-first hierarchy, reserved for modals/dialogs (per design-system.md §Depth Strategy "Modal elevation" + §Color Palette Surface Scale row Raised-3).
- Modal border MUST be 1px solid; default is `rgba(74, 144, 226, 0.3)` (Subtle, Earth Blue 30%) per design-system.md §Border Progression Subtle row + §Depth Strategy "Modal elevation: ... 1px border (subtle or emphasis depending on context)". No box-shadow elevation — the system commits to borders-only depth (per §Depth Strategy "Chosen approach: borders-only").
- Modal radius MUST be `--radius-lg` (8px) per design-system.md §Border Radius "radius-lg ... Modals, large containers — reserved for largest surfaces."
- Internal padding MUST use spacing scale tokens; `--spacing-md` (16px) for standard inner padding and `--spacing-lg` (24px) for major section separation. No magic-number pixel values (per §Spacing "Base unit: 4px — all values are multiples of this" + §Anti-Patterns Token Test).
- Close button MUST follow Secondary button pattern (background `#262A33` Raised-1, text `#E8EEF7` Primary, border `rgba(74, 144, 226, 0.3)` Subtle, hovered border `#4A90E2`) OR be an icon-only button using the existing icon registry (16–20px glyph, 8px padding) per design-system.md §Component Patterns "Buttons" Secondary row + §Iconography "Size grid" + "Padding within containers".
- Focus ring on close button + any focusable child MUST be 3–4px outset, color `#4A90E2`, rendered via `box-shadow: 0 0 0 3px rgba(74, 144, 226, 0.2)` or `outline: 3px solid #4A90E2` per design-system.md §Border Progression Focus row + §Surface: desktop-webview Focus / Keyboard Navigation.
- Modal entrance animation MUST cap at 200ms ease-out fade (chrome budget for 0.35 webview surface); MUST respect `prefers-reduced-motion: reduce` and degrade to instant 0ms per design-system.md §Motion "Transitions" row + §Motion "Accessibility" + Hard Limits "NO opacity fades longer than 200ms".

## Patterns to follow

- Surface-elevation pattern: each modal lifts content from card surface (Raised-1 #262A33) up to dialog surface (Raised-3 #343A45) via background lightness only — NO shadows, NO gradients (per §Depth Strategy + §Anti-Patterns "NEVER use gradient overlays or glassmorphic effects on the dashboard chrome").
- Component composition pattern: modals reuse existing Card pattern semantics (1px border + radius + token padding) but at the larger Raised-3 surface, not Raised-1 — same vocabulary, different elevation step (per §Component Patterns "Cards / Panels" baseline composed up).
- Title typography pattern: modal headers use the existing Heading role (IBM Plex Sans 600 / 20px / tracking 0) for primary modal title; Body role (IBM Plex Sans 400 / 14px) for descriptive paragraphs; no new font tokens introduced (per §Typography table rows Heading + Body).
- Close button glyph pattern: an inline "X" close glyph fits the existing Iconography vocabulary (Lucide/Heroicons fallback acceptable per §Iconography "Secondary library: Lucide or Heroicons as fallback for ... navigation, validation states") at 16–20px sized per the size grid; observatory-themed glyphs (aperture/telescope/etc.) are NOT semantically appropriate for a generic close action.
- Native dialog ban pattern: modal primitive is implemented in webview React (not OS-native dialogs) — per §Anti-Patterns desktop-webview "NEVER use `alert()` / `confirm()` / `prompt()` — use styled modals (shadcn/ui Dialog component)". Native file/confirmation dialogs are reserved for native file picker only (per §Component Patterns desktop-native "Dialog").

## Anti-patterns to avoid

- NEVER add box-shadow / drop-shadow / glow for modal elevation — depth strategy is borders-only; the Halo State Pulse is the ONLY exempted decorative blur surface, and it lives on the WebGPU canvas, not chrome (per §Anti-Patterns Universal Bans "NEVER use gradient overlays or glassmorphic effects" + §Depth Strategy).
- NEVER use spring physics, bounce easing, scale-and-overshoot entrance, or staggered reveal of modal contents — chrome at 0.35 expression rejects "delightful" framing in favor of "state-confirming" motion (per §Motion Hard Limits "NO spring physics or bounce easing" + "NO staggered reveals beyond component load").
- NEVER inline hex values, magic-number paddings, or one-off radii inside the modal component — every visual value must trace back to the `@theme` token block (per §Self-Validation Protocol Token Test + §Anti-Patterns Universal Bans implicit "Random hex values or magic numbers signal no system").

## Contract bindings

- **Design ↔ a11y**: Focus ring color `#4A90E2` on Raised-3 surface `#343A45` must remain perceivable; the focus-ring pair is on a11y's contrast verification harness watchlist (per §Downstream Readiness "For a11y specialist" + §Self-Validation Protocol Contrast Test). Design provides token; a11y verifies the SC 1.4.11 ≥3:1 ratio at chunk implementation time.
- **Design ↔ a11y (motion)**: Modal entrance 200ms fade binds to `prefers-reduced-motion: reduce` override per §Motion Accessibility — design provides the 200ms ceiling + the static-fallback fact; a11y owns the SC 2.3.3 AAA verification gate (per design focus guide §Cross-domain bindings "Motion tokens bind to a11y §Animation from interactions SC 2.3.3").
- **Design ↔ a11y (close-button affordance)**: Close button must NOT communicate "closeable" via color alone — pair the glyph with an accessible name ("Close", "Dismiss") and the visible "X" icon (per §Anti-Patterns Universal Bans "NEVER use color purely for decoration" + design focus guide cross-domain "State color + text label pairing binds to a11y SC 1.4.1"). a11y owns the formal aria-label / SR-only-text wiring; design owns the icon-plus-text pairing pattern.
- **Design ↔ layouts**: Settings modal (chunk #38) is the first concrete consumer of this primitive; chunk #37 ships the primitive shell only. Per-modal interior layout (Settings form fieldset arrangement, P3/P7 tab order) is layouts' domain at chunk #38, not #37.
