## Constraints

- Modal primitive MUST render an inner card with `background: color-raised-3`, 1px subtle border, `radius: radius-lg`, and `padding: space-md` — these are the four token bindings layout-templates.md prescribes verbatim for the modal card surface (per layout-templates.md §Component — Investigation modal "Layout" + §Component — Settings modal "Layout" sharing the same overlay+card structure).
- Modal primitive MUST cap inner card max-width and max-height to roughly 80% of viewport, with scrollable overflow on the content region — consistent ceiling for all modal consumers (per layout-templates.md §Component — Investigation modal "Layout" 4th bullet).
- Modal primitive MUST be wrapped in a high `z-index` semi-opaque overlay backdrop covering the parent viewport — the backdrop is part of the modal contract, not a per-consumer decision (per layout-templates.md §Component — Investigation modal "Layout" 1st bullet).
- Close button MUST live in the top-right corner of the inner card with `✕` glyph, base color `color-text-secondary`, hover `color-text-primary`, transition `duration-fast` ease-out — applies to every modal that uses this primitive (per layout-templates.md §Component — Investigation modal "Layout" final bullet).
- Modal title slot (when supplied by consumer) renders in `font-heading` with `color-text-primary` — title is a slot, not a fixed string; primitive provides the typography contract (per layout-templates.md §Component — Investigation modal "Layout" "Title:" row).
- Modal entrance MUST honour the Investigation Capture Collapse supporting-moment motion budget (`0.35` webview expression, scale + opacity ease-out, exempt from the 200ms hard limit) — chunk #37's primitive sets the motion contract that chunk #38 (Settings) and any current trace-detail Investigate flow inherit (per layout-templates.md §Component — Investigation modal "Motion" + §Decisions Log "Motion trigger placement").
- Modal dismissal via Escape minimizes / closes the modal back to the desktop-webview surface state — Esc semantics are the same on both surfaces (compact widget Esc minimizes к tray; modal Esc closes the modal) and the primitive owns the close-modal half (per layout-templates.md §IA notes "Keyboard shortcuts" Esc row + §Surface: desktop-webview "Keyboard navigation" "Escape to exit Settings modal").

## Patterns к follow

- Two existing modal layouts in layout-templates.md (Investigation, Settings) share the exact same outer structure — overlay backdrop + inner card with the four token bindings (`color-raised-3` / 1px subtle border / `radius-lg` / `space-md` padding) + top-right close button. The primitive consolidates these into a single component shape rather than re-implementing the structure per-consumer (per layout-templates.md §Component — Investigation modal "Layout" + §Component — Settings modal "Layout" — identical first sentence "Modal structure: same as Investigation").
- Form-section stacking with `gap: space-lg` is the established pattern for modal content regions when content is form-shaped (Settings modal example) — primitive should make this trivial via a content-slot composition rather than baking a layout into the primitive itself (per layout-templates.md §Component — Settings modal "Layout" 2nd bullet).
- Title + scrollable content + close button is the established three-region split inside the inner card (Investigation modal demonstrates the canonical arrangement: title row at top, scrollable content middle, close button absolutely positioned top-right) — primitive provides title slot + content slot + ambient close button rather than fixed pixel offsets (per layout-templates.md §Component — Investigation modal "Layout" Title/Content/Close button rows).
- Live region (aria-live) and busy-state signaling (aria-busy) at the modal level support the Investigation Capture Collapse supporting moment + future status-bearing modals (e.g., Settings save confirmation per design's "form state confirmation" expression-level entry) — primitive surfaces these as opt-in hooks rather than always-on attributes (per route.md §2 chunk #37 description ("aria-busy/aria-live hooks") + layout-templates.md §Surface: desktop-webview "Expression level" "form state confirmation").

## Anti-patterns к avoid

- Do NOT bake the Investigation modal's "Investigate {trace-id}" title or the Settings modal's specific form sections into the primitive — those are consumer-supplied content; the primitive only owns overlay + card structure + close button + motion (per layout-templates.md §Component — Investigation modal vs. §Component — Settings modal showing two distinct content shapes inside the same outer chrome).
- Do NOT introduce a custom file browser-style internal navigation inside the modal primitive — when modal content needs file selection, layout-templates.md mandates the OS-native file picker (`NSOpenPanel` / `IFileDialog` / `zenity`), not in-app file browsing (per layout-templates.md §Component — File picker "Implementation" "Never a custom file browser inside the app UI").
- Do NOT animate the modal entrance с а chrome-budget motion (e.g., a 200ms transform that competes with the Halo State Pulse rendering loop) — the modal entrance is а supporting-moment motion (Investigation Capture Collapse), exempt from the 200ms hard limit but still bounded by `0.35` webview expression budget; do not slot а decorative transition outside that envelope (per layout-templates.md §Component — Investigation modal "Motion" + §Decisions Log "Motion trigger placement").
