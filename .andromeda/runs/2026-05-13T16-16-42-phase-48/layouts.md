## Anti-patterns к avoid

- **DO NOT automate tray icon via webview-only tools** — tray icon is OS-native per §Surface: desktop-native; tauri-driver (webview automation) is insufficient for tray surface. Per-platform GUI automation harness (e.g., AppleScript/cliclick for macOS, AutoHotkey/pywinauto for Windows, xdotool/ydotool for Linux) is required for tray icon click + tray menu item selection. (Cross-domain: tests-domain owns harness choice; layouts-domain flags the surface constraint.)
- **DO NOT assert per-service Halo State Pulse rendering on the compact widget** — per §Decisions Log Signature placement strategy: "Compact widget: unified single Halo State Pulse around the aggregated service-count badge"; per-service halos appear ONLY on full dashboard Traces view constellation map. Smoke tests targeting compact widget surface MUST NOT expect per-service halo dot rendering.
- **DO NOT expect tray menu to deep-link into app views (Traces, Metrics, etc.)** — per §IA notes Navigation model: "Menu actions are limited to 'open app', 'generate snapshot', 'toggle MCP', 'open settings', 'quit'. Deep navigation into app views (Traces, Metrics, etc.) happens inside the app window, not via the tray menu." Tray menu automation assertions are bounded to the 5 listed actions + read-only summary line.
- **DO NOT assert responsive breakpoint behaviors on compact widget** — per §Responsive breakpoints: "no CSS media-query breakpoints" for compact widget. Tests should not exercise viewport resize on compact widget surface expecting layout reflow (the surface is a fixed quarter-screen).
- **DO NOT automate notification toasts via webview DOM queries** — notifications are OS-native per §Component — Notifications Implementation: "native Notification Center on macOS, Action Center on Windows, freedesktop notifications on Linux." DOM-query-based assertion on notification visibility will yield false negatives.
