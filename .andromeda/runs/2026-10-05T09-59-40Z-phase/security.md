# security extract

## Relevance
partial — the chunk is a dev-probe measurement series (`pulse-app/examples/l4_decision_probe.rs`) with no product model/argv/sampling change, but it spawns `llama-cli` with digest-derived prompts, reads model/binary paths, writes generation text to disk and commits evidence, all of which touch the L4 argv, path-var, logging and secret-scanning rules.

## Constraints
- Any digest-derived text the probe hands to `llama-cli` as the `-p` operand must pass the bounded-prompt control before the `Command` is built: byte ceiling plus NUL/C0/C1 rejection with `\n` `\r` `\t` whitelisted, rejecting and never truncating (per security-plan §Input Validation, L4 inference argv prompt row; §Security Anti-Patterns → Code Patterns, the `Command::new(...).arg(user_input)` ban and its one admitted L4 path). The probe adds new shape families (A1–A7, B1–B3, C1–C3) and a probe-only "enriched" render that carries baselines and a trend, so prompts may be larger than the 7,405 B observed maximum. The plan's ceiling note records observed sizes as measurement notes, never as bounds. Research must answer two things: whether the probe routes its prompts through `validate_prompt_bounded` or the product's prompt composer at HEAD, and whether the enriched render stays under `MAX_PROMPT_BYTES`.
- The extra argv the probe adds (`--grammar-file` GBNF path, per-model sampling flags, `-c 8192 -rea off`, thinking-off switches) must be first-party constants or first-party file paths. No OTLP- or digest-derived string may reach argv except through the bounded `-p` path (per security-plan §Security Anti-Patterns → Code Patterns).
- Model and binary paths stay under the L4 path-var guard: trim, reject a `..` component before canonicalizing, length bound, `canonicalize()`, regular-file assert, and opt-in `ANDROMEDA_PULSE_L4_ALLOW_ROOT` confinement that fails closed (per security-plan §Security Anti-Patterns → Input, NARROWED EXCEPTION). The harness carve-out (trim + `is_file()` + clean skip) covers only vars the shipped binary never consumes. Whether the probe resolves its six GGUFs through the product's `validate_path_input` or through its own locator is research's question. If it reads `ANDROMEDA_PULSE_MODEL_PATH` / `_LLAMA_CUDA_BIN_PATH`, the product guard is the bar.
- No probe log line, and no committed evidence file, may carry a full product-consumed filesystem path (model GGUF dir, llama binary, allow-root). Use the canonicalized basename plus the env-var NAME (per security-plan §Logging & Monitoring, What NEVER to log; §Security Anti-Patterns → Logging).
- Synthetic digest text and raw model output stay in gitignored `target/` only. Committed evidence carries labels and aggregates only, so no generation text and no prompt text enters the tree (per security-plan §Logging & Monitoring, What NEVER to log: OTLP-derived content and the L4 no-output-bytes guarantee; §Secret Management, secret-scanning gate).
- If the probe adds a dependency (e.g. a sampler for the 10 % blind-audit draw), it is subject to `cargo deny check bans licenses sources` with `multiple-versions = "deny"` never relaxed, and to `cargo audit` (per security-plan §Dependency Security, CI integration and duplicate-version carve-outs).

## Patterns to follow
- `validate_prompt_bounded` → `PromptRejection::label()` as the only thing that reaches the log. A rejected composition is skipped and recorded as a bounded category, never truncated (per security-plan §Input Validation, L4 argv row).
- Bounded-category failure reporting on the inference-error leaf: child-wait io-error → `io_error` and stdout decode → `stdout_utf8_invalid`, carrying no output bytes and no prompt text. The scorer's `no reading` / invalid rows should take the same shape (per security-plan §Input Validation, L4 argv row).
- `std` both-sides-canonicalize on the `publish_workspace_key` precedent for any path the probe resolves (per security-plan §Security Anti-Patterns → Input).
- Synthetic fixtures are built from first-party content and passed through the product's own `render_payload` and `Digest::scrubbed_clone` path. The plan treats the OTLP-derived substring as already PII-scrubbed upstream, so the argv bound is a shape-and-length control, not a confidentiality fix (per security-plan §Security Anti-Patterns → Code Patterns).

## Anti-patterns to avoid
- NEVER pass a digest- or OTLP-derived string to `Command::arg` outside the bounded `-p` path, including through the GBNF path, a grammar string or sampling args (per security-plan §Security Anti-Patterns → Code Patterns).
- NEVER log or commit full model/binary/allow-root paths, raw model output or prompt text. The committed evidence is labels and aggregates only (per security-plan §Security Anti-Patterns → Logging).
- NEVER relax `multiple-versions = "deny"` or ignore-list an advisory that has a stated safe upgrade to land a probe dependency (per security-plan §Dependency Security).

## Contract bindings
- security ↔ tests: synthetic shape fixtures must hold no real PII or credential-shaped strings. If a shape deliberately carries a secret-shaped canary, it must be synthetic and must not trip the secret-scanning gate. The tree-wide secret scan is the CI security gate (per security-plan §Secret Management, Secret scanning in CI; binds tests §CI Integration).
- security ↔ obs: probe-side records follow the same NEVER-log set as product self-observation, with basename-only paths and bounded labels (per security-plan §Logging & Monitoring; binds obs-plan self-observation discipline).
- security ↔ arch [LLM Inference Runtime]: the enriched render must stay probe-only. A product-side digest seam would widen the OTLP-derived content confined to `digest.payload_summary`, and it would have to be re-checked against the L4 argv row and the scrub path at P4 (per security-plan §Input Validation, L4 argv row).

## Acceptance criteria contributions
- Every probe composition (A, B, C-today, C-enriched) is measured against `MAX_PROMPT_BYTES` before spawn. Any over-ceiling composition is rejected and recorded as a bounded label, never truncated, and the observed maximum is reported in evidence (per security-plan §Input Validation, L4 inference argv prompt row).
- A grep of the committed evidence and of the probe's log output shows 0 full model, binary or allow-root paths (absolute `/home/` and `AI-Model/` directory prefixes) and 0 prompt or generation text bodies. Only labels, aggregates and basenames appear (per security-plan §Logging & Monitoring, What NEVER to log).
- `git status` / `git ls-files` shows the synthetic digest texts and raw outputs only under ignored `target/`, none tracked, and the secret-scan gate passes on the chunk commit (per security-plan §Secret Management, Secret scanning in CI).
- If `Cargo.toml` / `Cargo.lock` change, `cargo deny check bans licenses sources` passes and `cargo audit` exits 0 (per security-plan §Dependency Security, CI integration).
