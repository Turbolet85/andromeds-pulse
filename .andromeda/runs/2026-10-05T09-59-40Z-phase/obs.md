# obs extract

## Relevance
partial. The chunk is a probe-only measurement series (`pulse-app/examples/l4_decision_probe.rs`) with no product model, argv or tracing change. Obs applies to what the probe records and commits (bounded labels, aggregates, latency readings, no-reading rows) and to the product's `interpretation.*` log surface if the probe drives it. It does not apply to self-observation instrumentation, because none is added.

## Constraints
- Default-deny on content: per obs-plan §8 PII Scrubbing (data classification table + "Default-deny posture"), only explicitly allowlisted, bounded fields may be emitted. The probe's committed evidence and anything it logs should therefore carry bounded labels (`detect` / `cause` / `valid` / `no reading`, decision class, model name) and aggregate numerics only. The synthetic digest text and the raw model output stay in gitignored `target/`, matching scope §Boundaries.
- Basename only for product-consumed paths: obs-plan §8 (the `interpretation.model.load.error` leaf: `path_basename` + `env_var` NAME, never the value) and §11 Logs ("NEVER log … full paths") require GGUF / `llama-cli` / GBNF paths to appear as basenames in any emitted record or committed evidence. Whether the probe's existing print sites already do this is research's question.
- The `interpretation.*` allowlist is exact-leaf only: obs-plan §8 (`interpretation.incident.created`: "no bare `interpretation` key may exist"; the L4 path-guard leaves) requires every `interpretation.*` target to resolve to its own exact leaf whose field set equals what the emit site emits. The chunk adds no product target (scope §Boundaries). If any implementation step does add or change a product emit site, that requirement applies in full. Whether the probe drives product emit sites (`interpretation.incident.skipped`, `interpretation.generation.damper`, `interpretation.model.load`) at all is research's question.
- Never PASS over empty input: obs-plan §10 CI gates (perf-budget arm: "never PASS over empty input"; "a REQUIRED empty arm fails") and the §10 frame-row two-state posture (an unrequired empty arm reads NEUTRAL, never FAIL and never PASS) are the obs-side form of CARRY 1. A zero-generation row is `no reading`. A model arm with no readable rows reports cannot-evaluate, never a percentage computed over zero.
- One percentile rule: obs-plan §10 snapshot row ("The p99 rule — the grader's, the one rule for every perf arm": nearest-rank, ⌈0.99·n⌉-th smallest, `(n * 99).div_ceil(100).max(1) - 1`) means any GPU-latency percentile in the per-model table should use the same nearest-rank rule as `xtask/src/perf_budget.rs`. The table should never use an interpolated quantile.
- No soft budgets: obs-plan §11 SLO ("NEVER define soft SLO budgets") applies to the `valid` atom's time budget, which must be a stated number. obs-plan §10's performance-budget table has no L4-generation latency row. So the budget cannot be sourced from obs-plan. P3/P4 must read it from the product's existing GPU-route budget (scope §Premises, `xtask/ci/l4-latency-p99.sh`) and cite it there.
- Bounded label cardinality: obs-plan §11 Metrics ("NEVER use unbounded label cardinality") requires every per-row and per-model label to come from a closed set enumerated upfront: shape id A1–A7 / B1–B3 / C1–C3, render `today` / `enriched`, the six model names, and the three scorer atoms plus `no reading`. Free model text is never a label.

## Patterns to follow
- Raw per-event values with aggregation downstream: per obs-plan §11 Metrics ("emit raw per-event `value` … agent computes percentiles … no precomputed quantiles in the emission path"), record per-generation `elapsed_ms` and footprint readings raw in the gitignored row data. Compute A-detect % / A-cause % / B-false-alarm % / C-today % / C-enriched % and the latency percentiles in the scorer pass. This keeps the whole-series re-grade after a failed blind audit possible without re-generating.
- A cause named from its own data on a 0-sample arm: per obs-plan §10 frame row (`frame_cause`: "a 0-frame run names its cause from its own log"), an empty or no-reading cell should state why it is empty. Examples: no generation, schema-invalid, over the time budget, sampler-init failure. A bare blank is not enough.
- Exact leaf plus field-set equality guard under `pulse-app/tests/`: per obs-plan §8 (L4 path-guard leaves, guarded by `pulse-app/tests/unit_observability_allowlist_l4_path_guard.rs`, plus the `[lib] test = false` rule), any product emit-site change the chunk is forced into gets its leaf and a both-directions field-set guard that actually runs.

## Anti-patterns to avoid
- Logging or committing content payloads: obs-plan §11 Logs + §11 PII Scrubbing ("NEVER include PII in logs / spans / metrics by default"). Synthetic digest text and raw model JSON must not appear in stdout captured into committed evidence, in tracing fields, or in the per-model table.
- An OTel exporter or own-port dial for measurement: obs-plan §11 Universal ("NEVER link an OTel SDK into the product's self-observation runtime"). Synthetic digests must be built in-process through `render_payload`, not by injecting OTLP into the probe's own `:4317`/`:4318` under the shared model slot. Whether S1–S6 are built in-process today is research's question.
- Reading a vacuous row as green: obs-plan §10 CI gates ("never PASS over empty input"). Counting a zero-generation row as a correct B dismissal is the exact failure CARRY 1 names.

## Contract bindings
- obs ↔ tests §10 / perf grader: the nearest-rank p99 rule and the empty-arm posture (NEUTRAL / cannot-evaluate, never PASS) are shared with `xtask::perf_budget`. The probe's latency columns and no-reading cells should match that grammar.
- obs ↔ security §Logging & redaction: basename-only for the L4 model and binary paths and for `ANDROMEDA_PULSE_L4_ALLOW_ROOT`. No content payloads in any log or committed artifact. Synthetic texts stay in gitignored `target/` (scope §Boundaries).
- obs ↔ arch [LLM Inference Runtime]: the `interpretation.*` exact-leaf allowlist (obs-plan §8) binds only if a product emit site changes. Scope §Boundaries says none does, so this binding is expected to be vacuous. Research confirms it with an empty diff on `pulse-app/src/observability.rs` and `pulse-app/src/inference_runtime.rs`.

## Acceptance criteria contributions
- (obs) Committed evidence for the series contains only bounded labels and aggregate numerics: no synthetic digest text, no raw model output, no full filesystem path. A path scan of the committed evidence finds 0 absolute paths, and model and binary files appear by basename only (per obs-plan §8 PII Scrubbing default-deny; §11 Logs).
- (obs) A zero-generation or no-output row is labelled `no reading`, is excluded from every percentage denominator, and is never counted as `valid` or as a correct B dismissal. A model arm or cell with zero readable rows prints a cannot-evaluate cell with a named cause, never a percentage (per obs-plan §10 CI gates "never PASS over empty input" + §10 frame-row two-state posture).
- (obs) Any reported GPU-latency percentile uses nearest-rank (`(n * 99).div_ceil(100).max(1) - 1` for p99) over raw per-generation `elapsed_ms`, with n stated beside it. The `valid` time budget is a stated number cited to its product source, not to obs-plan, which holds no L4 row (per obs-plan §10 snapshot-row p99 rule + §11 SLO "NEVER define soft SLO budgets").
- (obs) No product tracing target or allowlist leaf changes: `git diff` on `pulse-app/src/observability.rs` is empty at the chunk commit. If it is not empty, each changed `interpretation.*` target has an exact leaf with a both-directions field-set guard under `pulse-app/tests/` (per obs-plan §8, the `interpretation.incident.created` "no bare `interpretation` key" + L4 path-guard leaves).
