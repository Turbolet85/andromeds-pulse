# arch extract

## Relevance
relevant — the fix crosses the ingest → triage → pulse-app resolver boundary, and the P-027/P-025 observables plus any new xtask leg are arch-registered resources.

## Constraints
- Module dependency direction: dependencies flow toward `pulse-app`, the graph is a DAG rooted there, and no library crate depends on a sibling unless its declared contract requires it. An event-driven "register at first sighting" path from span ingest into `triage`'s service registry must therefore be wired at the `pulse-app` boundary, not by adding an `ingest → triage` (or reverse) edge. Whether such a wiring point already exists (the span broadcast fan-out, a `SpanObserver` tap) is research's question (per architecture §Cross-cutting Patterns → Module dependency direction; §Established Decisions [Module Boundaries]).
- A first-sighting signal travels over the sanctioned in-process channels: `tokio::sync::mpsc` for hand-off and `tokio::sync::broadcast` for buffer → subscriber fan-out. No new channel substrate is allowed (per architecture §Established Decisions [In-Process Channel Architecture]; §Inherited Defaults → Channels).
- `services.list_with_states` is registered as the pulse-app `ServicesApiImpl` returning `ServiceListPayload` from `triage::lifecycle::InMemoryServiceRegistry::list`. The fix should keep the dot sourced through that procedure. A new procedure, or a changed `ServiceListItem` shape (for example a first-seen anchor field), is a bridge-shape change: it must stay `serde::Serialize` and flows into the generated bindings (per architecture §Occupied Resources → Tauri IPC routes; §Cross-cutting Patterns → Cross-bridge data shape; §Conventions → Workspace API style).
- The P-027 observable is the registered delegated-timing route: `telemetry.frontend.record_constellation_discovery_latency` with `ConstellationDiscoveryInput` (aggregate `discovered_count`, bound 10_000) emits `metric.constellation.discovery_ms` with its own exact obs allowlist leaf. `telemetry.frontend.*` is the only sanctioned route for a bound that ends at a webview paint. If research moves the anchor to first-seen, this registry row changes with it. The sibling P-025 row stays as it is: `hue_update_ms` is anchored on `ServiceListItem.tier_effective_at_unix_nano` with one record per witnessed change (per architecture §Occupied Resources → Tauri IPC routes, the `telemetry.frontend.*` delegated-timing entry).
- Lifecycle cadence falls under the layered config precedence (env `ANDROMEDA_PULSE_*` > `config.toml` > built-in defaults), and duration fields are in seconds with the unit in the field name. Shortening the heartbeat tick would change a config-governed cadence contract, not just a constant. Whether the heartbeat interval is Settings- or env-sourced today is research's question (per architecture §Cross-cutting Patterns → Config management; §Conventions → Configuration units).
- A new live leg is an xtask CLI surface. It must be registered under the formalized-CLI-contract rule with a stated exit contract, and it must launch the dev-build binary path `target/{profile}/pulse-app[.exe]`, never `andromeda-pulse` (per architecture §Occupied Resources → xtask CLI surfaces; §Occupied Resources → Process / service identity).
- Test telemetry reaches the app only as OTLP to the loopback receivers `:4317`/`:4318` (ports resolved via `ANDROMEDA_PULSE_OTLP_{GRPC,HTTP}_PORT`). No new env var is reserved without an §Occupied Resources entry (per architecture §Cross-cutting Patterns → Test-time telemetry injection; §Occupied Resources → Environment variables).

## Patterns to follow
- The scenario-leg family: `cargo xtask smoke:hue-shift` (`xtask/src/hue_shift.rs`) drives the release binary, grades emitted wire records against a backend anchor event, and reports exit 0 PASS / 1 FAIL / 2 INCONCLUSIVE with an artifact under `target/<leg>/`. It is dev-host only and not wired into CI. Siblings are `smoke:gap-resume` and `smoke:external-resolve`. A first-seen-to-dot leg fits this shape (per architecture §Occupied Resources → xtask CLI surfaces).
- The delegated-timing observable route: the webview computes the paint-anchored duration and reports it through the bounded `telemetry.frontend.*` `TelemetryApi` input structs (ui-bridge `crates/ui-bridge/src/telemetry.rs`). The backend never infers paint time (per architecture §Occupied Resources → Tauri IPC routes).
- The single-process monolith: ingest → buffer → subscriber fan-out over shared memory, so an in-process first-sighting hook costs microseconds, not a network hop (per architecture §Design Philosophy → Single-process modular monolith).
- Lower crates stay free of the binary: `triage` exposes a public contract module, and `pulse-app` mounts the resolver and adapters (per architecture §Project Intent → Template patterns; §Conventions → Module visibility discipline).

## Anti-patterns to avoid
- An in-process test-mode bypass, a "test ingest" feature flag or a mock-channel back-door that makes the live leg pass without real OTLP ingest (per architecture §Cross-cutting Patterns → Test-time telemetry injection).
- A reverse or sibling dependency edge (for example `triage` depending on `ingest` or `pulse-app`) added to deliver first-sighting state (per architecture §Cross-cutting Patterns → Module dependency direction).
- Pointing any OTLP network exporter at the product's own `:4317`/`:4318` to generate the leg's "new service" traffic from inside the app (per architecture §Established Decisions [Self-Observation]; §Cross-cutting Patterns → Self-observation discipline).

## Contract bindings
- arch ↔ obs: the `metric.constellation.discovery_ms` and `metric.constellation.hue_update_ms` targets each carry their own exact allowlist leaf. A new anchor field or label on the discovery record needs its obs leaf, or the label is silently redacted (per architecture §Occupied Resources → Tauri IPC routes, delegated-timing entry).
- arch ↔ tests: any bridge-shape change (a new procedure, or a new `ServiceListItem` field) moves the generated bindings and the `EXPECTED_PROCEDURES` / capability-drift surface. The new leg joins the xtask scenario-leg family (per architecture §Occupied Resources → Tauri IPC routes; §Occupied Resources → xtask CLI surfaces).
- arch ↔ security: telemetry-input structs stay bounded (`discovered_count` ≤ 10_000), and the leg's traffic stays on the loopback OTLP receivers (per architecture §Occupied Resources → Tauri IPC routes; §Occupied Resources → Network ports).

## Acceptance criteria contributions
- No new library→library dependency edge that inverts the DAG. Any first-sighting wiring between ingest and the `triage` registry lives at the `pulse-app` boundary; `triage`'s `Cargo.toml` gains no `ingest`/`pulse-app` dep (per architecture §Cross-cutting Patterns → Module dependency direction).
- The dot stays sourced through `services.list_with_states` → `InMemoryServiceRegistry::list`. If a procedure or a bridge-crossing field is added or changed, the §Occupied Resources Tauri IPC routes entry is amended at wrap to match (per architecture §Occupied Resources → Tauri IPC routes).
- The new live leg is recorded in §Occupied Resources → xtask CLI surfaces with its exit contract (0 PASS / 1 FAIL / 2 INCONCLUSIVE). It injects via OTLP on loopback and launches `target/{profile}/pulse-app[.exe]` (per architecture §Occupied Resources → xtask CLI surfaces; §Cross-cutting Patterns → Test-time telemetry injection).
- The P-025 registry row keeps its anchor (`tier_effective_at_unix_nano`) and its one-sample-per-witnessed-change semantics unchanged. The P-027 row is amended only if research changes the discovery anchor (per architecture §Occupied Resources → Tauri IPC routes, delegated-timing entry).
