The zero-flakiness budget applies to the live leg too (per test-plan §10 Coverage thresholds + Zero-flakiness budget).

## Patterns to follow
- Reuse the scenario-leg scaffold: `xtask/src/hue_shift.rs` reuses `external_resolve`'s direct-binary helpers to run the release binary under a fresh data dir and grade a `metric.constellation.*` observable against an anchor record (per test-plan §3, the `smoke:hue-shift` paragraph).
- Add a structurally-impossible-verdict guard: a window that cannot reach the bound being graded is refused up front as INCONCLUSIVE (`observe_window_supports_verdict`) and unit-pinned at its boundary (per test-plan §3, the `smoke:gap-resume` / `smoke:external-resolve` paragraphs).
- The verdict comes from the app's own obs-log records (jq-parseable NDJSON), and the predicate matches an effect FIELD, never the target alone (per test-plan §3 Log format; §6 Drivers per surface, the webview-drive row).
- Telemetry enters only over real OTLP: `crates/ingest/examples/inject_demo.rs` is built outside the timed section and invoked by path. Env gates such as `ANDROMEDA_PULSE_L4_DETERMINISTIC` go into the spawned app's own env (per test-plan §6 Drivers per surface; §3 Direct-binary smoke variant).
- An event-driven registration path needs a trait seam in the lower crate so tests can stub it; inject collaborators as constructor-injected `Arc<dyn Trait>`, never by runtime patching (per test-plan §8 Anti-monkey-patching).

## Anti-patterns to avoid
- NEVER synchronize with `sleep(N)`. Wait for an explicit signal (a log record, health/`status` polling) (per test-plan §11 E2E).
- NEVER let the leg pass vacuously. A run whose precondition never happened (no new service seen, no dot sample) is INCONCLUSIVE, not PASS. Do not weaken the budget, re-anchor the observable, or add retry-once to get a green (per test-plan §3 scenario-leg paragraphs; §11 Quality + CI).
- NEVER assert with real wall-clock time in unit/integration tests. The live leg's wall-clock latency reading is the only sanctioned real-time measurement (per test-plan §11 Universal).

## Contract bindings
- tests ↔ obs: the live leg grades the `metric.constellation.discovery_ms` wire record, and `smoke:hue-shift` grades `metric.constellation.hue_update_ms`, both read from `<data_dir>/logs/agent-latest.jsonl*`. obs owns the record's fields and anchor semantics, and tests owns the leg that reads them. If P3 re-anchors P-027 to a first-seen timestamp, the obs contract rows change first and the leg's predicate follows (per test-plan §3 Log format; §3 `smoke:hue-shift` paragraph).
- tests ↔ arch (TauRPC bindings): the `git diff --quiet <chunk-base>` bindings close was measured only for a chunk that adds no procedure. The close for a changed procedure set is "not yet specified". If the fix adds a field to the `services.list_with_states` payload (e.g. a first-seen timestamp), the bindings change shape and the close must be escalated, not improvised. Whether the fix changes the payload is research's question (per test-plan §3 Per-chunk gate discipline, capability-drift ordering paragraph).
- tests ↔ Conductor (P-075): the ≤ 2000 ms P-025 and ≤ 5 s P-027 budgets are graded by Conductor's live leg. The Pulse-side leg grades its own anchor error / bound only as defined in its contract (per test-plan §3 `smoke:hue-shift` paragraph, "the P-025 budget is context only").
