# a11y extract

## Relevance
partial — the fix belongs to the discovery path (registry, lifecycle, resolver), which a11y-plan §1 treats as not-assertable. The a11y surface is limited to the constellation region, where a new dot now appears sooner, and to any edit of `ConstellationCanvas.tsx` (P-027 mark effect / P-025 hue effect). The canvas wrapper is must-be-accessible surface p11 (constellation semantics).

## Constraints
- Tier: Standard, WCAG 2.1 AA, plus the SC 2.3.3 AAA motion escalation. Zero WCAG AA violations are allowed on must-be-accessible paths, and p11 constellation semantics is one of them (per a11y-plan §1 A11y Scope Summary + §1 "Surface set extension" + §10 SLO Invariants).
- The constellation canvas wrapper keeps a STABLE literal accessible name (`Telemetry traces chart`). The live state goes only into the `aria-describedby` visually-hidden summary, which holds lifecycle counts and a findings tally. It is aggregate-only, so no service name reaches the accessible tree. Discovering a service sooner must not put its name into the region's name or description (per a11y-plan §7 Landmark roles).
- The constellation summary deliberately omits `role="status"`, because the ~1 s poll would stack announcements with the dashboard's existing live region. A discovery-path change must not add a per-discovery live announcement unless it records a conscious reversal of that choice (per a11y-plan §7 Landmark roles + §7 Live regions).
- Live updates must never steal focus from the user's current keyboard target, and focus must stay stable across re-renders when a new dot or service appears (per a11y-plan §1 Critical Paths P4 row, SC 2.1.1 / SC 2.4.3).
- If the fix changes how a newly discovered dot enters the canvas (a fade or scale-in, for example), that motion must degrade under `prefers-reduced-motion: reduce`. A vanilla canvas loop has to check `matchMedia` by hand (per a11y-plan §6 Motion tokens + §11 Motion).
- The dot hue is a severity signature. Severity must not be conveyed by hue alone, so the state also needs a text or aggregate supplement (the summary tally). Whether the current summary already covers a newly discovered service's tier is a question for research (per a11y-plan §6 State color tokens + §11 Visual).

## Patterns to follow
- Each surface has its own axe spec, and the existing p11 constellation-semantics spec is the regression guard for this surface. Fixtures must be POPULATED: a spec whose fixture has zero services audits a blank region and passes vacuously (per a11y-plan §3 Harness wiring & conventions).
- The Playwright IPC mock invokes `TauRPC__<router.path>`. If the `services.list_with_states` payload shape changes (for example a first-seen anchor field), the fixtures in `helpers/v02-fixtures.ts` change with it (per a11y-plan §3 Harness wiring & conventions).
- Check suite health cheaply with `npx playwright test --list` after any fixture or import change, because a list-time import failure once silently disabled the whole suite (per a11y-plan §3 Harness wiring & conventions).
- The reduced-motion Playwright pattern: `page.emulateMedia({ reducedMotion: 'reduce' })`, then assert computed durations of 0s and assert that state is still conveyed without motion (per a11y-plan §6 Motion tokens).

## Anti-patterns to avoid
- NEVER use motion as the ONLY signal that a service was discovered, and never run an animation loop that ignores `prefers-reduced-motion` (per a11y-plan §11 Motion).
- NEVER add excessive ARIA noise. That includes a live announcement on every poll or discovery for the constellation, which the plan's status-omission choice exists to prevent (per a11y-plan §11 Screen Reader + §7 Landmark roles).
- NEVER use a retry-once policy for an a11y violation or a flake in the p11 spec (per a11y-plan §11 SLO).

## Contract bindings
- a11y ↔ tests: the a11y job in `ci.yml` (`cargo xtask test:a11y`) diffs every PR against the base `a11y-violations-summary.json`. A new tuple on the p11 surface fails the PR (per a11y-plan §3 CI integration + §9 CI Integration).
- a11y ↔ design: the motion degrade for any dot-entry transition binds to design-system §Motion, and the hue-plus-supplement rule binds to design §Color Palette, which covers not-color-alone (per a11y-plan §6 Motion tokens + §6 State color tokens).
- a11y ↔ ui-bridge / IPC mock: any change to the shape of the `services.list_with_states` payload must be reflected in the a11y mock fixtures (per a11y-plan §3 Harness wiring & conventions).

## Acceptance criteria contributions
- (a11y) The p11 constellation-semantics axe spec and the full `cargo xtask test:a11y` chain pass with zero new violation tuples against `baselines/a11y-violations-summary.json`. The pass has to come from a populated fixture, not an empty one (per a11y-plan §3 Harness wiring & conventions + §10 SLO Invariants).
- (a11y) The constellation region's accessible name is still the literal `Telemetry traces chart`, and the `aria-describedby` summary stays aggregate-only with no service name, including right after a new service is discovered (per a11y-plan §7 Landmark roles).
- (a11y) If `ConstellationCanvas.tsx` gains or changes any dot-entry motion, the reduced-motion spec proves that the motion degrades to instant under `reducedMotion: 'reduce'` and that the new dot is still conveyed without motion (per a11y-plan §6 Motion tokens + §11 Motion).
