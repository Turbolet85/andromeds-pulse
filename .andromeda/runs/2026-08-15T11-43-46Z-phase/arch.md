## Constraints
- The corpus at-rest posture is arch-owned: cell-level AES-256-GCM with key sourcing INTENDED to be the OS keychain (macOS Keychain / Linux Secret Service / Windows DPAPI via the `keyring` crate), recorded as UNIMPLEMENTED with a per-process-ephemeral key as of 2026-08-15. This chunk's fix is exactly the mandate architecture.md §Occupied Resources → Corpus SQLite database / schema names → At-rest posture requires be satisfied; the cipher and the table/column-plaintext + opaque-BLOB shape stay as specified (per architecture.md §Occupied Resources).
- Reserved corpus tables are fixed: `baseline_state`, `service_registry`, `pipeline_metrics`, `incidents`, `incident_events`, `digest_archive`. Any orphaned-row disposition (purge or tombstone) must operate within this reserved set — a new tombstone/inventory table would be a new occupied resource requiring registration (per architecture.md §Occupied Resources → Corpus SQLite database / schema names, and §Conventions → Database entity naming: plural `snake_case`, `snake_case` columns).
- Workspace crate names are LOCKED (`corpus`, `security`, `mcp-server`, `pulse-app`, … ). The key-source change lives in the existing `corpus` crate; its wiring at boot lives in `pulse-app`, its cross-process consumer in `mcp-server`. No new crate is authorized by this chunk (per architecture.md §Inherited Defaults + §Occupied Resources → Cargo workspace crate names).
- Module-boundary + contract discipline: each crate exposes only its public contract module; no cross-crate `pub use` re-exports outside that contract module; dependency direction flows toward `pulse-app` and the DAG has `pulse-app` as its only root. A `keyring`-backed backend must therefore stay behind the `corpus` contract surface that `pulse-app` and the `andromeda-pulse-mcp` sidecar both consume (per architecture.md §Conventions → Module visibility discipline, §Cross-cutting Patterns → Module dependency direction).
- The keychain-service/account identity and any passphrase-fallback input are configuration, and config precedence is fixed: env vars (`ANDROMEDA_PULSE_*`) > `<data_dir>/config.toml` > built-in defaults. Any new knob this chunk introduces must be a new `ANDROMEDA_PULSE_*`-namespaced env var registered in §Occupied Resources, or a `config.toml` field — not an ad-hoc third channel (per architecture.md §Cross-cutting Patterns → Config management, §Occupied Resources → Environment variables).
- Error handling is fixed by shape: `thiserror` enums module-internal in `corpus`, `anyhow` at `main.rs`/boundaries, and any error crossing the TauRPC bridge is the `serde`-friendly `AppError` (`Storage { message }` is the pre-existing variant for storage-side failures). A fallback-engaged or decryption-failure condition surfaced to the webview must map into that stable variant set, not a new one (per architecture.md §Conventions → Error response schema (Tauri IPC), §Established Decisions → [Error Handling Pattern]).
- The `mcp-server` crate and the `andromeda-pulse-mcp` sidecar binary are feature-gated (`--features mcp-server`, default off) and feature-gate hygiene requires flag-specific deps stay out of the default build graph. Whether a platform-native `keyring` feature set leaks into the default graph via `corpus` (it will, since `corpus` is not feature-gated) is a deliberate size/dep decision this chunk makes (per architecture.md §Cross-cutting Patterns → Feature-gate hygiene, §Established Decisions → [MCP Server Surface]).
- Data-dir paths are per-platform-resolved from one root with `ANDROMEDA_PULSE_DATA_DIR` overriding on every platform; `corpus/corpus.db` and `run/workspace-key` are registered subpaths. Any new file this chunk writes (e.g. a fallback key material file or migration marker) must be a registered subpath under the resolved root — architecture.md §Occupied Resources → Filesystem locations names exactly ONE deliberate out-of-data-dir exception (the `storage.export_for_training` Downloads sink), and this chunk is not it.

## Patterns to follow

Any file-mediated key/identity material this chunk adds should mirror that shape (per architecture.md §Occupied Resources → Filesystem locations).
- Swap-boundary-behind-a-trait: the `LlmInferenceRunner` precedent (concrete impl swaps, trait unchanged; three documented sibling impls) is the arch-sanctioned way to change a runtime provider. The chunk's expectation that `Corpus::open(path, Arc<dyn KeychainBackend>)` needs no signature change is consistent with it — whether the current code actually holds that shape is research's question (per architecture.md §Established Decisions → [LLM Inference Runtime]).
- Bounded-enumeration labels for anything crossing a bridge or entering a log: `BackendKind::as_str()` follows the same bounded-variant discipline as `AppError`'s stable variants and the truthy-parse gate pattern cited for env vars. Keep the `PassphraseFallback` label inside that bounded set rather than free-form strings (per architecture.md §Conventions → Error response schema (Tauri IPC), §Occupied Resources → `ANDROMEDA_PULSE_L4_DETERMINISTIC` bounded truthy-parse).
- Registered-resource-first: every env var, filesystem subpath, IPC procedure, and reserved table is enumerated in §Occupied Resources, and additions land there at wrap (the amendment history shows this for `window-geometry.json`, the Downloads export sink, and `run/workspace-key`). Anything new this chunk lands follows the same registration path (per architecture.md §Occupied Resources; §Project Intent → How new functionality is added).
- Config-hot-reload / watch fan-out already exists as `config-watcher` + `pulse://stream/config-events` (aggregate-only, no raw config values or paths). If the fallback branch needs any runtime-visible state change, that existing aggregate-only event discipline is the precedent, not a new raw-value channel (per architecture.md §Occupied Resources → Tauri IPC events).

## Anti-patterns to avoid
- Do not add a new workspace crate, re-purpose a reserved crate name, or introduce a sibling-crate dependency whose contract does not require it — the key-source fix is a dependency-feature + wiring change inside `corpus`/`pulse-app`/`mcp-server` (per architecture.md §Inherited Defaults → Module boundaries, §Cross-cutting Patterns → Module dependency direction).
- Do not introduce an external secrets manager or any network-dialing key retrieval — this is a local-first, zero-infrastructure, zero-egress desktop app; the OS credential store is a local facility, and "no external secrets manager (this is a local OSS desktop app)" is stated in the plan (per architecture.md §Design Philosophy → Local-first, zero-infrastructure; §Cross-cutting Patterns → Config management).
- Do not write key material, fallback state, or migration artifacts outside the resolved data-dir root, and do not add a second out-of-data-dir exception — architecture.md §Occupied Resources → Filesystem locations authorizes exactly ONE (the training-export Downloads sink) and requires canonicalize-and-confine for path env vars.
