## Relevance
Relevant — this chunk is the impl closure of an open defect the plan itself records under §Secret Management → Storage → Runtime, and it touches key custody, at-rest corpus posture, dependency gates, and log redaction.

## Constraints
- The 32-byte AES-256-GCM corpus cell key MUST come from OS keychain primary (`MacosKeychain` / `LinuxSecretService` / `WindowsDpapi` via `keyring`) with `BackendKind::PassphraseFallback`-**with-warn** as the only sanctioned fallback; strict-keychain-only is explicitly NOT the chosen posture, and the fallback MUST emit a warn-level boot event announcing reduced key-custody guarantees (per security-plan.md §Secret Management → Storage → Runtime, chunk #73 P-049). The plan records the measured state as neither branch reached; whether the code now reaches either is research's question.
- The corpus encryption key is on the "what counts as secret" list: never logged, never exported or shared across installations, with `#[tracing::instrument(skip(key))]` discipline required at all key-handling call sites (per security-plan.md §Secret Management → What counts as secret). Whether that `skip(key)` discipline is already present at every site the chunk touches is research's question. Any passphrase used by the fallback inherits the same never-log rule (per security-plan.md §Logging & Monitoring → What NEVER to log, final bullet).
- The at-rest shape is fixed: AES-256-GCM cell-level encryption, table/column names plaintext, BLOB cell payloads opaque without the key, and **no plaintext runtime state on disk** (per security-plan.md §Data Protection → At rest → Persistent incident corpus). Whatever the retire-HOW fork produces — purge or tombstone/inventory — must not re-introduce plaintext payload on disk; the plaintext metadata that makes a keyless inventory buildable is limited to what that row already declares plaintext.
- New transitive trees pulled by platform-native `keyring` features MUST pass `cargo deny check bans licenses sources` (with `[bans] multiple-versions = "deny"`, the SPDX `[licenses]` allowlist that is load-bearing for the Homebrew/Scoop channels, and `[sources]` restricted to `crates-io`) plus `cargo audit` against RustSec, both wired into `ci.yml`; `Cargo.lock` stays checked in and the resolved pin recorded (per security-plan.md §Dependency Security → CI integration and §Bootstrap phases → `dep-audit-tooling-install` / `dep-security-ci-gate`).
- Secret scanning runs pre-commit and per-PR and the build fails on a detected secret; `.gitignore` covers `*.key` / `.env*` / `*.p12` / `*.pem` / `*.cer` (per security-plan.md §Secret Management → Secret scanning in CI; §Security Anti-Patterns → Secrets). This binds the chunk's test-hygiene directive: a test that mints a real credential-store entry writes real OS-level secret material, so a test-scoped service name plus cleanup is required and no fixture passphrase may land in the tree.
- If the fallback passphrase or any new key-source knob arrives via env var or file path, it is a new input boundary: bounded parse for scalars, and any `*_PATH` / `*_DIR` env var MUST be canonicalized and confined under the resolved data dir via `strict-path` (CWE-22 class) (per security-plan.md §Input Validation → CLI / env var inputs and §Security Anti-Patterns → Input). Whether the chunk introduces such a knob at all is research's question.
- Corpus open / key-acquisition / decryption failures crossing the TauRPC bridge MUST collapse to `AppError::{Storage, Internal}` carrying a sanitized one-liner — no stack traces, file paths, Rust struct names, or library versions reach the webview; the full chain stays in the internal log (per security-plan.md §Error Handling and §Security Anti-Patterns → Logging, bullet 4).

## Patterns to follow
- The `<data_dir>/run/workspace-key` precedent: log a byte count plus basename only, never the value, for a security-relevant file surface (per security-plan.md §Input Validation → Published workspace key row; §Logging & Monitoring). The scope's own invariant restates this for the cell key.
- Bounded enumeration as the cardinality-safe log field: a `BackendKind`-style closed enum with an `as_str()` label is the shape that satisfies structured-JSON field discipline without leaking (per security-plan.md §Logging & Monitoring → Log format — redaction applied at the subscriber layer, not at call sites).
- Warn-and-proceed graceful degradation: the MCP feature-flag mismatch logs at `warn` and continues rather than failing, and that behavior must not regress (per security-plan.md §Input Validation → CLI / env var inputs; §Logging & Monitoring → What to log). The P-049 fallback warning is the same shape — degrade with a visible signal, do not hard-fail.
- Uniform scrubber at every persistence boundary: anything crossing into `corpus.db` or `agent-latest.jsonl` passes `security::scrubber::scrub_attribute` first (per security-plan.md §Security Anti-Patterns → Logging, uniform-scrubber paragraph). Applies to any disposition path that rewrites rows or emits an orphan inventory.
- Self-written on-disk state uses atomic `.tmp`+rename with a graceful non-panicking default on missing/corrupt read (per security-plan.md §Input Validation → Persisted window geometry and Published workspace key rows) — the shape for any migration marker or disposition ledger this chunk adds.

## Anti-patterns to avoid
- NEVER log key material, a fallback passphrase, decryption-failure ciphertext, or raw attribute values from the failing rows — the never-log list explicitly includes "anything matching the §Secret Management 'What counts as secret' list" (per security-plan.md §Security Anti-Patterns → Logging; §Logging & Monitoring → What NEVER to log).
- NEVER resolve a new `cargo deny` finding from the keyring tree by widening an ignore blanket-style or relaxing `[bans] multiple-versions = "deny"` / the SPDX allowlist / the `crates-io`-only `[sources]` restriction (per security-plan.md §Dependency Security and §Bootstrap phases → `dep-audit-tooling-install`); exceptions must be ID-scoped and reasoned.
- NEVER surface internal detail (paths, struct names, library versions, error chains) through `AppError::Internal { message }` when key acquisition or decryption fails (per security-plan.md §Security Anti-Patterns → Logging, bullet 4).

## Acceptance criteria contributions
- (security) The corpus cell key resolves from a real platform credential store on a dev host and survives a process boundary — content written by one process decrypts in a later, separate process (per security-plan.md §Secret Management → Storage → Runtime).
- (security) Where no credential store is available (headless/CI), `BackendKind::PassphraseFallback` engages and emits its warn-level boot event announcing reduced key-custody guarantees; neither a silent mock-store success nor a hard failure satisfies this (per security-plan.md §Secret Management → Storage → Runtime, chunk #73 P-049).
- (security) No key bytes, passphrase, ciphertext, or failing-row attribute values appear in `agent-latest.jsonl` or any tracing event — only bounded backend-kind labels and counts; `#[tracing::instrument(skip(key))]` present at key-handling call sites (grep verifies) (per security-plan.md §Secret Management → What counts as secret + §Logging & Monitoring → What NEVER to log).
- (security) `cargo deny check bans licenses sources` and `cargo audit` pass with the new keyring transitive tree, with any exception ID-scoped, reasoned, and owner-named rather than an ignore widened (per security-plan.md §Dependency Security → CI integration + §Bootstrap phases → `dep-audit-tooling-install`).
