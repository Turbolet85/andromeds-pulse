# design extract

## Relevance
Partial — the reconciliation mechanism itself is backend/registry, but two chunk outcomes touch rendered surface: fork (c) ("make the staleness VISIBLE") is new UI by definition, and the active-incident set that this chunk reconciles is the documented driver of the constellation dot's severity hue.

## Constraints
- Any UI this chunk adds or changes must draw from the Tailwind v4 `@theme` custom properties (`--color-*`, `--spacing-*`, `--radius-*`, `--font-*`, `--duration-*`, `--easing-*`) — no hardcoded hex or px literals (per design-system.md §Surface: desktop-webview → Tokens; §Self-Validation Protocol → Token Test).
- Incident state must never be conveyed by color alone; a state color pairs with a text label or icon (per design-system.md §Anti-Patterns → Universal Bans "NEVER use color purely for decoration"; §Color Palette → Accent usage). Alert Burgundy `#C7556A` is a **non-text** token (≈3.8:1 on Base): it may carry a border or icon for a stale/resolved affordance, never body-size (≤14px) message text — that renders `var(--color-text-primary)`.
- Body-size message text (an "externally resolved" note, a staleness banner) uses Secondary `#B4BCCB` or Primary `#E8EEF7`; Tertiary `#7D8697` (≈4.2:1) is large-text-only (per design-system.md §Surface: desktop-webview → Loading / Empty States; §Color Palette → Text Hierarchy).
- Incident ids, timestamps, and counts render in the JetBrains Mono Data/Code roles (12px, tabular-nums for numerics); prose labels render IBM Plex Sans Body 14px / Label 12px. The mono-vs-sans split encodes "immutable telemetry fact" vs "operator communication" and is mandatory, not cosmetic (per design-system.md §Typography).
- The severity-hue axis and the connection/freshness axis are **orthogonal** (P-004): a "this row may be stale" signal must not be expressed by moving the Earth Blue ↔ Alert Burgundy severity hue, which design-system.md §Motion → High-impact moments (1) reserves for cumulative incident severity, with connection state as a separate grayout/desaturation axis.
- Chrome motion for a row leaving the active list stays inside the 0.35 webview budget: 150ms ease-out hover/focus, 200ms ease-out fade for panel/state transitions, **no entrance animations**, no staggered reveals of list items, no opacity fade &gt;200ms (per design-system.md §Motion → Duration scale + Hard limits).
- All motion respects `prefers-reduced-motion: reduce` — transitions collapse to 0ms; where a halo/dot pulse exists it degrades to a static glow with hue still tracking severity (per design-system.md §Motion → Accessibility).

## Patterns to follow
- **Tables (telemetry data)** for any active-incident list rendering: transparent rows on the parent card, hovered row `rgba(74,144,226,0.1)` with **no transition** (instant at 0.35 expression), 1px `rgba(74,144,226,0.1)` row borders, JetBrains Mono 12px data cells with tabular numerals, `space-sm` padding (per design-system.md §Surface: desktop-webview → Component Patterns → Tables).
- **Shared `EmptyState`** if reconciliation drains the active list to zero: decorative Observatory glyph (`telescope`, 24px, `aria-hidden`) + message + optional actionable hint, all `--color-text-secondary` / `font-body` 14px — and the **honest-error variant** (static "Couldn't load …", no hint) is checked BEFORE the empty branch so a failed read never masquerades as "no active incidents" (per design-system.md §Surface: desktop-webview → Loading / Empty States).
- **Cards / Panels** for any container holding the reconciled list or a staleness notice: Raised-1 `#262A33`, 1px `rgba(74,144,226,0.3)` subtle border, `space-md` padding, `radius-md` — borders-only depth, no shadow, no gradient (per design-system.md §Depth Strategy; §Component Patterns → Cards / Panels).
- **Custom icon set first** if the fork adds an affordance: `&lt;Icon glyph="…" /&gt;` from the registered Observatory glyphs (aperture / telescope / constellation-grid / star / circular-pulse); Lucide/Heroicons only where no domain glyph exists, at the 16/20/24px size grid. Icons clarify, never decorate — in the compact widget, an icon that loses no meaning when removed must be removed (per design-system.md §Iconography).
- **Semantic Colors rows** for a staleness/notice treatment: Info = Base bg + `#4A90E2` border + `#4A90E2` text; Warning/Error = Base bg + `#C7556A` border + `#E8EEF7` text (per design-system.md §Color Palette → Semantic Colors).

## Anti-patterns to avoid
- No `alert()` / `confirm()` / `prompt()` and no native-web dialog if a fork surfaces a confirmation or a "restart to reconcile" prompt — use the styled shadcn/ui Dialog on Raised-3 `#343A45` (per design-system.md §Anti-Patterns → Per-Surface Bans: desktop-webview; §Depth Strategy → Modal elevation).
- No gradient overlay, glassmorphism, or shadow to signal "stale/degraded" on chrome — the flat, matte, borders-only discipline holds; the Halo canvas is the ONLY gradient+blur exception (per design-system.md §Anti-Patterns → Universal Bans; §Depth Strategy).
- No uniform monochrome status icon (green check / red X) substituted for the two-dimensional encoding — that default is explicitly rejected; activity/liveness and severity are separate perceptual channels (per design-system.md §Anti-Patterns → Rejected Defaults).

## Contract bindings
- **design ↔ a11y:** token contrast is design's target, WCAG derivation is a11y's — Primary ≈8.5:1, Secondary ≈6.8:1, Tertiary large-text-only, accent non-text 3:1 (SC 1.4.11) (§Color Palette → Text Hierarchy / Accent usage). The not-color-alone rule for incident state binds to a11y SC 1.4.1; the `prefers-reduced-motion` override binds to a11y SC 2.3.3 (§Motion → Accessibility).
- **design ↔ obs:** the amendment sidecar's Downstream Readiness index assigns obs the Halo frequency + color-state hooks and permits instrumenting transitions into/out of loading/error visuals **without modifying the visual tokens** — relevant because this chunk's RED/GREEN legs ride `incidents.list_active.request` and `triage.incident.persist`.
- **design ↔ data-viz / constellation:** design-system.md §Brand Identity → Signature element and §Motion → High-impact moments (1) require the dot/halo hue to encode **cumulative incident severity** over the ACTIVE incident set. If that hue is computed from the same in-memory registry this chunk reconciles, a stale active row mis-encodes the signature element for the whole session. Whether the constellation dot's hue actually reads the registry's active set (vs. an independent path) is research's question.
- **design ↔ layouts:** where a staleness affordance sits on the compact widget vs. the full dashboard, and its focus order, are the layouts distiller's call, not mine.

## Acceptance criteria contributions
- (design) Any UI added or changed by the chosen fork uses only design tokens — zero hardcoded hex values and zero raw px literals outside the `@theme` block (per design-system.md §Surface: desktop-webview → Tokens).
- (design) Externally-resolved / stale incident state is conveyed by a text label or icon in addition to any color, and body-size message text uses `var(--color-text-primary)` or `--color-text-secondary` — Alert Burgundy appears as border/icon only (per design-system.md §Color Palette → Accent usage).
- (design) Any transition introduced (row removal, staleness banner appearance) is ≤200ms ease-out with no entrance or staggered animation, and is suppressed under `prefers-reduced-motion: reduce` (per design-system.md §Motion → Duration scale / Hard limits / Accessibility).
- (design) If reconciliation empties the active-incident list, the shared `EmptyState` empty variant renders — not the honest-error variant, and not a raw `AppError` string (per design-system.md §Surface: desktop-webview → Loading / Empty States).
