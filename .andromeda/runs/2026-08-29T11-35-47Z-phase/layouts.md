Whether the code already re-sizes on a count change mid-session (vs. only at open) is research's question.
- The findings window is required to reuse the P-080 `FindingsDropdown` row content on the opaque `--color-raised-2` popover surface — one row rendering, not a second variant for reconciled/removed rows (per layout-templates.md §Surface: desktop-webview → Primary screens — Findings window).
- The shared `EmptyState` component is scoped by the plan to the **Metrics / Logs / Snapshots** data views only; the plan mandates **no** empty-state layout for a findings list that reconciliation empties mid-session. Any zero-findings state this chunk surfaces is new layout truth needing an amendment (per layout-templates.md §Component — Empty / error state (desktop-webview data views)).
- The shipped desktop-webview signature is the **constellation dot hue keyed to cumulative incident severity** (`severityToHueFraction` → `ConstellationDot.priorityTier`), not error rate; the WebGPU halo layer is SPECIFIED-BUT-UNBUILT on both webview surfaces (per layout-templates.md §Signature placement and §Component — Halo State Pulse canvas, MEASURED 2026-08-21 note). Reconciliation changes that hue's input; whether the live dot hue already follows an externally-resolved incident is research's question.
- The Traces hero must keep the **STABLE literal accessible name `"Telemetry traces chart"`**, with lifecycle counts + the findings tally carried only by the visually-hidden `data-testid="constellation-summary"` element wired as its `aria-describedby` target; `role="status"` is deliberately NOT applied (per layout-templates.md §Wireframe notes — Full dashboard (Traces primary screen)).
- The Traces route is required to be a flex column bounded to the shell's `main` height with `overflow:hidden` and **no outer page scrollbar at any window size** — hero + `Errors only` toolbar `flex-shrink:0`, table `flex:1 / min-height:0 / overflow-y:auto` with sticky opaque thead. Any fork-(c) staleness affordance must be a fixed-height sibling inside that column (per layout-templates.md §Wireframe — Full dashboard (Traces primary screen) and §Component — Trace data table → Internal scroll region).
- The OS-native notification trigger registry is a closed enumeration of **four** triggers gated on `notifications_enabled`; a fork-(b) toast on external resolve would be trigger #5 and requires an explicit decision plus a plan amendment, never a silent addition (per layout-templates.md §Component — Notifications (OS-native) → Trigger events).

## Patterns to follow
- Floating-window geometry chain: findings window docked from the compact widget's live geometry (clamped), report window positioned left of findings (clamped) — the established shape for any re-layout driven by a changed incident count (layout-templates.md §Primary screens — Findings window / Report window).
- Live-poll readout without new chrome: the dashboard-only `ConnectionStatusLine` states plain-language truth in the footer at a 1s poll (words in `font-body`, numerics in the `font-code` Data role) while the compact widget stays aggregate-glance — the precedent shape if fork (c) must surface reconciliation lag (layout-templates.md §Component — Footer (read-only status bar) → Full dashboard).
- Roving-tabindex row list: the trace table contributes exactly ONE tab stop, Up/Down/Home/End traverse, Esc returns to the `Errors only` toggle, and **row focus survives the live re-poll** (P-081) — the model to preserve if a reconciliation removes the focused/active row between polls (layout-templates.md §Component — Trace data table → Keyboard / focus).
- Single disclosure entry point: the compact-widget unread badge opens the findings window; incident disclosure has one affordance, and the widget carries no other navigation beyond the gear (layout-templates.md §Primary screens — Findings window, §Component — Primary navigation → IA model, §IA notes → Navigation model).

## Anti-patterns to avoid
- Do not add worded status chrome to the compact widget — it is the minimalist aggregate-glance surface and the plan reserves the plain-language line to the dashboard footer (layout-templates.md §Component — Footer → Full dashboard, §IA notes → Navigation model).
- Do not introduce the Halo State Pulse WebGPU canvas on either webview surface as a side effect of touching the severity/incident path — its build-or-retire is owned by the separate working-route entry "Halo State Pulse canvas disposition", which this chunk's §Boundaries explicitly leaves untouched (layout-templates.md §Component — Halo State Pulse canvas, MEASURED note).
- Do not let the hero landmark's accessible name track the reconciled data — a name that churns thrashes the screen-reader rotor; the tally belongs in the description (layout-templates.md §Wireframe notes — Full dashboard (Traces primary screen)).
