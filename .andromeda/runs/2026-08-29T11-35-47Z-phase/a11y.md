# a11y extract

## Relevance
Partial — the chunk's core (registry/corpus/sidecar/persist cycle) is backend and out of a11y scope, but its stated outcome is defined by what a rendered surface stops displaying, so every fork touches the incidents/findings UI and inherits a11y constraints on that half only.

## Constraints
- Any UI-visible half of this chunk inherits **Standard tier → WCAG 2.1 AA** with the motion-sensitive SC 2.3.3 AAA escalation, and the hard gate "zero WCAG AA violations on must-be-accessible paths, no soft gate, no retry-once" (per a11y-plan.md §1 A11y Scope Summary + §10 SLO Invariants).
- Live list mutation must not steal or drop keyboard focus: §1 P4 requires live updates leave the current keyboard target intact and focus stable across re-renders, with the roving `tabindex` clamped and never reset (per a11y-plan.md §1 Critical Paths P4 + §5 Keyboard Navigation → full-dashboard-traces). P4's recorded acceptance is about the re-poll *preserving* the focused row; whether the code already handles the focused row being **removed** (not merely re-ordered) is research's question.
- A count/status change caused by reconciliation must be announced non-interruptively via `aria-live="polite"` (SC 4.1.3), and a second live region must NOT be stacked over an existing polled one — §7 records the deliberate omission of `role="status"` on the polled constellation summary precisely because a poll plus an existing live region stacks announcements (per a11y-plan.md §7 Screen Reader Support → Live regions + Landmark roles). §5 requires the findings badge's `0→N` transition announce once politely; whether the shipped badge/live region also handles the **decrease** (`N→N-1`, `N→0`) is research's question.
- Fork (c) ("make the staleness VISIBLE") adds a state indicator, so SC 1.4.1 not-color-alone applies: the state must carry an icon or text label, not color alone (per a11y-plan.md §6 State color tokens + §11 Anti-Patterns → Visual). Note §11 records that the `--color-secondary / --color-base` pair is **not yet defined** in design tokens — a warning/stale marker using it needs that pair defined before it ships.
- Adding a surface or state is a same-chunk obligation: every new route/modal/state ships one axe spec in the same chunk, fixtures must be POPULATED (an empty array audits a blank region and passes vacuously), and suite health is checked with `npx playwright test --list` (per a11y-plan.md §3 Harness wiring & conventions).
- A11y failures must emit machine-verifiable evidence in the structured violation JSON shape, and the per-PR gate compares tuples against the regression baseline (per a11y-plan.md §1 Structured Violation JSON Schema + §3 CI integration + §2 Agent-runnable invariants).

## Patterns to follow
- **Row-level roving-`tabindex` traversal** on the trace list — one tab stop per row, Up/Down/Home/End, Enter activates, Esc exits, `--border-focus` on `:focus-visible`, in-row action at `tabIndex={-1}` (a11y-plan.md §5 full-dashboard-traces + §11 Keyboard grid-lite carve-out). Any incident-row list this chunk mutates follows the same discipline.
- **Findings-window disclosure pattern** — badge with `aria-haspopup="dialog"`, rows tabbed within, cross-window focus restoration to the badge via first-party Tauri events (not `focus-trap-react`, which cannot cross windows) (a11y-plan.md §5 findings-window + §5 Focus restoration → Cross-window).
- **Stable landmark name + `aria-describedby` summary** — a landmark's accessible name stays a stable literal while changing aggregate state lives in a visually-hidden description, so the SR rotor does not churn as data changes (a11y-plan.md §7 Landmark roles). Directly applicable if reconciliation changes a counted aggregate.
- **Harness mock shape for reconciliation states** — `TauRPC__<router.path>` command regex, `plugin:event|listen` for push channels, and the `__mockReject` / `__mockDelayMs` sentinels that make error and in-flight states auditable rather than only settled-success (a11y-plan.md §3 Harness wiring & conventions).
- **Existing spec set `p1`–`p14`** plus `keyboard-focus/widget-and-modals.spec.ts` as the template for a new audit; p8 (findings dropdown) and p13 (empty states) are the surfaces this chunk's outcome most plausibly lands on (a11y-plan.md §1 Surface set extension).

## Anti-patterns to avoid
- NEVER convey "stale" / "resolved externally" by color alone, and never hide the affected content from assistive tech with `aria-hidden` while leaving it focusable (per a11y-plan.md §11 → Visual + Screen Reader).
- NEVER claim the reconciliation is accessible on manual/visual inspection alone, or defer the a11y check to post-merge — automated JSON evidence is primary and the gate is fail-fast (per a11y-plan.md §11 → Strategy, CI, Universal).
- NEVER introduce a second competing live region (or `role="status"`) for a poll-driven update alongside the existing one, and never regain focus order by setting `tabindex > 0` (per a11y-plan.md §7 Landmark roles + §11 → Keyboard).

## Contract bindings
- **Violation JSON ↔ obs**: violation records bind to obs's structured log format (`target: "a11y::assertion"`, `fields.wcag_criterion` / `violation_type` / `severity` / `surface` / `selector` / `remediation` / `tool` / `tool_result_id`) with the same `service.name` / `deployment.environment` resource attributes used for cross-correlation (a11y-plan.md §1 Structured Violation JSON Schema + §3 + §9).
- **CI a11y gate ↔ tests**: `npm run test:a11y` runs in the same `ci.yml` pipeline and reuses tests' 5-command E2E driver (`boot` / `run` / `status` / `cleanup` / `logs`); the per-PR regression gate diffs `{surface, wcag_criterion, selector, severity}` tuples against `baselines/a11y-violations-summary.json` (a11y-plan.md §3 CI integration + §9).
- **State color + focus ring ↔ design**: any fork-(c) indicator binds to design's token pairs — `--color-accent` / `--color-feedback-success` / `--color-secondary` against `--color-base` / `--color-inset`, and `--border-focus` at ≥ 3:1 non-text (a11y-plan.md §6 Color contrast pairs + Focus ring tokens).
- **Row focus order ↔ layouts**: the incident/findings row tab sequence and cross-window restoration anchors (a11y-plan.md §5).

## Acceptance criteria contributions
- (a11y) Under forks (a)/(b): removing an externally-resolved row from the displayed active list does not move, drop, or reset keyboard focus — the roving `tabindex` is clamped, and focus lands on a defined neighbour if the focused row itself is removed (per a11y-plan.md §1 Critical Paths P4 + §5).
- (a11y) The resulting count/state change is announced once, politely and non-interruptively, with no second live region stacked over the existing polled one; if the list reaches zero it lands on the shipped p13 empty state rather than an unannounced blank region (per a11y-plan.md §7 Live regions + §1 Surface set extension).
- (a11y) Any new or changed surface state (notably fork (c)'s staleness indicator) ships an axe spec in the same chunk with POPULATED fixtures, is not-color-alone (icon or text label), and its token pair meets SC 1.4.3 4.5:1 text / SC 1.4.11 3:1 non-text (per a11y-plan.md §3 Harness wiring & conventions + §6 State color tokens + §11 Visual).
- (a11y) The full a11y chain passes with zero new violation tuples versus `baselines/a11y-violations-summary.json` and Lighthouse a11y ≥ 90 on the touched surface — hard gate, no retry, no post-merge deferral (per a11y-plan.md §10 SLO Invariants + §3 CI integration).
