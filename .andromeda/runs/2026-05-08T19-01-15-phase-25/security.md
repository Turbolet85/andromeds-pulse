- WGSL shader sources MUST be first-party — bundled with the webview build, served via `'self'` origin; never loaded from a remote URL or from a plugin guest's returned bytes (per security plan §Threat Model Summary "webview content" trust boundary "WGSL shaders are first-party").
- The webview's runtime IPC capability surface MUST stay scoped to `pulse:default` enumerating only the procedures listed in arch §Occupied Resources; chunk #28 MUST NOT widen capabilities to grant `fs`/`shell`/`dialog`/`http` core APIs to satisfy WebGPU initialization (per security plan §API Security row "Updater capability isolation" + §Anti-Patterns API row 4).
- The `navigator.gpu === undefined` fallback message MUST render entirely from first-party assets — no remote image, font, or script loaded into the fallback DOM — preserving the `default-src 'self'` posture (per security plan §API Security CSP row + §Threat Model Summary "webview content").
- The Arrow data feeding the WebGPU canvas crosses the TauRPC bridge as `pulse://stream/{spans,metrics,logs}` Channel API payloads from first-party Rust crates (`viz`/`buffer`); chunk #28 is consumer-side and MUST NOT introduce unbounded payload-size acceptance on the JS side — the size-cap responsibility lives in the producing crate, but a defensive client-side max-size guard before GPU buffer upload is consistent with the §Input Validation row "Tauri IPC `Channel` API streaming payloads" "size cap before re-emit" pattern.
- Any error surfaced from WebGPU init failure (adapter request rejection, shader module compilation error) that crosses back to Rust via TauRPC for telemetry MUST be sanitized at the `From<...> for AppError` boundary — never serialize raw browser error strings, file paths, or library versions onto the bridge (per security plan §Anti-Patterns Logging row 4 + §Code Patterns row "NEVER serialize an `anyhow::Error` directly across the TauRPC bridge").

## Anti-patterns to avoid

- NEVER add `'unsafe-inline'` or `'unsafe-eval'` to `script-src` to expedite WGSL bundling/transpilation — `'unsafe-inline'` is permitted only on `style-src` as a documented risk acceptance for first-party styles (per security plan §API Security CSP row + §Anti-Patterns API).
- NEVER load shader source, fonts, or fallback message assets from a remote origin (no `https://cdn.…/shader.wgsl`, no Google-Fonts URL); all assets ship under `'self'` (per security plan §Threat Model Summary "webview content" + §API Security CSP row "NO remote content per Cross-cutting Patterns").
- NEVER widen `pulse:default` to grant `fs`/`shell`/`dialog`/`http` core APIs to read/write WGSL files at runtime — bundling-time embedding is the correct path; runtime FS access in the webview is explicitly out of scope (per security plan §Anti-Patterns API row 4 + §API Security row "Updater capability isolation").

## Contract bindings

- **security ↔ a11y**: the WebGPU-unavailable fallback message is also a screen-reader-accessible status surface — security forbids remote assets in the fallback DOM, a11y owns the message text + ARIA role/live-region semantics. - **security ↔ obs**: WebGPU init / frame_duration_ms telemetry crossing TauRPC back to Rust enters the `tracing` self-observation path; security requires the `From` impl sanitize browser-side error strings at the bridge (no paths/versions/stack traces leak), obs owns the span/event schema and PII scrubbing layer (per security plan §Anti-Patterns Logging row 4 + obs-plan §Self-observation discipline).

Security supplies the invariant; tests own the assertion mechanism.
