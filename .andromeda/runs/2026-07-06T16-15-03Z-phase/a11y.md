## Relevance
Relevant — a layout/positioning fix on the **p8 findings-dropdown**, a must-be-accessible surface (P1–P12 per a11y-plan.md §1); the a11y stake is regression-PRESERVATION of the existing chunk #87 disclosure + focus + reduced-motion contract and keeping the p8 axe spec green, not authoring new ARIA.

## Constraints
- The findings dropdown is in the must-be-accessible set (p8); the universal minimums **SC 2.1.1 Keyboard / SC 2.4.3 Focus Order / SC 4.1.2 Name-Role-Value** must remain satisfied after re-anchoring (per a11y-plan.md §1 surface-set-extension note + §10 coverage report).
- Standard tier → WCAG 2.1 AA with **zero WCAG AA violations on must-be-accessible paths AND zero NEW violations vs the re-baselined `a11y-violations-summary.json` per PR** (per a11y-plan.md §10); the p8 axe spec (zero critical/serious) is the machine gate.
- Preserve the disclosure semantics: native `<button>` trigger carrying `aria-expanded`/`aria-controls`/`aria-haspopup`, panel id matching `aria-controls`, focus remaining on / returning to the trigger (per a11y-plan.md §4 Disclosure/Button rows) — re-anchoring must not touch role/name/value.
- Focus order + restoration must survive repositioning: the panel's rows/footer stay in a visible, sensible Tab sequence and **Escape closes + restores focus to the counter trigger** (per a11y-plan.md §5 focus restoration + §1 P5 compact-widget Esc anchor); a panel laid out off the painted viewport strands focused rows off-screen.
- **SC 2.4.7 Focus Visible + SC 1.4.11 non-text contrast**: focused trigger and rows must show the `--border-focus` ring *within* the painted viewport — the bounded-popover fix is precisely what keeps focused content on-screen (per a11y-plan.md §6 Focus ring tokens).
- **Reduced-motion (SC 2.3.3 AAA + SC 2.3.1)**: the panel's opacity fade (`--duration-standard`/`--easing-out`) must degrade to instant under `prefers-reduced-motion: reduce`, state still conveyed non-motion (per a11y-plan.md §6 Motion tokens + §11 Motion bans).
- Row text (`--color-text-primary`) + timestamp (`--color-text-secondary`) over the opaque popover background must keep **SC 1.4.3** (≥4.5:1 / ≥3:1); keep an opaque design-token bg and do NOT swap to a token that regresses contrast (per a11y-plan.md §6 contrast pairs) — this resolves the scope's `--color-inset` vs `--color-raised-2` tension toward the contrast-safe opaque bg.

## Patterns to follow
- Trigger↔panel wiring already correct: `FindingsCounter` `<button aria-expanded aria-controls={FINDINGS_DROPDOWN_PANEL_ID} aria-haspopup>` ↔ `FindingsDropdown` `role="region" aria-label` with matching `id`; keep the id/`aria-controls` linkage when re-anchoring (a11y-plan.md §4).
- Escape + click-outside dismissal via useEffect document-level `keydown`/`mousedown` listeners with `triggerRef.current?.focus()` restore — the canonical click-outside pattern (NOT `onClick` on a non-interactive overlay), per a11y-plan.md §11 ARIA bans (and rules/a11y.md 2026-05-10 entry the component already cites); preserve as-is.
- Not-color-alone: the severity dot is `aria-hidden="true"` decorative while the severity word rides in the row's `aria-label` + an `sr-only` span (SC 1.4.1) — the layout fix must not drop these (a11y-plan.md §6 State color / §1 visual-discrimination trigger).
- Reduced-motion is inherited through the token: the tokens.css `@media (prefers-reduced-motion: reduce)` override zeroes `--duration-standard`, so the panel degrades without per-component JS (a11y-plan.md §6 Motion).

## Anti-patterns to avoid
- NEVER let focused rows render off the painted viewport or omit/replace `:focus-visible` `--border-focus` styling (SC 2.4.7) — the defect's off-viewport panel is itself the failure mode (a11y-plan.md §11 Keyboard bans).
- NEVER break the Escape escape-path or introduce a keyboard trap while re-anchoring (SC 2.1.2) (a11y-plan.md §11 Keyboard bans).
- NEVER convey severity by dot color alone, and NEVER leave the fade active under reduced-motion (a11y-plan.md §11 Visual + Motion bans).
