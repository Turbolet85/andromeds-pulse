## Notes for Phase 1 synthesis

- **The ruled order (intent §6):** what replaces a thing is reachable before the chunk that removes the thing. Applied here as: the console entry point, the harness and the engine's gate precede the window's gates and the window; the incident as the engine's own record precedes the local model; the capability record precedes the first removal; the door precedes the sidecar's removal (one chunk names both); the engine's own delivery (P-107) cannot precede the desktop distribution's removal by more than its CI build — the distribution workflow builds the bundle of the shell P-083 removes. hypothesis, for the operator at Phase 4.
- **Removals that ride the window's removal:** the plugin host, the training export and workspace detection each have an IPC router in the bridge; they follow the window so that what is left to remove is a crate, a dependency and a store key, not an interface.
- **Capabilities with halves in two epochs:** P-090 (memory in Epoch 4, the disk file in Epoch 5); P-112 (the record in Epoch 3, the one report form in Epoch 8); P-113 (CI legs in Epoch 1, the code in Epoch 2, the resolver with P-118); P-105 (the key in Epoch 3, "two tokens, one incident" with P-088 in Epoch 4); P-119 (consumers land in Epochs 6 and 7); P-116 (the first-read records in Epoch 3, the loopback rule with P-087 in Epoch 4).
- **Gate reachability:** the new gates that grow with the code — the engine end to end under a memory cap, a sender on a second host over an encrypted channel, the engine run as a service on a clean node — get one reachability chunk in Foundation. The old gates (`a11y`, `boot`, the webview suite, the headful drive and self-verify, the bundle job, the latency grader, the decision probe) are retired as a chunk's stated work.
- **The six plans** are read in Phase 1; three have the window as their whole subject and are cited only where a chunk retires what they describe.
