# a11y extract

## Relevance
Relevant — this is the P4 "Live trace list" critical-path surface (auto-updating `<table>` in the full-dashboard-traces layout); live-refresh behavior sits squarely in a11y domain.

## Constraints — domain rules that apply
- **Live updates must not steal or reset focus.** The re-poll must preserve `document.activeElement` and focus order across re-renders — a keyboard user on a sort header, the "Errors only" toggle, or an in-row Investigate button keeps focus when the interval fires (per a11y-plan §1 Critical Paths P4 — SC 2.1.1 "current focus preserved through live updates" + SC 2.4.3 "focus stable across re-renders").
- **Empty→populated and incremental updates are Status Messages.** Dynamic content transitions announce via `aria-live="polite"` (non-interrupting), never assertive/alert for routine row deltas (per a11y-plan §1 P4 — SC 4.1.3 + §7 Live regions "real-time telemetry trace feed → polite").
- **Name/Role/Value state survives refresh.** `aria-pressed` on the "Errors only" toggle and `aria-sort` on sortable columns must persist across a re-poll (the scope requires filter/sort state survive) — keep that state in the component, refresh only the `rows` prop (per a11y-plan §4 ARIA Patterns Button/SC 4.1.2).
- **Anomaly-first hoist must not be color-alone; contrast holds.** Erroring rows keep the ✗ glyph + `--color-accent` left border + count (not color/position alone); empty/loading cell text stays `--color-text-secondary` (4.5:1), not tertiary (per a11y-plan §11 Visual/SC 1.4.1 + §6 contrast pairs/SC 1.4.3).
- **No motion-induced flicker; reduce-motion respected.** Any row transition on refresh must degrade under `prefers-reduced-motion: reduce` and never flash >3×/sec (aligns with the scope's "no row-flicker") (per a11y-plan §1 motion-sensitive trigger + §6 Motion tokens/SC 2.3.3 AAA + SC 2.3.1).
- **Auto-update cadence stays within the SC 2.2.2 N/A determination.** The plan marks SC 2.2.2 not-applicable (live telemetry is essential auto-update; the constellation already polls 1s); staying within it requires the ~1s poll to be non-interrupting and to NOT emit a per-tick SR announcement (per a11y-plan §1 "SCs not applicable" — SC 2.2.2).
- **Zero WCAG AA violations / zero-new-per-PR on the P4 surface** (per a11y-plan §10 SLO Invariants).

## Patterns to follow — existing patterns relevant to implementation
- **Reuse the existing polite announcer.** `TraceTable.tsx` already calls `announce(...)` from `dashboard/StatusLiveRegion` (`useStatusAnnouncer`) for sort/filter changes (`TraceTable.tsx:5,31,43-55`); route the empty→populated announcement through this same `aria-live="polite"` region rather than adding a new live element.
- **Filter/sort state already lives in `useState` in the child.** `errorsOnly` + `sortState` (`TraceTable.tsx:29-30`) with `aria-pressed`/`aria-sort` bound (`:77`, `:110`) naturally survive a data-prop refresh — the pattern to preserve is: re-poll updates only the `rows` prop and must not remount the table subtree.
- **The target hook is `use-traces.ts`.** It runs `getClient().traces.query(args)` once in a `useEffect` keyed `[timeWindowSeconds, limit]` with a `cancelled` cleanup guard (`use-traces.ts:48-82`); add the interval here, merging into `state.rows`, and clean up the timer on unmount (no leaked timers).
- **The P4 axe spec already exists.** `pulse-app/ui/tests-a11y/axe/p4-live-trace-list.spec.ts` (+ `p1-traces.spec.ts`) sweep `/traces` — no NEW axe spec is required (no new route/modal added), but these must stay green under the refresh (per a11y-plan §3 "Adding a surface" standing rule — surface pre-exists).

## Anti-patterns to avoid
- **Never let the re-poll steal focus** (remounting the table, refocusing on data arrival, or keying the effect so the subtree unmounts each tick) — per a11y-plan §1 P4 + §11 Keyboard.
- **Never announce routine row updates via `aria-live="assertive"`/`role="alert"`** or stack per-tick announcements — polite, debounced/once for the state transition (per a11y-plan §11 Screen Reader "no excessive ARIA noise" + §7).
- **Never convey the anomaly-first (errors-hoisted) state by color/order alone** — retain the ✗ glyph + accent border + count (per a11y-plan §11 Visual/SC 1.4.1).

## Contract bindings
- **a11y ↔ tests:** the p4/p1 axe sweeps run through the shared Playwright E2E driver (`npm run test:a11y` reuses the boot/run/status/cleanup harness); the re-poll's interval timers must not leak in-test (aligns with tests' zero-flakiness) — per a11y-plan §3 CI binding + §9.
- **a11y ↔ tests fixtures:** if the refresh changes how `viz.query.traces` is invoked, the `TauRPC__<router.path>` mock in `tests-a11y/helpers/mock-tauri.ts` + `v02-fixtures.ts` must still resolve the traces query (per a11y-plan §3 Harness wiring).
- **a11y ↔ design:** contrast pairs (`--color-text-secondary`/`--color-base`), not-color-alone state colors (`--color-accent`), and the motion reduce override bind to design-system §Color Palette + §Motion (per a11y-plan §6).
- **a11y ↔ obs:** any regressed violation emits structured violation JSON on the obs §6 schema (`wcag_criterion`/`violation_type`/`severity`) — per a11y-plan §3.
