- Per a11y-plan §5 Keyboard Navigation (settings-modal focus order), the Tab sequence must still follow visual top-to-bottom order once the MCP switch leaves. Esc must still close the modal, and focus must return to the "Settings" button. Research must check whether any focus spec hard-codes the switch's position in that sequence.
- Per a11y-plan §5 Keyboard Navigation (tray-menu), the tray menu's remaining `menuitem`s keep Arrow Up/Down navigation, Return/Space activation and Escape close after the MCP tray item is removed. §1 A11y Scope Summary (desktop-native surface row) says this is verified manually and is supplemental only.
- Per a11y-plan §3 Harness wiring & conventions (Mock layer, Adding a surface), the removed Send-to-agent spec and helpers must leave as one consistent set: no spec, fixture in `helpers/v02-fixtures.ts`, or `TauRPC__mcp.*` mock in `tests-a11y/helpers/mock-tauri.ts` may still import or point at something that is gone. Research must find which of these reference the removed hook, button or `mcp.*` procedures.
- Per a11y-plan §3 Harness wiring & conventions (Regression baseline), `pulse-app/ui/tests-a11y/baselines/a11y-violations-summary.json` must stay committed in the tree. - Per a11y-plan §10 SLO Invariants & A11y Budgets, zero WCAG AA violations on must-be-accessible paths and zero new violation tuples per PR still hold for the remaining settings-modal, compact-widget and p1–p14 surfaces.
- Per a11y-plan §9 CI Integration, the `a11y` job stays its own blocking job in `ci.yml` on `ubuntu-22.04` while the `mcp-test` job and the `mcp-server` feature leave the workflow.

## Patterns to follow
- Use the suite-health check from a11y-plan §3 Harness wiring & conventions (Adding a surface): `npx playwright test --config=playwright-a11y.config.ts --list`, with the config named. The bare command always reports 0 tests. A list-time import failure once silently disabled the whole suite, so run this check after deleting the spec and helpers.
- a11y-plan §3 Harness wiring & conventions (Adding a surface) adds a surface's axe spec in the same chunk. Read in reverse, the removed button's spec and helpers leave in the same chunk as the button. The scope already says so.
- Use the focus-trap discipline in a11y-plan §5 Keyboard Navigation (Focus trap, Focus restoration) for the slimmed settings modal: Tab wraps within the modal, Esc deactivates it, and focus returns to the trigger.
- Use the Switch pattern in a11y-plan §4 ARIA Patterns & Roles (native checkbox or Headless UI Switch, `aria-checked`, Space toggles) for any settings switch that remains. Only the MCP instance leaves.

## Anti-patterns to avoid
- Per a11y-plan §11 A11y Anti-Patterns (Strategy), do not narrow the axe-core config (`runOnly` excluding default rules) or drop rules to get the trimmed suite green without a Decisions Log entry.
- Per a11y-plan §11 A11y Anti-Patterns (SLO), do not retry a flaking a11y spec once, and do not soft-skip one, while specs and helpers are being removed. Quarantine, investigate, then fix or delete.
- Per a11y-plan §11 A11y Anti-Patterns (Keyboard), do not leave a focus-order gap or use `tabindex > 0` to patch the settings-modal sequence once the switch is gone. Natural DOM order is the rule.
