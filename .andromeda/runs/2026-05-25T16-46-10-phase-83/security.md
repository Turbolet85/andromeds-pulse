## Constraints

- **TauRPC quadruple-binding for `diagnostics.retry_interpretation()`** — per security plan §API Security row "TauRPC capability authorization" and §Anti-Patterns §API row 3, EVERY new procedure requires (a) router registration in `crates/interpretation/` or `pulse-app/src/diagnostics_router.rs`, (b) entry in `pulse-app/capabilities/` JSON, (c) `xtask/src/main.rs::EXPECTED_PROCEDURES` extension, (d) the `emit_taurpc_bindings` test in `pulse-app/src/main.rs::tests` MUST include the impl in its `.merge(...)` chain. Missing any one = silent runtime rejection (per CLAUDE.md 2026-05-12 `pulse:notification` lesson at the `pulse:default` namespace).
- **`AppError` sanitization at the `diagnostics.retry_interpretation()` boundary** — per security plan §Error Handling TauRPC bridge row + §Anti-Patterns §Logging row 4, the procedure MUST return `Result<T, AppError>` where any `InferenceError` / `JsonParseError` / backoff-related internal error converts via a `From` impl that strips stack traces, file paths, library versions, Rust struct names, and ALSO any raw LLM-emitted text (the LLM may have echoed user attribute content). Use `AppError::Internal { message: "interpretation retry rejected" }` for the user-surfaced one-liner; full chain stays in `tracing-subscriber` JSON log via `tracing-error` SpanTrace.
- **Pre-scrub at corpus persistence boundary for resolution summaries** — per security plan §Data Protection §At rest Type 5 (Persistent incident corpus) + §Anti-Patterns §Logging uniform-scrubber-coverage framing paragraph, LLM-emitted resolution summary text MUST pass through `security::scrubber::scrub_attribute` BEFORE being attached к the `incidents` corpus row (write path goes through `crates/triage/incident::IncidentPersistence::attach_resolution_summary` or equivalent). - **L6 self-observation log redaction for JSON parse failures** — per security plan §Logging & Monitoring NEVER-log list rows 1+5 + §Anti-Patterns §Logging row 1, the failure-logging path MUST NOT emit raw LLM-emitted bytes (the malformed JSON may contain attribute values echoed from the digest's spans/logs). Log structured fields ONLY: `parse_error_kind`, `tier_label`, `attempt_count`, `consecutive_failure_count`, `degraded_mode_active: bool`, `backoff_seconds_remaining`, `incident_id` (an internally-generated identifier, not OTLP `trace_id` per CLAUDE.md per-trace-id cardinality discipline if applicable). Do NOT log the raw response, the digest input, or the prompt body.
- **Three new obs metrics MUST carry bounded cardinality labels** — per security plan §Logging & Monitoring NEVER-log list row "DuckDB query parameters" (analogous reasoning) + §Anti-Patterns §Logging row 1 generalization, the 3 metrics named in chunk spec MUST NOT carry incident_id (high cardinality / direct correlation к user data) or LLM-emitted strings as labels. The "Cross-domain bindings к flag" entry below redirects detail к obs extract.
- **L4 degraded-mode + backoff state MUST NOT panic on malformed LLM response** — per security plan §Anti-Patterns §Universal row 1 generalization (Rust 2024 safe-by-default) + CLAUDE.md 2026-05-20 bincode-OOM lesson generalization, `serde_json::from_str::<L4OutputJsonSchema>(response)` failure MUST be a graceful `Result::Err` path feeding the failure counter, not an `.unwrap()` / `expect()` / `panic!()`. A panic в the L4 subscriber halts the cadence-coordinator subscriber thread (per chunk #80 cadence-coordinator + chunk #81 LWW-queue substrate); operational regression of failure-handling discipline.

- **Async-trait dyn-compat via `Pin<Box<dyn Future + Send + 'a>>` return** per CLAUDE.md 2026-05-23 async-trait entry — if the `DegradedModeStatus::trigger_retry` trait method is async, declare с manual `Pin<Box<dyn Future + Send + 'a>>` return type rather than `#[async_trait]` macro (workspace deps delta is "none" per chunk #86 detail spec — adding `async-trait` would violate). ## Anti-patterns к avoid

- **NEVER `serde_json::from_str(llm_response).unwrap()` / `.expect()`** in the L4 retry path — per security plan §Anti-Patterns §Universal row 1 (Rust 2024 safe defaults) + CLAUDE.md 2026-05-20 bincode-OOM lesson generalization. Panic in the cadence-coordinator subscriber halts the L4 path; graceful `Result` propagation feeds the failure counter.
- **NEVER log raw LLM response bytes** в parse-failure logging — per security plan §Anti-Patterns §Logging row 1 + §Logging & Monitoring NEVER-log row 1 (incidentally captured secrets). LLM response is unbounded-cardinality + may echo OTLP attribute values from the digest's source spans. Structured fields only.
- **NEVER serialize raw LLM resolution-summary text across the TauRPC bridge for the `incidents` stream** without going through `security::scrubber::scrub_attribute` first — per security plan §Anti-Patterns §Logging uniform-scrubber-coverage framing + chunk #72 corpus-persistence-boundary invariant. The `pulse://stream/incidents` consumer is the webview; scrubbing at the corpus-write boundary AND at the broadcast-emission boundary is defense-in-depth (the broadcast and the corpus row should be derived from the SAME scrubbed value).
- **NEVER add a new TauRPC procedure (`diagnostics.retry_interpretation`) к the `pulse:default` capability JSON without ALSO extending `xtask/src/main.rs::EXPECTED_PROCEDURES` + the `emit_taurpc_bindings` test merge chain** — per CLAUDE.md 2026-05-12 quadruple-binding lesson. Missing any of the 4 produces silent runtime rejection OR `cargo xtask capability-drift` CI failure.
- **NEVER widen `pulse:default` capability JSON to grant Tauri core APIs (`fs`, `shell`, `dialog`, `http`)** for the diagnostics router — per security plan §Anti-Patterns §API row 4. The retry-trigger procedure is a pure in-process state-mutation invocation; no syscall surface needed.
