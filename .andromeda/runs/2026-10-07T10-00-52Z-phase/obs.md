# obs extract

## Relevance
partial — the chunk's first half (new probe shapes, a pre-registered reproduction reading) adds no product telemetry; obs binds only where a remedy touches a record on the digest corpus-retrieval or L4 path, and where a real-model leg's log family is graded.

## Constraints
- obs-plan §8 PII Scrubbing → Default-deny posture requires every emitted field to be named on an allowlist entry for its target, else it renders redacted. A remedy that adds or widens a record on the corpus-retrieval or L4 path (for example a post-selection line count beside the pre-selection count scope.md reads at `assembler.rs:309`) must register every field it emits. §8 enumerates NO leaf for a digest-assembler corpus-retrieval target: whether the record scope.md names resolves to an exact leaf at HEAD, and which target it is emitted on, is research's question.
- obs-plan §8 PII Scrubbing → Default-deny posture (the `interpretation.incident.created` and `triage.cue.tick` entries) requires each `interpretation.*` / `triage.*` target to resolve to its OWN exact leaf, with no bare `interpretation`, `triage` or `triage.cue` prefix key; a new record on either family needs its own leaf, never a prefix key.
- obs-plan §8 PII Scrubbing → Default-deny posture (the `interpretation.incident.skipped` and `interpretation.generation.damper` entries) requires L4-path records to carry bounded labels and aggregate numerics only — never `scope_id`, title, digest content, prompt text or model text. "Which scopes the corpus block held" may therefore reach a log only as counts (for example same-scope / other-scope / fingerprint-match line counts), never as scope identities or service names.
- obs-plan §5 Metric Coverage → Metric label cardinality discipline requires label fields bounded to enumerated values; a service name or `scope_id` is client-supplied and may not become a label on any record the remedy adds.
- obs-plan §11 Obs Anti-Patterns → Logs bars `info`-level logging on a hot path; a count the remedy makes observable is folded ONCE per digest assembly (or onto an existing per-cycle record), never per corpus row inside the selection loop.
- obs-plan §10 SLO Invariants & Telemetry Budgets → Performance budgets (the L4 constrained inference row) requires gpu-primary p99 <= 10000 ms on `metric.pipeline.l4.inference_latency_p99_milliseconds`, one record per L4 generation carrying `hardware_profile` and a numeric `duration_ms`, graded by nearest rank by the dev-host script `xtask/ci/l4-latency-p99.sh` over a real-model leg's `agent-latest.jsonl*` family (not CI-wired). A remedy that lengthens the prompt (restating the scope obligation) or reshapes the corpus block moves `duration_ms`, which spans prompt assembly + generation. Whether the probe's real-model legs emit this record at all (the probe is an example binary, not the app) is research's question.
- obs-plan §6 Log Coverage → Required fields requires any new record to be one JSON line with `timestamp` / `level` / `target` / `message` / `fields`; obs-plan §2 Telemetry Strategy → Naming conventions requires its target to follow `{module}.{operation}` (or `metric.{module}.{measure}` for a metric event).

## Patterns to follow
- Leaf completeness by field-set EQUALITY in both directions, in a guard file under `pulse-app/tests/` (the `[lib] test = false` rule), plus a no-bare-prefix fallback discriminator — the shape obs-plan §8 PII Scrubbing → Default-deny posture records for `triage.cue.tick` and `interpretation.generation.damper`. A resolver-only probe (`for_target(...).is_some()`) cannot guard a narrowed leaf.
- Counters ride as tick- or cycle-aggregated FIELDS on an existing record rather than as new per-event targets — the convention obs-plan §5 Metric Coverage → Conceptual instrument types states for `triage.cue.tick` and `triage.incident.persist`.
- A state that is otherwise indistinguishable from the ordinary one gets one bounded-label record that names it — the rationale obs-plan §8 PII Scrubbing → Default-deny posture records for `interpretation.incident.skipped` (a parse-ok generation that created nothing left no record). The same reasoning applies if the remedy caps or excludes corpus lines: a capped or filtered block is otherwise indistinguishable from an unfiltered one in the log.
- The L4 latency grader fails (exit 1) on a target record missing `hardware_profile` or a numeric `duration_ms`, never drops it — obs-plan §10 SLO Invariants & Telemetry Budgets → Performance budgets (the L4 row); an empty or non-applicable sample set is stated as such, never read as PASS.

## Anti-patterns to avoid
- Logging prompt text, digest content, a corpus line's text, model output or `scope_id` to make the miss "debuggable" — barred by obs-plan §11 Obs Anti-Patterns → PII Scrubbing and by obs-plan §8 PII Scrubbing → Default-deny posture (the `interpretation.incident.skipped` entry). The probe's own reading belongs to the chunk's evidence, not to `tracing` records in `agent-latest.jsonl`.
- Emitting a per-corpus-row or per-candidate record inside selection — barred by obs-plan §11 Obs Anti-Patterns → Logs (hot path) and obs-plan §11 Obs Anti-Patterns → Telemetry Strategy (over-instrumenting tight loops).
- Folding the open `interpretation.constrained.generate` redaction repair into this chunk because a real-model leg shows its `<redacted>` fields — obs-plan §8 PII Scrubbing → Default-deny posture (the muted-diagnostic backlog bullet) pins that recurrence on its own working-route entry ("L4 generation records render unredacted"); a leg here that shows `raw_output_bytes` / `extracted_bytes` redacted is the known open state, not this chunk's finding.
