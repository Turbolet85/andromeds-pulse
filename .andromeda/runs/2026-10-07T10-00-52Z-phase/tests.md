## Constraints
- A real-model generation is never a gate: test-plan §1 Pending coverage triggers (row `l4-decision-probe-arg-parse-unit-coverage`) classes the probe as dev-only and its real-model generations as unable to give a deterministic verdict. The pre-registered reproduction reading and the remedy reading are therefore evidence of record, never members of the plan's `## Test Commands`; what gates the chunk is the deterministic pin set around them.
- test-plan §2 Test Strategy (Agent-runnable invariants) requires every verdict to come from an exit code plus structured output, with no human-in-the-loop verification. The operator's go before a launch is a launch permission, not a verification step; the reading itself must be graded by the probe's closed-label grader, never by a person reading model text.
- test-plan §1 Pending coverage triggers (row `l4-decision-probe-arg-parse-unit-coverage`) holds the probe's pin ledger: shape ids, shape renders, arm composition, the closed `identifies` label set, the bar flags and their fold over shape halves, the selection order, the regression guard. New shapes and any new flag or arm owe pins of the same per-branch class, and must not widen that row's STILL OWED list. Which of those pins a new shape moves (the shape-set bound pin, the bar fold's half assignment) is research's question.
- test-plan §1 Pending coverage triggers (row `inject-demo-arg-parse-unit-coverage`, its correction note) requires an `[[example]]` target to declare `test = true` for nextest to collect its tests. Whether the probe's manifest entry already carries it, and whether a new `#[path]`-wired module would be collected in the same binary, is research's question.
- test-plan §4 Unit Test Strategy (What unit tests cover — triage crate) requires digest render properties to be pinned in-crate, mutation-checked, with the clock injected as an explicit parameter. A remedy that caps, reorders or scope-filters the corpus block owes pins in that form; recency ordering is asserted over injected timestamps. The plan names render pins only — it names no pin over the corpus selection itself, so whether one exists at HEAD is research's question.
- test-plan §4 Unit Test Strategy (What unit tests cover — interpretation crate) requires prompt-instruction text to be pinned exactly once in every tier's composed prompt, the version lineage to be asserted through the `PROMPT_VERSION_*` consts without literal duplication, and template ASCII-cleanliness to stay pinned. A remedy that restates the scope obligation owes all three.
- test-plan §3 Per-chunk gate discipline requires the standard gate set unconditionally, with the webview gates dropped only when no `pulse-app/ui/**` path is touched, and the bindings close for a chunk adding no procedure. Its Boot-smoke gate (conditional) binds only if the plan touches a listed boot/setup path; whether any remedy candidate does is research's question.

## Patterns to follow
- Asymmetric pin pairs with a recorded mutation check: each new pin is paired so that only one side reds under the named mutation, and a pin that holds on a tree lacking the feature is counted only as the negative half of its pair (per test-plan §4 Unit Test Strategy — triage crate; test-plan §1 Pending coverage triggers row `l4-decision-probe-arg-parse-unit-coverage`).
- Probe logic is tested through pure fns and the `parse_args_from` seam, never by launching a model; a shape's render is pinned against its control so the difference is the intended block alone (per test-plan §1 Pending coverage triggers row `l4-decision-probe-arg-parse-unit-coverage`).
- An unmet precondition reads INCONCLUSIVE, never PASS — the form the probe's bar flags and every scenario leg carry. A reproduction whose baseline passes everywhere needs its own non-pass reading in that family (per test-plan §1 Pending coverage triggers row `l4-decision-probe-arg-parse-unit-coverage`; test-plan §3 Per-chunk gate discipline). Whether the existing bar machinery can express "the baseline arm fails" as the expected reading is research's question.
- Narrow a `pulse-app` selection with `-E` under `--workspace`, not `-p`, so the run's scope matches the build's (per test-plan §3 `run`).
- Library-crate tests sit co-located in `src/`; `pulse-app` unit probes sit in `pulse-app/tests/*.rs` or the example binary, never in `pulse-app/src/` (per test-plan §2 Test Strategy — Test directory + naming conventions).

## Anti-patterns to avoid
- No captured or production telemetry in tests: probe shapes are synthetic, built at runtime by Rust builders (per test-plan §11 Test Anti-Patterns — Test Data). This is the test-side half of the scope's no-recovered-payload boundary.
- No model text or secret-shaped content in test output or stored run rows: closed labels only (per test-plan §11 Test Anti-Patterns — Universal; test-plan §1 Pending coverage triggers row `l4-decision-probe-arg-parse-unit-coverage`).
- No retry, no `#[ignore]`, no manual smoke step standing in for a gate: a stochastic real-model result is not wrapped into a nextest test to make it "pass" (per test-plan §11 Test Anti-Patterns — Quality; test-plan §10 Quality Gates & Coverage Targets — Zero-flakiness budget).

## Contract bindings
- tests ↔ security: the ASCII pin over composed prompt templates (test-plan §4 Unit Test Strategy — interpretation crate) and the CI English-only source gate (test-plan §9 CI Integration — `lint-test` job) both bind any new prompt or probe text to the argv-transport rule security owns.
- tests ↔ obs: `cargo xtask check:ingest-progress` in the standard gate set reads NEUTRAL for a chunk that boots nothing, keyed on obs-plan's stall definition (test-plan §3 Per-chunk gate discipline). The probe is not the 5-command harness; whether it boots the product or binds a port is research's question.
- tests ↔ arch: the Fault Identity decision (the retrieval's fingerprint arm stays fed; the `TRIGGER:` line carries the kind label only) has render-side pins in test-plan §4 Unit Test Strategy — triage crate; a scope-arm remedy must leave them green.

## Acceptance criteria contributions
- The standard gate set is green, `cargo nextest run --workspace --profile ci` collects the new probe pins in the example binary, and workspace coverage stays at or above the Standard thresholds (per test-plan §3 Per-chunk gate discipline; test-plan §10 Quality Gates & Coverage Targets)
- Every new probe shape carries deterministic pins — its id parses and an unknown id is refused, its render differs from its control in the corpus block only, it composes within the production prompt bound — with at least one mutation check recorded per new discriminating pin (per test-plan §1 Pending coverage triggers row `l4-decision-probe-arg-parse-unit-coverage`)
- The remedy's product change is pinned in its owning crate: a prompt-text remedy exactly once in every tier with the ASCII pin and the version consts green; a corpus-block remedy by in-crate render pins over injected timestamps (per test-plan §4 Unit Test Strategy — What unit tests cover)
- No real-model reading appears as a gate: both pre-registered readings are graded by closed labels through the probe's exit contract, a baseline that passes everywhere is recorded as a non-pass finding, and stored run rows hold no model text (per test-plan §1 Pending coverage triggers row `l4-decision-probe-arg-parse-unit-coverage`; test-plan §2 Test Strategy — Agent-runnable invariants)
