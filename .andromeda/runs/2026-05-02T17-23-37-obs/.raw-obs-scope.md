## 3. Observability Harness Specification

- **OTel SDK init:** `opentelemetry` crate (Rust stable) with `opentelemetry-stdout` exporter (only exporter for self-observation per arch excerpt Section 1 Observability Hints: "opentelemetry-stdout (or file exporter) is the only exporter the product itself uses"; security plan Section 2 calls this "never dial own OTLP ports"). Initialization order: (1) Load config + validate log level (`ANDROMEDA_PULSE_LOG_LEVEL` or fallback `RUST_LOG`), (2) init `tracing` subscriber with JSON formatter, (3) init OTel SDK with stdout exporter targeting `~/.andromeda-pulse/logs/`, (4) spawn Tauri app. Boot-time initialization before HTTP/gRPC server bind.

- **Service identity:** `service.name` = `com.andromeda.pulse` (compile-time: Tauri bundle identifier, arch excerpt Section 1); `service.version` = from `tauri.conf.json` (runtime) or `Cargo.toml` (compile-time `env!("CARGO_PKG_VERSION")` for CLI binary); `deployment.environment` = `production` (hardcoded for desktop app; no staging/dev distinction at runtime).

- **Logging stack:** `tracing` 0.1.x + `tracing-subscriber` JSON formatter; dual sink: (1) stderr pretty-printed (human-readable on terminal), (2) file sink to `~/.andromeda-pulse/logs/agent-latest.jsonl` (agent-mode JSON-only, no colors).     "span_count": 10,

- **Log file location:** `~/.andromeda-pulse/logs/agent-latest.jsonl` (arch excerpt Obs-Relevant Conventions: log file location pattern); configurable via `ANDROMEDA_PULSE_DATA_DIR` override (per-platform: `%APPDATA%\Andromeda Pulse\logs\` on Windows; `~/Library/Application Support/com.andromeda.pulse/logs/` on macOS; `~/.local/share/com.andromeda.pulse/logs/` on Linux); agent paste-to-AI workflow reads this file for debugging.

- **Snapshot / paste-to-AI integration:** Andromeda Pulse IS the OTLP receiver (self-observing product). Snapshot generation pipeline (creator brief Section 6: "Snapshot generation pipeline: (1) Time window selection... (5) Token budget") produces curated markdown snapshots saved to `~/.andromeda-pulse/snapshots/{timestamp}.md` with token count enforced (≤ 10k / ≤ 25k / ≤ 50k presets per creator brief). Snapshot payload contains deduped spans, anomaly markers (e.g., "⚠ latency spike", "🔴 error cluster"), aggregated metrics (p50/p95/p99/max), and critical path extraction — NOT raw OTLP JSON dump (tests excerpt P2: "response.markdown contains anomaly markers... response.dedup_count shows reductions"). MCP server query tools (`query_traces`, `query_metrics`, `query_logs`, `generate_snapshot`) emit JSON responses with no raw OTLP attribute logging (security plan vector 4: "MCP tool response bodies must NEVER be logged"). Snapshot file writes require non-suppressible clipboard-write toast event (security plan anti-pattern: "Snapshot file contents logged or unguarded").

- **Trace context propagation:** W3C `traceparent` header (HTTP) and gRPC metadata (`grpc-trace-bin`), arch excerpt Section 1 Standard Contracts. IPC envelope adds optional `traceparent` field for Tauri TauRPC commands (per Standard Contracts: "`POST /v1/traces` — trace context must propagate via W3C traceparent in request headers"; "`gRPC TraceService` — gRPC metadata carries trace context (grpc-trace-bin header)`"). Every TauRPC router handler extracts traceparent from envelope and initializes a span with matching trace_id / parent_span_id (maintains end-to-end correlation across app boundary + IPC boundary). Real-time push streams (arch excerpt Section 1: "`pulse://stream/spans`, `pulse://stream/metrics`, `pulse://stream/logs`") emit binary Arrow IPC payloads with Arrow metadata column reserved for traceparent (no JSON stringify; Arrow schema includes `_trace_context` field for trace_id + parent_span_id).

- **Heartbeat ticks:** Long-running tasks emit heartbeat metrics every 10–30 seconds: `ingest.tick` (with `span_count`, `buffer_capacity_pct`, `broadcast_subscribers` fields), `buffer.tick` (with `rows_ingested`, `retention_window_active`, `eviction_count`), `viz.tick` (with `query_latency_ms`, `subscribers_active`), `plugins.tick` (with `loaded_count`, `active_invocations`). Heartbeat spans integrate with `health` IPC command contract (arch excerpt Section 1 Standard Contracts: "`health` command returns liveness state of subsystems... `ready` command returns readiness state with checks..."). Heartbeats enable agent diagnostics for long-running buffer fill-and-drain cycles.

## 6. Observability Tier

**Tier: Standard (1)**

**Justification:**

Andromeda Pulse is a cross-platform desktop application (Windows/macOS/Linux via Tauri 2) with 8 instrumentable modules (ingest, buffer, viz, ui-bridge, snapshot, workspace-detector, plugins, mcp-server), 8 major surfaces (desktop-webview, desktop-native, IPC-internal, API service gRPC, API service HTTP, CLI, library-only plugin host, MCP stdio), and 7 critical user-facing must-trace paths (receive-and-visualize OTLP, generate curated snapshots, MCP tool queries, plugin lifecycle, UI layout transitions, real-time push via Arrow IPC, workspace detection). Security tier is Minimal (loopback-only binding, no user accounts, in-memory data, no compliance). Tests tier is Standard (span coverage across 19 testable entities, 7 critical paths, explicit rejection of 28+ attack vectors, explicit agent-driven discipline with deterministic test signals). Observability matches tests tier (Standard) because: (1) multi-surface coordination requires cross-surface trace propagation (W3C traceparent + IPC envelope + Arrow metadata), (2) creator brief explicitly asks for token-efficient snapshot guarantees (perf-budget-instruments trigger), (3) real-time push via binary Arrow IPC requires frontend instrumentation (browser OTel SDK + web-vitals + WebGPU render metrics), (4) security plan specifies 6 logging-sensitive vectors driving scrubbing rules + baseline anti-patterns (DuckDB SQL injection, plugin path validation, MCP double-gate), (5) self-observing product constraint (stdout-only exporter; network OTLP loopback banned) requires explicit recursion-guard architecture in obs harness. Standard tier provides network OTLP loopback (`:4318`/`:4317`), structured JSON logging (file + stdout dual sink), auto-instrumentation for HTTP/gRPC frameworks, heartbeat ticks for long-running tasks, and creator-explicit-telemetry triggers (realtime counters for animation, aggregation metrics for heatmap/sparkline).
