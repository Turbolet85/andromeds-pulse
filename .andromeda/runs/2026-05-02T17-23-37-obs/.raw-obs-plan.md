## 2. Telemetry Strategy

**Telemetry signal pyramid (per tier):**

| Signal | Coverage focus | Tier-specific depth |
|--------|---------------|---------------------|
| Spans / Traces | Critical paths (P1-P7) + module boundaries (ingest, buffer, viz, plugins, snapshot) | Standard: all 7 must-trace paths covered; per-surface auto-instrumentation for HTTP/gRPC; manual spans for IPC boundaries |
| Structured Logs | Boundary calls + state transitions + errors | Standard: JSON-per-line with `trace_id`/`span_id`; logging-sensitive vectors (Sec 5) apply scrubbing rules; heartbeat ticks emit info-level events |
| Errors | Captured panics + module-boundary errors | Standard: panic hook + tracing::error; optional sentry-rust 0.46.0 (opt-in via `ANDROMEDA_PULSE_SENTRY_DSN`, default off); SpanTrace integration (tracing-error 0.2.1) for sanitized error chains |
| Metrics | Counters / histograms / gauges per critical path | Standard: perf-budget histograms (snapshot.token_count_ms, webgpu.canvas.frame_duration_ms, buffer.memory_bytes); counters (ingest.throughput_events_per_sec, buffer.evicted_span_count); gauges (ingest.channel.broadcast_subscribers); opentelemetry_sdk 0.31.0 Meter + custom tokio interval ticks |
| Audit Logs | Compliance trail for privileged ops | N/A — security_tier=Minimal, no compliance triggers |

**Agent-readable invariants (apply across all signals):**
- Every signal produces machine-parseable output (OTLP-native JSON for spans/metrics; JSON-per-line for logs; structured error reports with tracing-error)
- No human-only dashboards, no Grafana / Kibana / Datadog UI as sole consumption
- No proprietary APM SDKs as primary exporter (Sentry is opt-in, not default)
- No human-review-gated log analysis ("ops team reviews daily")
- Every panic captured with structured SpanTrace (via tracing-error, no full Rust struct names)
- Every cross-surface call propagates trace context (W3C traceparent via tonic-tracing-opentelemetry 0.32.3 / axum-tracing-opentelemetry 0.32.3; IPC envelope via manual span initialization)

**Naming conventions:**
- **Span naming:** `{module}.{operation}` pattern (e.g., `ingest.grpc.export.request`, `duckdb.append`, `plugin.invoke.request`, `snapshot.generate.request`)
- **Metric naming:** OpenTelemetry semantic conventions (e.g., `snapshot.token_count_ms`, `buffer.ingest_throughput_spans_per_sec`, `webgpu.canvas.frame_duration_ms`, `trace.latency_percentiles`)
- **Log fields:** structured JSON with required fields per Section 6 (timestamp, level, target, message, fields with trace_id/span_id)
- **Resource attributes:** `service.name` (`com.andromeda.pulse`), `service.version` (from Cargo.toml / tauri.conf.json), `deployment.environment` (`production`)

## 3. Observability Harness Contract

Architecture committed to the harness pattern (verbatim from upstream-context Architecture Excerpt's Observability Hints): "`opentelemetry-stdout` (or file exporter) is the only exporter the product itself uses for its own telemetry; the OTLP network exporter is never pointed at the product's own `:4317`/`:4318` ports."

### OTel SDK init

- **SDK packages:** `opentelemetry` 0.31.0 + `opentelemetry_sdk` 0.31.0 (Rust stable, MSRV 1.75, comfortably satisfies arch rustc 1.84+ floor); `opentelemetry-stdout` 0.31.0 (primary exporter for self-observation); `tracing-opentelemetry` 0.32.0 (bridge macros to OTel SpanData)
- **Init order:** Before Tauri app spawn; before HTTP/gRPC server bind. Sequence: (1) Load env vars + config → validate log level, (2) Init tracing subscriber with JSON formatter + file sink, (3) Init OTel SDK with stdout exporter, (4) Guard against self-OTLP loopback (validate `ANDROMEDA_OBSERVER_URL` env var), (5) Spawn Tauri app + bind receivers
- **Init body sketch (≤ 5 lines):**
```rust
let _guard = init_tracing_opentelemetry::tracing_init()?; // Composes registry + fmt JSON + OtelLayer + file writer
let provider = TracerProviderBuilder::default()
  .with_simple_exporter(opentelemetry_stdout::SpanExporter::builder().with_writer(file_handle).build())
  .build();
validate_no_self_otlp_loopback(&env::var("ANDROMEDA_OBSERVER_URL").unwrap_or_default())?;
```

### Service identity

- **service.name:** compile-time constant `"com.andromeda.pulse"` (Tauri bundle identifier; fallback env!("CARGO_PKG_NAME") = "pulse-app"); for mcp-server sidecar: `"andromeda-pulse-mcp"` (distinct process identity per arch convention)
- **service.version:** runtime read from `tauri.conf.json` version field OR compile-time `env!("CARGO_PKG_VERSION")` for CLI binary
- **deployment.environment:** hardcoded `"production"` (desktop app, no staging/dev distinction at runtime)
- **Resource attributes:** initialized at SDK init via `Resource::builder().with_service_name("com.andromeda.pulse").with_service_version(env!("CARGO_PKG_VERSION")).with_attribute(KeyValue::new("service.bundle_id", "com.andromeda.pulse")).with_deployment_environment("production").build()` (opentelemetry_sdk 0.31.0 Resource API)

### Logging stack

- **Library:** `tracing` 0.1.41 (macro-driven instrumentation; `#[instrument]` attribute on router methods) + `tracing-subscriber` 0.3.20 (JSON formatter + sink composition) + `tracing-appender` 0.2.3 (rolling file sink) + `tracing-error` 0.2.1 (SpanTrace for sanitized error chains)
- **Format:** structured JSON-per-line matching binding contract (Section 6 log format JSON schema); agent-readable, machine-parseable
- **Sink:** Dual sink for app: (1) stderr pretty-printed (human dev terminal), (2) file `~/.andromeda-pulse/logs/agent-latest.jsonl` JSON-only (agent paste-to-AI). MCP stdio surface: stderr-only (prevent stdout JSON-RPC corruption via rmcp 0.6.0)
- **Agent-mode flag:** Automatic based on sink configuration. File sink is always JSON (agent-ready); stderr formatter can toggle between pretty (dev) and JSON (agent-mode) via `ANDROMEDA_PULSE_JSON_LOG_ONLY=true` env var (or detect via absence of TTY)

### Log format JSON schema

Verbatim from upstream-context Section 5 Test Plan Excerpt → Test Harness Contract Summary (binding contract):
```json
{
  "timestamp": "2026-05-02T16:18:34.567Z",
  "level": "INFO",
  "target": "ingest::grpc",
  "message": "TraceService.Export received 10 spans",
  "fields": {
    "span_count": 10,
    "service": "my-app"
  }
}
```

Extensions (optional fields per Section 5 telemetry triggers):
- `trace_id` (W3C 32 hex chars, via opentelemetry-appender-tracing 0.31.1 auto-attachment)
- `span_id` (W3C 16 hex chars)
- Per-trigger fields: `duration_ms`, `plugin_path_basename`, `query_id`, `param_count`, `token_count_actual`, `token_budget_limit`, `body_size_bytes`, `webview_backend`, `tray_api`, `dedup_count`, `anomaly_markers`, `latency_p50_ms`, `latency_p95_ms`, `latency_p99_ms`, `error_rate_percent`, etc.

### Log file location

- **Path:** `~/.andromeda-pulse/logs/agent-latest.jsonl` (default); configurable via `ANDROMEDA_PULSE_DATA_DIR` override: `%APPDATA%\Andromeda Pulse\logs\` (Windows), `~/Library/Application Support/com.andromeda.pulse/logs/` (macOS), `~/.local/share/com.andromeda.pulse/logs/` (Linux) per arch Obs-Relevant Conventions
- **Rotation:** Daily rotation via `tracing-appender::rolling::daily(...)`; previous day's file read by agent if current not yet created

### Snapshot / paste-to-AI integration

**Snapshot path:** `~/.andromeda-pulse/snapshots/{timestamp}.md` (curated markdown, not raw OTLP JSON); timestamp format `YYYY-MM-DDTHH:MM:SSZ`

**Snapshot schema:** Curated markdown with:
- Header: `## Snapshot from {time_range_start} to {time_range_end}`
- Metadata: `token_count: {N}`, `dedup_count: {reductions}`, `service_filter: {filter}`, `anomaly_markers: [...]` (e.g., "⚠ latency spike", "🔴 error cluster")
- Aggregation: Metrics (p50/p95/p99/max per service), top-slow-spans (critical path), trace IDs (for manual drill-down)
- Deduping: Identical span trees counted once, emission count tracked
- NOT raw OTLP JSON dump (per tests excerpt P2 and creator brief Section 6)

**Trigger:** TauRPC `snapshot.generate({time_range: [start, end], token_budget: 10000 | 25000 | 50000})` command from webview; span `session.snapshot` wraps entire pipeline; child spans emit token budget telemetry (Section 5 perf-budget-instruments trigger); snapshot file write emits non-suppressible toast event (per security plan anti-pattern)

**MCP tools:** `query_traces`, `query_metrics`, `query_logs` (via rmcp 0.6.0 JSON-RPC 2.0 interface); `generate_snapshot` (same curation pipeline, JSON output format); tool method spans emit `mcp.tools.call.request` (parent) → `duckdb.query.{traces|metrics|logs}` (child) → `mcp.tools.call.response` (emit result metadata only, NOT result_content, per security plan vector 4)

### Trace context propagation

- **HTTP boundaries:** W3C `traceparent` header auto-instrumented via `axum-tracing-opentelemetry` 0.32.3 middleware on `axum` 0.8.x server `:4318` OTLP/HTTP receiver; span extraction + child span creation automatic
- **gRPC boundaries:** gRPC metadata (`grpc-trace-bin` header) auto-instrumented via `tonic-tracing-opentelemetry` 0.32.3 on `tonic` 0.14.x server `:4317` OTLP/gRPC receiver; trace context propagation per W3C convention + gRPC spec
- **IPC boundaries:** TauRPC router handlers manually extract `traceparent` field from IPC envelope (opt-in field added to command struct per Standard Contracts); initialize child span with matching trace_id + parent_span_id via `tracing::Span::current()` pattern
- **Internal async boundaries:** tokio spawn + task scheduling: use `tracing::Span::current().in_current_span()` extension trait (via tracing-opentelemetry bridge) to propagate span context into spawned tasks

### Heartbeat ticks

- **Tick interval:** 15s for long-running subsystems (ingest, buffer, viz, plugins) via `tokio::time::interval(Duration::from_secs(15))`; 100ms for realtime throughput counter (separate high-frequency ticker for animation smoothness per creator brief)
- **Tick event format:** `tracing::info!(target: "ingest.tick", span_count=N, buffer_capacity_pct=M, broadcast_subscribers=X, "heartbeat")` + OTel gauge/counter metric per meter
- **Stall detection:** Agent reads recent ticks via CLI `logs` command or log file tail; missing tick = stall signal (no tick for >45s = unhealthy); `health` IPC command returns `uptime_ms` + subsystem liveness state

## 4. Span / Trace Coverage

**Span naming convention:** `{module}.{operation}` (e.g., `ingest.grpc.export.request`, `duckdb.append`, `snapshot.generate.request`, `plugin.invoke.request`). Avoid high-cardinality span names (no per-user-ID names, no per-trace-ID names).

**Span kinds:**
- `SpanKind::SERVER` — inbound handlers: `ingest.grpc.export.request` (gRPC), `ingest.http.export.request` (HTTP POST), TauRPC command handlers, MCP tool invocations
- `SpanKind::INTERNAL` — internal operations: `duckdb.append`, `snapshot.generate.request`, `plugin.invoke.request`, `buffer.tick`, `workspace.detect`
- `SpanKind::CLIENT` — not heavily used (app is receiver, not client); may appear for query/invoke spans if modeled as request-response

**Auto-instrumentation per surface:**

| Surface | Auto-instrumentation library | Manual instrumentation | Notes |
|---------|------------------------------|------------------------|-------|
| API service gRPC `:4317` | `tonic-tracing-opentelemetry` 0.32.3 (`OtelGrpcLayer` interceptor) | gRPC-specific spans inherit via header extraction; OTLP payload span_count attribute | Grpc metadata carries W3C traceparent; baseline gRPC server instrumentation per tonic 0.14.x integration |
| API service HTTP `:4318` | `axum-tracing-opentelemetry` 0.32.3 (`OtelAxumLayer` middleware) | HTTP request/response span wrapping; body-size validation spans (DefaultBodyLimit) | HTTP headers carry W3C traceparent; baseline HTTP server instrumentation per axum 0.8.x integration |
| IPC-internal (TauRPC) | N/A — manual via `tracing::instrument` macro | Each TauRPC router method: extract envelope traceparent → initialize span with matching trace_id; span wraps entire command execution | `#[tracing::instrument(skip_all, fields(traceparent = %tp))]` on router methods; child spans inherit context |
| Desktop-webview (React 19) | `@opentelemetry/auto-instrumentations-web` 0.61.0 (fetch/XHR auto-tracing) + `web-vitals` 5.1.0 (LCP/CLS/INP metrics) | Custom spans for component lifecycle, skeleton pulse duration, empty/error state counters | WebGPU canvas frame-time instrumentation via custom JavaScript (DOM performance.now() + WebGPU timestamp-query) |

**Must-trace path scenarios:**

#### Scenario: P1 — Receive OTLP telemetry (gRPC), visualize in WebGPU dashboard

- **Surfaces involved:** API service (gRPC `:4317`), buffer (DuckDB), viz (query layer), desktop-webview (WebGPU canvas), IPC-internal (TauRPC)
- **Must-trace spans:** `otlp.grpc.export.request` (gRPC handler entry) → `duckdb.append` (appender write latency) → `tauri.channel.emit` (emit to `pulse://stream/spans` Arrow IPC) → TauRPC `traces.query` (user invokes query) → `viz.query.traces` (query execution) → `webgpu.canvas.render` (WebGPU frame render)
- **Required span attributes:** `otlp.grpc.export.request`: `span_count` (from gRPC RPC payload), `service` (from span attributes, scrubbed per vector 1), `trace_ids` (list of trace IDs in batch); `duckdb.append`: `duration_ms`, `rows_appended`; `viz.query.traces`: `query_id`, `param_count`, `time_window_seconds`; `webgpu.canvas.render`: `render.frame_ms`, `render.fps`
- **Required log fields:** `trace_id`, `span_id`, `span_count`, `service`, `buffer.rows_ingested`, `render.frame_ms`, `render.fps`
- **Cleanup:** gRPC handler auto-ends span; append operation completes span; query spans end on result return; canvas frame span ends post-render

#### Scenario: P2 — Generate token-efficient curated snapshot

- **Surfaces involved:** Desktop-webview (TauRPC invocation), buffer (DuckDB queries), snapshot (markdown generator), IPC-internal
- **Must-trace spans:** TauRPC `snapshot.generate({time_range, token_budget})` (entry, parent `session.snapshot`) → `duckdb.query.aggregation` (aggregate metrics + dedup) → `snapshot.render.markdown` (markdown generation) → `snapshot.token.count.validate` (enforce budget limit)
- **Required span attributes:** `snapshot.generate.request`: `token_budget` (10k/25k/50k), `time_range_start`, `time_range_end`, `service_filter`; `duckdb.query.aggregation`: `query_id`, `dedup_count`, `output_row_count`; `snapshot.render.markdown`: `markdown_size_bytes`, `section_count`; `snapshot.token.count.validate`: `token_count_actual`, `token_budget_limit`, `budget_exceeded`
- **Required log fields:** `trace_id`, `token_budget`, `token_count_actual`, `dedup_count`, `anomaly_markers` (array), `time_range_start`, `time_range_end`, `service_filter`
- **Cleanup:** TauRPC command spans end post-response; async markdown generation task awaits completion before snapshot file write

#### Scenario: P3 — MCP server query (JSON-RPC 2.0 tool call)

- **Surfaces involved:** CLI (rmcp stdio), IPC-internal, buffer (DuckDB)
- **Must-trace spans:** `mcp.tools.call.request` (JSON-RPC 2.0 stdin method parse) → `mcp.feature.gate.check` (compile-time + runtime gate validation) → `duckdb.query.traces` / `.metrics` / `.logs` (per tool method) → `mcp.tools.call.response` (emit JSON result to stdout)
- **Required span attributes:** `mcp.tools.call.request`: `method` (query_traces / query_metrics / query_logs / generate_snapshot), `params_count`; `mcp.feature.gate.check`: `feature_flag_enabled`, `env_var_mcp_enabled`; `duckdb.query.*`: `query_id`, `param_count`, `time_range_start`, `time_range_end`, `service_filter`; `mcp.tools.call.response`: `result_type` (not `result_content`), `result_count`
- **Required log fields:** `trace_id`, `method`, `time_range_start`, `time_range_end`, `service_filter`, `result.count`, `feature_flag_enabled`, `env_var_mcp_enabled`
- **Cleanup:** rmcp auto-closes JSON-RPC stream; spans end after stdout result sent

#### Scenario: P4 — Plugin lifecycle (load, invoke, unload)

- **Surfaces involved:** IPC-internal (TauRPC), library-only (plugin host, wasmtime)
- **Must-trace spans:** TauRPC `plugins.reload` (entry) → `plugin.load.request` (load WASM file) → `wasmtime.instantiate` (module instantiation) → TauRPC `plugins.invoke({plugin, capability, input})` (invocation command) → `plugin.capability.check` (capability gating) → `plugin.invoke.request` (execute capability, or `plugin.invoke.error` on rejection)
- **Required span attributes:** `plugin.load.request`: `plugin_path_basename` (not full path), `wasm_size_bytes`, `duration_ms`; `wasmtime.instantiate`: `module_name`, `export_count`; `plugin.capability.check`: `capability_name`, `capability_allowed`, `error_msg` (if rejected); `plugin.invoke.request`: `plugin_name`, `capability_name`, `input_schema` (Arrow column names), `output_schema`, `duration_ms`
- **Required log fields:** `trace_id`, `plugin_name`, `plugin_path_basename`, `capability_name`, `capability_allowed`, `error_msg`, `duration_ms`, `wasm_size_bytes`
- **Cleanup:** plugin.load span ends after instantiation; capability.check span ends on allow/deny decision; invoke spans end post-execution; errors logged at WARN/ERROR level

#### Scenario: P5 — Widget compact mode ↔ dashboard expansion ↔ tray icon visibility toggle

- **Surfaces involved:** Desktop-webview (TauRPC layout command), desktop-native (tray icon), IPC-internal

## 6. Log Coverage

**Log format JSON schema:** Verbatim from upstream-context Section 5 Test Plan Excerpt → Test Harness Contract Summary (binding contract):
```json
{
  "timestamp": "2026-05-02T16:18:34.567Z",
  "level": "INFO",
  "target": "ingest::grpc",
  "message": "TraceService.Export received 10 spans",
  "fields": {
    "span_count": 10,
    "service": "my-app"
  }
}
```

**Required fields (every log line):**
- `timestamp` (ISO 8601 format: `YYYY-MM-DDTHH:MM:SS.fffZ`)
- `level` (debug / info / warn / error)
- `target` (module path, e.g., `ingest::grpc`, `buffer::appender`, `plugin::host`)
- `message` (human-readable summary, <200 chars)
- `fields` (map of structured attributes — always present, may be empty `{}`)
  - `trace_id` (optional, W3C 32 hex chars; attached by opentelemetry-appender-tracing 0.31.1)
  - `span_id` (optional, W3C 16 hex chars)
  - Per-trigger fields per Section 5 (span_count, service, duration_ms, token_count_actual, etc.)

**Log levels mapping:**

| Level | Use case | Example |
|-------|----------|---------|
| `error` | Module-boundary errors + captured panics + unrecoverable failures | `error!(target: "app.panic.fatal", "panic")`, `error!(target: "ingest.grpc.parse.error", ...)` on malformed OTLP |
| `warn` | Recoverable errors + degraded performance + retry-able | `warn!(target: "config.load.path_validation", "path canonicalization rejected")` on CWE-22 violation; `warn!(target: "mcp.gate.check", "MCP enabled but feature flag absent")` |
| `info` | Boundary call summaries + state transitions + heartbeat ticks | `info!(target: "ingest.grpc", "export received N spans")`, `info!(target: "ingest.tick", "heartbeat")` |
| `debug` | Internal control flow detail (gated by `ANDROMEDA_PULSE_LOG_LEVEL=debug` or `RUST_LOG=debug`) | `debug!(target: "buffer.append", "writing to ring buffer")` |
| `trace` | Span events + per-record processing detail (gated by `ANDROMEDA_PULSE_LOG_LEVEL=trace` or `RUST_LOG=trace`) | `trace!(target: "arrow.ipc.decode", "column {:?} validated")` — log at entry only if unhidden by flag |

**Per-module log levels:**

| Module | Recommended level | Reason |
|--------|------------------|--------|
| `ingest` (gRPC + HTTP receivers) | `info` (boundary calls) / `debug` (parsing detail) | Baseline info on export RPC received; debug on protobuf field extraction |
| `buffer` (DuckDB + appender) | `info` (append operations) / `debug` (row-level ops) | Baseline info on append completion; debug per-row processing |
| `viz` (query layer) | `info` (query execution) / `debug` (aggregation detail) | Baseline info on query start/end; debug on metric bucket assembly |
| `snapshot` (markdown generator) | `info` (generation summary) / `debug` (curation pipeline) | Baseline info on snapshot completion + token count; debug on dedup/anomaly detection |
| `plugins` (host) | `info` (load/invoke summary) / `debug` (capability checks) | Baseline info on plugin load/invoke; debug on per-capability gate |
| `workspace-detector` | `info` (detection summary) / `debug` (scan detail) | Baseline info on workspace root + project name; debug on .git/ traversal |
| `ui-bridge` (TauRPC) | `info` (command invocations) / `debug` (IPC detail) | Baseline info on TauRPC method call; debug on envelope parse |
| `mcp-server` (rmcp) | `info` (tool calls) / `debug` (JSON-RPC detail) | Baseline info on tool method invocation; debug on request parse |

**Sink configuration** (from Section 3):
- App (Tauri + receivers): stderr pretty-printed (human dev) + file JSON-only (`~/.andromeda-pulse/logs/agent-latest.jsonl`)
- MCP server (rmcp stdio): stderr JSON-only (prevent stdout JSON-RPC corruption) — NO pretty-print (binary protocol overhead)
- File rotation: daily rotation via `tracing-appender::rolling::daily(...)`

**Boundary-call wrappers (must-log events):**

| Boundary | Must-log fields | Example span |
|----------|-----------------|--------------|
| gRPC RPC entry/exit | `method`, `status`, `span_count` (from request), `latency_ms` | `otlp.grpc.export.request` |
| HTTP POST entry/exit | `route`, `status_code`, `body_size_bytes`, `latency_ms` | `ingest.http.export.request` |
| DuckDB query | `query_id`, `param_count`, `row_count_returned`, `duration_ms` (NOT query text per vector 5) | `duckdb.query.aggregation` |
| TauRPC invocation | `method_name`, `argument_digest` (hash, not content), `result_type`, `latency_ms` | TauRPC router method span |
| Plugin invocation | `plugin_name`, `capability_name`, `duration_ms` | `plugin.invoke.request` |
| Snapshot generation | `token_budget`, `token_count_actual`, `dedup_count`, `time_range_minutes` | `snapshot.generate.request` |

## 7. Error Capture & Reporting

**Platform pick:** `sentry-rust` 0.46.0 + `sentry-tauri` 0.5.0 (community-recommended Tauri 2 integration); optional / opt-in only. Default fallback: in-app panic hook + `tracing::error!()` (no external service required for Standard tier).

**Default state:** opt-in (default OFF). Enable via `ANDROMEDA_PULSE_SENTRY_DSN` env var (DSN string) or Settings UI toggle. Empty DSN / env var unset = SDK no-op. Default-off respects privacy-conscious users (per creator brief: "every byte of telemetry stays on the developer's machine").

**`before_send` scrubbing pattern** (REQUIRED if enabled):
- Scrub OTLP request payloads (may contain user code fragments)
- Strip stack traces of file paths beyond project root (kernel/stdlib paths redacted)
- Sanitize `AppError` stack traces (remove Rust struct names, library versions via tracing-error 0.2.1 SpanTrace integration)
- Redact plugin file paths (basename only per vector 3)
- Redact DuckDB query parameters (query_id + param_count only per vector 5)
- MCP response bodies NEVER logged per vector 4 (explicitly check event type before capture)
- Pattern: `before_send: Box::new(|event| { scrub_otlp_payloads(&event); scrub_file_paths(&event); scrub_query_params(&event); event })` (sentry_tauri callback)

**Panic hooks:**
- `std::panic::set_hook(Box::new(|info| { tracing::error!(target: "app.panic.fatal", panic_message = %info, location = ?info.location(), "panic"); emit_panic_span(...); if sentry_enabled { sentry::capture_message(&format!("{:?}", info), sentry::Level::Fatal); } }))` in app boot
- Panic message + backtrace (if `RUST_BACKTRACE=1`) logged to both stderr + file sink
- Emit span `app.panic.fatal` with `panic_message`, `backtrace` (array of strings)

**Error classes captured:**
- Unhandled panics (always via panic hook)
- Module-boundary errors (Standard+): explicit `tracing::error!(...)` + Sentry capture (if enabled) for "user-facing" category errors (IPC bridge, receiver parse failures, etc.)
- Tauri command errors: `AppError` enum serialization at IPC boundary (sanitized per vector 2)

**Error → span correlation:**
- Errors within span context include `trace_id` + `span_id` in error event (auto-attached by opentelemetry-appender-tracing 0.31.1)
- Sentry SDK (if enabled) auto-correlates via OTel bridge: sentry-opentelemetry crate provides `SentryPropagator` + `SentrySpanProcessor` (USE ONLY in user-initiated debug mode, NOT in primary OTel pipeline per sentry docs)

**Sentry config pattern (opt-in only):**
```rust
let sentry_dsn = env::var("ANDROMEDA_PULSE_SENTRY_DSN").ok().filter(|s| !s.is_empty());
if let Some(dsn) = sentry_dsn {
  let _sentry = sentry_tauri::init(sentry::ClientOptions { dsn: dsn.parse()?, before_send: Some(Box::new(scrub_before_send)), ..Default::default() });
}
```

## 8. PII Scrubbing & Compliance

### PII Scrubbing

**Data classification rules** (from upstream-context Section 2 Security Plan Excerpt → Data Classifications):

| Data type | Classification | Obs handling | Scrubbing mechanism |
|-----------|---------------|--------------|---------------------|
| Raw OTLP telemetry payloads (trace spans, metrics, logs) | High | scrub-required | `span.attributes` dict redacted from logs (only `attributes_count` + `service_name_tag` emitted); scrubber at ingest boundary via `#[instrument(skip(...), fields(...))]` |
| `AppError` enum variants (IPC bridge) | High | scrub-required | `before_send` callback (Sentry) strips stack traces + Rust struct names; use SpanTrace (tracing-error) for user-defined context only |
| Plugin file paths | High | scrub-required | Basename-only logging via `path.file_name().and_then(\|s\| s.to_str())` before field emission |
| DuckDB query parameters | High | scrub-required | Query anonymizer: `query_id` + `param_count` emitted, NOT `params` list; prepared statements enforced (never `format!` SQL) |
| MCP response bodies | High | scrub-required | Response redaction: `result_type` + `result_count` emitted, NOT `result_content`; explicitly check span event type per vector 4 |
| Environment variables (config) | Low | OK to log structured | Config keys (ANDROMEDA_PULSE_*) logged structurally; secrets MUST be identified by naming convention (`*_SECRET`, `*_TOKEN`, `*_KEY` redacted) |
| Plugin binaries (WASM) | High | scrub-required | Plugin path basename only in logs; WASM binary content NEVER logged |

**Scrubbing libraries** (from obs-research):
- `tracing` 0.1.41 `skip(...)` macro parameter: excludes sensitive fields at source (e.g., `#[instrument(skip(secret_token))]`)
- `tracing-subscriber` 0.3.20 custom filter layer: redacts regex-matched field patterns at log formatter stage
- `sentry-rust` 0.46.0 `before_send` callback: scrubs Sentry event fields pre-transmission
- `tracing-error` 0.2.1 SpanTrace: captures user-defined span context (not Rust stdlib/library names)

**Integration points:**
- OTel `SpanProcessor` middleware: custom processor wrapper around `opentelemetry_sdk::trace::SpanProcessor` that scrubs attributes post-collection, pre-export (e.g., `struct ScrubSpanProcessor<T> { inner: T } impl SpanProcessor for ScrubSpanProcessor { fn on_export(&self, spans) { spans.iter_mut().for_each(|s| scrub_span_attributes(s)); self.inner.on_export(spans); } }`)
- Logger formatter: custom `tracing-subscriber` layer that redacts log fields at format time (e.g., `fields.iter_mut().filter_map(|kv| if is_sensitive(kv.key) { None } else { Some(kv) })`)
- Sentry `before_send` callback: scrub event before transmission (if Sentry enabled)

**Default-deny posture:** unknown attribute types redacted by default; only explicitly allowlisted fields logged. Whitelist per module:
- `ingest`: `span_count`, `service` (not attributes)
- `buffer`: `rows_ingested`, `eviction_count`, `memory_bytes`, `retention_window_seconds`
- `plugin`: `plugin_name`, `plugin_path_basename`, `capability_name`, `error_msg`, `duration_ms`
- `snapshot`: `token_budget`, `token_count_actual`, `dedup_count`, `time_range_start`, `time_range_end`
- `viz`: `query_id`, `param_count`, `row_count`, `latency_ms`

**Compliance Trace Fields:** _SKIPPED — security_tier=Minimal, no compliance triggers (per constraint instructions)_

## 10. SLO Invariants & Telemetry Budgets

**Always-required SLO invariant (every tier):**
- **Zero unlogged panics:** every `panic!()` MUST be captured by panic hook (Section 7) + logged with structured backtrace (SpanTrace via tracing-error 0.2.1) + forwarded to Sentry if enabled. NO retry-once policies for panic handling — masks real failures. Verify in CI: grep log file for `app.panic.fatal` spans; fail build if panic unlogged.

**Standard+ invariants:**
- **Heartbeat ticks:** every long-running task (ingest, buffer, viz, plugins) emits tick every 10–30s (Section 3 Heartbeat ticks); absence of tick for >45s = stall signal
- **Module-boundary error logging:** every error at module boundary (ingest parse failure, DuckDB query error, plugin invoke rejection) logged at `WARN` or `ERROR` level with trace context + error category (not full stack trace per vector 2)
- **Trace context propagation:** every cross-surface call (gRPC→DuckDB→TauRPC→WebGPU) propagates W3C traceparent / IPC envelope context (Section 3 Trace context propagation)

**Performance budgets** (from Section 5 perf-budget-instruments triggers):

| Path / operation | p50 | p95 | p99 | Budget assertion |
|------------------|-----|-----|-----|------------------|
| Snapshot generation (25k token budget) | 100ms | 300ms | 500ms | OTel histogram `snapshot.token_count_ms` with p99 ≤ 500ms SLO (via `criterion` 0.5.1 regression test in xtask benches/) |
| WebGPU canvas frame (30 fps target) | 16ms | 20ms | 33ms | OTel histogram `webgpu.canvas.frame_duration_ms` with p99 ≤ 33ms SLO (no jank at high cardinality per creator brief) |
| Buffer memory bounded | N/A | N/A | N/A | OTel histogram `buffer.memory_bytes` with p99 ≤ 512MB SLO (10-min retention window at 10k spans/sec) |

**Error budget** (Standard tier):
- Definition: 0 unlogged panics per month (SLO = infinity, i.e., any panic is an incident)
- Measurement: parse log file for `app.panic.fatal` spans; counter = span count (should be 0)

**CI gates:**

## 11. Obs Anti-Patterns (NEVER do these)

### Telemetry Strategy

- NEVER over-instrument hot paths (appender inner loop, per-row DuckDB operations) — span overhead matters; profile before adding spans to tight loops
- NEVER skip spans on critical user-facing paths (P1-P7) — agent loses debug ability
- NEVER let signal pyramid drift toward logs-only (spans give request-scoped context logs alone can't; metrics give distribution, trends)
- NEVER use vendor-lock OTLP schemas (Datadog APM SDK / NewRelic agent / AppDynamics); if you use error reporting platform (Sentry), ensure `before_send` scrubbing + local log export always works

### Spans / Traces

- NEVER include raw OTLP attributes in span attributes (Vector 1 scrubbing) — include only `attributes_count` + `service_name_tag`
- NEVER use high-cardinality span names (per-user-ID names, per-trace-ID names, per-arbitrary-request-path) — kills distributed tracing storage
- NEVER skip trace context propagation across surface boundaries (IPC envelope, gRPC metadata, HTTP headers) — agent loses trace continuity for multi-surface debugging
- NEVER leave dangling spans (forgot to call `.end()` / span drop without explicit close) — leaks memory + blocks export
- NEVER serialize `anyhow::Error` directly across IPC boundary — convert to `AppError` enum + sanitize per Vector 2
- NEVER log full canonicalized plugin file paths (Vector 3) — basename only
- NEVER emit raw DuckDB query text in span attributes (Vector 5) — query_id + param_count only

### Metrics

- NEVER use unbounded label cardinality (service_name mapped to infinity, trace IDs, arbitrary request paths) — explodes metric storage; enumerate labels upfront
- NEVER create metric instruments inside hot path (instrument creation is not free) — create at SDK init, reuse
- NEVER skip histogram quantile reporting (need p50/p95/p99 for SLO enforcement); emit via Meter + export to file / stdout
- NEVER use metrics as sole SLO signal without span tracing (need both for end-to-end visibility)

### Logs

- NEVER use unstructured stderr text (agent can't parse fields) — always JSON-per-line to file sink
- NEVER skip `trace_id` / `span_id` fields in logs (when available) — agent loses correlation between logs and spans
- NEVER use multi-line stack traces without one-line serialization — breaks JSON-per-line parsing; use SpanTrace (tracing-error) instead of raw backtrace
- NEVER log in hot path at `info` level — spam costs throughput; use `trace` / `debug` gated by `ANDROMEDA_PULSE_LOG_LEVEL` env var
- NEVER log raw OTLP attribute values (Vector 1), stack traces with struct names (Vector 2), full paths (Vector 3), MCP response content (Vector 4), or query parameters (Vector 5)

### Error Reporting

- NEVER ship a real Sentry DSN in dev / committed to repo — security leak; use `ANDROMEDA_PULSE_SENTRY_DSN` env var only
- NEVER skip `before_send` scrubbing (if Sentry enabled) — PII leaks to external service
- NEVER enable error reporting by default — privacy violation; opt-in only (per creator brief: "every byte stays on developer's machine")
- NEVER use Sentry as the ONLY error sink — local panic hook + tracing::error log MUST always work even with Sentry disabled

### PII Scrubbing

- NEVER include PII in logs / spans / metrics by default (default-deny posture) — scrub at source via `skip(...)` macro or redact at processor stage
- NEVER scrub only at sink stage (Sentry `before_send`) — scrub at processor stage so failures upstream don't leak; apply at multiple layers
- NEVER hardcode scrubbing rules in single location — rules applied at logger formatter + OTel SpanProcessor + Sentry `before_send`
- NEVER log plugin-returned Arrow IPC payloads (untrusted) — size-cap + schema validation only
- NEVER log snapshot file contents to stdout (security plan anti-pattern) — snapshot file write emits non-suppressible toast event

### CI

- NEVER lose telemetry artifacts (log file + snapshot on failure) — uploaded as CI artifacts with retention
- NEVER use human-review-gated log analysis ("ops team reviews daily") without machine-parseable export — agent locked out
- NEVER skip snapshot generation on test failure — first-class debugging artifact
- NEVER rely on colored terminal output for CI parsing — CI artifacts MUST be structured (JSON) + machine-readable

### SLO

- NEVER skip zero-unlogged-panics invariant — most basic obs guarantee; every panic logged with structured backtrace
- NEVER add retry-once policies for panic handling — masks real failures (parallel to tests' zero-flakiness invariant)
- NEVER define soft SLO budgets (no enforcement) — formal SLOs MUST trigger build / deploy failure when exhausted (e.g., p99 frame duration > 33ms = release build fails)
- NEVER defer error budget decisions to humans ("team will review monthly") — agent-driven SLO assertions in CI

### Universal (agent-driven specific)

- NEVER use proprietary APM as ONLY exporter (Datadog APM SDK / NewRelic agent / AppDynamics as primary) — vendor schemas break paste-to-AI workflows; stdout/file mandatory
- NEVER use dashboards-only obs (Grafana / Kibana / Datadog UI as sole consumption surface) — every signal must have agent-readable consumption path (log file, OTLP JSON export, CLI query)
- NEVER use human-review-gated log analysis without machine-parseable export — blocks agent-driven debugging
- NEVER use real network OTLP in self-observing project (recursion guard) — project IS observer → stdout-only mandatory; network OTLP exporter only secondary / opt-in (validate loopback guard per trigger)
- NEVER hardcode service identity (`service.name = "myapp"`) — use compile-time `env!()` or runtime env var per Section 3
- NEVER skip `before_send` scrubbing in error reporting (if enabled) — PII → external service = privacy violation
- NEVER emit full OTLP protobuf to stdout/stderr (would corrupt JSON-RPC streams) — structured logs only; OTLP spans export as JSON-per-line to file sink
