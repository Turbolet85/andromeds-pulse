# a11y extract

## Relevance
**Partial** — no new UI surface, role, form, or contrast pair is introduced, but the chunk's open premise #1 (a webview-side mark) puts instrumentation inside the render paths of three already-assertable surfaces (halo, constellation dot = p11, counter) and its premise #2 (a new `telemetry.frontend` TauRPC method) touches the exact IPC-mock surface the a11y Playwright harness depends on.

## Constraints
- If a new TauRPC procedure is added, a11y-plan §3 (Harness wiring & conventions) requires it be mocked in `tests-a11y/helpers/mock-tauri.ts` under the `TauRPC__<router.path>` command shape, with any fixture payload in `helpers/v02-fixtures.ts` — an unmocked command invoked during render is exactly the failure class that once silently disabled the whole suite (§3; amendment 2026-06-10).
- a11y-plan §3 requires the "add one axe spec per new route/modal in the same chunk" standing rule; this chunk adds no route or modal, so the rule does not fire — but whether the three target surfaces are already covered by the p8–p12 specs (p11 constellation especially) is research's question, not something this extract can attest.
- a11y-plan §6 (Motion tokens) + §11 (Motion) require every animated path to degrade under `prefers-reduced-motion: reduce` and never use motion as the only signal; a timing mark taken at *animation completion* would make the measurement motion-dependent and would read differently under the reduced-motion emulation the existing specs assert. Marks must key off render/data-commit, not transition end.
- a11y-plan §1 Critical Path P4 requires push-driven re-renders to leave focus stable and to announce without interrupting (SC 2.4.3 / SC 4.1.3); instrumentation that changes re-render cadence on the constellation or counter surfaces must not perturb that. Whether the current code already satisfies P4 on these surfaces is research's question.
- a11y-plan §7 (Live regions) + §5 (findings-window entry) require the live counter badge's 0→N transition to announce once politely; if the P-045 counter observable adds a render or state hop, it must not multiply live-region announcements.
- a11y-plan §3 (regression baseline) + §10 (SLO Invariants) require zero new violation tuples vs `baselines/a11y-violations-summary.json` and forbid soft gates or retry-once on any a11y failure this chunk's webview edits might introduce.
- a11y-plan §11 (Universal / agent-driven) requires machine-verifiable evidence for any conformance claim — a manual "the widget still looks fine" check is not a substitute for re-running the chain.

## Patterns to follow
- The `TauRPC__<router.path>` regex mock + `helpers/v02-fixtures.ts` payloads + `plugin:event|listen` push handler, per a11y-plan §3 Harness wiring & conventions — the shape any new `telemetry.frontend` method must be added to.
- The cheap suite-health probe `npx playwright test --list` before trusting a green run (a11y-plan §3) — the specific guard against list-time import failures.
- The reduced-motion assertion pattern: `page.emulateMedia({ reducedMotion: 'reduce' })` then verify state is still conveyed by color/text/focus ring (a11y-plan §6 Motion tokens + §3 Contrast verification harness).
- Structured violation JSON at `target: "a11y::assertion"` with `fields.{wcag_criterion, violation_type, severity, surface, selector, remediation, tool, tool_result_id}`, emitted to `~/.andromeda-pulse/logs/` in the obs log format (a11y-plan §3 Structured violation JSON schema).

## Anti-patterns to avoid
- NEVER gate or measure a frame loop without honoring `window.matchMedia('(prefers-reduced-motion: reduce)')` / `useReducedMotion` — a11y-plan §11 (Motion) bans animation loops that ignore it; a new mark inside a canvas/frame loop inherits this ban.
- NEVER let an a11y spec failure introduced by instrumentation be deferred or soft-gated — a11y-plan §11 (CI) makes `test:a11y` a fail-fast merge gate with no "fix in follow-up".
- NEVER add ARIA or a hidden DOM node purely as a measurement hook — a11y-plan §11 (ARIA / Screen Reader) bans ARIA noise and `aria-hidden` on essential/focusable content; a mark must be non-semantic (e.g. `performance.mark`), not a marker element.

## Contract bindings
- **a11y violation JSON ↔ obs**: a11y-plan §3 binds the violation record to the obs structured-log schema and uses the `a11y::assertion` target, which resolves through the same default-deny allowlist registry (`::`-prefix rule) this chunk edits for its new `metric.*` leaves — research should confirm the new leaves do not disturb that resolution path.
- **a11y CI gate ↔ tests harness**: a11y-plan §3 / §9 run `npm run test:a11y` (`cargo xtask test:a11y`) inside the same `ci.yml` and reuse tests' `boot`/`run`/`status`/`cleanup`/`logs` 5-command discipline — the chunk's test-plan reconciliation should keep that step intact.
- **New TauRPC method ↔ a11y IPC mock**: any `telemetry.frontend` addition (chunk premise #2) is a joint edit — backend trait + `xtask EXPECTED_PROCEDURES` *and* the a11y `mock-tauri.ts` command map (a11y-plan §3).
