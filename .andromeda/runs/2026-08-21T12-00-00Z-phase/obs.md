# obs extract

## Relevance
Relevant — the chunk is pure instrumentation (three new `metric.*` emission surfaces + their allowlist leaves), which sits entirely inside the obs domain.

## Constraints
- New timing observables must be emitted as `tracing` events with a `metric.{module}.{measure}` target and a numeric `value` (or explicit duration) field plus enumerated label fields — no OTel SDK Meter/Histogram instrument, and **no precomputed percentiles in the emission path** (raw per-event samples; percentiles are computed agent-side by `jq` over `agent-latest.jsonl`) (per obs-plan §5 Metric Coverage; §2 Telemetry Strategy → naming conventions).
- Any webview-originated measurement must reach the log **only** through a TauRPC `telemetry.frontend.*` command that calls `tracing::info!(target: "metric.{name}", …)` on the backend; the webview has no browser OTel SDK and no direct file access, and the single JSON file is the unified self-observation surface (per obs-plan §1 Telemetry surfaces → desktop-webview row; §4 Span/Trace Coverage → desktop-webview row). This is the domain rule that bears on the chunk's central design fork (scope open premise 1).
- Every new target requires its own **EXACT** allowlist leaf enumerating **all** fields its emit site emits; a bare-prefix key is banned because it silently widens every sibling `{prefix}.*` target to one field set (per obs-plan §8 PII Scrubbing → Default-deny posture). Whether the code already resolves any `metric.*` target through a bare prefix key, and whether a leaf-less new target would be redacted at HEAD, is research's question.
- Label cardinality must be bounded to enumerated values; per-service-name, per-trace-id and per-arbitrary-path labels are barred for product-internal metrics. §5's unbounded-`service_name` exception is scoped to query-time aggregation events only and does not extend to new observables (per obs-plan §5 Metric label cardinality discipline). This constrains scope open premise 3 (three procedures vs one parameterized discriminant — the discriminant must be a bounded enum).
- Emission cadence must respect the hot-path rule: no per-event `info`-level emission on hot paths, and heavy payload formatting must be level-gated. Where a signal is inherently per-span or per-frame, the plan's precedent is folding counts into an existing 15s tick as FIELDS rather than minting a per-event target (per obs-plan §5 Conceptual instrument types → tick-aggregated counter row; §11 Telemetry Strategy + §11 Logs).
- Cross-surface start/end instants must carry trace correlation: every cross-surface call is required to propagate W3C traceparent / IPC-envelope context, so a bridge-crossing "span arrival" reference should ride that mechanism rather than a new ad-hoc field (per obs-plan §10 Standard+ invariants → Trace context propagation; §3 Trace context propagation → IPC boundaries). Whether such a reference already crosses the bridge (scope open premise 4) is research's question.
- Every new line must satisfy the log contract: `timestamp` / `level` / `target` / `message` / `fields`, with `service.name` / `service.version` / `deployment.environment` supplied as default subscriber fields rather than per-call boilerplate (per obs-plan §6 Log Coverage → Required fields; §3 Service identity).

## Patterns to follow
- The frontend-bridged distribution metric: `metric.webgpu.frame_duration_ms` measured in the webview and emitted backend-side via the `telemetry.frontend.record_frame_ms` TauRPC command — the plan's only worked example of a rendered-surface timing observable (per obs-plan §5 per-surface metric table; §4 desktop-webview row). This is the same precedent the scope names at `crates/ui-bridge/src/telemetry.rs:99`.
- The backend-measured `metric.*` target emitted from a Rust resolver around server-side work (per obs-plan §5 Metric emission convention) — the cheaper half of the scope's design fork.
- Tick-field folding instead of a new target when the natural cadence is per-event (per obs-plan §5 Conceptual instrument types → tick-aggregated counter row). Relevant to P-045's "counter refresh ≤ 1s" and P-027's per-span arrival.
- EXACT-leaf registration as practised for `app.boot.workspace_key` and `triage.baseline.bootstrap_window.override`, including the requirement that the field-completeness guard live under `pulse-app/tests/` and not in a src-level `mod tests` (per obs-plan §8 Default-deny posture; the same section records that `[lib] test = false` makes a src-level guard compile but never run).
- SLO assertion by post-run `jq` aggregation over the raw `value`/`duration_ms` events, with a two-state NEUTRAL/ACTIVE posture when the stream depends on a booted webview and check scripts required to be NEUTRAL-tolerant (per obs-plan §10 Performance budgets → WebGPU row; §10 Load-profile constraints).

## Anti-patterns to avoid
- Unbounded label cardinality on the new events (service names, trace ids, request paths), and precomputed quantiles baked into the emission path (per obs-plan §11 Metrics).
- Per-event `info`-level emission on a hot path, or unlevel-gated payload formatting inside a tight loop (per obs-plan §11 Telemetry Strategy → over-instrumenting hot paths; §11 Logs → hot-path `info` spam).
- Introducing any browser-side OTel SDK or a second self-observation sink to carry the webview mark — the `tracing` JSON file is the single agent surface, recursion-free by construction (per obs-plan §11 Universal; §1 architectural choice).

## Contract bindings
- **obs ↔ tests:** the log-format JSON schema is a binding contract taken verbatim from the test-plan harness contract — obs aligns to tests, not vice versa; the new targets' lines must satisfy it, and the scope's in-boundary "obs-plan/test-plan reconciliation" is this binding being restated on both sides (per obs-plan §3 Log format JSON schema; §6 Log Coverage).
- **obs ↔ security:** the default-deny allowlist is the enforcement point for the security plan's logging-sensitive vectors; each new leaf must enumerate only bounded/aggregate fields and never identity (per obs-plan §8 PII Scrubbing → Data classification rules + Default-deny posture).
- **obs ↔ ui-bridge (frontend):** `telemetry.frontend.*` is the only sanctioned webview→backend telemetry path; any new webview-side mark binds here (per obs-plan §1 Telemetry surfaces → desktop-webview; §4 desktop-webview row).
- **obs ↔ external Conductor verification:** the assertion of ≤2s / ≤5s / ≤1s is out of this chunk, but the obs contract on what Conductor consumes is per-event raw samples in `agent-latest.jsonl`, unredacted and `jq`-aggregatable (per obs-plan §5 Metric emission convention; §10 CI gates). A leaf-less target would leave the bound un-measurable even after the emit site ships.

## Acceptance criteria contributions
- (obs) Each of the three new observables emits at a distinct `metric.{module}.{measure}` target carrying a numeric per-event value and bounded enumerated labels only — no precomputed percentiles, no OTel instrument (per obs-plan §5 Metric Coverage).
- (obs) Each new target resolves to an EXACT allowlist leaf that enumerates every field its emit site emits, with no bare-prefix key introduced for its family, and its field-completeness guard placed where it actually runs (`pulse-app/tests/`) (per obs-plan §8 PII Scrubbing → Default-deny posture).
- (obs) No new event carries per-service, per-span-id or per-trace-id labels, and none is emitted per-frame/per-span at `info` level without tick aggregation or level gating (per obs-plan §5 Metric label cardinality discipline; §11 Metrics + §11 Logs).
- (obs) Each new line conforms to the NDJSON harness schema — `timestamp` / `level` / `target` / `message` / `fields` plus the default service-identity fields — and, if the stream is webview-dependent, its check script reports NEUTRAL rather than FAIL when no webview is present (per obs-plan §6 Log Coverage → Required fields; §10 Performance budgets two-state posture).
