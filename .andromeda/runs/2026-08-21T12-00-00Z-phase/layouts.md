## Constraints
- The rendered end of P-025's hue is the WebGPU Halo canvas: on the compact widget a single unified halo around the aggregated service-count badge, on the dashboard Traces hero per-service dots, with hue LCH-interpolated `color-primary` → `color-accent` by error rate (per layout-templates §Component — Halo State Pulse canvas → Signature element details; §Surface: desktop-webview → Signature placement). A "rendered hue" mark has two distinct surfaces, not one.
- The Halo canvas render loop is specified as 60 FPS via `requestAnimationFrame` with the `<canvas>` filling its container (per layout-templates §Component — Halo State Pulse canvas → Canvas rendering (WebGPU)) — that loop is the only rendered-instant boundary the plan defines for hue and for constellation dots.
- The plan requires two degraded paths that a webview-originated mark must respect: with WebGPU unavailable the canvas renders a `font-body` text message instead of any halo frame, and under `prefers-reduced-motion: reduce` the halo is a static glow while hue still updates per error rate (per layout-templates §Component — Halo State Pulse canvas → Fallback / Reduced motion).
- P-027's rendered target is the constellation map hero, which the plan requires to be a `flex-shrink:0` fixed region inside a flex column bounded to the shell's `main` height (`overflow:hidden`, no outer page scrollbar at any window size), above a `flex:1 / min-height:0` internally-scrolling table (per layout-templates §Wireframe — Full dashboard (Traces primary screen) wireframe notes). Instrumentation must add no layout-participating node to that column.
- P-045's counter maps to the compact-widget unread badge that opens the findings window (per layout-templates §Surface: desktop-webview → Primary screens → Findings window). Whether the code's counter surface is that badge rather than a footer readout is research's question; the plan documents no ASCII wireframe for it (deferred per the same section).
- Read-only status regions must stay read-only and affordance-free: the footer is a read-only status bar and the shared empty/error state is specified with no focusable element (per layout-templates §Component — Footer (read-only status bar); §Component — Empty / error state).
- The webview surface carries a 0.35 expression level and desktop-native 0.2, with Halo motion exempt only because it is data-driven, not decorative (per layout-templates §Surface: desktop-webview expression level; §Component — Halo State Pulse canvas → Signature element details). Nothing in this chunk may add visible motion or chrome.

## Patterns to follow
- Aggregate-vs-per-service surface split: the compact widget is aggregate by design ("24 services, avg 1.2% error"), the dashboard hero is per-service (per layout-templates §Component — Halo State Pulse canvas → Signature element details). If the aggregate-only cardinality rule binds, the widget's unified halo is the mark site that satisfies it without stripping fields.
- Sub-second read-only live readout without chrome or focus stops: the dashboard `ConnectionStatusLine` is specified to live-update on a 1s poll reusing the P-067 recency gate (per layout-templates §Component — Footer (read-only status bar) → Full dashboard). This is the plan's only precedent for a ~1s refresh cadence and is the nearest shape for P-045's bound.
- Shared upstream feed across all three surfaces via the `pulse://stream/spans` / `pulse://stream/metrics` broadcast channels, with identical shader logic on widget, dashboard and tray (per layout-templates §IA notes → Multi-surface coordination; §Surface: desktop-native → IA notes → Cross-surface coordination). This bears directly on scope open premise 4 (the start instant) — whether an arrival reference already crosses the bridge is research's question.
- Fixed-region composition on Traces (hero + `Errors only` toolbar fixed, table scrolls internally, sticky opaque thead) (per layout-templates §Component — Trace data table → Internal scroll region). Any mount point the chunk needs in that route must be non-rendering.
- Ownership boundary: canvas init, shader authoring, data-feed subscription and reduced-motion degradation are recorded as the route + obs implementation specialist's, with layouts supplying structure and token references only (per layout-templates-amendments 2026-05-02 → Handoff / ownership notes).

## Anti-patterns to avoid
- No visible debug/overlay chrome, badge, or counter added to the Halo canvas, the constellation hero, or the tray halo layer to expose timing — the signature layer is data-driven only (per layout-templates §Component — Halo State Pulse canvas; §Surface expression levels 0.35 / 0.2).
- No new focusable element anywhere the chunk touches — the footer and the shared empty/error region are specified affordance-free, so focus order must be unchanged (per layout-templates §Component — Footer (read-only status bar); §Component — Empty / error state).
- No restructuring of the Traces bounded flex column that would reintroduce an outer page scrollbar or unfix the hero/toolbar (per layout-templates §Wireframe — Full dashboard (Traces primary screen) wireframe notes).
