# tests extract

## Relevance
Relevant — the chunk's In-scope list names "their unit coverage" and the "obs-plan/test-plan reconciliation the new targets require", and it touches two gate-triggering paths (`pulse-app/src/observability.rs`, `crates/ui-bridge/src/`).

## Constraints
- The chunk plan's `## Test Commands` MUST carry the full standard gate set unconditionally (`cargo fmt --check`, `clippy --workspace --all-targets --all-features -D warnings`, `nextest run --workspace --profile ci`, `xtask capability-drift`, `xtask capability-widening-check`); the three `npm run … --prefix pulse-app/ui` gates are excludable ONLY if the Files-to-modify/New-files lists touch zero `pulse-app/ui/**` paths — so the scope's open premise 1 (webview-side mark vs backend-only timestamp) decides whether they are mandatory (per test-plan §3 Per-chunk gate discipline).
- A boot-smoke gate is additionally REQUIRED for chunks touching `pulse-app/src/observability.rs` or `crates/ui-bridge/src/` — both are on the trigger list, and the chunk's allowlist leaves + any new `telemetry.frontend` method land exactly there. Either the `npx @tauri-apps/cli dev` 60s form or the direct-binary variant (fresh `ANDROMEDA_PULSE_DATA_DIR`, seeded load, assert 0 `app.panic.fatal` / 0 `ERROR` in `<data_dir>/logs/agent-latest.jsonl*`, shutdown by specific pid) satisfies it (per test-plan §3 Boot-smoke gate + Direct-binary smoke variant).
- Test placement is not uniform: library crates (`ui-bridge` included) take co-located `#[cfg(test)] mod tests`, but `pulse-app` is the exception — `[lib] test = false` means a co-located `mod tests` compiles under clippy and NEVER RUNS, so pulse-app-side probes must be separate files under `pulse-app/tests/*.rs` reaching internals via `pub` + `#[doc(hidden)]` (per test-plan §4 Conventions → Test file location; §2 Test directory + naming conventions).
- No test may take an instant from an uninjected real clock or use `sleep(N)` for synchronization — determinism is an agent-driven invariant (per test-plan §11 Universal + §11 E2E; §2 Agent-runnable invariants). This is the test-side counterpart of the scope's own "intentionally NOT faked as a sleep-based unit test".
- Zero-flakiness is absolute: one flake ⇒ immediate quarantine + root cause, never a retry policy (per test-plan §10 Zero-flakiness budget). Timing-shaped assertions are the highest-risk shape this chunk can introduce.
- When narrowing a `pulse-app` run, use `--filter-expr` / `-E` **under `--workspace`**, not `-p` — `-p` resolves a narrower feature subgraph than a `--workspace` build produced and fails to link (per test-plan §3 `run` → Test selection, measured 2026-08-15).
- New emit-site code counts toward Standard-tier coverage: ≥ 75% line / ≥ 70% branch / ≥ 85% function (per test-plan §10 Coverage thresholds; §4 Coverage target).

## Patterns to follow
- Allowlist-leaf coverage as a dedicated `pulse-app/tests/unit_*.rs` integration-target probe asserting through the public resolution API rather than internals — the existing `unit_observability_allowlist_feed.rs` is the shape precedent (per test-plan §4 Conventions; §2). Whether that file already exercises `for_target` resolution generically enough to cover three new exact leaves is research's question.
- Clock/instant supplied as an explicit parameter (the `triage` crate's `now_nanos` form) in preference to `tokio::time::pause()` where the function under test already takes the instant as an argument — the plan records parameter injection as the STRONGER form for exactly this shape (per test-plan §4 "What unit tests cover" → triage crate).
- `rstest` `#[fixture]` builders + self-bootstrapping data (OTLP ingest or Rust builders at runtime, never a pre-baked DB or `.sql` seed) for any fixture the new observables need (per test-plan §7 Seed strategies + Self-bootstrapping requirement; §1 agent-driven-discipline).
- A new/extended `telemetry.frontend` TauRPC method is exercised in-process via `tauri::test::mock_builder()` + `get_ipc_response()`, with error serialization asserted against the `AppError` enum — the same driver row that covers the existing ui-bridge procedures (per test-plan §5 Drivers + §6 E2E driver table; §4 ui-bridge bullet).
- If the design fork lands a webview-side mark: co-located `*.test.tsx` under `pulse-app/ui/src/` on vitest 3.x + jsdom 26 + `@testing-library/react` 16, DOM-shape assertions only, JUnit to `target/junit-ui.xml` (per test-plan §4 webview framework; §1 surfaces table).

## Anti-patterns to avoid
- NEVER synchronize a timing test with `sleep(N)` or read a real clock without injection — poll an explicit signal or take the instant as a parameter (per test-plan §11 E2E + §11 Universal).
- NEVER assert against private crate-internal functions — the new emit sites and allowlist leaves must be asserted at public module boundaries (per test-plan §11 Unit).
- NEVER park a slow/timing-shaped test behind `#[ignore]`: `#[ignore]` is reserved for flake quarantine (and requires a tracked issue), while load-shaped tests join the `load-profiles` nextest profile instead (per test-plan §10 Load profiles + §11 Quality).

## Contract bindings
- **tests ↔ obs (log format):** the harness `logs` verb reads `tracing` JSON-lines and greps/`jq`s it; every new `metric.*` target must therefore be jq-extractable from the same stream the harness tails (per test-plan §3 Log format + §3 `logs`; obs-plan §3 binding).
- **tests ↔ obs (metric authority):** obs-plan §10's ms-form values GOVERN over test-plan §10's descriptive rows — `metric.webgpu.frame_duration_ms` p99 ≤ 33 ms is the asserted form and no test asserts an fps number. Three new ms-form timing targets inherit that convention (per test-plan §10 Frame-budget assertion note; amendment 2026-06-10 item 3).
- **tests ↔ CI/capability matrix:** `cargo xtask verify:capability-matrix` validates `docs/v0_2_0/capability-verification-matrix.json` ids/file-refs/grep-anchors and FAILS CI on dangling ones — so any edit to the P-025 / P-027 / P-045 `notes` clause, or any row added for P-075, must keep its anchors resolvable (per test-plan §9 Capability verification matrix). Whether the current rows' grep-anchors survive the new emit sites is research's question.
- **tests ↔ arch/security (binding cost):** the scope's open premise 2 (does a new method on an existing trait need new capability JSON / `xtask EXPECTED_PROCEDURES`?) is adjudicated by the two capability gates already in the standard gate set, not by a new test (per test-plan §3 Per-chunk gate discipline; §1 pending-trigger row `Capability widening static analysis`, LANDED).
