# design extract

## Relevance
Partial — this chunk adds no UI, but all three measured *end* instants are design-owned rendered surfaces (halo hue, constellation dot, throughput counter), so design constrains what counts as "rendered", where a webview-side mark can physically hook, and forbids the instrumentation from becoming visible.

## Constraints
- **The P-025 end instant is the severity-driven hue, not the rhythm.** design-system §Brand Identity "Signature element" + §Motion "High-impact moments" (1) define three *orthogonal* Halo axes: LCH hue Earth Blue `#4A90E2` ↔ Alert Burgundy `#C7556A` driven by cumulative incident severity; breathing cadence (4–5 s quiet → ~2 s active, ≈0.2–0.5 Hz) driven by *activity state*; connection state as a separate grayout/desaturation axis (P-004). "Pipeline latency ≤ 2 s to a rendered hue" terminates on the hue axis only.
- **Canvas surfaces are outside React's render tree.** design-system §Surface: desktop-webview "Performance notes" + §Component Patterns "Canvas Container" require Halo State Pulse, Latency River and the throughput counter to be drawn directly to the WebGPU canvas with Arrow data pushed via compute shader, *not* through VDOM. A webview-side end-of-render mark for these three bounds therefore cannot come from a React commit/effect for these surfaces. Whether the code already exposes a canvas-side frame/paint hook usable as that mark is research's question (bears directly on scope §Open premises 1).
- **Reduce-motion must not silence the observable.** design-system §Motion "Accessibility" requires the Halo to degrade to a *static glow* under `prefers-reduced-motion: reduce` — no pulsing rhythm, but hue still updating per severity. An emission keyed to a pulse cycle would go silent for reduce-motion users; the P-025 mark must key on the hue update. Whether any existing halo emission is cycle-driven is research's question.
- **Instrumentation may add no visible surface.** design-system §Motion "Hard limits" bans new canvas/WebGL (only the dedicated Halo layer is exempt), entrance animations and staggered reveals; §Iconography "Rule" — icons clarify, not decorate. No latency readout, spinner, badge or new transition may appear as a side effect of measurement. This matches scope §Boundaries ("instrumentation, not behaviour").
- **Any rendered numeric value is token-bound.** design-system §Typography "Data" mandates JetBrains Mono 400 / 12px / tabular-nums for metrics and counters; §Surface: desktop-webview "Tokens" requires values reach React through `--color-*` / `--font-*` / `--duration-*` custom properties. No hardcoded hex or px in anything this chunk touches that renders.
- **The P-027 "dot" has a fixed definition.** design-system §Brand Identity domain anchor "Constellation" + §Component Patterns "Canvas Container" define it as a service constellation dot with halo brightness encoding health, on the Inset `#0F1117` canvas background — the arrival instant is that dot's first paint on the WebGPU canvas, not a data-model insertion.
- **Chrome timing values are ceilings the chunk must not perturb.** design-system §Motion "This project's values": 150 ms ease-out micro-interactions, 200 ms fade transitions, entrance animations = none. Measurement must not introduce a new transition to make an end instant observable.

## Patterns to follow
- **Canvas Container + WebGPU fallback** (design-system §Component Patterns "Canvas Container"): initialization falls back to plain `<canvas>` when `navigator.gpu` is undefined. If a webview-side mark hangs off WebGPU frame completion, that fallback path is a silent-no-emission hole the design already anticipates.
- **Three-axis Halo vocabulary as field naming** (design-system §Brand Identity "Signature element"): severity-hue / activity-cadence / connection-grayout are the existing names for halo state; reusing them keeps the observable legible against the design model and keeps fields aggregate (which binds to the obs cardinality rule cited in scope §Surfaces and contracts).
- **Design→obs measurement hooks already specified** (design-system-amendments §Downstream Readiness "For obs specialist"): halo pulse frequency in Hz per cycle, logged as-is *without re-clamping*, plus halo color state (Earth Blue / Alert Burgundy / interpolated LCH) per pulse. New `metric.*` leaves for P-025 should reconcile against these rather than invent a parallel vocabulary.
- **Token indirection via Tailwind v4 `@theme`** (design-system §Surface: desktop-webview "Tokens") is the only sanctioned route from design values into the webview.

## Anti-patterns to avoid
- **Never represent latency with a generic progress affordance.** design-system §Self-Validation 1 "Swap Test" names "replace the Halo State Pulse with a generic loading spinner" as *the* failure mode; §Motion "Hard limits" reinforces it by banning new canvas/WebGL layers.
- **Never collapse the severity-hue and connection axes into one "halo state" value.** design-system §Motion "High-impact moments" (1) requires them orthogonal (P-004); a single fused field would misreport which axis moved and make the ≤2 s bound unfalsifiable.
- **Never introduce raw hex / magic numbers** in any rendering touched here (design-system §Anti-Patterns "Universal Bans" + §Self-Validation 4 "Token Test").

## Contract bindings
- **design ↔ obs:** design-system-amendments §Downstream Readiness "For obs specialist" is the pre-existing design→obs contract for halo frequency + color-state hooks; obs owns the allowlist leaf, target naming and cardinality (`.claude/rules/observability.md`), design owns what the measured state *means*.
- **design ↔ a11y:** design-system §Motion "Accessibility" (reduce-motion degradation, SC 2.3.3) decides whether a pulse-cycle-driven emission is viable at all; a11y owns the conformance derivation.
- **design ↔ tests:** design-system-amendments §Downstream Readiness "For tests specialist" lists the motion lint targets (durations 150/200/250/350 ms, easing names, the 7 hard-limit bans) that new instrumentation code must not trip.
- **design ↔ route:** the webview-side mark, if chosen (scope §Open premises 1), lands on the WebGPU canvas layer whose out-of-React placement is fixed by design-system §Surface: desktop-webview "Performance notes".

## Acceptance criteria contributions
- No new visible chrome: halo, constellation dots and throughput counter render identically before/after — no latency readout, spinner, badge, icon or added transition (per design-system §Motion "Hard limits" + §Anti-Patterns "Universal Bans").
- The P-025 observable keys on the severity-driven LCH hue update, not on a breathing cycle, so it still emits when the Halo is static under `prefers-reduced-motion: reduce` (per design-system §Motion "Accessibility").
- Severity-hue and connection-grayout remain distinct fields/axes in whatever is emitted; neither is folded into the other (per design-system §Brand Identity "Signature element").
- Any measured value surfaced in the webview uses `--font-data` (JetBrains Mono 400 / 12px / tabular-nums) and `--color-*` tokens, with no hardcoded hex or px (per design-system §Typography "Data" + §Surface: desktop-webview "Tokens").
