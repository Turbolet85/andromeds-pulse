# tests extract

## Relevance
Relevant — a Rust-crate change in `buffer` (+ possibly `security`) that lands directly on two OPEN tests-plan coverage triggers and requires an in-crate + wire-level proof.

## Constraints
- Standard tier mandates comprehensive unit depth — 75% line coverage minimum, **all module boundaries tested** (per test-plan.md §2 pyramid Unit row); a new or changed public boundary in `buffer`/`security` without a direct in-crate assertion is a gap by this rule, not an optional extra.
- Rust library crates (including `buffer` and `security`) must carry **co-located `#[cfg(test)] mod tests`** in the crate's own source; `pulse-app/tests/*.rs` is the exception form reserved for the binary crate (`[lib] test = false`) and does NOT count as in-crate coverage (per test-plan.md §4 Conventions → Test file location; §2 Test directory + naming conventions).
- §1 Pending coverage trigger `buffer-redaction-counter-unit-coverage` is recorded **OPEN** and names exactly this chunk's blast radius: the once-per-batch fold arithmetic, that BOTH batch builders contribute to the same tally, and that the fold stays separate from `record_feed_counts` — all still owed in-crate (per test-plan.md §1 Pending coverage triggers; §4 buffer bullet). Whether this chunk's edits satisfy or widen it is research's question.
- Fixture data must be **self-bootstrapping** — seeded at runtime via OTLP ingest or Rust builder factories (`MockTraceSpan::builder()`) composed through `rstest` `#[fixture]`; no pre-baked DuckDB, no `.sql` seeds, per-test isolation via `tempfile::TempDir` + in-memory DuckDB (per test-plan.md §7 Test Data & Fixtures; §3 Test data bootstrap).
- The ingest→buffer boundary is exercised **live**, not mocked: `tonic` gRPC client to loopback `:4317` with DuckDB verified by direct query; the `:4318` HTTP leg is **protobuf-only on this build** (`application/json` returns 415) (per test-plan.md §5 Boundary types covered + OTLP HTTP contract line).
- Every chunk plan's `## Test Commands` must carry the unconditional standard gate set — `cargo fmt --check`, `cargo clippy --workspace --all-targets --all-features -- -D warnings`, `cargo nextest run --workspace --profile ci`, `cargo xtask capability-drift`, `cargo xtask capability-widening-check`; webview gates excluded only if zero `pulse-app/ui/**` paths are touched (per test-plan.md §3 Per-chunk gate discipline).
- Perf budgets bind to the paths this chunk edits: DuckDB buffer insert (Arrow appender) p99 ≤ 50 ms and OTLP gRPC `TraceService.Export` p99 ≤ 100 ms — a per-cell scrub on the hot append path is inside both budgets (per test-plan.md §10 Performance budgets).

## Patterns to follow
- The `security` crate's existing paired-corpus shape: recall `#[rstest]` corpora **plus a first-class false-positive corpus** asserting that ordinary high-entropy identifiers keep returning `ScrubbedValue::Allowed(_)` — the direct precedent for this chunk's key-column identity-preservation requirement (per test-plan.md §4 security-crate bullet).
- Hang-safe `buffer` appender tests: run on a worker thread under a bounded `recv_timeout` so a hang fails rather than wedges, and assert schema/PK facts via `information_schema` rather than a duplicate-INSERT probe (a documented hang on this build) (per test-plan.md §4 buffer bullet).
- **Direct-binary smoke variant** as the accepted wire-level form when the verification needs a fresh `ANDROMEDA_PULSE_DATA_DIR` + sustained `inject_demo` load: launch `target/debug/pulse-app.exe` under those env vars, seed over the real receiver, assert from the run's own artifacts (0 `app.panic.fatal` / 0 `ERROR` in `<data_dir>/logs/agent-latest.jsonl*`), shut down by SPECIFIC pid, confirm `:4317`/`:4318` released (per test-plan.md §3 Direct-binary smoke variant).
- P1's step ordering as the discriminating-smoke template: poll `health` until `subsystems.buffer.rows_ingested` reaches the expected count **before** any downstream assertion — an absence claim is only meaningful after the feed precondition is proven (per test-plan.md §6 Scenario P1 steps 4-6; §3 Status endpoint shape agent reads).
- Explicit parameter injection over ambient state where the function already takes the value as an argument — the `triage` precedent chose `now_nanos` injection over `tokio::time::pause()` as the stronger form (per test-plan.md §4 triage bullet); applies if the per-class treatment is env- or config-tunable.

## Anti-patterns to avoid
- NEVER expose secrets in test output — no logging PII or raw OTLP payloads with credentials (per test-plan.md §11 Universal); the credential-shaped RED fixture must not itself leak into nextest stdout or `agent-latest.jsonl`.
- NEVER mock DuckDB at integration level and NEVER mock the OTLP receiver under test — the wire proof uses live loopback `:4317`/`:4318` + an ephemeral in-memory DuckDB (per test-plan.md §11 Integration, §11 Mocking).
- NEVER use `sleep(N)` for synchronization and NEVER pre-populate the test DB from `.sql` scripts or production telemetry dumps — wait on an explicit `health`/channel signal and generate every span synthetically (per test-plan.md §11 E2E, §11 Test Data).

## Contract bindings
- **tests ↔ obs (log format).** The harness `logs` verb and the smoke's absence assertions grep the obs-declared NDJSON at `<data_dir>/logs/agent-latest.jsonl*`; test-plan.md §3 Log format already names the data-leakage assertion shape (`! grep '<sensitive marker>' test.log`) that a "credential never appears in logs" check follows.
- **tests ↔ obs (status/heartbeat observables).** `subsystems.buffer.rows_ingested` (§3 Status endpoint shape) is the feed precondition, and the `redactions_applied` field on the `buffer.tick` heartbeat is the obs-owned counter the tests read; test-plan.md §1 records that counter as proven cross-crate only, so its in-crate assertion is the tests-side obligation while its schema is obs's.
- **tests ↔ security (ban ↔ trigger ledger).** security-plan §Logging owns the scrub mandate; test-plan.md §1 "Pending coverage triggers" is the tests-side ledger that a security ban carries a matching assertion — a new per-class treatment rule needs its trigger row, not just an impl.
- **tests ↔ security (dependency gate boundary).** The chunk's `cargo audit` / `cargo deny check advisories` PREREQ is a security-owned dependency gate; test-plan.md §9 owns only `cargo deny check bans` as a build-failure condition, so the advisory probe runs alongside but does not enter the tests standard gate set.

## Acceptance criteria contributions
- (tests) The full standard gate set passes — `cargo fmt --check`, `cargo clippy --workspace --all-targets --all-features -- -D warnings`, `cargo nextest run --workspace --profile ci`, `cargo xtask capability-drift`, `cargo xtask capability-widening-check`; webview gates omitted only if zero `pulse-app/ui/**` paths are touched (per test-plan.md §3 Per-chunk gate discipline).
- (tests) New/changed `buffer` and `security` boundaries are asserted **in-crate** and demonstrated by a per-crate run (`cargo nextest run -p buffer`, `cargo nextest run -p security`) — cross-crate `pulse-app/tests/*.rs` guards alone do not discharge this (per test-plan.md §4 Conventions → Test file location + §1 `buffer-redaction-counter-unit-coverage`).
- (tests) A false-positive corpus asserts identity preservation for the key/predicate columns — legitimate service names, metric names, and the `exception` event name survive the treatment unaltered (`ScrubbedValue::Allowed(_)` shape), alongside the recall corpus (per test-plan.md §4 security-crate bullet).
- (tests) The RED→GREEN wire proof is self-bootstrapping (spans generated at runtime via builder factories over the live receiver, in-memory DuckDB, no pre-baked data) and orders the feed precondition — `rows_ingested` / `redactions_applied` advance — before any absence assertion, so an absence cannot pass vacuously (per test-plan.md §7 Self-bootstrapping requirement + §6 Scenario P1 steps 4-6).
