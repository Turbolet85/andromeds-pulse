## Patterns to follow
- RED-at-base / GREEN-after measurement: run the same check at the chunk base and after the change, and record both readings as evidence. The `smoke:hue-shift` leg ("RED at the pre-fix HEAD, GREEN after") and the MEASURE-FIRST RED/GREEN leg pairing are the precedents, per test-plan §3 Per-chunk gate discipline. For this chunk, the RED reading is taken against the named base `1dfca74`, per the scope's W182 directive.
- Mutation-checked discrimination: a guard counts as proven only when neutralising the thing it guards turns it RED. The §1 Pending coverage triggers rows cite "mutation-checked" as the landed-coverage standard (e.g. the `credit_card` precision cases at test-plan §4). A license witness should be shown to go red when the dual-license value or file is reverted.
- Tri-state xtask verdicts (exit 0 green · 1 findings red · 2 cannot-evaluate, one JSON verdict), as used by `check:npm-supply-chain` / `check:staged-artifacts` / `pre-push:linux`, per test-plan §3 and §9. If P4 makes the witness an xtask check, a missing input reads `cannot-evaluate`, never green.
- Test location/naming if the witness is a Rust test: co-located `#[cfg(test)] mod tests` in library crates, with `pulse-app` unit-shaped probes under `pulse-app/tests/*.rs`, per test-plan §2 Test directory + naming conventions and §4 Conventions. To narrow a pulse-app run, use `--workspace -E 'binary(…)'`, not `-p pulse-app`, per test-plan §3 5-command implementation.

## Anti-patterns to avoid
- NEVER make real network calls in a test. A witness must not fetch the SPDX list, the Apache/MIT canonical texts or Conductor's files over the network; it asserts against committed repo content only, per test-plan §11 Universal.
- NEVER weaken, skip or relax a supply-chain gate to get green: no `cargo deny` skip or ignore added for the project's own crates, no npm-policy exception for the root package's license, and no lowered threshold. Per test-plan §11 Test Strategy / CI ("NEVER lower coverage threshold to pass build" and the same class) and §9 Build failure conditions.
- NEVER call a witness proven when its reading is vacuous. A check that is green at the base as well as after the change (e.g. cargo-deny already license-checks own crates, so scope item 5's premise is at risk) is not a red-before/green-after witness, and P4 must pick a subject that is actually RED at `1dfca74`. Per the test-plan §3 wrong-reason-pass discipline (the Direct-binary smoke variant's "passes VACUOUSLY" rule).
