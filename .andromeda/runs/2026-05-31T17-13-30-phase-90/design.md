## Patterns to follow

- **Severity-to-halo mapping via `severity-to-halo.ts` helpers**: chunk #90 established `severityToHueFraction`, `severityToBlurPx`, `activityStateToBreathingPeriodMs`, `connectionStateToDim` as the canonical transformation layer. The dashboard `ConstellationCanvas` should import and reuse these helpers for per-service dot rendering — do NOT inline the mapping logic. (per design-tokens.md §Motion + `HaloCanvas.tsx` lines 38–41)
- **`HaloCanvas` props shape as the canonical API**: the existing `HaloCanvasProps` (`ariaLabel`, `connectionState: ConnectionState`, `cumulativeSeverity: PriorityTier | null`, `activityState: ActivityState`) is the established contract from chunks #90/#91 widget migration. The dashboard ConstellationCanvas cascade reuses this same prop shape per-service dot rather than inventing a new API. (per `HaloCanvas.tsx` lines 45–50 + design-system.md §Brand Identity "Signature element")
- **`readDesignToken(name, fallback)` pattern for CSSOM token reads**: the widget-side `HaloCanvas.tsx` reads `--color-primary` and `--color-accent` from CSSOM at pipeline init time (lines 127–128). The dashboard canvas must follow the same pattern for both token resolution AND the hardcoded-hex-in-shader prevention rule. (per design-tokens.md Session Additions 2026-05-08 + `HaloCanvas.tsx` lines 64–68, 127–128)
- **Reduced-motion static-glow path**: the existing `HaloCanvas.tsx` implements the `prefersReducedMotion` static-glow degradation — rAF loop suppressed, one static render per data change via `restartLoopRef`. The dashboard cascade must not regress this path when wiring per-service dots. (per design-system.md §Motion Accessibility + a11y rules §Motion)
- **Per-service dot seeded scatter positioning**: chunk #91 established brightness=activity, hue=severity, seeded-scatter layout for the widget ConstellationCanvas. The dashboard ConstellationCanvas mirrors this positioning model at full-window scale — dormant services dimmed, archived services hidden. (per route.md §2 Epoch 9 chunk #91 + #93 description)

## Anti-patterns to avoid

- **NEVER retain or reference `throughput-to-hz.ts` / `error-rate-to-blur.ts`** after this chunk. These files are the explicit deletion targets; any import left behind reintroduces the pre-v0.2.0 mapping model that chunk #90 superseded. The post-chunk state MUST have zero imports of these modules across the webview source. (per design-system.md §Motion Decisions Log 2026-05-29 + design-tokens.md §Motion "Supersedes the chunk #31-era 0.8–2.4 Hz figure")
- **NEVER use gradient overlays or glassmorphic effects on the dashboard ConstellationCanvas chrome** (outer containers, labels, legend). Only the `<canvas>` Halo glow layer itself (rendered by WebGPU shader) is permitted blur + radial-gradient. Any surrounding panel MUST be flat `--color-raised-1` / `--color-base` with borders-only depth. (per design-system.md §Anti-Patterns "NEVER gradient overlays" + §Depth Strategy)
- **NEVER encode severity or activity state using color alone** for per-service dot labels or legend text. Any text indicator of service health must pair the color with a text label or icon per the not-color-alone discipline. (per design-system.md §Anti-Patterns "NEVER use color purely for decoration" + design-tokens.md §Color palette; a11y binding below)

## Contract bindings

- **Design tokens ↔ a11y contrast**: `--color-primary` (`#4A90E2`) used as the Halo Earth Blue endpoint and `--color-accent` (`#C7556A`) as the Alert Burgundy endpoint must satisfy the non-text contrast thresholds (≥3:1 SC 1.4.11) against `--color-inset` (`#0F1117`) canvas background. Design system §Color Palette 2026-05-03 Decisions Log entry locked `#C7556A` specifically for this compliance. The contrast assertion is a11y's formal gate, but design token usage must stay on these locked values for the contract to hold.
- **Motion tokens ↔ a11y `prefers-reduced-motion`**: all Halo animation (breathing, LCH interpolation updates) MUST respect `prefers-reduced-motion: reduce` — Halo degrades to static glow, hue still updates per `cumulativeSeverity`, no animation loop runs. The `useReducedMotion` hook path in `HaloCanvas.tsx` is the canonical implementation; the dashboard ConstellationCanvas inherits this via `HaloCanvas` reuse (no separate implementation needed). (per design-system.md §Motion Accessibility + a11y rules §Motion)
- **State color + text label pairing ↔ a11y SC 1.4.1**: per-service constellation dots communicate severity state (Earth Blue → Alert Burgundy hue) as a data-driven visual. Any companion text labels, tooltips, or legend items for service health MUST pair color with a text descriptor — color alone is insufficient. This is a design anti-pattern ban that the a11y domain enforces via axe SC 1.4.1.
