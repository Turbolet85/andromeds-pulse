## Patterns to follow
- **Two-half stage verdict** — an obs-log half plus a DOM half, each asserted on a named field (the shipped precedent is `widget-close` requiring `ui.layout.transition {layout_mode_from, layout_mode_to}` AND `tray.signpost.shown {window_label}`, where bare record presence no longer satisfies). Whether the copy path emits any obs record at HEAD to serve as the obs half is research's question (per test-plan §6 Drivers per surface; §6 P5 Status).
- **Code-driven RED arm** — `cargo xtask webview-drive --no-inject --expect-absent &lt;STAGE&gt;`; every stage id is `--expect-absent`-eligible with no CLI change, and an unknown id is a hard error listing valid ids. Note the plan records the *capability-revoke* arm (the mutation that matches THIS defect) as still by-hand (per test-plan §6 Drivers per surface; §1 `webview-drive-mutation-arm-not-gated`).
- **Extend the existing `report-window` stage position** — the 15-stage path already opens the report window between `findings-window` and `investigate`; the plan also records that a stage which navigates routes or perturbs downstream window state killed a RED arm's WebDriver session, so placement is load-bearing (per test-plan §6 Drivers per surface).
- **Accessible-name press of a production control** — the shipped precedent is `button[aria-label="Investigate"]` / `button[aria-label="Close to tray"]`; the Copy control's anchor must be measured at HEAD, not assumed (per test-plan §6 Selector strategy).
- **Webview unit tier for any `use-report.ts` / `ReportRenderer.tsx` logic** — `vitest` 3.x + `jsdom` 26 + `@testing-library/react` 16, co-located `*.test.tsx`, JUnit XML to `target/junit-ui.xml`; this is the home for a copy-state / diagnostic assertion if scope item 4 lands one (per test-plan §4 Framework (webview unit tests); §1 Surfaces under test).

## Anti-patterns to avoid
- NEVER xpath, NEVER a brittle/hashed-class selector — both bans are operative now that the leg is DOM-driven (per test-plan §11 E2E).
- NEVER `sleep(N)` for synchronization, and no retry-once policy to paper over a flake — wait on an explicit signal; flake = real bug (per test-plan §11 E2E, §11 CI, §11 Quality).
- NEVER let a human-confirmed or screenshot-approved observation stand as the verdict, and NEVER let a one-time hand-run proof stand in for a per-run gate — the plan's standing remedy for the latter is to mint a §1 pending coverage trigger naming what is owed (per test-plan §11 Universal; §2 Agent-runnable invariants; §1 Pending coverage triggers).

## Contract bindings
- **tests ↔ obs** — if the discriminating copy-succeeded observable (scope item 3) or the de-silencing diagnostic (item 4) is an obs record, the stage's obs half greps the app's own NDJSON rotated family `agent-latest.jsonl*`, and the leaf must be obs-declared/allowlisted; the leaf and its fields are obs's call, tests bind to it through the harness log-format contract (per test-plan §3 Log format + `logs` verb; §6 Drivers per surface).
- **tests ↔ security/arch (capability gates)** — the plan states plainly that no shipped gate catches a left-revoked or mis-scoped grant: `capability-widening-check` covers only `pulse:notification` / `pulse:tray` / `pulse:plugin-fs` and only in the widening direction, while `capability-drift` diffs procedures parsed from bindings and never reads grants. `clipboard.json` is therefore statically ungated, which is exactly why the headful press is this chunk's regression guard (per test-plan §1 `webview-drive-mutation-arm-not-gated`; §3 standard gate set).
- **tests ↔ a11y** — the browser-driven a11y chain (`cargo xtask test:a11y`: Playwright + axe + pa11y + Lighthouse, real Chromium against built `ui/dist` with IPC mocked) is the second driver on this surface and IS CI-wired; if the Copy control's accessible name changes, that tier is where real-keypress DOM behaviour is pinned (per test-plan §6 Drivers per surface; §9 A11y suite).
