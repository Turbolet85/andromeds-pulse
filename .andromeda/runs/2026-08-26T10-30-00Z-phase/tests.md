## Constraints
- **A new public boundary that enforces the bound is owed a DIRECT in-crate test, not only coverage through its one caller.** Standard tier mandates all module boundaries tested at unit level (per test-plan §2 Test Strategy → pyramid Unit row); §1 records this exact failure mode twice as a minted gap (`buffer-log-seq-allocator-unit-coverage`, `viz-read-connection-router-wiring-coverage` — a single call site whose removal would leave every test green). If the ceiling lands as a `pub fn` in `crates/triage/src/cadence/`, §2 requires its own contract (monotonicity/refusal/reset arithmetic) pinned in-crate.
- **Clock injection, not ambient time.** test-plan §4 → What unit tests cover → triage crate requires the `triage` crate's convention: the instant is passed as an explicit `now_nanos` parameter rather than controlled via `tokio::time::pause()`, "because these functions take the instant as an argument and there is no ambient clock to control" — stated there as the stronger form. Where a new cadence limiter instead reads an ambient clock, §7 Test Data & Fixtures → Time-sensitive data requires `tokio::time::pause()` + `advance()`.
- **The unconditional standard gate set applies regardless of scope**, including `cargo xtask check:ingest-progress` and with `cargo xtask capability-drift` LAST (per test-plan §3 Per-chunk gate discipline). §3 records that gate's four verdict arms (`buffer.consumer.stalled` with `reason != recovered` ⇒ exit 1 · recovery ⇒ green · advancing ticks ⇒ PASS · no `buffer.tick` ⇒ NEUTRAL); the chunk's scope forbids modifying it, so this domain's requirement is that it be listed and run, unchanged.
- **Load-shaped tests join the `load-profiles` nextest profile, never `#[ignore]`** (per test-plan §10 → Load profiles). §10 also fixes the `high` profile's assertion as *L1a Q1–Q7 p99 < 500 ms at production 20s cadence* — the same Q1–Q7 surface the chunk's scope names as the multiplied work — and holds a zero-flakiness budget (a flake is quarantine + root-cause, never a retry).
- **`pulse-app` unit-shaped probes live in `pulse-app/tests/*.rs`, reaching internals via `pub` + `#[doc(hidden)]`** (per test-plan §4 Conventions → Test file location, and §2 Directory pattern) — `[lib] test = false` makes a co-located `mod tests` compile but never run. This binds any pin on `digest_runtime.rs::spawn_cadence_subscriber` or the `main.rs` runtime builder.
- **Run-scope must match build-scope:** narrow a `pulse-app` run with `--filter-expr` / `-E` under `--workspace`, not with `-p` (per test-plan §3 → `run` → Test selection, measured 2026-08-15).
- **Fixtures self-bootstrap; no pre-baked data** (per test-plan §7 Self-bootstrapping requirement + §11 Test Data). §3 Bootstrap item 6 records that all three builder factories (`MockTraceSpan` / `MockArrowBatch` / `MockMetricPoint`) are specified-but-unimplemented, so a load or cadence fixture must seed over the live receiver or by direct in-memory DuckDB inserts plus `rstest`.

## Patterns to follow
- **Direct-binary smoke variant** (per test-plan §3 Per-chunk gate discipline) — the accepted form for exactly this chunk's shape: fresh `ANDROMEDA_PULSE_DATA_DIR` per leg, a sustained `inject_demo` OTLP load, verdict read from the run's own `agent-latest.jsonl*` artifacts (0 `app.panic.fatal`, 0 ERROR), clean shutdown by specific pid with `:4317`/`:4318` confirmed released. §3 further scopes the clean-log assertion to the **GREEN leg only** for measure-first chunks, since a RED leg must produce the ERROR it measures and records it as evidence, not gate failure.
- **Rotated log-family resolution** (per test-plan §3 → `logs`): read `agent-latest.jsonl*` across the three precedence-ordered bases, newest match in the first base that resolves — never a bare name, never a `*.log` glob. Load-bearing here because the chunk's own evidence file is date-suffixed (`agent-latest.jsonl.2026-08-25`) and a bare-name reader false-reports an empty log.
- **Two-half verdict with effect-FIELD predicates** (per test-plan §6 → Drivers per surface): the driver reports, the Rust caller asserts, and every predicate matches an effect FIELD, never the target alone. Applied here: a bound assertion should read a *value* (trigger count per window, refusal counter) rather than the mere presence of `cadence.trigger`.
- **Discriminating (mutation-checked) pin** — the precedent §1 sets at `redaction_counter_folds_once_per_batch_across_all_four_builders` (neutralize the guarded sites ⇒ RED) and at the two open "one-time proof standing in for a gate" rows (`webview-drive-mutation-arm-not-gated`, `window-navigation-check-behaviour-unit-coverage`). Per those §1 rows, a live observation of a healthy run is explicitly *not* a regression guard.
- **Concurrency-shaped integration setup** (per test-plan §5 → Setup / teardown lifecycle): `#[tokio::test(flavor = "multi_thread")]` with per-test `tempfile::TempDir` + `open_in_memory()`, no shared session state.

## Anti-patterns to avoid
- **NEVER `sleep(N)` for synchronization, and NEVER real wall-clock time without injection** (per test-plan §11 → E2E + §11 → Universal) — wait on an explicit signal (status poll / channel event / log record). Acutely relevant: a rate-ceiling test is the archetypal place a wall-clock sleep gets smuggled in.
- **NEVER add a retry-once policy or tolerate a flake** (per test-plan §11 → Quality + §10 Zero-flakiness budget) — a flake is quarantined and root-caused, on the stated ground that agent-driven development cannot distinguish flake from real bug.
- **NEVER over-mock at the integration level** (per test-plan §11 → Test Strategy + §11 → Mocking) — drive the live loopback receivers and an in-memory DuckDB; mock only traits you own via constructor-injected `Arc<dyn Trait>`.

## Contract bindings
- **tests ↔ obs (log format).** test-plan §3 → Log format + Agent-parseable signals binds the harness to obs-plan §3's NDJSON records/fields; any assertion on the bound greps/jq-extracts `cadence.trigger` / `cadence.tick` (scope: `TARGET_CADENCE_TRIGGER` / `TARGET_CADENCE_TICK`, `cadence/mod.rs:42-43`). obs owns declaring the record + fields; tests own the family-resolved read path and the assertion.
- **tests ↔ obs (drain gate).** `cargo xtask check:ingest-progress` in the §3 standard gate set keys on obs's `buffer.consumer.stalled` / `buffer.tick` pair. The chunk's Outcome 2 is to make that gate's RED arm unreachable in practice while leaving the gate itself untouched.
- **tests ↔ obs (budget authority).** test-plan §10's frame-budget note establishes the standing rule that obs-plan §10's ms-form `metric.*` values govern over test-plan's descriptive figures. If this chunk states its ceiling as a numeric budget, the asserted form binds to obs's `metric.*` declaration, not to prose here.
- **tests ↔ obs (status readiness).** §3 Status endpoint shape supplies `subsystems.buffer.rows_ingested` as the drain-progress read; §3 also warns `bash scripts/agent-run.sh status` exits 0 against a dead system, so it evidences the harness contract, never that this run was live.
