# arch extract

## Relevance
Relevant — the chunk lands product code in a locked workspace crate (`crates/triage`) plus the `pulse-app` binary, touches the single-runtime decision, and may add a new tunable/registry resource.

## Constraints
- The single multi-threaded tokio runtime is a locked decision serving both OTLP ports, IPC, and every `spawn_blocking` user (arch §Stack and Technologies → Async runtime; §Inherited Defaults). The bound must be implemented inside that one runtime — a second runtime, a dedicated blocking executor, or a `crossbeam` bridge is a decision change, not an implementation choice (arch §Established Decisions [In-Process Channel Architecture] rejected `crossbeam-channel` explicitly for the pure-tokio stack).
- The ingest→appender substrate is locked: bounded `tokio::sync::mpsc` with built-in backpressure for the hand-off, `tokio::sync::broadcast` for buffer→subscriber fan-out (arch §Established Decisions [In-Process Channel Architecture]). The scope's "no change to the ingest→buffer substrate" boundary is this decision restated; a bound realized by re-typing `CadenceTriggerChannel`'s carrier or widening a buffer would collide with it.
- Workspace crate names are reserved and cannot be re-purposed; `triage`, `pulse-app` and `xtask` are on the locked list, and no new crate name may be introduced for this work (arch §Occupied Resources → Cargo workspace crate names).
- Dependencies flow toward `pulse-app`; no library crate depends on the binary, and the graph is a DAG with `pulse-app` as the only root (arch §Cross-cutting Patterns → Module dependency direction). A bound expressed in `crates/triage` therefore cannot read `pulse-app`'s runtime builder, and a runtime-level bound (`max_blocking_threads`, which the scope permits only as a documented companion) can only live in `pulse-app`.
- Any duration-shaped tunable this chunk introduces must be seconds with the unit in the field name (`*_seconds`), and any port-shaped value `u16` + `TryFrom` (arch §Conventions → Configuration units). Layered precedence is env `ANDROMEDA_PULSE_*` > `~/.andromeda-pulse/config.toml` > built-in defaults (arch §Cross-cutting Patterns → Config management; §Inherited Defaults).
- Every new env var, IPC procedure, or `pulse://stream/*` topic must be registered in arch §Occupied Resources; a new TauRPC procedure additionally requires its `EXPECTED_PROCEDURES` pin in `xtask/src/main.rs` (the `capability-drift` gate's diff target) and NOT a capability-JSON edit (arch §Cross-cutting Patterns → Webview IPC capability policy). Whether the chunk needs any such new surface at all is research's question.
- The product's own telemetry — including any counter this chunk adds for suppressed/admitted triggers — goes only to `opentelemetry-stdout` / the file exporter under `~/.andromeda-pulse/logs/`; the product never dials its own `:4317`/`:4318` (arch §Established Decisions [Self-Observation]; §Cross-cutting Patterns → Self-observation discipline).

## Patterns to follow
- **Production-consumed bounded env override in `crates/triage`** — arch §Occupied Resources registers `ANDROMEDA_PULSE_BASELINE_BOOTSTRAP_SECONDS` (`crates/triage/src/cue/thresholds.rs`) as the shape: bounded parse with an explicit valid range, whitespace-trimmed, every rejection falling back to the default without a panic, resolved ONCE at boot and handed to the consumers so they share ONE bound, with a single WARN per boot when a non-default value is resolved. This is the nearest precedent for a cue/cadence-path ceiling knob.
- **Bounded-invocation defense-in-depth** — arch §Established Decisions [LLM Inference Runtime] states the project's established answer to unbounded work: layered ceilings (`-n` cap + `-st` + an outer wall-clock `tokio::time::timeout`), each independently sufficient, rather than a larger resource pool. A cadence bound should be stated the same way — an enforced ceiling at the origin plus a stated outer guard.
- **Crate contract module as the only `pub` surface** — each crate exposes its public contract via `pub`, internals stay `pub(crate)`, no cross-crate `pub use` re-exports outside the contract module (arch §Conventions → Module visibility discipline; §Project Intent → Template patterns). A bound type that `pulse-app`'s `digest_runtime` must see belongs in `triage`'s contract module; one confined to the coordinator stays `pub(crate)`.
- **Sustained-load evidence over the real wire** — arch §Cross-cutting Patterns → Test-time telemetry injection requires synthetic telemetry to enter by speaking OTLP to `:4317`/`:4318`, with no in-process bypass, no test-ingest feature flag, no mock-channel back-door; §Stack (GUI verification harness row) records `crates/ingest/examples/inject_demo --sustained` (unbounded, moderate error rate, `--minutes=N`, range-checked `--error-pct`) as the sanctioned generator, existing precisely to remove the finite-storm ageing-out false negative.
- **`cargo xtask` as the task surface** — all shared CI/verification logic that needs Rust lives in the `xtask` crate so the same command runs locally and in CI (arch §Infrastructure Patterns → CI/CD approach; §Cross-cutting Patterns → Development Style: agent-driven, deterministic harness invocations + machine-parseable output).

## Anti-patterns to avoid
- Introducing a second async runtime, a `crossbeam` bridge, or a separate blocking executor to absorb the flood — the single-tokio-runtime and mpsc/broadcast decisions are locked (arch §Established Decisions [In-Process Channel Architecture]; §Stack → Async runtime).
- Adding an unregistered resource: a new env var, stream topic, or IPC procedure that does not land in arch §Occupied Resources (and, for a procedure, the `EXPECTED_PROCEDURES` pin) is a registry breach regardless of how small the code change is (arch §Occupied Resources; §Cross-cutting Patterns → Webview IPC capability policy).
- Proving the bound with an in-process injection path or a test-only feature flag instead of real OTLP on the receiver ports (arch §Cross-cutting Patterns → Test-time telemetry injection).

## Contract bindings
- **arch ↔ obs** — any counter/gauge this chunk adds for admitted-vs-suppressed triggers routes through the self-observation exporter to `~/.andromeda-pulse/logs/` per arch §Cross-cutting Patterns; the target name, level, and the exact label allowlist leaf are obs-plan's (arch registers only that `TARGET_CADENCE_TICK`/`TARGET_CADENCE_TRIGGER` live in `crates/triage/src/cadence/`). obs-plan §10 is cited by the scope as the load-constraint/isolation-topology owner.
- **arch ↔ tests** — the sustained-load leg's telemetry source is fixed by arch (real OTLP, `inject_demo`); the stage list, budgets, and gate wiring are tests' to specify. Note arch §Stack records that `xtask::webview_drive` threads NO arguments to the injector (`PULSE_INJECTOR` carries the path only), so the existing headful leg always runs the arg-less finite storm — a sustained leg needs its own invocation path.
- **arch ↔ security** — a new env var inherits the bounded-parse / never-panic / never-log posture arch records for the `ANDROMEDA_PULSE_*` set; the confinement carve-outs are security-plan's.
- **arch ↔ config** — if the bound becomes user-facing rather than env-only, it enters the `config.toml` + `config.reload`/`config.status` hot-apply path (`crates/config-watcher`, arch §Occupied Resources), which the 2026-08-16 amendment notes was deliberately declined for the sibling triage bound.

## Acceptance criteria contributions
- (arch) The bound's code lives in `crates/triage` (cadence/cue) and/or `pulse-app`, with no new workspace crate and no library→binary dependency edge (per arch §Occupied Resources → Cargo workspace crate names + §Cross-cutting Patterns → Module dependency direction).
- (arch) No substrate change: ingest→appender remains bounded `tokio::sync::mpsc`, fan-out remains `tokio::sync::broadcast`, and no second runtime or non-tokio channel is introduced (per arch §Established Decisions [In-Process Channel Architecture]).
- (arch) Any new tunable is seconds-suffixed and honours env > `config.toml` > default precedence; if it is an env var it is registered in §Occupied Resources with a stated valid range and a never-panic fallback (per arch §Conventions → Configuration units + §Cross-cutting Patterns → Config management + §Occupied Resources).
- (arch) The sustained-load evidence for the bound enters over real OTLP on `:4317`/`:4318` with no in-process bypass, and the app's own new counters reach only the stdout/file self-observation sink (per arch §Cross-cutting Patterns → Test-time telemetry injection + Self-observation discipline).
