- §10 DuckDB Connection Isolation requires any DuckDB consumer with a multi-second statement to hold a dedicated `try_clone()` connection (write/sweep/read topology; L1a and viz already named in the isolated set). obs-plan mandates **no** blocking-pool-depth instrument anywhere — so if this chunk introduces one, it is a brand-new registration subject to the dual/triple-site rules below, not an existing mandate.
- Site-count rules for the resulting amendment: a NEW target is a dual-site apply (§6 log-level mapping with its emission discipline + §8 exact leaf); a tick that GAINS fields is a triple-site apply (§1 Heartbeat ticks field list + §5 Counter row + §8 module whitelist) — per §8/§6 as applied by the predecessor chunk.

## Patterns to follow
- The `buffer.consumer.stalled` transition-WARN shape (§6 warn row + §8 exact leaf): bounded static `reason`/`consequence` tokens plus numerics, fired once per transition and once on recovery, with the firing threshold sited above the in-spec operational cap so a legitimate condition cannot trip it. This is the direct template for a cadence-bound / trigger-throttle signal.
- Tick-aggregated counter fields (§5 Counter rows — `record_feed_counts`, `record_redactions`, `rows_ingested_delta` / `last_append_age_seconds`): fold per batch or per interval at a site where the outcome is already known, ride out on the existing 15s tick, aggregate counts only.
- EXACT-leaf guard placement (§8, bootstrap-window and consumer-stall notes): guards live under `pulse-app/tests/` because `[lib] test = false` compiles but never runs a src-level `mod tests` guard; include a fallback-discrimination test so the guard cannot pass vacuously once the leaf is deleted, and mutation-check it.
- Naming: spans `{module}.{operation}` with `span.kind = "internal"` for internal operations (§4 Span naming / Span kind convention); metric events `metric.{module}.{measure}` with a numeric `value` plus enumerated label fields (§5 Metric emission convention).
- Warn-on-fallback shape for a resource-degradation signal (§10 DuckDB Connection Isolation, `viz.query` with `fallback = "shared_connection"`): name the fallback that was taken rather than only the failure.

## Anti-patterns to avoid
- Never emit per-trigger, per-rejection, or per-suppressed-cycle at `info` on the cadence path (§11 Telemetry Strategy: no over-instrumenting hot paths; §11 Logs: no `info` in hot path) — that reproduces the flood in the log file.
- Never attach an unbounded label to a new cadence/trigger metric (cue id, trigger id, incident id, client-supplied `service_name`) — §11 Metrics + §5 cardinality discipline permit enumerated values only, with the query-time-aggregation exception not applying here.
- Never state the loop's ceiling as a soft budget (§11 SLO: no unenforced SLO budgets; §10 CI gates) — a stated bound needs an assertion that fails, not a documented number.
