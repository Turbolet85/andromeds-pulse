- A plan touching `pulse-app/src/main.rs` or `pulse-app/src/observability.rs` (the exit hook and its flush sit on the boot/subscriber path) MUST add the runtime boot-smoke gate. The direct-binary variant (fresh `ANDROMEDA_PULSE_DATA_DIR`, launch the binary by path, teardown by specific pid, `:4317`/`:4318` confirmed released) is the accepted form when the leg needs state the dev-CLI form cannot express, such as an induced exit (per test-plan §3 Per-chunk gate discipline → Boot-smoke gate / Direct-binary smoke variant). Any run that launches pulse-app needs an operator slot (scope §Boundaries).
- The clean-log assertion (0 `app.panic.fatal` / 0 `ERROR`) binds the GREEN leg only. An exit-cause witness is BLOCK-shaped at the base: the defect is a missing record. So a RED leg there passes a clean-log check VACUOUSLY, and its evidence must be the ABSENCE of the cause record. Decide the shape before choosing evidence, and give each leg its own fresh data dir (per test-plan §3 Direct-binary smoke variant).
- Witness reads MUST resolve the rotated log family `agent-latest.jsonl*` (the daily sink date-suffixes every file), never a bare name (per test-plan §3 `logs`). Whether a line written just before exit survives the non-blocking appender is the property under test, not an assumption.
- The harness's existing exit instruments are §3 `status`'s `ended` field (bounded to ≤ 48 printable ASCII, one line) and the `boot` wrapper's `run/andromeda-pulse.exit` record. They are harness-only and record HOW the app ended, not WHY. The new in-app cause record complements them. Changing their grammar or arms is a contract change (per test-plan §3 `status` / `boot` / PID file).
- pulse-app is `[lib] test = false`, so new pulse-app tests live in `pulse-app/tests/*.rs`. The flat-zero ratchet `pulse_app_src_carries_no_new_dead_test_attributes` forbids `#[test]` in lib sources (`main.rs` exempt). An `[[example]]` used as a test carrier needs `test = true`, or nextest collects nothing (per test-plan §2 Test directory conventions; §1 `inject-demo-arg-parse-unit-coverage` correction).
- The Linux CI `boot` job is GATING. It is the only runner-side observation of the 69f0b93 death class: `agent-run.sh boot`/`status`/`cleanup` under `xvfb-run`, then `cargo xtask ci-gates` over the smoke's log, with `logs-boot-*` uploaded `if: always()` (per test-plan §9 Boot smoke row). `pre-push:linux` has no boot stage (per test-plan §3 `pre-push:linux`), so the Linux exit class cannot be reproduced on the dev host.

## Patterns to follow
- **Scenario-leg shape** for any new Pulse-side xtask witness. Exit 0 PASS · 1 FAIL · 2 INCONCLUSIVE. The leg proves its own preconditions: an unmet precondition is INCONCLUSIVE, never PASS. It refuses a window that cannot reach a verdict, and writes artifacts under `target/<leg>/`. It stays dev-host and off the standard gate set unless deliberately CI-wired (per test-plan §3 `smoke:hue-shift` / `smoke:discovery` legs).
- **Measure first, RED→GREEN.** Run the same direct-binary form at the base (`a2addb3`) and after the fix, one induced exit per loggable class. Record the expected RED-leg readings as evidence, not as gate failures (per test-plan §3 Direct-binary smoke variant).
- **Mutation-check every new pin.** Neutralizing the cause emit or the flush must redden it. A live observation alone is the recorded "one-time proof standing in for a gate" class. If a committed test cannot carry an arm, record it as a new §1 pending trigger instead of leaving it implicit (per test-plan §1 Pending coverage triggers, e.g. `discovery-observer-wiring-coverage` / `llamacli-inference-error-emission-coverage`).
- A new tracing target gets its exact allowlist-leaf pin in a `pulse-app/tests/*.rs` allowlist test, plus a per-category emission assertion. The `llamacli-inference-error-emission-coverage` row shows the gap when only the leaf is pinned (per test-plan §1).
- **P-025 is graded by Conductor's live leg.** The Pulse-side `smoke:hue-shift` / `smoke:discovery` legs grade observable anchoring only, with the budget as context. A Pulse-side measurement alone does not verify a Conductor-graded budget (per test-plan §3 `smoke:hue-shift`; scope §The P-075 claim).

## Anti-patterns to avoid
- NEVER treat the 1-in-2 CI boot death as resolved by its green re-run. A flake is a real bug: root-cause it, no retry-once disposition (per test-plan §10 Zero-flakiness budget; §11 Quality).
- NEVER synchronize an exit witness with `sleep(N)`. Wait on an explicit signal: process reaped, pid dead, log record present (per test-plan §11 E2E).
- NEVER let a manual or one-off observation stand as the verification. Every check must exit with a machine-parseable verdict. External evidence is cited (Conductor's paths), never approved by eye (per test-plan §11 Universal; §2 Agent-runnable invariants).

## Contract bindings
- **tests §3 `logs` ↔ obs §3 log file location / §8 allowlist.** The new exit-cause target needs its exact allowlist leaf, and its fields must be bounded: no full paths (`log_basename`), no payload content. obs owns the schema and the appender-guard drain; tests owns the witness that reads it back after process end.
- **tests §3 `status` `ended` / `boot` exit recorder ↔ security harness-only state-file carve-out** (`run/andromeda-pulse.{spawn,exit}`, never read by the product). These instruments must stay harness-only.
- **tests §9 Boot smoke ↔ ci.yml `boot` job + `cargo xtask ci-gates`.** The runner-side observation that the next unexplained death names itself.
- **tests §6 P3 / §1 `mcp-incident-read-back-cross-process-coverage` ↔ the P-075 MCP read-back.** Conductor's external round asserts content fidelity through MCP. Pulse's committed cross-process content coverage for `retrieve_telemetry_slice` / `retrieve_report` / `query_incident_list` is still owed per §1. External smoke evidence is not a committed regression guard; whether this chunk discharges any of it is a scope question.
- **tests ↔ Conductor contracts (external, read-only).** `pulse-p025-measurement-contract.md` and `pulse-capabilities.toml` define what is graded. Which contract file defines the P-075 round, and which Pulse sha it runs against, is research's question.

## Acceptance criteria contributions
- The standard gate set passes in the mandated order and ends with the bindings close against the chunk base: `git diff --quiet a2addb3 -- pulse-app/ui/src/bindings/index.ts` exits 0 if no procedure is added, else the staged-bindings sequence (per test-plan §3 Per-chunk gate discipline).

Any arm left without a committed test is recorded as a §1 pending trigger. Workspace coverage stays ≥ 75 % line / ≥ 70 % branch / ≥ 85 % function (per test-plan §2 Test directory conventions; §1; §10 Coverage thresholds).
- The Linux CI `boot` job on the chunk's pushed sha reads `running-healthy` with `ci-gates` green, and the `logs-boot-*` artifact is uploaded (per test-plan §9 Boot smoke row).
