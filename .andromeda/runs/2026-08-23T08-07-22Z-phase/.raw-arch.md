# arch extract

## Relevance
Relevant — the chunk edits an arch-owned convention (the `metrics_points` primary key), a registered DuckDB table, and the sanctioned E2E injection route; workspace placement applies throughout.

## Constraints
- The metric-point key is arch-stated **by column** — `metric_name` + `ts_unix_nano` + `resource_hash` (per `.andromeda/architecture.md` §Conventions → Primary key convention). That line is the target-state spec, not an observation of code; changing the key changes an arch convention and therefore obliges an amendment at wrap. Whether the DDL at HEAD already matches that line in all three representations is research's question.
- **No UUID or random surrogate keys.** §Conventions → Primary key convention names `seq` as *the one declared exception*: a monotonic in-process ordinal allocated per batch. Any discriminator this chunk adds to `metrics_points` must be of that same class — an internal ordinal — not a random or content-hashed surrogate (per §Conventions → Primary key convention).
- **The ordinal must stay non-observable.** §Conventions → Primary key convention requires `seq` to be absent from `BufferStateSnapshot`, `buffer.tick`, the `viz` `SELECT_LOGS` column list and the MCP response shape. The metrics analogue must likewise stay out of `SELECT_METRICS`, `COUNT_METRICS`, the `metrics.*` IPC response and the MCP `query_metrics` response — that non-observability is what keeps the reader blast radius zero (per §Conventions → Primary key convention).
- **Workspace placement is locked.** `buffer`, `viz`, `ingest`, `mcp-server` are reserved names that cannot be re-purposed (per §Occupied Resources → Cargo workspace crate names); schema/appender/retention work belongs in `buffer`, the query fixture in `viz`, the OTLP producer example in `ingest`. No library crate may depend on a sibling unless its declared contract requires it, and the graph must stay a DAG rooted at `pulse-app` (per §Cross-cutting Patterns → Module dependency direction).
- **The measurement route is fixed by arch, not by the tests plan.** E2E injection speaks OTLP to `:4317` / `:4318` — the same surface external SDKs use — with *no in-process test-mode bypass, no separate "test ingest" feature flag, no mock-channel back-door*; tests needing buffer state read it back through the TauRPC `metrics.*` query router, and a non-default port resolves via `ANDROMEDA_PULSE_OTLP_{GRPC,HTTP}_PORT` (per §Cross-cutting Patterns → Test-time telemetry injection). The producer this chunk needs must emit spec-conformant classic OTLP with no project envelope (per §Established Decisions → [OTLP Wire Format Coverage] and [API Style — OTLP Receiver Surface 1]).
- **New columns follow the column rules**: `snake_case`; nanosecond precision carried as a sibling `BIGINT ts_unix_nano` next to a `TIMESTAMPTZ`; nullable reserved for OTLP-spec-optional fields, required spec fields `NOT NULL` (per §Conventions → Database entity naming, Timestamp handling, Nullable patterns). A label representation is OTLP-spec-optional, so nullable is permitted.
- **If the label half lands as a side table**, the table name is a registered resource — §Occupied Resources is the canonical table list and the Convention defines only the shape (per §Conventions → Database entity naming; §Occupied Resources → DuckDB database / schema names) — and it must enter the periodic retention `DELETE … WHERE ts &lt; cutoff` sweep, since the buffer is in-memory ring-buffer-only with no migration layer (per §Established Decisions → [ORM / Migrations] and [Telemetry Retention Surface]).

## Patterns to follow
- **The `log_records` / `seq` shape as the in-repo identity-ordinal precedent** — a buffer-owned monotonic counter, reserved once per batch, with the `viz` fixture mirroring the allocator (per §Conventions → Primary key convention). Reuse the shape; the per-batch-resetting `event_index` variant is explicitly rejected (see Anti-patterns).
- **Contract-module visibility** — each crate exposes only its public contract via `pub`, internals are `pub(crate)`, and no `pub use` crosses a crate boundary except in that crate's explicit contract module (per §Conventions → Module visibility discipline; §Project Intent → Template patterns). An ordinal allocator shared between `buffer::state` and `buffer::appender` stays `pub(crate)`.
- **Arrow zero-copy write path** — DuckDB writes go through `Appender::append_record_batch()`, one record-batch builder per table, with no ORM marshalling (per §Inherited Defaults → Columnar interchange; §Established Decisions → [ORM / Migrations]).
- **Registry-amendment-at-wrap** — a changed key or a new reserved table is recorded by an amendment entry against §Conventions / §Occupied Resources; the 2026-05-21 `log_templates` registration and the 2026-08-22 PK restatement are the two shapes to follow (per §Occupied Resources → DuckDB database / schema names).

## Anti-patterns to avoid
- **Random/UUID surrogate key, or a per-batch-resetting ordinal.** §Conventions → Primary key convention records the `event_index`-style ordinal as REJECTED for a table with no unique parent scoping its key; `metrics_points` has no `(trace_id, span_id)`-equivalent parent either, so a per-batch reset would leave two same-timestamp points in different export batches both at index 0.
- **Any in-process shortcut for the RED/GREEN measurement** — a test-mode bypass, a `test-ingest` feature flag, or writing record batches directly to the appender in place of speaking OTLP (per §Cross-cutting Patterns → Test-time telemetry injection).
- **Minting a reserved DuckDB table with no producer.** §Occupied Resources → DuckDB database / schema names now records `resources`, `instrumentation_scopes` and `span_links` as declared-and-swept but never written, with three retention DELETEs sweeping permanently-empty tables. A label side table landing without a producer and without a sweep reproduces exactly that defect class.

## Contract bindings
- **arch ↔ security** — collision source (2) is the ingest-boundary scrub of `metric_name`; arch owns the table registry and the key, security owns the scrub set. If a label column lands, its values are client-controlled text, which is the property §Occupied Resources → DuckDB schema names cites as putting a column in the PII frame at all — so the label half moves a new column into security-plan's scrub-coverage remit.
- **arch ↔ tests** — arch fixes *how* telemetry may be injected (OTLP only, readback via `metrics.*`) per §Cross-cutting Patterns → Test-time telemetry injection; tests owns the harness invocation surface and commands. The `crates/ingest/examples/` OTLP producer is the shared artifact between the two.
- **arch ↔ obs** — the whole-batch append failure surfaces on a `tracing` target, and the chunk's own "the ordinal makes the label loss SILENT" consequence is a signal question obs owns; arch constrains only the IPC error envelope (`AppError::Storage { message }` / `Ingest { message }`) if the condition crosses the bridge (per §Conventions → Error response schema (Tauri IPC)).
- **arch ↔ design/viz** — if labels reach the `metrics.*` response shape, every cross-bridge type must be `serde::Serialize` and the frontend consumes only TauRPC-generated `.ts` bindings, which regenerate (per §Cross-cutting Patterns → Cross-bridge data shape; §Conventions → Workspace API style). The `xtask` `EXPECTED_PROCEDURES` pin only moves if a *new procedure* lands, not for a changed payload (per §Cross-cutting Patterns → Webview IPC capability policy).

- (arch) Both the RED and the GREEN measurements inject over OTLP on `:4317`/`:4318` with no in-process bypass, test-only feature flag or mock-channel back-door, and inspect buffer state through the `metrics.*` query router (per architecture.md §Cross-cutting Patterns → Test-time telemetry injection).
