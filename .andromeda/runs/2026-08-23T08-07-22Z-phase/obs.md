## Constraints
- The qualifying end-to-end measurement's agent-readable surface is the JSON-per-line log at the §3 "Log file location" path, in the §3/§6 log-format schema (`timestamp`/`level`/`target`/`message`/`fields`); evidence must be read from that file, not from stderr scrape (per obs-plan §3 Logging stack + §6 Log Coverage "Required fields").
- Module-boundary errors — explicitly including DuckDB errors — are required to be logged at WARN/ERROR with trace context and an error **category**, never a full stack trace (per obs-plan §10 "Standard+ invariants" → Module-boundary error logging; §7 Vector 2 sanitization). The scope's observed whole-batch `tracing::error!(target: "duckdb.append", …)` is the shape this mandate calls for; whether the current emission already carries a category field rather than a raw error string is research's question.
- `duckdb.append` is required to carry `duration_ms` + `rows_appended` as span attributes on the P1 must-trace chain (per obs-plan §4 Scenario P1 "Required span attributes"). The scope reports `record_rows_appended` being skipped on batch rejection; whether the metrics path emits these attributes at all today is research's question, and any key change must not remove them.
- `redactions_applied` counts redactions to **persisted cells only**, and its registered scope explicitly names the `metrics_points.metric_name` write boundary as one of the four builders folding into it (per obs-plan §5 Metric Coverage → tick-aggregated Counter row, scope widened 2026-08-23). A batch that scrubs the metric name and is then rejected at `flush()` would have folded a count for a cell that never persisted — whether the current fold reconciles rejection with the persisted-cells rule is research's question, and it bears directly on this chunk's source-(2) redacted-name collision.
- Counters born of ingestion volume must fold **once per batch** and ride out as FIELDS on the existing 15s `buffer.tick`, not as per-point events or new `metric.buffer.*` targets (per obs-plan §5 tick-aggregated Counter rows; §11 Telemetry Strategy hot-path rule).
- Any new or changed emission target/field on the buffer path requires an EXACT §8 allowlist leaf enumerating **every** field its emit site emits — `for_target`'s prefix fallback otherwise resolves a dotted target to an unrelated field set and silently redacts it (per obs-plan §8 "Default-deny posture", `buffer` whitelist + the `app.boot.*` leaf precedents).
- Metric-point label/attribute values are raw OTLP payload, classified High / scrub-required: only counts and bounded tags may be emitted, never the attribute dict or its values (per obs-plan §8 Data classification "Raw OTLP telemetry payloads" → Vector 1). This binds the label-half decision whichever way it lands.

## Patterns to follow
- Tick-aggregated counter as a `buffer.tick` field, folded once per batch by a `BufferState::record_*` method — the established shape for both the feed counters and `redactions_applied` (per obs-plan §5 tick-aggregated Counter rows; §1 Heartbeat ticks `buffer.tick` field enumeration).
- Restating-site discipline: the `buffer.tick` field set is stated at **three** sites (§1 Heartbeat ticks, §5 Metric Coverage, §8 `buffer` whitelist); a change applied to one leaves the others stale (per obs-plan §1/§5/§8, and the 2026-08-22 amendment's explicit three-site note).
- Allowlist guards live under `pulse-app/tests/` rather than a src-level `mod tests`, because `[lib] test = false` compiles but never runs them (per obs-plan §8 `triage.baseline.bootstrap_window.override` + `interpretation.incident.created` leaf notes).
- Injection-canary verification: emit a canary through the real producer path, then assert the literal appears **0** times in the obs log while the aggregate counter advances (per obs-plan §5 `redactions_applied` row; §1 telemetry trigger "logging-sensitive" Vector 1 negative test). This is the pattern the chunk's OTLP producer measurement should reuse.
- Any xtask/check script reading `agent-latest.jsonl` must be NEUTRAL-tolerant — an absent stream is not a failure — so headless and booted runs share one script set (per obs-plan §10 "Load-profile constraints").

## Anti-patterns to avoid
- Never instrument the appender inner loop or per-row/per-data-point operations (per obs-plan §11 Telemetry Strategy) — the collision measurement must not add per-point emissions to `collect_metric_points`/`push_metric_row`.
- Never log raw OTLP attribute values; only `attributes_count` + a bounded service tag (per obs-plan §11 Spans/Traces + Logs; §8 Vector 1). If the label half lands this chunk, stored labels must not become log fields.
- Never introduce an unbounded label on a `metric.*` event or a tick field — metric names and label sets are client-controlled (per obs-plan §11 Metrics; §5 "Metric label cardinality discipline"; the only sanctioned exception is query-time `service_name`).

## Contract bindings
- **obs ↔ tests:** the log-format JSON schema is verbatim from the tests harness contract and obs aligns to tests, not vice versa (per obs-plan §3 "Log format JSON schema" / §6) — the chunk's read-back assertions consume this shape.
- **obs ↔ security:** metric-point labels and the scrubbed `metric_name` sit on Vector 1 (raw OTLP payload) and the `*_SECRET`/`*_TOKEN`/`*_KEY`/`*_PASSPHRASE` redaction convention (per obs-plan §8 Data classification rules) — the redacted-name collision pair is generated by that scrubber.
- **obs ↔ arch/buffer identity:** if the ordinal fix removes the loud whole-batch ERROR, the §10 module-boundary-error invariant no longer surfaces the label loss; the resulting silent-loss consequence is the evidence the chunk's CARRY (or in-chunk decision) must carry — the span-side drop-observability CARRY itself is owned elsewhere per the chunk scope.

## Acceptance criteria contributions
- Metric-point label values and the redacted-name canary literals appear **0 times** in `agent-latest.jsonl` across the measurement run; only counts/bounded tags present (per obs-plan §8 Data classification "Raw OTLP telemetry payloads" → Vector 1, and §11 Logs).
- No per-point or per-row emission added to the metrics collect/push path; any count introduced folds once per batch and rides `buffer.tick` (per obs-plan §5 tick-aggregated Counter rows and §11 Telemetry Strategy hot-path rule).
