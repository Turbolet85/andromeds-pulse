## Constraints

- Self-observation runtime MUST be `tracing` + `tracing-subscriber` JSON + `tracing-appender` daily file sink ONLY — NO OTel SDK linked into the product binary for self-observation; never add an OTLP network exporter pointed at the product's own `:4317`/`:4318` (per security plan §Security Anti-Patterns API "infinite loop" ban + Cross-cutting Patterns Self-observation discipline).
- Field redaction MUST be applied at the `tracing-subscriber` layer, not at log call sites (per security plan §Logging & Monitoring "Log format" — redaction at subscriber layer is the single enforcement point).
- The NEVER-log list is binding for every `tracing` event the harness emits: OTLP attribute values, span/log/metric content payloads, snapshot file contents, clipboard contents, MCP tool response bodies, full plugin file paths (basename of canonicalized path only), DuckDB query parameter values, Tauri updater download URL query strings, and anything matching the §Secret Management "What counts as secret" list (per security plan §Logging & Monitoring "What NEVER to log" + §Security Anti-Patterns Logging).
- `AppError::Internal { message }` content surfaced to the webview MUST NOT contain stack traces, Rust struct names, file paths, or library versions; sanitization happens at the `From<thiserror::Error> for AppError` impl. Full chain stays in the internal `tracing-error` SpanTrace (per security plan §Error Handling + §Security Anti-Patterns Logging).
- Logs directory `~/.andromeda-pulse/logs/` MUST inherit OS user permissions (mode 0700 on Unix-like, ACL-restricted to current user on Windows) and the daily-rotation default is "last 7 days on disk" pending obs spec (per security plan §Logging & Monitoring "Access controls" + "Log retention").
- The `service.name` discipline (chunk #7's Layer::with_default_fields including `service_name`, `service_version`, `deployment_environment`) MUST treat `deployment_environment` reads from `CI_RUN_ID`/`GIT_COMMIT_SHA` as untrusted env input — bound them via `serde`/`TryFrom` and never inject the raw env string into a path or shell command (per security plan §Input Validation row "CLI / env var inputs" + §Security Anti-Patterns Code Patterns `tokio::process::Command` ban).
- If a Sentry-style `before_send` pattern is wired (currently no Sentry dep present, so no-op skeleton), the same NEVER-log list MUST be enforced inside `before_send` before any payload leaves the process boundary, and Sentry transmission MUST require explicit user opt-in per local-first principle (per security plan §Error Handling "Error reporting integration").

## Patterns to follow

- Structured (JSON) `tracing` + `tracing-subscriber` with redaction Layer is the canonical Rust-ecosystem pairing the security plan calls out — no custom log envelope (per security plan §Logging & Monitoring "Log format").
- Snapshot/clipboard/MCP-tool-response hygiene model: user-facing warning at the medium boundary instead of attempted attribute-value sanitization (the data is user-instrumented). Apply the same posture to log redaction — redact known-secret-class fields at the Layer; do NOT attempt to scan free-form OTLP attribute values for secrets at log time (per security plan §Logging & Monitoring "Snapshot / clipboard / MCP-tool-response hygiene").
- The plugin-path basename pattern (canonicalize via `strict-path`, log basename only) is the existing template for any chunk that emits paths into log fields (per security plan §Bootstrap phases `input-validation-library-install` + §Security Anti-Patterns Logging "basename of canonicalized path only").
- DuckDB query logging shape: `query_id` + `param_count` + `param_types` only — never the parameter values. The PII scrubber Layer should treat any field name matching `*query_param*`, `*db_param*`, or DuckDB-specific `?`-bind metadata as drop-class fields by default (per security plan §Security Anti-Patterns Logging + §Input Validation row "DuckDB query parameters").
- `AppError`-shaped error sanitization at boundary: existing `From` impls strip stack/path/version content; the `tracing-error` SpanTrace captures the unsanitized chain in the internal log only — same Layer split is the model for the PII scrubber (sanitize on emit, retain raw in-memory only if absolutely needed, never persist to disk) (per security plan §Error Handling "Internal logging").

## Anti-patterns to avoid

- NEVER instrument the product's own telemetry with an OTLP network exporter pointed at the product's own `:4317`/`:4318` ports — infinite loop + bypasses loopback authorization model (per security plan §Security Anti-Patterns API "Self-observation discipline" + §Universal CLAUDE.md invariant).
- NEVER log raw OTLP attribute values, span/log/metric content payloads, snapshot file contents, clipboard contents, MCP tool response bodies, full plugin file paths, or DuckDB query parameter values — incidentally captured secrets from instrumented host applications. Even debug-level emissions count (per security plan §Security Anti-Patterns Logging — top item, no severity carve-out).
- NEVER rely on call-site discipline ("just don't log secrets") instead of subscriber-layer redaction — the security plan explicitly mandates "Field redaction is applied at the subscriber layer, not at log call sites" because per-call-site discipline regresses the moment a new module forgets the rule (per security plan §Logging & Monitoring "Log format").

## Contract bindings

- **security ↔ obs**: PII scrubbing rules cross-cut. Security owns the NEVER-log list (snapshot files / clipboard / MCP responses / OTLP attribute values / plugin paths / DuckDB params / updater URL query strings); obs owns the `tracing` Layer wiring + field-name conventions. Chunk #8 is the wire-up point — security's NEVER-log list MUST be the authoritative input to the redaction Layer's drop-list, not a parallel obs-defined list.
- **security ↔ tests**: CI security gate ties to test harness — secret-scanning runs pre-commit + per-PR (already wired in chunks 5-6) and any new Sentry/PII fixture data MUST contain no real secrets (test plan owns no-real-PII-in-fixtures rule; security plan §Security Anti-Patterns Secrets bans real `.env`/`*.key`/`*.pem` commits to git).
- **security ↔ arch (self-observation)**: arch's "no OTel SDK in self-runtime" Established Decision is enforced by chunk #7's library choice (`tracing` ecosystem only). If chunk #7 ever adds `opentelemetry-sdk` or `opentelemetry-otlp` to `pulse-app/Cargo.toml`, that's the exact regression the security plan §Security Anti-Patterns API ban catches at review.
