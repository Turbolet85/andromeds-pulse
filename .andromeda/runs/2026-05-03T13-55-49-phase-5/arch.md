## Constraints

- Self-observation runtime is `tracing` + `tracing-subscriber` JSON + `tracing-appender` daily file sink only — NO OTel SDK linked into the product binary for self-observation; an OTLP network exporter pointed at the product's own `:4317`/`:4318` is forbidden by construction (per architecture.md §Established Decisions [Self-Observation] + §Cross-cutting Patterns "Self-observation discipline").
- Daily file sink target on every platform is the resolved `<data_dir>/logs/` subpath (Linux `~/.andromeda-pulse/logs/`, macOS `~/Library/Application Support/com.andromeda.pulse/logs/`, Windows `%APPDATA%\andromeda-pulse\logs\`); `ANDROMEDA_PULSE_DATA_DIR` overrides the resolved root and the subpath layout under override is identical to the per-platform default (per architecture.md §Occupied Resources Filesystem locations).
- Log-level filter precedence MUST honor `ANDROMEDA_PULSE_LOG_LEVEL` (`trace|debug|info|warn|error`) with `RUST_LOG` as fallback (per architecture.md §Occupied Resources Environment variables) — no new env var beyond this reserved set may be introduced by chunk #7 or #8 without scope-arch.
- Subscriber default fields MUST encode the `service.name` / `service.version` / `deployment_environment` envelope identity that mirrors the `app_info` standard contract (`name`, `version`, `rust_version`, `tauri_version`, `features`, `build_profile`) — the introspection envelope is the canonical service identity (per architecture.md §Standard Contracts `app_info` command).
- Tracing harness code lives within the `pulse-app` binary (it is the runtime owner) and any reusable scrubber/Layer types live in a workspace library crate consumed by `pulse-app`; no library crate may depend on `pulse-app` (DAG with `pulse-app` as the only root, per architecture.md §Cross-cutting Patterns "Module dependency direction").
- Workspace crate names are LOCKED — chunks #7-#8 may NOT introduce a new crate named outside the reserved set `ingest, buffer, viz, ui-bridge, snapshot, workspace-detector, plugins, mcp-server, pulse-app, xtask` (per architecture.md §Occupied Resources Cargo workspace crate names + §Project Intent "How new functionality is added"). Adding a new self-observation crate (e.g., `obs` / `telemetry`) requires `/andromeda-scope-arch`.
- Sentry `before_send` pattern is conditional — if a Sentry path is wired, the dependency MUST sit behind a Cargo feature flag in `kebab-case` (off by default), preserving small-binary baseline (per architecture.md §Conventions "Feature flags" + §Cross-cutting Patterns "Feature-gate hygiene"). Lacking a Sentry feature decision in arch today, a no-op skeleton is acceptable.
- Any toggle introduced by chunk #7 or #8 (e.g., `pii_scrub_enabled`, `log_format`) MUST follow layered config precedence: process env vars (`ANDROMEDA_PULSE_*`) > `~/.andromeda-pulse/config.toml` > built-in defaults (per architecture.md §Cross-cutting Patterns "Config management").
- Scrubber input domain — span attribute values, log message bodies, and any scrubber-emitted text crossing the IPC bridge — must remain `serde::Serialize` (per architecture.md §Cross-cutting Patterns "Cross-bridge data shape"); scrubber output written to `AppError::Internal { message }` shape MUST be a sanitized one-liner (per architecture.md §Conventions "Error response schema (Tauri IPC)").

## Patterns to follow

- Each library crate exposes a public contract module (the only `pub` surface), `pub(crate)` internals, `thiserror`-derived error enum (per architecture.md §Project Intent "Template patterns" + §Conventions "Module visibility discipline"); a self-observation Layer / scrubber crate follows the same shape with a single `pub` API and `pub(crate)` internals (no cross-crate `pub use` re-exports).
- Cargo features are `kebab-case` with minimal defaults — examples in arch are `mcp-server`, `otap-ingest` (per architecture.md §Conventions "Feature flags"); a Sentry path under chunk #8 follows that shape (e.g., `sentry-redaction`, off by default).
- Configuration units convention: durations are seconds with explicit unit suffix in field names (`retention_seconds`); ports are `u16` validated via `TryFrom<u16>` (per architecture.md §Conventions "Configuration units") — any tracing-harness duration knob (e.g., file-rotation interval if added) follows the same shape.
- Standard Contracts `app_info` envelope is the canonical service-identity source — emit subscriber default-fields keyed off the same identity columns (`name`, `version`, `rust_version`, `tauri_version`, `features`, `build_profile`) so log lines and IPC introspection agree (per architecture.md §Standard Contracts).
- Existing `pulse-app/src/main.rs` already wires a basic JSON subscriber via chunk #4; chunk #7 extends that subscriber stack via `Layer` composition rather than replacing it (per route §3 phase-5 starting point note + architecture.md §Established Decisions [Error Handling Pattern]).
- Workspace member directory pattern is `crates/<module-name>/` with `Cargo.toml` + `src/`; binary crate is `pulse-app/`; `xtask/` is the task-runner crate (per architecture.md §Infrastructure Patterns "Project directory structure").

## Anti-patterns to avoid

- DO NOT link the OpenTelemetry SDK into the product binary for self-observation, and DO NOT point any OTLP network exporter at the product's own `:4317`/`:4318` — bypasses the architecture's locked self-observation invariant and creates infinite recursion (per architecture.md §Established Decisions [Self-Observation] + §Cross-cutting Patterns "Self-observation discipline").
- DO NOT introduce a new crate name outside the reserved set; DO NOT rename or re-purpose any of the ten reserved workspace crate names; DO NOT make a library crate depend on `pulse-app` (per architecture.md §Occupied Resources Cargo workspace crate names + §Cross-cutting Patterns "Module dependency direction").
- DO NOT add a new `ANDROMEDA_PULSE_*` env var beyond the reserved set in §Occupied Resources for chunks #7-#8; settings such as PII-scrub toggles or Sentry DSN belong either in `config.toml` (under existing precedence) or behind a Cargo feature flag — env-var namespace expansion is a scope-arch decision (per architecture.md §Occupied Resources Environment variables).
- DO NOT widen Sentry / scrubber types to `pub use` re-exports across crate boundaries beyond each crate's explicit contract module (per architecture.md §Conventions "Module visibility discipline").
