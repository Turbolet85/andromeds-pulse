## Patterns to follow

- **Init body sketch (≤5 lines)** from obs-plan §3 Tracing init: `let (file_writer, _guard) = tracing_appender::non_blocking(rolling::daily(log_dir, "agent-latest.jsonl")); tracing_subscriber::registry().with(fmt::layer().json().with_writer(file_writer)).with(EnvFilter::from_env("ANDROMEDA_PULSE_LOG_LEVEL")).with(ErrorLayer::default()).init(); std::panic::set_hook(Box::new(panic_to_tracing_error));` — keep init local + minimal; the `_guard` is the non-blocking writer flush guard and MUST be held for the lifetime of the app (per obs-plan §3 Tracing init body sketch).
- **Source-level scrubbing pattern**: every handler / boundary fn carrying potential PII is annotated `#[tracing::instrument(skip(<sensitive_param>...), fields(<allowlist>...))]` so sensitive parameters never enter the span — first line of defense (per obs-plan §8 Integration points "At source").
- **Subscriber Layer scrubbing pattern (defense-in-depth)**: custom `tracing-subscriber` Layer wrapping the JSON formatter; iterates emitted event fields and redacts based on the per-module allowlist — applied before serialization to file. This is the last defense line before file write (per obs-plan §8 Integration points "At subscriber Layer").
- **Sentry `before_send` callback shape** (only when Sentry enabled): `before_send: Box::new(|event| { scrub_otlp_payloads(&event); scrub_file_paths(&event); scrub_query_params(&event); event })` (sentry-tauri 0.5 callback signature) (per obs-plan §7 `before_send` scrubbing pattern).
- **Plugin path basename extraction**: `path.file_name().and_then(|s| s.to_str())` before any `tracing::info!` field emission — never log the full canonicalized path (per obs-plan §8 Plugin file paths row).
- **DuckDB query anonymization**: emit `query_id: "q_abc123"` + `param_count: 2` + `param_types: ["string", "timestamp"]`; never emit raw `params` list or query text (per obs-plan §8 DuckDB query parameters row + Section 5 Vector 5).
- **MCP response redaction**: emit `result_type: "traces"` + `result_count: 42` only; explicitly check span event type before any `result_content` field emission would be possible (per obs-plan §8 MCP response bodies row + Section 5 Vector 4).
- **Secret-named env var redaction**: env-var names matching `*_SECRET`, `*_TOKEN`, `*_KEY` redacted by naming convention even if otherwise low-classification (per obs-plan §8 Environment variables row).

## Anti-patterns to avoid

- NEVER link an OTel SDK (`opentelemetry`, `opentelemetry-sdk`, `opentelemetry-otlp`, `opentelemetry-stdout`) into the self-observation runtime — re-introduces the recursion concern this project explicitly chose to eliminate by construction. Only `tonic` + `axum` + `prost` + `opentelemetry-proto` (wire-format-only crates) appear in the dependency graph for the OTLP receiver path; none of them require an OTel SDK runtime (per obs-plan §11 Universal anti-patterns + §12 Decisions Log 2026-05-02 pivot).
- NEVER write to stdout from any subsystem when running as the rmcp stdio sidecar — stdout is reserved for JSON-RPC 2.0 framing; any accidental `println!` / `dbg!` / library stdout write corrupts the protocol and silently disconnects the MCP client (per obs-plan §11 Universal anti-patterns "rmcp stdio sidecar").
- NEVER hardcode service identity (`service.name = "myapp"` literal) — use compile-time `env!()` / Tauri bundle id with a single source of truth registered as a default subscriber field (per obs-plan §11 Universal anti-patterns "hardcode service identity").
- NEVER scrub only at sink stage — scrub at processor stage so failures upstream don't leak; rules MUST live at multiple layers, not one location (per obs-plan §11 PII Scrubbing).
- NEVER ship a real Sentry DSN in dev / committed to repo; default Sentry off; `before_send` scrubbing required when enabled (per obs-plan §11 Error Reporting + §7 Default state).
- NEVER use unstructured stderr text or multi-line stack traces — always JSON-per-line; use `SpanTrace` (tracing-error) instead of raw backtrace (per obs-plan §11 Logs).
- NEVER include raw OTLP attributes, query parameters, plugin full paths, MCP response bodies, AppError stack traces with Rust struct names, or canonicalized file paths in logs (Vectors 1–6) (per obs-plan §11 Spans / Traces + Logs).
- NEVER hold a `tracing::Span` guard across `.await` without `.in_current_span()` — span context bleeds into unrelated tokio tasks, breaking trace_id correlation and bloating memory until the holder drops (per obs-plan §11 Spans / Traces).
