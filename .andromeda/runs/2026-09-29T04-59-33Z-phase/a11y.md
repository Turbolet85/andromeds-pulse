## Relevance
partial. §A changes the constellation canvas fire site (`ConstellationCanvas.tsx`), a must-be-accessible surface (p11 constellation semantics). The change is a timing observable, not new visible UI, so no new component, focus, keyboard or form scope arises. §B's CI parse fix is the first time since 2026-07-25 that the a11y CI stage can actually run.

## Constraints
- The canvas wrapper must keep its region landmark exactly as specified: the stable literal accessible name `Telemetry traces chart`, not a live state summary, plus a visually hidden aggregate summary wired through `aria-describedby` (per a11y-plan §7 Landmark roles; §3 Critical paths P1 row). Per-changed-service emission must not change the landmark's name, and the change must leave both the landmark and the summary unchanged. Whether the fire-site edit can be confined so the render/JSX path is untouched is research's question.
- The accessible summary must stay aggregate-only, meaning lifecycle counts and a findings tally, with no service name reaching the accessible tree (per a11y-plan §7 Landmark roles). Moving to per-changed-service emission must not route a service identifier into the DOM or the summary text.
- The severity carried by dot hue must not depend on color alone (per a11y-plan §6 State color tokens, SC 1.4.1; §1 WCAG Criteria Mapping, visual-discrimination trigger). Recomputing what the hue timing measures must not remove whatever non-color supplement the surface ships. Whether the aggregate findings tally is the current supplement is research's question.
- Reduced motion (per a11y-plan §6 Motion tokens, SC 2.3.3 AAA; §1 motion-sensitive trigger): the state change must still come through under `prefers-reduced-motion: reduce`, with motion only as a supplement. The paint instant used as the end of the `duration_ms` interval must be defined, and the leaf must still emit, when reduced motion is on. Whether the canvas has a reduced-motion branch that changes when or how the hue paints is research's question.
- Required SLO: zero new WCAG AA violations on must-be-accessible paths, now P1–P14 including p11 constellation semantics, and zero new violation tuples per PR against `baselines/a11y-violations-summary.json` (per a11y-plan §10 SLO Invariants; §3 Harness wiring & conventions, regression baseline; §3 Critical paths, surface set extension).
- The a11y harness mock is standing: fixtures consumed through the `TauRPC__` command shape must be POPULATED (per a11y-plan §3 Harness wiring & conventions). If `ServiceListItem` gains `tier_effective_at`, the service fixtures in `helpers/v02-fixtures.ts`, or inline in the p11 spec, must still type-check and render populated dots. Whether those fixtures are typed against the regenerated bindings is research's question.
- A11y runs as a fail-fast gate in the same `ci.yml` pipeline as the tests' E2E (per a11y-plan §3 CI integration; §9 CI Integration). Once §B's fix lets real jobs start, any a11y-stage failure on the first real run is a finding for this chunk under the scope's triage rule, never a soft gate. Whether `ci.yml` actually wires `npm run test:a11y` or the Playwright a11y suite today is research's question.

## Patterns to follow
- The shipped constellation landmark design (per a11y-plan §7 Landmark roles): a stable literal region name, the live summary as a description rather than the name, and `role="status"` deliberately left off the summary to avoid stacked announcements. Preserve all of this as is.
- Suite health probe (per a11y-plan §3 Harness wiring & conventions): `npx playwright test --list` detects the list-time import failure a bindings shape change could cause, which once silently disabled the whole suite.
- Reduced-motion assertion (per a11y-plan §3 WCAG criteria mapping; §6 Motion tokens): Playwright `page.emulateMedia({ reducedMotion: 'reduce' })` asserting that state is still shown without motion. This is the existing reduced-motion spec the p5/widget redesign updated (§3 Critical paths, surface set extension).
- Regression baseline comparison on `{surface, wcag_criterion, selector, severity}` tuples (per a11y-plan §3 CI integration). A clean chain means 0 tuples.

## Anti-patterns to avoid
- Adding a live region or `role="status"` to announce each changed service's hue shift. This is excessive ARIA noise and churns announcements (per a11y-plan §11 Screen Reader; §7 Landmark roles on the omitted `role="status"`).
- Using motion or hue as the only signal of a state change, or letting a timing change skip the paint under reduced motion (per a11y-plan §11 Motion; §11 Visual).
- Softening, deferring or retrying an a11y failure that surfaces when CI starts running for real (per a11y-plan §11 CI; §11 SLO).

## Contract bindings
- a11y ↔ design: the severity semantic carried by constellation dot hue, together with the reduced-motion degrade rule and the not-color-alone supplement, binds to design-system §Motion and §Color Palette (per a11y-plan §6 Motion tokens and §6 State color tokens). The Halo glow layer's reduced-motion degrade is deferred with that layer and stays out of scope.
- a11y ↔ obs/security: the aggregate-only accessible summary (no service name in the accessible tree) matches the no-service-label cardinality rule that closes the scope's per-changed-service emission shape (per a11y-plan §7 Landmark roles). Both must hold together.
- a11y ↔ tests: the a11y CI stage runs inside `ci.yml` and reuses the tests' E2E harness (per a11y-plan §3 CI integration; §9 CI Integration). §B's workflow-parse fix is what makes this binding executable again.
- a11y ↔ bindings: the `ServiceListItem` shape change reaches the a11y mock fixtures (per a11y-plan §3 Harness wiring & conventions).
