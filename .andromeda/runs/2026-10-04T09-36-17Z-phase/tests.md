## Patterns to follow
- Pure classifier pinned per arm: `classify(pid, alive, newest_log)` (per test-plan §3 `status`) is the model for a posture decision function under a "default" or "detect and fall back" shape. The inputs (OS, session type / driver signal, any pre-set value of the lever's env var) go in as explicit parameters, and each arm is unit-pinned. Explicit inputs follow the triage clock precedent (instant passed as a parameter, per test-plan §4 Conventions → triage crate) and the constructor-injection discipline (per test-plan §8 Anti-monkey-patching).
- Process-end witness form (per test-plan §3 Process-end witness form): if the chunk needs to prove a boot record SURVIVES into the log family, witness it with re-exec children on their own TempDir data dirs, not in-process, with the child's `app.boot.tracing.init` record as in-arm proof that the child ran. The plan states that this form cannot reach an `_exit` end.
- A scenario-leg verdict proves its own preconditions (per test-plan §3 Per-chunk gate discipline → `smoke:*` legs). If a measurement leg is built, a run not actually on native Wayland (e.g. `WAYLAND_DISPLAY` unset or `GDK_BACKEND=x11`) reads INCONCLUSIVE, never PASS. An observe window too short to reach the measured death time (~1.5 s) is refused up front, in the same way as `observe_window_supports_verdict`.
- Teardown is judged by independent probes: pid liveness plus the `:4317`/`:4318` handshake, with the one-token cleanup verdict (per test-plan §3 `cleanup`). This applies to every measurement launch, since the ports are shared with conductor-builder.

## Anti-patterns to avoid
- NEVER `std::env::set_var` mid-test without cleanup to exercise the lever (per test-plan §11 Mocking). Test the decision through injected inputs. Mutating process env in a parallel nextest run is the monkey-patch the plan bans.
- NEVER use a bare `sleep(N)` as the "stayed up" signal (per test-plan §11 E2E). Survival over the observe window is read from `harness:status` polling / the exit record.
- NEVER add a retry-once to, or ignore, the CI boot-smoke red to make the carried WATCH go away (per test-plan §11 CI "NEVER ignore flaky tests", §11 Quality "NEVER add retry-once policies"). The plan treats a flake as a real bug.
