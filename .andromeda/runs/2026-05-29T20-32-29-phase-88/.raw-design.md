## Patterns to follow

- WebGPU-canvas-outside-React: render dots directly to canvas via WebGPU/WGSL, NOT inside React's render tree — Arrow/state data pushed into canvas, side-stepping VDOM diffing during high-frequency telemetry updates (per §Surface desktop-webview §Performance notes + §Depth Strategy "WebGPU canvas, dedicated layer outside React's render tree").
- Halo State Pulse is the SOLE exemption from the "no gradient / no canvas" chrome bans — radial gradient + blur (4–16 px) is permitted for the signature dots only (per §Depth Strategy Rationale + §Motion Hard-limits "NO canvas/WebGL (except the dedicated Halo State Pulse layer)" + §Anti-Patterns Universal Bans gradient exception).
- WebGPU unavailable → fallback to `<canvas>` with "WebGPU not supported in this browser" message (per §Surface desktop-webview §Canvas Container WebGPU initialization).
- Empty / loading state: centered Tertiary-color text + optional telescope icon (24px, #7D8697) if no services yet — reuse the existing empty-state pattern, do not invent new (per §Surface desktop-webview §Loading / Empty States).
- Severity↔activity dual-dimension encoding precedent: chunk #90 Halo already drives hue from severity + cadence/breathing from activity-state; per-service dots reuse the SAME two-dimension model at per-dot granularity rather than aggregated (per §Brand Identity Signature element + Decisions Log 2026-05-29 + 2026-05-02 Signature element).
- Custom-glyph language: the `constellation-grid` glyph is the registered domain glyph for "service map" — if any header/label/icon accompanies the constellation it should use the custom set, not a stock library icon (per §Iconography Primary custom set + Rejected Defaults "Generic icons from a stock library … rejected").

## Anti-patterns to avoid

- NEVER encode service state with HUE ALONE — Archived/Dormant/severity distinctions need brightness + tooltip-text pairing (per §Anti-Patterns Universal Bans color-decoration ban; binds to a11y SC 1.4.1).
- NEVER drive dot hue/brightness from raw `throughput_hz` or rule-based `error_rate` — those are the SUPERSEDED chunk #31 inputs; severity + activity-state are the current drivers (per Decisions Log 2026-05-29; the 0.8–2.4 Hz / error-rate model is historical).
- NEVER use scale-based pulsing for dot animation, bounce/spring easing, or opacity fades > 200ms on chrome; data-driven Halo breathing is opacity+blur only and exempt-but-still-non-scale (per §Motion Hard limits + item 1 P-026).
- NEVER hardcode hex / pixel scatter constants outside the token system; the seeded scatter is a deterministic layout (seed = hash(service_name)) but COLORS still come from `@theme` tokens (per §Self-Validation §4 Token Test).
