## Chunk relevance

- route#90 "Halo formula refactor" — relevant. The Halo State Pulse is a WebGPU canvas animation on the compact-widget surface. The refactor changes the motion and color-encoding inputs — both are primary a11y concerns under the motion-sensitive trigger (SC 2.3.3 AAA) and the visual-discrimination trigger (SC 1.4.1). The `prefers-reduced-motion` contract is an explicit invariant in CLAUDE.md and the a11y plan.

## Constraints

- The Halo animation (breathing via opacity + blur modulation) MUST respect `prefers-reduced-motion: reduce` by degrading to a static glow — hue still updates per severity, but all time-based motion (opacity cycle, blur pulse) collapses to static. (per a11y-plan §6 Visual Design Verification — Motion tokens + §11 Anti-Patterns Motion "NEVER autoplay motion without `prefers-reduced-motion: reduce` respect"; SC 2.3.3 AAA escalation)

- The `useReducedMotion` hook from `motion/react 12.x` MUST be wired into the HaloCanvas WebGPU frame loop — not just CSS transitions — because canvas frame loops have no built-in `prefers-reduced-motion` support. The canvas render branch must check the hook result and suppress breathing animation when true. (per a11y-plan §3 Bootstrap phases "motion-tokens-respect-install"; §11 Anti-Patterns Motion "NEVER have animation loops that don't respect `window.matchMedia('(prefers-reduced-motion: reduce)').matches`")

- Halo hue encoding (Earth Blue → Alert Burgundy per cumulative severity) MUST NOT convey severity state by color alone; a supplemental non-color signal is required (e.g., the severity-derived findings counter and connection-state dot from chunk #89 serve as text/icon supplements). The Halo itself is a non-text indicator so SC 1.4.11 Non-text Contrast (3:1 against background) applies to the glow element. (per a11y-plan §6 Visual Design Verification — State color tokens (not-color-alone); SC 1.4.1 + SC 1.4.11)

- The breathing cadence MUST NOT flash faster than 3 times per second (0.33 Hz minimum cycle) — the spec states 0.8–2.4 Hz breathing which may approach the SC 2.3.1 Three Flashes threshold for seizure risk at maximum rate (2.4 Hz = 2.4 cycles/sec, which could produce 2.4 luminance changes/sec — within safe range, but the implementation MUST validate the rendered luminance change rate stays below 3 Hz). (per a11y-plan §11 Anti-Patterns Motion "NEVER flash content > 3 times per second (per SC 2.3.1 A)")

- Connection state gray-out of the Halo (the P-004 orthogonal axis) must still meet SC 1.4.11 non-text contrast when the glow is rendered in the grayed/inactive state. The grayed-out halo must have ≥ 3:1 contrast against the widget background token. (per a11y-plan §6 Visual Design Verification — Color contrast pairs; SC 1.4.11)

## Patterns к follow

- **Reduced-motion static-glow degradation pattern**: prior Halo implementation (chunks #31–#34) already wired `motion-reduce:` Tailwind variants and `useReducedMotion` for the chrome transitions; the Halo refactor must preserve and extend this — static-glow means opacity and blur are pinned to their resting values (no frame-loop animation tick modifies them under reduced motion), while hue continues updating to reflect severity. (per a11y-plan §3 Motion tokens verification + CLAUDE.md §Critical Warnings "prefers-reduced-motion: reduce — Halo degrades to static glow (hue still updates per error rate); WCAG 2.1 AAA SC 2.3.3")

- **Canvas-loop motion gate pattern**: the frame-render function (in `halo-pipeline.ts` / `halo.wgsl`) should gate animation tick application via a React state value derived from `useReducedMotion()` — the hook result is passed as a uniform or JS flag; when true, the tick function skips opacity/blur delta updates and emits the static glow values directly. (per a11y-plan §11 Anti-Patterns Motion; §3 Bootstrap phases "motion-tokens-respect-install")

- **Non-text contrast verification for hue range**: the LCH hue interpolation path must be checked against the background token at both endpoints (Earth Blue and Alert Burgundy) to confirm ≥ 3:1 non-text contrast throughout the interpolated range. Colorjs.io 0.6.x is the in-project tool for this check. (per a11y-plan §3 Contrast verification harness + §6 Color contrast pairs SC 1.4.11)

## Anti-patterns к avoid

- NEVER remove the `prefers-reduced-motion` gate while deleting the legacy mapping helpers (`error-rate-to-blur.ts`, `throughput-to-hz.ts`) — the gate lives in the canvas frame loop, not in the deleted files, but the deletion is a high-risk moment for accidental breakage. Verify the gate is intact post-deletion. (per a11y-plan §11 Anti-Patterns Motion; CLAUDE.md §Critical Warnings)

- NEVER use scale modulation as a breathing mechanism — the chunk spec explicitly bans scale per P-026 ("breathing via opacity AND blur modulation ONLY, NEVER scale"). Scale-based animation is additionally problematic for vestibular disorder users even under reduced-motion settings (scale creates spatial reorientation). (per a11y-plan §11 Anti-Patterns Motion "NEVER use motion as ONLY signal"; the not-scale constraint doubles as an a11y invariant)

- NEVER rely on Halo hue shift as the sole severity indicator — the findings counter (chunk #87) and connection dot (chunk #89) must remain present to satisfy SC 1.4.1 not-color-alone for severity state. Do not remove or suppress those elements in the same chunk. (per a11y-plan §6 State color tokens (not-color-alone); SC 1.4.1)
