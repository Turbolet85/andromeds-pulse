## Constraints

- The Halo State Pulse hue MUST interpolate via **LCH** color space from `--color-primary` (#4A90E2 Earth Blue) at healthy/info severity to `--color-accent` (#C7556A Alert Burgundy) at error/critical severity. Hardcoded hex or non-LCH interpolation is a design anti-pattern. (per design-system.md §Brand Identity "Signature element" + §Color Palette Core Colors + §Decisions Log 2026-05-03 Alert Burgundy lift)

- Breathing MUST be expressed as **opacity + blur modulation only** — 4–16 px blur radius, 0.6–1.2 s per breath cycle at base rate (4–5 s quiet cycle in new severity-driven scheme), accelerating under active incidents. `NEVER scale` is a P-026 invariant that also aligns with design-system.md §Motion hard limits (NO 3D transforms; chrome expression level 0.3–0.35 reserves scale transforms for supporting moments, not continuous background rhythm). (per design-system.md §Motion "High-impact moments" item 1 + §Anti-Patterns Universal Bans "Animated state transitions")

- Breathing frequency range 0.8–2.4 Hz is the canonical shader-driven range established in the design system's "Signature element" definition. The refactor may re-drive this from incident severity + activity state rather than raw throughput, but the clamped output range MUST remain 0.8–2.4 Hz. (per design-system.md §Brand Identity "Signature element" + §Motion "High-impact moments" item 1)

- Connection state "grayed out" visual (P-004 orthogonality) MUST NOT collapse the hue axis — it must be a **separate visual axis** (e.g., reduced saturation/opacity of the entire halo) that overlays without destroying the severity hue encoding. This preserves dual-dimension legibility established in §Rejected Defaults "Uniform monochrome status icons" rationale. (per design-system.md §Anti-Patterns §Rejected Defaults item 1)

- The Halo canvas background MUST remain `--color-inset` (#0F1117) — this recessive background is what allows the glowing halo to visually "pop." Any refactor of the WGSL shader or canvas container must preserve this token assignment. (per design-system.md §Surface: desktop-webview Component Patterns "Canvas Container")

- `prefers-reduced-motion: reduce` degradation is mandatory: the Halo degrades to **static glow** (no breathing rhythm; hue still updates per severity). The refactor must implement or preserve this override in the new severity-driven code path. (per design-system.md §Motion "Accessibility" + §Downstream Readiness "For a11y specialist")

## Patterns to follow

- **LCH hue interpolation via `lch.ts`**: existing `lch.ts` file at `pulse-app/ui/src/halo/` is the project's canonical color interpolation utility; chunk should extend or replace its input mapping (errorRate → cumulativeSeverity) while preserving the LCH-space interpolation logic. This is the "spectroscopy" domain metaphor materialized in code. (per design-system.md §Brand Identity "Spectroscopy" anchor + §Color Palette "Halo State Pulse Earth Blue ↔ Alert Burgundy LCH interpolation")

- **Halo as data-driven, exempt from chrome budget**: the design system explicitly classifies the Halo State Pulse as a "separate dimension governed by the data-viz layer and NOT bound by the chrome expression number." The new severity-driven breathing and hue are still in this exempt category — do not apply the 150ms/200ms chrome duration tokens to the halo's continuous animation. (per design-system.md §Motion opening paragraph + "High-impact moments" item 1)

- **Dual-dimension encoding preserved**: the existing Halo encodes TWO independent dimensions (rhythm = throughput/life signal; hue = error/severity). The refactor must maintain the dual-dimension model with new inputs (rhythm ← activity/connection state; hue ← cumulativeSeverity). Collapsing both dimensions into a single severity color would violate the design rationale for the signature element. (per design-system.md §Anti-Patterns §Rejected Defaults "Uniform monochrome status icons" + §Brand Identity "Signature element")

- **Obs measurement hooks on Halo**: design-system §Downstream Readiness specifies that the obs specialist must be able to log Halo pulse frequency (Hz) and Halo color state (LCH value) per pulse. The refactored implementation must preserve or update these observable fields (now driven by severity, not error rate) so obs instrumentation continues to function. (per design-system.md §Downstream Readiness "For obs specialist")

## Anti-patterns to avoid

- **NEVER use `scale` transforms for the Halo breathing animation.** Breathing is exclusively opacity + blur. Scale is reserved for supporting moments (Investigation Capture Collapse). Using scale for the continuous Halo rhythm violates P-026, the Motion hard limits, and the expression-level discipline simultaneously. (per design-system.md §Motion "Hard limits" NO 3D transforms + §Anti-Patterns "Animated state transitions using bounce easing and 500ms+ durations")

- **NEVER use color alone to encode severity state on the Halo.** The hue shift (Earth Blue → Alert Burgundy) MUST be accompanied by breathing rhythm change (or, under `prefers-reduced-motion`, the static glow must retain hue differentiation). Color-only state signaling violates SC 1.4.1 and the design system's "never color for decoration" discipline — severity must also be readable via rhythm cadence. (per design-system.md §Anti-Patterns Universal Bans "NEVER use color purely for decoration" + §Downstream Readiness "For a11y specialist")

- **NEVER introduce gradient overlays or glassmorphic effects on the Halo canvas container or surrounding chrome.** The Halo's radial gradient + blur is the sole exception to the flat-matte surface discipline; the *container* and widget chrome remain flat. The refactor must not "enhance" the new severity-driven halo with additional layered effects on the surrounding React elements. (per design-system.md §Anti-Patterns Universal Bans "NEVER use gradient overlays or glassmorphic effects on the dashboard chrome")

## Acceptance criteria contributions

- (design) Halo hue interpolation uses LCH color space between `--color-primary` (#4A90E2) and `--color-accent` (#C7556A) as defined in `lch.ts`; no hardcoded intermediate hex values or non-LCH interpolation paths appear in the refactored code.
- (design) Halo breathing uses opacity + blur modulation only; no `scale`, `transform`, or 3D CSS/WGSL animation appears in `HaloCanvas.tsx` or `halo.wgsl` for the continuous rhythm path.
- (design) When `prefers-reduced-motion: reduce` is active, the Halo renders as a static glow with hue still reflecting `cumulativeSeverity` (Earth Blue at healthy, Alert Burgundy at error/critical) and no pulsing rhythm — verifiable by setting the OS/browser reduced-motion preference and visually inspecting the widget.
- (design) Connection state "disconnected/stalled" grays out the halo as a distinct visual axis without eliminating the hue encoding; severity hue remains readable (though desaturated) alongside the connection-state signal — dual-dimension legibility preserved per §Anti-Patterns §Rejected Defaults item 1.
