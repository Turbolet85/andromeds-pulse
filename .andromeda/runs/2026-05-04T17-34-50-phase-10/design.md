## Patterns to follow

- Tailwind v4 `@theme` token consumption pattern: components reference design tokens via `bg-[var(--color-raised-1)]`, `border-[rgba(74,144,226,0.3)]`, `rounded-[var(--radius-md)]`, `p-[var(--spacing-md)]`, `transition-[duration:var(--duration-fast)] ease-[cubic-bezier(0.4,0,0.2,1)]` (per design-system.md §Surface: desktop-webview Tokens `@theme` block); future `react-aria-components` wrappers follow this consumption pattern unchanged.
- Focus ring specification (already locked in design tokens, will be enforced by `react-aria-components` `:focus-visible` semantics): 3–4 px outset, color `#4A90E2`, rendered via `box-shadow: 0 0 0 3px rgba(74, 144, 226, 0.2)` or `outline: 3px solid #4A90E2`; `react-aria-components` 1.17 `data-focus-visible` attribute should be styled via Tailwind to match this spec (per design-system.md §Border Progression Focus row + §Surface: desktop-webview Focus / Keyboard Navigation + §Downstream Readiness for a11y).
- State-color + text-label pairing convention (lift-accent `--color-accent: #C7556A` is now formally a NON-text token for input borders / error icons / alert badges / divider emphasis): error-state UI uses `--color-text-primary` for body-size message text + `--color-accent` for border + icon (per design-system.md §Design Decisions Log 2026-05-03 lift-accent §Usage scope refinement); `eslint-plugin-jsx-a11y` rule defaults for `role="alert"` / aria-describedby semantics are compatible with this pairing.
- `prefers-reduced-motion` discipline (already a universal invariant in CLAUDE.md): future component primitives wrapped from `react-aria-components` 1.17 MUST respect `prefers-reduced-motion: reduce` in transitions (chrome animations become 0ms per design-system.md §Motion Accessibility); install of motion/react `useReducedMotion` hook is chunk #15, not #13, so #13 is install-only and does not yet configure runtime motion fallbacks.

## Anti-patterns to avoid

- NEVER configure `eslint-plugin-jsx-a11y` 6.10 to enforce `<img alt="">` semantics on custom `<Icon glyph="..." />` components — the design plan classifies these glyphs as design-token-registered React components, not raster images, and the surrounding parent provides labeling context (per design-system.md §Iconography + §Anti-Patterns Universal Bans "Generic icons from a stock library used across chrome without modification" — bans imply custom Icon component is the discipline).
- NEVER install `react-aria-components` 1.17 with intent to render with default styling or examples-folder hex / px values — the primitive layer is structurally unstyled and MUST be wrapped to consume Tailwind `@theme` tokens only (per design-system.md §Anti-Patterns Universal Bans "NEVER use generic font families as primary" + "NEVER use Tailwind default palette colors" — both extend by precedent to "NEVER use unstyled-primitive examples as visual source").
- NEVER let `axe-core/playwright` 4.11 / Lighthouse 12 / pa11y 9 install introduce a CI gate that asserts contrast against pre-lift-accent palette values (`#8B2E3B`) — the lift-accent amendment (Decisions Log 2026-05-03) is canonical; chunk #12 contrast-report.json is the source of truth for current expected pairs (per design-system.md §Design Decisions Log 2026-05-03 + §Color Palette Core Colors).
