## Patterns to follow

- **Log schema per obs-plan §3 Log format JSON schema and §6 Required fields**: every log line MUST include `timestamp` (ISO 8601 `YYYY-MM-DDTHH:MM:SS.fffZ`), `level` (debug/info/warn/error), `target` (module path or `metric.{module}.{measure}`), `message` (<200 chars human summary), `fields` (always present, may be `{}`); default subscriber fields populate `service.name` / `service.version` / `deployment.environment` on every line.
- **Span/target naming per obs-plan §3 + §4 + §6**: `{module}.{operation}` for spans (e.g., `app.boot.workspace.detect`); for harness lifecycle events, follow `app.boot.*`, `tray.{event}`, etc. naming families already cited in obs-plan §1 Telemetry surfaces.
- **Panic hook installed at boot per obs-plan §3 Tracing init step (3) + §7 Panic hook**: `std::panic::set_hook(...)` calling `tracing::error!(target: "app.panic.fatal", ...)` with `tracing-error` SpanTrace — this is the zero-unlogged-panics SLO enforcement (§10).
- **PID file placement** is the harness's responsibility but should live under the same resolved data dir as the log file (`~/.andromeda-pulse/`), so the `cleanup` subcommand can find both via the same `ANDROMEDA_PULSE_DATA_DIR` resolution.
- **`logs` subcommand consumption pattern per obs-plan §3 Snapshot/paste-to-AI integration**: the JSON log file is "JSON-per-line, immediately greppable / `jq`-able / paste-to-LLM-able" — the `logs` subcommand should default to tailing or printing the latest JSONL file unprocessed; agents read raw.

## Anti-patterns to avoid

- NEVER write to stdout from the rmcp stdio sidecar code path (out of scope at route#4 but the harness `boot` / `run` for any future MCP-enabled invocation must not regress this) — per obs-plan §11 Universal "ANY accidental `println!` / `dbg!` / library stdout write corrupts the protocol".
- NEVER use unstructured stderr text per obs-plan §11 Logs — the JSON formatter is mandatory for the file sink; the only place pretty-printed text is acceptable is stderr-when-TTY.
- NEVER hardcode `service.name = "myapp"` or any literal that bypasses the compile-time identity source per obs-plan §11 Universal.
- NEVER link an OTel SDK into the harness binary or the product binary's self-observation runtime per obs-plan §11 Universal — `tracing` ecosystem is the SOLE self-observation primitive; no `opentelemetry-stdout`, no `opentelemetry-otlp` exporter pointed anywhere.
- NEVER skip the panic hook install at boot per obs-plan §10 zero-unlogged-panics SLO + §11 SLO.
- NEVER add retry-once policies for panic handling per obs-plan §11 SLO ("masks real failures").
- NEVER lose log file artifacts when `cleanup` is invoked — per obs-plan §9 CI Integration, the log file is the primary CI artifact uploaded for agent download via `gh run download`. Cleanup must preserve previous-day rotated files.
- NEVER use multi-line stack traces per obs-plan §11 Logs — SpanTrace via `tracing-error` is the convention; one-line serialization keeps JSON-per-line parseable.
