## Constraints

- The `mcp.status` TauRPC procedure return shape (whatever the plan settles on) MUST be sufficient for a future tray-menu consumer to render the "Toggle MCP Server" item per design-system.md §Surface: desktop-native Tray Menu — i.e., it must distinguish enabled / disabled / unavailable (feature flag off) states so the checkbox-marked variant + the "hidden when --features mcp-server not built" variant are both representable (per design-system.md §Surface: desktop-native Component Patterns Tray Menu Actions row).
- The `generate_snapshot` MCP `#[tool]` method MUST share the same curation pipeline as the existing `snapshot.generate` TauRPC procedure (chunk #44 substrate) — design's Decisions Log 2026-05-02 "Snapshot generation (curated observation log)" anchors snapshot as a single domain concept; divergent curation pipelines between IPC and MCP would split that concept and violate the design's Self-Validation Protocol Signature Test (snapshot is ONE concept, not two).
- Response-body redaction wiring (chunk #49 plan's "response.body never logged" requirement) MUST NOT regress the user-facing visible clipboard-write event contract (`pulse://stream/snapshot-progress` per security plan §Logging snapshot/clipboard hygiene; design's tray-menu "Generate Snapshot" action calls this codepath) — design-system.md §Surface: desktop-native Notifications row requires the OS-native "Snapshot ready | 2.5k tokens, 42 spans" toast on completion; suppressing response-body in the tracing layer is fine, but suppressing the user-facing event is a design regression.
- IF `mcp.status` returns a state struct that includes user-facing message strings (e.g., "MCP server stopped"), those strings MUST use the contemplative observational voice per design-system.md §Brand Identity ("Generate Snapshot" not "Export Data"; "Toggle MCP Server" not "Enable AI Integration") — no Title-Case generic productivity-app phrasing. Per design-system.md §Surface: desktop-native Tray Menu Tone row.

## Patterns to follow

- **Snapshot-as-shared-concept**: per design-system.md Decisions Log 2026-05-02, snapshot generation is ONE domain concept exposed at two surfaces (tray-menu/dashboard via TauRPC `snapshot.generate` + MCP `generate_snapshot` tool method). The chunk-49 plan's "shared curation" implementation pattern aligns directly with this — preserve at the curation-primitive level (per design-system.md §Brand Identity "Snapshot generation (curated observation log)" anchor).
- **Tray-menu "Toggle MCP Server" pre-existence**: design-system.md §Surface: desktop-native Tray Menu Actions already enumerates this menu item with the conditional gating "only when `--features mcp-server` is built; checkbox-marked if enabled; invokes `mcp.start` / `mcp.stop`". Chunk #49's TauRPC `mcp.start` / `mcp.stop` / `mcp.status` IPC surface IS the wire contract the tray menu will consume downstream — the design pattern is already locked, the chunk only implements the backend side.
- **Investigation Capture Collapse motion contract preservation**: design-system.md §Motion specifies a 250–350ms scale+opacity supporting moment triggered when the user clicks Investigate (which invokes `snapshot.generate`). The `generate_snapshot` MCP tool method does NOT have this visual handshake (MCP is non-interactive over stdio) — preserve the asymmetry; do not propagate the motion contract to the MCP path (motion is a webview-surface concept, not an IPC-surface concept).

## Anti-patterns to avoid

- NEVER design an `mcp.status` return shape that forces the tray-menu consumer to render the "Toggle MCP Server" menu item using two boolean flags requiring boolean-XOR logic at the consumer side to derive the visible state (this would bake state-derivation logic into the visual layer, violating design-system.md §Brand Identity "every interaction explainable via domain metaphor" — the IPC contract should expose state as a single tagged-enum-like discriminator that the visual surface renders 1:1). Per design-system.md §Self-Validation Protocol Token Test (random / magic combinations signal no system).
- NEVER add user-visible color or motion encoding to the chunk #49 IPC contract — `mcp.status` return state MUST be a plain data envelope; mapping state → tray-menu visual (checkbox-mark color, Halo encoding if any future tray-menu state pulse adds one) is downstream visual specialist work, NOT this chunk's domain. Per design-system.md §Anti-Patterns Universal Bans "NEVER use color purely for decoration" and "color in the palette communicates meaning".

- **Design ↔ Arch (Occupied Resources Tauri IPC routes)**: chunk #49 adds 3 new TauRPC procedures `mcp.{status,start,stop}` which arch §Occupied Resources already reserves (mcp-server crate, "only when `--features mcp-server`"). Tracing-layer redaction vs. user-event emission are two separate concerns; the chunk-49 plan must preserve the second while implementing the first.
