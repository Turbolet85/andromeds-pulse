## Anti-patterns to avoid
- Never satisfy a new observable by adding a bare parent prefix key (`triage`, `incidents`, `corpus`, `interpretation`) or by leaning on `for_target`'s fallback for a `metric.*` target — either widens siblings or silently redacts every label while `value` still prints (per obs-plan.md §8, §11 PII Scrubbing).
- Never instrument the storm stage with per-span-event or per-row `info` records to make it assertable — obs-plan.md §11 (Telemetry Strategy, Logs) bans hot-path spam; use the §5 tick-aggregated field shape.
- Never let a gate script FAIL on an absent metric stream, and never emit raw injected OTLP attribute values to make a stage visible — per obs-plan.md §10 (two-state posture / NEUTRAL-tolerance) and §11 (Logs, Vector 1).
