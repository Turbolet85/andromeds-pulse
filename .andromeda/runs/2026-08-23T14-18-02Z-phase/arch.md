# arch extract

## Relevance
Relevant — arch governs the harness stack, the telemetry-injection discipline, the resource registry, and the det-L4/incident-identity semantics the three acceptance assertions bind to.

## Constraints
- **Harness stack is already fixed and must be extended, not replaced.** architecture.md §Stack and Technologies ("GUI verification harness (dev-only)") registers `@crabnebula/tauri-driver` 2.x + `webdriverio` 9.x as npm devDependencies in `pulse-app/ui`, the win32 native driver via the napi optional dep (no `cargo install tauri-driver`, no Rust dependency), the host `msedgedriver` located via `ANDROMEDA_PULSE_MSEDGEDRIVER_PATH`, and `cargo xtask webview-drive` as the invocation. The staged leg must stay inside that stack and stay dev-only (devDeps only, no runtime/bundle impact).
- **All stage telemetry must enter over OTLP, and buffer read-backs must go through the query routers.** architecture.md §Cross-cutting Patterns → Test-time telemetry injection requires e2e tests to speak OTLP to `:4317`/`:4318` — the same surface external SDKs use — with *no in-process test-mode bypass, no separate "test ingest" feature flag, no mock-channel back-door*; non-default ports resolve via `ANDROMEDA_PULSE_OTLP_GRPC_PORT` / `_HTTP_PORT`, and buffer-state inspection reads back through `traces.*` / `metrics.*` / `logs.*`. This binds scope §5 open question 2 (storm mechanism): whatever injector the storm stage uses, it must be an OTLP client.
- **The verdict owner belongs in `xtask`.** architecture.md §Infrastructure Patterns → Build system + CI/CD approach requires all shared CI logic needing Rust to live in the `xtask` crate so contributors run identical commands locally (`ci.yml` runs fmt → clippy `-D warnings --workspace --all-targets --all-features` → `cargo xtask test`); `xtask` is a reserved workspace member per §Occupied Resources → Cargo workspace crate names.
- **det-L4 gate + fixture posture is contracted.** architecture.md §Occupied Resources → `ANDROMEDA_PULSE_L4_DETERMINISTIC` requires a bounded truthy parse (`1|true|yes`, default false, per the `crates/mcp-server/src/feature_gate.rs` pattern) resolved at `pulse-app` boot, and records that the canned arrays being POPULATED is load-bearing for gradeability while `EvidenceRefs.trace_id` / `span_ids` / `timestamps_unix_nano` are mandated empty in EVERY mode. Assertions must therefore bind to *presence* of populated values; an absence check over the always-empty siblings passes for the wrong reason.
- **The storm→incident assertion must respect L2 coalesce identity.** architecture.md §Established Decisions → [Fault Identity] fixes incident coalescing on the cue tuple `(kind, scope, scope_id)` — effectively per-service for storms — so a second storm with a different fingerprint on a service that already has an open incident is absorbed by design; an incident-count assertion must not assume one incident per fingerprint. The same section requires that `Incident.fingerprint` reach no rendered surface (the webview `IncidentRecord` view drops it), so no DOM assertion may bind to it.
- **Investigate results are transient by contract.** architecture.md §Occupied Resources → Tauri IPC routes specifies `investigate.run_action` returns a TRANSIENT scrubbed `InvestigateResultDto` with NO incident created/persisted and NO broadcast, honouring the det-L4 gate — so assertion 3 must bind to the returned/rendered result or its outcome record, never to corpus or incident state.
- **Every new occupied resource must be registered.** architecture.md §Occupied Resources is the canonical registry for env vars, data-dir subpaths, ports, TauRPC procedures and broadcast topics; harness-only env vars are a declared class explicitly marked "NOT consumed by the production binary" (`_PIDFILE` / `_LOGFILE` / `_DATA_DIR_KEEP` / `_MSEDGEDRIVER_PATH` precedent). Whether this leg lands any new resource at all is research's question — scope §2 predicts none `[inferred]`.

## Patterns to follow
- **`cargo xtask <task>` as the single command surface** for anything CI or an agent must reproduce (architecture.md §Infrastructure Patterns → Build system; §Cross-cutting Patterns → Development Style: agent-driven, deterministic harness invocations + machine-parseable outputs).
- **Bounded env-var parse with a documented non-panicking fallback** — the registered precedents are `_MSEDGEDRIVER_PATH` (whitespace-trimmed + `is_file()`-guarded ⇒ clean SKIP), `_BASELINE_BOOTSTRAP_SECONDS` (range-bounded ⇒ default), and the truthy gate (architecture.md §Occupied Resources → Environment variables). Note the tension the scope names: arch mandates the clean-SKIP behaviour, so making the leg *fire* is a matter of supplying the var, not of changing the guard.
- **One data-dir override addresses every artifact the leg reads.** `ANDROMEDA_PULSE_DATA_DIR` overrides the root with an identical subpath layout, so `logs/` (the self-telemetry exporter destination the driver tails), `run/andromeda-pulse.pid`, `run/workspace-key` and `corpus/corpus.db` all resolve from it (architecture.md §Occupied Resources → Filesystem locations). `run/workspace-key` is the published cross-process incident-filter identity — directly the substrate of absorbed CARRY #11.
- **Read back through contracted surfaces only** — TauRPC query routers for buffer state, `incidents.list_active` / `incidents.get_report` / `storage.inspect` for incident+corpus state (architecture.md §Occupied Resources → Tauri IPC routes; §Cross-cutting Patterns → Test-time telemetry injection). Absorbed CARRYs #11/#12 are read-back consistency observations across exactly these.
- **Config precedence: env vars > `config.toml` > built-in defaults** (architecture.md §Cross-cutting Patterns → Config management) — the leg's env layer wins over anything on disk in its temp data dir.

## Anti-patterns to avoid
- **No back-door ingest.** No in-process test-mode bypass, no "test ingest" feature flag, no mock-channel injection for any stage (architecture.md §Cross-cutting Patterns → Test-time telemetry injection).
- **No per-procedure capability JSON edit** — TauRPC dispatches every method through one invoke handler, so the per-procedure gate is the `EXPECTED_PROCEDURES` pin in `xtask/src/main.rs`, not `pulse-app/capabilities/`. Conversely, never assume an ungranted Tauri **core** API is reachable: fs / shell / dialog / http and each `core:window:*` permission require an explicit grant and are *silently rejected* when missing (architecture.md §Cross-cutting Patterns → Webview IPC capability policy). Any stage that would need a file dialog is out — §Occupied Resources records no `tauri-plugin-dialog`.
- **No unregistered occupied resource.** An env var, port, data-dir path, procedure or broadcast topic landing without a §Occupied Resources entry is registry drift (architecture.md §Occupied Resources).

## Contract bindings
- **arch ↔ tests** — arch owns the harness *stack* row and the `cargo xtask webview-drive` command surface plus the OTLP-only injection rule; test-plan owns the leg's test structure and the `mcp-incident-read-back-cross-process-coverage` trigger that scope §3 re-pins CARRY #10 onto (whether that trigger is live is research's question).
- **arch ↔ obs** — `<data_dir>/logs/` is arch's registered self-telemetry sink (§Occupied Resources → Filesystem locations; §Cross-cutting Patterns → Self-observation discipline), but the *allowlist leaf* for any observable the driver asserts on is obs-plan's contract. arch registers exact leaf targets alongside procedures (the `telemetry.frontend.*` entries do this explicitly); whether the candidate observables in scope §1 already emit with a usable exact leaf is research's question.
- **arch ↔ security** — `ANDROMEDA_PULSE_MSEDGEDRIVER_PATH` is deliberately NOT canonicalize-and-confined under the data dir, cross-referencing the security-plan §Input Validation harness-only carve-out; `ANDROMEDA_PULSE_DATA_DIR` and every path under it remain subject to the confinement rule (architecture.md §Occupied Resources → Environment variables / Filesystem locations).
- **arch ↔ design** — DOM selectors and per-screen layout on Traces / constellation / findings / Investigate are design's; arch fixes only that webview source files follow the design specialist's convention (§Conventions → File naming) and that the shell is dense/dark-default (§Design Philosophy → Developer-tool surface).

## Acceptance criteria contributions
- (arch) The staged leg runs on the registered dev-only harness — `cargo xtask webview-drive` driving `@crabnebula/tauri-driver` 2.x + `webdriverio` 9.x from `pulse-app/ui` devDependencies, with no new driver stack, no Rust `tauri-driver` dependency and no runtime/bundle impact (per architecture.md §Stack and Technologies → GUI verification harness (dev-only)).
- (arch) Every stage's telemetry enters via OTLP on `:4317`/`:4318` (non-default ports via `ANDROMEDA_PULSE_OTLP_*_PORT`) with no in-process bypass, feature flag or mock channel, and buffer read-backs go through the `traces.*` / `metrics.*` / `logs.*` routers (per architecture.md §Cross-cutting Patterns → Test-time telemetry injection).
- (arch) No new env var, port, data-dir path, TauRPC procedure or broadcast topic lands unregistered; if one does, it carries a §Occupied Resources entry and — for a harness var — the explicit "NOT consumed by the production binary" marking, and no per-procedure capability JSON is edited (per architecture.md §Occupied Resources + §Cross-cutting Patterns → Webview IPC capability policy).
- (arch) The incident stage asserts against coalesce-per-cue-identity `(kind, scope, scope_id)` — not one-incident-per-fingerprint — and no assertion binds to `Incident.fingerprint` as a rendered value or to the always-empty `EvidenceRefs.trace_id` / `span_ids` / `timestamps_unix_nano` (per architecture.md §Established Decisions → [Fault Identity] and §Occupied Resources → `ANDROMEDA_PULSE_L4_DETERMINISTIC`).
