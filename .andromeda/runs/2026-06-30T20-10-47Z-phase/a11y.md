2. §3 Harness Contract: all new interactive elements must pass axe-core assertions (no WCAG AA violations) and be included in Playwright focus-order + keyboard test harness.
3. §4 ARIA Patterns, Button pattern: use native `<button>` element (not `role="button"` on `<div>`); must have accessible name via visible text or `aria-label`; Enter/Space must activate the button.
4. §5 Keyboard Navigation, compact-widget focus order (line 434): expand button must be in the natural DOM focus order; Esc must close/minimize the widget (existing escape path unchanged).
5. §6 Visual Design, target-size tokens (line 492–494): button interactive area must meet ≥ 24×24 CSS px minimum (SC 2.5.8 AA); if larger, can use `--target-button-min` token.
6. §6 Visual Design, color-contrast pairs (line 475–481): button text must meet `--color-text-primary / --color-base` ≥ 4.5:1 (SC 1.4.3); focus ring must meet `--border-focus` ≥ 3:1 contrast (SC 1.4.11).

## Patterns to follow
1. From P5 row (§1): compact-widget layout Tab sequence should include the expand button between existing controls (e.g., title → expand button → minimize button).
2. From §4 Button + §6 Focus ring: apply `--border-focus` token outline on `:focus-visible` to the button; verify via Playwright `page.evaluate()` checking computed style after Tab navigation.
3. From §5 compact-widget (line 434–435): if expand button triggers window show/focus, the focus must remain on the button in the webview (not steal focus to the main window during activation, per P5 focus-order discipline).
4. From §3 CI Integration (line 586–589): add the button to the `keyboard-focus/widget-and-modals.spec.ts` test suite (per 2026-06-10 amendment, widget specs were updated); assert Tab reaches button and Enter/Space activates it.

## Anti-patterns to avoid
1. §11 ARIA (line 636): never use `role="button"` on a `<div>` — use native semantic `<button>`.
2. §11 Keyboard (line 644): never omit focus styles; always apply `--border-focus` outline on `:focus-visible` — do not remove default outline without replacement.
3. §11 Keyboard (line 646): never nest focusable elements (e.g., button containing another button) — the expand button must stand alone.
