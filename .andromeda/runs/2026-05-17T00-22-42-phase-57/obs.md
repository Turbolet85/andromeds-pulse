## Anti-patterns к avoid

- NEVER emit `service.name` as a high-cardinality field on per-span `tracing::warn!` for missing-service-identity cases — aggregate by tick, emit count + sample-N (per obs-plan §11 Metrics row 1 + explicit route §3 chunk #61 mandate). Per-span warn is the canonical mistake here.
- NEVER add `#[tracing::instrument]` to `EwmaTracker::update()` / `TDigest::insert()` / `RollingWindow::push()` — these run inside the ingest hot path on every span and span construction overhead destroys the throughput budget (per obs-plan §11 Telemetry Strategy row 1). Instrument the *enclosing* per-batch / per-tick wrapper only.
- NEVER log corpus file path verbatim — emit `corpus_basename` only (e.g., `"baselines.bin"`), never `/home/user/.andromeda-pulse/baselines.bin` (per obs-plan §11 Spans row 6 Vector 3 plugin-path analog + §8 path scrubbing). Same canonicalization discipline as plugin paths.
- NEVER log raw `service.name` strings inside the missing-identity warn — `service.name` is OTLP-client-controlled input which may carry secrets; emit sanitized hashes or `service_id_count` only (per obs-plan §11 Logs row 5 Vector 1 + §8 ingest whitelist `span_count + service` interpretation — `service` allowlist applies to known-trusted module fields, not OTLP-attribute-derived in error paths).
