## Relevance
Partial — the ACL-rejection record itself is a wire/observability artifact with no layout surface, but the CARRY fix (`pulse-app/ui/src/report/Report.tsx` `ErrorState`) and the report-Copy retro-fit land inside the Report-window surface and error-state region that layout-templates owns.

## Constraints
- The Diagnostic Report must remain the six-section `Report` rendered in the `Modal` **`fill`** variant (edge-to-edge on `--color-base`, no backdrop), in a separate borderless always-on-top window positioned relative to (left of, clamped) the findings window — this chunk must leave that structure intact (per layout-templates §Surface: desktop-webview → Primary screens → Report window). Whether the shipped `Report.tsx` still matches that structure at HEAD is research's question.
- The error variant of a data-view state region is required to be a distinct branch checked BEFORE the empty branch, showing a **static** message and **never the raw `AppError`**, with no exporter hint — so a failure never masquerades as "no data" (per layout-templates §Component — Empty / error state (desktop-webview data views) → Error). Note that section's stated "Applies to" names Metrics / Logs / Snapshots; whether the Report window's `ErrorState` is inside that shared component's contract or a sibling is research's question.
- `color-accent` (Alert Burgundy) is required to stay reserved for an optional error **icon / border** under the "never color alone" discipline, with the body-size message text carrying a role that meets the body-text contrast floor (the section names `color-text-secondary`, explicitly NOT `color-text-tertiary`) (per layout-templates §Component — Empty / error state → Empty + Error).
- The desktop-webview screen inventory is a documented, closed list (compact widget · four dashboard views · Settings panel · findings window · report window); any new user-visible screen, region, or chrome introduced by the rejection-record mechanism would require a layout amendment at wrap (per layout-templates §Surface: desktop-webview → Primary screens).
- ASCII wireframes for the findings and report windows are recorded as deliberately deferred to a future targeted touch-up per the P-070/P-082 sketch-lag handoff pattern — this chunk is NOT obliged to author a Report wireframe and should not (per layout-templates §Primary screens → Findings window / Report window).
- The surface's component stack is first-party `react-aria-components` + Tailwind; the radix family is lockfile-absent and denylisted by `pulse-app/ui/npm-policy.json`, so no shadcn/Radix component may enter the CARRY fix (per layout-templates §Surface: desktop-webview → Tooling context).

## Patterns to follow
- One shared state component backing sibling views "so the data views read as one system" — the report's error path should read consistently with the shared `EmptyState` treatment rather than diverging into a bespoke error style (per layout-templates §Component — Empty / error state).
- Error-before-empty branch ordering with static, non-raw copy — the established honest-failure shape for this surface (per layout-templates §Component — Empty / error state → Error).
- Separate borderless always-on-top window positioned from the sibling window's **live geometry**, work-area / multi-monitor clamped — the pattern the findings and report windows both follow and that any report-adjacent change must preserve (per layout-templates §Primary screens → Findings window / Report window).
- Section-level status notes govern over illustrative ASCII sketches; sketch detail is allowed to lag current truth and is corrected only by a targeted touch-up (per layout-templates §Wireframe notes — Full dashboard (Traces primary screen) and §Component — Halo State Pulse canvas status block).
- Documented tab-stop discipline as precedent: where the surface's focusable inventory changes, the layout doc records the tab-stop count and traversal explicitly rather than leaving it implicit (per layout-templates §Component — Trace data table → Keyboard / focus).

## Anti-patterns to avoid
- Body-size error text in `color-accent` — accent may carry the icon or border only, never the message itself (per layout-templates §Component — Empty / error state → Error, "never color alone").
- Surfacing raw `AppError` / ACL-rejection strings (e.g. `... not allowed by ACL`) in user-facing copy; the rejection detail belongs at the wire record, not on the surface (per layout-templates §Component — Empty / error state → Error).
- Introducing an undocumented screen, region, banner, or toast on desktop-webview to expose the rejection — the screen inventory is closed without an amendment (per layout-templates §Primary screens).

## Contract bindings
- layouts ↔ a11y: the CARRY fix's contrast ratio is a11y's SC 1.4.3 call (the layout section cites SC 1.4.3 for body-size text); layouts owns only the structural reservation of `color-accent` to icon/border. Binding per layout-templates §Component — Empty / error state.
- layouts ↔ design: **token discrepancy to resolve at plan** — layout-templates §Component — Empty / error state names `color-text-secondary` for the error-variant message, while the chunk scope's CARRY fix names `--color-text-primary` for the Report `ErrorState`. Which token lands is the design distiller's / plan's ruling; layouts requires only that accent leave the text.
- layouts ↔ obs / security: the rejection record is a wire observable, not a surface element; layouts' contribution is the negative assertion that no visible region, control, or focusable element is added to the Report or findings windows by the record mechanism (per layout-templates §Primary screens).

## Acceptance criteria contributions
- (layouts) The Report window still renders as the six-section `Report` in the `Modal` `fill` variant (edge-to-edge on `--color-base`, no backdrop, positioned left of the findings window and clamped), with no region or chrome added by the rejection-record work (per layout-templates §Primary screens → Report window).
- (layouts) After the CARRY fix, the report `ErrorState` message text no longer carries `color-accent`; accent survives only on an icon or border, per the "never color alone" reservation (per layout-templates §Component — Empty / error state → Error).
- (layouts) The report error path shows a static message and never the raw `AppError` or the ACL-rejection string; the attributable text appears only in the wire record (per layout-templates §Component — Empty / error state → Error).
- (layouts) The desktop-webview screen inventory is unchanged — no new screen, window, or visible region; if any visible control or region IS added, a D-layout-surface amendment to §Primary screens is owed at wrap (per layout-templates §Primary screens).
