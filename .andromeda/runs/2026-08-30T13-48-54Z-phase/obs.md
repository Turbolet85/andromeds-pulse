## Constraints
- The new rejection record MUST get its OWN EXACT allowlist leaf; a leaf-less target falls through `for_target`'s first-`.`-segment resolution, and the failure direction depends on whether a bare prefix key exists — no bare `app` key is registered (so `app.*` leaf-less = every field redacts), while a bare `metric` key legitimately exists (so `metric.*` leaf-less = `value` survives and every label silently redacts). Which shape applies to this chunk's chosen target prefix is research's question (per obs-plan §8 Default-deny posture; `app.boot.window.navigation` + delegated-timing entries).
- The leaf MUST enumerate EVERY field the emit site emits, asserted by set EQUALITY in both directions plus a fallback discriminator proving the prefix set cannot serve the target — a leaf naming fewer fields leaves the target PARTLY redacted, the shape no resolver-only probe can see (per obs-plan §8, `triage.incident.persist` five-field rule + `triage.cue.tick` completion narrative).
- The guard MUST live under `pulse-app/tests/`, not in a src-level `mod tests` — `[lib] test = false` means a src-level guard compiles but never runs (per obs-plan §8 `triage.baseline.bootstrap_window.override` / `tray.signpost.shown` / `interpretation.incident.created` entries).
- Dual-site registration is required: a new self-observation target is registered at BOTH §6 (level + its emission discipline — once per rejection, never per retry/render, off any hot path) AND §8 (the leaf). A §8-only apply leaves §6 stale (per obs-plan §6 Log levels mapping + §8; the rule as stated at the `app.boot.window.navigation` and L4 path-guard entries).
- Fields MUST be bounded only: a bounded static `error_category`, a `sanitize_window_label`-shaped label (bounded 4-window-label set + `unknown`), and a byte count. The IPC-bridge error text itself is Vector 2 material — error category + user-facing message only, never the `source()` chain, Rust struct names, file paths, or library versions (per obs-plan §1 logging-sensitive Vector 2 + §8 Data classification, `AppError` row).
- If the frontend arm wins, the hand-rolled TauRPC `telemetry.frontend.*` bridge is the DECIDED and only sanctioned route — the webview has NO browser OTel SDK and NO direct file access; all frontend telemetry goes through TauRPC → backend `tracing` (per obs-plan §3 Logging stack → Frontend bridge, and §1 Telemetry surfaces desktop-webview row).
- The record MUST be NDJSON on the shared sink at `~/.andromeda-pulse/logs/agent-latest.jsonl` carrying the required line fields (`timestamp` / `level` / `target` / `message` / `fields`) plus the service-identity default subscriber fields — the log-format schema is a binding contract obs aligns TO tests, not vice versa (per obs-plan §3 Log format JSON schema + §6 Required fields).

## Patterns to follow
- `tray.signpost.shown` — the nearest precedent in shape: a single `window_label` field produced by `sanitize_window_label`, an EXACT leaf, a no-bare-`tray`-prefix ban, a mutation-checked guard, and a headful stage that matches the record BY the label field rather than by record presence (per obs-plan §8).
- `app.boot.window.navigation` — a three-field EXACT leaf (`window_label` / bool / bounded `reason`) with the field most likely to be added "for debuggability" (the URL) banned outright, and the recorded failure mode that a leaf-less version makes the measurement read as all-zeroes (per obs-plan §8).
- `interpretation.model.load.error` — the bounded-`error_category` precedent: a per-rejection WARN with its category drawn from an explicitly enumerated set and a basename-only path discipline, bounded to a non-hot-path site (per obs-plan §6 `warn` row + §8 L4 leaves).
- TauRPC router instrumentation — `#[tracing::instrument(skip_all, fields(traceparent = %tp))]` on each router method, with the §6 boundary-wrapper field set for a TauRPC invocation (`method_name`, `argument_digest` as a hash not content, `result_type`, `latency_ms`) and the `ui-bridge` allowlist that matches it (per obs-plan §4 Instrumentation per surface + §6 Boundary-call wrappers + §8 `ui-bridge`).
- Any xtask check script added over `agent-latest.jsonl` for the headful leg must be NEUTRAL-tolerant (absent stream ≠ failure) so headless and full-app sessions share one script set (per obs-plan §10 Load-profile constraints).

## Anti-patterns to avoid
- NEVER log the payload, clipboard content, or raw attribute/parameter values on the rejection record — default-deny posture, scrub at source via `skip(...)` plus the subscriber Layer, never at one layer only (per obs-plan §11 PII Scrubbing + §11 Logs).
- NEVER serialize `anyhow::Error` (or the raw runtime rejection string) directly across the IPC boundary into the record — convert to `AppError` and sanitize per Vector 2 (per obs-plan §11 Spans/Traces).
- NEVER emit at `info` on a hot path — the record's emission discipline must be once per rejection transition, never per render, retry, or component re-mount (per obs-plan §11 Logs hot-path ban).

## Contract bindings
- **obs ↔ tests**: the §3 log-format JSON schema is taken verbatim FROM the tests Test Harness Contract; the headful/wire assertion for this chunk consumes that format, and obs §10's NEUTRAL-tolerance rule governs any new check script. Whether the existing `report-copy` stage can already match a FIELD (vs. record presence) is research's question.
- **obs ↔ security**: the chunk's driver is security-plan §Logging & Monitoring "What to log" (capability-rejected IPC calls); obs §8 PII scrubbing + §1 Vector 2 (AppError sanitization at the IPC bridge) are the obs-side terms of that binding.
- **obs ↔ a11y**: none for this chunk — obs owns only the a11y violation-JSON → structured-log binding, which the CARRY `Report.tsx` contrast fix does not touch.

## Acceptance criteria contributions
- The new rejection target resolves to its OWN exact allowlist leaf whose field set equals the emit site's, asserted both ways plus a fallback discriminator, in a guard under `pulse-app/tests/` where it actually runs (per obs-plan §8 Default-deny posture).
- The record is registered at BOTH §6 (level + once-per-rejection emission discipline) and §8 (the leaf) — a §8-only apply fails this check (per obs-plan §6 Log levels mapping + §8).
- At the wire, the record's fields appear UNREDACTED in `agent-latest.jsonl` while the payload / clipboard content / raw error text appear 0 times — the discriminating revoked-vs-granted pair from the scope is what makes this gradeable (per obs-plan §8 + §11 Logs).
