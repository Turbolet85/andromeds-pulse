## Constraints

- The connection-state dot color MUST come from the NASA Deep Space palette semantic mapping, not arbitrary hex: healthy states (Listening/Receiving/Idle) → `--color-primary` (#4A90E2 Earth Blue = "service running, responding nominally"); Stalled (Severity::Warning) → `--color-accent` (#C7556A Alert Burgundy = anomaly/suspect); ReceiverFailed (Severity::Critical) → `--color-accent` (#C7556A); success/confirmation-only states would use `--color-feedback-success` (#17B3A3) but no connection state maps there (per design-system §Color Palette Core Colors + §Semantic Colors). No new hex values may be introduced without a Decisions Log entry.
- The dot is a small round status indicator → use `radius-full` (9999px) per the §Border Radius mixed strategy ("only badges and toggles use radius-full to signal complete/whole, reinforcing the constellation/halo metaphor"). The 6–8px spec from the chunk brief fits the badge size class.
- Tooltip surface MUST use `--color-raised-2` (#2D3139) background — the §Surface Scale designates Raised-2 explicitly for "dropdowns, popovers, tooltips" — with a 1px subtle border `rgba(74, 144, 226, 0.1)` per §Depth Strategy (borders-only; NO shadow on dark surfaces) and `--radius-md` (6px) per §Border Radius cards/panels class (per design-system §Surface Scale + §Depth Strategy).
- Tooltip text MUST follow the typography split: the connection state label + descriptive prose in `--font-body` (IBM Plex Sans) 12px Label/14px Body; the "last span <ago>" duration value in `--font-code` (JetBrains Mono) 12px with tabular-nums (the existing FooterBand `NUMERIC_STYLE` is the precedent — monospace = "immutable telemetry fact") (per design-system §Typography Data/Body rows).
- All spacing for dot placement, dot-to-icon gap, and tooltip padding MUST use the 4px-base scale tokens (`--spacing-micro` 2px / `--spacing-xs` 4px / `--spacing-sm` 8px); the dot-to-app-icon gap in the titlebar mirrors the existing `gap: var(--spacing-sm)` titlebar rhythm (per design-system §Spacing).
- Compact-widget chrome density discipline: "every pixel of chrome counts — icons must serve information architecture, not visual filler" (§Iconography Rule). The footer-band removal aligns with this; the connection dot must be load-bearing (state encoding), not decorative.

## Patterns к follow

- Custom Observatory glyphs over stock icons: the titlebar app icon already uses `<Icon glyph="constellation-grid" size={16} />` (`pulse-app/ui/src/components/Titlebar.tsx`); the connection dot sits adjacent to it. If a glyph is wanted for the dot, prefer the custom set / a simple round element over a Lucide/Heroicons stock status glyph (per design-system §Iconography + §Rejected Defaults "Generic icons from a stock library").
- State-via-color-AND-shape (not color alone): the existing FooterBand error-value pattern pairs `--color-accent` border with `--color-text-primary` text + the percentage number carrying meaning (`pulse-app/ui/src/widget/FooterBand.tsx` lines 56-57, 110-122); the connection dot must carry its state via the accompanying tooltip text label / aria-label, not the dot color in isolation (per design-system §Anti-Patterns "NEVER use color purely for decoration" + §Decisions Log 2026-05-03 "never communicate state with color alone").
- Reduced-motion-aware transitions on hover affordances: existing titlebar buttons carry `className="...motion-reduce:transition-none motion-reduce:duration-0"` + `transitionDuration: var(--duration-fast)` (Titlebar.tsx lines 97/107-108/118/127-128); any tooltip fade-in or dot color transition follows the same `--duration-fast` (150ms) ease-out with the `motion-reduce:` variant (per design-system §Motion micro-interactions + §Motion Accessibility).
- Titlebar segment-order convention `[app-icon + title | grow | settings | window-controls]` (Titlebar.tsx header comment lines 30-31) — the connection dot inserts within the app-icon segment (near the icon, before/after the 16px glyph), preserving the established left-cluster grouping and the `data-tauri-drag-region` drag behavior on non-interactive elements (per design-system §Surface desktop-webview Component Patterns Navigation/App Shell — Titlebar).

## Anti-patterns к avoid

- NEVER use a uniform monochrome status icon (green ✓ / red ✗) for the connection dot — this is an explicitly Rejected Default; the dot encodes state via the NASA-palette hue taxonomy (Earth Blue healthy / Alert Burgundy anomaly), not a generic on/off checkmark (per design-system §Rejected Defaults "Uniform monochrome status icons").
- NEVER add a shadow, gradient, or glassmorphic effect to the tooltip popover — depth is borders-only on dark surfaces; the Halo State Pulse is the only gradient/blur exception (per design-system §Depth Strategy + §Anti-Patterns Universal Bans).
- NEVER use an opacity fade longer than 200ms or any spring/bounce easing for the tooltip emergence — chrome motion is capped at 150–200ms ease-out (per design-system §Motion Hard limits).
- NEVER hardcode the 6–8px dot size or any color as a raw pixel/hex literal in the component — derive size from the badge size class and color from `--color-*` tokens (per design-system §Self-Validation Token Test + §Anti-Patterns).

## Contract bindings

- **Design ↔ a11y (Use of Color SC 1.4.1)**: the connection dot color encodes state but MUST be paired with a text affordance — the chunk brief's tooltip ("current connection state + last-span-ago") and the a11y aria-label ("Connection: <state> — last span <ago>") satisfy the not-color-alone discipline. Design supplies the palette tokens; a11y owns the SC 1.4.1 conformance assertion.
- **Design ↔ a11y (Contrast SC 1.4.3 / SC 1.4.11)**: the dot color on the `--color-base` (#1A1D24) titlebar background and the tooltip text on `--color-raised-2` (#2D3139) MUST meet non-text 3:1 (dot) and text 4.5:1 (tooltip body) thresholds. Note: `--color-accent` (#C7556A) is classified as a non-text token (~3.8:1 on Base per §Decisions Log 2026-05-03) — it clears the 3:1 dot threshold but is BELOW 4.5:1 for normal-size text, so any Stalled/ReceiverFailed text label must use `--color-text-primary` (#E8EEF7), not accent-colored text. Design supplies target ratios; a11y owns formal WCAG derivation.
- **Design ↔ a11y (Motion SC 2.3.3 AAA)**: every dot/tooltip transition respects `prefers-reduced-motion: reduce` (instant, no fade). Design supplies the `motion-reduce:` token pattern; a11y verifies via Playwright `emulateMedia`.
