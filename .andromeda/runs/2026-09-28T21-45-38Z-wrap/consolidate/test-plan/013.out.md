## 2026-08-15-tier-1-incident-path-investigation — run-scope must match build-scope; observability.rs is a boot path
**Section:** §3 Test Harness Contract → `run` (Test selection) · §3 Per-chunk gate discipline → Boot-smoke gate
**Change:**
1. §3 `run`: narrow a `pulse-app` run with `--filter-expr` / `-E` **under `--workspace`**, not with `-p` — `--workspace` unifies features across members while `-p` resolves a narrower subgraph, so a `-p` selection is not guaranteed compatible with artifacts a `--workspace` build produced. `-p` is NOT banned generally: `cargo test --test <name> -p pulse-app` remains the documented single-binary path for the rlib family.
2. The Boot-smoke gate's trigger list gains `pulse-app/src/observability.rs` (boot-time subscriber/allowlist init, before the OTLP bind); a new "Direct-binary smoke variant" paragraph accepts an alternative form — fresh `ANDROMEDA_PULSE_DATA_DIR` + an env-gated mode + a sustained `inject_demo` load, asserted from the run's own log artifacts with clean shutdown by specific pid — for verifications the `npx @tauri-apps/cli dev` and harness `run` forms cannot express.
**Why:** measured: `cargo nextest run -p pulse-app -E 'binary(…)'` failed to link with `crate X required to be available in rlib format` immediately after a green `cargo build --workspace --tests`, while the identical selection under `--workspace` passed. The chunk's only production edit was `observability.rs`, a boot path absent from the trigger list, and its fields are produced only by a live storm across full boots — no in-process form could observe them. Doc-only: the chunk's own commands were already correct, no impl half.
