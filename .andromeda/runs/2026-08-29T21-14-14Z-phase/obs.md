## Relevance
Partial — the chunk adds no telemetry target, but its bumps cross three instrumented surfaces (MCP sidecar, plugin host, OTLP/HTTP ingest) and the strict-path decision touches the basename-only path-logging discipline; the obs obligation is preservation-under-bump, not new instrumentation.

## Constraints
- The rmcp stdio sidecar must write NOTHING to stdout (reserved for JSON-RPC 2.0 framing) and must force ALL `tracing` output to stderr as JSON with the TTY check disabled — per obs-plan §11 Universal and §3 Logging stack / §6 Sink configuration. A 0.6→1.4 major jump can move transport plumbing or introduce library-side stdout writes; whether the shipped sidecar already forces stderr-JSON and emits zero stdout noise is research's question.
- MCP tool records must carry `result_type` + `result_count` metadata ONLY, never `result_content`, and `mcp.feature.gate.check` must carry `feature_flag_enabled` + `env_var_mcp_enabled` — per obs-plan §8 (`mcp-server` whitelist), §1 (logging-sensitive Vector 4 trigger), §4 Scenario P3, §11 Project-specific. If the `#[tool]` macro surface changes shape, the fields reaching `tracing` must not widen.
- The P4 plugin-lifecycle chain (`plugin.load.request` → `wasmtime.instantiate` → `plugin.capability.check` → `plugin.invoke.request` / `.error`) must survive the wasmtime bump with host-side `#[tracing::instrument(skip(input, output))]` wrappers, `plugin_path_basename` never a full canonicalized path, and plugin-returned Arrow IPC size-capped (8 MB) rather than logged — per obs-plan §4 Scenario P4, §1 Vector 3 trigger, §8 (`plugin` whitelist), §11 Spans/Traces + Project-specific.
- Whatever the strict-path decision, the invariant is basename-only path emission, not the primitive that enforces it: §1's Vector 6 row requires basename-only at every path-guard site (explicitly NOT only `config.load`, and explicitly including `ANDROMEDA_PULSE_L4_ALLOW_ROOT` which matches neither `*_PATH` nor `*_DIR`), and §8 pins the affected leaves — `app.boot.workspace_key` (`workspace_root_basename` + `key_bytes` only), `interpretation.model.allow_root` (`confinement`, `root_basename`), `interpretation.model.load.error` (6 fields incl. `env_var`, `path_basename`).
- The self-observation runtime is `tracing` + `tracing-subscriber` + `tracing-appender` + `tracing-error` ONLY, pinned at workspace level, with NO OTel SDK linked into the product binary; the OTLP wire crates (`tonic`/`axum`/`prost`/`opentelemetry-proto`) are parse-only and must stay that way through the lockfile churn — per obs-plan §3 Logging stack, §1 (architectural choice), §11 Universal.
- The h2/hyper/axum path crosses the instrumented HTTP ingest boundary: `ingest.http.export.request` must keep emitting `route` / `status_code` / `body_size_bytes` / `latency_ms`, and DefaultBodyLimit rejection must keep emitting `ingest.http.body_size.exceeded` (`body_size_bytes`, `limit_bytes: 8388608`, `http_response_code: 413`) as plain `tracing` spans via the manual `tower::Layer`, never OTel-flavored — per obs-plan §6 Boundary-call wrappers, §4 (API service HTTP `:4318` row), §1 chaos-instrumentation trigger.
- CI/verification gates apply unchanged to every post-bump run: zero `app.panic.fatal` records, ≤45s heartbeat gaps across `ingest`/`buffer`/`viz`/`plugins` ticks, and NEUTRAL-tolerant check scripts over `agent-latest.jsonl` — per obs-plan §10 CI gates + Load-profile constraints, §10 Always-required invariant.

## Patterns to follow
- Dependency-bump-closes-an-obs-defect precedent (obs-plan §10, DuckDB Connection Isolation defect 4): the `duckdb`/`libduckdb-sys` `1.10502.0 → 1.10505.0` close came from a stale lockfile under an untouched `^1.10500` requirement — the same shape as this chunk's lock-only `h2` update. The recorded discipline is to verify the behaviour change at the wire (timed pin: 30s timeout vs 0.06s pass), not to infer it from the requirement.
- Exact-allowlist-leaf discipline (obs-plan §8 Default-deny posture): any target whose fields move must have its own EXACT leaf enumerating every field its emit site emits, asserted by equality in BOTH directions, with the guard under `pulse-app/tests/` — `[lib] test = false` means a guard in `observability.rs`'s own `mod tests` compiles but never runs.
- Manual instrumentation only (obs-plan §4 instrumentation-per-surface table): `#[tracing::instrument]` on handlers, no auto-instrumentation crates; `tower-http::TraceLayer` acceptable only in its plain-`tracing` (non-OTel) form.
- Warn-on-fallback shape for degraded-but-functional paths (obs-plan §10, `viz::query::read_connection`: target + `fallback = "shared_connection"`), with `reason` / `error_category` drawn from bounded static token sets (obs-plan §6 `warn` row).

## Anti-patterns to avoid
- NEVER write to stdout from any subsystem running as the rmcp stdio sidecar — any `println!` / `dbg!` / library stdout write corrupts JSON-RPC framing and silently disconnects the client (obs-plan §11 Universal).
- NEVER log MCP tool response bodies (§11 Project-specific, Vector 4) or full canonicalized plugin file paths (§11 Spans/Traces, Vector 3) — the two bans most exposed by an rmcp major jump and a wasmtime host-wrapper rewrite.
- NEVER link an OTel SDK into the self-observation runtime (obs-plan §11 Universal) — a transitive pull-in through the bumped dependency graph would violate the by-construction recursion guarantee of §1/§3.

## Contract bindings
- **obs ↔ tests harness:** the JSON log schema in obs-plan §3 / §6 is verbatim from the tests harness contract and obs aligns to tests, not vice versa — the entry-mandated plugin-host and MCP-sidecar verification legs consume `~/.andromeda-pulse/logs/agent-latest.jsonl` and the `health` IPC shape; §10 names `cargo xtask check:ingest-progress` and `xtask/ci/heartbeat-gap-check.sh` as the post-run assertions, and requires NEUTRAL-tolerance so headless runs share one script set.
- **obs ↔ security:** the basename-only path rules and the response-body/query-parameter bans are the security plan's logging Vectors 1–6 realized at logger config (obs-plan §1 telemetry triggers, §8 Data classification). The strict-path adopt-or-drop decision changes the primitive; it must not change what reaches the log line.
- **obs ↔ arch/deps:** obs-plan §3 Logging stack states the `tracing` crate set is pinned at workspace level — the same workspace `Cargo.toml` this chunk edits.
