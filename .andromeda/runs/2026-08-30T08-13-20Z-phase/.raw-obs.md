## Constraints
- Every emitting target must resolve to its OWN EXACT allowlist leaf enumerating EVERY field its emit site emits — the emit site is the authority, and a leaf naming fewer leaves the target PARTLY redacted, a shape no resolver probe can see because the named fields keep rendering fine (per obs-plan §8 Default-deny posture, incident-path leaves + `triage.cue.tick`). This is the rule behind A1/A2/A4/A5 and any new C1 leaf.
- The fallback shape dictates the repair, and it differs by family: a bare `metric` key legitimately exists (`value`/`unit`/`module`), so the `metric.*` rule is per-target-own-leaf — without one `for_target`'s first-`.`-segment fallback KEEPS `value` and silently redacts every label; for the `triage` / `corpus` / `interpretation` families the rule is that NO bare prefix key may exist (per obs-plan §8, delegated-timing leaves + muted-diagnostic backlog). A1/A2 are the bare-`metric` partial shape; A4 is the one target resolving to nothing.
- obs-plan §8 states the no-bare-`interpretation` invariant as a requirement AND records it as VIOLATED IN CODE (measured 2026-08-26 at `pulse-app/src/observability.rs:1934`), naming this route entry as owner; the plan requires the invariant, and whether the breach still stands at HEAD is research's question (per obs-plan §8, `interpretation.incident.created` entry).
- Allowlist guards must live under `pulse-app/tests/` — `[lib] test = false` makes a src-level `mod tests` compile, pass clippy and never run — and must assert the field set by EQUALITY IN BOTH DIRECTIONS plus a fallback discriminator, because a resolver-only probe passes vacuously when a bare prefix key can serve the target (per obs-plan §8; the plan names the `interpretation.incident.created` field-completeness guard migration to this entry).
- No record may emit a full canonicalized filesystem path; path-bearing fields carry basename only, and §8 requires this beyond the `config.load` site — `config.load` is explicitly NOT the sole enforcement site and `*_PATH` / `*_DIR` is explicitly NOT an exhaustive naming convention (per obs-plan §1 logging-sensitive Vector 6 row; §8 `app.boot.workspace_key` basename+byte-count-only precedent). Governs A7.
- Per-cue / per-row / per-record emission on a hot path is barred; the sanctioned alternative is a fold computed once per batch or cycle and ridden out as FIELDS on an existing heartbeat record, aggregate counts only (per obs-plan §5 tick-aggregated Counter rows; §11 Telemetry Strategy + Logs hot-path bans). Governs A8's disposition and C1's `append_rejections` shape.
- The JSON log line schema is a BINDING contract that obs aligns TO tests (not vice versa), and the file is daily-rotated by `tracing_appender::rolling::daily(log_dir, "agent-latest.jsonl")` with the previous day's file read when the current one does not yet exist; any check script over that file must be NEUTRAL-tolerant (absent stream ≠ failure) (per obs-plan §3 Log format JSON schema + Log file location; §10 Load-profile constraints). Governs B2's readers.
- Heartbeat ticks and the `health` command are complementary and must not be conflated: ticks are asynchronous retroactive LIVENESS, `health` is synchronous active liveness probing, and both are tick-derived so neither reports PROGRESS (per obs-plan §3 Heartbeat ticks + complementarity paragraph; §1; §10 Standard+ invariants). Bears on B1 — a status verb that describes a mock reports on neither.

## Patterns to follow
- Leaf COMPLETION over leaf addition, with three-way mutation checking: `triage.cue.tick` 5→9 fields and `triage.incident.persist` 2→3→4→5 fields are the worked precedents, including the narrowed-leaf mutation arm in which the exact-resolve pin PASSES while the field-set pin fails (per obs-plan §8).
- Exact leaf + fallback-discriminator test where a legitimate parent key exists: `buffer.consumer.stalled` (bare `buffer` exists, so the fallback would redact all four fields) and the three delegated-timing `metric.*` leaves (bare `metric` keeps `value`, drops labels) (per obs-plan §8).
- Tick-aggregated FIELDS counter for C1: mirror `BufferState::record_redactions` / `record_feed_counts` — fold once per batch, return the per-batch tally from the builder and fold at the table's OWN post-append site so a rejected batch contributes zero, aggregate counts only, never identity (per obs-plan §5 Conceptual instrument types, `redactions_applied` row).
- Explicit leaf for dotted `app.*` boot targets: `app.boot.buffer.degraded`, `app.boot.workspace_key` and `app.boot.window.navigation` each carry an exact leaf precisely because the fallback would resolve an `app`-prefixed dotted target to an unrelated field set (per obs-plan §8) — the shape A7's `app.boot.tracing.init` / `app.boot.pid` records sit in.
- Bounded-value sanitizers as the emission-site guard: `workspace_root_basename`, `plugin_path_basename`, `root_basename`, `path_basename`, `sanitize_window_label` (per obs-plan §8; §1 Vector 3/6 rows).
- Dual-site / triple-site restating discipline for wrap amendments: a new or changed WARN target is stated in BOTH §6 and §8, and a `buffer.tick` field change is stated at all three restating sites (§1 field list, §5 counter row, §8 whitelist) (per obs-plan §6 + §8; §1 Heartbeat ticks).

## Anti-patterns to avoid
- NEVER log full canonicalized paths — basename only (per obs-plan §11 Logs/Spans; §1 Vectors 3 and 6). A7's "state the exception at the emit sites" arm is a deviation from an unconditional §11 ban and would have to be recorded as such, not adopted silently.
- NEVER log in a hot path at `info` level, and never emit per-row / per-cue / per-record where a once-per-cycle fold will do (per obs-plan §11 Telemetry Strategy + Logs; §5 hot-path bar restated on every tick-aggregated counter row). Directly governs A8's 4,599-records-per-wedge shape.
- NEVER admit identity or unbounded values into a leaf — no `scope_id`, service name, query text, row content, path value, or matched redaction value; aggregate counts and bounded static labels only (per obs-plan §8 Default-deny posture; §11 PII Scrubbing).
