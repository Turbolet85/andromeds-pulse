## Constraints
- **Crate placement is locked; no new workspace member.** Every touched surface must land in an already-reserved crate — `pulse-app` (allowlist leaves, emit sites, never-run-test migration), `buffer` (schema/retention/counter), `triage` (cue/cadence), `corpus` (DDL), `xtask` (harness verbs) — and no library crate may depend on the binary crate (per architecture.md §Occupied Resources → Cargo workspace crate names; §Cross-cutting Patterns → Module dependency direction; §Inherited Defaults → Module boundaries).
- **The three producer-less DuckDB tables are arch-owned work, not optional cleanup.** §Occupied Resources → DuckDB database / schema names records `resources` / `instrumentation_scopes` / `span_links` as declared-and-swept-but-never-written (measured 2026-08-23) and explicitly names this entry as owner of the impl disposition; either fork (producer lands / dead schema + dead DELETEs retired) requires the registry restated at wrap (per architecture.md §Occupied Resources → DuckDB schema names).
- **Corpus and event registries are amendment surfaces.** `baseline_state` is enumerated in §Occupied Resources → Corpus SQLite reserved tables, and `pulse://stream/incidents` is enumerated among live §Occupied Resources → Tauri IPC events; a C2 drop (DDL + `SCHEMA_VERSION`) or a C6 "producer-only" qualification changes what those registries assert and must be carried as a wrap amendment (per architecture.md §Occupied Resources → Corpus SQLite database / schema names + Tauri IPC events).
- **New crate-public state must surface through the contract module only.** A C1 `append_rejections` fold on `BufferState` follows the crate's `pub`-contract / `pub(crate)`-internals discipline and the in-repo boundary precedent (`BufferState::reserve_log_seq_block` / `reserve_metric_seq_block`) — unlike `seq`, which §Conventions declares deliberately *never* an observable, this counter is intended as one, so it needs its own exact allowlist leaf rather than riding an existing key (per architecture.md §Conventions → Module visibility discipline + Primary key convention).
- **Unit-bearing field names are a convention, not a preference.** §Conventions → Configuration units requires durations to carry explicit units in the field name; a `persistence_seconds` holding a raw sample count (C4) is a convention violation as written, so the fix must resolve on one side (rename-to-truth or convert-to-seconds) — which side is a P4 fork, and whether the divergence still reproduces at HEAD is research's question (per architecture.md §Conventions → Configuration units).
- **Harness truth rides registered resources.** §Occupied Resources → Process / service identity locks the dev-build path `target/{profile}/pulse-app(.exe)` against the bundled `andromeda-pulse(.exe)` (the latter exists on no host), and §Occupied Resources → Filesystem locations registers `run/andromeda-pulse.pid` as written by the production binary and consumed by `scripts/agent-run.{sh,ps1}` for status/cleanup; B1/B2 fixes must use those, plus the harness-only env class (`ANDROMEDA_PULSE_PIDFILE` / `_LOGFILE` / `_DATA_DIR_KEEP`) rather than inventing a resource (per architecture.md §Occupied Resources → Process / service identity + Filesystem locations + Environment variables).
- **The GUI-harness Role cell is arch's only statement of the assembled path.** §Stack and Technologies → GUI verification harness (dev-only) enumerates the stage list, its growth lineage, the `cargo xtask webview-drive [--expect-absent &lt;STAGE&gt;] [--no-inject]` CLI shape, and the rule that `PULSE_INJECTOR` carries the PATH only with no arguments threaded (so the storm BUDGET, not bytes, is the leg's dependency); a B6 stage addition amends that cell and must not thread injector args (per architecture.md §Stack → GUI verification harness; §Occupied Resources → Environment variables `PULSE_INJECTOR`).

## Patterns to follow
- **Apply-as-measured, defer-impl-with-a-named-owner** — the registry records measurement at one wrap and names the entry that owns the cleanup (the 2026-08-23 reserved-tables amendment did exactly this and named this chunk). Dispositions taken here close that loop in the same shape: measured statement in the body, change record in the sidecar.
- **Tag-defer rather than hard-delete for unconsumed surfaces** — §Occupied Resources already carries "(deferred — no runtime emitter/consumer as of chunk #74)" tags on `snapshot.list_recent`, `workspace.list`, `pulse://stream/plugin-events`, `ANDROMEDA_PULSE_CONFIG_PATH`. That is the sanctioned wording shape for C6's "record as producer-only" arm and for a document-not-drop arm on C2/C3.
- **Reservation ≠ live write path** — §Occupied Resources already distinguishes declared tables from written ones in prose; any new claim keyed on "the reserved tables" must carry the same qualification rather than re-flattening the list.
- **Narrow read port at the binary boundary when a consumer is needed across the DAG** — §Established Decisions [Corpus Write Arbitration] describes `DurableActiveIncidents::active_incident_ids` (declared in `triage`, implemented at the `pulse-app` boundary, no new crate edge) as the shape for adding a cross-layer consumer; C6's "wire a consumer" arm should follow it rather than adding a crate dependency.
- **Formalized xtask CLI contract shape** — §Occupied Resources → xtask CLI surfaces records `check:npm-supply-chain`'s contract (exit codes, named verdict arms, one JSON object on stdout) as the registry-worthy form; if B1 gives `harness:status` an honest formalized contract, that is the shape and it becomes a registry item.

## Anti-patterns to avoid
- **No mock/in-process stand-in standing in for the process under test.** §Cross-cutting Patterns → Test-time telemetry injection bans in-process bypasses and mock back-doors for verification and requires E2E to speak the real surface; a `tauri::test::mock_builder` app answering `harness:status` (B1) is that ban's shape — the replacement observes the real process or fails.
- **No new crate, no re-purposed reserved name, no library→binary dependency.** §Project Intent states the reserved crate names cannot be re-purposed and §Cross-cutting Patterns → Module dependency direction requires a DAG rooted at `pulse-app`; a C6 consumer or a C3 producer must not invert it.
- **Never dial the product's own OTLP ports for self-telemetry.** §Established Decisions [Self-Observation] + §Cross-cutting Patterns → Self-observation discipline confine the product's own records to the stdout/file exporter under `logs/`; Family A un-muting stays entirely on that path.
