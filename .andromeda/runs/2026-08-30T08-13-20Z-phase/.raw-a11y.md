## Constraints
- Every new/unaudited surface state must get an axe spec **in the same chunk**, and `installTauriIpcMock`'s `__mockReject` (settle rejected) and `__mockDelayMs` (settle late) sentinels exist precisely so error and in-flight states are auditable, not only the settled-success one — B7 is a direct application of this standing rule (per a11y-plan §3 Harness wiring &amp; conventions → "Adding a surface"). Whether p9's rejected/in-flight copy states are genuinely unaudited at HEAD is research's question; the scope records it as a 2026-08-27 measurement, and my plan can only state the requirement.
- Fixtures driving any added spec must be POPULATED — an empty array renders nothing, so a sweep audits a blank region and passes by comparing nothing (per a11y-plan §3 Harness wiring &amp; conventions). This is the same false-green class the chunk exists to close.
- p9 (diagnostic report modal) is inside the must-be-accessible set P1–P14; the universal minimums **SC 2.1.1 Keyboard / SC 2.4.3 Focus Order / SC 4.1.2 Name, Role, Value** plus the §10 SLO coverage apply to it and therefore to any state of it that is audited (per a11y-plan §1 Surface set extension + §10 Standard+ WCAG SC coverage report).
- A rejected copy attempt is a status message: blocking errors require `role="alert"` / `aria-live="assertive"`, non-blocking status `aria-live="polite"` (SC 4.1.3); an async control in flight carries `aria-busy` (per a11y-plan §7 Live regions + §4 Button / Status-Alert rows). Whether the shipped copy affordance already exposes these is research's question.
- Rejected/success state colours must not be color-alone and must meet their pair ratios — `--color-accent / --color-base` and `--color-feedback-success / --color-inset` at 4.5:1 text / 3:1 non-text (SC 1.4.1, SC 1.4.3, SC 1.4.11) (per a11y-plan §6 Color contrast pairs + State color tokens).
- Anything the new coverage surfaces is a **hard gate**, not a soft one: zero new WCAG AA violation tuples vs `baselines/a11y-violations-summary.json`, no retry-once, no deferral to a follow-up (per a11y-plan §3 Regression baseline, §10 Build/deploy failure conditions, §11 CI + SLO).
- Every WCAG claim needs machine-verifiable evidence; a "disposition recorded" outcome for B7 that rests on manual SR/keyboard inspection does not discharge it (per a11y-plan §2 Agent-runnable invariants + §11 Universal).

## Patterns to follow
- The p8–p14 axe specs are the template for adding coverage, with the `keyboard-focus/widget-and-modals.spec.ts` focus spec alongside; single-surface fixtures may live inline in the spec rather than in `helpers/v02-fixtures.ts` (per a11y-plan §3 Harness wiring &amp; conventions).
- Cheap suite-health verification via `npx playwright test --list` — my plan records that a list-time import failure once silently disabled the whole a11y suite (per a11y-plan §3 Harness wiring &amp; conventions). Same defect class as B4's never-run `#[test]` block; the check belongs in this sweep's evidence, not just its narrative.
- IPC mocking shape: TauRPC procedures invoked as `TauRPC__&lt;router.path&gt;` (taurpc 0.7); window label read from `__TAURI_INTERNALS__.metadata.currentWebview.label`; `plugin:event|listen` handled for push channels; SPA served via `helpers/static-server.mjs` with `-P` fallback because TanStack Router uses browser history (per a11y-plan §3 Harness wiring &amp; conventions).
- The report window is `role="dialog"` (Modal `fill` variant) with focus trapped in-window and Esc/✕ restoring focus **cross-window** to the findings window via first-party Tauri events, not `focus-trap-react` (per a11y-plan §5 report-window entry + Focus restoration). A copy-completion or copy-failure state must not steal or drop that focus.
- Harness selectors bind accessible-name-first per the measured-per-surface convention; `data-testid` is retained only where no accessible anchor ships (per a11y-plan §1 P1 row, as discharged by `2026-08-23-headful-leg-extension`). B6's new boot-geometry stage should follow that convention rather than minting testids.

## Anti-patterns to avoid
- NEVER ship lint-only a11y without runtime axe-core / pa11y / Lighthouse, and NEVER treat an a11y check as a soft gate or skip it on failure (per a11y-plan §11 CI). A mute-by-omission audit is the exact failure this chunk is sweeping for elsewhere.
- NEVER absorb a newly-surfaced violation into the regression baseline or apply a retry-once policy — quarantine-investigate-fix, never mask (per a11y-plan §11 SLO + §10 Zero new violations per PR).
- NEVER leave rejected/error content out of the accessible tree (visual-only failure text, `aria-hidden` on essential content) (per a11y-plan §11 Screen Reader).
