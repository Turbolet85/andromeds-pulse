# tests extract

## Relevance
relevant — both halves land on test-plan surfaces: the PREREQ extends a CI lint step and the `pre-push:linux` verb contract, and the surfacing half needs a measure-first live leg plus a deterministic regression witness.

## Constraints
- The plan's `## Test Commands` MUST carry the unconditional standard gate set in the stated order: `capability-drift` BEFORE `cargo nextest run --workspace --profile ci`, then the `--features mcp-server` `emit_taurpc_bindings` regen as the last cargo-adjacent step. For a chunk adding no TauRPC procedure, the close is `git diff --quiet 09d0809 -- pulse-app/ui/src/bindings/index.ts`. The webview npm gates are excluded only if no `pulse-app/ui/**` path is touched (per test-plan §3 Per-chunk gate discipline).
- `cargo xtask pre-push:linux` has a fixed contract: ordered stages that stop at the first failure, exit 0 green / 1 red / 2 cannot-evaluate, and one pretty-JSON verdict `{verdict, reason, head, tree, stages[{name, ok, ms}], missing[], remediation, cache}` plus `target/pre-push/report.json`. It binds no port and starts no `pulse-app`. A source-lint stage added to it must keep that shape: a named stage, red on a hit, and no green when a needed tool is missing (per test-plan §3 `pre-push:linux` paragraph).
- Every committed test layer must give a deterministic, machine-parseable verdict. There may be no flaky retries and no human check of the result (per test-plan §2 Agent-runnable invariants). Flakiness has a zero budget: no retry-once, and a flake is quarantined and root-caused (per test-plan §10 Zero-flakiness budget). A real-model generation therefore cannot be a committed standard-gate test. The committed witness must be offline and deterministic.
- pulse-app unit-shaped tests go in `pulse-app/tests/*.rs`, not `pulse-app/src/`. `[lib] test = false`, and the flat-zero ratchet `pulse_app_src_carries_no_new_dead_test_attributes` turns the build red on any `#[test]` in lib src. `interpretation` crate pins stay co-located in `prompt.rs` `mod tests` (per test-plan §2 Test directory + naming conventions; §4 Conventions).
- The live leg follows the direct-binary smoke form. Each RED leg (at base) and GREEN leg (after the fix) uses its own fresh `ANDROMEDA_PULSE_DATA_DIR`, teardown is by specific pid, and the ports are confirmed released. Decide the defect's SHAPE before choosing its evidence. A dismissal creates no incident and emits no ERROR, so "0 ERROR / 0 panic" passes VACUOUSLY on the RED leg. The evidence of record has to be the per-generation decision outcome (per test-plan §3 Direct-binary smoke variant).
- A scenario leg proves its own preconditions. If no storm digest reached the model, the verdict is INCONCLUSIVE, never PASS. The usual exit contract is 0 PASS / 1 FAIL / 2 INCONCLUSIVE, with the artifact under `target/<leg>/` (per test-plan §3 `smoke:gap-resume` / `smoke:external-resolve` / `smoke:hue-shift` paragraphs). Those legs set `ANDROMEDA_PULSE_L4_DETERMINISTIC`. A surfacing leg run that way exercises the deterministic runner and says nothing about the real model.
- A ci.yml edit rides the CI build-failure conditions and the workflow self-lint guards (`workflow_env_references_no_step_only_context`, `data_dir_export_precedes_every_consumer`). It must not add a floating-tag action (per test-plan §9 CI Integration, Boot smoke row + Build failure conditions; §11 CI).

## Patterns to follow
- Mutation-checked discrimination: each new pin is shown to turn red when the fix is reverted, with RED-at-base evidence recorded in the chunk's `evidence/`. The `security` crate `span_mask` pins and the `l4-path-guard` 9/6/4-branch pins are the precedent (per test-plan §4 security crate; §1 `l4-path-guard-callsite-wiring-coverage`).
- Pin the prompt surface through the `PROMPT_VERSION_*` consts and in-crate `prompt.rs` pins, not by duplicating literals. Section-order and instruction-presence assertions follow the citable-evidence precedent (per test-plan §4 interpretation crate).
- A function-level pin does not cover its production call site. If the fix lands in `build_llama_cli_args` or the creation predicate, the `generate_constrained` call-site wiring needs either its own pin or an explicitly recorded coverage trigger, following the one-time-proof precedent (per test-plan §1 `l4-path-guard-callsite-wiring-coverage`, `llamacli-inference-error-emission-coverage`).
- The encoding class is already a tracked gap. `harness-encoding-relay-coverage` records that the UTF-8 relay is asserted only by presence-of-export. The Cyrillic check's readable-output fix needs a behavioural witness: a hit printed readably under a non-UTF-8 console, not a reconfigure line merely being present (per test-plan §1 `harness-encoding-relay-coverage`).
- Scenario legs are dev-host only and not CI-wired. They refuse a structurally impossible observation window up front through `observe_window_supports_verdict` (per test-plan §3 scenario-leg paragraphs). Whether the live measurement becomes an xtask leg or stays a one-off recorded run is a P4 question.

## Anti-patterns to avoid
- No retune-until-pass dressed as testing: no retry policy, and no re-sampling until green. A non-deterministic generator needs seed control (per test-plan §10 Zero-flakiness budget; §11 Quality "NEVER add retry-once policies"; §11 Test Data "NEVER use non-deterministic generators without seed control").
- Never commit live-run captures (recorded prompts or digests from real telemetry) as fixtures. Fixtures are synthetic and generated at runtime, and test output never exposes secrets or raw payloads (per test-plan §11 Test Data "NEVER use production telemetry dumps"; §11 Universal "NEVER expose secrets in test output"; §2 Self-bootstrapping fixtures).
- No manual verification step. The operator slot grants the run, but the leg's verdict must still come from exit code plus log artifacts (per test-plan §11 Universal "NEVER include manual smoke step").

## Contract bindings
- tests ↔ obs: the live leg's evidence is read from the rotated `agent-latest.jsonl*` family through the `logs` resolution rules (per test-plan §3 5-command implementation `logs`), keyed on `interpretation.incident.created` and the inference decision records. obs §3 owns that schema. Research has to answer whether a per-generation record carries the decision (surface/dismiss/watch) and a bounded justification category without raw content.
- tests ↔ security: the prompt-template ASCII pin `composed_prompt_templates_are_ascii_clean_for_argv_transport` must stay green across any prompt edit, and the scrubber pins stay untouched (per test-plan §4 security / interpretation crate; scope Boundaries).
- tests ↔ CI: the Cyrillic step lives in ci.yml's lint-test matrix (all three OS), and `pre-push:linux` must reach the same check. Whether they share one xtask verb or are duplicated is the P4 fork (per test-plan §9 Pipeline structure; §3 `pre-push:linux`).
- tests ↔ capability matrix: if a P-0xx entry with `env-gated-runtime` (real llama-cli) mode is touched, `cargo xtask verify:capability-matrix` requires its refs and anchors to resolve (per test-plan §9 Capability verification matrix).

## Acceptance criteria contributions
- The standard gate set passes in the mandated order, closed by `git diff --quiet 09d0809 -- pulse-app/ui/src/bindings/index.ts` exiting 0 for a no-procedure chunk (per test-plan §3 Per-chunk gate discipline).
- A planted Cyrillic literal in a scanned path makes `cargo xtask pre-push:linux` exit 1 with a named failing stage in its JSON verdict. The CI-side check exits non-zero and prints file:line readably under a cp1252 console. A clean tree exits 0 (per test-plan §3 `pre-push:linux` paragraph; §1 `harness-encoding-relay-coverage`).
- A committed deterministic regression witness for the surfacing fix runs in `cargo nextest run --workspace --profile ci`. It is mutation-checked to turn red when the fix is reverted and needs no live model (per test-plan §2 Agent-runnable invariants; §10 Zero-flakiness budget).
- The live re-measurement's count is fixed in the plan before it runs. RED (base) and GREEN legs run on fresh data dirs, and the verdict comes from per-generation decision evidence. If no storm digest reached the real model, the result is INCONCLUSIVE, never PASS (per test-plan §3 Direct-binary smoke variant; §3 scenario-leg precondition rule).
