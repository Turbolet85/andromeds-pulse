# design extract

## Relevance
**Partial** — no surface renders in this chunk, but the dead `#[cfg(test)]` blocks in `pulse-app/src/tray.rs` and `pulse-app/src/window.rs` are the executable pins of design-spec'd native/shell contracts (tray glyph, tray menu id set, four-corner widget position), so their MIGRATE/DELETE disposition is design-load-bearing; the other 12 files are out of my domain.

## Constraints
- The tray menu item set and its contemplative-voice labels are a design mandate — flat hierarchy, "Open andromeda-pulse"/focus, read-only summary line, "Generate Snapshot", "Toggle MCP Server" only under `--features mcp-server`, "Open Settings", divider, "Quit" (per design-system.md §Surface: desktop-native → Component Patterns → Tray Menu). The dead `tray.rs` tests assert the id constants for exactly that set (one of them names "design plan §Surface: desktop-native menu structure" in its own comment); a DELETE disposition must not leave the spec'd set with zero collected-by-name coverage. Whether an equivalent executed pin already exists under `D:\dev\projects\andromeda-pulse\pulse-app\tests\` is research's question.
- The tray icon is required to be a SINGLE monochrome glyph — stylized pulsar / constellation star with a circular outline (the aperture metaphor), no animation in the glyph itself (per design-system.md §Surface: desktop-native → Component Patterns → Tray Icon; §Iconography custom-glyph + monochrome rule). The dead glyph-raster tests (buffer size, lit-pixel floor, white-opaque-or-fully-transparent, outer-ring cardinals) are that mandate's only executable expression in the migration set.
- The compact widget's position model is required to be the FOUR-corner `WidgetPosition` set with default top-right (per design-system.md §Surface: desktop-webview → Component Patterns → Navigation / App Shell, as corrected by the 2026-08-30 amendment off the nine-value corners+edges+center grid). Migrated `window.rs` tests must preserve exhaustive four-corner coverage; a first-run failure here is a design-contract finding, not a nuisance.
- The Halo State Pulse glow layer is DEFERRED for 0.3.0 on every surface, and outputs must not CLAIM it renders (per design-system.md §Brand Identity → Signature element; §Self-Validation Protocol #3). Any migrated test name, comment, or fixture touching halo/pulse must state the deferred status, not present-tense rendering. Whether any of the 14 files' dead tests reference the halo is research's question.
- Numeric literals surviving into migrated tests must trace to the plan's scales, not be magic numbers — e.g. the snap margin `24` is the `space-lg` step of the 4px-multiple scale (per design-system.md §Spacing; §Self-Validation Protocol #4 Token Test). No new hardcoded color/size literals may enter test fixtures (per design-system.md §Anti-Patterns → Universal Bans).

## Patterns to follow
- Keep design-contract pins grouped with the surface they pin (tray glyph + menu ids ↔ desktop-native; window labels + snap math ↔ app shell), so the spec'd sets stay discoverable after relocation — consistent with §Surface: desktop-native / §Surface: desktop-webview being the single owners of those contracts.
- Structural raster assertions over pixel-exact goldens for the glyph (size, lit-pixel floor, binary alpha, ring cardinals): this preserves the "monochrome, adaptable per state" latitude the design plan grants (§Iconography; §Surface: desktop-native → Tray Icon) while still catching shape regressions.
- Bounded-value-set collapse (`sanitize_menu_id`, `sanitize_window_label`, `widget_position_label`) draws its value set FROM the design spec — the menu items (§Surface: desktop-native → Tray Menu) and the four corner labels (§Navigation / App Shell). Migrations should keep the design spec as the source of the enumerated values.
- Visibility widenings only, production behavior byte-identical (chunk scope) — this matches the design plan's position that no token, palette, typography, motion or iconography value changes ride a test-infrastructure chunk (§Anti-Patterns → Universal Bans; §Self-Validation Protocol #4).

## Anti-patterns to avoid
- NEVER weaken a design-contract assertion to make a first-run failure pass — e.g. narrowing four-corner exhaustiveness to a subset, or dropping the white-opaque/fully-transparent binary check (per §Surface: desktop-webview → Navigation / App Shell; §Surface: desktop-native → Tray Icon).
- NEVER let migrated test names, comments, or docstrings assert that the Halo State Pulse glow layer renders in 0.3.0 (per §Brand Identity → Signature element; §Self-Validation Protocol #3).
- NEVER introduce hardcoded hex / pixel literals into migrated fixtures that do not trace to the Color Palette, Spacing, or Border Radius tables (per §Self-Validation Protocol #4; §Anti-Patterns → Universal Bans).

## Contract bindings
- **design ↔ obs:** the tray menu-id constants are the VALUE set behind the obs allowlist's `menu_item` field (the dead test in `D:\dev\projects\andromeda-pulse\pulse-app\src\tray.rs` explicitly cross-references `pulse-app/src/observability.rs`). Design owns the spec'd item set; obs owns the allowlist leaf — and the chunk scope bans allowlist-leaf changes beyond what relocation itself requires.
- **design ↔ route/contract:** the four-corner `WidgetPosition` in `crates/ui-bridge/src/contract.rs` is the shipped enum the design plan was corrected against (2026-08-30 amendment); design's §Navigation / App Shell text is downstream of it, so a mismatch surfaced at first run belongs to that contract, not to a token.
- **design ↔ tests:** design-derived lint targets (motion durations, banned fonts, hard-limit bans) live in the materialized rule files per §Downstream Readiness "For tests specialist"/"For setup-project specialist"; this Rust-side migration must not disturb them.

## Acceptance criteria contributions
- (design) After migration, the spec'd tray menu id set (open · snapshot · open_settings · quit · summary, plus mcp_toggle under `--features mcp-server`) is covered by at least one test collected BY NAME in the gate — whether by a migrated test or a pre-existing one (per design-system.md §Surface: desktop-native → Component Patterns → Tray Menu).
- (design) After migration, the tray glyph remains pinned as a single monochrome, binary-alpha, aperture-motif raster by a collected-by-name test, or its deletion carries an explicit rationale naming an equivalent executed pin (per design-system.md §Surface: desktop-native → Component Patterns → Tray Icon; §Iconography).
- (design) `WidgetPosition` coverage remains exhaustive over the four corners (top-left / top-right / bottom-left / bottom-right) in the gate after migration (per design-system.md §Surface: desktop-webview → Component Patterns → Navigation / App Shell).
