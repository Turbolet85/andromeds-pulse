## Patterns to follow
- **Mechanical-pin enforcement**: a security invariant is held by a CI-checked constant, not by review — `EXPECTED_PROCEDURES` + `staged_gate::EXPECTED_GRANTS` in `xtask/src/main.rs`, asserted in both directions with unpinned-file and staged-deletion both red (per security-plan §API Security → TauRPC capability authorization).
- **Exact-leaf allowlist pin shape**: `pulse-app/tests/unit_observability_allowlist_ipc_rejection.rs` pins the `ui.ipc.rejection` boundary ×4 including the fallback discriminator and banned-field checks — the shipped precedent for how a security assertion lives as an *executed* integration test in `pulse-app/tests/` (per security-plan §Security Anti-Patterns → Logging).
- **Mutation-check discrimination**: security pins are proven to discriminate by neutralizing the guard and observing RED (the ingestion-scrub-coverage record: neutralizing four scrub sites turns 5 pins red). A never-run test being newly executed should be shown to actually discriminate, not merely to compile and pass (per security-plan §Security Anti-Patterns → Logging, MEASURED-reality paragraph).
- **Prune-not-keep for stale entries**: the `windows-core`/`windows-result`/`windows-strings` skips were pruned rather than kept once their duplicates vanished, because a stale skip hides the duplicate's return — the same discipline applies to draining `LEGACY_DEAD_BASELINE` entries per file rather than leaving them (per security-plan §Dependency Security → Duplicate-version carve-outs).
- **Basename-only path discipline is categorical** since chunk `2026-08-30-diagnostics-un-muting-harness-truth-sweep` (`observability::log_basename`) — any migrated test that asserts on a path must assert on the basename form (per security-plan §Security Anti-Patterns → Logging; §Logging &amp; Monitoring → What NEVER to log).

## Anti-patterns to avoid
- NEVER let a TauRPC procedure or a `core:window:*` / core-API capability grant change as a side effect of test relocation without its `EXPECTED_PROCEDURES` / `EXPECTED_GRANTS` pin updated in the same commit — a left-REVOKED or silently-ADDED grant is caught only by the staged-grants assertion (per security-plan §Security Anti-Patterns → API).
- NEVER have a migrated test log or re-assert raw OTLP attribute values, full product-consumed filesystem paths, clipboard/snapshot contents, MCP tool response bodies, or DuckDB query parameter values (per security-plan §Security Anti-Patterns → Logging, the five NEVER bullets).
- NEVER commit real secret material (`.env`, `*.key`, `*.pem`, `*.p12`) as a migration fixture (per security-plan §Security Anti-Patterns → Secrets).
