## Patterns to follow
- Doc-body-as-oracle: layout-templates' body holds ONLY current truth, with the how-it-got-there in the amendment sidecar (plan header note). When a first-run failure pits a never-run assert against a documented layout model, the body section is the oracle for deciding stale-test vs. real-defect.
- Measured-at-HEAD correction: per the 2026-08-21 / 2026-08-30 amendment precedent, a spec claim disproved by measurement is CORRECTED in layout-templates, not worked around. If a first-run failure shows the doc (not the test) is wrong, the disposition is a layout-templates amendment, not a silent test weakening.
- Duplicate-occurrence sweep: the 2026-08-23-a11y-verification and 2026-08-30 amendments both swept every restating site so no contradictory half survived. Same discipline applies where the same layout contract is asserted from more than one of the 14 files (e.g. snap position in both `window.rs` and `tray.rs`).
- Sketch-lag governance: ASCII wireframes are illustrative and knowingly lag current truth; the section-level status notes govern (layout-templates §Wireframe notes — Full dashboard; §Component — Halo State Pulse canvas). Never derive a test expectation from wireframe ASCII.

## Anti-patterns to avoid
- Silently relaxing or deleting a migrated assertion so it goes green when it contradicts a layout-documented model — the scope requires an explicit disposition (fix / delete with rationale / surface the defect), and layout truth is doc-owned, not test-owned.
- Letting a test-migration chunk shift any geometry, snap model, menu ordering, or window docking behavior as a side-effect of visibility widenings (layout-templates §IA notes; §Primary screens).
- Introducing a fifth notification trigger or any new user-facing surface as migration collateral (layout-templates §Component — Notifications → Trigger events).
