## Constraints
- pulse-app unit-shaped probes MUST live as separate integration-target files under `pulse-app/tests/*.rs` and reach module internals via `pub` + `#[doc(hidden)]` accessors — co-located `#[cfg(test)] mod tests` in pulse-app LIB sources compiles but never runs under `[lib] test = false`, with `main.rs` exempt as the `[[bin]]` target (per test-plan §2 Test directory + naming conventions; RESTATED verbatim at §4 Conventions → Test file location, so a wrap amendment must sweep both sites plus the §1 trigger row).
- The ratchet is a standing mandate, not a chunk artifact: zero `#[test]` in any NEW pulse-app lib-src file, legacy files capped at their enumerated `LEGACY_DEAD_BASELINE`, growth reds the build, migration shrinks the baseline (per test-plan §2 Test directory + naming conventions; §1 Pending coverage triggers → `pulse-app-dead-lib-src-tests-migration`). §1 states the owed work as "migrate the ~101 to `pulse-app/tests/*.rs`, shrinking the baseline to empty" — whether the constant at HEAD still enumerates those 14 files/counts is research's question, since the plan records a census, not the code.
- Run scope must match build scope: narrow a pulse-app run with `--filter-expr` / `-E` **under `--workspace`**, never with `-p` (measured rlib-format link failure); `cargo test --test &lt;name&gt; -p pulse-app` remains the documented single-binary path for iteration (per test-plan §3 `run` → Test selection).
- The standard gate set is unconditional regardless of scope, with `cargo xtask capability-drift` LAST (after every command that can regenerate `bindings/index.ts`, including `nextest --workspace`); the three webview gates are excluded ONLY when the chunk's file lists touch zero `pulse-app/ui/**` paths (per test-plan §3 Per-chunk gate discipline). Whether this chunk touches any `pulse-app/ui/**` path is research's question.
- The boot-smoke gate is conditional on a named trigger path list (`pulse-app/src/main.rs`, `crates/ui-bridge/src/`, `pulse-app/src/observability.rs`, `src-tauri/tauri.conf.json`, `capabilities/*.json`) — none of the 14 named source files is on that list, so the gate fires only if a visibility widening reaches one of them (per test-plan §3 Per-chunk gate discipline → Boot-smoke gate).
- Unit tier tests public module boundaries, never private crate-internal functions (per test-plan §11 Unit) — this bounds the widenings: a migrated test expressible only by exposing a private internal is a redesign-or-DELETE candidate, not a blanket `pub`.
- Migrated tests must satisfy the agent-runnable invariants on first real execution: deterministic, machine-parseable, no real `setTimeout`/wall clock without injection, self-bootstrapping fixtures (per test-plan §2 Agent-runnable invariants; §11 Universal). Note the three builder factories (`MockTraceSpan`/`MockArrowBatch`/`MockMetricPoint`) are recorded UNIMPLEMENTED (per test-plan §1 `test-data-bootstrap-factories-unimplemented`, §3 Bootstrap phases item 6), so a migrated test needing setup data must not assume them.

## Patterns to follow
- `pulse-app/tests/observability_pins.rs` — the 130-test `observability.rs` migration is the named shape precedent: `#[doc(hidden)] pub` widening, each test collected BY NAME, count arithmetic reconciled against added-by-name (per test-plan §1 `pulse-app-dead-lib-src-tests-migration`).
- Existing `pulse-app/tests/` file-naming families the plan cites by name: `unit_*` for unit-shaped probes (`unit_observability_allowlist_sweep.rs`, `unit_llamacli_inference.rs`, `unit_observability_allowlist_window_navigation.rs`), `integration_*`, `e2e_p{N}_*`; flat `#[test]` fns, no nested groups, `test_&lt;entity&gt;_&lt;scenario&gt;` naming (per test-plan §4 Conventions → Test function naming / Test grouping).
- Collection must be verified by NAME, not by total arithmetic — the plan records a measured case where a file hosting 8 `#[cfg(test)]` tests was collected ZERO by nextest until the manifest declared the target (workspace moved +4, not +12) (per test-plan §1 `inject-demo-arg-parse-unit-coverage` closing correction).
- Mutation-check discipline for pins whose discrimination is in doubt — neutralize the production site and confirm RED, the precedent set by `redaction_counter_folds_once_per_batch_across_all_four_builders` (per test-plan §4 buffer crate; amendment 2026-08-23-ingestion-scrub-coverage). Directly applicable here: a test that has never executed may pass for free.
- Hang-safe form where a migrated test can wedge: run on a worker thread under an explicit `recv_timeout` so a hang FAILS rather than blocks the gate (per test-plan §4 buffer crate pins).

## Anti-patterns to avoid
- NEVER weaken or park a first-run failure: no `#[ignore]` without an open tracking issue, no retry-once policy, no treating a flake as noise (per test-plan §11 Quality + §11 CI) — matches the scope's own rule that each first-run failure gets an explicit disposition.
- NEVER assert against private crate-internal functions or fixture-internal ids; assert the public contract (per test-plan §11 Unit).
- NEVER `unwrap()` in a test without a panic message (use `expect("reason")`), and NEVER use real time without injection (per test-plan §11 Unit / §11 Universal) — likely to surface in never-run tests written before these bans were operative.

## Contract bindings
- tests ↔ obs: the ratchet and `LEGACY_DEAD_BASELINE` live inside `pulse-app/tests/unit_observability_allowlist_sweep.rs`, an obs-allowlist file, and five of the 14 in-scope sources are obs emitters (`heartbeat.rs`, `restart_observer.rs`, `storm_observer.rs`, `baseline_observer.rs`, `diagnostics_router.rs`), so migrated assertions may bind to obs-plan allowlist leaves / record-field shapes (test-plan §3 log-format binding). Whether those tests assert obs leaves or pure logic is research's question.
- tests ↔ arch/security: `#[doc(hidden)] pub` widenings expand the crate surface, and the gate set's `cargo xtask capability-drift` + `cargo xtask check:staged-artifacts` (staged `bindings/index.ts` + `capabilities/*.json` pins, set-equality both directions, no neutral arm) must stay clean; scope forbids any TauRPC/capability change, so these are regression gates rather than deliverables (per test-plan §3 Per-chunk gate discipline).
- tests ↔ a11y/webview: none expected — the a11y and vitest gates attach only through the `pulse-app/ui/**` trigger (per test-plan §3 Per-chunk gate discipline).

## Acceptance criteria contributions
- `cargo nextest run --workspace --profile ci` passes, and every migrated test is confirmed COLLECTED BY NAME in the run output — the workspace total moving by the expected delta is not sufficient evidence on its own (per test-plan §3 `run` → Test selection + §1 `inject-demo-arg-parse-unit-coverage` collection correction).
- `LEGACY_DEAD_BASELINE` is empty and `pulse_app_src_carries_no_new_dead_test_attributes` is green, with `main.rs` still exempt (per test-plan §2 Test directory + naming conventions; §1 `pulse-app-dead-lib-src-tests-migration`).
- The full standard gate set runs green with `cargo xtask capability-drift` LAST, the webview trio included only if a `pulse-app/ui/**` path is touched (per test-plan §3 Per-chunk gate discipline).
- No migrated test lands `#[ignore]`d, retried, or weakened to green; each first-run failure carries a recorded disposition (fix-as-stale / delete-with-rationale / surface-the-defect) (per test-plan §11 Quality + §11 CI).
