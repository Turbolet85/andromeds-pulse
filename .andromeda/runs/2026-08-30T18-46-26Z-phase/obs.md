## Patterns to follow
- `pulse-app/tests/observability_pins.rs` as the migration landing site for obs assertions collected BY NAME — the exact precedent obs-plan §8 records for the `interpretation.incident.created` field-completeness guard moved out of a deleted src-level `mod tests` (per obs-plan §8; scope names the same file as its 130-test shape precedent).
- One guard file per leaf family, named `pulse-app/tests/unit_observability_allowlist_{topic}.rs`, each carrying exact-resolve + set-equality-both-ways + a no-bare-prefix / fallback discriminator (per obs-plan §8 — the consumer_stall, cue_tick, window_navigation, close_signpost, ipc_rejection, l4_path_guard, delegated_timing entries all follow this shape).
- Mutation-check a migrated guard rather than trusting it green: neutralize the leaf → expect RED, restore → GREEN, and record which pins stayed green and why (per obs-plan §8, delegated-timing and cue_tick entries).
- Assert through the public allowlist surface (`AllowList::production()` / `for_target`) rather than crate internals, so a migrated obs guard needs no visibility widening beyond the scope's `#[doc(hidden)] pub` precedent (per obs-plan §8 Integration points → "At subscriber Layer").
- Bounded-label helpers are cited by leaf entries as the bounding mechanism (`window.rs::sanitize_window_label` backs three §8 leaves — `tray.signpost.shown`, `app.boot.window.navigation`, `ui.ipc.rejection`); `window.rs` is one of the 14 files, so its dead tests may be the only assertion of that bounded domain (per obs-plan §8).

## Anti-patterns to avoid
- Never leave, re-create, or migrate an obs guard into a location where it does not execute — a src-level `mod tests` under `[lib] test = false` reads green while asserting nothing (per obs-plan §8, the `[lib] test = false` rule; the class origin is the 2026-08-16 `interpretation.incident.created` dead-guard finding).
- Never weaken a migrated assertion to make it pass on first real execution — masking a failure is the same defect class the plan bans for panic handling (per obs-plan §11 SLO, "NEVER add retry-once policies … masks real failures"); a first-run RED is a finding needing an explicit disposition.
- Never DELETE a test that is a §8 leaf's only field-completeness assertion — a leaf naming fewer fields than its emit site emits leaves the target PARTLY redacted, the shape every gate passes and no resolver probe can see (per obs-plan §8, `triage.incident.persist` / `triage.cue.tick` completion entries).

- **obs ↔ tests, shared file:** `pulse-app/tests/unit_observability_allowlist_sweep.rs` is dual-purpose — the tests-domain ratchet (`LEGACY_DEAD_BASELINE`, growth guard) and the obs-domain standing leaf-equality gate live in one file (per obs-plan §8 backlog-CLOSED entry; scope §Work surfaces).
