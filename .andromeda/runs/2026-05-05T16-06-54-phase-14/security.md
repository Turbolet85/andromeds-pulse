## Constraints

- HTTP receiver MUST bind exclusively to `127.0.0.1:<configured>` — loopback is the de-facto authorization boundary; any non-loopback bind invalidates the entire Minimal-tier risk model (per security plan §Security Anti-Patterns § API "NEVER bind the OTLP receivers to `0.0.0.0` or any non-`127.0.0.1` interface" + §Threat Model Summary auth model).
- `axum::DefaultBodyLimit::max(8 * 1024 * 1024)` (or equivalent `tower_http::limit::RequestBodyLimitLayer`) MUST be attached at router build for every `/v1/*` route — the JFrog axum-core advisory documents that bypassing this is the root cause of unbounded request DoS (per security plan §Input Validation row 2 + §Anti-Patterns § Input "NEVER trust `Content-Length` or trailers as a substitute"; §API Security Request size limit row).
- Host-header allowlist middleware MUST reject requests where `Host` header is not in `{127.0.0.1:<configured>, localhost:<configured>, [::1]:<configured>}`; configured port resolves from `ANDROMEDA_PULSE_OTLP_HTTP_PORT` so the allowlist tracks runtime config — DNS-rebinding mitigation against the Coder Agent CVE-2025-09-19 + MCP TypeScript SDK CVE-2025-66414 cluster (per security plan §API Security Host header row + §Anti-Patterns § API "localhost is not a security boundary").
- CORS middleware MUST be default-deny — `tower_http::cors::CorsLayer::new()` with no `allow_origin` calls; NEVER `CorsLayer::permissive()` / `allow_origin(Any)` (per security plan §API Security CORS row + §Anti-Patterns § API).
- Post-`prost`-decode invariant checks MUST run on every HTTP/protobuf payload before hand-off to `buffer::Appender` — `span_id` is 8 bytes, `trace_id` is 16 bytes, attribute keys/values bounded; `prost` only validates wire format (per security plan §Input Validation row 1 + §Anti-Patterns § Input). HTTP/JSON path is symmetric: `serde_json::from_slice::<T>(buf)` MUST run only after `DefaultBodyLimit` has size-bounded `buf` (per §Anti-Patterns § Code Patterns).
- Path env var `ANDROMEDA_PULSE_OTLP_HTTP_PORT` MUST be parsed via `TryFrom<u16>` returning `Error::InvalidPort { value }` on failure with warn-on-invalid fallback to default 4318 (per security plan §Input Validation CLI/env row + Conventions Configuration units, mirroring chunk #16's `resolve_grpc_port()` precedent).
- HTTP-receiver errors MUST surface as `Status` proto in body (HTTP/protobuf) or HTTP/JSON `Status` (HTTP/JSON) per OTLP spec; internal error chains MUST NOT leak across the boundary — no stack traces / file paths / library versions / Rust struct names (per security plan §Error Handling OTLP receiver row + §Anti-Patterns § Logging).

## Patterns to follow

- **Loopback bind + try_bind/serve split** — chunk #16 (gRPC) established `try_bind(addr) -> TcpListener` + `serve_on(listener)` split so `BindStatus::Ok` is recordable immediately after the listener accepts (before the long-running serve future); HTTP receiver should adopt the same shape using `tokio::net::TcpListener::bind` + `axum::serve(listener, app)` so `subsystems.otlp_http_receiver.{status,error_msg}` populates symmetrically in `current_health()` (per chunk #16 precedent at `crates/ingest/src/grpc.rs` + security plan §Input Validation OTLP HTTP row).
- **`HeartbeatState` slot + `BindStatus` reuse** — extend `ui_bridge::health::HeartbeatState` with `otlp_http_bind: Mutex<Option<BindStatus>>` slot + setter/reader, mirroring the `otlp_grpc_bind` slot added in chunk #16; `current_health()` populates the new subsystem entry from this slot and degrades the envelope `status` on `BindStatus::Failed` (per session-handoff "HeartbeatState extended" pattern + security plan §API Security Tauri capability authorization indirect signal).
- **`#[tracing::instrument]` boundary span allowlist** — gRPC server module instruments `TraceServiceImpl` / `MetricsServiceImpl` / `LogsServiceImpl` with `skip(req)` + bounded `fields(rpc.system, rpc.service, rpc.method, span_count, traceparent)`; HTTP handlers should instrument with the analogous skip+fields shape (e.g., `http.method, http.route, content_type, span_count, traceparent`) — keep field allowlist explicit so PII-scrubbing in `pulse-app/src/observability.rs` continues to apply (per security plan §Logging & Monitoring "What NEVER to log" + chunk #16 precedent).
- **Vendored `.proto` + `tonic-prost-build`** — chunk #16 established that `crates/ingest/proto/opentelemetry/proto/collector/trace/v1/trace_service.proto` + `metrics_service.proto` + `logs_service.proto` already exist (vendored Apache 2.0 from opentelemetry-proto v1.7.0). HTTP/protobuf handlers MUST reuse the SAME generated `prost` types from `ingest::grpc::proto::*` — do NOT introduce a parallel proto compilation path or re-vendor (per security plan §Dependency Security Pinning + §Universal "tonic 0.14 vs opentelemetry-otlp 0.31 duplicate" anchor; chunk #16 `cargo tree -p ingest | grep opentelemetry` is empty by design).
- **W3C traceparent extraction at the HTTP boundary** — gRPC server module exposes `extract_traceparent(metadata)` reading `grpc-trace-bin`; HTTP handler equivalent reads `traceparent` HTTP header (RFC W3C Trace Context) and propagates as a `traceparent` field on the boundary span (per route Decisions Log "per-receiver tracing instrumentation + W3C traceparent extraction at boundaries" + chunk #16 grpc.rs precedent).

## Anti-patterns to avoid

- NEVER use `tower_http::cors::CorsLayer::permissive()` or `allow_origin(Any)` on `:4318` — default-deny is the correct posture (per security plan §Anti-Patterns § API; security plan rule).
- NEVER bind `:4318` to `0.0.0.0`, `Ipv4Addr::UNSPECIFIED`, or `[::]` — the security gate `no_non_loopback_bind_literals_in_ingest_src` (introduced in chunk #16's tests/grpc_loopback.rs) walks `crates/ingest/src/` recursively asserting zero such literals; chunk #17 must extend or share the same gate (per security plan §Anti-Patterns § API + chunk #16 test precedent).
- NEVER skip Host-header allowlist on `:4318` even though it appears redundant with loopback bind — DNS rebinding from a browser tab is the documented attack and the explicit lesson is "localhost is not a security boundary" (per security plan §Anti-Patterns § API + §API Security Host header row).
