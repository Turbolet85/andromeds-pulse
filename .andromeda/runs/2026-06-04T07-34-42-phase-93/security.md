## Constraints

- The config-file boundary MUST validate every reloaded field: field shape via `serde` derive; port range via `TryFrom<u16>` (non-privileged unless explicitly allowed); retention seconds bounded; log level enum; thresholds positive; multipliers in allowed ranges — malformed config rejected with the previous valid config retained (per security plan §Input Validation row "Configuration values — `config.toml`"; route §94 "malformed config rejected with previous valid config retained").
- The config file path (and the watched dir) MUST be derived through the same canonicalize-and-confine discipline as existing path env vars: if the watch target is resolved from `ANDROMEDA_PULSE_CONFIG_PATH` / `ANDROMEDA_PULSE_DATA_DIR`, it MUST `canonicalize()` + assert the resolved path lives under the resolved per-platform data dir (or the `ANDROMEDA_PULSE_DATA_DIR` override base) via `strict-path` BEFORE the `notify` watcher attaches (per security plan §Input Validation row "CLI / env var inputs" + §Anti-Patterns §Input path-traversal ban; CWE-22).
- The `notify` filesystem-watcher dependency MUST be a pinned version recorded in workspace `Cargo.toml` (no `"*"` / `"latest"`), pass `cargo audit` + `cargo deny check bans licenses sources`, with any new transitive duplicates added to `deny.toml [bans] skip` with provenance comments rather than relaxing `multiple-versions = "deny"` (per security plan §Dependency Security + CLAUDE.md §Session-Learnings 2026-05-03 deny-skip discipline).
- The two new TauRPC procedures (`config.reload`, `config.status`) MUST each return `Result<T, AppError>` and have a matching entry path through `pulse-app/capabilities/` JSON (Tauri negative-default) — router registration alone is a silent runtime rejection (per security plan §API Security row "TauRPC capability authorization" + §Anti-Patterns §API).
- `config.status` (last-reload timestamp + errors) and the `pulse://stream/config-events` payload MUST NOT echo raw config-file contents, OTLP attribute values, full file paths, or any secret-shaped material; parse-error detail surfaced to the webview MUST be a sanitized one-liner (no file paths / Rust struct names / library versions) per the `AppError::Validation { field, reason }` / `AppError::Internal { message }` sanitization rule (per security plan §Error Handling + §Logging & Monitoring NEVER-log list).
- The config-watcher MUST NOT use any reloaded config string as an argument to `tokio::process::Command` (e.g., model-path / Drain-param keys are restart-required NOTICE-only — they must not be hot-spawned) per the command-injection ban (per security plan §Anti-Patterns §Code Patterns).

## Patterns к follow

- Settings-extension precedence path: the existing `Settings` struct (`crates/ui-bridge/src/contract.rs`) flowing through `get_settings`/`update_settings` is the established config surface; reloaded keys should respect arch config precedence (env vars `ANDROMEDA_PULSE_*` > `config.toml` > defaults) so a hot-reloaded `config.toml` value never silently overrides an env-var override (per security plan §Input Validation config row + arch §Cross-cutting Patterns Config management).
- Scaled-integer storage for any float-shaped tunable that must round-trip through the Settings/TauRPC bindings (e.g., a multiplier persisted as `_x100: u32`) — the `Settings` `PartialEq + Eq` derive bans raw `f32` (per CLAUDE.md §Session-Learnings 2026-05-19 `drain_similarity_x100` precedent).
- Cross-crate error mapping at the resolver boundary: convert config-watcher / parse errors (lower crate) → `AppError` via a free `fn …_error_to_app_error(...)` in the pulse-app router file (orphan-rule-safe `.map_err(...)`), not an `impl From` in ui-bridge or the watcher crate (per CLAUDE.md §Session-Learnings 2026-05-18 free-fn map_err precedent; preserves arch DAG).
- Bounded-cardinality `_label: String` for any cross-crate enum referenced in the `config-events` broadcast payload, rather than forcing serde derives onto a source-crate enum (per CLAUDE.md §Session-Learnings 2026-05-24 cross-crate-serde-label precedent).
- Debounce (route §94 specifies 500ms) is a security-positive control here too: it bounds re-parse work per filesystem event so a rapidly-rewritten `config.toml` cannot saturate the validation path.

## Anti-patterns к avoid

- NEVER read the `ANDROMEDA_PULSE_*_PATH` / `*_DIR` env var that resolves the watched config location without `canonicalize()` + assert-under-data-dir — TOCTOU / symlink-chain traversal class (per security plan §Anti-Patterns §Input).
- NEVER apply a reloaded value before validation (positive thresholds, multipliers in range, port `TryFrom<u16>`); reject-and-retain-previous is mandatory — a malformed `config.toml` must never partially-apply or zero out live thresholds (per security plan §Input Validation config row).
- NEVER log raw `config.toml` contents, the reloaded values, or full file paths in the watcher's tracing events / `config-events` payload — config may carry incidentally-secret-shaped strings; emit field names + sanitized reasons only (per security plan §Logging & Monitoring NEVER-log list).
