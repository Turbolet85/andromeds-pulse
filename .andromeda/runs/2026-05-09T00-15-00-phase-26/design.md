- Frame-loop instrumentation feeding `frame_duration_ms` MUST respect `prefers-reduced-motion: reduce`: Halo State Pulse degrades to a static glow (rhythm suppressed; LCH hue still updates per error rate); all chrome transitions become instant (per design-system.md §Motion Accessibility + §Anti-Patterns hard-limit row "NO canvas/WebGL except dedicated Halo State Pulse layer, EXEMPT per WebGPU mandate").
- Compute-shader pipeline ownership stays inside the WebGPU canvas layer; results MUST NOT escape into React's render tree as per-frame state (per design-system.md §Surface: desktop-webview Performance notes — "Charts (Halo State Pulse, Latency River) are rendered directly to canvas, NOT inside React's render tree — Arrow data is pushed into canvas via WebGPU compute shader, side-stepping VDOM diffing cost").

- WebGPU adapter unavailability fallback message MUST remain "WebGPU not supported in this browser" verbatim (per design-system.md §Surface: desktop-webview Component Patterns Canvas Container; chunk #28 cross-domain rot resolution canonicalized this wording over layouts-extract alternatives).

## Patterns к follow

- Halo State Pulse data-driven motion as the canonical exemption pattern: data-driven canvas motion at 0.8–2.4 Hz lives outside chrome expression budget (0.35 webview / 0.2 native), so compute-shader-driven aggregation feeding pulse rhythm + LCH hue follows the same exemption envelope (per design-system.md §Motion High-impact moments row 1 "Halo State Pulse breathing").
- CSSOM → uniform color binding pattern from chunk #28 substrate: at canvas-init, read `--color-primary` / `--color-accent` / `--color-base` / `--color-inset` via `getComputedStyle(document.documentElement).getPropertyValue(...)`, parse, and pass to compute / fragment uniform buffers — never hardcode hex in WGSL (per design-system.md §Surface: desktop-webview Tokens `@theme` block + chunk #28 session-learnings).
- Canvas Container chrome (`#0F1117` Inset background, full container width/height) as the parent for any compute-driven visualization region; aggregated time-series renders inside the same `<section role="region">` semantic wrapper from chunk #28 (per design-system.md §Component Patterns Canvas Container).
- Reduced-motion branch at the frame-loop / pulse-emission boundary: the gate fires once per `prefers-reduced-motion: reduce` query change and switches the Halo from data-driven rhythm to static-glow + hue-only updates; compute aggregation itself continues unchanged (only the visual rhythm is suppressed) (per design-system.md §Motion Accessibility).
- Performance-budget pattern: rendering directly to canvas from compute-shader output side-steps VDOM diffing for high-frequency telemetry — the same React 19 Compiler v1.0 + canvas-side-step strategy from chunk #28 substrate (per design-system.md §Surface: desktop-webview Performance notes).

## Anti-patterns к avoid

- NEVER inline RGB / hex literals in WGSL fragment or compute shader sources for design-token-derived colors. Structural literals like `vec4<f32>(0.0, 0.0, 0.0, 0.0)` (clear color, position output) are permitted; tinted values (the 6 NASA palette hexes or any derivation) MUST flow as uniforms (per design-system.md §Color Palette source-of-truth + chunk #28 session-learnings WGSL color-uniform discipline).
- NEVER add canvas/WebGL motion outside the dedicated Halo State Pulse layer, even for "debug" or "loading" visualizations of the compute-aggregation pipeline. Skeleton states use the existing pulse pattern (`#262A33` Raised-1 background, opacity 0.5–1.0, 1.2s ease-in-out) — not WebGPU (per design-system.md §Anti-Patterns Universal Bans + §Motion Hard limits row "NO canvas/WebGL except Halo").
- NEVER let frame-budget pressure justify bounce / spring / staggered / scroll-driven motion in chrome compensation. Chrome easing remains ease-out / ease-in-out at 150–200ms regardless of compute-pipeline frame timing (per design-system.md §Motion Easing + Hard limits).

## Contract bindings

- **design ↔ a11y**: `prefers-reduced-motion: reduce` reduced-motion gate at the frame-loop / pulse-emission boundary is the design-side enforcement of WCAG SC 2.3.3 (a11y SC). Halo State Pulse rhythm suppression + LCH hue-only updates is the design-supplied degradation; a11y owns the assertion that the gate fires correctly via media-query test fixtures.
- **design ↔ obs**: `metric.webgpu.frame_duration_ms` AllowList entry (pre-staged in chunk #28 at `pulse-app/src/observability.rs:668+`) carries bounded fields `[duration_ms, wgpu_backend, webview_backend, timing_method]`. - **design ↔ tests**: Motion lint targets — durations 150ms / 200ms / 250ms / 350ms; easing names ease-out / ease-in-out; 7 hard-limit bans (parallax / scroll / spring / staggered / 3D / canvas-except-Halo / opacity > 200ms). Compute-aggregation chunk introduces no new motion tokens, but tests assert no regressions in the existing token set (per design-system.md §Downstream Readiness tests specialist directive).
