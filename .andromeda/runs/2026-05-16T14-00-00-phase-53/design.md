- Loading state (stream subscribed, no data yet) MUST use the Skeleton pattern: `#262A33` (Raised-1) background with `animation: pulse 1.2s ease-in-out infinite;` opacity 0.5–1.0 — discrete 50ms-on/off discipline NOT smooth fade (per design-system.md §Surface: desktop-webview Component Patterns Loading / Empty States).
- Empty state (subscription active, zero metrics in window) uses Tertiary text `#7D8697` with optional `telescope` glyph 24px in the same Tertiary color, centered, copy in contemplative tone (e.g., "Awaiting telemetry") — never a generic spinner or "Loading..." string (per design-system.md §Surface: desktop-webview Loading / Empty States + §Anti-Patterns Rejected Defaults uniform monochrome status icons rejection).
- Error state for stream subscription failure: border `1px rgba(199, 85, 106, 0.5)` (Alert Burgundy 50%), error message text uses `--color-text-primary` (#E8EEF7) paired with `--color-accent` (#C7556A) border + icon — NEVER state-by-color-alone (per design-system.md §Design Decisions Log 2026-05-03 lift entry + Component Patterns Error state).
- All motion introduced by the real-data path (pulse cadence, value transitions in FooterBand) MUST respect `prefers-reduced-motion: reduce`: Halo degrades to static glow (hue still updates per error rate, rhythm freezes); any FooterBand value-change transition collapses to instant (per design-system.md §Motion Accessibility).

## Patterns to follow

- Halo State Pulse runs on the dedicated WebGPU canvas layer outside React's render tree; real-data binding pushes `errorRate` / `throughputHz` values into the canvas data feed, NOT into React state that triggers VDOM diffing (per design-system.md §Brand Identity Signature element + §Surface: desktop-webview Performance notes).
- FooterBand read-only data uses tabular-nums (Data role JetBrains Mono `font-feature-settings: 'tnum'`) so digit width stays constant across stream updates; prevents column-shimmer when real values replace synthetic (per design-system.md §Typography Data row "tabular numerals align columns for readability").
- Token-only consumption: every color / spacing / radius value referenced by CompactWidget.tsx + FooterBand.tsx after the swap should be a CSS custom property from the `@theme` block (`var(--color-base)`, `var(--color-text-secondary)`, `var(--spacing-md)`, `var(--radius-md)` etc.) — no inline hex / px literals introduced by the wiring change (per design-system.md §Surface: desktop-webview Tokens `@theme` block).
- Skeleton pulsing pattern already established for compact widget — keep as the visual handshake while the broadcast channel has not yet yielded a frame (per design-system.md §Surface: desktop-webview Loading / Empty States Skeleton).
- Footer band in compact widget is read-only and surfaces "Ingest: {spans/sec} | Retention: {min} used | Error rate: {%}" exactly as designed; do not add interactions during this wire change (per design-system.md §Surface: desktop-webview Navigation Pattern Compact widget item 3).

## Anti-patterns to avoid

- NEVER replace Halo State Pulse rhythm with a generic loading spinner or static dot while waiting for first real frame — defeats the signature element. Use Skeleton (Raised-1 pulse) or static halo glow per reduced-motion fallback (per design-system.md §Anti-Patterns Rejected Defaults uniform monochrome status icons + §Self-Validation Protocol Signature Test).
- NEVER introduce decorative gradients, glassmorphism, or shadow ornamentation while doing the wire swap. Borders-only depth strategy holds — even if real data tempts "show the data is live" via glow effects, the Halo is the only exception surface (per design-system.md §Anti-Patterns Universal Bans + §Depth Strategy).
- NEVER convey stream state (subscribed / disconnected / errored) by color alone in FooterBand. Pair Alert Burgundy border with a textual label or icon (per design-system.md §Anti-Patterns Universal Bans color-purely-for-decoration + §Design Decisions Log 2026-05-03 state-by-color-alone discipline).
