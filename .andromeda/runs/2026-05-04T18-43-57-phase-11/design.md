## Constraints

- Per-surface fixtures MUST cover BOTH desktop-webview (compact widget + full dashboard) AND desktop-native (tray icon + tray menu + OS notifications) — these are the two committed surfaces (per design-system.md §Surface: desktop-webview and §Surface: desktop-native; locked in §Design Decisions Log 2026-05-02 row "Surfaces").
- Fixture per-surface descriptors MUST treat tray menu + OS notifications as OS-controlled (system-ui font, native menu chrome, no custom keyboard nav at tray level) — fixture text must not assert custom chrome announcements where the OS owns the surface (per §Surface: desktop-native Component Patterns "Tray Menu" + Navigation Pattern "No keyboard navigation at the tray level — tray menu is OS-controlled").
- Custom Icon glyphs (aperture / telescope / constellation-grid / star / circular-pulse) MUST have semantic announcement labels in fixtures (NOT raw "img" or filename) — these are registered as `<Icon glyph="telescope" />` React components with domain meaning (per §Iconography "Primary custom set" + Decisions Log Anti-Patterns "Generic icons from a stock library used across chrome without modification — rejected").
- Halo State Pulse fixtures MUST describe the data-driven canvas as decorative-with-data-meaning (NOT chrome animation) — SR announcement strategy is to surface the underlying telemetry state (throughput, error rate) via aria-live status region, not to describe the visual animation itself (per §Motion "Canvas motion … is a separate dimension governed by the data-viz layer and NOT bound by the chrome expression number" + §Brand Identity "Signature element").
- Investigation Capture Collapse fixture MUST cover the supporting-moment 350ms scale+opacity motion as an SR-announced state change ("Snapshot generation started" / "Snapshot ready") via aria-live, NOT as visual motion narration (per §Motion "Supporting moments" + §Design Decisions Log "Investigation Capture Collapse supporting moment in Motion is the visual handshake for this action").
- Reduced-motion fixture variant MUST be included for any surface that has motion — Halo Pulse degrades to static glow (hue still updates per error rate), other transitions become instant (per §Motion "Accessibility: All motion respects `prefers-reduced-motion` media query").

## Patterns to follow

- Surface naming convention from design-system: use exactly "desktop-webview" and "desktop-native" as fixture surface IDs — these are the locked surface names across the design system (per §Surface: desktop-webview and §Surface: desktop-native section headers).
- Per-surface motion expression-level annotation: fixtures may carry the expression-level number (0.35 webview / 0.2 native / 0.3 base) as metadata so downstream a11y manual passes know motion budget per surface (per §Brand Identity "Expression level" Per-surface table).
- Custom titlebar accessibility scope: desktop-webview fixtures must cover the custom-drawn 32px titlebar (frameless, contains app icon + title + settings button + window controls) — this is non-OS chrome that requires keyboard reachability + SR labeling (per §Surface: desktop-webview Component Patterns "Navigation / App Shell" + Platform-Specific Notes Windows/macOS/Linux window controls subsection).
- Settings panel modality: when fixtures touch the Settings panel, treat as a modal/side-drawer surface (Phase 8 will determine which) using the `radius-lg` (8px) + `Raised-3` (#343A45) modal-elevation pattern — per §Surface: desktop-webview Component Patterns + §Border Radius radius-lg note "Modals, large containers".

## Anti-patterns to avoid

- Do NOT include fixtures asserting custom chrome behavior on the tray menu or OS notifications — these are platform-controlled surfaces and any fixture that prescribes custom font, custom radius, or custom motion at this layer violates the "NEVER use web-style design language … in native menus" + "NEVER fight the system font" Per-Surface Bans (per §Anti-Patterns Per-Surface Bans desktop-native bullets 1 + 3).
- Do NOT fixture generic icon labels ("alert icon", "settings icon") for the custom Icon registry glyphs — must use the domain-specific glyph names from §Iconography (`aperture`, `telescope`, `constellation-grid`, `star`, `circular-pulse`); generic-stock-library labels are an anti-pattern per §Anti-Patterns Rejected Defaults item 5.
- Do NOT fixture the Halo State Pulse as if it were chrome motion subject to the 200ms hard limit — Halo is data-viz layer (WebGPU canvas, EXEMPT per §Motion "Hard limits … NO canvas/WebGL (except the dedicated Halo State Pulse layer, which is EXEMPT per WebGPU mandate)"); a fixture that asserts chrome budget on Halo is wrong by construction.
