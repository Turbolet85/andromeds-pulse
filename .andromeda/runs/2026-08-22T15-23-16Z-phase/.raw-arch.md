# arch extract

## Relevance
Partial — arch governs crate placement, the end-to-end measurement route, and resource registration; the catalog/false-positive decision itself belongs to security.

## Constraints
- The scrubber stays in the arch-locked `security` crate; `buffer`, `interpretation`, `triage` and `pulse-app` reach it as declared dependencies flowing toward the binary, and no consumer may fork or re-implement the pattern catalog locally (per architecture.md §Occupied Resources → Cargo workspace crate names; §Cross-cutting Patterns → Module dependency direction).
- Cross-crate reach is through the crate's public contract module only — `pub` contract surface, `pub(crate)` internals, no cross-crate `pub use` outside that module (per architecture.md §Conventions → Module visibility discipline; §Project Intent → Template patterns). Whether the existing scrub entry points already sit on that surface is research's question.
- The end-to-end leg must speak OTLP to a running receiver on `:4317`/`:4318` — arch bans an in-process test-mode bypass, a separate "test ingest" feature flag, and any mock-channel back door — with non-default ports resolved via `ANDROMEDA_PULSE_OTLP_GRPC_PORT` / `_HTTP_PORT`, and buffer state read back through the `traces.*` / `metrics.*` / `logs.*` query routers (per architecture.md §Cross-cutting Patterns → Test-time telemetry injection; §Occupied Resources → Environment variables).
- "Stored fields" spans two arch-reserved substrates: the DuckDB in-memory ring-buffer tables (`spans`, `span_events`, `span_links`, `metrics_points`, `log_records`, `resources`, `instrumentation_scopes`, `log_templates`) and the corpus SQLite tables (`incidents`, `incident_events`, `digest_archive`, …). Corpus cells carry AES-256-GCM at rest; ring-buffer rows carry no encryption — arch's at-rest posture is therefore not a substitute for redaction on the DuckDB path (per architecture.md §Occupied Resources → DuckDB database / schema names + Corpus SQLite database / schema names).
- Any resource the CARRY #10 observability decision would land must be registered: a new env var, event topic, or TauRPC procedure goes into §Occupied Resources, and a procedure additionally requires router registration plus its `EXPECTED_PROCEDURES` pin in `xtask/src/main.rs` — a capability-JSON edit is explicitly NOT the gate for a TauRPC procedure (per architecture.md §Occupied Resources; §Cross-cutting Patterns → Webview IPC capability policy).
- If a redaction counter emits as the product's own telemetry, it goes to the stdout/file exporter under `&lt;data_dir&gt;/logs/` and must never dial the app's own `:4317`/`:4318` (per architecture.md §Established Decisions → [Self-Observation]; §Cross-cutting Patterns → Self-observation discipline).
- New Cargo features are kebab-case and default-off, and default features are minimal — so a recall fix parked behind a new off-by-default flag would leave the gap in every default build; and §Established Decisions → [Validation Library] keeps validation at `serde` + smart enum types + `TryFrom`, so no validation crate is pulled in for a shape check (per architecture.md §Conventions → Feature flags; §Cross-cutting Patterns → Feature-gate hygiene; §Established Decisions → [Validation Library]).

## Patterns to follow
- Library-crate template shape: one public contract module as the only `pub` surface, `pub(crate)` internals, `thiserror`-derived error enum (architecture.md §Project Intent → Template patterns; §Established Decisions → [Error Handling Pattern]).
- Second-boundary defense-in-depth precedent: the training-export egress sink calls `security::scrubber::scrub_attribute` on top of the producer-side scrub — the established shape for adding a scrub at an additional boundary rather than widening one call site (architecture.md §Occupied Resources → Filesystem locations → Out-of-data-dir egress sink).
- Synthetic-telemetry injection over the real OTLP surface with readback through the query routers is the sanctioned harness route for any "does it reach stored fields" claim (architecture.md §Cross-cutting Patterns → Test-time telemetry injection).
- Bounded env-var parse discipline if any tunable appears: whitespace-trimmed, range-checked, every rejection falling back to the documented default without a panic, resolved once at boot, under config precedence env &gt; `config.toml` &gt; built-in defaults (architecture.md §Cross-cutting Patterns → Config management; §Occupied Resources → Environment variables).
- Register-on-landing: new occupied resources are recorded in §Occupied Resources via a wrap amendment in the sidecar rather than left implicit (architecture.md §Occupied Resources).

## Anti-patterns to avoid
- Manufacturing the end-to-end measurement through an in-process bypass, a test-only ingest feature flag, or a mock channel instead of the real OTLP surface (architecture.md §Cross-cutting Patterns → Test-time telemetry injection).
- Standing up a new crate for the recall fix, or re-purposing any reserved workspace crate name (architecture.md §Project Intent → How new functionality is added; §Occupied Resources → Cargo workspace crate names).
- Emitting the product's own telemetry into its own OTLP receiver ports (architecture.md §Established Decisions → [Self-Observation]).

## Contract bindings
- **arch ↔ security** — arch locks WHERE the catalog lives (`crates/security`, public contract module); security owns the recall-vs-false-positive decision the scope names as plan-owned.
- **arch ↔ tests** — the §Cross-cutting Patterns injection route is the harness contract for the e2e leg (OTLP ports + query-router readback); the scope names `pulse-app/tests/e2e_pii_scrubber_persistence_coverage.rs` as the existing home, and whether that file already drives real OTLP or an in-process shortcut is research's question.
- **arch ↔ obs (CARRY #10)** — a redaction-count field binds to §Established Decisions [Self-Observation] and, per the 2026-08-21 amendment, to the per-target obs-allowlist-leaf rule: a leaf-less `metric.*` target keeps only `value`/`unit`/`module` and has every label silently redacted, so a new counter needs its OWN exact allowlist leaf or the count arrives label-stripped.
- **arch ↔ external Conductor harness** — the only Pulse-side contract Conductor speaks is the spec-conformant OTLP receiver (§Standard Contracts → OTLP receiver, no project envelope), so an eighth PII category would need no Pulse contract change; per scope this is recorded, not acted on.

## Acceptance criteria contributions
- (arch) The catalog change lands in `crates/security` and every consumer reaches it through that crate's public contract module — no sibling crate carries its own copy of the pattern (per architecture.md §Occupied Resources → Cargo workspace crate names + §Conventions → Module visibility discipline).
- (arch) The end-to-end leg injects the bare-key value by speaking OTLP to a running receiver on `:4317`/`:4318` (ports via `ANDROMEDA_PULSE_OTLP_GRPC_PORT` / `_HTTP_PORT`) and reads the stored field back through a real query surface — no in-process bypass, no test-ingest feature flag, no mock channel (per architecture.md §Cross-cutting Patterns → Test-time telemetry injection).
- (arch) No unregistered resource ships: any new env var, event topic, DuckDB/corpus table, or TauRPC procedure appears in §Occupied Resources, and a procedure also appears in the `EXPECTED_PROCEDURES` pin in `xtask/src/main.rs` (per architecture.md §Occupied Resources + §Cross-cutting Patterns → Webview IPC capability policy).
- (arch) If the CARRY #10 counter lands, it emits via the stdout/file self-telemetry exporter under `&lt;data_dir&gt;/logs/` and never dials the app's own OTLP ports (per architecture.md §Established Decisions → [Self-Observation]).
