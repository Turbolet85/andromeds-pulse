## Constraints
- The chunk's claim is about the DATA-plane stored fields (DuckDB), but obs-plan.md §11 (Project-specific) forbids conflating the external-OTLP pipeline with the self-observation surface at `~/.andromeda-pulse/logs/agent-latest.jsonl`. Any observable this chunk adds lands on the self-observation surface and must not carry external clients' OTLP payload content across into it.
- obs-plan.md §1 (Telemetry triggers, logging-sensitive Vector 1) requires ingest-boundary events to emit `attributes_count` + `service_name_tag` only, never the raw `span.attributes` dict — and names the exact negative test shape for this chunk's measurement leg: send a span carrying a secret in an attribute value, verify the secret does NOT appear in `agent-latest.jsonl`.
- obs-plan.md §5 (Conceptual instrument types, tick-aggregated row) requires counters on the buffer path to be folded once per batch and ridden out as FIELDS on the existing 15s `buffer.tick`, not as per-event emissions; per-span-event emission is explicitly barred by the §11 hot-path rule. A redaction count is the same class.
- obs-plan.md §8 (Default-deny posture) requires every emitted field to resolve to an EXACT allowlist leaf enumerating EVERY field its emit site emits; `for_target`'s first-`.`-segment fallback otherwise silently redacts unlisted fields. The §8 `buffer` whitelist as written enumerates `rows_ingested` / `eviction_count` / `memory_bytes` / `retention_window_seconds` / `span_events_seen` / `fingerprints_computed` / `observer_invocations` — no redaction counter — so a CARRY #10 landing requires a §8 (and §5, and §4 if it rides `duckdb.append`) amendment. Whether the shipped `AllowList::production()` already carries such a leaf is research's question.
- obs-plan.md §5 (Metric label cardinality discipline) + §8 (data classification, raw OTLP payloads = High/scrub-required) require any redaction observable to be aggregate counts and bounded static labels only — never the matched credential, the redacted substring, the OTLP attribute key, or a client-supplied `service_name` as a label.
- obs-plan.md §8 (UI-vocabulary exemption) already states the plan's way of separating secret *formats* from ordinary vocabulary, naming an anchored-prefix + length-floor family (`sk-[a-zA-Z0-9]{40,}`, `ghp_[a-zA-Z0-9]{36}`, `AKIA[0-9A-Z]{16}`, `Bearer [a-zA-Z0-9]{40,}`, `password=[^\s]+`) and warning that over-broad patterns produce false positives. This is directly on the chunk's named design tension, and the plan's own lean is anchored-prefix.
- obs-plan.md §3 (Log format JSON schema) binds verbatim to the tests harness contract; any new field must ride the existing `fields` map of the JSON-per-line schema rather than changing line shape.

## Patterns to follow
- `buffer.tick` tick-aggregated counter fields folded by `BufferState::record_feed_counts` (per obs-plan.md §5) — the shipped, in-plan template for adding a hot-path-safe count to the buffer module.
- EXACT allowlist leaf plus a `for_target` fallback-discrimination guard living under `pulse-app/tests/` (per obs-plan.md §8) — src-level `mod tests` guards compile but never run under `[lib] test = false`, so a guard placed there would be dead.
- The §8 secret-format regex family as the reference shape vocabulary for an anchored-prefix arm, paired with the negative-corpus discipline that keeps ordinary identifiers (the scope's `trace_id=abc-123` pin) out of the match set.
- Once-per-boundary WARN discipline for degraded/notable conditions (`corpus.read.undecryptable` = one aggregate per QUERY, never per row; per obs-plan.md §6 log-levels `warn` row) if the chunk wants a visible signal rather than a silent counter.
- NEUTRAL-tolerant, run-window-scoped check scripts over `agent-latest.jsonl` (per obs-plan.md §10 Load-profile constraints) if a CI check is added — absent stream ≠ failure.

## Anti-patterns to avoid
- NEVER emit a log/span event per scrubbed field on the appender (`scrub_otlp_field`) or drain path — obs-plan.md §11 (Telemetry Strategy: no over-instrumenting the appender inner loop / per-row DuckDB ops; Logs: no `info` in hot path).
- NEVER log the matched credential or the raw attribute value anywhere, including inside a message describing that a redaction fired, or at `debug`/`trace` — obs-plan.md §11 (Logs, PII Scrubbing) + §8 Vector 1.
- NEVER widen a prefix key (bare `buffer`, or a new bare `security`) to make a new field visible — obs-plan.md §8 requires an EXACT leaf; and §11 (PII Scrubbing) bans single-location scrubbing rules, so a source-level fix must not replace the subscriber-Layer redaction.

## Contract bindings
- **obs ↔ security:** obs-plan.md §8 derives its scrub-required classifications and Vectors 1–6 from the security plan; §8 (Integration points) requires the source-level `skip(...)`, the subscriber Layer, and the Sentry `before_send` path to agree on the SAME rules — so a catalog change in `crates/security` must be reflected wherever obs restates the rule, not only at the scrub call site.
- **obs ↔ tests:** obs-plan.md §3 log-format JSON schema is bound verbatim to the tests harness contract (obs aligns to tests); the measurement leg's read of `agent-latest.jsonl` and any new `buffer.tick` field must not perturb the §10 heartbeat-gap CI check (`xtask/ci/heartbeat-gap-check.sh`) or the §10 zero-panic / zero-span gates.
- **obs ↔ external harness (the scope's CARRY #10 "gradeable from outside the process"):** the redaction counter is the field an out-of-process witness would read; obs-plan.md §2 (agent-readable invariants) requires it be readable from the JSON log file alone, with no dashboard or human-review step. Recording the cross-project consequence is the report's job; the Conductor repo is out of scope.

- If a redaction observable lands, it is tick-aggregated as `buffer.tick` fields (or an own-leaf `metric.buffer.*` target), with zero per-scrubbed-field emissions on the appender/drain path (per obs-plan.md §5, §11).
- Every field newly emitted by this chunk resolves to an EXACT §8 allowlist leaf enumerating every field its emit site emits, guarded by a test under `pulse-app/tests/` that fails when the leaf is neutralized (per obs-plan.md §8).
- The end-to-end measurement additionally asserts the bare-key literal appears nowhere in `agent-latest.jsonl` for the run window — the self-observation half of the leak, distinct from the stored-field half (per obs-plan.md §1 Telemetry triggers Vector 1).
- New fields are counts and bounded static labels only: no redacted value, no matched substring, no attribute key, no client-supplied `service_name` label (per obs-plan.md §5, §8).
