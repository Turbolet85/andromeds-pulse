# security extract

## Relevance
Relevant — this chunk is squarely in the security domain: `crates/security/src/scrubber.rs` is the plan's named PII-redaction primitive and the "stored fields" boundary is the plan's own persistence-scrub invariant.

## Constraints
- **The invariant under test is the persistence-boundary scrub, not the regex.** security-plan.md §Security Anti-Patterns → Logging (Uniform scrubber coverage) requires that any attribute value crossing into persistent storage (corpus.db) OR the self-observation sink `agent-latest.jsonl` pass through `scrub_attribute()` returning `ScrubbedValue::Allowed(_)` or `ScrubbedValue::Redacted` first, and it enumerates the covered call sites (OTLP appender DuckDB writes for `spans`/`log_records`/`span_events`; Drain corpus persist; BaselineState / ServiceRegistry / RetryStormState `scrubbed_clone`). The measurement leg must land on a boundary inside that enumerated set. Whether a bare provider key actually survives at any of them is research's question — the plan states the invariant, it cannot attest the catalog's recall. (Note: the plan's inline line anchors are chunk-#72-era, e.g. `appender.rs:332-356` vs. the scope's re-derived `:304`; the call-site *list* is authoritative, its line numbers are not.)
- **The leaked value must never become log or test output.** §Security Anti-Patterns → Logging bullet 1 and §Logging & Monitoring ("What NEVER to log") ban raw OTLP attribute values, span/log/metric content payloads, snapshot contents, clipboard contents, and MCP tool response bodies. A canary-absence comparison is the permitted proof shape; dumping the stored field to demonstrate the leak is not.
- **A redaction counter, if CARRY #10 lands, is count-and-identifier only.** §Security Anti-Patterns → Logging bullet 3 sets the shape precedent explicitly (log query identifier + parameter count, never parameter values), and §Secret Management mandates `#[tracing::instrument(skip(...))]` at secret-handling call sites. A `redaction_count` field on `duckdb.append` / `buffer.tick` satisfies this; a matched-substring, matched-pattern-value, or content-derived digest field does not.
- **Do not extend the redaction mandate onto the snapshot / clipboard / MCP surfaces.** §Logging & Monitoring (Snapshot / clipboard / MCP-tool-response hygiene) deliberately does NOT mandate sanitization of OTLP attribute values on those three paths — it mandates a user-facing warning, a non-suppressible clipboard-write toast, and documented-behavior framing for MCP. Improved catalog recall must not be reported as those surfaces now being "sanitized"; the stated posture there is a decision, not a gap.
- **False-positive guard fixtures are secret-scanner input.** §Secret Management (Secret scanning in CI) requires a secret-scanning step pre-commit and per-PR with build failure on detection, and §Security Anti-Patterns → Secrets bans committing credential-shaped material. A corpus of `sk_live_`/`sk-proj-`-shaped literals is exactly what that gate is built to catch: fixtures must be synthetic non-resolvable canaries, and any needed allowlist entry must be explicit rather than discovered by a red CI run.
- **Any dependency pulled in for an entropy/shape floor rides the existing gates.** §Dependency Security → CI integration requires `cargo deny check bans licenses sources` clean with `multiple-versions = "deny"` never relaxed, the `tonic` canary never skipped, `[sources]` restricted to crates-io, and the SPDX allowlist honored for the Homebrew/Scoop channels.
- **The `cargo audit` standing deferral has an explicit between-interval obligation.** §Dependency Security → CI integration (Standing deferral) requires re-verifying basis + overlap and recording `probe skipped per ratified interval (next: {point})` — never a silent skip — with overlap findings carrying visible dispositions: a finding with a stated safe upgrade is owner-named, never ignore-listed.

## Patterns to follow
- The two-outcome `scrub_attribute` → `ScrubbedValue::{Allowed, Redacted}` contract (§Security Anti-Patterns → Logging) — a new catalog arm extends that contract in place; a parallel scrub path at a call site would break the single-invariant framing the section rests on.
- `Allowed(_)` is a first-class assertion, not just the absence of `Redacted` (§Security Anti-Patterns → Logging) — the false-positive guard corpus asserts on the Allowed arm the same way the positive corpus asserts on Redacted.
- Identifier-plus-count field shape for anything observable about sensitive data (§Security Anti-Patterns → Logging bullet 3; §Secret Management `skip(key)` discipline).
- Source-side `#[instrument(skip(...))]` plus subscriber-layer redaction as two layers (§Logging & Monitoring, Log format: "field redaction is applied at the subscriber layer, not at log call sites").
- Registry-completeness amendment precedent: every chunk that added a validated boundary registered it in the plan as routine (§Input Validation rows added 2026-06-28, 2026-06-29, 2026-08-14, 2026-08-16). The analogue here is §Security Anti-Patterns → Logging as the site of record if a new catalog arm lands.

## Anti-patterns to avoid
- NEVER emit the raw attribute value, the matched credential substring, or a value-echoing digest into `agent-latest.jsonl`, a span field, a new counter, or a test failure message (§Security Anti-Patterns → Logging; §Logging & Monitoring "What NEVER to log").
- NEVER commit a real credential as a positive-corpus fixture; `.env` / `*.key` / credential material is `.gitignore`-banned and secret-scanner-enforced (§Security Anti-Patterns → Secrets; §Secret Management → Secret scanning in CI).
- NEVER relax `multiple-versions = "deny"`, skip the `tonic` canary, or ignore-list an advisory that has a stated safe upgrade in order to land a new dependency (§Dependency Security → CI integration; §Security Anti-Patterns → Universal).

## Acceptance criteria contributions
- A bare provider-key canary driven through a real enumerated persistence-boundary call site is absent verbatim from the stored field on read-back AND absent from `agent-latest.jsonl`; a regex-level unit assertion alone does not satisfy this (per security-plan.md §Security Anti-Patterns → Logging, uniform scrubber coverage invariant).
- The Allowed corpus does not regress: `trace_id`-class high-entropy identifiers still return `ScrubbedValue::Allowed(_)` after any shape-based arm, and no new arm turns an ordinary identifier into `Redacted` (per security-plan.md §Security Anti-Patterns → Logging).
- No added or changed fixture contains a real credential, and the pre-commit + per-PR secret-scanning gate passes on the resulting tree (per security-plan.md §Secret Management → Secret scanning in CI).
- If the chunk adds a dependency, `cargo deny check bans licenses sources` passes with `multiple-versions = "deny"` unrelaxed and the `tonic` canary unskipped; and the wrap re-verifies basis + overlap and records `probe skipped per ratified interval (next: 34)`, with RUSTSEC-2026-0258 (`h2`, safe upgrade ≥0.4.16) owner-named rather than ignore-listed (per security-plan.md §Dependency Security → CI integration).
