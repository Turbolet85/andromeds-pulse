## Constraints
- The desktop-webview E2E driver is **pinned by the plan** to `tauri-driver` 2.x + `WebdriverIO` 9.x + `mocha`, headless xvfb-run on Linux / native on macOS+Windows (per test-plan.md §6 "Drivers per surface", restated in §1 "Surfaces under test" desktop-webview row and §9 E2E matrix). Candidate shape (b) (WebView2 remote debugging + Playwright `connectOverCDP`) is **not** the plan's named stack; if research picks it, that is a plan deviation owing an amendment, not a silent substitution.
- §2 "Agent-runnable invariants" forbids "no human-in-loop verification, **no Playwright headful mode**, no manual screenshot comparison", and §1 `agent-driven-discipline: No manual verification checkpoints` requires every test to exit with a deterministic agent-readable signal (exit code / structured stdout / log-line match). Whether that clause bans shape (b)'s transport or only its human-review intent is a question the P3 research must resolve explicitly rather than assume.
- Every `/andromeda-phase` chunk plan's `## Test Commands` MUST carry the full standard gate set unconditionally — `cargo fmt --check`, `cargo clippy --workspace --all-targets --all-features -- -D warnings`, `cargo nextest run --workspace --profile ci`, `cargo xtask capability-drift`, `cargo xtask capability-widening-check` — plus the three `--prefix pulse-app/ui` webview gates (`lint` / `typecheck` / `test`) whenever the Files-to-modify or New-files lists touch any `pulse-app/ui/**` path (per test-plan.md §3 "Per-chunk gate discipline"). The scope's `[inferred]` harness surface (ui devDeps + driver config + spec file) would trip the webview half.
- The boot-smoke gate is conditional on a trigger list that **includes `pulse-app/capabilities/*.json`** (per test-plan.md §3 "Boot-smoke gate (conditional)"). This chunk's mutation check revokes `core:window:allow-close` and rebuilds; whether that makes capabilities a *touched* path (versus read-only-plus-revert) decides whether the boot-smoke gate is owed — research's call.
- The two-leg mutation check maps onto the codified **Direct-binary smoke variant** (test-plan.md §3): each leg gets its OWN fresh `ANDROMEDA_PULSE_DATA_DIR`, the **0-ERROR / 0-`app.panic.fatal` clean-log assertion binds the GREEN leg only**, and the RED leg must record the ERROR it is measuring (target + reject reason) as *evidence*, not as a gate failure. Same section also requires shutdown by SPECIFIC pid with `:4317`/`:4318` confirmed released, and warns `bash scripts/agent-run.sh status` exits 0 with a full payload against a dead system, so it never evidences that THIS run was live.
- Zero-flakiness is absolute: a headful GUI leg that flakes once is quarantined + root-caused, never retried; `#[ignore]` is reserved for flake quarantine (per test-plan.md §10 "Zero-flakiness budget" and the load-profiles note).
- Any `pulse-app`-scoped nextest selection must be narrowed with `--filter-expr` / `-E` **under `--workspace`**, not with `-p` — measured rlib-format link failures otherwise (per test-plan.md §3 `run` → Test selection).

## Patterns to follow
- Role-based / accessible-name selection: §11 E2E bans xpath and hashed-CSS selectors and prefers role-based or `data-testid`. The scope's control already exposes `aria-label="Close to tray"`, so the leg's selector should consume that accessible name.
- Explicit-signal synchronization instead of sleeps: §3 `boot` polls the `health` TauRPC every 500ms to a 10s timeout with defined readiness fields; §11 E2E bans `sleep(N)`. The "window became hidden" observation needs an equivalent explicit signal (window-state query, obs event, or IPC), not a timed wait.
- Per-leg isolation via env override — fresh `tempfile::TempDir` + `ANDROMEDA_PULSE_DATA_DIR`, `RUST_LOG`, ephemeral ports (per test-plan.md §3 "Test data bootstrap" and §7 "Test data lifecycle").
- Machine-parseable JUnit-shaped output: nextest writes `target/nextest/junit.xml` and the webview vitest run writes `target/junit-ui.xml` deliberately matching that shape (per test-plan.md §4 webview framework, §9 "Test report format"). A new runner should emit the same shape so one agent parser covers all layers.
- If any leg needs a Rust home: `pulse-app`'s `[lib] test = false` means co-located `mod tests` compiles but never runs — pulse-app probes live in `pulse-app/tests/*.rs` reaching internals via `pub` + `#[doc(hidden)]` (per test-plan.md §2 "Test directory + naming conventions" and §4 "Test file location").

## Anti-patterns to avoid
- No visual-regression or human-approved artifacts: §11 Universal bans Percy/Chromatic/Applitools, "human reviews canvas", and manual smoke steps; §11 E2E bans visual regression requiring human approval. The scope's operator legs may stay as judgment items but must not be committed as automated gates.
- No `sleep(N)` synchronization, no retry-once policy, no committed `#[ignore]` without a tracked reason (per test-plan.md §11 E2E + §11 Quality).
- If shape (b) lands: §11 Universal bans Selenium IDE / Playwright codegen-recorder **as test author** — recorder output may only be used behind a headless/scripted runner.

## Contract bindings
- **tests ↔ obs** — §3 "Log format" binds the harness's log verb to the `tracing` JSON-lines stream, and the Direct-binary smoke variant asserts over `&lt;data_dir&gt;/logs/agent-latest.jsonl*` (the date-suffixed glob the scope also flags as mandatory). Whether the close path's `tray.signpost.shown` event is the right deterministic signal for the leg is an obs+research decision.
- **tests ↔ a11y** — the leg's selector is the button's accessible name, so §11 E2E's role-based-selector mandate consumes the a11y contract; shape (b) would also reuse the existing `@axe-core/playwright` a11y chain that §6/§9 currently rely on for the browser-driven residual.
- **tests ↔ arch/security (capabilities)** — the mutation target `pulse-app/capabilities/default.json` is guarded by `cargo xtask capability-drift` + `cargo xtask capability-widening-check`, both in §3's standard gate set; those gates must run with the file RESTORED.
- **tests ↔ §6 P5 residual** — §6 P5 records the `tauri-driver` headful suite as a *deferred, documented residual* (chunk #51 Path A' precedent, reaffirmed at chunk #99). One driver + one leg does not by itself discharge the P5 tray/window matrix; any narrowing of that residual is a wrap-time amendment, not a claim this chunk makes.
