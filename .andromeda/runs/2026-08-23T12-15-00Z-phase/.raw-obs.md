# obs extract

## Relevance
Partial — no production emission is expected to change, but the chunk's observation surface (the obs-log family), the P5 must-trace path it drives, and any new/driver-visible target fall under obs.

## Constraints
- The self-observation surface the leg reads is the JSON-per-line file with **daily rotation via `tracing-appender::rolling::daily`** (per obs-plan.md §3 Log file location) — the plan mandates rotation, which is what makes the scope's date-suffixed `agent-latest.jsonl*` glob mandatory rather than optional; a bare-name reader is reading a file the plan does not guarantee exists.
- The ✕ leg drives the P5 path, whose must-trace spans are `ui.layout.transition` → `tray.visibility.toggle` → `ipc.health.check` with attributes `layout_mode_from` / `layout_mode_to` / `tray_visible` / `health.status` (per obs-plan.md §4 Scenario P5). The same section records P5 as **"deferred to tauri-driver headful E2E suite"** — this chunk is that deferral's enabler. Whether the ✕→hide path already emits any of these (the scope names a `tray.signpost.shown` emission that obs-plan does not name anywhere) is research's question.
- Every log line must carry `timestamp` / `level` / `target` / `message` / `fields`, with `service.name` / `service.version` / `deployment.environment` as subscriber default fields (per obs-plan.md §6 Required fields, §3 Service identity) — any emission the driver adds or asserts on is held to this shape.
- §8 operates **default-deny with EXACT per-target leaves**, and `for_target`'s prefix fallback silently redacts fields of any target lacking one (per obs-plan.md §8 Default-deny posture). The whitelist enumerates no `tray`, `ui`, `window` or `app.boot.webview.*` entry — so whether the fields the leg wants to assert on are emitted un-redacted at HEAD is research's question, not something the plan attests.
- Zero-unlogged-panics is an always-required invariant, and module-boundary errors must be logged at WARN/ERROR with trace context and an error **category** (not a stack trace, per Vector 2) (per obs-plan.md §10 Always-required / Standard+ invariants). This binds the RED arm of the mutation check: an ACL-revoked `getCurrentWindow().close()` must surface as a logged boundary rejection, not a silent no-op, and neither arm may panic unlogged.
- Any xtask check script run over `agent-latest.jsonl` must be **NEUTRAL-tolerant** (absent stream ≠ failure) and scoped to the run window via `write_run_window_log` (per obs-plan.md §10 Load-profile constraints, and the frame-budget two-state posture in §10 Performance budgets). A headful driver run flips the frame stream from NEUTRAL to ACTIVE for the first time — the same script set must serve both.
- Heartbeat gap &gt;45s for `ingest.tick` / `buffer.tick` / `viz.tick` / `plugins.tick` is a build-failing gate (per obs-plan.md §10 CI gates, §3 Heartbeat ticks) — a window hidden mid-run must not be read as a subsystem stall.

## Patterns to follow
- **Observe-by-log-tail:** assertions read the JSON file with `jq` post-run (`select(.target == ...)`), the plan's standing agent-readable consumption path (per obs-plan.md §10 CI gates, §9 CI failure → artifact triage).
- **Tick vs `health` complementarity:** the synchronous TauRPC `health` command is the active boot/runtime liveness probe (harness polls until ok); 15s ticks are for retroactive analysis and must not be conflated (per obs-plan.md §3 Heartbeat ticks complementarity). For a driver waiting to attach, `health` is the readiness pattern.
- **Platform-attest startup spans:** `app.boot.webview.init` (`webview_backend: WebView2`), `app.boot.gpu.check` (`wgpu_backend`), `app.boot.tray.init` (`tray_api: NotifyIcon`) are the plan's existing means of attesting *which* real surface booted (per obs-plan.md §1 multi-platform-exporter-compat trigger) — the natural evidence that the driver attached to the real Windows WebView2 window rather than a Chromium `dist`.
- **EXACT allowlist leaf + live guard:** new targets land with a leaf enumerating *every* field the emit site emits, guarded by a test under `pulse-app/tests/` (src-level `mod tests` is dead under `[lib] test = false`), and the guard is mutation-checked (per obs-plan.md §8 Default-deny posture). The chunk's own mutation-check discipline for the leg is the same shape.

## Anti-patterns to avoid
- NEVER introduce a browser-side OTel SDK or any second exporter to make the webview observable to the driver — frontend telemetry flows only through the TauRPC `telemetry.frontend.*` bridge to backend `tracing` (per obs-plan.md §11 Universal, §1 desktop-webview surface). A CDP-attach probe is a *driver* channel, not a telemetry channel.
- NEVER make unstructured stderr text the harness's observation channel, and NEVER assert on multi-line stack traces — JSON-per-line to the file sink only (per obs-plan.md §11 Logs).
- NEVER add a bare-prefix allowlist key (e.g. a `tray` or `ui` prefix) to make a driver-visible field readable — it widens every sibling target to one field set (per obs-plan.md §8 Default-deny posture); and no per-frame/hot-path `info` emission added for driver convenience (per obs-plan.md §11 Telemetry Strategy).

## Contract bindings
- **obs ↔ tests (harness contract):** the §3 log-format JSON schema is bound *verbatim* to the tests plan's Test Harness Contract ("obs aligns to tests, not vice versa", per obs-plan.md §3 Log format JSON schema) — whatever the driver asserts on must be that shape. §4 P5's "deferred to tauri-driver headful E2E suite" note is the tests-side hook this chunk unblocks; the driver-shape pick (tauri-driver/WDIO vs CDP/Playwright) is not an obs decision.
- **obs ↔ tests (readiness):** the TauRPC `health` command's synchronous status shape is the boot-readiness probe the harness polls (per obs-plan.md §3 Heartbeat ticks complementarity, §4 P5 `ipc.health.check`).
- **obs ↔ security:** the mutation-check arm (revoke `core:window:allow-close`, rebuild) must not leak canonicalized paths, Rust struct names or library versions into the log — sanitized `AppError` + SpanTrace, basename-only (per obs-plan.md §8 Data classification rules, Vectors 2/3/6).
- **obs ↔ a11y:** if the driver carries an axe binding (`@axe-core/webdriverio` / `@axe-core/playwright` per the scope's candidate stacks), violation JSON must ride the structured log format; the §8 UI-vocabulary exemption governs any PII grep over UI labels such as `aria-label="Close to tray"`. Out of this chunk's declared scope (the a11y entry is downstream), flagged only so the binding is not re-derived there.

## Acceptance criteria contributions
- The leg's log-side assertion reads the date-suffixed `agent-latest.jsonl*` family (glob, newest-wins), never a bare filename — daily rotation is mandated, so a bare-name reader can silently find nothing (per obs-plan.md §3 Log file location).
- Both arms of the mutation check (green ✕ and ACL-revoked RED) produce zero `app.panic.fatal` events, and the revoked arm surfaces the rejected close as a WARN/ERROR module-boundary event with an error category rather than silently (per obs-plan.md §10 SLO Invariants — always-required + Standard+ invariants).
- Any check script the harness adds over the obs-log family is NEUTRAL-tolerant (absent stream ≠ FAIL) and run-window scoped, so the new ACTIVE-webview state and existing headless runs share one script set (per obs-plan.md §10 Performance budgets / Load-profile constraints).
- If the chunk adds any new `tracing` target (e.g. a test-only gate or driver-visibility event), it ships with an EXACT §8 allowlist leaf enumerating every field its emit site emits, guarded under `pulse-app/tests/`, mutation-discriminated, and with no bare prefix key (per obs-plan.md §8 Default-deny posture).
