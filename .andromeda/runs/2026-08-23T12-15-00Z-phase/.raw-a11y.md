# a11y extract

## Relevance
**Partial** — no new UI surface is built, but the chunk lands a driver inside `pulse-app/ui/` (the same Playwright surface the a11y suite owns per a11y-plan.md §3 Harness wiring &amp; conventions) and its canonical leg presses a control that sits on critical path P5.

## Constraints
- The desktop-webview surface carries **Standard tier → WCAG 2.1 AA + SC 2.3.3 AAA (motion)**; any harness or test-only affordance added under `pulse-app/ui/` inherits that target and may not lower it (per a11y-plan.md §1 A11y Scope Summary).
- §3 pins the desktop-webview a11y runner stack to **@axe-core/playwright 4.11.x + Lighthouse 12.x + pa11y 9.x**. Driver shape (a) brings a WebdriverIO world (and, in Conductor, `@axe-core/webdriverio`); adopting a second axe adapter *as an a11y assertion path* deviates from the pinned pick and needs an amendment. A WebdriverIO driver used purely as a non-a11y affordance driver does not (per a11y-plan.md §3 A11y testing tool pick).
- The existing a11y chain depends on load-bearing wiring that a real-window driver must not repoint or displace: the `TauRPC__&lt;router.path&gt;` IPC mock, the metadata-shaped window label, the SPA-fallback static server, and the pa11y server-lifecycle runner. §3 also mandates the cheap suite-health check (`npx playwright test --list`) because a list-time import failure once silently disabled the whole suite (per a11y-plan.md §3 Harness wiring &amp; conventions).
- Hard gates stay hard: zero new violation tuples vs the stored regression baseline, Lighthouse a11y ≥ 90, keyboard focus-order test green, no retry-once policy (per a11y-plan.md §10 SLO Invariants &amp; A11y Budgets).
- The leg's surface is governed by **P5**, which requires SC 2.1.1 / 2.1.2 / 2.4.3 / 2.4.7 / 4.1.2 plus the Esc escape path from the widget with focus returning to the tray icon on restoration. A pointer-click proof does **not** discharge the keyboard-path requirement (per a11y-plan.md §1 Critical paths P5 + §5 Keyboard Navigation, compact-widget row).
- Every WCAG SC must retain a machine-verifiable path; operator/manual legs are supplemental only. The chunk's "operator legs reserved for judgment items" is compatible, but no a11y SC may migrate to an operator-only leg as a side effect of the driver landing (per a11y-plan.md §2 Agent-runnable invariants + §11 Universal).
- §1 P5 names the tray-minimize affordance `button[aria-label="Minimize to tray"]`, while the chunk's leg targets `aria-label="Close to tray"` on the titlebar ✕. Whether these are the same control (and therefore whether the P5 row's accessible name is stale, as happened in the 2026-06-30 amendment) is **research's question** — the plan states the target name, and I cannot attest what the code renders.

## Patterns to follow
- **Scripted-keyboard focus harness** (Playwright + `tabbable` ground truth, `page.keyboard.press('Tab' / 'Shift+Tab' / 'Escape')`, assert against `document.activeElement`) — the established shape for asserting an affordance's effect; driver shape (b) reuses it verbatim over CDP (per a11y-plan.md §3 Focus management test harness + §5 Test harness pattern).
- **Native `&lt;button&gt;` + accessible name, Enter/Space activation** — the ✕ leg's control is already this pattern per the scope; the driver should select it by role + accessible name rather than by a test-only attribute grafted onto the DOM (per a11y-plan.md §4 ARIA Patterns &amp; Roles, Button row).
- **compact-widget focus model as the leg's semantic contract**: title / expand / minimize order, Esc minimizes to tray, focus returns to the tray icon on restoration — this is what "the window became hidden" means in a11y terms (per a11y-plan.md §5 Keyboard Navigation).
- **Mocked-IPC + static-served SPA remains the audit path**; the real-window driver is a complement, not a replacement, so the mock/static/pa11y helpers stay intact and the `--list` health check runs after any `pulse-app/ui/` devDep or config change (per a11y-plan.md §3 Harness wiring &amp; conventions).
- **"One axe spec per new route/modal" standing rule** — a no-op here since the chunk adds no route or modal, but it fires immediately if a probe forces a drivability affordance that renders UI (per a11y-plan.md §3 Harness wiring &amp; conventions).

## Anti-patterns to avoid
- Never add ARIA attributes (or churn an existing `aria-label`) merely to give the driver a selector — semantic HTML first, and no excessive ARIA noise (per a11y-plan.md §11 ARIA + §11 Screen Reader).
- Never let a new runner soften the a11y gate: no lint-only or manual-only substitution for the runtime axe/pa11y/Lighthouse pass, no soft gate, no retry-once (per a11y-plan.md §11 CI + §11 SLO).
- Never introduce a keyboard trap, `tabindex &gt; 0`, or suppressed focus ring via a test-only drivability hook (per a11y-plan.md §11 Keyboard).

## Contract bindings
- **a11y ↔ tests:** §3 binds the a11y harness to the tests-domain E2E driver and its 5-command discipline (`boot`/`run`/`status`/`cleanup`/`logs`). A new headful driver is a tests-domain surface; whether it shares or forks that lifecycle determines whether `npm run test:a11y` / `cargo xtask test:a11y` still resolve (per a11y-plan.md §3 Focus management test harness contract binding + §9 CI Integration).
- **a11y ↔ obs:** if the driver emits any a11y-tagged record into the `agent-latest.jsonl*` family the chunk reads, it must use the structured violation shape (`target: "a11y::assertion"`, `fields.wcag_criterion` / `violation_type` / `severity` / `surface` / `selector` / `remediation` / `tool` / `tool_result_id`) in obs's log format (per a11y-plan.md §3 Structured violation JSON schema).
- **a11y ↔ design:** the WindowControls buttons carry a target-size floor (SC 2.5.8, ≥ 24×24 CSS px, via `--target-button-min` / `--target-input-min`); relevant only if the mutation-check rebuild touches that component (per a11y-plan.md §6 Target size tokens).

## Acceptance criteria contributions
- (a11y) After the driver lands, the a11y suite still imports cleanly (`npx playwright test --list` on `tests-a11y` lists specs, no list-time import failure) and the full axe + Lighthouse + pa11y chain reports **0 violation tuples** against the stored regression baseline, Lighthouse a11y ≥ 90 (per a11y-plan.md §3 Harness wiring &amp; conventions + §10).
- (a11y) The clicked ✕ is targeted by **role + accessible name** and keeps a non-empty accessible name and native button role after the chunk (SC 4.1.2); no `aria-*` attribute is added for test-selection purposes (per a11y-plan.md §4 ARIA Patterns &amp; Roles + §11 ARIA).
- (a11y) After the mutation check restores `core:window:allow-close`, P5's escape path is re-verified intact — Esc from the compact widget minimizes to tray and focus returns per the compact-widget anchor (SC 2.1.1 / 2.1.2 / 2.4.3); the leg must not leave the keyboard path unasserted because the pointer path was proven (per a11y-plan.md §1 Critical paths P5 + §5 Keyboard Navigation).
- (a11y) If a drivability affordance (env gate, hook, marker element) is added to the app, it introduces no new focusable element, no landmark change, and no ARIA noise; if it renders a surface, it ships with an axe spec in this chunk (per a11y-plan.md §3 Harness wiring &amp; conventions "Adding a surface" + §11 Screen Reader).
