## Constraints
- **Half B's blank window is an a11y failure mode, not only a UX one.** a11y-plan §5 (Focus order per layout → findings-window / report-window) requires focus to move INTO the findings panel on open (first incident row, Tab cycles rows → "Mark all as read", Esc/blur/mark-all-read dismiss) and the report window to be a focus-trapped `role="dialog"` with Esc close; §5 Focus restoration requires cross-window restore via first-party Tauri events (`findings:dismissed` / `report:closed`), explicitly NOT `focus-trap-react`. A never-navigated webview can satisfy none of these — no first row to focus, no Esc handler mounted, no event emitter to restore the badge. Whether the shipped code already re-navigates or otherwise confines a blank victim window is research's question. (per a11y-plan §5)
- **This headful leg is not the WCAG evidence path and must not be worded as one.** a11y-plan §10 makes zero WCAG AA violations on must-be-accessible paths the SLO and §3/§9 put the machine-verifiable evidence in the `test:a11y` chain (axe-core/Lighthouse/pa11y JSON + `keyboard-focus/widget-and-modals.spec.ts`); §11 Strategy bans any WCAG conformance claim without that machine-verifiable evidence. A `StageHalves{obs, dom}` verdict is stage evidence, not conformance evidence. (per a11y-plan §10 + §11 Strategy)
- **Any a11y violation this chunk emits must use the §3 structured violation JSON schema** — `wcag_criterion` / `violation_type` / `severity` / `surface` / `selector` / `remediation` / `tool` / `tool_result_id`, aligned to obs §6 — never an ad-hoc shape folded into the leg's stage report. The chunk's own expectation (scope §7) is that no new obs leaf is needed; if that holds, no a11y JSON is owed. (per a11y-plan §3 Structured violation JSON schema)
- **The drag stage must reach `data-tauri-drag-region` through the OS pointer path, never by making it focusable.** a11y-plan §11 ARIA bans ARIA on non-semantic HTML and §11 Keyboard bans `tabindex &gt; 0` and nested tab stops (the grid-lite carve-out is scoped to roving-`tabindex` containers only); §5's compact-widget focus order admits exactly four stops (title → Toggle dashboard → Minimize → Close to tray) and no drag affordance. (per a11y-plan §11 Keyboard + §5 compact-widget)
- **The resize stage does not re-open the SCs the plan has already ruled out.** a11y-plan §1's applicability list records **SC 1.4.10 Reflow** and **SC 1.4.4 Resize Text** as NOT applicable ("desktop-only Tauri app; viewport stable"), so P-082's internal-scroll containment is a layout fact, not a reflow assertion — framing it as one would contradict a recorded determination. What does bind at the clamped minimum is §6 Target size tokens: `--target-button-min` / `--target-input-min`, SC 2.5.8 ≥ 24×24 CSS px measured on `button` / `input` / `[role="switch"]` with padding counting. (per a11y-plan §1 applicability list + §6 Target size tokens)
- **A recorded decline on the native-menu stage is the plan-sanctioned posture, not a gap.** a11y-plan §1's surface table records that OS-native menu internals expose no automated tool reach (Windows UIA / macOS NSAccessibility / Linux ATK; "No axe-core reach for tray menu internals"), and §3's Screen reader test pattern makes manual SR/keyboard verification supplemental and never sole. The decline reason must therefore not be converted into an a11y claim in either direction. (per a11y-plan §1 surfaces table + §3 Screen reader test pattern)
- **The tray-restore mechanic touches a live focus contract.** a11y-plan §1 P5 requires Esc-to-tray to return focus to the tray icon on restoration and §5 Focus restoration requires focus to return to the compact-widget when re-expanded; the OS toast itself is a §1 assertable `os-notification` entity whose content must be screen-reader readable via the OS a11y API, with no automated tool reach. Whether the shipped restore path already moves focus per P5 is research's question. (per a11y-plan §1 P5 + §5 Focus restoration)

## Patterns to follow
- **Accessible-name-first selector binding (measured-per-surface convention).** a11y-plan §1 P1 records the headful leg binding `region[aria-label="Telemetry traces chart"]`, the native `table` and `.trace-row`, retaining `data-testid` only where no accessible anchor ships (`trace-table-empty`). New widget-control stages should bind the shipped accessible names from §1 P5 / §5: `button[aria-label="Minimize"]`, `button[aria-label="Close to tray"]`, `button[aria-label="Toggle dashboard"]`.
- **Measure the selector at HEAD before pinning it.** The phantom-selector discipline established across the 2026-08-23 amendments — a name asserted in a plan is not evidence the product ships it, and a claimed absence must be checked against the component that actually owns the surface.
- **Focus-order assertion via `tabbable` ground-truth.** a11y-plan §3 Focus management test harness computes the expected sequence with `tabbable(container)` and compares against `document.activeElement` after scripted `Tab` / `Shift+Tab` — the existing mechanism for proving a landed drag/resize stage did not disturb the widget's Tab order.
- **Reduced-motion emulation stays in the existing spec.** a11y-plan §6 Motion tokens / §3 use `page.emulateMedia({ reducedMotion: 'reduce' })`; if a landed stage introduces an animated window transition, the existing reduced-motion spec is the home for it, not a new mechanism.
- **Harness-health and state-sentinel conventions.** a11y-plan §3 Harness wiring records `npx playwright test --list` as the cheap suite-health check (a list-time import failure once silently disabled the whole suite), the populated-fixture requirement, and the `__mockReject` / `__mockDelayMs` sentinels for auditing error and in-flight states — the existing analogue if a not-yet-navigated / late-settling window state needs auditing.

## Anti-patterns to avoid
- **Never add a role, `tabindex`, or accessible name to non-semantic markup to make an OS mechanic drivable** (drag region, native menu). a11y-plan §11 ARIA (ARIA on non-semantic HTML) + §11 Keyboard (`tabindex &gt; 0`, nested tab stops).
- **Never let a declined or manual-only native-surface stage stand in as a11y evidence,** and never derive a WCAG conformance statement from a stage verdict. a11y-plan §11 Strategy + §11 Universal (manual/vendor-limited never sole; no conformance claim without machine-verifiable evidence).
- **Never ship a new user-visible surface without its axe spec in the same chunk.** If Half B's guard path introduces any visible state (a fallback, blank, or error view), a11y-plan §3's "Adding a surface" standing rule requires one axe spec in-chunk, and §11 CI bans deferring a11y to a follow-up.

## Contract bindings
- **a11y ↔ obs:** structured violation JSON per a11y-plan §3 is a binding contract onto obs §6 (`target: "a11y::assertion"`, the eight required `fields`). Applies only if this chunk emits an a11y violation record; the chunk's stated expectation of no new obs leaf keeps this dormant.
- **a11y ↔ tests:** a11y-plan §3 Focus management harness reuses tests' E2E driver under the 5-command discipline (`boot` / `run` / `status` / `cleanup` / `logs`), and §9 runs the a11y step in the same `ci.yml`. The chunk's boundary (scope §6: does not CI-wire the leg) leaves the a11y gate exactly where §10 puts it — this chunk neither extends nor weakens it.
- **a11y ↔ design-system:** a11y-plan §6 binds `--target-button-min` / `--target-input-min` (SC 2.5.8) and `--border-focus` (SC 2.4.7 + SC 1.4.11) — both bind at the widget's aspect-clamp minimum size if the resize stage lands.
