## Constraints
- layout-templates §Component — Custom titlebar (desktop-webview specific) → Layout requires the drag region to span the full titlebar width EXCEPT the buttons (`data-tauri-drag-region` on the container), with flex segments `[app-icon + title | grow | settings-button | window-controls]`. A drag stage's press point must sit inside that region and outside the settings/window-control segments, or a negative result measures the wrong element rather than the driver. Whether the shipped titlebar markup already carries that attribute across that span is research's question.
- layout-templates §IA notes (desktop-webview) → Responsive behavior requires the compact widget to be a fixed quarter-screen surface with NO CSS media-query breakpoints — user-resizable, but the layout does not reflow. A resize stage may assert the OS-level rect/aspect clamp; it must not expect or assert in-widget reflow at any size.
- layout-templates §Wireframe — Full dashboard (Traces primary screen) → wireframe notes requires the Traces route to be a flex column bounded to the shell's `main` height (`overflow:hidden`) so the dashboard shows no outer page scrollbar **at any window size**, with the constellation hero and the `Errors only` toolbar fixed (`flex-shrink:0`) above a flex-filling table. Combined with §IA notes "full dashboard resizable with no hard breakpoints", the multi-window-size half must hold ONE invariant at every size, not per-breakpoint variants.
- layout-templates §Component — Trace data table → Internal scroll region requires the table's own region to be the scrolling element (`flex:1 / min-height:0 / overflow-y:auto`) under a sticky opaque `color-base` thead. The DOM half of any resize stage must read that region's scroll state, not the document's. The plan documents this containment as a multi-element chain (route column bound → parent flex → region overflow), which is the layouts-side reason the scope's "layered containment" warning holds.
- layout-templates §Primary screens (desktop-webview) → Findings window / Report window require the findings window to be a borderless always-on-top list docked directly below the compact widget from the widget's LIVE geometry (work-area / multi-monitor clamped), sized to the incident count (caps ~8, then scrolls), and the report window to be the `Modal` **`fill`** variant positioned left of findings and clamped. A navigation-race victim would present these as blank windows — Half B's "unmeasured production exposure" is therefore a layout-surface failure, not only a harness artifact.
- layout-templates §Component — Notifications (OS-native) → Trigger events #4 requires the signpost on EVERY close that sends the app to the tray — the compact-widget ✕ signposts; the dashboard ✕ merely collapses to the widget and never signposts — gated on `notifications_enabled` alone. The repetition proof must drive the widget ✕ twice, and its restore leg must use the documented tray entry points per §IA notes (desktop-native) → Navigation model: left-click focuses/restores the compact widget, right-click menu top item "Open andromeda-pulse" targets the same widget. Both are OS surfaces, which is the layouts-side basis for the scope's "may be undrivable, decline is acceptable" premise.

## Patterns to follow
- Titlebar flex-segment map (§Component — Custom titlebar) as the coordinate source for a safe drag press point and for the excluded button hit-zones.
- Snap-to-edge boot geometry: the widget boots to a snap position per Settings (§Primary screens → Compact widget; §Component — Settings modal → "Widget snap position" nine-cell grid) — the P-061 boot-geometry sub-part reads that documented posture, not an arbitrary origin.
- The P-082 bounded-route pattern already documented in §Wireframe notes + §Component — Trace data table: fixed hero + fixed `Errors only` toolbar + internally-scrolling table with sticky thead. Reuse it as the single assertion shape across the driven sizes.
- Geometry-derived window docking (§Primary screens → Findings / Report window): a stage that MOVES or RESIZES the widget changes the input to findings-window placement, so drag/resize stages and the findings surface share one geometry source.
- Notification presentation shape for the repeated toast (§Component — Notifications (OS-native) → Notification format / Reduced motion): terse 1–2 word title, ≤2-line body, instant emergence at the `0.2` desktop-native expression level.

## Anti-patterns to avoid
- No stage may key on the Halo State Pulse canvas rendering on either webview surface — §Component — Halo State Pulse canvas records it as SPECIFIED-BUT-UNBUILT (measured 2026-08-21), so such a stage would be vacuous or false; disposition is a separate route entry the scope explicitly excludes.
- No custom in-webview context menu or custom chrome introduced to make the native-menu stage observable — the only right-click menu layouts documents is the OS-native tray menu (§Wireframe — Tray menu), and §Component — File picker states the same discipline ("never a custom file browser inside the app UI"). Suppression (`defaultPrevented`) or a recorded decline are the layout-consistent outcomes.
- No page-level scrollbar or reflow shortcut introduced as a resize accommodation — §Wireframe notes bans an outer page scrollbar at any window size and §IA notes bans widget reflow.

## Contract bindings
- Focus order ↔ a11y: §Component — Trace data table → Keyboard / focus (roving-tabindex row list, Enter investigates, Esc returns to the `Errors only` toggle, focus survives the live re-poll per P-081) binds to a11y §Focus Order — if a resize stage re-renders the table, focus survival is the a11y-owned half, layouts owns only that the toolbar + hero stay fixed above it.
- Modal patterns ↔ a11y: the `report` window is the `Modal` **`fill`** variant (§Primary screens → Report window); a11y §Modal focus trap (Escape dismiss + restore focus) governs its dismissal contract, which a non-blank first-open assertion depends on.
- Layout bound ↔ design tokens: the Traces route's height calc includes `footer var(--spacing-lg)` (§Wireframe notes), so a design §Spacing token change shifts the bound the multi-size stage asserts.
- Layout ↔ obs/tests: which close surface signposts (widget ✕ yes, dashboard ✕ no) is layouts truth per §Component — Notifications trigger #4; the `tray.signpost.shown` record and its allowlist leaf are obs-owned.
