## Relevance
Relevant — this chunk IS a tests-domain chunk: it extends the headful `cargo xtask webview-drive` E2E leg (test-plan §6 P5) and corrects the §6 durable boundary text.

## Constraints
- The leg's verdict shape is fixed: `pulse-app/ui/tests-e2e/webview-drive.mjs` **drives and REPORTS only** (DOM observations to a per-run TempDir `webview-drive-stages.json`); assertions live in `xtask/src/webview_drive.rs`, which reads BOTH the app's obs log and that artifact and reports **two independent halves** `StageHalves{obs,dom}` (`None` = inapplicable) — a combined boolean cannot distinguish "telemetry failed to land" from "failed to reach the screen" (per test-plan §6 Drivers per surface). Every landed stage must conform.
- Every stage predicate must match an **effect FIELD**, never the target alone; every stage id must stay `--expect-absent`-eligible with no CLI change, and an unknown stage id is a hard error listing the valid ids (per test-plan §6 Drivers per surface). This is the plan-side rule the chunk's "no vacuous stage" boundary rests on.
- A green exit code is **not** evidence the leg ran: `msedgedriver` unset ⇒ clean SKIP at exit 0 (per test-plan §6 Drivers per surface). Evidence of record is the per-stage report. Any probe result — including a *declined* stage — must be read off the report, not an exit code.
- Headful automation stays in scope only while agent-driven: verdict from exit code + the app's obs records + the driver's DOM artifact, **never from a human looking at it**; Playwright/CDP `connectOverCDP` attach remains UNADOPTED (per test-plan §2 Agent-runnable invariants). A drag/resize/native-menu stage judged by eye is out of bounds even though the mechanic is visual.
- Selectors are measured-per-surface: accessible name where one ships, `data-testid` where none does, never xpath, never a hashed/utility class — and **measure the selector at HEAD before pinning it, measuring a claimed ABSENCE the same way against the component that actually owns the surface** (per test-plan §6 Selector strategy; §11 Anti-Patterns → E2E). Both the `Minimize to tray` phantom-name and the Traces phantom-absence precedents are recorded there.
- The standard gate set is unconditional at every chunk (`cargo fmt --check`, `cargo clippy --workspace --all-targets --all-features -- -D warnings`, `cargo nextest run --workspace --profile ci`, `cargo xtask capability-drift`, `cargo xtask capability-widening-check`), plus the three webview gates because the chunk's expected surfaces include `pulse-app/ui/tests-e2e/webview-drive.mjs` (per test-plan §3 Per-chunk gate discipline). Narrow any `pulse-app` selection with `-E`/`--filter-expr` **under `--workspace`**, not `-p` (per §3 `run`).
- Zero-flakiness budget: one flake ⇒ quarantine + root-cause, never a retry-once policy, and `sleep(N)` is banned for synchronization (per test-plan §10 Quality Gates; §11 Anti-Patterns → E2E). Binds the resize stage in particular (the 150 ms aspect debounce must be waited on by an observable signal, not a timer) and the two-close repetition proof.

## Patterns to follow
- The existing 13-stage leg shape as the template for each new stage: real press/gesture on a production control → driver records the DOM observation → Rust asserts obs half + DOM half separately, with the field-level predicate (e.g. widget-close requires `ui.layout.transition {layout_mode_from, layout_mode_to}` AND `tray.signpost.shown` with `window_label == "compact-widget"`) (per test-plan §6 Scenario P5 Status).
- The **code** RED arm: `cargo xtask webview-drive --no-inject --expect-absent <STAGE>` — suppresses the injector and asserts the named stage reddens while telemetry-independent stages stay green; run every time it is invoked (per test-plan §6 P5 Status, §1 `webview-drive-mutation-arm-not-gated`).
- Telemetry enters only over **real OTLP** via `crates/ingest/examples/inject_demo.rs` (built outside the timed section, invoked by path), with `ANDROMEDA_PULSE_L4_DETERMINISTIC` set into the *driver's spawn env* because the app under test is a grandchild process (per test-plan §6 Drivers per surface; §7 self-bootstrapping requirement).
- The **direct-binary smoke variant** — fresh `ANDROMEDA_PULSE_DATA_DIR`, direct `target/debug/pulse-app.exe` launch, assertions read from the run's own `agent-latest.jsonl*` artifacts, shutdown by specific pid with `:4317`/`:4318` confirmed released — is the accepted form for runtime state neither `npx @tauri-apps/cli dev` nor the harness `run` verb can express (per test-plan §3 Per-chunk gate discipline). This is the plan-shaped vehicle for Half B path (a)'s plain-boot measurement; a MEASURE-FIRST chunk runs it **twice with a separate fresh data dir per leg**, and the 0-ERROR clean-log assertion binds the GREEN leg only.
- The `region[aria-label="Telemetry traces chart"]` / native `table` / `.trace-row` anchors plus the deliberately retained `data-testid="trace-table-empty"` are the discharged migration precedent for how a new stage picks its anchor tier (per test-plan §6 Selector strategy).

## Anti-patterns to avoid
- NEVER xpath, NEVER hashed/utility-class CSS selectors — both operative since the leg became DOM-driven (per test-plan §11 → E2E).
- NEVER `sleep(N)` for synchronization; wait on an explicit signal (per test-plan §11 → E2E). Also NEVER add a retry to make a mechanics stage settle (per §10 zero-flakiness).
- NEVER a verification step that needs human approval — no screenshot diff, no "human reviews canvas", no Percy/Chromatic-class visual regression (per test-plan §11 → E2E and → Universal). A drag/resize/native-menu mechanic that can only be confirmed visually must be **declined with a recorded reason**, not softened into a human check.

## Contract bindings
- **tests ↔ obs:** every stage's obs half is read from the app's own NDJSON obs log, so any new stage needing a record depends on that target/leaf existing in `pulse-app/src/observability.rs`'s allowlist with the bounded field the predicate matches (per test-plan §3 Bootstrap item 4 log-format-bind-with-obs; §6 Drivers per surface). Whether `WindowEvent::Moved` (scope §3.1) already emits an assertable record with a position field, or is geometry-persistence only, is research's question — it decides whether the drag stage can have an obs half at all.
- **tests ↔ security/capabilities:** the capability-revoke RED arm mutates `pulse-app/capabilities/*.json`, and byte-identical restore is a **discipline no shipped gate enforces** — `cargo xtask capability-drift` diffs procedures parsed from `bindings.ts` and never reads grants, while `cargo xtask capability-widening-check` covers only the 3 NEVER-widen caps and only in the widening direction (per test-plan §1 `webview-drive-mutation-arm-not-gated`). The mechanical fix is CARRY'd onto the Staged-bindings assertion route entry, not this chunk.
- **tests ↔ a11y:** stage anchors bind to the accessible names the a11y surface ships, so a name regression fails the stage; the browser-driven a11y chain (`cargo xtask test:a11y`, real Chromium against `ui/dist`) is the complementary second driver for this surface (per test-plan §6 Drivers per surface, Selector strategy).
- **tests ↔ CI:** §9's E2E row records the leg is NOT wired into any workflow; if it is ever wired, the wiring must assert the leg **RAN** (its per-stage report), never just its exit code, and needs `msedgedriver` matched to the runner's WebView2 build, `node`, and a prebuilt injector (per test-plan §9 CI Integration). The chunk's own boundary declines CI wiring, so this binding is a constraint on what may NOT be claimed.
- **§3 boot-smoke gate applicability:** `pulse-app/capabilities/*.json` and `pulse-app/src/observability.rs` are both on §3's boot-path trigger list and both appear in the chunk's expected-surfaces table; `pulse-app/src/window.rs` (the Half B guard site) is **not** enumerated there. Whether the revoke-and-restore RED arm and a Half B guard trigger the boot-smoke gate is a plan-application call P3/P4 must settle against the final files-to-modify list.
