## Anti-patterns к avoid

- NEVER log the assembled prompt body, the L3 digest payload, the tokenized prompt, the raw model output, or any partial-stream generation chunks — the prompt embeds curated EXTERNAL-OTLP content (service names, template fingerprints, error excerpts) covered by security plan §Logging Vectors 1/4 + the universal "NEVER log raw OTLP attribute values, snapshot file contents, clipboard contents, MCP tool response bodies" invariant in CLAUDE.md §Critical Warnings; only `digest_kind` / `digest_id` (opaque corpus ID, not contents) + token counts + result enum may appear (per obs-plan §Obs Anti-Patterns Spans + §8 PII Scrubbing table row "Raw OTLP telemetry payloads").
- NEVER use unbounded label cardinality on the three new metrics: no `digest_id` / `incident_id` / `service_name` / `fingerprint` labels on `pipeline.l4.*` events — those metrics are time-series-stored across runs; only enumerated `result` / `model_tier` / `hardware_profile` labels are permitted (per obs-plan §Obs Anti-Patterns Metrics + §5 cardinality discipline).
- NEVER hold a `tracing::Span` guard across the model inference `.await` without `.in_current_span()` — the async `LlmInferenceRunner::run(...)` future is long-running (1-30s typical per hardware profile per dist-arch v3 §L4 matrix); span context bleed into unrelated tokio tasks breaks trace_id correlation and bloats memory (per obs-plan §Obs Anti-Patterns Spans + 2026-05-23 session-learning on async-Pin-Box trait pattern).
- NEVER over-instrument hot inference loops (e.g., per-token-emitted spans inside the grammar-constrained sampler) — span overhead matters; wrap heavy field arg evaluation in `if tracing::enabled!(Level::DEBUG) { ... }` for any per-token instrumentation (per obs-plan §Obs Anti-Patterns Metrics + §Telemetry Strategy "NEVER over-instrument hot paths").
