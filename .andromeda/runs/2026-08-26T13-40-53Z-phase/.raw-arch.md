# arch extract

## Relevance
Relevant — the chunk edits code in the locked `pulse-app` binary crate, touches three arch-registered environment variables, and reshapes the argv of the runtime governed by arch §Established Decisions [LLM Inference Runtime].

## Constraints
- **Placement + dependency direction.** The guard and the bound land in the `pulse-app` binary crate, one of the 16 reserved workspace crate names that "cannot be reused by scopes" (`architecture.md` §Occupied Resources → Cargo workspace crate names). §Cross-cutting Patterns → Module dependency direction requires deps to flow *toward* `pulse-app` and forbids any library crate depending on it — so a path-guard helper placed in `pulse-app` can never be shared with `crates/security` / `crates/interpretation`; if reuse is wanted it must land in a library crate's explicit contract module (§Conventions → Module visibility discipline).
- **All three vars are registered arch resources whose registry text states the posture this chunk changes.** §Occupied Resources → Environment variables records `ANDROMEDA_PULSE_LLAMA_CUDA_BIN_PATH` / `_CPU_BIN_PATH` as "canonicalized + `is_file()`-asserted before spawn" and `ANDROMEDA_PULSE_MODEL_PATH` as "canonicalized but deliberately NOT confined under the data dir — see security-plan …for that measured exception and its owner". Whatever guard lands, those three entries owe an amendment at wrap (D-arch-resources). Whether HEAD matches the registry text is research's question, not something this extract can attest.
- **A new env var (the P-1 allow-root) is a new occupied resource with a fixed shape.** §Cross-cutting Patterns → Config management fixes precedence env &gt; `config.toml` &gt; built-in defaults, and every production-consumed var registered in §Occupied Resources → Environment variables carries an `ANDROMEDA_PULSE_` prefix plus a bounded parse whose every rejection falls back to a default rather than panicking or blocking startup. Registration in §Occupied Resources is due at wrap.
- **Deliverable B must not disturb the locked invocation discipline.** §Established Decisions [LLM Inference Runtime] requires explicit `-n {max_tokens}` + `-st` single-turn + an outer `tokio::time::timeout` wall-clock guard, spawned via `tokio::process::Command` with `kill_on_drop(true)`, with constrained sampling by llama.cpp-native GBNF `--json-schema-file`. The same entry pins the binary to build tag `b9305` exact, "bumps are deliberate chunk-scoped events, never 'latest tag' drift" — so a prompt-file flag that postdates b9305 is not available to this chunk.
- **The guard must survive the still-open distribution caveat.** §Established Decisions [LLM Inference Runtime] carries as an explicitly OPEN caveat whether the CUDA/CPU `llama-cli.exe` and the GGUF ship in the Tauri bundle, are fetched by an `xtask` boot step, or rely on the env pair. The scope puts that decision out of frame, so the bound must hold under all three outcomes and must not foreclose the decision arch still owns.
- **The `strict-path` fork (P-2) is arch-touching in one direction only.** Arch names no path-confinement library anywhere: §Stack and Technologies "Validation" row and §Established Decisions [Validation Library] lock validation at "None — `serde` + smart enum types + `TryFrom&lt;u16&gt;`", listing *file paths* inside that hand-rolled surface, with `garde` as the sole documented upgrade path. Adopting `strict-path` as the canonicalize-and-confine primitive makes it a load-bearing runtime dependency with no §Stack row (the `keyring` and tauri-driver precedents both required one); the `std` fallback requires no arch change.
- **Failure mode is contract-shaped.** §Established Decisions [Error Handling Pattern] keeps module-internal errors `thiserror`-derived, and §Cross-cutting Patterns → Cross-bridge data shape requires anything crossing TauRPC to be `serde::Serialize`. The degraded-boot path the scope names is already registered observable surface — `model.current_profile` (`load_status`), `pulse://stream/model-status`, `diagnostics.snapshot` (§Occupied Resources → Tauri IPC routes / IPC events) — so a rejection must be representable there without a new procedure.

## Patterns to follow
- **Bounded env resolution with a graceful default and one WARN.** `ANDROMEDA_PULSE_BASELINE_BOOTSTRAP_SECONDS` (§Occupied Resources → Environment variables): resolved once at boot, whitespace-trimmed, unset/empty/unparseable/out-of-range ⇒ the default "never a panic"; env-layer only (no `Settings` / `config.toml`, hence no TauRPC contract and no hot-reload delta); a non-default resolved bound emits one WARN per boot on a named target. Closest registered precedent for an operator-declared allow-root, including its observable.
- **Opt-in-only var whose absence is "not configured", not an error.** `ANDROMEDA_PULSE_CORPUS_PASSPHRASE` (same section): bounded parse, unset/empty/over-long ⇒ not-configured "so a transient store failure can never silently switch keys", plus a once-per-boot WARN announcing reduced guarantees. The shape to copy if the allow-root defaults to unconfined-but-announced.
- **Arch's two registered, grounded departures from the categorical confinement rule.** The `~/Downloads` training-export sink is recorded as "the ONE deliberate exception to the under-data-dir path-confinement rule", validated by `..`-rejection + parent-must-exist + egress scrub (§Occupied Resources → Filesystem locations); `ANDROMEDA_PULSE_MSEDGEDRIVER_PATH` is recorded as "deliberately NOT canonicalize-and-confined … because the driver lives outside the data dir by design", cross-referencing the security-plan carve-out (§Occupied Resources → Environment variables). Both state the ground *at the resource entry* — the template for the scope's outcome 3.
- **Arch's own canonicalize-and-confine + bounded-read instance.** `run/workspace-key` is registered as published "via atomic `.tmp`+rename with a canonicalize-and-confine guard", read cross-process, "bounded ≤ `MAX_WORKSPACE_KEY_BYTES` (4096) on read, consumed as an opaque filter string and never joined as a path" (§Occupied Resources → Filesystem locations) — arch's registered form of both halves this chunk needs.
- **Keep the change inside the concrete impl, not the trait.** §Established Decisions [LLM Inference Runtime] makes `LlmInferenceRunner` (`crates/interpretation/src/contract.rs`) the swap boundary across three documented sibling runtimes — "only the concrete impl changes". A guard inside `LlamaCliInference` leaves the deterministic runner and the second consumer `investigate.run_action` (§Occupied Resources → Tauri IPC routes) untouched.

## Anti-patterns to avoid
- **No Tauri core-API surface to source or pick the root.** fs / shell / dialog / http are not granted to `pulse:default` and "ARE silently rejected when missing" (§Cross-cutting Patterns → Webview IPC capability policy); chunk #95 deliberately shipped its egress path with "No native file picker (no `tauri-plugin-dialog`) — preserves the `pulse:default` capability surface" (§Occupied Resources → Filesystem locations).
- **No new crate, no new TauRPC procedure, no new `pulse://stream/*` topic for the guard.** Reserved crate names cannot be re-purposed (§Occupied Resources → Cargo workspace crate names; §Project Intent), and a new procedure costs a router registration + an §Occupied Resources entry + its `EXPECTED_PROCEDURES` pin (§Cross-cutting Patterns → Webview IPC capability policy).
- **No hard startup failure and no pin bump to obtain a flag.** Arch's registered precedent for a misconfigured path/gate var is `ANDROMEDA_PULSE_MCP_ENABLED`, which warns and proceeds "rather than failing to start" (§Occupied Resources → Environment variables); the b9305 pin discipline is stated in §Established Decisions [LLM Inference Runtime].

## Contract bindings
- **arch ↔ security** — arch's `ANDROMEDA_PULSE_MODEL_PATH` entry explicitly defers the confinement posture to security-plan §Security Anti-Patterns → Input and names it as carrying the exception's owner. The narrower ground must end the chunk stated at BOTH sites (arch's registry entries + the security artifacts) or they re-diverge.
- **arch ↔ obs** — arch records the mechanism by which a guard's evidence can be silently lost: "Each target carries its OWN exact obs allowlist leaf — a bare `metric` key exists carrying only `value`/`unit`/`module`, so a leaf-less `metric.*` target keeps `value` and has every label silently redacted" (§Occupied Resources → Tauri IPC routes, `telemetry.frontend.*` entry). A new field on the scope's `interpretation.model.load` observable needs its leaf, or the rejection is the dead-guard class again. Leaf ownership is obs-plan's; target registration is arch's if the target is new.
- **arch ↔ tests** — the sanctioned 15-stage GUI harness runs "under the deterministic-L4 gate the driver sets into the spawned app's environment" (§Stack → GUI verification harness row; §Occupied Resources → `ANDROMEDA_PULSE_L4_DETERMINISTIC`), and the deterministic runner is a *different* impl behind the same trait — so that leg would not exercise a guard living in `LlamaCliInference`. Whether any existing harness leg reaches this code is research's question.
- **arch ↔ arch (deferred)** — the binary/model *distribution* decision stays arch's open caveat; this chunk guards a supplied path without resolving its origin.

## Acceptance criteria contributions
- (arch) The guard and the bound land inside the `pulse-app` binary crate with no new workspace crate and no library crate taking a dependency on `pulse-app` (per architecture.md §Occupied Resources → Cargo workspace crate names + §Cross-cutting Patterns → Module dependency direction).
- (arch) The spawned invocation still carries `-n {max_tokens}`, `-st`, `--json-schema-file`, the outer wall-clock `tokio::time::timeout` and `kill_on_drop(true)`, against an unbumped `b9305` pin (per architecture.md §Established Decisions [LLM Inference Runtime]).
- (arch) Any new env var is `ANDROMEDA_PULSE_`-prefixed, parses bounded with fallback to its default on unset/empty/unparseable and never panics or blocks boot, and gains an §Occupied Resources → Environment variables entry at wrap; the three existing path vars' entries are amended to the posture that actually lands (per architecture.md §Occupied Resources → Environment variables + §Cross-cutting Patterns → Config management).
- (arch) The rejection is reachable through the existing `ModelStatus` / `model.current_profile` / `pulse://stream/model-status` surfaces — no new TauRPC procedure, no new `pulse://stream/*` topic, no `pulse-app/capabilities/` edit (per architecture.md §Cross-cutting Patterns → Webview IPC capability policy + §Occupied Resources → Tauri IPC routes).
