## Anti-patterns to avoid
- NEVER monkey-patch production code at runtime — `std::env::set_var` mid-test without cleanup is named explicitly; use constructor injection / `#[fixture]` config (per test-plan §11 Mocking). Directly binds here: the guard is an env-var read.
- NEVER test private crate internals — assert public module boundaries; for pulse-app that means `pub` + `#[doc(hidden)]` surfaces, and NEVER `unwrap()` without an `expect("reason")` (per test-plan §11 Unit).
- NEVER let a one-time live observation stand in for a per-run gate — §1 mints a pending trigger every time this happens (`viz-read-connection-router-wiring-coverage`, `cue-latch-emitter-wiring-coverage`, `webview-drive-mutation-arm-not-gated`) rather than treating the observation as coverage (per test-plan §1 Pending coverage triggers).
