- All input fields within the form MUST use `--color-inset` (#0F1117) background, 1px border `rgba(74, 144, 226, 0.3)` at rest, transitioning to 1px `#4A90E2` + `box-shadow: 0 0 0 3px rgba(74, 144, 226, 0.2)` on focus; error state uses `rgba(199, 85, 106, 0.5)` border (per §Surface: desktop-webview Component Patterns Input Fields / Form Controls).

- Spacing within the modal form MUST use only tokens from the 4px-base scale: `--spacing-sm` (8px) for input padding, `--spacing-md` (16px) for card/section padding, `--spacing-lg` (24px) for major section separation (per §Spacing table).
- Toggle controls (MCP-enable, theme-mode) MUST use `--radius-full` (9999px) for the toggle pill/thumb; number inputs and select dropdowns use `--radius-sm` (4px); the modal container itself uses `--radius-lg` (8px) inherited from chunk #37 primitive (per §Border Radius).
- Motion for form state transitions (toggle on/off state, dropdown opening, focus ring appearance) MUST not exceed `--duration-fast` 150ms ease-out; no scroll animations, no staggered reveals, no spring physics within the form (per §Motion Hard Limits, expression level 0.35 webview, and §Motion Duration scale table).
- Button layout within the form (Save / Cancel) MUST follow: primary action = `--color-primary` (#4A90E2) background, `--color-base` (#1A1D24) text, `--radius-sm` (4px), `--spacing-sm` padding; secondary/cancel = `--color-raised-1` (#262A33) background, `--color-text-primary` text, 1px border `rgba(74, 144, 226, 0.3)` (per §Surface: desktop-webview Component Patterns Buttons).

## Patterns to follow

- **Modal-content composition:** Chunk #37 Modal primitive provides the `--color-raised-3` card surface + close button + focus-trap scaffold; chunk #38 fills that card with form controls. The form-in-modal pattern belongs to the category "a form (settings) ≠ a data table (traces)" — intentionally differentiated content type, not a generic card-grid (per §Anti-Patterns Universal Bans "NEVER use the same layout for different information types").
- **Input Field / Form Controls pattern:** All text inputs, number inputs, and select dropdowns follow the established §Surface: desktop-webview Component Patterns "Input Fields / Form Controls" definition (inset background, subtle border, focus emphasis border + glow, error border, placeholder muted italic).
- **Focus/keyboard navigation pattern:** Focus ring is 3–4px outset `#4A90E2`, `:focus-visible` always shown, all form controls Tab-navigable — this is the universal webview Focus/Keyboard Navigation rule (per §Surface: desktop-webview Focus / Keyboard Navigation + §Downstream Readiness a11y specialist handoff).
- **Semantic color + label pairing:** Toggle "MCP enabled" state MUST pair the Earth Blue active-state color with a visible "On"/"Off" text label (not color alone) per §Color Palette anti-pattern note on SC 1.4.1 discipline. Snapshot budget / format preset fields that use `--color-accent` for error/validation indicators MUST pair with text copy (per §Design Decisions Log 2026-05-03 usage scope refinement — accent is non-text; error message text uses `--color-text-primary`).
- **Aperture icon for settings trigger:** The aperture SVG glyph (`<Icon glyph="aperture" />`) is the canonical icon for "view settings" and SHOULD appear in the modal header or the titlebar settings button that opens this form (per §Iconography Primary custom set).

## Anti-patterns to avoid

- NEVER use hardcoded hex values or magic pixel values — every color, spacing, radius, and duration value must trace back to a named CSS custom property from the `@theme` block (per §Self-Validation Protocol Token Test + §Anti-Patterns Universal Bans NASA palette is source of truth).
- NEVER apply gradient overlays, glassmorphic effects, or shadow-based elevation to the modal or any form control within it — modal elevation is achieved by `--color-raised-3` background + border only; box-shadow is permitted exclusively for focus rings (per §Depth Strategy + §Anti-Patterns Universal Bans "gradient overlays or glassmorphic effects" ban).
- NEVER use color as the sole state indicator for toggle/select controls — active states (MCP toggle on, theme-selected option, preset selected) MUST pair color change with a text label or icon change to satisfy SC 1.4.1 (per §Design Decisions Log 2026-05-03 usage scope refinement and §Anti-Patterns Universal Bans "color purely for decoration" ban).

## Contract bindings

- **Design tokens ↔ a11y (SC 1.4.3 / SC 1.4.11):** `--color-text-primary` (#E8EEF7) on `--color-raised-3` (#343A45) must maintain ≥4.5:1 for normal-size label text; `--color-accent` (#C7556A) used as non-text border/icon in error states targets ≥3:1 (non-text, SC 1.4.11). a11y specialist owns formal WCAG derivation; design provides target ratios per §Self-Validation Protocol Contrast Test + §Design Decisions Log 2026-05-03 (accent reclassified as non-text at 3.8:1).
- **Motion tokens ↔ a11y (SC 2.3.3):** All form transitions at `--duration-fast` 150ms / `--duration-standard` 200ms MUST degrade to 0ms when `prefers-reduced-motion: reduce` is active; toggle animations become instant; no animation exceptions within chrome (per §Motion Accessibility — Halo State Pulse is the only exempt motion, not applicable to form controls).
- **State color + label pairing ↔ a11y (SC 1.4.1):** Toggle and selection controls using `--color-primary` (active) or `--color-accent` (error) MUST always have an accompanying text or aria-label to avoid color-only state conveyance. a11y specialist enforces ARIA; design enforces the pairing at the token + component pattern level (per §Anti-Patterns "color purely for decoration" ban + §Downstream Readiness a11y handoff).

## Acceptance criteria contributions

- (design) All form control colors, spacing, and border-radius values in the Settings modal trace back to named CSS custom properties from the `@theme` block — no hardcoded hex or magic pixel values present in the component source.
- (design) Toggle controls (MCP-enable, theme-mode) pair their `--color-primary` active-state color with a visible "On"/"Off" (or equivalent) text label — state is never communicated by color alone.
