- Every form control MUST have a programmatically associated label — `<label htmlFor="…">` is preferred; `aria-labelledby` or `aria-label` only where a visible label is not feasible; `aria-describedby` links error messages to their inputs (per a11y-plan §7 Form labels; WCAG SC 3.3.2, SC 4.1.2).
- Theme and widget-position pickers MUST be `radiogroup` + `radio` (or React Aria `RadioGroup`); MCP toggle MUST be `role="switch"` with `aria-checked`; snapshot-preset + budget MUST use `combobox`/`select` or `radiogroup`; retention MUST be `<input type="number">` with `min`/`max` + `aria-label` (per a11y-plan §4 Per-component pattern catalog; WCAG SC 4.1.2).
- Form validation errors MUST set `aria-invalid="true"` on the offending input and announce via `aria-describedby`-linked error `<span>`; save-success status MUST use `aria-live="polite"` (non-blocking); validation error MUST use `role="alert"` or `aria-live="assertive"` (per a11y-plan §7 Live regions; WCAG SC 3.3.1, SC 4.1.3).
- Focus order MUST follow visual top-to-bottom DOM sequence: theme radio group → widget-position radio group → retention input → MCP switch → snapshot-preset → budget → format → plugin-manager list → Save button → Cancel button; Tab on Cancel MUST wrap to theme (focus-trap-react `returnFocusOnDeactivate: true`; per a11y-plan §5 settings-modal focus order; WCAG SC 2.4.3).
- All interactive elements (radio, switch, number input, combobox, buttons) MUST render the `--border-focus` token on `:focus-visible`; the focus ring MUST meet ≥ 3:1 non-text contrast against the modal background (per a11y-plan §6 Focus ring tokens; WCAG SC 2.4.7, SC 1.4.11).
- Any entry/exit transition on the modal (open/close scale or opacity) MUST degrade to `transition-duration: 0s` under `prefers-reduced-motion: reduce` via Tailwind `motion-reduce:` variants; state change MUST remain conveyed by color + text + focus indicator, not motion alone (per a11y-plan §6 Motion tokens; WCAG AAA SC 2.3.3).

## Anti-patterns to avoid

- **`outline: none` without a replacement focus indicator**: removing the default outline on any form control (radio, switch, input, button) without substituting the `--border-focus` token violates SC 2.4.7 and breaks keyboard-only navigation entirely (a11y-plan §11 Anti-patterns).
- **Conveying form field state by color alone**: error and success state colors (`--color-accent`, `--color-feedback-success`) MUST be supplemented with an icon or text label — never a color-only border change — to satisfy SC 1.4.1 (a11y-plan §6 State color tokens not-color-alone).
- **Adding `role="dialog"` on a `<div>` without `aria-modal` + trapped focus**: duplicating a modal wrapper outside the chunk #37 primitive risks an accessible-name-less dialog that does not constrain AT virtual cursor; always compose inside the Modal primitive (a11y-plan §4 Dialog pattern).
