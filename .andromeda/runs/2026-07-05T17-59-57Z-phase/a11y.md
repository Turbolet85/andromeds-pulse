# a11y extract

## Relevance
Relevant — fully in-domain: a color-encoded, motion-bearing, labeled UI surface (the constellation canvas) touching SC 1.4.1 / 1.4.11 / 1.4.3 / 2.3.3 / 4.1.2 head-on.

## Constraints
- **Not-color-alone health cue (SC 1.4.1).** Dot severity/health must not be carried by hue alone — pair color with a text label / shape / icon / severity token. axe-core does NOT detect this; a custom Playwright DOM-inspect assertion is mandatory. Per a11y-plan §6 (State color tokens) + §11 (Visual) + §1 (visual-discrimination trigger).
- **Canvas has no built-in a11y.** Per-dot identity + semantics must come from DOM/wrapper element semantics, not the `<canvas>` bitmap; canvas-drawn text is invisible to axe-core and screen readers. The canvas wrapper carries a `region` landmark with an accessible label; dot service names must be programmatically determinable via DOM/ARIA. Per a11y-plan §1 (WebGPU canvas entity: "no built-in accessibility; relies on wrapper element semantics") + §7 (Landmark roles) + §1 SR test step 9.
- **Reduced-motion override for Halo (SC 2.3.3 AAA).** Halo animation must degrade under `prefers-reduced-motion: reduce` (scope → static glow, hue still updates); a vanilla canvas render loop must itself check `matchMedia('(prefers-reduced-motion: reduce)')` / `useReducedMotion`, not rely on Tailwind variants alone; state must remain conveyed via color+label, never motion alone. Per a11y-plan §6 (Motion tokens) + §11 (Motion) + §1 (motion-sensitive trigger).
- **Contrast (SC 1.4.3 text / SC 1.4.11 non-text).** Label text meets 4.5:1 (`--color-text-primary / --color-base`); the dot severity color / graphical object meets ≥3:1 non-text against its background. Verified via axe-core color-contrast + colorjs.io token checker reading tokens verbatim. Per a11y-plan §6 (Color contrast pairs) + §1 (Contrast Verification Harness).
- **Universal minimums on P1–P12.** SC 2.1.1 Keyboard, SC 2.4.3 Focus Order, SC 4.1.2 Name/Role/Value apply to this must-be-accessible surface; if dots become focus/hover-interactive, each needs an accessible name (service name) + role/value + keyboard reach. Zero WCAG AA violations, zero new violation tuples per PR. Per a11y-plan §10 (SLO) + §1 (surface-extension note, p11 constellation).
- **Semantic HTML first, ARIA second.** Any DOM label overlay uses semantic elements; no redundant/conflicting ARIA; never `aria-hidden` essential dot content. Per a11y-plan §2 (canonical principle) + §11 (ARIA).

## Patterns to follow
- **Extend the existing p11 constellation-semantics axe spec in THIS chunk** (added at chunk #99, v0.2.0). Standing rule: a surface that gains semantics adds/updates its axe spec in-chunk; fixtures live in `helpers/v02-fixtures.ts` (service payload); mock TauRPC via the `TauRPC__<router.path>` command shape; check suite health with `npx playwright test --list`. Per a11y-plan §3 (Harness wiring) + §1 surface-extension note.
- **Canvas wrapper region-landmark pattern:** `<region aria-label=...>` supplies the context the `<canvas>` lacks; SR test asserts the region is announced with a semantic label (not bare `<canvas>`). Per a11y-plan §7 (Landmark roles) + §1 SR step 9.
- **Not-color-alone verification pattern:** custom Playwright DOM assertion that each state color is accompanied by text/icon — reuse the chunk #99 remediation template (severity text → `text-primary` + severity-colored borders). Per a11y-plan §6 (State color tokens) + §11.
- **Reduced-motion assertion pattern:** `page.emulateMedia({ reducedMotion: 'reduce' })` → assert Halo animation-duration → 0s / disabled while state still conveyed via color+label; wire `useReducedMotion` from `motion/react` into the frame loop. Per a11y-plan §6 (Motion tokens) + §3 (motion-tokens-respect-install).
- **Token-verbatim contrast checker:** colorjs.io reads design tokens via `getComputedStyle`; never invent tokens. Per a11y-plan §6 + §3 (Contrast harness).

## Anti-patterns to avoid
- **NEVER convey health/severity by color alone** — hue-only dots are the exact SC 1.4.1 gap this chunk closes (a11y-plan §11 Visual).
- **NEVER run the Halo canvas loop without respecting `prefers-reduced-motion`**, and never let motion be the ONLY state signal — vanilla canvas loops require a manual `matchMedia` check (a11y-plan §11 Motion).
- **NEVER put identity/labels that must be assertable/SR-reachable only on the canvas bitmap**, and never `aria-hidden` essential dot content (a11y-plan §11 Screen Reader + §7).

## Contract bindings
- **a11y ↔ design:** dot severity color scale + Halo State Pulse mapping + contrast pairs + reduced-motion override are owned by `design-system.md`; SC 1.4.11 (dot non-text) / SC 1.4.3 (label text) / SC 1.4.1 (not-color-alone) bind to design §Color Palette + §Motion (a11y-plan §6; scope §Design tokens).
- **a11y ↔ tests/CI:** the p11 constellation axe spec + reduced-motion spec run inside the same `ci.yml` a11y gate (`npm run test:a11y` / `cargo xtask test:a11y`), compared against `baselines/a11y-violations-summary.json` (a11y-plan §3 + §9 + §10).
- **a11y ↔ obs:** any contrast / 1.4.1 violation emits structured violation JSON (`wcag_criterion` / `violation_type` / `severity` / `surface` / `selector`) per obs §6 (a11y-plan §3).
- **a11y ↔ data:** whichever `ServiceListItem` field drives dot color (`state` vs `priority_tier` vs incident-derived severity) must also drive the non-color cue — field choice is a data/design decision, the not-color-alone pairing is the a11y binding (scope §Data source; a11y-plan §6 State color tokens).

## Acceptance criteria contributions
- (a11y) Not-color-alone: a custom Playwright DOM assertion confirms each dot's health/severity is accompanied by a text label / shape / icon / severity token, not hue alone (SC 1.4.1); axe-core alone is insufficient. (a11y-plan §6 / §11)
- (a11y) Reduced-motion: under `prefers-reduced-motion: reduce`, Halo degrades to static glow (animation-duration → 0s) while hue still updates per severity; state conveyed without motion (SC 2.3.3 AAA). (a11y-plan §6 / §11)
- (a11y) Contrast: dot severity color meets SC 1.4.11 non-text 3:1 vs background and any label text meets SC 1.4.3 4.5:1 (`--color-text-primary / --color-base`), via axe-core + colorjs.io. (a11y-plan §6)
- (a11y) The p11 constellation axe spec is extended in-chunk with per-dot name/health semantics; `npm run test:a11y` passes with zero new violation tuples vs baseline; each dot's service name is programmatically determinable via DOM/ARIA, not canvas-only (SC 4.1.2). (a11y-plan §3 / §10)
