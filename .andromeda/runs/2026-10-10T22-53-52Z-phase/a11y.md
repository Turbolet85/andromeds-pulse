# a11y extract

## Relevance
partial — the door, its socket, its tools and its call records are non-UI and outside the a11y scope (a11y-plan §1 A11y scope table classes the IPC bridge, the receivers and the storage as Not-assertable); the one tie is the sidecar's footprint in the window: the MCP toggle of the settings modal, which scope.md lists under "the window's settings that enable it" for disposition (removed here, or by a named later entry).

## Constraints
- a11y-plan §1 A11y scope table requires no a11y assertion on a backend or IPC surface: the door itself adds no assertable entity, and no WCAG criterion is triggered by the door, its tools or its log records.
- a11y-plan §1 Critical paths row P3 requires the settings modal's MCP toggle to be a `switch[aria-checked]` reached by Tab and toggled by Space, focus staying on it, with an OS notification on state change. If this chunk removes or changes that toggle, P3's required roles and focus rule no longer describe the surface; whether the settings modal ships that switch today, and whether this chunk or a later entry removes it, is research's question and the plan's disposition.
- a11y-plan §1 Critical paths row P7 requires a fixed settings-modal Tab sequence that names the MCP toggle switch between the retention input and the snapshot preset. A chunk that removes the toggle must leave the remaining sequence in visual top-to-bottom order with no gap or orphaned label (SC 2.4.3, SC 3.3.2, SC 4.1.2).
- a11y-plan §5 Keyboard Navigation (settings-modal) requires the same focus order, Esc closing the modal and focus returning to the "Settings" button; a control removed from the form must not break the trap's wrap or the restoration (SC 2.1.2).
- a11y-plan §10 SLO Invariants requires zero WCAG AA violations on must-be-accessible paths and zero new violation tuples per PR against the baseline committed in the tree; any webview edit this chunk makes is held to it, with no retry.
- a11y-plan §3 Harness wiring & conventions (Adding a surface) requires one axe spec per new route or modal in the same chunk. The scope names no new route or modal; if the P4 dialog adds a window-side reader of the door, the standing rule applies to it.
- a11y-plan §3 Harness wiring & conventions (Mock layer) requires every TauRPC procedure a fixture consumes to be mocked through the `TauRPC__` command shape. Whether the a11y helpers or fixtures mock the sidecar's `mcp.*` procedures, and so must change when those procedures leave, is research's question.

## Patterns to follow
- Switch pattern per a11y-plan §4 ARIA Patterns & Roles (Switch row): if the toggle stays in any form at this chunk, it keeps `aria-checked`, Space toggles, focus remains on the switch.
- Focus-order ground truth per a11y-plan §3 Focus management test harness: the expected Tab sequence is computed by `tabbable(container)` and compared with the actual sequence, so a removed control is reflected by the computation, not by a hand-edited list; whether the settings-modal spec also names the MCP switch literally is research's question.
- Suite health check per a11y-plan §3 Harness wiring & conventions (Adding a surface): after a fixture, mock or spec is removed, list the suite with the a11y config named; the bare list command reads the inert default config and proves nothing.
- Regression baseline per a11y-plan §3 Harness wiring & conventions (Regression baseline): the baseline is the file committed in the tree; a clean pass holds zero violation tuples, and an absent baseline is an error.

## Anti-patterns to avoid
- a11y-plan §11 A11y Anti-Patterns → Screen Reader bans a form input without an associated label and hiding essential content from assistive tech: a toggle removed from the form takes its label and its `aria-describedby` hint with it; a toggle left as dead UI is not hidden with `aria-hidden` while still focusable (a11y-plan §11 → ARIA, conflicting states).
- a11y-plan §11 A11y Anti-Patterns → CI bans deferring a11y to post-merge and skipping a11y on CI failure: a settings-modal change made here is gated here, not left for the entry that retires the window.
- a11y-plan §11 A11y Anti-Patterns → SLO bans a retry-once policy and a soft gate: a spec that reads red after the sidecar's window footprint leaves is fixed or re-pointed, never retried or skipped without the quarantine the section names.

## Contract bindings
- a11y ↔ tests/CI: the `a11y` job of `ci.yml` (`cargo xtask test:a11y`, artifacts `a11y-violations-Linux` and `playwright-a11y-report-Linux`) is the gate any webview edit of this chunk passes, per a11y-plan §9 CI Integration and a11y-plan §3 CI integration.
- a11y ↔ architecture/security (the sidecar's double gate and its `mcp.*` TauRPC procedures): the a11y mock layer mirrors the TauRPC procedure set per a11y-plan §3 Harness wiring & conventions (Mock layer); a removal of those procedures in this chunk reaches the a11y helpers only if they mock them (research's question).
- a11y ↔ layouts (settings-modal focus sequence): a11y-plan §5 Keyboard Navigation names the MCP toggle in the settings-modal order; the layout and the a11y plan change together.
- a11y ↔ spec masters: a11y-plan §1 (Settings modal form entity; Critical paths rows P3 and P7) and a11y-plan §5 name the MCP toggle and the sidecar identity. The masters are read-only at phase; if this chunk removes the toggle, those statements are the wrap's to amend, and if a later entry removes it the plan names that entry.

## Acceptance criteria contributions
- (a11y) The plan states the disposition of the settings modal's MCP toggle: removed in this chunk, or left to a named later entry with the reason it cannot go now (per a11y-plan §1 Critical paths rows P3 and P7).
- (a11y) If the chunk edits the settings modal or any a11y helper, fixture or spec: `cargo xtask test:a11y` passes, and its regression leg finds no violation tuple the committed baseline lacks (per a11y-plan §10 SLO Invariants; a11y-plan §3 CI integration).
- (a11y) If the toggle is removed: the settings-modal focus-order assertion passes on the remaining controls, Esc closes the modal and focus returns to the "Settings" button (per a11y-plan §5 Keyboard Navigation).
- (a11y) If any a11y helper, fixture or spec is removed or edited: the config-named Playwright list prints a non-zero test count, exit 0 (per a11y-plan §3 Harness wiring & conventions).
