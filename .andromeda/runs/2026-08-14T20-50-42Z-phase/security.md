## Patterns to follow
- Scrubber-at-the-boundary shape: `scrub_attribute()` returning `ScrubbedValue::Allowed(_) | ::Redacted` before persistence/log emission, as the plan records it at `crates/buffer/src/appender.rs` and `StormStateSnapshot::scrubbed_clone` (per security-plan §Security Anti-Patterns § Logging).
- Redaction applied at the `tracing-subscriber` layer rather than at individual log call sites, with structured JSON fields (per security-plan §Logging & Monitoring Log format).
- `#[tracing::instrument(skip(...))]` discipline at call sites handling sensitive payloads, the pattern the plan mandates for the corpus key (per security-plan §Secret Management "What counts as secret").
- Internal error logging carries full detail with stack-local context only (span id / request id at the ingest boundary); boundary-facing errors collapse to sanitized `AppError` variants with no stack traces, file paths, or Rust struct names (per security-plan §Error Handling).
- Bounded env-var registration playbook: code-validated bounded parse + unit test, then routine addition to the §Input Validation boundary table (per security-plan §Input Validation CLI/env var inputs row).

## Anti-patterns to avoid
- NEVER log raw OTLP attribute values, span-event content, or snapshot/clipboard payloads from the new boundary instrumentation (per security-plan §Security Anti-Patterns § Logging).
- NEVER skip or relax post-`prost` invariant checks in `ingest` as a means of unblocking the feed (per security-plan §Security Anti-Patterns § Input).
- NEVER instrument the product's own telemetry through its own OTLP ports or via a network exporter (per security-plan §Security Anti-Patterns § API).
