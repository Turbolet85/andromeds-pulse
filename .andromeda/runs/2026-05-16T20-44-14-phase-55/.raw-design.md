## Patterns к follow

- Semantic-state naming convention (the `Listening` / `Receiving` / `Idle` / `Stalled` / `ReceiverFailed` enum) mirrors the existing Semantic Colors taxonomy pattern (Success / Warning / Error / Info) — state names describe MEANING not appearance, which is the design-system pattern for stable token-mapping (per design-system.md §Color Palette Semantic Colors).
- Orthogonal-health-domain pattern (connection state ≠ ingestion throughput ≠ error rate) follows the same separation-of-concerns discipline the Halo State Pulse uses (rhythm dimension separate from hue dimension separate from blur dimension) — one signal per visual axis (per design-system.md §Brand Identity "Signature element" multi-dimensional encoding).

## Anti-patterns к avoid

- NEVER encode color choices into the backend state enum variants (e.g., `ConnectionState::Red` / `ConnectionState::Yellow`) — variants must be semantic (`ReceiverFailed` / `Stalled`); color mapping is a webview-layer concern that consumes the semantic state. Binding visual presentation into a Rust enum violates §Anti-Patterns Universal Bans "NEVER use color purely for decoration. Every color in the palette communicates meaning" — meaning lives in the semantic name, color is mapped к meaning at the rendering boundary.
- When the future UI surfaces these states, NEVER use uniform monochrome status icons (green checkmark / red X) for the 5-state distinction — Mission Control discipline requires state encoding via hue + icon-or-text-label pairing, never icon-shape-alone or color-alone (per design-system.md §Anti-Patterns Rejected Defaults "Uniform monochrome status icons").
- Backend identifiers (state strings emitted on `pulse://stream/connection-state` payloads) MUST NOT carry presentation hints (no `displayColor` / `iconGlyph` fields in the event payload) — keep the backend payload behavior-only; visual mapping lives in webview token system (per design-system.md §Brand Identity "motion is data-driven and never decorative" — by extension, state names are behavior-driven, not decoration-driven).
