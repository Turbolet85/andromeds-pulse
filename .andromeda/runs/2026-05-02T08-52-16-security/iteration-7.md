## Threat Model Summary

_[ALL tiers — VERBATIM copy from threat-assessment.md]_

**Security tier:** `Minimal (0)`

_Justification: This is a local-first, zero-infrastructure single-user desktop app (Design Philosophy + Project Intent) with no user accounts, no persistent user data store (in-memory DuckDB ring buffer with 5–10 min retention), no internet-exposed network surface (OTLP receivers bound to `127.0.0.1` only per Occupied Resources), and no compliance-regulated data classifications. Standard tier is not warranted because there is no public API, no user authentication surface, and no multi-tenant data; Hardened tier is not warranted because no payment, health, or compliance-regulated data is present._

**Data classification:**

- **Type:** user-content (telemetry payloads — traces, metrics, logs)
  - **Where:** OTLP receivers (`ingest` crate on `:4317`/`:4318`), DuckDB in-memory ring buffer (`buffer` crate, schema `pulse_buffer.main`, tables `spans`, `span_events`, `span_links`, `metrics_points`, `log_records`, `resources`, `instrumentation_scopes`), broadcast fan-out to viz/MCP, and curated snapshot markdown files written to `~/.andromeda-pulse/snapshots/`.
  - **Volume:** transient (5–10 min in-memory ring buffer, configurable via `ANDROMEDA_PULSE_RETENTION_SECONDS`); aggregate within retention window (10k spans/sec target). Snapshots persist to disk under the per-platform data dir.
  - **Sensitivity note:** Telemetry can contain incidentally captured secrets, IDs, URLs, error messages, and SQL fragments from the host application being instrumented. OTLP attributes are user-controlled content.

- **Type:** config (user settings)
  - **Where:** `~/.andromeda-pulse/config.toml`, env vars `ANDROMEDA_PULSE_*`. Surface is small: enum settings, port ranges, file paths, retention seconds, log level, MCP enabled flag, plugin dir.
  - **Volume:** per-user (single-user local app).

- **Type:** config (signing/release credentials — out of app runtime)
  - **Where:** GitHub Actions encrypted secrets and Azure Key Vault. Apple Developer ID for notarization. Updater public key is baked into the Tauri config.
  - **Volume:** N/A at runtime (build/release pipeline only); the binary ships only the public verification key.

- **Type:** user-content (third-party WASM plugin binaries)
  - **Where:** `~/.andromeda-pulse/plugins/` loaded by `wasmtime` Component Model host (`plugins` crate). Capability-scoped per WIT imports. Signed-plugin verification deferred post-v1.
  - **Volume:** per-user; arbitrary number.

- **Type:** none — credentials / PII / payment / health
  - **Where:** N/A. No user accounts, no payment SDK, no identity provider, no health-domain framing.

**Attack surface:**

- **Vector:** public API (network-bound on loopback only)
  - **Entry point:** OTLP/gRPC on `:4317` and OTLP/HTTP on `:4318`, both bound `127.0.0.1` only. Routes `POST /v1/traces`, `POST /v1/metrics`, `POST /v1/logs`. Wire formats: protobuf via `prost`/`tonic` decode, plus HTTP/JSON.
  - **Trust boundary:** `prost`/`tonic` protobuf decode validates wire shape. Loopback-only binding means any local process (including unprivileged user processes, container sidecars, browser tabs via DNS rebinding considerations) can post telemetry. No auth declared at this surface.

- **Vector:** IPC (Tauri TauRPC bridge — webview ↔ Rust)
  - **Entry point:** Procedures: top-level `app_info`, `health`, `ready`, `get_settings`, `update_settings`; routers `traces.*`, `metrics.*`, `logs.*`, `snapshot.{generate,list_recent,copy_to_clipboard}`, `plugins.{list,reload,invoke}`, `mcp.{status,start,stop}` (feature-gated), `workspace.{detect,list}`. Real-time push events `pulse://stream/*` via Tauri IPC `Channel` API with binary Arrow IPC payloads.
  - **Trust boundary:** Tauri 2 capability gating — `pulse:default` permits exactly the enumerated procedures. Errors crossing the bridge are forced to `Serialize`-able `AppError` enum variants. Validation surface relies on `serde` deserialization plus `TryFrom<u16>` for ports/enums.

- **Vector:** plugin host (WASM Component Model)
  - **Entry point:** `~/.andromeda-pulse/plugins/` filesystem load by `wasmtime` 25+ via `plugins` crate; `plugins.invoke` IPC dispatches into a guest. Capability `pulse:plugin-fs` gates host's read of the plugin dir.
  - **Trust boundary:** Capability-scoped sandboxing — guests receive only host imports declared in their WIT. No syscalls, file, or socket access unless explicitly granted in WIT. Signed-plugin verification deferred post-v1.

- **Vector:** MCP stdio surface (feature-gated)
  - **Entry point:** `andromeda-pulse-mcp` rmcp sidecar. JSON-RPC 2.0 over stdin/stdout: `initialize`, `tools/list`, `tools/call`, `notifications/*`. Tools: `query_traces`, `query_metrics`, `query_logs`, `generate_snapshot`. Only present when `--features mcp-server` AND `ANDROMEDA_PULSE_MCP_ENABLED=true`.
  - **Trust boundary:** Stdio caller is whatever process the user launched the sidecar from (typically an LLM client). No network exposure. JSON-RPC framing per MCP spec.

- **Vector:** filesystem reads (config + workspace detection)
  - **Entry point:** `config.toml` under per-platform data dir; env-var-overridable paths (`ANDROMEDA_PULSE_CONFIG_PATH`, `ANDROMEDA_PULSE_DATA_DIR`, `ANDROMEDA_PULSE_PLUGIN_DIR`); workspace-detector crate inspects host project context (`workspace.detect`, `workspace.list`).
  - **Trust boundary:** No declared validation in arch beyond `serde` + smart enum types + `TryFrom<u16>`. Path validation discipline not declared.

- **Vector:** in-app updater
  - **Entry point:** `tauri-plugin-updater` 2.x consuming `latest.json` from GitHub Releases.
  - **Trust boundary:** Updater public key baked into Tauri config; updater capability `pulse:updater` is bound to the plugin flow and "is not exposed to webview JavaScript."

- **Vector:** OS notification / tray surfaces
  - **Entry point:** `tauri-plugin-notification` (capability `pulse:notification`); tray icon (capability `pulse:tray`). Outbound user-facing only.
  - **Trust boundary:** Outbound surfaces; not an input vector. Capability-gated.

- **Vector:** CLI input (env vars + binary launch)
  - **Entry point:** Reserved env vars `ANDROMEDA_PULSE_*`, `RUST_LOG`.
  - **Trust boundary:** `serde` + `TryFrom<u16>` for ports; an MCP feature-flag env-var mismatch logs a warning rather than failing. Path env vars have no declared canonicalization.

- **Vector:** webview content (host-side)
  - **Entry point:** WebView2 (Windows) / WKWebView (macOS/Linux). WebGPU canvas rendered from Arrow data. Webview source under `pulse-app/ui/`.
  - **Trust boundary:** Tauri capability model (`pulse:default`) gates IPC procedures; no `fs`, `shell`, `dialog`, `http` core APIs granted. WGSL shaders are first-party.

- **Vector:** none — public internet API, OAuth flow, webhook, file upload from internet
  - All N/A. Local-only desktop app; no inbound internet exposure.

**Auth model:**
- **Approach:** none
- **Provider:** N/A
- **Scope:** N/A — Tauri capability-based authorization (`pulse:default`) is the trust model; the OS user owns the app. Loopback-only OTLP binding is the de facto authorization boundary.

**Infrastructure:**
- **Hosting:** local-only — public OSS desktop app distributed via GitHub Releases; runs as a single Tauri process on the user's Windows/macOS/Linux machine.
- **Database:** embedded — DuckDB 1.5.x via `duckdb` crate, in-memory `:memory:` connection (`pulse_buffer`), no persistent disk database.
- **Networking:** local only — OTLP receivers bound `127.0.0.1` only; MCP over stdio (no socket); updater is outbound HTTPS to GitHub Releases; no inbound internet exposure.
- **CI/CD:** GitHub Actions — `ci.yml` (fmt + clippy + xtask test + workspace build, matrix Linux/macOS/Windows); `release.yml` (`tauri-action` builds `.msi`/`.dmg`/`.AppImage`/`.deb`, signs Windows via Azure Key Vault EV, notarizes macOS via Apple Developer ID, uploads bundles + `latest.json` to GitHub Releases); `update-channels.yml` (Homebrew tap + Scoop manifest). Code-signing secrets live in GitHub Actions encrypted secrets and Azure Key Vault.

**Compliance triggers:**

None — no compliance-regulated data detected. No payment SDK → no PCI DSS. No user accounts / no PII collection by the app itself; telemetry stays on the local machine within v1 → no GDPR-as-controller posture. No health-domain framing → no HIPAA. No children's-product framing → no COPPA.

This tier is the SINGLE SOURCE OF TRUTH for how much security rigor downstream
skills (security-pass per phase + cross-cutting reads from design / tests /
obs / a11y) should apply.

## Data Protection

_[Minimal-tier-retained — the bullet `HTTPS enforced` + `no sensitive data stored` template hint does NOT apply: this section is load-bearing for the distribution channel (Tauri updater Minisign verification, Azure Key Vault HSM custody for Windows EV + Apple Developer ID + updater Minisign keypair, per-medium at-rest posture for ring buffer / snapshots / config / logs / plugins). DO NOT trim during right-sizing. A Standard-tier upgrade would add: backup encryption posture, log-chain tamper evidence, KMS rotation logs, full SBOM / sigstore intermediate-build signing.]_

**In transit:**
- **TLS:** N/A for inbound — OTLP receivers bind `127.0.0.1` only and do not terminate TLS. The `tonic` 0.14.x and `axum` 0.8.x servers run plaintext loopback.
- **TLS for outbound:** the only outbound network surface is the Tauri updater consuming `latest.json` from GitHub Releases — `tauri-plugin-updater` 2.x uses HTTPS with `rustls` defaults (TLS 1.2+ minimum); do not override certificate verification.
- **Updater integrity in transit:** `tauri-plugin-updater` Minisign Ed25519 signature verification is mandatory and cannot be disabled per security-research; this is the load-bearing in-transit integrity check, not the transport TLS.
- **HSTS / Certificate pinning:** N/A — no TLS server surface.

**At rest — per medium:**

For Minimal tier, the at-rest controls reduce to:

- **DuckDB ring buffer:** in-memory `:memory:` connection (`pulse_buffer`) with no persistent disk database per Established Decisions Telemetry Retention Surface; encryption is N/A and DuckDB encryption CVE-2025-64429 is not applicable. Ring buffer cutoff via periodic `DELETE FROM <table> WHERE ts < now() - INTERVAL '<retention> minutes'` (per Conventions Database entity naming).
- **Snapshot files (`~/.andromeda-pulse/snapshots/`):** persisted as plaintext markdown under the per-platform data dir; access control inherits OS user permissions. Snapshots can incidentally contain PII/secrets harvested from instrumented OTLP attributes — see §Logging & Monitoring snapshot/clipboard hygiene note and §Code Patterns anti-patterns.
- **Config (`~/.andromeda-pulse/config.toml`):** plaintext under user data dir; Established Decisions explicitly note this app does not store secrets in `config.toml`. No encryption.
- **Logs (`~/.andromeda-pulse/logs/`):** `opentelemetry-stdout`/file exporter destination per Cross-cutting Patterns Self-observation; redaction rules in §Logging & Monitoring apply.
- **Plugins (`~/.andromeda-pulse/plugins/`):** WASM bytes; integrity not signed in v1 per Established Decisions Plugin Distribution Channel. Documented as a residual risk in §Security Decisions Log.

**Data lifecycle:**

- **Telemetry retention:** 5–10 minute in-memory ring buffer per Established Decisions; configurable via `ANDROMEDA_PULSE_RETENTION_SECONDS`. No persistence.
- **Snapshot retention:** indefinite on disk; user-managed (no auto-purge declared in arch). Document in user-facing README that snapshots may contain incidentally captured secrets and live until the user deletes them.
- **No GDPR right-to-deletion process** because the app is not a data controller — the user owns and deletes their own data dir (`~/.andromeda-pulse/`).

**Code-signing key custody (Minimal-tier load-bearing detail):**

Per security-research §Azure Key Vault OIDC, code-signing private keys (Windows EV cert via Azure Key Vault HSM-RSA, Apple Developer ID for macOS notarization, Tauri updater Minisign Ed25519) MUST live exclusively in Azure Key Vault Premium SKU + GitHub OIDC federation; no long-lived service principal secret stored in GitHub Actions secrets. See §Secret Management for the full custody policy.

## Dependency Security

_[ALL tiers]_

**Audit tool:** `cargo-audit` 0.22.1 (Rust Secure Code WG) — checks `Cargo.lock` against the RustSec Advisory Database; non-zero exit makes it a clean CI gate. Catches "unmaintained crate" advisories the way other ecosystems don't, directly relevant to the ~30 transitive dep stack flagged in Established Decisions.

**Pinning:** `Cargo.lock` checked into the repository (standard for binary crates). Workspace pins per Stack table. Open reconciliation items from Established Decisions: (a) `tonic` 0.14 vs `opentelemetry-otlp` 0.31 (which still pins `tonic` 0.13) — must be resolved before tagging v0.1.0 per the Inherited Defaults open question; (b) `rmcp` "1.5.0" reference vs published 0.3.x line — reconcile per the same Inherited Defaults open question.

**Update policy:** Dependabot configured for both `cargo` and `github-actions` ecosystems; `.github/dependabot.yml` opens PRs against `main` for both; reviewer is the project maintainer.

**CI integration:**
- `cargo audit` runs as a step in `ci.yml` matrix using `actions-rust-lang/audit` action (pinned by 40-char SHA per §Security Anti-Patterns § Secrets `@v2`/floating-tag ban, and §Bootstrap phases `dep-security-ci-gate` SHA-pinning convention).

## Error Handling

_[ALL tiers]_

**External responses (to API consumers / end users):** sanitized — no stack
traces, file paths, internal hostnames, library versions, or implementation
details exposed.

- **TauRPC bridge:** every `#[taurpc::procedure]` returns `Result<T, AppError>` per Conventions Error response schema (Tauri IPC). `AppError` is a `serde`-friendly enum with stable variants `Validation { field, reason }`, `NotFound { resource }`, `Internal { message }`, `Plugin { plugin_id, message }`, `Storage { message }`, `Ingest { message }`. Module-internal `thiserror` 2.x enums convert at the bridge via `From` impls. The `Internal { message }` variant carries a sanitized one-liner suitable for surfacing in the UI; full error chain stays in the internal log per the redaction rules below.
- **OTLP receiver:** per OpenTelemetry HTTP spec — non-2xx responses carry `Status` proto in body for HTTP/protobuf, or HTTP/JSON for HTTP/JSON; gRPC errors use standard `tonic::Status` codes per Conventions Error response schema (OTLP receiver).
- **MCP server:** standard JSON-RPC 2.0 error object with stable `code` (numeric), `message` (string), and optional `data`; MCP-spec error codes are honored per Conventions Error response schema (MCP).

**Internal logging (for debugging):** full error details to `opentelemetry-stdout` / file exporter at `~/.andromeda-pulse/logs/` per Cross-cutting Patterns Self-observation — include only stack-local context that this app actually has (request id / span id from the OTLP boundary, plugin id at the WASM call boundary, MCP request id at the JSON-RPC boundary). Do NOT log a "user id" — auth approach=none per Threat Model Summary, the OS user owns the app, and there is no per-user identity surface to redact. NEVER log sensitive fields per Logging & Monitoring NEVER-log list.

**Error format:** Per Conventions Error response schema sections — TauRPC `AppError` JSON enum, OTLP `Status` proto / JSON, MCP JSON-RPC 2.0 error object. No invention of new envelopes.

**Error reporting integration:** No third-party error reporting platform (Sentry / Bugsnag / Rollbar) declared in arch — local OSS desktop app sends crashes only to local logs. If a future scope adds opt-in crash reporting, that scope must scrub OTLP attribute values + paths + plugin IDs per Logging & Monitoring NEVER-log list before transmission, and must require explicit user opt-in per the Project Intent local-first principle.

## Security Anti-Patterns (NEVER do these)

_[ALL tiers — single source of truth for all security bans]_

### Authentication

_[Auth-specific bans omitted — auth approach=none. Capability-system bans below cover the Tauri authorization model that substitutes for runtime auth.]_

### Input

- NEVER trust `Content-Length` or trailers as a substitute for `axum::extract::DefaultBodyLimit` / `tower_http::limit::RequestBodyLimitLayer` on the OTLP HTTP `:4318` routes — the JFrog axum-core advisory documents this as the root cause of unbounded request DoS.
- NEVER `format!("SELECT … WHERE service_name = '{}'", user_input)` against the `duckdb` crate `Connection`; ALWAYS use `Connection::prepare` with `?` placeholders and `Statement::execute([&param])` parameter binding — the Dagster GHSA-mjw2-v2hm-wj34, Vanna CVE-2024-5827, dagster-duckdb CVE-2026-41490 cluster proves this is the dominant 2026 DuckDB vuln class. DuckDB explicitly warns: "Treat SQL in DuckDB like code in Bash or Python and do not execute SQL from untrusted sources without proper sandboxing."
- NEVER skip post-`prost`-decode invariant checks on OTLP payloads — `prost` only validates wire format; `span_id` is 8 bytes, `trace_id` is 16 bytes, attribute keys aren't 1 GB, etc. must be checked in the `ingest` crate before handing to `buffer::Appender` per security-research §prost.
- NEVER read `ANDROMEDA_PULSE_*_PATH` / `*_DIR` env vars without `std::path::Path::canonicalize()` + an assertion that the canonical path starts under the resolved per-platform data dir (or under the explicit override base if `ANDROMEDA_PULSE_DATA_DIR` is set). This is a CWE-22 (Path Traversal) class defense; specific 2025–2026 CVE anchors (e.g., zip crate CVE-2025-29787, RustFS CVE-2025-68705) involve crates not in this project's dependency graph but document the same symlink-chain / TOCTOU traversal class that `tauri-plugin-fs`-style file APIs and any user-overridable path env-var construct are equally exposed to. Use `strict-path` per §Bootstrap phases `input-validation-library-install` for the canonicalize-and-confine primitive.
- NEVER call `tonic::transport::Server::builder()...add_service(generated_server)` without `.max_decoding_message_size(8 * 1024 * 1024)` set on each `*ServiceServer` builder — `tonic` historically accepted 1 GB+ unary requests by default per security-research §tonic.
- NEVER trust plugin-returned Arrow IPC bytes without a size cap before re-emitting on the Tauri `Channel` API.

### Data Protection

- NEVER add a non-Cranelift `wasmtime` feature flag on x86_64 builds without re-checking the April 2026 advisory cluster — Cranelift backend on x86_64 was the unaffected configuration for the two Critical sandbox escapes (CVE-2026-34941, CVE-2026-35195). A future "use the experimental Winch backend" change would re-introduce the exposure per security-research §wasmtime 25+.
- NEVER override the `tauri-plugin-updater` 2.x signature verification — Minisign Ed25519 verification cannot be disabled per security-research §tauri-plugin-updater, and any wrapper code must not attempt to bypass it.
- NEVER ship the Tauri updater Minisign **private** key in the repo or in any build artifact — only the public key belongs in `tauri.conf.json` per security-research §Tauri 2 Updater Signature Verification.
- NEVER store the Windows EV signing cert outside Azure Key Vault HSM — per security-research §Azure Key Vault OIDC, only DigiCert or GlobalSign HSM-RSA CAs are supported and the key must never leave the HSM.
- NEVER enable DuckDB encryption at rest on the in-memory ring buffer — CVE-2025-64429 is documented against the encryption feature; the in-memory `:memory:` connection avoids the entire surface and an unnecessary feature flip would re-introduce it.

### API

- NEVER use `tower_http::cors::CorsLayer::permissive()` or `allow_origin(Any)` on the OTLP HTTP `:4318` router — default-deny is the correct posture per security-research §CORS deny-by-default.
- NEVER skip the Host-header allowlist middleware on `:4318` — DNS rebinding is the documented attack against localhost OTLP/HTTP receivers per security-research §Host header validation (Coder Agent API CVE 2025-09-19, CVE-2025-66414 against MCP TypeScript SDK Dec 2025); "localhost is not a security boundary" is the explicit lesson.
- NEVER add a TauRPC procedure to a router crate without a matching entry in `pulse-app/capabilities/` per Cross-cutting Patterns Webview IPC capability policy and security-research §Tauri 2 Capability System — the bridge call is silently rejected at runtime, which becomes a hard-to-diagnose UX bug. The xtask drift check is the enforcement mechanism.
- NEVER grant Tauri core APIs (`fs`, `shell`, `dialog`, `http`) to `pulse:default` without an explicit per-feature capability addition with stated rationale per Cross-cutting Patterns Webview IPC capability policy.
- NEVER expose `pulse:updater` to webview JavaScript per Cross-cutting Patterns Webview IPC capability policy — the updater capability is bound to the `tauri-plugin-updater` flow only.
- NEVER widen `pulse:notification` (`tauri-plugin-notification`) or `pulse:tray` (tray icon) beyond outbound-only emit calls per Threat Model Summary "OS notification / tray surfaces" trust-boundary classification — both are outbound user-facing surfaces, not input vectors. Granting webview-side input handlers (e.g., notification action callbacks that re-enter Rust with arbitrary string payloads, tray menu items wired to invoke arbitrary IPC) converts an outbound surface into a phishing / IPC-abuse vector. The capability JSON for both MUST list only the outbound emit subset; any incoming-event handler MUST go through a separately-named capability with stated rationale.
- NEVER bind the OTLP receivers to `0.0.0.0` or any non-`127.0.0.1` interface — the loopback-only binding is the de facto authorization boundary per Phase 1 Sec 3 reasoning; binding to `0.0.0.0` invalidates the entire Minimal-tier risk model.
- NEVER instrument the product's own telemetry with an OTLP network exporter pointed at the product's own `:4317`/`:4318` ports per Cross-cutting Patterns Self-observation discipline — creates an infinite loop and bypasses the loopback authorization model.

### Secrets

- NEVER commit `.env`, `*.p12`, `*.pem`, `*.cer`, `*.key`, or `~/.tauri/*.key` files to git — `.gitignore` enforces; gitleaks CI step verifies.
- NEVER store the Azure Key Vault service principal as a long-lived GitHub Actions secret — use GitHub OIDC federation per security-research §Azure Key Vault OIDC.
- NEVER reference third-party GitHub Actions by `@v2` / floating tag — pin by 40-char commit SHA per security-research §Pin GitHub Actions by SHA + Dependabot. The tj-actions/changed-files CVE-2025-30066 (23k repos) demonstrated the retroactive-tag-rewrite attack class.
- NEVER grant `permissions: { contents: write }` at the workflow level — set workflow-level to `contents: read` and elevate per-job to `write` only on the publish step per security-research §Minimum GITHUB_TOKEN permissions.
- NEVER place Azure Key Vault credentials, Apple Developer ID credentials, or Tauri updater Minisign private key outside the GitHub Environment named `production-release` with manual approval gate.

### Logging

- NEVER log raw OTLP attribute values, span/log/metric content payloads, snapshot file contents, clipboard contents, or MCP tool response bodies — they may contain incidentally captured secrets from the instrumented host application.
- NEVER log full plugin file paths — basename of canonicalized path only.
- NEVER log DuckDB query parameter values — log query identifier + parameter count instead.
- NEVER expose stack traces, Rust struct names, file paths, or library versions in `AppError::Internal { message }` content surfaced to the webview — sanitize at the `From<thiserror::Error> for AppError` impl.
- NEVER expose internal hostnames or IPs in OTLP error responses or MCP error objects.

### Code Patterns

- NEVER use `tokio::process::Command::new(...).arg(user_input)` against any string sourced from an OTLP attribute, MCP tool argument, or workspace-detector output — the MCP STDIO command-injection cluster (CVE-2025-49596 MCP Inspector, CVE-2025-54994, CVE-2025-54136 Cursor, CVE-2026-22252 LibreChat) demonstrates this is a live 2025–2026 class.
- NEVER load a plugin from a path that wasn't canonicalized and asserted to be inside the resolved plugin dir — pair with the §Input ban above; this defends against `~/.andromeda-pulse/plugins/../../etc/...` walks via `ANDROMEDA_PULSE_PLUGIN_DIR`.
- NEVER spawn the rmcp sidecar without verifying both the compile-time `--features mcp-server` build flag AND the runtime `ANDROMEDA_PULSE_MCP_ENABLED=true` env var — single-gate is a regression of the architecture's declared double-gate per Established Decisions MCP Server Surface.
- NEVER serialize an `anyhow::Error` directly across the TauRPC bridge — must convert to the `serde`-friendly `AppError` enum first per Conventions Error response schema (Tauri IPC). Direct serialization either fails to compile (no `Serialize` impl) or, if hand-implemented, leaks the full error chain to the webview.
- NEVER use `serde_json::from_slice::<T>(buf)` on a buffer that hasn't been size-bounded by the `axum` `DefaultBodyLimit` layer — covers the OTLP HTTP/JSON path on `:4318`.
- NEVER use the `wasmtime` `Linker` to expose host functions outside the WIT contract for a given guest — bypasses the architecture's capability-scoped sandbox per Established Decisions Plugin Runtime.
