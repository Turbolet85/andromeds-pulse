## Anti-patterns to avoid

Mirrors the chunk #39 pattern that collapses InvalidSpanRecord variants to constant strings without leaking `kind`/`parent`/`reason` to the bridge.
- **NEVER log raw aggregation input or raw attribute keys/values via `tracing` fields.** Per `.claude/rules/observability.md` §PII scrubbing Vector 1 + 3 + 4: even at `debug` level, raw OTLP attribute values must not appear in `~/.andromeda-pulse/logs/agent-latest.jsonl`. Wrap any `tracing::debug!` of attribute KEYS in `if tracing::enabled!(Level::DEBUG)` — and even then, log only key sets / counts, never values.
- **NEVER reach into DuckDB from the snapshot crate to compute p50/p95/p99.** If the chunk plan considers "delegate percentile computation to DuckDB SQL with `quantile_cont`", that introduces a SQL surface inside the snapshot crate — re-exposing the §Code Patterns 2026 DuckDB CVE pattern.
