# a11y extract

## Relevance
partial — the chunk is a backend model swap with no planned UI surface change. Its only a11y exposure is indirect: L4 output text renders in the must-be-accessible p9 diagnostic report surface, and the shipped model identity may reach a webview surface (whether any webview surface renders `ModelIdentity` or the `pulse://stream/model-status` payload is research's question).

## Constraints
- The a11y tier is Standard WCAG 2.1 AA with an SC 2.3.3 AAA motion escalation (per a11y-plan §1 A11y Scope Summary). Any webview surface this chunk touches is held to that target. The TauRPC bridge and backend runtimes are listed there as Not-assertable, so the model swap itself carries no a11y assertion.
- The must-be-accessible set is P1–P14, and it includes p9 (the diagnostic report modal/window) and p14 (Investigate result/error/progress states). Both carry their own axe spec, and the universal minimums SC 2.1.1 / SC 2.4.3 / SC 4.1.2 apply (per a11y-plan §3 Surface set extension). A new model changes the L4 text those surfaces render. Their role, focus and SC discipline must hold over the new text's length and shape, including longer hypotheses or an empty or degraded interpretation.
- The report-window keeps its `role="dialog"`, its focus trap, its Esc/✕ close and its cross-window focus restore to the findings window (per a11y-plan §5 Keyboard Navigation report-window row and §6 Cross-window). Whether this chunk touches any of these is research's question. The scope names none.
- If the chunk surfaces the model identity or its load state in the webview (for example a model-status indicator, or a degraded/"Interpretation pending" notice), a status update must use `aria-live="polite"` and a blocking failure must use `role="alert"` (per a11y-plan §7 Screen Reader Support → Live regions, SC 4.1.3). A model-status state shown by color must also carry a text or icon supplement (per a11y-plan §11 A11y Anti-Patterns → Visual, SC 1.4.1).
- Zero new WCAG AA violations per PR on the must-be-accessible paths, with no retry-once (per a11y-plan §10 SLO Invariants & A11y Budgets).

## Patterns to follow
- Playwright a11y specs mock TauRPC via `tests-a11y/helpers/mock-tauri.ts`, with report/incident fixture payloads in `helpers/v02-fixtures.ts` (per a11y-plan §3 Harness wiring & conventions). If the chosen model's output shape differs from the baseline's, the p9/p14 fixtures are the place to represent it. Whether the existing fixtures already cover the new shape is research's question.
- Aggregate-only, stable accessible names: a landmark name stays a stable literal while live data rides in a description (per a11y-plan §7 Landmark roles). This applies by analogy if model identity or load state reaches the accessible tree.
- Hybrid/degraded render: a missing or unparseable interpretation shows an explicit text notice rather than an empty region (per a11y-plan §7 Live regions, plus the p9 surface discipline in §3). A model that fails to load or answer must still leave p9 perceivable.

## Anti-patterns to avoid
- NEVER convey a model-status or interpretation state by color alone (per a11y-plan §11 A11y Anti-Patterns → Visual, SC 1.4.1).
- NEVER claim WCAG conformance for an affected surface without machine-verifiable axe/pa11y/Lighthouse JSON (per a11y-plan §11 A11y Anti-Patterns → Strategy / Universal).
- NEVER retry an a11y failure, and never defer one to a follow-up (per a11y-plan §11 A11y Anti-Patterns → SLO / CI).

## Contract bindings
- a11y ↔ tests: the p9/p14 axe specs run in the ci.yml `a11y` job against the tests' 5-command harness and the shared mock-tauri fixtures (per a11y-plan §9 CI Integration). If the L4 output fixtures or bindings change, both domains consume the change.
- a11y ↔ obs: any violation JSON uses the shared structured log format (per a11y-plan §3 Structured violation JSON schema). This chunk does not change it.

## Acceptance criteria contributions
- (a11y) If the chunk changes any webview file, its rendered L4 text, or the report/incident fixtures, `npm run test:a11y` passes the p9 and p14 axe specs with zero new violations against the base branch. If no webview file or fixture changes, record that as "no a11y surface touched" instead (per a11y-plan §10 SLO Invariants & A11y Budgets).
- (a11y) If the model identity or load state is newly rendered in the webview, that element has an accessible name and a text (not color-only) state, and any change of state is announced through `aria-live="polite"` (per a11y-plan §7 Live regions, SC 4.1.2 / SC 4.1.3 / SC 1.4.1).
- (a11y) Keyboard focus spec `keyboard-focus/widget-and-modals.spec.ts` stays green: the report window's focus trap, Esc close and cross-window focus restore are unchanged (per a11y-plan §6 Cross-window and §3 Surface set extension).
