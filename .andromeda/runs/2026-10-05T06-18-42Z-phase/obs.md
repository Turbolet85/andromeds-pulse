# obs extract

## Relevance
partial — the chunk is mostly a measurement series and a model-default swap. Its obs surface is the L4 model-identity and path telemetry (`interpretation.model.load` / `.load.error` / `.allow_root`) that the new default flows through, plus any new record the no-thinking or footprint work might be tempted to add.

## Constraints
- obs-plan §8 PII Scrubbing (the `interpretation.model.load` muted-backlog close) requires the `interpretation.model.load` leaf to stay exactly `{model_identity, tier, load_status, inference_mode}`, with `model_identity` carrying the semantic model name at the loaded emit. Shipping a new default changes the VALUE `model_identity` carries, never the leaf's field set. Whether the emit site derives that name from the resolved model or from a hardcoded Llama literal is research's question.
- obs-plan §3 Telemetry triggers (logging-sensitive, Vector 6) and §8 (`interpretation.model.load.error` / `interpretation.model.allow_root`) require basename-only path logging for `ANDROMEDA_PULSE_MODEL_PATH` · `_LLAMA_{CUDA,CPU}_BIN_PATH` · `ANDROMEDA_PULSE_L4_ALLOW_ROOT`. The `.load.error` leaf is the 6-field set `{error_msg, model_identity, recovery_action, error_category, env_var, path_basename}`, and `allow_root` is `{confinement, root_basename}`. A new candidate GGUF filename may appear only as a basename, never with its `AI-Model/` directory.
- obs-plan §8 (`interpretation.incident.created` paragraph) says no bare `interpretation` allowlist key may exist (`for_target("interpretation").is_none()`). Any NEW `interpretation.*` target this chunk adds (for example a thinking-block detection record or a per-generation footprint record) needs its own EXACT leaf carrying every field its emit site emits. Its guard file goes under `pulse-app/tests/`, never a src-level `mod tests`, per the `[lib] test = false` rule restated throughout §8.
- obs-plan §5 Metric Coverage (naming and cardinality discipline) applies to any footprint or latency figure that becomes product telemetry. It must use `metric.{module}.{measure}` naming with a numeric `value` and labels bounded to enumerated values. A model label is admissible only as a closed set, never as free text from a path or model card. A new `metric.*` target needs its own exact leaf, because the bare `metric` key keeps `value` and silently redacts every label (§8 delegated-timing paragraph).
- obs-plan §8 data classifications are default-deny: only allowlisted fields are logged. The `interpretation.incident.skipped` entry bans prompt and model text from logs. Generated text, including any `<think>` / reasoning-block content a candidate emits, falls under that ban. A no-thinking proof logged in-product may carry only a bounded verdict or count, never the block itself.
- obs-plan §10 SLO Invariants & Telemetry Budgets lists no L4 latency or RAM/VRAM arm. `perf:budget` grades memory, snapshot and frame only, and the memory gauge is a row-count estimate, not process RSS. So the chunk's footprint figures are series evidence, not a gated SLO. Making any of them a product budget would need an enforced gate (see the anti-patterns below).
- obs-plan §1 Architectural choice and §11 Universal require self-observation through `tracing` alone. The probe or any harness driving real-model runs must not link an OTel SDK, and must not dial the product's own `:4317`/`:4318` (shared with conductor-builder during the granted slot).

## Patterns to follow
- obs-plan §8 leaf-guard pattern: a leaf is asserted by exact-resolve, field-set equality in BOTH directions, and a no-bare-prefix fallback discriminator, and the guard is mutation-checked. Precedents are `pulse-app/tests/unit_observability_allowlist_l4_path_guard.rs` and `unit_observability_allowlist_sweep.rs`, which hold the `interpretation.model.load` set.
- obs-plan §6 Log levels (`warn` row) handles a degraded or overridden boot with a once-per-boot record carrying bounded static labels, for example `interpretation.model.allow_root` (WARN on `unconfined`). If the chosen default falls back from CUDA to CPU, or to a different model, that is the shape the record should take, never per-generation spam.
- obs-plan §5 tick-aggregated counter convention: aggregate counts ride as FIELDS on an existing heartbeat (for example the `metric.pipeline.l4.backoff_remaining_seconds` gauge carrying `generations_suppressed_total` / `generations_run_total`), not as a new per-event target.
- obs-plan §3 Telemetry triggers Vector 6 row: path vars are validated at USE (`llamacli_inference.rs::validate_path_input`), and the env var NAME is OK to log while its value is not. Reuse this for any changed default path.

## Anti-patterns to avoid
- obs-plan §11 SLO: NEVER define soft SLO budgets. If footprint or CPU-latency thresholds from the series are written into a spec as product budgets, they must fail a gate when exceeded. Otherwise they stay recorded evidence, not an "SLO".
- obs-plan §11 Logs / §8: NEVER log raw model output, prompt text, or full model/binary paths. That includes a candidate's reasoning block, captured stdout, and the `AI-Model/` directory.
- obs-plan §11 Metrics: NEVER use unbounded label cardinality. A model-identity label taken from a filename or model-card string is unbounded unless it is mapped to a closed set first.

## Contract bindings
- obs ↔ security: basename-only logging of the L4 model, binary and allow-root paths binds to security-plan §Security Anti-Patterns → Input (the L4 narrowed exception) and §Logging. The `interpretation.model.load.error` / `.allow_root` leaves are the shared surface (obs-plan §3 Telemetry triggers Vector 6, §8).
- obs ↔ tests: the `interpretation.*` leaf guards under `pulse-app/tests/` (l4_path_guard, sweep, generation_damper) are test-plan-owned pins over obs-plan §8 field sets. A changed `model_identity` value must not need a field-set change, and any new leaf brings its own guard file (obs-plan §8).
- obs ↔ arch: the `model_identity` value the `interpretation.model.load` record carries should match the arch §Established Decisions [LLM Inference Runtime] model record the chunk updates. Whether one source of truth feeds both is research's question.

## Acceptance criteria contributions
- (obs) After the default swap, a boot log's `interpretation.model.load` record carries exactly `{model_identity, tier, load_status, inference_mode}`, with no `<redacted>` field. `model_identity` names the chosen model, not Llama 3.2 3B. The existing `interpretation.*` leaf-guard files stay green unmodified, or are changed only by a value, never by a field set (per obs-plan §8 PII Scrubbing, `interpretation.model.load` entry).
- (obs) Across the chunk's real-model and boot logs, the `AI-Model/` directory or any full candidate GGUF path appears 0×, and a candidate filename appears only as `path_basename` (per obs-plan §3 Telemetry triggers Vector 6 and §8 `interpretation.model.load.error`).
- (obs) Any new `interpretation.*` or `metric.*` target the chunk introduces has an exact leaf equal to its emit-site field set and a guard under `pulse-app/tests/`, and `for_target("interpretation").is_none()` still holds. If no new target is added, record that (per obs-plan §8, `interpretation.incident.created` and delegated-timing paragraphs).
- (obs) No log record carries generated model text or reasoning-block content. If the no-thinking proof is emitted in-product, its record carries only bounded labels or counts (per obs-plan §8 default-deny and the `interpretation.incident.skipped` ban; §11 Logs).
