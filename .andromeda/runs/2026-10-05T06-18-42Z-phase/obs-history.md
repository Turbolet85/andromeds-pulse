The probe or harness driving the candidate series must not link an OTel SDK or dial `:4317`/`:4318` (§1/§11 constraint in the extract).

The chunk's CPU-only and GPU latency figures for the new model bear on it, and if any of them is promoted to a budget, the never-soft-SLO rule applies.
- **2026-08-15-tier-1-incident-path-investigation** (five-target muted backlog) — recorded `interpretation.model.load` → `inference_mode` as measured-redacted. This is the start of the leaf-completeness history behind the `{model_identity, tier, load_status, inference_mode}` field set that the default swap must keep unchanged.
- **2026-08-16-baseline-family-reachability** — set the dual-site rule: every once-per-boot WARN is stated in BOTH §6 and §8, and a §8-only apply leaves §6 stale. It also set the registry-completeness disposition (bounded fields, an exact leaf and a guard that runs make the change routine, not a PII hole). Both apply if the chunk adds a once-per-boot fallback or override record, such as CUDA→CPU or a model fallback.

- **2026-08-21-delegated-timing-observables** — set the `metric.*` own-exact-leaf rule. A bare `metric` key exists (`value`/`unit`/`module`), so a target without its own leaf keeps `value` and silently redacts every label. This governs any footprint or latency figure that becomes a `metric.*` product target, including a model label, which must be a closed set.
