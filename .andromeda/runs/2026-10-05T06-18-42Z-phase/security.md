# security extract

## Relevance
partial. Most of the chunk is a real-model measurement series plus a default-model swap. It does touch the L4 subprocess surface: the product-consumed model and binary path vars, the argv `-p` prompt, new llama-cli argv flags for no-thinking, the stdout decode, and the model-identity and path logging.

## Constraints
- The three product-consumed L4 path vars (`ANDROMEDA_PULSE_MODEL_PATH` · `_LLAMA_CUDA_BIN_PATH` · `_LLAMA_CPU_BIN_PATH`) must keep the always-on guard: trim plus reject-empty, reject a `..` component before canonicalizing, a 4096-byte length bound, `canonicalize()`, and assert regular-file. Confinement stays opt-in through `ANDROMEDA_PULSE_L4_ALLOW_ROOT`, which fails closed when set but unresolvable. Shipping a new default model must not open a path into the product that skips this guard (per security-plan §Input Validation, CLI / env var row; §Security Anti-Patterns → Input, NARROWED EXCEPTION). Research must answer whether a compiled-in or harness default model path, the shape a "ship the chosen model as the L4 default" change would take, is resolved through `validate_path_input` today.
- Never log a full product-consumed filesystem path. The model GGUF, both llama-cli binaries and the allow-root are emitted only as `path_basename` / `root_basename` plus the env-var NAME. This covers every new or renamed model-identity or load record the swap touches (per security-plan §Logging & Monitoring, What NEVER to log; §Security Anti-Patterns → Logging, path bullet).
- Any argv the chunk adds to the llama-cli `Command` must be a first-party constant, never a string from OTLP, MCP or workspace-detector input. That includes a no-thinking or reasoning-budget flag, a chat-template override or a template kwarg. The only OTLP-derived argv value stays the `-p` prompt, admitted through `validate_prompt_bounded` (per security-plan §Security Anti-Patterns → Code Patterns, the `Command::new(...).arg(user_input)` ban and its L4 `-p` admission).
- The `-p` operand keeps its 16384-byte `MAX_PROMPT_BYTES` ceiling and its NUL/C0/C1 rejection, with `\n` `\r` `\t` whitelisted. Over-long input is rejected, never truncated. The ceiling is derived from a measured maximum: 7,405 B at v2.5, primary builder only. If a candidate's handling changes what crosses argv, for example a no-think directive added to the prompt text, that maximum must be re-measured. The scope's boundary forbids silent folding of such a change (per security-plan §Input Validation, L4 inference argv prompt row).
- L4 failures stay bounded categories on `interpretation.inference.error`, with no prompt text and no model-output bytes. This covers a candidate that fails to load, emits a reasoning block, or produces stdout that fails UTF-8 decode (the existing `stdout_utf8_invalid` / `io_error` arms). Output is model-authored, so the no-output-bytes guarantee is the load-bearing half (per security-plan §Input Validation, L4 argv row; §Error Handling, Internal logging).
- No new Cargo dependency or runtime is expected, because the scope keeps b9305 and the trait surface. If any Cargo or lockfile delta lands anyway, it passes `cargo deny check bans licenses sources` as a pass/fail gate and `cargo audit`. `cargo deny check advisories` is observed separately (per security-plan §Dependency Security, CI integration).

## Patterns to follow
- The `std` both-sides-canonicalize primitive on the `workspace_detector::contract::publish_workspace_key` precedent. It is the single project path primitive for any new default or override path resolution, with both the candidate and the root canonicalized (per security-plan §Security Anti-Patterns → Input, NARROWED EXCEPTION).
- The once-per-boot WARN on `interpretation.model.allow_root` announcing the unconfined posture when the root is unset. Keep it intact across the default swap (per security-plan §Security Anti-Patterns → Input).
- The bounded-category rejection shape: `PromptRejection::label()` / `InferenceError` categories reach the log, and content never does (per security-plan §Input Validation, L4 argv row).
- Model distribution is an open arch caveat by design, because the GGUF and llama-cli live outside the data dir. The plan's license and advisory gates cover only the Cargo and npm channels (§Dependency Security), so GGUF weights fall outside every automated gate. The scope's per-candidate licence record from the model card is the only control on the model artifact, and a non-Apache-2.0 card is surfaced, never kept silently (per security-plan §Security Anti-Patterns → Input, the open distribution caveat; §Dependency Security, licenses scope).

## Anti-patterns to avoid
- NEVER build a llama-cli argv element from OTLP-, MCP- or workspace-derived text beyond the bounded `-p` operand. That covers a model name, a template, or a flag value sourced from telemetry or the digest (per security-plan §Security Anti-Patterns → Code Patterns).
- NEVER log the model GGUF's or llama-cli binary's full path or containing directory, a prompt excerpt, or raw model output, including a captured `<think>` block, in harness-run or product records (per security-plan §Security Anti-Patterns → Logging).
- NEVER resolve a new default model path outside the guarded `validate_path_input` route, and never relax the fail-closed allow-root (per security-plan §Security Anti-Patterns → Input).

## Contract bindings
- security ↔ obs: the basename-only path rule and the bounded `interpretation.inference.error` categories bind to obs-plan's records for `interpretation.model.load` / `interpretation.model.allow_root` / `interpretation.prompt.assemble`. Any field the swap adds to `ModelIdentity` / `ModelLoadEvent` must stay basename and label only (per security-plan §Logging & Monitoring).
- security ↔ tests: the prompt ceiling's measured maximum lives in two lockstep sites, security-plan §Input Validation L4 row and §Security Anti-Patterns → Code Patterns. Any re-measurement updates both, alongside test-plan's probe pins. The argv ASCII-cleanliness pin `composed_prompt_templates_are_ascii_clean_for_argv_transport` comes from `.claude/rules/security.md` Session Additions 2026-08-27, not this plan. It binds if any template or no-think text is added.
- security ↔ arch: the arch §Established Decisions [LLM Inference Runtime] record and the open model-distribution caveat are the arch-side owners of the default-model identity. Security owns only the path, argv and log boundaries around it.

## Acceptance criteria contributions
- Over each candidate's real-model run log family, the model GGUF's and llama-cli binaries' containing directory appears 0×, and only the basename and env-var NAME appear (per security-plan §Security Anti-Patterns → Logging, path bullet).
- Every argv token added for the no-thinking configuration is a source-level constant (grep of the `build_llama_cli_args` site), and the `-p` operand still passes through `validate_prompt_bounded` at its single production caller (per security-plan §Security Anti-Patterns → Code Patterns).
- If the composed prompt changes for any candidate, its re-measured maximum stays below `MAX_PROMPT_BYTES` (16384), and security-plan §Input Validation L4 row and §Security Anti-Patterns → Code Patterns are amended in lockstep. Otherwise both stay untouched (per security-plan §Input Validation, L4 inference argv prompt row).
- With `ANDROMEDA_PULSE_L4_ALLOW_ROOT` set to a directory that excludes the chosen model, the shipped default is rejected to `ModelNotConfigured`, not loaded, which shows the new default goes through the guard (per security-plan §Input Validation, CLI / env var row).
