## Constraints
- The real-L4 arm's `ANDROMEDA_PULSE_MODEL_PATH` / `_LLAMA_CUDA_BIN_PATH` / `_LLAMA_CPU_BIN_PATH` (and `ANDROMEDA_LLAMA3_TOKENIZER_PATH`) are read by the **product** binary per scope §Real-L4 feasibility, so security-plan §Security Anti-Patterns → Input requires `canonicalize()` + confinement under the resolved data dir; the 2026-08-23 carve-out is explicitly scoped to harness/xtask-only, not-production-consumed vars and does not reach these. Separately, security-plan §Input Validation (CLI / env var inputs row) presents itself as the complete boundary enumeration and does not name them. Whether the code already canonicalizes/confines them, and whether a ratified carve-out or a registry row is owed, is research's question.
- security-plan §Security Anti-Patterns → Code Patterns forbids `Command::new(...).arg(user_input)` for any string sourced from an OTLP attribute or workspace-detector output. The headline leg spawns `llama-cli` on a digest assembled from injector-driven telemetry, so this ban is directly in play; whether the current wiring passes prompt content via argv versus stdin/file is research's question.
- Sustained/continuous injector mode is exactly the "runaway local producer saturating the OTLP path" case security-plan §API Security (Rate limiting) writes controls against (coarse global cap + per-source-port `tower_governor`), and it must not require relaxing the `:4317` `.max_decoding_message_size(8 MiB)` cap or the post-`prost`-decode invariant checks required by security-plan §Input Validation (OTLP/gRPC row) and §Security Anti-Patterns → Input. Whether those controls are wired today is research's question.
- The `cargo audit` standing deferral (security-plan §Dependency Security → CI integration) requires this wrap to re-verify basis + overlap and record `probe skipped per ratified interval (next: 46)` — never a silent skip — with `cargo deny check bans licenses sources` and `cargo deny check advisories` results recorded, and DISTINCT `RUSTSEC-` ids enumerated (the plan's counting rule (a): 10 error blocks ≠ 8 owned IDs).
- The `lint:a11y` harness fix must not add an npm dependency if avoidable: security-plan §Dependency Security records as MEASURED that the `pulse-app/ui` npm channel gets Dependabot version updates but **no** advisory/license/ban scanning, so any added devDependency lands where no gate would fail on an advisory. The config-only shape (rules into `eslint.config.mjs`) stays inside the declared controls.
- The injector's sustained stream traverses the five persisted client-controlled ring-buffer cells and the corpus write paths that security-plan §Security Anti-Patterns → Logging mandates pass `scrub_attribute` at their write boundary; demo payloads must be synthetic, and any new client-controlled persisted cell or corpus write path introduced by sustained mode must scrub at its write boundary.
- Any documented smoke/verification recipe must not embed `ANDROMEDA_PULSE_CORPUS_PASSPHRASE` — it is secret-class per security-plan §Secret Management ("What counts as secret") and inherits never-logged / never-committed, backed by the `.gitignore` + secret-scanning bans in §Security Anti-Patterns → Secrets.

## Patterns to follow
- Registry-completeness rows for code-validated + unit-tested env boundaries (`ANDROMEDA_PULSE_L4_DETERMINISTIC`, `BASELINE_BOOTSTRAP_SECONDS`, `window-geometry.json`) — the routine shape if the model/CUDA path vars need registering, per security-plan §Input Validation (CLI / env var inputs row).
- The harness-only tool-locator guard: trim + `is_file()` + **clean SKIP** (exit 0, print the fetch recipe), resolved value never logged — only the variable NAME appears — per security-plan §Security Anti-Patterns → Input (`ANDROMEDA_PULSE_MSEDGEDRIVER_PATH` carve-out). This is the nearest precedent for an absent-model / absent-CUDA-runtime skip in the documented recipe.
- Bounded truthy-parse (`1|true|yes`, default false, no unbounded string) for the det-L4 gate, per security-plan §Input Validation — the shape for any additional gate the sustained mode introduces.
- The three ratified scrub shapes — choke-point (`extract_service_name`), push-site (`scrub_otlp_field`), and joined `key=value` UNION bare value (`metrics_points.labels`) — per security-plan §Security Anti-Patterns → Logging; a new persisted cell picks one, it does not invent a fourth.
- Deferral bookkeeping form: basis quoted byte-identically, overlap re-enumerated first-hand, exit read directly (never through a pipe), per security-plan §Dependency Security → CI integration.

## Anti-patterns to avoid
- NEVER pass an OTLP-attribute- or digest-derived string as a spawned-process argument (security-plan §Security Anti-Patterns → Code Patterns; MCP-STDIO command-injection cluster).
- NEVER read a product-binary `ANDROMEDA_PULSE_*_PATH` / `*_DIR` without canonicalize-and-confine, and NEVER stretch the harness-only carve-out to cover a var the shipped binary reads (security-plan §Security Anti-Patterns → Input).
- NEVER log raw OTLP attribute values, brief/snapshot contents, or a resolved tool/model path into harness output or the agent log (security-plan §Security Anti-Patterns → Logging + §Logging & Monitoring NEVER-log list).

## Contract bindings
- **tests** — the CI security gate stays one job in the single workflow (security-plan §Bootstrap phases `dep-security-ci-gate`); the smoke recipe's `rows_ingested > 0` feed-precondition is tests-owned, security binds only the "no real PII/secret material in injector fixtures" side.
- **obs** — PII scrubbing cross-cuts: the `redactions_applied` counter and the `agent-latest.jsonl` sink that leg 4b's glob fix reads; security-plan §Logging & Monitoring assigns that sink's rotation/retention to the obs specialist, so the `agent-latest.jsonl*` rolling-suffix shape is obs's contract and security only requires the reader not echo raw log content.
- **arch** — scope declares the `EXPECTED_PROCEDURES` / capability-drift chain out of play; security-plan §Security Anti-Patterns → API re-arms it immediately if any TauRPC procedure or `core:window:*` permission lands.
