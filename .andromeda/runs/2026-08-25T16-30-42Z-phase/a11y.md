## Constraints
- The a11y lint gate is a **hard, fail-fast CI gate**, not a warning: the 4c repair is a harness-script fix only and may not weaken, drop, downgrade, or narrow jsx-a11y rule coverage to make the Windows quoting bug go away, and it must keep emitting ESLint-JSON-format machine output for the PR annotation consumer (per a11y-plan §9 Lint stage row + §11 CI "no soft gates").
- If the inline `--rule` args move into `eslint.config.mjs`, the config must still extend `plugin:jsx-a11y/recommended` (eslint-plugin-jsx-a11y 6.10.x is the compile-time gate); any deliberate narrowing of the rule set requires an explicit Decisions Log entry rather than a silent config change (per a11y-plan §3 A11y testing tool pick + §11 Strategy partial-configuration ban + §12).
- Lint is a **subset** gate and never a substitute for the runtime chain: repairing `lint:a11y` does not discharge `npm run test:a11y` (axe-core/playwright + Lighthouse + pa11y), which remains the primary gate (per a11y-plan §11 CI "NEVER ship lint-only a11y without runtime axe-core / pa11y / Lighthouse" + §3 CI integration).
- A green a11y command whose harness never actually ran is indistinguishable from conformance — §3 Harness wiring & conventions mandates a cheap suite-health check for exactly this reason (a list-time import failure once silently disabled the whole Playwright suite). The 4c repair must be shown to **execute** the rules, not merely exit 0 (per a11y-plan §3 Harness wiring & conventions).
- Sustained, continuous live updates must not disturb keyboard state: §1 P4 requires that live updates never steal focus from the current keyboard target and that the re-poll **preserve the focused row** (roving `tabindex` clamped, never reset), under SC 2.1.1 / SC 2.4.3 / SC 4.1.3. Whether the shipped trace table already holds this under a *continuous unique-stream* injector (as opposed to the finite burst it was verified against) is research's question (per a11y-plan §1 P1/P4 + §5 full-dashboard-traces).
- Telemetry-driven motion under a sustained stream stays bounded: no flashing more than 3 times per second (SC 2.3.1) and the canvas frame loop must honour `prefers-reduced-motion` via `useReducedMotion`; motion may never be the only conveyance of a state change (per a11y-plan §6 Motion tokens + §11 Motion).
- Operator judgement of the interpretation brief (the ManualCheck-class headline leg) is **never** a11y evidence: every WCAG claim needs a machine-verifiable path (axe-core / Lighthouse / pa11y / structured violation JSON); manual passes are supplemental only (per a11y-plan §2 Agent-runnable invariants + §11 Universal).

## Patterns to follow
- **Populated-fixture / feed-precondition discipline** — §3 Harness wiring & conventions requires a11y fixtures be POPULATED because "an empty array renders nothing, so the sweep audits a blank region and passes by comparing nothing." This is the identical failure shape leg 2c's `rows_ingested > 0` assertion targets; the a11y rule is the in-repo precedent for how to phrase it (per a11y-plan §3).
- **Prove the harness is alive before trusting a green result** — the `npx playwright test --list` health check convention in §3 Harness wiring & conventions; apply its analogue to the repaired lint script (per a11y-plan §3).
- **Repair the harness, retain the tooling stack** — the chunk-#99 precedent rewrote helpers/config with no tooling-stack change (axe / Lighthouse / pa11y retained). The 4c fix should follow the same shape: quoting/config plumbing changes, rule set untouched (per a11y-plan §3 Harness wiring & conventions).
- **Row-level roving-tabindex contract for the trace table** — anything the sustained leg observes in the traces surface must be read against the row-level contract (each `<tr>` one tab stop; Up/Down/Home/End; Enter activates Investigate; Esc to toolbar; in-row button at `tabIndex={-1}` under the grid-lite carve-out), not a 2-D cell-traversal contract, which is deliberately NOT the contract (per a11y-plan §5 + §11 Keyboard).
- **Structured violation JSON in the obs log shape** — any a11y result artifact this chunk touches keeps the `target: "a11y::assertion"` + `fields.{wcag_criterion, violation_type, severity, surface, selector, remediation, tool, tool_result_id}` shape and the fixed artifact filenames under `~/.andromeda-pulse/logs/` (per a11y-plan §3 Structured violation JSON schema + §3 CI integration).

## Anti-patterns to avoid
- NEVER convert the a11y lint step into a warning, soft gate, or deferred follow-up to route around the Windows quoting bug — a11y gates PR merge, with no "fix in follow-up" (per a11y-plan §11 CI).
- NEVER treat a repaired lint gate as a11y coverage on its own; lint catches the ARIA-on-non-semantic subset, runtime axe-core/pa11y/Lighthouse catch the rest (per a11y-plan §11 CI).
- NEVER record the operator-judged live leg as WCAG conformance evidence — human-only review without machine output is banned (per a11y-plan §11 Universal).
