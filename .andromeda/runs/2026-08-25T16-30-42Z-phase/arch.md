# arch extract

## Relevance
Relevant — arch governs the injector's ingest surface, workspace placement, the real-L4 runtime pins, the `ready` envelope the feed-precondition reads, and the env-var registry the real-model leg consumes.

## Constraints
- Telemetry injection MUST speak real OTLP to the running receiver on `:4317`/`:4318` — the same surface external SDKs use; **no in-process test-mode bypass, no separate "test ingest" feature flag, no mock-channel back-door**, and non-default ports resolved only via `ANDROMEDA_PULSE_OTLP_GRPC_PORT` / `_HTTP_PORT` (per architecture.md §Cross-cutting Patterns → Test-time telemetry injection). This binds the §2a sustained-mode shape: sustained emission is a client-side change to `inject_demo`, never a new ingest path.
- The OTLP ports are spec-fixed and bound on `127.0.0.1` only, with no project envelope over the OTLP wire (per architecture.md §Occupied Resources → Network ports; §Established Decisions → [API Style — OTLP Receiver Surface 1]). The scope's inferred claim that sustained mode adds no new OTLP surface is the correct target state; a sustained mode that added a port, endpoint or wire shape would breach this.
- Workspace crate names are reserved and cannot be re-purposed: the injector example belongs to `ingest`, the LWW queue to `triage`, the task runner to `xtask`, and the dependency graph is a DAG rooted at `pulse-app` with no library crate depending on the binary (per architecture.md §Occupied Resources → Cargo workspace crate names; §Cross-cutting Patterns → Module dependency direction; §Inherited Defaults → Module boundaries).
- Every env var the **product** consumes must be registered in the registry, `ANDROMEDA_PULSE_`-prefixed; harness-only vars are registered as a distinct class and the `PULSE_*` xtask→node relay set is explicitly never consumed by the production binary (per architecture.md §Occupied Resources → Environment variables). Note the real-L4 leg's `ANDROMEDA_PULSE_MODEL_PATH` and `ANDROMEDA_LLAMA3_TOKENIZER_PATH` do **not** appear in that registry — `MODEL_PATH` is named only in the [LLM Inference Runtime] prose as an open co-design item, `LLAMA3_TOKENIZER_PATH` nowhere. Whether production/build code already consumes them (and therefore whether registry closure is owed at wrap) is research's question.
- The L4 runtime pin is `b9305` **exact**, with CUDA build + `-ngl 99` for gpu-primary/gpu-fallback and CPU build + `-ngl 0` otherwise, routed by `HardwareProfileSource` tier, under bounded-invocation discipline (`-n {max_tokens}` + `-st` + outer wall-clock timeout, `kill_on_drop`); binary paths come from the registered `ANDROMEDA_PULSE_LLAMA_CUDA_BIN_PATH` / `_CPU_BIN_PATH` pair (per architecture.md §Established Decisions → [LLM Inference Runtime — L4 interpretation layer]; §Occupied Resources → Environment variables).
- `ready` is a **Standard Contract**, and `rows_ingested` / `buffer_used_seconds` / `retention_seconds` are contracted checks inside its `checks` object (per architecture.md §Standard Contracts → Tauri IPC readiness). The §2c feed-precondition (`rows_ingested > 0`) must read that contracted field; changing the envelope's shape would be an arch amendment, not a harness edit. Whether the documented smoke recipes already read it there is research's question.
- Fault identity bounds the §2a "unique-enough" open question: L1 normalization is TOKEN-LEADING and **relative path structure is identity-significant** (so varied content splits fingerprints), while L2 incidents coalesce on `(kind, scope, scope_id)` — a storm carrying a different fingerprint on a service with an open incident is **absorbed by design** (per architecture.md §Established Decisions → [Fault Identity — what makes two faults ONE fault]). Consequence for P4: varying the fingerprint alone will not produce a second incident, and over-varying risks preventing storm formation outright.

## Patterns to follow
- **Prebuilt-binary-by-path invocation already has an in-repo precedent**: the registered harness relay `PULSE_INJECTOR` carries the path to the prebuilt `crates/ingest/examples/inject_demo` binary and is set by `xtask::webview_drive`, omitted by `--no-inject` (per architecture.md §Occupied Resources → Environment variables; §Stack → GUI verification harness row). §2b's documented form should align with that existing contract rather than invent a second convention.
- **xtask is the single Rust task-runner surface** — shared CI/harness logic that needs Rust lives in `xtask` so contributors run identical commands locally (per architecture.md §Infrastructure Patterns → CI/CD approach; §Established Decisions → [CI Task Runner]). The `smoke.rs` log-reader fix and any build-then-run recipe belong on that surface.
- **Read buffer state back through contracted surfaces**, not by peeking at DuckDB: tests inspect via the `traces.*` / `metrics.*` / `logs.*` query routers and the `ready` envelope (per architecture.md §Cross-cutting Patterns → Test-time telemetry injection; §Standard Contracts).
- **Agent-driven development style** — deterministic harness invocations, machine-parseable outputs, schema-stable contracts (per architecture.md §Cross-cutting Patterns → Development Style). The ManualCheck real-L4 arm is additive to, not a replacement for, the deterministic arm.
- **Module visibility discipline**: each crate exposes only its public contract; cross-crate utilities are `pub(crate)` (per architecture.md §Conventions → Module visibility discipline). Removing the dead `drain_all` surface shrinks `triage`'s public contract in the sanctioned direction.
- **Self-observation discipline**: the product's own telemetry goes to the stdout/file exporter under the `logs/` data-dir subpath and never dials `:4317`/`:4318` (per architecture.md §Cross-cutting Patterns → Self-observation discipline; §Occupied Resources → Filesystem locations). The injector dialing `:4317` is an *external client*, a distinct thing from self-observation — do not conflate the two when reworking the log readers.

## Anti-patterns to avoid
- Adding an in-process injection path, a `test-ingest`-shaped feature flag, or a mock-channel back-door to make sustained mode easier (banned outright by architecture.md §Cross-cutting Patterns → Test-time telemetry injection).
- "Latest tag" drift on the llama.cpp build, or settling the prebuilt-binary/model distribution question in this chunk — arch marks distribution an explicitly OPEN caveat and pin bumps deliberate chunk-scoped events (per architecture.md §Established Decisions → [LLM Inference Runtime] pin discipline + open caveat), matching the scope's own non-goal.
- Landing a new default-on Cargo feature or pulling a new dependency into the default build graph for a dev/test tool — features are `kebab-case` and defaults minimal, flag-specific deps enter only when enabled (per architecture.md §Cross-cutting Patterns → Feature-gate hygiene; §Conventions → Feature flags).

## Contract bindings
- **`ready` envelope ↔ tests harness**: `rows_ingested` is arch-contracted (§Standard Contracts) and is the field the tests domain's §2c feed-precondition assertion consumes — one shape, two owners.
- **Test-time telemetry injection ↔ tests + security**: the "no bypass surface" rule is arch's, but it is what keeps the tests harness from opening an ingest path security would have to validate.
- **Env-var registry ↔ wrap-time amendment (D-arch-resources)**: if the real-L4 leg's `ANDROMEDA_PULSE_MODEL_PATH` / `ANDROMEDA_LLAMA3_TOKENIZER_PATH` prove production/build-consumed, §Occupied Resources owes registration; the harness-only `PULSE_*` relay set is already registered.
- **det-L4 gate ↔ tests + obs**: `ANDROMEDA_PULSE_L4_DETERMINISTIC` is arch-registered and is the deterministic regression arm the tests domain drives; the real arm must not disturb its registration or fixture posture.
- **Workspace crate names ↔ all domains**: `ingest` / `triage` / `xtask` placement is arch-locked for every specialist's content.

## Acceptance criteria contributions
- (arch) Sustained injector mode emits only as an external OTLP client against `:4317`/`:4318`; no in-process bypass, no test-only ingest feature flag, no mock channel is introduced (per architecture.md §Cross-cutting Patterns → Test-time telemetry injection).
- (arch) All chunk code stays inside the locked crates `ingest` / `triage` / `xtask` / `pulse-app`; no new workspace crate, no reserved-name reuse, no library→binary dependency (per architecture.md §Occupied Resources → Cargo workspace crate names; §Cross-cutting Patterns → Module dependency direction).
- (arch) The feed-precondition assertion reads the contracted `ready` check `rows_ingested`; the `ready` envelope's field set is unchanged (per architecture.md §Standard Contracts → Tauri IPC readiness).
- (arch) The real-L4 leg runs the b9305-pinned prebuilt `llama-cli.exe` resolved through the registered `ANDROMEDA_PULSE_LLAMA_{CUDA,CPU}_BIN_PATH` pair with the det-L4 gate off, bumping no pin and settling no distribution question; every env var the leg relies on is either already in §Occupied Resources or registered at wrap (per architecture.md §Established Decisions → [LLM Inference Runtime]; §Occupied Resources → Environment variables).
