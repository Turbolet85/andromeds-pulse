## Relevance
**Partial** — the headline real-L4 leg and legs 2a/2c/4b sit squarely in obs (agent-log reader family, feed-precondition signal, sustained-run SLO + hot-path discipline, incident-path allowlist leaves); legs 3, 4a and 4c touch obs only at their edges.

## Constraints
- The self-observation sink is a **daily-rotated family**, not a fixed filename — `rolling::daily` date-suffixing plus the "previous day's file if the current one does not yet exist" case are both mandated, so any reader of the agent log must resolve the family (per obs-plan §3 *Log file location*). CARRY 4b's three bare-name readers are exactly this class; whether each already globs is research's question.
- The log-line shape is a **binding contract taken verbatim from the tests harness contract** — obs aligns to tests, not the reverse — with `timestamp` / `level` / `target` / `message` / `fields` required on every line (per obs-plan §3 *Log format JSON schema*, restated §6 *Required fields*). Any smoke recipe that greps the log must key on `target` + `fields`, one JSON object per line.
- Any xtask check script reading the agent log must be **NEUTRAL-tolerant** (an absent signal stream is not a failure) and scoped to the run window, so headless and full-app sessions share one script set (per obs-plan §10 *Load-profile constraints*). A sustained injector leg is precisely the "full-app session" half of that pair.
- The always-on SLO gates apply to any sustained run this chunk performs: zero unlogged panics (`app.panic.fatal`), no >45 s gap between consecutive ticks for `ingest.tick` / `buffer.tick` / `viz.tick` / `plugins.tick`, and "zero spans in the log = instrumentation missing, fail" (per obs-plan §10 *Always-required SLO invariant* + *CI gates*).
- Sustained / continuous emission must not be paid for with per-record logging: per-span-event emission is barred and hot paths must not log at `info` (per obs-plan §11 *Telemetry Strategy* + *Logs*). Volume-scaling counters ride the existing 15 s tick as fields (per obs-plan §5 *Counter (monotonic, tick-aggregated as FIELDS)*).
- Injector-generated telemetry is **external OTLP client data** and is governed by Vector 1: only `attributes_count` + `service_name_tag` may reach the self-observation log, and the two surfaces (DuckDB-held external data vs. the JSON log) must never be conflated (per obs-plan §8 *Data classification rules* + §11 *Project-specific*). "Unique-enough content" in 2a must vary payload identity without routing payload values into `agent-latest.jsonl`.
- `interpretation.model.load` → `inference_mode` is recorded on the **muted-diagnostic backlog** — redacted in production, owned by the "Diagnostics un-muting + harness-truth sweep" route entry, not by this chunk (per obs-plan §8 *Muted-diagnostic backlog*). The real-L4-vs-det-L4 arm distinction therefore cannot be evidenced by that field unless the leg first establishes its current state; whether it is still muted at HEAD is research's question.

## Patterns to follow
- **Positive-liveness reading, not inferred-from-silence** — §1 *Heartbeat ticks* / §5 feed-counter row exist so that a live feed reads as a POSITIVE field rather than being inferred from a downstream zero. This is the exact template for leg 2c: assert the producer's own counter before judging any consumer counter. `rows_ingested` is an allowlisted `buffer` field on `buffer.tick` (per obs-plan §1 *Heartbeat ticks*, §8 `buffer` whitelist).
- **Tick vs. `health` complementarity** — the async 15 s tick (retroactive log analysis) and the synchronous `health` command (active liveness probing) are complementary and must not be conflated (per obs-plan §3 *Complementarity with the `health` command*). A smoke recipe may read either, but must name which.
- **EXACT allowlist leaf per target, guard where it runs** — every emitting target gets its own leaf enumerating *every* field its emit site emits; no bare prefix key for the `triage` / `incidents` / `interpretation` / `corpus` families; for `metric.*` the rule is per-target-own-leaf rather than no-bare-prefix (per obs-plan §8 *Default-deny posture*). Guard tests live under `pulse-app/tests/`, never `observability.rs`'s own `mod tests` (`[lib] test = false` compiles but never runs), and are mutation-checked.
- **Incident-formation evidence comes from landed leaves** — `interpretation.incident.created`, `incidents.list_active.request`, `triage.incident.persist` are registered EXACT leaves with enumerated fields (per obs-plan §8 *Incident-path diagnostic leaves* + `interpretation.incident.created` entry). The headline leg's "an incident forms" claim should be evidenced from these targets in the agent log.
- **Restating-site discipline** — the `buffer.tick` field set is stated at three sites (§1 *Heartbeat ticks*, §5 instrument-type table, §8 `buffer` whitelist); a change to it that lands at only one leaves the master internally stale (per obs-plan §5/§8 and the 2026-08-22 amendment).

## Anti-patterns to avoid
- Never buy sustained-mode throughput visibility with per-record or per-span-event emission, and never log on a hot path at `info` (per obs-plan §11 *Telemetry Strategy* + *Logs*).
- Never let injected demo payload values (attribute values, span content) reach `agent-latest.jsonl`, and never conflate the external-OTLP surface with the self-observation surface (per obs-plan §11 *Spans / Traces* + *Project-specific*, Vector 1).
- Never soften an SLO gate to make a long sustained run pass — soft/unenforced budgets and any relaxation of the zero-unlogged-panics invariant are banned outright (per obs-plan §11 *SLO*).

## Contract bindings
- **obs ↔ tests (harness contract):** the log-line JSON schema is inherited verbatim from the tests Test Harness Contract, so a doc/spec edit under leg 3 or a recipe edit under 2b/2c must not restate the shape divergently (obs-plan §3 *Log format JSON schema*, §6).
- **obs ↔ tests (smoke):** heartbeat presence and the `buffer.tick` field set are what a smoke asserts liveness from; leg 2c's `rows_ingested > 0` precondition is the obs-side half of that binding (obs-plan §1 *Heartbeat ticks*, §8 `buffer` whitelist).
- **obs ↔ tests (CI scripts):** NEUTRAL-tolerance + run-window scoping is an obs-side rule that every xtask check script over the agent log inherits (obs-plan §10 *Load-profile constraints*).
- **obs ↔ a11y:** the a11y CI gate's grep-based PII heuristics are governed by the UI-vocabulary exemption — secret *formats* by regex, never UI-label words (obs-plan §8 *UI-vocabulary exemption*). Bears on CARRY 4c if the `lint:a11y` rules move into `eslint.config.mjs`.
- **obs ↔ security:** Vectors 1 and 5 (raw OTLP values, query parameters) are the scrubbing rules the injector's sustained payloads and any new smoke query must respect (obs-plan §8 *Data classification rules*).

## Acceptance criteria contributions
- Every agent-log reader touched by the chunk resolves the rotated family (`agent-latest.jsonl*`, newest-first, previous-day fallback) rather than a bare filename (per obs-plan §3 *Log file location*).
- Each documented smoke recipe asserts the producer-side feed precondition (`rows_ingested > 0` on `buffer.tick` / `health`) before any downstream counter is judged, so "producer never ran" is distinguishable from "feature broken" (per obs-plan §10 *CI gates* zero-spans rule + §1 *Heartbeat ticks*).
- The sustained real-L4 run's agent log contains zero `app.panic.fatal` records and no >45 s gap between consecutive ticks for any tick target over the run window, with any check script reporting NEUTRAL — not FAIL — for streams absent in that configuration (per obs-plan §10 *Always-required SLO invariant*, *CI gates*, *Load-profile constraints*).
- No injected demo attribute value or synthetic payload content appears in `agent-latest.jsonl`; only aggregate/bounded fields do (per obs-plan §8 Vector 1 + §11 *Logs*).
