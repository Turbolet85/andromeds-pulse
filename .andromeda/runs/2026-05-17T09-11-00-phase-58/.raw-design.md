## Constraints

- The `priority_tier` enum variants emitted on the broadcast (Hard / Medium / Baseline) MUST map cleanly к the project's three-state visual taxonomy (anomaly / warning / nominal) so downstream UI can mechanically pick the rendering color without translation: Hard → Alert Burgundy `#C7556A` (anomaly hue), Medium → Earth Blue emphasis `#4A90E2` (60% opacity / focus), Baseline → Status White-Blue `#E8EEF7` text on Base surface (nominal-context). The emitter MUST NOT serialize hex values in the cue payload — only enum variants (per design-system.md §Color Palette Semantic Colors + §Anti-Patterns Universal Bans "color purely for decoration"; rendering color is the UI consumer's lookup, not the backend's responsibility).
- Cue payload fields driving display strings (titles / descriptions / detail) MUST stay locale/typography-neutral content — no embedded ANSI codes, no embedded hex values, no embedded units (e.g., "1500ms" inline) that would force a downstream renderer to either parse-and-restyle or violate the JetBrains Mono / IBM Plex Sans split. If a numeric value (latency_ms / error_rate) is part of the cue, it MUST be a structured field (e.g., `evidence.value: f64 + evidence.unit: &str`), not pre-formatted text (per design-system.md §Typography "Monospace signals 'immutable telemetry fact'" — splits encode domain semantics; pre-baked strings collapse the split).
- The 1-2s tick cadence MUST NOT couple к the Halo State Pulse rhythm (0.8–2.4 Hz, data-driven from throughput_hz / 1000) — these are independent dimensions. The chunk MUST emit cues on its own schedule regardless of canvas pulse phase; downstream UI handles visual coalescing if needed (per design-system.md §Motion "Canvas motion ... is a separate dimension ... NOT bound by the chrome expression number").
- `cadence-triggers` channel emit (Tier-2 cues only) is a backend coordination contract for chunk #72 — the design domain has no surface for this channel today; the chunk MUST keep it strictly backend-internal (no broadcast topic name leaking к webview via `pulse://stream/*` until a separate UI-facing chunk justifies it; backend-only protects the chrome surface from accidental cue-storm rendering — per design-system.md §Brand Identity "minimal chrome ... data-driven and never decorative").

## Patterns к follow

- Per design-system.md §Color Palette Semantic Colors: the four-row taxonomy (Success / Warning / Error / Info) is the canonical state→color contract. `priority_tier` Hard maps onto the Error/Warning row (border `#C7556A`), Medium onto Info row (border `#4A90E2`), Baseline onto nominal-text-on-Base (no border). The emitter does NOT name colors; it names tiers and lets the UI consumer apply the table.
- Per design-system.md §Anti-Patterns Rejected Defaults "Uniform monochrome status icons (green checkmark / red X)" rejection: the cue payload SHOULD provide enough structured signal (priority_tier + magnitude + confidence + kind) for downstream rendering to encode TWO independent dimensions (priority via color, magnitude/rate via Halo pulse frequency or alternate visual). Flat boolean "is_critical" alone defeats this rejection — keep the payload multi-dimensional.
- Per design-system.md §Surface: desktop-webview Component Patterns "Loading / Empty States": when no cues are active (Baseline-only stream), downstream UI defaults to nominal/empty rendering; the emitter SHOULD emit Baseline cues sparingly (or with explicit `kind` discrimination) so empty-state semantics survive — flooding the broadcast with low-priority Baseline cues degrades the "no cues = nominal" visual signal.

## Anti-patterns к avoid

- NEVER embed pre-formatted color hex / Tailwind class names / token names into the `AttentionCue` payload. The cue is a domain event, not a render hint — backend ↔ UI separation requires the UI to map `priority_tier` к design tokens via the design-system.md §Color Palette Semantic Colors table, not pull them off the wire (per design-system.md §Anti-Patterns Universal Bans "NEVER use color purely for decoration. Every color in the palette communicates meaning").
- NEVER name a `priority_tier` variant after a banned default ("delightful" / "warning-soft" / "critical-bold" / etc.) — the locked taxonomy is Hard / Medium / Baseline per the chunk text + P-019 contract; introducing softer wording dilutes the Mission Control state-confirming voice (per design-system.md §Brand Identity "contemplative tone rejects the 'delightful' framing in favor of 'state-confirming' motion").
- NEVER let the emitter's 1-2s tick cadence indirectly drive UI animation durations (e.g., by encoding a "duration_ms" hint in the payload that downstream renderers blindly apply). All chrome animation is 150–200ms ease-out per design-system.md §Motion duration scale (0.3–0.35 expression band); Halo pulse cycles are data-driven 0.6–1.2s per breath from canvas layer. Cue-arrival → animation pairing is the downstream UI's decision, bounded by chrome budget.
