## Anti-patterns к avoid

- NEVER convey clipboard-success or generation-error by color alone — pair `--color-feedback-success` with checkmark icon + text label; pair `--color-accent` (error) with icon + sanitized message text per SC 1.4.1 (a11y plan §11 Visual row 1 + §6 State color tokens not-color-alone).
- NEVER expose stack-traces / file-system paths / library versions / Rust struct names in the user-visible error string emitted to the alert region — `AppError::Internal { message }` is a sanitized one-liner per security ↔ a11y boundary; the alert text is the same string. Stripping is enforced upstream but a11y test asserts the rendered alert text contains no `\\.rs:` / `at line ` / canonicalized paths (per a11y plan §11 Screen Reader row 1 + obs hygiene; cross-references security rules.md error sanitization).
- NEVER fire-and-forget clipboard write without an `aria-live="polite"` user-visible confirmation — silent clipboard mutation is both a security hygiene gap (snapshot/clipboard hygiene from security rules) AND an SC 4.1.3 Status Messages a11y gap (a11y plan §7 Live regions row 1 + §11 Screen Reader row 1).
- NEVER ship `outline: none` on the new Generate trigger / preset-prompt buttons / close button without replacement — SC 2.4.7 Focus Visible requires the `--border-focus` token outline on `:focus-visible` (per a11y plan §11 Keyboard row 2).
- NEVER set `aria-hidden="true"` on the result-state region after async resolution (it must remain in the SR a11y tree); axe-core `aria-hidden-focus` would catch focusable hidden but the deeper bug is announcement loss (per a11y plan §11 Screen Reader row 1).
