## Constraints

- Result-state UI (InvestigationModalForm post-`snapshot.generate`) MUST use only `@theme` tokens — `--color-raised-3` (#343A45) for modal background, 1px subtle/emphasis border per Border Progression, `--radius-lg` (8px) for modal container, `--spacing-md` (16px) padding (per design-system.md §Depth Strategy Modal elevation + §Surface: desktop-webview Component Patterns Cards/Panels + §Border Radius radius-lg).
- PresetPromptList MUST render preset prompt buttons using Secondary button pattern (`--color-raised-1` background, `--color-text-primary`, 1px subtle border, `--radius-sm` 4px, padding `--spacing-sm`/`--spacing-xs`) — not Primary (Primary `#4A90E2` is reserved for the "Investigate" action itself, not for downstream picker affordances) (per design-system.md §Surface: desktop-webview Component Patterns Buttons + §Color Palette Primary usage row).
- Result-state success copy MUST use Feedback Cyan `#17B3A3` as border + accent (e.g., "Snapshot ready — X bytes copied"), NEVER Primary Earth Blue; success state is sparingly-used confirmation per §Semantic Colors Success row (per design-system.md §Color Palette Semantic Colors + Rejected Defaults "Feedback Cyan used sparingly for confirmation states").
- Investigation Capture Collapse supporting moment MUST be preserved across the result-state transition — the 350ms scale+opacity ease into the centered snapshot object is the visual handshake for `snapshot.generate` invocation; the result-state UI emerges INSIDE that collapsed object (not as a separate fade) (per design-system.md §Motion High-impact moments item 2 + §Design Decisions Log 2026-05-02 "Investigation Capture Collapse supporting moment is the visual handshake for this action").
- ALL motion (capture collapse, button hover, error-state border shift) MUST respect `prefers-reduced-motion: reduce` — collapse degrades to instant transition (350ms → 0ms); button hover (150ms) → 0ms; no spring/bounce easing (per design-system.md §Motion Accessibility + §Motion Hard limits "NO spring physics or bounce easing").
- Error-state surface (failed `snapshot.generate`) MUST use Alert Burgundy `#C7556A` border at 50% opacity + error message text in `--color-text-primary` (NOT in `#C7556A` for body text per a11y SC 1.4.1 / SC 1.4.3 normal-text 4.5:1 — accent is non-text-token classification) (per design-system.md §Surface: desktop-webview Input Fields Error state + §Design Decisions Log 2026-05-03 Lift `--color-accent` "usage scope refinement: accent is now formally classified as a non-text token").
- Notification copy ("Snapshot ready | X tokens, N spans") MUST be terse, 2 lines max, contemplative observational voice — NOT "Snapshot exported successfully!" or marketing tone (per design-system.md §Surface: desktop-native Notifications + Tray Menu Tone "Generate Snapshot not Export Data").

## Patterns to follow

- Modal primitive scaffold pattern (chunk #36): result-state UI overlays the existing InvestigationModalForm — `--color-raised-3` background + 1px subtle border + `--radius-lg` padding + close button → reuse the existing modal shell rather than re-implementing (per design-system.md §Surface: desktop-webview Component Patterns Modal elevation + chunk #36 modal primitive scaffold lineage).
- Telescope iconography (`<Icon glyph="telescope" />`) is the established glyph for "investigate" — result-state UI can reuse the same glyph at 20px or 24px (button context vs hero/heading context) for visual continuity with the trigger button on widget/main/context-menu/trace-row (chunk #42 Investigate trigger surfaces) (per design-system.md §Iconography Primary custom set "telescope (for investigate)" + §Iconography Size grid).
- Loading/empty/error state patterns are already specified for the webview surface — apply them verbatim to the result-state UI: skeleton pulse `#262A33` (Raised-1) with discrete 50ms on/off opacity, error icon + 2-line message in `--color-text-primary`, telescope empty-state icon at 24px (per design-system.md §Surface: desktop-webview Component Patterns Loading/Empty States).
- Form-style preset prompts (PresetPromptList) follow the Input Fields pattern for selected-state visual: `--color-inset` (#0F1117) recessive background + emphasis border (`rgba(74, 144, 226, 0.6)`) on the currently-active preset; tabular Label typography (IBM Plex Sans 500/12px) for the preset titles (per design-system.md §Surface: desktop-webview Input Fields + §Typography Label row).
- Notification + clipboard hygiene visual handshake: emit `pulse://stream/snapshot-progress` event at clipboard-write time so UI shows non-suppressible "X bytes copied" confirmation in the result-state UI (per design-system.md §Surface: desktop-native Notifications Format "terse, 2 lines max" + binds to security plan snapshot/clipboard hygiene rule).
- Self-Validation Protocol Token Test (check 4) applies before commit: every color / spacing / radius value in the new UI traces back to the Color World + spacing scale + font stack — no magic numbers (per design-system.md §Self-Validation Protocol Token Test).

## Anti-patterns to avoid

- NEVER use gradients, glassmorphism, or shadow-based depth on the result-state modal or PresetPromptList — chrome stays flat/matte; only the Halo State Pulse (NOT involved in this chunk) is the gradient/blur exception (per design-system.md §Anti-Patterns Universal Bans "NEVER use gradient overlays or glassmorphic effects on the dashboard chrome").
- NEVER use bounce easing, spring physics, or opacity fades >200ms for chrome transitions in the result-state UI — the 350ms Investigation Capture Collapse is the ONLY budgeted supporting moment and must use scale+opacity ease, not bounce (per design-system.md §Motion Hard limits + Rejected Defaults "Animated state transitions using bounce easing and 500ms+ durations").
- NEVER use generic fonts (Inter, Roboto, system-ui, Space Grotesk) anywhere in PresetPromptList or result-state UI labels — IBM Plex Sans for UI text, JetBrains Mono ONLY for data values like the byte count / span count in the success line (per design-system.md §Anti-Patterns Universal Bans banned fonts + §Typography role split).
- NEVER use `alert()` / `confirm()` / `prompt()` for the success/error states — use the existing styled modal pattern with `--color-raised-3` background (per design-system.md §Surface: desktop-webview desktop-webview Per-Surface Bans "NEVER use alert/confirm/prompt").
- NEVER use color alone to communicate result-state success vs. failure — Feedback Cyan border + checkmark/telescope icon + text label "Snapshot ready" (success) vs Alert Burgundy border + error icon + text label (failure); state must be conveyed by AT LEAST color + icon + text (per design-system.md §Anti-Patterns Universal Bans "NEVER use color purely for decoration" + cross-binds to a11y SC 1.4.1).

- **Design ↔ a11y (not-color-alone)**: result-state success/error must pair color (Feedback Cyan / Alert Burgundy) with icon AND text label; design provides token + icon glyph, a11y verifies SC 1.4.1 conformance via axe-core / pa11y assertions (per design-system.md §Color Palette Semantic Colors + §Rejected Defaults "Uniform monochrome status icons rejected because Halo State Pulse encodes TWO independent dimensions" — same not-color-alone principle applies to all state encoding).
- **Design ↔ a11y (motion / reduced-motion)**: Investigation Capture Collapse 350ms + button hover 150ms + result-state emergence must collapse to instant under `prefers-reduced-motion: reduce`; design specifies motion tokens, a11y verifies media-query branching exists in CSS / animation logic (per design-system.md §Motion Accessibility + binds to a11y SC 2.3.3 AAA).
- **Design ↔ a11y (contrast)**: result-state UI text on `--color-raised-3` (#343A45) modal background must clear SC 1.4.3 4.5:1 for normal text — `--color-text-primary` #E8EEF7 on #343A45 ≈ 7.8:1 PASS; `--color-text-secondary` #B4BCCB on #343A45 ≈ 6.0:1 PASS; design provides token target ratios, a11y verifies via chunk #12 contrast-verification harness (per design-system.md §Text Hierarchy + §Downstream Readiness "For a11y specialist: Contrast targets see Text Hierarchy table").
- **Design ↔ obs (clipboard-write event UI surfacing)**: design specifies the non-suppressible "X bytes copied" visual confirmation in the result-state UI; obs (and security snapshot/clipboard hygiene) requires the `pulse://stream/snapshot-progress` emit at clipboard-write time — UI subscribes to the event and renders the confirmation banner using Feedback Cyan + text + telescope icon (per design-system.md §Surface: desktop-webview Component Patterns + binds to security plan Snapshot/clipboard hygiene rule).
