# design extract

## Relevance
**Partial** — the chunk builds no UI surface, but three of the four delegated timing caps it must assert (P-025 halo hue, P-027 constellation discovery, P-045 counter refresh) grade design-owned signature behavior, and the design plan's obs handoff defines the measurement hooks those caps would be read through.

## Constraints
- The halo's hue axis is driven by **cumulative incident severity**, LCH-interpolated between Earth Blue `#4A90E2` and Alert Burgundy `#C7556A`; connection state is an **orthogonal grayout/desaturation axis**, independent of the severity-hue axis (per design-system.md §Brand Identity signature element, §Motion high-impact #1). A P-025 ≤2 s assertion must grade the severity axis, not throughput/error-rate — whether the code currently drives hue from severity or from the superseded pre-2026-05-29 model is research's question.
- Halo modulation is **opacity + blur ONLY, never scale** (P-026), blur 4–16 px per cycle, breathing period 4–5 s quiet → ~2 s active (≈0.2–0.5 Hz, well under SC 2.3.1's 3 Hz) (per design-system.md §Motion). Breathing period encodes the *activity* dimension and is not a proxy for hue latency; a harness must not conflate the two axes.
- Under `prefers-reduced-motion: reduce` the halo degrades to a **static glow whose hue still updates per severity**; other transitions collapse to 0 ms (per design-system.md §Motion → Accessibility). The ≤2 s hue cap therefore must hold in both motion modes.
- **Entrance animations: none; no staggered reveals** (per design-system.md §Motion → hard limits). A newly discovered service dot renders instantly, so P-027 ≤5 s is pure data-arrival latency with no animation budget folded in.
- Canvas motion (Halo State Pulse, Latency River, **throughput counter**) is a separate dimension exempt from the chrome expression budget (per design-system.md §Motion preamble); any DOM-side numeric readout refreshed at ≤1 s must use the Data role — JetBrains Mono 12px, tabular-nums — so a P-045 refresh does not jitter column widths (per design-system.md §Typography).
- State is **never conveyed by color alone**; every palette color communicates meaning and pairs with a label/icon (per design-system.md §Anti-Patterns → Universal Bans, §Color Palette accent note). This is also the design plan's own reason a non-color numeric mirror of halo state must exist — which is precisely what an external harness can assert against.
- Halo state values must trace back to the palette and documented envelopes; random hex or magic numbers signal no system (per design-system.md §Self-Validation Protocol #4 Token Test).

## Patterns to follow
- **Halo measurement-hook pattern** (design specifies intent, obs emits): log halo **pulse frequency in Hz** per cycle, derived from activity state by the data-viz layer and logged **as-is without re-clamping**, plus **halo color state** (Earth Blue / Alert Burgundy / interpolated LCH value) on each pulse — per design-system-amendments.md §Downstream Readiness (For obs specialist). This is the plan's designated surface for reading halo state externally; whether it is emitted today is research's question (scope P3 Q3).
- **Canvas-outside-React**: halo / Latency River / counter render directly to canvas, not inside React's render tree (per design-system.md §Surface: desktop-webview → Performance notes). Implication for P3 Q3: halo hue is not DOM-assertable by construction, so the gradeable surface must be a logged or IPC-carried value.
- **Numeric non-color mirrors of the same state already specified**: compact-widget read-only footer `Ingest: {spans/sec}` / `Retention: {min}` / `Error rate: {%}` (§Surface: desktop-webview → Navigation Pattern) and tray Summary line `Ingest: … | Error: % | Retention: … used` (§Surface: desktop-native → Tray Menu) — candidate observable surfaces for P-045 counter refresh.
- **Verifiable-numeric-criteria pattern for halo equivalence**: the tray fallback is graded on stated numbers — blur 4–16 px per cycle, LCH interpolation fidelity ≥95 % of the `#4A90E2` ↔ `#C7556A` shift, opacity 0.6–1.0 envelope (per design-system.md §Surface: desktop-native → Tray Icon). Follow this shape when authoring halo assertions rather than "looks right".
- **A failure must never read as absence**: the error `EmptyState` variant is checked BEFORE the empty branch, with a static message and no actionable hint, so a query failure cannot masquerade as "no data" (per design-system.md §Surface: desktop-webview → Loading / Empty States). Same defect shape as this chunk's precondition (empty `evidence_refs` making an absence check pass for the wrong reason).

## Anti-patterns to avoid
- **Do not reduce halo state to a binary/monochrome status proxy** (green checkmark / red X) to make it assertable — explicitly rejected because the halo encodes two independent dimensions, activity rhythm and severity hue (per design-system.md §Anti-Patterns → Rejected Defaults).
- **Do not grade against the superseded halo formula** (0.8–2.4 Hz clamped `throughput_hz / 1000`, hue from error rate) — superseded by the severity/activity/connection model (per design-system.md §Motion; amendment 2026-05-29).
- **Do not add motion to make state observable** — no scale modulation on the halo, no entrance/scroll/spring/staggered animation, no opacity fade > 200 ms (per design-system.md §Motion → hard limits).

## Contract bindings
- **design ↔ obs**: halo pulse-frequency and color-state hooks per design-system-amendments.md §Downstream Readiness (For obs specialist) — design owns the measurement intent and value semantics, obs owns emission and backend. This binding is the likely answer path for scope P3 Q3 (which Pulse-side surfaces expose the four caps at all).
- **design ↔ a11y**: hue-only conveyance is banned (SC 1.4.1) and the reduce-motion override is mandatory (SC 2.3.3, with 0.2–0.5 Hz keeping SC 2.3.1 headroom) — so the ≤2 s hue cap must be assertable in the reduce-motion path too, per design-system.md §Motion → Accessibility.
- **design ↔ tests harness**: motion lint targets (durations 150/200/250/350 ms, ease-out / ease-in-out, the 7 hard-limit bans) and Component-Patterns value verification against the Color Palette / Spacing tables, per design-system-amendments.md §Downstream Readiness (For tests specialist) — the assertion vocabulary an external harness should reuse rather than invent.
- **design ↔ external instrument (Conductor)**: if Conductor encodes halo semantics in its assertions, they must encode the post-2026-05-29 severity model and the current `#C7556A` endpoint; any such re-alignment is executed in that repo only, per scope §Boundaries ("never from here").

## Acceptance criteria contributions
- (design) A P-025 halo-hue assertion grades the cumulative-incident-severity LCH axis between Earth Blue `#4A90E2` and Alert Burgundy `#C7556A`, with connection-state grayout treated as an independent axis — never throughput or error rate (per design-system.md §Motion / §Brand Identity).
- (design) The ≤2 s hue-update cap holds with `prefers-reduced-motion: reduce` active, where the halo is a static glow whose hue still updates per severity (per design-system.md §Motion → Accessibility).
- (design) Whatever value the harness reads for halo state traces to palette tokens and the documented envelopes (LCH endpoints, blur 4–16 px, opacity 0.6–1.0, ≈0.2–0.5 Hz) with no arbitrary magic values (per design-system.md §Self-Validation Protocol #4 Token Test).
- (design) P-027 ≤5 s discovery is measured with no entrance animation in the path (instant render is mandated), and any DOM-side readout used to observe P-045 ≤1 s uses the Data role JetBrains Mono 12px with tabular-nums (per design-system.md §Motion → hard limits, §Typography).
