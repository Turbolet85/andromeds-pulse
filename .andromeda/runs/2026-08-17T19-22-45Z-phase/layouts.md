# layouts extract

## Relevance
**Partial** — this chunk builds no surface, but three of its four delegated timing caps (P-025 halo hue, P-027 constellation discovery, P-037 report render, P-045 counter refresh) name surfaces whose owning regions/components are defined by my plan, so layouts fixes *where* each cap's observable lives.

## Constraints
- P-025's halo hue is defined as an LCH interpolation `color-primary` → `color-accent` driven by **error rate**, rendered on the WebGPU canvas layer (unified badge halo on the compact widget, per-service dot halos on the dashboard Traces hero) — layout-templates.md §Signature placement + §Component — Halo State Pulse canvas require the hue live on that canvas layer, not in chrome or text. Whether that layer has any non-pixel observable an external harness can read is research's question.
- P-027's constellation-discovery observable is per-service dots in the **fixed (`flex-shrink:0`) hero region** of the Traces primary screen, one dot per service in the `traces.query` result, with always-on per-dot name + severity-token labels (per layout-templates.md §Wireframe — Full dashboard (Traces primary screen) and §Component — Halo State Pulse canvas "For each service in the constellation").
- P-037's report-render surface is required to be a **separate borderless always-on-top Report window** — the six-section `Report` in the `Modal` **`fill`** variant, edge-to-edge on `--color-base`, no backdrop, positioned left of and clamped to the findings window, opened by selecting a findings row (per layout-templates.md §Primary screens — Report window). Timing must be measured against that window, not an in-dashboard overlay.
- P-045's counter surfaces are the **full-dashboard footer**: `ConnectionStatusLine` (connected-source count, spans/s, buffer fill) plus the read-only ingest-rate / error-% readouts, mandated to live-update on a **1 s poll** with the connected count gated by P-067 live-recency (per layout-templates.md §Component — Footer (read-only status bar) → Full dashboard). A ≤1 s cap against a plan-mandated 1 s poll is boundary-tight — research should confirm the measurement point.
- The deterministic incident's disclosure path runs compact-widget unread badge → **findings window** (borderless, docked below the widget from live geometry, work-area/multi-monitor clamped, sizes to incident count, caps ~8 then scrolls, reuses P-080 FindingsDropdown row content) → report window (per layout-templates.md §Primary screens — Findings window / Report window). One deterministic incident must therefore yield exactly one selectable row.
- layout-templates.md's top-of-file scope note requires the document not be edited during implementation runs; a verification chunk that introduces no user-facing surface adds **no** wireframe, component-placement, or focus-order change.
- Reduced motion (`prefers-reduced-motion: reduce`) is required to keep the halo hue updating per error rate while the pulse becomes a static glow (per layout-templates.md §Component — Halo State Pulse canvas → Reduced motion) — so P-025's hue observable must survive a reduced-motion harness environment; the pulse frequency is not what P-025 caps.

## Patterns to follow
- **Fixed-hero + bounded route** (P-082): the Traces route is a flex column bounded to the shell's `main` height (`calc(100vh − titlebar 32px − tabnav 40px − footer var(--spacing-lg))`, `overflow:hidden`); hero + `Errors only` toolbar are fixed and only the table's own region scrolls (§Wireframe — Full dashboard (Traces primary screen), §Component — Trace data table). Harness-driven telemetry volume must not grow an outer page scrollbar.
- **Anomaly-first default order + `Errors only` `aria-pressed` toggle** above the table (P-068) — the deterministic incident's erroring rows are required to be hoisted to the top in the default unsorted order (§Component — Trace data table → Sorting / Filter toolbar), which is the natural place to confirm a driven incident is visible.
- **Read-only status bands**: compact-widget footer is `Ingest / Error / Retention` only and the widget stays aggregate-glance with no worded line; worded connection status is dashboard-only (§Wireframe — Compact widget, §Component — Footer).
- **Empty vs. error variants checked error-first** in the Metrics/Logs/Snapshots data views, empty shown only on a *settled* zero-data load and never flashed while loading (§Component — Empty / error state) — a driven run must not leave a data view in the empty branch after ingest lands.
- **Sketch-lag handoff pattern** (P-070/P-082): ASCII wireframes may lag current truth and are corrected only by a future *targeted* touch-up — not opportunistically inside an unrelated chunk (§Wireframe notes, Traces).

## Anti-patterns to avoid
- Do not add a verification-only readout, timing badge, hidden text node, or debug affordance to any user-facing surface just to make a cap gradeable — the compact widget is mandated minimalist/aggregate-glance chrome and its footer is read-only status (per §IA notes → Navigation model, §Component — Footer).
- Do not render the Diagnostic Report as a centered in-dashboard modal over a backdrop; §Primary screens — Report window mandates the separate borderless `fill`-variant window with no backdrop.
- Do not amend layout-templates.md ASCII wireframes or add a new §Component from this chunk — no new surface is introduced, and the deferred Findings/Report wireframes are explicitly a separate targeted touch-up (§Primary screens — Findings window, and the 2026-07-09 / 2026-07-10 handoff notes).

## Contract bindings
- **P-025/P-027 observables ↔ obs domain**: layouts fixes the *region* (canvas hero, per-service dot) but a WebGPU canvas layer is not text-readable by an external harness; whether an obs-log event or MCP response field exposes hue/discovery timing is scope premise 3 and belongs to obs — layouts only asserts the surface identity (§Component — Halo State Pulse canvas).
- **P-045 ↔ obs/tests cadence**: the footer's mandated 1 s poll (§Component — Footer → Full dashboard) sets the floor any ≤1 s refresh assertion measures against; harness sampling interval must be reconciled with it.
- **Report window content ↔ MCP/report domain**: the six-section Report is the layout container; which sections carry the newly-populated `evidence_refs` is the report/MCP domain's contract, and whether the code already renders them is research's question (§Primary screens — Report window).
- **Findings window geometry ↔ native/window domain**: docking from the compact widget's live geometry with work-area/multi-monitor clamping is a layout mandate implemented via native window APIs (§Primary screens — Findings window).
- **Reduced motion ↔ design Motion / a11y**: the static-glow-with-live-hue degradation is shared with design-system Motion accessibility (§Component — Halo State Pulse canvas → Reduced motion).
