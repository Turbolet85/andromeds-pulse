## Constraints
- The deterministic L4 producer, Tauri IPC bridge, OTLP receivers and DuckDB are classified **Not-assertable** for a11y, so the fix to `deterministic_inference.rs`, the MCP read-back, and Conductor's drive recipe carry **no a11y assertion obligation** — a11y does not gate the chunk's core (per a11y-plan.md §1 A11y scope table).
- The four timed surfaces sit inside the must-be-accessible set **P1–P12** (p5 compact-widget, p8 findings dropdown/counter, p9 diagnostic report modal, p11 constellation semantics), which a11y-plan.md §1 (surface-set extension, chunk #99) + §10 require to carry the universal minimums SC 2.1.1 Keyboard / SC 2.4.3 Focus Order / SC 4.1.2 Name-Role-Value and one axe spec each. Whether this chunk touches their DOM at all — vs. reading timings from the obs log / MCP responses only — is research's question (chunk premise 3).
- A timing cap asserted on a **visual transition** must not require motion to be present: a11y-plan.md §1 (A11y triggers → motion-sensitive) + §6 Motion tokens require every `--duration-*` token to degrade under `prefers-reduced-motion: reduce`, so a "hue reaches target ≤2 s" style assertion must hold both with motion and with motion disabled (SC 2.3.3 AAA escalation).
- Whatever state the caps time (halo hue, counter value, constellation status, report readiness) must be conveyed by **color + text/icon**, never color or motion alone — a11y-plan.md §6 State color tokens (SC 1.4.1) and §11 Motion ("NEVER use motion as ONLY signal"). Whether those surfaces already carry the text/icon supplement is research's question.
- If the chunk adds any webview readout to make a cap observable, a11y-plan.md §7 Live regions requires `role="status"` / `aria-live="polite"` for non-blocking updates, and §1 Critical Paths P4 requires that live updates **not steal focus** from the current keyboard target.
- Any DOM/CSS change (including instrumentation hooks or data attributes that alter rendered markup) re-arms the hard gates in a11y-plan.md §10: zero new WCAG AA violations vs base branch, Lighthouse a11y ≥ 90, keyboard focus-order pass, contrast token-pair pass — compared against `baselines/a11y-violations-summary.json` per §3 Harness wiring & conventions (clean pass = 0 violation tuples).
- a11y-plan.md §2 (agent-runnable invariant) + §11 CI forbid the exact failure shape this chunk's CARRY names: a conformance claim without machine-verifiable evidence behind it. A green chain is not evidence unless the assertion is shown to be non-vacuous.

- Per-surface axe spec pattern at `D:\dev\projects\andromeda-pulse\pulse-app\ui\tests-a11y\axe\` (p1–p13 specs), with the Tauri IPC mocked through `helpers/mock-tauri.ts` on the `TauRPC__<router.path>` command shape and payloads in `helpers/v02-fixtures.ts` — the established channel for rendering a deterministic incident fixture in the webview (a11y-plan.md §3 Harness wiring & conventions).

- Reduced-motion assertion pattern: `page.emulateMedia({ reducedMotion: 'reduce' })` then assert computed `transition-duration` / `animation-duration` = 0s and that state remains conveyed statically — `tests-a11y/reduced-motion.spec.ts` (a11y-plan.md §3 Reduced-motion assertion + §6 Motion tokens).
- Structured violation/measurement JSON in obs Section 6 record shape (`wcag_criterion` / `violation_type` / `severity` / `surface` / `selector` / `remediation` / `tool` / `tool_result_id`, plus optional `measured_value` / `required_value`) emitted to `~/.andromeda-pulse/logs/` — the existing precedent for a numeric measured-vs-required pair in a machine-gradeable log record (a11y-plan.md §3 Structured violation JSON schema).
- The a11y harness taps the tests' **5-command E2E session** (`boot` / `run` / `status` / `cleanup` / `logs`) rather than owning its own lifecycle (a11y-plan.md §3 Focus management test harness → contract binding); an external instrument launching pulse-app must not collide with that shared lifecycle.

## Anti-patterns to avoid
- NEVER express a cap in a way that depends on motion being enabled, or measure only the animated path — a11y-plan.md §11 Motion ("NEVER use motion as ONLY signal"; "NEVER autoplay motion without `prefers-reduced-motion: reduce` respect").
- NEVER treat a passing a11y/e2e chain as conformance evidence without machine-verifiable output behind the assertion — a11y-plan.md §11 CI + §2 agent-runnable invariants.
- NEVER retry-once, soft-gate, or defer an a11y failure surfaced while closing this chunk — a11y-plan.md §11 SLO + §10 Build/deploy failure conditions (hard gates only).

## Contract bindings
- **a11y ↔ obs:** a11y violation/measurement records must use the obs Section 6 structured-log shape (a11y-plan.md §3 Structured violation JSON schema). If this chunk lands timing observables in the obs log for the four caps, that same record shape (`measured_value` / `required_value`) is the precedent a11y assertions would later read.
- **a11y ↔ tests:** a11y runs in the same `ci.yml` pipeline and reuses the tests' E2E driver; commands `npm run test:a11y` / `cargo xtask test:a11y` (a11y-plan.md §3 CI integration + §9). An external instrument driving pulse-app must leave that boot/cleanup contract intact.
- **a11y ↔ design:** the halo-hue and counter-refresh caps time transitions governed by `--duration-fast` / `--duration-standard` / `--duration-investigation-collapse` and the state color tokens, so any cap value must be consistent with those durations **and** their reduce-motion override (a11y-plan.md §6 Motion tokens + State color tokens).
