# arch extract

## Relevance
Relevant — arch owns the workspace placement of the deterministic L4 producer, the MCP read-back envelope, the reserved `ANDROMEDA_PULSE_L4_DETERMINISTIC` gate, the OTLP-only e2e-drive discipline, and the two cross-process resources (`run/workspace-key`, corpus cell key) the read-back path depends on.

## Constraints
- **Producer placement + trait boundary.** The deterministic runner is a third impl behind the unchanged `pub trait LlmInferenceRunner` at `crates/interpretation/src/contract.rs`, living in the `pulse-app` binary crate; the swap boundary is the trait and only concrete impls change (per architecture.md §Established Decisions [LLM Inference Runtime — L4 interpretation layer]). Dependencies flow toward `pulse-app` and no library crate may depend on it, so any canned-fixture shape that must be shared belongs in the `interpretation` contract module, not in `pulse-app` (per architecture.md §Cross-cutting Patterns > Module dependency direction; §Conventions > Module visibility discipline).
- **The mode gate is already a reserved resource.** `ANDROMEDA_PULSE_L4_DETERMINISTIC` is registered as a truthy gate (`1|true|yes`, default false) with a bounded parse following the `crates/mcp-server/src/feature_gate.rs` pattern, consumed at `pulse-app` boot by `pulse-app/src/deterministic_inference.rs`; arch requires that any *additional* env var this chunk lands be registered at wrap (per architecture.md §Occupied Resources > Environment variables).
- **The e2e drive must speak OTLP on the reserved ports.** Arch requires end-to-end tests to inject synthetic spans/metrics/logs over `:4317` (gRPC) or `:4318` (HTTP) — the same surface external SDKs use — with no in-process test-mode bypass, no separate "test ingest" feature flag, and no mock-channel back-door; non-default ports resolve via `ANDROMEDA_PULSE_OTLP_GRPC_PORT` / `ANDROMEDA_PULSE_OTLP_HTTP_PORT` (per architecture.md §Cross-cutting Patterns > Test-time telemetry injection).
- **MCP read-back envelope is spec-fixed and feature-gated.** The read-back tools are 4 of the 8 registered `#[tool]` methods (`query_incident_list` / `retrieve_report` / `retrieve_telemetry_slice` / `mark_incident_resolved`), framed as JSON-RPC 2.0 over stdio with no project-specific envelope, errors as standard JSON-RPC error objects with stable numeric `code`; the surface exists only under `--features mcp-server` (off by default) plus `ANDROMEDA_PULSE_MCP_ENABLED=true`, served by the `andromeda-pulse-mcp` sidecar process (per architecture.md §Standard Contracts > MCP server; §Conventions > External wire — MCP server + Error response schema (MCP); §Cross-cutting Patterns > Feature-gate hygiene; §Occupied Resources > Process / service identity).
- **Any field graded across the boundary must be `Serialize`-able.** Arch requires every type that crosses the TauRPC bridge or appears in an MCP tool response to be `serde::Serialize`, enforced by the bridge/tool derive macros — this governs whether populated `evidence_refs` can actually reach the tool response the acceptance grades on (per architecture.md §Cross-cutting Patterns > Cross-bridge data shape).
- **The two cross-process read-back preconditions are arch-registered resources.** `run/workspace-key` is required to be published by the app at boot (atomic `.tmp`+rename, canonicalize-and-confine) and read by the sidecar bounded at ≤4096 bytes as an opaque filter string never joined as a path; `corpus/corpus.db` cell payloads are required to be AES-256-GCM with the key sourced from the OS credential store (opt-in `ANDROMEDA_PULSE_CORPUS_PASSPHRASE` BLAKE3 fallback), degrading to absent rather than inventing a key (per architecture.md §Occupied Resources > Filesystem locations; §Occupied Resources > Corpus SQLite database / schema names > At-rest posture). Whether the app+sidecar pair already satisfies both mandates end-to-end on this host is research's question — the scope's "two blockers removed" claim rests on it.
- **Fault identity is consumed, not redefined — and arch already constrains what the canned output can grade.** L1 TOKEN-LEADING normalization and L2 coalesce-on-`(kind, scope, scope_id)` are both decided; arch explicitly records `L4Output.fingerprint` as model-authored and **a constant under the deterministic runner**, which is why keying dedupe on it was REJECTED. Arch also records that the L1 fingerprint reaches **no viz / MCP / UI rendered surface** (the webview `IncidentRecord` view drops it, `PreviouslySeenMatch` omits it, `span_events.fingerprint` is never SELECTed) — so a fidelity assertion cannot assume fingerprint visibility on the MCP boundary without research confirming a consumer (per architecture.md §Established Decisions [Fault Identity — what makes two faults ONE fault]).

## Patterns to follow
- **Third-impl-behind-the-trait**, sibling to `pulse-app/src/llamacli_inference.rs`: modify only the concrete deterministic impl, leave `LlmInferenceRunner` and its other consumers' call shape untouched (per architecture.md §Established Decisions [LLM Inference Runtime]; §Inherited Defaults > LLM inference runtime).
- **Bounded env-gate parse** modelled on `crates/mcp-server/src/feature_gate.rs` — truthy allowlist, every rejection falling back to the documented default without a panic; the `ANDROMEDA_PULSE_BASELINE_BOOTSTRAP_SECONDS` entry is the fullest worked example of the bounded-parse-plus-one-WARN shape (per architecture.md §Occupied Resources > Environment variables).
- **Read-back through the declared query surface**, not through internals: buffer state is inspected via the `traces.*` / `metrics.*` / `logs.*` routers, incident state via the registered `incidents.*` / MCP tool surface (per architecture.md §Cross-cutting Patterns > Test-time telemetry injection; §Occupied Resources > Tauri IPC routes).
- **Cross-process file handshake**: atomic `.tmp`+rename publish with a canonicalize-and-confine guard on write and a byte-bounded opaque read on the consumer side — the pattern shared by `run/workspace-key`, `window-geometry.json`, and `corpus/orphaned-inventory-{unix_nano}.md` (per architecture.md §Occupied Resources > Filesystem locations).
- **Agent-driven harness ergonomics**: deterministic invocations, machine-parseable outputs, schema-stable contracts, `cargo xtask` task surfaces — arch names this as the discipline downstream harness work must follow (per architecture.md §Cross-cutting Patterns > Development Style).

## Anti-patterns to avoid
- **No in-process bypass for the drive** — no test-mode channel injection, no "test ingest" feature flag, no mock-channel back-door substituting for OTLP on `:4317`/`:4318` (per architecture.md §Cross-cutting Patterns > Test-time telemetry injection).
- **No custom wire format or project-specific envelope** on the MCP read-back; rmcp's `#[tool]` macros plus spec JSON-RPC 2.0 framing are the canonical surface (per architecture.md §Established Decisions [API Style — MCP Server Surface 3]; §Standard Contracts > MCP server).
- **No OTLP network exporter aimed at Pulse's own ports** if timing-cap instrumentation is added — self-telemetry uses `opentelemetry-stdout` / a file exporter to `<data_dir>/logs/` only (per architecture.md §Established Decisions [Self-Observation]; §Cross-cutting Patterns > Self-observation discipline).

## Contract bindings
- **MCP tool-response envelope ↔ tests harness**: the external Conductor assertions bind to the spec-conformant JSON-RPC 2.0 shape + `Serialize`-able payload types; the tests plan owns the fixture, arch owns the envelope (architecture.md §Standard Contracts > MCP server; §Cross-cutting Patterns > Cross-bridge data shape).
- **Timing-cap observability surface ↔ obs**: P3 premise 3 (which surfaces expose halo-hue / constellation-discovery / report-render / counter-refresh latency) resolves against obs's logging stack, and arch constrains the answer to an existing reserved IPC/MCP resource or the stdout/file self-observation exporter; a genuinely new IPC procedure additionally needs a router registration plus a `pulse-app/capabilities/` entry (architecture.md §Cross-cutting Patterns > Webview IPC capability policy).
- **`run/workspace-key` + corpus cell key ↔ security**: key custody, secret-class env handling (`ANDROMEDA_PULSE_CORPUS_PASSPHRASE` never logged, never in `Debug`), and the path-confinement guard are security-plan-owned mandates that arch registers as occupied resources (architecture.md §Occupied Resources > Corpus SQLite > At-rest posture).
- **Feature-gate hygiene ↔ tests build profiles**: the read-back exists only in an `--features mcp-server` build, while CI lint runs `--all-features`; the harness invocation must state which profile it drives (architecture.md §Cross-cutting Patterns > Feature-gate hygiene; §Infrastructure Patterns > Build system).
- **Reserved crate names ↔ all domains**: any code this chunk lands must sit inside the locked member set (`interpretation`, `triage`, `corpus`, `mcp-server`, `pulse-app`, `xtask`, …) (architecture.md §Occupied Resources > Cargo workspace crate names).

## Acceptance criteria contributions
- (arch) Conductor drives the known incident by speaking OTLP to `:4317`/`:4318` only — no in-process test-mode bypass, mock channel, or test-only ingest feature flag (per architecture.md §Cross-cutting Patterns > Test-time telemetry injection).
- (arch) Every field the fidelity assertion grades on is `serde::Serialize` and reaches the MCP tool response under spec JSON-RPC 2.0 framing with no project-specific envelope, and MCP failures surface as standard JSON-RPC error objects (per architecture.md §Cross-cutting Patterns > Cross-bridge data shape + §Standard Contracts > MCP server).
- (arch) The deterministic producer remains a `pulse-app` impl behind the unchanged `crates/interpretation/src/contract.rs::LlmInferenceRunner` trait, selected by the already-reserved `ANDROMEDA_PULSE_L4_DETERMINISTIC` truthy gate; no new env var, IPC procedure, event topic, or crate lands unregistered — anything new is amended into §Occupied Resources at wrap (per architecture.md §Established Decisions [LLM Inference Runtime] + §Occupied Resources > Environment variables).
- (arch) Any surface added to make a timing cap observable is an existing reserved IPC/MCP resource or the stdout/file self-observation exporter under `<data_dir>/logs/` — never an OTLP exporter dialing Pulse's own receiver ports; a new TauRPC procedure additionally carries a router registration plus a `pulse-app/capabilities/` entry (per architecture.md §Established Decisions [Self-Observation] + §Cross-cutting Patterns > Webview IPC capability policy).
