# tests extract

## Relevance
Relevant — the chunk's only implement-side deliverable (the det-L4 blind-spot pins in `pulse-app/tests/`) is entirely a test-domain artifact; the doc-side defer and residual carry no test surface beyond gate discipline.

## Constraints
- Standard tier, unit level: the pins are unit-shaped assertions over module boundaries, which the pyramid mandates at "all module boundaries tested" depth (per test-plan §1 Test Scope Summary, §2 Test pyramid → Unit row). No E2E path is added — the chunk builds no user-visible flow, so §6 P1–P7 and the 16-stage `webview-drive` leg are untouched.
- Pins MUST live in `pulse-app/tests/*.rs` and reach internals via `pub` + `#[doc(hidden)]`, never as co-located `#[cfg(test)] mod tests` — `pulse-app`'s `[lib] test = false` makes co-located modules compile under clippy but never run (per test-plan §2 Test directory + naming conventions, restated §4 Conventions → Test file location). This matches the scope's `[inferred]` placement, so P3 need only confirm the file, not the directory.
- The standard gate set is unconditional regardless of scope, with `cargo xtask capability-drift` running LAST (every command above it can regenerate `bindings/index.ts`), and `cargo xtask check:ingest-progress` safe to list because its no-`buffer.tick` arm is NEUTRAL — this chunk boots nothing (per test-plan §3 Per-chunk gate discipline). The webview gates are excluded only if the chunk's file lists touch zero `pulse-app/ui/**` paths — the scope's "code untouched, `HaloCanvas.tsx` stays as-is" boundary implies exclusion; research confirms the final file list.
- Narrow a `pulse-app` run with `--filter-expr` / `-E` **under `--workspace`**, not with `-p pulse-app` — a `-p` selection is not guaranteed compatible with artifacts a `--workspace` build produced (measured rlib-format link failure) (per test-plan §3 `run` → Test selection). `cargo test --test &lt;name&gt; -p pulse-app` remains the sanctioned single-binary path.
- A pin over a by-construction absence must DISCRIMINATE, or it becomes the very vacuous check the chunk exists to remove. The plan names this hazard repeatedly and always resolves it by mutation-check evidence (per test-plan §1 Pending coverage triggers — the L4 confinement row's "would pass VACUOUSLY as a confinement test", the `viz-read-connection-router-wiring-coverage` / `cue-latch-emitter-wiring-coverage` "one-time live proof standing in for a gate" family; §3 Direct-binary smoke variant's BLOCK-shaped vacuous-pass record). Whether a mutation (constructing a `ResolutionSummary`, or populating `EvidenceRefs`) actually reddens each proposed pin is research's question.
- The plan's existing channel for "this cannot fire by construction" is a §1 coverage-scope classification marked **by-construction-satisfied with no test generated** (the self-OTLP rows), and its channel for owed-but-unwritten coverage is a §1 Pending coverage trigger. The chunk proposes a third shape — a committed test that ASSERTS the by-construction property so a future populate flips it. Whether the wrap-side amendment should register these as §1 rows (and in which of the two forms) is a wrap decision the report must carry; test-plan §1 is the anchor either way.
- Agent-runnable invariants bind: deterministic, machine-parseable, exit-code verdict, no human-in-loop (per test-plan §2 Agent-runnable invariants). A pin that records unreachability only in a comment or a test name, without an assertion that can fail, does not satisfy this.

## Patterns to follow
- Blind-spot / wiring pins landed beside the artifact in `pulse-app/tests/unit_*.rs` reaching `pub` + `#[doc(hidden)]` surfaces — the precedent set is `pulse-app/tests/unit_llamacli_inference.rs` (9 path-guard + 6 prompt-bound + 4 allow-root branches, mutation-checked) and `pulse-app/tests/unit_observability_allowlist_window_navigation.rs` (per test-plan §1 Coverage scope → Path canonicalization row; §4 Test file location).
- Const-riding assertions rather than duplicated literals, so the pin tracks the producer instead of restating it — the `interpretation` crate's `PROMPT_VERSION_*` lineage pins are the shipped form (per test-plan §4 What unit tests cover → interpretation crate). Applies directly to pin (b): assert the producer's emitted field values, so populating `EvidenceRefs.trace_id` / `span_ids` / `timestamps_unix_nano` flips the pin rather than silently coexisting with it.
- Pairs that discriminate only together — `consumer::tests::dispatch_folds_redactions_after_a_successful_append` / `…when_the_append_is_rejected` — and selectivity controls that prove the harness itself is live (`benign_and_high_entropy_label_values_survive_byte_identical`; the security scrubber's false-positive corpus) (per test-plan §4 What unit tests cover → buffer crate, security crate). The natural shape for a by-construction pin: the absence assertion plus a control that would go green if the construction changed.
- Name the pin for what it PROVES. The plan records a live cost for the opposite: `pulse-app/tests/e2e_p3_mcp_incident_tools.rs` is in-process despite its `e2e_p3_` name, which had to be corrected in-plan (per test-plan §1 Pending coverage triggers → `mcp-incident-read-back-cross-process-coverage`). The scope's "a test whose name/assertion records that the path cannot fire" is exactly this discipline.
- Every predicate matches an effect FIELD, never the target alone — the standing rule for absence-shaped assertions (per test-plan §6 Drivers per surface → desktop-webview row).

## Anti-patterns to avoid
- NEVER test implementation details / private crate-internal functions — assert public module boundaries; for `pulse-app` that means the `pub` + `#[doc(hidden)]` accessor route, not ad-hoc widening (per test-plan §11 Unit).
- NEVER commit `#[ignore]` without an open tracking issue; `#[ignore]` is reserved for flake quarantine and load-shaped tests join the `load-profiles` nextest profile instead (per test-plan §10 Zero-flakiness budget + Load profiles, §11 Quality). A blind-spot pin must run in the default `--workspace` profile, not be parked.
- NEVER `unwrap()` in tests without a panic message — use `expect("reason why this must succeed")` (per test-plan §11 Unit).

## Contract bindings
- **tests ↔ the det-L4 gate (arch/obs):** `ANDROMEDA_PULSE_L4_DETERMINISTIC` is set into the spawn env of three shipped legs — the 16-stage `webview-drive` path (§6 Drivers per surface), `cargo xtask smoke:gap-resume` and `cargo xtask smoke:external-resolve` (§3 Per-chunk gate discipline). So the blind spots this chunk pins are not local to one test file: any absence check any of those three legs performs over `DigestKind::ResolutionSummary` or `EvidenceRefs` is vacuous for the same reason. Whether any of the three currently asserts over those surfaces is research's question.
- **tests ↔ obs:** the scope's `[inferred]` "no new obs target, no allowlist delta" must hold against test-plan §3 Log format (NDJSON, binds obs-plan §3) — if any pin asserts on an obs record it inherits the allowlist boundary, the shape `unit_observability_allowlist_*.rs` files already carry (§4).
- **tests ↔ security:** test-plan §11 Test Strategy bans skipping `cargo deny check bans`; the chunk's folded-in PREREQ (audit pin #22) runs `cargo deny check advisories` and `bans licenses sources` at wrap, so the §11 ban is satisfied by that leg rather than needing a separate gate.
- **tests ↔ a11y:** the browser-driven a11y tier (`cargo xtask test:a11y` → Playwright `p1`–`p14` + `reduced-motion`) is a tests-owned harness (§2 runner inventory, §6 Drivers per surface, §9 A11y suite stage). The scope's `[inferred]` blast radius includes a11y-plan's SC 2.3.3 Halo degrade-to-static-glow wording — whether the `reduced-motion` spec set asserts anything halo-shaped (which a doc-side defer would orphan) is research's question.

## Acceptance criteria contributions
- (tests) The full standard gate set passes, `capability-drift` LAST, `check:ingest-progress` NEUTRAL-tolerant; webview gates included iff any `pulse-app/ui/**` path is touched (per test-plan §3 Per-chunk gate discipline).
- (tests) The new pins run and pass under `cargo nextest run --workspace --profile ci`, narrowed for iteration with `-E`/`--filter-expr` under `--workspace` and never with `-p pulse-app` (per test-plan §3 `run`).
- (tests) Each blind-spot pin is mutation-checked and reddens when its by-construction property is neutralized — an unreachable-path pin that would pass with the path reachable, or an emptiness pin that would pass with the fields populated, is itself a vacuous absence check (per test-plan §1 Pending coverage triggers → the vacuous-confinement and one-time-proof rows; §3 Direct-binary smoke variant).
- (tests) Pins live in `pulse-app/tests/*.rs`, assert only `pub` + `#[doc(hidden)]` surfaces, carry no bare `unwrap()` and no `#[ignore]` (per test-plan §2 Test directory conventions, §4 Test file location, §11 Unit + Quality).
