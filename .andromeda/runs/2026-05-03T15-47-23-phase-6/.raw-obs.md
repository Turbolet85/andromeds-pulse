- Tick event format MUST be `tracing::info!(target: "{module}.tick", ..., "heartbeat")` emitted at `info` level with the fixed message string `"heartbeat"`, and ride the same `tracing-subscriber` JSON file sink wired in chunk #7 (per obs plan §3 Heartbeat ticks → Tick event format + §6 Log Coverage `info` row).
- Per-module field allowlist is the contract at the formatter Layer wired in chunk #8 — `ingest.tick` MUST emit `span_count` + `buffer_capacity_pct` + `broadcast_subscribers`; `buffer.tick` MUST emit `rows_ingested` + `retention_window_active` + `eviction_count` (mapped к §8 allowlist `rows_ingested` / `eviction_count` / `memory_bytes` / `retention_window_seconds`); `viz.tick` MUST emit `query_latency_ms` + `subscribers_active`; `plugins.tick` MUST emit `loaded_count` + `active_invocations` (per obs plan §1 Telemetry surfaces row Heartbeat ticks + §8 Default-deny allowlist).

- Tick events MUST NOT be over-instrumented as spans inside the timer body — they are bare `tracing::info!` macro calls (no `#[instrument]`, no span guard, no `.in_current_span()` boilerplate); span overhead matters for periodic emitters and the tick is a state snapshot, not a request-scoped operation (per obs plan §11 Telemetry Strategy + §11 Spans / Traces "NEVER over-instrument hot paths" + "NEVER hold a `tracing::Span` guard across `.await` points").

- Tick task MUST be spawned with `tokio::spawn` on the same multi-threaded runtime as ingest/buffer; missing a tick when the runtime stalls (e.g., a blocking call on the executor) is the explicit failure mode the §10 CI gate detects, so the timer body MUST stay non-blocking and avoid synchronous I/O (per obs plan §3 Heartbeat ticks + §10 Heartbeat ticks invariant; route epoch-context: piggybacks on chunk #7's subscriber stack).

## Patterns к follow

- **Bare `tracing::info!` per tick (no span guard)**: emit one structured event per interval per module with the fixed message `"heartbeat"` and module-prefixed target — same JSON file sink emitted by chunk #7's `JsonWithDefaults` formatter, same per-module allowlist enforced by chunk #8's `JsonFieldVisitor` (per obs plan §3 Heartbeat ticks → Tick event format + handoff "PiiScrubLayer's per-module allowlist already covers the .tick suffix via for_target strip-suffix lookup").
- **`{module}.tick` target taxonomy**: the four targets (`ingest.tick`, `buffer.tick`, `viz.tick`, `plugins.tick`) are reserved for stall detection; do NOT introduce additional `*.tick` targets in this chunk and do NOT collapse the four into a shared `app.tick` target — the CI gate parses each independently (per obs plan §10 CI gates "for any of `ingest.tick` / `buffer.tick` / `viz.tick` / `plugins.tick`").
- **Field-arg cheapness**: tick fields are simple primitives (`u64` / `f64` / `usize`) read from already-tracked counters; do NOT format expensive payloads inside the timer body (no `format!`, no `serde_json::to_string`) — fields evaluate eagerly when the macro is reached regardless of subscriber filter (per obs plan §11 Metrics anti-patterns "NEVER format expensive `tracing` event payloads inside hot paths without level-gating").
- **Trace context at tick boundary**: ticks are NOT request-scoped, so they have no inbound `traceparent`; do NOT synthesize a fake trace_id field. The `service.name` / `service.version` / `deployment.environment` / `ci.run.id` / `git.commit.sha` default fields injected by the chunk #7 `JsonWithDefaults` formatter are sufficient identity (per obs plan §3 Service identity + §9 CI-specific default fields).
- **Health command parity**: the `health` TauRPC command exposes the same per-subsystem snapshot fields the ticks emit, so the source of truth (a `Arc<AtomicU64>` counter / channel-capacity probe / DuckDB `COUNT(*)` etc.) MUST be readable both from the tick task AND the health handler. Plumb the shared state once; the tick reads + emits, the health handler reads + returns (per obs plan §3 Heartbeat ticks → Stall detection + chunk #4 health command established).

## Anti-patterns к avoid

- NEVER over-instrument the tick body with `#[tracing::instrument]` + nested child spans for the field reads — span overhead matters for periodic emitters; the tick is one event, not a request (per obs plan §11 Telemetry Strategy "NEVER over-instrument hot paths" + §11 Spans/Traces "NEVER hold a `tracing::Span` guard across `.await`").
- NEVER include unbounded labels in tick fields (e.g., `service_name` from external OTLP, per-trace-ID values, arbitrary request paths) — bounded enumerated values only; `service_name` as a tick field would explode JSON line size and `jq`-aggregation cost (per obs plan §11 Metrics + §5 Metric label cardinality discipline).
- NEVER emit ticks at `debug` or `trace` level (would drop in production `EnvFilter::info` default and break the §10 CI stall gate); NEVER emit at `warn` / `error` level (would pollute panic-detection grep) — `info` only with the `"heartbeat"` message string (per obs plan §6 Log levels mapping `info` row + §10 CI gates panic-grep separation).
- NEVER format the timestamp manually inside the tick body — the chunk #7 `JsonWithDefaults` formatter is the single timestamp authority (RFC 3339 / ISO 8601 microsecond precision); a per-tick `chrono::Utc::now().to_rfc3339()` would race the formatter timestamp and break the §10 gap-analysis script which keys on the emitted `timestamp` field (per obs plan §6 Required fields → `timestamp` + §10 CI gates "parse `timestamp` field (ISO 8601) for each tick target").
