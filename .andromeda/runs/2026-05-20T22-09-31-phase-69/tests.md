## Anti-patterns к avoid

- NEVER assert on raw-secret payload bytes in test output even when the assertion is "this got redacted" — assertions must compare to the redaction marker shape (e.g., `ScrubbedValue::Redacted` variant / `[REDACTED:JWT]` marker / scrubber-defined placeholder), NEVER print the canary substring к test stdout / CI logs / JUnit XML (per §11 Universal "NEVER expose secrets in test output … use data sanitizers or explicit filtering").
- NEVER mock the scrubber (`crates/security`) at integration tests for appender / drain / corpus boundaries — call the real `scrub_attribute()` so the test asserts the actual production invocation point, not a stub return value (per §8 "NEVER use `mockall` for external libraries … use real implementations; mock only traits you own" — scrubber primitive is owned-but-shared, treat as real).
- NEVER skip negative tests for the 7 P-047 categories by claiming "covered by scrubber primitive unit tests" — chunk #68 already tested the primitive; chunk #72's job is asserting INVOCATION at each new persistence site, which requires per-site × per-category coverage matrix (per the test-plan 2026-05-08 Decisions Log gap entry: "no test asserts the ban via grep on … after MCP invocation" — same gap shape at appender / drain / corpus persist).
- NEVER use `#[ignore]` to skip a failing scrubber-coverage negative test "because the scrubber is wired but not yet asserting" — per §10 zero-flakiness budget + §11 CI "NEVER ignore flaky tests — quarantine and fix immediately". If a redaction assertion fails, the scrubber wire is incomplete and the chunk has not landed.
