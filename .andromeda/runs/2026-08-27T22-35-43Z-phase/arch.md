# arch extract

## Relevance
Relevant — this is a corpus write-path repair spanning three locked workspace crates (`corpus`, `triage`, `pulse-app`) and touching a registered durable resource (`corpus/corpus.db` → `incidents`), so arch's crate boundaries, direct-SQL/no-migration decision, at-rest posture and resource-registration rules all bind.

## Constraints
- **Crate placement is locked and the fix must stay inside it.** `corpus`, `triage` and `pulse-app` are reserved workspace member names that cannot be re-purposed or re-created (per architecture.md §Occupied Resources → Cargo workspace crate names); the write path the scope names (`crates/corpus/src/contract.rs`, `crates/triage/src/incident/persistence.rs`, `pulse-app/src/incident_observer.rs`, `pulse-app/src/main.rs`) already sits across exactly those three, so no new crate is warranted by this chunk.
- **Dependency direction is a DAG rooted at the binary.** No library crate may depend on `pulse-app`, and no library crate may depend on a sibling unless its declared contract requires it (per architecture.md §Cross-cutting Patterns → Module dependency direction). If the chosen remedy needs registry-side state at write time, it must not pull `corpus` → `triage` or either → `pulse-app`; the arbitration must ride an existing contract seam or be composed at the `main.rs` boot root.
- **Cross-crate surface goes through the contract module only.** Each crate exposes its public contract via `pub`, internals stay `pub(crate)`, and no `pub use` re-exports cross a crate boundary outside the explicit contract module (per architecture.md §Conventions → Module visibility discipline; §Project Intent → Template patterns). A conditional-update / re-read-at-write method is therefore a contract-module addition on `corpus` (and, if mirrored, on the `triage` persistence trait), not a widened internal.
- **Persistence is direct SQL with no ORM and no migration layer.** The corpus write must remain a hand-written statement on the `Connection`; schema lifecycle is create-on-startup (per architecture.md §Established Decisions [ORM / Migrations]). A status-guarded `UPDATE … WHERE` predicate fits that decision as-is; a version/CAS **column** would be a schema change, which the scope already routes to a P4/P5 escalation.
- **The guard predicate must be expressible over the corpus's plaintext-comparable columns.** Cell-level AES-256-GCM is in force — table and column names are plaintext but BLOB cell payloads are opaque without the key (per architecture.md §Occupied Resources → Corpus SQLite → At-rest posture). No predicate can be written against the bincode `payload` BLOB; only scalar columns already used in `WHERE` clauses (the precedent being `load_active_incidents`' `workspace` / `status` filter) can arbitrate a write. This is also why the scope's out-of-scope `read_at_unix_nano`-inside-the-BLOB divergence cannot be fixed by a SQL guard.
- **No DDL / `SCHEMA_VERSION` bump lands silently, and no new resource lands unregistered.** §Occupied Resources is the canonical list for IPC procedures, env vars, corpus tables and filesystem paths (per architecture.md §Occupied Resources; the whole amendment sidecar is D-arch-resources closures). If the remedy introduces a tunable (e.g. de-aligning the 30 s/60 s epochs by config), it must be a registered env var with a bounded, never-panicking parse and `_seconds`-suffixed naming (per architecture.md §Conventions → Configuration units; §Cross-cutting Patterns → Config management, env > `config.toml` > defaults).
- **Error typing at the boundary is fixed.** Module-internal errors are `thiserror` enums, boundaries use `anyhow`, and anything crossing the TauRPC bridge is the `serde`-friendly `AppError` with stable variants (`Storage { message }` / `Internal { message }`) (per architecture.md §Established Decisions [Error Handling Pattern]; §Conventions → Error response schema (Tauri IPC)). Relevant because the existing statement's only error arm is `rows == 0`: a status-guarded UPDATE makes a zero-row result a legitimate no-op rather than a fault, so whichever arm the fix repurposes must still map to those variants — whether the current arm is even reachable from `incidents.mark_resolved` is research's question.
- **The corpus is read across a process boundary by the MCP sidecar, whose surface is spec-fixed.** `query_incident_list` / `mark_incident_resolved` are 2 of the 8 `#[tool]` methods over JSON-RPC 2.0 stdio, feature-gated behind `--features mcp-server` (per architecture.md §Stack → MCP server; §Standard Contracts → MCP server — spec-conformant). A write-path repair must not change the tool surface, the wire format or the workspace-filter contract (`run/workspace-key`, §Occupied Resources → Filesystem locations).

## Patterns to follow
- **Contract-module boundary for the new write shape** — `crates/corpus/src/contract.rs` and `crates/triage/src/contract.rs` are already the sanctioned public seams for the statement and the `IncidentPersistence` trait respectively (architecture.md §Conventions → Module visibility discipline).
- **No-DDL corpus repair precedent** — the corpus orphan-disposition work landed a behavioural corpus change with "no DDL and no `SCHEMA_VERSION` bump" (architecture.md §Occupied Resources → Corpus SQLite → At-rest posture, chunk `2026-08-15-corpus-key-persistence`); the scope's expectation matches that precedent exactly.
- **Boot-wiring at the single DAG root** — both racing loops are spawned in `pulse-app/src/main.rs`, which is the only place allowed to compose across crates (architecture.md §Cross-cutting Patterns → Module dependency direction; §Infrastructure Patterns → project structure).
- **Registered env-var shape if a tunable is needed** — the `ANDROMEDA_PULSE_BASELINE_BOOTSTRAP_SECONDS` entry is the house form: production-consumed, whitespace-trimmed bounded parse, resolved ONCE at boot, every rejection falling back to a default without a panic, one WARN per boot on a non-default value (architecture.md §Occupied Resources → Environment variables).
- **Real-OTLP-only telemetry for any end-to-end arm** — e2e legs speak OTLP to `:4317`/`:4318` via `crates/ingest/examples/inject_demo`, and the `cargo xtask webview-drive` harness threads no injector arguments, so the arg-less storm profile is byte-identical by construction (architecture.md §Cross-cutting Patterns → Test-time telemetry injection; §Stack → GUI verification harness row).

## Anti-patterns to avoid
- **No in-process test bypass to force the RED collision.** No test-mode ingest back-door, no mock-channel shortcut, no "test ingest" feature flag (per architecture.md §Cross-cutting Patterns → Test-time telemetry injection). Determinism for scope item 3 must come from controlling the *loops'* scheduling/clock, not from a synthetic path into the buffer.
- **No new cross-crate dependency edge to make the guard work** — in particular no `corpus` → `triage` edge and no library → `pulse-app` edge (per architecture.md §Cross-cutting Patterns → Module dependency direction).
- **No unregistered resource riding the fix** — a silently-added env var, IPC procedure, corpus column or data-dir file is registry drift; note that adding a TauRPC procedure requires a router registration + an §Occupied Resources entry + the `EXPECTED_PROCEDURES` pin in `xtask/src/main.rs`, and specifically *not* a capability-JSON edit (per architecture.md §Cross-cutting Patterns → Webview IPC capability policy).

## Contract bindings
- **arch ↔ obs**: the VERIFY leg rides the already-registered `incidents.list_active.request` → `item_count` exact allowlist leaf; arch's binding is only that its emit site is the registered `incidents.*` router surface (architecture.md §Occupied Resources → Tauri IPC routes, `incidents.*`, chunk #78) and that no new IPC procedure is introduced for the read-back without registration. The leaf's allowlist shape and the "exact leaf, never a bare `metric.*` prefix" rule are obs's to state (arch records the widening hazard at §Occupied Resources → `telemetry.frontend.*`).
- **arch ↔ tests**: if the corpus read-back leg becomes a harness stage, §Stack's GUI-verification-harness Role cell is arch's single site stating the assembled path (currently **16 stages**, lineage 7 → 13 → 15 → 16) and would need a wrap amendment; stage design and `--expect-absent` RED wiring are tests' domain (architecture.md §Stack → GUI verification harness (dev-only)).
- **arch ↔ security**: the at-rest posture (cell-level AES-256-GCM, key from the OS credential store) and the PII-scrub-at-egress rule bound what a read-back leg may print; arch registers the posture, security-plan owns the scrubbing mandate (architecture.md §Occupied Resources → Corpus SQLite → At-rest posture; §Occupied Resources → Filesystem locations → egress sink).
- **arch ↔ MCP surface (cross-process)**: `andromeda-pulse-mcp` reads the same `corpus/corpus.db` filtered by `run/workspace-key`; the zombie-active class the scope describes reaches an agent through `query_incident_list`, so any read-back verification that spawns the sidecar inherits the feature gate `--features mcp-server` + `ANDROMEDA_PULSE_MCP_ENABLED` (architecture.md §Occupied Resources → Process / service identity, Filesystem locations, Environment variables).
- **Note for P4**: arch's body carries **no** write-arbitration / optimistic-locking / transaction-scope decision for the corpus at all (grep-verified: no such entry in §Established Decisions or §Cross-cutting Patterns). Whichever shape P4 picks — status-aware conditional update vs. delta persistence — is therefore a candidate NEW §Established Decisions entry at wrap, not an application of an existing one.

## Acceptance criteria contributions
- (arch) The change lands only in the locked crates `corpus` / `triage` / `pulse-app`; no new workspace member, and the `Cargo.toml` graph gains no library→`pulse-app` edge and no new sibling edge (per architecture.md §Occupied Resources → Cargo workspace crate names + §Cross-cutting Patterns → Module dependency direction).
- (arch) Any new cross-crate method (conditional update / re-read-at-write / delta write) is declared in the owning crate's contract module with no `pub(crate)` widened across the boundary (per architecture.md §Conventions → Module visibility discipline).
- (arch) The remedy is expressed as direct SQL over `incidents`' plaintext-comparable columns with no ORM/migration layer, and lands **no** DDL or `SCHEMA_VERSION` bump; if it does, that is an explicit P4/P5 escalation plus an §Occupied Resources → Corpus SQLite amendment, never a silent migration (per architecture.md §Established Decisions [ORM / Migrations] + §Occupied Resources → Corpus SQLite → At-rest posture).
- (arch) No unregistered resource ships: any new env var, IPC procedure, corpus column or data-dir path appears in §Occupied Resources at wrap, and a new tunable interval uses the bounded-parse, resolved-once-at-boot, never-panic, `_seconds`-named shape (per architecture.md §Occupied Resources → Environment variables + §Conventions → Configuration units).
