Partial — no surface, wireframe, region, or focus-order change is in scope; layouts contributes count/severity-driven **no-visible-change invariants** for the incident-facing surfaces the corpus write path feeds.

- The chunk's own boundary ("the UI reads correctly today; this is a corpus write-path repair") means the documented incident surfaces — Findings window and Report window — keep their layout truth unchanged; layout-templates §Surface: desktop-webview → Primary screens requires the findings window remain a borderless always-on-top disclosure list docked below the compact widget and the report window remain the `Modal` **`fill`** variant positioned relative to it.

Any change in what counts as active/unread propagates directly into that window's height, so the fix must not alter the count the window sizes on. Whether that count is derived from the in-memory registry (unaffected) or from a corpus read (affected by zombie-active rows, and by the boot-restore rehydration the scope names) is research's question.
- The shipped desktop-webview signature is the constellation **dot hue keyed to cumulative incident severity tiers**, and the Halo State Pulse canvas is SPECIFIED-BUT-UNBUILT on both webview surfaces (layout-templates §Component — Halo State Pulse canvas, MEASURED 2026-08-21). Incident severity is a layout-visible input; the hue mapping itself is out of this chunk's remit.
- layout-templates §Wireframe notes — Full dashboard (Traces primary screen) requires the hero to be a landmark `<section>` with the STABLE literal name `"Telemetry traces chart"` described by the visually-hidden `data-testid="constellation-summary"` element carrying **lifecycle counts + a findings tally**. - layout-templates §Wireframe notes (P-082) requires the Traces route stay bounded to the shell's `main` height with `overflow:hidden` and only the table's own region scrolling — no outer page scrollbar at any window size. No new fixed band may be introduced above the table.

## Patterns to follow
- **Count-driven window sizing** (§Primary screens — Findings window): the window fits rows then caps and scrolls, rather than reflowing the surface — the established shape for anything whose height tracks incident volume.
- **Stable name + live description** (§Wireframe notes — Traces primary screen; §Primary screens — Full dashboard Traces bullet): counts/tallies live in the `aria-describedby` summary, never in the landmark's accessible name, so the screen-reader rotor does not churn as data moves.
- **Shared-feed derivation** (§IA notes — Multi-surface coordination): both webview surfaces read the same TauRPC routers / `pulse://stream/*` broadcast channels; UI state is derived from the live feed, not from a corpus read-back.
- **Error variant checked before the empty variant** (§Component — Empty / error state, desktop-webview data views): a static "Couldn't load …" with no exporter hint, so a query failure never masquerades as "no data" — the pattern to reuse if any read-back leg's failure ever reaches a data view.
- **Read-only aggregate glance on the compact widget** (§Component — Footer, Compact widget): ingest / error / retention only; worded status lines are dashboard-footer-only (§Component — Footer, Full dashboard / `ConnectionStatusLine`).

## Anti-patterns to avoid
- Do not add new user-facing chrome (badge, banner, worded status line, divergence indicator) to signal the corpus/registry divergence — layout-templates §Component — Footer keeps the compact widget aggregate-glance and confines worded lines to the dashboard footer.
- Do not let an incident-count shift grow the Findings window past its ~8-row cap (§Primary screens — Findings window) or grow the dashboard an outer page scrollbar (§Wireframe notes, P-082).
- Do not treat incident-severity work as licence to build the Halo State Pulse canvas — §Component — Halo State Pulse canvas records it unbuilt with build-or-retire owned by the separate working-route entry "Halo State Pulse canvas disposition".
