# tests extract

## Relevance
Relevant — a Rust write-path race in `triage`/`corpus`/`pulse-app` with a measured-RED requirement and a corpus read-back VERIFY leg; unit + integration tiers, gate set, and determinism rules all apply.

## Constraints
- **Test-tier + placement.** Standard tier requires module boundaries pinned at the unit tier (per test-plan §2 Test pyramid → Unit row). New pins for `triage` (`incident/persistence.rs`, `incident/registry.rs`) and `corpus` (`contract.rs`) belong in co-located `#[cfg(test)] mod tests`, while anything reaching `pulse-app/src/incident_observer.rs` or the `main.rs` spawn wiring MUST live in `pulse-app/tests/*.rs` — `pulse-app`'s `[lib] test = false` makes co-located tests compile but never run (per test-plan §2 Directory pattern + §4 Conventions → Test file location).
- **Unconditional standard gate set.** The chunk's `## Test Commands` must list `cargo fmt --check` · `clippy --workspace --all-targets --all-features -D warnings` · `cargo nextest run --workspace --profile ci` · `cargo xtask capability-widening-check` · `cargo xtask check:ingest-progress` · `cargo xtask capability-drift` **last** (ordering is load-bearing: everything above can regenerate `bindings/index.ts`). Webview gates are excluded only if zero `pulse-app/ui/**` paths are touched (per test-plan §3 Per-chunk gate discipline).
- **Boot-smoke is mandatory here.** `pulse-app/src/main.rs` is an enumerated boot-path trigger, and the scope edits/reads it at `:1490-1515`, so a runtime smoke gate is required — either `npx @tauri-apps/cli dev` (60s) or the sanctioned **direct-binary smoke variant** when the verification needs a fresh `ANDROMEDA_PULSE_DATA_DIR` and sustained load (per test-plan §3 Per-chunk gate discipline → Boot-smoke gate / Direct-binary smoke variant).
- **Measure-first legs are contractually shaped.** A RED leg and a GREEN leg each get their OWN fresh data dir; the "0 `ERROR` / 0 `app.panic.fatal` in `<data_dir>/logs/agent-latest.jsonl*`" assertion **binds the GREEN leg only** — the RED leg records its expected ERROR/reject reason as evidence, not as gate failure. `bash scripts/agent-run.sh status` exits 0 against a dead system, so it evidences the harness contract and never that this run was live (per test-plan §3 Direct-binary smoke variant).
- **Determinism, not waiting, forces the epoch collision.** Real `sleep(N)` for synchronization is banned (per test-plan §11 E2E); real clocks without injection are banned (per test-plan §11 Universal); time is mocked via `tokio::time::pause()` + `advance()` (per test-plan §7 Time-sensitive data / §8 Time mocking), and where the function already takes the instant as an argument the plan's `triage` precedent prefers explicit parameter injection over an ambient clock (per test-plan §4 What unit tests cover → triage crate). The 60s persist / 30s auto-resolve alignment must be produced by a seam, not hoped for.
- **Zero-flakiness budget.** A race test that reproduces only sometimes is a flake: first flake ⇒ immediate quarantine + root cause, never a retry-once policy; `#[ignore]` is reserved for flake quarantine (load-shaped tests join the `load-profiles` nextest profile instead) (per test-plan §10 Zero-flakiness budget + Load profiles; §11 Quality).
- **The persistence boundary is exercised against a real store.** DuckDB must not be mocked at the integration tier — use an ephemeral in-memory instance per test with `tempfile::TempDir` isolation, and seed at runtime (no pre-baked DB, no `.sql` scripts) (per test-plan §11 Integration + §7 Self-bootstrapping requirement).
- **Run-scope must match build-scope.** Narrow a `pulse-app` selection with `--filter-expr`/`-E` **under `--workspace`**, not with `-p` (per test-plan §3 `run` → Test selection).

## Patterns to follow
- **Process-boundary test where the in-process form would pass vacuously.** `corpus`'s cross-process key test re-executes its own test binary precisely because an in-process two-instance check passed while the defect was live (per test-plan §4 What unit tests cover → corpus crate). The same reasoning applies to the scope's read-back leg: an in-registry assertion cannot witness a zombie-active row.
- **Two independent halves for the VERIFY leg.** The plan's established verdict shape reports each stage as separate obs and non-obs halves so a failure says *which* side broke (per test-plan §6 Drivers per surface → `StageHalves{obs,dom}`). Here that maps to the obs record (`incidents.list_active.request` → `item_count`) and the corpus read-back — the scope requires both to agree.
- **Mutation-check the new pin.** The plan repeatedly records a pin as trustworthy only after neutralizing the production change reddens it (redaction-counter fold, the window-navigation detector, the L4 guards) (per test-plan §1 Pending coverage triggers + §4 buffer crate). A status-guarded UPDATE pin should be shown to redden when the guard is reverted.
- **Mint a §1 pending coverage trigger for unpinned production wiring.** The plan's recurring "one-time live proof standing in for a per-run gate" class (`viz-read-connection-router-wiring-coverage`, `cue-latch-emitter-wiring-coverage`, `damper-shared-instance-wiring-coverage`, `l4-path-guard-callsite-wiring-coverage`) requires that when the fix's behaviour is pinned but its `main.rs` call-site wiring is not, the gap is recorded as a trigger rather than left to live evidence (per test-plan §1 Pending coverage triggers).
- **Seed via the real path; `rstest` fixtures for composition.** The three mandated builder factories (`MockTraceSpan` / `MockArrowBatch` / `MockMetricPoint`) are recorded as **specified but unimplemented**, so fixtures self-bootstrap through the live receiver or direct in-memory inserts plus `rstest` (per test-plan §7 Self-bootstrapping requirement + §3 Bootstrap phases item 6).

## Anti-patterns to avoid
- **NEVER `sleep(N)` to line up the two intervals** — wait on an explicit signal or drive an injected clock (per test-plan §11 E2E; §11 Universal "no real time without injection").
- **NEVER mock DuckDB (or the corpus persistence trait you are testing) at the integration tier**, and never mock libraries you do not own — `mockall` is for owned traits only, with constructor injection rather than mid-test `set_var` (per test-plan §11 Integration + §11 Mocking + §8 Anti-monkey-patching).
- **NEVER absorb a flake with a retry or an undocumented `#[ignore]`** — quarantine and root-cause; an agent cannot distinguish flake from real bug (per test-plan §10 Zero-flakiness budget + §11 Quality/CI).

## Contract bindings
- **obs ↔ tests (log format).** The harness `logs` verb and every read-back assertion resolve the **rotated family** `agent-latest.jsonl*` across three precedence-ordered bases (newest match in the first base that resolves) — a bare-name or `*.log` reader silently finds nothing and false-reports an empty log; this mirrors obs-plan §3 Log file location (per test-plan §3 `logs` + §1 Test harness requirements).
- **obs ↔ tests (the VERIFY leaf).** The scope's registered observable `incidents.list_active.request` → `item_count` is an obs-owned allowlist leaf; tests consume it and the leaf's guard file (`pulse-app/tests/unit_observability_allowlist_incident_diagnostics.rs`) is the tests-side artifact. Whether the emit already produces the field unredacted on the paths this chunk exercises is research's question — the plan states target state, not shipped behaviour (per test-plan §3 Log format → Agent-parseable signals).
- **tests ↔ MCP surface.** `query_incident_list` and the incident read-back tools are recorded as guarded **only** by in-process `dispatch_tool` assertions, with the cross-process form owned by the open trigger `mcp-incident-read-back-cross-process-coverage`; whether this chunk's read-back leg discharges any part of that is research's question (per test-plan §6 Scenario P3 → Current residual + §1 Pending coverage triggers).
- **tests ↔ security (dependency gate).** The chunk's folded `cargo audit` PREREQ overlaps the plan's standing ban on skipping `cargo deny check bans` (per test-plan §11 Test Strategy); the interval disposition itself is security/route-owned, not a tests gate.
- **tests ↔ arch (status endpoint).** `status` returns the obs-declared JSON subsystem shape used by `boot` readiness polling (per test-plan §3 Status endpoint shape).
