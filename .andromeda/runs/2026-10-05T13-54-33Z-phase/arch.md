## Anti-patterns to avoid
- Bumping or floating the llama.cpp build tag to escape the grammar-prefill trap. The plan records that b9305's `--json-schema-file` is prefilled and fails gemma4, and that a `--grammar-file` user grammar is never prefilled. The fix is the flag swap, never "latest tag" drift (per architecture §Established Decisions [LLM Inference Runtime], "b9305 grammar-prefill trap" + "Pin discipline").
- Pulling runtime-specific types or a llama.cpp/grammar dependency into `crates/interpretation`, or adding a reverse dependency edge toward `pulse-app` (per architecture §Cross-cutting Patterns → Module dependency direction; §Established Decisions [LLM Inference Runtime], "Bus-factor").
- Adding a Python toolchain dependency to the product build or CI path without recording it. §Stack and Technologies and §Inherited Defaults (Build: Cargo + `cargo-xtask`) name no Python step, so a test that runs the external `json_schema_to_grammar.py` is a P4 fork to resolve consciously, not a silent addition (per architecture §Inherited Defaults → Build; §Stack and Technologies).
