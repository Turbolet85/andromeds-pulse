## Patterns to follow
- **Pure-fn argv pins through a seam.** The probe already pins its `gb` arm (`--grammar-file` in place of `--json-schema-file`), `--sampling` with per-value validation, and `-rea off` handling through pure fns and `parse_args_from`, with each pin mutation-checked (per test-plan §1 row `l4-decision-probe-arg-parse-unit-coverage`). The product-side `build_llama_cli_args` should be pinned the same way: the swapped flag pair present, `--json-schema-file` absent, the four authors' sampling flags with their exact values, and `-rea off` retained. Each pin should be mutation-checked so that removing a flag reds a named test.
- **Accept-side pins, not only reject-side.** The 2026-08-26 layout-chars precedent showed that only an accept pin catches a guard that disables instead of leaking. In the same spirit, the GBNF-equality test must prove it can fail. A one-byte schema edit, or a stale grammar, must red it (scope's verbatim requirement). Record that RED reading in the chunk evidence (per test-plan §1 rows `l4-path-guard-callsite-wiring-coverage` / `l4-decision-probe-arg-parse-unit-coverage`, mutation-checked pin discipline).
- **The `[[example]]` collection rule.** If the probe `pulse-app/examples/l4_decision_probe.rs` is touched (e.g. its `shipped` arm now carries the grammar form, or its `gb` arm is retired as redundant), its 61 collected pins must stay collected, which requires `test = true` on the `[[example]]`. Any change in the pin count is recorded in the §1 row (per test-plan §1 rows `inject-demo-arg-parse-unit-coverage` (correction) and `l4-decision-probe-arg-parse-unit-coverage`).
- **Measure-first RED/GREEN legs, each with its own fresh data dir.** The real-model leg's shape decides its evidence. The json-schema argv on gemma4 fails with `Failed to initialize samplers` and exit 0 with no JSON. That is a silent, BLOCK-like defect, so a HEAD leg's clean log passes vacuously, and its evidence is the absence of a parseable L4 output, not an ERROR count (per test-plan §3 Direct-binary smoke variant, the REJECT- vs BLOCK-shaped rule).

## Anti-patterns to avoid
- NEVER set `ANDROMEDA_PULSE_MODEL_PATH` (or any L4 env var) with `std::env::set_var` mid-test without cleanup. Thread the configuration through a constructor or seam (per test-plan §11 Mocking).
- NEVER commit the real-model run as an `#[ignore]`d or retry-tolerant test. A nondeterministic generation inside the gate set breaks the zero-flakiness budget. It stays a dev-host leg with its readings in `evidence/` (per test-plan §11 Quality; §10 Zero-flakiness budget).
- NEVER lower a threshold to pass a build (per test-plan §11 CI). The SLO raise is legitimate only as the founder-ratified figure (inputs#I1 ruling 2), recorded in its spec homes. A budget loosened beyond that figure to make a run pass is the banned shape.
