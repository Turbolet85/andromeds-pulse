## Patterns to follow

- `#[tracing::instrument(skip(req), fields(rpc.system = "grpc", rpc.service, rpc.method, span_count, traceparent))]` on tonic gRPC handlers; `#[tracing::instrument]` + tower-http TraceLayer on axum HTTP handlers (already established by chunks #16 + #17) — reuse for the post-decode invariant span layer (per obs-plan §3 Trace context propagation + §4 Instrumentation per surface).
- Span naming `{module}.{operation}` with `span.kind` field: `ingest.grpc.parse.error` / `ingest.http.parse.error` for invariant violations; `ingest.channel.send` / `ingest.channel.full` for mpsc backpressure events; `ingest.tick` for heartbeats (per obs-plan §4 Span naming + Span kind convention).
- Default subscriber fields (`service.name = "com.andromeda.pulse"`, `service.version`, `deployment.environment`) registered once at boot via `Layer::with_default_fields(...)` — do not repeat in `info!` macro calls inside this chunk's code (per obs-plan §3 Service identity + §2 Default subscriber fields).
- Trace context inheritance via `tracing::Span::current()` for downstream tasks; if mpsc consumer task is spawned via `tokio::spawn`, use `.in_current_span()` extension trait to propagate the trace_id from receiver entry into the appender task (per obs-plan §3 Trace context propagation + §11 Spans/Traces "NEVER hold guard across .await").
- AllowList registration pattern (already established by chunk #17 in `pulse-app/src/observability.rs`): add `ingest.{grpc,http}.parse.error` + `ingest.tick` + `ingest.channel.send` to `by_target` registry; register fields `span_field_invalid`, `expected_length`, `actual_length`, `rejection_reason`, `attributes_count`, `service_name_tag`, `capacity_pct`, `subscribers` in the `ingest` allowlist (per obs-plan §8 Default-deny posture + Whitelist per module).

## Anti-patterns to avoid

- NEVER log full post-decode `prost`-deserialized attribute values, span body content, or trace_id raw bytes (Vector 1) — use `attributes_count` + `service_name_tag` enumerated tags; chaos test verifies secret payload absence in `agent-latest.jsonl` (per obs-plan §11 Project-specific + §1 Vector 1).
- NEVER emit per-message spans inside the mpsc `send` hot path — span overhead matters at 10k spans/sec; use heartbeat-tick aggregation (`metric.ingest.throughput_events_per_sec` per 100ms ticker for animation, `ingest.tick` per 15s for liveness) (per obs-plan §11 Telemetry Strategy "NEVER over-instrument hot paths" + §5 Update frequency rows).
- NEVER hold a `tracing::Span` guard across an `.await` on the mpsc `send().await` or receive loop without `.in_current_span()` — span context bleeds into unrelated tokio tasks, breaks trace_id correlation, bloats memory until guard drops (per obs-plan §11 Spans/Traces row 4).
