## Anti-patterns к avoid

- NEVER add a "test mode" feature flag that disables the Host-header allowlist, CORS deny, body-size cap, or MCP double-gate to "simplify E2E plumbing" — these are the load-bearing Minimal-tier mitigations against the documented DNS-rebinding / DoS / accidental-enablement classes (per security plan §Anti-Patterns API rows 1-2 + §Anti-Patterns Code Patterns row 3).
- NEVER capture full `~/.andromeda-pulse/snapshots/*.md` contents, `pulse://stream/*` Channel payloads, or MCP `tools/call` response `result` fields into E2E test logs / artifacts uploaded to CI — these surfaces are the documented OTLP-attribute leakage paths (per security plan §Logging NEVER-log list + snapshot/clipboard/MCP hygiene note). Use byte-length + structural-shape assertions instead of value-equality assertions.
- NEVER use `tokio::process::Command::new(...).arg(user_input)` against any string sourced from synthetic OTLP attributes, MCP tool arguments, or workspace-detector output even in test fixtures — preserves the command-injection ban (per security plan §Anti-Patterns Code Patterns row 1; CVE-2025-49596 / CVE-2025-54994 / CVE-2025-54136 / CVE-2026-22252 cluster).
