## Constraints
- **A human reading the brief cannot be the gate.** test-plan §2 (Agent-runnable invariants) and §1 (coverage trigger `agent-driven-discipline: No manual verification checkpoints`) require every verification to exit with a deterministic signal — exit code, structured JSON, or an obs log-line match — readable without human review. The scope's operator-judgment leg is therefore *evidence*, and the chunk's own `[inferred]` code-level pins must carry the verdict. This is the load-bearing constraint for this chunk.
- **The standard gate set is unconditional and ordered.** test-plan §3 (Per-chunk gate discipline) requires `cargo fmt --check` · `cargo clippy --workspace --all-targets --all-features -- -D warnings` · `cargo nextest run --workspace --profile ci` · `cargo xtask capability-widening-check` · `cargo xtask check:ingest-progress` · `cargo xtask capability-drift` **LAST** (every command above it can regenerate `bindings/index.ts`), plus the three `--prefix pulse-app/ui` webview gates only when the chunk touches `pulse-app/ui/**`.
- **`pulse-app` unit-shaped pins do not live under `src/`.** test-plan §4 (Conventions → Test file location) and §2 (directory pattern) record the `[lib] test = false` exception: co-located `mod tests` in `pulse-app` compiles under clippy but never runs, so probes over `pulse-app/src/incidents_router.rs` and `pulse-app/src/inference_runtime.rs` must be separate targets under `pulse-app/tests/*.rs` reaching internals via `pub` + `#[doc(hidden)]`.
- **The sustained real-L4 run has a sanctioned form.** test-plan §3 (Direct-binary smoke variant) requires: launch the product binary directly (either profile) under a **fresh `ANDROMEDA_PULSE_DATA_DIR` per leg**, seed over the real receiver via `inject_demo`, assert from that run's own `&lt;data_dir&gt;/logs/agent-latest.jsonl*`, and shut down by **specific pid** with `:4317`/`:4318` confirmed released. The 0-`ERROR` / 0-`app.panic.fatal` clean-log assertion **binds the GREEN leg only** — a measure-first RED leg at HEAD must produce the record it is measuring.
- **Boot-smoke is conditional on the file set.** test-plan §3 lists the triggering paths (`pulse-app/src/main.rs`, `crates/ui-bridge/src/`, `pulse-app/src/observability.rs`, `tauri.conf.json`, `pulse-app/capabilities/*.json`). `incidents_router.rs` / `inference_runtime.rs` are not on that list, but a new obs leaf registered in `observability.rs` would pull the gate in — whether this fix requires such a leaf is research's question.
- **Fixtures self-bootstrap; nothing pre-baked.** test-plan §7 (Self-bootstrapping requirement) and §1 (`agent-driven-discipline: Self-bootstrapping test data`) require all fixture data generated at test runtime via OTLP ingest through the live receiver or per-test in-memory DuckDB seeding. - **Gates + budgets that apply regardless of scope.** test-plan §10 requires ≥75% line / ≥70% branch / ≥85% function coverage and a **zero-flakiness budget** (one flake ⇒ quarantine + root-cause, never retry); §11 (Test Strategy) and §9 (Build failure conditions) require `cargo deny check bans` never be skipped — which is the same command the chunk's PREREQ re-verifies as basis.

## Patterns to follow
- **Two-half stage verdicts.** test-plan §6 (Drivers per surface) records that `cargo xtask webview-drive` reports each stage as `StageHalves{obs,dom}` — the app's own obs record and the driver's DOM artifact asserted independently, because a combined boolean cannot say whether the effect failed to land or merely failed to reach the screen. §1's P5 row already names the `investigate` (`investigate.run_action.request status = "success"`) and `report-window` stages this chunk's surface sits behind, with `ANDROMEDA_PULSE_L4_DETERMINISTIC` set into the **driver's spawn env** (the app under test is a grandchild process and cannot inherit the caller's shell).
- **RED-first + mutation-check as the evidence standard.** The plan's recurring shape: a pin that passes for free is not a guard. Precedents to model on — `appender::tests::redaction_counter_folds_once_per_batch_across_all_four_builders` (neutralize the scrub sites ⇒ RED, §4 buffer bullet); the code-driven `--no-inject --expect-absent &lt;STAGE&gt;` arm (§6 drivers row); the `NAVIGATION_SETTLE`-collapse validation of the blank detector (§6). Matches the chunk's own `[inferred]` Verification bullet.
- **Direct in-crate pins over indirect/cross-crate proof.** test-plan §2 (pyramid Unit row) mandates all module boundaries tested at Standard tier; §4's `state::tests` allocator pins (which closed `buffer-log-seq-allocator-unit-coverage`) are the model for a new `pub` boundary on the L4Output persistence/retrieval seam.
- **Measure the selector — and the claimed absence — at HEAD.** test-plan §6 (Selector strategy) requires accessible name where one ships, `data-testid` only where none does, never xpath or a hashed class, and extends the measure-at-HEAD rule to claimed ABSENCES, against the component that actually owns the surface.
- **Per-test isolation via env + temp dir.** test-plan §3 (Test data bootstrap) / §7 (lifecycle): `tempfile::TempDir` + `ANDROMEDA_PULSE_DATA_DIR` + ephemeral in-memory DuckDB; env vars are the sanctioned config-injection mechanism.

## Anti-patterns to avoid
- **NEVER let a manual step be the gate** — test-plan §11 (Universal) bans "developer verifies build before deploy" and "human reviews canvas" steps; the operator reading the six-section brief is evidence, not a passing condition.
- **NEVER pre-populate a test DB from a `.sql` script or a committed DB snapshot** — test-plan §11 (Test Data); this binds the preserved 2.3 MB `corpus.db` and any decrypt experiment built on it.
- **NEVER `sleep(N)` to synchronize, and NEVER use real time without injection** — test-plan §11 (E2E + Universal): wait on an explicit signal (`health` poll or obs record). Directly relevant given the async two-event `interpretation.constrained.generate` shape the scope flags for research.
