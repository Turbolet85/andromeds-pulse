## Constraints
- The six-section brief must render inside the existing Report window structure — a separate borderless always-on-top Diagnostic Report window, the `Report` in the `Modal` **`fill`** variant (edge-to-edge on `--color-base`, no backdrop), positioned relative to (left of) the findings window and clamped; no new window and no centered-card modal may be introduced for restored content (per layout-templates §Surface: desktop-webview → Primary screens, "Report window").
- The disclosure path is fixed: the report opens by selecting a row in the findings window, which sizes itself to the incident count (fits rows, caps ~8 then the list scrolls) (per layout-templates §Primary screens, "Findings window"). A content fix must not add a new trigger or entry surface.
- Content that grows must scroll inside its OWN bounded region — the documented desktop-webview pattern is a route bounded to its shell height with fixed regions above and one `flex:1 / min-height:0 / overflow-y:auto` fill region under a sticky opaque `color-base` header, so no outer page scrollbar appears at any window size (per layout-templates §Wireframe notes — Full dashboard (Traces primary screen), P-082; §Component — Trace data table, "Internal scroll region"). Replacing a one-line "_Interpretation pending_" notice with six populated sections is exactly this growth case; whether the Report window already bounds and scrolls its sections is research's question.
- Modal-shaped surfaces cap to the viewport with scrollable overflow rather than overflowing their host window (per layout-templates §Component — Investigation modal, Layout) — the sibling precedent governing the Report's own overflow behavior.
- Honest degradation is a layout branch rule, not only copy: the failure variant is a DISTINCT variant checked BEFORE the empty/no-data branch, carries a static message (never the raw `AppError`), and must never masquerade as the other state (per layout-templates §Component — Empty / error state (desktop-webview data views)). This chunk's inverse mandate — a clean parse must never render the degraded notice — is the same branch-ordering discipline applied to the report; whether the current branch ordering satisfies it is research's question.
- Degraded/empty regions as specified carry NO focusable element (centered column, `aria-hidden` decorative glyph, message + optional hint, read-only and affordance-exempt) (per layout-templates §Component — Empty / error state, Layout). If the retained "retry interpretation" UX (scope Deliverable A) is a focusable control, it departs from that pattern and must be placed as section-body content with a declared focus-order position, not folded into the empty-state region.
- No responsive/breakpoint work is owed: the full dashboard is resizable with no hard breakpoints, the compact widget is fixed quarter-screen, and the findings/report windows position from live widget geometry with work-area / multi-monitor clamping (per layout-templates §IA notes → Responsive behavior; §Primary screens → Findings/Report windows).

## Patterns to follow
- Fixed regions stacked above a single flex-filling internal scroll region with a sticky opaque header — the house pattern for long content in a bounded surface (per layout-templates §Component — Trace data table, "Internal scroll region"; §Wireframe notes Traces, P-082).
- Window sizes to its content with a cap, then the list scrolls (findings window: fits rows, caps ~8) — the documented precedent for a surface whose content length varies with data (per layout-templates §Primary screens, "Findings window").
- One shared component backs every variant of a state so surfaces "read as one system" (a single `EmptyState` backing Metrics/Logs/Snapshots) (per layout-templates §Component — Empty / error state). Keep one component owning the degraded-vs-full-render branch rather than two divergent renderers.
- Read-only, text-first section content; where a row/section gains an action, the surface contributes exactly ONE tab stop (roving `tabindex`, in-row action `tabIndex={-1}`, Enter activates, Esc exits to the prior control) (per layout-templates §Component — Trace data table, "Keyboard / focus"). The precedent if Evidence refs become interactive.
- ASCII-sketch lag is resolved by a targeted touch-up handoff, not by inline drift or a same-chunk rewrite (per layout-templates §Primary screens, "Findings window" wireframe-deferred note; §Wireframe notes Traces sketch-lag note).

## Anti-patterns to avoid
- Do not let restored six-section content grow an outer page scrollbar or an unbounded route — the surface bounds, the inner region scrolls (per layout-templates §Wireframe notes — Full dashboard (Traces primary screen), P-082).
- Do not render one state's region for another state — a failure must not masquerade as "no data", and (this chunk's inverse) a successful parse must not render the degraded/pending notice (per layout-templates §Component — Empty / error state, Error variant checked BEFORE empty).
- Do not surface raw error text in the region — a static, plain message only, never the raw `AppError` (per layout-templates §Component — Empty / error state, Error).
