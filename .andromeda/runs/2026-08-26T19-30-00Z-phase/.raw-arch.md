## Relevance
Relevant — arch governs workspace placement, the `incidents.get_report` IPC registration, the fingerprint encoding decision that Deliverable B's "citing = copying" depends on, and the deterministic-L4 fixture posture the chunk must not regress.

## Constraints
- **Workspace placement is fixed; the join belongs at the binary.** The touch points the scope names live in already-reserved members — `pulse-app` (`incidents_router.rs`, `inference_runtime.rs`), `crates/interpretation` (prompt + runner), `crates/triage` (cue/digest/incident contract), `crates/corpus` (persistence). The 16 workspace crate names are reserved and cannot be re-purposed, and deps form a DAG rooted at `pulse-app` with no library crate depending on a sibling unless its declared contract requires it — so moving real ids from a triage-owned digest into an interpretation-owned prompt is a binary-crate join, not a new sibling dependency (per architecture.md §Occupied Resources → Cargo workspace crate names; §Cross-cutting Patterns → Module dependency direction).
- **`incidents.get_report` is already registered; a NEW procedure is not free.** Changing what the existing procedure renders needs no registration. If the L4-retrieval seam surfaces a new procedure, arch requires one of two authorized shapes (`&lt;router&gt;.&lt;verb&gt;` dotted, or a top-level bare envelope verb), a `Result&lt;T, AppError&gt;` return over the stable variant set, an §Occupied Resources entry, and its `EXPECTED_PROCEDURES` pin in `xtask/src/main.rs` — the capability JSON is explicitly *not* the gate for TauRPC procedures (per architecture.md §Occupied Resources → Tauri IPC routes; §Conventions → Endpoint naming + Error response schema (Tauri IPC); §Cross-cutting Patterns → Webview IPC capability policy).
- **Fingerprint encoding is a decided, load-bearing choice — full hex, never the prefix.** Arch requires the L1 value to be full 32-char lowercase hex via the crate-internal `triage::contract::hex_lower`, threaded `AttentionCue.fingerprint` → `DigestCueRef.fingerprint` → `Incident.fingerprint` (`Option&lt;String&gt;`, `#[serde(default)]`, `None` for baseline-derived families), and explicitly *not* the 8-char `pattern::storm::fingerprint_to_hex_prefix` — "a prefix here could never match". Any id injected into the prompt or cited in Evidence must therefore be the full-hex form for a citation to resolve (per architecture.md §Established Decisions → [Fault Identity — what makes two faults ONE fault], L1 clause).
- **Prompt growth runs under an unrelaxable invocation bound.** Generation goes through `pub trait LlmInferenceRunner: Send + Sync` (`crates/interpretation/src/contract.rs`) as the swap boundary, spawn-per-generation, with explicit `-n {max_tokens}` + `-st` single-turn + an outer wall-clock `tokio::time::timeout` as defense-in-depth against unbounded generation. Injecting real ids may not be paid for by relaxing any of the three (per architecture.md §Established Decisions → [LLM Inference Runtime — L4 interpretation layer]).
- **The deterministic fixture's chain is arch-recorded and must not regress.** Arch records canned `evidence_refs` → the single producer join at `pulse-app/src/inference_runtime.rs` → `Incident.evidence_refs.fingerprint_hashes` → MCP `retrieve_telemetry_slice.fingerprint_refs` → the Report's Evidence section, and requires the arrays stay populated because while empty, absence checks passed for the wrong reason. The same entry records `trace_id` / `span_ids` / `timestamps_unix_nano` as hardcoded empty at that producer in every mode (Deliverable B's [inferred] residual) and records `degraded_mode` as `Report.degraded_mode = parsed_l4.is_none()` driven by Resolved-only `resolution_summary_text` persistence. These are spec claims as of chunk 2026-08-17 — **whether HEAD still matches them is research's question** (per architecture.md §Occupied Resources → Environment variables → `ANDROMEDA_PULSE_L4_DETERMINISTIC`).
- **`L4Output` has a second consumer outside the incident path.** `investigate.run_action` reuses the incident `L4Output` schema + `parse_bounded` against the same `generate_constrained` trait method and is deterministic-L4-aware. Any change to that schema, the constrained-generation prompt contract, or the parse path is in Investigate's blast radius (per architecture.md §Occupied Resources → Tauri IPC routes → `investigate.run_action`).
- **Corpus/schema resources are registry-governed, and the key path records nothing data-dir-derived.** The corpus reserved tables are enumerated (`incidents`, `incident_events`, `digest_archive`, `baseline_state`, `service_registry`, `pipeline_metrics`); cell payloads are AES-256-GCM with the key sourced from the OS credential store under service id `com.andromeda.pulse` (Windows entry `corpus-key.com.andromeda.pulse`), persisting across processes, with the opt-in `ANDROMEDA_PULSE_CORPUS_PASSPHRASE` BLAKE3 fallback folding in the *service id*. For open question 1, arch names no data-dir-derived input to key resolution and registers `ANDROMEDA_PULSE_DATA_DIR` as the sanctioned way to point a process at another root — suggestive, not dispositive; research must establish it (per architecture.md §Occupied Resources → Corpus SQLite database / schema names → At-rest posture; §Occupied Resources → Filesystem locations).

## Patterns to follow
- **Contract-module + serde-across-the-bridge shape**: each crate's public contract module is its only `pub` surface, `thiserror` internally with conversion at the bridge, and every type crossing TauRPC or an MCP response is `serde::Serialize` (per architecture.md §Project Intent → Template patterns; §Cross-cutting Patterns → Cross-bridge data shape).
- **Never-fabricate / honest-degradation render precedent**: `diagnostics.snapshot` is registered as HYBRID-RENDER where sub-fields with no production producer render an explicit "not yet recorded", never a fabricated value — the same discipline Deliverable A asks of `degraded_mode` and the six-section brief (per architecture.md §Occupied Resources → Tauri IPC routes → `diagnostics.snapshot`).
- **Env-layer-only knob shape**, if the fix needs a toggle: bounded whitespace-trimmed parse, resolved once at boot, never panics, one WARN per boot when non-default, and deliberately no `Settings`/`config.toml` field — hence no TauRPC contract change and no hot-reload delta (`ANDROMEDA_PULSE_BASELINE_BOOTSTRAP_SECONDS` and `ANDROMEDA_PULSE_L4_ALLOW_ROOT` are the two worked examples) (per architecture.md §Occupied Resources → Environment variables).
- **Telemetry enters only over real OTLP** for the verification leg — no in-process test-mode bypass, no mock-channel back-door; the `--sustained` injector run conforms because `crates/ingest/examples/inject_demo` speaks the same `:4317`/`:4318` surface external SDKs use (per architecture.md §Cross-cutting Patterns → Test-time telemetry injection; §Stack and Technologies → GUI verification harness row).
- **Name the dev binary correctly in any smoke/operator command**: `target/{profile}/pulse-app.exe` is what `cargo build` emits; `andromeda-pulse.exe` is bundler-only and `target/{profile}/andromeda-pulse` exists on no host (per architecture.md §Occupied Resources → Process / service identity).

## Anti-patterns to avoid
- **No new workspace crate and no re-purposed reserved crate name**; no library crate depending on `pulse-app` (per architecture.md §Occupied Resources → Cargo workspace crate names; §Cross-cutting Patterns → Module dependency direction).
- **No unregistered occupied resource** — a new env var, DuckDB or corpus table, TauRPC procedure, or `pulse://stream/*` topic landing without an §Occupied Resources amendment at wrap is the recurring drift class this registry exists to catch (per architecture.md §Occupied Resources, sustained by the D-arch-resources amendment precedent).
- **No bespoke envelope for the report payload** — `Result&lt;T, AppError&gt;` over the stable variants, and any list-returning surface uses `{items, total, next_cursor}` (per architecture.md §Conventions → Error response schema (Tauri IPC); §Standard Contracts → Common response envelope).
