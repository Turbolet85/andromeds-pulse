## Patterns to follow

- SHA-pinning convention `<owner>/<repo>@<40-char-SHA> # vX.Y.Z` for every third-party Action — version comment alongside SHA so Dependabot can bump both atomically (per security plan §Bootstrap phases `dep-security-ci-gate`).
- `egress-policy: audit` → `block` promotion ladder for `step-security/harden-runner` — start in audit mode, observe a clean window, then promote to block with allowlist (per security plan §Bootstrap phases + §API Security harden-runner reference).
- `cargo audit` invocation pattern via `actions-rust-lang/audit` action (SHA-pinned); `cargo deny check bans licenses sources` invocation via `EmbarkStudios/cargo-deny-action` (SHA-pinned); both fail the build on any finding above warning severity (per security plan §Dependency Security CI integration).
- `deny.toml` skip-list pattern from session learnings: each Tauri major+minor bump introduces transitive duplicates that need one-line provenance comments under `[bans] skip` — do NOT relax `multiple-versions = "deny"` to absorb them; the `tonic 0.14 ↔ 0.13` check MUST stay outside the skip list (per `.claude/rules/security.md` §Session Additions 2026-05-03).
- Existing session-handoff record shows `deny.toml skip-list +4: ctor + windows-core + windows-result + windows-strings` — pattern continues for #5/#6: every duplicate added by a Tauri/plugin minor-version bump gets a one-line provenance comment, never relaxes the deny rule.

## Anti-patterns to avoid

- NEVER reference any third-party GitHub Action by `@v2` / `@latest` / any floating tag — pin by 40-char commit SHA only (per security plan §Anti-Patterns § Secrets; `tj-actions/changed-files` CVE-2025-30066 anchor — 23k repos affected by retroactive-tag-rewrite).
- NEVER set `permissions: { contents: write }` at the workflow level in `ci.yml` — workflow level is `contents: read`; write is per-job, publish-step only (per security plan §Anti-Patterns § Secrets).
- NEVER store the Azure Key Vault service principal as a long-lived GitHub Actions secret — GitHub OIDC federation only; this constraint shapes how `production-release` Environment is configured in chunk #6 (per security plan §Anti-Patterns § Secrets + §Secret Management Storage).
- NEVER place Azure Key Vault credentials, Apple Developer ID credentials, or Tauri updater Minisign private key outside the `production-release` Environment with manual approval gate — even when the actual signing automation lands in chunk #46, the Environment + secret scaffolding MUST be set up correctly here (per security plan §Anti-Patterns § Secrets).
- NEVER relax `[bans] multiple-versions = "deny"` in `deny.toml` to absorb a duplicate — add a one-line skip-list entry with provenance comment, OR fix the upstream duplicate; the unconditional setting is what catches the documented `tonic 0.14 ↔ 0.13` duplicate (per `.claude/rules/security.md` §Session Additions 2026-05-03).
