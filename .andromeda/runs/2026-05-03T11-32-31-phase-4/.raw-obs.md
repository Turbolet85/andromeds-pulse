## Anti-patterns to avoid

- NEVER use colored terminal output for CI parsing — CI artifacts MUST be structured (JSON) + machine-readable; `cargo test` default human output must be replaced with `cargo nextest --message-format json` (or equivalent JSON-emitting harness) in route#5 (per obs-plan §11 CI anti-pattern row 4).
- NEVER use human-review-gated log analysis without machine-parseable export — blocks agent-driven debugging; CI failure triage MUST go through the JSON artifact + `jq` pipeline, not "ops team reviews daily" (per obs-plan §11 Universal anti-pattern + §11 CI row 2).
- NEVER skip snapshot generation on integration test failure — first-class debugging artifact (per obs-plan §11 CI row 3); route#5 integration-test job (when added in later epoch) must include snapshot upload-on-failure; route#5's first iteration (Foundation, no integration tests yet) lays the artifact-upload primitive but defers the snapshot generation hook to the integration-test introduction chunk.
- NEVER define soft SLO budgets (no enforcement) — formal SLOs MUST trigger build/deploy failure when exhausted; the four §10 CI gates are hard fails, not warnings (per obs-plan §11 SLO anti-pattern row 3).

## Contract bindings

- **obs ↔ tests harness contract**: route#5 `cargo nextest` step is the runtime that emits the JSON log lines; the §6 binding contract (verbatim 5-field schema `{timestamp, level, target, message, fields}`) is what tests and obs both consume — neither can drift unilaterally. The existing `xtask harness:status` (chunk #4) already emits canonical health envelope; CI must validate the schema didn't drift via the `jq '.status == "ok" and .subsystems.{4 keys}'` assertion (existing in session-handoff `harness:status` shape gate). Route#5 elevates this gate from local-only to CI-enforced.
- **obs ↔ security PII scrubbing**: route#6 gitleaks output and `cargo audit` output ARE potential PII surfaces (matched secrets, vulnerable-version package names that may correspond to internal forks). The `*_SECRET / *_TOKEN / *_KEY` redaction convention (obs-plan §8 row 6) MUST extend to scanner output paths — scanner artifacts are scoped to ephemeral CI logs, not the durable `agent-latest.jsonl` artifact.
- **obs ↔ tests SLO gates**: route#5 coverage gate (≥75% line / ≥70% branch / ≥85% function) is a tests-domain threshold; obs gates (zero-panic / heartbeat-gap / perf-budget p99) are obs-domain thresholds — both fail the CI build, both compose into the same `ci.yml` job graph. The `xtask` invocation surface unifies them: `xtask ci-gates` (or per-gate subcommands) emits structured exit codes consumed by the GitHub Actions step.
- **obs ↔ arch CI/CD**: arch §Infrastructure Patterns "matrix over Linux/macOS/Windows" + arch §Standard Contracts "binding contract" obligation flow into route#5 — the same JSON schema must serialize identically across all three OS runners; CI must verify cross-platform schema parity (a test failing on macOS but not Linux due to subscriber-format drift = obs regression, not test regression).
