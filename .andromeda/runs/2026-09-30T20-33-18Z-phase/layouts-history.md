## Relevant amendment history
- **2026-05-02 — Initial layout templates generated by `/andromeda-design` Phase 8** — set the Snapshots view as a list with view/copy actions and deferred the snapshot-markdown viewer layout (modal vs full-page) to the implementation route. That deferral was folded into the body at the 2026-06-28 v3 migration. It is the basis for the extract's Snapshots constraint: longer span-masked snapshot bodies change content length only, and the chunk has no viewer layout to re-derive. The same entry assigned ownership of the `snapshot.generate` wiring to the route specialist and its logic to `ui-bridge`, so layout owns no part of the snapshot text change.
- **2026-07-08-self-explaining-empty-states** — added §Component — Empty / error state: a shared `EmptyState` region with a zero-data message and exporter hint, and a distinct static honest-error variant that shows no internals and is checked first. It is the source of the extract's pattern that a redaction placeholder is data inside a populated view and must never route into the `EmptyState` or error branch. A consumer that today treats a whole-value `[redacted:…]` as "no content" is the trap to check at P3.
- **2026-07-09-traces-table-layout-polish** — documented the Traces screen as a flex column bounded to the shell's `main` height with `overflow:hidden` and no outer page scrollbar. The hero and the `Errors only` toolbar are fixed; the table flex-fills the rest (`flex:1 / min-height:0 / overflow-y:auto`) with a sticky opaque thead. This is the exact containment the extract binds span-masked ring-buffer cells to: longer masked text must scroll inside that region and never grow the page. The entry also recorded that the ASCII sketch lags the body. Section text governs, not the sketch.
- **2026-07-10-incidents-floating-window-disclosure** — added the `report` window: a separate Diagnostic Report in the then-new Modal `fill` variant, positioned relative to the `findings` window, which is borderless, always-on-top and sized to incident count. This is the fixed Report surface the extract says span masking must not restructure: same six sections, same `fill` variant, same position. ASCII wireframes for both windows were deferred under the sketch-lag pattern, so there is no Report wireframe to update.
- **2026-08-23-a11y-verification** — gave the trace data table its Keyboard / focus contract: the row is the table body's single tab stop via roving `tabindex`, Up/Down/Home/End traverse, Enter investigates, Esc exits, the in-row Investigate button is `tabIndex={-1}`, and focus-move scrolls the table's own region. The Investigation-modal Trigger stopped being click-only. The extract's "no new focusable element / Traces table stays one tab stop" criterion and its anti-pattern against an inline reveal control rest on this contract. The entry also made the hero's accessible name a STABLE literal, "Telemetry traces chart", with an aggregate-only `aria-describedby` summary carrying no service name. That precedent keeps data-derived text out of accessible names, so masked text must not be surfaced there either.
- **2026-08-30-diagnostics-un-muting-harness-truth-sweep** — replaced the Traces-table "shadcn `Table`" claim with the native `<table>` markup that actually ships (implicit ARIA role intact), and replaced the shadcn/Radix Tooling-context claim with the shipped `react-aria-components` + Tailwind stack. Any layout reasoning about how table cells or modal regions absorb longer span-masked text should go against native table cells and react-aria components, not the retired shadcn stack.
