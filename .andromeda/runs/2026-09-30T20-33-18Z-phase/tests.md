# tests extract

## Relevance
relevant — the chunk changes the P-047/P-048 scrubber contract and migrates consumers across library crates and `pulse-app`, all of which carry per-crate unit pins and redaction canaries this plan governs.

## Constraints
- Test tier is Standard: unit tests are required at every module boundary the chunk touches, and integration coverage is required where a consumer crosses a crate boundary (scrubber → buffer / triage digest / interpretation markdown / pulse-app resolvers) (per test-plan §1 Test Scope Summary; §2 Test Strategy pyramid).
- Test location is split: library-crate pins go in co-located `#[cfg(test)] mod tests` (security, buffer, triage, interpretation, corpus). Any `pulse-app` consumer pin (digest_runtime, inference_runtime, investigate_router, training_export, persistence adapters) goes in `pulse-app/tests/*.rs` through `pub` + `#[doc(hidden)]` accessors. The ratchet is a flat zero, so a `#[test]` added under `pulse-app/src/` reds the build (`main.rs` exempt) (per test-plan §2 Test directory + naming conventions; §4 Conventions).
- The plan's `## Test Commands` must carry the full standard gate set, in its order: `capability-drift` BEFORE the workspace nextest, the `--features mcp-server` `emit_taurpc_bindings` regen as the last cargo-adjacent step, then the `git diff --quiet <chunk-base> -- pulse-app/ui/src/bindings/index.ts` close (scope states no TauRPC procedure change). The webview npm gates are excluded only if no `pulse-app/ui/**` path is touched (per test-plan §3 Per-chunk gate discipline).
- §4 describes the security crate's scrubber pins as recall + false-positive `#[rstest]` corpora in `crates/security/src/scrubber.rs`, and states "`scrub_attribute` and the `ScrubbedValue` contract are asserted unchanged". This chunk deliberately changes what `Redacted` carries or how it is consumed, so that sentence is an amendment target. Recall of all 8 arms (incl. the Luhn-gated `credit_card` corpora) and the false-positive half must stay green, byte for byte (per test-plan §4 What unit tests cover → security crate).
- The buffer crate's five-cell write-boundary redaction pins must keep holding under span masking. They are: the `appender::tests` per-column canary-redacted / legit-byte-identical pairs, the `metrics_points.labels` keyed + bare classes with the key surviving verbatim, and `redaction_counter_folds_once_per_batch_across_all_four_builders` plus the `consumer::tests` fold pair. Whether span masking changes what a "redaction" counts (per value vs per span) is research's question (per test-plan §4 What unit tests cover → buffer crate; §1 `buffer-redaction-counter-unit-coverage` row).
- Coverage thresholds of ≥ 75 % line, ≥ 70 % branch and ≥ 85 % function hold for the new span-masking code. They must never be lowered to pass (per test-plan §10 Coverage thresholds; §11 CI).
- Fixtures are self-bootstrapped synthetic canaries built with `rstest` fixtures at runtime. No production telemetry dumps and no pre-seeded DB (per test-plan §7 Self-bootstrapping requirement; §11 Test Data).

## Patterns to follow
- Paired recall / false-positive `#[rstest]` case tables in `scrubber.rs`, extended with span-level cases: a secret embedded mid-text, several secrets of different categories in one value, a secret at start or end, and a multi-line digest-shaped value. Each case asserts the exact masked output string (per test-plan §4 security crate).
- A keyed + bare two-class canary corpus for any pair-shaped site. A span mask over a key-anchored match must be shown not to re-expose the value half, and the key must survive verbatim (per test-plan §4 buffer crate, `credential_label_values_redact_in_both_classes_and_keys_survive`).
- Mutation-checked discrimination: neutralize the span-masking branch and confirm the new pins redden. Record which pins reddened, not just that "a test failed" (per test-plan §4 security crate "mutation-checked so each rejection branch discriminates"; §1 `buffer-redaction-counter-unit-coverage` mutation note).
- Invert the measured pin rather than delete it. `pii_scrub_closure_still_collapses_a_digest_carrying_a_card` becomes a pin that asserts the digest keeps its other lines and masks only the card span. This follows the per-chunk RED/GREEN evidence discipline: witness at base, then fix (per test-plan §3 Per-chunk gate discipline, MEASURE-FIRST RED/GREEN leg note).
- Test report and MCP readers through the existing direct-library and in-process paths. The P2 curation invariants run through `pulse-app/tests/e2e_p2_snapshot_generate.rs`. The MCP incident readers run as in-process `dispatch_tool` assertions (per test-plan §6 P2 / P3 Current residual; §1 `snapshot-resolver-level-coverage`, where the resolver itself has no executed carrier).

## Anti-patterns to avoid
- NEVER put a secret-shaped canary in test output in a way that proves nothing. Assertions must check that the canary is ABSENT from the masked output and that the placeholder is present. Assertion or panic messages must never echo the unmasked input (per test-plan §11 Universal "NEVER expose secrets in test output").
- NEVER test private crate internals or use bare `unwrap()`. Pin the public `scrub_attribute` / `ScrubbedValue` (or sibling fn) boundary, with `expect("…")` context (per test-plan §11 Unit).
- NEVER `#[ignore]` a now-failing whole-value pin, or lower a threshold, to get green. A pin that encoded the old whole-value semantics is inverted or re-asserted with its rationale recorded (per test-plan §11 Quality; §11 CI).

## Contract bindings
- tests ↔ security: the 8-arm recall corpora are the executable form of the scope's never-weaken outcome. A span-level P-048 change needs a matching security-plan §Security Anti-Patterns → Logging amendment, and test-plan §4's "`ScrubbedValue` contract asserted unchanged" line needs one too (per test-plan §4 security crate).
- tests ↔ capability matrix: `cargo xtask verify:capability-matrix` fails CI on a dangling P-048 file-ref or grep-anchor. Renaming or inverting the measured digest pin must update the matrix entry's anchor in the same chunk (per test-plan §9 CI Integration, `verify:capability-matrix` step).
- tests ↔ obs: the `redactions_applied` heartbeat tally (`BufferHeartbeat` / `BufferStateSnapshot`) is pinned in `buffer`. If span masking changes the counting unit, the obs field's meaning and its pin move together (per test-plan §1 `buffer-redaction-counter-unit-coverage` row).
