# arch extract

## Relevance
partial — the chunk changes a primitive's return semantics inside the reserved `security` crate and migrates consumers across five crates. Arch governs where it lives, which dependency edges and resources it may touch, and two identity decisions that a scrubbed value feeds. The redaction semantics themselves (P-048, the placeholder shape) belong to the security domain.

## Constraints
- The span-level result lives in the reserved `security` crate (`crates/security/src/scrubber.rs`), and consumers stay in their current crates (`buffer`, `corpus`, `interpretation`, `triage`, `pulse-app`). No new crate is added and no reserved name is repurposed (per architecture §Occupied Resources → Cargo workspace crate names; §Established Decisions [Module Boundaries]).
- The migration must not add a dependency edge against the DAG. Dependencies flow toward `pulse-app`, and no library crate depends on a sibling unless its declared contract requires it (per architecture §Cross-cutting Patterns → Module dependency direction). Research must answer, from the Cargo.toml files, which of the listed consumer crates (notably `triage`) already depend on `security` directly and which receive the scrub by injection.
- Whatever new shape the scrubber exposes (a new variant, a field on `Redacted`, or a sibling fn) is published through the `security` crate's public contract surface only. `pub(crate)` covers internals, and there is no cross-crate `pub use` outside a contract module (per architecture §Conventions → Module visibility discipline; §Project Intent → Template patterns).
- The chunk adds no occupied resource: no TauRPC procedure (the `EXPECTED_PROCEDURES` pin set is unchanged), no DuckDB or corpus table, no column, no `SCHEMA_VERSION` bump from 2, and no env var (per architecture §Occupied Resources → Tauri IPC routes / DuckDB reserved tables / Corpus SQLite reserved tables + at-rest posture / env vars; §Cross-cutting Patterns → Webview IPC capability policy).
- **Fault identity:** a scrubbed value that feeds identity is decided, not inferred. The L1 fingerprint is computed over exception stacktraces, which are a scrubbed column. L2 coalesces on `(kind, scope, scope_id)`, where `scope_id` is the service identity (a scrubbed `service_name`). If either input moves from a whole-value placeholder to span-masked text, the identity values change for redacted inputs. Research must answer whether the fingerprint and `scope_id` are derived before or after the scrub (per architecture §Established Decisions [Fault Identity]).
- **Primary key convention:** `metrics_points.metric_name` sits inside the primary key. The convention text states that two distinct credential-shaped names redact to one placeholder and collide, with `seq` separating them. Under span masking, names with different non-secret remainders would stay distinct. `seq` must stay the key's disambiguator either way, and the prose becomes a probable amendment target (per architecture §Conventions → Primary key convention).
- **Training export:** the out-of-data-dir training export scrubs at its egress through `security::scrubber::scrub_attribute`. It is in the consumer set, so its egress output changes from whole-value to span-masked text while its path rules stay unchanged (per architecture §Occupied Resources → Out-of-data-dir egress sink (training export)).

## Patterns to follow
- **Crate template:** a public contract module, `pub(crate)` internals and a `thiserror` enum. Any new scrubber type follows the `security` crate's existing template (per architecture §Project Intent → Template patterns).
- **Transport-agnostic change:** the change is data-only across the cross-process boundary. The `andromeda-pulse-mcp` sidecar reads the same corpus rows, so span-masked text written by the producer reaches MCP readers purely as data, with no wire or schema change (per architecture §Established Decisions [Corpus Write Arbitration]; §Standard Contracts → MCP server — spec-conformant).
- **Serialize requirement:** if the new scrubber result ever crosses TauRPC or appears in an MCP tool response, it must be `serde::Serialize`. The scope expects no bridge-type change, so an internal-only type stays unconstrained (per architecture §Cross-cutting Patterns → Cross-bridge data shape).

## Anti-patterns to avoid
- Adding a direct `security` dependency to a leaf crate that does not already declare one, or any reverse edge, just to call the new span-level API. Inject the transform from the binary boundary instead (per architecture §Cross-cutting Patterns → Module dependency direction).
- Adding a corpus or ring-buffer column, table or schema bump to carry span-level redaction metadata. The scope's boundaries exclude it, and it would widen §Occupied Resources (per architecture §Occupied Resources → Corpus SQLite / DuckDB reserved tables).
- Letting a span-masked value silently change an identity key (fingerprint, `scope_id`, primary-key `metric_name`) without recording it as a decision. Identity is decided, never inferred from code shape (per architecture §Established Decisions [Fault Identity]).

## Contract bindings
- **arch ↔ security:** the P-048 whole-value semantics, the security-plan §Security Anti-Patterns → Logging amendment and the placeholder-spelling question are security's to decide. Arch contributes only the placement (reserved `security` crate) and the DAG constraints on how consumers reach the primitive.
- **arch ↔ tests:** fault-identity and primary-key behaviour under span masking (whether a redacted service name or stacktrace yields the same identity as before) binds to test fixtures that pin the fingerprint, `scope_id` and `seq` collision behaviour.
- **arch ↔ MCP sidecar (cross-process):** span-masked text written to corpus BLOBs is read by `andromeda-pulse-mcp` through the shared corpus substrate. If the persisted shape changes, the codec compat contract applies. The scope expects no shape change.

## Acceptance criteria contributions
- No occupied resource is added. `EXPECTED_PROCEDURES` and the regenerated bindings show no procedure delta, no DuckDB or corpus table or column is added, corpus `SCHEMA_VERSION` stays 2, and no new `ANDROMEDA_PULSE_*` var appears (per architecture §Occupied Resources).
- No new inter-crate dependency edge violates the DAG. The Cargo.toml diff adds no `security` (or other sibling) dependency to a library crate that lacked one, unless its contract requires it and the edge is recorded (per architecture §Cross-cutting Patterns → Module dependency direction).
- The span-level scrubber API is reachable only through the `security` crate's public contract surface, with no cross-crate `pub use` outside a contract module (per architecture §Conventions → Module visibility discipline).
- For any redacted input that feeds identity (`service_name` → `scope_id`, exception stacktrace → L1 fingerprint, `metric_name` → primary key), the chunk either shows the identity value unchanged or records the change as a §Established Decisions [Fault Identity] / §Conventions → Primary key convention amendment at wrap (per architecture §Established Decisions [Fault Identity]; §Conventions → Primary key convention).
