## Relevance
Relevant — the chunk lands a regression fix plus an obs-allowlist repair, both of which the test-plan governs via the per-chunk gate set, regression-lock discipline, and harness/log-grep bindings.

## Constraints
- The standard gate set is unconditional for every `/andromeda-phase` chunk plan's `## Test Commands`: `cargo fmt --check`, `cargo clippy --workspace --all-targets --all-features -- -D warnings`, `cargo nextest run --workspace --profile ci`, `cargo xtask capability-drift`, `cargo xtask capability-widening-check`; the three `--prefix pulse-app/ui` webview gates are excluded only if the Files-to-modify / New-files lists touch zero `pulse-app/ui/**` paths (per test-plan.md §3 Per-chunk gate discipline). Scope §"Surfaces likely touched" names no UI path, but the exclusion is decided from the final file list, not the scope guess.
- The boot-smoke gate (`npx @tauri-apps/cli dev`, 60s timeout, watch stdout for `Local:` / `ready in` / `Compiled successfully` before SIGTERM) is MANDATORY when the plan touches `pulse-app/src/main.rs`, `crates/ui-bridge/src/`, `pulse-app/src-tauri/tauri.conf.json`, or `pulse-app/capabilities/*.json` (per test-plan.md §3 Boot-smoke gate). `pulse-app/src/digest_runtime.rs` is not on that list, so whether §3's fix reaches one of the four trigger paths — and therefore whether this gate binds — is research's question.
- Any pulse-app-side probe must live as a separate integration-target file under `pulse-app/tests/*.rs` reaching internals via `pub` + `#[doc(hidden)]`; co-located `#[cfg(test)] mod tests` inside `pulse-app` compiles under clippy but never runs because `[lib] test = false` (per test-plan.md §2 Test directory + naming conventions and §4 Conventions → Test file location). This binds directly, since the ranked suspect's file is `pulse-app/src/digest_runtime.rs`.
- Fixture data must be self-bootstrapped at runtime with per-test isolation (`tempfile::TempDir` + `ANDROMEDA_PULSE_DATA_DIR`, env-var config overrides); no pre-baked DB, no `.sql` seeding (per test-plan.md §7 Self-bootstrapping requirement and §3 Test data bootstrap). The chunk's fresh-data-dir + `inject_demo` premise-check is the compliant shape; keyless `sqlite3` reads of `corpus.db` are evidence reads, not seeding, so they sit outside that ban.
- Every layer must be deterministic and agent-parseable — exit code plus structured stdout/JSON/log-line, no `sleep(N)` synchronization, no real clock without injection, no flaky-retry budget (per test-plan.md §2 Agent-runnable invariants and §10 Zero-flakiness budget). The chunk's `ANDROMEDA_PULSE_L4_DETERMINISTIC=true` capture is the determinism lever for this seam.
- A cross-module seam (triage storm/cue/incident → `digest_runtime` → corpus persistence) is Integration-tier work: all Standard Contracts crossing a module boundary require integration coverage, driven live rather than mocked (per test-plan.md §2 pyramid Integration row and §5 Boundary types covered).
- test-plan.md §4's "What unit tests cover" record enumerates ingest / buffer / viz / ui-bridge / snapshot / workspace-detector / corpus / plugins / mcp-server / webview and carries no `triage` bullet, while §2's pyramid Unit row omits it too — the same enumeration gap the corpus chunk closed. Whether `crates/triage/` already carries co-located tests (making this a doc-only gap) is research's question.

## Patterns to follow
- Process-boundary test form where the in-process form would pass while the defect is live: the corpus key test re-executes its own test binary precisely because an in-process two-instance check would have been green against a live defect (per test-plan.md §4 corpus bullet). The same reasoning governs the regression lock here — a test that could not have failed before the fix is not coverage.
- Byte-equality + fallback pairing on a key boundary: publish/read round-trip asserted byte-equal against the app's filter key, with the absent/invalid-file fallback asserted on both ends (per test-plan.md §5 boundary row `pulse-app boot → <data_dir>/run/workspace-key → mcp-server`). This is the exact invariant the scope's ranked hypothesis (stamped vs filtered workspace key) puts under test.
- Counter-differencing over point-in-time reads via the status endpoint and JSON log lines — `subsystems.*.rows_ingested` increments and `jq`/`grep` extraction from the NDJSON `tracing` stream (per test-plan.md §3 Status endpoint shape and §3 Log format → Agent-parseable signals). Matches the chunk's §5 "counters over gauges" and "every claim names its query" directives.
- `rstest` 0.26.1 `#[fixture]` composition over builder factories (`MockTraceSpan::builder()` and siblings) rather than raw literals (per test-plan.md §7 Fixture library and §4 Fixture pattern at unit level).
- MCP sidecar exercised as a real subprocess over JSON-RPC 2.0 via `tokio::process::Command` when the read-back leg is asserted (per test-plan.md §5 Module ↔ MCP sidecar and §6 P3), which is the shape the `workspace-key-cross-process-coverage` pending trigger still awaits.

## Anti-patterns to avoid
- NEVER pre-populate the test DB via `.sql` scripts or DB snapshots, and NEVER share mutable state across parallel tests (per test-plan.md §11 Test Data).
- NEVER use `sleep(N)` for synchronization or real `Instant::now()` / `Utc::now()` without injection; wait on an explicit signal (per test-plan.md §11 E2E + Universal).
- NEVER assert against private crate-internal functions; test public module boundaries — and NEVER land `#[ignore]` outside flake quarantine with a tracking issue (per test-plan.md §11 Unit + Quality, §10 Load profiles note).

## Contract bindings
- **tests §3 Log format ↔ obs allowlist (scope §4).** The harness `logs` leg greps a JSON-lines `tracing` stream and the pending PII triggers assert by grep on `agent-latest.jsonl`; test-plan.md §3 therefore requires the four `triage.*` / `incidents.*` leaves the chunk adds to remain NDJSON-shaped and jq/grep-extractable. obs owns the schema and the redaction ruling; tests owns the harness-readability binding.
- **tests §3 Status endpoint ↔ obs status shape.** `status` polls the obs-declared JSON (`status`, `subsystems.*.status`, `subsystems.buffer.rows_ingested`, `pid`, `uptime_ms`) per test-plan.md §3 Status endpoint shape.
- **tests pending PII triggers ↔ security §Logging vectors 2/4.** `AppError sanitization` and `MCP response body redaction` are asserted by grep on `agent-latest.jsonl` (per test-plan.md §1 Pending coverage triggers); new count/enum leaves must not widen that surface.
- **tests §3 gate set ↔ security capability bans.** `cargo xtask capability-drift` + `cargo xtask capability-widening-check` run in the standard gate set (per test-plan.md §3), which is consistent with the scope's "no new capability surface" boundary.

## Acceptance criteria contributions
- (tests) The standard gate set passes: `cargo fmt --check`, `cargo clippy --workspace --all-targets --all-features -- -D warnings`, `cargo nextest run --workspace --profile ci`, `cargo xtask capability-drift`, `cargo xtask capability-widening-check`; webview gates included iff any `pulse-app/ui/**` path is touched (per test-plan.md §3 Per-chunk gate discipline).
- (tests) The located break is locked by an automated regression test that would have FAILED against pre-fix code — an in-process or log-only form that could have passed while the defect was live does not satisfy this (per test-plan.md §4 corpus cross-process-key precedent and §10 Zero-flakiness budget).
- (tests) The reproducible capture proving `incidents` rows > 0 runs on a fresh data dir with runtime-generated fixture data and per-test isolation — no pre-baked DB, no `.sql` seed (per test-plan.md §7 Self-bootstrapping requirement).
- (tests) Any pulse-app-side probe added for `digest_runtime.rs` lives under `pulse-app/tests/*.rs` and reaches internals via `pub` + `#[doc(hidden)]`, never as a co-located `mod tests` (per test-plan.md §2 Test directory + naming conventions).
