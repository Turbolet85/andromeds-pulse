## Patterns to follow
- Crate template shape: each library crate exposes only its public contract module, `pub(crate)` internals, and a `thiserror`-derived error enum — a fix inside `triage` must route through `triage::contract` rather than widening cross-crate visibility (per architecture.md §Project Intent → Template patterns; §Conventions → Module visibility discipline).
- Error handling layering: `thiserror` enums module-internal, `From` conversion into the `serde`-friendly `AppError` at the TauRPC bridge, `anyhow` at `main.rs` — if the located break is a silently-swallowed error, the repair must surface it through this existing ladder, not a new error type crossing the bridge (per architecture.md §Conventions → Error response schema (Tauri IPC); §Established Decisions → Error Handling Pattern).
- Env-var bounded-parse precedent: truthy gates follow the `crates/mcp-server/src/feature_gate.rs` pattern and path vars are canonicalized + `is_file()`-asserted before use — the workspace-key read already follows the bounded-read variant (per architecture.md §Occupied Resources → Environment variables).
- Atomic `.tmp`+rename write discipline for data-dir artifacts (`run/workspace-key`, `window-geometry.json`, `corpus/orphaned-inventory-{unix_nano}.md`) — any evidence or state file the fix writes under the data dir follows the same pattern (per architecture.md §Occupied Resources → Filesystem locations).
- Test-time telemetry injection speaks OTLP to `:4317`/`:4318` — the same surface external SDKs use, with no in-process bypass and no test-mode feature flag; buffer state is read back through `traces.*` / `metrics.*` / `logs.*`. The §1 `inject_demo` reproduction and any regression test must respect this (per architecture.md §Cross-cutting Patterns → Test-time telemetry injection).

## Anti-patterns to avoid
- No in-process test-mode bypass, mock-channel back-door, or "test ingest" feature flag to force an incident into existence — the reproduction must go through the real OTLP receiver surface (per architecture.md §Cross-cutting Patterns → Test-time telemetry injection).
- No new env var, TauRPC procedure, corpus table, or capability landed without a matching §Occupied Resources registration; the registry is canonical and unregistered resources are the recurring drift class the amendment history records (per architecture.md §Occupied Resources).
- No self-observation via the product's own OTLP ports — the §4 obs-allowlist repair must stay on the `opentelemetry-stdout`/file-exporter path to `<data_dir>/logs/`, never dialing `:4317`/`:4318` (per architecture.md §Cross-cutting Patterns → Self-observation discipline; §Established Decisions → Self-Observation).
