# a11y extract

## Relevance
**Partial (narrow)** — the chunk's §1–§3 work is backend Rust (storm→cue→incident seam) with no a11y assertion obligation; a11y touches it only via (a) the obs field-allowlist mechanism §4 repairs, which also governs a11y violation-JSON emission, (b) the per-PR a11y regression gate that binds every PR, and (c) the incident-consuming webview surfaces (findings badge/dropdown, report window) whose live 0→N behavior this fix re-enables.

## Constraints
- Backend entities are **not-assertable**: `crates/triage/`, `pulse-app/src/digest_runtime.rs`, corpus storage, and the TauRPC IPC bridge carry **no** a11y assertion obligation — a11y-plan.md §1 (A11y scope entity table) marks backend/IPC surfaces "no UI surface, no a11y testing scope". No a11y work is owed for scope §1–§3 unless the located fix reaches the webview.
- A11y violation records MUST emit on target `a11y::assertion` in obs's structured log format with all eight required fields (`wcag_criterion`, `violation_type`, `severity`, `surface`, `selector`, `remediation`, `tool`, `tool_result_id`) — per a11y-plan.md §3 (Structured violation JSON schema, restated in §1). The chunk's §4 edits the **same default-deny field allowlist** that decides which leaves survive redaction; **whether `a11y::assertion` field leaves are already allowlisted on HEAD is research's question**, and the §4 additions must not narrow/alter the mechanism in a way that redacts them.
- Zero **new** WCAG AA violation tuples per PR vs the base artifact — a11y-plan.md §10 (Standard+ invariant) + §3 (Harness wiring: `baselines/a11y-violations-summary.json`, tuple diff on `{surface, wcag_criterion, selector, severity}`). This is a hard merge gate for any PR, including backend-only ones.
- Standing rule: **any new route/modal adds its axe spec + fixtures in the same chunk** — a11y-plan.md §3 (Harness wiring & conventions, "Adding a surface"). The scope declares "no new capability surface" `[inferred]`; if §3's located fix adds or reshapes a webview surface, this rule fires in-chunk, not in follow-up.
- The incident-count live badge (findings window / FindingsCounter, opened via `aria-haspopup="dialog"`) is required to announce a 0→N change **once, politely** under SC 4.1.3 — a11y-plan.md §5 (findings-window focus-order entry). Restoring incident creation is exactly what drives that 0→N transition at runtime; **whether the shipped UI already satisfies this announce-once mandate is research's question**.
- Universal SC minimums **SC 2.1.1 Keyboard / SC 2.4.3 Focus Order / SC 4.1.2 Name, Role, Value** apply across **P1–P12**, including the incident-consuming surfaces p8 (findings dropdown) and p9 (diagnostic report modal) — a11y-plan.md §1 (surface-set extension note) + §10 (WCAG SC coverage report).
- No a11y conformance claim without machine-verifiable output; manual SR/keyboard/contrast is supplemental, never sole — a11y-plan.md §2 (agent-runnable invariants). The chunk's "every claim names its query" evidence discipline is compatible; an a11y claim must name the axe/Lighthouse/pa11y JSON that backs it.

## Patterns to follow
- **Fixture-driven IPC mocking**, not live data: a11y specs drive the incident surfaces through `helpers/mock-tauri.ts` (regex `TauRPC__<router.path>`, taurpc 0.7 shape; `plugin:event|listen` for push channels) with payloads in `helpers/v02-fixtures.ts` (incident / report / diagnostics) — a11y-plan.md §3. If the fix reshapes an incident-serving procedure (e.g. the one behind `incidents.list_active`), these fixtures are the a11y-side touchpoint.
- **Suite-health check before trusting green**: `npx playwright test --list` — a11y-plan.md §3 records that a list-time import failure once silently disabled the whole suite, so a "passing" a11y chain must first be proven non-empty.
- **Regression-gate diff pattern**: download base `a11y-violations-summary.json`, jq/node tuple filter, emit `regression-set.json` as audit artifact — a11y-plan.md §3 (CI integration) + §9.
- **Violation JSON lands in the same log plumbing** the chunk is repairing: JSONL/JSON artifacts under `~/.andromeda-pulse/logs/` in obs log format — a11y-plan.md §1 (CI integration) + §9 (per-stage artifacts).

## Anti-patterns to avoid
- NEVER declare a11y unaffected on assertion alone — no WCAG conformance/regression claim without machine-verifiable evidence (a11y-plan.md §11 Strategy + §11 Universal). "Backend-only, so a11y is fine" needs either the chain output or an explicit recorded no-webview-touch determination.
- NEVER soft-gate or defer a11y: it is a fail-fast PR gate, no warning-only mode, no "fix in follow-up" (a11y-plan.md §11 CI).
- NEVER retry-to-green an a11y failure (no retry-once, no soft SLO) — quarantine, investigate, fix (a11y-plan.md §11 SLO + §10).

## Contract bindings
- **a11y ↔ obs** (primary for this chunk): the `a11y::assertion` violation record is defined against obs's structured log schema and flows through the same default-deny field allowlist the scope's §4 repairs — a11y-plan.md §3 (Structured violation JSON schema). Also binds resource attributes `service.name` = `"com.andromeda.pulse"` / `deployment.environment` to obs service identity — a11y-plan.md §9.
- **a11y ↔ tests**: the a11y chain reuses tests' E2E driver under the 5-command discipline (`boot` / `run` / `status` / `cleanup` / `logs`) and runs in the same `ci.yml` as tests E2E — a11y-plan.md §3 (Focus management test harness) + §9.
- **a11y ↔ design**: contrast/motion/target-size token pairs (a11y-plan.md §6) bind only if the located fix renders or restyles a webview surface; dormant otherwise.

## Acceptance criteria contributions
- (a11y) The a11y chain (`npm run test:a11y` / `cargo xtask test:a11y`) runs and reports **zero new violation tuples** vs `baselines/a11y-violations-summary.json`, with `npx playwright test --list` confirming the suite is non-empty (per a11y-plan.md §3 Harness wiring & conventions + §10 SLO Invariants).
- (a11y) The §4 obs allowlist change leaves `a11y::assertion` records emitting all eight required fields un-redacted — verified by reading the allowlist on HEAD for those leaves alongside the `triage.*` / `incidents.*` additions (per a11y-plan.md §3 Structured violation JSON schema).
- (a11y) If the located fix touches any webview surface, that surface carries its axe spec + fixture in **this** chunk and satisfies the universal minimums SC 2.1.1 / SC 2.4.3 / SC 4.1.2 (per a11y-plan.md §3 "Adding a surface" standing rule + §1 P1–P12 surface set).
- (a11y) With incidents restored to > 0, the findings badge's 0→N transition announces once politely under SC 4.1.3 and cross-window Esc/dismiss focus restoration to the FindingsCounter badge still holds (per a11y-plan.md §5 findings-window / Focus restoration) — applies only if the fix or its verification touches those windows.
