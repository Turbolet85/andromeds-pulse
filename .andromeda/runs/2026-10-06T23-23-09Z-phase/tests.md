## Constraints
- Tier is Standard: the unit level is the comprehensive one for the `triage` and `interpretation` crates, and every layer must end in a machine-parseable verdict (exit code, structured output, log line) with no human reading the result (per test-plan §1 Test tier · §2 Test pyramid · §2 Agent-runnable invariants).
- The plan's `## Test Commands` must carry the standard gate set unconditionally, in the stated order: `capability-drift` before the default-features workspace nextest, the `--features mcp-server` `emit_taurpc_bindings` regen as the last cargo-adjacent step, and the `git diff --quiet <chunk-base>` bindings close for a chunk that adds no TauRPC procedure. The webview gates drop out only when no `pulse-app/ui/**` path is touched (per test-plan §3 Per-chunk gate discipline).
- New and moved tests live co-located in `#[cfg(test)] mod tests` inside the `triage` and `interpretation` library sources; anything unit-shaped on the `pulse-app` side lives under `pulse-app/tests/*.rs` (or in the `[[example]]` probe, which must declare `test = true` to be collected), and the dead-test ratchet forbids a `#[test]` in `pulse-app/src/` (per test-plan §2 Test directory + naming conventions · §4 Conventions · §1 Pending coverage triggers `l4-decision-probe-arg-parse-unit-coverage`).
- The digest framing-line pin set must stay true after the change: exactly one `TRIGGER:` line keyed on the FIRST cue, directly after `OVERALL:`, none without a cue, ASCII, every `CueKind`. §4 requires the "omits" pins to be read as the negative half of a pair, so a service-bearing trigger line needs its own positive pin beside the no-`scope_id` arm. Whether the assert at `assembler.rs:1186` is the first-cue pin §4 names, and which other pins match the trigger line's exact text, is research's question (per test-plan §4 What unit tests cover → triage crate).
- The prompt surface pins must stay true: the shared framing instruction exactly once in every tier's Output Instructions, its first-hypothesis obligation clause exactly once in every tier's composed prompt, template text ASCII for argv transport, and the `PROMPT_VERSION_*` lineage bumped together and asserted through the consts without literal duplication. Whether the chunk's chosen form changes the instruction text (and so owes a version bump) is the plan's decision at P4 (per test-plan §4 What unit tests cover → interpretation crate).
- A real-model generation is never a gate: it cannot give a deterministic verdict, and the default suite must stay deterministic with zero flake tolerance. The pre-registered reading therefore rides as leg evidence, and what the suite gates on is the grading rule as code (per test-plan §1 Pending coverage triggers `l4-decision-probe-arg-parse-unit-coverage` · §2 Agent-runnable invariants · §10 Zero-flakiness budget).
- Workspace coverage thresholds apply to the new code (line ≥ 75 %, branch ≥ 70 %, function ≥ 85 %, `xtask/` excluded for now); a narrowed `pulse-app` run goes through `-E` under `--workspace`, never `-p` (per test-plan §10 Coverage thresholds · §3 `run` → Narrow a `pulse-app` run).

## Patterns to follow
- Render pins assert over the real renderer through its `#[doc(hidden)] pub` contract surface (`render_payload`, `cue_summary`), with the fixture built at test time, and each pin is mutation-checked so it discriminates (the recorded precedent: keying the line on the wrong cue reds the first-cue pin) (per test-plan §4 What unit tests cover → triage crate).
- A grader for a real-model reading is a pure function over a closed label set, pinned by asymmetric pairs: a statement that passes beside a near-miss that must fail, first hypothesis only, an unreadable row reading as no-reading rather than a miss. The recorded cause scorer already separates `hit` from `service_only` and `word_only`; whether that scorer grades the service as a whole word the way the scope's bar requires (`conductor` beside `conductor-canary`) is research's question (per test-plan §1 Pending coverage triggers `l4-decision-probe-arg-parse-unit-coverage`).
- A pre-registered rule is committed and unit-pinned before any run, and a whole-series re-grade from stored stdout must reproduce the generation-time labels, so the reading can be re-read without the model (per test-plan §1 Pending coverage triggers `l4-decision-probe-arg-parse-unit-coverage`).
- A leg that drives the product or the model proves its own preconditions and reports INCONCLUSIVE, never PASS, when one is unmet (unset or guard-rejected L4 path, no generation, no readable row); exit contract 0 PASS · 1 FAIL · 2 INCONCLUSIVE. If the leg boots the product binary it takes the direct-binary form: fresh data dir per leg, clean-log assertion on the GREEN leg only, shutdown by specific pid, `:4317` / `:4318` confirmed released (per test-plan §3 Per-chunk gate discipline · §3 Direct-binary smoke variant).
- Probe shapes that carry a trigger line are pinned as shapes: every arm × shape composes within the production prompt bound, a cueless shape renders no `TRIGGER:` line, and the arm that strips framing lines is count-checked per removal. Whether the service part of the line changes what those pins count is research's question (per test-plan §1 Pending coverage triggers `l4-decision-probe-arg-parse-unit-coverage`).

## Anti-patterns to avoid
- Never make a real-model generation, or a person reading its output, the pass/fail of a committed test or of the chunk's gate set; never add a retry or `#[ignore]` to absorb a nondeterministic run (per test-plan §11 Universal (agent-driven specific) · §11 Quality · §10 Zero-flakiness budget).
- Never commit the fourth series' captured digests or statements as test fixtures: the d3-shaped case (trigger scoped to one service, context naming its hyphenated sibling) is built synthetically through the renderer at test time, and no test output carries raw OTLP-derived content (per test-plan §11 Test Data · §11 Universal (agent-driven specific) · §7 Self-bootstrapping requirement).
- Never land a pin that holds on a tree which never emits the line it guards: the no-`scope_id` (global-scope) arm guards only as the negative half of a pair with the scoped arm (per test-plan §4 What unit tests cover → triage crate).

## Contract bindings
- tests ↔ obs: a leg that boots the product reads its verdict from the app's own `agent-latest.jsonl*` family (rotated, date-suffixed) and the harness `status` verdict, never from a bare-name log read (per test-plan §3 `logs` · §3 `status` · §3 Direct-binary smoke variant).
- tests ↔ security: the trigger line would carry OTLP-derived text into the argv prompt; the template half stays ASCII under the existing argv-transport pin, and the scrub fixture is tied to the real renderer by a pulse-app pin. Whether that fixture carries a `TRIGGER:` line that moves with this chunk is research's question (per test-plan §4 What unit tests cover → triage crate · → interpretation crate).
- tests ↔ arch (Fault Identity): the first-cue keying of the trigger line is a pinned behaviour; the service part must be read from that same first cue, so the existing first-cue mutation still reds (per test-plan §4 What unit tests cover → triage crate).
- tests ↔ CI: the workspace run needs a Python 3 interpreter for `unit_l4_grammar`; this chunk's boundary bars any GBNF or schema change, so that pin must stay byte-green untouched (per test-plan §4 Framework (Rust crates) · §9 Pipeline structure → lint-test).
