## Relevance
Relevant — the chunk repairs a defect that architecture.md §Established Decisions [Fault Identity] names by hand, and its code sits in three locked workspace crates.

## Constraints
- The fault-identity decision is binding at both layers and this chunk consumes rather than redefines it: L1 normalization semantics are settled, and L2 incident identity stays keyed on the cue tuple `(kind, scope, scope_id)` (per architecture.md §Established Decisions [Fault Identity — what makes two faults ONE fault]).
- That same entry states the producer mandate this chunk implements — `Incident.fingerprint` is contracted and consumed as a lowercase-hex grouping hash, and names the DEFERRED path (threading a real `ExceptionFingerprint` through `AttentionCue` → `DigestCueRef` → the producer) as the documented route, with keying on `L4Output.fingerprint` explicitly REJECTED because it is a constant under the deterministic runner. Whether the code already threads any part of this is research's question (per architecture.md §Established Decisions [Fault Identity]).
- Workspace crate names are reserved and cannot be re-purposed; the crates in play (`buffer`, `triage`, `pulse-app`) are all on the locked list, and no new crate is warranted for a value-kind repair (per architecture.md §Occupied Resources → Cargo workspace crate names, §Inherited Defaults → Module boundaries).
- Any new cross-crate edge introduced by the threading must respect the dependency DAG rooted at `pulse-app` — no library crate depends on a sibling unless its declared contract requires it — and must cross only through the target crate's explicit contract module (no `pub use` re-export across crate boundaries). Whether `triage` already carries a `buffer` edge, and whether the L1 fingerprint type is already on `buffer`'s public contract surface, is research's question (per architecture.md §Cross-cutting Patterns → Module dependency direction; §Conventions → Module visibility discipline).
- `Incident` reaches both the TauRPC bridge (`incidents.list_active` / `incidents.get_report`) and MCP tool responses (`query_incident_list` / `retrieve_report`), so every type in the changed contract path must remain `serde::Serialize` (per architecture.md §Cross-cutting Patterns → Cross-bridge data shape; §Occupied Resources → Tauri IPC routes; §Standard Contracts → MCP server).
- The corpus SQLite reserved-table set (`incidents`, `incident_events`, `digest_archive`, …) is canonical and cell-encrypted AES-256-GCM at rest; a value-kind change must land without new tables or DDL, and any implied reinterpretation of already-stored rows is a finding to raise, not a silent carry (per architecture.md §Occupied Resources → Corpus SQLite database / schema names).
- `ANDROMEDA_PULSE_L4_DETERMINISTIC` is registered at arch level with a fixed contract (truthy gate, canned `L4Output`, no GPU/model); the "every incident matches every other as previously-seen" consequence must be resolved without altering that registered contract or adding a sibling env var (per architecture.md §Occupied Resources → Environment variables).

## Patterns to follow
- Contract-module template: each library crate's only `pub` surface is its contract module with `pub(crate)` internals and a `thiserror`-derived error enum — a `triage::contract` type change follows that shape (per architecture.md §Project Intent → Template patterns; §Conventions → Module visibility discipline).
- Stable-contract / swappable-impl precedent: the `LlmInferenceRunner` trait shows how a typed contract boundary absorbs an impl change without rippling — the same discipline applies to threading a value through `AttentionCue` → `DigestCueRef` (per architecture.md §Established Decisions [LLM Inference Runtime]).
- Error discipline on any new fallible conversion in the threading path: `thiserror` module-internal, `anyhow` at boundaries, `serde`-friendly `AppError` at the IPC bridge (per architecture.md §Established Decisions [Error Handling Pattern]; §Conventions → Error response schema (Tauri IPC)).
- Registered-resource discipline at wrap: any resource that does land (procedure, event, env var, crate, table, data-dir path) gets an §Occupied Resources entry recorded through the amendment sidecar (per architecture.md §Occupied Resources; architecture-amendments.md § Registry-closure amendments).

## Anti-patterns to avoid
- Do not simplify away the starved corpus-retrieval `fingerprint_match` arm — arch records it as correct-per-contract and STARVED, never dead, with an explicit "do not simplify this arm away" (per architecture.md §Established Decisions [Fault Identity]).
- Do not re-key L2 incident coalescing on the model-authored `L4Output.fingerprint`, and do not partially implement the deferred threading path — both are named rejections in the same entry (per architecture.md §Established Decisions [Fault Identity]).
- Do not verify via an in-process test-mode bypass, mock-channel back-door, or a "test ingest" feature flag; and do not land an unregistered env var / IPC procedure / event / table (per architecture.md §Cross-cutting Patterns → Test-time telemetry injection; §Occupied Resources).

## Contract bindings
- **arch ↔ tests**: E2E proof that a real fault hash reaches the incident site must inject synthetic telemetry over OTLP `:4317`/`:4318` and read state back through the TauRPC query/incident routers — no in-process bypass (architecture.md §Cross-cutting Patterns → Test-time telemetry injection). The 2026-08-16 amendment also records an external read-only Conductor harness aligned to L1 fingerprint semantics; its switching cost is cited, never copied.
- **arch ↔ security**: the contracted field is an *anonymized* grouping hash; arch fixes the value kind, security owns the anonymization/PII property and the corpus at-rest posture the stored value inherits (architecture.md §Occupied Resources → Corpus SQLite → At-rest posture).
- **arch ↔ obs**: any WARN/counter emitted when a fingerprint is absent or falls back must use the product's own stdout/file exporter and must never dial the product's own OTLP ports (architecture.md §Cross-cutting Patterns → Self-observation discipline; §Established Decisions [Self-Observation]).

## Acceptance criteria contributions
- (arch) The produced `Incident.fingerprint` is the contracted kind — a grouping hash derived from the L1 exception fingerprint — rather than the model-authored `L4Output.fingerprint` (per architecture.md §Established Decisions [Fault Identity]).
- (arch) L2 incident identity remains keyed on `(kind, scope, scope_id)` with no fingerprint entering the coalescing key (per architecture.md §Established Decisions [Fault Identity]).
- (arch) All changed code lives in the locked crates `buffer` / `triage` / `pulse-app`; any new cross-crate edge points toward `pulse-app` and crosses only the target crate's contract module, with no cross-boundary `pub use` re-export (per architecture.md §Occupied Resources → Cargo workspace crate names; §Cross-cutting Patterns → Module dependency direction; §Conventions → Module visibility discipline).
- (arch) No new TauRPC procedure, IPC event, env var, port, crate, DuckDB table or corpus table beyond §Occupied Resources; if one lands it requires an §Occupied Resources amendment, and a new procedure additionally requires a `pulse-app/capabilities/` entry (per architecture.md §Occupied Resources; §Cross-cutting Patterns → Webview IPC capability policy).
