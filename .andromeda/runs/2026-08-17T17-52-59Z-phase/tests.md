## Constraints
- Test tier is Standard, and the pyramid puts a pure producer/threading value-kind change at the **unit** level with per-crate comprehensive depth (`triage`, `buffer`, plus the `pulse-app` producer) — E2E is not the obligated layer here (per test-plan.md §1 Scope Summary, §2 Test Strategy pyramid).
- The producer at `pulse-app/src/inference_runtime.rs` falls under the **pulse-app test-location exception**: because `[lib] test = false`, a co-located `#[cfg(test)] mod tests` compiles under clippy but never executes, so pulse-app probes must be separate integration-target files under `pulse-app/tests/*.rs` reaching internals via `pub` + `#[doc(hidden)]` accessors. The scope's "three pinned producer tests" must therefore land in that form (per test-plan.md §2 Test directory + naming conventions, §4 Conventions → Test file location). Whether the existing pins already live there is research's question.
- Any narrowed run of the new pulse-app probes must be selected with `--filter-expr` / `-E` **under `--workspace`**, not with `-p` — run-scope must match build-scope or the pulse-app test binaries fail to link (`required to be available in rlib format`) (per test-plan.md §3 `run`).
- The chunk plan's `## Test Commands` MUST carry the full standard gate set unconditionally (`cargo fmt --check`; `cargo clippy --workspace --all-targets --all-features -- -D warnings`; `cargo nextest run --workspace --profile ci`; `cargo xtask capability-drift`; `cargo xtask capability-widening-check`), with the three `--prefix pulse-app/ui` webview gates excluded only if the Files-to-modify / New-files lists touch zero `pulse-app/ui/**` paths (per test-plan.md §3 Per-chunk gate discipline). The scope predicts no webview work — confirm at P3 from the file lists.
- `ANDROMEDA_PULSE_L4_DETERMINISTIC` is an env-gated mode the chunk must reason about; the plan bans runtime monkey-patching of production state (`std::env::set_var` mid-test without cleanup) and requires constructor/parameter injection instead (per test-plan.md §8 Anti-monkey-patching, §11 Mocking).
- Assertions must bind to the **contract kind**, not to fixture-internal or literal produced values — the plan's stated form is "assert span_id is 8 bytes / trace_id is 16 bytes", whose analogue here is asserting the fingerprint's shape and its stability/distinctness properties rather than a hardcoded digest (per test-plan.md §11 Unit).
- Any incident read-back exercise must be self-bootstrapping: fixture data generated at runtime via builders/`rstest`, never a pre-baked corpus DB, `.sql` script, or committed snapshot (per test-plan.md §7 Self-bootstrapping requirement, §11 Test Data).
- Zero-flakiness budget applies and `#[ignore]` stays reserved for flake quarantine with a tracking issue — the existing pin `distinct_fingerprint_same_service_still_coalesces_to_one_incident` and the `assembler.rs` tests that rejected the prior retrieval-arm removal must stay green, not be skipped (per test-plan.md §10 Quality Gates, §11 Quality).

## Patterns to follow
- `rstest` `#[fixture]` + builder-factory composition for span/fault inputs rather than raw literals; flat `#[test] fn test_<entity>_<scenario>()` functions, no nested describe blocks (per test-plan.md §4 Fixture pattern + Conventions, §7).
- Explicit-parameter injection over ambient control, following the `triage` precedent where the clock is passed as `now_nanos` because the function takes the instant as an argument — the same reasoning applies to threading a fingerprint through `synthesize_cue` → cue-ref → producer instead of reaching for ambient/global state (per test-plan.md §4 "What unit tests cover" → triage crate).
- pulse-app internals reached through `pub` + `#[doc(hidden)]` accessors from `pulse-app/tests/*.rs` (per test-plan.md §2, §4).
- Prefer the expensive real-boundary form when the obvious in-process form would pass while the defect is live — the `corpus` cross-process key test is the plan's recorded precedent for that judgment call (per test-plan.md §4 → corpus crate).
- The `triage` crate's per-crate unit bullet in §4 (plus the §2 pyramid Unit row and §4 test-file-location list) is the plan's record of what each crate's tests cover; extending a crate's covered surface has repeatedly required a same-chunk amendment to those three restating sites (per test-plan.md §4 "What unit tests cover").

## Anti-patterns to avoid
- NEVER test private crate-internal functions as such — test public module boundaries (per test-plan.md §11 Unit); the pulse-app probe form is the sanctioned way to reach producer internals, not a licence to assert on incidental internals.
- NEVER assert against builder/fixture-internal identifiers or a hardcoded expected digest string — assert the contracted property (per test-plan.md §11 Unit).
- NEVER pre-populate a test DB from `.sql` scripts or stored snapshots, and NEVER share mutable state across parallel tests — each test gets its own `tempfile::TempDir` + in-memory instance (per test-plan.md §11 Test Data).
