# design extract — phase-32

## Chunk relevance

- route#35 "Metrics charts + logs stream" — IN DOMAIN. This chunk introduces two webview surfaces (Metrics tab content + Logs tab content) within the full dashboard shell. It involves: visual rendering on WebGPU canvas (time-series charts), tabular log stream with severity colors (semantic palette), and search/filter UI controls (form input pattern). All three sub-surfaces require design tokens, motion respect, and component pattern reuse from `design-system.md`.

## Constraints

- **Color tokens for time-series charts (Metrics tab):** Canvas Container background MUST be `#0F1117` (`--color-inset`) per `design-system.md` §Component Patterns "Canvas Container (Halo State Pulse, Latency River, throughput counter)". Chart line/series colors MUST come from the locked palette: `#4A90E2` (`--color-primary` Earth Blue) for healthy/nominal series; `#C7556A` (`--color-accent` Alert Burgundy) for anomaly/error series; `#17B3A3` (`--color-feedback-success`) sparingly for success/confirmation series. No new hues introduced by this chunk per `design-system.md` §Anti-Patterns Universal Bans "NEVER use color purely for decoration".
- **Log severity color encoding (Logs tab):** Severity-to-color mapping MUST use Semantic Colors from `design-system.md` §Color Palette: ERROR/FATAL → `#C7556A` (Alert Burgundy text + border); WARN → `#C7556A` border + `#E8EEF7` text (per Warning row in Semantic Colors table); INFO → `#4A90E2` (Earth Blue Info row); DEBUG/TRACE → `#7D8697` (`--color-text-tertiary`) per Text Hierarchy. No introduction of yellow/orange/green sentinels — palette is locked to NASA Deep Space at 6 named hues.
- **Severity color paired with text/icon (not color alone):** ERROR/WARN/INFO log rows MUST display the severity text label (e.g., "ERROR", "WARN") OR an icon adjacent to the colored row indicator per `design-system.md` §Anti-Patterns Universal Bans "NEVER use color purely for decoration. Every color in the palette communicates meaning". Color alone is insufficient state encoding (a11y SC 1.4.1 binding flagged below).
- **Typography on chart axes / log rows:** Metrics chart axis labels + log timestamps + log message bodies + severity values MUST use `--font-code` (JetBrains Mono, 12px, 0.5 tracking for code-like values, 0 tracking + tabular-nums for data) per `design-system.md` §Typography rows "Code" + "Data" — monospace signals "immutable telemetry fact". Log row supplemental UI labels (search field placeholder, filter dropdown labels, severity filter chip text) use `--font-body` (IBM Plex Sans 14px) for "Body" or `--font-display`/Label for filter chips.
- **Spacing on log row stream:** Row internal padding MUST be `--spacing-sm` (8px) per `design-system.md` §Component Patterns Tables "padding space-sm (8px)"; data table row borders 1px `rgba(74, 144, 226, 0.1)` (Subtle) between rows. Hovered log row background `rgba(74, 144, 226, 0.1)` (Primary at 10%) with no transition (instant per 0.35 expression budget per `design-system.md` §Component Patterns Tables).
- **Spacing on metrics chart cards:** Each chart card uses Card pattern: `--color-raised-1` (#262A33) background, 1px border `rgba(74, 144, 226, 0.3)` (subtle), padding `--spacing-md` (16px), `--radius-md` (6px) per `design-system.md` §Component Patterns "Cards / Panels".
- **Search/filter input styling:** Search bar follows `design-system.md` §Component Patterns "Input Fields / Form Controls": `--color-inset` (#0F1117) background, 1px subtle border, focused 1px `#4A90E2` border + 3px outset box-shadow `0 0 0 3px rgba(74, 144, 226, 0.2)`, placeholder `#56606E` italic, padding `--spacing-sm` horizontal + `--spacing-xs` vertical. Filter dropdown popover uses `--color-raised-2` (#2D3139) per Surface Scale row "Raised-2 — dropdowns, popovers, tooltips".
- **WebGPU canvas fallback message:** Metrics chart MUST gracefully degrade when `navigator.gpu` undefined per `design-system.md` §Component Patterns Canvas Container "fallback to `<canvas>` with message 'WebGPU not supported in this browser' if `navigator.gpu` is undefined". Fallback message text uses `--color-text-tertiary` (#7D8697) on Inset background.
- **Empty / loading / error states for metrics + logs:** Empty state ("No metrics in window" / "No logs match filter") centered text `#7D8697` (Tertiary) with optional 24px telescope icon per `design-system.md` §Component Patterns "Loading / Empty States". Skeleton uses `--color-raised-1` background with discrete 50ms on/off opacity pulse, NOT smooth fade, per design-system.md Component Patterns Loading constraint at expression 0.35.
- **Border radius:** Cards/panels use `--radius-md` (6px); search input + filter chips use `--radius-sm` (4px); severity badges (if used as pills around the severity value) use `--radius-full` (9999px) per `design-system.md` §Border Radius "Avatars, pills, toggles, badges — service status badges, loading indicators".
- **Motion budget for chart updates / log stream entries:** Chart re-render on time-window change uses 200ms ease-out fade (panel transition tier) per `design-system.md` §Motion table at expression 0.35. New log row arrival is INSTANT (no entrance animation) per `design-system.md` §Motion "Entrance animations: none — components render instantly; motion confirms state changes only, not arrivals" + Hard limits "NO staggered reveals beyond component load (no sequential entrance of list items)".
- **Halo State Pulse exemption boundary:** WebGPU compute aggregation pipeline for time-series metrics is data-viz layer rendering — it is part of the "data-driven motion" dimension separate from chrome expression budget per `design-system.md` §Motion intro "Canvas motion (WebGPU shader-driven Halo State Pulse, Latency River, throughput counter) is a separate dimension governed by the data-viz layer and NOT bound by the chrome expression number". The metrics charts inherit the same exemption: chart pulse/redraw cadence is data-driven, NOT chrome.

## Patterns to follow

- **Canvas Container reuse for metrics chart:** Apply `design-system.md` §Component Patterns "Canvas Container" tokens — `--color-inset` background, full container width/height responsive, free aspect ratio, WebGPU-or-fallback initialization. Same pattern that chunk #28 (CanvasContainer reservation) and chunk #34 (ConstellationCanvas) follow. Reuse helper functions chunk #34 already exposes: `requestWebGPUAdapter`, `createFrameLoop`, `recordFrameMs`, `useReducedMotion` (per session-handoff "TracesRoute layout refactor" listing helpers).
- **Tables pattern for log stream:** Follow `design-system.md` §Component Patterns "Tables (telemetry data)" exactly: transparent row background, hovered row `rgba(74, 144, 226, 0.1)` with no transition, header background `--color-base` + 600 weight + 12px, data cells JetBrains Mono 12px tabular-numerals + `--spacing-sm` padding, 1px `rgba(74, 144, 226, 0.1)` row borders. This is the same pattern chunk #34's TraceTable consumed.
- **Card pattern for chart panels:** Each metric chart wrapped in a Card per `design-system.md` §Component Patterns "Cards / Panels" — Default state border subtle, Hovered border emphasis, Selected/Active border emphasis or solid Primary.
- **Form Controls pattern for search/filter:** Search input + filter dropdown follow `design-system.md` §Component Patterns "Input Fields / Form Controls" + "Buttons" (Secondary variant for filter pill toggles: `--color-raised-1` background, `--color-text-primary` text, 1px subtle border, hovered border `#4A90E2`).
- **Iconography for severity / filter / search:** Use Lucide/Heroicons fallback library per `design-system.md` §Iconography "Secondary library" for generic search-magnifier glyph + filter funnel glyph + severity-class icons (info-circle, alert-triangle, x-circle). Custom domain set (aperture/telescope/constellation-grid/star/circular-pulse) does NOT include severity icons; library fallback is the correct path. Icon size 16px inline within rows, 20px for search-bar leading icon per Iconography size grid.
- **Focus ring pattern:** Focus on chart card, log row, search input, filter chip MUST render `box-shadow: 0 0 0 3px rgba(74, 144, 226, 0.2)` or `outline: 3px solid #4A90E2` per `design-system.md` §Surface: desktop-webview "Focus / Keyboard Navigation".

## Anti-patterns to avoid

- **NEVER introduce non-palette colors for severity or chart series.** Per `design-system.md` §Anti-Patterns "Universal Bans": only the 6 named hues (Deep Control Gray / Earth Blue / Alert Burgundy / Status White-Blue / Stellar Indigo / Feedback Cyan) are permitted. In particular: do NOT pick orange/yellow for WARN even though that's the dashboard convention elsewhere — the palette is locked to NASA Deep Space.
- **NEVER use bright contrasty white-on-pure-black for chart axes / log timestamps.** Per `design-system.md` §Anti-Patterns Rejected Defaults — `#E8EEF7` Status White-Blue on `#1A1D24` is the right contrast pair (~8.5:1, deliberately reduced from pure white for circadian alignment in marathon observation sessions).
- **NEVER apply gradients or glassmorphism to chart cards or log rows.** Per `design-system.md` §Anti-Patterns Universal Bans — flat, matte surfaces only. The Halo State Pulse WebGPU layer is the SOLE gradient/blur exception. Chart fill gradients (line-area-fill style) are NOT permitted; use solid line colors only.
- **NEVER use spring physics, bounce easing, or 500ms+ durations for log row appearance / chart transitions.** Per `design-system.md` §Motion Hard limits and Rejected Defaults "Animated state transitions using bounce easing and 500ms+ durations".
- **NEVER apply staggered reveals to a list of new log rows or new metric data points.** Per `design-system.md` §Motion Hard limits "NO staggered reveals beyond component load".
- **NEVER use hover-only severity-color tooltips without a keyboard alternative.** Per `design-system.md` §Anti-Patterns desktop-webview "NEVER use hover-only interactions without keyboard alternatives".
- **NEVER use `alert()` / `confirm()` / `prompt()` for filter validation errors.** Per `design-system.md` §Anti-Patterns desktop-webview — surface filter parse errors via inline error border `rgba(199, 85, 106, 0.5)` + error text `#C7556A` below input per Form Controls error state.
- **NEVER use generic Lucide library icons as the primary visual language for the chunk's chrome.** Per `design-system.md` §Anti-Patterns Rejected Defaults — Lucide is fallback only. Severity, search, filter icons are acceptable Lucide use; primary navigation/identity icons stay in the custom set.
- **NEVER converge on the safe choice (table-with-search-bar-on-top + chart-grid sidebar).** Per `design-system.md` §Anti-Patterns Universal Bans "NEVER converge on common 'safe' choices". Layout composition is the layouts specialist's domain — design only flags the discipline.

## Contract bindings

- **Design ↔ a11y (Use of Color SC 1.4.1):** Severity color encoding in log rows binds to a11y "not-color-alone" discipline. Each ERROR/WARN/INFO/DEBUG row MUST pair the colored indicator with text label OR icon — design tokens supply the colors; a11y validates the pairing rule. Cited in `design-system.md` §Anti-Patterns Universal Bans + §Decisions Log 2026-05-03 "Lift `--color-accent`" Usage Scope Refinement (`--color-text-primary` text + `--color-accent` border + icon for state conveyance).
- **Design ↔ a11y (Contrast SC 1.4.3 / 1.4.11):** Text Hierarchy table contrast targets (Primary ≈ 8.5:1, Secondary ≈ 6.8:1, Tertiary ≈ 4.2:1 large text only, Muted ≈ 2.1:1 decorative only) must hold for all log row text + chart axis labels. Tertiary `#7D8697` is large-text-only — any 12px tertiary text in log rows or chart axis labels triggers a11y review.
- **Design ↔ a11y (Reduced Motion SC 2.3.3 AAA):** Per `design-system.md` §Motion Accessibility, all chart transitions + log stream entry behavior MUST respect `prefers-reduced-motion: reduce` — chart re-render fade goes 200ms → 0ms; severity flash on new error log row goes instant. WebGPU compute aggregation pulse cadence (if metrics chart inherits Halo-style breathing for "live data" visual) degrades to static glow analog per Brand Identity signature element rule. Universal invariant from `CLAUDE.md` Critical Warnings: "Every transition (chrome AND data-driven Halo State Pulse) MUST respect `prefers-reduced-motion: reduce`".
- **Design ↔ obs (frame budget instrumentation):** Per `design-system.md` §Downstream Readiness "For obs specialist", the metrics chart's WebGPU compute aggregation reuses chunk #29's `telemetry.frontend.record_frame_ms` bridge (per session-handoff "Trace timeline + per-service constellation" pattern). Frame duration metric MUST be emitted from the metrics chart canvas per obs plan SLO ≤33ms p99. Design provides the measurement intent (canvas pulse cadence stays data-driven); obs configures the bridge.
- **Design ↔ layouts:** Per-screen wireframe + focus order for Metrics tab and Logs tab is layouts specialist's domain (separate sub-agent). Design here only contributes tokens + component patterns; layout composition (chart-grid columns, log-stream height, search bar position) is owned by `layout-templates.md`.
