## Constraints

- The new `incidents.get_report(id)` TauRPC procedure MUST follow the QUADRUPLE-binding discipline: (1) router registration in the owning crate; (2) entry in `pulse-app/capabilities/` JSON gated under `pulse:default`; (3) `xtask/src/main.rs::EXPECTED_PROCEDURES` extension; (4) `emit_taurpc_bindings` test merge — per CLAUDE.md §Session Additions 2026-05-12 + per security plan §API Security row "TauRPC capability authorization." Bridge call is silently rejected at runtime if (2) is missing.
- The `id` argument MUST be `serde`-deserialized + `TryFrom`-validated (e.g., incident ID shape check — UUID/u64/opaque-string-bounded — and reject empty / overlong values) at the procedure entry per security plan §Input Validation row "TauRPC bridge" — return `AppError::Validation { field, reason }` on rejection per Conventions Error response schema.
- Markdown serialization of telemetry excerpts (P-035 Anonymized Telemetry Excerpts) MUST route every OTLP-derived attribute value through `security::scrubber::scrub_attribute` BEFORE the markdown string is composed, per security plan §Security Anti-Patterns §Logging "Uniform scrubber coverage (post-chunk-#72 reality)" — the invariant is "any attribute value crossing into … self-observation log sink OR persistent storage" and the clipboard payload is an equivalent egress surface (visible to LLM clients, screen recordings, paste history) that demands the same gate. Apply BEFORE bincode/JSON/markdown encoding, never after.
- The Copy Report markdown payload MUST emit a visible `pulse://stream/snapshot-progress`-equivalent event (or reuse the existing topic — orchestrator to decide whether to extend) at clipboard-write time per security plan §Logging "Snapshot / clipboard / MCP-tool-response hygiene" — clipboard exfil is a load-bearing Minimal-tier concern, the non-suppressible "X bytes copied" toast is the visible-signal contract.
- The `Report` surface MUST honor the existing `pulse:clipboard` capability (write-only — read excluded per arch §Occupied Resources 2026-05-11 entry); clipboard read MUST NOT be added к this capability per security plan §Security Anti-Patterns §API capability-widening ban.
- `AppError::Internal { message }` returned from `incidents.get_report(id)` MUST be sanitized one-liners (no stack traces, file paths, Rust struct names, library versions, internal hostnames) per security plan §Error Handling §TauRPC bridge — full chain stays in `tracing-subscriber` JSON sink.

## Anti-patterns к avoid

- NEVER serialize an `anyhow::Error` directly across `incidents.get_report(id)` — convert to `AppError` first per CLAUDE.md "Never serialize anyhow::Error directly across the TauRPC bridge" + security plan §Security Anti-Patterns §Code Patterns row.
