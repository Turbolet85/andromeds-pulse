## Constraints

- Pulse frequency MUST be data-driven: `clamp(throughput_hz / 1000, 0.8, 2.4)` Hz; the data-viz layer applies the clamp before pulse-cycle emission. Frequency derives from telemetry throughput, NOT from chrome timing tokens or animation timeline (per §Brand Identity Signature element + §Downstream Readiness obs-handoff line 1; the obs handoff explicitly confirms the frontend clamps before logging — frontend owns the clamp).
- Color interpolation MUST use **LCH color space** (not RGB, not HSL) between Earth Blue `#4A90E2` and Alert Burgundy `#C7556A`, mapped from service error rate. LCH is the spec — RGB midpoint produces muddy gray transit (per §Brand Identity Signature element + §Color Palette Core Colors + §Decisions Log 2026-05-03 burgundy lift note "LCH chroma ~12 unit shift").
- Blur radius MUST sweep `4–16 px` per pulse cycle, period `0.6–1.2 s` per breath (inverse of frequency clamp). Cycle is sinusoidal (per §Motion High-impact moment #1 Halo State Pulse breathing).
- Canvas background MUST be `#0F1117` (Inset / `--color-inset`) — the recessive surface is calibrated к let the radial gradient + blur halos pop. NEVER place Halo on `--color-base` or `--color-raised-*` backgrounds (per §Surface: desktop-webview Component Patterns "Canvas Container" + §Color Palette Surface Scale "Inset" usage).
- Halo State Pulse is **EXEMPT from chrome expression budget** (0.3 base / 0.35 webview / 0.2 native). It runs on its own dedicated WebGPU canvas layer outside React's render tree and is governed by data-viz dimension, NOT by the 150–200ms chrome motion ceiling (per §Motion intro paragraph + §Motion Hard-limits "NO canvas/WebGL except dedicated Halo State Pulse layer, EXEMPT per WebGPU mandate").
- Halo State Pulse is the **ONLY exception** to the depth-strategy `borders-only` rule (it uses radial gradient + blur). Visual weight is reserved for the signature element; do NOT export the gradient/blur technique к chrome (per §Depth Strategy Rationale + §Anti-Patterns Universal Bans "Halo State Pulse is the ONLY exception").
- `prefers-reduced-motion: reduce` MUST degrade pulse к static glow (no pulsing rhythm, no blur sweep) BUT hue MUST still update per error rate (LCH interpolation continues at static blur radius, e.g., midpoint 10px) (per §Motion Accessibility line + §Downstream Readiness a11y handoff line 4).
- WebGPU initialization MUST follow the established pattern: render fallback message "WebGPU not supported in this browser" if `navigator.gpu` is undefined (per §Surface: desktop-webview Component Patterns "Canvas Container").

Arrow data is pushed into canvas via WebGPU compute shader (chunks #28+#29 establish the pipeline), side-stepping VDOM diffing cost. Render Halo on its own layer above/around the constellation dot positions (per §Surface: desktop-webview "Performance notes" + §Color Palette §Border Progression composition rule).
- **Three-surface signature presence (mandatory triple-placement)**: Halo MUST render in (1) full dashboard canvas (per-service constellation dots), (2) compact widget (aggregated badge), and (3) tray icon (unified halo around service-count badge). Chunk #31 is the foundation — it ships the WGSL shader + LCH interp module that all 3 surfaces consume; downstream chunks #32 (compact widget infographics) and tray-icon chunk consume it (per §Self-Validation Protocol Test 3 Signature Test + §Brand Identity Signature element).
- **Tray-icon visual equivalence fallback**: if the tray context cannot run WebGPU, SVG filter substitution is permitted PROVIDED visual equivalence: blur radius 4–16 px per pulse cycle, LCH color interpolation fidelity ≥95% of Earth Blue ↔ Alert Burgundy shift, opacity envelope 0.6–1.0 matching WebGPU baseline. Chunk #31 should design the WGSL shader + LCH interp module к be portable enough that an SVG-filter equivalent can mirror its math (per §Surface: desktop-native Component Patterns Tray Icon halo encoding paragraph).

Stellar Indigo / Feedback Cyan / Status White-Blue do NOT participate in Halo color interpolation — they belong к other semantic roles (per §Color Palette Core Colors anchors).
- **Tokens not magic numbers**: pulse hex endpoints reference `--color-primary` (#4A90E2) and `--color-accent` (#C7556A) tokens; canvas background references `--color-inset` (#0F1117). ## Anti-patterns к avoid

- **NEVER render Halo using RGB (or HSL) interpolation between endpoints** — produces muddy gray midpoint transit. LCH color space is the locked technique per §Brand Identity Signature element + §Decisions Log 2026-05-03 LCH-chroma anchor. RGB midpoint between `#4A90E2` and `#C7556A` is approximately `#896E96` (a desaturated lavender) — semantically wrong for an anomaly indicator.
- **NEVER use uniform monochrome status icons (green checkmark / red X) as a substitute** for Halo State Pulse on any service-health surface — explicitly rejected per §Anti-Patterns Rejected Defaults: "Halo State Pulse encodes TWO independent dimensions (throughput rhythm + error hue). At-a-glance peripheral detection of both 'is the service alive?' (pulsing) and 'is the service broken?' (color) simultaneously."
- **NEVER apply gradient or blur techniques to chrome elements** even if Halo's gradient looks attractive — Halo is the ONLY exception to the borders-only depth strategy. Glassmorphism, decorative gradients, and shadow-on-dark are universally banned everywhere else (per §Depth Strategy + §Anti-Patterns Universal Bans).
- **NEVER let chrome motion budget constrain Halo** — chrome is 150–200ms ease-out; Halo runs at 0.6–1.2 s per breath (data-driven). Conversely, do NOT export Halo's data-driven duration model к chrome animations (which must stay snap/scale/opacity at 150–250ms per §Motion duration scale).
- **NEVER use bounce easing or spring physics on Halo** — sinusoidal breathing is the spec; bounce/spring is universally banned at this expression level (per §Motion Hard limits + §Anti-Patterns Rejected Defaults bullet 3).
