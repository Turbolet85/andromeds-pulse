## Patterns к follow

- Tailwind v4 `@theme` block already declared in chunk #10 owns ALL design tokens including motion (`--duration-fast`, `--duration-standard`, `--easing-out`, `--easing-in-out`); chunk #15 consumers reference these via `var()` or Tailwind utility classes (`duration-150` / `ease-out`) — no inline durations or magic numbers in component code (per design plan §Surface: desktop-webview Tokens block).
- Custom React hook + Tailwind variant dual-surface pattern: `useReducedMotion()` from motion/react for React components needing imperative branching (e.g., conditionally skipping a `motion.div` animation prop), `motion-reduce:transition-none` Tailwind v4 variant for static CSS-only elements — both surfaces map к the same OS-level `prefers-reduced-motion: reduce` media query (per design plan §Motion Accessibility row + §Surface: desktop-webview Tokens motion section).
- Hard limits subsection in §Motion is the lint target list: durations (150ms, 200ms, 250ms, 350ms only), easing names (ease-out, ease-in-out only), 7 hard-limit bans (NO parallax / NO scroll animations / NO spring physics / NO staggered reveals / NO 3D transforms / NO canvas/WebGL except Halo / NO opacity > 200ms) — chunk #15 wires the runtime; chunk #46 (a11y audit + perf SLO) verifies no consumer violates the list (per design plan §Motion Hard limits subsection + §Downstream Readiness "For tests specialist" bullet).
- Per-surface expression-level inheritance: chunk #15's motion wiring applies to desktop-webview (0.35 expression — skeleton pulsing, 200ms panel transition, Investigation Capture Collapse supporting moment) and inherits hard limits к desktop-native (0.2 expression — tray icon state changes only); the canvas frame loop reduced-motion gate is desktop-webview only (tray icon halo composition is TBD by Phase 8 per design plan §Surface: desktop-native Tray Icon row).

## Anti-patterns к avoid

- NEVER add spring physics, bounce easing, parallax, scroll-driven animations, staggered list reveals, 3D transforms, or opacity fades > 200ms к the motion library wiring — these are the 7 hard-limit bans for 0.3–0.35 expression (per design plan §Motion Hard limits subsection).
- NEVER use a generic loading spinner, decorative motion, or "delightful" entrance animations on chrome surfaces — design rejects "delightful" framing in favor of "state-confirming" motion; entrance animations are explicitly NONE for this expression level (per design plan §Motion This project's values "Entrance animations: none" + §Anti-Patterns Rejected Defaults "Animated state transitions using bounce easing").
- NEVER hardcode duration values (e.g., `transition: 150ms` literal in JSX style prop) — all motion values MUST trace к `--duration-fast` / `--duration-standard` `@theme` tokens via Tailwind utility classes or `var()` (per design plan §Self-Validation Protocol Token Test "Random hex values or magic numbers signal no system" applied к motion).
- NEVER suppress LCH hue interpolation on Halo State Pulse in reduced-motion mode — color shifts per error rate MUST continue; only the sinusoidal pulse + blur radius cycling is suppressed (per design plan §Motion Accessibility "Halo State Pulse degrades to static glow (no pulsing rhythm, but hue still updates per error rate)").
