## Patterns to follow
- The `aria-describedby` visually-hidden aggregate-summary pattern at the named `<section>` landmark (stable literal name, data-varying text in the DESCRIPTION, not the name) — the established way to expose changing counts without churning the SR rotor (a11y-plan §7 Landmark roles).
- Harness wiring as-is if any spec is touched: `helpers/mock-tauri.ts` (`/^TauRPC__([\w.]+)$/`, `plugin:event|listen`, metadata-shaped window label), `helpers/v02-fixtures.ts`, `helpers/static-server.mjs` SPA fallback, `pa11y/run-pa11y.mjs` (a11y-plan §3 Harness wiring & conventions).
- Mock response sentinels `__mockReject` / `__mockDelayMs` for auditing error and in-flight states — the precedent if a damped/suppressed/reused-generation state ever needs an audited UI state (a11y-plan §3 Harness wiring & conventions).
- Suite-health check `npx playwright test --list` before trusting a green a11y run (a list-time import failure once silently disabled the whole suite) (a11y-plan §3 Harness wiring & conventions).
- Accessible-name-first selector binding under the measured-per-surface convention, `data-testid` only where no accessible anchor ships (a11y-plan §1 Critical paths → P1 row).

## Anti-patterns to avoid
- NEVER add excessive ARIA noise / stack announcements — do not wire a new `aria-live` or `role="status"` region for damper state, generation counts, or suppression outcomes (a11y-plan §11 Screen Reader).
- NEVER skip a11y on CI failure or defer it post-merge — the gate is fail-fast, and a backend chunk does not exempt the PR (a11y-plan §11 CI).
- NEVER claim WCAG conformance without machine output; manual/eyeball "no UI change" reasoning is not a substitute for the axe/Lighthouse/pa11y JSON (a11y-plan §11 Universal).
