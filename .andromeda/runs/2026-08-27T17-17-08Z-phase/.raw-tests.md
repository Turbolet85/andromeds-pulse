## Constraints
- Standard tier applies: the damper's decision logic is a module boundary and must carry **in-crate** `#[cfg(test)] mod tests` inside `crates/triage/src/cadence/` — cross-crate-only proof does not satisfy the Unit row (per test-plan §2 Test pyramid → Unit row; §4 Conventions → Test file location → Rust, which lists `triage` as a co-located-tests library crate).
- `pulse-app` is the standing exception: `[lib] test = false` makes co-located `mod tests` compile but never run, so any subscriber-boundary or obs-allowlist probe must live as a separate target under `pulse-app/tests/*.rs`, reaching internals via `pub` + `#[doc(hidden)]` (per test-plan §2 Test directory + naming conventions; §4 Conventions → Test file location).
- Clock must be injected, never read ambiently — and for `triage` specifically the plan records **explicit `now_nanos` parameter injection as the stronger form** over `tokio::time::pause()` where the function takes the instant as an argument (per test-plan §4 What unit tests cover → triage crate; §11 Universal → "NEVER use real time … without injection"). A refractory/benign-window damper is exactly this shape.
- Every chunk plan's `## Test Commands` must carry the **unconditional standard gate set** — `cargo fmt --check` · clippy `-D warnings` · `cargo nextest run --workspace --profile ci` · `cargo xtask capability-widening-check` · `cargo xtask check:ingest-progress` · `cargo xtask capability-drift` **LAST**; the three `npm` webview gates drop only when zero `pulse-app/ui/**` paths are touched (per test-plan §3 Per-chunk gate discipline).
- If the new observable lands in `pulse-app/src/observability.rs`, the **conditional boot-smoke gate fires** — that file is named in the trigger list as a boot path (boot-time subscriber/allowlist init, before the OTLP bind) (per test-plan §3 Per-chunk gate discipline → Boot-smoke gate).
- Narrow any `pulse-app` selection with `--filter-expr` / `-E` **under `--workspace`**, not with `-p` — measured rlib-format link failure otherwise; match run scope to build scope (per test-plan §3 `run` → Test selection).
- Zero-flakiness budget: a timing-window test that flakes once is quarantined and root-caused, never retried — no retry-once policy, no auto-retry (per test-plan §10 Zero-flakiness budget; §11 Quality).
- Fixtures self-bootstrap: telemetry for the idle/sustained leg enters over the real OTLP receiver (`crates/ingest/examples/inject_demo.rs`), never a pre-baked DB or `.sql` seed (per test-plan §7 Self-bootstrapping requirement; §2 Agent-runnable invariants).

## Patterns to follow
- The `triage` bounded-env-parse test family already established for `ANDROMEDA_PULSE_BASELINE_BOOTSTRAP_SECONDS` — rejects zero / empty / unparseable / at-or-above-ceiling, trims whitespace, unset is byte-identical to the default, and **every rejection falls back rather than panicking** — is the template if the damper introduces a growing-refractory or window-length knob (per test-plan §4 → triage crate).
- Obs-leaf allowlist probes under `pulse-app/tests/*.rs` (the `unit_observability_allowlist_*` shape) pin that the allowlist **permits** a new exact leaf; the plan is explicit that this is a boundary assertion, not a behavioural one, so it does not substitute for the in-crate pin (per test-plan §4 Conventions; §1 Pending coverage triggers → `cadence-cycle-rate-in-crate-coverage`).
- Time-window elapse via `#[tokio::test(start_paused = true)]` + `tokio::time::advance(Duration)` where an ambient clock does exist (per test-plan §7 Seed strategies → Time-sensitive data; §8 Mocking table → Time mocking).
- **Direct-binary smoke variant** is the sanctioned form for the idle-window rate measurement: launch `target/{debug,release}/pulse-app.exe` under a fresh `ANDROMEDA_PULSE_DATA_DIR`, seed over the real receiver, assert from the run's own `&lt;data_dir&gt;/logs/agent-latest.jsonl*` artifacts, shut down by specific pid with `:4317`/`:4318` confirmed released. **Measure-first RED and GREEN legs each get their own fresh data dir**, and the 0-ERROR clean-log assertion binds the GREEN leg only (per test-plan §3 Direct-binary smoke variant).
- Mutation-check every new pin so it demonstrably discriminates (neutralize the mechanism ⇒ RED) — the plan's repeated finding is that a one-time live observation standing in for a per-run gate leaves regressions invisible (per test-plan §1 Pending coverage triggers → `cue-latch-emitter-wiring-coverage`, `viz-read-connection-router-wiring-coverage`).

## Anti-patterns to avoid
- NEVER `sleep(N)` for synchronization — wait on an explicit signal (status poll / channel / obs record). A refractory-elapse test built on wall-clock sleeps is both flaky and slow (per test-plan §11 E2E).
- NEVER test crate-private implementation details — pin the **public module boundary**. If the damper decision lives inside an async closure or tick loop, the plan's precedent is to lift the classification into a pure fn so it can be asserted (per test-plan §11 Unit; §1 `window-navigation-check-behaviour-unit-coverage`).
- NEVER `std::env::set_var` mid-test without cleanup to steer a window constant — use constructor/fixture injection (per test-plan §11 Mocking → anti-monkey-patching; §8 Anti-monkey-patching).

## Contract bindings
- **tests ↔ obs (log format).** The harness `logs` verb and `xtask::smoke` read the ROTATED family `agent-latest.jsonl*` across three precedence-ordered bases — the `*` is load-bearing because the sink is `tracing_appender::rolling::daily`. Any damper observable the chunk adds is asserted by grep/jq over that NDJSON, so the scope's outcome-3 "exact allowlist leaf, no bare prefix key" is what makes the tests-side assertion expressible (per test-plan §3 `logs` Command body + §3 Log format + §3 Bootstrap item 4 `log-format-bind-with-obs`).
- **tests ↔ obs (status/readiness).** The boot leg's readiness signal is the TauRPC `health` shape (`status` / `subsystems.*.status` / `pid` / `uptime_ms`); note `bash scripts/agent-run.sh status` exits 0 against a dead system, so it evidences the harness contract only — the run's own artifacts are the evidence of record (per test-plan §3 Status endpoint shape; §3 Direct-binary smoke variant).
- **tests ↔ obs (ingest-progress gate).** `cargo xtask check:ingest-progress` keys on obs `buffer.tick` / `buffer.consumer.stalled` records; its **NEUTRAL arm (no `buffer.tick` at all)** is what makes the gate safe over a deliberately-idle leg — relevant because this chunk's target scenario is zero ingest by construction (per test-plan §3 Per-chunk gate discipline).
