# obs extract

## Relevance
Relevant — the chunk's outcome 3 ("the damper's decisions are observable... an exact allowlist leaf, no bare prefix key") is an obs deliverable, and the touched seam (`crates/triage` cue/cadence + the pulse-app subscriber boundary) is a registered `triage.*` / `cadence.*` telemetry family under obs-plan §8.

## Constraints
- Any NEW damper observable requires its OWN **exact** allowlist leaf enumerating **every** field its emit site emits, and **no bare `triage` / `triage.cue` / `triage.cadence` prefix key may exist** — a prefix key widens every sibling target to one field set (per obs-plan §8 Default-deny posture, `triage.cue.tick` + `triage.baseline.bootstrap_window.override` entries). If the observable is named `metric.*` instead, the rule inverts: a bare `metric` key legitimately exists and keeps `value` while silently redacting every label, so a per-target leaf is still mandatory (per obs-plan §8, delegated-timing block).
- A partial leaf is worse than an absent one: it leaves the target **partly redacted while an exact-resolve probe still passes**. Guards must assert the field SET in both directions plus a fallback discriminator, and must live under `pulse-app/tests/` because `[lib] test = false` compiles but never runs a src-level `mod tests` (per obs-plan §8, `triage.cue.tick` three-way mutation check).
- New damper counters must be **tick-aggregated as FIELDS** on an existing heartbeat rather than emitted per cue / per suppression / per generation decision — per-cue and per-trigger emission is barred by the §11 hot-path rule, and §5 names `cadence.trigger`'s one-record-per-cycle as why the runaway log reached 131 MB (per obs-plan §5 Conceptual instrument types, cue-admission-bound + cadence-cycle-rate rows; §11 Telemetry Strategy / Logs).
- Damper fields must be aggregate numerics or bounded static labels only — never `scope_id`, a service name, incident identity, query text, or hashed digest content. §8 records that the CueLatch's `(kind, scope_id)` map key stays in memory and is never logged; a content-hash design direction must not turn the digest into a field (also §11 Metrics unbounded-cardinality ban) (per obs-plan §8 `triage.cue.tick` entry; §11 Metrics).
- A damper state-transition log (engaged / released) must fire **once per transition and once on recovery, never per cue**, with bounded static `reason` + `consequence` and a threshold sited so an in-spec condition cannot trip it — the `buffer.consumer.stalled` shape (per obs-plan §6 Log levels mapping, `warn` row).
- **Tick presence is LIVENESS, not PROGRESS** — a damper that legitimately suppresses generations must not leave "suppressed" and "dead" reading identically to the liveness signal; the companion progress-style reading is what makes the difference legible (per obs-plan §1 Heartbeat ticks; §10 Standard+ invariants).
- Every new field is restated at all of its sites: a tick field at §1 + §5 + §8 (triple-site), a new WARN target at §6 + §8 (dual-site) — a §8-only apply leaves the others stale (per obs-plan §8 entries; amendment-history rules of 2026-08-26 and 2026-08-16).

## Patterns to follow
- **Tick-aggregated counter as fields on an existing heartbeat**: `triage.cue.tick` (9 fields, emitted from `crates/triage/src/cue/emitter.rs::run_one_emit_cycle`) and `cadence.tick` (8 fields, `crates/triage/src/cadence/coordinator.rs`) are the registered carriers at exactly this seam (per obs-plan §5 + §8).
- **Transition-WARN precedent**: `buffer.consumer.stalled` — bounded static `reason`/`consequence` + two numerics, once per healthy→stalled transition and once on recovery, threshold deliberately above the in-spec cap, with the "otherwise indistinguishable from healthy" rationale stated in §6 (per obs-plan §6 `warn` row; §8 leaf; §10).
- **Leaf-guard file pattern**: `pulse-app/tests/unit_observability_allowlist_*.rs` (e.g. `unit_observability_allowlist_cue_tick.rs`, `..._consumer_stall.rs`), each with exact-resolve + complete-set-both-ways + a fallback discriminator, mutation-checked (per obs-plan §8).
- **PII canary at the emitter**: `run_one_emit_cycle_pii_canary_does_not_leak_into_tracing_fields` already guards the cue emit path against `scope_id` leakage — the shape a damper field addition should extend (per obs-plan §8 `triage.cue.tick`).
- **Bounded-static `error_category` / `reason` sets enumerated in the plan text**, as done for `interpretation.model.load.error` and `triage.baseline.bootstrap_window.override` (per obs-plan §6 `warn` row).

## Anti-patterns to avoid
- NEVER emit one record per cue, per suppression decision, or per reused brief — hot-path instrumentation and `info`-level hot-path logging are both banned (per obs-plan §11 Telemetry Strategy + Logs).
- NEVER register a bare prefix key (`triage`, `triage.cadence`) or ship a narrowed leaf; §8 records the bare-`interpretation` key at `pulse-app/src/observability.rs:1934` as a standing invariant breach and the exact reason a resolver-only probe passes vacuously (per obs-plan §8; §11 PII Scrubbing).
- NEVER label a damper observable with a digest, hash, `scope_id`, or client-supplied service name — unbounded cardinality in `tracing` fields is banned outside the §5 query-time exception (per obs-plan §11 Metrics; §5 cardinality discipline).

## Contract bindings
- **obs ↔ tests harness**: the log-format JSON schema is verbatim FROM the tests harness contract and obs aligns to tests, not vice versa — any harness assertion on damper behaviour reads the exact leaf's fields out of `~/.andromeda-pulse/logs/agent-latest.jsonl` (per obs-plan §3 Log format JSON schema; §6 Required fields).
- **obs ↔ security**: §8 Vectors 1/5 bind the damper's fields — no query text, no OTLP attribute values, no scope/service identity; a content-hash direction inherits this (per obs-plan §8 Data classification rules).
- **obs ↔ CI**: §10 CI gates run `xtask/ci/heartbeat-gap-check.sh` (&gt;45s per tick target) and `cargo xtask check:ingest-progress`; any new check script over `agent-latest.jsonl` must be NEUTRAL-tolerant (absent stream ≠ failure) and run-window-scoped (per obs-plan §10 CI gates + Load-profile constraints).
- **obs ↔ route backlog ("Diagnostics un-muting + harness-truth sweep")**: §8's remaining four-target muted backlog includes `triage.incident.auto_resolve.tick` (`duration_ms`, `evaluated_count`, `resolved_count`), which resolves to **nothing** and is redacted in production. That target sits in this chunk's auto-resolve outcome area but its un-muting is owned by the sweep entry, which the chunk's Boundaries explicitly exclude — so whether the auto-resolve churn outcome can be verified at the wire without that leaf is a question the plan must answer (per obs-plan §8 muted-diagnostic backlog).

- Every new damper observable resolves to its own EXACT allowlist leaf enumerating all emitted fields, with no bare `triage`/`triage.cadence`/`metric` prefix key serving it, guarded under `pulse-app/tests/` by a field-SET-both-ways test plus a fallback discriminator, mutation-checked (per obs-plan §8 Default-deny posture).

Whether HEAD's leaves actually stand at 9 / 8 is research's question.
- A PII canary run shows the damper's fields unredacted at the wire while `scope_id`, service names, digest content, and query text appear 0 times in the log (per obs-plan §8 PII Scrubbing + §11 PII Scrubbing).
- Over a comparable idle window, "quiet because damped" is distinguishable from "quiet because dead" from `agent-latest.jsonl` alone, and the §10 heartbeat gate stays green (no &gt;45s gap on any tick target) through that window (per obs-plan §10 Standard+ invariants + §1 Heartbeat ticks liveness-vs-progress).
