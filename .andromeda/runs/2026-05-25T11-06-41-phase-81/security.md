## Constraints

- Subprocess invocation of `llama-cli.exe` MUST treat the binary path AND every argument as deeply untrusted with respect to command injection: never construct args by string interpolation of OTLP-derived attribute values, fingerprints, digest fields, or any string field reaching the inference runner from a `pulse://stream/digests` payload (per §Security Anti-Patterns §Code Patterns first bullet — MCP STDIO command-injection cluster CVE-2025-49596 / -54994 / -54136 / -22252 anchors). All variable inputs (the rendered prompt, the schema reference) MUST flow through stdin (`-st --simple-io`) or file paths (`--json-schema-file <static-path>`) under our control, never `Command::arg(user_input)`.
- The `ANDROMEDA_PULSE_LLAMA_CUDA_BIN` and `ANDROMEDA_PULSE_LLAMA_CPU_BIN` env vars MUST be canonicalized via `strict-path` and asserted to point at an executable on disk before spawn — same pattern as `ANDROMEDA_PULSE_PLUGIN_DIR` / `ANDROMEDA_PULSE_DATA_DIR` (per §Input Validation row "CLI / env var inputs" + §Security Anti-Patterns §Input bullet "NEVER read `ANDROMEDA_PULSE_*_PATH` / `*_DIR` env vars without `Path::canonicalize()` + an assertion" — CWE-22 path traversal class; the binary path is functionally the same trust boundary as the plugin dir).
- Subprocess discipline (defense-in-depth against unbounded generation runaways already witnessed twice in spike work) MUST stack four bounds at every spawn site: (a) `kill_on_drop(true)` on `tokio::process::Command`; (b) explicit `-n {max_tokens}` argument; (c) `-st` single-turn flag forbidding conversation-mode auto-continue; (d) outer `tokio::time::timeout` wall-clock guard wrapping the entire await chain (per CLAUDE.md Tier 2 session learning 2026-05-25 "Subprocess discipline for long-running external tools"; chunk #84 architectural context explicitly cites this defense-in-depth). Missing any one of the four constitutes a regression of the swap's stated security posture.
- The `mistralrs` workspace dep + per-crate `mistralrs.workspace = true` in `pulse-app/Cargo.toml` MUST be REMOVED in the same commit that lands `LlamaCliInference`, not deferred. The deletion is load-bearing for `cargo deny check bans` posture — `mistralrs = "=0.8.0"` was the original Pre-D1 pin; leaving it in the lockfile + workspace dep list compounds dependency-closure risk against §Dependency Security CI gate (per §Anti-Pattern §Universal "NEVER ship a release without resolving... duplicate" generalized to "unused heavy dep").
- L4 inference subprocess stdout (the LLM-generated JSON) is functionally equivalent to an MCP tool response body and MUST NOT be logged verbatim — apply §Logging NEVER-log rule for "MCP tool response bodies" (the LLM-generated content can echo OTLP attribute values surfaced in the digest prompt; transitive PII leakage). Log only fingerprint metadata (token count / generation duration / schema-validation pass-fail / model tier label) — same redaction discipline as `crates/buffer/src/appender.rs` writes (per §Logging "What NEVER to log" list).
- AppError at the TauRPC bridge MUST sanitize subprocess failure modes (binary-not-found, spawn-failed, kill-on-timeout, non-zero exit, schema-validation-failed) into `AppError::Internal { message: <sanitized-one-liner> }` variants — never expose subprocess command-line strings, binary absolute paths, CUDA driver version strings, or model file paths to the webview (per §Error Handling external responses + §Security Anti-Patterns §Logging "NEVER expose stack traces, Rust struct names, file paths, or library versions in `AppError::Internal { message }`").
