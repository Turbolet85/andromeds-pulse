## Patterns to follow
- Pure decision, pinned per arm: `decide_ready`, `decide_settled`, `classify`, the witness reader and the series' decisions are pure functions with one unit pin per arm; a new counting arm for the before-ready boot follows that shape (per test-plan §1 Pending coverage triggers → `harness-cleanup-verdict-and-boot-spawn-shell-coverage`).
- Bounded readers of harness state files: the exit record is read through `read_ended`'s grammar (one line, at most 48 printable ASCII, anything else reads as no record, unit-pinned), and the witness file is read under a bound with one closed label out (per test-plan §3 `status`).
- Measure-first legs: the same form run twice, RED at the base and GREEN after, each leg on its own fresh data dir, the RED leg's expected signal recorded as evidence. A self-end leaves no `app.exit` and no `app.panic.fatal`, so the clean-log assertion passes vacuously over it; the evidence of record is the settle verdict, the witness label and the series verdict (per test-plan §3 Per-chunk gate discipline → Direct-binary smoke variant (accepted alternative form)).
- A leg proves its own preconditions: a run that could not evaluate reads `cannot-evaluate` / INCONCLUSIVE, never a pass — the close's "no self-end" reading holds only for boots that ran and took a verdict (per test-plan §3 Per-chunk gate discipline).
- Narrow a `pulse-app` test run with `--workspace -E 'binary(quality_gate_workflow)'`, not `-p pulse-app` (per test-plan §3 `run`).

## Anti-patterns to avoid
- NEVER add a retry-once policy for a flaky result — it masks the real failure (per test-plan §11 Test Anti-Patterns → Quality).
- NEVER ignore a flake; a flake is a real bug — and NEVER reference a third-party GitHub Action by floating tag if the close adds one to the boot job (per test-plan §11 Test Anti-Patterns → CI).
- NEVER a manual verification step: the variation and the green series are read from exit codes and the kept verdict files, not by a person looking (per test-plan §11 Test Anti-Patterns → Universal (agent-driven specific)).
