# tests extract

## Relevance
Relevant — the chunk's in-scope deliverable explicitly includes "test coverage that pins the decided semantic so it cannot silently drift back", across a library crate (`crates/buffer`) and the `pulse-app` binary crate.

## Constraints
- Standard tier (1) governs breadth: the decided semantics must be pinned at the **unit** level first (pyramid Unit row = comprehensive, all module boundaries), with integration only where the decision crosses a boundary (`span_events.fingerprint` read-back, incident registry) — per `.andromeda/test-plan.md` §1 (Test tier) + §2 (Test pyramid).
- **Test-location split is mandatory and asymmetric.** Layer-1 (`crates/buffer`) tests belong co-located as `#[cfg(test)] mod tests` in-crate; Layer-2 (`pulse-app/src/inference_runtime.rs`) probes MUST be separate integration-target files under `pulse-app/tests/*.rs` reaching internals via `pub` + `#[doc(hidden)]`, because `[lib] test = false` (the Windows WebView2 workaround) makes a co-located `mod tests` in `pulse-app` compile under clippy but **never run** — per §2 (Test directory + naming conventions) and §4 (Conventions → Test file location).
- The chunk plan's `## Test Commands` MUST carry the unconditional standard gate set — `cargo fmt --check`, `cargo clippy --workspace --all-targets --all-features -- -D warnings`, `cargo nextest run --workspace --profile ci`, `cargo xtask capability-drift`, `cargo xtask capability-widening-check` — with the webview trio (`npm run lint|typecheck|test --prefix pulse-app/ui`) excluded only if Files-to-modify touches zero `pulse-app/ui/**` paths (per §3 Per-chunk gate discipline). Whether the Layer-2 resolution reaches the incident-list UI (scope open question 2) decides that exclusion; research answers it.
- Any narrowed `pulse-app` run MUST use `--filter-expr`/`-E` **under `--workspace`**, not `-p` — §3 (`run` → Test selection) requires run-scope to match build-scope, since `-p` resolves a narrower subgraph than the artifacts a `--workspace` build produced.
- Fixtures must be self-bootstrapping at runtime via builder factories (`MockTraceSpan::builder()` et al.) + `rstest` `#[fixture]`; no pre-baked DuckDB rows, `.sql` seeds, or captured production telemetry (per §7 Self-bootstrapping requirement + §1 `agent-driven-discipline: Self-bootstrapping test data`).
- Layer-2's ~5-minute auto-resolve window is time-dependent and must be driven by injected time — `tokio::time::pause()`/`advance()`, or an explicit instant parameter where the function already takes one (per §8 Mocking → Time, §11 Universal "NEVER use real time without injection").
- Every assertion must be agent-parseable (exit code + structured stdout/JSON/log line); no human checkpoints (per §1 `agent-driven-discipline: No manual verification checkpoints`, §2 Agent-runnable invariants). Coverage/flakiness gates from §10 still bind: ≥ 75% line / 70% branch / 85% function, zero-flakiness (no retry budget).

## Patterns to follow
- **Boundary-pair pinning** — the `triage` bullet in §4 ("What unit tests cover") establishes the shape for pinning a decided threshold: assert **at** the boundary and **either side** of it. For Layer 1 that is the scope's worked pair (`src/a.rs` vs `src/b/c.rs`) plus a true-absolute case (`/…`, `C:\…`), so whichever semantic is chosen, the losing semantic fails the suite.
- **`rstest` fixture + flat naming** — `#[fixture]` reusable builders, flat `#[test] fn test_<entity>_<scenario>()` functions, no nested describe blocks (per §4 Fixture pattern + Conventions).
- **pulse-app integration-target probe** — the established form for reaching `inference_runtime` internals is a `pulse-app/tests/*.rs` file against `pub` + `#[doc(hidden)]` accessors (per §2/§4; precedent `pulse-app/tests/unit_observability_allowlist_feed.rs`).
- **Direct-binary smoke variant** — when the verification needs runtime state the harness `run` verb and `npx @tauri-apps/cli dev` cannot express (a live storm producing a second concurrent incident, `ANDROMEDA_PULSE_L4_DETERMINISTIC=true`, a fresh `ANDROMEDA_PULSE_DATA_DIR`, sustained `inject_demo` load), §3 accepts launching `target/debug/pulse-app.exe` directly and asserting from the run's own artifacts: 0 `app.panic.fatal` / 0 `ERROR` in `<data_dir>/logs/agent-latest.jsonl*`, shutdown by specific pid, `:4317`/`:4318` released — with `bash scripts/agent-run.sh status` still run as the listed harness gate.
- **Ephemeral in-memory DuckDB + `tempfile::TempDir` per test** for any fingerprint-column read-back leg (per §5 Setup/teardown, §11 Integration "NEVER mock DuckDB at integration level").

## Anti-patterns to avoid
- NEVER pin the semantic by testing private crate internals directly — §11 (Unit) requires assertions at public module boundaries; if `normalize_stacktrace`/`normalize_frame` are not public, the sanctioned route is the `pub` + `#[doc(hidden)]` accessor pattern, not a reach-in (§2/§4).
- NEVER synchronize the Layer-2 dedupe/auto-resolve assertions with `sleep(N)` or wall-clock time — wait on an explicit signal (status poll, channel/log event) or injected time (§11 E2E + Universal).
- NEVER seed the buffer for fingerprint fixtures from pre-baked rows or a production telemetry dump; generate synthetically at runtime (§11 Test Data, §7).

## Contract bindings
- **tests ↔ obs (log format):** the direct-binary smoke variant and any `created:false`/`deduped:true` outcome assertions grep `<data_dir>/logs/agent-latest.jsonl*` NDJSON — obs owns the field schema for the incident-outcome event, tests own the grep/jq assertion (§3 Log format; obs §Log format).
- **tests ↔ obs (status endpoint):** `bash scripts/agent-run.sh status` / TauRPC `health` readiness fields are the smoke gate's readiness signal; shape is obs-owned (§3 Status endpoint shape).
- **tests ↔ external Conductor harness:** the scope records that Conductor's P-017 spec clause, `FingerprintVariant` tests, and `scenarios/fingerprint-storm.toml` encode the current Layer-1 semantic. Per the chunk's Boundaries those files are READ-ONLY evidence (cite, never copy); the re-alignment cost is recorded in this repo's decision record and executed in that repo — it is not a test this chunk writes.
- **tests ↔ downstream acceptance authoring:** P-075/P-076 acceptances are explicitly out of scope; this chunk supplies the decided semantic they will encode (scope §"Why this precedes P-075 / P-076").
