# a11y extract

## Relevance
**Partial** — both decided layers are backend (a11y-plan §1 lists the Rust/IPC/storage entities as *Not-assertable*), but the chunk's own research question 2 (findings window, unread badge, per-service constellation severity join) lands squarely on assertable surfaces p8/p11 and the §5 findings-window focus contract; a11y binds only if the Layer-2 resolution changes what those surfaces render.

## Constraints
- The must-be-accessible set is **P1–P12** (extended from P1–P7), and every path must carry the universal minimums SC 2.1.1 Keyboard / SC 2.4.3 Focus Order / SC 4.1.2 Name-Role-Value with **zero WCAG AA violations** — no soft gate, no retry-once (per a11y-plan §1 surface-set extension note + §10 SLO Invariants).
- Any UI change flowing from the Layer-2 decision must hold the per-PR regression gate at **0 violation tuples** against `baselines/a11y-violations-summary.json` (informational Lighthouse-score tuples allowed), compared on the `{surface, wcag_criterion, selector, severity}` tuple (per a11y-plan §3 *Harness wiring & conventions* + §3 *CI integration*).
- The findings-window keyboard contract is fixed: focus enters at the first incident row, Tab cycles rows → "Mark all as read", Esc / blur / mark-all-read dismiss and restore focus **cross-window** to the FindingsCounter badge, row-select opens the report window without dismissing (per a11y-plan §5 *Focus order per layout* — findings-window). More concurrent rows must not perturb that sequence (SC 2.4.3) or create a trap (SC 2.1.2).
- The unread badge's 0→N transition must announce **once, politely** (SC 4.1.3), and live incremental updates must not steal focus from the current keyboard target (per a11y-plan §5 findings-window + §1 P4 row + §7 *Live regions*).
- Severity on the findings list and the per-service constellation join must not be conveyed by color alone — text label or icon supplement required (SC 1.4.1), with token pairs meeting SC 1.4.3 / 1.4.11 (per a11y-plan §6 *State color tokens* + §11 *Visual*).
- Standing rule: every new route/modal added in a chunk ships **one axe spec in the same chunk**, its fixtures in `helpers/v02-fixtures.ts`, and any newly-consumed TauRPC procedure mocked in the `TauRPC__<router.path>` shape; suite health verified with `npx playwright test --list` before trusting a green run (per a11y-plan §3 *Harness wiring & conventions*).
- No WCAG conformance claim without machine-verifiable evidence (axe-core / Lighthouse / pa11y / Playwright JSON); manual SR or keyboard passes are supplemental, never sole (per a11y-plan §2 *Agent-runnable invariants* + §11 *Universal*).

## Patterns to follow
- The **p8 findings dropdown / p9 diagnostic report modal / p11 constellation** axe specs are the template for asserting a changed incident surface; the `keyboard-focus/widget-and-modals.spec.ts` focus spec is the template for a changed Tab sequence (per a11y-plan §1 surface-set extension note + §3 *Harness wiring*).
- Simulating "two concurrent incidents for one service" is a **fixture** change in `helpers/v02-fixtures.ts` (incident payloads) driven through the existing `mock-tauri.ts` `TauRPC__` regex mock plus the `plugin:event|listen` push handler — not a new mock mechanism (per a11y-plan §3 *Harness wiring & conventions*).
- Cross-window focus restoration uses first-party Tauri events (`findings:dismissed` / `report:closed`), **not** `focus-trap-react` `returnFocusOnDeactivate`, which cannot cross window boundaries (per a11y-plan §5 *Focus restoration*).
- Status pattern for counts and non-blocking incident arrival: `status` / `aria-live="polite"`; `role="alert"` / `assertive` is reserved for blocking errors (per a11y-plan §4 *Status / Alert* row + §7 *Live regions*).
- Contrast/state assertions read design tokens verbatim via `getComputedStyle` + colorjs.io and emit PASS/FAIL per token pair with an SC reference (per a11y-plan §3 *Contrast verification harness* + §6).

## Anti-patterns to avoid
- NEVER convey a service's incident severity by color alone — pair `--color-accent` / `--color-feedback-success` with icon + text (per a11y-plan §11 *Visual*, SC 1.4.1).
- NEVER escalate incremental incident-count updates to `aria-live="assertive"` / `role="alert"`, and never let a live update move focus or emit redundant ARIA noise (per a11y-plan §11 *Screen Reader* + §1 P4 row).
- NEVER assert "a11y unaffected" from a human read, and NEVER defer a11y remediation to a follow-up chunk — a11y is a fail-fast PR gate with machine output required (per a11y-plan §11 *CI* + §2).

## Contract bindings
- **A11y violation JSON ↔ obs §6** — violations emit in obs's structured log format with `wcag_criterion` / `violation_type` / `severity` / `surface` / `selector` / `remediation` / `tool` / `tool_result_id`, tagged with `service.name` = `com.andromeda.pulse` (per a11y-plan §3 *Structured violation JSON schema* + §9).
- **A11y CI gate ↔ tests harness** — `npm run test:a11y` / `cargo xtask test:a11y` reuses the tests' 5-command E2E driver (`boot` / `run` / `status` / `cleanup` / `logs`) inside the same `ci.yml` (per a11y-plan §3 *Focus management test harness* contract binding + §9).
- **Severity/state colors ↔ design §Color Palette** — `--color-accent` / `--color-feedback-success` / `--color-primary` token pairs must meet SC 1.4.3 (4.5:1 text) or SC 1.4.11 (3:1 non-text) (per a11y-plan §6 *Color contrast pairs*).
- **Findings/report focus order ↔ layouts focus management** — the widget → findings → report window chain is the tab-sequence authority for these surfaces (per a11y-plan §5).
- Note: if the decision lands on **coalesce-per-service (status quo)** with no rendering change, the only binding that fires is the regression gate (baseline stays at 0 violation tuples). Whether the current findings/badge/constellation code already satisfies the §5 focus contract and the §7 polite-announcement requirement under a *second concurrent* incident is **research's question** — this plan states target state only.

## Acceptance criteria contributions
- (a11y) If the Layer-2 resolution changes any rendered incident surface, the full chain (`cargo xtask test:a11y` — axe-core/playwright + Lighthouse + pa11y) passes with **0 new violation tuples** vs `baselines/a11y-violations-summary.json` and Lighthouse a11y score ≥ 90 (per a11y-plan §3 *Harness wiring & conventions* + §10 *Build/deploy failure conditions*).
- (a11y) With two concurrent incidents for one service in the fixture set, the findings-window Tab sequence still matches visual order and Esc / mark-all-read still restores focus cross-window to the FindingsCounter badge (per a11y-plan §5 *Focus order per layout* + *Focus restoration*, SC 2.4.3 / 2.1.2).
- (a11y) An unread-count change from a second concurrent incident announces once via `aria-live="polite"` and does not move focus (per a11y-plan §5 findings-window + §7 *Live regions*, SC 4.1.3).
- (a11y) Per-service severity in the constellation/findings list remains conveyed by text or icon in addition to color when a second incident joins on `scope_id` (per a11y-plan §11 *Visual* + §6 *State color tokens*, SC 1.4.1).
