# obs extract

## Relevance
Partial — the fault-identity *decision* is domain/arch-owned, but both layers' evidence and drift-pinning run through obs emissions (incident-outcome fields, `buffer.tick` feed counters) governed by the default-deny allowlist and the cardinality/hot-path bans.

## Constraints
- **Default-deny allowlist, EXACT leaves only.** Every field on an emission this chunk adds or changes must resolve to an explicit leaf; `for_target`'s prefix fallback otherwise resolves a dotted target to an unrelated field set and redacts it. No bare `incidents` / `triage` / `triage.baseline` prefix key may exist — either widens every sibling target to one field set (per obs-plan §8 Default-deny posture). **Note:** §8 enumerates leaves for `incidents.list_active.request`, `triage.incident.persist`, `triage.incident.corpus_restore` and names `triage.cue.tick` / `triage.incident.auto_resolve.tick` as measured-redacted backlog — it enumerates **no** leaf matching the incident-outcome emission at `inference_runtime.rs:661-682`. Whether that emit site's target already resolves to an existing leaf or is redacted today is research's question, and it decides whether the `created`/`deduped` evidence the scope relies on is readable at all.
- **A leaf must cover ALL fields the emit site emits.** A short entry leaves the target *partly* redacted — §8 records this as the `triage.incident.persist` `duration_ms` case (per obs-plan §8 Incident-path diagnostic leaves).
- **Fingerprint identity is barred from the buffer counter surface.** The feed counters are aggregate counts only — never service / span / fingerprint identity (per obs-plan §8 whitelist, `buffer` row).
- **Cardinality discipline.** No unbounded label values in `tracing` event fields and no high-cardinality span names. A blake3 fingerprint and a `scope_id` are unbounded by construction, so neither may become a metric label field or a span name (per obs-plan §5 Metric label cardinality discipline; §11 Spans / Metrics).
- **No per-span-event emission on the fingerprint compute path.** Fingerprint-feed counting is folded once per batch and ridden out as fields on the existing 15s tick; per-span-event emission is explicitly barred (per obs-plan §5 Conceptual instrument types, tick-aggregated row; §11 hot-path rule).
- **Log-shape contract.** Every emission the chunk touches stays NDJSON with the required fields plus subscriber-default service identity, at the level §6's mapping assigns; once-per-boot / once-per-query WARN discipline applies to any new degraded-state signal (per obs-plan §3 Log format JSON schema; §6 Required fields + Log levels mapping).
- **If the fingerprint reaches the MCP surface** (scope research Q3, blast radius): response bodies are never logged — only `result_type` + `result_count` metadata (per obs-plan §8 whitelist `mcp-server`; §11 Project-specific).

## Patterns to follow
- **EXACT leaf + guard test under `pulse-app/tests/`** — §8 records that a guard placed in a src-level `mod tests` compiles but never runs because `[lib] test = false`, which is why the bootstrap-window and incident-diagnostics guards live under `pulse-app/tests/` (per obs-plan §8).
- **Bounded-substitute-for-identity** — emit a derived bounded value (basename, count, `&'static str` label) in place of the identity itself; §8 cites `workspace_root_basename` + `key_bytes` and `plugin_path_basename` as the precedents. Applies directly if a decided Layer-1/Layer-2 semantic wants to make identity visible in the log.
- **Positive-reading counter pairs** — §5 records that equality of `observer_invocations` with `fingerprints_computed` makes a live storm-detector feed a POSITIVE reading rather than something inferred from downstream silence. The same shape is the reusable way to make a decided identity semantic observable instead of inferred.
- **Tick-aggregated fields over new targets** — fold per-batch counts and carry them as fields on the existing `buffer.tick` rather than minting `metric.buffer.*` targets (per obs-plan §5; §1 Heartbeat ticks).

## Anti-patterns to avoid
- Using a fingerprint digest, `scope_id`, or a client-supplied service name as a metric label field or a span name (per obs-plan §11 Metrics / Spans).
- Emitting per span event, per row, or at `info` level on the fingerprint/ingest hot path (per obs-plan §11 Logs, §11 Telemetry Strategy).
- Adding a bare-prefix allowlist key (`incidents`, `triage`) as a shortcut instead of an exact leaf — it silently widens every sibling target (per obs-plan §8).

## Contract bindings
- **obs ↔ tests** — §3's log-format JSON schema is verbatim from the tests harness contract (obs aligns to tests, not vice versa); the scope's "test coverage that pins the decided semantic" and any new allowlist guard test bind through it, with the guard-test location rule from §8.
- **obs ↔ security** — §8 Vectors 1-6 own the redaction paths configured at the subscriber Layer; any new identity-bearing field is a §8 classification question before it is a logging question.
- **obs ↔ external Conductor harness** — the scope treats Conductor as READ-ONLY evidence. §2's agent-readable invariants and §3's Log file location make `agent-latest.jsonl` the single agent-readable self-observation surface; whether Conductor's `FingerprintVariant` tests / `fingerprint-storm.toml` assert against that surface (and would therefore be affected by an emission change, not just an impl change) is research's question.

## Acceptance criteria contributions
- Every field on an emission this chunk adds or changes resolves to an EXACT allowlist leaf covering **all** fields the emit site emits, with no bare `incidents`/`triage` prefix key, guarded by a test under `pulse-app/tests/` (per obs-plan §8 Default-deny posture).
- The evidence fields for the Layer-2 decision (the incident-outcome created/deduped pair and any dedupe-key field) are verified **un-redacted by reading `agent-latest.jsonl` on a live storm run**, not inferred from downstream behaviour (per obs-plan §8 Default-deny posture; §2 Agent-readable invariants).
- No fingerprint digest, `scope_id`, or service name appears as a span name or as a metric label field; identity is represented by counts or bounded derived labels only (per obs-plan §11 Spans/Metrics; §8 whitelist `buffer`).
- Any new fingerprint-path counting rides the existing 15s `buffer.tick` as fields rather than emitting per span event or minting a new `metric.buffer.*` target (per obs-plan §5 tick-aggregated counter row; §11 hot-path rule).
