# arch extract

## Relevance
Partial — the fault-identity *semantic* is triage/domain territory, but arch governs where each layer's code lives, which storage/IPC resources it may touch, and how a decided semantic gets recorded and registered.

## Constraints
- Layer 1 normalization stays in the `buffer` crate and Layer 2 incident creation in `pulse-app` against the `triage` incident-registry contract; `buffer`, `triage`, `corpus`, `mcp-server`, `pulse-app` are reserved workspace names that cannot be re-purposed or split (per architecture.md §Occupied Resources → Cargo workspace crate names; §Project Intent → How new functionality is added).
- If the Layer 2 decision makes `fingerprint` part of the dedupe key, the join must respect the dependency DAG — deps flow toward `pulse-app`, no library crate depends on the binary, and no sibling dep unless the declared contract requires it (per architecture.md §Cross-cutting Patterns → Module dependency direction).
- Any fingerprint type/helper newly consumed across a crate boundary is exposed through that crate's contract module only; no cross-crate `pub use` re-exports and no `pub(crate)` leakage (per architecture.md §Conventions → Module visibility discipline).
- `span_events` (DuckDB, in-memory `pulse_buffer`) and `incidents` / `incident_events` (corpus SQLite) are canonical reserved tables with `snake_case` columns; identity is OTLP-native or derived, no UUID surrogate keys introduced (per architecture.md §Occupied Resources → DuckDB / Corpus SQLite schema names; §Conventions → Primary key convention).
- Downstream incident surfaces are already-registered resources — `incidents.list_active` / `acknowledge` / `mark_resolved` / `mark_all_read` / `get_report` and `pulse://stream/incidents`; any *new* procedure, stream topic, env var or capability the decision lands must be registered in §Occupied Resources at wrap and, for IPC, paired with a `pulse-app/capabilities/` entry or the bridge call is rejected at runtime (per architecture.md §Occupied Resources → Tauri IPC routes/events; §Cross-cutting Patterns → Webview IPC capability policy).
- Anything whose shape changes across the TauRPC bridge (incident DTOs, dedupe-outcome payloads) must stay `serde::Serialize`, with module-internal `thiserror` enums converting to the stable `AppError` variants at the bridge (per architecture.md §Cross-cutting Patterns → Cross-bridge data shape; §Conventions → Error response schema (Tauri IPC)).
- If either decision is expressed as a knob rather than one fixed semantic, config precedence is env `ANDROMEDA_PULSE_*` > `config.toml` > built-in defaults, with a bounded parse falling back to the default rather than panicking (per architecture.md §Cross-cutting Patterns → Config management; §Occupied Resources → Environment variables, `ANDROMEDA_PULSE_BASELINE_BOOTSTRAP_SECONDS` precedent).

## Patterns to follow
- Crate template shape: public contract module as the only `pub` surface, `pub(crate)` internals, `thiserror` error enum, TauRPC router mounted by `pulse-app` where applicable (architecture.md §Project Intent → Template patterns).
- Decided semantics that rise to arch level live as current truth in §Established Decisions with the evolution narrative pushed to `architecture-amendments.md` §Decision-history — the body states the decision, the sidecar states why it changed (architecture-amendments.md header; architecture.md §Established Decisions → [LLM Inference Runtime] cross-ref).
- Registry-closure amendment at wrap for any newly occupied resource, and APPLY-AS-MEASURED correction when a registry claim is disproved by measurement (architecture-amendments.md §Registry-closure amendments, 2026-08-14 workspace-key-alignment precedent).
- E2E verification speaks OTLP on `:4317`/`:4318` and reads buffer state back through the registered `traces.*` / `metrics.*` / `logs.*` query routers (architecture.md §Cross-cutting Patterns → Test-time telemetry injection).
- Incident identity is already workspace-scoped by a cross-process artifact: `run/workspace-key` is published by the app and read by the `andromeda-pulse-mcp` sidecar so both filter incidents by the same identity (architecture.md §Occupied Resources → Filesystem locations). Whether the Layer 2 dedupe predicate's `list_active(&digest.workspace)` argument derives from that published key is research's question.

## Anti-patterns to avoid
- No in-process test-mode bypass, "test ingest" feature flag, or mock-channel back-door to pin the decided semantic end-to-end (architecture.md §Cross-cutting Patterns → Test-time telemetry injection).
- No unregistered surface: a new TauRPC procedure, `pulse://stream/*` topic, env var, or MCP tool added to carry the decision without a §Occupied Resources entry (and, for MCP, without amending the locked 8-`#[tool]` list) is a registry breach (architecture.md §Occupied Resources; §Standard Contracts → MCP server).
- No surrogate identity key invented alongside the existing derived identity — identity comes from the spec-defined/derived IDs already in play (architecture.md §Conventions → Primary key convention).

## Contract bindings
- arch ↔ tests: the pinning suite inherits the injection discipline (OTLP ports in, registered query routers out); unit-level normalization pins stay inside the owning crate (architecture.md §Cross-cutting Patterns → Test-time telemetry injection).
- arch ↔ obs: the `created` / `deduped` incident-outcome signals ride the self-observation discipline — stdout/file exporter to `logs/` only, never the product's own `:4317`/`:4318` (architecture.md §Cross-cutting Patterns → Self-observation discipline). Event/field naming is obs's; transport is arch's.
- arch ↔ security/corpus: persisted incident rows are cell-level AES-256-GCM with an OS-credential-store key; if a decided semantic invalidates the interpretation of already-persisted rows, the inventory-then-purge disposition (`corpus::disposition`) is the established precedent for retiring them (architecture.md §Occupied Resources → Corpus SQLite → At-rest posture).
- arch ↔ MCP surface: the tool list is locked at 8 methods including `query_incident_list` / `retrieve_report` / `retrieve_telemetry_slice`; whether any of them already surfaces `span_events.fingerprint` (the scope's Layer-1 blast-radius question) is research's question, but expanding the tool list to answer it requires an amendment (architecture.md §Standard Contracts → MCP server; §Conventions → External wire — MCP server).
- Cross-repo: Conductor lives outside this Cargo workspace, so the workspace-boundary rule reinforces the scope's read-only stance — the re-alignment cost is *recorded* here, executed there (architecture.md §Infrastructure Patterns → Project directory structure).

## Acceptance criteria contributions
- (arch) Layer 1 changes land in `crates/buffer`, Layer 2 in `pulse-app` against the `triage` contract; no library crate gains a dependency on `pulse-app` and no new cross-crate re-export bypasses a contract module (per architecture.md §Cross-cutting Patterns → Module dependency direction; §Conventions → Module visibility discipline).
- (arch) No new TauRPC procedure, `pulse://stream/*` topic, env var, capability, or MCP tool beyond the registered set; if the decision lands one, it is registered in §Occupied Resources at wrap and, for IPC, accompanied by a `pulse-app/capabilities/` entry (per architecture.md §Occupied Resources; §Cross-cutting Patterns → Webview IPC capability policy).
- (arch) Any bridge-crossing type touched by the decision stays `serde::Serialize` and surfaces failures as stable `AppError` variants, with `thiserror` enums converting at the boundary (per architecture.md §Cross-cutting Patterns → Cross-bridge data shape; §Conventions → Error response schema (Tauri IPC)).
- (arch) The decided semantic is recorded where arch keeps decisions — current truth in the body, rationale + switching cost in the sidecar — and any storage-shape consequence keeps table names inside the reserved DuckDB / corpus sets (per architecture-amendments.md §Decision-history convention; architecture.md §Occupied Resources → DuckDB / Corpus SQLite schema names).
