# design extract

## Relevance
**Partial** — the chunk's deliverable is Rust semantics + docs + tests, but Layer 2's open research question 2 (Findings window, unread badge, per-service constellation severity join keyed on `scope_id`) lands squarely on design's signature encoding; if Layer 2 resolves to *incident-per-identity*, the Halo severity encoding is the constraint that governs. A doc-only Layer 1 outcome carries no design surface.

## Constraints
- The Halo State Pulse hue axis is driven by **cumulative incident severity = the max active-incident priority tier**, not by incident count — a second concurrent incident for one service must not brighten, saturate, or shift hue merely by existing at a distinct fingerprint (per design-system.md §Motion → High-impact moments → "Halo State Pulse breathing", and §Brand Identity → Signature element). Whether the current per-service severity join already reduces by max rather than sum/first-wins is research's question.
- Connection state is an **orthogonal grayout/desaturation axis, independent of the severity-hue axis** (P-004 health-vs-severity orthogonality) — an incident-cardinality change must not leak into that axis (per design-system.md §Motion → High-impact moments; §Brand Identity → Signature element).
- Breathing modulation is **opacity + blur ONLY, never scale**, blur 4–16 px, period 4–5 s quiet → ~2 s active (≈0.2–0.5 Hz) — a change in incident count is not a permitted input to rhythm (per design-system.md §Motion → High-impact moments, P-026).
- Accent `#C7556A` is a **non-text token** (≈3.8:1 on `#1A1D24`): incident/error *message* text at body size (≤14px regular) must use `--color-text-primary` (or Secondary `#B4BCCB` per the EmptyState pattern), with the accent carried by border/icon only (per design-system.md §Color Palette → "Accent usage (non-text token)").
- Any surface that distinguishes one incident from two must convey the distinction with a **text label or glyph, not color alone**; every color must carry meaning, never decoration (per design-system.md §Anti-Patterns → Universal Bans).
- Fingerprint / identity values and counts are "immutable telemetry fact" → **JetBrains Mono 12px** (`Data` role, tabular-nums for counts; `Code` role, tracking 0.5 for IDs/paths); labels and prose → IBM Plex Sans (per design-system.md §Typography).
- Entrance animations are **none** and staggered reveals are banned at expression 0.3–0.35 — a second concurrent incident appearing in a list renders instantly; only state-confirming transitions (150ms hover / 200ms fade, `cubic-bezier(0.4, 0, 0.2, 1)`) are permitted, and all motion respects `prefers-reduced-motion` (per design-system.md §Motion → Hard limits + §Motion → Accessibility).

## Patterns to follow
- **Tables (telemetry data)** for any incident/findings row surface: transparent row background over the parent card, `rgba(74,144,226,0.1)` hovered row with no transition, 1px `rgba(74,144,226,0.1)` row borders, JetBrains Mono 12px tabular-nums cells, `space-sm` (8px) padding (per design-system.md §Surface: desktop-webview → Component Patterns → Tables).
- **Cards / Panels** for an incident card: `#262A33` (Raised-1) + 1px `rgba(74,144,226,0.3)` border, `radius-md` (6px), `space-md` (16px) padding; hover/active raises the border to `rgba(74,144,226,0.6)` — borders-only depth, never shadow (per design-system.md §Depth Strategy; §Surface: desktop-webview → Component Patterns → Cards / Panels).
- **Shared `EmptyState` + its honest-error variant** (error branch checked *before* empty) for an incident list that can be empty or fail to load — message in `#B4BCCB` Secondary, `font-body` 14px, decorative glyph `aria-hidden` (per design-system.md §Surface: desktop-webview → Component Patterns → Loading / Empty States).
- **Badge as `radius-full` pill**, and the tray's single unified halo around the aggregated service-count badge — an unread/incident-count badge stays inside that existing aggregation model rather than adding a second halo (per design-system.md §Border Radius; §Surface: desktop-native → Component Patterns → Tray Icon).
- **Custom `<Icon glyph="telescope" />`** for any investigate affordance on a finding/incident row; Lucide/Heroicons only where no domain glyph exists; size grid 16/20/24px (per design-system.md §Iconography).

## Anti-patterns to avoid
- **NEVER** encode incident state as uniform monochrome status icons (green check / red X) — explicitly rejected because the Halo carries two independent dimensions that must remain readable at a glance (per design-system.md §Anti-Patterns → Rejected Defaults).
- **NEVER** introduce a gradient, glow, or glassmorphic treatment on chrome to signal "second concurrent incident" — the Halo canvas is the sole exception to flat, matte surfaces (per design-system.md §Anti-Patterns → Universal Bans).
- **NEVER** emit hardcoded hex or magic pixel values in any touched UI; values must trace to the Color World palette, the 4px spacing scale, and the JetBrains Mono + IBM Plex Sans stack (per design-system.md §Self-Validation Protocol → 4. Token Test).

## Contract bindings
- **design ↔ a11y:** accent non-text classification (SC 1.4.11 at ≈3.8:1, below SC 1.4.3 normal-text 4.5:1); state-color-plus-label (SC 1.4.1); reduce-motion override on all transitions and Halo degradation to static glow (SC 2.3.3); Text Hierarchy contrast targets are design's, formal WCAG derivation is a11y's (per design-system.md §Color Palette; §Motion → Accessibility; design-system-amendments.md §Downstream Readiness → "For a11y specialist").
- **design ↔ obs/data-viz:** obs logs Halo color state (LCH interpolated value) and pulse frequency per cycle as the data-viz layer emits them, without re-clamping — if Layer 2 changes how many active incidents a service can have, it changes what feeds that logged severity signal (per design-system-amendments.md §Downstream Readiness → "For obs specialist").
- **design ↔ tests:** the motion lint targets (150/200/250/350ms, ease-out / ease-in-out, the 7 hard-limit bans) and the token/hex verification of Component Patterns are the tests specialist's extraction from these sections (per design-system-amendments.md §Downstream Readiness → "For tests specialist").
- **design ↔ layouts:** per-screen placement of a second incident row in the Findings window / incident list is layouts' domain, not design's — design supplies tokens and the Halo encoding contract only.

## Acceptance criteria contributions
- (design) If Layer 2 resolves to incident-per-identity, the per-service constellation and tray Halo hue still derives from the **max** active-incident severity tier — not a count, sum, or first-match — and the connection grayout stays an independent axis (per design-system.md §Motion → High-impact moments → Halo State Pulse breathing).
- (design) Any incident/finding state rendered in a touched surface is conveyed by a text label or glyph alongside color, never by color alone; body-size message text uses `--color-text-primary`/Secondary with accent restricted to border or icon (per design-system.md §Color Palette → "Accent usage (non-text token)").
- (design) Any touched UI uses design tokens only — no hardcoded hex or magic pixel values — with fingerprint/identity values in JetBrains Mono 12px and labels in IBM Plex Sans (per design-system.md §Typography; §Self-Validation Protocol → 4. Token Test).
- (design) A second concurrent incident appears with no entrance or staggered animation; any accompanying transition is ≤200ms fade / 150ms hover and collapses to instant under `prefers-reduced-motion: reduce` (per design-system.md §Motion → Hard limits + §Motion → Accessibility).
