## Patterns to follow

- `rstest` parameterized table tests with `#[fixture]` builders for the three primitive families (per test-plan §4 fixture pattern):
  - Dedup: parametric `[(input_spans, expected_unique_count, expected_dedup_count)]` rows; one row per equivalence class (identical name + service + duration → 1 unique + N-1 dedup; differing one field → 2 unique + 0 dedup; etc.).
  - Anomaly highlight: parametric rows for the three anomaly types named in chunk title — latency outliers (z-score / IQR threshold), error correlation (spans with `status.code == ERROR` clustered by service), cardinality spikes (attribute keyspace explosion).
  - Critical-path extraction: build a small DAG via `MockTraceSpan::builder()` with explicit `parent_span_id`; assert returned path is the longest single-trace root-to-leaf chain by duration.
- Boundary tests on input invariants (per test-plan §1 OTLP anti-pattern rejection): empty input → returns empty/None; single span → trivial cases (no dedup possible, no anomaly possible from N=1, critical path is the single span); span_id length != 8 / trace_id length != 16 → MUST NOT panic (rejection path already lives at `ingest`'s `prost`-decode boundary, but defensive primitives should not assume well-formed input).
- AAA pattern visible per test, one assertion concept per test (per `.claude/rules/testing.md` Patterns); flat `#[test] fn test_<entity>_<scenario>()` naming (per test-plan §4 conventions).
- Unit-level `#[automock]` mocking is NOT needed for chunk #39 — primitives are pure functions over span vectors; no module-level dependency to stub. NEVER reach for `mockall` here (per test-plan §11 Mocking "mock only traits you own"; here there are no traits).
- Property-based generators via `proptest` 1.10.0 with `proptest-regressions/` regression files (per test-plan §7 Randomized data row + §4 invariants list): use for "dedup over arbitrary span vector preserves contract" (idempotent, count_in == unique_out + dedup_count) and "critical-path is contiguous parent-chain" assertions. Seeded deterministically per test (per test-plan §11 Test Data anti-pattern "NEVER use non-deterministic generators without seed control").
- For any helper that emits `tracing::warn!` / `tracing::info!` (e.g., "anomaly threshold exceeded" diagnostic), use the in-process `CapturingSubscriber` pattern from `.claude/rules/testing.md` Session Additions 2026-05-07 (`tracing::subscriber::with_default(subscriber, closure)` for sync; `set_default(...)` returning `DefaultGuard` per Session Additions 2026-05-09 for async). ## Anti-patterns to avoid

- NEVER assert "raw OTLP JSON dump" passes as snapshot output — chunk #39's primitives MUST measurably reduce input volume (`dedup_count > 0`) and MUST surface anomaly markers; tests that only assert "output is non-empty" miss the design-goal contract (per test-plan §11 Project-specific andromeda-pulse + §1 P2 critical path "not raw OTLP dump").
- NEVER bake golden-output `.md` / `.json` snapshot fixtures into the test tree (i.e., do NOT use `insta` snapshot testing with committed `.snap` files for curation output) — assertions MUST be content-shape-based (regex / count / structural predicates), not byte-equality with hand-curated baselines, because chunk #41's markdown formatter is the layer that rasterizes to a stable string. Curation-primitive output is a typed AST / value, not a string.
- NEVER write a test that depends on per-trace-ID iteration order — if dedup/anomaly internals use `HashMap`, sort outputs deterministically before assertion (`HashMap::iter()` order is non-deterministic across rustc versions; flake risk per test-plan §10 zero-flakiness budget).
- NEVER skip `cargo deny check bans` if the chunk introduces a new dep (e.g., a percentile-computation crate like `quantogram`/`hdrhistogram`) — `multiple-versions = "deny"` blocks regressions per test-plan §9 + §10 + `.claude/rules/testing.md` Quality gates (the `tonic` 0.14/0.13 canary stays outside any skip list per `.claude/rules/security.md` Session Additions 2026-05-03).
