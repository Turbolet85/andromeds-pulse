## Chunk relevance

- route#87 "Findings counter + dropdown" — relevant. Introduces two NEW visual primitives (compact circular counter + severity-colored dropdown rows + footer action) attached к the compact widget surface (desktop-webview). Both render text, color-encoded state, micro-interactions (click expand, hover row), and require explicit token compliance + a contemplative motion budget. P-030 invariant ("No interrupting notifications") binds the design к а silent-visual-only discipline (no toasts, no modals) which directly maps к §Anti-Patterns Per-Surface Bans (no `alert()`/`confirm()`).

## Constraints

- Counter circle MUST use `radius-full` (9999px) per §Border Radius — pill/badge shape signals "complete/whole" reinforcing constellation/halo metaphor; counter is а status badge by classification.
- Counter background severity color MUST source от Color Palette tokens — `--color-accent` (#C7556A Alert Burgundy) for high severity, `--color-primary` (#4A90E2 Earth Blue) for info/low severity, `--color-feedback-success` (#17B3A3 Feedback Cyan) NOT applicable (success state is not а "finding"); zero counter MUST be hidden entirely (per project-doc §86 "Hidden when count is zero") (per §Color Palette Core Colors + §Semantic Colors).
- Dropdown popover surface MUST use `--color-raised-2` (#2D3139) per §Surface Scale "Dropdowns, popovers, tooltips" + 1px subtle border `rgba(74, 144, 226, 0.3)` per §Border Progression "Subtle" + `radius-md` (6px) per §Border Radius (per §Depth Strategy borders-only + §Surface: desktop-webview Component Patterns Cards/Panels).
- Severity-dot indicator on each dropdown row MUST be color-paired-with-icon-or-text-label (severity is conveyed both by the dot color AND the row's title/timestamp text + sort order) — per §Anti-Patterns Universal Bans "NEVER use color purely for decoration"; severity-color-alone fails state conveyance.
- Relative timestamp text ("3m ago") MUST use `--font-code` (JetBrains Mono, 12px, tabular-nums) per §Typography Data row — timestamps are metric/data, monospace signals immutable telemetry fact + tabular numerals align across rows. Row title text MUST use `--font-body` (IBM Plex Sans, 14px) per §Typography Body row (per §Typography surface-conditional desktop-webview applies).
- Counter click → dropdown expand transition MUST be ≤200ms ease-out fade per §Motion Duration scale "Panel open, page change" + respect `prefers-reduced-motion: reduce` (instant 0ms) per §Motion Accessibility (per §Motion Hard limits + Accessibility).

## Patterns к follow

- Cards/Panels primitive (per §Surface: desktop-webview Component Patterns Cards/Panels): use `--color-raised-2` background + subtle border + `space-md` (16px) padding for dropdown popover; severity-bordered emphasis if focused (per §Border Progression Emphasis `rgba(74, 144, 226, 0.6)`).
- Secondary Button primitive for "Mark all as read" footer action (per §Component Patterns Buttons Secondary): background `--color-raised-1` (#262A33) + text `--color-text-primary` + 1px subtle border + 150ms ease-out hover transition (per §Motion Micro-interactions).
- Empty/zero-count discipline: counter follows §Component Patterns Loading / Empty States "Empty state" principle by being hidden (per project-doc §86) rather than rendered as а "0" badge — visual silence at zero count aligns с contemplative tone (per §Brand Identity Expression level 0.35 webview).
- Focus ring discipline (per §Surface: desktop-webview Focus / Keyboard Navigation): counter click target + each dropdown row + footer action use `outline: 3px solid #4A90E2` or box-shadow `0 0 0 3px rgba(74, 144, 226, 0.2)` (per §Border Progression Focus token).
- Iconography rule: per §Iconography "Icons clarify, not decorate" + compact widget chrome density warning ("every pixel of chrome counts"). Severity is encoded via colored dot (radius-full, ~8-10px) — а domain-appropriate "constellation star" micro-glyph; do NOT add decorative library icons unless they carry independent meaning (per §Iconography Rule + §Anti-Patterns "NEVER use color purely for decoration").

## Anti-patterns к avoid

- NEVER render the counter с а purple/gradient background or shadow-elevated raised effect — §Anti-Patterns Universal Bans "NEVER use gradient overlays or glassmorphic effects on dashboard chrome"; severity is а flat color block per §Depth Strategy borders-only discipline.
- NEVER pop а modal, toast, or OS notification when the counter increments — directly conflicts с chunk #87 P-030 invariant + §Anti-Patterns Per-Surface Bans desktop-webview "NEVER use `alert()` / `confirm()` / `prompt()`"; the counter IS the notification surface.
- NEVER use spring/bounce easing or duration >200ms on the dropdown expand — per §Motion Hard limits "NO spring physics or bounce easing" + "NO opacity fades longer than 200ms"; dropdown is а chrome transition, not а supporting moment (Investigation Capture Collapse 350ms exception does not extend к dropdown UI).

## Contract bindings

- **Design ↔ a11y (contrast verification)**: severity color tokens used on the counter background MUST satisfy the §Text Hierarchy contrast targets when paired с the counter's numeric text. Counter number text on Alert Burgundy `--color-accent` (#C7556A) needs contrast verification per а11y SC 1.4.3 — likely needs `--color-text-primary` (#E8EEF7) or `--color-base` (#1A1D24) depending on background luminance; design provides target tokens, a11y owns formal WCAG conformance assertion (per §Downstream Readiness "For a11y specialist" + §Color Palette Text Hierarchy table).
- **Design ↔ a11y (motion reduce-motion override)**: counter→dropdown expand transition (≤200ms ease-out fade) MUST degrade к instant (0ms) when `prefers-reduced-motion: reduce` is set — design specifies the token boundaries, a11y verifies the override is wired in implementation (per §Motion Accessibility + §Downstream Readiness "For a11y specialist" Motion accessibility row).
- **Design ↔ a11y (state-not-color-alone)**: severity is encoded via BOTH the dot color AND the row sort position (severity descending) + title text — single-color-encoding violates §Anti-Patterns Universal Bans "NEVER use color purely for decoration" which mirrors SC 1.4.1. Design provides the dual-encoding pattern; a11y verifies screen reader announces severity via title text or aria-label (per §Anti-Patterns Universal Bans + a11y SC 1.4.1 binding).
