# a11y extract — phase-84

## Chunk relevance

Chunk #87 "Findings counter + dropdown" is a NEW desktop-webview UI surface introducing two new interactive components (`pulse-app/ui/widget/FindingsCounter.tsx` + `pulse-app/ui/widget/FindingsDropdown.tsx`) under the compact-widget layout. Both components are fully in a11y domain:
- **FindingsCounter**: circular numeric button trigger; conveys severity via color + count; hidden when count is zero
- **FindingsDropdown**: disclosure panel listing severity-sorted incident rows; row click opens future Report; footer "Mark all as read" action
- **Capabilities binding**: P-028 (counter), P-029 (dropdown), P-030 (No Interrupting Notifications — drives a11y choice of inline disclosure over OS toast / modal)

Chunk does NOT introduce backend / IPC surface beyond corpus read; new TauRPC procedure `incidents.mark_all_read()` is backend domain (arch).

## Constraints (WCAG criteria applicable)

**Counter (button trigger):**
- **SC 4.1.2 Name, Role, Value** — counter MUST have accessible name conveying "Findings: N unread incidents" (not just the digit); native `<button>` provides role; `aria-label` provides name when only visual content is the digit
- **SC 1.4.1 Use of Color** (a11y-plan §6 State color tokens) — counter color encodes severity (Autonomous / Suggested / Curious); MUST be paired with non-color signal (numeric count + accessible label naming the severity tier)
- **SC 2.1.1 Keyboard** — counter activatable via Enter / Space (native `<button>`)
- **SC 2.4.7 Focus Visible** — `--border-focus` outline applied on `:focus-visible` (a11y-plan §6 Focus ring tokens)
- **SC 1.4.11 Non-text Contrast** — circular counter background and severity color ≥ 3:1 against widget chrome (a11y-plan §6)
- **SC 1.4.3 Contrast (Minimum)** — counter digit ≥ 4.5:1 against counter background
- **SC 2.5.8 Target Size (Minimum)** — counter interactive area ≥ 24×24 CSS px (a11y-plan §6 Target size tokens; `--target-button-min`)
- **SC 4.1.3 Status Messages** — counter visual change (digit increment / clear-to-hidden when "Mark all as read" fires) MUST be announced via `aria-live="polite"` on a containing status region (non-interrupting per P-030 invariant)

**Counter hidden when count is zero:**
- Use conditional render (omit from DOM) OR `hidden` attribute — NEVER `aria-hidden="true"` on a focusable element (a11y-plan §11 Screen Reader anti-pattern: `aria-hidden-focus` rule)
- When hidden, MUST NOT appear in tab order

**Dropdown (disclosure pattern):**
- **SC 4.1.2 Name, Role, Value** — counter trigger uses `aria-expanded` (true/false) + `aria-controls` pointing к dropdown panel id (a11y-plan §4 Disclosure pattern)
- **SC 2.1.1 Keyboard** — dropdown reachable + operable via keyboard
- **SC 2.1.2 No Keyboard Trap** — Escape closes dropdown
- **SC 2.4.3 Focus Order** — focus moves into dropdown on open; focus returns к counter trigger on close (a11y-plan §5 Focus restoration)
- **SC 2.4.7 Focus Visible** — focus ring visible on each row + footer action

**Dropdown rows:**
- **SC 4.1.2 Name, Role, Value** — each row is `<button>` (row click opens Report); accessible name conveys "{severity}: {title}, {relative time}" so SR users hear the severity (not only the colored dot)
- **SC 1.4.1 Use of Color** — severity color dot supplemented by severity word in label (NOT color alone)
- **SC 1.4.3 / 1.4.11 Contrast** — row text + dot color meet contrast pair thresholds (a11y-plan §6)

**Footer "Mark all as read" action:**
- **SC 4.1.2 Name, Role, Value** — native `<button>` with visible "Mark all as read" text
- **SC 4.1.3 Status Messages** — after activation, status region announces "Findings cleared" via `aria-live="polite"`

**P-030 anti-pattern enforcement:**
- **NO OS notification / toast / modal** for finding events — dropdown is the entire surface
- Aligns с a11y-plan §11 ARIA anti-pattern "NEVER create keyboard traps (modal without Escape close)" — by NOT using a modal, the chunk avoids the focus-trap obligation entirely

## Patterns к follow

**Counter component (a11y-plan §4 Button + Disclosure patterns):**
- Native `<button>` element (semantic HTML first; a11y-plan §11 ARIA anti-pattern "NEVER use ARIA on non-semantic HTML")
- `aria-label="Findings: {count} unread, {highest severity} severity"` — accessible name conveys count + severity tier in words; supersedes the visual digit-only content (SC 4.1.2 + SC 1.4.1)
- `aria-expanded={isOpen}` + `aria-controls="findings-dropdown-panel"` — disclosure pattern (a11y-plan §4 Disclosure row)
- `aria-haspopup="true"` — signals popup affordance
- Conditional render when count === 0 (do NOT render а disabled / hidden focusable button)
- `:focus-visible` outline composition uses `--border-focus` token (a11y-plan §6 Focus ring tokens)
- Target area ≥ `--target-button-min` (a11y-plan §6)

**Dropdown panel (a11y-plan §4 Menu pattern — adapted as а list-of-actions disclosure):**
- Container: semantic `<ul>` or `<div role="list">` with `id="findings-dropdown-panel"`
- Each row: native `<button>` element wrapping severity dot + title + relative time
- Row accessible name pattern: `aria-label="{severity tier}: {title}, {relative time}"` — е.g., "Autonomous: Database connection timeout, 3 minutes ago"
- Footer "Mark all as read" is а separate native `<button>` outside the list
- Dropdown anchored к counter trigger; positioned below widget per project-doc §86

**Keyboard navigation (a11y-plan §5 + §4 Menu pattern):**
- **Enter / Space on counter** → opens dropdown + moves focus к first row
- **Tab / Shift+Tab** within dropdown → navigates rows + footer button in document order (preferred over Arrow keys для а disclosure-of-buttons; Arrow keys reserved for true `role="menu"`. The chunk uses а button-list disclosure, not а menu role, because rows open Reports rather than executing menu commands.)
- **Escape** → closes dropdown + returns focus к counter trigger (a11y-plan §5 Focus restoration; per WCAG SC 2.1.2 No Keyboard Trap)
- **Enter / Space on row** → triggers row action (opens future Report chunk #88)
- **Enter / Space on footer** → triggers "Mark all as read" + closes dropdown + returns focus к counter trigger (OR counter unmounts if count was the trigger's sole reason к exist; в that case focus returns к а stable anchor per а11y-plan §5 Focus restoration — е.g., the widget's main content region)
- Click outside dropdown → closes dropdown + returns focus к counter trigger

**Focus management (a11y-plan §5):**
- On counter activation: move focus к first row in dropdown (not the panel container itself — rows are the actionable elements)
- On Escape: return focus к counter trigger
- On row click: dropdown remains open OR closes per UX choice — when Report opens (future chunk #88), focus moves to Report; on Report close, focus returns к the originating row OR the counter trigger (defer К chunk #88 spec)
- On "Mark all as read": dropdown closes; if counter is now hidden (count=0), focus moves к а stable anchor (widget main region OR document body); per а11y-plan §5 "Route change (SPA navigation) → focus to main heading or `<main>` landmark"

**Live region for state changes (a11y-plan §7 Live regions):**
- Add а `<div role="status" aria-live="polite" class="sr-only">` к the widget (single instance shared across components)
- On counter mount with non-zero count: announce "Findings: {count} unread"
- On counter increment: announce "{new total} unread findings"
- On "Mark all as read" success: announce "All findings marked as read"
- Use `aria-live="polite"` (not `assertive`) per P-030 invariant — findings are non-interrupting status, not alerts

**Severity not-color-alone (a11y-plan §6 State color tokens):**
- Each severity dot has а text supplement OR icon supplement в the accessible name
- The aria-label of each row includes the severity word (Autonomous / Suggested / Curious) so SR users don't depend on dot color
- Visual: pair colored dot с а small severity glyph (а design-domain choice; a11y assertion is "non-color supplement present")

## Anti-patterns к avoid

(a11y-plan §11)

**Counter:**
- NEVER render counter as `<div onClick>` — use native `<button>` (a11y-plan §11 ARIA: NEVER use ARIA on non-semantic HTML)
- NEVER `aria-hidden="true"` on the counter when count is zero — counter is focusable; use conditional render OR `hidden` attribute instead (a11y-plan §11 Screen Reader: NEVER hide important content from assistive tech via aria-hidden on focusable elements; axe-core `aria-hidden-focus` rule)
- NEVER `outline: none` on `:focus-visible` without `--border-focus` replacement (a11y-plan §11 Keyboard: SC 2.4.7 violation)
- NEVER convey severity by dot color alone — accessible name + visible severity glyph required (a11y-plan §11 Visual: SC 1.4.1)
- NEVER use `tabindex > 0` to force counter into focus order (a11y-plan §11 Keyboard)
- NEVER autoplay а pulse / breathing animation on counter without `prefers-reduced-motion` respect (a11y-plan §11 Motion: SC 2.3.3 AAA — counter changing color/scale on new incident MUST degrade under `prefers-reduced-motion: reduce`)

**Dropdown:**
- NEVER trap focus inside dropdown without Escape exit (a11y-plan §11 Keyboard: SC 2.1.2 No Keyboard Trap)
- NEVER nest а `<button>` inside another `<button>` (a11y-plan §11 Keyboard) — row IS the button; severity dot + title + time are children of the row button
- NEVER render а dropdown footer "Mark all as read" as а link (`<a>`) — it triggers an action, not navigation; native `<button>` required (SC 4.1.2 correct role)
- NEVER use OS notification / toast / modal for finding events (P-030 — also prevents the modal focus-trap obligation under a11y-plan §5)

**Live region:**
- NEVER use `aria-live="assertive"` for findings status (a11y-plan §7 Live regions — findings are non-blocking; `role="alert"` / `assertive` reserved for blocking validation errors)
- NEVER omit the live region entirely — counter changes МUST be announced (SC 4.1.3 Status Messages)
- NEVER add multiple competing live regions — single `aria-live="polite"` region shared across widget
