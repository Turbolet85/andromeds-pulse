## Patterns to follow
- Committed per-arm pins for an xtask gate that reads a file: the gate's pure decision pinned per arm, driven over constructed inputs in scratch roots, as the plan records for `empty_input_tests` in `xtask/src/main.rs` (per test-plan §9 Pipeline structure, the `lint-test` row); fixtures are real files under `tempfile::TempDir`, not mocks (per test-plan §8 Mocking & Stubbing Discipline, Filesystem; test-plan §7 Test Data & Fixtures, Test data lifecycle).
- An absent or empty input is a failing or cannot-evaluate arm, never a pass: the plan's gates fail on an absent `lcov.info`, an absent log family and an absent a11y baseline, with the exit convention 0 pass · 1 findings · 2 cannot-evaluate (per test-plan §9 Pipeline structure, the Quality gates and Boot smoke rows). Whether `verify:capability-matrix` has such an arm for an absent or id-less record today is research's question.
- A pin that the gate's committed input exists in the tree, beside the per-arm pins over constructed inputs — the shape the plan records for the a11y baseline (per test-plan §9 Pipeline structure, the A11y suite row).
- A discrimination shown once by hand is not a regression guard: the plan carries such cases as owed coverage triggers until a committed test fails on the regression (per test-plan §1 Pending coverage triggers). "The gate carries no retired id" and "each of the 82 ids appears exactly once with one of two dispositions" each need a committed pin that reddens under the opposite record.
- Narrowed selections for fast iteration use a filter expression under `--workspace` (per test-plan §3 `run`, Test selection); a selection that matches no test must fail, not pass (per test-plan §9 Pipeline structure, the `lint-test` row).

## Anti-patterns to avoid
- No test is `#[ignore]`d, removed or softened because its capability is recorded as retired: no surface leaves in this chunk, `#[ignore]` is reserved for flake quarantine and needs a tracking issue (per test-plan §11 Test Anti-Patterns, Quality; test-plan §10 Load profiles).
- No verification by a person reading the record, and no gate or test that reaches outside the tree (a sibling repository, a remote) to compare sets — every layer is exit-code driven and deterministic (per test-plan §11 Test Anti-Patterns, Universal; test-plan §2 Test Strategy, Agent-runnable invariants). The external harness's accepted set has no test-plan check in this repository.
- No pin on private parser internals or fixture-internal values; pins assert the gate's contract — verdict, exit code, the id set (per test-plan §11 Test Anti-Patterns, Unit).
