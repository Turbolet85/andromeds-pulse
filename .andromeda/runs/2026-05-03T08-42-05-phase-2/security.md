## Constraints

- Code-signing private keys (Windows EV cert HSM-RSA, Apple Developer ID, Tauri updater Minisign Ed25519) MUST live exclusively in Azure Key Vault Premium SKU; GitHub Actions reaches the Vault via GitHub OIDC → Azure managed identity federation with NO long-lived Azure service principal secret stored in GitHub Actions secrets (per security plan §Secret Management Storage + §Bootstrap phases `secret-management-init`).
- Windows EV signing cert MUST use only DigiCert or GlobalSign HSM-RSA CAs; the cert key must never leave the Azure Key Vault HSM (per security plan §Data Protection Code-signing key custody + §Anti-Patterns Data Protection).
- Tauri updater Minisign Ed25519 keypair MUST be generated via `tauri signer generate -w ~/.tauri/andromeda-pulse.key`; ONLY the public key is committed into `tauri.conf.json`; private key + password go to Azure Key Vault and are exposed to `release.yml` as `TAURI_SIGNING_PRIVATE_KEY` + `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` GitHub Actions secrets (per security plan §Bootstrap phases `secret-management-init`).
- All code-signing secrets (Tauri Minisign private key, Windows EV/AzureSignTool credentials, Apple Developer ID `APPLE_ID` / `APPLE_PASSWORD` / `APPLE_TEAM_ID`, any non-OIDC fallback creds, Homebrew/Scoop push tokens if not `GITHUB_TOKEN`) MUST be scoped to a GitHub Environment named `production-release` with manual approval gate (per security plan §Secret Management GitHub Environment scoping + §Anti-Patterns Secrets).
- Workflow-level `permissions:` MUST be `contents: read` only; per-job elevation to `contents: write` is permitted ONLY on the publish step (per security plan §Secret Management GitHub Environment scoping + §Anti-Patterns Secrets).
- `.gitignore` MUST cover `*.p12`, `*.pem`, `*.cer`, `.env*`, `*.key`, `~/.tauri/*.key` before any signing setup work that may produce key material on disk (per security plan §Secret Management secret scanning + §Anti-Patterns Secrets).
- Tauri updater Minisign Ed25519 verification cannot be disabled; the public key embedded in `tauri.conf.json` is the load-bearing in-transit integrity check for the updater (per security plan §Data Protection in transit + §Anti-Patterns Data Protection).
- Document a key-rotation runbook for the Tauri updater Minisign keypair BEFORE v0.1.0 ships (covering: emergency new-key generation, transitional release with both old + new public keys, advisory communication, final rotation release dropping the old key) per security plan §Secret Management Rotation cadence + §Decisions Log open questions.

## Patterns to follow

- GitHub OIDC → Azure managed identity federation pattern (no long-lived Azure SP secret) is the documented best-practice path for OSS desktop apps in 2026 (per security plan §Secret Management Storage + §Decisions Log key decision on code-signing key custody).
- Manual approval gate via GitHub Environment `production-release` is the mitigation for "EV signing cert has no test analog (one cert per legal entity per CA)" (per security plan §Secret Management dev/prod separation).
- Public key only in `tauri.conf.json`; private key in Azure Key Vault next to the Windows EV cert — single Vault holds all release signing material to keep custody + audit log (Premium SKU) co-located (per security plan §Secret Management Access auditing + §Decisions Log).
- Rotation cadence pattern: Windows EV cert renewed per CA policy (1–3 years) but HSM key never rotates (key never leaves HSM, only the cert renews); Apple Developer ID rotated per Apple cert lifecycle (annually); Azure OIDC federation trust rotated when GitHub repo owner/path changes or on suspected compromise (per security plan §Secret Management Rotation cadence).

## Anti-patterns to avoid

- NEVER store the Azure Key Vault service principal as a long-lived GitHub Actions secret — use GitHub OIDC federation (per security plan §Anti-Patterns Secrets).
- NEVER ship the Tauri updater Minisign **private** key in the repo or in any build artifact — only the public key belongs in `tauri.conf.json` (per security plan §Anti-Patterns Data Protection).
- NEVER store the Windows EV signing cert outside Azure Key Vault HSM; only DigiCert / GlobalSign HSM-RSA CAs are supported (per security plan §Anti-Patterns Data Protection).
- NEVER override the `tauri-plugin-updater` 2.x Minisign Ed25519 signature verification, and any wrapper code must not attempt to bypass it (per security plan §Anti-Patterns Data Protection).
- NEVER place Azure Key Vault credentials, Apple Developer ID credentials, or Tauri updater Minisign private key outside the GitHub Environment named `production-release` with manual approval gate (per security plan §Anti-Patterns Secrets).
- NEVER commit `.env`, `*.p12`, `*.pem`, `*.cer`, `*.key`, or `~/.tauri/*.key` files to git (per security plan §Anti-Patterns Secrets).
- NEVER grant `permissions: { contents: write }` at the workflow level — workflow-level is `contents: read`, per-job elevation only on publish (per security plan §Anti-Patterns Secrets).
