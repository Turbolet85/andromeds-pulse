## Patterns to follow

- Frameless main window with custom-drawn 32px titlebar (drag region + window controls) is the established App Shell pattern across all three platforms; `tauri.conf.json` must enable it via `decorations: false` so downstream titlebar implementation is unblocked (per design-system.md §Surface: desktop-webview / Component Patterns / Navigation / App Shell + Platform-Specific Notes for Windows/macOS/Linux).
- Window close behavior is "minimize-to-tray, not terminate-process" (terminate requires explicit Quit menu item) — `tauri.conf.json` window event configuration must align so the tray-icon-as-always-on surface contract holds (per CLAUDE.md @architecture.md §Cross-cutting Patterns / "Tray icon policy" + design-system.md §Surface: desktop-native / Component Patterns / Tray Icon "clicking the icon opens/focuses the compact widget").
- Local-bundled assets pattern: any future visual assets (fonts, icons, shaders) live under `pulse-app/ui/` rooted at the bundle, NEVER referenced from a third-party CDN — applies retroactively from chunk #2 to all subsequent design-token / iconography chunks (per design-system.md §Typography "Loading" + §Surface: desktop-webview "CSP policy" + Universal Bans).

## Anti-patterns to avoid

- NEVER configure the webview to allow third-party CDN script/font/style sources in CSP — even at scaffolding stage. The `script-src 'self'` discipline is the foundation that the WOFF2-bundled font and WGSL-inline-shader downstream chunks depend on; relaxing it now creates a downstream regression surface (per design-system.md §Surface: desktop-webview / "CSP policy: `script-src 'self'`").
- NEVER ship `tauri.conf.json` with default OS-decorations enabled — losing the frameless window invalidates the custom titlebar + traffic-light/control-button positioning conventions in Surface: desktop-webview / Platform-Specific Notes (per design-system.md §Per-Surface Bans / desktop-webview "NEVER use browser-style navigation" + §Component Patterns titlebar specification).
- NEVER configure default light-mode-only color scheme — dark-first is brand identity, not a preference (per design-system.md §Brand Identity "dark-first aesthetic" + Universal Bans "NEVER use ... bright, contrasty color palette ... rejected").

## Contract bindings

- **design ↔ security**: CSP `script-src 'self'` policy in `tauri.conf.json` is enforced both as a security invariant (per `.claude/rules/security.md` "supply-chain + CI" + bundled-asset discipline) AND a design invariant (locally-bundled WOFF2 fonts, no CDN). Both sides bind to the same `tauri.conf.json` field; loosening it for one breaks both contracts.
- **design ↔ a11y**: The `prefers-color-scheme: dark` default (set at scaffold time in webview shell config) is the surface that downstream a11y motion-token chunk (chunk #15 "Motion tokens library install") wires `prefers-reduced-motion` to alongside it — both media queries are read in the same Tailwind v4 `@theme` integration. Foundation chunk #2 establishes the dark-mode-default surface; subsequent design-tokens chunk owns the actual `@theme` block.
- **design ↔ arch (downstream)**: The five capability JSON identifiers (`pulse:default`, `pulse:tray`, `pulse:notification`, `pulse:updater`, `pulse:plugin-fs`) created in chunk #2 are the gates that the design surfaces Halo State Pulse tray glow (`pulse:tray`) and "Snapshot ready" toast (`pulse:notification`) depend on in Epoch 5–6 — naming and identifier reservation must match exactly per CLAUDE.md @architecture.md §Occupied Resources reservation list.
