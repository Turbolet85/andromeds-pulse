# arch extract

## Relevance
Relevant — arch governs crate placement, the locked tokio-channel + DuckDB-connection substrate the defect sits on, and the harness surface the new arm lands on; the attribution itself (candidate (a) vs (b)) is not an arch question.

## Constraints
- **Channel substrate is locked and its purpose is stated**: ingest→appender is `tokio::sync::mpsc` (chosen *for* built-in backpressure to "absorb receiver bursts"), buffer→subscribers is `tokio::sync::broadcast`; `crossbeam-channel` was explicitly rejected. A repair fixes the consumer side of that channel rather than the substrate (per `architecture.md` §Established Decisions → [In-Process Channel Architecture]).
- **One shared multi-threaded tokio runtime serves both OTLP ports and IPC** (`architecture.md` §Stack and Technologies → Async runtime; §Inherited Defaults). Blocking-pool threads and worker threads are therefore app-global, not `crates/buffer`-local — candidate (b) and any repair that adds, holds, or resizes threads has whole-app blast radius (retention, corpus writes, L4 subprocess supervision all share it).
- **§Occupied Resources records the ring buffer as a SINGLE in-memory `:memory:` DuckDB connection, identity `pulse_buffer`, schema `main`.** The chunk's in-scope "shared-appender-connection topology" therefore touches a registered arch resource: a repair that splits write/sweep/read onto separate connections changes that entry and must be surfaced as an arch amendment at wrap, not assumed (`architecture.md` §Occupied Resources → DuckDB database / schema names). Whether the shipped code already matches this single-connection registry entry or already deviates from it is research's question.
- **Storage access stays direct SQL via the `duckdb` crate's `Connection` + `Appender` with Arrow zero-copy `append_record_batch()`** — no ORM, no abstraction layer; lifecycle is create-on-startup plus the periodic `DELETE ... WHERE ts < cutoff` retention task (`architecture.md` §Established Decisions → [Database], [ORM / Migrations]; §Stack → Columnar interchange).
- **Code lands in the LOCKED workspace crate names** `buffer` (repair) and `xtask` (arm); no new workspace member, dependencies flow toward `pulse-app`, no library crate depends on the binary, no new sibling edge unless a declared contract requires it (`architecture.md` §Occupied Resources → Cargo workspace crate names; §Cross-cutting Patterns → Module dependency direction; §Inherited Defaults → Module boundaries).
- **Error shape**: module-internal errors are `thiserror` enums surfaced only through the crate's contract module; anything crossing the TauRPC bridge must be `Serialize` and map to the stable `AppError` variants (`Storage` / `Ingest`) (`architecture.md` §Established Decisions → [Error Handling Pattern]; §Conventions → Module visibility discipline + Error response schema; §Cross-cutting Patterns → Cross-bridge data shape). Note the scope's "0 ERROR, nothing returns so nothing reports" — if the repair introduces a bounded/timeout path, arch requires that path to produce a typed error, not a silent degrade.
- **Any new tunable follows env > `config.toml` > built-in defaults**, with a bounded never-panicking parse, `*_seconds` naming for durations, and registration in §Occupied Resources → Environment variables — arch registers harness-only vars as their own class too (`architecture.md` §Cross-cutting Patterns → Config management; §Conventions → Configuration units; §Occupied Resources → Environment variables).

## Patterns to follow
- **Harness surfaces are `cargo xtask` subcommands** — "all shared CI logic that needs Rust lives in the `xtask` crate so contributors can run identical commands locally" (`architecture.md` §Infrastructure Patterns → CI/CD; §Established Decisions → [CI Task Runner]). The registered precedent for a flagged harness CLI is `cargo xtask webview-drive [--expect-absent <STAGE>] [--no-inject]` in §Stack → GUI verification harness; a new arm/mode on `smoke:gap-resume` follows that shape.
- **Real-OTLP-only telemetry injection**: e2e/scenario arms speak OTLP on `:4317`/`:4318` — the same surface external SDKs use — with port overrides via `ANDROMEDA_PULSE_OTLP_GRPC_PORT` / `_HTTP_PORT`, and buffer state read back through the `traces.*` / `metrics.*` / `logs.*` routers (`architecture.md` §Cross-cutting Patterns → Test-time telemetry injection).
- **Env-layer-only bounded knob resolved once at boot** if the repair needs a threshold: no `Settings` field, no `config.toml` key, hence no TauRPC contract and no hot-reload delta — precedent entries `ANDROMEDA_PULSE_BASELINE_BOOTSTRAP_SECONDS` and `ANDROMEDA_PULSE_L4_ALLOW_ROOT` (`architecture.md` §Occupied Resources → Environment variables).
- **Choke-point concurrency guard, expected-loss typed as an outcome not an error** — the arch-endorsed shape for arbitration/contention fixes: place the guard at the one point every writer traverses, and encode the expected losing case as a returned outcome so call sites don't log it as failure (`architecture.md` §Established Decisions → [Corpus Write Arbitration]). Different substrate (corpus SQLite), same design shape.
- **Crate template**: public contract module as the only `pub` surface, `pub(crate)` internals, `thiserror` error enum (`architecture.md` §Project Intent → Template patterns; §Conventions → Module visibility discipline).

## Anti-patterns to avoid
- **No in-process bypass for the new arm** — no test-mode feature flag, no mock-channel back-door, no direct appender call that skips the receivers (`architecture.md` §Cross-cutting Patterns → Test-time telemetry injection).
- **No channel-substrate swap and no second runtime** — not `crossbeam-channel`, not a private tokio runtime for the consumer (`architecture.md` §Established Decisions → [In-Process Channel Architecture]; §Stack → Async runtime, "single multi-threaded runtime serving both OTLP ports and IPC").
- **No cross-crate `pub use` re-export outside the contract module and no library→binary dependency** if the repair needs to expose new state for the arm to observe (`architecture.md` §Conventions → Module visibility discipline; §Cross-cutting Patterns → Module dependency direction).

## Contract bindings
- **arch ↔ obs (envelope)**: `architecture.md` §Standard Contracts locks `health.subsystems.{buffer, ingest_channel}` (degraded ⇒ the subsystem string becomes the failure reason) and `ready.checks.{ingest_mpsc_capacity_pct, rows_ingested, buffer_used_seconds, retention_seconds}` — the exact quantities the scope's arm A measures. Whether the wedge is already reported through these envelopes today is research's question; if the repair adds a field there it is a §Standard Contracts amendment (precedent: the 2026-07-07 `ready` +3-fields amendment).
- **arch ↔ obs (connection topology)**: the DuckDB connection-isolation invariant lives in obs-plan §10 / `rules/observability.md`, while `architecture.md` §Occupied Resources records a single `:memory:` connection named `pulse_buffer`. Whatever topology the repair lands must reconcile the two documents, not just one.
- **arch ↔ tests (harness resources)**: the injector's CLI contract and the `PULSE_BIN` / `PULSE_DATA_DIR` / `MSEDGEDRIVER_PATH` / `PULSE_INJECTOR` relay set are arch-registered (`architecture.md` §Stack → GUI verification harness; §Occupied Resources → Environment variables), and the arg-less default's byte-identical emission is recorded as load-bearing. A new arm reusing `inject_demo` must not change that default; a new harness env var joins the registered `PULSE_*` set.

## Acceptance criteria contributions
- The repair lands in `crates/buffer` with the arm in `xtask`; no new workspace member, no new inter-crate dependency edge, and the dep graph stays a DAG rooted at `pulse-app` (per `architecture.md` §Occupied Resources → Cargo workspace crate names + §Cross-cutting Patterns → Module dependency direction).
- The reconnect-without-gap arm is a `cargo xtask` subcommand/mode that drives telemetry only over real OTLP on `:4317`/`:4318`, with no in-process bypass and no test-only feature flag (per `architecture.md` §Cross-cutting Patterns → Test-time telemetry injection + §Infrastructure Patterns → CI/CD).
- Ingest→appender remains `tokio::sync::mpsc` on the one shared runtime, with backpressure absorbing the post-resume burst instead of wedging the loop (per `architecture.md` §Established Decisions → [In-Process Channel Architecture] + §Stack → Async runtime).
- If the repair changes the DuckDB connection topology or adds any env var/tunable, the corresponding §Occupied Resources entry (DuckDB `pulse_buffer` single-connection line; Environment variables list) is amended at wrap with a bounded `*_seconds`-style parse for any duration (per `architecture.md` §Occupied Resources → DuckDB database / schema names + Environment variables; §Conventions → Configuration units).
