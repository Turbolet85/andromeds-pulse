## Anti-patterns to avoid

- NEVER include raw OTLP attribute values, span/log/metric content payloads, or full instrumentation_scope.name strings on the `RestartEvent` payload — restart evidence is `service.name` (identifier-class) + last-seen-ts + gap_seconds + resume-ts only; the §Logging & Monitoring NEVER-log list applies to outbound stream payloads the same as it applies to log records (telemetry is user-controlled content per §Threat Model Summary data classification).
- NEVER make restart-window suppression a blanket "if-restart-active-skip-all-cues" branch — the chunk spec demands surgical suppression (only `ErrorRateSpike` with `persistence < 30s` within 60s suppression window). A blanket skip silently swallows real `LatencyOutlier` / `CardinalitySpike` / `MagnitudeBypass` cues that the dual-condition bypass invariant (P-057) is designed to surface — defeats the catastrophic-regression-visibility guarantee (per chunk spec behavioral note).
- NEVER spawn `tokio::process::Command::new(...)` for restart correlation against any string sourced from OTLP attributes, MCP tool arguments, or workspace-detector output — the MCP STDIO command-injection cluster (CVE-2025-49596, CVE-2025-54994, CVE-2025-54136, CVE-2026-22252) and §Security Anti-Patterns § Code Patterns row 1 are direct hits; restart detection MUST be pure in-process gap-detection on `LastSpanSeenTracker` data structures.
