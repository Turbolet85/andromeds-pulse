# obs extract

## Relevance
Relevant — this chunk consumes the drain-progress observable, reads the self-observation JSON log as its primary evidence base, and may add instrumentation to `crates/buffer` / `crates/triage` / `pulse-app` (scope §5–§6).

## Constraints
- **Exact-leaf discipline is mandatory for any new target/field.** Per obs-plan.md §8 (Default-deny posture) a bare `buffer` key EXISTS, so a new `buffer.*` target resolves via `for_target`'s first-`.`-segment fallback to the *tick* field set and every field redacts silently; the `buffer.consumer.stalled` entry is the precedent (its exactness is load-bearing in the OPPOSITE direction to the `app.`-prefixed leaves). A new leaf must enumerate EVERY field its emit site emits, and its guard must live under `pulse-app/tests/` because `[lib] test = false` compiles but never runs a src-level `mod tests` guard (per obs-plan.md §8).
- **Restatement rule — a tick FIELD is a three-site change, a WARN TARGET a two-site change.** A new `buffer.tick` field must land at §1 Heartbeat ticks + §5 (its own tick-aggregated Counter row) + §8 `buffer` whitelist; a new WARN target at §6 `warn` row + §8 leaf (per obs-plan.md §1/§5/§6/§8).
- **Stall semantics are two-signal and fixed.** Tick presence is LIVENESS; drain progress (`rows_ingested_delta` staying 0 across consecutive `buffer.tick`s while the ingest channel holds queued work) is the companion PROGRESS signal, announced ONCE per healthy→stalled transition and once on recovery after 30 consecutive non-draining ticks (450s), sited deliberately above §10's own 420s sustained-drain cap. The `health` IPC command, being tick-derived, reports liveness and NOT progress for the same reason (per obs-plan.md §3 Heartbeat ticks / Stall detection + §10 Standard+ invariants). Scope §5 places these OUT of scope to edit — this chunk consumes them.
- **The blocking-pool mechanism the scope's §4 names has a plan-side precedent.** obs-plan.md §10 (DuckDB Connection Isolation) records defect class #2 verbatim — `tokio::time::timeout` wrapped a `spawn_blocking` query holding the mutex but could not cancel it, repaired via a dedicated read connection plus explicit `interrupt_handle().interrupt()` on timeout — and mandates that any future DuckDB consumer with a multi-second statement take a dedicated `try_clone()` connection, never the shared appender connection. Whether every production `spawn_blocking` site at HEAD carries that interrupt-on-timeout treatment (or only the viz/L1a read paths named in §10) is research's question.
- **A known non-defect must not be mistaken for the mechanism.** obs-plan.md §10 marks *characterized-not-fixed*: the append path performs multi-row-group maintenance that can block a single append inside `spawn_blocking` for >60s on a ~12.7M-row table, absorbed by the 1024-batch mpsc, "degraded-but-functional, zero L0 loss", in-spec. Long blocking-thread occupancy alone is therefore not evidence of the wedge.
- **Hot-path emission is banned.** No per-batch, per-row, per-cue, per-trigger, or per-decision emission; counters fold once and ride an existing 15s tick (per obs-plan.md §11 Telemetry Strategy + Logs, enforced by every §5 tick-aggregated Counter row). §5's cadence row records the cost directly: one `cadence.trigger` record per cycle is why the wedge log reached 131 MB — the same file this chunk's forensic pass must read.
- **Any new forensic field is bounded-label-or-basename only.** Per obs-plan.md §8 (Data classification + Vectors 3/5/6) and §11 Metrics: bounded static labels, basenames, and aggregate numerics only — never full canonicalized paths, DuckDB query text, bound parameter values, or per-thread / per-task / per-trace identity as a label.
- **Silence is itself a defect class here.** obs-plan.md §10 Standard+ requires every module-boundary error logged at WARN/ERROR with trace context + error category, and §10's always-required invariant requires zero unlogged panics — a wedge that ran 16 minutes at 0 ERROR is the condition these invariants exist to prevent recurring undiagnosed.

## Patterns to follow
- **Fold-once-and-ride-a-tick.** The established shape for a new bounded observable is a per-batch/per-cycle fold folded onto an existing 15s heartbeat as a FIELD, not a new `metric.*` target — `BufferState::record_feed_counts`, `record_redactions`, and the `rows_ingested_delta` / `last_append_age_seconds` pair are the three worked precedents (obs-plan.md §5 tick-aggregated Counter rows).
- **Transition-WARN shape.** `buffer.consumer.stalled` — once per healthy→stalled transition and once on recovery, never per batch, with bounded static `reason` / `consequence` tokens plus numerics (obs-plan.md §6 `warn` row, §8 leaf). `interpretation.generation.damper` follows the same engage/release-only shape.
- **Warn-on-fallback on connection acquisition.** `buffer::retention`, `TriageSqlState::new`, and `viz::query::read_connection` share one shape — dedicated `try_clone()` taken once at construction, WARN with `fallback = "shared_connection"` when it cannot be taken (obs-plan.md §10). If this chunk adds any pool/connection guard, this is the precedent to match.
- **Leaf guard construction + mutation check.** `pulse-app/tests/unit_observability_allowlist_*.rs`: exact-resolve, field-set equality in BOTH directions, and a fallback discriminator proving the prefix set cannot serve the target — without the discriminator the guard passes vacuously after a leaf is deleted (obs-plan.md §8, `unit_observability_allowlist_consumer_stall.rs` and `..._cue_tick.rs` as worked examples, both mutation-checked).
- **Agent-side aggregation over the JSONL.** obs-plan.md §5/§10 make `jq` over `agent-latest.jsonl` the consumption convention (percentiles computed agent-side, never precomputed in the emission path) — the same read the scope's forensic pass performs over the preserved 131 MB corpus.

## Anti-patterns to avoid
- Adding any per-`spawn_blocking`-call, per-batch, or per-record emission to characterize the pool — obs-plan.md §11 Logs ("NEVER log in hot path at `info` level") and §11 Telemetry Strategy ("NEVER over-instrument hot paths — appender inner loop, per-row DuckDB operations").
- Labeling a new blocking-pool observable with unbounded cardinality — no thread id, task id, trace id, or arbitrary call-site path as a label; enumerate label values upfront (obs-plan.md §11 Metrics).
- Emitting query text, bound parameters, or full canonicalized paths in any new forensic field, however debuggable it would be (obs-plan.md §11 Logs + Spans, Vectors 3/5).

## Contract bindings
- **obs ↔ tests harness (§3 Log format JSON schema):** the JSON log schema is verbatim FROM the tests plan's Test Harness Contract — obs aligns to tests, not vice versa. Any field this chunk adds rides inside `fields`, never as a new top-level key.
- **obs ↔ tests/CI gates (§10):** `cargo xtask check:ingest-progress` asserts the drain-progress invariant; `xtask/ci/heartbeat-gap-check.sh` asserts ≤45s consecutive-tick gaps for `ingest.tick` / `buffer.tick` / `viz.tick` / `plugins.tick`. Both must stay green, and per §10 load-profile constraints every xtask check script over `agent-latest.jsonl` must remain NEUTRAL-tolerant (absent stream ≠ failure) and run-window-scoped via `write_run_window_log`.
- **obs ↔ arch Standard Contracts (§3 complementarity paragraph):** the TauRPC `health` command exposes the tick-derived fields synchronously; ticks and `health` must not be conflated, and `health` reports liveness rather than progress.
- **obs ↔ security (§8 Vectors 3/5/6):** the basename / bounded-label / aggregate-only discipline is where the security plan's logging-sensitive vectors land on every new field.

## Acceptance criteria contributions
- Any new observability target this chunk adds resolves to its OWN exact allowlist leaf enumerating every field its emit site emits, guarded under `pulse-app/tests/` by a test asserting the set by equality in both directions plus a bare-`buffer` fallback discriminator, and mutation-checked (per obs-plan.md §8).
- No new emission sits on a per-batch, per-row, per-`spawn_blocking`-call or per-decision path: any new counter folds once and rides an existing 15s tick as a FIELD, and any new state signal fires once per transition (per obs-plan.md §11 + §5).
- `buffer.consumer.stalled`, `rows_ingested_delta`, `last_append_age_seconds` and the 450s / 30-tick threshold retain their shipped semantics; `cargo xtask check:ingest-progress` and `xtask/ci/heartbeat-gap-check.sh` pass NEUTRAL-tolerant over the run window (per obs-plan.md §10).
- Every field naming a blocking-pool site, lock, connection, path, or query is a bounded static label, a basename, or an aggregate numeric — no full path, query text, bound parameter value, or per-thread/per-task identity (per obs-plan.md §8 + §11 Metrics).
