## Constraints

- The preview/confirmation dialog MUST use `dialog` role + `aria-modal="true"` + `aria-labelledby` (title) and, if a description summary is announced, `aria-describedby`; initial focus lands on the dialog title or the close/cancel control (per a11y plan §4 Dialog pattern + §5 focus trap).
- The dialog MUST be a focus trap with an explicit Escape escape path: Esc closes the dialog and Tab/Shift+Tab cycle within (wrap on last/first), with NO keyboard trap (per a11y plan §5 Focus trap + §11 Keyboard "NEVER create keyboard traps"; SC 2.1.2 + SC 2.4.3).
- On dialog close (Esc, Cancel, or post-export dismiss), focus MUST restore to the triggering "Export for community training" button (focus-trap-react `returnFocusOnDeactivate: true`) (per a11y plan §5 Focus restoration; SC 2.4.3).
- The export-completion / file-written outcome and any "exporting…" progress MUST be announced via a live region — `aria-live="polite"` for non-blocking completion ("Exported N records to {path}"); `role="alert"`/`aria-live="assertive"` for an export error (per a11y plan §7 Live regions + §1 Critical-path P3/P6 status pattern; SC 4.1.3).
- Action button + confirm/cancel buttons MUST be native `<button>` with accessible names; the dialog content (counts, date range, anonymization confirmation) MUST use semantic HTML first, ARIA second (per a11y plan §4 Button/§2 "semantic HTML first"; SC 4.1.2).
- All interactive controls (action button, confirm, cancel, close ✕) MUST show the `--border-focus` focus ring on `:focus-visible` and meet the SC 2.4.7 visible-focus + SC 1.4.11 ≥3:1 non-text contrast bar; targets ≥24×24 CSS px (`--target-button-min`) per SC 2.5.8 (per a11y plan §6 Focus ring tokens / Target size tokens).
- Any text rendered in the dialog (summary, anonymization confirmation, file path) MUST meet SC 1.4.3 contrast via design tokens (`--color-text-primary / --color-base` 4.5:1; secondary/tertiary 3:1) — no ad-hoc colors (per a11y plan §6 Color contrast pairs).

## Patterns to follow

- Modal pattern: reuse the existing settings-modal / investigation-modal Dialog convention (focus-trap-react v12 with `escapeDeactivates: true` + `returnFocusOnDeactivate: true`; initial focus on title or first control) rather than authoring a new modal primitive (per a11y plan §5 Focus trap + §4 Dialog; the project already ships a Modal primitive scaffold per route Epoch 5).
- Status/confirmation pattern: mirror the snapshot-generation async status pattern — `aria-busy` on the confirm/export button during the write, then `aria-live` announcement of the result token/record count (per a11y plan §1 Critical Path P2/P6 + §7 Live regions).
- Not-color-alone for the anonymization-confirmation indicator: if a "PII-scrubbed / anonymized ✓" status is shown with a state color (`--color-feedback-success`), pair it with an icon AND a text label (custom DOM assertion required; axe-core does not detect this) (per a11y plan §6 State color tokens + §11 Visual "NEVER convey information by color alone").
- Reduce-motion: any modal open/close or button transition must degrade to instant under `prefers-reduced-motion: reduce` via Tailwind `motion-reduce:` variants / `useReducedMotion`, with state still conveyed by text + focus ring (per a11y plan §6 Motion tokens + §9; SC 2.3.3 AAA escalation).
- Compile-time gate: new TSX components must pass `eslint-plugin-jsx-a11y` recommended config (labels present, no ARIA on non-semantic HTML) (per a11y plan §2 Understandable + §3.5 a11y-linting-install).

## Anti-patterns to avoid

- NEVER ship a confirmation/preview modal without an Escape close + focus trap + focus restoration — an inaccessible modal that breaks the keyboard navigation chain (per a11y plan §11 Keyboard + Universal "NEVER use inaccessible … modal that breaks keyboard navigation").
- NEVER convey the anonymization/export-success state by color alone, and NEVER use `outline: none` (or omit `--border-focus`) on the action/confirm/cancel controls (per a11y plan §11 Visual; SC 1.4.1 + SC 2.4.7).
- NEVER add redundant/excessive ARIA (`role="button"` on `<button>`, `role="dialog"` on a native `<dialog>` element, `aria-label` on every node) — semantic HTML first (per a11y plan §11 ARIA + Screen Reader).
