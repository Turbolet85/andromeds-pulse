# a11y extract

## Relevance
PARTIAL — the "still running" signpost surface requires a11y treatment (screen reader + contrast); the self-verify harness reuses existing a11y/contrast assertions; the close behavior itself (hide-to-tray) is not a11y-specific but must preserve P5 focus/keyboard contracts.

## Constraints
1. A11y tier Standard → WCAG 2.1 AA full + motion-sensitive AAA escalation (SC 2.3.3 Animation from Interactions) per a11y-plan §1 Scope Summary
2. Tray-icon surface is assertable; tray menu has limited automated tool reach (OS-native a11y APIs only); manual keyboard + screen reader testing required per a11y-plan §3 Screen Reader Test Pattern and §1 Scope table row "desktop-native (tray-icon menu)"
3. If signpost is OS notification: must be screen-reader accessible via OS notification API per a11y-plan §1 Scope table row 3; if web-tooltip: must follow P5 focus/keyboard contracts per a11y-plan §5 Focus Management
4. Self-verify harness must integrate existing a11y/contrast assertion suite (`npm run test:a11y` via @axe-core/playwright + Lighthouse + pa11y) per a11y-plan §3 CI Integration and §3 Harness Contract
5. Close behavior must preserve P5 focus-restore on re-expansion per a11y-plan §1 Critical Path P5 + §5 Focus restoration
6. Per amendment 2026-06-10 standing rule: if signpost is a new web-accessible surface, it requires an axe spec per a11y-plan §3 "Adding a surface (standing rule)"

## Patterns to follow
1. Reuse existing a11y/contrast harness (@axe-core/playwright 4.11.x, Lighthouse 12.x, pa11y 9.x) for self-verify integration; compose existing pieces per a11y-plan §3 Harness Contract (binding to tests §5 E2E driver: boot/run/status/cleanup/logs)
2. Tray-icon surface uses OS-native a11y; manual keyboard + SR testing only; no automated tool reach for tray menu internals per a11y-plan §1 Scope table + §3 Screen Reader Test Pattern
3. Web surfaces: apply semantic HTML first (native `<div role="status">` + `aria-live="polite"`) per a11y-plan §2 invariant

## Anti-patterns to avoid
1. No manual-only a11y verification for web surfaces (supplemental OK, never sole) per a11y-plan §2 Agent-driven invariant + amendment 2026-06-10
2. No ARIA on non-semantic HTML per a11y-plan §2
3. Do not break P5 focus-restore on close-to-tray / tray→Open per a11y-plan §1 Critical Path P5

## Contract bindings
- Self-verify harness ↔ tests §5 E2E driver (reuses 5-command discipline per a11y-plan §3 Harness Contract)
- Self-verify harness ↔ a11y-plan §3 Harness Contract (invokes `npm run test:a11y`; emits machine-readable violation JSON)
- Signpost surface (if OS notification) ↔ obs §6 (notification event logging per a11y-plan §1 Scope table row 3)
- Signpost surface (if web-tooltip) ↔ design §Color Palette (contrast verification per a11y-plan §3 Contrast Verification Harness)

## Acceptance criteria contributions
1. "(a11y) Self-verify harness boots the app, runs `npm run test:a11y`, and exits with deterministic pass/fail (0 = pass, non-zero = fail) per a11y-plan §3 CI Integration."
2. If signpost is web-tooltip: "(a11y) Signpost surface passes `npm test:a11y:axe-core` with no critical/serious WCAG violations per a11y-plan §3 CI gate."
3. If signpost is OS notification: "(a11y) Signpost notification content is screen-reader accessible via OS a11y APIs; verified via manual SR pass (NVDA/VoiceOver/Orca) per a11y-plan §3 Screen Reader Test Pattern."
4. "(a11y) Close-to-tray preserves P5 focus-restore: after minimize-to-tray / tray→Open, focus returns to previously focused element per a11y-plan §5 Focus restoration."
