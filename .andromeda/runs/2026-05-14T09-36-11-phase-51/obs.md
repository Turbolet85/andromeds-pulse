## Constraints

- **§10 Performance budgets table — WebGPU canvas frame budget**: p50 16ms, p95 20ms, **p99 ≤33ms** (30 fps target). Backed by `tracing` events at `metric.webgpu.frame_duration_ms` (bridged from frontend via TauRPC `telemetry.frontend.record_frame_ms`); SLO enforced via CI post-test tail using `jq '.fields.duration_ms' < agent-latest.jsonl | sort -n | quantile 0.99`; offline criterion bench supports stable-hardware regression detection.
- **§10 Performance budgets table — buffer memory bounded**: p99 ≤512 MB at 10k spans/sec for 10-min window. Backed by `tracing` events at `metric.buffer.memory_bytes` per heartbeat tick (`buffer.tick`); SLO `value` field ≤512_000_000; CI tail-and-max post-test.
- **§5 Metric event naming for the perf SLO**: target prefix is `metric.webgpu.frame_duration_ms` (Distribution; unit ms) with label fields `wgpu_backend: vulkan|metal|dx12`, `webview_backend: WebView2|WKWebView|GTKWebKit`, `timing_method: cpu|gpu`. Per-event `value` / `duration_ms` is the raw sample — agent computes p99 via `jq`. The 10k spans/sec throughput sample target is `metric.buffer.ingest_throughput_spans_per_sec` with `spans_per_sec` + `dropped_span_count` fields, per heartbeat tick.
- **§10 Always-required SLO invariant — zero unlogged panics**: applies to any new audit harness code path. Every `panic!()` MUST be captured by the panic hook and logged with structured backtrace; the audit harness CI step itself must respect this.
- **§9 CI artifact handling — criterion bench JSON on perf-budget regression**: when `xtask bench` runs, `target/criterion/<bench>/new/estimates.json` MUST be uploaded as a CI artifact; parsed for SLO regression detection (e.g., `snapshot.token_count_ms` p99 ≤500ms — chunk #54 adds `frame_duration_ms` p99 ≤33ms to the same regression detection pattern).
- **§9 CI-specific default fields**: any new CI gate workflow setting up `tracing-subscriber` (e.g., the perf SLO harness) MUST extend `with_default_fields([service.name, service.version, deployment.environment, ci.run.id, git.commit.sha])` so every JSON line carries CI provenance — agent triage requires this.
- **§8 Default-deny allowlist whitelist per module** — violation-JSON regression tests MUST NOT log raw violation `html` payloads or DOM `outerHTML` strings as fields — those values can contain incidentally-captured OTLP attribute strings during live ingest. Emit `wcag_criterion` + `selector` + `severity` + `surface` only (per a11y violation JSON schema binding к obs structured log format per focus guide cross-domain bindings).
- **§Decisions Log 2026-05-04 — PII grep heuristic UI-vocabulary exemption**: violation-JSON regression test fixtures (per-surface `{wcag_criterion, selector, severity}` tuples) MUST use literal secret-format regexes (`Bearer [a-zA-Z0-9]{40,}`, `password=[^\s]+`, `api_key=[^\s]+`, `AKIA[0-9A-Z]{16}`, `sk-[a-zA-Z0-9]{40,}`, `ghp_[a-zA-Z0-9]{36}`, `xox[baprs]-[0-9a-zA-Z-]{10,}`) when scanning artifacts — NOT the bare word "token" / "password" / "auth" / "key" which collide with mandated UI vocabulary (per a11y-plan §3 P2 "Token budget" slider).

## Patterns к follow

- **§5 Metric emission convention**: every metric is `tracing::info!(target: "metric.{module}.{measure}", value = N, ...)` — NO OTel Meter / Histogram / Counter instruments. The perf SLO gate must read raw events from `~/.andromeda-pulse/logs/agent-latest.jsonl` and compute p99 via `jq`-style aggregation. This is the existing convention from chunks #25 (WebGPU canvas perf) + #26 (compute aggregation + frame budget). Chunk #54 audits + enforces, doesn't introduce new instrumentation.
- **§10 CI gates pattern** (existing precedent — chunk #54 extends to frame duration): build fails if perf-budget p99 exceeds SLO. Format: `xtask bench` step produces criterion JSON + post-bench p99 assertion via `jq` aggregation over `metric.*` events. CI script post-test: `jq '. | select(.target == "metric.webgpu.frame_duration_ms") | .fields.duration_ms' agent-latest.jsonl | sort -n | tail -1` must be ≤33 or exit 1.
- **§10 Heartbeat-gap CI gate pattern** (`xtask/ci/heartbeat-gap-check.sh`): the perf SLO regression detector mirrors this shape — parse `timestamp` field for each `metric.webgpu.frame_duration_ms` event, compute consecutive deltas per surface, aggregate p99 per surface, assert SLO or exit 1.
- **§9 Pipeline integration — Integration tests (P1-P7)**: logs artifact + curated-snapshot artifact on failure. Chunk #54's a11y audit produces a third sibling artifact class: violation-JSON tuple baselines + current-run JSON, compared per-surface for regression detection.
- **§Section 1 perf-budget-instruments trigger row 2** (existing instrumentation, not new): `metric.webgpu.frame_duration_ms` events are already emitted per chunks #25 + #26; chunk #54 consumes them. The 10k spans/sec injection harness already exists conceptually via tests-plan §6 P1 + the chaos-instrumentation triggers (`metric.buffer.ingest_throughput_spans_per_sec` per heartbeat).
- **§3 Snapshot / paste-to-AI integration — Self-observation surface**: when the a11y audit run fails, the agent reads `~/.andromeda-pulse/logs/agent-latest.jsonl` for triage. The violation-JSON regression diff output should ALSO be JSON-per-line if it's emitted into the log file (rather than a sibling artifact) — but the per-surface tuple regression artifact is naturally a separate JSON file uploaded alongside the log file, mirroring the criterion JSON pattern in §9.

## Anti-patterns к avoid

- **§11 SLO — NEVER define soft SLO budgets (no enforcement)**: the perf SLO p99 ≤33ms MUST trigger build failure when exceeded (`xtask bench` step exit 1). Do NOT add this as a warning-only gate.
- **§11 SLO — NEVER defer error budget decisions к humans**: agent-driven SLO assertions in CI. The violation-JSON regression gate must be machine-decidable (per-surface tuple diff), not "maintainer reviews on green").
- **§11 SLO — NEVER skip zero-unlogged-panics invariant**: applies к the audit harness code itself. If axe-core / Lighthouse / pa11y CLI invocation panics or crashes the harness, panic hook must capture it; the gate cannot silently pass on harness crash.
- **§11 Metrics — NEVER skip p50/p95/p99 coverage on perf-budget metrics**: emit raw per-event `value` field; agent computes percentiles by tailing JSON. Do NOT precompute quantiles at emission time (would lose distribution data for regression analysis).
- **§11 Logs — NEVER use unstructured stderr text**: any new `xtask perf-audit` / `xtask a11y-audit` subcommands must emit JSON-per-line via the established `tracing-subscriber` dual-sink, not raw `println!`.
- **§11 PII Scrubbing — NEVER include PII в logs / spans / metrics by default**: the a11y violation JSON schema MUST emit `wcag_criterion` / `selector` / `severity` / `surface` only — not violation `html` / DOM snippet content (incidentally captures any OTLP attribute strings rendered into the UI during live ingest tests).
- **§11 CI — NEVER lose telemetry artifacts**: violation-JSON regression baselines + current run + criterion bench JSON + log file all uploaded as CI artifacts with 14-day retention.
- **§11 Universal — NEVER link an OTel SDK into the product's self-observation runtime**: the a11y / perf audit harness must NOT introduce an OTel SDK as a "monitoring my monitor" backdoor. All telemetry from the audit harness flows through existing `tracing` events into `agent-latest.jsonl`.
- **§11 SLO — NEVER add retry-once policies for panic handling** (extends к flakiness): the perf SLO gate cannot be paired with retries to mask intermittent SLO violations. (Note: this is obs-domain framing; tests-domain §Flakiness in chunk #55 covers the broader test-flakiness retry policy.)
