## Anti-patterns к avoid

- **NEVER skip a11y CI on failure** — a11y is FAIL-fast gate, NOT а warning; PR cannot merge с violations; no soft gates / "fix in follow-up" deferrals (per a11y plan §11 CI Anti-Patterns).
- **NEVER use retry-once policy for a11y violations** — masks real failures (parallel к tests' zero-flakiness budget); if а11y test flakes, quarantine via `#[ignore]` / skip, investigate, fix or delete before unquarantining (per a11y plan §10 SLO + §11 SLO Anti-Patterns).
- **NEVER omit per-PR diff regression detection** at Standard+ tier — without it, latent violations from base-branch persist invisibly (per a11y plan §11 SLO Anti-Patterns).
- **NEVER claim WCAG conformance from lint-only (`eslint-plugin-jsx-a11y`)** — lint catches subset (ARIA on non-semantic); runtime axe-core / pa11y / Lighthouse catch rest; both MUST run (per a11y plan §11 CI Anti-Patterns).
- **NEVER pass perf SLO by globally disabling motion in test config** — that masks SC 2.3.3 regressions; perf gate AND reduced-motion gate run independently with independent pass conditions.
