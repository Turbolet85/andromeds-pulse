## 2026-05-02 — Initial layout templates generated by `/andromeda-design` Phase 8

- **Section:** whole document (foundational). Surfaces covered: desktop-webview
  (compact widget + full dashboard) and desktop-native (tray icon + menu).
- **Change:** one-shot Phase 8 generation (no iteration loop) that established
  the per-surface layout truth now in the body:
  - **Key layout choices** — compact widget as a fixed quarter-screen glance
    surface (frameless titlebar, snap-to-edge, always-on-top, Halo canvas hero,
    read-only footer; Esc → tray; settings toggle expands to the full
    dashboard); full dashboard as a resizable window (custom titlebar for
    continuity, tabs-or-sidebar nav over Traces / Metrics / Logs / Snapshots /
    Settings, per-service Halo on the constellation map hero); tray icon as a
    monochrome SVG glyph with a unified Halo layer (WebGPU canvas or SVG-filter
    fallback) plus a flat right-click action menu.
  - **Cross-surface IA** — three-surface coherence (glance / exploration /
    ambient status) with consistent Halo shader logic and shared Tauri 2
    broadcast data feeds; the same frameless titlebar across both webview
    surfaces; an OS-native tray + menu respecting platform conventions.
  - **Signature placement** — unified Halo on the compact-widget aggregated
    service-count badge (bottom-right of the canvas); per-service Halo dots on
    the full-dashboard constellation map; unified Halo composited around the
    tray glyph; all data-driven (throughput → pulse frequency, error rate →
    LCH hue), not decorative.
  - **Motion triggers** — Investigation Capture Collapse on the full-dashboard
    "Investigate" action; continuous data-driven Halo "breathing" on all three
    surfaces (exempt from the chrome budget, separate WebGPU canvas layer);
    Settings-modal panel transitions over `duration-standard`; OS-native
    (instant) tray-menu emergence per the `0.2` desktop-native expression level.
- **Why:** initial generation by `/andromeda-design` Phase 8.
- **Body now:** these decisions ARE the current body — the desktop-webview and
  desktop-native surface sections (Primary screens, Wireframes, Components, IA
  notes). Four current-truth items that lived ONLY in the Decisions Log were
  folded into the body during v3 normalization:
  - **Responsive posture (webview)** → desktop-webview IA notes "Responsive
    behavior" — compact widget fixed quarter-screen with no CSS media-query
    breakpoints (min-readable on a 13-inch laptop); full dashboard resizable
    with no hard breakpoints, nav may collapse tabs → hamburger at narrow
    widths, both models valid.
  - **Snapshot detail-viewer deferral** → desktop-webview Primary screens
    (Snapshots view) — the snapshot-markdown viewer layout (modal vs.
    full-page) is deferred to the implementation route; snapshots are generated
    via the TauRPC `snapshot.generate` command.
  - **Desktop-only scope** → top-of-file scope note — Windows / macOS / Linux
    only; no mobile or touch surface; the tray follows platform conventions
    (no mobile gestures).
  - **Settings-modal panel-transition motion** → desktop-webview Settings modal
    component "Motion" — open / close eases over `duration-standard`, within the
    `0.35` webview budget.
- **Deferrals recorded (already body current-truth, no fold needed):** full
  dashboard navigation model committed to "either tabs OR sidebar" without
  prescribing which (body: Primary navigation component); deep-link / URL-hash
  route structure deferred downstream while committing to routable views
  (`/traces`, `/metrics`, `/logs`, `/snapshots`, `/settings`) + keyboard
  shortcuts (body: IA notes Deep-link convention + Keyboard shortcuts).
- **Handoff / ownership notes (recorded; build-ownership boundaries, not
  body-layout truth):**
  - **Custom titlebar** — drag region + window-control buttons owned by the
    route specialist (React + Tailwind in the webview); design provides layout
    structure + token references, implementation owns the exact Tauri 2 IPC
    calls (minimize / maximize / close).
  - **Halo State Pulse** — WebGPU canvas + WGSL shader for all three surfaces,
    SVG-filter fallback for the tray-icon halo when WebGPU is unavailable; the
    route + obs implementation specialist owns canvas init, shader authoring,
    data-feed subscription, and reduced-motion degradation.
  - **TauRPC command surface (IPC bridge)** — Settings-modal submits, Investigate
    clicks, and snapshot generation all trigger TauRPC commands (e.g.
    `snapshot.generate`, `health` polling for the tray summary line); the route
    specialist wires them and the `ui-bridge` crate (Tauri side) implements the
    logic.
  - **DuckDB query layer** — constellation positions (service topology),
    `traces.query`, `metrics.query`, and `logs.query` flow DuckDB → TauRPC →
    webview React components; the viz crate owns the query schema, the route
    specialist owns component integration.
  (Layout/token substance for each lives in the body; these record the original
  log's build-ownership boundaries.)
- **Marker:** none (initial generation). By: `/andromeda-design` Phase 8.
