**CI/CD approach.**
- Platform: GitHub Actions.
- `ci.yml` runs on every PR and push to main as six independent jobs, each on `ubuntu-22.04` with no matrix and no `needs:` edge, so a round lasts as long as its longest job: `lint-test` (`cargo fmt --check` → `cargo clippy ... -D warnings` → the xtask gates → `cargo xtask test`, then `perf:slo-load`, `cargo nextest run --workspace --profile perf-samples --no-tests=fail` (the `pulse-app/tests/perf_budget_samples.rs` producer, excluded from the default nextest filter; the flag since chunk 2026-10-10-no-gate-stands-while-reading-nothing, when every nextest invocation of the workflow began to fail on a selection that matches no test), `cargo xtask perf:budget --data-dir target/tmp/perf-budget-samples --require memory,snapshot`, and an `if: always()` `logs-perf-samples-{os}` upload) · `mcp-test` (nextest with `--features mcp-server`) · `a11y` (`cargo xtask test:a11y`) · `boot` (the mcp-feature release build → `Build the exit witness`, where `cc` builds `scripts/exit-witness.c` into `$RUNNER_TEMP` and names it through `$GITHUB_ENV` as `ANDROMEDA_PULSE_EXIT_WITNESS_LIB` → the agent-harness boot smoke, its lines unchanged → `Boot series (equal source)`, a plain `run: cargo xtask harness:boot-series --count 7` under `if: always()` with no soft-fail key → `cargo xtask ci-gates`; since chunk 2026-10-10-boot-smoke-s-self-end-named-from-a-run one run of the job reads eight boots, a boot that ended by itself fails the job — its settle verdict reads `ended`, or, since chunk 2026-10-10-boot-smoke-s-self-end-closed, it took no settle verdict and its exit record is an end the app made itself (any record but the boot verb's own `signal 15 (TERM)` / `signal 9 (KILL)`) — `ci-gates` is skipped when the smoke or the series fails and the upload still runs; the two steps are pinned by three workflow tests in `pulse-app/tests/quality_gate_workflow.rs`. As measured on `ci#38026637514` (pull_request, the pushed tip `4e61553b`, the merge commit `69c81cb339a9`): success on attempts 1, 2 and 3 — attempt 1 all six jobs, attempts 2 and 3 the `boot` job alone — each attempt 8 of 8 boots settled and `boot-series.json` `all-settled` with `settled` 7; 24 boots, 0 self-ended. The series stays a gating step, and a self-end in it is a new reading to bring to the operator, not an expected red) · `supply-chain` (`cargo audit` as a plain `run:` step since chunk 2026-10-09-supply-chain-job-same-on-push-and-pull-request — no action, no token, nothing published, so it ends the same on a pull-request run and on a push run; exit 0 clean · 1 a vulnerability · 2 could not evaluate, on the runner image's own `cargo-audit`, which no step installs; pinned by the self-lint test `ci_workflow_audit_step_is_a_plain_run_step`; its `cargo auditable build --workspace --release` is a release-build smoke) · `coverage`. The trigger block (`pull_request`, and `push` on `main`) is pinned as it stands by `ci_workflow_triggers_are_pull_request_and_push_on_main`. A `pull_request` run builds the pull request's merge ref, not the pushed tip: as measured on `ci#37979648967`, the boot job fetched and checked out `refs/remotes/pull/40/merge` — `88d5ed30`, whose parents are `main`'s tip `178ebac5` and the pushed tip `e2931127` — so every pull-request reading of a build branch is a reading of that branch merged with `main`, its log's `git.commit.sha` names the merge commit, and "equal source" across such runs means the branch tip AND `main`'s tip both unchanged. On that run the merged tree was equal to the pushed tip's (0 files differ), which holds only while `main` holds nothing the branch lacks (chunk 2026-10-09-boot-smoke-s-early-exit-found-and-closed). No CI job compiles or tests on Windows or macOS since chunk 2026-10-09-ci-on-linux-alone: the three-system matrices of `lint-test` and `a11y` and the macOS/Windows `release` job left, and the frame budget stays the dev-host `perf:frame-sample`. The workspace release build keeps two CI witnesses, `supply-chain`'s `cargo auditable build --workspace --release` and `boot`'s `cargo build --workspace --release --features mcp-server`, pinned by the self-lint test `ci_workflow_keeps_the_linux_release_build_witnesses`; `ci_workflow_runs_on_linux_only` pins that the workflow names no other system, matrix value or system condition. - `release.yml` runs on tag push (`v*`): `tauri-action` builds `.msi` / `.dmg` / `.AppImage` / `.deb` per OS in matrix (macOS `.app` bundle is built then wrapped into `.dmg`, not published standalone); signs Windows artifacts via Azure Key Vault EV cert; notarizes macOS artifacts via Apple Developer ID; uploads bundles + `latest.json` to GitHub Releases.
- `update-channels.yml` runs on completion of `release.yml`: updates Homebrew tap and Scoop manifest with new version + sha256.
- All shared CI logic that needs Rust lives in the `xtask` crate so contributors can run identical commands locally with `cargo xtask <task>`.
