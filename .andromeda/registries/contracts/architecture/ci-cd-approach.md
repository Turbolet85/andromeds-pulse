**CI/CD approach.**
- Platform: GitHub Actions.
- `ci.yml` runs on every PR and push to main as six independent jobs, each on `ubuntu-22.04` with no matrix and no `needs:` edge, so a round lasts as long as its longest job: `lint-test` (`cargo fmt --check` → `cargo clippy ... -D warnings` → the xtask gates → `cargo xtask test`, then `perf:slo-load`, `cargo nextest run --workspace --profile perf-samples` (the `pulse-app/tests/perf_budget_samples.rs` producer, excluded from the default nextest filter), `cargo xtask perf:budget --data-dir target/tmp/perf-budget-samples --require memory,snapshot`, and an `if: always()` `logs-perf-samples-{os}` upload) · `mcp-test` (nextest with `--features mcp-server`) · `a11y` (`cargo xtask test:a11y`) · `boot` (the mcp-feature release build, the agent-harness boot smoke, then `cargo xtask ci-gates`) · `supply-chain` (its `cargo auditable build --workspace --release` is a release-build smoke) · `coverage`. No CI job compiles or tests on Windows or macOS since chunk 2026-10-09-ci-on-linux-alone: the three-system matrices of `lint-test` and `a11y` and the macOS/Windows `release` job left, and the frame budget stays the dev-host `perf:frame-sample`. The workspace release build keeps two CI witnesses, `supply-chain`'s `cargo auditable build --workspace --release` and `boot`'s `cargo build --workspace --release --features mcp-server`, pinned by the self-lint test `ci_workflow_keeps_the_linux_release_build_witnesses`; `ci_workflow_runs_on_linux_only` pins that the workflow names no other system, matrix value or system condition. Rust caches are budgeted against the 10 GB repository cap: `lint-test` and `boot` own target caches keyed `lint-test-{os}` / `boot-Linux` and save on failure too; `mcp-test` and `a11y` restore `lint-test-{os}` read-only and `supply-chain` restores `boot-Linux` read-only; `coverage` caches the registry only (chunk 2026-09-29-ci-wall-time-and-round-trips). `{os}` resolves to `Linux` alone, and no job writes `release-{os}` or a Windows or macOS `lint-test-{os}` key any more. - `release.yml` runs on tag push (`v*`): `tauri-action` builds `.msi` / `.dmg` / `.AppImage` / `.deb` per OS in matrix (macOS `.app` bundle is built then wrapped into `.dmg`, not published standalone); signs Windows artifacts via Azure Key Vault EV cert; notarizes macOS artifacts via Apple Developer ID; uploads bundles + `latest.json` to GitHub Releases.
- `update-channels.yml` runs on completion of `release.yml`: updates Homebrew tap and Scoop manifest with new version + sha256.
- All shared CI logic that needs Rust lives in the `xtask` crate so contributors can run identical commands locally with `cargo xtask <task>`.
