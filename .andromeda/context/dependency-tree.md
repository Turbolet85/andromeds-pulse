## Planned dependency edges

Per arch §Cross-cutting Patterns Module dependency direction: dependencies in `Cargo.toml` flow toward the `pulse-app` binary; no library crate depends on the binary crate; no library crate depends on a sibling unless its declared contract requires it. The dependency graph forms a DAG with `pulse-app` as the only root.

Anticipated edges (to be confirmed at first reconcile from actual `Cargo.toml`):

- `pulse-app` → `ingest` / `buffer` / `viz` / `ui-bridge` / `snapshot` / `workspace-detector` / `plugins` / `mcp-server` (binary composes all library crates)
- `ingest` → `buffer` (mpsc hand-off; ingest decodes OTLP and feeds buffer's Arrow appender per arch §Established Decisions [In-Process Channel Architecture])
- `viz` → `buffer` (query layer reads buffer state)
- `snapshot` → `buffer` (curation pipeline reads buffer rows for dedupe / aggregation)
- `mcp-server` → `viz` + `snapshot` (MCP tool methods share the curation pipeline + query API per obs plan §3 Snapshot/paste-to-AI integration)
- `ui-bridge` → all router-providing crates (ingest / buffer / viz / snapshot / workspace-detector / plugins / mcp-server) for TauRPC procedure registration
- `xtask` → workspace metadata only (no runtime deps on library crates)
