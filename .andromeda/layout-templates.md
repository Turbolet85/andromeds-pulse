## Surface: desktop-webview

**Tooling context:** Framework React 19.x (Vite + TanStack Router), CSS Tailwind CSS v4.x, Components shadcn/ui (Radix UI primitives + Tailwind).

**Expression level (this surface):** 0.35 (skeleton pulsing, panel transitions, form state confirmation, command-palette emergence). Halo State Pulse (WebGPU shader-driven) is exempt from chrome budget per design-system Motion.

**Signature placement:** "Halo State Pulse" animates in two distinct contexts on desktop-webview:
1. **Full dashboard constellation map** — WebGPU canvas layer renders per-service halo dots pulsing at the design-system frequency range (throughput-driven) with hue interpolation `color-primary` → `color-accent` based on error rate. Blur radius span per the Brand Identity signature spec.
2. **Compact widget aggregated badge** — single unified halo circles the service-count badge in the bottom-right quadrant of the canvas, encoding aggregated service health and ingest volume.

### Primary screens

- **Compact widget** — quarter-screen glance surface (always-on, snap-to-edge, custom frameless titlebar). Displays aggregated Halo State Pulse badge + read-only metadata footer (ingest rate, retention used, error %).
- **Full dashboard (Traces view)** — expanded window; constellation service map with per-service Halo State Pulse; table of trace samples below.
- **Full dashboard (Metrics view)** — time-series overlay for throughput + latency; same header/nav structure as Traces.
- **Full dashboard (Logs view)** — log record table with severity color-coding; same header/nav structure.
- **Full dashboard (Snapshots view)** — list of generated snapshots with timestamp, token count, and view/copy actions. Snapshots are generated via the TauRPC `snapshot.generate` command; the snapshot-detail viewer layout (modal vs. full-page) is deferred to the implementation route.
- **Settings panel** — theme (dark/light/auto), widget snap position, retention duration, MCP server toggle (when feature is built).

### Component — Custom titlebar (desktop-webview specific)

**Layout:**
- Flex row, `height: space-lg`, `padding: 0 space-sm`, `gap: space-sm`.
- Background: `color-base`.
- Drag region: full width except buttons (Tauri 2 `data-tauri-drag-region` attribute on titlebar container).
- Flex segments: `[app-icon + title | grow | settings-button | window-controls]`.

**Components:**
- **App icon:** small custom glyph (aperture or constellation-grid), `color-primary`, clickable → focus main window.
- **Title:** `font-label` weight, `color-text-primary`, `"andromeda-pulse"` (compact widget) or `"andromeda-pulse — {view}"` (full dashboard).
- **Settings button:** aperture glyph icon, `color-text-secondary`, hover → `color-text-primary` over `duration-fast` ease-out, click → Settings modal.
- **Window controls (Windows / Linux):** three buttons (minimize, maximize, close) on the right side; `color-text-secondary`, hover state darkens background to `color-raised-2`. macOS uses traffic-light buttons (red, yellow, green) on the left side via the OS chrome convention.

**Border:** bottom 1px subtle border (`Border Progression Subtle` token).

### Component — Halo State Pulse canvas (hero / signature)

**Layout:**
- Container: `position: relative`, `width: 100%`, `height: 100%` (compact widget) or fixed hero height (full dashboard).
- Background: `color-inset`.
- Border: 1px subtle border with `radius-md`.
- Padding: `space-md`.
- `<canvas>` element fills the container; `devicePixelRatio` scaling is handled by React + the browser.

**Canvas rendering (WebGPU):**
- Render loop at 60 FPS via `requestAnimationFrame`.
- For each service in the constellation (from `traces.query` result):
  - Render a service dot at the constellation position (computed from service topology via the viz crate).
  - Overlay a circular halo glow (WebGPU fragment shader) implementing the Brand Identity signature spec: pulse frequency clamped from `throughput_hz / 1000`, blur radius envelope per pulse cycle, hue LCH-interpolated from `color-primary` (Earth Blue) → `color-accent` (Alert Burgundy) based on error rate, opacity envelope per pulse cycle.
- **Fallback (if WebGPU unavailable):** the `<canvas>` shows a `font-body` message in `color-text-tertiary` ("WebGPU not supported in this context").
- **Reduced motion (`prefers-reduced-motion: reduce`):** the halo becomes a static glow (no pulsing rhythm), but hue still updates per error rate. Per design-system Motion accessibility section.

**Signature element details:**
- On compact widget: a unified single halo around an aggregated badge (e.g., "24 services, avg 1.2% error").
- On full dashboard Traces view: per-service halos on each constellation dot.
- Motion is data-driven (not decorative) — throughput directly controls pulse frequency, error rate directly controls hue.

### Component — Trace data table (primary content block)

**Layout:**
- Grid: shadcn `Table` component (thead + tbody + rows).
- Header row: `background: color-base`, `color: color-text-primary`, `font-weight: 600`, `font: font-label`.
- Data rows: transparent background (parent surface shows through); 1px bottom border subtle.
- Padding: each cell `padding: space-sm`.
- Hover state: row background fades to `color-primary` at 10% opacity — no transition (instant per `0.35` expression).

**Columns (sample):**
- **Trace ID:** `font-code` monospace, `color-text-primary`, selectable for copy.
- **Service:** `font-body`, `color-text-primary`.
- **Latency:** `font-data` (monospace tabular numerals), `color-text-secondary`, right-aligned.
- **Error:** `font-label`, status glyph (✓ in `color-feedback-success`, ✗ in `color-accent`).

**Sorting:** column headers clickable; click cycles through ascending → descending → unsorted (visual feedback: text bold, small caret in `color-primary`). The default (unsorted) order is anomaly-first — erroring rows hoisted to the top (P-068).

**Filter toolbar (above the table):** a right-aligned `Errors only` toggle (`aria-pressed`) sits in its own toolbar row directly above the table, narrowing to `error_count > 0` rows; the constellation hero + this toolbar stay fixed above the scrolling table (P-068 / P-082).

**Internal scroll region:** the table sits in its own bounded scroll region (`flex:1 / min-height:0 / overflow-y:auto`, custom scrollbar per §Anti-Patterns Per-Surface Bans) with a **sticky opaque `color-base` thead**, so rows scroll internally while the hero + toolbar + header stay fixed and the dashboard never grows an outer page scrollbar — the route is bounded to the shell's `main` height (P-082).

**Pagination / virtualization:** TBD by downstream; the table's own scroll region (above) handles overflow, and the telescope-icon "investigate" action triggers a detail view (not in-table inline expansion).

### Component — Empty / error state (desktop-webview data views)

**Applies to:** the Metrics / Logs / Snapshots data views — rendered in the primary content region in place of the chart / table / list when there is no data or a query fails. A single shared `EmptyState` component backs all three so the data views read as one system.

**Layout:** centered column in the primary content region — a decorative Observatory glyph (telescope, 24px, `aria-hidden`) above a message (`font-body` 14px) and an optional actionable hint; `gap: space-sm`, `padding: space-xl`. No focusable element (read-only, affordance-exempt).

**Empty (no data):** message + hint in `color-text-secondary` (a11y SC 1.4.3 — body-size text needs ≥4.5:1; NOT `color-text-tertiary`, 4.2:1 large-text-only). The hint names the OTLP receiver ports (`:4318` / `:4317`, in `font-code`) — e.g. "No metrics received yet" / "Point an OTLP metrics exporter at :4318 / :4317". Shown only on a settled zero-data load (never flashed while loading; hidden once populated).

**Error (query failure):** a distinct variant checked BEFORE the empty branch — a static message ("Couldn't load {metrics|logs}", never the raw `AppError`) with NO exporter hint, so a failure never masquerades as "no data". `color-text-secondary`; `color-accent` (Alert Burgundy) remains available for an optional error icon / border per the "never color alone" discipline.

## Surface: desktop-native

**Tooling context:** Framework Tauri 2.x (native window management, tray via `tauri-plugin-notification`, custom menu via Tauri's menu builder). OS-native UI (no React webview at this surface).

**Expression level (this surface):** 0.2 (minimal motion — icon state changes, traffic-light color transitions, badge emergence only). Tray menu is OS-native; no custom chrome animation.

**Signature placement:** "Halo State Pulse" renders as a unified animated glow around the aggregated service-count badge in the tray icon area:
1. **Tray icon glyph** — monochrome SVG template image (platform-dependent size). Shape: a stylized constellation star or pulsar with a circular outline (aperture metaphor). The OS handles template-image tinting.
2. **Halo State Pulse (secondary composited layer)** — WebGPU canvas in a small click-through overlay window positioned behind / around the tray icon glyph, rendering the unified halo per the Brand Identity spec. SVG-filter fallback substitutes when WebGPU is unavailable in the tray context, honoring the visual equivalence criteria from design-system Surface: desktop-native (blur radius envelope, LCH fidelity ≥95%, opacity envelope).

### Primary screens

- **Tray icon** — always-visible status glyph with Halo State Pulse (unified badge encoding aggregated service health and ingest volume).
- **Tray menu** — flat hierarchy menu triggered by right-click on the tray icon. Actions: open / focus main window, generate snapshot, toggle MCP server (when feature is built), open settings, quit.
- **Notifications (OS-native)** — toasts fired on snapshot generation completion, MCP server state changes, updater state transitions, and the first window-close-to-tray signpost (P-063).

### Component — Tray icon (desktop-native specific)

**Design:**
- Single monochrome SVG glyph (aperture or constellation-star motif). Platform size conventions are honored automatically by the OS tray API.
- Color on macOS: template-image flag set, OS auto-tints to menu-bar color (typically white on dark, black on light).
- Color on Windows / Linux: SVG fill defaults to `color-text-primary`; system tint is applied where the platform's tray protocol supports it.

**SVG construction:**
- ViewBox sized for crisp rendering at small platform sizes.
- Simple line-based design (no complex fills, all strokes) for clarity at small sizes:
  - Outer circle (stroke 1px).
  - Inner star or aperture cross (4–6 strokes forming a simple glyph).
  - No gradients, no shadows, no embellishment.

**Halo State Pulse (secondary layer):**
- **Option A (WebGPU, preferred):** a separate transparent, click-through, always-on-top window hosting a small `<canvas>` element rendering the Halo State Pulse via the same WebGPU shader used on desktop-webview. Pulsing frequency, blur radius envelope, LCH hue shift, and opacity envelope all per the Brand Identity signature spec. Positioned to overlap the tray icon glyph (platform-specific positioning via Tauri 2 window APIs).
- **Option B (SVG-filter fallback):** inline SVG with CSS `filter: blur(...)` and CSS animations matching the WebGPU output. Hue shift via `<feColorMatrix>` interpolating between `color-primary` and `color-accent` per error rate. Visual equivalence ≥95% per design-system Surface: desktop-native criteria.

**State variants:**
- **Healthy (low error rate):** halo glows `color-primary`, pulsing smoothly at throughput frequency.
- **Degraded:** halo shifts toward an intermediate LCH hue, pulsing rate increases with error magnitude.
- **Unhealthy (high error rate):** halo glows `color-accent`, pulsing at the maximum clamped frequency — urgent visual signal without visual noise.
- **Silent (zero throughput):** halo dims to the low end of the opacity envelope, pulsing rate drops to the minimum (a faint, ambient signal).

**Reduced motion (`prefers-reduced-motion: reduce`):** halo becomes a static glow (no pulsing animation), but hue still updates per error rate.

### Component — Notifications (OS-native)

**Trigger events:**
1. Snapshot generation completion (via `snapshot.generate` TauRPC command).
2. MCP server status change (start / stop, when feature is built).
3. Update available (Tauri updater plugin fires the notification when a new release is detected).
4. First window-close to tray (the predictable-close signpost): fires ONCE per session on the first window-close (compact widget or dashboard) that minimizes to the tray, when `notifications_enabled` is true — a clear "still running in the tray — right-click the tray icon to quit" indication so close→hide-to-tray is predictable (P-063, intent F3).

**Notification format:**
- Title: terse (1–2 words). Examples: "Snapshot ready", "MCP Server started", "Update available".
- Body: 2 lines max, descriptive but compact. Examples: "2.5k tokens, 42 spans", "Ready to accept Claude Code connections".
- Icon: app icon at the OS-conventional notification size.
- Action button (when OS supports): "View" (opens snapshot viewer in app) or "Copy to Clipboard" (direct action without opening app).

**Implementation:**
- Via Tauri 2 `tauri-plugin-notification` (native Notification Center on macOS, Action Center on Windows, freedesktop notifications on Linux).
- User opt-out: `notifications_enabled` boolean in `~/.andromeda-pulse/config.toml` (default true). When disabled, snapshot generation and updater still complete but suppress the toast.

**Reduced motion:** notification emergence is instant (no fade-in animation per the `0.2` expression level).

### IA notes

**Navigation model (tray surface only):**
- Single entry point: tray icon click (left-click) focuses / restores the compact widget; right-click opens the menu.
- Menu actions are limited to "open app", "generate snapshot", "toggle MCP", "open settings", "quit". Deep navigation into app views (Traces, Metrics, etc.) happens inside the app window, not via the tray menu.

**Keyboard shortcuts (tray level):**
- Tray menu: arrow keys navigate, Return selects, Escape closes. No global hotkeys at the tray level (e.g., `Ctrl+Shift+P` does NOT toggle tray menu visibility).

**Cross-surface coordination:**
- Tray icon Halo State Pulse and compact widget Halo State Pulse are fed by the same real-time data stream (`pulse://stream/spans` broadcast channel). Visual consistency is maintained: both render the unified halo at the same frequency and hue.
- Full dashboard Traces view renders per-service halos (separate from the tray's unified halo), but all three surfaces share the same Halo State Pulse shader logic (frequency clamping, LCH interpolation).

**Platform-specific notes:**

**macOS:**
- Tray icon uses the `NSStatusItem` API; the template-image flag makes the SVG scale and tint automatically.
- Menu uses `NSMenu` + `NSMenuItem`; standard platform look-and-feel.
- Button ordering (when a confirmation dialog appears): Cancel left, Confirm right.
- Notification Center integration via `NSUserNotification` / `UNNotificationCenter`.
- Cmd+Q to quit is respected by Tauri 2 by default.

**Windows:**
- Tray icon uses the `NotifyIcon` API; high-DPI support required (125%, 150%, 200% via `devicePixelRatio` scaling or multi-resolution SVG).
- Menu uses `ContextMenuStrip`; system look-and-feel.
- Button ordering (when a confirmation dialog appears): Confirm left, Cancel right.
- Action Center integration via Windows Toast.

**Linux:**
- Tray icon uses AppIndicator or StatusNotifier protocol (Tauri 2 abstracts both).
- Menu uses GTK+ menu integration; respects system theme (light / dark adaptation).
- Button ordering (when a confirmation dialog appears): standard Linux convention.
- Notification support via freedesktop notifications (`libnotify`).
- XDG desktop integration for autostart (TBD by downstream if Settings includes a "Launch on startup" toggle).
- Support both X11 and Wayland tray protocols (Tauri 2 handles fallback automatically).
