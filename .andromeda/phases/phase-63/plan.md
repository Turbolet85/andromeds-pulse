## Combined goal

Implement the L1b service identity formal lifecycle layer (capability P-027 — Service Constellation Auto-Discovery, formal lifecycle) as the final chunk of Epoch 9 Foundation v0.2.0. The chunk introduces a 7-state per-service finite state machine (Unknown → Bootstrapping → Active → Quiet → Silent → Dormant → Archived) in a new internal submodule `crates/triage/src/lifecycle/`, with transitions driven by inputs from chunk #61 baseline trackers (per-service activity via `BaselineState`/`RollingWindow`) and chunk #63 restart detector (restart events feed Bootstrapping transition). Configurable thresholds (`dormant_after_secs` default 3600 / `archived_after_secs` default 86400) flow through the existing `Settings` struct extension path (per security.md Session Additions 2026-05-09 lower-cost pattern). Per-service registry state lives in-memory via `DashMap<String, ServiceRegistryEntry>` mirroring chunk #61 `BaselineState` precedent — the v0.2.0-plan §68 reference to a DuckDB `service_registry` schema table is dropped per arch §Established Decisions [Telemetry Retention Surface] guardrail (OTLP-spec entities only). State transitions emit on the new `pulse://stream/service-lifecycle` broadcast topic via `ServiceLifecycleBroadcast` (mirrors chunk #63 `RestartEventBroadcast` pattern). The new `services.list_with_states` TauRPC procedure (located in `pulse-app/src/services_router.rs` per chunk #59 `connection_router.rs` precedent) exposes per-service state to the webview. The Settings → Services manual-override UI pane is **deferred to a follow-up chunk** (per chunk #43 → #44 substrate-then-UI precedent); the backend support for manual overrides (per-service `manual_override: Option<ServiceLifecycleState>` storage + Settings field for threshold knobs) lands in this chunk so the follow-up UI chunk has a TauRPC + state surface ready.

The chunk follows the quadruple-binding discipline for new TauRPC namespaces (router registration + `EXPECTED_PROCEDURES` extension + `emit_taurpc_bindings` test merge — capability JSON requires no edit per router-level coverage) and the per-target AllowList registration pattern for 6 new tracing targets (`triage.lifecycle.{tick, transition, corpus_restore}`, `services.list_with_states.request`, `pipeline.l1b.tracked_services_total`, `metric.triage.lifecycle.state_distribution`) per `.claude/rules/observability.md` Session Addition 2026-05-17 session 84 tighter aggregate-only convention.
