## Open questions

- **Q1: Should the placeholder IPC live in `crates/snapshot/src/ipc.rs` (snapshot crate owns the router) or `crates/ui-bridge/src/snapshot_ipc.rs` (ui-bridge centralizes routers)?** — Reading ui-bridge's existing routers (introspection / settings / telemetry) suggests ui-bridge centralizes IPC for cross-cutting envelope concerns. But arch §Occupied Resources reserves `snapshot.*` for the `snapshot` crate, and the telemetry pattern shows per-crate routers are acceptable. **Recommendation:** snapshot crate owns the router (`crates/snapshot/src/ipc.rs`) per arch §Conventions Workspace API style + arch §Occupied Resources crate ownership; ui-bridge merges via `pulse-app/src/main.rs`. Verify against the consumer expectations at /implement Phase 1 review.

- **Q2: Trigger button placement on compact widget — titlebar icon button or canvas overlay?** — Layouts extract: "actionable element belongs in the titlebar segment or context-menu surface"; CompactWidget.tsx current comment: "the titlebar gear remains the only tab stop" — so titlebar gear is precedent. **Recommendation:** titlebar icon button next to settings gear (mirroring Titlebar.tsx onSettingsClick pattern). Canvas overlay rejected because canvas is dedicated to Halo Pulse + aggregated badge (chunk #32 spec) and the IA notes call out "minimalist chrome".

- **Q3: Should TraceTable rows get a 5th column "Action" with inline Investigate icon-button, OR should the inline trigger live within the existing rightmost cell?** — Layouts extract: "Trace-row click and dedicated Investigate-button click both route to the same Investigation modal (no in-table inline expansion)". The inline button needs visual presence. **Recommendation:** add a 5th column "Action" with header `aria-label="Investigate action"` and an InvestigateButton icon-button per row. This keeps the existing 4 columns visually clean and gives the inline trigger a discoverable position. Confirm with user at Phase 6 if 5-column expansion is acceptable, OR collapse into the existing 4-column header row (with action button at end of "Error" cell).

- **Q4: Should the supporting-moment animation live in InvestigationModalForm's open state OR in InvestigateButton's click feedback?** — Design extract: "Capture Collapse motion MUST render as centered snapshot object (modal at viewport center), scale + opacity ease-out"; layouts: "Investigation Capture Collapse motion MUST render as a centered snapshot object (modal at viewport center)". **Recommendation:** modal-level animation. The button click triggers modal open; the modal mount transition IS the supporting moment (scale from 0.95 to 1.0, opacity 0 to 1, over 350ms). The button itself gets only its standard hover/focus transitions (150ms ease-out). InvestigateButton handles aria-busy display during the IPC call; Modal handles the supporting-moment animation via CSS transform + opacity on initial mount.

- **Q5: How does the use-investigation context coordinate across compact widget vs main dashboard windows?** — Tauri 2 webview labels split via `useWindowLabel` (chunk #32 hook); InvestigationProvider lives PER WINDOW (each webview has its own React tree). The snapshot.generate IPC is global (one stub for both), but the modal/trigger pair is per-window. **Recommendation:** InvestigationProvider rendered in App.tsx within each window branch (CompactWidget vs Dashboard), so each window's triggers and modal coordinate independently. Both end up calling the same TauRPC snapshot.generate stub.
