## Implementation notes

- **Order matters within step 1 + 2:** install `motion@12.x` first (`npm install`) so `motion/react` resolves; then create the hook re-export file. If hook file is created first, `tsc --noEmit` will fail with `Cannot find module 'motion/react'`. The /implement should `cd pulse-app/ui && npm install motion@^12.0.0` (or hand-edit package.json then `npm install`) before writing `use-reduced-motion.ts`.
- **`mock-reduced-motion.ts` must NOT match Vitest test-discovery glob** — keep filename `mock-reduced-motion.ts` (no `.test.` segment) so Vitest treats it as a helper module, not a test file. Verified against `vitest.config.mjs` `include: ["src/**/*.{test,spec}.{ts,tsx}"]`.
- **Avoid `Object.defineProperty(window, 'matchMedia', { ... })` in test-setup.ts** — assigning directly via `window.matchMedia = vi.fn(...)` is sufficient under jsdom; `defineProperty` adds noise without benefit. The helper `mockReducedMotion(value)` does the actual flip per-test.
- **Do NOT import `motion/react` `<motion.div>` or animation primitives** — only `useReducedMotion` named import. If the implement agent reaches for `motion.div` to test the hook, redirect to a plain `<div className="...">` + `renderHook` from `@testing-library/react` 16 instead.
- **`createFrameLoop` should not register a `resize` listener** — the loop is a pure rAF tick scheduler; window resize handling lives in the eventual WebGPU canvas integration (chunk #25). Keep the scaffold minimal; do not gold-plate.
- **Static-paint pattern for reduced-motion**: when `prefersReducedMotion: true`, `start()` invokes `onReducedMotionFrame?.(performance.now())` exactly once and does NOT schedule subsequent rAF — this matches design constraint "frequency Hz → 0 + blur radius → fixed midpoint" (a single static draw, not a paused but live loop). Consumers in chunks #25 / #28 may re-call `start()` if they need to repaint after data updates (e.g., LCH hue change per error rate); the contract is "reduced-motion = no rhythm envelope, but consumer-driven repaints permitted for hue updates" per layouts §Decisions Log "data-driven, not decorative".
