## Conventions to follow

- **GitHub Action SHA-pin format**: `<owner>/<repo>@<40-char-SHA> # vX.Y.Z` (per ci.yml precedent). Provenance comment is the version tag corresponding к the SHA. NEVER `@v2` / `@latest` / branch reference.
- **Workflow-level `permissions: { contents: read }`** (ci.yml:8-9). Per-job elevation к `write` only on the upload-к-releases step. Workflows publishing к releases set permission scope of `contents: write` (NOT `pull-requests: write` — different surface).
- **Conventional commits**: `feat(release):` / `chore(release):` per session-handoff git log examples + project commit style.
- **YAML formatting**: 2-space indent, `name:` first key per job / step, `runs-on` early, `steps:` block last. Match ci.yml stylistic conventions.
- **Runbook YAML / shell snippets**: use PowerShell for Windows-specific commands (per existing runbooks) + bash for Linux-specific; `gh api` / `gh secret set --env <env>` for GitHub Environment manipulation.
