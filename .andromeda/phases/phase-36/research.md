## Conventions to follow

- **Module visibility:** new modules `pub(crate) mod dedupe;` / `pub(crate) mod anomaly;` / `pub(crate) mod critical_path;` declared in `crates/snapshot/src/lib.rs`. Public types (Error variants, `CurationOutput`, `AnomalyKind`, `AnomalyMarker`, `CriticalPathStep`) live in `crates/snapshot/src/contract.rs` (the existing single `pub` surface).
- **File naming:** `snake_case.rs`; type naming `UpperCamelCase`; function/variable naming `snake_case`; constant naming `SCREAMING_SNAKE_CASE` (e.g., `LATENCY_OUTLIER_Z_THRESHOLD: f64 = 3.0`).
- **Error variants carry typed scalar payloads only** — `Duration`, `usize`, `&'static str` kinds, span identifiers `[u8; 16]` / `[u8; 8]`, never `String` carrying OTLP attribute values (per security extract acceptance criterion). Reason strings MAY carry sanitized internal context but NEVER user-data attribute values.
- **Workspace dep usage:** `serde.workspace = true`, `tracing.workspace = true`, `chrono.workspace = true` in `Cargo.toml [dependencies]`; `rstest.workspace = true`, `proptest.workspace = true` in `[dev-dependencies]` (when added). Inherit `thiserror.workspace = true` already present.
- **Pre-bridge typing:** primitive function signatures use plain Rust types (`Vec<SpanRecord>`, `&[SpanRecord]`, `Vec<AnomalyMarker>`); no `taurpc::*` / `tauri::*` / `rmcp::*` imports. Cross-bridge `serde::Serialize + specta::Type` derives apply to public output structs in `contract.rs` so chunks #41/#43/#46 can re-export.
- **Tracing target naming:** `snapshot.curate.{operation}` — `snapshot.curate.dedup`, `snapshot.curate.anomaly_detect`, `snapshot.curate.critical_path_extract`. Span kind = "internal" implicit (no `rpc.system` field).
- **Sanitized tracing messages:** every `tracing::*!` invocation in curation primitives includes only count fields, time bounds, categorical labels — NEVER `service_name` directly from input attributes (use `service_count` if categorical), NEVER attribute key strings beyond bounded enums.
- **Determinism:** all curation outputs are deterministic — no `HashMap` iteration without sort-before-return; no `std::time::Instant::now()` or `chrono::Utc::now()` outside injectable clock helper; explicit time-range bounds passed in via input args.
- **Severity-descending output ordering** (per design extract acceptance criterion): anomaly markers and critical-path step lists are pre-sorted before return so chunk #41 markdown formatter can apply token-budget truncation predictably.

## Open questions

- **Q1: Buffer dependency vs in-memory inputs from caller** — Should `crates/snapshot` add `buffer.workspace = true` dependency (curation primitive queries the DuckDB ring buffer directly) OR keep zero sibling-crate deps (caller passes pre-fetched span/metric/log slices)? Arch extract notes "the latter preserves looser coupling and is consistent with the snapshot crate having zero current sibling dependencies"; tests extract notes "Most likely chunk #39 operates over span vectors already in memory"; design extract notes "data-driven, not chrome-driven" suggests deterministic input-driven primitives. **Recommended:** in-memory inputs via public `pub fn curate(spans: &[SpanRecord]) -> Result<CurationOutput, Error>`; caller (chunk #41 TauRPC `snapshot.generate`) does the buffer query and passes results in. Surface to user at Phase 6 if alternative preferred.
- **Q2: Module layout — flat sibling files vs umbrella `curate/` mod** — `src/dedupe.rs`/`src/anomaly.rs`/`src/critical_path.rs` (3 sibling files) vs `src/curate/{dedupe,anomaly,critical_path}.rs` (umbrella). **Recommended:** flat sibling files (matches `crates/ingest/` pattern: `state.rs`/`channel.rs`/`grpc.rs`/`http.rs` as siblings). Surface to user at Phase 6 if alternative preferred.
- **Q3: SnapshotPreset consumption at curation primitives layer** — Does `pub fn curate(...)` accept `SnapshotPreset` from `ui-bridge::contract` as a hint (anomaly aggressiveness / critical-path depth varies per preset), OR does it emit all anomalies and chunk #41 does the truncation? Arch extract notes "Chunk #39 primitives operate on inputs irrespective of budget; budget enforcement is chunk #41's job"; design extract notes "Curation primitives do NOT directly enforce the budget (that's chunk #41), but the SnapshotPreset enum value should be plumbed through curation's public API as a hint". **Recommended:** chunk #39 emits all anomalies in deterministic severity-descending order WITHOUT preset hint; chunk #41 (markdown formatter) applies token-budget truncation per `SnapshotPreset` mapping. Cleaner separation of concerns + no cross-crate dep snapshot → ui-bridge (which would invert the dependency direction). Surface to user at Phase 6 if alternative preferred.
- **Q4: Clock injection for any time-range gating** — anomaly detection (e.g., "spike vs prior 5-minute baseline") and critical-path windowing (e.g., "last 30 seconds only") may need a baseline timestamp comparison. Tests extract: "if any internal time gating is introduced, it MUST take an injected clock". **Recommended:** primitives accept explicit time-range as `(start_unix_nano: i64, end_unix_nano: i64)` parameters when needed; baseline-vs-current comparisons take both windows as input args; no internal `chrono::Utc::now()` call. Caller (chunk #41) computes the time bounds. Surface to user at Phase 6 if alternative preferred.
