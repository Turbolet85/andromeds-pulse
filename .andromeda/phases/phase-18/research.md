## Open questions

1. **Retention sweep cadence vs heartbeat tick cadence:** the obs extract says `buffer.tick` stays at 15s regardless of sweep cadence; sweep can run on its own interval. If sweep at `retention_seconds / 6` (e.g., every 100s for default 600s retention), eviction is gradual; if sweep at every tick (every 15s), eviction is finer-grained. Plan.md decision: recommend `tokio::time::interval(Duration::from_secs(retention_seconds.max(60) / 6))` — gives at least 10s cadence at minimum 60s retention floor, and 100s cadence at 600s default — tuneable without changing tick.
2. **`eviction_count_since_last_tick` delta tracking location:** `BufferState` (atomic) vs `HeartbeatState` (Mutex<u64>) vs in-emit-buffer-tick local closure. Recommendation: `HeartbeatState` slot since the delta is heartbeat-output-specific (other consumers of BufferState don't need it). Alternative: compute delta in `emit_buffer_tick` from `state.eviction_count - state.last_emitted_eviction_count` and atomically swap. Plan.md decision.
3. **`BufferConnectionStatus` widening:** enum widening (`InitFailed(String)` + `RetentionFailed(String)`) is cleaner; reason-string pattern matching is less invasive. Plan.md should pick one with rationale.
4. **`ANDROMEDA_PULSE_RETENTION_SECONDS` bounds:** security extract suggests `[60, 86400]`; arch extract suggests "default 300–600s range". The arch range is the *default* recommendation, not a *bound*. Plan.md should set explicit bounds (recommend `[60, 86400]` per security) and explicit fallback default (e.g., 600 — arch's upper-default).
5. **`metric.buffer.memory_bytes.rows_active` semantics:** is `rows_active` the row count post-sweep across all 7 tables (sum), or per-table? Per-table is high-cardinality (multiplies tick output by 7); sum is opaque but bounded. Recommendation: sum, matching `metric.buffer.memory_bytes.value` aggregate semantics.
6. **`memory_bytes` measurement source:** DuckDB exposes `pragma_database_size()` or `current_setting('memory_limit')` — but `pragma_database_size()` is the actual in-memory footprint. Plan.md decision: use `pragma_database_size()` post-sweep, store via `state.set_memory_bytes(value)`. Alternative is row-count × estimated-size-per-row (less accurate, simpler).
