## Combined goal

Wire the periodic retention sweep that holds the in-memory ring buffer to its bounded window. Chunk #20 shipped the static schema (`crates/buffer/src/schema.rs` 7 reserved tables) + the Arrow appender (`crates/buffer/src/appender.rs`) + the `BufferState` atomic counters (`record_eviction(n)`, `set_memory_bytes(n)` already present per research §state.rs). Chunk #21 closes the loop: a long-running `run_retention(...)` task issues `DELETE FROM <table> WHERE ts_unix_nano < ?` against each of the 7 reserved tables on a derived cadence; flips the `retention_window_active` flag once the first sweep completes; updates `eviction_count` + `memory_bytes` atomic counters; surfaces both new gauges in the existing `buffer.tick` heartbeat at the established 15s cadence (per obs-plan §3 + research §heartbeat.rs); emits two `metric.buffer.*` events per tick for SLO observability (`metric.buffer.memory_bytes` ≤ 512MB SLO + `metric.buffer.evicted_span_count`); and surfaces fatal retention failure as `subsystems.buffer.status = "retention_failed"` in the `health` IPC envelope (mirroring chunk #20's `init_failed` precedent per research §health.rs).

The chunk is single-domain (storage/buffer crate), backend-only — design / layouts / a11y all returned `## No domain coverage`. Cross-domain bindings are concentrated on security ↔ obs ↔ tests: prepared-statement DELETE only (security), `query_id` + `param_count` + `param_types` log envelope (obs Vector 5), tokio paused-clock determinism + chaos test for buffer overflow (tests). - **`heartbeat_payload` signature change** is a breaking API change for the buffer crate's public surface. Compile errors will surface in `pulse-app/src/heartbeat.rs::emit_buffer_tick` immediately — that's expected and fixed by Step 10. Update the `cargo public-api --simplified` baseline at wrap-session.
- **`pragma_database_size()` decision tradeoff:** the cheaper alternative is per-table SELECT COUNT(*) sum (7 single-column queries, no DuckDB internals exposure). `pragma_database_size()` returns the in-memory database size in bytes (closer to true `memory_bytes` semantic) but is DuckDB-specific. Recommendation for `/implement`: start with `pragma_database_size()` since the field name is `memory_bytes`; fall back to row-count-sum × estimated-bytes-per-row only if pragma proves unreliable in tests. Plan.md explicitly leaves this decision tunable.
- **`eviction_count_since_last_tick` initial-tick semantics:** at first tick (process start, no prior tick), `last_emitted_eviction_count = 0`, current `eviction_count = 0` → delta = 0. After first sweep evicts N rows but BEFORE second tick fires → next tick emits delta = N. Rolling delta semantics mean `eviction_count_since_last_tick` is roughly equivalent to "evictions per 15s window" once retention has been running >1 tick.
- **Boundary case: retention_seconds < 60.** The `retention_seconds.max(60) / 6` cadence formula yields 10s minimum sweep cadence. Step 8's `resolve_retention_seconds()` rejects `< 60` env values with `reject_reason = "out_of_range"` and falls back to 600 default — so the `< 60` branch of the cadence formula is unreachable in production. The `.max(60)` defensive minimum protects against future callers that bypass the env-var resolution.
- **Test isolation concern:** if tests run in parallel and the BufferState global static were used (it isn't — each test creates its own `Arc<BufferState>`), the `retention_window_active` AtomicBool would cross-contaminate. Verify: each test uses `let state = Arc::new(BufferState::new())` per-test (chunk #20 precedent, line 79 in state.rs and consumer.rs:113).
- **CI obs heartbeat-gap gate:** `xtask/ci/heartbeat-gap-check.sh` is referenced in obs-plan §10 but may not be implemented yet (per route this is post-Polish epoch). Plan.md does not enforce this gate as an acceptance criterion for chunk #21 — only the in-process `buffer.tick` cadence preservation is asserted.
