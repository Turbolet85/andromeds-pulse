## Combined goal

Close Epoch 2 by hardening the OTLP receivers added in chunks #16-#18 with two complementary controls: (a) a coarse-global + per-source-port `tower_governor` rate-limit middleware on both `:4317` (tonic 0.14) and `:4318` (axum 0.8) so a single rogue local OTLP producer cannot starve well-behaved producers, and (b) a `TryFrom<u16>`-based smart-port validator on the `ANDROMEDA_PULSE_OTLP_GRPC_PORT` / `ANDROMEDA_PULSE_OTLP_HTTP_PORT` env-var paths in `pulse-app/src/main.rs` that enforces the arch §Conventions "non-privileged-or-explicitly-allowed range" invariant. Both controls land entirely in the `ingest` crate + `pulse-app` binary; no new TauRPC procedures, no new capabilities/ JSON entry, no new env-var name (per arch §Occupied Resources). All emissions ride the existing `tracing` JSON sink with new bounded-cardinality target keys appended to `pulse-app/src/observability.rs::AllowList::production()` (per chunk #18 Vector-6 allowlist convention). The receivers continue to bind `127.0.0.1` only; the `no_non_loopback_bind_literals_in_ingest_src` grep gate from `crates/ingest/tests/grpc_loopback.rs` must remain green.

The work is small in surface but spans three crates (ingest / ui-bridge / pulse-app) and two test driver patterns (saturation/recovery + boundary `#[rstest]`), so it fits a single-chunk phase. Discovery during Phase 3 revealed that `IngestError::InvalidPort { value: String }` already exists in `crates/ingest/src/contract.rs` AND is already mapped by `From<IngestError> for AppError` to `AppError::Ingest { message: "invalid OTLP port configuration" }` — chunk #19 plumbs this existing variant through the `resolve_*_port` startup paths rather than introducing it.
