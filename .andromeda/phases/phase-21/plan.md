## Combined goal

Stand up the desktop-webview surface that every later UI chunk inherits: render the frameless main window with a custom 32px titlebar (drag region + platform-conditional window controls + aperture settings glyph), wire close→minimize-to-tray window-state policy, and emit platform-tagged boot spans (`app.boot.webview.init` / `app.boot.gpu.check` / `app.boot.tray.init`) with enumerated backend labels per obs §1 multi-platform-exporter-compat trigger. The shell honors the canonical CSP literal already pinned in `tauri.conf.json` (`worker-src 'self' blob:` for chunk #28's WebGPU compute), keeps `pulse:default` capability as the negative-default trust boundary (no `fs`/`shell`/`dialog`/`http` core API grants), and binds AppError as the only error shape crossing TauRPC. Frontend is the first React 19 + Tailwind v4 surface to consume the design tokens scaffolded in chunk #10 + the `useReducedMotion` hook from chunk #15 — semantic `<header>` landmark hosts the titlebar, native `<button>` window controls carry `aria-label`s, and the drag region is `aria-hidden` non-focusable so Tab sequence skips it. The chunk does NOT scaffold the `telemetry.frontend.record_*` TauRPC bridge (deferred to chunk #28/#29 web-vitals/WebGPU frame-timing landing), does NOT create the actual tray icon glyph or menu (deferred to chunk #32), and does NOT expose `pulse:updater` to webview JS — close-to-tray is internal Tauri window-state handling and requires no inbound capability widening.

## Implementation notes

- **Order sensitivity**: Apply Rust changes BEFORE frontend changes — the Rust `WindowEvent::CloseRequested` handler must be in place before `useWindowControls` (frontend) calls `getCurrentWindow().close()` and triggers the close-to-tray flow. If frontend lands first without the handler, `.close()` actually closes the window (no prevent_close) and the test surrogate fails.
- **Token mismatch surfacing**: design constraint says titlebar height 32px; layouts says `space-lg`; tokens.css `--spacing-lg = 24px`. This is a documented mismatch in design plan vs implementation tokens. Plan recommendation is option (c) hardcode 32px with comment; surface to user at Phase 6 review for explicit decision. If user picks (b), need a new `--space-titlebar = 32px` token in tokens.css.
- **Telemetry frontend bridge deferred**: obs extract suggested scaffolding `telemetry.frontend.record_*` TauRPC commands at chunk #24. Plan synthesis defers to chunk #28/#29 because (a) chunk #24 already touches many surfaces, (b) the bridge needs a real consumer (web-vitals / WebGPU frame timing) which is chunk #28-29 scope, (c) introducing a new `telemetry.*` TauRPC namespace risks the same D3 drift as `streams.*` (chunk #23). Documented as Open Question 1 in research.md.
- **Tray icon plumbing minimal**: chunk #24 emits `app.boot.tray.init` with detected `tray_api` enumerated label, but does NOT create the actual Tauri tray icon. The tray icon glyph + menu lands at chunk #32. The `tray.*` event targets are registered in AllowList now (proactive default-deny coverage) but are not emitted until chunk #32. Documented as Open Question 4 in research.md.
- **A11y plan silence on titlebar**: a11y plan is silent on the custom titlebar component. Plan derives requirements from §4 Button + §7 Landmark templates (semantic `<header>`, native `<button>`, `<main id="main-content">`). If /implement encounters mismatch (e.g., titlebar-specific focus order needs custom ARIA), surface as Trigger 4 dialogue rather than silent extension. Documented as Open Question 5 in research.md.
- **`compact-widget.resizable` flip**: tauri.conf.json currently has `resizable: false` on compact-widget but design constraint requires resizable. Plan flips this. If user prefers compact widget non-resizable for "always quarter-screen" rationale, surface at Phase 6 review.
- **Test discipline**: agent-driven scope only. Full GUI exercise of close→tray + cross-platform window-control rendering is DEFERRED to tauri-driver headful matrix at chunk #46 (test-plan §6 P5). Chunk #24 covers IPC-contract surrogate (Rust unit test on `handle_close_requested`).
