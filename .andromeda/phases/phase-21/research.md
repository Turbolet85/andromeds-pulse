## Patterns detected

- **TauRPC procedure trait pattern** (`pulse-app/src/streams.rs:11-16`): `#[taurpc::procedures(path = "streams")] pub trait StreamsApi { async fn name(...) -> Result<(), AppError>; }` paired with `#[taurpc::resolvers] impl StreamsApi for StreamsApiImpl`. Constructor `Impl::new(state)`. Methods that spawn long-lived tasks use `tokio::spawn(forward_loop(...))` and return `Ok(())` synchronously. Reusable for any new TauRPC trait chunk #24 might add (e.g., `telemetry.frontend.record_*`).
- **TauRPC merge into invoke router** (`pulse-app/src/main.rs:214-224`): `taurpc::Router::new().merge(HealthApiImpl.into_handler()).merge(...).merge(StreamsApiImpl::new(...).into_handler())`. Two arms: `Some(conn)` (full handler set including viz routers) vs `None` (degraded — health + streams only). Chunk #24's new TauRPC traits (if any) merge into the same router both arms.
- **Tauri builder setup closure** (`pulse-app/src/main.rs:226-348`): `tauri::Builder::default().plugin(updater).invoke_handler(invoke_router.into_handler()).setup(move |_app| { ... ; Ok(()) })`. The setup closure spawns ALL background work via `tauri::async_runtime::spawn(...)`. Window-related lifecycle hooks (e.g., `WindowEvent::CloseRequested`) would attach via `.on_window_event(...)` on the builder before `.run(...)`.
- **Observability init order** (`pulse-app/src/main.rs:170-173`): `let _guard = observability::init(&data_dir); record_start(); write_pid_file(&data_dir);` — runs BEFORE Tauri builder, so any boot-time `tracing::info!` is captured. The non-blocking writer guard MUST stay on stack for the lifetime of the program. New `app.boot.webview.init` / `app.boot.gpu.check` / `app.boot.tray.init` spans MUST emit AFTER this init (current pattern aligns with obs constraint).
- **AllowList per-target dotted naming** (`pulse-app/src/observability.rs:111-120`): `by_target.insert("ingest", [...])`. Session-additions 2026-05-05 documents that dotted field names like `"http.method"` / `"http.route"` work as exact-string keys; `for_target("app.boot.otlp.http.bind")` is its own registry entry, not a fallback to `app`. New chunk #24 targets become NEW separate entries.
- **PII-safe path logging via strict-path** (`pulse-app/src/main.rs:131-167`): `fs::canonicalize(data_dir)` + `canonical_run.starts_with(&canonical_data)` defense before write. `?path` debug-formats are kept (data_dir is project-controlled) while plugin-path basenames stay redacted in production targets per security plan §Logging Vector 2.
- **Co-located vitest test** (`pulse-app/ui/src/components/icons/Icon.test.tsx`): chunk #11 precedent for webview unit tests; tests live next to the source file. `pulse-app/ui/src/test-setup.ts` registers `afterEach(cleanup)`.
- **Frontend useReducedMotion hook** (`pulse-app/ui/src/hooks/use-reduced-motion.ts`): single canonical re-export of `motion/react`'s hook; all surfaces consume one import path.
- **Iconography registry consumption pattern**: `<Icon glyph="aperture" />` per `pulse-app/ui/src/components/icons/Icon.tsx` (chunk #11). Aperture glyph is the design-required settings button.
