## Implementation notes

- **Order matters at step 1.** Resolve Q1 (`opentelemetry-proto` 0.31 transitive `tonic` version) before writing any handler code — if the `gen-tonic` feature pulls `tonic 0.13`, the entire `crates/ingest/src/grpc.rs` import surface changes (vendored stubs use a different module path). - **Tonic 0.14 service trait surface check.** During step 3, verify the actual trait method signatures in tonic 0.14's `*ServiceServer::new(impl)` builder + `.max_decoding_message_size(usize)` method. The `8 * 1024 * 1024` literal MAY need to be `usize::try_from(8 * 1024 * 1024).unwrap()` depending on the exact signature — confirm at /implement time, not pre-judged here.
- **Bind status timing.** The `try_bind_and_serve` helper recommendation in step 8 is critical: `tonic::transport::Server::serve()` returns a future that resolves only when the server stops, so `Ok(())` from the future doesn't mean "server is bound" — it means "server has shut down." Split into a bind step (returns `tokio::net::TcpListener` or equivalent; on success → record `BindStatus::Ok`) and a serve step (consumes the listener; on permanent error → record `BindStatus::Failed(...)`). This is necessary so `xtask harness:status` can poll `health` immediately after boot and see `"otlp_grpc_receiver": "ok"`.
- **`health` envelope back-compat.** `HealthEnvelope` already has 6 subsystems including `otlp_grpc_receiver` — chunk #16 only modifies the value population path, NOT the schema shape. Frontend/test consumers see no schema change.
- **PII allowlist gotcha.** Per `.claude/rules/observability.md` Session Additions 2026-05-03: `for_target("ingest.grpc.export.request")` strip-suffix lookup must resolve to either the existing `ingest` key (if the visitor strips `.grpc.export.request` to leave `ingest`) OR a new dedicated `ingest.grpc.export.request` allowlist entry. **Verify at /implement time** how the existing strip logic handles deeper target paths — if it only strips trailing `.tick`, then add a new `ingest.grpc.export.request` key explicitly. If it traverses dots, the `ingest` key suffices.
- **Chunk #18 seam.** Step 3's `Result<DecodedBatch, IngestError>` boundary at the prost-decode site is the explicit forward-reference: chunk #18 will replace the placeholder decode with full invariant checks. Do not gold-plate the seam — leave a clear function boundary like `fn decode_export_request(req: ExportTraceServiceRequest) -> Result<DecodedBatch, IngestError>` so chunk #18 can edit only this function plus add the AppError::Ingest conversion.
- **No mpsc producer wiring this chunk.** Despite combined.md §Cross-domain binding "arch ↔ ingest channel chunk #18" mentioning the mpsc producer side as chunk #16's responsibility, the combined.md is consistent that mpsc-send happens at chunk #18 (post-invariants, AppError variant).
