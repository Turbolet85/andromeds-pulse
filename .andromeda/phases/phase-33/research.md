## Open questions

- **(Q1) Halo overlay technique on tray surface (HIGH-SCOPE)**: design + layouts plans both prescribe WebGPU canvas overlay (Option A) with SVG-filter fallback (Option B). But OS-native tray APIs (NSStatusItem / NotifyIcon / AppIndicator) are NOT WebGPU contexts — there is no canvas at the tray icon's screen position. Three pragmatic paths:
  - **Option A (true WebGPU overlay)**: spawn a Tauri webview window positioned over the tray icon's screen coordinates, transparent + click-through + always-on-top. Render WebGPU canvas with same WGSL shader as chunk #31. **Platform-specific complexity HIGH**: macOS NSWindow can be made click-through via `NSWindow.setIgnoresMouseEvents(true)`; Windows requires `WS_EX_LAYERED + WS_EX_TRANSPARENT`; Linux X11/Wayland varies. Determining tray icon screen coords is itself non-trivial across platforms. **Probably NOT achievable in one chunk**.
  - **Option B (SVG-filter fallback rendered into tray icon)**: render the Halo as part of the tray icon image itself via SVG `<feColorMatrix>` + CSS animation, then export PNG variants per state to `tray_icon.set_icon(image)`. CSS animation doesn't survive PNG export — need to swap pre-rendered PNGs at the pulse rate. **Equivalent to Option C below.**
  - **Option C (icon-swap with periodic update)**: pre-render or runtime-render N hue-shifted icon variants (e.g., 8 frames over a pulse cycle); periodic task reads broadcast state, computes target hue + frequency, calls `tray_icon.set_icon(variant)` at 100-300ms intervals. State communicated via icon hue + (separately) menu summary line. **Pragmatic; matches "≥95% LCH fidelity" criterion if variants are LCH-interpolated correctly.**
  - **Option D (defer Halo to follow-up chunk; static glyph only)**: chunk #36 ships static monochrome glyph + menu structure; Halo overlay deferred as a follow-up chunk after epoch 5 closes. Menu summary line still carries state.
  - **Recommendation**: Surface options A/C/D at Phase 6 review. Default toward **Option C** for chunk #36 scope (icon swap); **Option D** is acceptable opt-out if Halo overlay technique needs deeper design exploration.
