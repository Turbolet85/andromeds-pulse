## Open questions

- **Token-counting algorithm choice:** simple char-count heuristic (~ceil(byte_count/4)) chosen by default for chunk #41 to avoid new workspace dep. Real tokenizer (e.g., tiktoken-rs) would match GPT/Claude tokenization more accurately, but adds a transitive deps surface that chunk #40's "zero new deps" precedent + plan-level constraint argues against. Plan should call this out explicitly: chunk #41 ships char-count heuristic; future chunk MAY swap to a real tokenizer behind a feature flag. The proptest invariant `report.token_count <= budget.as_token_count()` is independent of tokenization algorithm — proptest only verifies the budget contract.
- **TokenBudget naming alignment vs `SnapshotPreset`:** ui-bridge ships `SnapshotPreset { Conservative, Balanced, Detailed }` (chunk #38). Sub-agents suggested various namings (`TenK/TwentyFiveK/FiftyK`, `Compact10k/Balanced25k/Generous50k`). Research recommends matching ui-bridge: `TokenBudget { Conservative, Balanced, Detailed }` for cross-readability. The numeric values align via `as_token_count()` (10_000 / 25_000 / 50_000). A future `From<SnapshotPreset> for TokenBudget` impl in ui-bridge will trivially map by variant name when chunk #43 wires `snapshot.generate`.
- **`FormatError → AppError` conversion deferred:** per session-handoff "chunk #41 stays pure-substrate" guidance, the `From<FormatError> for AppError` impl is NOT included in chunk #41. It lands at the chunk that wires the formatter into a TauRPC procedure (likely chunk #43 / `snapshot.generate`). When that lands, the conversion should map `BudgetExceeded` → `AppError::Validation { field: "token_budget", reason: <constant message> }` per security extract, and `AnchorEncodingFailed` → `AppError::Internal { message: <constant> }` matching the existing `From<SnapshotError> for AppError` discipline at `ui-bridge/src/contract.rs:321-349`. Acceptance criterion (security) is currently phrased as "verified by a fail-closed test where ... returns Err(AppError::Validation)" — for chunk #41 this is interpreted as "returns Err(FormatError::BudgetExceeded)" (the AppError translation lands later); plan acceptance criteria should be re-phrased to FormatError-level assertions.
