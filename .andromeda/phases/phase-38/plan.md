## Combined goal

Land a hierarchical markdown formatter as a pure-Rust algorithmic substrate inside the `snapshot` crate that consumes the `CurationOutput` produced by `curate()` (chunks #39 + #40 combined) and renders an observation-log markdown string sized to a 3-tier token budget (Conservative=10k / Balanced=25k default / Detailed=50k tokens). Smart truncation prioritizes anomaly evidence (latency outliers / error correlation / cardinality spikes from chunk #39's `detect_anomalies`) — when the budget binds, low-signal verbose attribute detail and aggregated percentile rows drop FIRST, anomalies survive last. Markdown structure follows a stable hierarchical shape (one H1 page title → H2 section bands → H3 per-service / per-anomaly subsections) so citation anchors remain stable across budget-preset re-runs. The formatter is a NEW PUBLIC CONSUMER that wraps `curate()`'s output rather than extending its body — per session-handoff Tier 3 entry "primitives EXTEND curate() vs new consumers WRAP its output". Per security plan §Logging & Monitoring, OTLP-derived attribute values are user-controlled content: every value interpolation goes through an escape helper backslash-escaping markdown structural characters and enforcing the 256-byte cap from chunk #40's `MAX_ATTRIBUTE_VALUE_BYTES`. Per obs-plan §3 + §10, the formatter emits two new tracing spans (`snapshot.render.markdown` + `snapshot.token.count.validate`) and one perf-budget metric event (`metric.snapshot.token_count_ms`) into the existing JSON file sink, all default-deny field-allowlisted at `pulse-app/src/observability.rs::AllowList::production()` mirroring chunk #40's `snapshot.curate.aggregate` precedent. Chunk stays pure-substrate: no new TauRPC procedure, no new env var, no AppError conversion — the eventual `snapshot.generate` IPC wiring lands at a later chunk and will reuse the same formatter substrate, as will chunk #46's MCP `generate_snapshot` tool method per arch §Established Decisions [MCP Server Surface].

   - `render_section_aggregation(buf: &mut String, agg: &AggregationResult)` — H2 "Service constellation summary" with per-service p50/p95/p99/max table; iteration order Alert-Burgundy-first (services with `status_code == 2 (Error)` from contract.rs:39 OR services tagged in any anomaly marker) then Earth-Blue (the rest), within each band BTreeMap-default alphabetical.
   - `render_section_unique_spans(buf: &mut String, spans: &[SpanRecord])` — H2 "Span detail" listing remaining unique spans with attributes (each attribute key + escaped value); LAST-priority truncation tier.
   - Truncation marker copy: `"_(N additional spans elided to honor {budget_label} token budget; anomaly-priority preserved)_"` (per design extract observation-log voice).
3. Implement smart-truncation algorithm in `format_markdown`:
   - Phase A (always emit): H1 title `# andromeda-pulse — Observation log {ISO-timestamp from curated.input_row_count derivation OR placeholder}` + H2 "Anomaly observations" (full content) + H2 "Critical path" (full content). These are the always-survive tier.
   - Phase B (drop verbose attribute detail before drop spans): emit `render_section_aggregation` (compact). Test cumulative `count_tokens(buf)`. If still under budget, emit `render_section_unique_spans` with full attribute list per span; if exceeding, drop attributes from spans starting from the lowest-anomaly-affinity spans (spans not in any `AnomalyMarker.affected_span_ids` and not in `critical_path`); emit truncation marker.
   - Phase C (drop spans entirely): if dropping all attributes still exceeds budget, drop unique spans entirely starting from same low-anomaly-affinity tail; emit truncation marker with dropped count.
   - Phase D (fail closed): if Phase A alone exceeds budget (anomalies + critical path > budget), return `Err(FormatError::BudgetExceeded { budget_tokens: budget.as_token_count(), actual_tokens: count_tokens(&buf) })`. The truncation algorithm preserves anomaly evidence as last-survivor — Phase D fires only when anomaly+critical-path content alone overflows, which is genuinely degenerate input.

## Implementation notes

- **Phase D fail-closed semantic:** the formatter's `BudgetExceeded` Err return is reserved for the genuinely-degenerate case where Phase A content (always-survive: anomaly observations + critical path) alone exceeds the budget. Phases B + C (drop attribute detail then drop low-signal spans) are expected to bring all "normal" inputs under any budget tier. Phase D firing is informative — surfaces to chunk #42 UI as `role="alert"` per a11y constraint.
- **Token-counting algorithm note:** char-count heuristic (`ceil(byte_len / 4)`) chosen for chunk #41 to avoid new workspace dep per chunk #40 precedent. Real tokenizer (e.g., tiktoken-rs / tokenizers) tracks GPT/Claude tokenization more accurately but is a 5-10MB dep with C dependencies. The proptest invariant `report.token_count <= budget.as_token_count()` is independent of tokenization algorithm correctness; future chunk MAY swap to a real tokenizer behind a feature flag without breaking the contract.
- **Smart-truncation determinism:** order is `dedup → critical_path → aggregation → unique_spans (with attributes) → unique_spans (sans attributes) → fail-closed`. Identical inputs MUST produce byte-identical markdown for `agent diffs across runs become meaningful` (per obs-plan §1 agent-driven invariant). The `BTreeMap` iteration in aggregation already gives deterministic order; the unique_spans Vec iteration follows insertion order from `dedupe` which is itself deterministic per chunk #39's `output_ordering_is_deterministic_across_invocations` test.
- **The `kept_attribute_count` / `dropped_attribute_count` from chunk #40** are READ from `CurationOutput` for telemetry purposes (recorded on `snapshot.render.markdown` span) but NOT for truncation decisions — the chunk #40 attribute filter has already removed verbose attributes; chunk #41 only further-truncates the kept set if budget binds (Phase B). The `kept_attribute_count` from chunk #40 is the input ceiling; chunk #41's `truncated_attribute_count` records additional drops applied by the formatter.
- **Order of file creation matters for the implement step:** create `token_budget.rs` first (defines `TokenBudget` consumed by `markdown.rs`), then `markdown.rs` (consumes `TokenBudget`), then update `lib.rs` (declares both modules), then update `contract.rs` (re-exports + new types).
