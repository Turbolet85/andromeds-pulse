## Patterns detected

- **New-API severity/activity canvas model** (`halo/HaloCanvas.tsx` + `halo/severity-to-halo.ts`): hue=`lchInterpolate(severityToHueFraction(tier))`, blur=`severityToBlurPx(tier)`, breathing=`activityStateToBreathingPeriodMs(state)`, dim=`connectionStateToDim`. This is the model chunk #91 MUST use (NOT the dashboard ConstellationCanvas's legacy `errorRate`/`throughputHz`).
- **Per-service canvas draw loop** (`dashboard/.../ConstellationCanvas.tsx:117-159`): iterate services, per-call uniform write + `draw(6)`, first service `clear` then `load`. Reusable structure; the widget version swaps the legacy mappers for the new severity/activity ones and adds true positional scatter.
- **PULL-poll hook for emit-only broadcasts** (`use-connection-state.ts` + `use-findings.ts`): mount + 1s interval + `window.focus` poll, `.catch(() => {})` jsdom-silent, public shape stable so a future Channel subscriber can be added without API churn. This is the established posture for `pulse://stream/service-lifecycle` (which has no Channel subscriber).
- **Pure-function formatter + `"—"` placeholder for non-finite** (`widget-types.ts`): the testable-pure-function convention; new constellation pure fns (seeded scatter, lifecycle→brightness, filter, accessible summary) follow this.
- **Accessible canvas wrapper** (`dashboard ConstellationCanvas` + `HaloCanvas`): `<section aria-label="…">` (implicit `role="region"`, no explicit role), `Fallback` on WebGPU-unavailable, `data-service-count` attribute for DOM-shape tests.

## Open questions

1. **[DECISION REQUIRED — routed to Phase 6 AskUserQuestion] Per-service severity + per-service activity + push subscription are NOT in the shipped contract.** The chunk #91 detail spec assumes (a) "hue = per-service severity from incidents scoped to that service", (b) "brightness = recent activity from histogram", (c) "subscribes to `pulse://stream/service-lifecycle`". Codebase reality:
   - `ServiceListItem` carries only `{ service, state (7-state lifecycle), last_seen_unix_nano, manual_override }` — no severity, no activity rate.
   - `IncidentRecord` has `scope` + `workspace` + `severity` but **no `service` name field** → incidents cannot be joined to a service to compute per-service severity webview-side.
   - There is **no `subscribe_service_lifecycle` Channel** procedure — the established posture (use-connection-state / use-findings) is PULL-poll of `list_with_states()`.
   This is the chunk-#88 "capability assumed but not yet implemented" situation (CLAUDE.md 2026-05-26 HYBRID RENDER PATTERN). Three resolutions, surfaced to the user:
   - **(a) Hybrid render (recommended, zero-delta scope):** position = seeded `hash(service_name)` scatter ✓; **brightness = lifecycle-state tier** (active brightest → quiet → silent → dormant dim — the lifecycle state IS the chunk #67 activity classification); Dormant dimmed / Archived hidden from `state` ✓; **hue = calm Earth-Blue baseline** (per-service severity deferred — documented in the off-canvas summary), OR optionally a global tint from `findings.severityMax`; tooltip = name + lifecycle-state label + "last seen N ago" (from `last_seen_unix_nano`); data via PULL-poll. Stays consumer-side, zero arch-registry delta, reuses the documented degraded-mode + PULL-poll patterns. Per-service-severity hue lands in a later backend chunk.
   - **(b) Extend scope:** add per-service severity to the backend (a `severity`/`priority_tier` field on `ServiceListItem` computed by joining service-scoped incidents in the Rust resolver, OR a `service` field on `IncidentRecord`). Touches `crates/triage` + `pulse-app/src/{services,incidents}_router.rs` + arch §Occupied Resources (payload shape change) + bindings regen + `/andromeda-evolve --allow-arch-registry`. Most faithful to the detail spec; contradicts the chunk's stated "consumer-side / zero registry delta".
   - **(c) Defer:** split — a backend-first chunk adds per-service severity, then this renders. Slowest; introduces a route-append cycle.
2. **Seeded scatter requires canvas/shader work.** The existing halo pipeline (`halo.wgsl` via `createHaloPipeline`) draws a centered full-quad radial gradient; the dashboard ConstellationCanvas computes `position` but never writes it to the uniform (dots overlap). True scatter needs either (i) extend the halo uniform with a per-dot center-offset + scale (`vec2` + `f32`) + adjust `halo.wgsl` to translate/scale the gradient, or (ii) a new lightweight "dot" pipeline. Both are consumer-side webview work (no backend); this is an /implement design choice, flagged so the plan budgets for it.
3. **`AggregatedBadgeCanvas` deletion vs retention.** Detail spec says "replace"; tests-domain says delete/rewrite the test in lockstep. `CompactWidget` is the sole importer (grep-confirmed). Recommend clean deletion of component + test (no `#[cfg(any())]`-style shimming).
