## Conventions to follow

- **`<section aria-label="...">` without explicit `role="region"`** per `.claude/rules/a11y.md` §Session Additions 2026-05-09 — implicit role from HTML AAM. Footer band semantic structure: prefer `<footer>` (implicit `contentinfo` only when descendant of `<body>` not nested in `<article>`/`<section>`; otherwise generic) OR `<div role="status" aria-live="polite">` for live-region semantics.
- **Co-located tests** at `pulse-app/ui/src/<path>/<Component>.test.tsx` per `.claude/rules/testing.md` §File placement — vitest discovers via `pulse-app/ui/vitest.config.mjs` `include: ["src/**/*.{test,spec}.{ts,tsx}"]`.
- **`vi.unstubAllGlobals()` in `afterEach`** for any test stubbing `navigator` / `userAgent` / `localStorage` / `matchMedia` — global stubs not auto-restored (testing.md 2026-05-08 entry).
- **`useEffect` mock-count assertion via `toHaveBeenCalled()`** (≥1) for effects with async-resolved deps (testing.md 2026-05-08 entry; chunk #28/#31 precedent).
- **`useReducedMotion` test reset in `beforeEach`**: `hasReducedMotionListener.current = false; prefersReducedMotion.current = null;` from `motion-dom` (testing.md 2026-05-04 entry; required ONLY if footer/badge motion is hook-gated — likely not for chunk #32 since motion lives in chunk #31's HaloCanvas).
- **Inline WebGPU spec constants** as module-level numeric literals — jsdom does not expose `GPUBufferUsage` etc. globally; chunk #32 footer band has no direct WebGPU dependency (HaloCanvas is reused as-is) so this convention may not apply unless the badge-overlay needs WebGPU directly (it doesn't — badge text is HTML/CSS).
- **TypeScript strict mode + ES modules** per global CLAUDE.md — no `any`, no `as` casts without justification.
- **Webview consumes only TauRPC-generated bindings** from `pulse-app/ui/src/bindings/index.ts` per `.claude/rules/frontend.md` — no manual TS re-declaration. For chunk #32 this matters only if a new IPC call is needed (it shouldn't be — Settings + streams.* exist).
- **Conditional window-label rendering** is a new convention — chunk #32 introduces it. Detection via `@tauri-apps/api/webviewWindow.getCurrentWebviewWindow().label` (Tauri 2 standard API). Adoption pattern: a `useWindowLabel()` hook returning `"compact-widget" | "main" | "unknown"` mirroring the Rust-side `sanitize_window_label` set; App.tsx reads the hook + branches.

## Open questions

- **`@tauri-apps/api/webviewWindow.getCurrentWebviewWindow()` capability**: this API may or may not require a `pulse-app/capabilities/` JSON addition (it's a `core:webview` permission group, possibly already covered by `core:default`). The implementer should verify at /implement time by attempting the import + checking for runtime IPC rejection. If it requires a capability addition, that's a `core:*` permission (Tauri-built-in), NOT a custom TauRPC procedure, so it does NOT trigger the security ↔ tests/CI ↔ arch capability-drift triple binding (the triple binding applies only to custom `#[taurpc::procedures(...)]` macros). Resolution path: add to existing `pulse-app/capabilities/default.json` (or whichever capability gates `core:default`) if needed; document in plan acceptance criteria.
- **Synthetic simulator scope expansion**: chunk #31's simulator drives `{ throughputHz, errorRate }`; chunk #32 needs `{ serviceCount, throughputHz, errorRate, retentionUsedSeconds, retentionMaxSeconds }`. Decision: extend the existing simulator's `useState` shape OR introduce a separate `useSyntheticWidgetMetrics` hook. Recommendation: SEPARATE hook because (a) the simulator now drives 2 surfaces (HaloCanvas inputs + footer/badge metrics) with different cadence requirements (Halo can use the existing 250ms sine-wave; footer values can use longer cadence like 1-2s for human-readable legibility), (b) cleaner replacement boundary when chunks #34/#35 land the real broadcast subscriber.
- **HaloCanvas overlay vs HaloCanvas children prop**: should chunk #32 add a `children` prop to HaloCanvas to accept the absolutely-positioned overlay, or should the overlay live in `AggregatedBadgeCanvas` wrapping HaloCanvas in a parent? Recommendation: WRAP via `AggregatedBadgeCanvas` (parent has `position: relative`; HaloCanvas + overlay are siblings absolutely positioned over a shared container). Avoids touching HaloCanvas, preserving chunk #31's locked acceptance criterion ("portable enough for compact-widget aggregated-badge consumption" — implementer chose to make it overlay-able via composition, not via API extension).
- **Retention metric source**: combined.md (obs) cites `subsystems.buffer.retention_seconds` from `health` TauRPC envelope, but that's a CONFIGURED retention window (e.g., 600s = 10 min default), not "used vs max" — the chunk title's `"Retention: 8m / 10m used"` shape implies a USED value. Recommendation: chunk #32 ships with `retentionUsedSeconds = retentionMaxSeconds` (synthetic 100% used) for the placeholder simulator; real `metric.buffer.memory_bytes` aggregation → `retention_used_seconds` derivation deferred to chunks #34/#35 alongside other broadcast subscribers. Document the placeholder as a synthetic-data note in the plan.
- **Footer error-rate threshold for accent state**: design/a11y both reference "non-zero error rate triggers accent state with paired text/icon"; layouts cites "exceeds threshold (e.g., 5%)". The threshold is implementation choice. Recommendation: 5% threshold to align with industry-standard observability error-rate alerting AND avoid noise from sub-1% transient errors. Surface as a constant in `widget-types.ts` (`ERROR_RATE_ACCENT_THRESHOLD = 0.05`) for testability.
