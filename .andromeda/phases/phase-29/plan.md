## Implementation notes

- **Window-label detection error path**: if `getCurrentWebviewWindow().label` throws (Tauri context not available, e.g., SSR / vitest jsdom without Tauri mock), `useWindowLabel()` returns `"unknown"` so App.tsx falls through to the `<Dashboard>` branch (safe default — Dashboard is the more featureful surface). Tests for the hook explicitly exercise this fallback path via `vi.mock("@tauri-apps/api/webviewWindow")` with the import throwing.

- **Synthetic simulator separation rationale**: chunk #31's HaloCanvas needs frequent (250ms) `{ throughputHz, errorRate }` updates so the LCH hue interpolation + pulse rhythm look smooth. Chunk #32's footer band needs slower updates (1000ms+) so SR users don't thrash; numeric values rarely flick without context. Two simulators with different cadence avoids both extremes — Halo simulator stays fast for visual smoothness; widget simulator slower for SR sanity. When chunks #34/#35 land the real broadcast subscribers, the widget simulator's parent-state-debounce pattern translates 1:1 to the real broadcast subscriber pattern (subscribe → throttle → setState).

- **AggregatedBadgeCanvas overlay vs HaloCanvas children prop decision**: chunk #31 phase-28 plan acceptance criterion calls for HaloCanvas portability "for compact-widget aggregated-badge consumption" without specifying API. Chunk #32 chooses composition (HaloCanvas in a `position: relative` parent + sibling overlay) over API extension (adding `children` to HaloCanvas). Rationale: composition keeps HaloCanvas's tight contract intact (3 props in, 1 component out); future tray-icon downstream chunk can compose differently (e.g., wrap HaloCanvas in a smaller container with an SVG-filter fallback) without HaloCanvas API churn.

- **Capability JSON conditional addition**: step 2's `core:webview:default` verification might or might not require an addition. Tauri 2's `core:default` capability bundle includes some core webview metadata access by default. If `getCurrentWebviewWindow().label` works at runtime without modification: do nothing. If runtime IPC rejection fires (Tauri 2 emits a clear "permission denied: core:webview:default-current" error in dev console): add the missing permission to `pulse-app/capabilities/default.json` with a 1-line addition to the `permissions` array. This is a `core:*` permission — not a custom IPC procedure — so does NOT trigger the security ↔ tests/CI ↔ arch capability-drift triple binding (the triple binding is specifically for `#[taurpc::procedures(...)]` macros that the xtask gate parses). Document the verification outcome in the commit message body.

Chunk #32 ships with `retentionUsedSeconds = retentionMaxSeconds` (synthetic 100% used) for the placeholder simulator OR with a linear ramp 0 → 600 then reset for visual interest — implementer's choice for the simulator shape.
