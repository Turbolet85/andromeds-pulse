## Patterns detected

- **Separate-process MCP sidecar with empty ephemeral state** (`andromeda-pulse-mcp.rs:49-54` + `tools.rs:338-343`): the existing tools query an empty in-memory buffer; the sidecar is spawned but never fed telemetry. Production MCP tools today return empty result sets. This is the deferred-cross-process-sharing reality.
- **Corpus as the cross-process shared substrate** (`corpus/contract.rs` + `andromeda-pulse-mcp.rs:26-47`): `corpus/corpus.db` is on-disk SQLite the sidecar can open via `resolve_data_dir()` + `corpus::Corpus::open`. This is the ONLY live shared state path between main process and sidecar.
- **Report serializer already in a library crate; only the assembly glue is binary-trapped** (`interpretation::markdown::serialize_report` is reachable; `incidents_router.rs:567 assemble_report` is the ~135-line glue to move). `interpretation → triage` edge already exists; only `interpretation → security` is new.
- **Corpus incident-read surface is incomplete for the new tools** (`corpus/contract.rs`): `CorpusWriter` has `load_active_incidents(workspace)` + `count_active_unread(workspace)` + `update_incident_status(id, ...)` + `mark_incident_read(id, ts)`, but NO `get_incident_by_id(id)` and NO list-all-incl-resolved. `query_incident_list` can use `load_active_incidents`; `retrieve_report(id)` + `mark_incident_resolved(id)` NEED a new `load_incident_by_id(id) -> Option<IncidentRowRaw>` corpus method (read-modify-write for the resolve path).
- **mcp.status three-state discriminator** (`mcp_router.rs:29-42`): `McpServerState{Enabled,Disabled,Unavailable}` + `sidecar_running` + `pid`. The chunk's "connected agent identity" extends this (the main process knows sidecar-running, not agent-connected).
- **JSON-RPC tool-list as hardcoded schema array** (`jsonrpc.rs:123-179`): the 4 tool schemas are an inline `json!` array; adding tools = extending this fn + `ALL_TOOL_NAMES` + the `dispatch_tool` match.
- **Five-place cfg-gate for the mcp-server feature** (`mcp_router.rs` + `main.rs:86` `#[cfg(feature = "mcp-server")]`): the `mcp.*` namespace + router wiring + emit_taurpc_bindings test are all feature-gated (chunk #49 precedent).

## Conventions to follow

- **Prepared statements only** for any DuckDB/SQLite read — `tools.rs:51-56` `SELECT_SPANS_RECENT` uses `?` placeholders + `duckdb::params![]`; corpus reads go through `CorpusReader` parameterized methods.
- **Error sanitization at the JSON-RPC boundary** — `tools.rs:290` `short_reason()` + `jsonrpc.rs:72` `sanitize_error_data()` strip paths/versions/`::`; new tools reuse `short_reason` for their error reasons.
- **Tool dispatch span discipline** — `tools.rs:128-178` emits `mcp.tools.call.response` with `result_type` + `result_count` + `duration_ms`, NEVER `result_content`; new tools mirror this (extend `result_type_label` + `result_count_for`).

- **specta::Type derive on cross-bridge types** — `mcp_router.rs:29-53` all DTOs derive `Serialize + Deserialize + specta::Type`; the `mcp.status` extension payload follows suit.
- **`[lib] test = false` + integration tests in `pulse-app/tests/`** — per CLAUDE.md 2026-05-20, any pulse-app test goes in `pulse-app/tests/`, never source-level `mod tests`.

2. **[RESOLVED by research correction] Report-serialization shared home.** No `report.rs` exists; `serialize_report` is already in `interpretation::markdown`. 3. **"Agent connected" semantics.** The main process knows sidecar-running (Child handle), not agent-connected (stdio peer). Resolution for A: `mcp.status()` extends `McpStatusDto` with a bounded `connected_agent: Option<String>` that at this chunk's scope equals the sidecar-running state surfaced as a label (`Some("stdio-client")` when `sidecar_running`, else `None`); a true sidecar→main agent-handshake round-trip is deferred. The "Send to agent" button gates on `mcp_enable (configured) AND sidecar_running`. EXTENSION of the existing `mcp.status` return shape — NO new TauRPC procedure, NO capability-drift delta.
4. **[for /implement Phase 1] Incident-BLOB decode location.** The sidecar reads `IncidentRowRaw.payload` (decrypted BLOB) and bincode-decodes → `triage::contract::Incident` (which already derives Serialize/Deserialize). CONFIRM the same bincode config is used on both write (pulse-app `incident_persistence.rs`) + read (sidecar) sides — a config mismatch silently fails decode. If a non-default `bincode::Options` is used, extract the encode/decode pair to a shared helper (`triage::contract` or `interpretation`).
5. **[for /implement] `retrieve_telemetry_slice(id)` payload shape.** Live spans/metrics/logs for an incident are NOT cross-process reachable. Recommended shape: return the incident's `evidence_refs` (span_ids / fingerprint_hashes) + (if present) the most-recent `digest_archive` summary fields — NOT raw telemetry rows. Document the limitation in the tool's MCP `description` ("persisted incident context; live telemetry is served by the separate `query_traces`/`query_logs` tools against the live buffer").
