## Open questions

- **Coverage regression threshold**: should the default be 0pp (no decrease allowed) or а small grace margin (e.g., -0.5pp tolerance for noise on small diffs)? Per test-plan §10 + §11 "NEVER lower coverage thresholds к pass build" — strictest interpretation is 0pp. Plan defaults к 0pp; xtask CLI flag (`--threshold-pp 0.0`) allows ad-hoc tightening (e.g., `+1pp` к require improvement); production CI uses 0pp default.
- **Criterion regression threshold**: similar question. Criterion 0.5's `change.json` includes `mean.point_estimate` + `change.point_estimate` (relative change); standard practice is fail on >10% median regression OR >5% slope regression. Plan defaults к +10% median / +5% slope; xtask CLI flag for ad-hoc.
- **Aggregated log summary**: chunk #56 combined.md mentions "log aggregation" — current ci.yml uploads per-OS logs as `logs-${runner.os}` artifacts. The "aggregation" interpretation has two readings: (a) "logs are aggregated into а single CI artifact" (already done by `actions/upload-artifact` glob covering the log dir) OR (b) "а single agent-readable summary stitching across all OSes". Plan adopts (a) — existing pattern is sufficient; defers (b) к а future tooling chunk if multi-OS triage becomes а pain point.
- **Quarantine convention enforcement scope**: should the check grep Rust source only (`crates/*/src/**/*.rs` + `pulse-app/{src,tests}/**/*.rs` + `xtask/src/**/*.rs`) OR also webview source (`pulse-app/ui/src/**/*.{ts,tsx}` `.skip()`)? Per test-plan §11 the convention is about `#[ignore]` Rust-side; vitest's `.skip` has its own ergonomic — plan defaults к Rust-source-only for chunk #55 scope; webview `.skip` quarantine convention can be а follow-on chunk if test plan amends.
