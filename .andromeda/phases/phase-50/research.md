3. **External tap repo bootstrap (turbolet85/homebrew-andromeda-pulse + turbolet85/scoop-andromeda-pulse)**: Neither repo exists yet (assumed; not verified via `gh repo view`). Per arch §Established Decisions Deferral path + chunk #3 + chunk #52 ACTIVE/DEFERRED Path A precedent: bootstrap stays operator-driven. The workflow file lands consuming secrets that don't exist yet; secret population unblocks publishing without YAML edits. Recommendation: Path A — workflow file + runbook update is the ACTIVE chunk #53 deliverable; external repo creation + PAT provisioning + Environment secret population stays operator-driven as а new pre-v0.1.0 DEFERRED scope item in production-release-environment.md (numbered alongside existing items 1-4).

4. **Cross-repo update mechanism: direct push vs PR creation**: Two valid patterns:
   - **Direct push** (simpler; mirrors `mislav/bump-homebrew-formula-action`-style): workflow commits directly к tap/bucket repos via PAT.
   - **PR creation** (safer; allows manual review of formula updates): workflow opens а PR via `peter-evans/create-pull-request@<SHA>` к tap/bucket repos.
   Recommendation: defer к /implement Phase 6 Open Question. Either path satisfies the chunk; PR creation is slightly more operator-friendly but requires PAT с `pull_request: write` scope. Direct push с `--rebase` is faster for routine version bumps. The choice doesn't affect chunk #53's plan structure; both can be implemented within the same workflow shape.

5. **Job structure: single job с per-channel steps vs separate jobs per channel**: Two valid patterns:
   - **Single job**: simpler; all channel updates share one Environment approval gate.
   - **Separate jobs**: parallelizable; finer-grained Environment approval per channel; better if one channel update fails (e.g., Homebrew tap unreachable) but the other should still proceed.
   Recommendation: separate jobs (`update-homebrew` + `update-scoop`) — matches chunk #52's per-OS matrix structure precedent + gives clearer audit trail per-channel.
