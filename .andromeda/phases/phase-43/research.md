## Conventions to follow

- **Module visibility:** `pub` for contract-module surface (types crossing crate boundary), `pub(crate)` for internals like `sanitize_wasmtime_error`. New `sandbox.rs` + `capability.rs` modules expose their public API via `crate::contract` re-exports where appropriate (per arch §Conventions "Module visibility discipline" + arch §Project Intent "Template patterns").
- **File naming:** `snake_case.rs` per arch §Conventions (chunk #46 files: `sandbox.rs` + `capability.rs`).
- **Colocated tests:** `#[cfg(test)] mod tests { … }` at the bottom of each source file (engine.rs:110-153, wit_loader.rs:104-229, contract.rs:73-102) per `.claude/rules/testing.md` "File placement".
- **No-Debug wasmtime types:** `Engine` / `Component` / `Store` / `Instance` / `Linker` lack `std::fmt::Debug` impls; `#[tracing::instrument]` on functions taking these MUST `skip(engine, ...)`; test match arms destructure (`Err(other) => panic!("got {other:?}")`) per session-learning 2026-05-11.
- **Clippy-friendly compile-time bounds:** module-scope `const _: () = { assert!(...) };` blocks rather than runtime `#[test]` assertions on constants (per session-learning 2026-05-11; engine.rs:42-45 precedent).
- **Field allowlist discipline:** new events emitted from `crates/plugins/` MUST use field names from the existing `plugin` allowlist (5 fields) OR `plugins` allowlist (2 fields) at `pulse-app/src/observability.rs`. Cap values exceeded? Format into `error_msg: "memory cap exceeded: 67108864 bytes requested, 67108864 configured"` rather than separate `limit_bytes` / `requested_bytes` fields (which would be silently redacted by the subscriber Layer). The trade-off: less queryable / less greppable, but no allowlist extension required.
- **`AppError::Plugin` variant exists already:** chunk #46 EXTENDS `plugins::contract::Error` with new variants but does NOT touch ui-bridge's `From<PluginsError>` impl (the existing `AppError::Internal` mapping handles new variants by adding match arms in the existing impl).
