## Implementation notes

(Orchestrator's notes for /implement on edge cases / order sensitivity / known pitfalls discovered during Phase 3 research.)

- **Implementation order matters:** Step 1 (`sandbox.rs`) → Step 2 (`capability.rs`) → Step 3 (extend `contract.rs` `Error` enum) → Step 4 (extend `wit_loader.rs` tests with sandbox-stack integration test, which references `sandbox::store_for_category` + `capability::linker_for_category` types from Steps 1+2) → Step 5 (`lib.rs` mod declarations) → Step 6 (`engine.rs` doc-comment) → Step 7 (`ui-bridge/contract.rs` From impl extension) → Step 8 (service-doc maintenance). Steps 1 + 2 + 3 are leaf changes; Steps 4+ reference them.
- **No-Debug wasmtime types caveat:** Per session-learning 2026-05-11 (testing rule): `wasmtime::Engine` / `Component` / `Store` / `Instance` / `Linker` lack `Debug` impls. Any `panic!("...{x:?}", ...)` against these types fails compile. Use destructured match arms (`Err(other) => panic!("got {other:?}")`) where the error type has Debug, but for tests asserting on `Store` / `Linker` state use direct property access (e.g., `store.data().mem_max == 64 * 1024 * 1024`).
- **Clippy const-assertions caveat:** Per session-learning 2026-05-11 (testing rule): runtime `assert!(MY_CONSTANT > 0)` inside `#[test]` fn fails clippy `assertions_on_constants` under `-D warnings`. Use module-scope `const _: () = { assert!(...) };` blocks instead — `engine.rs:42-45` is the precedent for the new sandbox constants.
- **Field allowlist constraint at obs:** Per session-learnings 2026-05-03 (obs rule) + 2026-05-07 (security rule): the `plugin` (singular) AllowList registry entry at `pulse-app/src/observability.rs:158-170` has exactly 5 allowed fields. Chunk #46 emissions MUST stay within these 5 fields OR explicitly extend the registry (cross-crate change). The plan recommends using `error_msg` field for cap-rejection details (e.g., `error_msg = "memory cap exceeded: 67108864 requested, 67108864 cap"`) rather than adding `limit_bytes` field.
