## Combined goal

Replace the compact widget's dashboard-mindset footer band with an ambient connection-state signal. Two moves: (1) **remove** the `Ingest / Error / Retention` `FooterBand` entirely (it violates the P-024 Widget Ambient Surface invariant — a glance widget should not be a metrics dashboard); (2) **add** a small (6–8px) connection-state dot near the app icon in the titlebar, color-encoded per the chunk #59 connection FSM state, with a hover tooltip showing the current state + last-span-ago. The dot is the first webview consumer of connection-state: it polls the existing `connection.current_state()` TauRPC (per arch §Occupied Resources, chunk #59) — no new TauRPC procedure, broadcast topic, capability, env var, or crate (arch-registry delta: none; consumer-side only). This is purely webview work under `pulse-app/ui/`, satisfying capabilities P-001 (connection visual signal) + P-024 (chrome cleanup), per arch §Standard Contracts Real-time push + the design-system NASA palette + a11y not-color-alone (SC 1.4.1) / non-text contrast (SC 1.4.11) disciplines.

## Implementation Steps

### 1. New PULL hook — `pulse-app/ui/src/hooks/use-connection-state.ts`

Mirror the `use-findings.ts` (chunk #87) + `use-widget-metrics.ts` (chunk #57) precedents:
- `createTauRPCProxy()`; poll `proxy.connection.current_state()` on mount, on a `window.setInterval(~1000ms)`, and on `window` `focus`. Each call wrapped in `.catch(() => {})` (jsdom / pre-init Tauri context → keep last/default state silently, no console noise).
- Return `ConnectionStatePayload | null` (null until the first successful poll; consumers treat null as a neutral "connecting…" default).
- Cleanup: clear the interval + remove the focus listener on unmount.
- Emit ZERO `tracing`/`console.*` per poll (cardinality discipline; the backend already logs connection-state transitions).

### 2. New component + pure helpers — `pulse-app/ui/src/components/ConnectionDot.tsx`

- Consume `useConnectionState()` internally (self-contained — no new Titlebar data prop).
- Render a `role="img"` element (NOT a `<button>` — the dot is a non-actionable ambient status indicator) carrying `aria-label="Connection: <state-label> — last span <ago>"` (always-present accessible name → satisfies SC 1.4.1 not-color-alone without relying on the visual tooltip).
- Visual: a round dot, size from spacing tokens (≈6–8px → `var(--spacing-sm)`-class), `borderRadius: var(--radius-full)`, `background` from the state→token map. The dot element does NOT carry `data-tauri-drag-region` (so hover works inside the drag-region header).
- Hover tooltip: `onMouseEnter`/`onMouseLeave` toggles an `aria-hidden` popover (`background: var(--color-raised-2)`, 1px `rgba(74,144,226,0.1)` border, `borderRadius: var(--radius-md)`, NO box-shadow). State label in `var(--font-body)`; the last-span-ago value in `var(--font-code)` with `fontVariantNumeric: "tabular-nums"`. Tooltip appears instantly (no fade) — trivially reduced-motion-safe; if a fade is added it MUST be ≤150ms `var(--easing-out)` with `motion-reduce:transition-none motion-reduce:duration-0`. `data-testid="connection-dot"` on the dot, `data-testid="connection-tooltip"` on the popover.
- Export pure helpers for direct unit testing:
  - `connectionStateLabel(state: ConnectionState): string` — "Listening" / "Receiving" / "Idle" / "Stalled" / "Receiver failed" (humanize the discriminator; append the sanitized `reason`/`message` for ReceiverFailed when present).

  - `formatLastSpanAgo(ms: number): string` — "just now" / "<N>s ago" / "<N>m ago" (relative-time precedent from FindingsDropdown).
- Display ONLY the bounded state label + last-span-ago (+ the already-sanitized `message`/`reason`); NEVER interpolate raw OTLP attribute/span/service strings (security plan §Logging & Monitoring).

## Implementation notes

- **Build the hook (Step 1) + helpers (Step 2 pure fns) before the component render**, since `ConnectionDot` consumes both; tests for helpers are DOM-free and fastest to land first.
- **`ConnectionState` is a discriminated union** (`{ state: "…" }`), not a bare string — switch on `state.state`. The bindings docstring notes the compiler enforces an exhaustive switch, which is the not-color-alone affordance at the wire boundary; keep the switch exhaustive (all 5 arms) so a future 6th state is a compile error, not a silent color gap.
- **Non-interactive dot decision** (per research.md Open questions): `role="img"` + always-present `aria-label` + `aria-hidden` hover tooltip. This keeps a11y-plan §1's "SC 1.4.13 not applicable" valid and adds no tab stop. If Phase 6 review prefers an interactive button-dot, that is a scope change (SC 1.4.13 applies + a11y-plan §1 needs `/andromeda-a11y`).
- **Dot renders in BOTH titlebars** (shared `Titlebar` component). Defensible (P-001 is global) and cheap. If compact-widget-only is wanted, add a `showConnectionDot?: boolean` prop gated true by `CompactWidget` — flagged for Phase 6.
- **No "expand-to-dashboard button" exists today** despite the project-doc phrasing; the plan preserves existing affordances and adds none. Flagged for Phase 6.
- **`message`/`reason` are already sanitized** at the wire boundary (bindings docstring); safe to render in the tooltip — they are bounded FSM strings, not raw OTLP.
