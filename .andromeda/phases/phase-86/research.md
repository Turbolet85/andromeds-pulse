## Patterns detected

- **PULL-via-poll hook** (`use-findings.ts:43-79` + `use-widget-metrics.ts:60-97`): `createTauRPCProxy()` → `await proxy.<router>.<method>()` inside `.catch(() => {})` → poll on mount + `window` `focus` (findings) or `setInterval` (metrics) → cleanup on unmount. The new `use-connection-state` hook mirrors this with `connection.current_state()` + a periodic `setInterval` (state + `last_span_ago_ms` drift on a seconds timescale) + window-focus refetch.
- **Titlebar inline-style + token chrome** (`Titlebar.tsx:54-134`): inline `style={{...}}` objects referencing `var(--token)`, NOT Tailwind classes (except the `motion-reduce:` utility classes). New dot follows the same inline-style-with-tokens shape.
- **Not-color-alone precedent** (`FooterBand.tsx:11-14,56-57`): `--color-accent` border paired with `--color-text-primary` text + the numeric value carrying meaning. The dot's analogue: color + an always-present accessible name carrying the state word.
- **Decorative vs meaningful icon** (`Titlebar.tsx:70-75,111`): the app-icon span + button-inner glyphs are `aria-hidden="true"` because an ancestor `aria-label` carries the name. The connection dot is the OPPOSITE — it is the meaningful graphic, so it gets `role="img"` + its own `aria-label` (NOT aria-hidden).
- **Test mock + injection** (`CompactWidget.test.tsx:8-21,68-73` + `Titlebar.test.tsx:6-16`): `vi.mock("../hooks/<hook>", …)` + `vi.hoisted` state object + per-test setter; `tabbable(container)` for focus-order ground-truth (`CompactWidget.test.tsx:133-138`). Per testing.md 2026-05-09, per-test hook override via `vi.mocked(...).mockReturnValue(...)` + `mockReset()` in `afterEach`.
- **Relative-time rendering** (`CompactWidget.tsx:107` passes `nowUnixNano`; FindingsDropdown renders "3m ago"): precedent for a `formatLastSpanAgo(ms)` helper ("just now" / "2s ago" / "3m ago").

## Conventions to follow

- **jsdom silent posture**: every `createTauRPCProxy()` invocation wrapped in `.catch(() => {})` (or try/catch) so jsdom/pre-init Tauri context falls back to a default with no console noise (`use-widget-metrics.ts:70-72,78-80`, `use-findings.ts:45-50`).
- **Tokens only, no raw hex/px**: dot color via `var(--color-primary)` / `var(--color-accent)`; size via spacing tokens; radius `var(--radius-full)`; tooltip bg `var(--color-raised-2)` + 1px `rgba(74,144,226,0.1)` border + `var(--radius-md)`, NO box-shadow (per `.claude/rules/design-tokens.md` + design extract).
- **`data-testid` for test targeting**: existing convention (`titlebar`, `footer-band`, `footer-error-value`, `findings-counter`, `findings-live-region`). New: `connection-dot` (+ `connection-tooltip` for the hover popover).
- **Non-drag-region for hover targets**: interactive/hover elements inside the `data-tauri-drag-region` header must NOT carry the drag attribute (buttons omit it) so pointer events fire (`Titlebar.tsx` buttons; layouts extract).
- **`role="img"` for accessible graphics** without redundant role on semantic elements (per `.claude/rules/a11y.md` "Semantic HTML first" — a status graphic with no native element uses `role="img"` + `aria-label`).
- **Pure-helper colocation + unit tests**: `widget-types.ts`/`findings-types.ts` precedent — pure formatters/mappers live in a sibling module with `.test.ts` (DOM-free unit tests).

## Open questions

- **Dot interactivity (RESOLVED — confirm at Phase 6):** the dot is an ambient STATUS indicator with no action. Plan makes it **non-interactive** (`role="img"` + always-present `aria-label` + hover-only visual tooltip that is `aria-hidden`). This satisfies SC 1.4.1 (state in accessible name, not color alone) + SC 1.4.11 (≥3:1 non-text), and SIDESTEPS SC 1.4.13 (no interactive UI component reveals hidden content; the accessible name is always present to AT). It also avoids a pointless tab stop / "button with no action" anti-pattern and keeps the titlebar focus order unchanged (Investigate → Settings → window controls). If the user instead wants an interactive button-dot, SC 1.4.13 becomes applicable and a11y-plan §1's "not applicable" line needs an `/andromeda-a11y` update (out of phase scope).
- **SC 1.4.13 applicability shift:** because the dot is non-interactive, a11y-plan §1's "SC 1.4.13 not applicable" stays valid. No specialist-plan edit required this chunk. (Flagged from combined.md open questions — resolved by the non-interactive choice.)
- **"expand-to-dashboard button (existing affordance, kept)":** the project-doc summary lists this, but the current titlebar has Investigate + Settings + window controls — there is NO literal "expand-to-dashboard" button. Plan preserves all existing affordances untouched and does NOT invent a new expand button. Confirm at Phase 6 whether a dedicated expand-to-dashboard button is wanted (would be a scope addition).
- **Dot appears in BOTH titlebars:** `Titlebar` is shared by the compact widget AND the full dashboard. A self-contained `<ConnectionDot />` rendered unconditionally appears in both. This is defensible (P-001 connection signal is globally relevant) and adds only a cheap 1s poll. Confirm at Phase 6 whether to prop-gate the dot to the compact widget only.
- **Color mapping source:** plan maps color by the `state` discriminator (exhaustive 5-way switch: Listening/Receiving/Idle → `--color-primary`; Stalled/ReceiverFailed → `--color-accent`) to match the design extract verbatim. The payload's `severity` field (info/warning/critical) is an equivalent 3-way classification and is used only to enrich the tooltip text, not to drive color.
