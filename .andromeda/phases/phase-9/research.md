## Conventions to follow

- **ESM (`.mjs`) for Node.js scripts** — `build.mjs` already uses `import` + `#!/usr/bin/env node` shebang + `node:` import prefix. Contrast harness should follow same convention: `pulse-app/ui/scripts/verify-contrast.mjs`.
- **`pulse-app/ui` cwd discipline** — npm scripts run from `pulse-app/ui/`; paths are derived via `dirname(dirname(fileURLToPath(import.meta.url)))` pattern from `build.mjs` for "two levels up from `scripts/foo.mjs`" = `pulse-app/ui/`.
- **`tokens.css` lives at TWO paths**: input is `pulse-app/ui/src/styles/tokens.css` (Tailwind v4 `@theme static` source), output is `pulse-app/ui/dist/tokens.css` (built artifact, minified). Harness MUST read the BUILT output (`pulse-app/ui/dist/tokens.css`) per arch §Design Philosophy "Concrete tokens are owned by the design specialist" + a11y-plan §3 "Source-of-truth tokens" — design plan says read `pulse-app/ui/dist/tokens.css` (chunk #10 output), not the input.
- **Token name verbatim** — `--color-text-primary`, `--color-base`, `--color-inset`, `--color-feedback-success`, `--color-accent`, `--color-primary`, `--color-text-secondary`, `--color-text-tertiary`, `--color-text-muted`, `--color-secondary`, `--color-raised-1`, `--color-raised-2`, `--color-raised-3`, `--border-focus` — use these exact identifiers in JSON output (a11y extract constraint).
- **Vitest test file location** — pure-function helper unit tests (e.g., for a CSS-token parser) belong adjacent to source: `pulse-app/ui/src/contrast/parse-tokens.test.ts` or `pulse-app/ui/src/contrast/__tests__/parse-tokens.test.ts`. Vitest discovers via `src/**/*.{test,spec}.{ts,tsx}` glob.
- **JSON output to `pulse-app/ui/dist/contrast-report.json`** — `dist/` is already `.gitignore`-covered; harness output is build-time artifact (gitignored). Stable path per arch + tests + a11y extracts.
- **Exit code semantics** — exit 0 = all pairs PASS at their declared thresholds; exit non-zero = at least one FAIL (per tests + a11y extracts). Agent reads exit code directly without parsing stdout.
- **No xtask delegation at chunk #12** — current xtask tasks delegate to `cargo`, not `npm`/`node`. Adding a Node.js shell-out would be the first such precedent. Defer to chunk #13 or later if cross-language workspace command becomes necessary; chunk #12 stays pure npm.
- **Process-launch hygiene** — `execFileSync(process.execPath, [...])` for spawning Node binaries (build.mjs pattern); never `child_process.exec()` with shell-interpreted strings (CWE-78 class — security plan §Code Patterns Process commands).

## New files to create

- **`pulse-app/ui/scripts/verify-contrast.mjs`** — Node.js entry point. Reads `pulse-app/ui/dist/tokens.css`, parses CSS custom properties, computes contrast ratios via `colorjs.io` 0.6.x `Color.contrast(fg, bg, 'WCAG21')`, emits JSON to `pulse-app/ui/dist/contrast-report.json`, exits 0 if all required pairs ≥ target, non-zero if any fail. Uses `node:fs.readFileSync` for synchronous I/O (matches build.mjs pattern); imports `colorjs.io` via `import Color from 'colorjs.io'`.
- **`pulse-app/ui/src/contrast/pairs.mjs`** — Static catalog of token pairs to verify, exported as a const array. Each entry: `{ pair_name, fg_token, bg_token, target_ratio, wcag_criterion, wcag_level, usage }`. Includes the 6 required pairs from a11y-plan §6 + chunk #11's manual pre-flight pairs (text-primary/base, feedback-success/inset, border-focus/base) + design extract's surface-scale focus-ring variants (informational tier).
- **`pulse-app/ui/src/contrast/parse-tokens.mjs`** — Pure-function helper that parses Tailwind-emitted CSS custom-property declarations and returns a `Map<string, string>` of token name → hex value. Case-insensitive on hex; normalizes to uppercase. Importable from both `verify-contrast.mjs` and Vitest.
- **`pulse-app/ui/src/contrast/parse-tokens.test.ts`** — Vitest unit tests for the parser (5–10 cases: minified Tailwind output, uppercase/lowercase hex, missing token, malformed declaration, comment-stripped form). Pure function = high-coverage friendly.
