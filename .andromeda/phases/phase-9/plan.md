5. **Create `pulse-app/ui/scripts/verify-contrast.mjs`** — Node.js entry point. Pseudocode:
   ```
   #!/usr/bin/env node
   import Color from 'colorjs.io';
   import { parseTokens } from '../src/contrast/parse-tokens.mjs';
   import { PAIRS } from '../src/contrast/pairs.mjs';
   import { readFileSync, writeFileSync } from 'node:fs';
   import { dirname, join } from 'node:path';
   import { fileURLToPath } from 'node:url';

   const ROOT = dirname(dirname(fileURLToPath(import.meta.url)));
   const TOKENS_CSS = join(ROOT, 'dist', 'tokens.css');
   const REPORT_JSON = join(ROOT, 'dist', 'contrast-report.json');

   const css = readFileSync(TOKENS_CSS, 'utf8');
   const tokens = parseTokens(css);

   const records = PAIRS.map(p => {
     const fgHex = tokens.get(p.fg_token); // throw if missing
     const bgHex = tokens.get(p.bg_token);
     const ratio = new Color(fgHex).contrast(new Color(bgHex), 'WCAG21');
     const pass = p.severity === 'informational' ? true : ratio >= p.target_ratio;
     return {
       timestamp: new Date().toISOString(),
       level: pass ? 'INFO' : 'ERROR',
       target: 'a11y::contrast',
       message: pass ? `WCAG ${p.wcag_criterion} pass for ${p.pair_name}` : `WCAG ${p.wcag_criterion} violation for ${p.pair_name}`,
       fields: {
         service: { name: 'com.andromeda.pulse' },
         deployment: { environment: 'production' },
         wcag_criterion: p.wcag_criterion,
         violation_type: 'color-contrast',
         severity: p.severity,
         surface: 'desktop-webview',
         token_name: p.pair_name,
         actual_contrast_ratio: Number(ratio.toFixed(2)),
         required_ratio: p.target_ratio,
         remediation: pass ? null : `adjust ${p.fg_token} or ${p.bg_token} to meet ${p.target_ratio}:1`,
         tool: 'colorjs.io',
         tool_result_id: `${p.pair_name}@${tokens.get(p.fg_token)}-on-${tokens.get(p.bg_token)}`,
         measured_value: Number(ratio.toFixed(2)),
         required_value: p.target_ratio,
         usage: p.usage,
         wcag_level: p.wcag_level,
         pass,
       },
     };
   });

   writeFileSync(REPORT_JSON, JSON.stringify({ schema_version: 1, generated_at: new Date().toISOString(), records }, null, 2) + '\n');

   const failures = records.filter(r => r.fields.severity === 'critical' && !r.fields.pass);
   if (failures.length > 0) {
     console.error(`verify-contrast: ${failures.length} critical failure(s) — see ${REPORT_JSON}`);
     process.exit(1);
   }
   console.log(`verify-contrast: ${records.length} pairs evaluated, all critical pairs pass — see ${REPORT_JSON}`);
   process.exit(0);
   ```
   Schema fields conform to a11y-plan §3 Structured Violation JSON Schema (security extract + a11y extract acceptance criteria).

## Implementation notes

- **OQ1 backfill mechanism:** chunk #11 contributed three manual contrast values in session-handoff (text-primary/base 14.46:1, feedback-success/inset 7.20:1, border-focus/base 5.12:1). The harness recomputes these from `tokens.css` via `colorjs.io`; no transcription. The recorded `actual_contrast_ratio` may differ from the manual values by ±0.01 due to floating-point precision differences between manual calc and `colorjs.io`'s WCAG21 algorithm — both are spec-conformant; the harness value is canonical going forward.
- **OQ2 / xtask deferral:** when chunk #45 (a11y CI gate) wires the harness into CI, evaluate whether to add `cargo xtask verify-contrast` as a thin shell-out or wire `npm run verify:contrast` directly into `ci.yml`. Both are valid; current xtask pattern is cargo-only, so direct npm in CI may be cleaner. Decision deferred to chunk #45 plan.
- **OQ3 surface-scale enumeration rationale:** focus rings can appear on any elevated surface (cards on `--color-raised-1`, dropdowns on `--color-raised-2`, modals on `--color-raised-3`); a strict "only validate against base" stance under-specifies. But making all 5 CI-blocking would block legitimate UI patterns where the focus ring still meets ≥3:1 against the dominant background even if the variant fails. Compromise: emit all 5 records, gate only on the `border-focus/base` baseline; designers can review the informational records to catch latent issues without CI churn.
- **Tailwind hex case round-trip:** input `tokens.css` has uppercase hex (`#4A90E2`); minified output has lowercase (`#4a90e2`). `colorjs.io` is case-insensitive natively, so no normalization needed for ratio computation; the parser normalizes to uppercase for predictable JSON output and stable `tool_result_id` strings.
- **Vitest test count delta:** N≈5–8 new tests is a guideline; actual count emerges during implementation. Aim for one test per parse-tokens edge case + one integration test that parses the actual `dist/tokens.css` and asserts presence of the 14 token names. CI count baseline updates accordingly when next session-handoff is written.
- **No Rust source change:** living artifacts (`dependency-tree.md` / `api-surface.md`) need no refresh per arch extract pattern; wrap-session Phase 5 reconcile will produce byte-identical LIVING blocks.
