- **Workspace dependency hub pattern** (per arch §Stack + obs §3 + tests §3): pin shared 3rd-party crates in workspace-root `[workspace.dependencies]`; per-crate `Cargo.toml` references via `{ workspace = true }`. Source-of-truth: arch §Inherited Defaults + obs plan §3 Logging stack.
- **Crate template shape** (per arch §Project Intent Template patterns): each library crate exposes a public contract module (the only `pub` surface), `pub(crate)` internals, `thiserror`-derived error enum. Source-of-truth: arch §Project Intent.
- **Dependency direction DAG with `pulse-app` as the only root** (per arch §Cross-cutting Patterns Module dependency direction): no library → `pulse-app` edges; siblings only when contract requires.
- **Negative-default capability discipline** (per arch §Cross-cutting Patterns Webview IPC capability policy + security plan §API Security TauRPC capability authorization): `pulse:default` enumerates only the explicitly-listed introspection procedures (`app_info`, `health`, `ready`, `get_settings`, `update_settings`); core APIs (`fs`, `shell`, `dialog`, `http`) NEVER granted to `pulse:default` without per-feature rationale.
- **Binary owns subscriber init** (per obs §3 Init order): `pulse-app/src/main.rs` is the only place `tracing_subscriber::registry().init()` is allowed; library crate stubs MUST NOT call it.
- **Feature-gate hygiene** (per arch §Cross-cutting Patterns Feature-gate hygiene + obs §3): `mcp-server` and `otap-ingest` features default off; `rmcp` and OTAP-specific deps enter the build graph only behind their respective feature flags.
