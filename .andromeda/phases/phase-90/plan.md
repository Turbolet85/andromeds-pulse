## Combined goal

Complete the deferred dashboard-side half of the v0.2.0 Halo/constellation
cascade. Chunks #90/#91 migrated the WIDGET surface (and the header
`HaloCanvas`) to the per-service severity/activity API — hue = cumulative
incident severity, brightness = lifecycle activity, seeded-scatter position —
but left the full-window dashboard `ConstellationCanvas` on the legacy
error-rate/throughput single-blob model, plus a pile of now-dead plumbing.
This chunk migrates the dashboard `ConstellationCanvas` to mirror the widget
(reuse `widget/constellation-types.ts` + `widget/constellation-pipeline.ts`,
fed by `useServiceConstellation`), then removes every module the migration
orphans: the legacy `error-rate-to-blur` / `throughput-to-hz` helpers, the
orphaned `use-widget-metrics` hook, the now-orphaned `use-constellation-data`
aggregate, and the fully-dead synthetic `HaloInput` chain
(`use-synthetic-halo-input` → `HaloInputProvider` → `useHaloInput`, which has
zero call sites). It is webview-only (TypeScript / React / WGSL), consumer-side
IPC only (reuses `services.list_with_states`, chunk #67), with zero arch-registry
delta — per arch §Occupied Resources (no new TauRPC / capability / broadcast),
design-system.md §Motion Decisions Log 2026-05-29 (severity-driven Halo, legacy
mapping superseded), a11y-plan §6/§11 (SC 2.3.3 reduced-motion + SC 1.4.1
not-color-alone), and obs-plan §1/§10 (the `metric.webgpu.frame_duration_ms`
bridge is preserved). Two scope decisions were resolved with the user at Phase 3:
"retype HaloInput" → **delete the dead chain**; orphan cleanup → **delete
everything orphaned** (incl. `use-constellation-data`).

**NOTE — `HaloCanvas.tsx` is intentionally NOT touched:** it was already
migrated by chunk #90 (it consumes `cumulativeSeverity`/`activityState`/
`connectionState` via `severity-to-halo`). The route §2 phrase "migrate …
HaloCanvas" is imprecise; the §91 source spec scopes the work to
`pulse-app/ui/dashboard/ConstellationCanvas.tsx` only.

## Implementation notes

- **Order sensitivity:** do steps 1–2 (migrate consumers) before steps 3–4 (delete sources) so the legacy modules are unreferenced at deletion time and `tsc` stays meaningful. The grep acceptance criterion is the final backstop.
- **Mirror, don't reinvent:** the widget `ConstellationCanvas.tsx` is a near-exact template — copy its pipeline/render structure and change only the container height (`240px` vs `100%`) and `data-testid` (`constellation-canvas` vs `service-constellation`). The dashboard keeps its own `data-testid="constellation-canvas"` so existing route tests that key on it still resolve.
- **`ServiceListItem.priority_tier` is `#[serde(default)]` + `Option`** → it lands in bindings as `priority_tier?: PriorityTier | null`; `visibleDots` already normalizes via `item.priority_tier ?? null` (per frontend.md 2026-05-30). The dashboard inherits this for free by reusing `visibleDots`.
- **bindings.ts regen discipline:** if Phase 2 fix-loop runs any default-features `cargo nextest`/`cargo run` that overwrites `pulse-app/ui/src/bindings/index.ts`, regenerate via `cargo nextest run -p pulse-app --features mcp-server --bin pulse-app -E 'test(emit_taurpc_bindings)'` and verify `grep -c '"mcp":' pulse-app/ui/src/bindings/index.ts` ≥1 before `cargo xtask capability-drift` + before commit (per testing.md 2026-05-17/2026-05-25).
- **rlib-format / cold-build race:** if `cargo nextest run --workspace` fails naming a native `-sys` dep, run `cargo build -p pulse-app` first to materialize dep rlibs, then re-run nextest (per testing.md 2026-05-31). Webview-only change means a Rust rebuild is unlikely, but the workspace gate still links pulse-app test binaries.
