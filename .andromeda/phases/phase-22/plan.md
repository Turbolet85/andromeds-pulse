## Combined goal

Wire `taurpc` 0.7 + `specta` 2.0.0-rc.22 to auto-generate TypeScript bindings for the existing five TauRPC routers (`HealthApi` from chunk #14 in `crates/ui-bridge/src/health.rs`; `TracesApi`/`MetricsApi`/`LogsApi` from chunk #22 in `pulse-app/src/viz_routers.rs`; `StreamsApi` from chunk #23 in `pulse-app/src/streams.rs`), and land the `tsc --noEmit` typecheck gate that arch §Stack + §Inherited Defaults declares as the locked webview-side typecheck. Per arch §Established Decisions [Tauri IPC Bridge — Surface 2] the rationale is drift elimination: the webview frontend will import generated `.d.ts` rather than re-declaring command signatures, eliminating the manual TS↔Rust synchronization tax across the 8-module monolith. The `tsc --noEmit` gate runs against the merged source-tree (existing `pulse-app/ui/src/**/*` + newly emitted `pulse-app/ui/src/bindings/**/*`) and joins CI's existing Lint stage alongside `cargo fmt --check` + `cargo clippy ... -D warnings` in `.github/workflows/ci.yml` `lint-test-build` job (per security-plan §Dependency Security CI integration + test-plan §9 Lint row).

The chunk introduces NO new TauRPC procedures, NO new capability JSON entries, NO new runtime spans (binding generation is build-time per obs extract Anti-pattern), NO modifications to `AppError` (chunk #26 territory), NO modifications to `tauri.conf.json` `app.security.csp`, and NO drift remediation for the carried-over D3 `streams.*` namespace (chunk #27 territory per the route#23 wrap recommendation; chunk #25 surfaces the typed `streams.subscribe_*` bindings while flagging the absence in arch §Occupied Resources). Specta `derive(specta::Type)` is already wired across all router types (chunk #14 conditional `cfg_attr` for `AppError`/`HealthEnvelope` + chunk #22/#23 unconditional for `viz` query types) — this chunk consumes that wiring at the binding-emission step rather than extending it.

The implementation has one upstream probe (taurpc 0.7's actual `.ts` emission mechanism — macro arg `export_to = "..."` vs build script vs runtime dev-mode bake) + four downstream wiring concerns (binding directory + tsc gate + xtask wrapper + CI step). Plan synthesis defers the probe to /implement Step 1 because taurpc-version-specific API surface is below the abstraction threshold of phase planning.

2. Confirm exact emission API. Likely candidates (in priority order):
   - **(a) Macro arg**: `#[taurpc::procedures(path = "streams", export_to = "../ui/src/bindings/streams.ts")]` — emission at compile time per call-site, output path relative to the source file. Most idiomatic for taurpc; matches the per-router-file pattern already established.
   - **(b) Build script**: `pulse-app/build.rs` invoking `taurpc::ts::export_to(...)` or similar; runs at `cargo build` time.
