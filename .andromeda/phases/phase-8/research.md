## Patterns detected

- **execFileSync direct-`.mjs` invocation pattern** (`pulse-app/ui/scripts/build.mjs:24-27`): wraps tooling that ships an npm `.cmd` Windows shim. Bypass via `execFileSync(process.execPath, [<entry-point-mjs>, ...args])` — verified working for Tailwind v4. Same pattern needed for Vite: `execFileSync(process.execPath, [<root>/node_modules/vite/bin/vite.js, "build"], {...})` (vite ships ESM entry at `vite/bin/vite.js`).
- **Bundle-in-tree, no remote fetch pattern** (`pulse-app/ui/public/fonts/*.woff2` + WOFF2 + OFL license texts committed to git per chunk #10): SVG glyph sources should follow same in-tree pattern. Possible authoring approaches: (a) commit `.svg` source files under `pulse-app/ui/public/icons/` + import as React components via a build step; (b) author SVGs directly as JSX inside `*.tsx` files (no separate `.svg` files, no build-time SVG-to-JSX transform). Approach (b) is simpler + matches design-tokens.md "registered as React components" verbatim + avoids introducing svgr/equivalent build-time tool.
- **`@theme static` + Tailwind v4 utility class scan** (`pulse-app/ui/src/styles/tokens.css:3` + Session Addition 2026-05-03): tokens emit all 33 vars to `:root` regardless of utility-class consumption. ## Conventions to follow

- **Webview source root is `pulse-app/ui/`** (per arch §Project directory structure + chunk #10's already-realized scaffolding); icons land at `pulse-app/ui/src/components/icons/`. Verified path matches design-system.md verbatim.
- **TS/TSX file naming follows React conventions** (per arch §Conventions "Webview source files follow the design specialist's convention"): PascalCase for component files (`Aperture.tsx`, `Telescope.tsx`, `ConstellationGrid.tsx`, `Star.tsx`, `CircularPulse.tsx`) OR all-lowercase-kebab matching glyph names (`aperture.tsx`, etc.). Design-system.md uses kebab-case glyph names in API (`<Icon glyph="constellation-grid" />`); arch defers to design specialist. **Recommend:** PascalCase per-glyph component files matching React conventions, plus a `Icon.tsx` dispatcher accepting `glyph={"aperture"|"telescope"|...}`, plus `index.ts` barrel.
- **Barrel export pattern** (per arch §Conventions "Module visibility discipline" mirrored to webview): `pulse-app/ui/src/components/icons/index.ts` re-exports glyphs + `Icon` dispatcher; consumers import via `@/components/icons` or relative path.
- **Inline-SVG-as-JSX pattern** (per security plan + combined.md security constraint #3): no `dangerouslySetInnerHTML`, no `<img src="...svg">` from `data:` URIs. Glyphs authored as TSX directly with hardcoded `<svg viewBox="0 0 {16|20|24} {16|20|24}" ...><path d="..." stroke="currentColor" fill="..." /></svg>`.
- **`currentColor` for fill/stroke** (per design + a11y bindings): every icon SVG uses `fill="currentColor"` and/or `stroke="currentColor"` — not `fill="#E8EEF7"`. Color cascade from parent CSS `color` property (set via Tailwind `text-text-primary` etc.).
- **Static SVG attributes only** (per security constraint #4-#5): hardcoded `viewBox`, `aria-hidden` (default `true`), `focusable="false"` on `<svg>`. No interpolation of any data props into security-sensitive attrs.
- **Component prop API** (synthesized from design + a11y + layouts): `<Icon glyph={GlyphName} size={16|20|24} aria-label?={string} aria-labelledby?={string} title?={string} className?={string} />`. Default `aria-hidden="true"`; if `aria-label` provided, set `role="img"` and remove `aria-hidden`.
- **Per-glyph component + dispatcher pattern**: each glyph as named React function component (e.g., `export function Aperture(props: IconProps)`) + `Icon` dispatcher that switches on `glyph` prop. Allows tree-shaking (consumer can `import { Aperture } from '@/components/icons'` for a single glyph) AND the design-system.md-prescribed `<Icon glyph="aperture" />` form.
