## Combined goal

Land the project's first React components: 5 custom SVG glyph components (`aperture`, `telescope`, `constellation-grid`, `star`, `circular-pulse`) at `pulse-app/ui/src/components/icons/`, addressable both as named per-glyph components AND via the design-system-prescribed `<Icon glyph="..." />` dispatcher. Each glyph is an inlined React-JSX `<svg>` with `currentColor` fill/stroke (consuming chunk #10's `--color-text-primary` token), static attribute values (no user-input interpolation), `aria-hidden="true"` decorative default with `aria-label`/`aria-labelledby` override flipping to `role="img"`, line-based geometry (no gradients/shadows/animations), and three size variants 16/20/24px (per design-system.md §Iconography). The Observatory / Mission Control metaphor is the brand DNA — generic stock-library shapes (Lucide / Heroicons) are explicitly rejected for these five slots.

Because chunk #11 is the FIRST React-component chunk in the project, this phase introduces the **minimum-viable** React + Vite + TypeScript + Vitest tooling needed to author and unit-test the icon registry: `react@^19.2.0`, `react-dom@^19.2.0`, `vite@^7.0.0`, `@vitejs/plugin-react@^5.0.0`, `vitest@^3.0.0`, `@testing-library/react@^16.0.0`, `jsdom@^26.0.0`, `typescript@^5.7.0`. The fuller stack prescribed by `.claude/rules/frontend.md` (TanStack Router, shadcn/ui, react-hook-form, Zustand, react-aria-components, motion/react) is intentionally NOT introduced here — those land at chunks #13 (a11y dev stack), #15 (motion library), and #25 (webview shell) per route §2. The build pipeline established by chunk #10 (`pulse-app/ui/scripts/build.mjs` orchestrating Tailwind via `execFileSync(process.execPath, [<cli-mjs>, ...args])` to bypass Windows npm `.cmd` shim CVE-2024-27980) is extended to also invoke Vite using the same hardening pattern. The CSP in `pulse-app/tauri.conf.json` already permits `script-src 'self'` — no widening required for React bundle loading. Workspace crate count remains exactly 10 per arch §Occupied Resources LOCKED set; capability files unchanged at 5; Tauri build chain continues to consume `pulse-app/ui/dist/` via `frontendDist` per chunk #10's reconciliation.

The registry's API contract is shaped by cross-domain bindings: security ↔ a11y converges on "static, declarative SVG attributes; aria-hidden default; aria-label override"; design ↔ a11y on `currentColor` propagation + SC 1.4.11 ≥3:1 non-text contrast; design ↔ a11y on `circular-pulse` motion semantics being deferred to consumer surfaces (Halo State Pulse on WebGPU canvas at chunk #28, never as `<animate>` inside the SVG). Consumer surfaces (custom titlebar with aperture + Investigate trigger with telescope at chunk #25, tray icon with star variant at chunk #34) are committed but NOT implemented at this phase — registry components must compile + render in isolation.

## Implementation notes

- **Order sensitivity:** create `package.json` updates + `vite.config.mjs` + `tsconfig.json` + `vitest.config.mjs` BEFORE running any `npm install` (so the install resolves the new deps in one pass). Author the icon component sources before running `npm run typecheck` or `npm run test` (otherwise tests reference non-existent imports and fail). Run `cargo nextest run --workspace --profile ci` first (sanity check that no Rust regressions are pending from prior session before adding new files); should match the 36-test baseline.
- **Windows `npm install` first-run:** the `pulse-app/ui/node_modules/` directory may take several minutes on cold cache. Use `--prefer-offline` on subsequent runs.
- **SVG path geometry authoring:** the 5 glyph paths must be drawn from scratch — no upstream open-source set provides aperture/telescope/constellation-grid/star/circular-pulse in the Observatory Mission Control aesthetic. Plan budgets ~1 hour per glyph for first-pass + iteration. The geometry is judgment-based (no agent-runnable correctness assertion); user review at Phase 6 confirms Sameness Test pass.
- **`circular-pulse` semantic risk:** the glyph name suggests motion but the SVG is STATIC. Make this explicit in `README.md` so future contributors don't add `<animate>` thinking they're "completing" the circular-pulse. The kinetic interpretation lives at chunks #15 (motion tokens) + #28 (Halo State Pulse on WebGPU canvas).
- **Vite output collision risk:** Vite's default behavior is to clean `outDir` before build. The `--emptyOutDir=false` flag is **mandatory** (Vite errors with "outDir is not under root, are you sure you want to empty it?" otherwise; with the flag, Vite leaves the existing `tokens.css` + `fonts/` written by Tailwind step alone). Verified by manual run of build.mjs after Vite addition.
- **JUnit XML path:** Vitest writes to `target/junit-ui.xml` at the workspace root (matching the Rust `target/` convention). Path must be relative-to-vitest-config (`../../target/...` from `pulse-app/ui/`). CI uploads as artifact for agent-parseable test reporting.
- **TauRPC bindings absent:** chunk #11 introduces zero IPC; `pulse-app/ui/src/bindings/` directory referenced by `.claude/rules/frontend.md` is NOT yet created. That lands at chunk #21 (TauRPC routers + TypeScript bindings) per route §2 Epoch 4. Icons compile + render without it.
