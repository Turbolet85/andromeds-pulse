## Combined goal

Wire OTLP span-event decoding through the existing buffer ingestion path so `Span.events[]` (currently traversed by `validate_resource_spans` only down to `span.attributes`) populates the already-reserved `span_events` DuckDB table with `exception.type` / `exception.message` / `exception.stacktrace` attribute values. This extends the L0 (schema population) + L1c (decode in ingestion path) distillation layers per `docs/v0_2_0/pulse-v0_2_0-route.md` §Phase 2 line 225-238 and enables capability P-006 (Exception Event Capture). The chunk is storage-side only — no new TauRPC procedure, no new broadcast topic, no new workspace crate, no arch registry mutation; the `span_events` table is already declared in `crates/buffer/src/schema.rs` (chunk #20 substrate) but unused until now.

Two adjacent disciplines land alongside: (a) the post-`prost`-decode invariant traversal in `crates/ingest/src/invariants.rs::validate_resource_spans` extends into `span.events[].attributes` (closing a documented gap that maps directly to security plan §Input Validation row 1); (b) the production-path `duckdb.append` tracing emission moves from `#[cfg(test)]` wrappers into `crates/buffer/src/consumer.rs::dispatch_batch` (matching the per-table emission shape across all 4 reserved-table writes — spans / span_events / metrics_points / log_records — that the obs plan §4 must-trace P1 contract requires but the current production hot path doesn't actually emit, only tests do). A `duckdb` allowlist entry in `pulse-app/src/observability.rs::AllowList::production()` is added so the new emission's `rows_appended` / `duration_ms` / `table_name` fields aren't silently redacted to `[redacted]` by the default-deny `JsonFieldVisitor` per observability rules 2026-05-03 + 2026-05-07.

Per security plan §Logging "What NEVER to log" rows 1-2, the exception attribute values themselves NEVER reach self-observation logs — only counters + bounded enum tags. A PII negative-canary test (canary string in `exception.message`, asserted absent across the decode + append path via the `CapturingSubscriber + FieldCollector` pattern per testing.md Session Additions 2026-05-11) verifies the redaction discipline at chunk-authoring time. The `span_events.fingerprint BLOB NULL` column is created as a substrate for chunk #66 (exception fingerprinting + retry storm detector) but NOT populated by chunk #65 — verified via "fingerprint accepts NULL inserts" round-trip assertion.

## Implementation notes

- **Schema parity is testably enforced.** The `ddl_constants_match_concatenated_schema` test at schema.rs:332 will fail compile-test if `CREATE_SPAN_EVENTS` const is updated but `SCHEMA_DDL` concat is not (or vice versa). Update both in the same commit; the test is the safety net.
- **Production duckdb.append emission is a small adjacent improvement.** The existing per-table emission lives only in `#[cfg(test)]` wrappers in appender.rs (lines 318/342/365). The obs criterion in combined.md says "ONE event per batch matching the existing spans / metrics_points / log_records pattern at crates/buffer/src/appender.rs:317" — but that line is in a TEST wrapper, not production. To honor the criterion, this chunk lifts the emission to `consumer::dispatch_batch` for all 4 tables. This is wider than chunk #65's literal source-plan scope but minimally adjacent + necessary for the obs acceptance criterion to be verifiable in production. Surface this design decision at Phase 6 review.
- **`duckdb` allowlist entry is REQUIRED for the production emission to be observable.** Without it, `JsonFieldVisitor` redacts all fields of `duckdb.append` events per the default-deny posture (per observability.md 2026-05-03 + 2026-05-07 Session Additions). Test-only emissions don't go through `JsonFieldVisitor` (tests install their own subscriber), so the gap was previously invisible.
- **Span events do NOT increment `BufferState::rows_ingested`.** The existing field has per-batch-type semantics (one increment per Batch::Spans / Batch::Metrics / Batch::Logs); span events are derived from a Batch::Spans batch. Keeping them out of `rows_ingested` preserves the heartbeat tick's "1 batch = 1 increment" arithmetic per chunk #20's design. The span_events count surfaces independently via the new production `duckdb.append` emission's `rows_appended` field (one event per table).
- **`fingerprint` column populated NULL.** Per source plan, chunk #66 fills the column with `hash(exception.type + normalized stacktrace)`. Chunk #65 just creates the column NULL-able and tests that NULL inserts succeed — this gives chunk #66 a stable substrate without requiring a second schema migration.
- **`extract_string_attribute` helper is parametric.** Avoid duplicating the KeyValue-walk-and-extract pattern from `extract_service_name`; introduce a parametric `extract_string_attribute(attrs: &[KeyValue], key: &str) -> Option<String>` helper called once per (event, target_key) pair. Used 3× in `build_span_events_record_batch` (for the 3 exception.* keys). Keep `extract_service_name` as-is (it's a service-name-specific specialization with different semantics — empty-string default vs Option).
- **Test helper copy is the accepted convention.** `CapturingSubscriber + FieldCollector` lives in `pulse-app/src/snapshot_runtime.rs::tests` but cannot be imported into the buffer crate (workspace direction: pulse-app depends on buffer, not vice versa). Copying ~50 lines of test-only helper is the accepted pattern per chunks #41 + #44 precedent — both crates have their own copy. The buffer crate's copy lives co-located in `appender.rs::tests`.
- **No `#[tracing::instrument]` on `build_span_events_record_batch`.** The function takes `&[ResourceSpans]` which doesn't implement Debug (per testing.md 2026-05-11 wasmtime types Session Addition — same Debug-trait absence applies to OTLP proto types via tonic-generated code). Adding `#[instrument]` would require explicit `skip(batch)`. Per the obs criterion the only emission needed is at the dispatch boundary (`duckdb.append`); no per-function span needed. Keep the function plain.
- **Order of edits for /implement to minimize compile breakage:** (1) extend schema.rs first; (2) extend invariants.rs; (3) add build_span_events_record_batch to appender.rs; (4) wire into consumer.rs; (5) add duckdb allowlist + probe test to observability.rs. Each step compiles + tests pass before the next. Doing steps in this order means the wider workspace nextest run is clean at each intermediate state.
