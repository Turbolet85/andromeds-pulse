- **rmcp feature names:** the workspace dep example `features = ["server", "transport-io"]` is illustrative — at /implement time, run `cargo doc --open -p rmcp` or read the crate's README to verify exact feature names (rmcp's server + stdio transport feature names have varied historically across 0.3 / 1.x lines). Pin minimal feature set; expand only if compile-time errors arise.
- **`JsonWithDefaults` duplication:** the chunk #48 sidecar copies the formatter struct from `pulse-app/src/observability.rs`. Duplication is intentional — lifting to a shared `crates/observability-base/` crate is a future refactor (would require extracting 5+ types + AllowList registry to a shared crate). At chunk #48, accept duplication; revisit at chunk #49 or chunk #50 if a second consumer emerges.
- **rmcp stdio loop entry call:** rmcp 0.3.x typically exposes either `rmcp::Server::stdio().await` or `rmcp::transport::stdio::serve(handler).await` (or similar). At /implement, verify the exact entry function from rmcp docs + match against arch's MCP spec requirements (initialize handshake on first frame; tools/list returns `[]` for chunk #48 substrate; tools/call returns `-32601 Method not found` until chunk #49 registers methods).
- **Test 5 (negative compile-time)** in step 12: the cleanest verification is `cargo metadata --format-version 1 | jq '.packages[] | select(.name == "mcp-server") | .targets[] | select(.kind[0] == "bin")'` AND assert the `required-features` field includes `"mcp-server"`. File existence check is secondary (depends on CI artifact paths).

Integration tests should not hardcode `release` vs `debug` — use `env!("CARGO_BIN_EXE_andromeda-pulse-mcp")` (Cargo's per-test env var pointing to the built binary) for path resolution per testing.md §integration patterns.
