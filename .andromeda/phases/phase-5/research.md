## Patterns detected

- **Per-platform data dir resolution** (`pulse-app/src/main.rs:15-36`): `ANDROMEDA_PULSE_DATA_DIR` override → Windows `%APPDATA%\andromeda-pulse` → macOS `$HOME/Library/Application Support/com.andromeda.pulse` → Linux `$XDG_CONFIG_HOME/andromeda-pulse` or `$HOME/.andromeda-pulse` → fallback `$TMPDIR/andromeda-pulse`. Note macOS uses the bundle id literal (`com.andromeda.pulse`) while Linux/Windows use `andromeda-pulse`. Mirror the same lookup in `xtask/src/main.rs:238-260` for `resolve_log_dir`.
- **Writer guard discipline** (`pulse-app/src/main.rs:38,136`): `init_tracing` returns `WorkerGuard`; main holds `let _guard = init_tracing(...);` for the lifetime of `tauri::Builder`. The non-blocking writer is flushed when `_guard` drops at process exit. This is the canonical pattern obs-plan §3 mandates and chunks 7-8 must preserve when the init fn is moved into `pulse-app/src/observability.rs`.
- **Path containment via canonicalize + starts_with** (`pulse-app/src/main.rs:103-125`): `write_pid_file` canonicalizes `data_dir` + `run_dir` then asserts `canonical_run.starts_with(&canonical_data)` before writing the PID file — refuses to write if escape detected. The same pattern (per security plan §Input Validation row "CLI / env var inputs") applies to any path derived from env input. Chunk #7 should adopt this for the logs dir if that path becomes env-overridable.
- **Compile-time service identity constants** (`pulse-app/src/main.rs:12-13`): `SERVICE_NAME` is a `&'static str` literal (the Tauri bundle id), `service_version` is `env!("CARGO_PKG_VERSION")` evaluated at compile time. Per obs-plan §11 Universal anti-patterns: NEVER read `service.name` from runtime env. Chunks 7-8 must keep the compile-time literal; only `ci.run.id` and `git.commit.sha` come from process env at runtime.
- **Explicit `target` on every event** (`pulse-app/src/main.rs:62,87,99,106,112,118,128,131`): every emitted event uses `target: "app.boot.<sub>"` / `target: "app.panic.fatal"` / `target: "app.boot.pid"`. Chunks 7-8 must follow this convention; future heartbeat tick events at chunk #9 will use `target: "{module}.tick"`. The xtask ci-gates greps these target prefixes.
- **xtask panic-detection contract** (`xtask/src/main.rs:177-180`): `if target == "app.panic.fatal" && level == "ERROR"` then violation is recorded. This is the exact contract chunk #7's panic hook already produces (matches case-sensitively). Chunks 7-8 must not regress this.
- **AppError serde-friendly enum** (`crates/ui-bridge/src/contract.rs:5-25`): `#[serde(tag = "kind", rename_all = "snake_case")]` with stable variant names. The scrubber's sanitized one-liner output feeds `AppError::Internal { message: String }`. Chunks 7-8 DO NOT modify this enum; they only ensure the message text is sanitized before construction.
- **Test profile** (`.config/nextest.toml:1-7`): `retries = 0` is the zero-flake invariant. Chunks 7-8 tests must be deterministic; daily-rotation tests using `tokio::time::pause()` keep this invariant.

## Conventions to follow

- **Module visibility discipline** (per `crates/ui-bridge/src/lib.rs:1-5`): each library crate exposes only its public contract module via `pub`; internals are `pub(crate)`. The new `observability` module in `pulse-app` will be `mod observability;` (private to the binary), with all helpers `pub(crate)` or plain `fn`.
- **Workspace dependency style** (per `pulse-app/Cargo.toml:14-23` + workspace `Cargo.toml:24-41`): `crate.workspace = true` in `[dependencies]`; pinning lives once in workspace `[workspace.dependencies]`. Chunks 7-8 add no new workspace deps for the in-scope (no-Sentry) path.
- **Test placement** (per test-plan §4 + observed crate structure): co-located `#[cfg(test)] mod tests { … }` in the source file. New tests for the scrubber Layer + default-fields injection live in `pulse-app/src/observability.rs` `#[cfg(test)] mod tests {}`.
- **Per-test isolation via `tempfile::TempDir`** (per test-plan §3 + obs binding): tests that exercise the daily file sink set `ANDROMEDA_PULSE_DATA_DIR` to a temp dir before calling `init_tracing`, so the developer's real `~/.andromeda-pulse/logs/` is never touched.
- **Constructor-injection over global subscriber** (per test-plan §11 Mocking): tests do NOT call `tracing::subscriber::set_global_default(...)`; instead, build the registry, attach a `tracing_subscriber::with_default(...)` scope guard for the duration of the test, then drop. This avoids "subscriber already set" panics under `cargo nextest run` per-process isolation.
- **Explicit `target` on every emitted event** (project-wide convention, see "Patterns detected"): always pass `target: "{module}.{operation}"` — never rely on default `module_path!()`.
- **Sanitized one-liner for AppError::Internal** (per security plan §Error Handling): when the scrubber Layer produces text destined for `AppError::Internal { message }`, the message must be a single line with no `at /home/...` / `at C:\\...` / `panicked at 'src/...'` / Rust struct path / library version. Full chain stays in `tracing-error::SpanTrace` only.

## Open questions

1. **`with_default_fields` implementation choice.** The obs-plan body sketch references `Layer::with_default_fields([service.name, service.version, deployment.environment])` but `tracing-subscriber 0.3.x` `fmt::Layer` does not expose a method by that name. The three workable approaches:
   - (a) **Custom `FormatEvent` impl** — small wrapper around the JSON formatter that prepends `DefaultFields` keys before invoking inner formatter. Cleanest; ~30 lines of glue.
   - (b) **Root info span pattern** — call `tracing::info_span!("app.session", service.name = ..., service.version = ..., ...).entered()` at the top of `main` and hold the entered guard for the app lifetime; configure the JSON layer with `with_current_span(true)` (already set at main.rs:53). Events inherit parent-span fields. Brittle: requires every spawned tokio task to use `.in_current_span()` to inherit.
   - (c) **Custom `Layer<S>::on_event` impl** — intercept events, mutate fields before forwarding to inner layer. Most flexible but ties the scrubber and default-fields concerns together.
   
   **Recommendation for plan.md:** option (a) — custom `FormatEvent` impl. Keeps the scrubber Layer (chunk #8) and default-fields (chunk #7) cleanly separable; `FormatEvent` is the documented extension point.

2. **CI env var bounding.** `GITHUB_RUN_ID` is a numeric string (≤20 chars typically); `GITHUB_SHA` is a 40-char lowercase hex string. Per security plan §Input Validation row "CLI / env var inputs", both should be bounded before injecting into tracing fields. **Recommendation for plan.md:** validate `ci.run.id` matches `^[0-9]{1,32}$` and `git.commit.sha` matches `^[0-9a-f]{7,64}$`; if validation fails, emit `tracing::warn!(target: "app.boot.ci-fields", ...)` and proceed without the bad field set.

3. **Sentry skeleton scope.** Two options:
   - (i) Add `sentry-rust = "0.46"` and `sentry-tauri = "0.5"` as workspace optional deps + `sentry-redaction` feature flag in `pulse-app/Cargo.toml`, with a real (but minimal) `before_send` body.
   - (ii) Defer entirely — comment-only stub in `observability.rs` documenting the future shape; no Cargo.toml change.
   
   **Recommendation for plan.md:** option (ii) — defer. Per arch "no Sentry feature decision in arch today, a no-op skeleton is acceptable" + per security plan §Dependency Security default-features-minimal pattern. Keep dependency closure tight; activate Sentry in a future scope-arch.

4. **PII scrubber Layer ordering in registry composition.** Layers in `tracing_subscriber::registry().with(...).with(...).with(...)` are stacked outermost-first. The order matters for filtering vs mutation:
   - `EnvFilter` first (filter out events below configured level — never see them)
   - `PiiScrubLayer` second (mutate field set on surviving events)
   - `json_layer` third (serialize the mutated event to file)
   - `ErrorLayer::default()` fourth (capture SpanTrace context for later retrieval at error-bridge boundary)
   
   **Recommendation for plan.md:** lock this ordering; document in observability.rs init body comments. Lock is testable: a unit test enables `tracing_subscriber::registry().with(EnvFilter::new("debug")).with(PiiScrubLayer::new()).with(json_layer)`, emits a synthetic event with a non-allowlisted field, asserts the field is absent in JSON output.

5. **Logs-dir mode 0700 on Windows.** Linux/macOS support is straightforward via `std::os::unix::fs::PermissionsExt::set_mode(0o700)` after `fs::create_dir_all`. Windows has no chmod; ACL-restricting the dir to the current user requires either `windows-permissions` crate, manual `windows-rs` `SetSecurityInfo`, or accepting the OS default ACL (which on a typical Windows install is already restricted to the user via `%APPDATA%`).
   
   **Recommendation for plan.md:** Implement chmod 0700 on Unix-like in chunk #7. Document Windows as "OS default ACL inherited from `%APPDATA%`" with a TODO comment for future explicit ACL hardening if a security review demands it. The security plan §Logging "Access controls" specifies the goal but allows OS-inherited Windows ACLs as a starting state; tightening is a security-scope-arch concern, not chunk #7.

6. **Daily-rotation deterministic test.** `tracing-appender::rolling::daily(...)` uses internal time tracking; it is not directly mockable via `tokio::time::pause()`. Three options:
   - (i) Skip the rotation test entirely; rely on integration smoke at chunk #8 commit (a real overnight run during CI).
   - (ii) Hand-write a small `MockClock` + custom `Rotation` impl for a unit test (maintenance burden).
   - (iii) Test the file-name-formatting + appender-builder behavior independently (not the actual rotation event).
   
   **Recommendation for plan.md:** option (iii) — assert the resolved file-name pattern (`agent-latest.jsonl.YYYY-MM-DD`) is correct via inspecting the appender's directory after a synthetic write; defer real rotation verification to operational testing.

7. **`log_basename` helper placement.** Options:
   - (i) Inline in `pulse-app/src/observability.rs` as `pub(crate) fn`.
   - (ii) Add to `crates/ui-bridge/src/lib.rs` as `pub fn` (since ui-bridge already imports `strict-path` and is the natural shared-utilities home).
   - (iii) New file `crates/ui-bridge/src/path_safe.rs`.
   
   **Recommendation for plan.md:** option (i) — keep it `pub(crate)` in `observability.rs` for now. Chunks 7-8 are the only consumers; later chunks (e.g., plugin loader at route#37) can elevate to a shared crate when there's a second user. Avoids premature abstraction.
