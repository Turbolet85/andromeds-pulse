- **Atomic counter shared via `Arc<IngestState>`** (`crates/ingest/src/state.rs`): single struct holds multiple `AtomicU64`/`AtomicU32` counters; hot-path methods are non-async and use `Ordering::Relaxed`. **LastIngestTracker fits cleanly** as 5th atomic field `last_ingest_at_nanos: AtomicI64` storing `chrono::Utc::now().timestamp_nanos_opt().unwrap_or(0)` (or equivalent unix nanos). - **Heartbeat tick task pattern** (`pulse-app/src/heartbeat.rs:41-81`): `tokio::time::interval(Duration::from_secs(TICK_INTERVAL_SECS))` loop emitting `tracing::info!(target: "{module}.tick", ...)`. **15s cadence is THE invariant** — applies to `connection.tick` heartbeat. NO new panic-hook installation needed — relies on existing app-level hook.

## Open questions

- **Atomic timestamp type:** `AtomicI64` storing unix nanos vs `tokio::sync::watch::Sender<Instant>`. Atomic chosen for read-on-hot-path-no-contention; poller does periodic read. Plan should commit to `AtomicI64` per arch precedent (existing `IngestState` is all atomics).
- **Threshold tuning:** Idle vs Stalled boundary (e.g., Idle after 5s no ingest, Stalled after 30s no ingest, ReceiverFailed after 60s + bind-failed flag). Plan should pick exact thresholds aligned with obs heartbeat-gap CI gate (max 45s gap) — propose Stalled threshold ≤30s so FSM detects stall BEFORE heartbeat-gap CI alarm fires.
- **Subscribe namespace:** `connection.current_state` is point-query; the broadcast topic `pulse://stream/connection-state` needs a subscribe TauRPC method too (mirroring `streams.subscribe_spans`). Either:
  - Add `streams.subscribe_connection_state(channel: Channel<Vec<u8>>)` to existing `StreamsApi` (extends streams crate scope — slight scope creep but architecturally clean)
  - Add `connection.subscribe_state(channel: Channel<Vec<u8>>)` to new `ConnectionApi` (keeps connection namespace self-contained)
  Plan should pick — recommend second (connection self-contained) since the broadcast topic name matches the namespace.
- **Receiver-task panic detection:** Plan should disambiguate (a) rely on stale `last_ingest_at_nanos` + `HeartbeatState::otlp_*_bind == Failed` for ReceiverFailed detection (simpler) vs (b) add explicit `AtomicBool alive` flag set to `false` in a `Drop` guard on each receiver task closure (more direct but more code). Recommend (a) — leverages existing infrastructure; (b) adds zero functional value if the bind-status + heartbeat-stale combination is comprehensive.
- **ConnectionStatePayload location:** Define in `crates/ingest/src/connection.rs` so the FSM + payload share a contract module; router file in pulse-app imports it. OR define in `crates/ui-bridge/src/contract.rs` alongside `AppError` if a11y wants the same `taurpc-runtime`-gated `specta::Type` discipline. Plan should commit — recommend `crates/ingest/src/connection.rs` (cohesion with FSM logic; router file re-imports + applies specta gate at the API impl).
