## Patterns detected

- **N-trait-from-single-Arc<Corpus>** (`crates/corpus/src/contract.rs:53-257`): `Corpus` holds `Arc<Mutex<Connection>>` + path + schema_version + encryption key. Both `CorpusReader` (read-only-by-design per P-051) and `CorpusWriter` (write-side; covers pipeline_metric + service_registry now; chunk #78 extends with incident-shaped methods) impl on the SAME concrete `Corpus`. At binary boundary in `pulse-app/src/main.rs`, derive `Arc<dyn CorpusReader>` AND `Arc<dyn CorpusWriter>` from one `Arc<Corpus>` intermediate (single SQLite connection mutex; single encryption key). The CorpusWriter trait docstring at line 168-196 enumerates the producer-side-PII-scrub invariant — payloads MUST be pre-scrubbed via `security::scrubber::scrub_attribute` at the caller; corpus impl does NOT double-scrub.
- **Per-row UPSERT prepared statement** (`crates/corpus/src/contract.rs:304-335` for `save_service_registry_row`): `ON CONFLICT(service_name) DO UPDATE SET state = excluded.state, ...`. Chunk #78 incidents will use INSERT (incident ids are immutable; status/acknowledged_at/resolved_at change via UPDATE rather than UPSERT). Plain UPDATE statements: `UPDATE incidents SET status = ?, resolved_unix_nano = ?, updated_unix_nano = ? WHERE id = ?`.
- **Cell-level AES-256-GCM at BLOB write** (`crates/corpus/src/contract.rs:259-303` for `save_pipeline_metric` / `load_pipeline_metric`): `let encrypted = cell_encrypt(self.key(), payload)?; ... INSERT ... (?, ?, ?, &encrypted[..])`. On load: `let plaintext = cell_decrypt(self.key(), &encrypted)?;`. The `incidents.payload BLOB NOT NULL` column will store the encrypted serialized `Incident` struct (bincode or serde_json — pattern-wise, chunk #69 uses bincode for state snapshots; chunk #78 incidents can use bincode too).
- **TauRPC `<router>.<verb>` snake_case wiring** (`pulse-app/src/services_router.rs:32-81`): `#[taurpc::procedures(path = "services")]` trait declaration; `#[derive(Clone)]` + `Arc<dyn Trait>` field constructor; `#[taurpc::resolvers] impl ... for ...Impl`; `#[tracing::instrument(skip_all, fields(... = tracing::field::Empty))]` per method; `span.record("field_name", value)` + `tracing::info!(target: "services.list_with_states.request", ...)`. Chunk #78 generates `IncidentsApi` trait + `IncidentsApiImpl` + per-method tracing.
- **Free-function `corpus::Error → AppError` mapper at binary boundary** (`pulse-app/src/storage_router.rs:154-169`): `pub fn corpus_error_to_app_error(err: CorpusError) -> AppError`; sanitized one-liner per-variant message map (`KeyringUnavailable` → "keychain unavailable"; `QueryFailed` → "corpus query failed"; etc.). Chunk #78 reuses this exact free-function (single canonical mapper across all corpus-backed routers); extends with `AppError::NotFound { resource: "incident" }` for "row absent" case via а new helper or via the resolver inspecting query-result Option pattern.
- **Broadcast wrapper around tokio::sync::broadcast::Sender** (`crates/triage/src/lifecycle/broadcast.rs`): `pub const STREAM_NAME_*: &str = "pulse://stream/{kebab}"`; `pub const BROADCAST_CAPACITY: usize = 32`; `pub struct *Broadcast { sender: broadcast::Sender<EventType> }` with `new()` / `sender()` / `subscribe()` / `subscriber_count()`. Cheap to clone (Arc shares); negative-canary PII-field test asserts bounded enum fields only.

## Open questions

- **Q1 — Incident `kind` enum source**: chunk #78 description references "5-min cool-down per kind-and-scope" but the current `triage::contract::Incident` has `severity: Severity` + `priority_tier: PriorityTier` but no `kind` field. Options: (a) add new `IncidentKind` enum (bounded — `ErrorRateSpike`, `LatencyRegression`, `ServiceWentSilent`, `RestartEvent`, `RetryStorm`, etc. — mirroring `CueKind`); (b) reuse `CueKind` directly via `kind: CueKind`; (c) use the `priority_tier` field as the cool-down key. Recommended: (b) reuse `CueKind` — incidents are emitted from cues per dist-arch v3, so kind alignment is natural; saves а new enum.
- **Q2 — Auto-resolution evaluation cadence**: 120s no-reemission window means EITHER (a) per-incident timer (1 tokio task per Active incident; scales linearly with concurrent incidents — acceptable for bounded volume), (b) periodic sweep every 30s evaluating all Active incidents (cheaper steady-state; latency up to 30s for resolution). Recommended: (b) periodic sweep — mirrors chunk #63 restart-event detector cadence + chunk #67 lifecycle heartbeat (60s); single observer task; aggregate tick event per cycle.
- **Q3 — `incidents.list_active()` payload shape**: `Vec<IncidentRecord>` or paginated `IncidentsListPayload { items, total, next_cursor }`? Recommended: paginated envelope (per services_router precedent + arch §Standard Contracts Common response envelope); future-proofs for incident counts >100 even though chunk #78 scope bounded.
- **Q4 — Read-state update trigger**: chunk #78 summary says "Read-state updates on Report-opening event" but Report opens are out-of-scope for chunk #78 (Report generation is chunks #87+). Options: (a) defer read-state update to chunk #87 (read_unix_nano stays NULL throughout chunk #78; counter still works); (b) expose `incidents.mark_read(id)` TauRPC procedure in chunk #78 so future Report-opening callsite can invoke it without adding а new TauRPC procedure later. Recommended: (a) defer — chunk #78 acceptance only requires the corpus column to exist (chunk #68 substrate) + counter SQL to work; read-state mutation is а future-chunk concern. Document the deferral in plan §Acceptance Criteria → Deferred.
- **Q5 — `health.subsystems` corpus health field**: combined.md Cross-domain rot scan flagged this as а unilateral binding (tests mentions; obs silent). Recommended: defer to а follow-up chunk — chunk #78 scope is incidents persistence; adding а `corpus` field к `health.subsystems` is а ui-bridge concern; can land via а micro-chunk OR alongside chunk #79 next.
