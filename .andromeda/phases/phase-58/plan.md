## Combined goal

Chunk #62 transforms the triage crate from passive primitives (chunk #60 contract types + chunk #61 streaming baseline trackers — `EwmaTracker` / `TDigestPair` / `RollingWindow` exposed via `triage::contract`) into the first **algorithmic detection layer** of pulse v0.2.0. The chunk delivers three coordinated pieces: (a) a 1-second background tick task that reads all per-service and per-operation baselines, compares current values against threshold multipliers (3.0× for error rates, 2.5× for latencies), classifies each above-threshold deviation into a `PriorityTier` (`Autonomous` / `Suggested` / `Curious` per chunk #60 contract — see Implementation note 1 for the route §62 "Hard / Medium / Baseline" → contract-name mapping), and emits the resulting `AttentionCue` payloads to a new broadcast topic `pulse://stream/attention-cues`; (b) the boot-wiring that chunk #61 explicitly deferred to chunk #62 per `crates/triage/src/baseline/mod.rs:5` — tapping the OTLP ingest hot path so each decoded span feeds `BaselineState::observe_span(...)`, spawning the chunk #61 corpus persist loop at boot, and registering the on-shutdown persist hook; (c) a parallel `cadence-triggers` channel that re-emits Tier-2 (`Suggested`) cues for downstream consumption by the future Cadence Coordinator (chunk #72).

Per route §3 Decisions Log 2026-05-17 chunk #62 amendment, the chunk implements capability P-021 (Algorithmic Attention Cues) and partial P-019 (PriorityTier classification — Autonomous / Suggested / Curious). Threshold multipliers are loaded from a `Thresholds` config struct with hardcoded defaults this chunk; hot-reload wiring lands in chunk #86. 1. **PriorityTier naming reconciliation (Open question 2 resolved).** Route §2 chunk text says "(Hard / Medium / Baseline based on confidence and magnitude)" but chunk #60 contract at `crates/triage/src/contract.rs:48-54` declares `pub enum PriorityTier { Autonomous, Suggested, Curious }`. Mapping convention documented for future readers: `Autonomous` ≈ "Hard" (high-confidence, prominent halo shift, surfaces with counter increment per capability spec P-019 doc string); `Suggested` ≈ "Medium" / Tier-2 (likely-problem with reservations, quiet counter increment, minimal halo; **THIS is the tier that fan-outs to `cadence-triggers` channel** per route §62 text); `Curious` ≈ "Baseline" (worth recording for pattern learning, no interruption — Findings dropdown collapsed section). 2. **Ingest hot-path tap scope (Open question 1 resolved).** Chunk #62 scope INCLUDES ingest-tap wiring per chunk #61 baseline/mod.rs:5 deferral note. If user prefers narrower scope (just emitter; skip ingest-tap until a later chunk), surface at Phase 6 review BEFORE /implement runs. Skipping ingest-tap means BaselineState never receives spans → emitter has nothing to evaluate → cue emission rate is zero → the chunk is functionally inert as shipped. 3. **Base error-rate floor + warm-up gate (Open question 3 resolved).** Chunk text says "3.0× error rate multiplier" — the multiplier applies to a base error rate (proposed `DEFAULT_BASE_ERROR_RATE: f64 = 0.01` = 1%) for ErrorRateSpike detection. Cues fire only when EWMA value ≥ `base_error_rate × multiplier` (= 0.03 = 3% with defaults) AND samples ≥ `MIN_EWMA_SAMPLES` (= 10) (warm-up gate to avoid noise during cold-start). The "multiplier" is NOT "× the EWMA itself" because that's mathematically degenerate at cold start. /implement Phase 1 may refine if a different semantic is preferred — anchor the test for whichever shape lands.

Cues fire when `live_p95 ≥ previous_p95 × thresholds.latency_multiplier`. If chunk #61 `TDigestPair` does NOT expose `previous_percentile(q)` API, /implement Phase 1 may need to add a minor accessor — flag as a sub-step if so.
