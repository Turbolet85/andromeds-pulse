## Combined goal

Chunk #85 closes the L4 LLM interpretation pipeline by adding the fallback tier prompt + reduced-quality output contract for hardware-constrained tiers (3-4B class models on CPU-fallback profiles). The work is scoped entirely к `crates/interpretation/` (per chunk spec "Crates touched") + the L4 inference subscriber in `pulse-app/src/inference_runtime.rs` (binary boundary tier-dispatch). The fallback prompt occupies а ~500-700 token system budget vs primary's ~800-1000 + instructs the model к emit а single hypothesis instead of а ranked list + up to 2 investigation steps instead of 5. The `model_tier: "fallback"` discriminator embedded in the L4 output JSON enables downstream consumers (future Report UI per P-053; obs aggregation queries today) к stratify primary vs fallback inference outputs. Capability P-053 (Fallback Model Tier — full) reaches "full" status with this chunk; no new TauRPC procedures, no new broadcast topics, no new workspace deps, no new env vars, no arch registry changes — pure additive extension of the existing chunk #82/#83/#84 substrate per arch §Established Decisions [LLM Inference Runtime — L4 interpretation layer] bus-factor discipline.

The implementation reuses the existing `LlmInferenceRunner` trait surface (chunk #82) + `LlamaCliInference` concrete subprocess impl (chunk #84) + `L4_OUTPUT_JSON_SCHEMA` JSON schema (chunk #83) unchanged. Fallback tier dispatch happens at the L4 subscriber (`pulse-app/src/inference_runtime.rs::handle_digest`) which currently always calls `build_primary_tier_prompt`; chunk #85 branches on `runner.tier()` к select primary vs fallback prompt builder. Defense-in-depth: post-parse validation in `crates/interpretation/src/schema.rs::validate` is extended to enforce tier-specific bounds (1-hypothesis / ≤2-step cap when `model_tier == "fallback"`) on top of the prompt-level constraint. Per security plan §Anti-Patterns Code Patterns + obs plan §11 cardinality discipline, no new fields are admitted к the observability AllowList — all `interpretation.*` + `metric.pipeline.l4.*` targets already permit `model_tier` field values from chunks #82/#83.
