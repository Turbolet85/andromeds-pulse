## Combined goal

Deliver the read-only L6 self-observability surface — a "Settings → Diagnostics" view bringing the pipeline's own state into one webview surface (capability P-058) — by extending the existing `diagnostics.*` TauRPC router with two procedures and adding a new `Diagnostics.tsx` webview surface with five sections (Connection / Model / Pipeline / Hardware / Templates). Per the Phase-3 producer-check, `pipeline_metrics` is an opaque latest-only state-snapshot store (not numeric metric-history) and no production path records per-metric numeric time-series, so this chunk takes the **hybrid-render** path: `diagnostics.snapshot()` aggregates the live in-memory state that genuinely exists (connection state, model tier/profile/load-status + backoff countdown from the degraded-mode FSM the router already holds, Drain template distribution + count, hardware profile label), and explicitly marks the not-yet-produced sub-fields (inference success rate, queue depth, full L0-L5 per-layer numerics, 30-day history) as "not yet recorded"; `diagnostics.history(metric_name, window_seconds)` lands as a validated stub returning an empty series + a degraded notice. The surface reuses existing read resolvers where they exist (`connection.current_state` #59 for the Connection section; `diagnostics.template_distribution` #69 + the existing `TemplateDistribution.tsx` for the Templates section) per arch §Cross-cutting HYBRID-RENDER discipline, so `snapshot()` carries only the Model/Hardware/Pipeline self-observability data that has no dedicated resolver yet. Per security plan §Error Handling + §Logging, both procedures return `Result<T, AppError>` with aggregate-only tracing; per arch §Occupied Resources the arch-registry delta is exactly +2 TauRPC procedures (no new env var / table / broadcast topic / workspace dep). Scope reconciliation vs source §95: because the hybrid path runs NO corpus time-series query, `crates/corpus/` is NOT touched this chunk (the source-§95 "metric history queries" + the prepared-statement / query-anonymizer constraints are N/A-by-construction); the real-history producer + corpus query path is deferred to a future chunk once a numeric-metric-history producer exists.
