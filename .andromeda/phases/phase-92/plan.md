## Combined goal

Add a privacy-preserving "Export for community training" action to the Settings → Storage surface that produces an anonymized JSONL dump of the incident corpus (one record per incident: trigger context, model interpretation, user feedback, resolution outcome). A pre-write **preview** dialog shows what will be exported (count by status + severity, date range, anonymization-confirmed) BEFORE any file is written; the user explicitly confirms; the file is written locally (default `~/Downloads/pulse-corpus-export-{timestamp}.jsonl`) and **never auto-submitted** — the user manually shares it. This is the L5 export channel (capability P-046), the terminal chunk of the route. Backend = one new TauRPC procedure `storage.export_for_training` in the existing `storage.*` router (`pulse-app/src/storage_router.rs`) reading the corpus via a new `CorpusWriter::load_all_incidents()`, with PII scrubbed at the egress boundary via `security::scrubber::scrub_attribute` (defense-in-depth, per the chunk #88 `incidents.get_report` resolver-scrub precedent). Frontend = a new `ExportForTraining` component mounted in a new Storage section of the chunk #38 Settings modal, reusing the chunk #37 `Modal` primitive for the preview/confirm dialog. Per arch §Occupied Resources (`storage.*` namespace) + security plan §API/§Input/§Logging + obs-plan §6/§8 + design-system §Per-Surface Bans + a11y plan §4/§5/§7 + tests §6/§11. **Workspace deps delta = none; arch registry delta = +1 TauRPC procedure.**

## Implementation notes

- **Surface the two design decisions in Phase 1 of /implement** (both already in research Open Questions 1+2): (a) the `~/Downloads` out-of-data-dir default + optional `target_path` override + NO native picker (preserves deps-delta=none); (b) the `confirm: bool` preview-then-write gate on the single procedure. Both are recommended-resolved here; if the user prefers a different shape (e.g., a separate `storage.preview_export` procedure), re-plan.
- **Order**: land Steps 1-9 (backend) to capability-drift-clean BEFORE Steps 10-11 (UI) — the bindings.ts the UI imports come from the backend emit.
- **Nested modal**: the preview `Modal` opens over the Settings `Modal` (two FocusTraps; v12 stacks/pauses). If vitest trap-stacking proves fragile, fall back to a single in-section confirm step with `aria-modal` semantics (still a distinct confirmation gate, not inline-bypassing).
- **Determinism**: thread an injected `now_unix_nano: i64` through `resolve_default_target` + any date-range computation so unit tests assert exact filenames/ranges (NEVER `SystemTime::now()` in the testable path; CLAUDE.md tokio-time/clock-injection discipline).
- **Export scope**: `load_all_incidents` reads ALL incidents (any status, any workspace) — full corpus dump; resolved incidents carry `resolution_summary_text` (interpretation), active ones null. Digests are NOT exported (no `load_digest` read; incidents are the L5 record unit).
- **bincode parity**: decode with plain `bincode::deserialize::<Incident>` (no `Options`) to match the `CorpusIncidentPersistence` producer.
- **pulse-app tests = integration tests** (`[lib] test=false`): all resolver/module tests in `pulse-app/tests/*.rs`; the `load_all_incidents` test stays co-located in `crates/corpus/src/contract.rs::tests`.
