Implement the production Drain3 Rust port behind the L1c log-template-mining layer (capability P-007), threading template assignment into the OTLP log-record ingestion hot path at `crates/buffer/src/appender.rs` between OTLP decode and DuckDB append with a per-event latency budget of <50μs p99 (Phase A spike measured 2μs in isolation — 25× headroom). The implementation extends the existing `crates/buffer/` crate with a new `drain` module (DrainMiner + DrainTree + DrainConfig + regex-config-driven masker + LRU eviction at `max_clusters=1000`), wires a new `log_templates` table + `log_records.template_id` nullable column into the in-memory DuckDB ring buffer schema (extending RESERVED_TABLES from 7 to 8), persists the template tree to the corpus SQLite substrate (chunk #68) via a NEW `DrainPersistence` trait pattern (trait-in-lower-crate per CLAUDE.md 2026-05-16; `CorpusWriter` trait added to corpus crate to complement the read-only `CorpusReader`), exposes a `diagnostics.template_distribution()` TauRPC procedure following the storage_router.rs precedent (free-function `drain_error_to_app_error` at binary boundary per CLAUDE.md 2026-05-18 orphan-rule pattern), and surfaces a Settings → Diagnostics "Template Distribution" panel (`TemplateDistribution.tsx`) rendering the top-50 templates as a semantic `<table>` with `aria-live="polite"` restart-required notice per P-055.
