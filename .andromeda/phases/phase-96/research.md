## Patterns detected

- **In-process loopback load pattern** (`pulse-app/tests/perf_slo_10k_spans.rs:23-50`): ephemeral gRPC receiver + real DuckDB connection + `run_consumer` task + tonic client batching `BATCH_SIZE`-span requests against `TARGET_SPANS`/`TIMEOUT_SECS` consts. The four-profile suite extends THIS pattern (parameterize rate × duration × pass criteria), not a new mechanism.
- **Workflow self-lint pattern** (`a11y_perf_workflow.rs` / `quality_gate_workflow.rs` / `distribution_manifests.rs`): pure file-read + substring/pattern assertions over `ci.yml` + `.config/nextest.toml` guard gate posture. Any new gate wiring must extend these self-lints in the same commit.
- **NEUTRAL-pass activation discipline** (`xtask/ci/perf-slo-check.sh:18-33`, `l4-latency-p99.sh` INACTIVE note): check scripts exit 0 with a notice when their metric stream is empty (webview not booted / L4 not configured), and activate organically when records appear. The chunk's booted-app load window flips these from NEUTRAL to ACTIVE.
- **Env-var-gated real-runtime tests** (`integration_real_llama_cli.rs:6-20`): three env vars present → real subprocess coverage; absent → eprintln skip + early return, never a failure. The per-hardware-profile latency verification follows this gating shape (profile pinned via `ANDROMEDA_PULSE_HARDWARE_PROFILE`).
- **A11y pipeline chain + tuple regression** (`package.json test:a11y` + `tests-a11y/{aggregator,regression-detector}.mjs` + `baselines/a11y-violations-summary.json`): contrast → axe → lighthouse → pa11y → aggregate → regression-detect against the checked-in baseline. Re-baselining = regenerating the summary after a zero-violation pass over the extended surface set.
- **Capability citations in test doc-comments**: E2E files cite P-XXX ids in `//!` headers (`e2e_pii_scrubber_persistence_coverage.rs`, `e2e_p3_mcp_incident_tools.rs`, etc.) — the capability matrix can bind P-ids to NAMED existing tests; the mapping mostly exists in prose and needs formalizing into a machine-parseable artifact.
- **Paired-script convention** (`xtask/ci/*.{sh,ps1}`): every CI check ships both shells; any new check script must too.
