## Patterns detected

- **`Settings` is the single config surface** (`crates/ui-bridge/src/contract.rs`): all hot-reload candidates already live here + `validate()` already enforces bounds + `load_from_data_dir` already parses `<data_dir>/config.toml`. The watcher re-loads + re-validates through THIS surface — no parallel config struct. (Settings-extension precedent, CLAUDE.md 2026-05-09.)
- **Read-once-at-boot consumers** (main.rs §boot + cadence/coordinator.rs): cadence coordinator, lifecycle heartbeat, and the cue/baseline/storm tick loops all capture config at spawn. There is NO existing live-reconfiguration channel. This is the central implementation gap: hot-reload delivery must be ADDED to each consumer that needs live application.
- **Broadcast topic pattern** (cadence/broadcast.rs): thin `broadcast::Sender` wrapper + `pulse://stream/<kebab>` const + capacity 32 + aggregate-only `#[derive(Serialize)]` payload + PII-negative-canary test. Directly templatable for `ConfigEvent` + `ConfigEventBroadcast`.
- **TauRPC router pattern** (diagnostics_router.rs): trait + `Impl` + resolvers + instrument + free-fn error map. `config.*` is a new dotted namespace; `diagnostics.reevaluate_recent_window` extends the existing `diagnostics` trait.
- **`tokio::sync::watch` is the zero-new-dep delivery mechanism** (Cargo.toml tokio "full"): a `watch::Sender<HotConfig>` published by the watcher + `watch::Receiver` select-arms in consumer loops gives prospective live application without `arc-swap`. The cadence broadcast/cue precedents use `tokio::sync::broadcast`; `watch` (latest-value, no backlog) is the better fit for "current config" semantics.

## Conventions to follow

- **Capability registration = description-block only** (capabilities/default.json): append a `config.{reload,status}` (+ optional `diagnostics.reevaluate_recent_window`) sentence to the `description` string; do NOT add permission array entries. `cargo xtask capability-drift` reads the merged `bindings/index.ts`, not the JSON permissions (per CLAUDE.md 2026-05-03/2026-05-12 quadruple-binding).
- **Quadruple+ binding for new TauRPC namespace** (CLAUDE.md 2026-05-12): router registration in main.rs `.merge(...)` chain + `pulse-app/capabilities/default.json` description + `xtask/src/main.rs::EXPECTED_PROCEDURES` + the `emit_taurpc_bindings` test's `.merge(...)` chain. Multi-line trait doc goes ABOVE the `#[taurpc::procedures]` macro (2026-05-25).
- **Cross-crate state via trait-in-lower-crate + `Arc<dyn Trait>`** / **errors via free-fn `map_err` at the binary boundary** (CLAUDE.md 2026-05-16 / 2026-05-18): if a watcher lives in a lower crate and a consumer in another, deliver via `Arc<dyn Trait>` / `watch::Receiver` injected at the pulse-app boundary; convert watcher errors → `AppError` via a free fn in the router file.
- **Async-trait via manual `Pin<Box<dyn Future + Send + 'a>>`** (CLAUDE.md 2026-05-23) if any async hook crosses the boundary — no `async-trait` dep.
- **Aggregate-only self-observation fields** (CLAUDE.md 2026-05-17 session 84 + observability.rs AllowList): the `config.*` tracing targets + `config-events` payload carry bounded counts + enum labels + sanitized field names ONLY — never raw config values / full paths / secret-shaped strings. New targets need explicit AllowList entries in `pulse-app/src/observability.rs` (default-deny redaction).
- **pulse-app tests live in `pulse-app/tests/`, NOT source-level `#[cfg(test)] mod tests`** (CLAUDE.md 2026-05-20): `[lib] test = false` means source-level pulse-app tests never run. A NEW lower crate (`crates/config-watcher/`) CAN carry co-located `#[cfg(test)] mod tests` that run normally.
- **Time-deterministic tests** (testing.md): `#[tokio::test(start_paused = true)]` + `tokio::time::advance` for debounce/apply-window; NEVER `sleep(N)`. Note `start_paused` requires `current_thread` flavor + `tokio` `test-util` dev-feature (CLAUDE.md 2026-05-03 / 2026-05-06).
- **`notify` dep discipline** (security.md + CLAUDE.md 2026-05-03): pin a version, pass `cargo deny check bans licenses sources`; add new transitive duplicates to `deny.toml [bans] skip` with provenance (do not relax `multiple-versions = "deny"`).
