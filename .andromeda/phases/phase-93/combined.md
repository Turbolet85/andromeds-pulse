## Per-chunk extracts

### Chunk route#96: "Configuration hot reload + prospective threshold application"

Capabilities P-055 (Configuration Hot Reload) + P-056 (Prospective Threshold Application). Filesystem watcher on `~/.andromeda-pulse/config.toml` (500ms debounce); hot-reloadable keys (thresholds, cadences, severity rules, suppression, lifecycle boundaries) apply ≤2s; restart-required keys (Drain params, model path, ports, storage path) raise a Diagnostics notice without applying; threshold changes apply **prospectively** (no baseline reset, no retroactive rolling-window re-eval); opt-in `diagnostics.reevaluate_recent_window()` action provides retrospective application; malformed config rejected with previous valid config retained.

**Constraints across domains:**

- (arch) **Config precedence is fixed**: env vars `ANDROMEDA_PULSE_*` > `~/.andromeda-pulse/config.toml` > built-in defaults. Hot-reload MUST reapply file-tier values only and MUST NOT override a key an env var has already set (per arch §Cross-cutting Patterns "Config management").
- (arch) **Hot-reload target already lives in `Settings`**: re-load + re-validate through the existing `crates/ui-bridge/src/contract.rs::Settings` (loaded via `Settings::load_from_data_dir`, validated via `Settings::validate()` with `_MIN`/`_MAX` bound constants; cadence keys from chunk #80 are the prime target) rather than a parallel config struct (per arch §Cross-cutting Patterns config management + §Occupied Resources `get_settings`/`update_settings`).
- (arch) **Restart-required vs hot-reloadable partition** maps to arch-locked one-time-init substrate: Drain params, model path, OTLP `:4317`/`:4318` binds, storage/data-dir path are init-time — they raise a Diagnostics notice via the new broadcast topic, never apply live (per arch §Established Decisions [Telemetry Retention] / [Database] / [LLM Inference Runtime]).
- (arch) **`config.<verb>` dotted-namespace `snake_case`** procedure shape; the dedicated `config.*` namespace is justified because reload/status are *operations*, not get/set state (per arch §Conventions "Endpoint naming").
- (security/arch) **The watched config path MUST canonicalize + confine**: if resolved from `ANDROMEDA_PULSE_CONFIG_PATH` / `ANDROMEDA_PULSE_DATA_DIR`, `canonicalize()` + assert resolved path under the data dir via `strict-path` BEFORE the `notify` watcher attaches (per security plan §Input Validation "CLI / env var inputs" + §Anti-Patterns §Input; arch §Critical Warnings path-env-var rule; CWE-22). NOTE: `ANDROMEDA_PULSE_CONFIG_PATH` is tagged deferred (no runtime consumer as of chunk #74) — confirm at /implement Step 1 whether this chunk activates it or stays on the fixed `<data_dir>/config.toml`.
- (security) **Validate every reloaded field before applying**: shape via `serde`; port via `TryFrom<u16>`; retention bounded; log level enum; thresholds positive; multipliers in allowed ranges — malformed config rejected with previous valid config retained (per security plan §Input Validation "Configuration values — `config.toml`").
- (security) **`notify` dep pinned** in workspace `Cargo.toml` (no `*`/`latest`); passes `cargo audit` + `cargo deny check bans licenses sources`; new transitive duplicates → `deny.toml [bans] skip` with provenance, never relax `multiple-versions = "deny"` (per security plan §Dependency Security + CLAUDE.md 2026-05-03 deny-skip discipline).
- (security/arch) **+2 TauRPC procedures return `Result<T, AppError>`** AND have a `pulse-app/capabilities/` JSON entry (negative-default; router registration alone is a silent runtime rejection) (per security plan §API Security + arch §Cross-cutting "Webview IPC capability policy" + §Critical Warnings).
- (security) **config-watcher MUST NOT pass any reloaded config string to `tokio::process::Command`** (model-path / Drain-param keys are restart-required NOTICE-only) (per security plan §Anti-Patterns §Code Patterns; command-injection ban).
- (tests) New `crates/config-watcher/` (+ `crates/triage/` hooks) carries co-located `#[cfg(test)] mod tests`; new code meets Standard-tier coverage ≥75% line / ≥70% branch / ≥85% function (per test-plan §10 + §4).
- (tests) Watcher tests self-bootstrap via `tempfile::TempDir` + `ANDROMEDA_PULSE_DATA_DIR` override (write `config.toml`, then mutate it); NO committed config fixtures (per test-plan §3 + §11).
- (tests) **500ms debounce + ≤2s apply timing tested deterministically with `tokio::time::pause()` + `advance()`** (`#[tokio::test(start_paused = true)]`), NEVER `sleep(N)` / real wall-clock (per test-plan §8 Time + §11 bans).
- (obs) Config load/reload is a boundary that MUST emit structured logs: success → `info` (which keys reloaded, count, last-reload timestamp); validation/path failure → `warn`; use `{module}.{operation}` target naming (per obs-plan §6 Log levels + §2/§4 naming).
- (obs) TauRPC handlers `config.reload`/`config.status` instrumented with `#[tracing::instrument(skip_all, fields(traceparent = %tp))]` extracting the IPC-envelope traceparent (per obs-plan §3 IPC trace-context propagation + §4).
- (obs) **Config keys Low-classification + OK to log structurally, BUT** redact secret-shaped keys (`*_SECRET`/`*_TOKEN`/`*_KEY`) and log file-path values basename-only — never the full canonicalized config/data-dir path (per obs-plan §8 Data classification + Vector 6 CWE-22).
- (design) IF a restart-required notice / reload-status indicator renders, use only design tokens (container = `--color-raised-1` + subtle border + `--spacing-md` + `--radius-md`); no hardcoded hex/px (per design-system §Color Palette + §Border Radius + Component Patterns Cards/Panels).
- (design/a11y) **Not-color-alone**: any restart-required / reload-failed / reload-OK state MUST pair color with a text label and/or icon (per design-system §Anti-Patterns Universal Bans + a11y plan §6 / §11 Visual SC 1.4.1).
- (a11y) IF a dynamic status notice renders in webview, it MUST live in an `aria-live` region (`polite` for confirmations / last-reload timestamp; `assertive`/`role="alert"` for config-rejected errors) and MUST NOT steal keyboard focus on async appearance (per a11y plan §7 Live regions + §11 Status Messages SC 4.1.3 + §4 P4).

**Patterns к follow:**

- (arch) Settings-extension over new namespace where state fits the `Settings` shape (bool flags / enum choices / scaled-integer tuned values flow through `get_settings`/`update_settings`); reserve `config.*` for reload/status operations (per arch §Conventions).
- (arch/security) Cross-crate async state delivery WITHOUT `async-trait` dep: manual `Pin<Box<dyn Future + Send + 'a>>` return types (chunk #80 `SqlQueryRunner` precedent); cross-crate sync state via trait-in-lower-crate + `Arc<dyn Trait>` injection at the binary boundary (per arch §Cross-cutting Module dependency direction).
- (security) Cross-crate error mapping: convert watcher/parse errors → `AppError` via a free `fn …_error_to_app_error(...)` in the pulse-app router file (orphan-rule-safe), not an `impl From` in ui-bridge/watcher (CLAUDE.md 2026-05-18 free-fn map_err precedent).
- (security/arch) Float-shaped tunables stored as scaled integers (`_x100`/`_x1000`) to preserve `Settings`' `Eq` derive (CLAUDE.md 2026-05-19 `drain_similarity_x100` precedent; arch §Established Decisions [Validation Library]).
- (security) Bounded-cardinality `_label: String` for any cross-crate enum referenced in the `config-events` broadcast payload (CLAUDE.md 2026-05-24 precedent).
- (obs) Boundary-call wrapper logging: `method_name` + `argument_digest` (hash, not content) + `result_type` + `latency_ms`, matching the established `ui-bridge` TauRPC allowlist (per obs-plan §6 + §8 whitelist).
- (obs) New broadcast topic follows the real-time-push pattern: emit site span-wrapped (`channel_name`, `payload_size_bytes`), Tauri 2 IPC `Channel`, `pulse://stream/<kebab>` naming (per obs-plan §4 P6 + arch §Standard Contracts real-time push).
- (obs) Self-observation via `tracing` + `tracing-subscriber` JSON + `tracing-appender` file sink ONLY (NO OTel SDK); config-watcher emits into the shared JSON sink (per obs-plan §3).
- (design) Notice container reuses the Cards/Panels primitive (borders-only depth, NO shadow/gradient); error state reuses documented Error state (`--color-accent` border + icon + ≤2-line message); prefer custom `aperture` glyph for config semantics (per design-system §Surface desktop-webview Component Patterns + §Iconography).
- (a11y) Status-message pattern: `role="status"`/`aria-live="polite"` (confirmations) vs `role="alert"`/`aria-live="assertive"` (config-rejected); reduced-motion override via `motion-reduce:` variants (per a11y plan §4 + §6 + §7).

**Anti-patterns к avoid:**

- (security) NEVER read the `ANDROMEDA_PULSE_*_PATH`/`*_DIR` env var resolving the watched location without `canonicalize()` + assert-under-data-dir (TOCTOU / symlink traversal) (per security plan §Anti-Patterns §Input).
- (security) NEVER apply a reloaded value before validation; reject-and-retain-previous is mandatory — never partially-apply or zero out live thresholds (per security plan §Input Validation config row).
- (security/obs) NEVER log raw `config.toml` contents, reloaded values, or full file paths in watcher tracing events / `config-events` payload — emit field names + sanitized reasons / basename only (per security plan §Logging NEVER-log list + obs-plan §11 + Vectors 3/6).
- (obs) NEVER emit a multi-line deserialize/`thiserror` stack trace on malformed-config rejection — one-line sanitized SpanTrace; never serialize `anyhow::Error` across the IPC boundary (per obs-plan §11 + Vector 2).
- (obs) NEVER let a tight `notify` debounce/event loop log at `info` per filesystem event — gate verbose per-event detail behind `debug`/`trace`; only the settled 500ms-debounced outcome warrants `info` (per obs-plan §11 Logs hot-path ban).
- (arch) NEVER bind a new network surface/socket (config-watcher is filesystem-only; OTLP stays loopback `:4317`/`:4318`); NEVER add a new env var beyond the `ANDROMEDA_PULSE_*` namespace without a registry amendment; NEVER let hot-reload mutate locked startup-time decisions live (per arch §Occupied Resources + §Established Decisions).
- (design/a11y) NEVER convey reload state by color alone; NEVER ship a dynamic status surface without an `aria-live` region; NEVER use `alert()`/`confirm()`/native dialogs; NEVER use banned/generic fonts (per design-system §Anti-Patterns + a11y plan §11).
