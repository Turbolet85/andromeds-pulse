Implementation verifies against crates.io at write-time.
2. **Capability JSON permission shape for taurpc procedures**: Tauri 2.x capability `"permissions"` array typically lists strings like `"core:default"` or `"plugin-name:permission-name"`. For `taurpc`-registered procedures, the permission identifier shape may be `"taurpc:health"` or just `"health"`. Verify against `taurpc` 0.6+ docs / examples at implementation. If unclear, surface to user at Phase 6 review.
3. **Subsystem placeholder values in `health` envelope**: tests-plan §3 says receiver subsystems initialize as placeholder values (e.g., `"initialized": false`) at chunk #4 since chunks #15-#18 implement actual receivers. The placeholder shape: should each subsystem be `SubsystemStatus { status: "initialized", error_msg: None }` or just a string `"initialized"` as arch shows? Tests-plan + obs-plan use object form; arch §Standard Contracts shows string form ("ok" or failure-reason). Plan should pick the object form (matches tests + obs canonical extension).
4. **PID file primary location decision**: tests-plan §1 + §3 specify `$XDG_RUNTIME_DIR/andromeda-pulse.pid` primary on Linux, with `~/.andromeda-pulse/run/andromeda-pulse.pid` fallback. The shell scripts use `$DATA_DIR/run/andromeda-pulse.pid` (the fallback location, not XDG_RUNTIME_DIR primary). At chunk #4 implementation, the pulse-app binary writes PID — should it follow XDG_RUNTIME_DIR primary (more correct, but adds platform-dispatch logic) OR the script's `$DATA_DIR/run/` (simpler, consistent with existing harness)? Plan should pick the simpler path consistent with existing scripts; bump to XDG_RUNTIME_DIR if test-plan strictly requires.
5. **`harness:boot` / `harness:cleanup` xtask subcommands**: should the scripts' inline boot/cleanup logic be moved into xtask subcommands now (single source of truth) OR stay in scripts (simpler at chunk #4)? combined.md tests extract uses `bash scripts/agent-run.sh boot` in AC; arch extract says harness surface is `cargo xtask <subcommand>`.
