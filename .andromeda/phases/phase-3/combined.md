## Per-chunk extracts

### Chunk route#4: "xtask agent-run harness — 5-command discipline (boot/run/status/cleanup/logs) + health TauRPC command (status/subsystems/pid/uptime_ms) + PID file + JSON log format"

**Constraints across domains:**

- (security) `health` TauRPC procedure MUST be registered in BOTH the owning `ui-bridge` router AND `pulse-app/capabilities/default.json` — Tauri 2 capabilities are negative-default; missing entry = silent runtime rejection (per security plan §API Security TauRPC capability authorization).
- (security) `health` MUST return `Result<HealthEnvelope, AppError>` — `AppError` is the `serde`-friendly enum (`Validation`/`NotFound`/`Internal`/`Plugin`/`Storage`/`Ingest`); never serialize `anyhow::Error` directly across the bridge (per security plan §Error Handling TauRPC bridge).
- (security) PID file path resolution MUST canonicalize via `strict-path` and assert resolved path lives under the resolved data dir (or `ANDROMEDA_PULSE_DATA_DIR` override) — CWE-22 path-traversal class defense (per security plan §Input Validation env-var row).
- (security) `xtask` MUST NOT pass externally-sourced strings into `tokio::process::Command::new(...).arg(...)` without prior validation — MCP STDIO command-injection class (per security plan §Anti-Patterns Code Patterns).
- (security) JSON log format MUST apply field redaction at the `tracing-subscriber` Layer (not at log call sites); NEVER-log list enforced from day 1 (per security plan §Logging & Monitoring + `logging-redaction-wire` bootstrap).
- (security) `health` envelope MUST sanitize internal subsystem identifiers to stable Standard-Contract strings (`otlp_grpc_receiver`, `otlp_http_receiver`, `buffer`, `ingest_channel`); failure reasons collapse to short strings with no Rust struct names / file paths / library versions.
- (arch) Harness code lives in `xtask` crate (workspace-reserved name); `health` command implementation lives in `ui-bridge` crate; neither relocatable / renamable / mergeable (per arch §Occupied Resources + §Inherited Defaults).
- (arch) `health` TauRPC procedure MUST conform to §Standard Contracts envelope: top-level bare `snake_case` verb (no router prefix), returning `{ status, checked_at, subsystems }` with `status ∈ {"ok","degraded"}`, `checked_at` as RFC 3339 UTC, `subsystems` as string-keyed map. Note: tests-plan §3 + obs-plan §3 both extend this with `pid` + `uptime_ms` fields per the chunk title — this is the canonical envelope at chunk #4 implementation time.
- (arch) PID file location MUST sit under the per-platform resolved data root respecting `ANDROMEDA_PULSE_DATA_DIR` overrides; no new top-level subdir beyond `config.toml` / `plugins/` / `snapshots/` / `logs/` without scope-arch event (per arch §Occupied Resources Filesystem locations).
- (arch) JSON log format emission targets `~/.andromeda-pulse/logs/`; uses no OTLP network exporter — self-observation is `tracing` + file/stdout sinks only (per arch §Established Decisions [Self-Observation]).
- (arch) 5-command harness surface realized through `cargo xtask <subcommand>` only — `xtask` is locked CI task runner (per arch §Stack + §Cross-cutting Patterns Development Style).
- (tests) 5-command discipline MUST be materialized in `scripts/agent-run.sh` (or xtask equivalent) per test-plan §3 5-command implementation bodies (per test-plan §3 Bootstrap phase 2 `5-command-discipline-wire`).
- (tests) `boot` MUST poll `health` TauRPC every 500ms up to 10s timeout, asserting `status == "ok"` AND `subsystems.otlp_grpc_receiver.status == "initialized"` AND `subsystems.buffer.status == "ready"` before returning exit 0.
- (tests) `health` MUST return canonical envelope: `status` enum + `subsystems` object with otlp_grpc_receiver + otlp_http_receiver + buffer + ingest_channel + `pid` + `uptime_ms` (binding contract — both surfaces share one shape).
- (tests) Receiver subsystem statuses (otlp_grpc_receiver / otlp_http_receiver / buffer / ingest_channel) initialize as placeholder values at chunk-completion time since chunks #15-#18 implement actual receivers; envelope must accept canonical key set BEFORE subsystems exist.
- (tests) `cleanup` MUST be idempotent (kill -TERM + wait + escalate kill -9 if needed); second invocation no-op.
- (tests) `logs` MUST emit Rust `tracing` JSON-lines with required fields `timestamp` / `level` / `target` / `message` / optional `fields`.
- (tests) PID file location MUST follow XDG-spec primary `$XDG_RUNTIME_DIR/andromeda-pulse.pid` with `~/.andromeda-pulse/run/andromeda-pulse.pid` fallback (Linux), `$TMPDIR/andromeda-pulse.pid` (macOS), `%LOCALAPPDATA%\andromeda-pulse\pid` (Windows); written at `boot` after `ready` confirms; format is single decimal PID.
- (obs) Service identity is compile-time per obs-plan §3: `service.name = "com.andromeda.pulse"` (Tauri bundle id, fallback `env!("CARGO_PKG_NAME")`); `service.version = env!("CARGO_PKG_VERSION")`; `deployment.environment = "production"`. NEVER hardcode `"myapp"`.
- (obs) Log file path FIXED per obs-plan §3: `~/.andromeda-pulse/logs/agent-latest.jsonl` default with per-platform overrides; configurable via `ANDROMEDA_PULSE_DATA_DIR`.
- (obs) Log level gated via `EnvFilter::from_env("ANDROMEDA_PULSE_LOG_LEVEL")` with `RUST_LOG` fallback; xtask harness must pass-through (NOT override) user env vars to spawned `pulse-app` child.
- (obs) Heartbeat tick interval per obs-plan §3: 15s for long-running subsystems via `tokio::time::interval(Duration::from_secs(15))`; stall threshold = >45s gap. Tick targets `{module}.tick`. Per-tick fields: `span_count`, `buffer_capacity_pct`, `broadcast_subscribers`, `rows_ingested`, `eviction_count`, etc.
- (obs) Status endpoint shape: `status` xtask subcommand calls `health` over IPC and returns subsystem fields matching `*.tick` event field names — binding contract that tests §3 also consumes.
- (obs) For app stderr: dual sink — stderr (pretty-printed when TTY for dev convenience, JSON when not a TTY) + file (always JSON-only via `tracing-appender`).
- (obs) Panic hook installed at boot per obs-plan §3 + §7: `std::panic::set_hook(...)` calling `tracing::error!(target: "app.panic.fatal", ...)` with `tracing-error` SpanTrace — zero-unlogged-panics SLO enforcement.

**Patterns к follow:**

- (security) Structured-logging redaction pattern: `tracing` + `tracing-subscriber` JSON layer with redaction filter at the subscriber, not at call sites.
- (arch) Cross-cutting envelope procedure shape: `health` is top-level bare `snake_case` verb (no router prefix), grouped with `app_info` / `ready` / `get_settings` / `update_settings` and owned by `ui-bridge` crate.

- (arch) Module dependency direction: `xtask` may depend on workspace member crates downward but no library crate depends on `xtask` or `pulse-app`.
- (arch) Configuration precedence: env vars (`ANDROMEDA_PULSE_*`, `RUST_LOG`) > user `config.toml` > built-in defaults.
- (tests) Boot/cleanup verification via `health` poll + TCP handshake check, NOT `sleep N` — mirrors test-plan §11 E2E anti-pattern.
