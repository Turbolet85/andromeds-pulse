### Step 2 — Add markdown serializer module к crates/interpretation/

Create `crates/interpretation/src/markdown.rs`:
- Public `pub struct Report { ... }` type with fields: `incident_id: i64, title: String, workspace: String, opened_at_unix_nano: i64, status: String, severity: String, symptom: String, timeline: String, hypotheses: Vec<HypothesisView>, investigation_steps: Vec<InvestigationStepView>, evidence_refs: Vec<String>, project_context: String, degraded_mode: bool, resolution_summary: Option<String>, previously_seen: Vec<PreviouslySeenMatch>`.
- Public `pub fn serialize_report(report: &Report) -> String` producing the markdown form. Layout:
  ```
  # Diagnostic Report: {title}
  
  - **Incident ID:** {id}
  - **Workspace:** {workspace}
  - **Opened:** {ISO timestamp from opened_at_unix_nano}
  - **Status:** {status}
  - **Severity:** {severity}
  
  ## Symptom
  
  {symptom text — pre-scrubbed}
  
  ## Timeline
  
  {timeline text — pre-scrubbed}
  
  ## Hypotheses
  
  {if degraded_mode → "_Interpretation degraded — hypotheses omitted. See diagnostics for retry options._"}
  {else → per-hypothesis bullets: `- ({likelihood}) {title}\n  {description}`}
  
  ## Investigation Steps
  
  {if degraded_mode → "_Interpretation degraded — investigation steps omitted._"}
  {else → numbered list of steps}
  
  ## Evidence
  
  {evidence_refs as bullet list of span IDs / fingerprints — pre-scrubbed}
  
  ## Project Context
  
  {workspace + service registry context — workspace name + top-services list + lifecycle states}
  
  {if resolution_summary.is_some() →
  ## Resolution Summary
  
  {resolution_summary text — pre-scrubbed}
  }
  
  {if !previously_seen.is_empty() →
  ## Previously Seen
  
  {per-match bullets: `- {opened_at} — {title} ({workspace})`}
  }
  ```
- Co-located `#[cfg(test)] mod tests`: six-section markers present; degraded-mode notice when hypotheses/investigation_steps empty; resolution_summary section when populated; "Previously seen" subsection when matches non-empty; determinism (two identical inputs produce byte-identical output via `assert_eq!(serialize_report(&r), serialize_report(&r))`); PII pass-through (pre-scrubbed input strings survive verbatim — no re-scrubbing); empty optional sections omitted cleanly (no `## Resolution Summary\n\n` blank-body).
- Update `crates/interpretation/src/lib.rs` to add `pub mod markdown;`.

Note: `Report` struct lives in the interpretation crate so the markdown serializer can own its input type without depending on triage. The pulse-app resolver assembles the `Report` from Incident + L4Output + corpus matches at the binary boundary per arch §Module dependency direction.
