## Combined goal

Refactor the Halo State Pulse signature element so its visual encoding is driven by the v0.2.0 distillation pipeline's real signals instead of the legacy rule-based `(errorRate, throughputHz)` simulator. The Halo gains a **three-axis** model: (1) **hue + blur** ← cumulative incident attention (LCH-interpolated Earth Blue → Alert Burgundy via `lch.ts`); (2) **saturation/grayout** ← `connectionState` (P-004 orthogonal health axis); (3) **breathing pace** ← a new `activityState` (telemetry-flow tier). `HaloCanvas`'s prop surface changes from `(ariaLabel, throughputHz, errorRate)` to `(ariaLabel, connectionState, cumulativeSeverity, activityState)`; the legacy mapping helpers `error-rate-to-blur.ts` + `throughput-to-hz.ts` are deleted. Per design-system §Motion + §Color Palette (LCH + opacity/blur-only, NEVER scale — P-026), a11y-plan §6/§11 (reduced-motion static glow + SC 1.4.11 non-text contrast), obs-plan §5 (preserve the `record_frame_ms` SLO bridge), and security plan §API/§Logging (CSP unchanged, no new logging). Per **two user decisions at Phase 6 pre-planning** (Phase 3 research surfaced both): (Q1) `activityState` is built as a **real third axis** — there is no `ActivityState` type or source in the codebase today, so the plan introduces it webview-side, derived from the existing throughput signal, keeping arch §Occupied Resources delta = none; (Q2) breathing adopts the calmer **4–5 s quiet / ~2 s active** cadence, which **changes the locked design-system 0.8–2.4 Hz motion token** — a design-system specialist-plan edit (route §90 declared "Specialist plan touches: design-system") that is the one action exceeding pure consumer-side scope.

## Implementation notes

- **Decision Q1 (ActivityState, user-chosen "Extend"):** `activityState` is built as a real third axis. The plan sources it **webview-side** from the existing throughput signal (`use-widget-metrics().throughputHz`, #57) so it adds a first-class `ActivityState` type + derivation WITHOUT a new TauRPC procedure/broadcast — arch §Occupied Resources stays clean and `capability-drift` passes. **Upgrade path (documented, not in this chunk):** if `activityState` should be backend-authoritative (an aggregate of triage/baseline activity or service-lifecycle from #67), that needs a new TauRPC surface (or to ride an existing one like `services.list_with_states`) + an `/andromeda-evolve --allow-arch-registry` amendment FIRST — at which point route §90's "arch registry delta: none" line would need updating. Flag this trade-off at Phase 6; the webview-derived path is the shippable default.
- **Decision Q2 (breathing band, user-chosen "4–5 s / 2 s"):** Step 1 edits the locked design-system motion token. This is the single action beyond pure consumer-side scope. If you'd rather NOT change the locked token, the fallback is to keep 0.8–2.4 Hz and only re-map the rate driver — but the user explicitly chose the slower cadence, so Step 1 proceeds. Coordinate so code + design-system.md + design-tokens.md land in the same chunk commit (avoids D4 plan-to-plan drift).
- **OQ3 (severity signal, defaulted — not asked):** the plan uses `PriorityTier` (from the ready `use-findings.severityMax`) for the hue+blur axis because (a) the project-doc §89 blur table uses PriorityTier names (Autonomous/Suggested/Curious/None) and (b) it needs no extra derivation. If strict `IncidentSeverity` (info/warn/error/critical) is preferred (the prop is *named* `cumulativeSeverity`), derive `max(IncidentRecord.severity)` over active incidents instead and adjust the mapper + `halo-types.ts` type to `IncidentSeverity | null`. Cheap to swap; surfaced for Phase 6.
- **WGSL buffer:** the 2 spare pad floats (`_pad0`/`_pad1`) fit `connection_dim` + `opacity_target` with NO `UNIFORM_BUFFER_SIZE` change — preferred. Only resize (and bump the const + JS `Float32Array` together) if a 3rd new scalar is needed.

- **Reduced-motion repaint:** re-key the static-glow repaint effect on `[connectionState, cumulativeSeverity, activityState, reducedMotion]` so hue/grayout still update while motion stays suppressed (preserve the existing pattern, new deps).
