## Patterns detected

- **Single-file contract module per crate** (`crates/snapshot/src/contract.rs:1-442`, also `crates/ui-bridge/src/contract.rs` per CLAUDE.md pointer table): each library crate exposes its public Rust API via a dedicated `contract.rs` module. The module declares `pub` types, constants, and (sometimes) functions. Internal modules use `pub(crate)` and import types from `crate::contract`. The new `crates/curation/src/contract.rs` follows this pattern verbatim.
- **Cross-module orchestration pattern** (`crates/snapshot/src/contract.rs:8-12`): snapshot's `contract.rs` orchestrates the 4 moved primitives by importing their `pub(crate) fn` directly and calling them in the curation pipeline (likely in a `pub fn generate_snapshot(...)` or equivalent — not yet inspected past line 100). After refactor, snapshot::contract's orchestrator imports `use curation::contract::{aggregate_metrics, detect_anomalies, extract_critical_path, dedupe_spans};` instead of `use crate::{aggregation,anomaly,critical_path,dedupe}::*;`.
- **Shared type circular-dependency risk** (`crates/snapshot/src/anomaly.rs:7` + `crates/snapshot/src/contract.rs:33-100`): the moved modules import types (`SpanRecord`, `AnomalyMarker`, `AnomalyKind`, `CriticalPathStep`, `CurationOutput`, `ServicePercentiles`) FROM snapshot::contract. After move к curation, those types are no longer reachable as `crate::contract::*` — and curation cannot depend on snapshot per the DAG invariant. **Resolution: shared types MUST move from snapshot::contract к curation::contract.** snapshot::contract then re-exports them via `pub use curation::contract::{SpanRecord, AnomalyKind, AnomalyMarker, CriticalPathStep, CurationOutput, ServicePercentiles, AggregationResult, ...};` to preserve its external Rust API surface (anything currently importable as `snapshot::contract::SpanRecord` stays importable; the implementation moves but the path is preserved).
- **Tracing instrumentation present in every moved module** (grep `tracing::instrument` matched 7 files including the 4 movers): each moved module has `#[instrument(skip_all, fields(input_row_count = X, ..., duration_ms = tracing::field::Empty))]` decorators on its public entry point + `span.record(...)` calls inside. Migration preserves these decorators verbatim per obs extract constraints; `target: "snapshot::dedupe"`-style log targets (if any) are renamed к `curation::dedupe` per obs constraint.
- **Workspace-dep inheritance via `.workspace = true`** (`crates/snapshot/Cargo.toml:10-13`): per-crate Cargo.toml uses `chrono.workspace = true` form to inherit the version pin from the workspace root. New `crates/curation/Cargo.toml` follows the same pattern.
- **Co-located unit tests** (per `.claude/rules/testing.md` "File placement: Rust: co-located `#[cfg(test)] mod tests { … }` within each crate's `src/` (no separate `tests/` directory per arch convention)"). Each moving module's `#[cfg(test)] mod tests` block moves verbatim into the new crate.
- **Snapshot crate has zero DuckDB dep** (grep `duckdb|Connection|Statement` in `crates/snapshot/src/` returned no matches): resolves security extract's open question. Curation modules operate on pre-queried Arrow data shapes (likely `Vec<SpanRecord>` or similar); no direct DuckDB SQL paths to audit. Security constraint "use Connection::prepare with `?` placeholders, never format-string SQL" is by-construction-satisfied in the moved modules (no SQL surface).
