## Combined goal

Add per-span-event exception fingerprinting + a retry storm detector that emits attention cues when the same exception fingerprint reoccurs ≥5 times within a 30-second sliding window (Suggested tier) or ≥10 times (Autonomous tier). The fingerprint = blake3(`exception.type` + normalized first-3-frame stacktrace) truncated to 16 bytes; normalization strips absolute paths, memory addresses, and line numbers so the hash is stable across host-environment differences and never co-mingles incidentally captured PII bytes from instrumented host applications (per security plan §Logging "What NEVER to log" + chunk #66 `Specialist plan touches: security` annotation). Fingerprints are written to the existing `span_events.fingerprint BLOB NULL` column (chunk #65 substrate) on the OTLP-decode → DuckDB-appender ingestion hot path, and emitted in-process to a new `RetryStormDetector` that holds a `DashMap<[u8; 16], FingerprintState>` with a 60-second rolling window. The detector emits `AttentionCue { kind: CueKind::RetryStorm, priority_tier: Suggested|Autonomous }` payloads through the existing `pulse://stream/attention-cues` broadcast channel (chunk #62 substrate; no new TauRPC procedure, no new broadcast topic, no arch registry delta). Per arch §Cross-cutting Patterns Module dependency direction, fingerprint computation lives in the lower buffer crate (no `triage` dep) via a new `FingerprintObserver` trait declared in `crates/buffer/src/fingerprint.rs`; the storm-detection state machine lives in `crates/triage/src/pattern/storm.rs` (sibling к chunks #62/#63 cue emitter + restart detector); the cross-crate bridge `StormObserverAdapter` lives at the `pulse-app` binary boundary in `pulse-app/src/storm_observer.rs` (mirrors `RestartObserverAdapter` chunk #63 + `BaselineObserverAdapter` chunk #62 precedent). Self-observation discipline preserved per security plan §Logging + obs-plan §8 default-deny posture: no raw `exception.message`/`exception.stacktrace` content enters `tracing` events (verified by negative-canary tests injecting `SECRET_CANARY_*` substrings); per-target field allowlist in `pulse-app/src/observability.rs::AllowList::production()` extends with new entries listing ONLY identifier-class fields per chunks #62/#63/#64 convention (`fingerprint_hex` 8-char prefix, `severity_hint`, `occurrence_count`, `window_seconds`, `tracked_fingerprints_count`, `active_storm_count` — never `exception_message` / `service_name` / `scope_id`).

## Implementation notes

- **Order sensitivity**: complete Implementation Steps 1-5 (buffer side: dep + fingerprint module + appender modification + consumer signature change) BEFORE Steps 6-9 (triage storm detector + pulse-app adapter), so triage tests don't fail-compile waiting на the buffer trait existence. Step 10 (main.rs boot wiring) is the final integration step; Step 12 (e2e integration test) requires Steps 1-11 complete.
- **Service-id semantics for cross-service fingerprint reuse (Open Question 1)**: a single exception fingerprint occurring across multiple services within the 60s window updates a SINGLE `FingerprintState` keyed by fingerprint (NOT by `(fingerprint, service)` tuple). The `service` field on the state is set к the first-observed service and NOT updated on subsequent observations from different services. This means cross-service propagation of the same exception fingerprint contributes к ONE storm cue, attributed к the first-observed service. **Validate в Phase 6 user review** — alternative semantics (per-service-per-fingerprint keying) is possible but doubles cardinality and changes the storm-detection semantics (a fanout across 5 services of the same fingerprint would emit 5 separate Suggested cues instead of 1).
- **Storm-cue dedup window (Open Question 2)**: per-tier one-shot dedup — `Suggested` cue fires once on first 5th crossing per fingerprint; `Autonomous` cue fires once on first 10th crossing (escalation from Suggested к Autonomous); subsequent occurrences silent until detection-window-resets via timestamp-pruning + recrossing. Avoids duplicate-cue log-spam under sustained high-rate exception storms.
- **`StormObserverAdapter` is NOT held in `CompositeSpanObserver`**: chunks #62/#63 BaselineObserverAdapter + RestartObserverAdapter compose into `CompositeSpanObserver` because they both implement `ingest::observer::SpanObserver` (per-span hook). Chunk #66's `StormObserverAdapter` implements the NEW `buffer::fingerprint::FingerprintObserver` trait (per-span-event hook) — these are SEPARATE observer pathways. The chunk doesn't need a `CompositeFingerprintObserver` because только one FingerprintObserver impl is planned. If a future chunk adds a second FingerprintObserver impl (e.g., chunk #69 corpus persistence), the composite pattern lifts directly from chunk #63 then.
- **Bindings.ts regeneration discipline (per testing.md §Session Additions 2026-05-13 + 2026-05-17)**: the standard chunk-gate baseline includes `cargo nextest run --workspace --features mcp-server` to ensure `pulse-app/ui/src/bindings/index.ts` ends в canonical full-set state (с `mcp.{start,status,stop}` namespace) post-test. Pre-commit verification: `grep -c '"mcp":' pulse-app/ui/src/bindings/index.ts` must return ≥1. If chunk #66 default-features nextest run overwrites bindings.ts after the mcp-server-features run, regenerate via the mcp-server-features run BEFORE staging files for commit.
- **Stack normalization regex safety**: the path-stripping + address-stripping + line-number-stripping regexes в `crates/buffer/src/fingerprint.rs::normalize_stacktrace` should be compiled lazily via `once_cell::Lazy` (already в lockfile via transitive deps) OR as `static` patterns to avoid per-call compilation cost. If `regex` crate isn't workspace-pinned, consider hand-rolled string scanning (faster + no new dep) OR add `regex = "1"` workspace pin. **Decision deferred к /implement Phase 2**: prefer hand-rolled string scanning to avoid regex dep; pattern is simple (3 strip operations on 3 short lines per fingerprint).
