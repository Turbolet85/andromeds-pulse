## Implementation Steps

1. **Create `pulse-app/ui/src/components/Modal.tsx`** — the generic modal primitive. Component signature:
   ```
   interface ModalProps {
     open: boolean;
     onClose: () => void;
     triggerRef: React.RefObject<HTMLElement | null>;
     titleId: string;
     title: string;
     children: React.ReactNode;
     busy?: boolean;
     liveRegionLevel?: 'polite' | 'assertive';
     liveMessage?: string;
     clickOutsideDeactivates?: boolean;
     initialFocus?: React.RefObject<HTMLElement | null>;
   }
   ```
   Render shape (when `open=true`):
   - Outer overlay backdrop: `<div>` with `position: fixed; inset: 0; zIndex: 200; background: rgba(15, 17, 23, 0.6); display: flex; alignItems: center; justifyContent: center;` + `className="motion-reduce:transition-none motion-reduce:duration-0"` + opacity-fade entrance ≤200ms ease-out (chrome budget per design-tokens.md `--duration-standard`).
   - Inner card: `<div role="dialog" aria-modal="true" aria-labelledby={titleId} aria-busy={busy ? 'true' : 'false'}>` with inline style: `background: var(--color-raised-3); border: 1px solid rgba(74, 144, 226, 0.3); borderRadius: var(--radius-lg); padding: var(--spacing-md); display: flex; flexDirection: column; gap: var(--spacing-sm); color: var(--color-text-primary); fontFamily: var(--font-body); maxWidth: 80vw; maxHeight: 80vh; overflow: hidden;`.
   - Header row: `<header style={{ display: 'flex', justifyContent: 'space-between', alignItems: 'center' }}>` containing `<h2 id={titleId} style={{ fontFamily: 'var(--font-display)', fontSize: '20px', fontWeight: 600, margin: 0 }}>{title}</h2>` + close button.
   - Close button: `<button type="button" aria-label="Close" onClick={onClose}>` styled per Secondary button pattern (background `var(--color-raised-1)`, text `var(--color-text-primary)`, border `1px solid rgba(74, 144, 226, 0.3)`, hover border `#4A90E2`) with the `✕` glyph as text content (Path B from research.md open question — no new icon registry entry); minimum size 24×24 CSS px (`padding: var(--spacing-xs)` + content sizing) per a11y plan §6 Target size SC 2.5.8.
   - Content slot: `<div style={{ flex: 1, overflowY: 'auto' }}>{children}</div>` with scrollable overflow per layouts §Component Investigation modal Layout 4th bullet.
   - Live region (always rendered): `<div role="status" aria-live={liveRegionLevel ?? 'polite'}>` containing `{liveMessage ?? ''}`; visually-hidden styling (clip-rect pattern per `pulse-app/ui/src/dashboard/StatusLiveRegion.tsx:51-67`).
   - Wrap the entire dialog tree in `<FocusTrap active={open} focusTrapOptions={{ initialFocus: () => initialFocus?.current ?? null, escapeDeactivates: true, clickOutsideDeactivates: clickOutsideDeactivates ?? false, returnFocusOnDeactivate: true, onDeactivate: () => triggerRef.current?.focus(), tabbableOptions: { displayCheck: 'none' } }}>` (matching CommandPalette.tsx:117-128 shape; `clickOutsideDeactivates` defaults to false per Modal semantics — explicit close button is the primary dismissal).
   - Esc dismissal: handled by `focus-trap-react`'s `escapeDeactivates: true` (which fires `onDeactivate` → restores focus to trigger AND consumer can detect deactivate via `onDeactivate` callback chain — but the canonical pattern is to call `onClose` from a separate `useEffect` listening for the trap's deactivation, OR put `onKeyDown` on the dialog content. Per a11y.md Session Additions 2026-05-09 second entry, do NOT put `onKeyDown` on the `<div role="dialog">` wrapper — `eslint-plugin-jsx-a11y` flags it as `no-noninteractive-element-interactions`. The cleanest path: pass an inline `onDeactivate` to FocusTrap that calls both `triggerRef.current?.focus()` AND `onClose()`).
   - When `open=false`: return `null` (per CommandPalette.tsx:73-75 pattern — primitive renders nothing).

## Implementation notes

- **Motion budget reconciliation (Pattern 3 rot warning)**: primitive defaults to 200ms ease-out fade (chrome-budget per design-system §Motion Hard Limits). Supporting-moment exemption (Investigation Capture Collapse 250-350ms) is opt-in per consumer via prop addition at chunk #41 wiring time (NOT in chunk #37's primitive API — keep the primitive surface minimal). This resolves the design ↔ layouts ambiguity in favor of design's chrome-default while preserving layouts' supporting-moment exemption as explicit consumer opt-in.
- **Esc handling via `focus-trap-react` `onDeactivate`**: the cleanest path is to put both `triggerRef.current?.focus()` AND `onClose()` calls inside the `onDeactivate` callback (called by FocusTrap on Esc / clickOutside / programmatic deactivation). This avoids the `no-noninteractive-element-interactions` ESLint warning that would fire if `onKeyDown` were placed on `<div role="dialog">` per a11y.md Session Additions 2026-05-09 second entry. CommandPalette puts `onKeyDown` on the inner `<input role="combobox">` (an interactive element), but the Modal primitive's first focusable is the close button (a `<button>`, also interactive); placing keydown there is an alternative valid pattern.
- **Always-render aria-live**: the modal's `<div role="status" aria-live="polite">` is rendered always (even when `liveMessage` is empty/undefined), matching StatusLiveRegion.tsx pattern and ensuring screen-reader registers the region at modal mount time. Late-mounting an aria-live region misses the initial announcement.
- **Test sequencing**: write the Modal.tsx component first (with `if (!open) return null` short-circuit); compile + lint + typecheck before writing tests. Then write Modal.test.tsx following CommandPalette.test.tsx pattern; run vitest after each test case to catch regressions early.
- **`focus-trap-react` 12 jsdom workaround MUST be present in all Modal mount tests** per testing.md Session Additions 2026-05-09 last entry. Apply via `focusTrapOptions: { tabbableOptions: { displayCheck: 'none' }, ... }` in the production component itself (matches CommandPalette.tsx:126 pattern — option lives in production code, not test-only) so production WebView2/WKWebView (which has real layout) is unaffected and jsdom (which has zero layout) doesn't crash FocusTrap.
- **No D3 capability-drift cleanup coupling here**: chunk #37 does NOT consume any of the previously-cleaned-up procedures (streams.* / telemetry.frontend.*) so the security.md Session Additions 2026-05-10 "couple cleanup with consuming chunk" recommendation does not apply. The clean baseline from chunk #34 is preserved by virtue of the chunk introducing zero new procedures.
- **Future consumer expectations**: the primitive's API (open / onClose / triggerRef / titleId / title / children / busy / liveRegionLevel / liveMessage / clickOutsideDeactivates / initialFocus) is designed to satisfy chunk #38 Settings modal (Tab cycle through form controls, focus on title-or-first-input, Esc returns focus to trigger, aria-busy during save) AND chunk #41 Investigate trigger (aria-busy during snapshot generation, status[aria-live="polite"] for progress, status[aria-live="assertive"] for completion).
