## Patterns detected

- **FocusTrap + role="dialog" + inline-token-style overlay** (`pulse-app/ui/src/dashboard/CommandPalette.tsx:117-264`): the canonical project pattern for any modal-class overlay. Two-layer DOM (outer overlay backdrop with `position: fixed; inset: 0; zIndex` + inner card with token-styled background/border/radius/padding) wrapped in `<FocusTrap>` with the standard `focusTrapOptions` (escapeDeactivates / clickOutsideDeactivates / returnFocusOnDeactivate / onDeactivate / tabbableOptions.displayCheck="none"). Modal primitive lifts this 1:1.
- **Inline `style={{...}}` instead of Tailwind classes** for token-bound surface chrome (`CommandPalette.tsx:132-263`, `SettingsRoute.tsx:13-67`, `StatusLiveRegion.tsx:51-67`). Pattern: token classes (e.g., `var(--color-raised-3)`) consumed via `style` prop's CSS variable interpolation; Tailwind `motion-reduce:` variants applied via `className` for the reduced-motion override (since matchMedia-driven state isn't a CSS-variable concern). Tradeoff acknowledged: inline styles bypass `tailwindcss/no-custom-classname` lint warnings AND give full IDE autocomplete via React's CSSProperties type. NEVER hardcode hex literals — always `var(--token)`.
- **`triggerRef` + `onDeactivate` focus restoration contract** (`CommandPalette.tsx:24, 109-112`): consumers pass a `React.RefObject<HTMLElement | null>` for the element that triggered the modal; primitive's `FocusTrap` `onDeactivate` calls `triggerRef.current?.focus()` to restore focus on Esc/click-outside/programmatic close. Avoids consumer needing to manually re-focus.
- **`vi.unstubAllGlobals()` per-file `afterEach` discipline** (`CommandPalette.test.tsx:34-36`, also covered in testing.md Session Additions 2026-05-08): tests stubbing `navigator`/`matchMedia`/etc. MUST clean up; global `test-setup.ts` only invokes `cleanup()`. Apply to Modal tests if they stub `matchMedia` for reduced-motion testing.
- **`vi.hoisted` for vi.mock factory references** (testing.md Session Additions 2026-05-09): if Modal mocks any module that needs external references in the factory closure (e.g., `vi.mock("@tauri-apps/api/window", ...)` to test backdrop-click → window-close interactions), wrap external refs in `vi.hoisted(() => ({ ... }))`.
- **`<section aria-label="...">` implicit `role="region"`** (a11y.md Session Additions 2026-05-09 first entry; visible in `SettingsRoute.tsx:9-19`): NEVER add explicit `role="region"` on `<section aria-label>` — `eslint-plugin-jsx-a11y` 6.10's `no-redundant-roles` rule flags it. Modal primitive should put `role="dialog"` on a `<div>` (since `<dialog>` HTML element + `showModal()` would create CSS / native styling collisions — the project chose div+role per CommandPalette precedent).
- **Inline numeric WebGPU constants** (testing.md Session Additions 2026-05-09 jsdom WebGPU constants entry): irrelevant for chunk #37 (no WebGPU usage in modal primitive); referenced for completeness as pattern context.
- **`focus-trap-react` `displayCheck: 'none'` jsdom workaround** (testing.md Session Additions 2026-05-09 last entry; CommandPalette.tsx:126): standard test-time-only option needed to bypass jsdom's zero `getBoundingClientRect`. Modal primitive's tests MUST include this.
- **Reduced-motion test pattern** (`pulse-app/ui/src/hooks/mock-reduced-motion.ts` + testing.md Session Additions 2026-05-04): `mockReducedMotion(true)` flips `window.matchMedia` deterministically; `motion-dom` module-global state reset in `beforeEach` to prevent cross-test bleed.
- **No new TauRPC procedures = capability-drift baseline preserved** (xtask/src/main.rs:376-394; combined.md security/arch/tests acceptance criteria): chunk #37 webview-only scope = `EXPECTED_PROCEDURES` UNCHANGED + 5 capability JSON files byte-identical pre/post chunk.

## Open questions

- **Motion budget reconciliation** (Pattern 3 rot warning in combined.md): orchestrator's recommendation in Phase 4 plan: default to chrome-budget 200ms ease-out fade for the BASE primitive (matching design-system.md §Motion Hard Limits + design-tokens.md "duration-standard 200ms" + the chrome-default of CommandPalette which uses `motion-reduce:transition-none motion-reduce:duration-0` on a CSS transition). Investigation modal (chunk #41) and Settings modal (chunk #38) can each opt into the supporting-moment longer duration via prop if needed. Rationale: per design-tokens.md "Investigation Capture Collapse 250–350ms (supporting moment, EXEMPT from 200ms hard limit)" — exemption is per-instance, not the primitive default. Consumers exercise the exemption explicitly when the consumer's UX is a supporting moment (Investigation Capture Collapse), not by default. This resolves the conflict in favor of design's chrome-default while preserving layouts' supporting-moment exemption as an opt-in.
- **Close-button glyph source**: design extract says "inline 'X' close glyph fits the existing Iconography vocabulary (Lucide/Heroicons fallback acceptable per §Iconography Secondary library)". Existing icon registry at `pulse-app/ui/src/components/icons/` has 5 custom SVGs (aperture / telescope / constellation-grid / star / circular-pulse) + a generic `Icon` dispatcher (`pulse-app/ui/src/components/icons/Icon.tsx`). NO existing "close" / "X" / "dismiss" glyph. Two paths: (a) add a 6th SVG `Close.tsx` to the icon registry (extends the Observatory vocabulary with a generic close glyph — minor scope creep but cleanest); (b) inline the "X" Unicode glyph directly in the close button text content (matches CommandPalette which inlines text content; layout-templates.md says "✕ glyph"). Path (b) is the lower-cost match to layouts §Component Investigation modal "Close button: top-right corner, ✕ glyph". Choosing (b) for chunk #37; future chunk can promote to icon registry if usage grows.
- **`role="dialog"` vs native `<dialog>` element**: a11y extract notes both options. Project pattern (CommandPalette) uses `<div role="dialog" aria-modal="true">` — chosen over native `<dialog>` because (a) native `<dialog>` `showModal()` adds a top-layer + ::backdrop pseudo-element with browser-default styling that fights the project's borders-only depth strategy; (b) the project's `inline-style + design-token` discipline composes more cleanly on a `<div>`; (c) consistency with CommandPalette precedent. Choose `<div role="dialog">` for chunk #37.
- **`aria-live` slot wiring** — should the modal's `aria-live` region be rendered always (with `aria-live="polite"` default + empty `liveMessage`) or only when `liveMessage` is non-empty? Always-rendering is the safer pattern for screen-reader consistency (otherwise SR misses initial mount); this matches StatusLiveRegion's always-mount pattern. Phase 4 plan goes with always-render + opt-in level via prop.
- **`react-aria-components` `Modal`/`Dialog` adoption**: a11y extract recommends "Prefer react-aria-components ... `Modal` + `Dialog` + `Heading`" OR native `<dialog>`. Project pattern (CommandPalette) does NOT use react-aria-components — uses focus-trap-react directly. Switching the modal primitive to react-aria-components would create a precedent split across the project (CommandPalette uses focus-trap-react; Modal would use react-aria-components). Per frontend.md "react-aria-components 1.17.x (preferred) OR @headlessui/react 2.2.x — pick ONE; mixing causes style/behavior conflicts" — but focus-trap-react is NOT a react-aria-components alternative, it's a single-purpose library. focus-trap-react and react-aria-components can coexist. Choosing focus-trap-react for chunk #37 per CommandPalette precedent (lower risk + zero additional integration work + matches the test pattern that already exists for the focus-trap library).
