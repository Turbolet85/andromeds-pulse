## Combined goal

Wire the long-running-subsystem heartbeat tick mechanism specified by obs-plan §3 onto the existing chunk #4 + #7 + #8 self-observation substrate. Four `tokio::spawn`'d tasks, each driven by `tokio::time::interval(Duration::from_secs(15))`, emit `tracing::info!(target: "{module}.tick", ..., "heartbeat")` events for `ingest`, `buffer`, `viz`, and `plugins` per the locked target taxonomy in `xtask/ci/heartbeat-gap-check.{sh,ps1}`. Tick payload fields are bounded numeric snapshots of per-module liveness state (no OTLP attribute strings, no SQL fragments, no PII per security plan §Logging & Monitoring). Field names align with the obs §8 default-deny per-module allowlist; chunk #8's `JsonFieldVisitor` strip-suffix `.tick` lookup already routes tick events through the right allowlist (existing test `scrubber_passes_tick_suffix_fields` confirms). Heartbeat task ownership lives in `pulse-app/` per arch §Cross-cutting Patterns "Module dependency direction" — library crates expose only a `pub` `heartbeat_payload()` contract callable, never own the timer themselves.

The `health` IPC envelope gains parity with the tick stream per the obs ↔ arch contract binding: each `SubsystemStatus` gains an additive `last_tick_at: Option<DateTime<Utc>>` field; `SubsystemStatuses` gains two new entries (`viz`, `plugins`) so all four tick targets correspond to a queryable subsystem record. The pulse-app boot wires shared heartbeat state via a `OnceLock<Arc<HeartbeatState>>` mirror of the existing `APP_START` pattern in `crates/ui-bridge/src/health.rs`. The xtask CI gate `cargo xtask ci-gates` already calls into `xtask/ci/heartbeat-gap-check.{sh,ps1}` (which has been waiting in INACTIVE state since chunk #6) — once chunk #9 ships, the gate transitions from NEUTRAL to ACTIVE the first time integration tests boot pulse-app long enough to emit ticks.

This is a single-substantial chunk per the route grouping heuristic: it crosses ingest / buffer / viz / plugins / pulse-app / ui-bridge / xtask configuration files, but is not coupled to chunk #10 (Design tokens bundle — frontend Tailwind/CSS, separate concern).

## Implementation notes

- **Spawn order matters**: heartbeat tasks must spawn AFTER `observability::init` (tracing subscriber must exist) AND AFTER `register_heartbeat_state` (so the health handler can read the same shared state). Spawn BEFORE `tauri::Builder::default().run()` because `.run()` blocks main thread.
- **Drop the `WorkerGuard` last**: `pulse-app/src/main.rs:71` uses `let _guard = observability::init(&data_dir)` — the underscored binding holds for `main()`'s full duration. Heartbeat task `JoinHandle`s should be similarly held (`let _heartbeat_handles = ...`) so they aren't dropped early; alternatively, deliberately drop them at the end of `main()` so tokio's runtime shutdown cancels the tasks gracefully.
- **`OnceLock<Arc<HeartbeatState>>` registry pattern in ui-bridge**: mirror the existing `static APP_START: OnceLock<Instant>` at `crates/ui-bridge/src/health.rs:10`. `register_heartbeat_state(state)` calls `STATE.set(state)` (idempotent on first call; later calls quietly silently noop or error-log per project taste). `current_health()` reads `STATE.get()` and pulls per-subsystem timestamps via the appropriate accessor.
- **Foundation-stub `heartbeat_payload()` returns zero values**: each library crate's contract function is а placeholder until the underlying functionality lands (route#16+). The shape is correct now; real values flow through automatically once implementations exist (heartbeat structs are passed by value into `tracing::info!` macro field args).
- **Test discipline**: paused-clock tests via `#[tokio::test(start_paused = true)]` are the only acceptable timer-driven tests per `.claude/rules/testing.md` Patterns. NEVER use `std::thread::sleep`, `tokio::time::sleep` with real time, or assertions on wall-clock cadence.
- **The `plugin` (singular) vs `plugins` (plural) coexistence**: in `AllowList::production()`, both entries are kept side-by-side. `plugin` covers plugin-invoke events (legacy obs-plan §plugin allowlist); `plugins` (NEW) covers heartbeat ticks. The `for_target` strip-suffix lookup routes `plugins.tick` → `plugins` lookup, NOT through the `plugin` (singular) entry. Confusion between the two is а pitfall — be explicit in test assertions.
- **TIER 2 rule edit in step 6**: editing `.claude/rules/verification-harness.md` is а deliberate policy change synchronized with the additive envelope shape extension. Per setup-project precedent (chunk #8 added а Session Addition к `.claude/rules/observability.md`), this edit is appropriate during chunk implementation rather than deferred к а separate documentation chunk.
