Chunk #45 substrate has no plugin-loading state (loader is #47); heartbeat with always-zero fields is busywork without semantic value. Acceptance criteria reflect this: obs criteria reduced from 4 to 2 (basename redaction + allowlist enforcement remain; heartbeat cadence + status-endpoint reciprocation defer to #47).
- **From impl + tracing target sub-namespace deferred to chunk #47**: Step 9 extends `From<PluginsError> for AppError` mapping new variants to `AppError::Internal` rather than `AppError::Plugin { plugin_id, message }` because no IPC consumer exists yet (no `plugins.*` TauRPC procedure). Chunk #47 will refactor: (a) re-route new PluginsError variants to `AppError::Plugin`; (b) add explicit `ui-bridge.error.plugin` allowlist entry in `pulse-app/src/observability.rs::AllowList::production()` per testing.md 2026-05-07 Session Addition; (c) emit boundary-call `plugin.invoke.request` spans at the IPC resolver per obs extract.
- **WIT fixture WASM generation**: Step 8 fixture creation may be non-trivial without a build-time WAT-to-WASM toolchain. /implement Phase 1 options: (a) use the `wat` crate at dev-dep level to emit minimal WASM from `.wat` text sources (committed alongside `.wasm`); (b) hand-craft `.wasm` binaries (small ones are tractable); (c) generate from a build script. Recommendation: (a) — `.wat` text is human-readable and the `wat` crate is a workspace-able dev-dep. Fixture file size for a minimal Component is small (low hundreds of bytes), so committing both `.wat` source and compiled `.wasm` is fine.
- **Coverage gate exclusion of generated code**: `cargo llvm-cov nextest -p plugins --lcov --ignore-filename-regex 'bindgen|component/__generated'` excludes wasmtime `bindgen!` macro output. The exact regex pattern depends on where wasmtime places generated code — typically in `$OUT_DIR/<crate>/component/__generated.rs` or `target/debug/build/<hash>/out/...`. /implement Phase 2 may need to adjust the regex once `cargo llvm-cov` surfaces actual paths.
- **Skipping fixture WASM compilation in fast iteration**: if the /implement loop's fix-cycle is slow due to fixture WASM rebuilds, fixture compilation can be moved behind a `[features] heavy-fixtures` Cargo feature flag (default off, on in CI). The trade-off is /implement Phase 2 still needs the fixtures for the unit tests to pass — so feature-flagging them out only saves the rebuild cost when iterating on a non-fixture-touching change. Not recommended for chunk #45 (small, well-scoped chunk); flagged as a possible iteration aid only.
- **a11y obligations as WIT doc-comments**: the WIT language supports `///` doc-comments per the [WIT spec](https://component-model.bytecodealliance.org/design/wit.html). Chunk #45 articulates a11y obligations there; downstream chunks (loader at #47, invoke at #47, re-emit beyond #49) enforce mechanically. The doc-comment is informational at chunk #45; the enforcement seam is the host-side re-emission logic when plugin output is rendered. Future chunks may add a static analysis seam (e.g., a `crates/plugins/src/a11y_guard.rs` that scans plugin-returned DOM fragments for semantic-HTML compliance) — out-of-scope for chunk #45.
