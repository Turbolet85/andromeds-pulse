## Patterns detected

- **Centralized-substrate-config pattern** (`crates/buffer/src/schema.rs:1-186`): one module owns the substrate configuration (constants + creation fn + sanitization helper). Subsequent chunks extend rather than replace. Direct analog for chunk #45: a single `crates/plugins/src/engine.rs` (or similar) owns `wasmtime::Config` construction + Engine creation; chunks #46-#47 attach ResourceLimiter + loader on top.
- **`#[tracing::instrument(skip_all, fields(...))]` with `Span::current().record()`** (`crates/workspace-detector/src/detect.rs:20-49`): the canonical span pattern for boundary calls that need latency tracking. `skip_all` keeps untrusted inputs out of fields; `fields(latency_ms = tracing::field::Empty)` reserves the field; `span.record("latency_ms", elapsed)` populates it pre-return. Direct analog for chunk #45 wasmtime host wrappers — `plugin.engine.init`, `wasmtime.instantiate` spans should follow this pattern.
- **Module-declaration-only `lib.rs` with `pub mod contract` + internal `pub(crate) mod`** (`crates/snapshot/src/lib.rs`): the standard shape for library crates whose primary public surface is a single contract module. Chunk #45 can mirror this OR follow workspace-detector's multi-module pattern (`pub mod contract` + `pub mod engine`) depending on whether the substrate module deserves a separate public surface.
- **`#[cfg(test)] mod tests` with rstest parametric cases** (`crates/buffer/src/schema.rs:188-303`): tests live next to source. `use rstest::rstest;` for `#[case]`-parameterized tests covering N similar scenarios. Direct analog for chunk #45 — WIT-category fixture loading tests would use rstest with `#[case("custom-dashboard")]` / `#[case("data-transform")]` / `#[case("snapshot-template")]`.
- **Selective `pub use` of own internal items** (`crates/snapshot/src/contract.rs:14-15`): `pub use crate::markdown::format_markdown;` is the established pattern to expose internal-module items via the contract surface. Distinct from the arch §Conventions ban on `pub use` of FOREIGN types (e.g., `pub use wasmtime::Engine` would be banned because it leaks an external dependency's type through the crate's public boundary).
- **`From<E> for AppError` pattern with tracing warn at bridge** (`crates/ui-bridge/src/contract.rs:387-403`): the existing PluginsError → AppError From impl currently lands at `AppError::Internal` because PluginsError only has `Placeholder`. New variants added in chunk #45 should map to `AppError::Plugin { plugin_id, message }` (the reserved variant) — but since chunk #45 has no IPC procedure yet (no `plugins.*` TauRPC routes), the From impl update is OPTIONAL this chunk. Chunk #47 (loader + IPC routers) will refresh the From impl.

## Conventions to follow

- **Workspace-inherited dep declaration**: `crates/plugins/Cargo.toml` declares deps via `<name>.workspace = true` for workspace-pinned versions OR `<name> = "x.y"` for crate-specific pins. New `wasmtime` dep MUST be added to workspace.dependencies (`Cargo.toml` line ~24+ workspace.dependencies block) first, then referenced from `crates/plugins/Cargo.toml`. See workspace.dependencies precedent: `tokio = { version = "1", features = ["full"] }`, `thiserror = "2"`, `rstest = "0.26"`, `tempfile = "3"` (lines 25-62).
- **`#[derive(Debug, Error)]` + `thiserror::Error`** for module-internal error types (per arch §Conventions Error response schema + existing `crates/plugins/src/contract.rs:3-7` precedent). New variants should follow the existing snake_case pattern: `EngineInit { reason: String }`, `WitLoad { plugin_id: String, reason: String }`, `ComponentInstantiate { plugin_id: String, reason: String }`. The `Placeholder` variant from the stub should be removed once at least one real variant lands, OR kept temporarily for backward compat — recommendation: replace, since `From<PluginsError::Placeholder>` is only referenced in a unit test.
- **Tracing target naming** (`{crate}.{operation}` per `.claude/rules/observability.md` §Span discipline): `plugin.engine.init`, `wasmtime.instantiate`, `plugins.tick` are canonical. Note the `plugin` (singular) vs `plugins` (plural) distinction documented in observability.md 2026-05-03 Session Addition — `plugins.tick` heartbeat events route via the `plugins` (plural) allowlist; `plugin.{operation}` invocation events route via the `plugin` (singular) allowlist. The substrate chunk #45 may add only `plugin.engine.init` style events; heartbeat (`plugins.tick`) interval task may be deferred to chunk #47 when there's actual state to track (`loaded_count` is meaningful only when the loader is wired).
- **Plugin host substrate logs use `#[instrument(skip(...))]` + literal `fields(...)`** (per observability.md Span discipline section). For chunk #45 substrate, the substrate fns to wrap include `build_engine()` / `parse_wit_world()` / `instantiate_component()` (names TBD); fields per obs extract include `plugin_path_basename`, `wasm_size_bytes`, `duration_ms`, `module_name`, `export_count`.
- **Test fixture location**: `crates/plugins/tests/fixtures/` for fixture WASM Component Model `.wasm` binaries (per tests extract + arch §Infrastructure Patterns project directory structure; analogous to `crates/buffer/tests/` precedent). Pre-compiled, committed to repo, read-only per suite.
- **`cargo deny check bans` skip-list provenance comment**: every new entry in `deny.toml [bans] skip` MUST have a one-line provenance comment naming the chunk + date that introduced the duplicate (per `.claude/rules/security.md` 2026-05-03 Session Addition + existing skip-list comments at deny.toml lines 76 / 88 / 92 / 99 / 110). ## Open questions

- **wasmtime version pin**: `wasmtime` 25.x is the route §2 chunk text spec ("wasmtime 25+"). Latest patched version as of 2026-05-11 should be verified at /implement time against `cargo audit` to ensure CVE-2026-27572 / CVE-2026-34941 / CVE-2026-35195 (April 2026 cluster) are remediated. - **Component Model API surface**: `wasmtime::component::bindgen!` macro vs. manual `wit-parser` + `wasmtime::component::Component::from_binary` — both work; macro is more ergonomic but generates code that needs to be excluded from coverage (per tests extract acceptance criterion #2 `--exclude-files` for generated `bindgen!` output). Recommendation: use `bindgen!` for the 3 WIT category schemas; coverage tooling excludes generated files via `cargo llvm-cov nextest -p plugins --lcov --ignore-filename-regex 'bindgen|component/__generated'` or similar pattern.
- **wasmtime-wasi inclusion**: chunk #45 introduces 3 plugin categories; if any of the 3 needs `wasi:io` / `wasi:logging` / similar standard WASI imports, then `wasmtime-wasi` is needed. If all 3 categories define entirely-bespoke host imports without WASI, then `wasmtime-wasi` is optional. /implement Phase 1 design decision; either way the security extract constraint applies (only declared imports).
- **Heartbeat task at substrate level**: obs extract specifies `plugins.tick` heartbeat every 15s. But at chunk #45 substrate level there's no `loaded_count` or `active_invocations` state to report (loader is #47). Two paths: (a) implement the heartbeat task with always-zero fields as substrate; (b) defer heartbeat task to chunk #47 when state exists. Recommendation: (b) — heartbeat with always-zero is busywork without semantic value; the obs acceptance criterion can be relaxed to "heartbeat infrastructure present, fields populated when state exists" if needed. /implement Phase 6 user review can settle this.
- **From impl extension scope**: if chunk #45 adds new PluginsError variants, exhaustive-match in `crates/ui-bridge/src/contract.rs:389` requires updating the From impl. Quick fix maps new variants to `AppError::Internal { message: "..." }` (with substrate-internal context); chunk #47 will refactor to `AppError::Plugin { plugin_id, message }` when the IPC procedure introduces the plugin_id at the call site. /implement decision.
