## Implementation notes

- **Order sensitivity:** implement step 3 (channel.rs) BEFORE step 4-7 (state/contract/grpc/http changes) — receivers reference `IngestSender` from `ingest::channel` so the type must exist first. Within step 14, build `start_test_grpc_server()` helper BEFORE writing test bodies — helper signature drives test ergonomics.
- **`ChannelFull` vs `tonic::Status::resource_exhausted`:** the OTLP gRPC spec recommends `RESOURCE_EXHAUSTED` for retriable saturation (not `UNAVAILABLE` — which means receiver down, different signal). HTTP analog is `503 Service Unavailable` (also retriable per RFC 9457). Both signal the client to back off + retry.
- **Per-receiver vs shared `IngestSender`:** chunk #18 uses ONE `Arc<IngestSender>` shared across both gRPC and HTTP receivers (single channel, both hand-off to same consumer). This matches arch §Established Decisions [In-Process Channel Architecture] "OTLP-ingest → DuckDB-appender hand-off". Per-receiver channels would multiply consumer logic + capacity discipline.
- **Placeholder consumer task** in `pulse-app/src/main.rs` step 11 is a *known* placeholder — it drains and drops `Batch` messages. The real DuckDB appender lands in Epoch 3 chunk #20. Wrap-session can flag this if the placeholder is forgotten past chunk #20; for now it's load-bearing scaffolding.
- **`MAX_ATTRIBUTE_KEY_BYTES = 256`, `MAX_ATTRIBUTE_VALUE_BYTES = 4096`, `MAX_ATTRIBUTES_PER_SPAN = 128`:** these are not pinned by spec or by specialist plans — they are reasonable starting bounds derived from common OTel semconv guidance (semconv recommends ≤128 chars per attribute key, ≤8KB per value, ≤128 attributes per scope). If specialist plan §X surfaces specific bounds at later review, /implement can adjust to match.
- **Why a fresh `From<IngestError> for AppError` impl rather than chaining through existing `AppError::internal(...)`:** `AppError::internal` produces `Internal { message }` variant, not `Ingest { message }`. For ingest-pipeline failures we want the `Ingest` variant on the wire so consumers can `match AppError::Ingest { .. } => …` distinctly from generic internals.
- **`crates/ingest/proptest-regressions/` dir convention:** if no failing seed has been replayed yet, an empty dir won't be tracked by git. Create `crates/ingest/proptest-regressions/.gitkeep` at /implement time so the dir is tracked even when empty.
