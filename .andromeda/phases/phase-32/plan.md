The route's stated capability "log stream with span correlation + severity colors" requires `trace_id` and `severity_text` columns on `LogRow` that do not exist today (current `LogRow` is 3 fields: `ts_unix_nano` / `resource_hash` / `severity_number`). Similarly, "time-series WebGPU compute aggregation" benefits from a `value` column on `MetricRow` that does not exist today (current `MetricRow` is 3 fields: `metric_name` / `ts_unix_nano` / `resource_hash`). Following chunk #34's buffer-schema-extension precedent (cross-crate ripple buffer/schema → buffer/appender → buffer/retention → viz/query → webview row decoder + tests), this plan defaults to **Path B (full schema extension)** to preserve the route's stated capability end-to-end. **Path A (UI shell only with placeholder data)** is preserved as a Phase 6 opt-out for users who want to defer the buffer ripple to a follow-up chunk; the implementation path will be confirmed at Phase 6 review before /andromeda-implement runs.

## Implementation notes

- **Phase 6 scope decision (recommended Path B):** chunk #35's stated capability "log stream with span correlation + severity colors" requires `trace_id` and `severity_text` fields on `LogRow` that don't exist today. Path B (full schema extension via cross-crate ripple buffer/schema → buffer/appender → buffer/retention → viz/query → webview row decoder + tests) preserves the route's stated capability end-to-end and mirrors chunk #34's precedent. Path A (UI shell only with placeholder data) preserves UI shipping speed at the cost of punting the body/trace_id surfaces to a follow-up chunk. The user already chose Path B for chunk #34; recommend the same here unless there's an ergonomic reason to defer.
- **Search/filter implementation: client-side filter chosen over server-side LogsQueryArgs extension.** v1 chunk #35 keeps the change set minimum: search filters loaded rows in-memory (LIMIT_DEFAULT=100, LIMIT_MAX=1000 per query.rs:10-11). Server-side filter is a deferred follow-up (extends LogsQueryArgs with `body_search: Option<String>` + `severity_filter: Vec<i32>` — backward-compatible struct addition, no new TauRPC procedure name needed; defer to chunk #36+ if needed).
- **Live log stream subscription deferred:** v1 chunk #35 ships with periodic refresh polling (refetch on TIME_WINDOW_SECONDS interval driven by the existing useEffect dep array). Live `streams.subscribe_logs` Arrow IPC subscription is documented capability but adds Channel substrate test surface; defer to a follow-up chunk if needed.
- **Severity tier mapping (4 tiers, 4 colors):** ERROR/FATAL → `--color-accent` border + text; WARN → `--color-accent` border + `--color-text-primary` text (the locked palette doesn't have a true warning hue; use the accent border + primary text combination per design extract recommendation, sidestepping the `--color-secondary / --color-base` undefined contrast pair flagged in a11y-plan §11); INFO → `--color-primary`; DEBUG/TRACE → `--color-text-tertiary` (large-text-only — apply only to row-level severity label sized ≥18px, not to dense row text).
- **Metrics chart aggregation: client-side aggregation over query result rows.** Per-bucket count (or per-bucket avg of `value` if Path B) computed client-side via per-row aggregator hook mirroring use-constellation-data.ts. No new server-side aggregation route. Bounded cardinality: bucket by metric_name (unbounded but small in practice) and time window (bounded N buckets per window). For LIMIT_DEFAULT=100 row count, client-side aggregation cost is trivial.
- **WGSL shader colors via CSSOM:** chart series colors flow through `readDesignToken('--color-primary', '#4A90E2')` etc. into `vec4<f32>` uniform values written to the buffer at canvas init (per .claude/rules/design-tokens.md Session Additions 2026-05-08). NO inline RGB literals in shader source.
- **Window-label conditional rendering:** MetricsRoute and LogsRoute live inside the Full dashboard window only. Compact widget window does not render either route per layout-templates.md §Primary screens. The chunk #32 `useWindowLabel()` hook already routes the dashboard ≠ widget split at App level; routes inside dashboard don't need additional window-label gating.
- **boot-smoke gate rationale:** chunk #35 doesn't directly touch `pulse-app/src/main.rs` or `crates/ui-bridge/src/`, but Path B extends DuckDB schema (CREATE TABLE) which executes at boot via `create_schema()`. A regression in DDL syntax or column-name typo could surface as a startup panic. Boot smoke (`npx @tauri-apps/cli dev` + 60s ready window + zero `app.panic.fatal` greps) catches this class of regression.
