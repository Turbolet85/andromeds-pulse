## 1. Test Scope Summary

**Test tier:** Standard (1)

**Justification:** Andromeda Pulse is a cross-platform desktop application (Windows/macOS/Linux via Tauri 2) with two primary surfaces (desktop-webview: React + WebGPU dashboard; desktop-native: tray icon + menu) and persistent in-memory data (DuckDB ring buffer holding 5–10 min of OTLP telemetry). The coverage scope spans 19 entities (8 library crates + ingest/buffer/viz layers + OTLP anti-pattern enforcement + Tauri capability gating + plugin sandbox + MCP sidecar), with 7 critical user-facing flows (ingest + visualize, generate curated snapshots, query via MCP, plugin lifecycle, widget ↔ dashboard toggle, real-time push, workspace detection). Security tier is Minimal (loopback-only binding, no persistent user accounts, no encrypted data at rest), but the architecture explicitly rejects 28+ attack vectors and enforces high-quality rejection logic (path canonicalization, SQL parameter binding, post-protobuf invariant checks, capability-scoped WASM sandbox, Minisign signature verification). Creator's risk tolerance signals "portfolio-worthy GPU-accelerated visualization" and "approach Jaeger UI quality", implying above-MVP quality bar. The agent-driven development style requires every test layer to be machine-parseable and runnable end-to-end with no human in the loop.

**Test harness requirements:**

_The 5-command harness, status-endpoint shape, log format, PID-file location, and test-data strategy are specified in full as current truth in **§3 Test Harness Contract** — see there. One-line summary: `boot` (Tauri `pulse-app`; accepts `ANDROMEDA_PULSE_*` env — `*_PORT` / `DATA_DIR` / `CONFIG_PATH` / `RUST_LOG`; confirms TCP handshake on `:4317`/`:4318`), `run` (`cargo nextest run --workspace`), `status` (`cargo xtask harness:status` — real-process verdict JSON `{verdict, pid, ended, log_file_basename, last_write_age_seconds, stale_after_seconds}` from PID file + that pid's liveness + log-family mtime — a dead pid is `not-running` — exits 0/1/1/2, per §3), `cleanup` (terminate the pid the pidfile holds — the app's own `write_pid_file` value is canonical — then probe pid liveness + both resolved OTLP ports independently; ONE bounded verdict token, exit 0 only on `clean`, per §3), `logs` (JSON-lines `tracing` output; resolves the ROTATED `agent-latest.jsonl*` family across three precedence-ordered bases, newest match within the first base that resolves — never a bare name and never a `*.log` glob, per §3). Status-endpoint JSON shape, agent-parseable log signals, per-OS PID paths, and the self-bootstrapping OTLP test-data strategy all live in §3 (and §7 Test Data & Fixtures)._

## 2. Test Strategy

**Test pyramid (per Standard tier):**

| Level | Coverage focus | Standard tier depth |
|-------|---------------|---------------------|
| Unit | Pure functions, isolated module logic (per-crate tests: ingest, buffer, viz, ui-bridge, snapshot, workspace-detector, plugins, mcp-server, corpus, triage, security, interpretation) | Comprehensive — 75% line coverage minimum; all module boundaries tested with mocked dependencies |
| Integration | Cross-module + IPC + DB + external boundaries (OTLP receivers to buffer roundtrip; TauRPC IPC to buffer query; Channel subscription flow) | Required — all Standard Contracts tested; each surface driver tested with live receiver + buffer |
| E2E | All 7 critical paths via surfaces (P1–P7 from test-scope Section 4) | All critical paths — each via tauri-driver (desktop-webview) or direct IPC client (TauRPC/MCP/Channels) |
| Property-based | Invariant assertions over random inputs (post-prost OTLP invariant checks; DuckDB retention window edge cases; Arrow schema validation) | Selective per trigger — performance-budget and chaos triggers in test-scope Sec 5 require property tests (10k spans/sec stress) |
| Performance / Load | Budget assertions on perf-critical paths (10k spans/sec throughput; token budget enforcement) | Trigger-driven — performance-budget and load-test triggers in test-scope Sec 5 require these |
| Chaos / Fault | Failure injection (buffer retention window enforcement; broadcast channel disconnect; WASM sandbox escape attempts) | Trigger-driven — chaos-test and security-vector triggers require these |

**Agent-runnable invariants (apply across all levels):**
- Every test layer produces machine-parseable output (exit code + structured stdout / JSON / log line)
- No human-in-loop verification, no manual screenshot comparison. **Headful GUI automation is IN scope when it is agent-driven** (operator ruling 2026-08-22): `tauri-driver` + `WebdriverIO`, invoked by `cargo xtask webview-drive`, presses real production controls across a 17-stage path in the live Tauri window, and the verdict comes from an exit code plus BOTH the app's own obs-log records and the driver's DOM report artifact — never from a human looking at it. The driver reports; only the Rust caller asserts. What stays banned is the human-in-the-loop half: a person confirming the result, or a screenshot approved by eye. Playwright/CDP (`connectOverCDP`) attaches successfully but remains UNADOPTED (measured 2026-08-23-webview-self-verify)
- Deterministic — no flaky retries, no real `setTimeout`, no real network except localhost stub (tonic gRPC on `:4317`, axum HTTP on `:4318`)
- Self-bootstrapping fixtures — no developer-seeded data; all fixture data generated at test runtime via OTLP ingest or Rust builders

**Test directory + naming conventions:**
- **Directory pattern:** co-located with source under each crate's `src/` (no separate `tests/` directory per upstream-context arch Test-Relevant Conventions) — **EXCEPT the `pulse-app` binary crate**, whose `[lib] test = false` (the Windows WebView2 load workaround) makes co-located `mod tests` in LIB sources compile under clippy but never run — **`main.rs` is exempt**: it is the `[[bin]]` target, whose tests genuinely execute (e.g. `emit_taurpc_bindings`). pulse-app's unit-shaped probes therefore live as separate integration-target files under `pulse-app/tests/*.rs`, reaching module internals via `pub` + `#[doc(hidden)]` accessors. **A mechanical RATCHET enforces this since chunk 2026-08-30-diagnostics-un-muting-harness-truth-sweep** (`pulse_app_src_carries_no_new_dead_test_attributes` in `pulse-app/tests/unit_observability_allowlist_sweep.rs`) — and since chunk 2026-08-30-dead-lib-src-test-migration it is a FLAT ZERO for every pulse-app lib-src file: `LEGACY_DEAD_BASELINE` drained to EMPTY, so any `#[test]` / `#[tokio::test]` reappearing in `pulse-app/src/` reds the build; `main.rs` exempt
- **File naming:** standard Rust test module naming (`#[cfg(test)] mod tests { … }`)
- **Test function naming:** `#[test]` functions and `#[tokio::test]` for async; per-module test submodules live in `src/` for the library crates, while pulse-app's are `#[test]` fns in `pulse-app/tests/*.rs`

## 11. Test Anti-Patterns (NEVER do these)

### Test Strategy

- NEVER violate test pyramid — avoid heavy E2E with sparse unit tests (slow + brittle feedback loop); Standard tier requires 75% line coverage at unit level
- NEVER over-mock at integration level (mocking OTLP gRPC receiver in `traces.query` test defeats the point) — use live loopback `:4317` / `:4318` + in-memory DuckDB
- NEVER run tests sequentially when parallelizable — `cargo nextest` enables parallel per-process by default (respects test isolation)
- NEVER skip `cargo deny check bans` (tonic 0.14 vs opentelemetry-otlp duplicate would cause linker conflicts)

### Unit

- NEVER test implementation details (private crate-internal functions) — test public module boundaries
- NEVER write assertions against builder fixture-internal IDs (e.g., assert `mock_span.internal_id == 42`) — assert on contract (span_id is 8 bytes, trace_id is 16 bytes)
- NEVER use `unwrap()` in tests without clear panic message — use `expect("reason why this must succeed")` or assert with context

### Integration

- NEVER mock DuckDB at integration level — always use ephemeral in-memory instance (`duckdb::open_in_memory()`)
- NEVER skip cleanup between integration tests (e.g., shared DuckDB connection across tests) — creates order-dependent failures
- NEVER assert on raw OTLP protobuf bytes (e.g., `assert_eq!(response.encode(), expected_bytes)`) — assert on decoded fields (service_name, latency_ms, etc.)

### E2E

- NEVER use xpath selectors — tauri-driver uses W3C WebDriver, prefer accessible-name / role-based selectors, or `data-testid` where no accessible name ships (**operative since 2026-08-23-integration-ux-e2e-test**: the webview-drive leg is DOM-driven, so this ban binds — it was moot only while the sole surface was procedure-based TauRPC)
- NEVER use `sleep(N)` for synchronization — wait for explicit signal via `health` status polling or Channel event subscription
- NEVER use brittle CSS selectors with hashed class names — accessible name first, `data-testid` as the fallback, never a hashed/utility class (**operative since 2026-08-23-integration-ux-e2e-test**, same reason as the xpath ban above)
- NEVER include visual regression checks requiring human approval (Percy / Chromatic) — pixel inspection is agent-untestable; assert IPC contract instead

### Test Data

- NEVER use production telemetry dumps in tests — generate synthetic spans via `MockTraceSpan::builder()`
- NEVER share mutable state across parallel tests — each test gets `tempfile::TempDir` + in-memory DuckDB
- NEVER use non-deterministic generators without seed control — `proptest` regression files in `proptest-regressions/` ensure replay
- NEVER pre-populate test DB via `.sql` scripts or SQLite snapshots — all fixture data generated at runtime

### Mocking

- NEVER mock the OTLP receiver you're testing — use live `tonic` gRPC client against loopback `:4317`
- NEVER use `mockall` for external libraries (e.g., tokio, tonic) — use real implementations; mock only traits you own
- NEVER monkey-patch production code at runtime (e.g., `std::env::set_var` mid-test without cleanup) — use constructor injection (`#[fixture] fn config() -> Config { … }`)
- NEVER serialize mocks into log files — mocks are test infrastructure only; assert on real behavior

### CI

- NEVER reference third-party GitHub Actions by floating tag (e.g., `tauri-action@v0`) — pin by 40-char commit SHA
- NEVER run tests sequentially in CI (set `--test-threads=1` only for debugging; remove before commit)
- NEVER ignore flaky tests — quarantine and fix immediately; flake = real bug
- NEVER lower coverage threshold to pass build — raise code quality instead

### Quality

- NEVER add retry-once policies for flaky tests (masks real failures)
- NEVER commit `#[ignore]` tests without open GitHub issue (tracking reason for skip)
- NEVER ship release with known test failures — all gates must be green

### Universal (agent-driven specific)

- NEVER use Percy / Chromatic / Applitools (visual regression with human review) — agent cannot approve screenshots
- NEVER include manual smoke step ("developer verifies build before deploy") — all verification automated
- NEVER use Selenium IDE / Playwright codegen-recorder as test author — use as headless runner only
- NEVER include "human reviews canvas" in test steps — canvas compilation success is sufficient (pixel inspection out of scope)
- NEVER use real network calls without mocks (e.g., calling external GitHub API in tests) — use loopback stubs
- NEVER use real time (`std::time::Instant::now()`, `chrono::Utc::now()`) without injection — use `tokio::time::pause()` for determinism
- NEVER expose secrets in test output (log PII, raw OTLP payloads with credentials) — use data sanitizers or explicit filtering

### Project-specific (andromeda-pulse)

- OTLP self-dialing (receiver instrumented with exporter pointing back to own `:4317`/`:4318`) is prevented **by construction** — no OTel SDK is linked into the self-observation runtime, so no exporter exists to misconfigure and no `ANDROMEDA_OBSERVER_URL`-shaped config surface exists (per obs-plan Phase 3.5 pivot). No negative test required. (Previously a "NEVER self-dial / negative test must assert" rule; deprecation history in test-plan-amendments.md.)
- NEVER dump raw OTLP JSON as snapshot (defeats token-efficiency design goal) — snapshot tests must assert dedup, anomaly markers, aggregates
- NEVER skip post-`prost` OTLP invariant checks (span_id != 8 bytes, trace_id != 16 bytes must be rejected) — negative tests validate
- NEVER bind OTLP receivers to `0.0.0.0` (breaks loopback-only security model) — tests must assert rejection of non-loopback binds
