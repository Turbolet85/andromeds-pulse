## Threat Model Summary

_[ALL tiers — VERBATIM copy from threat-assessment.md]_

**Security tier:** `Minimal (0)`

_Justification: This is a local-first, zero-infrastructure single-user desktop app (Design Philosophy + Project Intent) with no user accounts, no persistent user data store (in-memory DuckDB ring buffer with 5–10 min retention), no internet-exposed network surface (OTLP receivers bound to `127.0.0.1` only per Occupied Resources), and no compliance-regulated data classifications. Standard tier is not warranted because there is no public API, no user authentication surface, and no multi-tenant data; Hardened tier is not warranted because no payment, health, or compliance-regulated data is present._

**Data classification:**

- **Type:** user-content (telemetry payloads — traces, metrics, logs)
  - **Where:** OTLP receivers (`ingest` crate on `:4317`/`:4318`), DuckDB in-memory ring buffer (`buffer` crate, schema `pulse_buffer.main`, tables `spans`, `span_events`, `metrics_points`, `log_records` — the producer-less `span_links` / `resources` / `instrumentation_scopes` CREATEs were deleted at chunk 2026-08-30-diagnostics-un-muting-harness-truth-sweep), broadcast fan-out to viz/MCP, and curated snapshot markdown files written to `~/.andromeda-pulse/snapshots/`.
  - **Volume:** transient (5–10 min in-memory ring buffer, configurable via `ANDROMEDA_PULSE_RETENTION_SECONDS`); aggregate within retention window (10k spans/sec target). Snapshots persist to disk under the per-platform data dir.
  - **Sensitivity note:** Telemetry can contain incidentally captured secrets, IDs, URLs, error messages, and SQL fragments from the host application being instrumented. OTLP attributes are user-controlled content.

- **Type:** config (user settings)
  - **Where:** `~/.andromeda-pulse/config.toml`, env vars `ANDROMEDA_PULSE_*`. Surface is small: enum settings, port ranges, file paths, retention seconds, log level, MCP enabled flag, plugin dir.
  - **Volume:** per-user (single-user local app).

- **Type:** config (signing/release credentials — out of app runtime)
  - **Where:** GitHub Actions encrypted secrets and Azure Key Vault. Apple Developer ID for notarization. Updater public key is baked into the Tauri config.
  - **Volume:** N/A at runtime (build/release pipeline only); the binary ships only the public verification key.

- **Type:** user-content (third-party WASM plugin binaries)
  - **Where:** `~/.andromeda-pulse/plugins/` loaded by `wasmtime` Component Model host (`plugins` crate). Capability-scoped per WIT imports. Signed-plugin verification deferred post-v1.
  - **Volume:** per-user; arbitrary number.

- **Type:** user-content (persistent incident corpus — post-#68 substrate)
  - **Where:** `~/.andromeda-pulse/corpus/corpus.db` SQLite database (`corpus` crate). Holds 5 tables (6 → 5 at chunk 2026-08-30-diagnostics-un-muting-harness-truth-sweep — `baseline_state` DROPPED as dead schema via the SCHEMA_VERSION 1→2 ladder migration; its writer had moved to the file-based `baseline_persistence` path at chunk #72): `service_registry` (lifecycle state machine per chunk #71), `pipeline_metrics` (incl. storm-detector state per chunk #71 + Drain template-mining persistence per chunk #69), `incidents` + `incident_events` + `digest_archive` (Phase 7+ surfaces). All cell-level encrypted via AES-256-GCM. The 32-byte key comes from the OS credential store primary (`MacosKeychain` / `LinuxSecretService` / `WindowsDpapi` via the `keyring` crate, declared with the explicit platform feature set) OR the opt-in passphrase-fallback-with-warning posture per chunk #73 P-049 (`BackendKind::PassphraseFallback`). Both branches are reached as of 2026-08-15-corpus-key-persistence: the key persists across processes (measured — a second boot decrypted its predecessor's rows with 0 `decryption_failed`), concurrent first-run processes converge on one key through the locked create-or-read (measured at 2026-10-04-corpus-key-creation-is-race-free — 8 processes, 1 distinct key), and the fallback emits its once-per-boot WARN when configured and the store is unreachable or the corpus-key lock dir is unusable (see §Secret Management → Runtime).
  - **Volume:** per-user persistent; bounded by retention/compaction (pipeline_metrics rolls off per chunk #69 cadence).
  - **Sensitivity note:** Corpus stores PII-scrubbed projections of telemetry per chunk #72 uniform-scrubber coverage (OTLP attribute values pass through `security::scrubber::mask_secret_spans` — span-level masking gated by `scrub_attribute`'s verdict, since 2026-09-30-span-level-redaction — at every CORPUS write path before write — the corpus projections are covered; the DuckDB ring buffer's five client-controlled cells are covered too since 2026-08-23 — four columns, plus `metrics_points.labels` since 2026-08-23-metrics-points-labels — see §Security Anti-Patterns → Logging, which also records the ring buffer as still unencrypted). At-rest confidentiality protected by AES-256-GCM cell encryption; integrity by GCM authentication tag. Pre-chunk-#70 flat-file `baseline-corpus.bin` artifact is eliminated; no plaintext runtime state survives on disk.

- **Type:** none — credentials / PII / payment / health
  - **Where:** N/A. No user accounts, no payment SDK, no identity provider, no health-domain framing.

**Attack surface:**

- **Vector:** public API (network-bound on loopback only)
  - **Entry point:** OTLP/gRPC on `:4317` and OTLP/HTTP on `:4318`, both bound `127.0.0.1` only. Routes `POST /v1/traces`, `POST /v1/metrics`, `POST /v1/logs`. Wire formats: protobuf via `prost`/`tonic` decode, plus HTTP/JSON.
  - **Trust boundary:** `prost`/`tonic` protobuf decode validates wire shape. Loopback-only binding means any local process (including unprivileged user processes, container sidecars, browser tabs via DNS rebinding considerations) can post telemetry. No auth declared at this surface.

- **Vector:** IPC (Tauri TauRPC bridge — webview ↔ Rust)
  - **Entry point:** Procedures: top-level `app_info`, `health`, `ready`, `get_settings`, `update_settings`; routers `traces.*`, `metrics.*`, `logs.*`, `snapshot.{generate,list_recent,copy_to_clipboard}`, `plugins.{list,reload,invoke}`, `mcp.{status,start,stop}` (feature-gated), `workspace.{detect,list}`. Real-time push events `pulse://stream/*` via Tauri IPC `Channel` API with binary Arrow IPC payloads.
  - **Trust boundary:** Tauri 2 capability gating admits the webview to the IPC LAYER as a whole — `pulse:default` does not enumerate individual procedures (TauRPC dispatches every router method through one invoke handler; measured 2026-08-21). Per-procedure coverage therefore rests on argument-level validation plus the `EXPECTED_PROCEDURES` drift gate, not on the capability layer. Errors crossing the bridge are forced to `Serialize`-able `AppError` enum variants. Validation surface relies on `serde` deserialization plus `TryFrom<u16>` for ports/enums.

- **Vector:** plugin host (WASM Component Model)
  - **Entry point:** `~/.andromeda-pulse/plugins/` filesystem load by `wasmtime` 25+ via `plugins` crate; `plugins.invoke` IPC dispatches into a guest. Capability `pulse:plugin-fs` gates host's read of the plugin dir.
  - **Trust boundary:** Capability-scoped sandboxing — guests receive only host imports declared in their WIT. No syscalls, file, or socket access unless explicitly granted in WIT. Signed-plugin verification deferred post-v1.

- **Vector:** MCP stdio surface (feature-gated)
  - **Entry point:** `andromeda-pulse-mcp` sidecar — hand-rolled serde JSON-RPC 2.0 over stdin/stdout (`crates/mcp-server/src/jsonrpc.rs`; `rmcp` is a feature-gated anchor import, not the protocol layer — measured chunk `2026-08-29-advisory-backlog`): `initialize`, `tools/list`, `tools/call`, `notifications/*`. Tools: 9 — `query_traces`, `query_metrics`, `query_logs`, `generate_snapshot` (telemetry) + `query_incident_list`, `retrieve_report`, `retrieve_telemetry_slice`, `mark_incident_resolved` (corpus-backed, chunk #94) + `retrieve_incident_events` (corpus-backed, read-only, chunk `2026-10-02-incident-events-readable-through-mcp`: returns only a coerced closed event-kind label + a timestamp per event, bounded at 256). Only present when `--features mcp-server` AND `ANDROMEDA_PULSE_MCP_ENABLED=true`. **Stdio is no longer its only input:** since chunk 2026-08-14-workspace-key-alignment the sidecar also reads `<data_dir>/run/workspace-key` at `init_incident_context`, falling back to `data_dir` on any absent or invalid value.
  - **Trust boundary:** Stdio caller is whatever process the user launched the sidecar from (typically an LLM client). No network exposure. JSON-RPC framing per MCP spec. The published-key read is validated per §Input Validation (bounded, UTF-8, control-char rejected) and consumed only as an opaque filter string.

- **Vector:** filesystem reads (config + workspace detection)
  - **Entry point:** `config.toml` under per-platform data dir; env-var-overridable paths (`ANDROMEDA_PULSE_CONFIG_PATH`, `ANDROMEDA_PULSE_DATA_DIR`, `ANDROMEDA_PULSE_PLUGIN_DIR`); workspace-detector crate inspects host project context (`workspace.detect`, `workspace.list`); `<data_dir>/run/workspace-key`, written by the app and read by the sidecar (chunk 2026-08-14-workspace-key-alignment).
  - **Trust boundary:** arch declares only `serde` + smart enum types + `TryFrom<u16>`. For the published workspace key the discipline IS declared (§Input Validation): canonicalize-and-confine on write, bounded + UTF-8 + control-char-rejecting read, and the value used only as an opaque filter string, never as a path.

- **Vector:** in-app updater
  - **Entry point:** `tauri-plugin-updater` 2.x consuming `latest.json` from GitHub Releases.
  - **Trust boundary:** Updater public key baked into Tauri config; updater capability `pulse:updater` is bound to the plugin flow and "is not exposed to webview JavaScript."

- **Vector:** OS notification / tray surfaces
  - **Entry point:** `tauri-plugin-notification` (capability `pulse:notification`); tray icon (capability `pulse:tray`). Outbound user-facing only.
  - **Trust boundary:** Outbound surfaces; not an input vector. Capability-gated.

- **Vector:** CLI input (env vars + binary launch)
  - **Entry point:** Reserved env vars `ANDROMEDA_PULSE_*`, `RUST_LOG`, plus the system `XDG_RUNTIME_DIR` (Linux; the corpus-key lock dir, read by both product binaries through `Corpus::open` since chunk `2026-10-04-corpus-key-creation-is-race-free`), and the system `__NV_DISABLE_EXPLICIT_SYNC` (Linux; presence-read at the head of `main()` and product-set to `1` when absent, since chunk `2026-10-04-linux-launch-stays-up-on-nvidia-wayland`).
  - **Trust boundary:** `serde` + `TryFrom<u16>` for ports; an MCP feature-flag env-var mismatch logs a warning rather than failing. `XDG_RUNTIME_DIR` is trimmed, then — when set — must be absolute, `canonicalize()` and be a directory, else lock-dir resolution FAILS CLOSED (never a fallback); it is deliberately not confined under the data dir (founder-ratified 2026-10-04; §Security Anti-Patterns → Input). Product-consumed path env vars are trim + traversal-rejected + length-bounded (4096) + `canonicalize()`d + asserted regular-file, with confinement OPT-IN via `ANDROMEDA_PULSE_L4_ALLOW_ROOT` for the three L4 vars (fail-closed when that root is set but unresolvable); the harness-only carve-out — tool-locator vars, plus the `agent-run.{sh,ps1}` `.spawn` / `.exit` boot-recorder state files, none product-consumed — stands per §Security Anti-Patterns → Input. `__NV_DISABLE_EXPLICIT_SYNC` is presence-only — never parsed, never logged; a preset value is honoured, never overwritten; the product writes the process environment only before any thread exists, and WebKitGTK's child processes inherit the value (founder-ratified widening 2026-10-04). Residual: a host that presets `0` keeps the NVIDIA + Wayland launch death, by design.

- **Vector:** webview content (host-side)
  - **Entry point:** WebView2 (Windows) / WKWebView (macOS/Linux). WebGPU canvas rendered from Arrow data. Webview source under `pulse-app/ui/`.
  - **Trust boundary:** Tauri capability model (`pulse:default`) gates IPC procedures; no `fs`, `shell`, `dialog`, `http` core APIs granted. WGSL shaders are first-party.

- **Vector:** none — public internet API, OAuth flow, webhook, file upload from internet
  - All N/A. Local-only desktop app; no inbound internet exposure.

**Auth model:**
- **Approach:** none
- **Provider:** N/A
- **Scope:** N/A — Tauri capability-based authorization (`pulse:default`) is the trust model; the OS user owns the app. Loopback-only OTLP binding is the de facto authorization boundary.

**Infrastructure:**
- **Hosting:** local-only — public OSS desktop app distributed via GitHub Releases; runs as a single Tauri process on the user's Windows/macOS/Linux machine.
- **Database:** embedded — DuckDB 1.5.x via `duckdb` crate, in-memory `:memory:` connection (`pulse_buffer`), no persistent disk database.
- **Networking:** local only — OTLP receivers bound `127.0.0.1` only; MCP over stdio (no socket); updater is outbound HTTPS to GitHub Releases; no inbound internet exposure.
- **CI/CD:** GitHub Actions — `ci.yml` (fmt + clippy + xtask test + workspace build, matrix Linux/macOS/Windows); `release.yml` (`tauri-action` builds `.msi`/`.dmg`/`.AppImage`/`.deb`, signs Windows via Azure Key Vault EV, notarizes macOS via Apple Developer ID, uploads bundles + `latest.json` to GitHub Releases); `update-channels.yml` (Homebrew tap + Scoop manifest). Code-signing secrets live in GitHub Actions encrypted secrets and Azure Key Vault.

None — no compliance-regulated data detected. No payment SDK → no PCI DSS. No user accounts / no PII collection by the app itself; telemetry stays on the local machine within v1 → no GDPR-as-controller posture. No health-domain framing → no HIPAA. No children's-product framing → no COPPA.

## Error Handling

_[ALL tiers]_

**External responses (to API consumers / end users):** sanitized — no stack

- **TauRPC bridge:** every `#[taurpc::procedure]` returns `Result<T, AppError>` per Conventions Error response schema (Tauri IPC). `AppError` is a `serde`-friendly enum with stable variants `Validation { field, reason }`, `NotFound { resource }`, `Internal { message }`, `Plugin { plugin_id, message }`, `Storage { message }`, `Ingest { message }`. Module-internal `thiserror` 2.x enums convert at the bridge via `From` impls. **Uniform scrubber coverage (post-chunk-#72 reality, corrected as measured 2026-08-22):** The PII scrubber (`crates/security/src/scrubber.rs`, chunk #68 substrate — since chunk `2026-09-30-span-level-redaction` reached through `security::scrubber::mask_secret_spans` at every boundary but one, `scrub_attribute` staying its detection verdict) is invoked at the persistence boundaries enumerated below — not single-site as the pre-#72 plan body implied. **The catalog carries EIGHT categories** since chunk `2026-08-22-pii-scrubber-recall`: JWT · bearer · api_key · secret_kv · **provider_key** · email · credit_card · ssn. The eighth (`provider_key`) closes the BARE-CREDENTIAL recall gap — the four credential arms before it are all key-name-anchored, so a standalone `sk_live_…` / `sk-proj-…` / `ghp_…` / `AKIA…` token matched nothing and reached stored fields verbatim (measured RED before the fix on both `log_records.body` and `span_events.exception_message`). It is anchored-prefix + length-floor by design, ordered after the keyed arms so `api_key=` keeps its own category and before `credit_card` so a digit-heavy key is not mis-labelled; the module's stated posture is recall over precision for seven of the eight arms, bounded by a false-positive corpus that keeps ordinary high-entropy identifiers Allowed. **The `credit_card` arm is precision-gated** since chunk `2026-09-29-scrubber-path-false-positive` (founder ratification 2026-09-30, "Luhn on windows"): its regex finds a candidate run of ASCII digit groups joined by single ` ` / `-` (`\b[0-9]+(?:[ \-][0-9]+)*\b`), and the arm matches only when some window of consecutive WHOLE groups carrying 13–19 digits passes Luhn — which every issued card number does (ISO/IEC 7812). It replaced the checksum-free `\b(?:\d[ \-]?){13,19}\b`. Windows never split a group, because Luhn at arbitrary offsets would pass most long digit runs by chance. This closes the measured harness-basename false positive: a date-time stamp such as `rm-20260923-093840` in a path, a `workspace=` key or the digest's `PROJECT:` line, and a 19-digit nanosecond timestamp, now return `Allowed` (as measured at `crates/security/src/scrubber.rs::scrubber_allows_non_card_digit_runs`, mutation-checked in both directions). **Accepted recall trade:** a Luhn-invalid (mistyped) card number, or one fused inside a longer single digit group, is no longer redacted. **Span-level masking replaces whole-value replacement** since chunk `2026-09-30-span-level-redaction` (a Boundary widening, founder ratification at P4 2026-10-01, «Ок давай по типу правила»): `mask_secret_spans` masks each secret where it sits and keeps the rest of the value byte-identical, so one card number no longer blanks a whole digest. The extent is CLASS-AWARE — keyed arms (`bearer`, `api_key`, `secret_kv`) mask from the key word to the end of the line holding the match end; bare arms (`jwt`, `provider_key`, `email`, `ssn`) mask the whole whitespace-delimited token; `credit_card` masks the Luhn-qualifying digit-group run; overlapping or touching spans merge under the earliest arm in catalog order. That extent is what keeps never-weaken: a multi-word value after `password:` and a base64 bearer tail past `+` / `/` (both outside their arm's regex match) are masked to the end of their line. Detection is unchanged — `scrub_attribute`'s verdict gates the mask (equality pinned over the recall and false-positive corpora and two proptests), a flagged value with no locatable span masks whole (fail closed), and a single-token secret masks exactly as whole-value replacement did. Masking re-runs to a bounded fixpoint (at most 4 extra passes), because a mask can expose a match its neighbour hid (a Luhn-valid digit run fused to a key word becomes a card candidate once the key is masked — as measured at the chunk's mutation m4, a proptest shrinking to exactly that case). Whole-value replacement survives at ONE site: `metrics_points.labels` (`encode_labels`, the only production `scrub_attribute` caller — see the third scrub shape below).
