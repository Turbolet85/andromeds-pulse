## Threat Model Summary

_[ALL tiers — VERBATIM copy from threat-assessment.md]_

**Security tier:** `Minimal (0)`

_Justification: This is a local-first, zero-infrastructure single-user desktop app (Design Philosophy + Project Intent) with no user accounts, no persistent user data store (in-memory DuckDB ring buffer with 5–10 min retention), no internet-exposed network surface (OTLP receivers bound to `127.0.0.1` only per Occupied Resources), and no compliance-regulated data classifications. Standard tier is not warranted because there is no public API, no user authentication surface, and no multi-tenant data; Hardened tier is not warranted because no payment, health, or compliance-regulated data is present._

**Data classification:**

- **Type:** user-content (telemetry payloads — traces, metrics, logs)
  - **Where:** OTLP receivers (`ingest` crate on `:4317`/`:4318`), DuckDB in-memory ring buffer (`buffer` crate, schema `pulse_buffer.main`, tables `spans`, `span_events`, `span_links`, `metrics_points`, `log_records`, `resources`, `instrumentation_scopes`), broadcast fan-out to viz/MCP, and curated snapshot markdown files written to `~/.andromeda-pulse/snapshots/`.
  - **Volume:** transient (5–10 min in-memory ring buffer, configurable via `ANDROMEDA_PULSE_RETENTION_SECONDS`); aggregate within retention window (10k spans/sec target). Snapshots persist to disk under the per-platform data dir.
  - **Sensitivity note:** Telemetry can contain incidentally captured secrets, IDs, URLs, error messages, and SQL fragments from the host application being instrumented. OTLP attributes are user-controlled content.

- **Type:** config (user settings)
  - **Where:** `~/.andromeda-pulse/config.toml`, env vars `ANDROMEDA_PULSE_*`. Surface is small: enum settings, port ranges, file paths, retention seconds, log level, MCP enabled flag, plugin dir.
  - **Volume:** per-user (single-user local app).

- **Type:** config (signing/release credentials — out of app runtime)
  - **Where:** GitHub Actions encrypted secrets and Azure Key Vault. Apple Developer ID for notarization. Updater public key is baked into the Tauri config.
  - **Volume:** N/A at runtime (build/release pipeline only); the binary ships only the public verification key.

- **Type:** user-content (third-party WASM plugin binaries)
  - **Where:** `~/.andromeda-pulse/plugins/` loaded by `wasmtime` Component Model host (`plugins` crate). Capability-scoped per WIT imports. Signed-plugin verification deferred post-v1.
  - **Volume:** per-user; arbitrary number.

- **Type:** user-content (persistent incident corpus — post-#68 substrate)
  - **Where:** `~/.andromeda-pulse/corpus/corpus.db` SQLite database (`corpus` crate). Holds 6 tables: `baseline_state` (per-service streaming-percentile snapshots per chunk #70), `service_registry` (lifecycle state machine per chunk #71), `pipeline_metrics` (incl. storm-detector state per chunk #71 + Drain template-mining persistence per chunk #69), `incidents` + `incident_events` + `digest_archive` (Phase 7+ surfaces). All cell-level encrypted via AES-256-GCM. The 32-byte key comes from the OS credential store primary (`MacosKeychain` / `LinuxSecretService` / `WindowsDpapi` via the `keyring` crate, declared with the explicit platform feature set) OR the opt-in passphrase-fallback-with-warning posture per chunk #73 P-049 (`BackendKind::PassphraseFallback`). Both branches are reached as of 2026-08-15-corpus-key-persistence: the key persists across processes (measured — a second boot decrypted its predecessor's rows with 0 `decryption_failed`), and the fallback emits its once-per-boot WARN when configured and the store is unreachable (see §Secret Management → Runtime).
  - **Volume:** per-user persistent; bounded by retention/compaction (pipeline_metrics rolls off per chunk #69 cadence + baseline_state snapshots at 60s intervals per chunk #70).
  - **Sensitivity note:** Corpus stores PII-scrubbed projections of telemetry per chunk #72 uniform-scrubber coverage (OTLP attribute values pass through `security::scrubber::scrub_attribute` at every CORPUS write path before write — the corpus projections are covered; the DuckDB ring buffer's five client-controlled cells are covered too since 2026-08-23 — four columns, plus `metrics_points.labels` since 2026-08-23-metrics-points-labels — see §Security Anti-Patterns → Logging, which also records `instrumentation_scopes` as producer-less and the ring buffer as still unencrypted). At-rest confidentiality protected by AES-256-GCM cell encryption; integrity by GCM authentication tag. Pre-chunk-#70 flat-file `baseline-corpus.bin` artifact is eliminated; no plaintext runtime state survives on disk.

- **Type:** none — credentials / PII / payment / health
  - **Where:** N/A. No user accounts, no payment SDK, no identity provider, no health-domain framing.

**Attack surface:**

- **Vector:** public API (network-bound on loopback only)
  - **Entry point:** OTLP/gRPC on `:4317` and OTLP/HTTP on `:4318`, both bound `127.0.0.1` only. Routes `POST /v1/traces`, `POST /v1/metrics`, `POST /v1/logs`. Wire formats: protobuf via `prost`/`tonic` decode, plus HTTP/JSON.
  - **Trust boundary:** `prost`/`tonic` protobuf decode validates wire shape. Loopback-only binding means any local process (including unprivileged user processes, container sidecars, browser tabs via DNS rebinding considerations) can post telemetry. No auth declared at this surface.

- **Vector:** IPC (Tauri TauRPC bridge — webview ↔ Rust)
  - **Entry point:** Procedures: top-level `app_info`, `health`, `ready`, `get_settings`, `update_settings`; routers `traces.*`, `metrics.*`, `logs.*`, `snapshot.{generate,list_recent,copy_to_clipboard}`, `plugins.{list,reload,invoke}`, `mcp.{status,start,stop}` (feature-gated), `workspace.{detect,list}`. Real-time push events `pulse://stream/*` via Tauri IPC `Channel` API with binary Arrow IPC payloads.
  - **Trust boundary:** Tauri 2 capability gating admits the webview to the IPC LAYER as a whole — `pulse:default` does not enumerate individual procedures (TauRPC dispatches every router method through one invoke handler; measured 2026-08-21). Per-procedure coverage therefore rests on argument-level validation plus the `EXPECTED_PROCEDURES` drift gate, not on the capability layer. Errors crossing the bridge are forced to `Serialize`-able `AppError` enum variants. Validation surface relies on `serde` deserialization plus `TryFrom<u16>` for ports/enums.

- **Vector:** plugin host (WASM Component Model)
  - **Entry point:** `~/.andromeda-pulse/plugins/` filesystem load by `wasmtime` 25+ via `plugins` crate; `plugins.invoke` IPC dispatches into a guest. Capability `pulse:plugin-fs` gates host's read of the plugin dir.
  - **Trust boundary:** Capability-scoped sandboxing — guests receive only host imports declared in their WIT. No syscalls, file, or socket access unless explicitly granted in WIT. Signed-plugin verification deferred post-v1.

- **Vector:** MCP stdio surface (feature-gated)
  - **Entry point:** `andromeda-pulse-mcp` rmcp sidecar. JSON-RPC 2.0 over stdin/stdout: `initialize`, `tools/list`, `tools/call`, `notifications/*`. Tools: `query_traces`, `query_metrics`, `query_logs`, `generate_snapshot`. Only present when `--features mcp-server` AND `ANDROMEDA_PULSE_MCP_ENABLED=true`. **Stdio is no longer its only input:** since chunk 2026-08-14-workspace-key-alignment the sidecar also reads `<data_dir>/run/workspace-key` at `init_incident_context`, falling back to `data_dir` on any absent or invalid value.
  - **Trust boundary:** Stdio caller is whatever process the user launched the sidecar from (typically an LLM client). No network exposure. JSON-RPC framing per MCP spec. The published-key read is validated per §Input Validation (bounded, UTF-8, control-char rejected) and consumed only as an opaque filter string.

- **Vector:** filesystem reads (config + workspace detection)
  - **Entry point:** `config.toml` under per-platform data dir; env-var-overridable paths (`ANDROMEDA_PULSE_CONFIG_PATH`, `ANDROMEDA_PULSE_DATA_DIR`, `ANDROMEDA_PULSE_PLUGIN_DIR`); workspace-detector crate inspects host project context (`workspace.detect`, `workspace.list`); `<data_dir>/run/workspace-key`, written by the app and read by the sidecar (chunk 2026-08-14-workspace-key-alignment).
  - **Trust boundary:** arch declares only `serde` + smart enum types + `TryFrom<u16>`. For the published workspace key the discipline IS declared (§Input Validation): canonicalize-and-confine on write, bounded + UTF-8 + control-char-rejecting read, and the value used only as an opaque filter string, never as a path.

- **Vector:** in-app updater
  - **Entry point:** `tauri-plugin-updater` 2.x consuming `latest.json` from GitHub Releases.
  - **Trust boundary:** Updater public key baked into Tauri config; updater capability `pulse:updater` is bound to the plugin flow and "is not exposed to webview JavaScript."

- **Vector:** OS notification / tray surfaces
  - **Entry point:** `tauri-plugin-notification` (capability `pulse:notification`); tray icon (capability `pulse:tray`). Outbound user-facing only.
  - **Trust boundary:** Outbound surfaces; not an input vector. Capability-gated.

- **Vector:** CLI input (env vars + binary launch)
  - **Entry point:** Reserved env vars `ANDROMEDA_PULSE_*`, `RUST_LOG`.
  - **Trust boundary:** `serde` + `TryFrom<u16>` for ports; an MCP feature-flag env-var mismatch logs a warning rather than failing. Product-consumed path env vars are trim + traversal-rejected + length-bounded (4096) + `canonicalize()`d + asserted regular-file, with confinement OPT-IN via `ANDROMEDA_PULSE_L4_ALLOW_ROOT` for the three L4 vars (fail-closed when that root is set but unresolvable); the harness-only tool-locator carve-out is unchanged.

- **Vector:** webview content (host-side)
  - **Entry point:** WebView2 (Windows) / WKWebView (macOS/Linux). WebGPU canvas rendered from Arrow data. Webview source under `pulse-app/ui/`.
  - **Trust boundary:** Tauri capability model (`pulse:default`) gates IPC procedures; no `fs`, `shell`, `dialog`, `http` core APIs granted. WGSL shaders are first-party.

- **Vector:** none — public internet API, OAuth flow, webhook, file upload from internet
  - All N/A. Local-only desktop app; no inbound internet exposure.

**Auth model:**
- **Approach:** none
- **Provider:** N/A
- **Scope:** N/A — Tauri capability-based authorization (`pulse:default`) is the trust model; the OS user owns the app. Loopback-only OTLP binding is the de facto authorization boundary.

**Infrastructure:**
- **Hosting:** local-only — public OSS desktop app distributed via GitHub Releases; runs as a single Tauri process on the user's Windows/macOS/Linux machine.
- **Database:** embedded — DuckDB 1.5.x via `duckdb` crate, in-memory `:memory:` connection (`pulse_buffer`), no persistent disk database.
- **Networking:** local only — OTLP receivers bound `127.0.0.1` only; MCP over stdio (no socket); updater is outbound HTTPS to GitHub Releases; no inbound internet exposure.
- **CI/CD:** GitHub Actions — `ci.yml` (fmt + clippy + xtask test + workspace build, matrix Linux/macOS/Windows); `release.yml` (`tauri-action` builds `.msi`/`.dmg`/`.AppImage`/`.deb`, signs Windows via Azure Key Vault EV, notarizes macOS via Apple Developer ID, uploads bundles + `latest.json` to GitHub Releases); `update-channels.yml` (Homebrew tap + Scoop manifest). Code-signing secrets live in GitHub Actions encrypted secrets and Azure Key Vault.

**Compliance triggers:**

None — no compliance-regulated data detected. No payment SDK → no PCI DSS. No user accounts / no PII collection by the app itself; telemetry stays on the local machine within v1 → no GDPR-as-controller posture. No health-domain framing → no HIPAA. No children's-product framing → no COPPA.

**At rest — per medium:**

For Minimal tier, the at-rest controls reduce to:

- **DuckDB ring buffer:** in-memory `:memory:` connection (`pulse_buffer`) with no persistent disk database per Established Decisions Telemetry Retention Surface; encryption is N/A and DuckDB encryption CVE-2025-64429 is not applicable. ### Input

- NEVER trust `Content-Length` or trailers as a substitute for `axum::extract::DefaultBodyLimit` / `tower_http::limit::RequestBodyLimitLayer` on the OTLP HTTP `:4318` routes — the JFrog axum-core advisory documents this as the root cause of unbounded request DoS.
- NEVER `format!("SELECT … WHERE service_name = '{}'", user_input)` against the `duckdb` crate `Connection`; ALWAYS use `Connection::prepare` with `?` placeholders and `Statement::execute([&param])` parameter binding — the Dagster GHSA-mjw2-v2hm-wj34, Vanna CVE-2024-5827, dagster-duckdb CVE-2026-41490 cluster proves this is the dominant 2026 DuckDB vuln class. DuckDB explicitly warns: "Treat SQL in DuckDB like code in Bash or Python and do not execute SQL from untrusted sources without proper sandboxing."
- NEVER skip post-`prost`-decode invariant checks on OTLP payloads — `prost` only validates wire format; `span_id` is 8 bytes, `trace_id` is 16 bytes, attribute keys aren't 1 GB, etc. must be checked in the `ingest` crate before handing to `buffer::Appender` per security-research §prost.
- NEVER read a **product-binary** `ANDROMEDA_PULSE_*_PATH` / `*_DIR` env var without `std::path::Path::canonicalize()` + an assertion that the canonical path starts under the resolved per-platform data dir (or under the explicit override base if `ANDROMEDA_PULSE_DATA_DIR` is set). **Carve-out — harness/xtask-only tool-locator vars:** a path var that is NOT consumed by the production binary and resolves an EXTERNAL tool which by design lives outside the data dir (`ANDROMEDA_PULSE_MSEDGEDRIVER_PATH`; the pre-existing `ANDROMEDA_PULSE_PIDFILE` / `_LOGFILE` are the same class) is guarded instead by a trim + `is_file()` existence check with a clean skip on absence. Confinement is inapplicable there — the tool is deliberately out-of-tree — and the var never reaches the shipped binary, so the CWE-22 surface it would otherwise widen does not exist. The carve-out is scoped to exactly that: harness-only, not-production-consumed, existence-guarded.

**NARROWED EXCEPTION — three product-consumed path vars are guarded, with confinement opt-in (guard landed 2026-08-26, chunk `2026-08-26-l4-runtime-security-residuals`; exception first recorded 2026-08-26 at chunk `2026-08-25-demo-injector-formalized-api-surface-retire`).** The sentence that stood here previously — "Everything the product reads stays under the categorical rule" — was FALSE, and had been since chunk #84. `ANDROMEDA_PULSE_MODEL_PATH` · `ANDROMEDA_PULSE_LLAMA_CUDA_BIN_PATH` · `ANDROMEDA_PULSE_LLAMA_CPU_BIN_PATH` are read by the SHIPPED binary (`pulse-app/src/llamacli_inference.rs`, `read_env_path` → `canonicalize_path` at construction), so the harness-only carve-out above does NOT reach them. **What they DO enforce:** trim + reject-empty, `canonicalize()`, and an assert that the resolved path is a REGULAR FILE (a directory or symlink-to-directory is rejected) — the half of the CWE-22 defense that resolves `..` and symlink chains. **What they ADDITIONALLY enforce since the guard landed:** a `..` traversal component is rejected BEFORE canonicalization (canonicalization erases `..`, so a post-check could never observe it), a raw value over `MAX_PATH_INPUT_BYTES` (4096) is rejected, and — when `ANDROMEDA_PULSE_L4_ALLOW_ROOT` resolves to a directory — the canonicalized candidate must live under the canonicalized root, both sides canonicalized per the `publish_workspace_key` precedent. A root that is SET but unresolvable **fails closed**, rejecting every candidate. **What is still deliberately OMITTED:** the categorical data-dir confinement assert of the ban above. Confinement is OPT-IN, not defaulted, with the rationale stated in code at `canonicalize_path` and unchanged in substance — the GGUF model and the prebuilt `llama-cli.exe` live outside the data dir by design and their distribution is an explicitly OPEN arch caveat, so a data-dir default would reject every configuration that has ever run L4 on this project. **Consequence, stated plainly and now scoped:** on a host that does NOT set `ANDROMEDA_PULSE_L4_ALLOW_ROOT`, an attacker who can set these env vars can still point the product at an arbitrary on-disk file — reading it as a model, or EXECUTING it as the inference binary. What changed is that this is no longer a silent convention: the unconfined posture is announced once per boot at WARN on `interpretation.model.allow_root`, and an enforcement mechanism is available to any host that wants it. That is a meaningful escalation over the msedgedriver carve-out, whose var never reaches the shipped binary. It is bounded by the same trust boundary as the rest of this tier (local single-user desktop; an attacker who can set the victim's environment has other paths), which is why it was accepted rather than blocking — but it is an accepted risk, not an absent one. **Owner: DISCHARGED** — the working-route entry *"L4 runtime security residuals"* landed as chunk `2026-08-26-l4-runtime-security-residuals`. The sibling argv-prompt residual it also owned is **CLOSED**: the digest-derived, OTLP-sourced `-p` value now passes `validate_prompt_bounded` at its single production caller before `build_llama_cli_args` is invoked (see the L4-argv row in §Input Validation). What remains is the scoped consequence above — opt-in confinement, announced when off — not a pending obligation. This is a CWE-22 (Path Traversal) class defense; specific 2025–2026 CVE anchors (e.g., zip crate CVE-2025-29787, RustFS CVE-2025-68705) involve crates not in this project's dependency graph but document the same symlink-chain / TOCTOU traversal class that `tauri-plugin-fs`-style file APIs and any user-overridable path env-var construct are equally exposed to. The canonicalize-and-confine primitive used HERE is `std` both-sides-canonicalize on the `workspace_detector::contract::publish_workspace_key` precedent, NOT `strict-path`, which was evaluated and declined for this boundary at the chunk-`2026-08-26` P4 review (zero `.rs` users repo-wide; unmeasured Windows `\\?\` behaviour; a security guard is the worst place for a library's first use). `strict-path` per §Bootstrap phases `input-validation-library-install` remains the intended primitive for the other product path boundaries.
- NEVER call `tonic::transport::Server::builder()...add_service(generated_server)` without `.max_decoding_message_size(8 * 1024 * 1024)` set on each `*ServiceServer` builder — `tonic` historically accepted 1 GB+ unary requests by default per security-research §tonic.
- NEVER trust plugin-returned Arrow IPC bytes without a size cap before re-emitting on the Tauri `Channel` API.

### Data Protection

- NEVER add a non-Cranelift `wasmtime` feature flag on x86_64 builds without re-checking the April 2026 advisory cluster — Cranelift backend on x86_64 was the unaffected configuration for the two Critical sandbox escapes (CVE-2026-34941, CVE-2026-35195). A future "use the experimental Winch backend" change would re-introduce the exposure per security-research §wasmtime 25+.

### API

- NEVER use `tower_http::cors::CorsLayer::permissive()` or `allow_origin(Any)` on the OTLP HTTP `:4318` router — default-deny is the correct posture per security-research §CORS deny-by-default.
- NEVER skip the Host-header allowlist middleware on `:4318` — DNS rebinding is the documented attack against localhost OTLP/HTTP receivers per security-research §Host header validation (Coder Agent API CVE 2025-09-19, CVE-2025-66414 against MCP TypeScript SDK Dec 2025); "localhost is not a security boundary" is the explicit lesson.
- NEVER add a TauRPC procedure to a router crate without its `EXPECTED_PROCEDURES` pin in `xtask/src/main.rs` AND a validated argument struct — the `xtask capability-drift` check is the enforcement mechanism and fails CI on an unpinned procedure. **A THIRD scrub SHAPE exists, and it is not optional** (chunk `2026-08-23-metrics-points-labels`). Beside the choke-point form (`extract_service_name`, one fn feeding three consumers) and the push-site form (`scrub_otlp_field` on a bare column value), `metrics_points.labels` scrubs the **JOINED `key=value` form, UNIONED with the bare value** — either match redacts. The joined form is load-bearing, not defensive: `scrub_attribute` takes a single `&str`, and TWO of the eight catalog arms are key-name-anchored — `secret_kv` (`(?i)(password|passwd|secret|token)[\s=:]+\S+`) and `api_key` (`(?i)(api[_\-]?key|access[_\-]?token|secret[_\-]?key|auth[_\-]?token)[\s=:]+[\w\-]{12,}`). No catalog arm is `^`/`$`-anchored, so joining with `=` is a superset in practice for the `\b`-anchored arms too; the union is what keeps that true if an anchored arm is ever added. **Label KEYS are stored verbatim** — only the VALUE becomes `[REDACTED:{category}]`, reconstructed as `{key}=[REDACTED:{category}]` from the key already held. **Failure mode of this treatment, accepted:** over-redaction when the KEY alone trips a match (`password=1` redacts a benign value), per the catalog's own recall-over-precision posture. ### Code Patterns

- NEVER use `tokio::process::Command::new(...).arg(user_input)` against any string sourced from an OTLP attribute, MCP tool argument, or workspace-detector output — the MCP STDIO command-injection cluster (CVE-2025-49596 MCP Inspector, CVE-2025-54994, CVE-2025-54136 Cursor, CVE-2026-22252 LibreChat) demonstrates this is a live 2025–2026 class. **ONE product path passes OTLP-derived text to argv and is admitted only through a bound** (chunk `2026-08-26-l4-runtime-security-residuals`): the L4 `-p` prompt, gated by `validate_prompt_bounded` — 16384-byte ceiling + NUL/C0/C1 rejection with `\n`, `\r`, `\t` whitelisted, since the prompt is multi-line markdown by construction and a naive `is_control()` predicate would reject every legitimate prompt and silently disable L4. The ceiling is measured, not guessed — re-based live at chunk `2026-08-26-interpretation-brief-completeness`: ~2.4× the observed maximum — 6,932 B, the 2026-08-27 reflection prompt (the 2026-08-26 sustained v2.2 range was 6715..=6830 B with the citable-evidence-ids section; measurement notes, never bounds) — and below the Windows `CreateProcess` 32767 limit so the guard fires before the OS. Note what the bound does and does NOT do — the OTLP-derived substring is already PII-scrubbed upstream by `Digest::scrubbed_clone`, so this is a SHAPE-and-LENGTH control against the banned argv construct, not a confidentiality fix.
- NEVER load a plugin from a path that wasn't canonicalized and asserted to be inside the resolved plugin dir — pair with the §Input ban above; this defends against `~/.andromeda-pulse/plugins/../../etc/...` walks via `ANDROMEDA_PULSE_PLUGIN_DIR`.
- NEVER spawn the rmcp sidecar without verifying both the compile-time `--features mcp-server` build flag AND the runtime `ANDROMEDA_PULSE_MCP_ENABLED=true` env var — single-gate is a regression of the architecture's declared double-gate per Established Decisions MCP Server Surface.
- NEVER serialize an `anyhow::Error` directly across the TauRPC bridge — must convert to the `serde`-friendly `AppError` enum first per Conventions Error response schema (Tauri IPC). Direct serialization either fails to compile (no `Serialize` impl) or, if hand-implemented, leaks the full error chain to the webview.
- NEVER use `serde_json::from_slice::<T>(buf)` on a buffer that hasn't been size-bounded by the `axum` `DefaultBodyLimit` layer — covers the OTLP HTTP/JSON path on `:4318`.
- NEVER use the `wasmtime` `Linker` to expose host functions outside the WIT contract for a given guest — bypasses the architecture's capability-scoped sandbox per Established Decisions Plugin Runtime.
